# モバイル画像履歴 UI 設計・仕様ドラフト

> Status: **レビュー版（採用候補、正式仕様への反映前）**  
> 対象: History（スナップショット／アルバム詳細）および Generate の履歴複数選択  
> 基準: `main` の現行UI。試作: `prototype/ui-review` の `ui-prototype/`。  
> 比較: [History Baseline](https://take4548.github.io/comfy-create-helper2/history?ui=baseline) / [History Proposal](https://take4548.github.io/comfy-create-helper2/history?ui=proposal) / [Generate Baseline](https://take4548.github.io/comfy-create-helper2/?ui=baseline) / [Generate Proposal](https://take4548.github.io/comfy-create-helper2/?ui=proposal)


> **仕様の配置整理:** 複数選択の状態遷移、上部「×＋件数」、下部ドック、共通ACは [既存モバイル共通UI改修案仕様（第8章）](./mobile-common-ui-redesign-proposal.md) が主文書。本書の第4章・複数選択関連ACは画面別適用例・検討経緯として参照する。矛盾時は共通UIドラフトを優先し、アクションの種類・意味は本書の画面別定義を優先する。

## 1. 背景・解決する問題

History のモバイル表示では、フィルター領域が高い、カード上の操作と日時が競合する、スナップショットとアルバム詳細でカード操作位置が違う、ヘッダーが窮屈、複数選択メニューの情報階層が散漫、という問題をレビューした。

複数選択UIについては History と Generate で異なる表現になっていたため、**上部は選択状態／下部は対象への操作**に分離する共通パターンを試作した。各画面固有の処理内容まで同一化しない。

## 2. 基準・変更範囲

- **Preserved**: 既存ダークテーマ、画像中心の情報設計、モバイル2列カード、通常時のナビゲーション、React が管理する選択・保存・削除・アルバム操作、PCレイアウト（今回の試作対象外）。
- **Modified**: History モバイルのヘッダー内操作配置、絞り込みUI、カードアクション、複数選択バー。Generate モバイル履歴の複数選択の見た目。
- **New (Proposal only)**: コンパクトなフィルターバー、カードの「⋯」メニュー、モバイル選択時の下部固定アクションドック、選択件数の隣の「×」。
- **非対象**: 本番 `main/frontend/backend` の更新、API仕様、永続化、他ページの共通コンポーネント変更。
- このドラフトは動作モックの現在の実装方法（DOM後処理／Vite変換）を本番の実装方法として要求しない。

## 3. History の通常表示

### 3.1 ヘッダーとフィルター

- 「スナップショット／アルバム」の画面切替をヘッダーの中心に置く。
- 「セリフ一括変換」はスナップショットのフィルター・ソート列側へ移し、ヘッダーを詰め込みすぎない。
- フィルター項目はモバイルで折りたたみ可能。展開状態では既存のWorkflow／LoRA／Tag Set等の条件入力を使えるようにする。
- ソートはフィルターの展開状態に依存せず、外側のアイコン操作で実行できる。
- アルバム表示にはスナップショット用のフィルターを出さず、遷移のたびに重複ツールバーを作らない。

### 3.2 画像カードとプレビュー

- **2列グリッドを維持**する。
- 各カードの右上に「⋯」操作メニュー、日時は左下。カード上の操作はスナップショットとアルバム詳細で揃える。
- 音声関連操作・ダウンロード・削除は、既存の機能・確認フローへ委譲する。
- 画像タップによるプレビューは継続し、画像がモバイル画面内で表示されること。モックの架空SVG画像でも表示を確認できること。
- アルバム詳細では長押しによる複数選択の開始を保持し、専用の「選択モード」ボタンをProposalでは非表示とする。発見可能性は別途評価する。

## 4. 共通の複数選択パターン（モバイル）

### 4.1 上部「選択状態バー」

- 通常モードから選択モードに入ると、上部に **「×」＋「N件（またはN枚）選択中」** を表示する。
- 「×」は選択モードを終了し、選択をクリアする。タッチ領域は少なくとも44pxを目安とする。
- 「すべて選択」「選択解除」は補助操作として残す。ゼロ件時の無効状態を含め、元の選択ロジックを維持。
- 緑・紫の大きな状態背景や複数の同格ボタンを減らし、選択件数を主情報とする。

### 4.2 下部「対象へのアクション」

- 選択中のみ、アプリ下部ナビゲーション**の直上**に固定アクションドックを表示する。
- モックの現行ナビゲーション実装は `54px + env(safe-area-inset-bottom)`。これは**現在の配置基準であり、共通トークンの確定変更ではない**。
- 選択モード終了／画面離脱時はドックを取り除く。非表示のまま透明なタップ領域を残さない。
- 有効／無効状態や進行中状態は、既存の実処理と同期させる。削除の確認手順を省略しない。

| コンテキスト | 下部アクションと表記 | 注意 |
|---|---|---|
| History スナップショット一覧 | **ダウンロード／アルバムへ追加／削除** | 「アルバム」だけでは追加先操作と伝わりにくいため明記 |
| History アルバム詳細 | **ダウンロード／削除** | 追加操作を新設しない |
| Generate の履歴 | **スナップショットに保存** | History の「ダウンロード」と別の既存機能。ラベル・挙動は同一化しない |

### 4.3 長押しと選択状態

1. 利用可能な画像を長押しすると選択モードへ入り、対象が選択される。
2. 選択モード中は画像タップで選択・解除できる。
3. 「すべて選択」で対象を全選択し、「選択解除」でゼロ件に戻す（モード自体は保持）。
4. 「×」で選択モードを終了し、通常表示に戻る。
5. 下部アクションの無効状態は選択件数等の実条件に従う。
6. Generate はモック専用SVG画像を使用する。画像存在確認の都合で通常の入力イベントが登録されない問題があり、**モック限定**の長押し対応を入れている。本番実装の仕様へその仕組みを転記しない。

## 5. レスポンシブとアクセシビリティ

- 今回のProposal対象は **767px以下のモバイル画面**。デスクトップへの展開は別判断。
- 選択バーと固定ドックでサムネイル・既存ナビゲーション・モーダルのタップ領域を妨げない。
- 選択モード終了は視覚上「×」でも `aria-label="選択モード終了"` 相当の意味を保持。
- 選択中カードの輪郭／チェック表示など、色だけに依存しない識別手段を維持。
- 横幅の狭い端末、セーフエリア、画面回転、ソフトウェアキーボード、拡大表示の確認を受け入れテストに含める。

## 6. 受け入れ条件（提案）

- **AC-01** History スナップショット一覧をモバイルで開くと、2列表示を維持し、日時と「⋯」が重ならない。
- **AC-02** フィルター折りたたみの前後でソートが実行可能であり、アルバムに切り替えて戻ってもフィルターバーが重複しない。
- **AC-03** カードをタップすると画像が表示されたプレビューを開ける（単にモーダル枠が開くだけでは不十分）。
- **AC-04** Historyの画像を長押しすると選択モードに入り、「×」で選択解除・終了できる。
- **AC-05** 選択中の下部ドックがモバイルナビゲーションの直上に隙間・重なりなく表示される。
- **AC-06** 一覧の「ダウンロード」「アルバムへ追加」「削除」、アルバム詳細の「ダウンロード」「削除」が、それぞれ既存の処理を起動する。
- **AC-07** Generate履歴の画像を長押しすると選択モードに入り、Historyと同じ「×＋選択件数」／下部ドックの構成を表示する。
- **AC-08** Generateの下部アクション「スナップショットに保存」は既存の保存モーダル／保存処理につながり、Historyのダウンロードとは混同されない。
- **AC-09** 各画面で選択0件・複数件・全選択・選択解除・終了を試し、ドックの残留、重複、押せない操作が発生しない。
- **AC-10** Baselineとデスクトップ表示、および他ページの共通選択ツールバーに意図しない変更がない。

## 7. 検証根拠・未確定事項

### ユーザー確認済みの範囲

- Historyプレビュー画像が表示されるようになったとのフィードバック。
- History下部ドックと下端側の意図しない隙間が解消したとのフィードバック。
- Generate履歴の長押しが有効になったとのフィードバック。
- 最終のGenerate選択UIについて「これでいいかな」との肯定的フィードバックがあり、**本書作成に進む判断**と解釈。ただし本番実装への確定承認・全項目の受け入れ完了とは同一視しない。

### 検証が残る事項

- 実端末での一括操作実行、削除確認、選択件数同期、選択終了時のドック除去。
- 小画面・セーフエリア・端末回転・スクリーンリーダーの確認。
- CI PASS はビルド等の成功を示すにとどまり、最終的な見た目やタッチ操作の保証ではない。
- アルバム詳細の「選択モード」ボタンを隠すことによる操作の発見可能性。
- 本番へ適用するときに共通選択UIとして抽出するか、画面別に適用するかの設計判断。

## 8. 実装引き渡しの注意

1. **共通ルールの採用は別途判断**する。現在の試作は `ui-prototype/` の隔離レイヤーに置かれており、共有 `MultiSelectToolbar` の正式改修を意味しない。
2. React側へ正式実装する場合は、DOM操作による疑似ボタンの代行ではなく、選択状態とアクションを状態駆動でレンダリングする。
3. offline fixture の画像表示・長押しの回避策を本番要件に含めない。
4. 仕様の確定時は、検証済みAC・未決事項・PCへの波及範囲を更新してから `ui-specification` 相当の正式仕様として採用する。
