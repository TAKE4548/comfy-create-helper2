## 1. 背景と目的

現行モバイルGenerateは、常駐プレビューとプロンプト／パラメータ／履歴の切替、プロファイル操作、固定生成バーにより、編集可能面積が圧迫される。履歴サムネイルの横列と画面切替操作が競合する。セグメント切替やプロファイル／タグ周辺には、親・行・部品自身の余白や枠が積み重なる。加えて `AppShell` の下部ナビゲーション用領域と `MobileLayout` の `100dvh` および下部余白の組合せにより、末尾の不要な空白が発生していた。

**目標**：画像確認の導線を維持しながら入力領域を広くする。横スワイプで主要セクションを移動可能にし、タップ操作も残す。縦方向の密度を高めつつ、サブメニュー編集やプリセット操作での誤タップを増やさない。

**対象外**：デスクトップ全体の再設計、共通トークン／共通チップの一律変更、本番API・生成処理の変更、B案（入力フォーカス時のみ小型生成ボタンを追加）。

## 3. 画面構成とレイアウト

1. 既存ヘッダーと固定進捗ラインを維持する。
2. 画像の常駐プレビューは表示しない。
3. 「プロンプト／パラメータ／履歴」を画面幅に並べる。選択中は下線と文字強調で示す。外枠は使わない。モック実装ではボタン最小高 **42px**。
4. プロンプト領域は既存のプロファイル操作、プロンプト種別タブ、チップエディタ、その他入力を保持する。Undo/Redoグループおよび管理ボタンの重なる枠や背景を減らす。
5. 履歴は **3列**・正方形トリミングのサムネイル一覧で、ページの縦スクロールに従う。選択時の画像ビューアでは元の縦横比を保持。
6. 生成バーは下部ナビゲーションの上に固定し、生成／保存／キューを引き続き操作できる。
7. スクロール本体は `AppShell` 内の利用可能な高さに収め、末尾には固定生成バー相当の余白のみ残す（モックでは72px）。実機のセーフエリア・キーボード表示時の適正値は要検証。

## 4. インタラクション

### 4.1 セクション移動

- タブ見出しのタップで対応するセクションへ切り替える。
- 通常のコンテンツ領域で水平方向の十分なジェスチャーを検出したら、隣接セクションへ切り替える。端に達した後はそれ以上移動しない。
- 縦スクロールを妨げない。入力・テキスト選択・スライダー等はそれぞれの既存ジェスチャーを優先する。
- 別の横スクロール可能な要素では、そのスクロールを優先する。履歴画像グリッドは横レールでないため左右スワイプでセクション切替が可能。
- **留意**：モックのスワイプはタッチ終了時の距離・方向判定であり、本番向けにはタップとの競合、スクロール可能な子要素、長押し・ドラッグ・アクセシビリティを再検証する。

### 4.2 画像確認

1. 履歴サムネイルをタップ：大きなボトムシートを開き、選択画像を表示する。
2. シートの画像をタップ：背景を黒にした画面全面の画像ビューアに切り替える。余計なシートヘッダー・ハンドル・フッターは隠す。
3. 全画面時に画像をタップ、または右上の閉じる操作：シートへ戻る。
4. シートの閉じる操作または背景タップ：画像表示を終了する。Escape操作にも対応する。
5. 空履歴時は既存の空状態を尊重し、画像があることを捏造しない。
6. 複数選択モードなど履歴の別操作は保護する。

**全画面の定義**：モックはブラウザのビューポート全面（`100dvh`）を使う。OSのステータスバー等まで隠すFullscreen APIは含まない。これがユーザー意図に十分かは未確定。

### 4.3 プロファイル・チップ

- プロファイル行の役割と既存機能は維持する。枠付きの二重ツールバーを減らし、背景を控えめにする。
- 名前表示・チェック・選択・閉じる操作の区別を維持する。誤タップが既知の課題であるため、閉じるボタンの重要なヒット領域は縮小しない。
- タグチップ本体だけでなく親コンテナのPadding・Gapを合わせて調整する。チップのサブメニュー編集を主利用シナリオとして検証する。

## 6. 受け入れ条件（改修案の検証条件）

- **AC-01** モバイルGenerateで常駐画像プレビューがなく、プロンプト編集に利用できる面積が増える。
- **AC-02** タブ見出しのタップおよびコンテンツ上の横スワイプで3セクションを前後移動でき、現在位置を識別できる。
- **AC-03** 縦スクロール、タグ・文字入力、横スクロール子要素、スライダー、プリセット選択／閉じるが横スワイプに奪われない。
- **AC-04** 履歴画像は3列グリッドで表示され、縦スクロール可能。サムネイルタップでシートが開く。
- **AC-05** シート画像タップで画面全面表示になり、画像の縦横比を維持する。閉じる操作で前の状態へ戻れる。
- **AC-06** プロンプト・パラメータ・履歴のいずれも、スクロール末尾に不必要な画面高さ相当の空白がない。固定生成バーに内容が隠れない。
- **AC-07** Undo/Redo、プリセットのチェック・選択・閉じる、タグサブメニュー、生成・保存・キュー機能が現行同等に動く。
- **AC-08** モバイル以外、Baselineおよび本番APIの挙動は意図せず変わらない。
- **AC-09** モバイル幅、セーフエリアあり／なし、ソフトキーボード開閉、履歴0枚／多数枚／原画なし、長文タグ、アクセシビリティ操作でレイアウトと操作を確認する。

## 9. 既存デザイン規約との整合・共通コンポーネント影響評価（追記）

### 9.1 設計判断の原則

- この文書は**改修案**であり、ここに書いた内容だけで共通デザインルールの変更を承認したことにはならない。
- Generate固有の構造・画像確認・画面切替はページスコープで扱う。
- **他画面でも使われている共通コンポーネントの視覚仕様は、Generate専用に別ルールを作ることを原則としない。** 局所モックで効果を検証した値を候補として提示し、他の利用画面を比較した上で共通仕様に採用するか判断する。
- 一方、ページ側コンテナの余白・背景等は、共通部品の内側寸法と区別して管理する。異なるレイアウト文脈で同じ外側余白を強制しない。
- 既存の配色・フォント・状態表示・操作パターン・アクセシビリティを優先し、必要な差分だけを導入する。

### 9.3 共通タグチップの決定フロー

1. **共有部品の候補値**：モックで試したチップ `padding: 3px 8px`、内部 `gap: 5px`、エディタ内 `padding/gap: 6px` は**比較候補**であり、Generate限定の本番仕様ではない。
2. **利用箇所の確認**：`TagChipEditor` を参照する画面を洗い出し、GenerateとTagSet作成・編集を最低限含めた同寸法での比較を行う。`TagChipInput`／`TagChipViewer` についても、表示体系の統一要否を別途判断する。
3. **操作試験**：通常の選択、既存チップのサブメニュー編集、ドラッグ順序変更、削除、入力、長文・多行、タッチとキーボード操作を確認する。
4. **採否判断**：共通部品として適合すれば一貫したトークン／コンポーネント変更を提案する。適合しない場合は、Generateのみを先行して例外化せず、違いの根拠と必要なバリアント設計を提示して別途判断を得る。
5. **変更の承認**：共有部品への適用は対象画面、比較結果、後方互換性、受け入れ条件を添えて承認を得るまで実施しない。

### 9.4 追加で確保すべき機能・アクセシビリティ条件

- **タップ領域**：3タブの見た目は控えめでも、十分な実ヒット領域と明瞭なフォーカス状態を保つ。モックの42pxは最終規格値ではない。既存の44px級コントロールを縮小する場合は、周辺要素との間隔、片手操作、誤タップ率を比較してから決定する。
- **プレビュー機能の継承**：常駐プレビューが担っていたダウンロード、選択画像・生成直後の画像表示、最新画像追従、画像のエラー表示、保存・複数選択などの機能を棚卸しし、どの操作先へ移すか明示する。機能を無断削除しない。
- **画像シート／全画面**：戻り先、閉じる方法、フォーカス制御、背景操作のブロック、画面回転、画像読込中・失敗時を確認する。Fullscreen APIの採用要否は独立した未確定事項。
- **画面移動**：スワイプは補助操作であり、タブタップを必ず残す。入力・タグサブメニュー・ドラッグ・横スクロール・支援技術の利用を妨げない。

### 9.5 追加受け入れ条件

- **AC-10 共通部品の整合**：タグチップ密度を本番に反映する場合、`TagChipEditor` の利用画面を列挙し、共通ルールとしての採否または明示されたバリアント理由を記録する。Generateのみの無根拠な例外を作らない。
- **AC-11 回帰試験**：Generate以外のタグ編集画面でもチップの表示、編集サブメニュー、削除、入力、折返し、キーボード／タッチ操作が従来同等に利用できる。
- **AC-12 画像機能の非退行**：常駐プレビュー撤去前後の画像機能対応表を作成し、各機能の移行先と検証証拠を確認する。
- **AC-13 操作対象**：小型タブ・管理ボタン・プリセットのチェック／閉じる操作でタップ・フォーカス・隣接ターゲットの誤操作が生じないことを実機相当で確認する。
- **AC-14 共通変更の明示的承認**：共通コンポーネントやシェルに及ぶ変更はページ固有の改修と分け、影響画面・トレードオフ・比較結果を示して採用判断を得る。

> **追記の位置づけ**：本節は改修案の設計ゲートと適用範囲を定めるもので、共通部品を実際に変更したことや最終採用を意味しない。モック内の局所CSSは見た目を評価するための暫定実装である。

## 10. 追加修正対象：タグチップが固定生成バーより前面に出る

### 問題

モバイルGenerateでプロンプト領域をスクロールしたとき、**タグチップが画面下部の固定生成バーより前面に描画される**とのユーザー報告がある。固定アクションの視認性と操作性を損なうため、今回の改修対象に含める。

- **確認済み**：ユーザーによる実画面の事象報告。
- **未確認**：発生する端末・位置・チップ操作状態、および具体的な原因。チップのドラッグ時の `z-index`、スタッキングコンテキスト、固定生成バーの階層などは実画面・DOM・CSSを照合して特定する。現段階では原因を断定しない。

### 期待する重なり順と動作

1. 通常のプロンプト本文・タグチップ・ドラッグ中のチップは、**固定生成バーの描画領域より背面**になる。スクロールしても生成・保存・キューボタンを隠さず、タップを奪わない。
2. モーダル、ボトムシート、全画面画像ビューア、チップの編集サブメニューなどのオーバーレイは、**用途に応じて明示的に階層を設計**する。単純に全要素の `z-index` を下げない。
3. タグチップのドラッグ、選択、サブメニュー表示、入力フォーカス、キーボード開閉を維持する。
4. 固定生成バーとボトムナビゲーションの相互関係、セーフエリア、スクロール末尾の余白を再確認する。
5. `TagChipEditor` が共通コンポーネントであることを踏まえ、**Generate専用の無根拠な例外を追加しない**。共通のドラッグ／ポップオーバー階層に問題がある場合は、他の利用画面を含めた影響調査と共通修正案の判断を先に行う。Generate固有の固定バーとの関係が原因なら、ページ側で局所的に解決する。
