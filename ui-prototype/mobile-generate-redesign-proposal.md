## 1. 背景と目的

現行モバイルGenerateは、常駐プレビューとプロンプト／パラメータ／履歴の切替、プロファイル操作、固定生成バーにより、編集可能面積が圧迫される。履歴サムネイルの横列と画面切替操作が競合する。セグメント切替やプロファイル／タグ周辺には、親・行・部品自身の余白や枠が積み重なる。加えて `AppShell` の下部ナビゲーション用領域と `MobileLayout` の `100dvh` および下部余白の組合せにより、末尾の不要な空白が発生していた。

**目標**：画像確認の導線を維持しながら入力領域を広くする。横スワイプで主要セクションを移動可能にし、タップ操作も残す。縦方向の密度を高めつつ、サブメニュー編集やプリセット操作での誤タップを増やさない。

**対象外**：デスクトップ全体の再設計、共通トークン／共通チップの一律変更、本番API・生成処理の変更、B案（入力フォーカス時のみ小型生成ボタンを追加）。

## 3. 画面構成とレイアウト

1. 既存ヘッダーと固定進捗ラインを維持する。
2. 画像の常駐プレビューは表示しない。
3. 「プロンプト／パラメータ／履歴」を画面幅に並べる。選択中は下線と文字強調で示す。外枠は使わない。モック実装ではボタン最小高 **42px**。
4. プロンプト領域は既存のプロファイル操作、プロンプト種別タブ、チップエディタ、その他入力を保持する。Undo/Redoグループおよび管理ボタンの重なる枠や背景を減らす。
5. 履歴は **3列**・正方形トリミングのサムネイル一覧で、ページの縦スクロールに従う。選択時の画像ビューアでは元の縦横比を保持。
6. 生成バーは下部ナビゲーションの上に固定し、生成／保存／キューを引き続き操作できる。
7. スクロール本体は `AppShell` 内の利用可能な高さに収め、末尾には固定生成バー相当の余白のみ残す（モックでは72px）。実機のセーフエリア・キーボード表示時の適正値は要検証。

## 4. インタラクション

### 4.1 セクション移動

- タブ見出しのタップで対応するセクションへ切り替える。
- 通常のコンテンツ領域で水平方向の十分なジェスチャーを検出したら、隣接セクションへ切り替える。端に達した後はそれ以上移動しない。
- 縦スクロールを妨げない。入力・テキスト選択・スライダー等はそれぞれの既存ジェスチャーを優先する。
- 別の横スクロール可能な要素では、そのスクロールを優先する。履歴画像グリッドは横レールでないため左右スワイプでセクション切替が可能。
- **留意**：モックのスワイプはタッチ終了時の距離・方向判定であり、本番向けにはタップとの競合、スクロール可能な子要素、長押し・ドラッグ・アクセシビリティを再検証する。

### 4.2 画像確認

1. 履歴サムネイルをタップ：大きなボトムシートを開き、選択画像を表示する。
2. シートの画像をタップ：背景を黒にした画面全面の画像ビューアに切り替える。余計なシートヘッダー・ハンドル・フッターは隠す。
3. 全画面時に画像をタップ、または右上の閉じる操作：シートへ戻る。
4. シートの閉じる操作または背景タップ：画像表示を終了する。Escape操作にも対応する。
5. 空履歴時は既存の空状態を尊重し、画像があることを捏造しない。
6. 複数選択モードなど履歴の別操作は保護する。

**全画面の定義**：モックはブラウザのビューポート全面（`100dvh`）を使う。OSのステータスバー等まで隠すFullscreen APIは含まない。これがユーザー意図に十分かは未確定。

### 4.3 プロファイル・チップ

- プロファイル行の役割と既存機能は維持する。枠付きの二重ツールバーを減らし、背景を控えめにする。
- 名前表示・チェック・選択・閉じる操作の区別を維持する。誤タップが既知の課題であるため、閉じるボタンの重要なヒット領域は縮小しない。
- タグチップ本体だけでなく親コンテナのPadding・Gapを合わせて調整する。チップのサブメニュー編集を主利用シナリオとして検証する。

## 5. モックで採用した寸法（最終確定値ではない）

| 項目 | 比較用Proposal値 |
|---|---|
| 3セクションナビゲーション | 背景透明、下線選択、外側左右12px、最小高42px、文字12px |
| プロファイル領域 | 上下Padding 4px、行間4px、グループ枠の簡素化 |
| プロファイル名称チップ | Paddingおおむね上下3px・左右8px、内部Gap約4px |
| プロンプト種別タブ領域 | 上下Padding 6px、内側スクロール行の上下Paddingなし |
| タグエディタコンテナ | Padding 6px、Gap 6px |
| タグチップ | Padding上下3px・左右8px、内部Gap 5px |
| 履歴サムネイル | 3列・列間8px・正方形 |
| Undo/Redo・プリセット閉じる・固定生成バー | 重要な操作領域を維持する方針 |
| スクロール下端 | 固定生成バーとの重なりを防ぐ72pxのクリアランス（モック） |

数値はCSS試作の目標値・設定値であり、実DOMでの最終実寸保証ではない。タップ領域の40〜44px近辺については本番適用前に再確認する。

## 6. 受け入れ条件（改修案の検証条件）

- **AC-01** モバイルGenerateで常駐画像プレビューがなく、プロンプト編集に利用できる面積が増える。
- **AC-02** タブ見出しのタップおよびコンテンツ上の横スワイプで3セクションを前後移動でき、現在位置を識別できる。
- **AC-03** 縦スクロール、タグ・文字入力、横スクロール子要素、スライダー、プリセット選択／閉じるが横スワイプに奪われない。
- **AC-04** 履歴画像は3列グリッドで表示され、縦スクロール可能。サムネイルタップでシートが開く。
- **AC-05** シート画像タップで画面全面表示になり、画像の縦横比を維持する。閉じる操作で前の状態へ戻れる。
- **AC-06** プロンプト・パラメータ・履歴のいずれも、スクロール末尾に不必要な画面高さ相当の空白がない。固定生成バーに内容が隠れない。
- **AC-07** Undo/Redo、プリセットのチェック・選択・閉じる、タグサブメニュー、生成・保存・キュー機能が現行同等に動く。
- **AC-08** モバイル以外、Baselineおよび本番APIの挙動は意図せず変わらない。
- **AC-09** モバイル幅、セーフエリアあり／なし、ソフトキーボード開閉、履歴0枚／多数枚／原画なし、長文タグ、アクセシビリティ操作でレイアウトと操作を確認する。

## 7. 検証実績と未検証事項

### 確認済み

- レビューモック上で、ユーザーがボトムシート、スワイプ、履歴グリッド、スクロール末尾の修正、余白調整を試し、総じて肯定的に評価している。
- GitHub Pages上でBaselineとProposalを比較可能。
- 2026-10-18 時点で最新コミットの `UI Prototype Check` と `UI Prototype Pages` が成功。
- モックは架空のワークフロー、プリセット、12枚のデータURL画像を使用し、本番APIから分離している。

### 未確認／制約

- 実運用の原画可用性判定・画像解像度・ダウンロード・エラーハンドリングとの統合。
- ブラウザや実機別のスワイプ競合、スクロール位置維持、フォーカス・スクリーンリーダー対応。
- 画像完了直後の通知・新画像への導線。常駐プレビュー撤去後に履歴への移動頻度が過大にならないか。
- 本番コードへの反映方式。現モックのCSSセレクターやDOM監視は試験用であり、実装手法として固定しない。
- 「本当の全画面」がFullscreen APIによるブラウザUI非表示まで必要かどうか。
- 画像件数が少ない場合の表示密度、狭幅端末・横向き端末でのタップ領域。
