# モバイル LoRA・タグセット画面 改修案仕様（レビュー版）

**上位共通仕様**：[モバイル共通 UI/UX 改修案仕様](./mobile-common-ui-redesign-proposal.md)。本書はLoRA・Tag Setのカード／詳細・編集／Subsets等の画面固有ルールを定義する。共通スクロール原則、固定操作、画像シート、共通コンポーネント変更手順は上位文書を参照し、ここでは両ページへの適用条件を記す。


- **状態**：改修案／採用未確定。本番実装の指示ではない。
- **対象**：LoRAs（`/loras`）・Tag Sets（`/tags`）のモバイル画面。Proposal CSS の主な適用範囲は幅 767px 以下。
- **比較環境**：`prototype/ui-review` の `ui-prototype/`。Baseline と Proposal で同じ架空データを使用。
- **LoRA比較**：[Baseline](https://take4548.github.io/comfy-create-helper2/loras?ui=baseline) ／ [Proposal](https://take4548.github.io/comfy-create-helper2/loras?ui=proposal)
- **タグセット比較**：[Baseline](https://take4548.github.io/comfy-create-helper2/tags?ui=baseline) ／ [Proposal](https://take4548.github.io/comfy-create-helper2/tags?ui=proposal)
- **主な現行実装**：`frontend/src/pages/LoRAsPage.tsx`、`frontend/src/pages/TagsPage.tsx`、`frontend/src/components/ImageCarousel.tsx`、`frontend/src/components/LoraModals/`、`frontend/src/components/TagSetModals/`
- **Proposal参照時点**：2026-10-18、コミット `54edfdca1ecee7e797f69d0dad9916291cef8ea3`。
- **判断区分**：ユーザーの「いいかな」は比較モックの方向性に対する評価。正式採用・数値確定・本番反映承認ではない。

## 1. 背景・目的

LoRAとタグセットは、共通してヘッダー、検索、新規作成、カテゴリ・Base Modelフィルター、カテゴリ別グリッド、カード並べ替え、詳細・編集・削除、一括操作を備える。モバイルの実画面レビューでは以下が指摘された。

1. カード右上の編集・削除ボタンが重なる。サムネイルの寄り方も気になる。
2. カード下部の独立スクロールがページ縦スクロールを妨げ、情報がはみ出す。
3. Stickyカテゴリ見出しがスクロール領域上端から不自然に離れる。
4. 詳細が中央モーダル風で、常駐する大きな画像とRelated Snapshotsが本文を圧迫する。
5. 詳細のEdit／Saveなどが末尾までスクロールしないと操作できず、途中のSticky配置では不自然な位置に浮いた。
6. 閲覧状態のClose/Editと編集状態のCancel/Saveの左右関係が一致しない。
7. タグセットはカードの編集アイコンと詳細からのEditで異なる編集画面に進む。
8. Tag SetのSubsets一覧が独立スクロールし、詳細編集・New Tag Set作成の両方で操作しにくい。
9. 一覧カードにカテゴリ表示が重複し、対象Base Modelは見えない。タグチップも小さく、可読性と収まりが悪い。

**目的**：一覧では対象を識別しやすく、ページ全体を自然にスクロールできること。詳細・編集では本文領域を広く取り、画像操作と確定操作へ迷わず到達できること。2画面の共通パターンを揃えながら、LoRA／Tag Set固有の機能を失わない。

## 2. Preserved / Modified / New

| 区分 | 対象 | 改修案 |
|---|---|---|
| Preserved | アプリ全体 | 既存テーマ、タイポグラフィ、PageHeader、グローバルナビゲーション、検索・カテゴリ／Base Model絞り込み |
| Preserved | 一覧機能 | カテゴリの折りたたみ、並べ替え、選択・一括操作、詳細閲覧、編集・削除 |
| Preserved | 詳細機能 | LoRAのトリガーワード・強度・パス・対象モデル、Tag Setのタグ・サブセット、コピー、画像・Cover管理 |
| Modified | カード表示 | **高さ320px固定**を維持したまま、下部は「タイトル・Description・対象Base Model」に限定 |
| Modified | テキスト | タイトル最大2行、Description最大2行、モデル名は下端に揃えて1行省略。全文は詳細へ |
| Modified | カテゴリ | カード内バッジを省き、既存のカテゴリ見出しに集約 |
| Modified | スクロール | カード内スクロールを撤去し、ページの縦スクロールを優先。Stickyカテゴリ見出しは上端に接する |
| Modified | カード操作 | 編集・削除を重ならない位置に整理し、サムネイル画像フレームを中央に合わせる |
| Modified | 詳細 | モバイルで下端起点のボトムシート。本文がスクロールし、独立したフッターが固定される |
| Modified | 詳細画像 | 常時表示は小型CoverとSnapshot件数に集約し、画像一覧はCoverタップで開く |
| Modified | アクション配置 | **左：Close／Cancel、右：Edit／Save** に統一 |
| Modified | Tag Setの編集 | カードからの編集と詳細内Editを同じ編集状態へ接続 |
| Modified | Subsets | 詳細編集・新規作成で一覧の独立スクロールをなくし、親画面のスクロールに統合 |
| New | 画像ギャラリー導線 | CoverタップからSnapshot一覧とCover候補の確認へ進む試作 |

## 3. 一覧カード仕様（両画面共通）

### 3.1 レイアウトと情報優先順位

- モバイルカードの外形は**固定高さ320px**。グリッドの同じ列・行で揃うことを重視する。幅はレスポンシブグリッドに従う。
- サムネイル表示領域を揃え、画像フレームを中央配置する。現行の画像アスペクト比設定の扱いは保持し、中央寄せが画像切れや歪みを生まないことを確認する。
- 下部の一覧情報は、**①タイトル、②Description、③対象Base Model** の3項目のみ。上下の順序を固定する。モデルは情報領域の下端へ揃える。
- タイトルは最大2行、Descriptionは最大2行とし、超過を省略する。モデル表示は1行で省略する。モデルが複数の場合の表示形式・全件確認導線は最終設計で決定する。
- カテゴリはセクションヘッダーに表示し、カード内で繰り返さない。未分類は未分類セクションに分類する。
- タグチップ、トリガーワード、強度、パス、サブセット、タグ数などは**カード下部の情報領域から除外**し、詳細で確認する。これは一覧での簡略化であり、関連機能の廃止を意味しない。
- 内部スクロールは設けない。長いテキストはカードからはみ出さない。ページ全体の縦スクロールを優先する。
- 編集・削除、並べ替えハンドル、複数選択時の操作は既存機能を維持する。タップ領域の重なりを避け、画像閲覧・カードタップ・ドラッグと競合させない。
- カテゴリSticky見出しはスクロール領域の上端に接し、不自然な空隙やカードへの重なりを生じさせない。

### 3.2 ページ固有情報

| LoRA | タグセット |
|---|---|
| タイトル＝モデル名、Description＝説明、対象Base Modelを表示 | タイトル＝タグセット名、Description＝説明、対象Base Modelを表示 |
| 詳細でトリガーワード／推奨強度／ファイルパスなどを確認 | 詳細でタグ／サブセット／コピー機能などを確認 |
| 一覧のトリガーワード単体コピー導線は簡略化による影響を検証 | 一覧のタグ単体コピー導線は簡略化による影響を検証 |

**注意**：現モックはDOM追加・CSSによる比較用の3項目表示であり、Reactの現行一覧実装自体の構造変更ではない。本番実装では、不要項目の単なるCSS隠蔽より、表示モデル／コンポーネントを整理する方法を検討する。

## 4. 詳細・編集シート（両画面共通）

1. スマートフォンで詳細を開くと下端からボトムシートを表示する。PCの既存ダイアログは原則として維持。
2. シートはヘッダー、**本文用の単一縦スクロール領域**、**下部固定アクションフッター**に分割する。
3. 閲覧中のフッターは左 **Close**／右 **Edit**。編集中は左 **Cancel**／右 **Save**。左＝戻る・取消、右＝進む・確定の規則を維持。
4. フッターは本文のスクロール距離に依存せず操作できる。セーフエリア、ソフトキーボード表示時、保存中・バリデーションエラーを確認する。
5. 常時大きな画像やRelated Snapshotsを表示せず、本文上部には小型**Coverサムネイル＋Snapshot件数**を表示する。
6. Coverタップで画像一覧の追加ビューを開き、関連画像を確認できる。必要に応じてCoverを選ぶ導線を提供し、閲覧と編集の権限・保存タイミングを分けて扱う。
7. 画像なし／Snapshotなし／画像読込失敗／縦長・横長画像でもレイアウトを破綻させない。
8. フォーカス移動、Escape／Close、背面タップ、キーボード、スクリーンリーダーの挙動は本番適用前に確認する。

**制約**：現在のProposalにあるCover設定導線はReact本体の編集機能への間接接続を含む暫定試作であり、全状態での動作保証はない。画像一覧のアイテム選択とCover設定の保存・取消、画像順、件数表示の整合は追加検証が必要。

## 5. Tag Set固有の編集・作成仕様

- カード上の編集アイコンと「詳細→Edit」は、同じタグセットに対し**同じ編集UI・フィールド・操作状態**を開く。異なる別モーダルを同一の操作として残さない。
- Tag Setの名前、Description、対象モデル、タグ、サブセット、各サブセットのタグ・画像変更機能を維持する。
- **Subsetsの一覧は内部高さ160pxの制限と独立縦スクロールを廃止**し、親シート／作成モーダルを一続きでスクロールする。
- 上記は**詳細からの編集**と**New Tag Setからの作成**の両導線に適用する。
- New Tag Setの作成UIは現時点では詳細用ボトムシートとは別構造。作成画面のフッター固定やボトムシート統一は最終判断前の別検証事項。
- 既存の `TagSetFormFields` は共通コンポーネント。共通部品のスクロール仕様を変更する場合、使用箇所を洗い出し、適用範囲と影響を明記する。

## 6. 共通部品・変更境界

| 対象 | 判定・方針 |
|---|---|
| `PageHeader`、共通テーマ、ページナビ | **Preserved**。今回の目的で変更しない |
| `ImageCarousel` | 共有部品。カード中央配置はまずページ側で調整。他の利用画面へグローバル変更を波及させない |
| `LoraDetailModal`／`TagSetDetailModal` | ページ固有の詳細機能を保ちつつモバイルシート構造は共通パターンへ |
| `TagSetEditModal`／`TagSetCreateModal` | 異なる入口・作成状態を棚卸しし、同じ用途には同じ表示・操作を提供する |
| `TagSetFormFields` | 共有フォーム。Subsetsスクロールの共通仕様／ページ固有制約を明確化する |
| `TagChipEditor`／`TagChipViewer` | Generate等との整合を確認。共通チップの密度・挙動を変更する場合は横断的に評価し、別途承認を得る |
| カテゴリ／Base Modelフィルター、ドラッグ／複数選択 | 機能維持。共通UIルールの変更は個別承認事項 |

Baseline-Preserving方針により、問題のない配色、余白、ラベル、共通操作は維持する。試験用のDOM監視・CSS上書きを本番実装方式として確定しない。

## 7. モック条件と試験データ

- `ui-prototype/src/fixtureData.ts`：LoRA **18件**、Tag Set **18件**、3カテゴリ＋未分類、2種の架空Base Model、説明文の長短、Snapshotの件数差など。
- `ui-prototype/src/offlineTransport.ts`：外部APIに接続しない隔離フィクスチャ。
- `ui-prototype/src/collectionProposal.ts`／`comparison.css`：Proposal限定のUI差分。
- 固定カード寸法320px、情報表示行数2／2／1は**比較用候補**であり最終確定値ではない。
- 他のデータ組合せ（極端な長文、対象モデル多数、空画像、カテゴリ多数、少数・大量データ、サイズ違い）での網羅的検証は未了。

## 8. 受け入れ条件（改修案としての検証ゲート）

- **AC-01** 2ページで一覧カードの外形が高さ320pxに揃い、狭い画面でもはみ出し・カード同士の重なりがない。
- **AC-02** 下部情報はタイトル・Description・対応Base Modelのみ。表示行数制限2／2／1、モデル行の下端揃えを確認する。
- **AC-03** カード内独立スクロールがなく、ページ全体の縦スクロールが途切れない。
- **AC-04** 編集・削除は重ならず、カードタップ・並べ替え・複数選択との操作競合がない。
- **AC-05** カテゴリ見出しは上端に適切にSticky表示され、カード内カテゴリバッジは重複表示しない。
- **AC-06** 詳細・編集がモバイルでボトムシート表示され、本文が主にスクロールし、アクションフッターが底部に固定される。
- **AC-07** 詳細はClose左／Edit右、編集中はCancel左／Save右。ボタンはスクロールせず利用できる。
- **AC-08** Cover＋Snapshot件数の簡潔な入口を表示し、画像一覧、画像なし、Cover設定、保存・取消を破綻なく操作できる。
- **AC-09** Tag Setのカード編集と詳細編集が同じ編集UIに遷移する。
- **AC-10** Tag SetのSubsets編集とNew Tag Set作成で内部スクロールがなく、親画面だけが縦スクロールする。
- **AC-11** タグ編集、LoRAトリガーワード・強度・コピー、作成、削除、一括操作、ドラッグ、絞り込みなど既存機能が失われない。
- **AC-12** フォーカス、タッチ領域、ソフトキーボード、セーフエリア、アクセシビリティ、タッチ／キーボード操作、長文・空状態を確認する。
- **AC-13** Baseline、PC画面、本番APIへの意図しない変更がなく、共通コンポーネントへの変更が別途明示・承認される。
