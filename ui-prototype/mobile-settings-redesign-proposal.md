# Settings モバイル UI/UX 改修仕様（レビュー合意版）

- **対象**：Settings（ワークフロー・モデル／プロンプト支援／セリフ支援／翻訳／システム・一般）のモバイル表示。
- **判断状況**：2026-10-18 のモックレビューで内容・方向性を了承。**UI/UX要件の合意**であり、本番実装・保存方式の技術設計・全デバイスの検証完了を意味しない。
- **比較**：[Baseline](https://take4548.github.io/comfy-create-helper2/settings?ui=baseline) ／ [Proposal](https://take4548.github.io/comfy-create-helper2/settings?ui=proposal)。
- **境界**：`prototype/ui-review` の `ui-prototype/` だけで比較。Baselineと`main`の`frontend/`・`backend/`は変更しない。
- **原則**：Baseline-Preserving, Problem-Driven Design。既存の配色、5分類、各機能、コンポーネントの基本意匠を維持する。

## 1. 解決する問題と維持する要素

### 維持（Preserved）
- 設定カテゴリの5分割、選択タブの可視化、タブ直接タップ、既存設定と利用可能な操作。
- 明示確定を要するマスター・プリセットの作成／更新やワークフロー構成の適用。
- 注意／警告、エラー、保存失敗、未保存状態、フィールドラベルと単位・意味が不可欠な説明。
- 既存のダークテーマ、タイポグラフィ、色のアクセント、主要なコンポーネント。

### 変更（Modified）
- モバイルでの外周余白・カード間隔を必要最小限に縮小し、読みやすさと操作領域を損なわない。
- 長い見出し、補足、操作ボタンが横一列に競合するレイアウトを整理。
- 設定の補足文章は常時大量に表示せず、必要なときに参照できる。
- 保存操作は原則オートセーブ、例外的に明示保存とするUI上の区別を明確化。
- 設定カテゴリ間の左右スワイプをタブタップの補助操作として加える。

## 2. ワークフロー・モデル：ノードマッピング

- `Node Mapping Masters` ヘッダーは、タイトルを識別できるようにし、本文説明と操作ボタンの競合をなくす。不要なヘッダー補足は常時表示しない。
- 主操作 **`Add Master`** は直接表示する。
- **「ステージ管理」「カスタム型マスタ」** は「管理 ⋯」サブメニュー内に移す。元の操作／遷移先は維持。
- `Add Master` と「管理 ⋯」は互いに重ならず、コンテナ幅を超えない。開いたメニューは必要な領域内で読め、操作できる。
- 変更によって既存マッピング編集やグループ切替を阻害しない。

## 3. セリフ支援／システム・一般：説明と info

- 初見で明白な言い換え（見出しを読み直すだけの文章）や重複説明は削減する。**すべての説明を一律info化しない**。
- 効果・条件・副作用など、読めば操作の判断に役立つ詳細説明のみ、控えめな **ⓘ** から参照する。画像処理フィルタの詳細パラメータ説明が主な対象。
- アイコンは小さく低強調。アイコン専用行は作らない。見出し・フィールドラベルと同じ行へ、タイトルや入力値に重ならず配置する。
- タイトルとⓘが重なる場合、タイトルを覆う絶対配置は使わず、幅を分けたインライン配置とする。無理な文字の切り捨ても避ける。
- ⓘのタップで内容を表示、再タップ・外側タップ・Escape・必要に応じたスクロールで閉じる。
- 説明表示は**不透明なダーク背景＋十分な文字コントラスト**。画面左右と上下に収まり、本文カードやスクロール領域にクリップされない。内容が長い場合は内部でスクロール可能。
- 表示位置の調整により、本来の設定画面のレイアウト幅・高さが増えない。
- 警告、失敗、保存状態などの重要情報は、隠れたinfoだけに依存させない。

## 4. 保存方式の基本ルール

| 分類 | 期待するUI | 対象例 | 判断理由 |
|---|---|---|---|
| 即時オートセーブ | 変更で保存、通常は保存ボタンなし | ON/OFF、表示設定、モデル選択、サムネイル比率、長押し関連 | 操作が単純で元に戻しやすい |
| 入力確定後オートセーブ | 編集中は意図しない連続送信を避け、入力確定後に保存。保存ボタンなし | LLM生成パラメータ、画像処理フィルタ、VRAM安全ガード閾値、翻訳入力待ち時間 | 個別設定値であり、都度「保存」を押す理由が薄い |
| 明示保存／適用 | 編集範囲内の操作末尾または適切なヘッダーに保存・適用を置く | 長文のLLMシステムプロンプト、翻訳サービス・認証設定、ワークフロー設定一括適用、口調プリセット／マスターの作成・編集 | 複数値をまとまりとして確定・検証する必要がある |

- 混在自体は許容するが、**同じ性質の設定は同じ保存規則**に揃える。保存ボタンは明示操作の価値がある場合だけ残す。
- オートセーブの**通常時は状態文言を常設しない**。保存中は必要に応じて控えめなフィードバック、保存成功は短く／必要時だけ、失敗・未保存は明確に残す。
- 保存失敗時に「保存済み」と誤表示しない。入力中・送信中・失敗後の扱い、競合リクエスト、取り消し、再試行はSDD設計フェーズで決める。
- **モックで保存ボタンを非表示にしても自動保存が実装されたことにはならない**。既存API／React保存ハンドラーの変更や機能検証は対象外。評価対象はボタンの要否と位置・状態表現。

## 5. 操作とレスポンシブ

- モバイルの設定カテゴリは**左右スワイプでも前後に切替可能**。タブの直接タップ・キーボード操作は維持する。
- 縦スクロールを優先し、意図的な横方向ジェスチャーと判定できる場合だけタブを移す。
- スライダー、入力、ボタン、モーダル／シート、横スクロールの独立領域、ドラッグ操作のジェスチャーは奪わない。先頭・末尾からは隣接しないタブへ移動しない。
- 口調プリセットのモバイルボトムシートは画面幅を超えず、**キャンセル左／保存右**の操作を崩さない。横方向のはみ出しを防ぎ、ソフトキーボード・セーフエリア・内容スクロールに注意する。
- コンパクト化してもボタン間が衝突せず、押しやすさ・フォーカス視認性を保つ。

## 6. 画面別受け入れ条件

| ID | 判定内容 |
|---|---|
| SET-01 | 5カテゴリと設定機能は維持。Baselineに不要な変更がない |
| SET-02 | 375px級で設定カードの余白が過剰でなく、横スクロール／重なりを生じない |
| SET-03 | Node Mapping Mastersの主操作と管理サブメニューが独立し、メニュー項目が利用できる |
| SET-04 | セリフ／システムのⓘは余分な独立行を作らず、タイトル・値・開閉アイコンと重ならない |
| SET-05 | すべての対象infoはタップで読め、不透明背景で全文の閲覧が可能。画面外・カード枠外クリップがない |
| SET-06 | 明白な説明は整理される一方、詳細パラメータの説明・重要な警告を参照できる |
| SET-07 | オートセーブ候補の保存ボタンを除き、明示保存が必要な画面の保存・適用導線を維持する |
| SET-08 | 保存中／成功／失敗／未保存の表現が矛盾せず、成功を常時過剰に表示しない |
| SET-09 | 左右スワイプ切替が可能で、縦スクロール・スライダー・入力・シートを妨げない |
| SET-10 | 口調プリセットのシートとキャンセル・保存が画面幅内で利用可能 |
| SET-11 | 既存の明示保存・接続確認・危険な設定の確認手順は不用意に自動確定化しない |
| SET-12 | プロトタイプは本番APIから隔離され、CI・実画面比較で評価する |

## 7. 確認状況と実装への引き継ぎ

- **ユーザーレビューで確認／了承**：カテゴリ分類維持、密度改善、ノード管理サブメニュー、説明のinfo化の方向、ポップオーバーの見切れ・背景不透明化、保存ボタンの原則、スワイプの要望。
- **モックで試作**：`ui-prototype/src/settingsProposal.ts`／`comparison.css`。レビュー中に実画面で発見された重なり・はみ出し・透過背景は都度修正。最終版の全条件について実機横断の完了確認は別途必要。
- **SDDへの引き継ぎ**：本番オートセーブのトリガー、入力確定・デバウンス、API整合性、エラー・再試行・状態管理、テスト構成はSDDの設計フェーズで決定する。本書は表示・操作・受け入れ要件であり、具体的な技術設計を拘束しない。
- **共通部品の影響**：Modalやタブ等の共通コンポーネントを変更する場合は他画面への影響を調査し、Settings固有改修と区別する。
