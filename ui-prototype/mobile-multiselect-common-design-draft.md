# 共通UI設計ドラフト — モバイル複数選択

> 状態: レビュー用・正式採用未確定。適用検討対象: History（スナップショット／アルバム詳細）、Generate（履歴）。  
> 基準: main、検討モック: prototype/ui-review の ui-prototype/。  
> 画面固有の定義: [モバイル画像履歴UI設計ドラフト](./mobile-history-generate-selection-design-draft.md)。

## 1. 共通ルールの適用範囲

本書は画像一覧等での**複数選択モードの共通UIパターン**を記述する。全ページへの展開、本番の共通コンポーネント変更は未承認。ページ固有のアクションの種類と処理内容は各画面仕様へ委譲する。

- Preserved: アプリ既存のダークテーマ、ナビゲーション、各画面の実処理、選択状態の既存ロジック。
- Modified（案）: 選択時の情報階層、終了操作、補助操作の配置、一括操作の表示。
- New（案）: モバイル下部の共通アクションドック。

## 2. 選択モードへの遷移

- 通常状態から対象画像の長押しにより選択モードへ入る。最初の対象を選択する。
- 選択モード中は対象のタップで選択・解除する。
- 「すべて選択」で対象範囲を全選択し、「選択解除」で選択0件にする。この操作ではモードを終了しない。
- 終了ボタン「×」で選択モードを終了し、選択内容をクリアする。
- 長押しをスクロールと誤判定しない。時間・移動許容値は既存の設定・操作方式を基準にし、モック専用の値を共通仕様にはしない。
- 選択できないアイテムの扱い、対象範囲、並べ替え／フィルター後の選択保持は各画面の既存挙動を尊重し、改変が必要なら別途判断する。

## 3. 上部の選択状態バー

- 左側にタップ領域44px以上を目安とした「×」ボタンと「N件選択中」（画像では「N枚選択中」も可）を横並び表示する。
- 「×」に「選択モード終了」のアクセシブルな名称を付与する。
- 選択件数を主情報とし、巨大な色付き背景や目立つアニメーションを前提としない。
- 「すべて選択」「選択解除」を補助操作として用意し、横幅の狭いモバイルでも読みやすさ・操作性を維持する。
- 選択中であることは各カードのチェック・輪郭等でも伝え、色の違いだけに依存させない。

## 4. 下部の一括操作ドック

- 選択モード中のみ、アプリのモバイルナビゲーション直上へ固定配置する。
- ドックの背景、ボタン高さ（44px以上目安）、境界線、余白は既存デザイントークンに整合させる。
- アクション名は結果が伝わる動詞・目的語を優先する（例: 「アルバムへ追加」）。
- 操作できるアクションのみ表示し、各アクションの無効／進行中状態は実処理と同期する。
- 破壊的操作は中立操作と区別し、既存の確認フローを省略しない。
- アクションを増やす際の折り返し・優先順位は別途設計判断する。すべてを無理に一列へ押し込まない。
- 選択終了または画面離脱時はドックを消去し、クリックできない透明領域を残さない。
- 実際の配置はモバイルナビゲーションの測定値・セーフエリアに合わせる。現行モックの `54px + safe-area` は実装固有の値で、共通固定トークンではない。

## 5. 画面別の操作定義（参照）

| 画面 | アクション | 注意 |
|---|---|---|
| History スナップショット一覧 | ダウンロード／アルバムへ追加／削除 | 各既存機能に接続 |
| History アルバム詳細 | ダウンロード／削除 | アルバム追加は出さない |
| Generate の履歴 | スナップショットに保存 | Historyのダウンロードとは異なる |

画面の上部／下部の表示ルールは共通だが、アクションの有無・イベント・確認ダイアログ・権限は各画面の仕様が決める。

## 6. 共通受け入れ条件（提案）

- C-01 対象の長押しで選択モードに入り、最初の対象が選択される。
- C-02 上部に「×＋選択件数」、下部に画面固有のアクションが表示される。
- C-03 個別の選択・解除、全選択、選択解除が正しく動作し、選択件数が一致する。
- C-04 「×」でモード終了・全選択解除ができ、下部ドックが残留しない。
- C-05 ドックと既存ナビゲーションに不自然な隙間や重なりがない。
- C-06 選択0件・処理中・処理不可で、操作の無効状態が一致する。
- C-07 危険な操作は既存の確認フローへ進み、意図せず即実行しない。
- C-08 Baselineや対象外画面に意図しない変更がなく、キーボード・読み上げを妨げない。
