# タグチップエディタ 詳細仕様

**対象プロジェクト**: Prompt Surgeon（仮）  
**関連仕様**: `concept_core.md`, `concept_suggestion.md`, `api_spec_draft.md`  
**作成日**: 2026-06-10

---

## 1. 概要と位置づけ

### 何を解決するか

現状のプロンプト入力は `textarea` による生文字列編集。タグが増えると以下の問題が生じる。

- どのタグが干渉しているかを確認するために一時的に削除→戻す操作が煩雑
- 試行錯誤中に「今何を変えたか」が見えない
- サジェスション機能の「削除候補を適用」が、削除という不可逆操作になる

### 解決方針

`textarea` をタグチップ列に置き換える。各チップは **有効 / 無効（グレーアウト）** をトグルできる。チップの並び替え・削除・追加も可能にするが、ComfyUIに投げるテキストは「有効チップのみをカンマ連結した文字列」として構築する。

### `input_type` との関係

`mapping_master.input_type = "textarea"` のフィールドに適用する。`int` / `float` / `select` は従来通り。

## 2. データ構造

### チップの内部表現

```typescript
type TagChip = {
  id: string;        // ローカルのみ。ドラッグ・再描画用のキー。nanoid等で生成
  text: string;      // タグ文字列（前後のスペースはtrim済み）
  enabled: boolean;  // false = 無効化（グレーアウト）
};
```

### ストアの持ち方

React Queryのサーバー状態とは分離し、コンポーネント内の `useState` で管理する。

```typescript
// 生成画面のフォーム状態（擬似コード）
type FieldState = {
  [role: string]: {
    chips: TagChip[];   // input_type === "textarea" の場合
    value: string | number;  // int / float / select の場合
  };
};
```

### ComfyUI投入時の変換

```typescript
function toPromptString(chips: TagChip[]): string {
  return chips
    .filter(c => c.enabled)
    .map(c => c.text)
    .join(", ");
}
```

無効チップはComfyUIには渡らない。テキスト上は存在しないのと同じ。

### スナップショット保存時

`params` の値として `toPromptString()` の結果（有効チップのみの文字列）を保存する。  
無効チップは保存しない。スナップショットは「この設定で生成した」記録なので、無効化中のタグは含めない。

> **設計判断の背景**: 無効チップを保存する場合、復元時に「なぜ無効にしていたか」の文脈が失われ、かえって混乱を招く。試行錯誤の途中状態はスナップショットに残さない。

## 3. UI仕様

### 3-1. 全体レイアウト

```
┌──────────────────────────────────────────────────────────┐
│ Main prompt                                [テキスト入力モードに切替] │
├──────────────────────────────────────────────────────────┤
│ ┌─────────┐ ┌──────────┐ ┌───────────┐ ┌──────────┐     │
│ │ 1girl  ×│ │  solo   ×│ │ smile    ×│ │ socks   ×│ +  │
│ └─────────┘ └──────────┘ └───────────┘ └──────────┘     │
│ ┌──────────────┐                                         │
│ │ worst quality│  ← 無効チップ（グレーアウト）              │
│ └──────────────┘                                         │
└──────────────────────────────────────────────────────────┘
```

- チップは折り返し表示（`flex-wrap: wrap`）。横幅に応じて自然に折り返す
- 入力欄（`+` の右）は常にフォーカス可能。Enterまたはカンマで確定

### 3-2. チップの外観

#### 有効チップ

```
┌─────────────────────────┐
│  1girl               ×  │
└─────────────────────────┘
```

- 背景: `#1f1f25`（サーフェス色）
- ボーダー: `rgba(255,255,255,0.12)`
- テキスト: `#e0e0e8`
- `×` ボタン: ホバー時のみ濃く表示（常時表示だが控えめ）
- カーソル: `grab`（ドラッグ可能であることを示す）

#### 無効チップ（グレーアウト）

```
┌─────────────────────────┐
│  socks               ×  │  ← 取り消し線 + 薄色
└─────────────────────────┘
```

- 背景: `#18181c`（1段暗い）
- テキスト: `rgba(255,255,255,0.3)`
- テキストに取り消し線（`text-decoration: line-through`）
- ボーダー: `rgba(255,255,255,0.05)`

### 3-3. チップのインタラクション

| 操作 | 動作 |
|------|------|
| クリック（テキスト部） | 有効 ↔ 無効 をトグル |
| `×` クリック | チップを削除 |
| ドラッグ＆ドロップ | 並び替え（`@dnd-kit/sortable` 使用） |
| ダブルクリック | インライン編集モード（後述） |
| `Delete` / `Backspace`（チップにフォーカス中） | チップを削除 |
| `Space`（チップにフォーカス中） | 有効 ↔ 無効 をトグル |

チップはフォーカス可能（`tabIndex={0}`）にして、キーボードで選択→Space/Deleteで操作できるようにする。

### 3-4. インライン編集

ダブルクリックでチップがテキスト入力に変化する。

```
┌──────────────────────────┐
│  [1girl             ]  × │  ← inputになる
└──────────────────────────┘
```

- Enter / Tab / フォーカス離脱 → 確定（空欄の場合は削除）
- Escape → キャンセル（元のテキストに戻す）

### 3-5. 新規タグ入力

チップ列の末尾に入力フィールドを常時表示する。

```
[1girl] [solo] [smile] [ ここに入力...   ]
```

| 操作 | 動作 |
|------|------|
| カンマ入力 | カーソル前のテキストをチップ化して確定。入力フィールドをクリア |
| Enter | 同上 |
| Tab | 同上（次のフィールドには移動しない） |
| ペースト（カンマ区切りテキスト） | 複数チップを一括生成 |
| Backspace（入力フィールドが空の状態） | 直前のチップを削除 |

ペーストの例：`"arms at sides, relaxed pose, standing at ease"` → 3チップが一括生成される。

### 3-6. テキスト入力モード（エスケープハッチ）

右上の「テキスト入力モードに切替」で `textarea` に戻せる。

- `textarea` → チップモードへ戻すとき: テキストをカンマ分割して再チップ化
- チップモード → `textarea` へ移るとき: 有効チップのみをカンマ連結して `textarea` に反映
- ラベルは「テキスト入力モードに切替」↔「チップモードに切替」でトグル

テキスト入力モードでの編集内容は、チップモードに戻った時点でパースし直す。無効チップは消える（テキストに含まれていないため）。

> この挙動はテキスト入力モード→チップモード切替時にラベルで明示する（後述）。

### 3-7. スマホ（`/mobile`）での扱い

スマホ向け `/mobile` ページのプロンプト編集はタブ切替＋共用テキストエリア構成のため、チップエディタは適用しない。スマホでは `textarea` のままとする。

## 4. サジェスション機能との連携

### 干渉タグ診断の結果を反映する

現仕様（`concept_suggestion.md`）では「削除候補リスト（チェックボックスで選択して適用）」となっているが、チップエディタの導入により **「無効化候補」として適用** する形に変更する。

```
干渉診断の結果 UI（修正後）:

  干渉している可能性があるタグ:
  ┌─────────────────────────────────────────┐
  │ ☑ socks  足元の描写を引き出し、引きの構図になりやすい │
  │ ☐ white shirt  （軽微）構図への影響は限定的           │
  └─────────────────────────────────────────┘
  [選択したタグを無効化]  ← 「削除」ではなく「無効化」
```

「無効化」ボタンを押すと、該当チップの `enabled` が `false` になる。削除ではないため、「やっぱり戻す」がチップをクリックするだけで済む。

### 語彙サジェストの結果を適用する

```
語彙サジェスト結果:
  ┌─────────────────────────────────────────┐
  │ [+ close-up]    顔への寄りを強調          │
  │ [+ face focus]  顔への集中を補強           │
  └─────────────────────────────────────────┘
```

`[+ タグ名]` ボタンで Main prompt チップ列の末尾に追加する。追加後のボタンは「追加済み」状態に変化する（冪等）。

## 5. キーボードショートカット

チップエディタが含まれるフォームに限定して有効にする。グローバルショートカットとの競合を避けるため、`onKeyDown` はチップエリアのコンテナにのみ設定する。

| ショートカット | 動作 |
|---|---|
| `Ctrl+Z` | チップ操作のUndo（追加・削除・無効化・並び替えを対象） |
| `Ctrl+Shift+Z` / `Ctrl+Y` | Redo |
| `Ctrl+A`（入力フィールドが空の状態） | 全チップを選択状態に |
| `Ctrl+D`（チップにフォーカス中） | そのチップを複製 |

### キーボードによる並び替えの制約

dnd-kit のキーボード操作（フォーカス中に `Space` でドラッグ開始 → `←` / `→` で移動 → `Space` で確定）は**前後方向のみ**に対応する。`flex-wrap` で折り返して複数段になっている場合でも、DOM順序は1次元のリストであるため `↑` / `↓` での「視覚的に上下のチップへの移動」はサポートしない。

視覚的な位置と操作が一致しないケース（例：10個のチップが2段に折り返しており、6番目を2番目に移動したい場合は `←` を4回押す）はキーボード操作より D&D の方が直感的なため、**並び替えのメイン操作は D&D とする**。キーボード操作は隣接チップの微調整用の補助と位置づける。

ドラッグハンドルのツールチップに「ドラッグで並び替え / キーボード: Space → ←→」と表示して期待値をコントロールする。

### Undo/Redo の管理

`useReducer` + `useRef` でチップ列のスナックショット履歴を保持する。`textarea` の標準Undoはタブ切替で消えるため、独自実装が必要。

```typescript
type ChipHistoryState = {
  past: TagChip[][];
  present: TagChip[];
  future: TagChip[][];
};

// アクションごとに past にスナップショットを積む
type ChipAction =
  | { type: "ADD"; chip: TagChip }
  | { type: "REMOVE"; id: string }
  | { type: "TOGGLE"; id: string }
  | { type: "REORDER"; chips: TagChip[] }
  | { type: "EDIT"; id: string; text: string }
  | { type: "UNDO" }
  | { type: "REDO" };
```

履歴の上限は **50件**。それ以上は古いものから捨てる。

## 6. コンポーネント構成

```
TagChipEditor/
  index.tsx          — メインコンポーネント。propsはフィールド定義と値・onChange
  TagChip.tsx        — 1チップのUI（有効/無効/編集中 の3状態）
  TagInput.tsx       — 新規タグ入力フィールド
  useChipHistory.ts  — Undo/Redo管理フック
  useChipParser.ts   — テキスト文字列 ↔ TagChip[] の相互変換
  tagChipEditor.css  — ドラッグ中のスタイル等、Tailwindで表現しにくいもの
```

### TagChipEditor の props

```typescript
type TagChipEditorProps = {
  value: string;              // カンマ区切りのプロンプト文字列（初期値・外部からの更新）
  onChange: (value: string) => void;  // 有効チップのみをカンマ連結した文字列を返す
  placeholder?: string;
  disabled?: boolean;
  suggestedDisables?: string[];   // サジェスション機能からの無効化候補タグ名リスト
  suggestedAdds?: string[];       // サジェスション機能からの追加候補タグ名リスト
};
```

`onChange` は有効チップのみの文字列を返す。呼び出し元（生成フォーム）は `textarea` のときと同じインターフェースで扱える。

### フォームとの統合

`mapping_master.input_type === "textarea"` のフィールドで `TagChipEditor` を使う。それ以外の `input_type` への影響はない。

```tsx
// 動的フォーム生成（既存ロジックへの差し込みイメージ）
{mapping.input_type === "textarea" ? (
  <TagChipEditor
    value={params[mapping.role]}
    onChange={(v) => setParam(mapping.role, v)}
    suggestedDisables={auditResult?.interference?.map(i => i.tag)}
    suggestedAdds={auditResult?.vocabulary?.map(v => v.suggestion)}
  />
) : (
  // int / float / select は従来通り
)}
```

## 7. テキスト変換仕様（パース）

### 文字列 → チップ配列

```typescript
function parseToChips(text: string): TagChip[] {
  return text
    .split(",")
    .map(s => s.trim())
    .filter(s => s.length > 0)
    .map(text => ({ id: nanoid(), text, enabled: true }));
}
```

### チップ配列 → 文字列（ComfyUI投入・onChange用）

```typescript
function chipsToString(chips: TagChip[]): string {
  return chips
    .filter(c => c.enabled)
    .map(c => c.text)
    .join(", ");
}
```

### 注意: アンダースコア正規化

`spec_usage_history.md` の使用履歴マッチングでは `normalize()` によりアンダースコアとスペースを統一しているが、チップエディタはユーザーの入力をそのまま保持する。正規化はマッチング時の責務。チップエディタ側では正規化しない。

| フェーズ | 内容 |
|------|------|

## 10. LLM補完オプション

### 概要

タグ入力時にローカルLLMを使って自然言語→SDタグ形式に変換するオプション機能。`concept_suggestion.md` のサジェスション機能と同じくオプション扱いとし、無効時は従来通りの入力フローを維持する。

### 入力確定時の自動補完

補完オプションが有効な状態で新規タグを入力確定すると、LLMによる変換を挟んでチップ化する。

```
入力: 「椅子に座ってる」 → Enter
  ↓ LLMに変換リクエスト（変換中はスピナー付きプレースホルダーチップを表示）
チップ化: [sitting on chair]
```

変換結果が気に食わない場合はダブルクリックによるインライン編集で直接修正する（再補完UIは持たない）。

### チップ単体への手動トリガー

補完OFFで作成したチップや、通常入力で確定してしまったチップに対して、後から個別に補完を適用できる。

```
[椅子に座ってる] を右クリック or チップメニュー
  → 「LLMで変換」
  → [sitting on chair]
```

チップ操作メニューの1項目として配置する。変換はUndo対象とする（`ChipAction` に `CONVERT` を追加）。

補完ONのデフォルトがOFFであることを考慮し、うっかり補完を使い忘れた場合のリカバリ手段として機能する。

### props追加

```typescript
type TagChipEditorProps = {
  // ...既存props...
  llmCompletion?: {
    enabled: boolean;
    convert: (input: string) => Promise<string[]>; // バックエンドAPI呼び出しをフックから渡す
  };
};
```

変換結果は1件を自動確定してチップ化する。複数候補の提示UIは将来の拡張とする。

### ChipActionへの追加

```typescript
type ChipAction =
  | { type: "ADD"; chip: TagChip }
  | { type: "REMOVE"; id: string }
  | { type: "TOGGLE"; id: string }
  | { type: "REORDER"; chips: TagChip[] }
  | { type: "EDIT"; id: string; text: string }
  | { type: "CONVERT"; id: string; text: string }  // 追加
  | { type: "UNDO" }
  | { type: "REDO" };
```

### 変換キュー管理

複数チップの同時変換（特にペースト時の一括入力）でLLMリクエストが同時多発しないよう、FE側でキューを管理する。

```
ペーストで5件入力確定
  ↓
全件スピナー状態でチップ化（即表示）
  ↓
キューに5件積む → 同時実行数1で順番に処理
  ↓
完了したチップから順次テキスト確定
```

同時実行数を1に絞ることでローカルLLMへの負荷集中を防ぐ。手入力1件ずつのケースは「次のタグを考えている間に変換が終わる」ため体感上の問題は起きにくいが、キューを通ることで一貫した処理になる。

実装は `useChipQueue.ts` フックとして切り出し、`TagInput.tsx`（自動補完）と手動トリガーの両方から同じキューに積む。

### 編集中チップへの変換結果の破棄

変換待ち中にユーザーがチップをダブルクリックしてインライン編集を開始した場合、変換完了時に編集内容を上書きしない。

```
[椅子に座ってる] スピナー中
  ↓ ユーザーがダブルクリックして編集開始 → 編集中状態に
  ↓ 変換完了（sitting on chair が返ってくる）
  → 編集中のため変換結果を破棄。チップは編集中のテキストを優先
```

チップの状態に `converting` フラグを持ち、インライン編集開始時に `converting` を解除することで実現する。

```typescript
type TagChip = {
  id: string;
  text: string;
  enabled: boolean;
  converting?: boolean;  // 追加: 変換キュー処理中フラグ
};
```

### 実装フェーズ

サジェスション機能（Phase 2）と合わせて実装する。

## 11. 履歴ベースのタグサジェスト

### 概要

現在のプロンプト構成をもとに、過去の生成履歴から「次に追加しそうなタグ」を候補として提示する機能。ユーザーが使い込むほど精度が上がる。LLMとのやり取りはFE→LLMサーバー直（他のLLM系機能と同じ構造）、履歴検索はBEが担当。

### アーキテクチャ

```
FE → BE: 現在のプロンプトを送信
BE:      SQLiteから類似プロンプトを検索・集計して候補タグ集合を返す
FE → LLMサーバー: 現在のプロンプト + 候補タグ集合をコンテキストに乗せてリクエスト
LLMサーバー → FE: 絞り込んだ提案（3〜5件）を返す
FE:      候補チップとして表示
```

BEはSQLite検索・集計に専念し、LLMとのやり取りはFEが直接行う。他のLLM系機能との構造的一貫性を保つ。

### 類似プロンプト検索

`spec_usage_history.md` のタグセットマッチング（60%閾値）と同じタグ重複率ベースの簡易マッチングを使用。ベクトル検索は不要。

候補タグ集合の構築：
- 類似プロンプトで使われていたタグのうち、現在のプロンプトに含まれていないものを集計
- LoRA使用状況など他の履歴軸との組み合わせで精度向上の余地あり（将来の拡張）

スナップショットが一定数溜まるまでは機能しない。Phase 3の生成履歴ツリーと同時期に育てる機能。

### 起動トリガー

2段構えのトリガーを採用する。

**初回: チップエディタマウント後の初回フォーカス**
ワークフロー選択時点でプロンプトが既に入った状態でエディタが開くため、チップ追加イベントが起きる前にもサジェストを出せるようにする。「編集するぞ」という意思と一致したタイミング。

**2回目以降: チップ確定のたびに再計算**
タグを追加するたびに自動で更新される。入力のリズムを止めず、候補がサイドに滲み出るように更新されるイメージ。

### キャンセル・AbortController

LM StudioはHTTPのAbortSignalに対応しているため、BE検索とLLM推論を同じAbortControllerで統一管理する。

```
初回フォーカス or チップ追加イベント
  → 前のAbortControllerをabort()
  → 新しいAbortControllerを生成
  → BE検索 → LLM推論を同じcontrollerで通す

deactive or アンマウント
  → abort()
```

新しいイベントが来たら前のをキャンセルして再キック、というdebounce的な動きで統一。BE検索とLLM推論の2段階であることを意識せず扱える。
