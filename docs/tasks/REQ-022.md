## 3. 実装要件 (Implementation Logic)
### バックエンド実装
1. **`backend/app/schemas.py` の修正**:
   - `SnapshotSummary` クラスに `params: Optional[dict[str, Any]] = None` を追加。

2. **`backend/app/routers/snapshots.py` の修正**:
   - `list_snapshots` 内でクエリ結果の `params` 文字列（JSON形式）を `json.loads` でデシリアライズし、`schemas.SnapshotSummary` オブジェクトのリストを明示的に構築して返却する。
   - `create_snapshot` 内で新しく登録された `s` に対して、同様に `json.loads(s.params)` を行い、`schemas.SnapshotSummary` オブジェクトを構築して返却する。

### フロントエンド実装
1. **履歴データのフェッチ**:
   - `GeneratePage.tsx` のコンポーネント内に React Query (`useQuery`) を用いて、`selectedWorkflowId` に対応する過去スナップショット履歴を取得する処理を追加。
   - クエリキー: `['snapshots', selectedWorkflowId]`
   - `enabled` 条件: `!!selectedWorkflowId`

2. **ドロップダウンUIの配置**:
   - `GeneratePage.tsx` の `#workflow-select` 要素のすぐ右隣（かつ `#rescan-btn` の左隣）に、セレクトボックスを追加。
   - ID: `snapshot-history-select`
   - 活性化条件: `selectedWorkflowId` が存在し、かつ取得したスナップショット履歴（`snapshots`）の要素数が 1 つ以上ある場合に活性化。それ以外（未選択または履歴ゼロ）は `disabled` とし、初期表示オプションを「履歴なし」とする（AC-5）。
   - ドロップダウン内のオプション：
     - 各過去スナップショット（時系列の降順）について、表示名を以下のようにフォーマットする（AC-2）：
       `{生成日時（YYYY/MM/DD HH:MM:SS）} - {ポジティブプロンプトの冒頭（25文字）...}`
     - ポジティブプロンプトは、`params` の中からキー名に `positive` または `prompt` が含まれ、かつ `negative` が含まれないものをキーとして抽出する。

3. **パラメータのロード処理**:
   - スナップショット選択ドロップダウンの `onChange` イベントにおいて、選択されたスナップショット（IDに対応するオブジェクト）を取得。
   - 取得した `params` オブジェクトを `setParamValues` アクションを介して上書き（AC-3）。
   - `params` に `Sampler_Seed`（シード値）が含まれている場合、その値を数値型に変換してストアの `setSeed` および `setSeedMode('fixed')` を呼び出し、固定シードモードにする。
   - 選択後、セレクトボックスを初期状態（「過去スナップショットを選択...」等のプレースホルダー表示）にリセットするための制御ステートを用意する。
   - ロード時にワークフローのマッピングやノード接続情報自体は一切変更しない（AC-4）。
