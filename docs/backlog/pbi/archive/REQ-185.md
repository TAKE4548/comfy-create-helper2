### REQ-185: 履歴・アルバム画面の表示・操作性向上（バッジ統一/常時表示、ソート改善、レスポンシブ崩れ防止、一括削除・削除オプション）
- **Type**: enhancement
- **Status**: ready
- **Current step**: Phase 3: Task Decomposition & Planning
- **Priority**: P2
- **Surface**: 履歴・アルバム画面の下記表示系項目を調整したい
  - サムネについているセリフ修正・ダウンロードのバッチが、履歴一覧とアルバム画面で位置が違うのを統一したい
  - サムネについているバッチがタッチ操作だと見えないままタップするしかないので、常時表示しておきたい
  - アルバム画面でカスタム順と登録順でソートできるが、昇順・降順が登録順でしか出来ないので、順序と昇順・降順を別々に指定できるようにしたい
  - モバイルやレスポンシブである程度画面幅になると、フィルタ・ソートメニュー、複数選択のメニューが画面から切れて操作できないものがある
  - 履歴画面で複数選択した後の操作に、一括削除を追加したい。削除には2段階操作をつけたい
  - アルバム画面からの削除時に、アルバムからの削除と元画像毎削除を選べるようにしたい
- **Root Cause**: 
  1. 【Visual/一貫性】履歴画面とアルバム画面でサムネイル上のバッジ配置（セリフ修正・ダウンロード等）が統一されておらず、認知負荷を与えている。
  2. 【Interaction/アクセシビリティ】バッジ表示がホバー状態に依存しているため、タッチデバイス等でホバー操作ができない環境においてバッジの存在や位置を視認できないまま操作せざるを得ない。
  3. 【Interaction/情報設計】アルバムのソートにおいてソート基準（カスタム/登録順）と方向（昇順/降順）が独立して設定できない制限がある。
  4. 【Visual/レスポンシブ】狭小画面・レスポンシブ表示時にツールバーやメニュー（フィルタ/ソート/複数選択操作バー）のはみ出し・折り返し制御が不足している。
  5. 【Interaction/機能性・安全性】履歴画面の複数選択操作に一括削除機能が不足しており、また誤操作防止のための2段階確認（安全策）が必要である。
  6. 【Interaction/データ管理】アルバムからの削除時に「アルバムからの紐付け解除のみ」か「元画像の実体削除」かのユーザー意図を区別・選択する導線が提供されていない。
- **Requirement**: 履歴およびアルバム画面において、サムネイルバッジの配置統一と常時表示化、アルバムソート軸の分離（基準と昇順/降順の独立指定）、レスポンシブ幅でのメニューはみ出し解消、履歴複数選択時の一括削除（2段階操作付き）、アルバム削除時のスコープ選択（アルバム解除 / 元画像ごと削除）を実現し、表示の一貫性と操作性を向上させる。
- **Acceptance criteria**:
  - [ ] AC-1: 履歴一覧とアルバム画面において、サムネイル上に表示されるバッジ（セリフ修正・ダウンロード等）の配置位置およびスタイルが統一されていること
  - [ ] AC-2: サムネイル上の各バッジがホバー時のみではなく常時視認可能な状態で表示され、タッチデバイス等でも迷わず操作できること
  - [ ] AC-3: アルバム画面において、ソート基準（カスタム順/登録順等）とソート方向（昇順/降順）をそれぞれ独立して選択・適用できること（カスタム順時にも昇順/降順が適用可能、または明確に独立指定できること）
  - [ ] AC-4: モバイルや幅狭画面表示時、フィルタ・ソートメニューや複数選択時の操作メニューが画面端からはみ出さず、適切に収まる/操作可能であること
  - [ ] AC-5: 履歴画面で複数選択した際の操作に「一括削除」が追加され、誤削除を防ぐための2段階操作（確認モーダルや確定ステップ）を経て削除が実行できること
  - [ ] AC-6: アルバム画面でアイテムを削除する際、「アルバムから削除（登録解除のみ）」と「元画像ごと削除（実データ含めた完全削除）」のいずれかをユーザーが選択して実行できること
  - [ ] AC-7: 既存の他機能・デスクトップ表示等に意図しない表示崩れや動作デグレーションが発生しないこと
