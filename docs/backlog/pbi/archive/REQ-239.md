### REQ-239: Fix WSL2 ComfyUI Port Detection in Server Manager

- **Status**: done (2026-09-09)
- **Description**: 
  `tools/server-manager` において、WSL2 上で動作する ComfyUI のポート (8188) 開放確認およびプロセス状態（稼働/停止）判定が Windows ネイティブの `Get-NetTCPConnection` に依存しているため、正常稼働中であってもポート確認がタイムアウトして fail 扱いとなり、ステータスが STOPPED と誤判定される問題を解消する。

#### Acceptance Criteria (AC)
- [x] AC-1: WSL2 で ComfyUI が起動している際、`server-manager.ps1` の一括起動 (`start`) および単体起動において、ポート 8188 の疎通がタイムアウトせず迅速に検知・成功すること。
- [x] AC-2: `server-manager.ps1 -Action status` および Web マネージャー (`server_api.py`) において、WSL2 ComfyUI が稼働中である場合に正しく稼働状態（LISTEN / running）として認識・表示されること。
- [x] AC-3: ComfyUI が未起動または停止状態の際には正しく未起動/停止（STOPPED）として判定されること。
- [x] AC-4: ComfyUI が既に起動している状態で `Start-ComfyUIProcess` が呼ばれた際、多重起動を防止して既存稼働を正しく検知できること。
- [x] AC-5: Windows ネイティブで動作する Backend (8000) および Frontend (5173) のポート確認・停止処理にリグレッションが発生しないこと。
- [x] AC-6: `Stop-ComfyUIProcess` およびサービス停止処理において、ポート閉鎖（停止完了）を待機し、停止しない場合の強制終了（SIGKILL / pkill -9）フォールバックとウィンドウ起動時の親 `cmd.exe` クリーンアップが機能すること。
- [x] AC-7: サービス再起動 (`restart`) 実行時において、ポート解放完了を待ってから起動が行われ、レースコンディションによる「起動スキップ（再起動の空振り）」が発生しないこと。
