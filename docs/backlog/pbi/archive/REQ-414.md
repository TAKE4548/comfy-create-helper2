### REQ-414: 新規ワークフロー取り込み時のComfyUI Node許容Seed範囲超過による検証エラー不具合

- **Type**: bug (Type B: Specification Gap)
- **Status**: done
- **Priority**: P1
- **Surface**: Frontend (`seedModel.ts`, `seedBatch.ts`, `SeedField.tsx`, `workflowParamInjector.ts`), Docs (`SPEC_GENERATE.md`)
- **Incident Report**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. なぜComfyUIからワークフローを取り込んだ際にSeedFieldにエラーが表示され生成が失敗するか: ComfyUIノードのSeed値がツールの許容上限（UINT32_MAX = 4294967295）を超過しているため。
  2. なぜComfyUIノードのSeed値がUINT32_MAXを超過するか: ComfyUIの標準ノード（KSampler等）はSeedを最大2^64-1（0xffffffffffffffff）として扱い、ComfyUI WebUIでも最大50bit（1125899906842624）等の大整数乱数が日常的に生成・保存されるため。
  3. なぜツール側はUINT32_MAXに制限していたか: REQ-350およびSPEC_GENERATE.md §2-5, §8の仕様策定時に、Seedの生成・検証範囲を32bit符号なし整数（0..4294967295）と過小に前提づけて規定していたため。
  4. なぜワークフロー取り込み時に即時エラーとなるか: `getInitialParams` がComfyUIノードのSeed値をそのまま抽出し、`parseSeedValue` および `readSeedSettings` がUINT32_MAX超過を厳格に拒否するため。
  5. 根本原因: ComfyUIのネイティブな大整数Seed許容仕様に対するツール側仕様（SSoT）の認識不足と、過剰に狭いUINT32_MAXバリデーション制約（Specification Gap）。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - ComfyUI標準ノードで扱われる大整数Seed（少なくともJavaScript安全整数空間 0〜Number.MAX_SAFE_INTEGER / 50bit空間、必要に応じて64bit整数空間）を正当なSeed値として受容し、不当な範囲外エラーを出さない。
  - **Interaction (インタラクション)**:
    - ワークフロー取り込み直後から有効なSeed値として保持され、SeedFieldでの値編集および生成バッチ実行が正常に行える。
  - **Visual (視覚デザイン)**:
    - 正当なComfyUI Seed値に対してSeedFieldに赤字の「Seed must be between 0 and 4294967295」警告が表示されない。
- **Requirement**:
  - **1. SSoT（SPEC_GENERATE.md）のSeed範囲契約改定**:
    - `docs/specs/SPEC_GENERATE.md` §2-5, §8 における「32bit乱数」「0..UINT32_MAX」等の記述を、ComfyUI互換の大整数範囲（最低でも `Number.MAX_SAFE_INTEGER` / 50bit、または文字列/BigIntによる 64bit `0xffffffffffffffff`）を許容・生成する契約へ改定する。
  - **2. seedModel.ts のバリデーション上限拡張**:
    - `parseSeedValue` における上限チェックを改定仕様に整合させ、ComfyUIノード由来の大整数Seedを安全にパース可能にする。
  - **3. SeedField.tsx の入力ガード更新**:
    - `<input type="number">` の `max` 属性を新仕様の上限に更新し、UI上でのエラー表示および無効化を防止する。
  - **4. seedBatch.ts および workflowParamInjector.ts の整合**:
    - バッチ生成時のSeed加算チェック、乱数生成関数、およびComfyUIへのパラメータ注入前チェックを新仕様に更新する。
- **Acceptance criteria**:
  - [x] AC-1: Given 4294967295（UINT32_MAX）を超える大整数Seed（例: 1052824982390234）を持つノードを含むワークフローJSON, When `getInitialParams` を実行したとき, Then 当該Seed値がエラーなく抽出され、`parseSeedValue` で正常にパースできること
  - [x] AC-2: Given 4294967295を超える大整数Seedを持つワークフロー, When 生成画面で表示したとき, Then `SeedField` に範囲外エラーが表示されず、入力欄が有効な状態を維持すること
  - [x] AC-3: Given 4294967295を超える固定Seedが設定された状態, When 複数枚（例: 2枚）バッチ生成を実行したとき, Then `validateSeedBatch` および `prepareSeedBatch` が拒否されずに連続するSeed値（例: N, N+1）を正常に生成すること
  - [x] AC-4: Given ランダムSeedモード, When `prepareSeedBatch` で乱数Seedを生成したとき, Then 新仕様で規定された許容範囲内の乱数Seedが生成され、ComfyUIワークフローJSONへ正常に注入されること
  - [x] AC-5: Given 不正なSeed（負数、小数値、空文字、文字列、新仕様の上限を超える値等）, When `parseSeedValue` または `validateSeedBatch` で検証したとき, Then 適切なエラーメッセージとともに要求が拒否されること
- **Inferred points**:
  - JavaScriptの `number` 型（倍精度浮動小数点）は `Number.MAX_SAFE_INTEGER`（9,007,199,254,740,991 = 約9×10^15）まで精度を保証。ComfyUI WebUIの `MAX_SEED` は `1125899906842624`（2^50）。2^64-1 までの完全対応を行うか、JS安全整数（Number.MAX_SAFE_INTEGER / ComfyUI WebUI相当）とするかは設計フェーズ（dev-design）で詳細化する。
- **Design doc**: docs/design/REQ-414.md
