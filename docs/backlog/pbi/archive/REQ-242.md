### REQ-242: Service Manager ターミナルバックグラウンド起動とタブ別コンソール出力表示

- **Type**: enhancement
- **Status**: done (2026-09-10)
- **Current step**: Phase 3
- **Priority**: P2
- **Surface**:
  - service managerで起動したとき、各サービスのターミナルがフォアグラウンドに出てくるのを防止したい。現状は一瞬フラッシュするだけでなく、普通に3つのターミナル（Backend, Frontend, ComfyUI）が前面に出てきて残り続ける動きになっている。
  - また、ターミナルが見えなくなる分、各サービスのターミナル情報をmanager側に表示できるようにしたい。コンソール出力のエリアをタブで分けて、みたいサービスのタブを選ぶ方式を想定。
- **Root Cause**:
  - (UX分類: Interaction / Information Design)
    1. `server-manager.ps1` 内のバックグラウンド起動に `Start-Process "conhost.exe" ... -WindowStyle Hidden` が使われており、Windows の仕様上 `conhost.exe` 自体がコンソールホストであるためウィンドウ非表示化（`SW_HIDE`）が効かず、常駐サーバーが動作することで 3 つのターミナルウィンドウが前面に開きっぱなしで残り続けてしまう。また非バックグラウンド時も `cmd.exe /k` により 3 つのウィンドウを明示的に維持する仕様となっていた。
    2. 各サービスの実行ログが外部ウィンドウに分散しており、Service Manager 上で一元的に確認・監視できる集約インターフェースが存在しない。
- **Requirement**:
  - Service Managerからサービス群を起動する際、外部ターミナルウィンドウが前面にポップアップして残り続ける現象を完全に抑止（ウィンドウ生成数 0）しつつ、各サービスのコンソールログ出力を Service Manager 内のタブ切り替えエリアに集約してリアルタイムに確認・監視できること
- **Acceptance criteria**:
  - [ ] AC-1: Service Managerからサービス群を一括または個別に起動した際、3つの外部ターミナルウィンドウ（cmd.exe / conhost.exe）が前面にポップアップして残り続けず、完全にバックグラウンド（ウィンドウ生成なし）で起動されること。
  - [ ] AC-2: Service Manager画面内にコンソール出力エリアが提供され、各サービスごとにタブを切り替えて対象サービスの出力を表示できること。
  - [ ] AC-3: 選択されたサービスのタブにおいて、標準出力・標準エラー出力を含む実行ログが時系列で表示されること。
  - [ ] AC-4: サービス実行中に新たなログが出力された際、リアルタイムに出力エリアへ反映されること。
  - [ ] AC-5: ログの閲覧時、過去ログへの手動スクロール確認が可能であり、かつ最新ログ追従（自動スクロール）の制御が行えること。
  - [ ] AC-6: サービスの停止・再起動が行われた場合でも、コンソールログ表示が正常に維持・更新されること。
