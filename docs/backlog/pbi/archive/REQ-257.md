### REQ-257: Server Manager の WSL / サブプロセス呼び出しタイムアウト保護と耐障害性の向上

- **Type**: defect
- **Status**: done (2026-09-14)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - WSL 側の ComfyUI や OS 全体がハング（無応答）になった際、Server Manager Web UI (`server_api.py`) および `server-manager.ps1` が状態取得 (`/api/status`) の呼び出しで同期ブロックし、Web UI 全体がフリーズする。
  - フロントエンドが 5 秒ごとに自動ポーリングしているため、ハングした `powershell.exe -Action status -Json` プロセスが無限にスタック（20個以上蓄積）し、システムリソースを浪費するとともにサーバーの全接続スレッドを枯渇させる。
- **Root Cause**:
  - (Lack of Failure Isolation / 障害分離の欠如): `server_api.py` の `subprocess.run` において `timeout` が指定されておらず、サブプロセスの終了を永久待機する。
  - `server-manager.ps1` の `Get-WslComfyPids` 等において `wsl bash -c "pgrep ..."` などの WSL コマンドがタイムアウトなしで同期実行されており、WSL 側の不応答がそのままスクリプト全体の永久ブロックを引き起こす。
- **Requirement**:
  - `server_api.py` のサブプロセス呼び出しにタイムアウト（5〜10秒）および例外捕捉を実装し、タイムアウト発生時も Web UI サーバーがクラッシュ／ハングせず適切なエラーレスポンスを返せるようにすること。
  - `server-manager.ps1` 内の外部プロセス／WSL 呼び出しに対してタイムアウト保護を導入し、WSL 側が無応答であっても短時間（例: 2〜3秒）で安全にフォールバック（空PIDまたはUNKNOWN/STOPPED扱い）して処理を完了させること。
  - WSL/ComfyUI が応答不能の際でも、Web Manager 画面上で「応答なし/タイムアウト」等の状態が識別可能であり、他の正常なサービス（Backend/Frontend）の操作が阻害されないこと。
- **Acceptance criteria**:
  - [x] AC-1: WSL が無応答（ハング・停止）状態であっても、Web UI (`/api/status`) がハングせず、規定のタイムアウト時間内に応答を返すこと。
  - [x] AC-2: Web UI の定期ポーリングによって `powershell.exe` や `wsl.exe` プロセスが多重スタック・蓄積しないこと。
  - [x] AC-3: `server-manager.ps1` による WSL への問い合わせが、WSL 無応答時に設定時間（例: 3秒以内）で安全にタイムアウト・中断され、スクリプト全体がブロックしないこと。
  - [x] AC-4: WSL/ComfyUI が応答不能の際、Web Manager 画面上に「応答なし (Timeout/Error)」等のステータスが表示され、他のサービス（Backend/Frontend）の確認・操作が引き続き可能であること。
