### REQ-423: マッピング保存時のinput_name属性欠落によるComfyUIへのSeed未伝播不具合

- **Type**: bug (Type A: Implementation Defect)
- **Status**: new
- **Priority**: P1
- **Surface**: `frontend/src/hooks/useMasterMappingRows.ts`, `frontend/src/pages/SettingsPage/components/WorkflowConnectionSection.tsx`, `frontend/src/components/RescanModal.tsx`, `frontend/src/pages/GeneratePage/hooks/useWorkflowManagement.ts`, `frontend/src/utils/workflowParamInjector.ts`
- **Incident Report**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. なぜ生成時のSeedを変えてもComfyUIで絵が変わらないか: ComfyUIに送信されたワークフローJSON内のサンプラーノードのシード値（`noise_seed`等）が変更されず固定値のままであったため。
  2. なぜサンプラーノードのシード値が更新されなかったか: `workflowParamInjector.ts` において、`seedNode.input_name` が空文字列であったためマスタ既定の `param_name`（`"seed"`）にフォールバックし、実在しない `node.inputs["seed"]` へ値が誤注入され、ノード本来の入力である `noise_seed` が書き換わらなかったため。
  3. なぜ画像のメタ情報表示には反映されていたか: メタ情報記録（`generationRecord.ts`）は注入された `node.inputs["seed"]` を優先検知して「実際のseed」として記録・表示していたため。
  4. なぜ `seedNode.input_name` が空文字列になっていたか: REQ-417でスキャナーが合致したノード入力名を `input_name` として永続化するSSoTが策定されたが、フロントエンドのマッピング保存処理（`useMasterMappingRows.ts:getMappings`, `WorkflowConnectionSection.tsx`, `RescanModal.tsx` 等）において `input_name` が除外され、DBに空文字列が保存されていたため。
  5. 根本原因: REQ-417実装時におけるフロントエンド保存ペイロードからの `input_name` 欠落（Type A: Implementation Defect）。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - ワークフローのマッピング情報において、ノードIDだけでなく合致した入力名（`input_name`）が欠落なく保存・保持されること。
    - 生成画像のメタ情報表示（実際のseed）と、ComfyUIで実際に使用されたサンプラーノードのシード値が完全に一致すること。
  - **Interaction (インタラクション)**:
    - 生成画面でSeed値を変更（またはランダム/固定切り替え）して生成を実行した際、ComfyUI側で確実にそのSeed値がサンプリングに反映され、絵柄が変化すること。
  - **Visual (視覚デザイン)**:
    - UI上の変化なし（既存の挙動の正常化）。
- **Requirement**:
  - **1. フロントエンド各保存経路における `input_name` の永続化**:
    - `useMasterMappingRows.ts` の `getMappings` が返す各マッピングオブジェクトに、スキャン結果または既存マッピングの `input_name` を確実に含める。
    - `WorkflowConnectionSection.tsx`、`RescanModal.tsx`、`useWorkflowManagement.ts`、`NodeRemapModal.tsx` 等の更新呼び出しにおいて、`input_name` をドロップせず API に送信する。
  - **2. `workflowParamInjector.ts` におけるシード注入のフォールバック堅牢化**:
    - `input_name` が空または未設定の場合でも、対象ノードの `inputs` に実在するシード関連キー（`noise_seed`, `seed`, `value` 等）を探索・解決し、実在しないキーの誤注入を防止する。
  - **3. 既存ワークフローの再スキャンによる `input_name` 復元**:
    - 再スキャン（`RescanModal`）を実行して保存した際、スキャン結果の `input_name` が DB に正常に保存・更新されることを保証する。
- **Acceptance criteria**:
  - [ ] AC-1: Given スキャン結果に `input_name` を持つワークフロー, When `useMasterMappingRows` の `getMappings` を実行したとき, Then 返却されるマッピング配列の各要素に正しい `input_name` が含まれること
  - [ ] AC-2: Given ワークフロー設定画面（`WorkflowConnectionSection`）または再スキャンモーダル（`RescanModal`）, When マッピングを保存したとき, Then バックエンド API への更新ペイロードに各マッピングの `input_name` が保持され、DBの `workflow_mappings.input_name` に永続化されること
  - [ ] AC-3: Given `noise_seed` を入力キーとするサンプラーノード（例: KSamplerAdvanced）を持つワークフロー, When 生成画面でSeed値を変更して生成バッチを実行したとき, Then ComfyUIに送信されるグラフのノード `inputs.noise_seed` に新しいSeed値が注入され、`node.inputs.seed` への誤注入が発生しないこと
  - [ ] AC-4: Given シード入力名が `input_name` に未設定（空文字列）のレガシーマッピング, When `injectWorkflowParams` を実行したとき, Then ノードの inputs に存在する `noise_seed` や `value` 等のキーを安全に検知してシード値が注入されること
- **Inferred points**:
  - バックエンド API（`PUT /api/workflows/{id}`）および DB スキーマ（`workflow_mappings.input_name`）は REQ-417 で既に対応済みであるため、主にフロントエンド側の保存処理とパラメータ注入ユーティリティの修正で完結する。
- **Design doc**: docs/design/REQ-423.md
