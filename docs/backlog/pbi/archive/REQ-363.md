### REQ-363: モバイルレイアウト破綻解消およびUI操作性最適化

- **Type**: feature
- **Status**: done (2026-10-15)
- **Priority**: P1
- **Surface**: frontend/src (pages/GeneratePage/layouts/MobileLayout.tsx, GeneratePage.tsx, pages/GeneratePage/components/PresetManagerPanel.tsx, pages/GeneratePage/components/ParamPanel.tsx, pages/GeneratePage/components/AddAssetModal.tsx, components/common/header/ResourceHoverMonitor.tsx)
- **Reference**: prompt_surgeon_mobile_layout_spec_and_mockups.html (原本モックアップ・仕様書)
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: スマートフォン実機環境（幅360px〜390px）において、プロンプトタブの重なり、ボタン消失、プレビュー常時占有による深いスクロール必須、モーダルのアドレスバー見切れ等が発生し、画像生成ワークフローが著しく阻害されているため。
  2. なぜその課題が発生するか: デスクトップ向けのコンポーネント構造・余白（p-6 等）・横並び Flex レイアウトが、モバイルの viewport/safe-area を考慮せずにそのまま流用されているため。
  3. なぜ現状の仕組みで不十分か: タブの shrink-0 欠落、isTextInput の checkbox 誤判定、max-h-[42vh] のプレビュー常時固定占有、モーダルの中央揃え突き抜けなど、複数の構造的不備が重なっているため。
  4. なぜこのアプローチを採用するか: 既存のデザインシステムおよび未改修機能（複数選択・一括操作等）を100%維持したまま、フロントエンドの CSS/DOM ラッパーのみを外科的に修正することで、デグレリスクゼロで一括解消できるため。
  5. 根本原因: デスクトップ前提の横並びFlexレイアウトや固定サイズ余白がそのまま流用され、モバイル端末固有のviewport制約・安全領域・タッチターゲット・フォームフォーカス判定に対する専用設計が欠落していたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - リソースモニタ展開時にヘッダーを覆う330px横長カプセルを廃止し、VRAM/RAMのプロポーショナルバーゲージを備えたドロップダウン詳細カードへ整理する。
    - パラメータ画面において、コントロールの種別特性（ステッパー/セレクト/トグル）に応じたスマート適応型1行レイアウトを採用し、無駄な2行化による余白の浪費を排除しつつ情報密度を最適化する。
  - **Interaction (インタラクション)**:
    - テキスト入力判定（isTextInput）で checkbox / radio を明示的に除外。チェックボックス操作時に下部アクションバー（Generate Batch）が誤って非表示化（消失）する重大バグを解消する。
    - メインプレビューの初期表示をコンパクト固定（約105px）とし、生成開始後も自動展開させずにタップ手動トグル（105px ⇔ 220px/42vh）とすることで、スクロール不要で連続してプロンプト編集・キュー追加を可能にする。
    - プリセット管理モーダルの最下部に「固定操作ドック」を配置。「全選択」「全解除」ボタンおよび「上書き保存」「別名で保存」をピン留めし、長大なスクロールなしで即座に操作可能にする。
  - **Visual (視覚デザイン)**:
    - プロンプト切り替えタブボタンに shrink-0 whitespace-nowrap を厳格適用し、狭小幅でのタブテキスト衝突・潰れを解消し横スクロール化する。
    - スクロール終端に十分な下部パディング（pb-[calc(54px+env(safe-area-inset-bottom)+56px+16px)] 等）を確保し、最下部タグチップが下部固定バーの下に潜り込んでタップ不能になる問題を解消する。
    - プリセット管理をボトムシート形式（上限 75dvh）へ変更し、ブラウザアドレスバーへの上部突き抜け・タイトル切断を根絶する。
    - アセット追加モーダル（AddAssetModal）等の余白を p-3.5（14px）に引き締め、一覧表示領域を拡大する。
- **Invariants (厳格遵守デザイン規約・非改修機能の完全保持)**:
  - カラートークンの不変性: #0F0F11, #18181C, #1F1F25, #3ecf8e, #7C6FDD, zinc-200 の完全維持。
  - プリセット管理の全機能維持: 一括操作モード切替（ListChecks ボタン）、複数選択ツールバー（全選択/全解除/一括編集/一括削除）、セット選択用「全選択」「全解除」ボタン、並び替えハンドル（GripVertical）、Scene Generator 連携ボタンを完全保持。
  - バックエンド・DB・API 変更ゼロ: フロントエンド純粋 UI レイヤー完結。
- **Requirement**:
  - **1.  プロンプト切り替えタブの文字重なり ＆ チップのボタン下潜り込み**:
    - タブの独立 pill 化: タブボタンに shrink-0 whitespace-nowrap を厳格適用し、横スクロールで文字衝突ゼロを保証。
    - スクロール終端パディング (pb): スクロールコンテナに pb-[calc(54px+env(safe-area-inset-bottom)+56px+16px)] を確保し、最下部チップがボタンの 16px 上で綺麗にスクロールアウト完了。
    - コンパクトチップ表示: モバイル時は text-xs px-2.5 py-1 の流動型タグチップへ切り替え、作業領域を 2 倍確保。
  - **2.  チェックボックスタップによる「Generate Batch」バー突然消失バグ**:
    - 入力タイプ判定の厳密化: isTextInput で target.type !== 'checkbox' && target.type !== 'radio' を必須条件に追加。
    - 安定したバー表示: チェックボックスやトグルスイッチ操作時もアクションバーは常時固定表示を維持。
  - **3.  プリセット管理: 上部はみ出し防止 ＆ 最下部スクロール不要な固定操作ドック（全選択/全解除ボタン・複数選択機能の完全維持）**:
    - 「全選択」「全解除」を固定ドック内に完全維持: プリセットチェック状態の一括切り替え（sets && onToggleCheck）用ボタンである「全選択」「全解除」を省略せず、保存ボタンと並び固定操作ドック内に常時配置。
    - 一括操作モードの完全維持: 右上の [☑ 選択]（ListChecks アイコン）、複数選択時のツールバー（全選択 / 全解除 / 一括編集 / 一括削除）、および Scene Generator 導線をそのまま 100% 保持。
    - 高さ上限キャップ (max-h-[75dvh]): 画面の 75% を上限とし、上部 25% の余白（背景タップで閉じる）を常時確保。アドレスバーへの突き抜けを根絶。
    - 最下部「固定操作ドック」: 「全選択 / 全解除」および「💾 上書き保存」「➕ 別名で保存」をボトムシート最下部にピン留め固定。リストの件数に関わらず、スクロール不要で即操作可能。
  - **4.  メインプレビュー領域: 現行の固定42vhスクロール必須の解消 ＆ タップ手動トグルによる「生成キュー継続」最優先設計**:
    - 初期状態をコンパクト（約 105px）に固定: 画面を開いた瞬間にプロンプト入力欄がファーストビューに収まり、スクロールなしで即座にタグ編集に着手可能。
    - タップによる手動トグル切替: プレビュー領域をタップすることで、[コンパクト: 105px] ⇔ [標準プレビュー: 220px/42vh] を手動で伸縮。
    - 生成開始時もコンパクト維持（編集継続最優先）: 生成が始まってもプレビューは自動展開せずコンパクト状態を維持。sticky プログレス行（22px）のみで進行を知らせ、連続して次のプロンプトを編集・キュー投入可能。
    - 全画面モーダル拡大は2段階タップ: 標準プレビュー状態で再度タップ（または拡大ボタン）で全画面モーダルへ展開。
  - **5.  リソースモニタ展開（ResourceHoverMonitor）のオーバーレイ適正化**:
    - ドロップダウンカード化: ピル直下にドロップダウンするフローティングカードを採用。VRAM（パープル）と RAM（ブルー）のプロポーショナルバーを完備。
    - ヘッダー要素の非破壊: タイトル「Generate」やステータスバッジを一切隠さず、共存表示。
    - 44px タッチ領域 & 外側タップ閉止: 快適に閉じるための十分なタップターゲットを確保。
  - **6.  パラメータ行: 無条件2行化を撤廃し、余白を無駄にしないスマート適応型1行レイアウト**:
    - 数値ステッパー・トグルは「厳格に1行維持」: Sampler Steps Rough や CFG、Denoise、Boolean はステッパー幅が約 105px とコンパクト。flex-1 pr-2 のラベル領域（約 200px）で確実に1行のまま快適に収まるため2行化しない。
    - セレクトボックスの適正幅化 (w-36固定撤廃): ドロップダウン選択（Sampler, Scheduler）は gap-2 に詰め、セレクト幅を w-[125px]（または流動）に最適化。長いラベルも 1 行（極端に長い場合のみ leading-tight で高さを抑えた軽微な2行化）にとどめ、余白の目立ちを根絶。
    - モーダルパディングの引き締め: AddAssetModal 等の余白を p-3.5（14px）に最適化。
- **Acceptance criteria**:
  - [ ] AC-1: Given: 画面幅360px端末で /generate を表示。When: プロンプトタブを横スクロール。Then: 全タブが重なりなく独立したピルとして描画され文字切れが発生しないこと。
  - [ ] AC-2: Given: 画面下部にアクションバーが表示中。When: Anima特化やSetチェックボックス等の非テキスト入力をタップした時。Then: isTextInputでフォーカス扱いと判定されず、アクションバーが非表示化（消失）せず固定位置かつ操作可能な状態を維持すること。
  - [ ] AC-3: Given: 多数のタグチップが登録されたロール。When: 画面最下部までスクロール。Then: 最下部のチップが Generate Batch ボタンの上に抜け、完全に視認・操作できること。
  - [ ] AC-4: Given: プリセット管理を開く。When: プリセットが多数存在。Then: 一括操作モード(ListChecks)および「全選択/全解除」ボタンを完全維持したまま、モーダルが上限75vhでアドレスバー突き抜けを防ぎ、最下部ドックで上書き/別名保存が即押せること。
  - [ ] AC-5: Given: メインプレビューを表示中。When: Generate Batchを押下して生成ジョブを開始した時。Then: 生成契機によるプレビューの強制展開を行わず直前の表示状態（コンパクト時ならコンパクト約105px、手動展開時ならその高さ）を維持し、プロンプト編集領域をファーストビューに残して連続編集可能であること。またプレビュー領域タップで手動トグル（約105px ⇔ 220px/42vh）できること。
  - [ ] AC-6: Given: ヘッダーの VRAM ピルを表示。When: ピルをタップ。Then: ヘッダーを覆う330px横長カプセルではなく、ゲージ付きドロップダウンカードが安全に展開されること。
  - [ ] AC-7: Given: パラメータ画面を表示。When: 画面幅360pxで表示。Then: 無条件の2行化による余白無駄を避け、ステッパーやセレクトがコンパクトな1行（または必要最小限の適応幅）で表示されラベルが切れないこと。
  - [ ] AC-8: Given: アセット追加モーダルを表示。When: 画面幅360pxで表示。Then: 余白が p-3.5 に引き締められ一覧の表示面積が確保されること。
  - [ ] AC-9: Given: 改修完了後のフロントエンド。When: npm run typecheck を実行。Then: TypeScript エラーが 0 件であること。
  - [ ] AC-10: Given: 改修完了後のフロントエンド。When: npm test を実行。Then: 既存テストスイートの失敗・退行が 0 件であること。
- **Inferred points**:
  - プレビュー領域は「生成開始時の強制自動展開を抑止し、ユーザーの直前の手動トグル状態（コンパクトor展開）を維持する」設計とし、意図せぬ画面ジャンプや編集妨害を防ぐ。
  - ボトムシートや下部固定バーの余白には dvh（動的ビューポート高）および env(safe-area-inset-bottom) を採用し、iOS Safari / Android Chromeのアドレスバー伸縮や仮想キーボード表示時のレイアウト破綻を防止する。
  - プレビュー領域の全画面モーダル拡大は標準プレビュー展開状態からの2段階タップまたは拡大アイコン押下で対応する。
  - モバイル検出は既存の画面幅ブレークポイント（md未満 / 768px未満）および MobileLayout.tsx の利用を想定する。
  - パラメータ行の極端に長いラベルで1行に収まらない例外的な項目のみ、leading-tight の軽微な2行折り返しを許容する。
