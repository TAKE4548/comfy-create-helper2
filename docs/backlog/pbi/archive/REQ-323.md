### REQ-323: Dataset Studio: プロジェクト即時永続化・オートセーブおよび sessionStorage 下書き復元による入力消失防止

- **Type**: feature
- **Status**: done (2026-10-08)
- **Current step**: none
- **Priority**: P1
- **Surface**: Dataset Studio (LoRA Studio) において、プロジェクト新規作成時の即時保存、その後の編集内容のオートセーブ、および保存ラグや画面遷移時の入力消失を防ぐ sessionStorage 下書きキャッシュと復元機構を提供する。
- **5 Whys / Root Cause**:
  1. なぜ変更が必要か: Dataset Studio で入力・設定中に画面遷移やリロードを行うと、入力内容が全てクリアされてしまい作業の手戻りとストレスが発生するため。
  2. なぜクリアされてしまうのか: プロジェクト作成時に即時永続化されず、編集中の入力状態がクライアントのインメモリのみに保持されており、サーバー永続化も手動または不完全であるため。
  3. なぜ最初に作成した時点で保存し、その後オートセーブにするのか: ユーザーの手動保存忘れを防ぎ、プロジェクト作成直後から一意な ID を持つエンティティとして追跡・自動保存可能にするため。
  4. なぜオートセーブだけでなく sessionStorage も必要なのか: オートセーブのデバウンス待機時間やネットワーク遅延（ラグ）の間にユーザーが画面遷移・タブ移動した場合、サーバーへの送信が間に合わず未保存の変更が失われるリスクがあるため。
  5. 根本原因: 「クライアント側ローカルキャッシュによる即時退避」と「サーバー永続化（オートセーブ）」の二重化保護機構が存在せず、画面離脱・非同期ラグに対するゼロ・データロス（Zero Data Loss）設計が欠如していたこと。
- **UX Classification**:
  - **Interaction (インタラクション設計)**:
    - プロジェクト新規作成時の即時サーバー永続化と作成失敗時のリカバリ
    - 入力変更時のデバウンス付きバックグラウンド・オートセーブ
    - 入力ごとのリアルタイムな `sessionStorage` への下書き同期（タイムスタンプ付き・例外ハンドリング）
    - 画面再訪時・リロード時の `sessionStorage` からの下書き自動復元（サーバー更新日時比較による整合性維持）
    - サーバー保存完了時のキャッシュ同期・クリーンアップ
  - **Information Design (情報設計)**:
    - 現在の保存状態（「編集中 / 未保存」「保存中...」「保存完了」「保存失敗 / 再試行」等）のインジケーター表示
- **Requirement**:
  - **1. プロジェクト初期作成の即時永続化**:
    - 新規プロジェクト作成時、バックエンド API（`datasetApi.createProject`）を即座に呼び出してサーバー上にプロジェクトを永続化する。
    - 作成完了と同時に発行されたプロジェクト ID で編集状態を開始する。作成失敗時はエラーを通知し、モーダル内の入力状態を維持して再試行可能とする。
  - **2. デバウンス付きオートセーブ**:
    - プロジェクト編集中、フォームや設定に変更があった場合、デバウンス（500ms〜1000ms）後に自動でサーバー更新 API を呼び出して永続化する。
    - 通信失敗時はリトライまたは未保存警告を表示し、下書きキャッシュを維持する。
  - **3. sessionStorage によるゼロラグ下書きキャッシュ**:
    - オートセーブのデバウンス待ちおよび通信ラグ中も、入力変更のたびに `sessionStorage` へプロジェクト ID 単位（`dataset_studio_draft_${projectId}`）でタイムスタンプ付き下書きデータを即時同期する。
    - ストレージ容量超過（QuotaExceededError）等の例外は安全に catch してアプリのクラッシュを防止する。
  - **4. 画面遷移・リロード時の自動復元**:
    - ユーザーが別画面へ遷移した後に戻った場合やリロード時、`sessionStorage` にサーバーデータより新しい未保存の下書きが存在すれば、下書きからフォーム入力内容を自動復元する。
  - **5. 保存完了時のキャッシュクリーンアップ**:
    - サーバー保存が正常に完了した時点で、`sessionStorage` の下書きデータを同期済み状態として更新またはクリアし、古い下書きによる不整合を防ぐ。
  - **6. 保存ステータス表示**:
    - 編集画面上に「変更を保存中...」「保存完了」「未保存（下書き保持）」などのステータスを表示し、保存状況を可視化する。
- **Acceptance criteria**:
  - [ ] AC-1: Given ユーザーが Dataset Studio で新規プロジェクトの作成操作を行ったとき, When プロジェクト作成がトリガーされた際, Then サーバー側 API へ即時保存リクエストが送信されてプロジェクトが永続化され、プロジェクト ID が確定して画面に保持されること。万一作成失敗した場合は入力内容を保持したままエラーを表示すること。
  - [ ] AC-2: Given プロジェクト編集中にユーザーがフォームや設定の値を変更したとき, When 変更後に所定のデバウンス時間（500ms〜1000ms）入力が停止した際, Then サーバーに対して自動的に保存リクエスト（オートセーブ）が送信され、最新の編集内容が永続化されること。
  - [ ] AC-3: Given ユーザーがフォームや設定を編集している最中であるとき, When キー入力や選択変更が行われるたび（デバウンス待ちおよび通信ラグ中を含む）, Then 直ちに `sessionStorage` に該当プロジェクトの最新入力状態と更新タイムスタンプが下書きキャッシュとして記録されること（例外発生時も画面がクラッシュしないこと）。
  - [ ] AC-4: Given サーバーへのオートセーブ完了前に画面遷移またはブラウザリロードが発生したとき, When 再び該当プロジェクト画面を表示した際, Then `sessionStorage` の下書きデータ（サーバーデータより新しいもの）から直前の編集状態が自動復元され、入力消失が発生しないこと。
  - [ ] AC-5: Given サーバーへのオートセーブまたは明示的保存が正常完了したとき, When 成功レスポンスを受信した際, Then `sessionStorage` 内の該当プロジェクトの下書きキャッシュが同期済みとして整理され、古い下書きとの不整合が発生しないこと。
  - [ ] AC-6: Given ユーザーが編集操作を行っているとき, When 保存状態が遷移した際（編集中、保存中、保存完了、保存失敗）, Then UI 上に現在の保存ステータス（「保存中...」「保存完了」「保存失敗」など）が視覚的にフィードバックされること。
  - [ ] AC-7: Given フロントエンドの実装変更, When `npm run typecheck` および `npm test` を実行した際, Then 型エラーおよびテスト失敗が 0 件であること。
- **Inferred points**:
  - `sessionStorage` のキーは `dataset_studio_draft_${projectId}` とし、プロジェクトごとの名前空間を分離。
  - 復元判定では、下書きデータのタイムスタンプがサーバー側の `updated_at` より新しい場合に復元を行い、別端末や外部更新との競合リスクを抑制。
  - オートセーブ失敗時は保存ステータスで「保存失敗（再試行中/未保存）」を明示し、下書きキャッシュは削除せず保持する。
