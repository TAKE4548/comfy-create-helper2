### REQ-402: 生成画面のプリセットタブを基準に他・左・右のタブを一括で閉じる

- **Type**: feature
- **Status**: frontmatter の `status` を参照（状態の正本）。
- **Priority**: P2（生成時のタブ整理の効率改善。仮置き）
- **Surface**: 生成画面のデスクトップ・モバイル共通のプリセットタブ。
- **利用者ニーズ**: 比較・編集のために増えたタブを、残したいプリセットを基準に少ない操作で整理したい。
- **課題の整理**: 個別に閉じる操作を繰り返す負担があると推定する。利用頻度・開く枚数は未確認で、数値効果は主張しない。
- **UX Classification**: Interaction（タブ整理の操作）。見た目全体の刷新は含めない。
- **Requirement**: タブの右クリック・ロングタップから、そのタブを基準とする「他のタブを閉じる」「左のタブをすべて閉じる」「右のタブをすべて閉じる」を実行できる。通常タップでも同じ操作へ到達できる。

## 操作の定義

- 基準タブはメニューを開いたプリセットタブ。現在のアクティブタブと異なってもよい。メニューを開くだけではアクティブタブを切り替えない。
- 左右は現在のタブ列の表示順で判定し、横スクロールで画面外に隠れたタブも含む。「左」は基準タブより左だけ、「右」は基準タブより右だけを対象とし、操作を開始した基準タブ自身は対象に含めず必ず残す。「他のタブを閉じる」も基準タブ自身は残す。
- 閉じるとは開いているタブから外すことであり、プリセット本体の削除ではない。残るタブの相対順序は変えない。
- 一括操作の対象に保存待ちの編集がある場合は、保存成功を確認してから閉じる。対象のいずれかで保存失敗・通信断・競合未解決がある場合は一括クローズ全体を中止し、全対象タブと編集内容を保持する。未解決状態の解消には既存の保存・競合解決経路を使い、無断破棄や強制上書きをしない。

## Acceptance Criteria

- [ ] AC-1: Given 生成画面でプリセットタブを表示している, When いずれかのタブを右クリックまたはロングタップする, Then そのタブを基準とする上記3項目のメニューが表示され、タブの選択・開閉・入力値は変わらないこと。
- [ ] AC-2: Given 左から A・B・C・D・E のタブを開いている, When C のメニューで「他のタブを閉じる」を確定し保存上の障害がない, Then C だけが残ること。
- [ ] AC-3: Given 左から A・B・C・D・E のタブを開き、一部が横スクロールで隠れている, When C のメニューで「左のタブをすべて閉じる」を確定し保存上の障害がない, Then A・B だけが閉じ、C・D・E がこの順で残ること。
- [ ] AC-4: Given 左から A・B・C・D・E のタブを開き、一部が横スクロールで隠れている, When C のメニューで「右のタブをすべて閉じる」を確定し保存上の障害がない, Then D・E だけが閉じ、A・B・C がこの順で残ること。
- [ ] AC-5: Given 基準タブの指定側にタブがない、または基準タブだけが開いている, When メニューを開く, Then 閉じる対象がない項目は無効と識別でき、その項目ではタブ構成・選択・入力値を変更できないこと。
- [ ] AC-6: Given アクティブタブと異なる基準タブからメニューを開いた, When 一括クローズが成功する, Then 元のアクティブタブが残る場合はその選択を維持し、閉じる場合は基準タブを選択してそのプリセットの入力内容を表示すること。
- [ ] AC-7: Given 閉じる対象に保存待ちの編集がある, When 一括クローズを確定する, Then 全対象の編集の保存成功を確認した場合だけ対象タブが閉じ、保存待ちの間は対象タブと編集内容を保持すること。
- [ ] AC-8: Given 一括クローズ対象に保存失敗・通信断・未解決競合がある, When 一括クローズを試みる, Then 全対象タブと編集内容を保持して一括クローズを中止し、保存失敗または競合の原因と既存の再試行・解決経路を利用者に示すこと。
- [ ] AC-9: Given 一括クローズが成功した, When 閉じたプリセットをプリセット管理から開き直す, Then プリセット本体は削除されておらず保存済み内容を再表示できること。
- [ ] AC-10: Given 一括クローズが成功した, When 生成画面を再読み込みする, Then 閉じたタブは再表示されず、残したタブとアクティブ選択が復元されること。
- [ ] AC-11: Given メニューを開いている, When メニュー外を操作するか Escape で取り消す, Then メニューが閉じ、タブの選択・開閉・入力値を変更しないこと。
- [ ] AC-12: Given プリセットタブを表示している, When 通常のタブ選択・チェック・個別クローズ・横スクロールを行う, Then ロングタップメニューが誤って開かず、従来の各操作を行えること。
- [ ] AC-13: Given 右クリックやロングタップを使わない, When 通常タップで利用できる代替入口から対象タブの操作を開く, Then 同じ3項目を同じ基準・効果で実行できること。

## Inferred points

<inferred_points>
- 利用者の明示要望は右クリック・ロングタップと3つの一括クローズ。メニューを開くだけで選択を変えないこと、クローズ後の選択規則、対象なしの無効表示、保存障害時に全体を中止することは安全性・予測可能性のための提案であり、物理PBIのレビューで確認する。
- 通常タップの代替入口は SPEC_COMMON §1-6 の MUI-10 と整合させるために含める。入口の表示形式や長押しの判定値は設計で具体化する。
- 保存待ち・失敗・競合を伴わない通常の一括クローズについて、追加の確認ダイアログは要求しない。
- 対象は現在のタブ列。別ワークフローのタブ、プリセット本体の削除、「すべてのタブを閉じる」、新規の並べ替え機能は範囲外。
- 要件取りまとめ時点では実装コードは未調査。タブバー自体のドラッグ並べ替えは、設計・実装時に既存操作との競合を確認する。
</inferred_points>
