### REQ-230: ComfyUIノードバイパス機能の不全解消とスキーマキャッシュ・エラーハンドリングの是正

- **Type**: defect
- **Status**: done (2026-09-09)
- **Current step**: none
- **Priority**: P1
- **Surface**: 229実装以降、バイパスが機能してない
- **Root Cause**: バックエンド `/api/comfy/object_info` の接続失敗時エラー握りつぶし（HTTP 200で空 `{}` 返却）、フロントエンド React Query の空データ1時間キャッシュ、`applyBypass` のスキーマ未取得時サイレントスキップ処理、および ComfyUI 再接続・画面初期化時のバイパスプロファイル同期不足
- **Requirement**: ComfyUIの稼働状況や起動順序にかかわらず、有効化されたバイパスプロファイルの対象ノードが生成実行時に確実にバイパス・結線再構築されてComfyUIに送信されること。また、スキーマ情報欠落時にサイレントに未バイパス投入されることなく、正常なエラーハンドリングが行われること
- **Design doc**: none

#### Acceptance Criteria (AC)
- [ ] AC-1: ComfyUIが未起動または起動途中の状態でアプリを起動・アクセスし、その後にComfyUIが起動・接続された場合でも、バイパスプロファイルを有効化して生成を実行した際、バイパス対象ノードが確実に除外・結線バイパスされてComfyUIへ投入されること。
- [ ] AC-2: ComfyUIとの接続が確立された際、または再接続された際に、ノードスキーマ情報が最新状態に同期され、古い空状態のまま固着しないこと。
- [ ] AC-3: ノードバイパスが有効化されている状態で、何らかの理由でノードスキーマ情報の取得が不完全または失敗している場合、警告なしに未バイパスのまま生成が実行されることなく、ユーザーに生成不可またはエラーが通知されること。
- [ ] AC-4: ワークフロー切り替え時および画面初期化時において、有効なバイパスプロファイルの状態が直ちに生成アクションと同期し、初回の生成から正しくバイパスが機能すること。
- [ ] AC-5: 既存のバイパスプロファイルCRUD操作、パラメータ同期（ParamSync）、およびマルチセット生成の既存機能に回帰影響がないこと。
