### REQ-320: LoRA Studio: Positive/Negative プロンプト注入先ノードのリマッピング機能および Negative 編集入力欄の追加

- **Type**: feature
- **Status**: done (2026-10-07)
- **Priority**: P2
- **Surface**: `frontend/src/pages/DatasetStudioPage/components/MatrixGenerationStep.tsx`, `frontend/src/pages/DatasetStudioPage/useStudioStore.ts`, `backend/app/models.py`, `backend/app/schemas/dataset.py`
- **5 Whys / Root Cause**:
  1. なぜ新設が必要か: LoRA Studio でワークフローを選択した際、Positive プロンプトの注入先が ComfyUI JSON 内の最初の CLIPTextEncode に決め打ちされており、また Negative プロンプトの入力欄が存在せず調整できないため。
  2. なぜ決め打ちだと問題か: ワークフロー内のノード順序やカスタムテキストノードの構成によって意図しないノードにプロンプトが流れたり、Negative 側に合成プロンプトが上書きされるリスクがあるため。
  3. なぜ Negative 編集が必要か: キャラクターLoRA素材生成時にも品質担保（崩れや不要要素の排除）のために Negative プロンプトの調整が不可欠であるため。
  4. なぜ Studio 側からリマッピングが必要か: ワークフロー選択時、どのノードが Positive / Negative に割り当てられているかを即座に確認・変更できないと、設定ページに戻る手間が発生しワークフローの切り替え体験が損なわれるため。
  5. 根本原因: LoRA Studio（Step 1）に Positive/Negative の対象ノード確認・手動リマッピングUIおよび Negative プロンプト専用の入力・管理コンポーネントが備わっていないこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 選択中ワークフローにおける Positive / Negative の対象ノード情報（Node ID, タイトル, クラス名）のインライン表示。
    - Step 1 のプロンプト入力エリアにおける「ネガティブプロンプト」枠（初期値表示、文字数/タグ数カウント）の配置。
  - **Interaction (インタラクション)**:
    - Studio 画面上から直接呼び出せるシームレスなノードリマッピング操作（ドロップダウンまたはクイックモーダル）。
    - GeneratePage 共通の TagChipEditor によるネガティブプロンプトのタグ追加/削除/並替/テキスト切替。
    - ComfyUI バッチ投入時に、マッピングされた Positive ノードおよび Negative ノードの各 `inputs[param_name]` へ正確に個別注入。
  - **Visual (視覚デザイン)**:
    - LoRA Studio のダークテーマ（#0F0F11, #18181C）に統一されたマッピングバッジおよびネガティブプロンプトカード。
- **Requirement**:
  - **1. ノードマッピングのシームレス表示・変更（リマッピング）**:
    - ワークフロー選択時、そのワークフローで `positive_prompt` および `negative_prompt` に割り当てられているノード情報を表示する。
    - Studio 画面から離れることなく、ワークフロー内のテキスト入力ノード一覧から Positive / Negative の注入先ノードを即座に変更・再選択できるようにする。
  - **2. Negative Prompt 編集入力欄の追加**:
    - Step 1 に Negative Prompt の入力エリア（TagChipEditor）を追加する。
    - ワークフローまたはプリセットに保存されている既存の Negative Prompt を初期値としてロード可能とし、ユーザーが自由に加筆・修正できるようにする。
    - プロジェクトモデル（`DatasetProject`）に `prompt_negative` およびカスタムマッピング設定を保持・永続化する。
  - **3. ComfyUI 投入時の確実な個別注入**:
    - `injectPromptAndSeed` を改修し、決め打ちではなくマッピングされた Positive ノードIDに合成プロンプト（`raw_prompt`）を、Negative ノードIDに設定された負プロンプトを確実に注入する。
- **Acceptance criteria**:
  - [ ] AC-1: Given ユーザーが LoRA Studio の Step 1 でワークフローを選択したとき, When ワークフロー情報エリアを確認した際, 選択中ワークフローで Positive および Negative に割り当てられているノード情報（ノードID、ノード名/タイトル）が明示表示されること。
  - [ ] AC-2: Given ユーザーが Studio 画面上でプロンプト注入先ノードを変更したいとき, When リマッピング操作（ノード選択セレクタまたはクイックモーダル）を実行した際, ワークフロー内のテキスト入力可能ノード一覧から Positive / Negative の注入対象ノードをシームレスに再選択・更新できること。
  - [ ] AC-3: Given ユーザーが Step 1 を開いたとき, When プロンプト入力エリアを確認した際, 3分割の正プロンプト枠に加えて「Negative プロンプト」入力欄（TagChipEditor / テキスト切替対応）が表示され、ワークフローのデフォルト値がロードされて自由に編集・保存できること。
  - [ ] AC-4: Given Step 1 で「ComfyUIにバッチ投入」を実行したとき, When ComfyUI へ送信されるプロンプトペイロードを検証した際, 正プロンプト（DOE合成結果）が指定された Positive ノードの inputs.text に、負プロンプトが指定された Negative ノードの inputs.text にそれぞれ正確に個別注入されて投入されること。
  - [ ] AC-5: Given プロジェクトの保存および再読み込みを行ったとき, When 保存された LoRA Studio プロジェクトを開いた際, 設定した Negative プロンプトおよび Positive/Negative のカスタムノードマッピング情報が正しく復元されること。
- **Inferred points**:
  - 既存の `workflow.mappings` を尊重しつつ、Studio 固有のオーバーライドまたはワークフロー本体のマッピング更新と連動可能にする。
  - GeneratePage の TagChipEditor 資産を再利用し、Negative 枠でもタグ補完・チップ操作を共通化する。
