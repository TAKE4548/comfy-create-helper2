### REQ-125: ノードリマッピング開始時の既存マッピング状態の初期値反映とミスマッチ項目の個別フォールバック

- **Type**: enhancement
- **Status**: done (2026-08-26)
- **Priority**: P2
- **Surface**: ノードリマッピングを行った際、現在のマッピング状態が初期値に反映されず、局所的に修正・追加したいときに既存部分も再設定しないといけなくて手間。リマッピング時はその時点のマッピング状態を初期値として反映した上で、編集を開始できるようにしたい。
- **Root Cause**: ノードリマッピング編集開始時に現在のノードマッピング設定状態をモーダル/編集フォームの初期値として復元・読み込む処理が未実装であり、常に空/デフォルトの初期状態でフォームが生成されているため。
- **Requirement**: 
  1. ノードリマッピング画面の初期化時、その時点で適用されている既存のノードマッピング状態を読み込み、編集フォームの初期値として反映する。
  2. 万一ノード・構造等の変更により一部項目でマッピングが無効（ミスマッチ）となった場合、正常な項目は既存設定をそのまま反映し、ミスマッチ項目のみ個別に初期登録時と同様のロジックでフォールバック初期値を設定した上で、その旨を注意表示（警告アイコン等）する。
  3. 全クリア/リセット機能は設けない（既存の全リセット動作ではなく部分修正UXに特化する）。

#### Acceptance Criteria (AC)
- [ ] AC-1: ノードリマッピングダイアログ/モーダル開始時、現在適用されているノードマッピング状態が初期値としてフォームに自動設定・保持されていること。
- [ ] AC-2: ノード変更等により無効となったマッピング項目（ミスマッチ）が存在する場合、正常項目は既存設定を保持しつつ、対象のミスマッチ項目のみ個別でデフォルトフォールバック値を適用し、ユーザーへ注意表示（警告メッセージやアイコン等）が行われること。
- [ ] AC-3: 正常なマッピング項目についてはユーザーが既存設定をそのまま引き継ぎつつ、局所的な修正・追加をスムーズに行えること。
