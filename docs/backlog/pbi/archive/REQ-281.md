### REQ-281: プリセット同期・状態ライフサイクルの根本是正（他プリセット誤上書き・切替時消失・他端末更新破棄の解消）

- **Type**: defect
- **Status**: done (2026-09-23)
- **Current step**: none
- **Priority**: P1
- **Surface**: プリセットのプロンプトが別のプリセットの内容で意図せず上書きされたり、別端末での編集内容が反映されず消失・巻き戻りが発生する。
- **Root Cause**:
  1. 新規プリセット作成（Add Set / 別名保存）時にストアのセット未登録状態で `activeSetId` 切り替えを試みて早期リターンし、直前に開いていたプリセットのパラメータが新プリセットの内容で上書き・恒久保存される。
  2. タブ切替時に進行中のオートセーブタイマーが未フラッシュのまま破棄され、編集差分がサーバーへ送信されずに脱落する。
  3. ポーリング同期時（`rawMappedSets`）に、未保存編集（dirty）かどうかの判定を行わずにローカルのインメモリ値をサーバー値の上に無条件マージし、他端末の更新を破棄している。
  4. ポーリング時に非アクティブプリセットのタイムスタンプが追跡されず、他端末の更新を正しく検知・ロードできない。
- **Requirement**:
  対症療法的なパッチやフォールバックに頼らず、プリセットの生成・切り替え・オートセーブ・サーバー再同期のライフサイクル全体を根本から整理し、単一端末・複数端末のいずれの利用状況下でもプリセットデータが別プリセットで破壊されることなく、安全かつ確実に同期・保存される堅牢な状態管理アーキテクチャを実現する。
- **Acceptance criteria**:
  - [ ] AC-1: プリセットAを開いた状態で「Add Set」または「別名で保存」により新規プリセットBを作成した際、プリセットAの内容がプリセットBの内容で上書きされることなく、プリセットA・B双方が正しいパラメータを保持すること。
  - [ ] AC-2: プリセットAのプロンプト編集中（オートセーブのデバウンス時間内）にプリセットBへタブ切り替えを行った場合、プリセットAの未保存の変更が消失することなくサーバーへ即時フラッシュ保存され、再度プリセットAを開いた際にも編集内容が保持されていること。
  - [ ] AC-3: 端末1でプリセットAを開いている間に別端末（端末2）でプリセットBを更新・保存した場合、端末1でプリセットBに切り替えた際に端末2で保存した最新のパラメータが確実に反映されること。
  - [ ] AC-4: 端末1で未編集のプリセットAが存在する状態で別端末（端末2）がプリセットAを更新・保存した場合、端末1の定期ポーリングまたはウィンドウフォーカス時に、端末2の最新データが端末1の古いメモリ値で上書き破棄されることなく正しく同期されること。
  - [ ] AC-5: プリセット管理パネルからの上書き保存や編集操作時において、アクティブでないプリセットが意図せずアクティブなプリセットの内容で上書きされないこと。
