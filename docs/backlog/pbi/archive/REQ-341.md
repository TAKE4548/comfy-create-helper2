### REQ-341: 全画面共通ヘッダーデザイン統一・左クラスタリング操作性最適化およびモバイル展開

- **Type**: feature
- **Status**: done (2026-10-11)
- **Priority**: P2
- **Surface**: frontend (全6画面のヘッダーおよびレイアウト: Generate, Studio, LoRAs, Tags, History, Settings)
- **Reference Spec**: tmp/prompt_surgeon_header_spec.html (UI-SPEC-2026-10-11-v3)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: 現状の画面ごとにヘッダーの高さ、フォント、アイコン色、状態表示がバラバラであり、画面遷移時のガタつきや視覚的不統一が発生しているため。また、PCワイド画面において主要操作が右端に偏在し、左サイドバーや作業キャンバスとの間で大きな視線・マウス移動が発生しているため。
  2. なぜその課題が発生するか: 共通ヘッダー（PageHeader）がHistory画面等の一部でのみ使用され、Generate、Studio、LoRAs、Tags、Settings画面では個別のdiv/header実装が乱立していたため。また、ワイド画面でのFitts Law（操作対象への距離と到達時間）を考慮したレイアウト設計がなされていなかったため。
  3. なぜ現状の仕組みで不十分か: 正常稼働時にも「FE 200 · BE 200 · Comfy 8188」といった冗長テキストが常時ヘッダー幅を圧迫し、一方でGPU/VRAMなどのリソース詳細情報やブラウザストレージの状況を把握する一貫したUIが存在しないため。さらに、FastAPIプロキシ経由への通信移行後も旧来のComfyUI本体URL表示が残存するなど、仕様の陳腐化が生じているため。
  4. なぜこのアプローチを採用するか: 「左クラスタリング（主要操作をタイトルの直後に集約）＋スリム状態バッジ＋右端受動リソースモニタ＆縦3点メニュー」を採用することで、PCワイド画面での操作距離を劇的に短縮しつつ、モバイル環境では展開式ピルによる2段構成で限られた画面幅を最大限に活用できるため。
  5. 根本原因 (Root Cause): 全画面共通のヘッダー情報設計・視覚規約の欠如、およびPCワイド画面とモバイル画面双方における操作導線とシステムテレメトリ（受動情報）の分離原則の未整備。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - ヘッダーを「左クラスター（能動的コンテキスト: タイトル・状態・主要アクション）」と「右クラスター（受動的テレメトリ: リソース・グローバル保守メニュー）」に明確に分離。
    - ワークフロー個別設定（ベースモデル紐付け、デフォルト値保存・リセット、複製等）をセレクタ直横の「⋯」メニューへ集約し、グローバルシステム設定と分離。
    - FastAPIリバースプロキシ構成への移行に伴い、ヘッダー上の不要な「ComfyUI本体URL」表示・入力を完全撤廃。
    - ブラウザストレージ表示は「Web Storage推定値（Estimate Only）」として位置づけ、ディスク容量と混同させない明示的ラベリングを行う。プライベートブラウジング等でAPIアクセス不可時はフォールバック表示を提供。
  - **Interaction Design (インタラクション設計)**:
    - PCデスクトップ: タイトル直後に主要操作を配置（左クラスタリング）することでマウス移動・視線移動の負荷を最小化（Fitts Law最適化）。
    - PCリソースモニタ: 受動チップへのマウスホバーで「m / n GB」形式の実メモリ消費量およびプロポーショナルバーを含む詳細Hover Cardをポップアップ表示。ポーリング頻度は過負荷防止のためスロットル制御（1〜2秒）。
    - モバイルリソースモニタ: 常時表示の「VRAM x% ◀」タップで、右端縦3点ボタンの上に覆いかぶさりつつ（z-index: 80 vs z-index: 10）左方向へスムーズに伸びる（幅96px→330px）ピル型オーバーレイを展開し、全リソース数値をインライン表示。閉じるタップまたは外側タップで自動格納され、縦3点ボタンのクリック可能性が即時復帰。
    - 縦3点メニュー（⋮）: クリックでlocalStorage/sessionStorage推定容量表示および保守アクション（設定画面遷移、キャッシュ再同期）をドロップダウン展開。
  - **Visual Design (視覚デザイン)**:
    - PCデスクトップ: 全画面共通で高さ50px固定、背景色・境界線を統一し、画面遷移時の縦揺れ・レイアウトシフトを完全排除。
    - タイトル・アイコン統一: タイトルは全画面で text-sm font-semibold text-zinc-200、アイコンはサイズ16px・カラー text-zinc-400 に統一。モバイルでの長文タイトルは white-space: nowrap; overflow: hidden; text-overflow: ellipsis; で丸め横あふれ・改行を防止。
    - スリム状態バッジ: 正常稼働時は緑枠ピル [● READY] のみを表示し、ホバーで詳細ツールチップを展開。モバイルでは7pxの緑発光ドットインジケーターのみを配置。
    - モバイル2段ヘッダー: ブレークポイント（width < 768px）において1段目にタイトル・状態・展開式リソースピル・縦3点メニュー、2段目に横スクロール可能なタッチ最適化アクションバー（overflow-x: auto, スクロールバー非表示）を配置。
- **Requirement**:
  - **1. 全画面共通ヘッダー基盤の統一 (PCデスクトップ)**:
    - 全6画面（Generate, Studio, LoRAs, Tags, History, Settings）において、統一されたヘッダー構造（高さ50px固定、共通背景・ボーダー・タイポグラフィ・アイコン規格）を提供すること。
    - 画面遷移時にヘッダーの高さ・位置・フォントサイズに起因するレイアウトシフトやガタつきが発生しないこと。
  - **2. 左クラスタリングによる主要操作の再配置**:
    - 各画面の主要アクション（セレクタ、検索窓、主要ボタン、Undo/Redo等）をタイトルの直後（左側）に配置し、ワイド画面での操作距離を短縮すること。
    - 各画面の配置構成:
      - **Generate**: ワークフロー選択 ＋「⋯」設定メニュー、Anima特化チェックボックス、Undo / Redo ボタン
      - **Studio**: プロジェクト選択、マトリクス/キュレーター/学習設定/評価 切り替えボタングループ
      - **LoRAs**: 検索ボックス、+ LoRA追加 ボタン、再スキャン ボタン、件数バッジ
      - **Tags**: タグセット検索ボックス、+ 新規作成 ボタン、エクスポート / インポート ボタン、件数バッジ
      - **History**: スナップショット / アルバム 切り替え、✨ セリフ一括変換 ボタン、+ アルバム追加 ボタン、件数バッジ
      - **Settings**: 設定カテゴリ切り替えチップ群（サービス接続、VRAMガード、マッピング、モデル、LLM等）
  - **3. 受動的リソースモニター & ホバーカード詳細表示**:
    - ヘッダー右端にCPU、RAM、GPU、VRAMの常時監視チップを厳密な順序（CPU -> RAM -> GPU -> VRAM）で集約配置すること（VRAMは専用アクセントカラーで強調）。
    - チップ領域へのマウスホバー時に、VRAM（m/n GB）、システムRAM（m/n GB）、GPU利用率、CPU負荷をプロポーショナルバー付きで表示するHover Card（幅250px）を展開すること。
    - バックエンドテレメトリ取得前の初期状態や通信遅延、接続エラー時にはスケルトン/プレースホルダー（--%）またはグレースフルなフォールバックを表示し、ヘッダーレイアウトの破綻・シフトを防止すること。
  - **4. 縦3点メニュー（⋮）規約 & Generate 画面設定項目の適切な再配置**:
    - ヘッダー最右端に縦3点（⋮）ケバブメニューを配置し、閲覧頻度の低い診断情報およびグローバル保守アクションをドロップダウン（幅270px）内に集約すること。
    - ブラウザストレージ使用量表示: LocalStorage および SessionStorage の UTF-16 概算推定使用量（Estimate Only）を明示表示すること。プライベートモードやアクセス拒否時は例外をキャッチし「推定容量: 取得不可」を安全に表示すること。
    - クイック保守機能: キャッシュ整合性再同期アクション、および本体設定画面（/settings）へのダイレクト導線を提供すること。
    - ComfyUI本体URL直通表示の完全廃止: FastAPIリバースプロキシ構成（/api/comfy/...）への完全移行に伴い、ヘッダーおよびポップオーバーから旧来の「ComfyUI本体URL」表示・入力UIを完全撤廃すること（必要な接続先設定は設定画面 /settings のみで管理）。
    - Generate画面設定項目の適切な再配置: 旧 SettingsPopover（歯車）に混在していたワークフロー個別設定（ベースモデル紐付け [Auto/Anima/SDXL]、デフォルト値保存・リセット、名前変更、複製、ノード再スキャン）をワークフローセレクタ直横の「⋯」メニューへ集約し、グローバルシステム設定と明確に分離すること。
  - **5. モバイル最適化 (2段レイアウト & スライド展開オーバーレイ)**:
    - モバイルブレークポイント（< 768px）において、2段ヘッダーレイアウトを提供すること:
      - **1段目 (トップバー)**: タイトル（white-space: nowrap; overflow: hidden; text-overflow: ellipsis; による1行省略）、7px緑発光ドットインジケーター（テキストなし）、VRAMピル、縦3点（⋮）メニューを配置すること。
      - **2段目 (アクションバー)**: 画面固有の主要アクションを横スクロール可能なタッチ最適化バー（overflow-x: auto; スクロールバー非表示）として配置すること。
    - VRAMピル左スライド展開オーバーレイ:
      - モバイルヘッダー右端では初期状態で最もクリティカルな [VRAM xx% ◀]（幅96px）のみを表示すること。
      - ピルタップ時に、右隣の縦3点（⋮）ボタンの上に覆いかぶさりつつ（オーバーレイ z-index: 80、縦3点ボタン z-index: 10）左方向へスムーズに伸びる（幅96px → 330px、イージング cubic-bezier(0.16, 1, 0.3, 1)）ピル型オーバーレイを展開し、全リソース数値（CPU xx% | RAM xxG | GPU xx% | VRAM xxG | ✕）をインライン表示すること。
      - ✕アイコンタップ、ピル再タップ、または領域外タップで自動的に格納され、元のサイズに戻って縦3点ボタンが即座に再露出・クリック可能となること。
- **Acceptance Criteria**:
  - [ ] **AC-1 (全6画面共通50pxヘッダー・デザイン統一)**: Given 利用者が全6画面（Generate, Studio, LoRAs, Tags, History, Settings）のいずれかを表示または画面遷移するとき, When ヘッダー領域が描画されるとき, Then PCデスクトップにおいてヘッダーの高さが50px固定、共通の背景・ボーダー・タイポグラフィ（	ext-sm font-semibold text-zinc-200）、アイコン規格（16px 	ext-zinc-400）で統一され、画面遷移時のレイアウトシフトや垂直方向のガタつきが一切発生しないこと。
  - [ ] **AC-2 (左クラスタリング操作性最適化)**: Given PCデスクトップ環境で各画面を表示しているとき, When 利用者が各画面の主要操作領域を確認・操作するとき, Then タイトルの直後（左側）に各画面固有の主要操作（Generate: ワークフロー選択＋「⋯」設定＋Animaチェックボックス＋Undo/Redo、Studio: プロジェクト選択＋マトリクス/キュレーター/学習設定/評価切替、LoRAs: 検索＋追加＋再スキャン、Tags: 検索＋新規作成＋エクスポート/インポート、History: スナップショット/アルバム切替＋セリフ一括変換＋アルバム追加、Settings: カテゴリ切替チップ）が左クラスタリング配置され、画面右端への無駄な視線移動・マウス移動なしに主要操作が完結できること。
  - [ ] **AC-3 (スリム状態バッジ & ツールチップ)**: Given 正常稼働状態（READY）のヘッダーを表示しているとき, When タイトル横の状態バッジを確認するとき, Then 冗長なテキスト（FE · BE · Comfy）が表示されずスリムな [● READY] ピルのみが表示され、当該ピルにマウスホバーしたときのみ詳細なサービス中継状態（FE 200 · BE 200 · Comfy (FastAPI中継 OK)）がツールチップとして表示されること。
  - [ ] **AC-4 (受動的リソースモニター & ホバーカード詳細表示)**: Given ヘッダー右端のリソースモニターを表示しているとき, When 通常時およびマウスホバー時, Then 通常時は厳密な順序（CPU → RAM → GPU → VRAM）でパーセンテージチップが表示され（VRAMはアクセントカラー表示）、チップ領域にマウスホバーしたとき、実メモリ消費量（m / n GB 形式）、CPU負荷、GPU利用率がプロポーショナルバー付きのHover Card（幅250px）としてポップアップ展開されること。また、テレメトリ未取得時や通信エラー時はプレースホルダー（--%）が表示されレイアウトが破綻しないこと。
  - [ ] **AC-5 (縦3点メニュー & ストレージ推定値 & ComfyUI直通URL撤廃)**: Given ヘッダー最右端の縦3点（⋮）メニューボタンをクリックしたとき, When ドロップダウンメニュー（幅270px）が展開されるとき, Then LocalStorageおよびSessionStorageの推定使用量（UTF-16概算・Estimate Only明記、例外時は安全なフォールバック表示）が表示され、キャッシュ整合性再同期アクションおよびSettings画面へのリンクが提供されること。かつ、旧ヘッダーに存在したComfyUI本体URL直通表示・入力欄が完全に排除されていること。
  - [ ] **AC-6 (Generate画面ワークフロー設定の分離集約)**: Given Generate画面においてワークフロー個別設定を行いたいとき, When ワークフローセレクタ直横の「⋯」ボタンをクリックしたとき, Then ベースモデル紐付け（Auto/Anima/SDXL）、デフォルト値保存・リセット、名前変更、複製、ノード再スキャンのメニューがドロップダウン展開され、グローバルシステム設定と分離してワークフロー単位の設定変更が直感的に行えること。
  - [ ] **AC-7 (モバイル2段レイアウト & 7px発光ドット)**: Given モバイルビューポート（幅 < 768px）で画面を表示したとき, When ヘッダーが描画されるとき, Then 1段目にタイトル（単行ellipsis省略）、7px緑発光ドットインジケーター（テキストなし）、VRAMピル、縦3点メニューが配置され、2段目にタッチ操作に最適化された横スクロール可能なアクションバー（overflow-x: auto;）が配置されること。
  - [ ] **AC-8 (モバイルVRAMピル左スライド展開オーバーレイ)**: Given モバイル環境においてヘッダー1段目の [VRAM xx% ◀]（幅96px）ピルをタップしたとき, When 展開アニメーションが実行されるとき, Then ピルが右隣の縦3点（⋮）ボタンの上に覆いかぶさりながら（z-index: 80 vs 10）左方向へスムーズに伸長（幅96px → 330px）してピル型オーバーレイとなり、内部に全リソース数値（CPU xx% | RAM xxG | GPU xx% | VRAM xxG | ✕）がインライン表示されること。また、✕アイコンタップ、ピル再タップ、または外側タップでスムーズに縮小格納され、縦3点ボタンが即座に再露出・操作可能となること。
