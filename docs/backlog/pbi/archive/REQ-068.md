### REQ-068: 既存ワークフローのCRUDとコピー機能

- **Type**: enhancement
- **Status**: ready
- **Current step**: Step 2
- **Priority**: P1
- **Surface**: 既存ワークフローのCRUDを可能にしたい。また、既存ワークフローを選択してコピーすることも可能にしたい。プロファイルはコピーするが、関連スナップショットはコピーしない
- **Root Cause**: 既存のワークフロー管理が削除機能しかなく（仕様上Settingsにあることになっているが実質未実装）、ワークフロー名やプロファイルの変更・整理が困難である。また、類似した構成のワークフローを作成する際に最初からマッピング等をやり直す必要があり、複製機能（スナップショット除外）がないため作業効率が悪い。
- **Requirement**: 
  - 既存ワークフローの名前変更、プロファイル（プリセット）の名前変更・並び替え、およびコピー（複製）を、生成ページ（Generate Page）と設定ページ（Settings Page）の両方から操作できるようにすること。
  - 既存のワークフロー新規追加は現行のJSONアップロード形式（Generate Page）を維持すること。
  - ワークフローの削除は設定ページ（Settings Page）からのみ可能とし、誤操作防止のための2段階確認（確認ダイアログ等）を必須とすること。
  - コピー（複製）の際、ワークフロー本体・マッピング・プロファイル（プリセット）は複製し、過去のスナップショット（生成履歴）は複製しないこと。
- **Acceptance criteria**:
  - **AC-1 (生成ページ内UI)**: 生成ページ（Generate Page）に、現在選択されているワークフローに対する「名前変更」「コピー」「プロファイル（プリセット）の名前変更・順序並び替え」ができるUIコントロールを配置すること。
  - **AC-2 (設定ページ内UI)**: 設定ページ（Settings Page）にワークフロー管理セクションを実装し、そこですべてのワークフローを対象として「名前変更」「コピー」「プロファイル（プリセット）の編集・順序並び替え」「削除」ができる統合UIを提供すること。
  - **AC-3 (安全な削除フロー)**: ワークフローの削除アクションは設定ページのみで提供され、実行時には「削除すると関連するすべてのプロファイルや履歴画像が失われます」等の警告を伴う2段階確認ダイアログ（例：確認ボタンの2回押しや、確認のためのチェックボックスONなど）を表示し、誤操作を防止すること。
  - **AC-4 (コピー機能とスナップショット除外)**: 既存ワークフローのコピー（複製）を行った際、ワークフローの JSON ボディ、マッピング情報、およびそれに紐づくプロファイル（プリセット）が正しく複製され、スナップショット（生成履歴）は複製されず空の状態で新しいワークフローが生成されること。
  - **AC-5 (名前重複チェック)**: ワークフローの新規作成、名前変更、コピー時に、他ワークフロー名との重複チェック（FastAPIによるバリデーションとフロントへのエラー提示）が行われ、一意性が担保されること。
  - **AC-6 (プロファイル（プリセット）の並び替え永続化)**: プロファイルの並び替え（Dnd等）を実行した際、表示順序（sort_order等）がデータベースに永続化されること。
