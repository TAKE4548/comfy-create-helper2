### REQ-364: FE環境切替（開発5173/本番8000）およびヘッダーステータス稼働モニタ表示

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: frontend (frontend/src/components/common/SystemStatusBadge.tsx, 共通ヘッダー)
- **Reference Spec**: Prompt Surgeon - FE環境切替＆ヘッダーステータスモニタ仕様書 (ラベル側インライン配置版)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: 開発者・利用者が Vite 開発サーバー (:5173) と FastAPI 本番ビルドホスティング (:8000) のどちらを参照しているか一目で把握できず、環境間の切り替えにブラウザのアドレスバー手動書き換えが必要で作業効率が低下しているため。
  2. なぜその課題が発生するか: 共通ヘッダーのステータスバッジに現在の接続先フロントエンド種別（DEV/PROD）のインジケーターが存在せず、また手動でのURL書き換え時にパスやクエリパラメータ、ハッシュの喪失・誤入力が発生しやすいため。
  3. なぜ現状の仕組みで不十分か: 単なるテキスト情報やアドレスバーの目視確認では誤認が生じやすく、また既存のポップオーバー内のサービス稼働状況表示も右側ステータス列の整列や個別サービスの操作属性が整理されていなかったため。
  4. なぜこのアプローチを採用するか: ヘッダーバッジ横への「DEV :5173」明示タグ配置、およびステータスモニタ内の「Frontend」ラベル横にインライン切替ピルボタン（[⇄ 本番用] / [⇄ 開発用]）を配置することで、右側ステータス列の統一感を100%保ったまま、現在のパス・クエリ・ハッシュを保持した1クリック環境切替を実現できるため。
  5. 根本原因: フロントエンド稼働環境の可視化手段および、パス・クエリ・ハッシュを維持したまま開発・本番サーバー間を相互移動するクイック導線の未整備。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 稼働環境（DEV :5173）の明示的タグ表示による作業コンテキストの即時把握。
    - システム稼働モニタ内における各サービス（Frontend, FastAPI BE, ComfyUI, Manager）の稼働状態およびポート情報の整理・階層化。
    - 切り替えボタンの文言をポート番号ではなく目的志向の「本番用」「開発用」として定義。
  - **Interaction (インタラクション)**:
    - ステータスバッジのクリックによる「システム稼働モニタ」ポップオーバーのスムーズな開閉（外側クリック / ESCキー閉止対応）。
    - 切替ピルボタン（[⇄ 本番用] / [⇄ 開発用]）押下時に、現在のURLパス（pathname）、クエリパラメータ（search）、およびハッシュ（hash）を完全に維持したまま、対象ポートへ1クリックで画面遷移（リダイレクト）。
    - ボタン押下時のイベント伝播抑止によるポップオーバーの意図せぬ誤動作防止。
  - **Visual (視覚デザイン)**:
    - デスクトップ環境かつ開発サーバー（DEV :5173）アクセス時のみアンバー調の「DEV :5173」タグバッジをステータスバッジ横にインライン配置（モバイル表示時はREQ-341/363規約に基づきコンパクト化/ドット表示）。
    - システム稼働モニタ内の右側ステータス列（● running (:ポート)）を全サービス行で同一フォーマット・右寄せで美しく整列。
    - 切替ピルボタンをFrontendラベルの直横にコンパクトに配置し、右側ステータス列の水平整列を乱さない調和のとれたレイアウトを実現。
- **Requirement**:
  - **1. 開発環境（DEV）インジケータータグ表示**:
    - フロントエンドがローカル開発サーバー（ポート5173）で動作している場合、PCデスクトップヘッダーのステータスバッジ（READY等）の直横にアンバー調の「DEV :5173」タグバッジを表示すること。
    - 本番サーバー（ポート8000等）で動作している場合、タグバッジを非表示とすること。
  - **2. システム稼働モニタポップオーバーの構造化と整列**:
    - ステータスバッジの押下により「システム稼働モニタ」ポップオーバーを開閉可能とすること。
    - モニタ内には各サービス（Frontend, FastAPI (BE), ComfyUI, Manager）の稼働状況を行形式で表示すること。
    - 各行の右端ステータス表示は、インジケータードットと「running (:ポート)」の統一フォーマットで整列させること。
  - **3. ラベル側インライン環境切替ピルボタン**:
    - 「Frontend」行のラベル横にインライン切替ピルボタン（[⇄ 本番用] または [⇄ 開発用]）を配置すること。
    - 開発環境（DEV）表示時は「⇄ 本番用」、本番環境（PROD）表示時は「⇄ 開発用」と表示すること。
  - **4. パス・クエリ・ハッシュを維持した環境遷移**:
    - 切替ボタン押下時、現在のURLパス（例: /generate）、クエリ文字列（例: ?workflow=1）、およびハッシュ（例: #preview）を保持したまま、対象ポート（本番: 8000 / 開発: 5173）の同一ホストURLへ画面遷移すること。
- **Acceptance criteria**:
  - [ ] AC-1: Given 開発サーバー（ポート:5173）経由で画面を表示しているとき, When PCデスクトップでヘッダーのステータスバッジ領域が描画されるとき, Then 既存バッジの横に「DEV :5173」タグバッジが表示されること。
  - [ ] AC-2: Given 本番サーバー（ポート:8000）経由で画面を表示しているとき, When ヘッダーのステータスバッジ領域が描画されるとき, Then 「DEV :5173」タグバッジが表示されないこと。
  - [ ] AC-3: Given ヘッダーが表示されているとき, When ステータスバッジをクリックする, Then 「システム稼働モニタ」ポップオーバーが展開され、Frontend / FastAPI (BE) / ComfyUI / Manager の各行が表示されること。また外側クリックまたはESCキー押下で閉じること。
  - [ ] AC-4: Given システム稼働モニタが展開されているとき, When 各サービスの行表示を確認するとき, Then 全サービス行の右端がインジケータードットと稼働状態テキスト（runningおよびポート番号）の統一フォーマットで垂直に整列して表示されること。
  - [ ] AC-5: Given 開発環境（ポート:5173）でパス・クエリ・ハッシュが存在する画面を表示中に稼働モニタを開いているとき, When Frontend行の「⇄ 本番用」ボタンをクリックする, Then 現在のパス・クエリ・ハッシュを完全に保持したまま本番ポート（:8000）の同一ホストURLへ画面遷移すること。
  - [ ] AC-6: Given 本番環境（ポート:8000）でパス・クエリ・ハッシュが存在する画面を表示中に稼働モニタを開いているとき, When Frontend行の「⇄ 開発用」ボタンをクリックする, Then 現在のパス・クエリ・ハッシュを完全に保持したまま開発ポート（:5173）の同一ホストURLへ画面遷移すること。
- **Inferred points**:
  - <inferred_points>
  - 本アプリはローカルデスクトップヘルパーとして単一ホスト（localhost/127.0.0.1）での動作を基本とし、動作環境の判定（DEV / PROD）は window.location.port === '5173' に基づく。
  - 遷移先URLの生成は window.location.protocol, window.location.hostname, 対象ポート番号（本番 8000 / 開発 5173）, window.location.pathname, window.location.search, window.location.hash を組み合わせて安全に行う。
  - 既存の SystemStatusBadge のProps契約（props.manager等）を維持し、既存の稼働ステータス判定ロジックと共存させる。
  - モバイル画面幅（<768px）では、REQ-341/REQ-363 のヘッダー規約に従いタグバッジの非表示またはコンパクト化を維持し、レイアウト破綻を防止する。
  - </inferred_points>
