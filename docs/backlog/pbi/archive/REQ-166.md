# REQ-166: ジョブ管理におけるキュー削除と全ジョブ中断の機能・UIボタン分離および中断状態同期の堅牢化

- **Type**: defect / enhancement
- **Status**: done (2026-08-26)
- **Priority**: P2
- **Surface**:
  - ジョブ管理モーダルにおいて「一括キャンセル」を実行した際、待機中キューは削除されるものの、現在生成中の1枚（実行中ジョブ）が停止せず最後まで生成・出力されてしまう。
  - 現在生成中の1枚を残して待機キューのみを空にしたいユースケースと、生成中も含めてすべて即座に中断（Abort）したいユースケースが存在するが、単一の「一括キャンセル」ボタンしかなく使い分けることができない。
- **Root Cause**:
  - `cancelAllJobs` 実行直後にフロントエンドのステート（`isGenerating: false` 等）を即時リセットしているが、ComfyUIの `/interrupt` 完了前に届く後続の WebSocket イベント（`progress` や `executing`）によってフロントエンド状態が `isGenerating: true` に再同期・上書きされてしまう。
  - ComfyUI の中断イベント（`execution_interrupted`）がフロントエンドで適切に処理されておらず、中断完了の確定が行われていない。
  - 「待機キューのみ削除（実行中ジョブは継続）」と「全ジョブ中断（実行中ジョブも停止）」の機能およびUIボタンが分離されていない。
- **Requirement**:
  - **ボタン・機能の明確な分離 (Frontend / Store)**:
    - ジョブ管理モーダルのフッター等に「キューのみクリア」ボタンと「すべて中断（全ジョブ中止）」ボタンの2つを個別に配置すること。
    - **「キューのみクリア」**: ComfyUI の `/queue` クリア API のみを発行し、待機中キュー（`queue_pending`）を空にする。現在生成中の1枚（`queue_running`）は中断（`/interrupt`）せず、そのまま生成を継続して完了させること。
    - **「すべて中断（全ジョブ中止）」**: 待機キューをクリアした上で ComfyUI の `/interrupt` を確実に発行し、現在実行中のジョブも即座に停止させること。
  - **中断状態同期とWebSocketハンドリングの堅牢化 (Frontend / Store)**:
    - ComfyUI の `execution_interrupted` イベントを適切にハンドリングし、中断時のステート確定（`isGenerating: false`, `activeBatch: null`, `currentPromptId: null` 等）を確実に行うこと。
    - 中断直後の残余イベント（`progress` 等）による不要なステート再活性化を防止すること。
  - **個別ジョブ操作UIの整合性向上 (Frontend / Modal)**:
    - 実行中ジョブと待機中ジョブの個別キャンセルボタン（ゴミ箱アイコン）のツールチップや挙動を明確にし、実行中ジョブの中断と待機中ジョブの個別削除を安全に行えること。
- **Acceptance criteria**:
  - AC-1: ジョブ管理モーダルに「キューのみクリア」と「すべて中断」の2つのボタンが独立して表示されていること。
  - AC-2: 「キューのみクリア」を実行した場合、待機中の全ジョブがキューから削除され、現在実行中の1枚は中断されずに最後まで生成完了して画像が表示・保存されること。
  - AC-3: 「すべて中断」を実行した場合、待機中の全ジョブが削除され、かつ現在実行中のジョブも即座に中断され、不要な画像生成が停止すること。
  - AC-4: 中断実行後に WebSocket の残余イベント等によってステートが勝手に「生成中」へ戻ってしまう誤動作が発生しないこと。
  - AC-5: 各アクション実行前に適切な確認ダイアログまたは明瞭なラベルが提示され、ユーザーが誤操作なく意図した操作を選択できること。
