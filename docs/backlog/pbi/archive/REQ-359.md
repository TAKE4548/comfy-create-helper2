### REQ-359: Generate画面のMaximum update depth exceededを修正

- **Type**: bug
- **Status**: done (2026-10-13)
- **Priority**: P1
- **Surface**: frontend/src/pages/GeneratePage/hooks/useWorkflowManagement.ts; frontend/src/utils/workflowMappingState.ts; frontend/src/store/slices/multiSetSlice.ts; docs/incident_report_react-update-depth.md
- **5 Whys / Root Cause**:
  1. なぜ修正が必要か: indexを開くとGenerate画面がReactの最大更新深度エラーで表示できない。
  2. なぜ課題が起きるか: workflowとbaseModelsの読み込み後、Anima判定effectがレンダーごとに再実行される。
  3. なぜeffectが繰り返すか: 生成用workflow変換が毎回新しいオブジェクトを返し、effectの依存値が安定しない。
  4. なぜ再レンダーが続くか: effect内のZustand更新が同じ値でも新しいstore stateを作り、GeneratePage全体を再レンダーする。
  5. 根本原因: 派生workflowの参照安定性がなく、Anima判定effectの更新が冪等化されていない。詳しくは `docs/incident_report_react-update-depth.md` を参照。
- **UX Classification**:
  - **Information Design (情報設計)**: 該当なし（画面表示障害の修正）。
  - **Interaction (インタラクション)**: indexを開いた後も画面が操作可能であること。
  - **Visual (視覚デザイン)**: 既存Generate画面の表示を維持すること。
- **Requirement**:
  - **1. レンダー収束**: 選択workflowとbaseModelsが取得された後、Anima判定による更新が収束し、同じ入力状態で連続するstore更新を起こさない。
  - **2. 派生workflowの安定性**: 同じraw workflowに対する表示用workflowは、無関係なGenerate画面の再レンダーで参照が変化しない。無効mappingの除外とraw workflow保持の既存契約は維持する。
  - **3. Anima判定の正確性**: workflowのtarget base modelに応じてAnima状態を設定し、workflow切替時には新しい状態へ更新する。
- **Acceptance criteria**:
  - [ ] AC-1: Given 選択workflowとbaseModelsの取得が完了している, When indexを開いて画面初期化が完了する, Then `Maximum update depth exceeded` が発生せずGenerate画面を表示できること。
  - [ ] AC-2: Given 同じraw workflow, When GeneratePageが無関係なstore更新で再レンダーされる, Then Anima判定effectが更新ループを起こさず、レンダーが収束すること。
  - [ ] AC-3: Given Animaおよび非Animaのbase modelを割り当てたworkflow, When 各workflowを選択する, Then Anima状態が対応する値になり、workflow切替後も正しく更新されること。
  - [ ] AC-4: Given 明示的に無効なmappingを含むworkflow, When GeneratePage用workflowを組み立てる, Then 無効mappingは生成用から除外され、raw workflow内のmappingと無効状態は保持されること。
  - [ ] AC-5: Given 上記変更, When 対象テストとfrontend typecheckを実行する, Then すべて成功すること。
- **Inferred points**:
  - workflow参照の安定化またはeffect依存値の限定と、Zustand更新の冪等化を設計で選ぶ。最小変更と既存テスト構造に沿う方法を優先する。
  - 既存の `docs/incident_report.md` は別件で使用中のため、今回の報告は `docs/incident_report_react-update-depth.md` を参照する。
