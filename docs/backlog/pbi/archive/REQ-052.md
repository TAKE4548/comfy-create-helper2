### REQ-052: Dynamic LoRA Stack (easyLoraStack) 対応

- **Type**: enhancement
- **Status**: done (2026-08-26)
- **Current step**: none
- **Priority**: P2
- **Surface**: `lora_stack` に対応する拡張を行いたい。LoRAのモデル選択ではLoRA管理を参照して、descriptionが登録されているものはそれをパスの代わりに表示したい。未登録のものはパスのままでよい。
- **Root Cause**: 複数のLoRAを適用する際、プロンプトへのテキスト埋め込みしかできず直感的な操作が難しい。また、ComfyUIの `easyLoraStack` のように動的にスロットを管理するノード構造にフロントエンドが対応していない。
- **Requirement**: 新しい入力タイプ `lora_stack` を定義し、スロットを動的に増減できる専用UI `LoraStackEditor` を実装する。LoRAモデル選択時に、LoRA管理（DB登録データ）を参照して `description` がある場合はその値を表示し、未登録の場合はファイルパスを表示する。
- **Acceptance criteria**:
  - [ ] AC-1: `useGenerationStore` が動的な `lora_count` と連動するスロットの増減をエラーなく管理できること。
  - [ ] AC-2: `LoraStackEditor` が `lora_count` に応じた行数分、LoRA名選択とウェイト調整UIをレンダリングすること。LoRA選択肢の表示名には、LoRA管理に登録され `description` を持つものはその `description`、未登録のものは `file_path` を表示すること。
  - [ ] AC-3: 各スロットの「🗑️ (削除)」ボタン押下時、後続のインデックスが正しく繰り上げられ（インデックス再計算）、空いたスロットが詰められること。
  - [ ] AC-4: ComfyUIへの実行ペイロード生成時、設定された `lora_count` を超えるインデックスのパラメータ（残骸）がJSONから削除されていること。
  - [ ] AC-5: 履歴詳細 (`HistoryModalPreview`) で `_lora_name_` 等のキーを検知し、「LoRA Stack」として視覚的にグループ化して表示できること。
  - [ ] AC-6: 関連する仕様書（`SPEC_SUMMARY.md`, `SPEC_GENERATE.md`, `SPEC_HISTORY.md`）に本機能の要件が追記されていること。
- **Design doc**: none
