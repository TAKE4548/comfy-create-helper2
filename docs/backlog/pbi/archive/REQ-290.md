### REQ-290: リソース監視 GPU使用率算出是正 (3D偏重解消および全エンジンMAX採用)

- **Status**: done (2026-09-27)
- **Description**: ComfyUI画像生成中やローカルLLM推論中にタスクマネージャーのGPU使用率が90〜100%に達しても、Prompt Surgeon上のGPU使用率が0.0%〜数%のまま推移する障害を解消する。PDHカウンターを全エンジン監視（`\GPU Engine(*)\Utilization Percentage`）に拡張し、物理エンジンごとのプロセス合算値から最大値（MAX）を算出するタスクマネージャー準拠の集計アーキテクチャに刷新する。

#### Acceptance Criteria (AC)
- [ ] AC-1: **ComfyUI画像生成時の推論負荷サンプリング検証**: 生成処理中、Computeエンジンの稼働に伴い `gpu_pct` が適正値（80〜100%）を示し、タスクマネージャーのピーク値と整合すること。
- [ ] AC-2: **ローカルLLM推論時の負荷サンプリング検証**: LM Studio / Ollama によるプロンプト処理およびトークン生成中、推論負荷が適正に `gpu_pct` に反映されること。
- [ ] AC-3: **アイドル時の低負荷復帰検証**: 生成・推論停止後、2.5秒以内の次サンプリングで `gpu_pct` が平常値（0.0〜数%）に速やかに復帰すること。
- [ ] AC-4: **サンプリングオーバーヘッド & 性能検証**: 全エンジン取得に伴うPDH処理時間が1.0ms未満に収まり、監視ループおよびサーバー性能に悪影響を与えないこと。
- [ ] AC-5: **自動回帰テスト & 例外堅牢性**: `backend/tests/test_ws.py` を含む自動テストスイートが 100% PASS し、PDHエラー時も未処理例外でクラッシュせず安全にフォールバックすること。
