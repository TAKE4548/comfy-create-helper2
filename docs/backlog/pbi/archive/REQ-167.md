# REQ-167: アプリ離脱・リロード時の生成履歴画像取得およびマージ順序の不具合修正

- **Type**: defect
- **Status**: done (2026-08-26)
- **Priority**: P1
- **Surface**:
  - モバイル等で画像生成を開始した後にアプリを離れ、後から戻っても生成履歴に画像が表示されない。リロードしても読み込まれない。
  - 生成自体は実施されており、ComfyUIのFEや別端末でアクティブにしてあるセッションでは表示される。
- **Root Cause**:
  - `frontend/src/store/useGenerationStore.ts` の `fetchHistory()` において、取得した履歴画像（`targetImages`）を `[...state.batchImages, ...targetImages]` と既存画像の末尾にマージしているため、`localStorage` に過去履歴がある場合に最新画像が末尾に追いやられ、`.slice(0, 50)` で切り捨てられたり最新画像として選択されない。
  - `backend/app/routers/comfy.py` の `GET /api/comfy/history` プロキシが `timeout=5.0` 固定かつ `max_items` クエリパラメータに対応しておらず、履歴肥大化時にタイムアウトして空オブジェクト `{}` を返す。
  - バッチ生成時（`isBatchIntermediate: true`）に `CURRENT_PROMPT_ID` が `localStorage` に保存されないため、アンロード後の復帰時に個別プロンプトのリカバリが行われない。
- **Requirement**:
  - **履歴画像マージ順序の是正 (Frontend / Store)**:
    - `fetchHistory()` において、新着履歴画像（`targetImages`）が先頭に来るようマージ順序を是正すること（`[...targetImages, ...state.batchImages]`）。
    - 取得された最新画像が適切に選択（`selectedImg`）およびプレビュー・履歴ストリップに即時反映されること。
  - **ComfyUI履歴プロキシの堅牢化 (Backend / FastAPI)**:
    - `backend/app/routers/comfy.py` の `GET /history` に `max_items`（デフォルト値設定等）パラメータを追加し、ComfyUIへ適切に中継すること。
    - タイムアウト値を適切に設定し、履歴取得時の安定性を確保すること。
  - **復帰・リロード時の状態同期強化 (Frontend / Hooks & Store)**:
    - アプリ復帰時（`visibilitychange` / `focus`）およびページ起動時に、最新の生成結果が確実に履歴ストリップに読み込まれること。
- **Acceptance criteria**:
  - AC-1: 生成中にWebSocketが切断されたりアプリを離脱しても、アプリ復帰時またはページリロード時に生成完了した画像が履歴ストリップの先頭に正常に表示されること。
  - AC-2: 過去の画像が `localStorage` に存在する場合でも、新しく取得された履歴画像が優先して先頭に配置されること。
  - AC-3: `filterOwnSession` が有効な場合は自セッションの生成画像が正しく抽出されて履歴に反映され、無効な場合は全セッションの履歴画像が表示されること。
  - AC-4: バックエンドの `/api/comfy/history` がクエリパラメータ `max_items` を中継でき、履歴件数が多い場合でもタイムアウトせず安定して履歴JSONを返却すること。
