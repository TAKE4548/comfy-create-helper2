### REQ-395: Gate 3 E2E の generateMobileGallery.spec.ts で /api/ws を遮断し実バックエンド非依存にする

- **Type**: bug
- **Status**: new
- **Priority**: P2
- **Surface**: frontend/e2e/generateMobileGallery.spec.ts（必須）; frontend/e2e 共通ヘルパー, scripts/run_e2e.py, docs/specs/SPEC_TEST_ARCHITECTURE.md（任意）
- **起点**: /triage（2026-10-25）。Gate 3 `scripts/run_e2e.py` で `generateMobileGallery.spec.ts` の [REQ-372/AC-3][AC-4][AC-5][AC-7] が FAIL。
- **根拠資料**: `docs/incident_report_e2e_ws.md`（Type A: Implementation Defect。症状・再現・対照実験・原因箇所を記録）。設計はこのインシデントレポートから開始する。
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: ローカルのバックエンド（:8000）が稼働していると、Gate 3 の `generateMobileGallery.spec.ts` が 4 件失敗し、Gate 3 の結果が実行環境に依存する。
  2. なぜ発生するか: `stubApi()` は `page.route` で HTTP の `/api/*` だけをスタブし、WebSocket `/api/ws` を遮断していない。`systemWsService.ts` が `/api/ws` に接続し、`vite.config.ts` のプロキシ（`ws: true`）経由で実バックエンドにつながり、実データの生成スナップショットがスタブの `/generation/state` を上書きする。
  3. なぜ現状の仕組みで不十分か: `page.route` は WebSocket を捕捉しない。`run_e2e.py` は :8000 の稼働を検査しない。SPEC の Gate 3 節には、実バックエンドに依存しないこと（WS を含む）の明示規定がない。
  4. なぜこのアプローチを採用するか: `page.routeWebSocket` で `/api/ws` を遮断する対照実験（スクラッチ複製に 1 行追加）で、同じ環境のまま 8 件すべて PASS した。製品コードは変更不要である。
  5. 根本原因: SPEC_TEST_ARCHITECTURE.md:22 が定めるネットワーク I/O 境界（WebSocket を含む）でのモックが、E2E の spec で HTTP にしか適用されていなかった。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 変更なし（テストのみ）。
  - **Interaction (インタラクション)**:
    - 変更なし。
  - **Visual (視覚デザイン)**:
    - 変更なし。
- **Requirement**:
  - **1. spec の WebSocket 遮断**:
    - `generateMobileGallery.spec.ts` の `stubApi()` で `/api/ws` を `page.routeWebSocket` により遮断する。テストが必要とするなら、決定論的なスナップショットを送る。
  - **2. 横展開（任意。設計で採否を決める）**:
    - HTTP と WS のスタブを `frontend/e2e` の共通ヘルパーに集約し、他の spec へ適用する。`run_e2e.py` で :8000 の稼働を検出して警告する。SPEC_TEST_ARCHITECTURE.md の Gate 3 節に、実バックエンドに依存しないことを MUST として明記する。
- **Acceptance criteria**:
  - [ ] AC-1: Given ローカルバックエンド（:8000）が稼働し、実 DB に他セッションの履歴がある, When `python scripts/run_e2e.py e2e/generateMobileGallery.spec.ts` を実行する, Then 8 件すべてが PASS すること。
  - [ ] AC-2: Given ローカルバックエンドが停止している, When AC-1 と同じコマンドを実行する, Then 8 件すべてが PASS すること。
  - [ ] AC-3: Given `generateMobileGallery.spec.ts` の実行中, When ページが `/api/ws` へ接続を試みる, Then 接続が実バックエンドへ到達せず、テストが用意したスタブで処理されること（spec 内の `routeWebSocket` の定義で確認する）。
  - [ ] AC-4: Given 変更後, When `python scripts/run_e2e.py`（Gate 3 全体）を実行する, Then 既存の E2E spec に新たな失敗がないこと。
- **Inferred points**:
  - frontend/e2e の他の spec も `routeWebSocket` を使っていないため同種のリスクがある（未検証）。横展開の範囲は設計で決める。
  - SPEC を追記する場合は SSoT の更新ありとして扱う（インシデントレポートの「SSoT_Update_Required: No」はヘルパーの既定値）。
