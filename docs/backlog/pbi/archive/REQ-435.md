### REQ-435: UI密度の整理（ボタン・タブ余白、プリセットタブのメニュー統合、モバイル進捗表示、Historyフィルタ折り畳み、ステージ表示と折り畳み）

- **Type**: feature
- **Priority**: P2
- **Surface**: Generate画面（プリセットタブバー、セクションタブ、プロファイル行、ツールバー、上部ステータスヘッダー、Prompt／Parameterのstage group）とHistory画面（ヘッダー、フィルター）。Desktop（幅768px以上）とMobile（幅767px以下）の両方。
- **Reference**:
  - docs/specs/SPEC_COMMON.md（§1-3 44px、§1-5-3 Hit-Slop、§1-6 MUI-06／MUI-10）
  - docs/specs/SPEC_GENERATE.md（§2 stage group・sticky見出し、§2-5 `stageGrouping`、§2-6 プリセットタブ一括クローズ（REQ-402）、§3-2 ステータスヘッダー、§3-8）
  - docs/specs/SPEC_HISTORY.md（複合フィルタ）
  - docs/backlog/pbi/active/REQ-373.md（Requirement 2とAC-6の密度整理の部分を本PBIで置き換える）
  - docs/backlog/pbi/active/REQ-374.md（AC-3のフィルター折りたたみを本PBIで置き換える）
  - 関連: REQ-434（同時起票。モバイルのプロンプト欄切替）
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: ボタンやタブの余白、重複した進捗バー、常時展開のフィルターが表示面積を占め、本来の作業領域が狭い。
  2. なぜその課題が発生するか: タップ領域を確保する規則を、見た目の外形の大きさで満たしている箇所がある。モバイル向けの寸法の一部がPC表示にも適用されている。
  3. なぜ現状の仕組みで不十分か: プリセットタブにメニュー用と閉じる用のボタンが並んでいる。モバイルでは全体とjob単体の2本の進捗バーが重複している。モバイルのパラメータ欄はステージで区切られず、同じロールの項目を見分けられない。
  4. なぜこのアプローチを採用するか: Hit-Slopでタップ領域を保ったまま外形を細くし、操作入口と表示を1つずつに統合すれば、誤タップを増やさずに面積を確保できる。ステージの折り畳みで、長いワークフローでも目的の項目へ早く到達できる。
  5. 根本原因: 操作領域の確保と表示面積の配分が、画面幅ごとに整理されないまま積み重なったこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 全体の進捗をn/mの文字表示にまとめる。モバイルのパラメータ欄をステージ単位でまとめる。折り畳んだフィルターでも絞り込み中であることを示す。
  - **Interaction (インタラクション)**:
    - タブのメニューを1つのボタンに統合する。フィルターとステージを折り畳めるようにし、ステージの開閉状態を覚えておく。
  - **Visual (視覚デザイン)**:
    - ボタンとタブの外形を細くする。PC表示からモバイル向けの寸法を除く。進捗バーを1本にする。
- **Requirement**:
  - **1. 余白の整理（モバイル）**: Generate画面とHistory画面のボタン・タブの見た目の外形を細くする。有効タップ領域は44×44px以上を保ち（Hit-Slop）、隣接する操作どうしで有効タップ領域が重ならないようにする。
  - **2. PC表示に残るモバイル寸法の除去**: 幅768px以上で、モバイル向けの最小寸法・余白が適用されている箇所（Generateのプリセット（プロファイル）タブなど）を特定し、デスクトップ向けの寸法にする。
  - **3. プリセットタブのメニュー統合**: 各タブのellipsisボタンと閉じる（×）ボタンを1つのボタンに統合する。このボタンのタップ／クリック、右クリック、500msの長押しで同じメニューを開く。メニューには「このタブを閉じる」と既存の一括クローズ（左／右／他）を並べる。
  - **4. モバイルの進捗表示**: 幅767px以下の生成中は、上部ステータスヘッダーに実行中jobの進捗バーを1本だけ表示し、全体の進捗は「n/m」の文字で表示する。
  - **5. Historyフィルターの折り畳み（モバイル）**: 幅767px以下では、フィルター領域を初期状態で折り畳み、展開して条件を指定できるようにする。ソートは開閉状態によらず使える。
  - **6. ステージ表示と折り畳み**: Mobileのパラメータ欄もDesktopと同じくステージ単位でまとめ、ステージ名の見出しを付ける。Desktop／Mobileのパラメータ欄とDesktopのプロンプト欄で、ステージの見出しを押すとそのステージを折り畳める。開閉状態は同じブラウザーで再読み込み後も保持する。
  - **7. 維持事項**: プリセットタブの選択・チェック・単件クローズの保存規則・一括クローズの対象集合と失敗時の挙動（REQ-402）、ETA・経過時間・キュー数・生成完了の導線、フィルターのAND結合と0件時のEmpty State、各入力値・ParamSync・Seedの保存と同期、折り畳んだステージの値の生成への反映。
  - **8. 非対象**: チップの寸法・余白、REQ-373のセクション切替（タブ・スワイプ）とスクロール末尾、REQ-374のその他の要件（ヘッダー整理・カード操作）、REQ-375の複数選択、API。
- **Acceptance criteria**:
  - [ ] AC-1: Given 幅360px・390pxのGenerateとHistory, When 設計で列挙したボタン・タブ（セクションタブ、プリセットタブ、プロファイル行の操作、プロンプトのツールバー、Historyのヘッダー・フィルター操作）の外形を測る, Then 各外形の高さが変更前の計測値より小さく、各操作の有効タップ領域が44×44px以上であること。
  - [ ] AC-2: Given AC-1の各操作, When 隣接する操作の有効タップ領域を比べる, Then 有効タップ領域が互いに重ならず、各操作の中心をタップするとその操作だけが実行されること。キーボードでフォーカスしたときにフォーカスが見えること。
  - [ ] AC-3: Given 幅1280pxと幅800pxのGenerate, When プリセットタブバーと、設計で特定したモバイル寸法の適用箇所を測る, Then 各要素の高さが44px未満で、モバイル向けの最小寸法・余白が適用されていないこと。
  - [ ] AC-4: Given Generateのプリセットタブ（Desktop／Mobile）, When タブを確認する, Then 各タブの操作ボタンが1つだけで、ellipsisボタンと閉じるボタンが別々に表示されていないこと。
  - [ ] AC-5: Given いずれかのプリセットタブ, When 統合ボタンをタップ／クリックする、タブを右クリックする、またはタブ名を500ms長押しする, Then いずれも同じメニューが開き（幅767px以下は下部シート、768px以上はデスクトップメニュー）、メニューを開くだけでは選択中のタブと入力値が変わらないこと。
  - [ ] AC-6: Given AC-5のメニュー, When 「このタブを閉じる」を選ぶ, Then 変更前の閉じるボタンと同じ保存・クローズの結果になること。「左のタブをすべて閉じる」「右のタブをすべて閉じる」「他のタブを閉じる」は、REQ-402の対象集合と失敗時の挙動を保つこと。
  - [ ] AC-7: Given 幅767px以下で複数jobの生成中, When 上部ステータスヘッダーを確認する, Then 画面上の進捗バーが実行中jobの1本だけで、全体の進捗が「n/m」の文字（mは今回の生成要求のjob総数）で表示されること。
  - [ ] AC-8: Given AC-7の状態, When jobが1件完了するたびに表示を確認する, Then 進捗バーが次のjobの進捗に切り替わり、n/mが1つ進むこと。経過時間・ETA・キュー数・生成完了の導線が引き続き表示されること。
  - [ ] AC-9: Given 幅768px以上のGenerateで生成中, When 進捗表示を確認する, Then 変更前と同じ進捗表示であること。
  - [ ] AC-10: Given 幅767px以下のHistoryスナップショット一覧（幅360px×高さ640px）, When 画面を開く, Then フィルター領域が折り畳まれた1行で表示され、最初の画像カードがスクロールせずに見えること。
  - [ ] AC-11: Given AC-10で絞り込み条件を1つ以上指定している, When フィルターを折り畳む, Then 折り畳んだ行に指定中の条件の件数が文字で表示されること。
  - [ ] AC-12: Given フィルターを折り畳んだ状態と展開した状態, When ソートを操作し、展開時にWorkflow／LoRA／Tag Setの条件を指定する, Then どちらの状態でもソートを実行でき、絞り込み結果（AND結合、0件時のEmpty Stateとフィルター解除）が変更前と同じであること。
  - [ ] AC-13: Given 同じロールで異なるステージのパラメータを含むワークフロー, When 幅767px以下でパラメータセクションを表示する, Then パラメータがワークフローのステージ順でグループにまとまり、各グループにステージ名の見出しが付き、同じロールの項目がどのステージに属するか区別できること。
  - [ ] AC-14: Given Desktop／Mobileのパラメータ欄、またはDesktopのプロンプト欄のステージ見出し, When 見出しをクリック／タップする（キーボードではEnter／Space）, Then そのステージの入力欄だけが折り畳まれ、もう一度押すと展開すること。見出しが開閉状態を文字またはアイコンと支援技術向けの状態（展開／折り畳み）で示すこと。
  - [ ] AC-15: Given 初めて開くワークフロー, When ステージのグループを表示する, Then すべてのステージが展開されていること。
  - [ ] AC-16: Given いくつかのステージを折り畳んだ, When ページを再読み込みする、または別のワークフローへ切り替えてから元のワークフローへ戻る, Then 同じブラウザーではワークフローごと・欄（プロンプト／パラメータ）ごとに折り畳み状態が再現されること。
  - [ ] AC-17: Given いくつかのステージを折り畳んだ状態, When 生成する、ParamSyncの同期元を変更する、プリセットを切り替える, Then 折り畳んだステージの値も生成要求と同期に従来どおり反映され、値が変わったり失われたりしないこと。
  - [ ] AC-18: Given Desktopでステージを折り畳んだ状態, When 欄をスクロールする, Then 見出しの境界での切替（sticky見出し）が保たれ、見出しが入力欄を覆わないこと。
  - [ ] AC-19: Given 幅360pxのMobileで、セーフエリアあり／なし、ソフトキーボードの開閉, When AC-1、AC-5、AC-7、AC-10、AC-14を実行する, Then レイアウトが崩れず、固定生成バーとボトムナビに操作対象が隠れないこと。
- **Inferred points**:
  - 「n/m」のnは実行中jobの通し番号（完了件数＋1、全件完了時はm/m）とする。キャンセルや失敗したjobの数え方は設計で決める。
  - 余白を整理する対象と変更前の計測値は、設計の段階で対象一覧と画面写真で確定する（AC-1の基準）。
  - ステージの開閉状態の保存先はブラウザーのローカル保存とする（ユーザー回答「localStorageくらいで」）。端末間では同期しない。存在しなくなったステージの保存状態は無視する。
  - モバイルのプロンプト欄はREQ-434でドロップダウン切替になり1欄ずつ表示するため、折り畳みの対象外とする。
  - プリセットタブの単件クローズは、メニューを経由する2タップ操作になる（ユーザー回答Q3-a）。
  - 完了時にSPEC_GENERATE §2（stageGroupingのMobile既定値）、§2-6、§3-2、§3-8、SPEC_HISTORYを更新する。REQ-373のRequirement 2・AC-6の密度部分とREQ-374のAC-3は、承認後に「REQ-435で置き換え」と整理する。
