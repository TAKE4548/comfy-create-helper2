### REQ-343: ワークフローマッピング画面のRole×ステージ多段階対応および未設定選択のUI/データ整合

- **Type**: bug
- **Status**: done (2026-10-11)
- **Priority**: P2
- **Surface**:
  - `frontend/src/components/UploadWorkflowModal.tsx`
  - `frontend/src/components/RescanModal.tsx`
  - `frontend/src/hooks/useMasterMappingRows.ts`
  - `frontend/src/components/AdaptiveWorkflowWiring.tsx`
  - `frontend/src/pages/SettingsPage/components/WorkflowConnectionSection.tsx`
  - `backend/app/routers/workflows.py`
  - `backend/app/schemas/workflow.py`
- **Reference Spec**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. **なぜ新設・改修が必要か**: マッピングマスタ側でRole×Stageの2軸正規化が行われたが、ワークフロー登録時・再スキャン時・配線画面がロール単位でしかノード設定できず、複数ステージ（Main, Rough, Detail等）を持つワークフローでマッピング不足となるため。また、不要な組み合わせを未設定にする操作性が不十分なため。
  2. **なぜその課題が発生するか**: ワークフロー登録・再スキャン画面が旧来の親MappingMaster単一選択のUI実装（`useMasterMappingRows`）のままであり、ワークフロー内の有効ステージを反映した複数選択スロットを展開する構造になっていないため。
  3. **なぜ現状の仕組みで不十分か**: 1つのRole（例: StepsやPrompt）につき1つのノードしか割り当てられず、Rough/Detail等の後続ステージのノードが未割当のまま保存されてしまう。さらに、ワークフロー保存バリデーション（`validateConfig`）で同一 `master_id` の重複がエラーとなり、バックエンドでも `variant_id` が欠落して永続化されないため。
  4. **なぜこのアプローチを採用するか**: ワークフローから検出された有効ステージごとに、各Roleのノード候補選択スロット（推奨ハイライト付き）を展開し、さらに各スロットに「未設定」選択肢およびワンクリック解除ボタンを設けることで、必要なステージのみを充足し不要な組み合わせは安全に除外できるようにするため。
  5. **根本原因 (Root Cause)**: REQ-336によるマスタ・バリアント層の刷新に対し、取り込み・再スキャン・配線側のUIおよび保存パイプラインが「Role主軸×有効ステージ展開」のマルチスロット仕様・オプトアウト設計に追従していなかったこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 各Role（親定義）に対し、ワークフロー内で検出された「有効ステージ（Main, Rough, Detail等）」を展開したスロット構造を提供。
    - 各スロットに「未設定（未割り当て）」状態をファーストクラスで明示し、ワークフローによって不要な組み合わせは未設定のまま保存可能とする。
  - **Interaction (インタラクション)**:
    - ロールごとに有効ステージ分の候補ノードドロップダウン（ステージ合致推奨ノードを優先表示）。
    - 各スロットにワンクリックで「未設定」にできるクリア（✕）操作および選択肢先頭の「未設定」を提供。
    - スキャン時にステージキーワードと合致したノードを各ステージスロットへ自動サジェスト。
  - **Visual (視覚デザイン)**:
    - Prompt Surgeon公式デザイン規約に準拠したダークテーマUI。
    - ステージバッジ（Main, Rough, Detail）、推奨ノード★バッジ、未設定状態の明瞭な視覚表現。
- **Requirement**:
  - **1. ワークフロー取り込み・再スキャン画面のRole×有効ステージ多段階展開UI (Frontend)**:
    - `UploadWorkflowModal` および `RescanModal` において、ワークフローから検出されたアクティブなステージに基づき、各Roleに対してステージごとの候補選択スロットを展開すること。
    - 同一Roleに対して、有効ステージ分（Main, Rough, Detail等）のノードを複数マッピング可能とすること。
  - **2. 未設定（オプトアウト）操作性の向上 (Frontend)**:
    - 各ステージスロットにおいて、明示的な「未設定」選択肢およびワンクリック解除（クリア）ボタンを提供すること。
    - ワークフローによって不要な組み合わせが存在する場合、未設定のまま保存を完了でき、未設定の項目が警告やエラーで進行を妨げないこと。
  - **3. 配線画面・設定保存パイプラインの整合 (Frontend/Settings)**:
    - `WorkflowConnectionSection.tsx` の `validateConfig` および `handleSaveLinks` において、同一 `master_id` を持つ複数バリアントの共存を許容し、`variant_id` を維持したまま保存すること。
    - 設定JSONのエクスポート/インポートでも `variant_id` が欠落しないようにすること。
  - **4. バックエンド `/api/workflows/scan` およびマッピング永続化の改修 (Backend)**:
    - `/api/workflows/scan` エンドポイントにおいて `scan_workflow_variants` を利用し、ステージ別・バリアント別のマッチング結果を返却すること。
    - `WorkflowMappingCreate` および `WorkflowMappingRead` スキーマに `variant_id` を追加し、DBに正確に永続化すること。
- **Acceptance criteria**:
  - [ ] **AC-1 (Role×有効ステージの複数ノードマッピング)**: Given 複数の有効ステージ（例: Main, Rough）を含むワークフローをアップロードまたは再スキャンするとき, When マッピング設定画面が表示されるとき, Then 各Roleに対して有効ステージごとのノード選択スロットが表示され、同一Roleに対してステージごとに異なるノードを選択・割り当てできること。
  - [ ] **AC-2 (不要な組み合わせの未設定化)**: Given マッピング設定画面において特定のステージとRoleの組み合わせが不要なとき, When ドロップダウンで「未設定」を選択またはクリア操作を実行するとき, Then 当該スロットが安全に未設定状態となり、保存時にバリデーションエラーとならず正常に登録・更新できること。
  - [ ] **AC-3 (バリアント単位の配線保存と重複master_id許容)**: Given 設定画面（WorkflowConnectionSection）において同一マスタの複数ステージバリアントがマッピングされているとき, When 保存処理またはJSONインポート/エクスポートを実行するとき, Then 重複エラーが発生せず、`variant_id` を保持して正常に永続化されること。
  - [ ] **AC-4 (バックエンドスキャンのステージバリアント対応)**: Given バックエンドの `/api/workflows/scan` を呼び出すとき, When ワークフロー内に各ステージのキーワードに合致するノードが存在するとき, Then ステージバリアントに応じたマッチング結果（variant_id, stage_key等）が返却されること。
- **Inferred points**:
  - REQ-336で導入された `StageMaster`、`MappingVariant`、`scan_workflow_variants` の既存資産を最大限に活用する。
  - ワークフローの生成実行時（`workflowParamInjector`）は既に `workflow.mappings` の各 `role`（例: `steps`, `steps_rough`）に対応しているため、各バリアントの `computed_role` で正確にマッピングが保持されれば実行時挙動も整合する。
