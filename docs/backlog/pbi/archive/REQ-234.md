### REQ-234: テスト基盤・フレームワークのセットアップ (Phase 1)

- **Type**: enhancement
- **Status**: done (2026-09-09)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - テスト監査レポート（`tmp/test_framework_implementation_plan.md`）において、フロントエンドがAPIクライアントをベタモックしていることによるMock Driftリスク、外部通信の異常系テスト不足、テスト順序依存性やDBセッションリークの未検知が指摘された。
  - 今後の画面テスト新設や耐障害性テスト拡充の基盤として、ネットワーク層モックツール（MSW, respx）やファジング・プロパティテストライブラリ（fast-check, hypothesis）、テスト隔離・リーク検知環境を先行してセットアップする必要がある。
- **Root Cause**:
  - 各機能開発時にアドホックなモック実装を行ってきたため、統一されたネットワーク層インターセプト機構や、DBセッション解放漏れ・順序依存を自動検知するテスト基盤機構が未導入のままとなっていた。
- **Requirement**:
  - フロントエンドにMSW (Mock Service Worker v2) を導入し、ネットワーク層でのインターセプトおよびハンドラ基盤（`handlers.ts`, `server.ts`, `setup.ts`）を整備する。
  - フロントエンドにプロパティテストライブラリ（`fast-check`）を導入し、`vite.config.ts` のテスト環境隔離設定（`isolate`, `restoreMocks`, `clearMocks`, `mockReset`）を強化する。
  - バックエンドに外部HTTPモック用ライブラリ（`respx`）、ランダム順序実行プラグイン（`pytest-randomly`）、境界値ファジングライブラリ（`hypothesis`）を導入する。
  - バックエンドの `backend/tests/conftest.py` に、各テスト終了時にSQLAlchemyのチェックアウト中コネクションが0であることを検証するDBコネクションリーク検知 Fixture を整備する。
  - 本基盤導入後も、既存の全テストが正常にパスすることを保証する。
- **Acceptance criteria**:
  - [ ] AC-1: フロントエンドにおいて、API通信（`/api/*`）およびComfyUI通信（`/api/comfy/*`）をネットワーク層でインターセプト・モック可能なMSW v2基盤（`handlers.ts`, `server.ts`, `setup.ts`連携）が整備されていること。
  - [ ] AC-2: `frontend/vite.config.ts` のテスト設定において、テストファイルごとの隔離（`isolate: true`）およびモック自動クリア・リセットが有効化されていること。
  - [ ] AC-3: フロントエンドにおいて、`fast-check` を用いたプロパティベーステストが実行可能な環境が整っていること。
  - [ ] AC-4: バックエンドにおいて、`respx` を用いた `httpx.AsyncClient` 通信のモックおよび障害注入が実行可能な環境が整っていること。
  - [ ] AC-5: バックエンドにおいて、`pytest-randomly` によるテスト順序ランダム化が動作すること。
  - [ ] AC-6: バックエンドの `conftest.py` において、テスト実行後にSQLAlchemyのDBプールコネクションリークを自動検知するFixture（`engine.pool.checkedout() == 0`）が機能すること。
  - [ ] AC-7: 新規パッケージおよび基盤設定導入後、既存のフロントエンドおよびバックエンドの全テストがパスすること。
- **Design doc**: tmp/test_framework_implementation_plan.md
