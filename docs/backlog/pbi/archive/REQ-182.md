### REQ-182: 生成中断処理（Abort / すべて中断）のレスポンス改善および実行中ジョブの確実な停止

- **Type**: bugfix
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**:
  1. 生成中に中断操作を行っても、Abort のレスポンス処理が正常に働かず、画面のステートが不正になる。
  2. 「すべて中断」を実行しても、現在生成中のジョブが停止せず、別途個別キャンセルを行わなければならない。
- **Root Cause**:
  1. **`request()` における空レスポンスの構文エラー**: `client.ts` の `request()` 関数が、ComfyUI の空ボディ 200 レスポンスに対して `res.json()` を実行して `SyntaxError` をスローし、`cancelAllJobs()` 内の後続 `interrupt()` 呼び出しがスキップされていた。
  2. **`queuePrompt` での Abort 未伝達**: `options.signal` が `comfyApi.queuePrompt` や通信前後のステート更新ガードに反映されていなかった。
  3. **非同期停止の競合（すり抜け投入）**: `cancelAllJobs()` 実行時に通信中だった `queuePrompt` の完了を待機していなかったため、待機キュー削除後にジョブが遅れて ComfyUI に登録されてしまうことがあった。
- **Requirement**:
  1. `client.ts` の `request()` で空ボディを安全にハンドリングし、構文エラーを根絶する。
  2. `queuePrompt` における `AbortSignal` ガードを徹底し、中断時は `isGenerating` などの不要なステート更新をスキップする。
  3. `cancelAllJobs()` において、通信中ジョブの完了待機（`await activeSubmissionPromise`）→ 待機キュー全削除（`deleteQueue`）→ 実行中ジョブ停止（`interrupt`）の順序で確実に実行し、個別ステップを独立保護する。
