### REQ-380: ComfyUIメモリ（VRAM）のオンデマンド解放機能とサービス管理導線の追加

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: frontend/src/pages/SettingsPage, tools/server-manager, docs/specs/SPEC_SETTINGS.md, docs/specs/server_manager_guide.md
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: ComfyUIが画像生成完了後もロード済みモデルとキャッシュメモリ（VRAM）を占有し続け、LMStudio等のローカルLLMや他プロセスがVRAM不足で動作不能または低速化するため。
  2. なぜその課題が発生するか: ComfyUIは次回生成の高速化を目的としてモデル重みをVRAM上に保持する設計となっており、プロセスがアイドル（未使用）状態になってもOSへメモリを自動返却しないため。
  3. なぜ現状の仕組みで不十分か: 現状VRAMを解放するにはComfyUIサービス自体を停止・再起動する必要があり、プロセス再起動に時間を要するほか、セッション切断や再接続待機などの大きなオーバーヘッドが生じるため。
  4. なぜこのアプローチを採用するか: ComfyUIが提供する軽量なメモリ・モデル解放API（/free）を活用し、サービスを再起動することなくオンデマンドでVRAMを返却可能にする。他ツールからの連携は素のComfyUIネイティブAPI（ポート8188）直接呼び出しで疎結合に保ちつつ、本ツールではユーザーが状態を見て安全に任意実行できるUI導線（サービス管理欄＋生成中ガード）を提供するため。
  5. 根本原因: ComfyUIのプロセス稼働を維持したままモデルアンロードおよびGPUメモリ解放を行うUI操作導線および安全ガードがサービス管理機能に存在せず、マルチプロセスでのVRAMリソース共有が困難であったこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 設定画面（`system` タブ）および Web Manager のサービス管理セクションにおいて、ComfyUI の稼働状態行に「メモリ解放（VRAM解放）」アクションを配置し、現在のVRAM状況とサービス死活状態を視認した上で操作可能な動線を構成する。
    - 生成中・停止中・解放処理中・完了の各状態をユーザーへ明確にフィードバックする。
  - **Interaction (インタラクション)**:
    - ユーザー操作（UI）: ComfyUI行のメモリ解放ボタンを押下することで、ComfyUIを停止することなくモデルアンロードおよびキャッシュクリアを即時要求する。
    - 生成中ガード: ComfyUIが画像生成中（Executing）の場合はボタンを非活性（disabled）とし、ツールチップ等で案内して生成中ジョブへの影響を防止する。
    - 連打防止 / 多重送信防止: 要求送信中はボタンを非活性（disabled）またはローディング表示とし、多重リクエストを防止する。
    - 外部連携の疎結合化: 外部ツール（LMStudioや外部スクリプト等）は本ツールに依存せず、素のComfyUIネイティブAPI（`http://127.0.0.1:8188/free`）を直接呼び出す運用とする。
  - **Visual (視覚デザイン)**:
    - サービス管理行（死活ランプ、「ログ ▼」）と親和性のあるコンパクトかつ識別しやすいボタンスタイル（例: 「メモリ解放」ボタン）を適用する。
    - モバイル画面（<768px）でもタップターゲット44×44px以上を確保し、UI 6大ハード不変条件に適合したレイアウト崩れのない表示を行う。
- **Requirement**:
  - **1. サービス管理UIへのメモリ解放導線の追加**:
    - アプリ設定画面（`system` タブ）のサービス管理エリアのComfyUI行に、メモリ解放（VRAM解放）トリガーボタンを追加する。リクエストは既存のサービス管理規約に従い、CORS許可範囲内のポート8899 Web Managerへ送信する。
    - Web Manager（ポート8899）ダッシュボードのComfyUI操作項目にもメモリ解放アクションを追加する。
  - **2. 生成実行中ガードおよび状態フィードバック**:
    - ComfyUIが画像生成中（Executing）の場合は、誤操作および意図しないアンロードを防止するため、UI上のメモリ解放ボタンを非活性（disabled）とし理由を明示する。
    - ComfyUI停止中（STOPPED）の場合もボタンを非活性とする。
    - リクエスト実行中の連打防止ロック（多重送信抑止）および成否の視覚的通知を提供する。
    - メモリ解放完了後、次回の定期ポーリング（最大5秒以内）または更新契機でVRAMメーター/ステータスが最新状態に同期されること。
  - **3. 外部ツール連携運用の明文化（依存排除）**:
    - 外部プロセスやスクリプトからComfyUIのメモリを解放したいユースケースについて、本ツールへの依存を持たせず、素のComfyUIネイティブAPI（`http://127.0.0.1:8188/free`）を直接利用する運用ガイドを整備する。
  - **4. SSoT仕様書（SPEC_SETTINGS.md, server_manager_guide.md）の同期**:
    - systemタブのサービス管理仕様およびWeb Managerのアクション仕様に、ComfyUIメモリ解放操作の契約および外部連携方針を明記する。
- **Acceptance criteria**:
  - [ ] AC-1: Given ComfyUIサービスが稼働（LISTEN）中かつアイドル状態である, When ユーザーが設定画面（systemタブ）のサービス管理セクションからComfyUIのメモリ解放操作を実行する（ポート8899 Web Manager `/api/action` への送信、またはWeb Manager画面での操作）, Then ComfyUIプロセスが再起動されることなくモデルアンロードおよびメモリ解放要求が発行され、成功結果がUIに通知されること。
  - [ ] AC-2: Given メモリ解放リクエストが送信中である, When ユーザーが操作ボタンを連続してクリックしようとする, Then ボタンが非活性（disabled）またはローディング状態となり、二重送信や競合が防止されること。
  - [ ] AC-3: Given ComfyUIが画像生成ジョブを実行中（Executing）である, When ユーザーが設定画面のサービス管理セクションを表示する, Then メモリ解放ボタンが非活性（disabled）表示となり、生成中である旨の案内が提示され、実行中ジョブへの誤操作が防止されること。
  - [ ] AC-4: Given ComfyUIが停止（STOPPED）中である, When 設定画面のサービス管理セクションを表示する, Then メモリ解放ボタンが非活性（disabled）表示となり、停止中のサービスに対する無効な要求送信が抑止されること。
  - [ ] AC-5: Given メモリ解放処理が完了した状態, When 画面上のリソース監視（VRAM情報）が次回ポーリング（5秒以内）または手動更新契機で取得される, Then 解放後の空き容量が正常に反映され、情報取得失敗時は既存の監視エラー規約に従ってUIに通知されること。
  - [ ] AC-6: Given 外部ツールやスクリプトからComfyUIのメモリ解放を行う場合, When 当該ツールがComfyUIネイティブAPI（`http://127.0.0.1:8188/free`）へ直接リクエストを発行する, Then 本ツールのバックエンドを経由することなくComfyUI単体でメモリ解放が実行される仕様・運用方針が `server_manager_guide.md` に明記されていること。
- **Inferred points**:
  - ComfyUIのメモリ解放はComfyUI標準の `/free` API（unload_models: true, free_memory: true）を利用することを想定する。
  - 設定画面（ポート8000配信）からのサービス管理操作は、SPEC_SETTINGS.mdおよびserver_manager_guide.mdに規定されたOrigin許可範囲（localhost, 127.0.0.1, LAN IP）に従い、ポート8899のWeb Manager APIと通信する。
  - 他ツールからの利用については、本ツールに余分なプロキシAPIを設けず、直接 `http://127.0.0.1:8188/free` を利用することで疎結合性を最大化する。
  - 画面幅768px未満のモバイル表示においては、Service Card内の行レイアウトが崩れないよう折り返しまたはボタンスタイルを調整し、44×44pxのタップ領域を確保する。
