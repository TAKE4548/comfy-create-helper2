### REQ-225: プリセット一括編集におけるComfyUI未登録LoRAモデルの選択連携

- **Type**: improvement
- **Status**: done (2026-09-06)
- **Priority**: P2
- **Surface**:
  - 生成プリセットの一括編集モーダル（`ProfileBulkEditModal`）のパラメータタブ内にある「新規追加LoRA（差分編集）」において、DBに未登録でComfyUI側にのみ存在するLoRAモデルが候補に表示されず、選択できない。
- **Symptom**:
  - 通常の生成画面のパラメータパネル（`LoraStackEditor`）では、ComfyUIのモデルディレクトリ内にある未登録LoRA（`Unregistered`）も検索・選択できるが、プリセット一括編集モーダル内ではDB登録済みのLoRAしか候補に表示されない。
- **Root Cause**:
  - `ProfileBulkEditModal.tsx` 内の `SearchableLoraSelect` に対して `comfyModels`（`/api/loras/comfy-models` の取得結果）が渡されておらず、DB登録済みの `loras` のみが渡されているため。
- **Requirement**:
  - プリセット一括編集モーダル（`ProfileBulkEditModal`）のパラメータタブにおいて、通常のパラメータパネルの `LoraStackEditor` と同一の表示仕様（`SearchableLoraSelect` + `comfyModels` 連携）に統一し、ComfyUI側で認識されている全LoRAモデル（未登録含む）をピックアップして検索・選択・一括適用できること。
  - **表示優先順位**: 個別LoRAスタックと同様に、DB登録済みのLoRAについては登録名称（`description` / `model_name`）を優先して表示し、未登録のものには `Unregistered` バッジおよびファイルパスを表示する。
  - なお、プロンプトへのトリガーワード反映を担うアセット機能（`AddAssetModal`）については、登録済みLoRAのみを対象とする現行仕様を維持すること。
- **Acceptance criteria**:
  - [x] AC-1: `ProfileBulkEditModal` のパラメータタブ（差分編集の「新規追加LoRA」等）において、ComfyUI側で認識されているLoRAモデル一覧（未登録LoRAを含む）が `SearchableLoraSelect` の選択肢・検索対象として正しく表示されること。
  - [x] AC-2: 個別LoRAスタックと同様に、登録済みLoRAは登録名（説明文／モデル名）が優先して表示され、未登録LoRAはファイルパスおよび `Unregistered` バッジが表示されること。
  - [x] AC-3: 未登録のComfyUI LoRAモデルを選択して一括適用した際、選択した各プリセットの `param_values` に当該LoRAのファイルパスおよび強度設定が正常に保存されること。
  - [x] AC-4: プロンプトへのアセット追加モーダル（`AddAssetModal`）は登録済みLoRAのみを対象とする仕様が維持され、退行が発生しないこと。
  - [x] AC-5: 関連するフロントエンドテスト（`ProfileBulkEditModal.test.tsx` 等）が追加・更新され、すべてパスすること。
