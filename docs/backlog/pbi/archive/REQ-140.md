### REQ-140: モバイルモードにおけるバッチ・複数プリセット生成のキュー登録高速化および取り消しレスポンス改善

- **Type**: bugfix
- **Status**: done (2026-08-26)
- **Current step**: none
- **Priority**: P1
- **Surface**: モバイルモードでバッチ・複数プリセットで生成実行した時、キューへの登録がやけに遅い。また取り消し時のレスポンスも悪い。
- **Root Cause**: 
  1. `handleGenerateSets` において、全プリセット×バッチサイズのジョブを逐次直列ループで処理し、毎回の `queuePrompt` 内で `POST /prompt` と `await fetchQueue()`（`GET /queue`）が直列実行されるため、Wi-Fi環境下でネットワーク往復遅延（RTT）が累積する。
  2. `queuePrompt` 実行毎に最大200件の `localStorage` メタデータ走査および同期 `JSON.parse` が実行され、モバイル端末のメインスレッドをブロックする。
  3. 毎ジョブのキュー取得に伴う Zustand 状態更新により、単一コンテナで構成された `MobileLayout` 全体が連続再レンダリングされ、UI描画負荷とイベント遅延が発生する。
  4. `handleGenerateSets` にキャンセル検知（AbortController / 中断シグナル）が存在せず、ユーザーがキャンセルを実行してもバックグラウンドの直列ループが残りのジョブをComfyUIに再投入し続けてしまう。
- **Requirement**:
  1. バッチ・複数プリセット生成時のキュー投入処理を最適化し、不要な毎ジョブごとの中間 `fetchQueue` 呼び出しを削減、またはバッチ登録完了後に1回のみキュー同期を行うようにする。
  2. queuePrompt における localStorage メタデータ走査（キャッシュ整理）処理を非同期化またはデバウンスし、メインスレッドのブロッキングを防止する。
  3. handleGenerateSets にキャンセル中断シグナル（AbortController 等）を導入し、ユーザーがジョブキャンセルを実行した際は直列投入ループを即座に中断して後続ジョブの再投入を防止する。

#### Acceptance Criteria (AC)

##### 1. キュー登録処理の高速化と直列ブロッキング解消
- [ ] AC-1-1: 複数プリセット・バッチ生成実行時、個々のジョブ投入毎の中間 fetchQueue（GET /queue）の無駄な直列呼び出しを行わず、全ジョブ投入後に一括または効率的にキュー状態を同期すること。
- [ ] AC-1-2: queuePrompt 内での localStorage メタデータ走査・削除処理がジョブ投入毎のメインスレッドブロッキングを引き起こさないこと。
- [ ] AC-1-3: モバイルモード（および低スペック端末・Wi-Fi環境）において、バッチ・複数プリセット生成ボタン押下後のキュー登録完了までの待機時間が大幅に短縮されること。

##### 2. 取り消し（キャンセル）時の即時中断と再投入防止
- [ ] AC-2-1: 複数プリセット・バッチ生成のキュー投入ループ実行中にユーザーがジョブキャンセル（単一キャンセルまたは一括キャンセル）を行った場合、投入ループが即座に中断（Abort）されること。
- [ ] AC-2-2: キャンセル完了後に、中断された後続ジョブがComfyUIキューへ再投入されないこと。
- [ ] AC-2-3: モバイル環境でキャンセル操作を実行した際、UIが固まらず即座にキャンセル要求が処理されること。

##### 3. バッチ状態管理と進捗表示の整合性
- [ ] AC-3-1: バッチ投入開始時から activeBatch が適切に初期化・追跡され、生成進捗バーおよびジョブ状態が正しく表示されること。
- [ ] AC-3-2: 既存の通常モード（デスクトップ・タブレット表示）における生成・キャンセル機能がリグレッションなく正常に動作すること。
