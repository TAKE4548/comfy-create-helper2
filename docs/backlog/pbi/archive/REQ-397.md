- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: SPEC は「ネットワーク I/O（fetch / WebSocket / httpx）の境界でモックする」と定めるが、Gate 3（Playwright E2E）で実バックエンドに依存しないことと、WebSocket も遮断することが明示されていない。
  2. なぜその課題が発生するか: 境界 E（WebSocket は `MockWebSocketController`）は Gate 2（FE）向けの規定で、Gate 3 の E2E には対応する規定がない。
  3. なぜ現状の仕組みで不十分か: E2E の作成者が HTTP だけをスタブし、WS を見落とした（REQ-372 の spec で発生、REQ-395 で修正）。
  4. なぜこのアプローチを採用するか: 規定を明示すれば、設計時・QA 時に確認できる基準になる。
  5. 根本原因: Gate 3 のネットワーク隔離の要件が SSoT に書かれていない。
