### REQ-288: WebSocket基盤導入およびPCリソース監視機能

- **Type**: Feature / Architecture
- **Status**: done (2026-09-26)
- **Current step**: none
- **Priority**: P2
- **Surface**:
  - ComfyUI と連携した画像生成実行時に GPU（AMD Radeon RX 9070 XT）、VRAM、RAM、CPU に集中的な負荷がかかるが、UI 上でリアルタイム消費状況を可視化する機能がなく、VRAM 逼迫による生成クラッシュ（Out of Memory）や過負荷の予兆を把握できない。
  - バックエンドからフロントエンドへの非同期プッシュ基盤が存在せず、今後の複数枚スナップショット一括保存やローカル LLM バッチ進捗通知に対応できない。
- **Root Cause**:
  - **Architecture & System Design**:
    - アプリ本体（FastAPI ⇔ React）間の低負荷かつ常時接続可能な双方向イベント通信基盤（WebSocket）が未構築。
    - ハードウェアメトリクス（psutil / ROCm SMI）を非同期サンプリングしてブロードキャストするサービス機構の欠如。
- **Requirement**:
  - FastAPI 側に汎用 WebSocket イベントバス基盤（`/api/ws`）を新設し、2.5 秒間隔でハードウェアメトリクス（CPU/RAM/GPU/VRAM）を Discriminated Union 形式（`SYSTEM_STATS`）で配信すること。
  - フロントエンドに自動再接続（指数バックオフ対応）および Zustand 連携フックを導入し、デスクトップ（プレビューエリア右上 HUD）およびモバイル（2段目サブヘッダーチップ）にレスポンシブなリソースゲージウィジェットを表示すること。
  - リソース使用率 85% / 95% 超過時の段階的警告カラー遷移、AMD SMI 取得不可時のフォールバック（GPU 項目 null 応答）、タブ非アクティブ時（Page Visibility API）の省電力制御を備えること。
  - 画像生成本体（ComfyUI port 8188 への直結接続）には影響を与えない疎結合設計を維持すること。
- **Acceptance criteria**:
  - [x] AC-1 (WebSocket 接続確立 & 自動再接続): フロントエンド起動時、FastAPI の `/api/ws` へ自動接続され、接続状態が Zustand に反映されること。サーバー再起動や一時切断時は指数バックオフ（1s, 2s, 4s, 最大10s）で自動再接続を試行すること。
  - [x] AC-2 (メトリクス取得正確性 & フォールバック): CPU、システム RAM（使用量/総量/比率）、GPU 使用率、VRAM（使用量/総量/比率）が正しくパースされ、2.5 秒間隔でブロードキャストされること。AMD SMI 取得不可環境では GPU 項目が null となり、UI 上で `--` 表示になること。
  - [x] AC-3 (画面別レイアウト適合 & 警告カラー): デスクトップではプレビューエリア右上/コントロールバーの半透明 HUD（`bg-[#18181C]/80 backdrop-blur`）として、モバイルでは 2 段目ヘッダーのチップとして適切に表示され、85% 超過時に警告カラー（黄）、95% 超過時に危険カラー（赤）へ滑らかに遷移すること。
  - [x] AC-4 (タブ非アクティブ時省電力制御): `document.visibilityState === 'hidden'` の際、無駄な再レンダリングやキュー滞留が発生しないこと。アンマウント時に接続・タイマーが正常に破棄され、メモリリークがないこと。
  - [x] AC-5 (型安全性・ビルド検査 Gate 1): `cd frontend && npm run typecheck` (`tsc -b --noEmit`) がエラー 0 件で PASS すること（型検査ゲート）。
  - [x] AC-6 (テスト検証 Gate 2): `pytest backend/tests/test_ws.py` および `cd frontend && npx vitest run` で既存テストを含む全テストスイートが PASS すること。
