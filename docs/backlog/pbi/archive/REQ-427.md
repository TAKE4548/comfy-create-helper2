### REQ-427: 参照画像（ref画像）入力型・汎用ロールおよび画像選択UIの追加

- **Type**: feature
- **Priority**: P2
- **Surface**: Generate (`ParamPanel`), Settings (`MappingMaster`)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: AnimaRefAdapter や Openpose などの参照画像（ref 画像）を用いるワークフローで、アプリ上から参照画像を指定・差し替えられるようにするため。
  2. なぜその課題が発生するか: 現在のパラメータ入力型（`input_type`）はテキストや数値・選択肢・Seed・LoRAスタック等に限定されており、画像を受け取る型・ロール・入力UIが存在しないため。
  3. なぜ現状の仕組みで不十分か: 画像入力欄がないため、参照画像を変更するたびに ComfyUI 側でワークフローを直接編集して再登録する必要があり、プリセットや生成履歴・Multi-Set と連動した運用ができないため。
  4. なぜこのアプローチを採用するか: 標準の `input_type` として `image` を追加し、`LoadImage` 系ノードを対象とした汎用ロール（`MappingMaster` / `RuleSet`）と、生成履歴・スナップショット選択および直接アップロード／D&D／ペーストに対応した画像入力UIを提供するため。
  5. 根本原因: ワークフローマッピングの標準入力型および初期マスタに「画像入力（`image`）」が定義されておらず、Generate 画面・プリセット・ComfyUI 投入経路が画像パラメータを扱えないこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 標準 `input_type: 'image'` の定義、および汎用参照画像ロール（`ref_image` 相当）と `LoadImage` 系ノード検出ルールの定義
  - **Interaction (インタラクション)**:
    - 生成履歴・スナップショットからの画像選択、ファイル選択による直接アップロード、ドラッグ＆ドロップ、クリップボード貼り付けによる画像指定、およびプリセット・Multi-Set・履歴再現・無効化との連動
  - **Visual (視覚デザイン)**:
    - パラメータ入力パネル（Desktop / Mobile）における画像入力欄と選択中画像のサムネイルプレビュー表示
- **Requirement**:
  - **1. 標準 `input_type: 'image'` の追加**:
    - `seed` と同様に、`ParamTypeMaster.widget_type` ではなく標準の `input_type` として `'image'` を追加し、Settings の MappingMaster 作成・編集画面および API で選択・保存可能にする。
  - **2. 汎用参照画像ロールと `LoadImage` 系判定ルールの初期定義**:
    - 汎用参照画像用の `MappingMaster`（例: `base_key: 'ref_image'`, `input_type: 'image'`）および `LoadImage` 系ノード（`class_type: 'LoadImage'` かつ `param_name: 'image'` 等）を検出対象とする初期 `RuleSet` / `MappingVariant` を追加し、新規登録・再スキャン時に推奨候補として検出・マッピング可能にする。
  - **3. 画像入力欄・プレビューUI（履歴/スナップショット選択・アップロード・D&D・ペースト）**:
    - 有効な `input_type === 'image'` マッピングに対し、Generate 画面のパラメータ入力パネル（Desktop / Mobile）に入力欄と選択中画像のサムネイルプレビューを表示する。
    - メイン導線として生成履歴・スナップショットから画像を選択できるほか、端末からの直接アップロード、ドラッグ＆ドロップ、クリップボード貼り付け（ペースト）にも対応する。クリアボタンは必須としない。
    - 非画像ファイルの指定やアップロード失敗時は UI 上にエラー通知を表示し、既に設定されていた有効な画像値およびサムネイルプレビューを変更せず保持する。
  - **4. 生成実行時の画像供給・プリセット/履歴/無効化連動**:
    - 生成実行時、指定された画像をバックエンド経由で ComfyUI 側へ供給（ComfyUI の画像入力として参照可能な状態へアップロード／配置）し、生成用ワークフロー JSON の該当ノード入力へ ComfyUI 側の参照ファイル名を注入して投入する。画像が未指定の場合は該当ノード入力を上書きせず、元のワークフロー JSON の値のまま投入する。
    - プリセット保存・Multi-Set・生成履歴からの再現・ワークフロー個別無効化（`mapping_slot_states`）およびマスタ側バリアント無効化（`is_enabled === false`）の対象に含める。
  - **5. 未参照画像の自動クリーンアップ（AC-9）**: アプリ側に保持する参照画像ストアは、未参照かつ猶予期間経過後の画像を定期的に自動削除し、肥大化を防ぐ。
  - **6. プロファイル一括編集での画像適用（AC-10）**: 一括編集でも `image` 型を通常入力同様のプレビュー付き選択で扱い、同一画像を複数プリセットへ適用できる。
- **Acceptance criteria**:
  - [ ] AC-1: Given Settings の MappingMaster 作成または編集画面を開いている状態, When 入力型（`input_type`）の選択肢を確認し `'image'` を選んで保存する, Then 標準 `input_type: 'image'` が `ParamTypeMaster` とは独立した標準型として選択・保存でき、再読み込み後も保持されること。
  - [ ] AC-2: Given `LoadImage` 系ノード（例: `class_type: 'LoadImage'`, `param_name: 'image'`）を含むワークフローを新規登録または再スキャンする, When 初期定義された汎用参照画像ロール（`ref_image` 等、`input_type: 'image'`）の候補判定を実行する, Then 該当 `LoadImage` 系ノードが推奨候補として提示され、マッピングとして割り当て・保存できること。
  - [ ] AC-3: Given 有効な `input_type === 'image'` マッピングを持つワークフローが選択されている Generate 画面（Desktop および Mobile）, When パラメータ入力パネルを表示する, Then 該当マッピングのラベル・画像入力欄および現在選択中の画像サムネイルプレビューが表示され、UI 6大ハード不変条件（44×44px 以上の操作領域、モバイル幅での横はみ出しなし等）を満たすこと。
  - [ ] AC-4: Given 画像入力欄が表示されている状態, When 生成履歴・スナップショットからの画像選択操作を開き、任意の既存画像を選択する, Then 選択した画像が該当マッピングの値として設定され、サムネイルプレビューが即時更新されること。
  - [ ] AC-5: Given 画像入力欄が表示されている状態, When 端末からのファイル選択アップロード、ドラッグ＆ドロップ、またはクリップボードからの画像貼り付け（ペースト）を実行する, Then 画像がアップロード・登録されて該当マッピングの値とサムネイルプレビューが更新され、非画像ファイルやアップロード失敗時はエラーが通知されて既存の有効な設定値が保持されること。
  - [ ] AC-6: Given `input_type === 'image'` マッピングに画像が指定された状態, When 画像生成を実行する, Then バックエンドが対象画像を ComfyUI 側へ供給したうえで生成用ワークフロー JSON の対象ノード入力へ ComfyUI 側の参照ファイル名を注入して投入すること。また、画像が未指定（空）の場合は該当ノード入力を上書きせず元のワークフロー JSON の値のまま投入できること。
  - [ ] AC-7: Given `input_type === 'image'` マッピングが存在し、かつワークフロー固有の無効化（`mapping_slot_states` が `false`）またはマスタ側バリアント無効化（`is_enabled === false`）が行われている状態, When Generate 画面の表示および画像生成実行を行う, Then パラメータ入力パネルに入力欄は表示されず、生成用ワークフロー JSON への画像注入も行われないこと。また、DB 上のマッピング定義は保持され、再有効化するとパラメータ入力パネルへの入力欄再表示および注入対象への復帰が行われること。
  - [ ] AC-8: Given `input_type === 'image'` マッピングに画像が指定された状態, When ワークフロープリセットの保存・切替、Multi-Set での管理、および生成履歴スナップショットからのパラメータ復元を実行する, Then 指定されていた画像情報とサムネイルプレビューが他パラメータと同様に保存・復元されること。
  - [ ] AC-9: Given 参照画像ストアに、どのプリセット・Multi-Set・生成履歴・スナップショット・ワークフロー定義・ジョブからも参照されておらず、かつ猶予期間（設計: 72時間）を過ぎた画像がある状態, When 定期クリーンアップ（設計: 起動後および6時間周期）が実行される, Then それらの未参照画像が自動削除され、参照中の画像および猶予期間内の画像は削除されないこと。また、参照の走査が一部でも失敗した場合は削除を一切行わないこと。
  - [ ] AC-10: Given Settings のプロファイル一括編集で複数プリセットを選択し、`input_type === 'image'` のロールが表示されている状態, When サムネイルプレビュー付きで履歴・スナップショット選択またはアップロード等により画像を選び、一括適用を実行する, Then 選択中の全プリセットの該当ロールへ同一の画像が適用されること。画像が未選択のロールは各プリセットの既存値を変更しないこと。
- **Inferred points**:
  - 汎用ロールの初期 `base_key` は `ref_image`（または同等の汎用識別子）とし、用途別に複数ロールが必要な場合は Settings の MappingMaster 追加で同じ `input_type: 'image'` を割り当てて増やせる運用を前提とする。
  - クリア（未指定へ戻す）操作は必須要件としない（AC 対象外）。
  - 画像値の保存形式（アプリ内画像識別子やメタデータ構造等）の詳細は設計フェーズで既存のアセット／履歴／プリセット仕様と整合する形で決定する。
