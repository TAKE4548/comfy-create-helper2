### REQ-426: ワークフロー複製時の 500 Internal Server Error（step_035 マイグレーション失敗による param_sync_groups.master_variant_id 欠落）

- **Type**: bug
- **Priority**: P1
- **Triage Classification**: Type B: Specification Gap
- **Incident Report**: docs/incident_report_20261113_workflow_copy_500.md
- **Surface**: backend/app/migrations/steps.py, backend/app/main.py, backend/app/models.py, backend/app/routers/workflows.py
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: ワークフロー複製保存（`POST /api/workflows/75/copy`）時に `sqlite3.OperationalError: no such column: param_sync_groups.master_variant_id` で HTTP 500（`request_id: req-ba3208fb2b9f`）が発生するため。
  2. なぜその課題が発生するか: 起動時マイグレーション `step_035_variant_id_references`（`backend/app/migrations/steps.py:1284-1389`）が `audit_role_references()` で未解決 `role` キー（ゴーストキー）を検出して `ValueError` を送出し、トランザクション全体をロールバックしているため。
  3. なぜ現状の仕組みで不十分か: 実 DB（`db/prompt_surgeon.db`）の `workflow_presets` / `param_sync_groups` に旧/未登録キーが残存している場合、毎回 `step_035` が失敗し、`param_sync_groups.master_variant_id` 列が追加されない。さらに `backend/app/main.py:63-66` がマイグレーション例外を握りつぶしてサーバ起動を続行するため、ORM と実 DB スキーマの不整合状態で稼働してしまう。
  4. なぜこのアプローチを採用するか: REQ-418 仕様で未定義だった既存 DB ゴーストキーの救済・クリーンアップ方針およびマイグレーション失敗時の起動制御を SSoT レベルで補完・実装するため。
  5. 根本原因: REQ-418 のマイグレーション仕様における既存データ（ゴーストキー）救済方針の欠落、および `main.py` lifespan におけるマイグレーション失敗時の起動継続。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 既存の有効なプリセット・同期グループ設定を保持しつつ未解決キーの扱いを明確化。
  - **Interaction (インタラクション)**:
    - ワークフロー複製保存が 500 エラーにならず正常完了すること。
  - **Visual (視覚デザイン)**:
    - 変更なし。
- **Requirement**:
  - **1. `step_035_variant_id_references` の未解決キー救済（案 A: 警告ログ＋スキップ）**:
    - `mapping_variants` テーブルまたは `role` 列が存在しない場合は引き続きエラー中断・ロールバックする。
    - `workflow_presets` および `param_sync_groups` に未解決 `role` キー（ゴーストキー）が存在する場合でも、`ValueError` で全体ロールバックせず、未解決キーを `logger.warning` に記録してスキップし、解決可能なキーの正規化テーブル移行と `param_sync_groups.master_variant_id` 列追加を完了させる。
  - **2. ワークフロー複製 (`copy_workflow`) の安全動作**:
    - `master_variant_id` が `None` または一部メンバーが未移行の `ParamSyncGroup` を含むワークフローを複製してもエラーにならず正常に複製保存（201 Created）できること。
  - **3. 起動時マイグレーション失敗時のフェイルファスト**:
    - `backend/app/main.py` の `lifespan` で `run_migrations()` が失敗した場合に例外を握りつぶして不整合状態のまま起動継続しないようにする。
- **Acceptance criteria**:
  - [ ] AC-1: Given `workflow_presets` または `param_sync_groups` に `mapping_variants` に存在しない未解決 `role` キー（ゴーストキー）と解決可能な `role` キーが混在する DB 状態, When `step_035_variant_id_references` を実行したとき, Then 未解決キーについて警告ログ（`logger.warning`）が出力された上で処理は中断・ロールバックされず、`param_sync_groups.master_variant_id` 列の追加および解決可能なキーの `workflow_preset_values` / `param_sync_group_members` への移行が完了し、再実行しても冪等であること（なお `mapping_variants` 欠如時は引き続き中断・ロールバックすること）
  - [ ] AC-2: Given `param_sync_groups`（`master_variant_id` が設定済みまたは `None` の双方）を持つワークフローが存在する状態, When `POST /api/workflows/{workflow_id}/copy` を実行したとき, Then 500 エラーにならず 201 Created で複製が保存され、同期グループおよびメンバーが複製先に引き継がれること
  - [ ] AC-3: Given `lifespan` 起動時に `run_migrations()` が例外を送出する状態, When FastAPI アプリケーションを起動したとき, Then 例外を握りつぶして起動継続せずエラーログ出力後に例外を再送出して起動を停止すること
- **Inferred points**:
  - `REQ-418` の AC-1「未解決行が存在する場合はロールバック」は本 PBI（REQ-426）により「`mapping_variants` 欠如時は中断ロールバック、データ内の未解決ゴーストキーは警告ログ出力のうえスキップしてスキーマ移行を完了する」仕様へ上書きされる。
  - `workflow_presets.param_values` の未解決キーは `step_035` で警告ログ出力後に除外し、`norm.reserved`（`__` 予約キー）のみ残すことで再実行時の冪等性を保つ。
