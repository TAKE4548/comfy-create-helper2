### REQ-308: REQ-303回帰修正: プロンプト区切りの適用範囲とサブメニュー編集時の末尾ドット保持

- **Status**: done (2026-10-02)
- **Description**: REQ-303の区切り変換をプロンプト入力欄のタグチップに限定し、タグチップのサブメニュー入力欄で末尾ドットを削除するとカンマ区切りへ戻るよう修正する。ユーザーが調査結果を承認して開発開始を指示済み。
- **Incident Reports**: [パラメータへの波及（Type A）](../../../incident_report_REQ-303-parameters.md)、[サブメニュー編集と仕様衝突（Type B）](../../../incident_report.md)
- **Confirmed Scope**: テキストモードとタグチップのダブルクリック編集では再付与が発生しない。サブメニュー入力欄での編集で発生する。

#### Acceptance Criteria (AC)
- [ ] AC-1: Given Animaモードでドットを含むcheckpoint・LoRA等の非プロンプト値がある、When プリセットを読み込み・一括更新・生成する、Then 値が元のまま保持され、タグ区切り変換の影響を受けない。
- [ ] AC-2: Given 末尾ドット付きのプロンプトタグチップがある、When サブメニュー入力欄でドットを削除して確定する、Then ドットは再付与されず、後続タグとの結合がカンマ区切りとなる。
- [ ] AC-3: Given ドット有無が異なるプロンプトタグチップがある、When 単語編集・強度変更・保存再読込を行う、Then 編集後の明示的な末尾ドット有無に従って区切りが決まり、Animaモードだけを理由にドットを追加しない。
- [ ] AC-4: Given テキストモード・ダブルクリック編集・非Animaモードを使う、When 編集と文字列化を行う、Then 既存の正しい動作を保持する。
- [ ] AC-5: REQ-303、REQ-306と関連SSoTのドット自動付与仕様を上記の挙動へ整合し、今回の失敗経路を検出する回帰テストを追加する。
