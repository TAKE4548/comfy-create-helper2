### REQ-176: セリフプリセット一覧の区分・ソート・検索フィルタ機能および表示設定の永続化

- **Type**: enhancement
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**: セリフのプリセット数が増加した際に、目的のプリセットを素早く探し出し・アクセスできるようにしたい。
  - テキスト付きとテキストなしを明確に区分し、それぞれ折り畳み可能にする。
  - 表示順序をソート可能にする（名前順・登録順の昇順/降順、デフォルトは名前の昇順）。
  - 自由テキストでの名前検索、および縦書き・横書き種別でのフィルタ機能を設ける。
  - 上記設定を `localStorage` で永続化し、別画像編集時等にも設定を引き継ぐ。
- **Root Cause**:
  1. **Information Design（情報設計）**: テキスト付きプリセットとテキストなし（スタイルのみ）プリセットが混在し、縦書き/横書き種別や名称による絞り込み・並び替え機構がないため、プリセット数増加に伴い目的の項目を見つける認知的・操作的コストが増大している。
  2. **Interaction（インタラクション & 継続性）**: セクション開閉や検索・ソート等の表示状態が保持されず、別の画像や吹き出しの編集時に毎回初期状態に戻ってしまう。
- **Requirement**:
  1. **区分と折り畳み**: プリセット一覧を「テキスト付き」と「テキストなし（スタイル専用）」の2区分に明確に分離表示し、各セクションを個別に折り畳み／展開可能にする。
  2. **ソート機能**: 「名前順（昇順/降順）」「登録順（昇順/降順）」の並び替え機能を提供し、デフォルトは「名前の昇順」とする。
  3. **検索・フィルタ機能**: 自由テキストによる名前のインクリメンタル検索機能、および「縦書き / 横書き / すべて」の種別フィルタを提供する。
  4. **表示状態の永続化**: ソート設定、フィルタ条件、セクション開閉状態を `localStorage` に保存し、セッションや別画像編集時にも状態を復元・維持する。
- **Acceptance criteria**:
  - AC-1: プリセット一覧が「テキスト付きプリセット」と「テキストなし（スタイルのみ）プリセット」の2セクションに明確に区分されて表示され、各セクションが独立して折り畳み/展開できること。
  - AC-2: ソート条件として「名前順（昇順・降順）」「登録日時順（昇順・降順）」が選択可能であり、デフォルト表示が「名前の昇順」となること。
  - AC-3: テキスト入力による名前検索により、合致するプリセットのみがリアルタイムに絞り込み表示されること。
  - AC-4: 縦書き／横書き種別によるフィルタ（すべて / 縦書き / 横書き）が機能し、指定種別のプリセットのみが表示されること。
  - AC-5: ユーザーが設定したソート順、フィルタ条件（検索クエリ・縦横種別）、各セクションの折り畳み状態が `localStorage` に保存され、モーダル再表示時や別画像の編集時にも引き継がれること。
- **Design doc**: none
