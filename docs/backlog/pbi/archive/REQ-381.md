### REQ-381: モバイルSettings：レイアウト密度改善・ノード管理サブメニュー・説明info化・保存方式整理

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: モバイルSettings（幅767px以下、特に375px級）の全5タブ（ワークフロー・モデル、プロンプト支援、セリフ支援、翻訳、システム・一般）。`frontend/src/pages/SettingsPage/` 配下の各コンポーネントおよびモーダル（`ParamTypeMasterManagerModal`、`StageManagerModal`、`SpeechTonePresetModal` 等）、`docs/specs/SPEC_SETTINGS.md`
- **Reference**:
  - docs/specs/SPEC_SETTINGS.md（§2 機能一覧、§3 画面仕様）
  - docs/specs/SPEC_COMMON.md（§1-3 共通UIルール、§1-4 共通モーダル、§1-6 モバイル共通規約 MUI-02/03/04/06/07/08/10、§2-4 ボトムナビ）
  - docs/design/mobile-ui-redesign/mobile-common-ui-redesign-proposal.md（§9.1 補足説明とinfo、§9.2 保存操作と結果のフィードバック、§9.3 横スワイプとスクロールの競合）
  - 先行PBI: REQ-378（共通規約）、REQ-380（Settings systemタブへのVRAM解放導線）、REQ-367/368（Modal・Settingsタブ保持）、REQ-348/349/351（Settings各種機能）
  - 比較モック: Baseline `https://take4548.github.io/comfy-create-helper2/settings?ui=baseline` ／ Proposal `https://take4548.github.io/comfy-create-helper2/settings?ui=proposal`（prototype/ui-review の ui-prototype/）
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: モバイルSettings画面で外周余白やカード間隔が過剰に広く、長い見出し・説明文・操作ボタンが横一列で競合してはみ出しや改行崩れが発生し、大量の補足説明文が画面を圧迫しているため。
  2. なぜその課題が発生するか: デスクトップ前提のカード余白や1行複数ボタンスタイルがモバイル幅にそのまま適用されており、補足説明も常時インライン展開されていたため。
  3. なぜ現状の仕組みで不十分か: 375px級の狭小画面でノードマッピングマスタの「Add Master」と「ステージ管理」「カスタム型マスタ」が競合して押しづらく、またオートセーブ対象と明示保存対象のUI上の区別が曖昧で保存状態フィードバックが過剰または不足するため。
  4. なぜこのアプローチを採用するか: モックレビュー（2026-10-18）で合意された方針に基づき、余白の最小化、「管理 ⋯」サブメニュー分離、詳細説明のインライン ⓘ ポップオーバー化、保存方式の3分類整理（即時／確定後／明示）、カテゴリ間横スワイプ移動を採用することで、既存の5分類・機能・配色を損なわずに操作性と可読性を最大化できるため。
  5. 根本原因: モバイル表示における情報階層（常時表示すべき情報と参照時情報）およびボタン階層・保存モデルの明確なモバイルUI仕様が未定義であったこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 設定カテゴリ5分割と全設定項目を維持。
    - Node Mapping Mastersの主操作（`Add Master`）と管理系（`ステージ管理`、`カスタム型マスタ`）を「管理 ⋯」サブメニューへ整理。
    - 明白な重複説明を削減し、画像処理パラメータ等の詳細説明のみを ⓘ ポップオーバーへ退避。
    - 保存規則を「即時オートセーブ」「入力確定後オートセーブ」「明示保存／適用」に3分類し、通常時の過剰な「保存済み」文言を排除。
  - **Interaction (インタラクション)**:
    - 5カテゴリタブ間の左右スワイプ切替（縦スクロール優先、スライダー・入力・シート・独立スクロールとの競合防止）。
    - ⓘ アイコンのタップによるポップオーバー表示、再タップ／外側タップ／Escape／スクロールによる閉じる動作。
    - 口調プリセット用ボトムシートのキャンセル（左）／保存（右）の配置維持。
  - **Visual (視覚デザイン)**:
    - 幅375px級でのカード外周余白・間隔の適正化（横スクロールや重なりの完全排除）。
    - ⓘ ポップオーバーの不透明ダーク背景と十分な文字コントラストの確保（画面端・カード枠外でのクリップ防止）。
    - 保存中／成功／失敗／未保存状態の控えめで矛盾のない視覚フィードバック。
- **Requirement**:
  - **1. 設定カテゴリ・機能の維持と密度改善**:
    - 5カテゴリ（ワークフロー・モデル、プロンプト支援、セリフ支援、翻訳、システム・一般）の分類、直接タップ、全設定項目を維持する。
    - モバイル（幅767px以下、特に375px級）での外周余白・カード間隔を縮小し、横スクロール・要素の重なり・見切れを発生させない。
  - **2. Node Mapping Masters ヘッダーとサブメニュー整理**:
    - タイトル視認性を確保し、「Add Master」を直接表示する主操作とする。
    - 「ステージ管理」「カスタム型マスタ」を「管理 ⋯」サブメニュー内に集約し、ボタン間の競合やコンテナ幅超過を解消する。
    - サブメニュー展開時も必要な領域内で読め、各操作先へ遷移可能とする。
  - **3. 補足説明の整理と ⓘ ポップオーバー化**:
    - 単なる見出しの言い換え・重複説明を削減する（一律のinfo化は行わない）。
    - 詳細なパラメータ説明（画像処理フィルタ等）は、見出し・ラベルと同一行にインライン配置した控えめな ⓘ アイコンからポップオーバー表示する。
    - ポップオーバーは不透明ダーク背景・高コントラストとし、画面端やカード枠外でクリップされず、内容が長い場合は内部スクロール可能とする。
    - 警告・エラー・保存状態等の重要情報は ⓘ に隠さず常時視認可能とする。
  - **4. 保存方式の3分類と状態フィードバックの整理**:
    - 即時オートセーブ（スイッチ、モデル選択、表示比率等）、入力確定後オートセーブ（LLMパラメータ、画像フィルタ、VRAMガード閾値等）、明示保存（LLMシステムプロンプト、翻訳認証情報、ワークフロー一括適用、口調プリセット等）の分類を明確化する。
    - オートセーブ項目の不要な個別保存ボタンを排除する。
    - 通常時は過剰な保存状態文言を常設せず、エラーや未保存は明瞭に残す。保存失敗時に「保存済み」と誤表示しない。
  - **5. カテゴリ間横スワイプとレスポンシブ操作性**:
    - 設定カテゴリ間の左右スワイプ切替をサポートする（縦スクロール優先判定、スライダー・入力・シート・独立スクロールとの競合防止）。
    - 口調プリセットボトムシートの「キャンセル左／保存右」を維持し、画面幅内・キーボード表示時もはみ出さず操作可能とする。
    - 最小44×44pxの有効タップ領域とフォーカス視認性を保つ。
  - **6. 先行PBI・デスクトップとの整合**:
    - 先行PBI（REQ-380）のComfyUIメモリ解放導線を含むシステムタブのレイアウトを破綻させない。
    - デスクトップ表示（幅768px以上）には本改修の影響を波及させず、既存の表示・操作性を維持する。
- **Acceptance criteria**:
  - [ ] AC-1: Given モバイル表示（幅767px以下、375px級を含む）のSettings画面, When 画面を開く, Then 5カテゴリ（ワークフロー・モデル、プロンプト支援、セリフ支援、翻訳、システム・一般）のタブが表示され、Baselineの既存設定値と操作項目が維持されていること。
  - [ ] AC-2: Given 幅375pxのモバイル画面, When Settingsの各カテゴリを閲覧する, Then 設定カードの外周余白・カード間隔が縮小されて情報密度が向上し、横スクロールの発生やコンテンツの重なり・見切れが生じないこと。
  - [ ] AC-3: Given 「ワークフロー・モデル」タブの Node Mapping Masters セクション, When モバイル画面でヘッダーを表示する, Then タイトルが識別可能であり、「Add Master」ボタンが主操作として直接表示され、「ステージ管理」「カスタム型マスタ」は「管理 ⋯」サブメニュー内に配置され、ボタン同士が重ならずコンテナ幅を超えないこと。
  - [ ] AC-4: Given 「管理 ⋯」サブメニュー, When サブメニューを開く, Then 「ステージ管理」「カスタム型マスタ」の各項目が画面内で視認・タップでき、それぞれのモーダル（StageManagerModal、ParamTypeMasterManagerModal）が従来どおり開くこと。
  - [ ] AC-5: Given 詳細説明を要するパラメータ（画像処理フィルタの詳細パラメータ、フキダシ検出パラメータ、翻訳待ち時間デバウンス等）の見出し・ラベル, When モバイル画面で表示する, Then 明白な重複説明が削減され、当該パラメータの見出し・ラベルと同一行に重なりなく控えめな ⓘ アイコンがインライン配置されること。
  - [ ] AC-6: Given 上記パラメータの ⓘ アイコン, When ユーザーがアイコンをタップする, Then 不透明なダーク背景と十分なコントラストを持つポップオーバーでパラメータの効果・条件・詳細説明の全文が表示され、カード枠外や画面端でクリップされず、再タップ・外側タップ・Escape・スクロール契機で閉じられること。
  - [ ] AC-7: Given オートセーブ対象の設定群（即時オートセーブ: スイッチON/OFF、サムネイル表示比率、モデル選択、長押し判定時間等 / 入力確定後オートセーブ: LLMパラメータ、画像処理フィルタ閾値、VRAM安全ガード閾値、翻訳デバウンス等）, When モバイル画面で確認・操作する, Then 個別の不要な保存ボタンが排除され、変更操作または入力確定により保存が行われるUI表現であること（常時「保存済み」文言を過剰表示せず、エラー時は未保存／失敗を明確に示すこと）。
  - [ ] AC-8: Given 明示保存が必要な設定群（長文LLMシステムプロンプト、翻訳サービス認証・APIキー設定、ワークフロー設定一括適用、口調プリセット新規作成・編集等）, When 該当設定カードを開く, Then 操作領域末尾または適切なヘッダーに明示的な「保存」「適用」ボタンが維持され、勝手な自動確定が行われないこと。
  - [ ] AC-9: Given Settingsの本文領域, When ユーザーが意図的な左右スワイプ操作を行う, Then 隣接する設定カテゴリタブへ切り替わり、縦スクロール・スライダー操作・テキスト入力・シート表示が妨げられないこと。
  - [ ] AC-10: Given セリフ支援タブの口調プリセットの編集・新規作成, When モバイル画面で開く, Then モバイル用ボトムシート（SpeechTonePresetModal）が画面幅内に収まり、左に「キャンセル」、右に「保存」の操作配置が維持され、ソフトキーボード表示中もはみ出さず操作できること。
  - [ ] AC-11: Given 先行PBI（REQ-380）で追加される system タブの ComfyUI サービス管理行（死活ランプ・ログ展開・「メモリ解放」ボタン導線）, When モバイル画面で表示する, Then レイアウト崩れやボタンの重なりを生じることなく、十分なタップ領域（最小44×44px）で視認・操作できること。
  - [ ] AC-12: Given 幅768px以上のデスクトップ表示, When Settings画面を開く, Then 既存のデスクトップ向けレイアウトと操作性が維持され、不要な回帰やデザイン崩れが発生しないこと。
- **Inferred points**:
  - 先行PBI REQ-378（SPEC_COMMON モバイル規約）の MUI-02〜MUI-10 に準拠する。
  - 先行PBI REQ-380（Settings systemタブへのVRAM解放導線）と競合しないよう、systemタブのカード密度調整時に該当要素のレイアウトを考慮する。
  - 先行PBI REQ-367（Modal focus/Escape）、REQ-368（Settingsタブ保持）、REQ-348/349/351（マスタ・パラメータ設定）の契約を維持する。
  - 本PBIはモックレビューで合意されたUI/UX要件の起票であり、オートセーブの実通信デバウンスやAPIトランザクションの詳細技術設計は後続のdev-designフェーズで策定する。
