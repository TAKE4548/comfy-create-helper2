### REQ-158: FEキャッシュ設計の最適化：冗長なBEアクセスの削減とレスポンス向上

- **Type**: enhancement
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**: 画像保存時のアルバム名表示ラグ（IDはキャッシュされているが名称取得にBEアクセスが必要）を筆頭に、FEが同一セッション内で不要なBEアクセスを繰り返している箇所が複数存在する。これによりUIの応答性が低下し、モーダル・ページ切替時に視認できるフリッカー・ラグが発生している。
- **Root Cause**:
  1. **React Queryバイパス**: 複数コンポーネントが `useQuery` を使わず `useEffect + raw fetch` で直接APIを呼び出しており、既存のReact Queryキャッシュを無視して重複HTTPリクエストが発生している。
  2. **staleTime 過小設定**: グローバルデフォルト `staleTime: 30,000ms`（30秒）が、事実上不変なデータ（フォント、ベースモデル、カテゴリ、LLMプロンプト設定等）に対しても適用されており、不必要な再フェッチが頻発している。
  3. **アルバム名マッピング欠如**: `lastSaveAlbumId`（localStorage）でアルバムIDはキャッシュしているが、ID→アルバム名のマッピングが保持されておらず、表示時に毎回BEアクセスが必要になる。
  4. **ワークフロー別データのキャッシュ欠如**: `bypassProfiles` / `paramSyncGroups` がZustandで配列保持のみで、ワークフロー切替時に前のワークフローのデータが破棄され、同一ワークフローに戻った際に再フェッチが発生する。
- **Requirement**:
  1. アルバムID→アルバム名のマッピングテーブルをFE側で保持し、アルバム名の即時表示を実現する。適切なタイミング（ページロード、アルバム作成・編集・並び替え後）でBEと同期する。
  2. React Queryをバイパスしている全コンポーネントを `useQuery` ベースに統一し、キャッシュの共有・重複排除を徹底する。
  3. 静的・準静的データ（フォント・ベースモデル・カテゴリ・コンフィグ等）の `staleTime` をデータ変化頻度に応じて適切な値に延長する。
  4. `bypassProfiles` / `paramSyncGroups` を `workflowId` をキーとするMap形式でキャッシュし、ワークフロー切替コストを削減する。
  5. `/config` エンドポイントへの重複呼び出し（現状3箇所）を単一の共通Hookに統一する。
