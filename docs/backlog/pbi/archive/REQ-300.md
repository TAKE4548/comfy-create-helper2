### REQ-300: デスクトップ生成画面におけるプリセットタブバーの画面全幅化と操作ボタンの左ペイン集約

- **Type**: improvement
- **Status**: done (2026-10-02)
- **Priority**: P2
- **UX Classification**:
  - **Information Design**: プリセットタブ一覧（SetTabsBar）を左ペイン内から2ペイン（入力・プレビュー）全体の直上へと独立・全幅展開し、プレビュー上部の余剰領域を活用してタブ表示領域を画面幅いっぱいに拡張
  - **Interaction Design**: 「Add Set（セット追加）」および「管理（プリセット管理）」ボタンを全幅タブバーの右端へ追いやらず、入力操作導線である左ペイン上部（Undo/Redoボタン配置エリア）へ近接配置することで、Fitts's Law に基づくマウス移動距離の最小化と操作導線の集約を実現
  - **Visual Design**: 全幅タブバーと直下の左右2ペイン構造の視覚的ヒエラルキーの明確化（下線境界・独立背景）、タブオーバーフロー時の独立横スクロール親和性維持、左ペイン側ツールバーの統一感あるアイコン/ボタングループのスタイリング
- **Surface**:
  - デスクトップ生成画面において、プリセットタブエリアが左ペイン内に押し込められており横幅が狭い。
  - 「Add Set」や「管理」アイコンボタンが同列に存在するため、プリセット名が付いていると大抵2つ程度しか同時にタブが表示できず、一覧性・切替作業性が著しく低下している。
  - 一方で、右カラム（プレビューエリア）の上部は空間を持て余しているため、ヘッダ部を独立させて画面幅いっぱいにタブエリアを拡張できるようにしたい。
  - ただし、「Add Set」と「管理」ボタンが画面右端に行ってしまうとマウス操作の移動距離が長くなり作業効率が悪化するため、Undo/Redoボタンがあるエリアなどの左ペイン側に属するように配置したい。
  - なお、モバイル側は元々ペインの概念がないため、現状維持とする。
- **5 Whys Analysis**:
  1. *Why*: 生成画面のプリセットタブエリアでタブが2つ程度しか見えず狭いと感じるのはなぜか？
     → プリセットタブバーが左ペイン（入力カラム）の幅制約の中に押し込められており、「Add Set」「管理」ボタンとも同一ライン上で幅を取り合っているため。
  2. *Why*: なぜ右側のプレビューエリア上部のスペースが活かされていないのか？
     → デスクトップ画面全体の構造として、上部ヘッダー直下から即座に左右2カラム（左: 入力、右: プレビュー）に分割されており、プリセットタブバーが左カラムの内部要素として閉じて配置されているため。
  3. *Why*: タブエリアを全幅にした場合、なぜ「Add Set」と「管理」ボタンを右端に配置してはいけないのか？
     → プリセットの追加や管理、プロンプト・パラメータ編集、Undo/Redoといった一連の試行錯誤ワークフローはすべて左ペインに集中しており、右端へボタンが移動するとマウス移動距離（Fitts's Law）が増大し、ユーザーの操作導線が大きく分断されるため。
  4. *Why*: モバイル画面は対象外とするのか？
     → モバイルレイアウト（MobileLayout）は元々シングルカラムであり、ペイン分割の概念が存在せず、独立したタブ・操作バーとして成立しているため、デスクトップ専用の構造変更で十分であるため。
  5. *Why*: 根本原因（Root Cause）は何か？
     → 【Information Design】左右2カラム構造の上位レイヤーへのプリセットタブの配置昇格（全幅化）が行われておらず、プレビュー上部空間が活用されていないこと。【Interaction Design】タブ一覧（全幅での一覧性が必要な情報）と操作系アクション（左ペインの操作導線に属すべきトリガーボタン）が構造上密結合していたこと。
- **Structural Blueprint (DesktopLayout)**:
  ```text
  [Desktop Container]
    ├── [Global Header (既存ヘッダー: ワークフロー選択等)]
    ├── [Full-Width Preset Tabs Bar (新規全幅配置)]
    │     └── プリセットタブ一覧（横スクロール可能・画面幅100%活用）
    └── [Dual-Pane Content Area (左右2ペイン)]
          ├── [Left Pane: 入力・設定]
          │     ├── [Left Pane Toolbar: Add Set / 管理 / Undo / Redo]
          │     └── [LLM Audit / Prompts / LoRA / Params...]
          └── [Right Pane: プレビュー・履歴]
                └── [Main Preview / Gallery / Snapshot / Queue...]
  ```
- **Requirement**:
  - デスクトップレイアウト（DesktopLayout）において、プリセットタブバーを左右2カラム（入力/プレビュー）の共通親コンテナ直上（画面幅100%）に配置し、プレビューエリア上部を含めた画面横幅全体にタブ表示領域を拡張すること。
  - プリセット名が長い場合や多数のプリセットが存在する場合でも、全幅を活用してより多くのタブを一度に視認・選択可能とすること。画面幅を超える場合はタブコンテナ固有の横スクロール（overflow-x: auto）によりスムーズに操作可能であること（画面全体の不要なスクロールやガタつきを発生させない）。
  - 「Add Set（セット追加）」ボタンおよび「管理（プリセット管理）」ボタンは、全幅タブバーの右端ではなく、左ペインの上部操作エリア（Undo/Redoボタンが存在するコントロールツールバー）に配置し、左ペインでのパラメータ/プロンプト操作と一元的にアクセス可能とすること。
  - 既存の各タブの選択・アクティブ表示・チェックボックス（一括生成/Multi-Set用）・タブ削除・Undo/Redo機能（アクティブプリセット内の履歴復元）・プリセット管理モーダルの開閉などの機能動作が完全に維持されること。
  - モバイルレイアウト（MobileLayout）のレイアウトおよびタブ・操作部構成は変更せず、現状維持（既存動作担保）とすること。画面幅リサイズ時にも既存ブレークポイントに応じた正常な切り替えが行われること。
- **Acceptance criteria**:
  - [ ] AC-1 (デスクトップにおけるタブバーの画面全幅表示):
    - **Given**: デスクトップ表示（DesktopLayout）でワークフローが選択されている生成画面。
    - **When**: プリセットタブ一覧の表示位置と幅を確認する。
    - **Then**: プリセットタブバーは左ペイン内ではなく、左ペイン（入力）および右ペイン（プレビュー）の両方の直上を横断する全幅（100%幅）として配置・展開され、プレビューエリア上部の横幅領域全体がタブ表示可能領域として活用されている。
  - [ ] AC-2 (複数プリセットの拡張表示とスクロール性):
    - **Given**: 3つ以上の名前付きプリセットが登録されている状態。
    - **When**: デスクトップ生成画面を表示する。
    - **Then**: 従来の左ペイン幅制約時よりも大幅に多くのプリセットタブが横一列に省略や見切れなく表示され、画面幅を超過した場合はタブ領域固有の横スクロール（overflow-x: auto）でスムーズに移動可能である。
  - [ ] AC-3 (「Add Set」「管理」ボタンの左ペイン内ツールバー配置・操作性):
    - **Given**: デスクトップ生成画面が表示されている。
    - **When**: 「Add Set（セット追加）」および「管理（プリセット管理）」ボタンの配置位置を確認する。
    - **Then**: 両ボタンは全幅タブバーの右端ではなく、左ペイン上部のツールバー領域（Undo/Redoボタンと同一または隣接するコントロールエリア）に配置され、左ペインの操作導線内でクリックして新規セット追加およびプリセット管理モーダルの起動が行える。
  - [ ] AC-4 (タブ切り替え・Undo/Redo・一括生成チェック等の機能完全維持):
    - **Given**: 全幅タブバーおよび左ペインツールバーが表示されている状態。
    - **When**: タブのクリックによるプリセット切り替え、チェックボックスによる選択状態の変更、タブ削除、Undo/Redoボタンの押下、「管理」ボタンによるプリセット管理モーダル起動を行う。
    - **Then**: すべての既存操作が意図通り正常に動作し、Undo/Redo操作がアクティブプリセットの状態復元として正しく機能し、データの不整合や自動保存・状態更新の阻害が発生しない。
  - [ ] AC-5 (モバイルレイアウトの現状維持とブレークポイント整合):
    - **Given**: モバイル画面幅（MobileLayout）で生成画面を表示、またはウィンドウ幅をリサイズする。
    - **When**: モバイルのタブ一覧および操作ボタン配置を確認する。
    - **Then**: デスクトップ側の全幅化レイアウト変更の影響を受けず、既存のモバイル専用レイアウト・操作性がそのまま完全に維持され、ブレークポイントに応じた切り替えが破綻なく動作する。
  - [ ] AC-6 (品質検証 - 型安全性とテスト通過):
    - **Given**: 実装完了後のリポジトリ。
    - **When**: cd frontend; npm run typecheck および npm test を実行する。
    - **Then**: 型チェックエラーおよびテスト失敗が0件である。
- **BA Audit Outcome**:
  - Model: qwen3.5-9b-claude-4.6-highiq-thinking-heretic-uncensored (Domain: reasoning)
  - Result: APPROVED WITH CONDITIONS
  - Observations & Mitigations:
    - 構造的階層の明確化: 画面最上部ヘッダー → 全幅プリセットタブバー → 左右2ペインの順序関係を明記。
    - 操作ボタンの認知性: 左ペインツールバー内に「Add Set」「管理」「Undo」「Redo」を集約し、操作導線の近接性とツールチップによる認知性を確保。
    - Undo/Redo対象の整合性: usePresetHistory によるアクティブプリセット内容の復元であり、タブ自体の選択解除等は行われないことを明記。
    - レスポンシブ境界: 既存の画面切り替えブレークポイントを順守し、リサイズ時にも表示崩れが発生しないことをAC-5に明記。
