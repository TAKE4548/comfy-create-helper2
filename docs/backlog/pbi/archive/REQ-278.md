### REQ-278: プリセット生成パラメータ未反映の根本原因解消と対症療法コードのクリーンアップ

- **Type**: defect
- **Status**: done (2026-09-19)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - 生成画面（Generate ページ）においてステップ数、CFG、解像度、LoRA などの各種生成パラメータを変更した後、ブラウザをリロード（F5）せずに生成を実行すると、変更前の古いパラメータ値のまま ComfyUI にキュー投入される。
  - プロンプト入力欄（`promptChips`）で変更したテキストはリロードなしでも即座に生成に反映されるが、パラメータのみが反映されない。
  - ブラウザを F5 リロードした直後は最新パラメータで正常に生成されるが、リロード後に再度弄ると再発する。
  - REQ-276 / REQ-277 での改修において、上流（`usePresetState`）のインメモリ上書き破壊が放置され、下流（`useGenerateAction`）に対症療法的なパッチが継ぎ足されていた。
- **Root Cause**:
  - **根本原因 1: `usePresetState.ts` の `rawMappedSets` によるインメモリ編集値の上書き破棄**:
    - `usePresetState.ts` (L827–L844) の `rawMappedSets` 生成時、`promptChips` は `existingSet?.promptChips` から既存インメモリ値を保持している一方、`paramValues` は `existingSet` のローカル編集値を無視してサーバー DB の旧値（`p.param_values`）で強制上書きしている。これによりオートセーブ完了後の React Query 再同期やポーリング契機でインメモリのセットが旧値で破壊されていた。
  - **根本原因 2: `usePresetState.ts` メイン Effect における `activeSetId` 解決フォールバックの片手落ち**:
    - `flushAutoSave` には「単一セット利用時（`sets.length === 1`）に `activeSetId` が未確定ならそのセットをアクティブとみなす」保護が追加されていたが、メインの `useEffect` (L817) には同様の保護がなく、`currentActiveSetId` が `null` のまま `rawMappedSets` による一括上書きが実行されていた。
  - **根本原因 3: 下流（`useGenerateAction.ts`）への対症療法パッチ混入による設計の歪み**:
    - 上流のインメモリ破壊を放置した結果、下流の `handleGenerateSets` において `checkedSets.length === 1` や非存在チェックによる複雑な `isActive` 判定・強制マージパッチが追加され、コードが肥大化・複雑化していた。
  - **根本原因 4: テスト検証の偽陽性（Test Gap）**:
    - REQ-277 の検証テスト（`useGenerateAction.test.ts: L1120`）等で、`usePresetState` フックを連携させずテストコードから手動でストアへ直接値を代入していたため、`useEffect` が走って `sets` を旧値で上書きする現象がテストをすり抜けていた。
- **Requirement**:
  - `usePresetState.ts` の `rawMappedSets` において、`existingSet?.paramValues` が存在する場合はローカル編集値を最優先で継承し、サーバー DB 値やデフォルト値によるインメモリ破壊を根絶すること。
  - `appliedAssets`, `batchSize`, `seedMode`, `seed` 等の関連プロパティについても既存インメモリ値を一貫して優先継承すること。
  - メインの `useEffect` においても単一セット時の `activeSetId` 解決フォールバックを導入し、`flushAutoSave` との方針分裂を解消すること。
  - 上流ストアの健全性が担保された上で、`useGenerateAction.ts` 内の不要・過剰な対症療法フォールバック判定を安全に整理・クリーンアップすること。
  - モックに頼らず、プリセット同期と生成パイプラインのライフサイクルを連携させた結合リグレッションテストを追加し、偽陽性を恒久防止すること。
- **Acceptance criteria**:
  - [ ] AC-1: 画面上でパラメータを変更後、ブラウザをリロードすることなく即時（1秒未満）またはオートセーブ完了後（1秒以上経過後）のいずれのタイミングで生成を実行した場合でも、変更後の最新パラメータ値が 100% 確実に ComfyUI 投入ペイロード（`wfJson` ノード inputs）に反映されること。
  - [ ] AC-2: パラメータ変更後、バックグラウンドでのプリセット再取得（React Query ポーリング等）が発生しても、画面上の入力値およびインメモリセット内のパラメータ値が古いサーバー DB 値で巻き戻らないこと。
  - [ ] AC-3: 単一セット運用時および複数セット運用時のいずれにおいても、アクティブなセットの最新編集値が確実に生成ペイロードに適用され、非アクティブセットの個別パラメータも正常に保持されること。
  - [ ] AC-4: `useGenerateAction.ts` から不要な対症療法的フォールバック判定がクリーンアップされ、単一責任かつシンプルなパラメータ解決パイプラインとして機能すること。
  - [ ] AC-5: プリセット同期ライフサイクルと生成アクションが結合された自動テストスイートが整備され、リロードなしでの生成反映が確実に保証されること。
