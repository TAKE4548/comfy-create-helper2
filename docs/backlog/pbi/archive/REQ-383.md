### REQ-383: Generate画面：連続横スクロールリールプレビュー・履歴双方向同期・端点ジャンプと共有コントロールの導入

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: Generate画面のデスクトップ向けプレビュー領域および履歴領域（幅768px以上、`/generate`）。`frontend/src/pages/GeneratePage/components/DesktopLayout.tsx`、`frontend/src/pages/GeneratePage/components/GenerateParallelPreview.tsx`、`frontend/src/pages/GeneratePage/sections/GenerationGallerySection.tsx`、`frontend/src/pages/GeneratePage/hooks/useGalleryInteraction.ts`、`frontend/src/pages/GeneratePage.tsx`、`docs/specs/SPEC_GENERATE.md`

  - `docs/specs/SPEC_COMMON.md`（§1-3 共通UIルール、§1-5 UI 6大ハード不変条件）
  - 先行PBI: REQ-264（自動追従/固定トグル）、REQ-334（再訪契約・分割比率）、REQ-339（並列プレビュー・混在アスペクト比）、REQ-362（プログレッシブキャッシュ）
  - 比較モック: Baseline `https://take4548.github.io/comfy-create-helper2/?ui=baseline` ／ Proposal `https://take4548.github.io/comfy-create-helper2/?ui=proposal`（prototype/ui-review、基準ブランチ）

- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: 現行のGenerate画面において、メインプレビューがページ送り式（コンテナ幅に収まる枚数ごとのページ分割）であるため、連続した生成結果を流れとして見比べにくく、微妙なプロンプトやパラメータの変化を前後の画像と比較しづらいため。
  2. なぜその課題が発生するか: 複数画像の同時並列表示を実現するにあたりページ分割モデルが採用されており、ページ境界を越える前後の画像比較が分断されていたため。
  3. なぜ現状の仕組みで不十分か: 履歴を開いても「新しい順 / 古い順」のソート切替によって時系列方向の意味が反転しやすく、履歴サムネイルをクリックしてもメインプレビューのスクロール位置が同期せず、履歴を閉じるにも右上の操作までマウスを戻す必要があり、直感的な往復閲覧が困難だったため。
  4. なぜこのアプローチを採用するか: リアルモック（`prototype/ui-review`）で検証された3階層の閲覧モデル（メインリール、履歴、詳細）に基づき、最新-first固定の連続横スクロールリール（慣性スクロール・中央吸着・端部余白）、履歴からの双方向追従、端点ジャンプ（`← 最新へ` / `最古へ →`）、プレビュー右上の共有操作（最新追従・自セッション）、および履歴ローカルCloseを導入することで、生成ワークフローにおける直近結果の連続比較性と過去画像への到達性を両立できるため。
  5. 根本原因: メインプレビューと履歴が「同一の時系列画像列に対する縮尺・密度の異なる2つの操作ビュー」として統合されておらず、ページ分割とソート反転による独立したUI状態として設計されていたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 閲覧モデルの3階層整理: (1) メインプレビュー（直近結果の連続閲覧・比較）、(2) 履歴（大量結果の俯瞰・ジャンプ・複数選択）、(3) 詳細表示（単一画像の拡大確認）。
    - 最新-first固定: ソート切替（新しい順/古い順）を廃止し、左側起点（index 0）を最新画像とする単一の時系列画像列モデルに固定。
    - 状態の共有・集約: 「最新追従（previewAutoFollow）」と「自セッション（filterOwnSession）」を履歴を開かずに通常プレビュー上部から操作可能とし、二重状態を排除して相互に完全同期。
  - **Interaction (インタラクション)**:
    - メインプレビューの連続横スクロール: マウスホイール（縦ホイール→横移動 impulse）およびトラックパッドのネイティブ横入力に対応し、最大速度制限と滑らかな慣性減衰、停止時の中央吸着（最寄り画像中心をプレビュー中央に収束）を実現。
    - 端点ジャンプ: 過去側閲覧時に表示される `← 最新へ`（進行中の慣性を停止し最新画像を中央復帰）、常時利用可能な `最古へ →`（最古画像を中央移動）。
    - 履歴との双方向同期: 通常モードで履歴サムネイルをクリックした際、メインプレビューが該当画像へ移動し中央表示。複数選択モード（または修飾キー押下）ではプレビュー移動を抑止。
    - 履歴ローカルClose: 履歴展開時、プレビューと履歴の境界付近に `⌄ 履歴を閉じる` 導線を配置し、視線・ポインタ移動コストを削減。
    - キーボード操作: Home（最新へ）、End（最古へ）、ArrowLeft/ArrowRight（隣接画像移動）。
    - 新規画像生成時の追従制御: 最新追従ON時は新規画像を中央表示。最新追従OFFまたは過去閲覧中はユーザーの閲覧位置（表示中画像）が視覚的に飛ばないようスクロールアンカーを補正。
  - **Visual (視覚デザイン)**:
    - アスペクト比維持と領域内表示: 縦長・正方形・横長（2:1含む）の混在画像に対し、元アスペクト比を維持しつつ均一な表示高を基準とし、横長画像の最大幅制限（viewportの約0.86倍等）により領域外オーバーフローや不自然な空枠・縮小を防止。
    - 端部スクロール余白: 最新画像（先頭）および最古画像（末尾）でもプレビュー中央に吸着・配置できるよう十分なスクロール余白を確保（画像幅を圧縮しない）。
    - ツールバー整列: プレビュー右上に時系列方向と一致させた `← 最新へ` → `最古へ →` → `最新追従` → `自セッション` → `履歴` を整列配置。
    - 画面全体のスクロール抑止: デスクトップ表示での操作中に document body に意図しない横スクロールバーを発生させない。
- **Requirement**:
  - **1. メインプレビューの連続横スクロールリール化**:
    - ページ送り式プレビューを廃止し、最新画像を論理上の先頭（index 0）とする最新-first固定の連続横スクロールリールへ変更する（右スクロールで過去方向へ進む）。
    - 初期表示時は端部余白により最新画像（先頭）の中心をプレビュー領域の水平中央に配置する。
    - マウスホイールおよび横入力による慣性スクロールをサポートし、停止時は最寄り画像の中心をプレビュー中央へ吸着させる。
    - 縦長・正方形・横長の混在画像で元アスペクト比を維持し、横長画像が領域外にはみ出さないよう幅上限を設ける。
    - 端点（最初・最後）の画像もプレビュー水平中央へ配置できるよう、画像自体の表示幅を圧縮しない端部スクロール余白を確保する。
  - **2. 端点ジャンプと共有コントロール**:
    - プレビュー右上に時系列順に `← 最新へ`、`最古へ →`、`最新追従`、`自セッション`、`履歴` を配置する。
    - `← 最新へ` は過去側を閲覧している場合に動的に表示し、押下契機で即座に進行中のスクロール慣性を停止して最新画像を中央へ戻す。
    - `最古へ →` は常時利用可能とし、押下契機で即座に進行中のスクロール慣性を停止して最古画像を中央へ移動する。
    - `最新追従` と `自セッション` を通常プレビューから直接操作可能とし、履歴側の状態と完全に同期する。
  - **3. 履歴の最新-first固定と双方向同期・ローカルClose**:
    - 履歴内の「新しい順 / 古い順」ソート切替UIを撤去し、最新-first固定とする。
    - 通常モードで履歴サムネイルをクリックした際、選択状態を更新するとともにメインプレビューを該当画像へ移動し中央に表示する。
    - 複数選択モード中（および複数選択修飾キー押下時）は、メインプレビューのスクロール位置を移動させない。
    - プレビューと履歴の境界付近に `⌄ 履歴を閉じる` 導線を追加し、通常プレビュー上部の操作と合わせてどちらからでも閉じられるようにする。
  - **4. 既存機能の維持とレスポンシブ境界**:
    - メインプレビュー画像クリックによる既存の詳細プレビューモーダル起動を維持する。
    - 履歴の複数選択、一括保存、選択解除、スナップショット操作を維持する。
    - 本改修は幅768px以上のデスクトップ表示を対象とし、モバイル表示（幅767px以下）の既存プレビュー・履歴仕様は変更しない。
    - プレビューおよび履歴の操作中に、document body に意図しない横スクロールバーを発生させない。
- **Acceptance criteria**:
  - [ ] AC-1: Given Generate に複数の生成画像がある, When メインプレビューを表示する, Then 画像列の論理順序が最新画像を先頭（index 0）として右方向へ進むほど過去画像となる順序で構成され、ソート順を反転する操作（新しい順／古い順切替）が表示されないこと。
  - [ ] AC-2: Given Generate を開いた初期状態, When メインプレビューが初期化される, Then 端部スクロール余白により最新画像（先頭）の中心がプレビュー領域の水平中央に配置され、先頭・末尾のいずれの端点画像も領域中央への吸着配置が可能なスクロール余白（画像表示幅を圧縮しない余白）が確保されていること。
  - [ ] AC-3: Given 複数画像があるメインプレビュー, When ユーザーがプレビュー上で連続横スクロール（マウスホイールまたはトラックパッド入力）する, Then 画像列が連続的に滑らかに移動し、連続入力時でも不要な振動や入力相殺による意図しない急停止が発生せず、スクロール減衰停止後に最も中心に近い画像がプレビューの水平中央へ吸着すること。
  - [ ] AC-4: Given 縦長、正方形、横長の画像が混在するプレビュー, When 画像列を表示する, Then 各画像の元アスペクト比が維持され、画像またはタイルがプレビュー領域を上下・左右にはみ出さず、細長い空枠や枠内で画像だけが極端に縮小する表示が発生しないこと。
  - [ ] AC-5: Given ユーザーが過去画像までスクロール移動している状態, When 「← 最新へ」を押下する, Then 押下契機で即座に進行中のスクロール慣性を停止し、最新画像がプレビューの水平中央に移動・中央表示されること。
  - [ ] AC-6: Given 履歴に複数画像がある状態, When 「最古へ →」を押下する, Then 押下契機で即座に進行中のスクロール慣性を停止し、最古画像がプレビューの水平中央に移動・表示されること。
  - [ ] AC-7: Given 履歴を展開している状態, When 通常モード（単一選択）で任意の履歴サムネイルをクリックする, Then 対象画像が選択状態となり、メインプレビューが該当画像へスクロール移動してプレビュー水平中央に表示されること。
  - [ ] AC-8: Given 履歴が複数選択モードである状態（または複数選択用の修飾キー押下時）, When 履歴サムネイルをクリックして選択／解除する, Then メインプレビューのスクロール位置が移動・ジャンプしないこと。
  - [ ] AC-9: Given 履歴が展開されている状態, When プレビューと履歴の境界バーに配置された「⌄ 履歴を閉じる」ボタンを押下する, Then 履歴ペインが閉じ、メインプレビューの表示領域が履歴展開前の通常表示高へ復帰すること。
  - [ ] AC-10: Given デスクトップ表示（幅768px以上）で履歴が展開されている状態, When 通常プレビュー上部または履歴ペインのいずれかで「最新追従」トグルを切り替える, Then もう一方の「最新追従」トグルの表示状態（ON/OFF）が即時に連動・同期し、単一の共有状態（previewAutoFollow）に従うこと。
  - [ ] AC-11: Given デスクトップ表示（幅768px以上）で履歴が展開されている状態, When 通常プレビュー上部または履歴ペインのいずれかで「自セッション」絞り込みを切り替える, Then もう一方の「自セッション」絞り込みの表示状態が即時に連動・同期し、表示対象の画像列が同一のフィルタ状態に従って更新されること。
  - [ ] AC-12: Given メインプレビューに画像が表示されている状態, When 任意の画像をクリックする, Then 既存の詳細プレビューモーダル（HistoryModalPreview）が開き、拡大表示および閉じる操作（Escapeキーまたは閉じるボタン）が正常に機能すること。
  - [ ] AC-13: Given 履歴が展開されている状態, When 履歴内の複数選択チェックボックス、一括保存、選択解除、およびスナップショットタブ操作を実行する, Then 改修前と同等の既存履歴操作が正常に動作すること。
  - [ ] AC-14: Given デスクトップ表示（幅768px以上）のGenerate画面, When メインプレビューの横スクロールおよび履歴の開閉・選択を操作する, Then document body に横スクロールバー（overflow-x）が発生しないこと。
- **Inferred points**:
  - 先行PBI REQ-264（プレビュー自動追従）、REQ-334（再訪契約・分割比率）、REQ-339（並列プレビュー）の設計原則を継承し、ページ送り式から連続横リールへ発展的置換を行う。
  - デスクトップ（幅768px以上）専用のUI/UX改修であり、幅767px以下のモバイル Generate UI（SPEC_GENERATE.md §2-9、コンパクト表示・object-contain・2段階モーダル）は変更対象外（現行動作を維持）。
  - モック検討で確認された参考値（縦ホイール0.38、横0.28、減衰0.89、停止閾値0.35、横長最大幅0.86×viewport、履歴展開高~185px、最新へ表示閾値~72px）は初期基準であり、本番実装時にAC-3/AC-4を満たす範囲でブラウザ/OS特性に応じて微調整可能。
  - 新規画像生成時の動的振る舞い（自動追従ON時は最新中央、OFFまたは過去閲覧中は表示中画像のスクロール位置アンカーを補正して視覚的ジャンプを防止）は本番実装時の追加検証項目とする。
