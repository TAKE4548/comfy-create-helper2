### REQ-252: 生成履歴サムネイル表示におけるイベントループブロッキング解消と多重ロード最適化

- **Type**: defect
- **Status**: done (2026-09-12)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - 生成履歴（Generate画面の履歴ストリップ）を表示した際に、以前よりも表示開始が著しく遅くなり、画面表示直後にUI全体やキュー監視が十数秒フリーズする
- **Root Cause**:
  - (UX分類: Interaction / Infrastructure Architecture)
  - バックエンド（`comfy.py`）の動的サムネイルエンドポイントにおいて、`async def` 内で同期的なPillow画像変換処理を実行しているためFastAPIのメインイベントループが1秒超ブロックされる。加えて横スクロールコンテナでのネイティブ遅延ロード不発により全件一括リクエストが殺到し、サーバー全体が同期ブロッキングキューで麻痺している
- **Requirement**:
  - 生成履歴ストリップ表示時において、バックエンドのイベントループを停止させず、画面表示直後も他通信やジョブキュー監視がフリーズすることなく軽快に動作すること。また、画面外のサムネイルによる無駄な一括同時通信を抑制し、ローカル環境・リモート環境双方で最適な表示レイテンシが得られること
- **Acceptance criteria**:
  - [ ] AC-1: Generate画面の生成履歴ストリップを開いた際、サムネイルの読み込み中であってもジョブキューのポーリングや他API通信がブロックされず、UIの操作性が維持されること。
  - [ ] AC-2: 生成履歴に多数の画像（20枚以上）が存在する場合でも、画面初期マウント時に画面外のサムネイルが一斉リクエストされず、表示領域内のサムネイルが優先的に素早く描画されること。
  - [ ] AC-3: ローカル実行環境において、サムネイル表示によるオーバーヘッドが最小化され、体感表示速度が以前の直接表示と同等以上の応答性を維持できること。
  - [ ] AC-4: サーバー再起動後などの初回アクセス時（コールドスタート時）でも、大量サムネイルによるサーバー全体のフリーズや大幅な遅延が発生しないこと。
