### REQ-338: Prompt Surgeon モバイル最適化および全ビュー共通基盤改修

- **Type**: feature
- **Status**: done (2026-10-11)
- **Priority**: P2
- **Surface**: frontend/src/components/ (Slider, Lightbox, Modal, GenerationView, BottomSheet, PromptInput), frontend/src/hooks/ (useAppLifecycleSync), frontend/src/styles/
- **Reference Spec**: [tmp/mobile_ui_guidelines_visual.html](file:///c:/Users/audih/ws/comfy-create-helper2/tmp/mobile_ui_guidelines_visual.html)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: スマートフォン・タブレット端末（360px〜768px未満）でのPrompt Surgeon操作時に、UI要素の押し潰れ・親指タップ不能・Safariツールバー潜水・キーボード遮蔽・背面連動スクロールが発生し、実用に耐えないため。
  2. なぜその課題が発生するか: デスクトップ基準の固定レイアウト（p-6余白、100vh、中央浮遊モーダル、画面上部アクションボタン、ホバー依存判定）がそのまま適用されているため。
  3. なぜ現状の仕組みで不十分か: 単なるCSSレスポンシブ（メディアクエリによる縮小）だけでは、粗調整と微調整の両立、スリープ復帰時のWebSocket切断凍結、IME起動時の入力欄圧迫、片手親指の操作域（Natural Thumb Zone）制約を解決できないため。
  4. なぜこのアプローチを採用するか: モバイル検討から導出された改善を「全ビュー共通基盤（PC含む）」と「モバイル特化仕様（< 768px）」に二大分類し、PCでの操作性（スライダーステッパー、全画面Lightbox、スリープ復帰0秒同期、モーダルScroll Lock）向上とモバイル特化の人間工学（Spacing圧縮、Hit-Slop、100dvh、ボトムシート、キーボード退避、下部40%集約）を同時に実現するため。
  5. 根本原因: マルチデバイスを前提としたUIアーキテクチャ境界（共通基盤 vs デバイス特化レイアウト）の未分離と、モバイル特有のビューポート・タッチ・ライフサイクルイベントへの適応設計の欠如。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 画面幅360px〜390px時の外枠余白をpx-3 py-2.5（12px/10px）、カード内余白をp-2.5（10px）に圧縮し、LoRAカード等の表示密度を最大化。
    - 数値表示（秒数、ETA、VRAM、Seed値、重み）にtabular-nums font-monoを適用し、桁揺れ・レイアウトシフトを防止。
    - 画面上部25%（Hard Zone: 閲覧・ステータス）、中央35%（Reach Zone: プレビュー・調整）、下部40%（Natural Zone: 生成・選別・アクション）の情報階層化。
  - **Interaction (インタラクション)**:
    - スライダーに微調整ステッパー（[-] [+]、±0.05等）と直接数値入力を併設。
    - 画像クリックで全画面Lightboxを展開し、1:1等倍ズーム・パンおよびA/Bカーテン比較を提供（高解像度画像の描画負荷を考慮したパフォーマンス制御含む）。
    - `document.visibilitychange` および `window.focus` を契機に、スリープ・タブ復帰時に古いソケット破棄＆WebSocket再接続（`systemWsService.resume()`）とREST API（GET `/api/generation/state`）のフェッチを並行実行し、0秒で最新世代（Epoch / Revision）を再同期。オフライン・ネットワーク瞬断時のフォールバック再試行を備える。
    - モーダル展開時の背面スクロール固定（`body { overflow: hidden }`）と、決定ボタンの常時可視化（Sticky Footer）。
    - モバイル（< 768px）ではモーダルを中央浮遊からボトムシート（Drawer）形式（コンポーネント型として明確に分離）に置換し、下スワイプクローズをサポート。
    - 仮想キーボード（IME）起動時、下部固定Action Barを自動退避（hidden）し、キーボード直上にサジェストバーを吸着配置。スライダーの単体インライン入力とメインプロンプト入力のフォーカスコンフリクトを回避する。
    - 端末回転（Portrait ↔ Landscape）時にもレイアウト崩壊を起こさず、Natural Zoneおよびセーフエリアを正しく維持。
  - **Visual (視覚デザイン)**:
    - タグ・チップ等のタップ判定領域に外形24pxを保ちつつ40px〜44pxの透明拡張（`before:-inset-2`）を適用。キーボード操作やアクセシビリティ（フォーカスリング、A11y）を阻害しない。
    - ルートコンテナに `100dvh` を適用し、固定フッターに `env(safe-area-inset-bottom)` を付与してiOS Home IndicatorおよびSafariバーとの干渉を完全排除。
    - リスト・モーダルに `overscroll-behavior: contain` を付与し、Pull-to-refresh誤爆およびスクロール連動を遮断。
    - `touch-action: manipulation` でダブルタップによる300ms遅延を排除、タッチデバイスでの `:hover` 貼り付きを抑止し `active:scale-[0.97]` のフィードバックを提供。
- **Requirement**:
  - **1. PART 1: 全ビュー共通基盤（Desktop / Tablet / Mobile 共通）**:
    - **C-01. スライダーステッパー＆直接入力**: 粗調整スライダーに [-] [+] ステッパーボタンとクリック直接数値入力を統合。
    - **C-02. 全画面Lightbox＆カーテン比較**: 画像拡大時に全画面モーダルを開き、ホイールズーム・パンおよび2枚画像のA/Bスプリットカーテン比較を提供。
    - **C-03. スリープ復帰0秒再同期**: `visibilitychange` / `focus` 検知で切断ソケット破棄＆WebSocket再接続とREST API一撃再フェッチを並行実行（`useAppLifecycleSync`）。
    - **C-04. モーダルScroll Lock＆Sticky Footer**: モーダル表示中のbodyスクロール固定、`overscroll-behavior: contain`、下部決定ボタンのSticky固定。
    - **C-05. 共通CSS防壁**: 横あふれ防止の `min-w-0 truncate` / `break-all`、数値の `tabular-nums font-mono` の徹底。
  - **2. PART 2: モバイル特化仕様（Mobile-Only: < 768px）**:
    - **M-01. 余白と情報密度**: 画面外枠 `px-3 py-2.5`、カード内 `p-2.5`、グリッド `gap-2` による実効表示領域の拡大。
    - **M-02. タッチ判定Hit-Slop**: 24pxタグチップに `before:-inset-2` による40pxタップ判定領域の確保。
    - **M-03. 100dvh＆セーフエリア**: `100dvh` によるブラウザバー動的追従、`pb-[calc(env(safe-area-inset-bottom)+12px)]` によるHome Indicator干渉防止。
    - **M-04. ボトムシート（Drawer）**: モバイル用モーダルのボトムシートコンポーネント化、下スワイプクローズ、親指ゾーンSticky Footer。
    - **M-05. IMEキーボード防御**: プロンプト等入力フォーカス時の固定Action Bar自動退避、キーボード直上アクセサリサジェストバー吸着。
    - **M-06. 親指エルゴノミクス（Thumb Zone）**: 下部40%領域への最重要アクション（Generate、キュー、選別判定）集約、`overscroll-behavior-y: contain` によるPull-to-refresh暴発防止。
- **Acceptance criteria**:
  - [ ] AC-1: Given スライダーコンポーネントが表示されている画面, When ユーザーが [-] または [+] ボタンをクリック/タップする、あるいは数値を直接クリックして数値を入力する, Then スライダー値が設定刻み幅で正確に増減または入力値に更新されること。
  - [ ] AC-2: Given 生成結果画像が表示されている画面, When 画像をクリック/タップする, Then 全画面Lightboxが開き、ホイール/ピンチズーム・パン操作、および2画像選択時のA/Bカーテン比較スプリット操作ができること。
  - [ ] AC-3: Given アプリを開いたタブがバックグラウンド休止または端末がスリープした状態, When 再度タブがアクティブまたはフォアグラウンドに復帰した（`visibilitychange` / `focus` 検知）, Then WebSocket再接続とREST状態フェッチが並行実行され、待ち時間ゼロ（即時）で最新の生成状態および成果物が画面へ再同期されること。
  - [ ] AC-4: Given 任意のモーダルダイアログが開いている状態, When モーダル内でスクロール操作を行う, Then 背面のメイン画面はスクロールせず固定され、かつ縦長モーダルであっても決定・キャンセルボタンが下部に常時固定（Sticky）表示されていること。
  - [ ] AC-5: Given 画面幅768px未満のモバイル環境, When ページを表示する, Then 画面外枠余白が12px以下に圧縮され、`100dvh` によりSafari等のツールバー伸縮に動的追従し、最下部要素がHome Indicatorと干渉しないセーフエリアマージンを保持すること。
  - [ ] AC-6: Given 画面幅768px未満のモバイル環境, When 設定やLoRA選択のモーダルを開く, Then 画面下部から引き出されるボトムシート（Drawer）形式で表示され、下スワイプ操作で閉じることができ、決定ボタンが親指可動域内に配置されていること。
  - [ ] AC-7: Given 画面幅768px未満のモバイル環境, When プロンプト入力欄にフォーカスして仮想キーボード（IME）が起動する, Then 下部の固定Action Barが自動退避（非表示）して入力カーソルが遮蔽されず、キーボード直上にタグサジェストバーが吸着配置されること。
  - [ ] AC-8: Given 画面幅768px未満のモバイル環境, When メイン生成画面を表示する, Then Generateボタン・選別判定ボタン・キュー情報が親指の自然な可動域である画面下部40%（Natural Zone）に集約配置され、画面上部スクロール時にブラウザのPull-to-refreshが暴発しないこと。
  - [ ] AC-9: Given 画面幅768px未満のモバイル環境, When 端末の向きを回転（縦向き ↔ 横向き）させた場合, Then レイアウトシフトによる要素の押し潰れや操作ボタンの画面外脱落が発生せず、Natural Zoneおよびセーフエリアの配置が適切に維持されること。
- **Inferred points**:
  - 本改修は `tmp/mobile_ui_guidelines_visual.html` の全24項目（共通10項目・モバイル14項目）の仕様に準拠する。
  - 既存のPCデスクトップ操作性を損なうことなく、PC側にもステッパーやLightbox、0秒同期、モーダル固定等の恩恵を波及させる共通基盤アプローチを採る。
  - 詳細設計（`/dev-design`）フェーズにおいて、共通コンポーネント化（Slider, Lightbox, Modal/Drawer）とビューごとのTailwindレスポンシブクラス適用タスクに分解して実装計画を策定する。
