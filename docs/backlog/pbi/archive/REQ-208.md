### REQ-208: 生成ページ状態フック（useGeneratePageState）のドメイン別分割およびStale Closure・再レンダリング防止
- **Type**: refactor
- **Status**: done (2026-08-30)
- **Current step**: Phase 2: Detailed Design
- **Priority**: P1
- **Surface**:
  - `frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts` が1,450行を超える超巨大フックとなっており、40以上のローカル状態（モーダル開閉、タブ、選択状態、リサイズ、ドラッグ状態）と数十のAPIミューテーションを集約している。
  - いずれか1つの状態（例: スライダのドラッグ、タブの切替）が変化するだけで `GeneratePage` 全体および下位の全コンポーネントが再レンダリングされ、高負荷および入力遅延を誘発している。
  - コールバック関数内で最新のStateを参照できず古いクロージャを参照する Stale Closures の潜在リスクがあり、非同期処理完了後の状態先祖返りや競合が発生しやすい。
  - `CustomEvent`（例: `tag-chip-editor:text-mode-toggle`）による `window` レベルの暗黙的イベント通信が行われており、影響範囲の追跡が極めて困難。
- **Root Cause**:
  - **Hook Over-Centralization**: 「ページの全状態を1箇所のフックで束ねて返す」という設計パターンにより、画面の肥大化に伴って責務境界が消失し、単一責任の原則（SRP）が破綻している。
  - **Implicit Event Coupling**: Reactの宣言的データフローやストアアクションを使用せず、グローバルDOMイベント（`window.dispatchEvent` / `addEventListener`）に依存して状態同期を行っている。
- **Requirement**:
  - `useGeneratePageState` を関心事ごとに複数の小さな専用フック（`useModalStates`, `usePresetDialogState`, `useWorkflowLayoutState`, `useAssetSelectionState` 等）に分解すること。
  - 再レンダリング境界を適切に分離し、入力変更時に関係のないコンポーネントが不要に再評価されないよう最適化すること。
  - グローバル `CustomEvent` を廃止し、Zustandストアまたは明示的なコールバックプロパティによる宣言的な状態連携に置き換えること。
- **Acceptance criteria**:
  - [ ] AC-1: `useGeneratePageState` がドメイン別サブフックに分割され、各フックが200〜300行以内の自己完結した構造になっていること。
  - [ ] AC-2: `tag-chip-editor:text-mode-toggle` 等の `window` レベル `CustomEvent` が撤廃され、状態遷移が明示的なデータフローで管理されていること。
  - [ ] AC-3: パラメータ入力やモーダル操作時の再レンダリング範囲が局所化され、不要なページ全体再描画が発生しないこと。
  - [ ] AC-4: 既存の `GeneratePage.test.tsx` および関連するコンポーネントテストがすべてグリーン（Pass）であること。
