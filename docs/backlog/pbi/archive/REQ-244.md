### REQ-244: Web Managerプロセス再起動の適正化とバッチ起動引数統一

- **Type**: defect
- **Status**: done (2026-09-10)
- **Current step**: Step 3
- **Priority**: P1
- **Surface**:
  - 242（ターミナル非表示・タブ別コンソール出力表示）を完了したにもかかわらず、Web UI 画面やサービス起動挙動が変わっていない。Web Manager（ポート8899）の再起動を行っても旧画面のまま更新されず、またバッチ経由で起動した際にも依然として 3 つのターミナルウィンドウがデスクトップ前面に出てきて残り続ける。
- **Root Cause**:
  - 1. `restart_web_manager.bat` において、特権等で常駐している既存 Web Manager プロセスの停止（kill）が失敗した場合にエラーが隠蔽され、ポートが未解放のまま新プロセスがクラッシュしたにもかかわらず、旧プロセスのリッスンを誤認して「再起動成功」と判定していたため、新コードが RAM 上に反映されていなかった。
  - 2. `start_servers.bat` や `toggle_servers.bat` において `server-manager.ps1` への `-Background` 引数が渡されておらず、前面ウィンドウ表示モード（`cmd.exe /k`）が実行され続けていた。また `start_background_all.bat` に旧式の `conhost.exe` 呼び出しが残存していた。
- **Requirement**:
  - `restart_web_manager.bat` において既存プロセスの確実な終了とポート解放を検証し、新コードでの稼働開始を厳密に担保すること（終了失敗時はエラーとして明示）。また、バッチファイル群からの起動時にも確実に完全バックグラウンド（ウィンドウ生成数 0）で起動されるよう引数・スクリプトを統一し、REQ-242 の機能が確実に利用できるようにすること。
- **Acceptance criteria**:
  - [x] AC-1: `restart_web_manager.bat` を実行した際、既存の Web Manager プロセスが確実に終了され、ポート解放および新プロセスの正常稼働が確認できた場合のみ成功として完了すること（停止失敗やポート競合時は成功と誤判定せず、エラーを明示して中断すること）。
  - [x] AC-2: Web Manager の再起動完了後、ブラウザでアクセスした画面上に REQ-242 のタブ別コンソール出力エリア（Backend / Frontend / ComfyUI / Manager）が正常に表示・動作すること。
  - [x] AC-3: `start_servers.bat` および `toggle_servers.bat` を実行した際、3つの外部ターミナルウィンドウがデスクトップ前面にポップアップして残り続けず、完全にバックグラウンドで起動されること。
  - [x] AC-4: `start_background_all.bat` を実行した際、レガシーな `conhost.exe` の残存によるウィンドウ生成が発生せず、完全にバックグラウンドで起動されること。
