### REQ-303: Animaモードにおけるピリオド区切りタグチップ分割とプロンプト結合制御

- **Type**: enhancement
- **Status**: done (2026-10-02)
- **Current step**: none
- **Priority**: P2
- **UX Classification**:
  - **Interaction Design**: タグ入力欄（TagInput）における `.` 入力およびテキストペースト時のトークン分割・確定挙動の自然言語対応
  - **Information Design**: チップ列から送信プロンプト文字列への変換（`chipsToString`）における区切り記号（`. ` / `, `）の動的判定・結合制御
  - **Visual**: 末尾ピリオドを省略・欠落させないタグチップ内ラベル表示
- **Surface**:
  - 生成画面のプロンプト欄（タグチップエディタ）において、Animaモード（自然言語/センテンス指向プロンプト）使用時は英文や自然言語の文（ピリオド終わりの文）を扱うことが多いが、現状は `,`（カンマ）のみが区切り判定となっているため、ピリオド終わりの文をタグチップとして分割・整理しづらい。
  - さらに、現在のプロンプト送信（平文変換）処理では全チップ間が一律に `, ` で結合されるため、ピリオド付きの文の後に `, ` が付与され（例: `1girl, solo., red dress.`）、自然言語プロンプトとして不自然な構文になってしまう。
  - Animaモードではピリオド `.` も区切りとみなしつつ、ピリオド自体は前のタグの末尾に残したままチップ化し、送信プロンプト生成時は直前がピリオド区切りの場合はカンマを付けず半角スペースのみで後続と結合したい。
- **Root Cause**:
  - **Interaction Design (自然言語入力とタグメタファーの不整合)**:
    - タグエディタの入力確定キーおよびパース境界がカンマ `,` に固定されており、Animaモードにおける自然言語センテンス単位（`.` 区切り）の入力・編集ライフサイクルに対応していない。
  - **Information Design (一律シリアライズによる構文破壊)**:
    - チップ配列から送信プロンプト文字列を再構成する結合ロジック（`chipsToString`）が `, ` の一律結合のみを想定しており、ピリオド終端トークンに対する適切な空白結合（`" "`）ロジックが欠如している。
- **Requirement**:
  - タグチップエディタが Animaモード（`isAnimaMode: true`）の場合において、カンマ `,` に加えてピリオド `.` もタグチップの区切り境界として認識・分割すること。
  - `.` による区切りの場合、カンマのように区切り記号を除去・省略せず、直前のタグチップ文字列の末尾に `.` を付与・保持した状態でチップ化すること。
  - パースおよびペースト処理において、各トークンの前後の余剰空白（Leading/Trailing Whitespace）は適切に `trim()` され、連続する区切り記号（`..` や `, .` 等）に起因する空トークンは除外されること。
  - 既存の括弧保護仕様を厳格に順守し、丸括弧 `(...)` 等のネスト内部に含まれるピリオド（例: `(tag:1.2)`）は区切り文字として扱わず、単一のトークンとして保護すること。
  - タグチップ列からプロンプト文字列を生成する際（ComfyUI送信時やテキスト変換時）、有効なタグチップ（`enabled: true`）の連続間において、直前のチップ末尾が `.` で終わる場合はカンマを付与せず半角スペース `" "` のみで後続チップと結合し、直前のチップ末尾が `.` 以外の場合は従来通り `, ` で結合すること（先頭チップの前や末尾チップの後に余剰な記号・空白が付与されないこと）。
  - 通常モード（非Animaモード）では従来通りの挙動（カンマ区切りおよび一律 `, ` 結合）を維持し、既存の操作感やプロンプト生成に影響を与えないこと。
- **Acceptance criteria**:
  - [ ] AC-1: Given: タグチップエディタでAnimaモードが有効である / When: ユーザーがテキスト入力欄で `.` を入力（または末尾に `.` を含むテキストを入力・確定）した / Then: 直前のテキストが末尾の `.` を保持した状態で単一のタグチップとして確定・表示されること。
  - [ ] AC-2: Given: タグチップエディタでAnimaモードが有効である / When: ピリオド `.` やカンマ `,` を含む複数文のテキストがペーストまたは初期値として入力された / Then: ピリオド区切りの部分は末尾に `.` を付けたチップとして分割され、カンマ区切りの部分はカンマを除去したチップとして分割され、かつ各チップの前後余剰空白がトリムされ空チップが生成されないこと。
  - [ ] AC-3: Given: タグチップエディタでAnimaモードが有効である / When: 重み付き括弧記法 `(tag:1.2)` を含むテキストが入力・パースされた / Then: 括弧内のピリオドは区切り判定されず、括弧ネスト全体が1つのタグチップとして保護されること。
  - [ ] AC-4: Given: Animaモードで作成されたピリオド終端チップと通常チップが混在している / When: ComfyUIへのプロンプト送信または平文変換（`chipsToString`）が実行された / Then: 有効チップ間で、直前のチップ末尾が `.` の場合は半角スペース `" "` のみ（例: `1girl. red dress.`）、直前のチップ末尾が `.` 以外の場合は従来通り `, `（例: `masterpiece, 1girl.`）で結合され、先頭や末尾に余計な区切り文字が付与されないこと。
  - [ ] AC-5: Given: ピリオド終端チップの直後に無効化（`enabled: false`）されたチップが存在する / When: プロンプト文字列への変換が実行された / Then: 無効化チップは除外され、直前の有効なピリオド終端チップと次の有効チップとの間が半角スペース `" "` のみで正しく結合されること。
  - [ ] AC-6: Given: タグチップエディタでAnimaモードが無効（通常モード）である / When: タグの入力、パース、およびプロンプト送信文字列への変換が行われた / Then: `.` は区切り文字として扱われず、全有効チップ間は従来通り `, ` で統一して結合されること。
  - [ ] AC-7: Given: Animaモードにおいてピリオド終端チップとカンマ区切りチップを含むプロンプトが設定されている / When: タグチップモードからテキスト入力モード（textarea）へ切り替え、再度タグチップモードへ復帰した / Then: ピリオド付きタグの末尾ピリオドおよびカンマ区切りタグの構造が壊れずに相互変換されること。
- **Inferred points & Assumptions**:
  - タグ強度表記 `(tag:1.2)` や括弧ネスト記法内の数値ピリオドは、SPEC_COMMON.mdの既存括弧保護ルールに従い、区切り文字として扱わず保持する。
  - 単語途中のピリオド（例: `1.5` などの小数点）は、括弧内や数値として扱われる場合を除き、区切り入力（`.` の単独押下やペースト時の文末判定）と誤認されないように配慮する。
