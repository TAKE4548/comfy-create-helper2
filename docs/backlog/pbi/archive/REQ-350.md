### REQ-350: Seed専用型へランダム・固定操作とバッチ生成規則を適用する

- **Type**: feature
- **Status**: done (2026-10-12)
- **Priority**: P2（仮置き）
- **Surface**: マッピング型選択・生成Seed入力・バッチ生成
- **Operational need**: マッピングしたSeedで再現生成と探索生成を選ぶ。
- **5 Whys / 業務上の課題整理**（ユーザー報告からの要約。実装原因の断定ではない）:
  1. Seedが通常float欄になりランダム機能が使えない。
  2. 入力型がSeedの意味と生成モードを表していない。
  3. 数値入力だけではランダム/固定とバッチ規則を選べない。
  4. 専用型へ既存操作を適用すれば生成目的を選べる。
  5. Seed型の意味がマッピングに反映されていないことが課題である。
- **UX Classification**: Information Design / Interaction
- **Requirement**:
  - Seed専用型を選択・保存でき既存ランダム/固定操作を適用する。
  - バッチの既存Random=32bit乱数、Fixed=seed+0始まりindexを適用する。
- **Acceptance criteria**:
  - [ ] AC-1: Given マッピングマスタ編集画面, When Seed専用型を選択し保存して再表示する, Then Seed型の選択が保持されること。
  - [ ] AC-2: Given Seed型をマッピングしたワークフロー, When 生成ページを開く, Then 当該欄にランダム/固定切替が表示されること。
  - [ ] AC-3: Given Seed型を固定モードで100に設定, When 3枚バッチ生成する, Then マッピング先で実使用Seedが100・101・102となること。
  - [ ] AC-4: Given ランダムモードで乱数取得結果を11・22・33とする検証条件, When 3枚バッチ生成する, Then 当該マッピング先に各々11・22・33が使用されること。
  - [ ] AC-5: Given ランダムモード, When 1枚生成する, Then 実使用Seedが0以上4294967295以下の整数であること。
  - [ ] AC-6: Given Main/Seedを固定100、Rough/Seedを固定200、同期なし, When 2枚バッチ生成する, Then Mainは100・101、Roughは200・201を使用すること。
  - [ ] AC-7: Given Seed型と通常float型が共存, When 入力を表示する, Then 通常float型にSeed切替を追加しないこと。
- **Reference docs**:
  - SPEC_GENERATE.md §2-5/生成フロー
  - SPEC_SETTINGS.md §4-1
- **Inferred points**:
<inferred_points>
- 同期なしならステージ別Seedは独立とする案。既存グローバルSeedとの優先関係は設計で明示する。
- 固定Seed+indexの上限超過時の従来規則は文書にないため境界動作は設計時に定義する。乱数の偶然一致を許容する。
</inferred_points>

- **BA contradiction audit**: 2026-10-11監査完了。結論はランダム検証と境界値の明確化が必要。監査直後のunload成功。証跡: [監査証跡](../../ba-audit/REQ-350.md)
- **BA audit response**: AC-4は乱数取得結果を固定した検証条件であり、通常実行で11・22・33を強制する要件ではないためAC-5と矛盾しない。32bit乱数および固定Seed+indexは既存SPEC_GENERATEの規則である。上限超過時の挙動は既に推論点へ明記済みの設計未決事項として保持し、BAでラップアラウンド等を独断で指定しない。型の保存形式・移行・生成中変更の整合は設計で確認する。監査の不足指摘を保持しPASSとは扱わない。
- **Human review gate**: 2026-10-11にユーザーが本PBIをOKと明示承認。承認済みとしてreadyへ変更する。ユーザー指示に従い開発への引継ぎは行わない。
- **Design doc**: 未作成（起票のみ）。
