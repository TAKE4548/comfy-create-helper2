### REQ-111: LoRA・タグセット管理のベースモデル使い分け機能の追加

- **Type**: enhancement
- **Status**: done (2026-08-26)
- **Priority**: P1
- **Surface**: 
  - LoRA管理とタグセット管理に対象モデルで使い分けられるようにしたい。現在のSDXL系（illusやNoobなど）に加え、Anima等アーキテクチャ違いのLoRA・タグセットを一緒に管理し、ワークフローに応じて使い分けたい。
  - 対象ベースモデルの属性を追加し、同じキャラやセットでもカード自体は別扱いで登録できること。また、派生元が同一（Illus・Noobなど）で共用可能なものもあるため、対象ベースモデルの指定・フィルタは単一指定ではなく任意の複数指定（複数選択）を可能にすること。
  - 生成画面の「Add Asset」でも対象ベースモデルでのフィルタをかけられること。ワークフローにベースモデルを設定しておき、デフォルトのフィルタがそれに依存すること。
  - ワークフローのベースモデル初期値は、ワークフローをパースしてチェックポイントローダーノードのファイル名から自動設定されること（補助機能であり、手動上書きが可能）。
  - 設定画面でベースモデルのCRUD、およびComfyUIから取得したチェックポイントファイルリストとベースモデルのマッピング情報を設定・管理できること。マッピングにない場合はファイル名の部分一致で推定し、判定不能時は未設定として検出不能の旨をファイル名とともにメッセージ表示すること。

- **Root Cause**:
  - LoRAおよびタグセットカードに「対象ベースモデル」の属性がなく、アーキテクチャや派生モデルに応じた分離・フィルタリングが行えない。
  - ワークフロー設定自体に「ターゲットとするベースモデル」を保持する仕組みがなく、チェックポイント名からの自動判定ロジックも存在しない。
  - アセット追加画面で、アクティブなワークフローに適合するアセットだけを絞り込む機能がない。

- **Requirement**:
  LoRA・タグセットのカードに対象ベースモデル情報を複数設定できるようにし、フィルタリングを容易にする。ワークフロー側でターゲットとするベースモデルを管理し、チェックポイント名から自動検出する補助機能を備えるとともに、設定画面でベースモデルの定義およびチェックポイントマッピングを管理できるようにする。生成画面のアセット追加時にもワークフローで指定されたベースモデルに基づいて自動でフィルタリングする。

#### Acceptance Criteria (AC)
- [ ] AC-1: **設定画面でのベースモデルCRUD**: 設定画面において、ベースモデル（マスタデータ）の作成、読み込み、更新、削除（CRUD）ができること。
- [ ] AC-2: **設定画面でのチェックポイントマッピング管理**: 設定画面において、ComfyUIから現在利用可能なチェックポイントファイル名の一覧を取得でき、それらとベースモデルの紐づけ情報（マッピングデータ）を保存・編集・削除できること。
- [ ] AC-3: **アセットへのベースモデル複数紐づけ**: LoRAカードおよびタグセットカードの作成・編集時に、対応する「対象ベースモデル」を複数選択して保存できること。また、同じLoRAやタグセットであってもベースモデル毎に別のカードとして個別に登録・管理できること。
- [ ] AC-4: **アセット一覧での複数ベースモデルフィルタ**: LoRAおよびタグセットの一覧画面において、対象ベースモデルによる複数選択でのフィルタリングが行えること。
- [ ] AC-5: **ワークフローへのベースモデル設定**: ワークフローの設定情報として、ターゲットとするベースモデルを保存でき、編集画面等で手動での選択・変更が行えること。
- [ ] AC-6: **チェックポイントからのベースモデル自動検出**: ワークフロー読み込み時、ワークフロー内のチェックポイントローダーノードが指すファイル名をパースし、マッピング情報に完全一致するファイルがあれば対応するベースモデルを自動で設定すること。一致するものがない場合は、ファイル名との部分一致（大文字小文字無視）で適合するベースモデルを推定して設定すること。部分一致すらしない場合は設定せず、「ベースモデルを検出できませんでした（ファイル名: {filename}）」等の通知メッセージを表示すること。この自動設定は手動で上書きできること。
- [ ] AC-7: **生成画面（Add Asset）での自動フィルタ**: 画像生成画面の「Add Asset」押下時のアセット追加モーダルまたはポップアップにおいて、現在適用されているワークフローのベースモデルに対応するアセット（LoRA/タグセット）が初期選択のフィルタとして自動適用されて絞り込まれること。また、ユーザーはこのフィルタを解除または変更できること。
