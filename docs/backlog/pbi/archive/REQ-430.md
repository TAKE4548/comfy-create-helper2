### REQ-430: Settings画面 Node Mapping Masters タイトル埋没およびワークフロー管理ペイン内部スクロール未対応

- **Type**: bug
- **Priority**: P2
- **Incident Report**: `docs/incident_report_20261114_settings_layout.md`
- **Classification**: Type A (Implementation Defect: Node Mapping Masters タイトル埋没) + Type B (Specification Gap: ワークフロー管理内部スクロール & ペイン高さ揃え)
- **Surface**: frontend/src/pages/SettingsPage.tsx, frontend/src/pages/SettingsPage/SettingsResponsive.css, frontend/src/pages/SettingsPage/components/MappingMasterSection.tsx, frontend/src/pages/SettingsPage/components/WorkflowConnectionSection.tsx, docs/specs/SPEC_SETTINGS.md
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: Settings画面（`workflows`タブ）で Node Mapping Masters のタイトルが埋もれて読めず、またワークフロー管理に多数件あると左ペインだけ縦に伸びすぎるため。
  2. なぜその課題が発生するか: (a) デスクトップ（>=768px）の `.settings-mobile-card` が単一行 flex になっており、`MasterRow` のステージ状態バッジ群（`shrink-0 whitespace-nowrap`）が `xl:grid-cols-2` 半幅カラム内でタイトルを押し潰しているため。(b) `WorkflowConnectionSection` のワークフロー一覧に内部スクロール上限がなく、`xl` 2カラム時の左右ペイン高さ揃え仕様も未定義のため。
  3. なぜ現状の仕組みで不十分か: モバイル（<768px）のみ2行カードが適用されており、デスクトップ半幅ではタイトルが数文字で省略され、`SPEC_SETTINGS.md` §3-1-1 の「1行目=名称と右端固定のアクション、2行目=バッジ」にも反している。またワークフロー管理一覧の独立スクロールとペイン高さ連動が未設計。
  4. なぜこのアプローチを採用するか: Node Mapping Masters は `SPEC_SETTINGS.md` §3-1-1 準拠の2行カード＋バッジ整理で視認性を回復し、ワークフロー管理は `SPEC_SETTINGS.md` §3-1-1 に `MUI-02` 例外を明記した上で `xl` グリッドの短い側セル基準の内部スクロールへ整備する。
  5. 根本原因: `SettingsResponsive.css:159-184` / `MappingMasterSection.tsx:85-175`（Type A）および `WorkflowConnectionSection.tsx:702-704` / `SettingsPage.tsx:108-130` / `SPEC_SETTINGS.md:151-157`（Type B）。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - Node Mapping Masters 行の1行目で名称と操作ボタンを明確に分離し、2行目で入力型・Variant数・ステージ状態バッジを視認できるようにする。
  - **Interaction (インタラクション)**:
    - 大量ワークフロー時にワークフロー管理一覧内を独立して縦スクロールでき、ページ全体の縦長肥大化を防ぐ。
  - **Visual (視覚デザイン)**:
    - `xl` 2カラムグリッドで左右ペインの高さバランスを保ち、短いほうのセルに合わせて長いほうを内部スクロールさせる。
- **Requirement**:
  - **1. Node Mapping Masters 行レイアウト修正（Type A）**:
    - デスクトップ（>=768px）およびモバイル（<768px）の双方で、タイトルがステージ状態バッジに押し潰されて埋没しないこと（1行目: 名称＋右端固定アクション、2行目: バッジ、および必要に応じたバッジのコンパクト化）。
  - **2. ワークフロー管理の内部スクロール・左右ペイン高さ整合（Type B）**:
    - `SPEC_SETTINGS.md` §3-1-1 を更新（`SPEC_COMMON.md` MUI-02 例外として明記）し、`xl` 2カラムグリッドで左右ペインの短いほうの高さに合わせて長いほうが内部スクロールするようにする。
- **Acceptance criteria**:
  - [ ] AC-1: Given Settings画面の `workflows` タブで複数のステージVariantを持つ Node Mapping Master が表示されている, When デスクトップ幅（`xl` 2カラム）およびモバイル幅（<768px）で表示する, Then マスタのタイトルがステージ状態バッジに圧迫されて埋没せず視認でき、1行目に名称と右端固定アクション、2行目にバッジが配置されていること。
  - [ ] AC-2: Given Settings画面の `workflows` タブで多数のワークフローが登録されている, When `xl`（>=1280px）2カラムで表示する, Then 左右ペインのグリッドセルのうち短いほうの高さに合わせて長いほう（ワークフロー管理一覧等）が内部スクロールし、左ペインだけが縦に長くなりすぎないこと。
  - [ ] AC-3: Given `SPEC_SETTINGS.md` §3-1-1 にワークフロー管理一覧の内部スクロール仕様（`SPEC_COMMON.md` MUI-02 例外）と左右ペイン高さ整合ルールが記載されている, When 既存の SettingsPage 単体・統合テストおよび Playwright E2E テストを実行する, Then すべての検証ゲートが PASS すること。
- **Inferred points**:
  - 右ペイン（MappingMasterSection）が短い場合に左ペイン（ワークフロー管理）を合わせるか、あるいは両方／短い側基準を CSS Grid / ResizeObserver / max-height のいずれで実現するかは `/dev-design` で設計する。
- **Design doc**: docs/design/REQ-430.md
