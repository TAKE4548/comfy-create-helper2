### REQ-415: ノードマッピング編集時のモバイルにおけるタイトル検索パターン追加不能不具合

- **Type**: bug (Type B: Specification Gap)
- **Status**: done (2026-11-06)
- **Priority**: P1
- **Surface**: Frontend (`PatternTagInput.tsx`, `MappingMasterEditModal.tsx`), Docs (`REQ-340.md`, `SPEC_COMMON.md`)
- **Incident Report**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. なぜスマホでタイトル検索パターンを追加できないか: 文字列入力後に仮想キーボードでEnterを押してもパターンチップとして追加されず、直下の「Role上書き」入力欄へフォーカスが遷移してしまうため。
  2. なぜフォーカスがRole上書きへ遷移してしまうか: `MappingMasterEditModal` の `<form>` 内において、`PatternTagInput` の `<input>` 直後にバリアント一覧の `custom_role_override`（Role上書き）入力欄が並んでおり、仮想キーボード（iOS/Android）がEnterを「次へ（Next）」と判定してネイティブフォーカス移動を先行実行するため。
  3. なぜEnter押下によるタグ追加や代替手段が機能しないか: `PatternTagInput` に `enterKeyHint="done"` がなくEnterのform遷移抑止が効かない上、`FallbackParamsInput` のようなタップ用「追加」ボタンや `onBlur` 時の自動確定フォールバックが存在しないため。
  4. なぜ「追加」ボタンやモバイル仮想キーボード対応が実装されていなかったか: REQ-340設計時（`docs/design/REQ-340.md §3.2`）にデスクトップ物理キーボード前提のEnter/Paste/インライン編集のみが規定され、モバイル環境での仮想キーボード挙動やタップ操作用「追加」ボタンの要件が欠落していたため。
  5. 根本原因: SSoT（REQ-340およびSPEC_COMMON）におけるモバイル入力・タッチ操作代替経路（MUI-10）要件の欠落（Specification Gap）。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - パターン追加用入力欄と確定操作導線（追加ボタン）を視覚的に一体化して提供し、入力状態と確定アクションを明確にする。
  - **Interaction (インタラクション)**:
    - モバイル仮想キーボードのEnter（完了）押下、明示的な「追加」ボタンのタップ、および入力完了後のフォーカス離脱（onBlur）のいずれでもパターンチップが確実に追加される。
    - 日本語IME変換中のEnter押下（確定操作）で誤って途中文字列がタグ化されないようガードする。
  - **Visual (視覚デザイン)**:
    - `FallbackParamsInput` と統一されたスタイル（`<Plus size={12} />` アイコン付きの「追加」ボタン）を入力欄の右側に配置し、44×44pxのHit-Slopを担保する。
- **Requirement**:
  - **1. SSoT仕様改定（REQ-340 / SPEC_COMMON）**:
    - `docs/design/REQ-340.md` §3.2 および `docs/specs/SPEC_COMMON.md` に、`PatternTagInput` におけるモバイル・タッチ操作要件（タップ追加ボタンの設置、enterKeyHint、IME/フォーカス離脱時の確定）を明記する。
  - **2. PatternTagInput への「追加」ボタン新設**:
    - `PatternTagInput.tsx` に、`FallbackParamsInput.tsx` と同様のタップ用「追加」ボタン（`<Plus size={12} />` 付き）を配置し、タップで `addTag` を実行可能にする。
  - **3. 仮想キーボード制御（enterKeyHint）とEnterフォーム遷移抑止**:
    - input要素に `enterKeyHint="done"` を付与し、仮想キーボード上で確定アクションを表示させてフォーム内の「次へ」遷移を抑止する。
  - **4. フォーカス離脱（onBlur）時の自動追加フォールバック**:
    - 入力欄に未追加文字列が残った状態でフォーカスが外れた場合（他フィールドへの遷移や外側タップ）、自動的に `addTag` を試みる（空文字・重複時は無視）。
  - **5. 日本語IME確定ガード**:
    - `handleKeyDown` において `e.nativeEvent.isComposing` または `e.keyCode === 229` の場合にEnterによるタグ追加を抑止し、IME変換確定後のEnterでのみ追加を許可する。
- **Acceptance criteria**:
  - [ ] AC-1: Given `PatternTagInput` の入力欄に文字列が入力されている状態, When 画面上の「追加」ボタンをタップ／クリックしたとき, Then 入力された文字列が新たなパターンチップとして追加され、入力欄がクリアされること
  - [ ] AC-2: Given モバイル仮想キーボード等で `enterKeyHint="done"` が設定された `PatternTagInput` の入力欄, When 仮想キーボードの確定／完了キー（Enter）を押下したとき, Then 直下の「Role上書き」入力欄へフォーカス移動せず、パターンチップが追加されること
  - [ ] AC-3: Given `PatternTagInput` の入力欄に文字列を入力したまま, When 別の入力フィールド（Role上書き等）にフォーカスが移動（Blur）したとき, Then 入力されていた有効な文字列がパターンチップとして自動的に追加されること
  - [ ] AC-4: Given 日本語IME入力中（isComposing = true）, When 変換候補確定のためにEnterキーを押下したとき, Then タグの追加処理は発火せず、変換確定後のEnter押下でのみパターンチップが追加されること
  - [ ] AC-5: Given 入力欄が空文字または既存パターンと重複している状態, When 「追加」ボタンの押下またはEnter押下されたとき, Then 「追加」ボタンは非活性（disabled）となり、重複パターンは追加されないこと
- **Inferred points**:
  - `FallbackParamsInput.tsx` とのUI一貫性を保ち、CSSクラスやボタンサイズ（44px Hit-Slop）を共通化する。
- **Design doc**: docs/design/REQ-415.md
