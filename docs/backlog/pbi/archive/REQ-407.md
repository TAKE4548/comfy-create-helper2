### REQ-407: Gate 3 の E2E 実行手順を、手順書どおりに実行して成立するよう直す

- **Type**: chore（文書）
- **Status**: frontmatter の `status` を参照（状態の正本）。
- **Priority**: P2（検証手順の誤解を防ぐ改善。仮置き）
- **Surface**: Gate 3（実ブラウザ E2E）の実行手順を記載している文書。確認できた記載箇所は `.agents/context.md`（Gate 3）、`docs/specs/SPEC_TEST_ARCHITECTURE.md` §6（実行ゲート表）、`README.md`（`npx playwright test`）。
- **利用者ニーズ**: 開発者・検証担当が手順書どおりに Gate 3 を実行したとき、E2E が成立し、環境の不備による大量の失敗に惑わされないようにしたい。
- **課題の整理（事実）**: `.agents/context.md` の Gate 3 は `cd frontend; npx playwright test` と書いている。しかし `playwright.config.ts` に `webServer` がなく、dev server（5173）を先に起動しないと、300 件が接続拒否で失敗する。正式な Gate 3 は `scripts/run_e2e.py` で、これが dev server を起動する。
- **5 Whys**:
  1. なぜ起票するか: 手順書どおりに E2E を実行すると、300 件が接続拒否で失敗するため。
  2. なぜ失敗するか: 手順書のコマンドは、dev server が起動済みであることを前提としているが、その前提が書かれていないため。
  3. なぜ前提が抜けたか: 正式な Gate 3 の実行が `scripts/run_e2e.py`（dev server の起動を含む）へ移った後も、手順書の記載が直接実行のコマンドのまま残っているため（推定）。
  4. なぜ見過ごされてきたか: 開発中に dev server が起動済みの環境では直接実行でも成立し、問題が表面化しにくいため（推定）。
  5. 根本原因: Gate 3 の正式な実行方法と前提が、手順書のどこにも一貫して記載されていない。
- **UX Classification**: N/A（開発者向けの検証手順の文書改善であり、製品利用者向けの Information Design / Interaction / Visual には当たらない）。
- **Requirement**: Gate 3 の手順書の記載どおりに実行すると、事前知識なしで E2E が成立すること。正式な Gate 3 の実行方法（wrapper を使うか、前提を明記するか）が、手順を載せたすべての文書で一貫して分かること。

## 範囲

- 対象: Gate 3 の実行手順を記載している文書の記述の是正（`.agents/context.md`、`docs/specs/SPEC_TEST_ARCHITECTURE.md` §6、`README.md`）。
- 対象外: Playwright の構成（`playwright.config.ts` への `webServer` 追加など）、`scripts/run_e2e.py` の変更。本番バンドル専用 E2E（`playwright.prod.config.ts`）の手順。個別の E2E テストの内容。

## Acceptance Criteria

- [ ] AC-1: 手順書どおりに実行すると E2E が成立する
  - Given dev server（5173）が起動していない新しいシェル
  - When Gate 3 の手順書（`.agents/context.md` の Gate 3 の記載）に書かれたとおりに、ほかの知識なしで実行する
  - Then 接続拒否による失敗が 0 件で、E2E のテストが実際に収集・実行され、結果が合否として報告されること
- [ ] AC-2: 正式な Gate 3 の実行方法が分かる
  - Given Gate 3 の実行手順を記載した文書
  - When 正式な実行方法を探す
  - Then 正式な Gate 3 が `scripts/run_e2e.py` を使う方法であることが記載され、それ以外のコマンドを載せる場合は、そのコマンドが正式な Gate 3 ではないことと前提（dev server の事前起動）が併記されていること
- [ ] AC-3: 直接実行する場合の前提が併記される
  - Given 手順書が `npx playwright test` を直接実行するコマンドを載せている（局所実行を含む）
  - When そのコマンドを読む
  - Then dev server（5173）を先に起動する必要があることと、未起動の場合に接続拒否で失敗することが、同じ箇所に記載されていること
- [ ] AC-4: 手順を載せた文書の記述が互いに矛盾しない
  - Given `.agents/context.md`、`docs/specs/SPEC_TEST_ARCHITECTURE.md` §6、`README.md`
  - When Gate 3 の実行方法の記述を比較する
  - Then 正式な実行方法と前提が 3 文書で矛盾せず、内容が一致していること
- [ ] AC-5: 他の箇所に同じ誤記が残らない
  - Given 本 PBI の変更後のリポジトリ
  - When 現行の文書（作業用の worktree、過去の PBI・設計・ログの記録を除く）で `npx playwright test` を探す
  - Then 見つかったすべての記述が AC-2 と AC-3 を満たすこと
- [ ] AC-6: Gate 3 の検証対象と収集件数が変わらない
  - Given 本 PBI の着手前の Gate 3 のテスト収集件数
  - When 変更後に Gate 3 のテスト収集件数を確認する
  - Then 件数が着手前と同じで、本番バンドル専用 E2E（`playwright.prod.config.ts`）が Gate 3 の既定の対象外のままであること
- [ ] AC-7: 変更が文書に限られる
  - Given 本 PBI の変更差分
  - When 変更されたファイルを確認する
  - Then 変更が文書および PBI・設計の記録に限られ、Playwright の構成、`scripts/run_e2e.py`、テストコードが含まれないこと
