### REQ-229: 端末間（マルチデバイス）でのプリセット同期不具合の修正とSSoT整合性の確立

- **Type**: defect
- **Status**: done (2026-09-08)
- **Current step**: none
- **Priority**: P1
- **Surface**: 端末を跨いだ時、別の端末で編集したプリセットが、同期で反映されない
- **Root Cause**: `usePresetState` における `existingSet?.paramValues` のローカル優先マージによるサーバー更新値の破棄、初回同期フラグ以降のストア更新欠落、および TanStack Query の `PersistQueryClientProvider` による古い LocalStorage キャッシュでの初回同期消費
- **Requirement**: 端末Aで編集・保存されたプリセットが端末B側でも確実に同期・反映され、サーバーDB（SSoT）の最新状態が手元の古いキャッシュやメモリステートに握りつぶされないようにする
- **Design doc**: docs/design/REQ-229.md

#### Acceptance Criteria (AC)
- [x] AC-1: 端末Aでプリセット（プロンプト・パラメータ等）を編集・保存後、端末Bでワークフロー画面を開く、あるいは画面表示中に再取得された際、端末Aの最新の `param_values`, `applied_assets`, `batch_size`, `seed_mode`, `seed` が端末BのUIおよびストアに即時反映されること。
- [x] AC-2: 端末B起動時、`PersistQueryClientProvider` による古い LocalStorage キャッシュによって最新サーバーデータの反映が阻害・破棄されないこと。
- [x] AC-3: 端末Aで新規作成されたプリセットが、端末Bのプリセット一覧およびタブバー（または管理モーダル）から正常に認識・同期できること。
- [x] AC-4: プリセット切り替え時または更新受信時に、プロンプト入力欄（`TagChipEditor`）のチップ状態が最新プロンプト文字列に基づき正しく再構築・同期されること。
- [x] AC-5: 既存のOCC楽観的ロック（409 Conflict検知と自動リカバリ）が破壊されず、回帰テストが全件パスすること。
