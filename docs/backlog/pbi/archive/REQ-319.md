### REQ-319: Prompt Surgeon: LoRA Studio（素材直交生成・キュレーション・ローカル学習・4軸ストレステスト評価）統合機能

- **Type**: feature
- **Status**: done (2026-10-07)
- **Current step**: none
- **Priority**: P1
- **Surface**: 	mp/lora_studio_spec.html および 	mp/lora_studio_ui_mockup.html に基づき、Prompt Surgeon 内にキャラクターLoRAの素材バッチ生成、キャプション・キュレーション、ローカル学習ディスパッチ、4軸ベンチマーク検証を一気通貫で完結できる専用ワークスペース「LoRA Studio」を新設・統合したい。
- **5 Whys / Root Cause**:
  1. なぜ新設が必要か: キャラクターLoRAの作成において、プロンプトの設計・バッチ生成・服装や特徴のタグ分離（デカップリング）・学習スクリプト実行・モデル検証の手順が分断されており、多大な手作業と試行錯誤が発生しているため。
  2. なぜ手作業が破綻しやすいのか: プロンプトを手動で乱雑に設定すると、立ち姿ばかり偏ったり特定の衣装装飾がキャラクター本体に癒着（衣装ベイクイン）して着せ替えが不可能になるため。
  3. なぜ衣装癒着やポーズ硬直が起こるのか: 直交計画（DOE）に基づく構図・表情・アングルの交絡排除と、専用衣装と別衣装の系統分離、およびキャプションでの厳密なタグ除去（ストリップ）処理が行われていないため。
  4. なぜローカル学習と検証のハードルが高いのか: WSL2/CLIでのパラメータ計算（総ステップ数、エポック、リピート）やハードウェア固有設定（bf16、TE Freeze、勾配チェックポイント）の把握が難しく、生成されたLoRAの品質（分離度・再現度・ポーズ追従・アングル追従）を網羅的にテストする仕組みがないため。
  5. 根本原因: Prompt Surgeon 内に、直交データセット生成からデカップリング・キャプション変換、ローカル学習ディスパッチ、4軸ストレステスト評価までを構造的・機械的に担保するEnd-to-EndのLoRAスタジオ機能が存在しないこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - Step 1〜4のウィザード型ワークスペース（マトリクス生成 → キュレーション → 学習ディスパッチ → 4軸ストレステスト）。
    - 3分割キャラ定義（①メタ情報、②身体的特徴、③専用服装）とキャラ/衣装トリガー命名の連動体系。
    - 学習スケジュール数式（総ステップ数、チェックポイント数）の動的表示と、全ハイパーパラメータの数学的意味・推奨値Tooltip解説。
    - 4列（衣装分離、衣装再現、ポーズ追従、アングル追従）× 3行（強度0.6, 0.8, 1.0）の4×3ベンチマークマトリクスおよび推奨運用強度（スイートスポット）の提示。
  - **Interaction (インタラクション)**:
    - GeneratePage共通のTagChipEditorによるタグ追加/削除/並替/テキスト切替/アセット添付。
    - バックエンドをプロキシしない、フロントエンドからComfyUI（Port 8188）への直接バッチ投入とWebSocketリアルタイム進捗受信（切断時の再接続制御含む）。
    - 不良画像の1枚単位での単発リロール機能（プロンプト・キャプション構造を維持したシード再生成）。
    - 手動オーバーライド可能なセマンティックキャプション編集と、学習用画像＋.txtキャプションペアの一括フォルダエクスポート。
    - WSL2上の学習サブプロセスの非同期起動、停止ボタンによる安全なプロセス中断、リアルタイムLoss/VRAM/温度テレメトリ監視。学習実行中の生成抑止（GPU競合防止）。
    - 1クリックでの4軸×3強度（計12件）テストプロンプト自動展開とComfyUI一括投入。
  - **Visual (視覚デザイン)**:
    - Prompt Surgeon共通のダークテーマ（#0F0F11、#18181C、グリーン・パープル・ブルーアクセント）。
    - 採用/除外のステータスバッジ、Loss収束SVGチャート、VRAMリソースバー、ターミナルログ表示エリア。
    - 4×3検証グリッドでの比較カード、拡大モーダルによる細部検証、推奨強度のハイライトカード。
- **Requirement**:
  - **Step 1: 素材マトリクス生成**:
    - 専用ページ（DatasetStudioPage）を開き、キャラトリガー名・本命衣装トリガー名を入力・連動管理可能とする。
    - GeneratePageと共通のTagChipEditorを用い、「①メタ情報」「②身体的特徴」「③専用服装」の3系統でタグ入力を行う。
    - 別衣装マスタから複数のプリセット衣装（パーカー、部屋着、水着、スーツ等）を選択可能とし、20件中5件（25%）の別衣装枠へ均等配分する。
    - 直交計画（DOE）ソルバーにより、設定された水準因子プールから交絡を最小化するN件（デフォルト20件）の直交プロンプト群を算出する。
    - フロントエンドからComfyUI（Port 8188）へ直接バッチ投入を行い、WebSocket経由で進捗をリアルタイム表示する。通信切断時の再試行・復帰制御を備える。
  - **Step 2: キュレーション & キャプション自動変換**:
    - 生成された全スロットのサムネイル一覧を表示し、APPROVED / REJECTEDのステータス管理を行う。
    - ②身体的特徴の入力タグを自動消去（ストリップ）してキャラトリガーへ置換し、本命衣装枠では③専用服装のタグを消去して衣装トリガーへ置換するデカップリングキャプションを自動生成する。ユーザーによる個別タグ編集・手動オーバーライドも可能とする。
    - サムネイルごとの単発リロールを実行可能とし、プロンプト・キャプション構成を維持したまま画像のみをインプレース更新する。
    - 画像ファイルと同名の.txtファイルペアを指定ディレクトリへ一括出力し、DB側メタデータとの整合性を保持する。
  - **Step 3: ローカル学習ディスパッチャー**:
    - Max Epochs、Repeats、Batch Size、Save Intervalの入力値から総ステップ数および保存チェックポイント数を動的に算出して表示する。
    - 各パラメータの?アイコンホバー時に、数学的・物理的意味およびハードウェア推奨値のTooltipを表示する。
    - 学習実行中はGPUリソース競合を防ぐため生成ジョブの実行をガードする。
    - バックグラウンドでWSL2上の学習プロセスを非同期起動し、WebSocketを通じてLoss・ステップ・VRAM・温度をリアルタイムストリーミング表示する。緊急停止ボタンによる安全なプロセス停止および出力チェックポイントの完全性検証を行う。
  - **Step 4: 4軸ストレステスト自動評価**:
    - 学習済み成果物（.safetensors）の存在を確認後、トリガー名に基づき「衣装分離」「衣装再現」「ポーズ追従」「アングル追従」の4項目×3強度（0.6, 0.8, 1.0）の計12件の検証用プロンプトを固定シードで自動生成し、ComfyUIへ一括投入する。
    - 生成結果を4×3の比較マトリクスグリッドで表示し、分離・再現・追従の成否を並列確認可能とする。
    - テスト結果から推奨運用強度（スイートスポット: 0.75〜0.85）を自動判定・ハイライト表示する。
- **Acceptance criteria**:
  - [ ] AC-1: Given ユーザーが素材スタジオのStep 1（素材マトリクス生成）を開いたとき, When 「①メタ情報」「②身体的特徴」「③専用服装」の各欄を操作した際, GeneratePageと同一のタグチップ編集（追加、削除、ドラッグ語順入替、テキストモード切替、アセット添付バー）が動作し、キャラトリガー名および本命衣装トリガー名と入力値が連動管理されること。
  - [ ] AC-2: Given ユーザーが別衣装マスタ一覧から複数のプリセット衣装を選択したとき, When 直交マトリクスを生成した際, 全20件中5件（25%）の別衣装枠に対して選択したプリセット衣装が均等に割り振られ、③専用服装の装飾タグが一切混入しないこと。
  - [ ] AC-3: Given 直交計画の各因子（ショット、アングル、表情、ポーズ、衣装枠）が設定されているとき, When 「直交マトリクス再計算」および「ComfyUIに20件直接投入」を実行した際, ショット・構図因子の交絡を排除した全20件の直交プロンプト群が算出され、バックエンドを画像プロキシせずフロントエンドからComfyUI（Port 8188）へ直接バッチ投入され、WebSocketによりリアルタイムに進捗が更新されること。
  - [ ] AC-4: Given Step 1で生成された素材アイテムが存在するとき, When Step 2（キュレーション & キャプション）でキャプションを確認・プレビューした際, ②身体的特徴の入力タグが自動的に完全消去（ストリップ）されてキャラトリガー名へ置換され、本命衣装枠では③専用服装の入力タグが消去されて衣装トリガー名へ置換され、別衣装枠では別衣装タグがそのまま保持されて衣装トリガー名が含まれず、必要に応じてユーザーがテキストを手動編集できること。
  - [ ] AC-5: Given 生成された20枚の素材画像があるとき, When 不良画像のサムネイル上で単発リロールを実行した際, 当該スロットのプロンプト構成およびキャプション定義を維持したまま新規シードでComfyUIへ単発再生成が行われて画像がインプレース更新され、また「学習用フォルダ一括出力」実行時に画像と同名の.txtファイルペアが指定フォルダに書き出されること。
  - [ ] AC-6: Given Step 3（ローカル学習統合）のパラメータ設定画面において素材枚数、リピート数、バッチサイズ、エポック数が入力されたとき, When パラメータ画面および各項目のヘルプアイコン（?）を確認した際, 総学習ステップ数が計算式に基づき動的に算出・表示され、Network Dim, Alpha, LR, Mixed Precision等の各パラメータにマウスホバーした際に数学的・物理的意味およびハードウェア推奨値の解説Tooltipが即座にポップアップ表示されること。
  - [ ] AC-7: Given 学習用データセットと学習パラメータが準備されているとき, When 「学習プロセス起動」を実行した際, ローカル学習プロセスが非同期に起動し、リアルタイムにLoss値、ステップ進捗、VRAM使用量等のテレメトリが受信されてLoss曲線グラフおよびターミナルログへ描画され、停止ボタンによる安全なプロセス中断が可能であること。
  - [ ] AC-8: Given 学習済みLoRAモデルの成果物（.safetensors）の完全性が確認されたとき, When Step 4（4軸ストレステスト評価）でベンチマークテストを実行した際, 設定されたトリガー名に基づき「①衣装分離」「②衣装再現」「③ポーズ追従」「④アングル追従」の4項目×3段階の強度（0.6, 0.8, 1.0）の計12件の検証用プロンプトが固定シードで自動生成されてComfyUIへ一括投入されること。
  - [ ] AC-9: Given 12枚の検証画像の生成が完了したとき, When 評価グリッド画面を表示した際, 4列（テスト軸）× 3行（強度）のマトリクスで画像と判定ステータスが並列比較表示され、各セルの詳細確認が可能であるとともに、分離・再現・追従の成否傾向から推奨運用強度（スイートスポット）が自動ハイライト・提示されること。

  - 既存のGeneratePageのTagChipEditor資産を再利用し、一貫した操作感を提供する。
