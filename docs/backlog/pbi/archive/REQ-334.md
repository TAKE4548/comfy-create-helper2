#### 利用者の目的 / 5 Whysの結論

1. なぜ見直すか：資料では生成条件の編集、画像確認、アセット整理の往復で作業が滞り、誤取消が起こるとされている。
2. なぜ滞るか：入力・進捗・生成操作の配置が競合し、端末幅によって重要操作を見つけにくい。
3. なぜ整理にも手間がかかるか：大量の画像・アセットに単件操作を繰り返し、画像と情報を同時に確認しにくい。
4. なぜ機能追加だけでは解決しないか：選択・取消・モーダル・ナビゲーションの規律と情報の強弱が画面間で揃わないため。
5. 根本的な運用ニーズ：端末幅に左右されず生成→確認→調整と一括整理を続けられ、不可逆操作の対象と結果を正しく把握できる作業環境が必要。

上記は添付からの推定であり、ユーザーへの5回の質問実施や現行画面の実測を意味しない。

#### UX Classification

- **Information Design**: 入力/実行の配置、二段進捗、キュー対象・状態、Studio工程、設定5タブ、検索・件数・保存状態。
- **Interaction**: ショートカット、分割比率、複数選択、一括操作、安全確認、ステップ調整、タグ編集、画像比較。
- **Visual**: ダーク配色、文字・数値、アイコン、カード画像面積、選択・否認表示、画面幅に応じた表示。

#### Requirement / 対象とロードマップ

添付の全9章・全20項目をひとつの改修要求として記録する。新しい利用者向け機能も含む。内部構造や採用ライブラリは指定しない。Task Card分割・依存関係は承認後の設計で具体化する。

#### 検証条件・共通定義

表示幅はCSS px。境界767/768/1023/1024、代表390/800/1440/2560、高さ900（Mobile844）。画像は2:3・1:1・明色画像、件数は0/1/複数。各ACの列挙は独立したパラメータ化ケースとして検証する。図のダミー値や「約」「100%視認」「90%無彩色」は達成保証へ転記しない。

| 表示属性 | 要求値 |
|---|---|
| 見出し/本文/補助/非活性の基本文字色 | #F4F4F5 / #D4D4D8 / #A1A1AA / #71717A |
| 最背面/主要面/カード/上位面の基本背景色 | #09090B / #121215 / #18181C / #202024 |
| 区切り/カード・入力/強調の白境界不透明度 | 6% / 10% / 18%（カード上辺ハイライト8%） |
| モーダル外枠/ボタン・入力・カード/チップ・バッジの角丸 | 12 / 8 / 6px |
| 主目的操作/AI支援/警告/削除・例外 | #3ECF8E / #7C6FDD / 琥珀 / 赤 |
