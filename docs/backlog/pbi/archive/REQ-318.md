### REQ-318: Prompt Surgeon: FuguMT 文脈保持型ハイブリッド和訳（タグ辞書引き＆非マッチ文単位推論統合）

- **Type**: enhancement
- **Status**: done (2026-10-07)
- **Current step**: none
- **Priority**: P2
- **Surface**: Prompt Surgeon のプロンプト和訳処理において、自然文（関係詞節や分詞構文などカンマを含む文）がカンマ単位で無条件に細切れに分割され、文脈崩壊や主述関係の喪失が発生しているため、Danbooruタグ即時辞書引きと辞書非該当部の文単位一括推論を統合した階層的ハイブリッド和訳パイプラインへ改修する。
- **5 Whys / Root Cause**:
  1. なぜ変更が必要か: カンマを含む自然文プロンプト（例: A cute girl with silver hair, who is reading a book under an oak tree, smiles gently.）を入力した際、カンマごとに文が分断され、修飾関係や主述関係が破綻した不自然な日本語訳になってしまうため。
  2. なぜカンマで分断されてしまうのか: 翻訳サービスがプロンプト分割時にカンマとピリオドを一律の区切り文字として扱い、カンマごとに独立したチャンクとして推論に流しているため。
  3. なぜカンマを一律の区切り文字としていたのか: 従来のプロンプトが Danbooru タグ中心（1girl, cat_ears, solo 等）であり、カンマで区切られたトークンを個別に辞書引きまたは翻訳すれば十分だったため。
  4. なぜ現代のプロンプトで破綻するのか: Flux や SD3、Anima などの最新モデルでは Danbooru タグとカンマを含む複文・修飾節を混在させた記述が多用され、FuguMT (MarianMT) 本来の系列変換・文脈理解能力を発揮させるには文全体の塊で入力する必要があるため。
  5. 根本原因: カンマの役割が「タグの列挙区切り」と「自然言語文内の節・句区切り」の2通り存在するにもかかわらず、プロンプト分割設計が階層化されておらず、すべてのカンマを一律にトークン境界として扱っていたこと。
- **UX Classification**:
  - **Information Design (情報設計)**: 辞書登録された定型タグと、文脈保持が必要な自然言語表現の境界を階層的に整理。文構造（主節・従属節・修飾語）を維持した自然な翻訳結果として再構成し、情報伝達精度を向上。
  - **Interaction (インタラクション)**: ユーザーがプロンプトを入力・確認する際、カンマを含む長文や重み付け構文（( ... :1.2)）が含まれていても、意図した意味と強度が保たれた自然な日本語訳が遅延なく提示される。
  - **Visual (視覚デザイン)**: 和訳結果の表示において、カンマごとに細切れになった意味不明なタグチップの乱立を防止し、1つの完結した意味単位として視認性の高いまとまりで提示する。
- **Requirement**:
  - **階層的プロンプト境界分割**:
    - 大枠の文境界（ピリオド＋空白・終端、改行、感嘆符/疑問符）と、文内部のタグ区切り（カンマ、読点）を分離して処理する。
    - プロンプト末尾にピリオドがない場合や、複数の文が含まれる場合でも、文の脱落なく正確に文ブロックとして認識する。
    - 連続するカンマや空チャンク（例: 	ag1,, tag2）は事前にサニタイズされ、空文字列の無駄な推論を防止する。
  - **Danbooru タグ優先辞書照会と非マッチ要素の文脈再結合**:
    - 文ブロック内の各要素について、Danbooru 辞書との完全一致照会（小文字化、スペースとアンダースコアの相互正規化）を先行して実施する。
    - 辞書に一致した定型タグは即時採用（0ms）とし、推論モデルへの無駄な送信を防止する。
    - 辞書に一致しなかった連続する要素（自然言語の節や句）は、元のカンマを保持した完全な1つの英文として再結合し、FuguMT へ送信して文単位で文脈を考慮した推論を行う。
  - **重み付け構文および特殊トークンの保護**:
    - 強度構文（例: (( ... :1.2))）は文境界・タグ分割よりも優先して外側の括弧・倍率をアンパックし、翻訳後に余剰な空白を除去して正確に再パックする。
    - 特殊構文（LoRA、Embedding 等）のメタトークン退避および復元処理と整合性を維持する。
  - **結果のマージと順序整合性**:
    - 辞書引き結果と FuguMT の文単位推論結果を、元のプロンプトの出現順序通りに整列・マージして出力する。
    - 既存の Frontend API レスポンス形式および UI カード構造に対する後方互換性を厳密に維持する。
- **Acceptance criteria**:
  - [ ] AC-1: Given Danbooru 辞書に登録された既知タグのみで構成されたプロンプト（例: 1girl, solo, silver_hair, cat_ears, masterpiece）が入力されたとき, When 和訳処理を実行した際, すべてのタグが Danbooru 辞書の対訳を用いて即時変換され、不必要なモデル推論が発生しないこと。
  - [ ] AC-2: Given カンマを含む関係詞節や分詞構文からなる自然文プロンプト（例: A cute girl with silver hair, who is reading a book under an oak tree, smiles gently.）が入力されたとき, When 和訳処理を実行した際, 内部のカンマによって文が細切れに分断されず、1つの完結した文として主述・係り受け関係が保たれた自然な日本語訳が得られること。
  - [ ] AC-3: Given Danbooru タグとカンマを含む自然文が混在したプロンプト（例: masterpiece, 1girl, A girl wearing a white dress, sitting on a bench, looks at viewer. best quality）が入力されたとき, When 和訳処理を実行した際, 辞書一致タグ（masterpiece, 1girl, est quality）は辞書訳が適用され、非一致の自然文部分は1文として文脈を考慮して和訳され、出力において元の出現順序が保持されていること。
  - [ ] AC-4: Given 自然文全体が強度指定括弧で囲まれたプロンプト（例: ((A girl holding a cat, smiling happily:1.2)), solo）が入力されたとき, When 和訳処理を実行した際, 外側の強度構文が保護された状態で内部の自然文が適切に和訳され、出力結果において前後の余分な空白を含まずに元の強度倍率と括弧のネスト構造（例: ((猫を抱いて幸せそうに微笑んでいる少女:1.2)), ソロ）が正確に復元されていること。
  - [ ] AC-5: Given ピリオドまたは改行で区切られた複数の自然文からなるプロンプトが入力されたとき, When 和訳処理を実行した際, 各文境界が正しく識別され、訳抜けや境界の脱落を起こすことなく全ブロックが順序通りに和訳されること。
  - [ ] AC-6: Given 末尾にピリオドが存在しないカンマ付き自然文プロンプト（例: A girl sitting on a chair, reading a book）が入力されたとき, When 和訳処理を実行した際, 終端が文境界として正しく認識され、カンマによる細切れ分割を起こさずに一連の文として統合的に和訳されること。
  - [ ] AC-7: Given 連続カンマや末尾カンマを含むプロンプト（例: 1girl, , solo,）が入力されたとき, When 和訳処理を実行した際, 空白要素が安全に無視され、エラーや空文字列の推論呼び出しを発生させることなく正常に処理が完了すること。
