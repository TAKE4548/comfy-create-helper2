### REQ-231: Prompt SurgeonおよびComfyUIサービスの一括ライフサイクル管理
- **Type**: enhancement
- **Status**: done (2026-09-09)
- **Current step**: Phase 1: Requirement Intake & Refinement
- **Priority**: P2
- **Surface**:
  - 「ツールのサービス、ComfyUIを手軽に起動できるようにしたい。@[tmp/windows_wsl2_server_manager.md] イメージはこんな感じ。」
  - 「1. wsl2で実行してる。ホームディレクトリでこんなshを実行してる（仮想環境アクティベート、環境変数設定、ComfyUI起動） / 2. ワンクリック（A）と常駐化（C）。CLI（B）も対応 / 3. 独立した画面表示。追々サービスrebootやログ確認等の機能拡張を前提としたい」
- **Root Cause**:
  - **UX Classification**: Interaction (ワークフローの摩擦 / 運用オーバーヘッド)
  - Prompt Surgeon の稼働に必要な各サービス（Windows上の Frontend, Backend）および WSL2 上で動作する ComfyUI を起動・停止・確認するために、個別コンソールを立ち上げて手動操作する必要があり、作業開始・終了時の運用負担と認知負荷が高い。
- **Requirement**:
  - Windowsホスト環境およびWSL2環境にまたがる複数サービス（Prompt Surgeon FE/BE、WSL2 ComfyUI）を一元的に管理し、ワンクリック起動・停止、状態確認、およびPC起動時の自動起動（常駐化）を容易に行えるライフサイクル管理基盤を提供する。
  - ComfyUIの生成進捗やコンソールログが視認可能であり、将来的なサービス個別再起動やログビュー機能等の拡張を受け入れ可能な構造とする。
- **Acceptance criteria**:
  - [x] AC-1: ワンアクション（ショートカット/バッチファイル等）により、Prompt Surgeon（FE, BE）および WSL2上のComfyUIが一括で起動され、各サービスが利用可能状態になること。
  - [x] AC-2: ComfyUIおよび各サービスの起動状況・実行ログが確認可能な画面表示（またはコンソール）が提供されること。
  - [x] AC-3: 稼働中の全サービスを一括で安全に停止、および稼働状態（リッスン/起動中/停止中）のステータス確認ができること。
  - [x] AC-4: PC起動時のバックグラウンド自動起動（常駐化）と、手動ワンクリック起動・停止の双方が行えること。
  - [x] AC-5: 将来的な個別サービスの再起動制御やログ参照ビューの追加に対応可能な、拡張性の高い制御構成・設定分離となっていること。
