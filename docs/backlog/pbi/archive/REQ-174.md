### REQ-174: セリフプリセット適用時のテキストロード不具合修正およびマイグレーション順序の是正

- **Type**: bug
- **Status**: ready
- **Priority**: P1
- **Surface**: テキスト付きのプリセットをロードした時に、テキストがロードされなくなっている。修飾はロードされている。
- **Root Cause**:
  1. **DBマイグレーション実行順序およびデータ引き継ぎ不整合**: `backend/app/main.py` の `run_migrations` において、`speech_bubble_presets` の一意制約マイグレーション（テーブル再構築）が `text` カラム追加処理より前に実行されていたため、既存テーブルに `text` カラムがない場合やマイグレーション時に `text` が正しく引き継がれず `NULL` にリセットされるリスクが存在する。
  2. **フロントエンドのテキスト適用およびテストケースの検証漏れ**: `SpeechBubbleControls.tsx` の `handleApplyPreset` において `preset.text` の適用条件が厳密であり、フロントエンド単体テストで「テキストを含むプリセットをロードした際に `onUpdate({ text: ... })` が呼ばれること」の検証が網羅されていなかった。
- **Requirement**:
  1. テキスト情報（`text`）を含むプリセットをクリック・選択してロードした際、エディタ上のテキスト入力エリアおよび吹き出しオブジェクトに保存されていたセリフテキストが確実にロード・反映されるようにする。
  2. `backend/app/main.py` の `run_migrations` において、`text` カラムの存在確認およびテーブル再構築時のデータ引き継ぎ順序を是正し、既存データの `text` が損失しない安全なマイグレーション構造にする。
  3. バックエンドおよびフロントエンドのテストスイートにおいて、テキスト付きプリセットの作成・取得・更新・適用の一連のライフサイクルを確実に検証するテストを追加する。
- **Acceptance criteria**:
  - AC-1: テキストを含むプリセット（`text` が非空文字列）をロード（クリック）した際、吹き出しのスタイル修飾とともに保存テキストがエディタ上の `text` として即座に反映されること。
  - AC-2: テキストを含まないプリセット（`text` が `null` または空文字）をロードした際、現在入力中のテキストが上書き・クリアされずに維持されること（非破壊ロード）。
  - AC-3: `backend/app/main.py` の `run_migrations` において、`text` カラムおよび `effects_json` カラムを含む既存データがテーブル移行時にも欠損なく安全に保持されること。
  - AC-4: バックエンドおよびフロントエンドの全自動テスト（`pytest`, `vitest`）が 100% PASS すること。
