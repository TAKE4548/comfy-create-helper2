### REQ-152: バッチ生成キュー登録時の不要オーバーヘッド削減およびキャンセル時状態復活デグレの修正

- **Type**: bugfix
- **Status**: done (2026-08-26)
- **Current step**: Verified & Archived
- **Priority**: P1
- **Surface**: バッチ・複数プリセット生成実行中において、キュー登録のレスポンスが重く、またキャンセルを実行しても直後にキャンセルしたはずのジョブ枠や生成中状態が復活してしまう。
- **Root Cause**:
  1. `handleGenerateSets` において、キャンセル操作（`cancelAllJobs` / `cancelJob`）でストアの `activeBatch` が `null` に初期化された後、投入ループ離脱時の `finally` ブロックで無条件に `setActiveBatch([...currentBatch])` および `fetchQueue()` が実行され、未投入のダミージョブを含むバッチ配列でストアが上書きされて生成状態が復活する（REQ-141のデグレ）。
  2. `useGenerationStore.ts` の `queuePrompt` 内 `fetch(/prompt)` に `AbortSignal` が渡されておらず、通信中にキャンセルしてもComfyUIへそのまま投入されてしまう。
  3. 逐次投入ループの各イテレーション毎に、ストアの `set({ isGenerating, ... })`、`handleGenerateSets` の `setActiveBatch()`、およびComfyUIからのWebSocket `status` 受信による `fetchQueue()` が連続発火し、メインスレッドとReact再レンダリングが飽和してUI応答が悪化している。
- **Requirement**:
  1. `handleGenerateSets` の `finally` 句において、`abortController.signal.aborted` が true の場合は `setActiveBatch` の上書きおよび `fetchQueue()` の呼び出しを抑止し、キャンセル後の状態復活を防止する。
  2. `queuePrompt` に `AbortSignal` を伝播し、キャンセル時に進行中の ComfyUI 投入リクエストをネットワーク層で即座に中断可能とする。
  3. 逐次投入中の冗長な中間ステート更新および WebSocket `status` による過剰なフェッチを抑制し、キュー登録およびキャンセル操作のUI応答性を最適化する。

#### Acceptance Criteria (AC)

##### 1. キャンセル中断時のステート復活防止と確実なクリーンアップ
- [x] AC-1-1: 複数プリセット・バッチ生成のキュー投入中に「一括キャンセル」または個別「キャンセル」を実行した際、`handleGenerateSets` の `finally` 処理によって `activeBatch` や生成中ステータスが復活せず、即座に停止・クリアされること。
- [x] AC-1-2: `queuePrompt` の ComfyUI 投入処理が `AbortSignal` に対応し、キャンセル時に進行中のHTTPリクエストが安全に中断されること。
- [x] AC-1-3: キャンセル後に未投入の仮ジョブ枠（`pending-...`）が画面上に残存しないこと。

##### 2. キュー逐次投入時のオーバーヘッド低減とUIレスポンス改善
- [x] AC-2-1: バッチ投入ループ実行中に、不要な重複状態更新や過剰な `fetchQueue()` が抑制され、UIやキャンセルボタンの操作遅延が発生しないこと。
- [x] AC-2-2: バッチ投入完了後に1回のみキュー状態が同期され、全ジョブの `promptId` が正常に確定すること。

##### 3. リグレッション防止
- [x] AC-3-1: 正常系での複数プリセット・バッチ生成において、REQ-141の 0ms pending 枠表示およびエラー時の特定通知機能が維持されること。
- [x] AC-3-2: 通常モード（デスクトップ）およびモバイルモードの双方において、生成・キャンセル動作がリグレッションなく動作すること。
