### REQ-058: マスタマッピングのサンプラ・スケジューラ選択肢の分離と初期アップロード時の設定値反映

- **Type**: enhancement
- **Status**: ready
- **Current step**: none
- **Priority**: P1
- **Surface**: サンプラ選択などをマスタマッピングに追加して入力欄を生成することはできるが、選択肢がLora一覧になってしまう。設定値の対象によって、適切な選択肢を表示できるようにしたい。また、初期アップロード時に設定値が反映されていないのも修正したい。
- **Root Cause**: 
  - フロントエンドの `GeneratePage.tsx` において、`input_type` が `select` のパラメータ入力欄をレンダリングする際、選択肢（options）として `loras` 一覧がハードコードされている。
  - このため、サンプラ名やスケジューラ名など、LoRA以外の選択肢を持つべき項目でもLoRA一覧が表示されてしまい、適切な値（例: "euler"）を選択できない。
  - また、ワークフローの初期ロード（アップロード）時にJSONからパースされたパラメータ初期値（例: "euler"）が、LoRA一覧の選択肢に含まれないため、ブラウザの `<select>` 挙動により空（未選択）として表示されてしまい、初期設定値が画面に反映されない。
- **Requirement**:
  - パラメータマスタマッピングの `input_type` に、サンプラ名選択用の `select_sampler` と、スケジューラ名選択用の `select_scheduler` を追加する。
  - フロントエンドのパラメータ描画部で、これら新しい `input_type` に応じて適切な選択肢を表示する。
  - 選択肢は、ComfyUI API（`/object_info` エンドポイントなど）から動的に取得したサンプラ一覧およびスケジューラ一覧を使用する。接続エラーなどのフォールバック用に、標準的なサンプラ名・スケジューラ名のリストを静的に定義して保持する。
  - 初期アップロード時（およびワークフロー初期ロード時）、JSON内の初期値と選択肢が一致することで、正しく初期値が反映されるようにする。
- **Acceptance criteria**:
  - [ ] AC-1: マスタマッピング定義（DBテーブル `mapping_masters` の `input_type`）において、新しく `select_sampler` および `select_scheduler` の入力タイプが使用可能であること。（設定画面の追加・編集フォームでもこれらのタイプが選択できること）
  - [ ] AC-2: パラメータ項目として `select_sampler` が設定されたノードについて、生成画面のパラメータ欄に該当のドロップダウンが表示され、ComfyUI上の有効なサンプラ一覧（例: `euler`, `dpmpp_2m` 等）が選択肢として表示されること。
  - [ ] AC-3: パラメータ項目として `select_scheduler` が設定されたノードについて、生成画面のパラメータ欄に該当のドロップダウンが表示され、ComfyUI上の有効なスケジューラ一覧（例: `normal`, `karras` 等）が選択肢として表示されること。
  - [ ] AC-4: ComfyUIへのAPI接続が失敗した場合でも、システム内に定義したフォールバック用の標準サンプラ/スケジューラリストから選択肢が生成され、画面描画が壊れないこと。
  - [ ] AC-5: ワークフローJSONファイルを初期アップロード（または新規ロード）した際、JSON内の該当ノードの入力値（サンプラ名、スケジューラ名）が初期パラメータ値として正しく読み込まれ、UI上のドロップダウンの初期選択状態に反映されること。
- **Design doc**: none
