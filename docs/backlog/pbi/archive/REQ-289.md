### REQ-289: Windows環境でのGPU/VRAM取得是正およびモバイルヘッダーリソース監視表示対応

- **Type**: bugfix
- **Status**: done (2026-09-26)
- **Current step**: none
- **Priority**: P1
- **Surface**: 
  1. Windows ホスト上で FastAPI を起動した際、CPU・RAM 情報は配信されるが、GPU 使用率（`gpu_pct`）および VRAM 使用量（`vram_used_gb`, `vram_pct`）が取得できず常に `null`（UI 表示上は `--`）となる。
  2. モバイル画面幅（`MobileLayout.tsx` 表示時）において、ヘッダーに配置されたリソース監視チップ（`ResourceGaugeChips`）が画面上に一切表示されない。
- **Root Cause**: 
  1. `backend/app/services/resource_monitor.py` で Linux（ROCm）専用コマンド `rocm-smi` を呼び出して `FileNotFoundError` が発生し、例外握りつぶしによってサイレント失敗していた。また、`_get_gpu_stats()` で GPU コア使用率サンプリングが未実装で常に `None` が返却されていた。
  2. `frontend/src/pages/GeneratePage/components/MobileLayout.tsx` で `useSystemStats()` フックの呼び出しが存在せず、WebSocket 接続処理が開始されていなかった。加えて、2段目ヘッダー行の `flex gap-2` 内で `select` の `flex-1` と競合し、狭小幅（360〜414px）で幅 0px に押し潰されるか描画領域外に押し出されていた。
- **Requirement**:
  - 【バックエンド是正】:
    - 外部ライブラリを追加せず、Windows 標準の Performance Data Helper API（`pdh.dll` + `ctypes`）を用いて常駐クエリを開設するサンプラークラス（`WindowsGpuMonitor`）を実装する。
    - 英語固定カウンター（`PdhAddEnglishCounterW`）により専用 VRAM 使用量（`\GPU Adapter Memory(*)\Dedicated Usage`）および 3D エンジン使用率（`\GPU Engine(*engtype_3D)\Utilization Percentage`）を取得する。
    - ComfyUI の稼働状態に一切依存せず、ホスト PC 本体の GPU/VRAM 負荷を直接サンプリングしてブロードキャストする。
  - 【フロントエンド是正】:
    - `MobileLayout.tsx` で `useSystemStats()` フックを呼び出し、モバイル環境でも確実に WebSocket 接続を確立する。
    - `ResourceGaugeChips` の配置を 2 段目のフォーム行から 1 段目（`<h1>Generate</h1>` の右側、`justify-between` スペース）へ移設し、幅競合と画面外はみ出しを解消する。
- **Acceptance criteria**:
  - [ ] AC-1: Windows ホスト上で FastAPI 起動後、WS 経由で `SYSTEM_STATS` が送信され、`gpu_pct` に 3D 使用率、`vram_used_gb` に実使用量、`vram_total_gb` に 16.0 が格納されること（ComfyUI 停止中でも計測されること）。
  - [ ] AC-2: モバイル画面幅で `MobileLayout` がマウントされた際、`useSystemStats()` により WebSocket 接続が確立し、`systemWsConnected: true` となること。
  - [ ] AC-3: 幅 360〜414px のモバイル表示において、1 段目ヘッダー右側に CPU/RAM/GPU/VRAM チップが崩れず視認できること。
  - [ ] AC-4: `cd frontend && npm run typecheck`（tsc -b --noEmit）がエラー 0 件で PASS すること。
  - [ ] AC-5: `cd frontend && npx vitest run` で既存テストが全件 PASS すること。
