### REQ-061: バッチ生成ジョブの一括キュー登録による制御向上

- **Type**: enhancement
- **Status**: done (2026-08-30)
- **Current step**: none
- **Priority**: P2
- **Surface**: 現状、バッチ生成時のキューへの登録が逐次行われているが、ComfyUI側でキューがあるので、最初に一気にキューに入れてしまいたい。選択してるセット数のバッチ回数の総和分のjobが最初に登録されることで、途中キャンセルがやりやすくなる。
- **Root Cause**: 現行のバッチ生成処理では、各バッチ処理の終了や進捗を待ってから次の生成リクエスト（ジョブ）をComfyUIのキューに追加（あるいはAPI呼び出し）しているため、ComfyUI側のネイティブなキューイングが活用しきれず、途中でバッチ生成全体をキャンセルすることが困難（または煩雑）になっている。
- **Requirement**: バッチ生成が開始された際、選択されたすべてのセットのバッチ回数の総和に相当するすべてのジョブを、最初に一括してComfyUIのキューに登録する。これにより、ComfyUIのキュー管理機能による一括または個別のキャンセルや割り込み制御の利便性を向上させる。
- **Acceptance criteria**:
  - [ ] AC-1: ユーザーがバッチ生成を開始した際、選択されたすべてのセットのバッチ回数の総和に相当するすべてのジョブが、開始時に即座にComfyUIのキューに一括で登録されること。
  - [ ] AC-2: 生成の進捗インジケーター（UI）が、セットを跨いだトータルの回数を分母とする "m/n Complete"（またはそれに類する形式。mは完了したジョブ数、nは総ジョブ数）で表示されること。
  - [ ] AC-3: 履歴への追加はジョブの完了通知を受け取るたびに順次行われ、現行同様に他セッションを含めて同期更新されること。
  - [ ] AC-4: ComfyUI側でキューのクリア（または登録したジョブのキャンセル）が発生した際、アプリ側でそれを検知し、進行中だった生成セッションを「キャンセル」として適切にステータス変更・リセットすること。
  - [ ] AC-5: 一括登録の開始後、完了を待たずにUIの入力フィールドのロックは行わず、ユーザーが追加でパラメーター編集や新規の生成ジョブの登録を行えること。
- **Design doc**: none
