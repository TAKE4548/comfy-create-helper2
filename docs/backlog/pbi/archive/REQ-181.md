### REQ-181: バッチ・複数プリセット生成時のキュー投入高速化と通信オーバーヘッド削減

- **Type**: performance
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**: 複数プリセットやバッチ数を指定して生成を実行した際、ComfyUIへのキュー投入完了までに1件ずつ数秒以上かかり、キューに積まれるまでの待機時間が長い。
- **Root Cause**:
  1. **WebSocket `status` 受信時の不要な `fetchHistory` 乱発**: ComfyUIにジョブが投入されるたびにWebSocket `status` イベントが届き、フロントエンドが毎回 `fetchHistory(100)`（最大100件の履歴全件取得・JSONパース・画像抽出・localStorage書き込み）を無条件に発火して通信帯域とメインスレッドを圧迫している。
  2. **バックエンドにおけるTCP接続の都度生成**: `backend/app/routers/comfy.py` のComfyUIプロキシ処理において、毎リクエスト `async with httpx.AsyncClient()` でTCP接続を都度生成・破棄しており、接続ハンドシェイクのオーバーヘッドが蓄積している。
- **Requirement**:
  1. WebSocket `status` 受信時の不要な `fetchHistory()` 呼び出しを廃止し、画像生成完了イベント（`executed` / `execution_complete`）時のみに限定する。
  2. バックエンド（FastAPI）で `httpx.AsyncClient` をシングルトン（Keep-Alive接続プール）として管理し、TCP接続を再利用する。
  3. プリセットおよびバッチの順次投入（FIFO順序）を確実に担保しつつ、最小限の通信オーバーヘッドで高速にキュー投入を完了させる。
