### REQ-370: 複数端末における生成履歴同期抜けの修正（スナップショット遷移判定・差分スロット上限・挿入位置時系列不整合）

- **Type**: bug (Type A: Implementation Defect)
- **Status**: ready
- **Priority**: P1
- **Surface**: Frontend (`frontend/src/store/slices/connectionSlice.ts`, `frontend/src/services/residualHistory.ts`, `frontend/src/pages/GeneratePage/hooks/useGenerateDisplayState.ts`)
- **Incident Report**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. なぜ他端末で生成されたバッチ画像が閲覧端末側の履歴に表示されない（抜け落ちる）か: 閲覧端末の履歴ストア（`comfyHistoryImages` / `batchImages`）に、他端末で完了したジョブの生成結果がマージされないため。
  2. なぜスナップショット再同期やHTTP取得時にマージされないか: `connectionSlice.ts` の `applyGenerationSnapshot` が「直前のスナップショットで succeeded 以外だったジョブが succeeded に遷移した瞬間」のみを `completedJobs` として抽出しており、初回ロード時や HTTP 再同期（`loadSnapshot`）で取得したスナップショット内の既完了ジョブが `mergeManagedHistory` に渡されず破棄されるため。
  3. なぜ閲覧端末で能動的な同期リクエストが飛ばないか: 画面アクティブ中およびタブ復帰時（`visibilitychange`）において、過剰通信抑制のため定期ポーリングおよびスナップショット再同期が完全に抑止されているため。
  4. なぜリロード時の残存履歴差分取得（`residual-history`）でも復元されない、または時系列が狂うか: `residualHistory.ts` のマージ処理が `allSlots = Math.max(0, 200 - existingAllCount)` で空き枠計算を行うため既存200件保持時に枠数0で全件切り捨てられ、かつ初回差分取得時に `insertAfterPrior` が `base.length`（配列最末尾・最古画像の後ろ）へ挿入するため。
  5. 根本原因: スナップショット適用時の遷移判定過度限定（初回/再同期の既完了ジョブ脱落）、バックグラウンド復帰時の再同期欠如、残存差分マージでの空き容量ベース切り捨て（FIFO不整合）、および差分挿入位置の時系列逆転という4つの実装欠陥の複合。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 複数端末・複数セッションでの生成履歴ギャラリーにおいて、どの端末で生成された画像であっても、時系列順に正しく網羅され、欠落なく一覧表示される。
  - **Interaction (インタラクション)**:
    - 他端末での生成完了がリアルタイムで反映され、また一時的なバックグラウンド移行やネットワーク瞬断からの復帰時にも、自動的に最新状態と同期して履歴抜けを修復する。
  - **Visual (視覚デザイン)**:
    - 既存ギャラリーUIのレイアウトや外観は維持。画像が消える・突如最古行に現れる現象を解消。
- **Requirement**:
  - **1. スナップショット適用時の未マージ完了ジョブ包括同期**:
    - `connectionSlice.ts` の `applyGenerationSnapshot` において、直前状態からの状態遷移ジョブだけでなく、スナップショット内に存在するすべての `status === 'succeeded'` かつ `outputs` を持つジョブを対象に `mergeManagedHistory` を実行し、未反映の完了画像を漏れなく履歴ストアにマージする。
  - **2. 残存履歴差分マージのスロット計算是正（FIFO方式化）**:
    - `residualHistory.ts` の `mergeResidualHistory` において、`200 - existingAllCount` による事前切り捨てを撤廃し、新規差分候補を受け入れた上でマージ後の配列全体を上限200件に制限するFIFO方式に変更する。
  - **3. 差分画像の挿入位置時系列整合化**:
    - `residualHistory.ts` の `insertAfterPrior` において、未保持の差分画像を配列最末尾（最古画像の後ろ）ではなく、最新側（または整合する時系列位置）へ挿入するよう補正する。
  - **4. タブ復帰時（visibilitychange）のスナップショット整合性再検証**:
    - `useGenerateDisplayState.ts` または関連フックにおいて、タブが非表示から可視状態へ戻った際、バックグラウンド中のイベント脱落を補償するため `generationApi.getState()` によるスナップショット整合性確認を実施する。
- **Acceptance criteria**:
  - [ ] AC-1: Given 直前スナップショットが存在しない（または直前 epoch と異なる/HTTP再同期）状態, When `succeeded` ジョブを含むスナップショットを `applyGenerationSnapshot` に適用したとき, Then 状態遷移を経由していない完了ジョブであっても `mergeManagedHistory` が呼び出され、履歴画像がストアに反映されること
  - [ ] AC-2: Given 閲覧端末側ですでに200件の履歴画像（`history.all`）が保持されている状態, When `mergeResidualHistory` に他端末で生成された新規差分アイテムが渡されたとき, Then 差分が0件に切り捨てられることなく追加され、マージ後の件数が200件上限に維持されること
  - [ ] AC-3: Given 残存履歴から初回差分画像を取得した状態, When 既存履歴とマージされたとき, Then 差分画像が配列の最古末尾ではなく、最新バッチと整合する適切な位置（先頭側）に配置されること
  - [ ] AC-4: Given バックグラウンド中に別端末で生成が完了した状態, When 閲覧端末のタブがフォアグラウンドに復帰したとき, Then スナップショットまたは残存履歴の再検証が行われ、取りこぼしたバッチ画像が画面リロードなしで履歴ギャラリーに反映されること
- **Inferred points**:
  - `mergeManagedHistory` 内部で `imageIdentity` に基づく重複排除がすでに行われているため、全 `succeeded` ジョブを渡しても重複登録は発生しない。
