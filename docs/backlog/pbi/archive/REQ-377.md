### REQ-377: モバイルLoRA／Tag Set：詳細・編集シートの再構成とTag Set編集入口・Subsetsの統一

- **Type**: feature
- **Status**: ready
- **Priority**: P3
- **Surface**: モバイルLoRAs／Tag Setsの詳細・編集シート、Tag Setの編集・新規作成、Subsets編集（幅767px以下）。`LoraDetailModal`、`TagSetDetailModal`、`TagSetEditModal`、`TagSetCreateModal`、共有 `TagSetFormFields` に関連
- **Reference**:
  - docs/design/mobile-ui-redesign/mobile-lora-tagset-redesign-proposal.md（§1、§4〜§6、§8 AC-06〜AC-13）
  - docs/design/mobile-ui-redesign/mobile-common-ui-redesign-proposal.md（COMMON-02 / 03 / 04 / 05 / 09、§3）
  - docs/specs/SPEC_LORAS.md（§5 登録・編集モーダル）／docs/specs/SPEC_TAGS.md（§2、§3）
  - docs/specs/SPEC_COMMON.md（§1-4 共通モーダルとレスポンシブ境界、§1-5 モバイル アンチパターン）
  - 比較モック: `/loras?ui=baseline|proposal`、`/tags?ui=baseline|proposal`
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: モバイルの詳細は常駐の大きな画像とRelated Snapshotsが本文を圧迫し、Edit／Saveが末尾までスクロールしないと押せず、Close/EditとCancel/Saveの左右関係も一致しないため。
  2. なぜその課題が発生するか: 画像・本文・操作が同じ縦スクロール面に並び、閲覧と編集で画面構造と操作位置が揃っていないため。
  3. なぜ現状の仕組みで不十分か: Tag Setではカードの編集アイコンと詳細内のEditが異なる編集画面へ進み、Subsetsの一覧が独立スクロール（内部高さ制限）で、編集・新規作成の両方で操作しにくい。
  4. なぜこのアプローチを採用するか: 本文を広く取り、確定操作を固定フッターに置き、画像は小型Coverと別導線に分離する方向を、ユーザーがモックで評価した。
  5. 根本原因: 詳細・編集シートの構造（スクロール領域とアクション位置）と、Tag Set編集の入口が一貫して設計されていないこと。
- **UX Classification**:
  - **Information Design (情報設計)**: 本文を主役にし、画像は小型Coverとスナップショット件数に集約する。
  - **Interaction (インタラクション)**: 下端起点のボトムシート、固定フッター、左＝戻る／取消、右＝進む／確定。Coverタップで画像一覧へ。Tag Setの編集入口を統一する。
  - **Visual (視覚デザイン)**: シート構造（ヘッダー／本文／固定フッター）。
- **Requirement**:
  - **1. ボトムシート構造**: 詳細・編集をヘッダー、単一の縦スクロール本文、固定アクションフッターに分割する。
  - **2. アクション配置**: 閲覧中は左 Close／右 Edit、編集中は左 Cancel／右 Save。フッターはスクロール距離に依存せず操作できる。
  - **3. 画像の扱い**: 本文上部に小型Cover＋スナップショット件数。Coverタップで画像一覧（Related Snapshots・Cover候補）を開く。画像の閲覧とCover変更（保存／取消）の扱いを分ける。
  - **4. Tag Setの編集入口の統一**: カードの編集アイコンと詳細内のEditが、同じタグセットに対し同じ編集UI・フィールド・状態を開く。
  - **5. Subsets**: 一覧の独立スクロール（内部高さ制限）を廃止し、親シート／作成画面のスクロールに統合する。詳細からの編集とNew Tag Setの両方に適用する。
  - **6. 既存機能の維持**: LoRAのトリガーワード・強度・パス・対象モデル、Tag Setの名前・説明・対象モデル・タグ・サブセット・タグと画像の変更、コピー、Cover管理、削除。
  - **7. 非対象**: PC表示、一覧カード（REQ-376）、New Tag Setのフッター固定の統一（別検証事項）、共通タグチップ（`TagChipEditor` / `TagChipViewer`）の密度変更。
- **Acceptance criteria**:
  - [ ] AC-1: Given 幅767px以下のLoRA／Tag Set詳細, When 詳細を開く, Then 下端起点のボトムシートが表示され、ヘッダー、単一の縦スクロール本文、固定フッターで構成され、スクロール領域が本文のみであること。
  - [ ] AC-2: Given 閲覧中の詳細, When フッターを確認する, Then 左に Close、右に Edit が表示され、本文を最上部から最下部までスクロールしても位置が変わらず常に操作できること。
  - [ ] AC-3: Given 編集中, When フッターを確認する, Then 左に Cancel、右に Save が表示され、本文のスクロール距離に依存せず操作でき、保存中の無効状態とバリデーションエラーが表示されること。
  - [ ] AC-4: Given ソフトウェアキーボードを表示した編集、セーフエリア、ボトムナビがある画面, When 入力・保存を行う, Then 固定フッターとフォーカス中の入力欄がキーボードやボトムナビに隠れず操作できること。
  - [ ] AC-5: Given 詳細の本文上部, When 画像関連を確認する, Then 常時の大きな画像やRelated Snapshotsの一覧が表示されず、小型Coverとスナップショット件数が表示されること。
  - [ ] AC-6: Given 小型Cover, When タップする, Then 関連画像の一覧（Related Snapshots）とCover候補を確認でき、Coverの変更は編集の権限と保存タイミング（保存／取消）に従い、取消後に元のCoverと画像順・件数が一致すること。
  - [ ] AC-7: Given 画像なし、スナップショットなし、画像の読込失敗、縦長・横長画像, When 詳細を開く, Then レイアウトが破綻しないこと。
  - [ ] AC-8: Given 同じタグセット, When カードの編集アイコンから開く場合と、詳細の Edit から開く場合を比較する, Then どちらも同じ編集UI・フィールド・操作状態（フッター配置を含む）が開き、異なる別の編集画面へ進まないこと。
  - [ ] AC-9: Given Tag Setの詳細からの編集およびNew Tag Setの作成, When 多数のSubsetsがある状態で編集する, Then Subsets一覧に内部の独立スクロールがなく、親のシート／作成画面だけが縦にスクロールすること。
  - [ ] AC-10: Given 共有の `TagSetFormFields` を使うすべての画面, When Subsetsのスクロール仕様を変更した後に操作する, Then 使用箇所の一覧が設計に記録され、各画面の表示・操作が破綻しないこと。
  - [ ] AC-11: Given LoRAの編集・詳細, When 操作する, Then トリガーワード、推奨強度、ファイルパス、対象モデルの閲覧・編集・コピーが従来どおり動作すること。
  - [ ] AC-12: Given Tag Setの編集・詳細, When 操作する, Then 名前、Description、対象モデル、メインタグ、各サブセットのタグと画像の変更、タグのコピー、保存、削除が従来どおり動作すること。
  - [ ] AC-13: Given 詳細・編集シート, When キーボード（Tab・Escape）、背面タップ、スクリーンリーダーで操作する, Then フォーカスがシート内に留まり、Escape・Close・背面タップで閉じる際の挙動（未保存変更がある場合の確認の有無を含む）が、本PBI前の現行の挙動と同一で、閉じ、閉じた後は開いた要素にフォーカスが戻ること。
  - [ ] AC-14: Given 幅768px以上、Baseline、`TagSetFormFields` を使わない他画面, When 操作する, Then 本PBI前から表示と挙動が変化しないこと。
- **Inferred points**:
  - 前提: REQ-378（モバイルUI共通規約のSPEC_COMMON反映）の完了後に設計に着手する。
  - **仕様の差異（要確認）**: 現行仕様（SPEC_COMMON §1-4／§1-5）では、`LoraDetailModal`、`TagSetDetailModal`、`TagSetEditModal`、`TagSetCreateModal` を含む `.modal-backdrop` のレガシーモーダルが幅768px未満で既に下部シート化される旨が記述されている。一方、モックの課題報告は「詳細が中央モーダル風」としている。実画面の現状を設計フェーズで確認し、ACは結果（AC-1）で規定する。
  - **仕様の差異**: SPEC_TAGSは編集と詳細をカードクリックで開くモーダルと定義。編集入口の統一（AC-8）の方向（どちらの画面に統一するか）は設計で決定し、完了時にSPEC_LORAS／SPEC_TAGSを更新する。
  - New Tag Setの作成画面は詳細用ボトムシートとは別構造。作成画面にも固定フッターを適用するか（編集画面との統一）は未確定の検証事項。本PBIの必須範囲はSubsetsのスクロール統一（AC-9）まで。
  - Cover設定の導線はモックで暫定試作（React本体への間接接続）であり、全状態での動作保証がない。保存・取消・画像順・件数表示の整合は追加検証が必要（AC-6）。
  - 関連既存PBI：REQ-302（モバイルモーダルをボトムナビ前面にする。status: new）、REQ-367（共通Modalのフォーカス／Escape／バックドロップ。status: ready）。設計時に重複・競合を確認する。
  - 共有部品（`TagSetFormFields`、`TagChipEditor`、`TagChipViewer`）の変更は、利用箇所の調査と別途承認を要する。タグチップ密度の変更は本PBIに含めない。
  - 「LoRA／Tag Setの詳細」を一括で扱うのは、同一パターンを2画面で揃えるため。設計時に実装規模が大きい場合はLoRAとTag Setに分割することを再検討する。
