### REQ-073: LoRA・タグセット適用時のスナップショット保存メタデータ不整合問題

- **Type**: defect
- **Status**: in-progress
- **Current step**: Step 2 (Detailed Design)
- **Priority**: P1
- **Surface**: Add AssetでLoRA・タグセットを適用して生成・保存したスナップショットのアセット情報がずれている、あるいは登録されない場合がある。複数のプロファイルやジョブでAsset適用状態が異なる連続生成を行った際などに頻発する。
- **Root Cause**: スナップショット保存時に、画像が生成された時点のメタデータではなく、Zustandストア内の現在のライブUI状態（`appliedAssets`, `paramValues`）を参照してAPIリクエストを送信しているため。
- **Requirement**: 各画像が生成された時点のアセット適用状態および生成パラメータ（メタデータ）をキュー送信時にキャッシュ保持し、スナップショット保存時は画像URLから生成ジョブ（`prompt_id`）を特定して、対応するキャッシュメタデータからアセット情報を復元・適用して保存する。
- **Design doc**: `docs/design/REQ-073.md`

#### Acceptance Criteria (AC)
- [ ] AC-1: 一括生成（Multi-Set 生成）時や、生成後にUIでプロファイル（Set）やパラメータを変更した場合でも、履歴サムネイルから保存するスナップショットのメタデータ（LoRA・タグセット、生成パラメータ）が、実際にその画像を生成した際のものと完全に一致して保存されること。
- [ ] AC-2: 生成完了時（websocket `executed` イベント受信時）に作成される画像URLのクエリパラメータ `t` が、`Date.now()` ではなく、対応する生成ジョブの `prompt_id` に設定されていること。
- [ ] AC-3: 画像生成キュー送信（`queuePrompt`）時に、そのジョブの `paramValues` と `appliedAssets` が `localStorage` 上に `prompt-surgeon-meta-{promptId}` の形式でキャッシュ保存されること。また、キャッシュ数が最大200件を超えた場合は、タイムスタンプが古い順に自動でクリーンアップ（削除）されること。
- [ ] AC-4: キャッシュが存在しない画像（外部生成やセッションクリア後など）をスナップショット保存する際、従来通りZustandストア内の現在のアセット適用状態およびパラメータがフォールバックとして使用されること（下位互換性の維持）。
