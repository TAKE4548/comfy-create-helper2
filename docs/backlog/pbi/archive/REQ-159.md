### REQ-159: モバイル端末における生成進捗表示・履歴同期・キュー投入耐性の改善

- **Type**: bug
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**: モバイル端末（および自セッションフィルタ有効時）における生成プログレスバーの非表示・点滅、バックグラウンド復帰時の生成画像履歴（サムネイル）反映漏れ、および投入直後のスリープ・バックグラウンド移行による生成枚数不足。
- **Root Cause**:
  1. `execution_start` WebSocketイベント受信時に `activeClientId` が `null` で上書きリセットされ、`isGeneratingHere` 判定（`activeClientId === clientId`）が `false` となってプログレスバーが非表示化される。
  2. バッチ投入時（`isBatchIntermediate: true`）に `activeClientId` が更新されない。
  3. 自セッション表示モード（`filterOwnSession: true`）時に `displayImages` がローカルの `batchImages`（リアルタイムWebSocket受信分）のみを参照しており、スリープ等で切断中にComfyUI側で完了した画像が `/history` から同期されない。
  4. バッチ投入がフロントエンドの直列 `async for` ループで行われているため、投入直後にモバイルOSがJavaScript実行をサスペンドすると後続ジョブのComfyUIキュー登録が停止する。
- **Requirement**:
  1. WebSocketの `execution_start` 受信時およびバッチジョブ進行中も自セッションの生成状態・`activeClientId`（または `activeBatch` に紐づく判定）を正常に維持し、ジョブ移行時も途切れることなくプログレスバーを継続表示する。
  2. 自セッション表示モード時、ComfyUIの `/history` から自クライアントID（`client_id`）に合致する画像を抽出・マージする同期処理を実装し、アプリ復帰（`visibilitychange`）やリロード時にバックグラウンド完了分の画像を確実に履歴・サムネイルへ反映する。
  3. 全体進捗とキュー残数の責務を明確に分離する:
     - **全体進捗（`n/M 枚目`）**: FEが投入した全予定枚数を母数 `M` とし、完了・失敗した数と現在実行中ジョブに基づいて進行を管理する。
     - **キュー残数（`Queue: X`）**: ComfyUI側の実キュー（`queue_running` + `queue_pending`）の受理確定数を反映し、送信に伴うリアルタイムな増加と実行に伴う減少を視認可能にする。

#### Acceptance Criteria (AC)

##### 1. プログレスバーの継続表示とジョブ移行耐性
- [ ] AC-1-1: モバイル端末および `filterOwnSession: true` 環境において、1枚目生成開始からバッチ全件完了まで、プログレスバー（全体進捗・ノード進捗・経過秒数）が途切れず正常に表示されること。
- [ ] AC-1-2: 1枚目の生成が完了して2枚目以降のジョブへ移行した際にも、`isGeneratingHere` が維持され、プログレスバーが「Ready (0%)」にリセット・非表示化されないこと。
- [ ] AC-1-3: 生成中にページをリロードした場合でも、実行中ジョブおよび残キューの進捗バーが継続表示されること。

##### 2. バックグラウンド完了画像の履歴・サムネイル自動同期
- [ ] AC-2-1: バッチ生成をキュー投入後、モバイル端末をスリープ／バックグラウンドにし、ComfyUI側で生成完了後にアプリを再アクティブ化（またはリロード）した際、バックグラウンド中に生成された画像がサムネイル一覧および履歴に漏れなく自動反映されること。
- [ ] AC-2-2: `filterOwnSession: true` が有効な場合、ComfyUIの `/history` から自セッション（`client_id`）に一致する画像のみが正確に抽出・マージされること。
- [ ] AC-2-3: 生成中にアプリ画面を復帰させた際（`visibilitychange` イベント等）に、未反映の完了画像が即座に同期されること。

##### 3. 全体進捗とキュー残数の明確な役割分離
- [ ] AC-3-1: 全体進捗の母数 `M` はFEが投入した全予定枚数（追加投入時は未完了分と合算）が一貫して保持され、完了または失敗したジョブ数に応じて進捗（`n/M 枚目`）が正しく進行すること。
- [ ] AC-3-2: `Queue: X` 表示はComfyUI側で実際に受理・キューイングされている実数が表示され、投入進行に応じて `1 → 2 → 3...` とカウントアップし、生成完了に伴い減少すること。
- [ ] AC-3-3: ユーザーが画面上の `Queue: X` で全件のComfyUI受理を確認した上で安心してアプリを離脱できること。
