### REQ-009: 生成セッション（WebSocket進捗同期）の維持

- **Status**: done (2026-08-30)
- **Type**: enhancement
- **Priority**: P1
- **Current step**: Step 7
- **Surface**: リロードや別画面遷移で、生成実行中の進捗やComfyUIとのWebSocketセッション（進行状態）がリセットされてしまう。BE稼働中は生成状態を維持し、画面を開き直してもシームレスに再開できること。
- **Root Cause**: 現状、画像生成進捗の監視やプレビュー画像の受信は、フロントエンドがComfyUIのWebSocketに直接接続してハンドリングしているため、ページのリロードや他ページ（LoRA管理、設定等）への遷移によってフロントエンドのWebSocket接続が切断されると、生成進行中のイベントデータや進捗状態が破棄され、画面を開き直した際（再接続時）に進行中の生成プロセスの進捗を追跡・同期できなくなってしまう。
- **Requirement**: 
  - 生成実行中の進行状況（進捗率、プレビュー、ログなど）を、リロードや別画面遷移後でもシームレスに同期再開できる仕組みを提供する。
  - 実装アプローチとして、以下の2つのいずれかを採用し、システム設計時に最終決定する。
    1. **バックエンド（FastAPI）中継アプローチ**: バックエンドでComfyUIとのWebSocketを常時監視・バッファし、フロントエンドからの再接続に対して進捗を復元・同期する（マルチデバイス同期や完了保証に強い）。
    2. **フロントエンド（FE）再アタッチアプローチ**: フロントエンドのみで完結させ、現在実行中のプロンプトID（ジョブID）を永続化（localStorage等）し、リロード時にComfyUI WebSocketへ自動で直接再接続して最新の進行状態へ復帰する（構成がシンプル）。
- **Acceptance criteria**:
  - [ ] AC-1: 画像生成の実行中、フロントエンドが別メニュー（LoRA管理、設定等）へ遷移した後に生成画面へ戻ってきた場合、生成中の進捗（プログレスバー）やプレビュー表示が途切れることなく正常に継続してレンダリングされること。
  - [ ] AC-2: 生成実行中にブラウザのリロード（F5）が発生した場合でも、画面の再ロード完了後に自動的にWebSocket接続（ComfyUI直接、またはBE経由）が再確立され、進行中のジョブの進捗率や処理中ノード、プレビュー画像が即座にUIに復元・同期されること。
  - [ ] AC-3: 一時的な通信切断が発生している間に生成が完了した場合でも、最終的に生成された画像データがフロントエンドに適切に取得され、履歴プレビューへ自動的に追加・反映されること。
- **Design doc**: none
