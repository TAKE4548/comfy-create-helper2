### REQ-238: server-manager起動時のVite EPERM rmdirエラーの解消
- **Type**: defect
- **Status**: done (2026-09-09)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - 「server-managerで一括起動すると、FEがエラー吐くようになった」
  - `Error: EPERM: operation not permitted, rmdir 'frontend/node_modules/.vite/deps'`
- **Root Cause**:
  - Windows環境において `frontend/node_modules/.vite/deps` などのディレクトリに `R` (Read-Only) 属性が付与されている場合、Vite のキャッシュ初期化処理 `await fsp.rm(depsCacheDir, { recursive: true, force: true })` が `rmdir` システムコールで `EPERM (Access Denied)` により失敗する。
  - キャッシュメタデータ（`_metadata.json`）がプロセス強制終了等により欠落・破損すると、Vite は起動のたびにキャッシュ削除を試みて即死するデッドロック状態に陥る。
  - 加えて `server-manager.ps1` の停止処理がポートリッスン中の PID に対する単発の `Stop-Process -Force` であるため、起動・最適化中のプロセスが途中終了しやすく、キャッシュ破損を引き起こす契機となっている。
- **Requirement**:
  - Windows 環境において `.vite/deps` ディレクトリの `R` 属性やキャッシュ破損に起因する `EPERM rmdir` 起動エラーを確実に解消・予防する仕組みを整備する。
  - `server-manager` からの起動時および開発時の `npm run dev` 実行時において、キャッシュ不整合が発生しても自律的に回復して Frontend サーバーが正常起動できるようにする。
  - `server-manager.ps1` における Frontend プロセスの停止・再起動処理を安全・堅牢にする。
- **Acceptance criteria**:
  - [ ] AC-1: `frontend/node_modules/.vite/deps` の `EPERM rmdir` エラーが解消され、`npm run dev` および `server-manager` から Frontend が正常に起動すること。
  - [ ] AC-2: キャッシュメタデータが欠落または破損した場合でも、`EPERM` でクラッシュせず正常にキャッシュが再生成されて起動できる回復機構が動作すること。
  - [ ] AC-3: `server-manager` の一括起動・再起動・停止処理において、Frontend プロセスおよび関連プロセスが安全にライフサイクル管理されること。
