### REQ-340: Prompt Surgeon: Settingsマッピングマスタ編集のUX強化（パターンコピペ・インライン編集・パラメータ表記ゆれ・ワークフロー指定プレビュー・逆引きノード登録）

- **Type**: feature
- **Status**: done (2026-10-11)
- **Priority**: P2
- **Surface**:
  - backend/app/models/ (MappingMaster モデルの fallback_param_names JSON配列定義・DBマイグレーション)
  - backend/app/schemas/ (MappingMaster 入出力スキーマ)
  - backend/app/services/ (マッピング判定エンジン・フォールバック解決・ワークフローノード抽出)
  - backend/app/routers/ (マッピングマスタAPI・ワークフロー解析エンドポイント)
  - frontend/src/pages/SettingsPage/components/MappingMasterSection.tsx
  - frontend/src/features/settings/MappingMasterEditModal.tsx
  - frontend/src/features/settings/components/ (PatternTagInput, FallbackParamsInput, WorkflowMappingPreview, WorkflowNodePicker)
  - frontend/src/types/mapping.ts
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: ComfyUIワークフローのマッピングマスタ設定において、パターンの重複手入力、タイポ修正時のやり直し、カスタムノード固有のパラメータ名差異（seedとnoise_seed等）によるマッピング失敗、プレビュー対象の不透明さ、および手動でのクラス名・パラメータ名入力の手間が大きく作業効率を著しく損ねているため。
  2. なぜその課題が発生するか: 複数ロール間で類似のノードパターンがあってもチップ単位・一括でのコピペができず、登録済みパターンの編集が不可で再入力が必要であり、単一のparam_nameしか定義できず、プレビューが特定のワークフローコンテキストを持たず、ワークフロー側からのノード逆引き設定機能が存在しないため。
  3. なぜ現状の仕組みで不十分か: タイトル検索パターンのタイポ修正に「削除→再フル入力」の手間がかかり、パラメータ名の表記ゆれに対してロール定義の重複やワークフロー毎の書き換えが発生し、リアルタイムプレビューが実際のワークフローに合致しているか確認できず、ワークフローの各ノードを手動で確認して手打ち登録する必要があるため。
  4. なぜこのアプローチを採用するか: チップのクリップボードコピペ＆インライン編集、複数フォールバックパラメータ名（エイリアス）の順次解決機構、既存登録ワークフロー（GET /api/workflows）および新規JSONの明示的バインドプレビュー、そしてワークフローから直接ノード・パラメータを抽出してマッピングへ安全に適用する逆引き登録UIを導入することで、設定作業の省力化と精度向上を両立できるため。
  5. 根本原因 (Root Cause): マッピングマスタ管理が「手動の順方向入力」のみを前提とした単一キー定義となっており、クリップボード連携、インライン編集、表記ゆれフォールバック、およびワークフローデータからの「コンテキスト連動プレビュー」「逆引き抽出登録」の機能的・情報的導線が欠落していたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - パラメータ定義におけるプライマリ名（param_name: string）と任意のフォールバック表記ゆれ候補（fallback_param_names: list[str] JSON配列）の階層化と厳格な順序保証。
    - プレビュー対象コンテキスト（既存の登録済みワークフロー選択: GET /api/workflows、またはドラッグ＆ドロップ/ペーストされたワークフローJSON）の明示的結合。
    - ワークフローノード構造（Node ID, Title, ClassType, Widgets/Inputs）の分解と、マッピングマスタ入力項目へのマッピング対応関係の構造化。
  - **Interaction (インタラクション)**:
    - タイトル検索パターンチップの一括コピー（クリップボード書き込み）および貼り付け（カンマ・改行・空白区切り文字列からトリム処理・重複排除・引用符正規化を伴う一括チップ生成、クリップボードAPI利用不可時の手動テキストフォールバック付き）。
    - 登録済みタイトル検索パターンのダブルクリックまたは編集ボタンによるモーダル内ドラフトのインライン編集（Enter/フォーカスアウトで確定、Escapeでキャンセル）。保存ボタン押下時に一括永続化。
    - 表記ゆれパラメータ名のチップ追加・編集・ドラッグ/ボタン並び替え（フォールバック優先順位）・削除操作。
    - プレビュー対象ワークフローのドロップダウン選択およびJSONファイルアップロード/D&Dによる即時バインドと合致結果のリアルタイム更新（JSON構文・セマンティック検証とファイルサイズ制限（上限10MB））。
    - ワークフロー内ノード一覧のブラウズと、対象ノード・パラメータの「このノードをマッピングに反映」操作における非破壊的自動補完（ClassType設定、タイトル文字列の検索パターンチップ追加、パラメータ名反映。既存入力値が存在する場合は上書き確認ダイアログを提示）。
  - **Visual (視覚デザイン)**:
    - チップの編集可能状態・コピー完了トースト/視覚フィードバック。
    - パラメータ表記ゆれ一覧のバッジ表示（プライマリとフォールバックの区別）。
    - プレビュー結果におけるマッチング状態の可視化（完全一致ノード、合致したパラメータ名：プライマリかフォールバックか、未合致理由）。
    - ワークフローノード抽出パネル/モーダルにおけるノードカードおよびパラメータ選択UI（Prompt Surgeonダークテーマ準拠）。
- **Requirement**:
  - **1. タイトル検索パターンのクリップボード連携（コピペ）**:
    - タイトル検索パターンチップ群を一括でクリップボードへコピー（カンマ区切りテキスト）できるボタン/アクションを提供すること。
    - カンマ、改行、または空白区切りの文字列を貼り付けた際、引用符の除去・前後の空白トリム・空文字除外・重複排除を行った上で複数のパターンチップへ一括分割・追加できること。ブラウザ権限制限等でClipboard APIが拒否された場合もテキスト入力によるフォールバック手段を提供すること。
  - **2. タイトル検索パターンのインライン編集**:
    - 編集モーダル内で登録済みのタイトル検索パターンチップをダブルクリック、またはチップ上の編集アイコンをクリックすることでインライン編集モードへ遷移できること。
    - Enterキーまたはフォーカスアウトでドラフト値を確定し、Escapeキーで編集をキャンセルできること。タイポ修正のために一度削除して再フル入力する手間を排除し、最終的なモーダル保存ボタン押下時に永続化すること。
  - **3. パラメータ名の表記ゆれ（フォールバックパラメータ名）登録と順次フォールバック解決**:
    - MappingMaster にプライマリの param_name に加え、任意の数の表記ゆれパラメータ名（allback_param_names: 文字列JSON配列）を順序を保持して登録・管理可能とすること。
    - マッピング判定およびパラメータ値取得・書き込み処理において、ノードにプライマリ param_name が存在しない場合、登録された allback_param_names を配列のインデックス順（先頭から）に探索して最初に合致したノード入力をバインドすること。
  - **4. ワークフロー指定（既存選択 / JSON指定）によるコンテキスト連動リアルタイムプレビュー**:
    - マッピングマスタ編集モーダルのプレビュー領域において、検証対象として「既存の登録済みワークフロー（GET /api/workflows 取得一覧からのドロップダウン選択）」または「新規ワークフローJSON（ファイル選択・ドラッグ＆ドロップ・テキスト貼付、上限10MB）」を指定できること。
    - 指定されたワークフロー内の実ノードに対して、現在のマッピング設定（期待ClassType、タイトル検索パターン（部分一致）、パラメータ名/表記ゆれ）を評価し、どのノード（ID、タイトル、クラス名）のどのパラメータ（プライマリ名または合致したフォールバック名）にバインドされるかをリアルタイムかつ視覚的に明瞭に表示すること。
  - **5. ワークフローからの逆引きノード列挙および安全なマッピング自動補完・登録**:
    - 渡されたワークフロー（既存選択またはJSON）に含まれる全ノードおよびその入力パラメータ（widgets/inputs）を一覧列挙・閲覧できるノードエクスプローラ機能を提供すること。
    - ユーザーが一覧から任意のノードおよびパラメータを選択した際、対象ノードのClassType（前後の空白トリム済み）、ノードタイトル（タイトル検索パターンの追加チップ）、およびパラメータ名（param_name）を編集フォームへ自動転記できること。既存の入力値が存在する場合はユーザーに上書き確認を行い、誤ったデータ喪失を防止すること。
- **Acceptance criteria**:
  - [ ] AC-1: Given マッピングマスタ編集モーダルでタイトル検索パターンが登録されているとき, When 「パターンをコピー」操作を行う、またはチップを選択してコピーする, Then クリップボードに検索パターン文字列（カンマ区切り）が格納され、別ロールの編集画面で貼り付け（Paste）を行った際にカンマ・改行・空白で自動分割（引用符除去・トリム・重複排除）されて複数チップとして一括展開・登録されること。
  - [ ] AC-2: Given マッピングマスタ編集モーダルで登録済みのタイトル検索パターンチップが表示されているとき, When チップをダブルクリックまたは編集操作する, Then チップがインライン入力状態へ遷移し、文字列を修正して確定（Enterキーまたはフォーカスアウト）した際にモーダル内のドラフトへ即座に反映され、最終的なモーダル保存時にDBへ永続化されること。
  - [ ] AC-3: Given マッピングマスタのパラメータ設定において, When プライマリのパラメータ名に加えて1つ以上の表記ゆれパラメータ名（例: seed に対して noise_seed）を追加・登録する, Then マッピング判定および値読み込み時に、プライマリ名が存在しない場合に登録された表記ゆれパラメータ名が登録順にフォールバック探索され、最初に合致したノードパラメータと正常にマッチングされること。
  - [ ] AC-4: Given マッピングマスタ編集のリアルタイムプレビュー領域において, When 登録済みワークフロー（GET /api/workflows）の選択、または任意のワークフローJSONをドロップ/指定する, Then そのワークフローのノード構成を対象としてマッチング判定が実行され、「合致したノード名/ID」および「バインドされたパラメータ（プライマリ/フォールバック種別）」がリアルタイムかつ明瞭に表示されること。
  - [ ] AC-5: Given ワークフローJSON（ファイルまたは選択）が渡されたとき, When ワークフロー内のノード列挙画面を表示する, Then ワークフローに含まれるノード一覧（ID、現在のタイトル、ClassType、入力パラメータ群）が一覧表示され、ユーザーが対象ノード・パラメータを選択した際、既存入力値の上書き確認を経た上で編集中のマッピングマスタ（ClassType設定、タイトル文字列のパターンチップ追加、パラメータ名反映）へ安全に自動補完・反映できること。
  - [ ] AC-6: Given 不正な形式のワークフローJSON（構文エラーや10MB超過）またはノード構造のセマンティック不整合が存在するとき, When プレビューまたは保存を実行する, Then 画面がクラッシュすることなく具体的なエラー・警告メッセージ（例: ノード構造不整合、入力パラメータ欠落等）が表示され、無効なデータは送信・登録されないこと。
- **Inferred points**:
  - allback_param_names はDBスキーマ上、mapping_masters テーブルに JSON カラム（SQLite/PostgreSQL対応）として保持し、既存レコードに対しては空配列（[]）をデフォルト値として適用して後方互換性を担保する。
  - 検証対象ワークフローは既存のワークフロー管理API（GET /api/workflows）のデータを再利用し、新規の外部ワークフローライブラリAPI等の不要なスコープ拡大は行わない。
  - リアルタイムプレビューおよびノード列挙はフロントエンド側の軽量パーサーで即座に実行可能とし、ComfyUI本体の稼働状態に依存せずスタンドアロンで利用可能とする。
