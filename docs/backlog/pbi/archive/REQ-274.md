### REQ-274: Windows環境におけるWeb Managerポーリングによるバックエンド(WinError 64)クラッシュの防止

- **Type**: bugfix
- **Status**: done (2026-09-17)
- **Current step**: Step 2 (Design Complete)
- **Priority**: P1
- **Surface**:
  - Web Managerからバックエンド（ポート8000）を起動した際、あるいはManager稼働中にバックエンドを動かしていると、バックエンドログに OSError: [WinError 64] 指定されたネットワーク名は利用できません。 が出力され、通信受付が失敗・プロセスが停止してしまう。
  - バックエンドが起動直後に落ちる、またはステータス監視が入ったタイミングでクラッシュする。
- **Root Cause**:
  - **Platform Incompatibility (Windows IOCP AcceptEx vs Fast TCP Healthcheck)**:
    - WindowsのPython 3.8+では asyncio のデフォルトイベントループが ProactorEventLoop（IOCP）となっている。
    - Web Manager（server_status.py / server_api.py）がサーバーステータス取得のために定期的に socket.create_connection(('127.0.0.1', 8000)) を実行し即座に接続クローズ（RST/FIN送信）を行う。
    - この接続直後の即時切断をIOCPの AcceptEx が処理する際、未完了のままソケットがリセットされることでOSレベルで [WinError 64] 指定されたネットワーク名は利用できません が送出され、asyncio の accept ループが未処理例外で停止・クラッシュする。
- **Requirement**:
  - バックエンド（Uvicorn / FastAPI）がWindows環境で稼働する際、IOCP AcceptEx 起因の [WinError 64] により通信ループがクラッシュしないよう、イベントループポリシーを適切に設定（WindowsSelectorEventLoopPolicy）または堅牢化すること。
  - Web Managerのポート監視（server_status.py および server-manager.ps1）において、バックエンドに対するヘルスチェックが不用意なRST切断やIOCPエラーを誘発しないよう接続処理を安全に行うこと。
  - Web Manager経由でバックエンドを起動・監視した際に、[WinError 64] が発生せず安定してポート8000で稼働し続けることを担保すること。
- **Acceptance criteria**:
  - [ ] AC-1: Windows環境においてバックエンド起動時に asyncio.WindowsSelectorEventLoopPolicy または同等の例外防御が適用され、ポートスキャンや即時切断による [WinError 64] でuvicornがクラッシュしないこと。
  - [ ] AC-2: Web Managerのポーリング監視（server_status.py）が動作している状態でバックエンド（ポート8000）が正常に起動し、Listen状態を維持できること。
  - [ ] AC-3: バックエンドの run_server.bat および直接実行（python -m uvicorn ...）の双方で本対策が有効に機能すること。
  - [ ] AC-4: 回帰テスト（既存の tests/unit/test_server_manager_*.py 等の自動テスト）がすべてパスすること。
- **Design doc**: docs/design/REQ-274.md
