### REQ-249: 履歴表示パイプライン（useGenerateDisplayState）のデータソース正規化とリアルタイム同期基盤整備

- **Type**: refactor
- **Status**: done (2026-09-12)
- **Current step**: none
- **Priority**: P2
- **Surface**:
  - `useGenerateDisplayState.ts` 内において、ローカル生成画像のリスト（`batchImages`）、ComfyUI 履歴画像（`comfyHistoryImages`）、スナップショットクエリ（`useQuery(['snapshots'])`）の3系統がアドホックに合成・ソートされている。
  - 別端末で生成された画像のリアルタイム同期（REQ-240）を実装する際、どのデータストアに画像を挿入すべきかの責務境界が曖昧であり、履歴順序の崩壊や表示画像の重複、プロンプト編集ステートとの競合が発生しやすい。
- **Root Cause**:
  - (Fragmented Source of Truth / 状態管理構造不全): 生成実行セッションごとのローカル配列とサーバー側の永続化スナップショットが二重管理されており、履歴リストに対する単一のデータフロー（SSoT）が確立されていない。
- **Requirement**:
  - 履歴画像のデータソースを正規化し、生成完了イベント（ローカル端末 / リモート端末を問わず）を単一のキャッシュ更新パイプラインに集約すること。
  - TanStack Query のキャッシュ無効化（`invalidateQueries`）または楽観的キャッシュ更新（`setQueryData`）を活用し、手動の配列マージ処理を廃止すること。
  - REQ-240（リアルタイム同期）の実装時に、プレビューモーダルやスクロール位置を崩さずに新規画像を先頭挿入できる拡張ポイントを確立すること。
- **Acceptance criteria**:
  - [ ] AC-1: `useGenerateDisplayState.ts` の画像ソースが TanStack Query のキャッシュ層を中心とした単一パイプラインに整理され、アドホックな三者合成ロジックが排除されていること。
  - [ ] AC-2: 新規画像が追加された際、既存のスクロール位置や詳細プレビューモーダルのインデックスが不意にジャンプしない構造になっていること。
  - [ ] AC-3: REQ-240 のリアルタイム同期イベント受信時に、単一のアクションで履歴リストの先頭に画像を安全に追加できること。
  - [ ] AC-4: `useGenerateDisplayState.test.tsx` の全テストがパスし、新規キャッシュパイプラインのテストが追加されていること。
- **Design doc**: docs/design/REQ-249.md
