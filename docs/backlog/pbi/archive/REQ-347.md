### REQ-347: 生成入力欄とSettingsマッピング欄をステージ別にまとめスクロール中も所属を示す

- **Type**: feature
- **Status**: done (2026-10-12)
- **Priority**: P2（仮置き）
- **Surface**: 生成ページで水平分割されているプロンプト入力欄とパラメータ入力欄それぞれ、Settingsのノードマッピング編集欄
- **Operational need**: 同名ロールの対象工程を見分け長い入力画面でも誤編集を避ける。
- **5 Whys / 業務上の課題整理**（ユーザー報告からの要約。実装原因の断定ではない）:
  1. 複数ステージで同名入力欄ができ区別できない。
  2. ロール名だけでは対象工程が伝わらない。
  3. 縦スクロールで所属を確認するため戻る必要がある。
  4. 工程ごとのまとまりと残る見出しなら現在の対象が分かる。
  5. 多段生成の工程文脈が入力欄に不足していることが課題である。
- **UX Classification**: Information Design / Interaction / Visual
- **Requirement**:
  - 生成ページで水平分割されているプロンプト入力欄とパラメータ入力欄のそれぞれでステージ別にグルーピングしステージ名を表示する。両欄を一つのグループや見出しへまとめない。
  - 各欄の同じステージ内ではその欄の見出しが当該入力エリア上部に残り、次のステージへ移ればその欄の見出しが切り替わる。
  - Settingsのノードマッピング編集欄でもステージ別グルーピング・当該編集エリア上部への見出し追従・ステージ境界での切替を適用する。
- **Acceptance criteria**:
  - AC-1/2/3/5は生成ページのプロンプト入力欄・パラメータ入力欄・Settingsノードマッピング編集欄の3領域それぞれで個別に検証する。プロンプト欄では同名Promptロール、パラメータ欄では同名Stepsロール、Settingsでは同名の対応付けロールを検証データとする。
  - [ ] AC-1: Given MainとRoughの両方に対象領域の同名ロールをマッピング, When その入力・編集領域を表示する, Then 当該領域内にMainとRoughのグループが各1つ表示され各欄の所属ステージが示されること。
  - [ ] AC-2: Given 同一ステージの長い入力グループ, When グループ途中へスクロールする, Then そのステージ名が入力エリア上端に見えること。
  - [ ] AC-3: Given Mainの次にRoughが並ぶ, When Rough先頭が入力エリア上端へ到達するまでスクロールする, Then 上部に残るタイトルがRoughへ切り替わること。
  - [ ] AC-4: Given 生成ページでMain/Steps=20とRough/Steps=30で同期設定なし, When Roughを40へ編集する, Then Mainは20のままでRoughだけ40になること。
  - [ ] AC-5: Given 上部に残るステージ見出し, When 直下の入力欄を操作する, Then 見出しが対象を隠さず編集できること。
  - [ ] AC-6: Given SettingsでMain/StepsがノードA、Rough/StepsがノードBへ対応付けられている, When Rough/StepsだけノードCへ変更する, Then MainはノードAを保持しRoughだけノードCになること。
  - [ ] AC-7: Given 生成プロンプト欄でMain/Promptが文字列A、Rough/Promptが文字列Bで同期設定なし, When Rough/Promptを文字列Cへ編集する, Then Mainは文字列Aを保持しRoughだけ文字列Cになること。
  - [ ] AC-8: Given 生成ページのプロンプト欄とパラメータ欄が水平分割して表示され両欄にMainとRoughの入力がある, When 両欄を表示する, Then 各欄内にそれぞれステージグループと見出しが表示され一つの共通見出しだけで代替されないこと。
