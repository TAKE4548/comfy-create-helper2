### REQ-067: 同一LoRA/タグセットを複数役割に指定した際のスナップショット保存失敗バグ

- **Type**: bug
- **Status**: done (2026-08-30)
- **Current step**: none
- **Priority**: P1
- **Surface**: 同一のLoRAやタグセットを複数の役割（例: `positive` と `negative`）に適用して生成し、スナップショットを保存しようとすると、サーバーエラー（500）が発生して保存に失敗する。
- **Root Cause**: `snapshot_loras` および `snapshot_tag_sets` テーブルのユニーク制約が `(snapshot_id, lora_id)` および `(snapshot_id, tag_set_id)` になっており、`role` カラムの重複考慮がないため、同じアセットIDが別々の役割で登録された場合に `IntegrityError` をスローする。
- **Requirement**: データベースのユニーク制約を `(snapshot_id, lora_id, role)` および `(snapshot_id, tag_set_id, role)` に更新し、同一のLoRAやタグセットを異なる役割で複数適用したスナップショットも正常に保存できるようにする。また、必要なマイグレーション処理を実装する。
- **Acceptance criteria**:
  - AC-1 (Database Schema): `models.py` における `SnapshotLora` および `SnapshotTagSet` の `UniqueConstraint` に `role` カラムを追加すること。
  - AC-2 (Migration): `main.py` の `run_migrations` にて、既存の SQLite データベースの `snapshot_loras` および `snapshot_tag_sets` テーブルのユニーク制約を `(snapshot_id, lora_id, role)` および `(snapshot_id, tag_set_id, role)` へ更新するマイグレーションロジック（SQLiteの制限により、一時テーブルを作成してデータ移行、またはインデックスの貼り替えなど）を適用すること。
  - AC-3 (Verification - LoRA): 同一の LoRA を `positive` と `negative` の双方に設定して画像を生成し、スナップショット保存を実行した際、エラーなく正常に保存され、データベースにそれぞれ異なる役割でレコードが保存されること。
  - AC-4 (Verification - TagSet): 同一のタグセットを異なる役割で適用してスナップショット保存を実行した際、エラーなく正常に保存され、データベースにそれぞれ異なる役割でレコードが保存されること。
- **Design doc**: none
