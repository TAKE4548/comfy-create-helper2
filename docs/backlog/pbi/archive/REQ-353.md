### REQ-353: Seed型randomがnoise_seedへ適用されず同一画像になる

- **Type**: bug
- **Status**: done (2026-10-12)
- **Priority**: P1
- **Surface**: frontend/src/utils/seedBatch.ts; frontend/src/utils/workflowParamInjector.ts; docs/design/REQ-350.md
- **Incident report**: [docs/incident_report_REQ-350-seed.md](../../../incident_report_REQ-350-seed.md)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: Seed型をrandomにして複数枚生成すると、ComfyUI側でも同一画像が保存される。
  2. なぜその課題が発生するか: SamplerCustomが読む`noise_seed`がバッチ間で変わらず、保存されたrandom値が実入力に反映されていない。
  3. なぜ現状の仕組みで不十分か: seed型の対象解決が`param_name`と`value`だけを確認し、設定済み`fallback_param_names`を参照しないため、`seed`という未使用キーを追加できてしまう。
  4. なぜこのアプローチを採用するか: seedバッチ検証とgraph注入で同一の実入力名を解決し、ComfyUIが実際に読むキーへの値反映を送信前に保証する必要がある。
  5. 根本原因: REQ-350のseed注入契約がfallback aliasの解決・未解決時の拒否を規定せず、`seed`/`noise_seed`の表記差があるworkflowで実値がgraphに適用されない。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 設定済みのseed型とrandom値が実際にComfyUIの入力へ届くようにし、設定表示と生成結果の不一致を解消する。
  - **Interaction (インタラクション)**:
    - graph入力名を解決できない場合は送信前に説明付きで拒否する。無効なキーを追加して生成を継続しない。
  - **Visual (視覚デザイン)**:
    - UIの見た目変更は要求しない。
- **Requirement**:
  - **1. Seed入力名の一貫した解決**:
    - Seed型mappingの実入力名を、主パラメータ名と登録済みfallback aliasから決定する。seed batch validationとgraph注入の両方で同じ解決結果を使う。
  - **2. 未解決入力の安全な扱い**:
    - 解決できるComfyUI入力がない場合、入力graphへ新しい未使用キーを追加せず、ComfyUIへの送信前に明確なエラーを返す。
  - **3. 既存workflowとの互換性**:
    - `seed`を主入力に持つSampler等のmappingと、legacyの非seed型global seed処理を維持する。
  - **4. 実値の一致**:
    - 履歴の実使用seed値とComfyUIへ送るgraphの該当入力値を一致させる。
- **Acceptance criteria**:
  - [ ] AC-1: Given `input_type=seed`、primary `param_name=seed`、fallback `noise_seed`のmappingと、`noise_seed`のみを持つSamplerCustom nodeがある, When batch seed値を解決してgraphを注入する, Then `noise_seed`が解決値で更新され、未使用の`seed`キーは追加されないこと。
  - [ ] AC-2: Given 上記mappingのrandom modeで3枚バッチを生成し、抽選値がテストで既知の異なる値である, When 各itemのgraphを送信payloadまで確認する, Then 3つのgraphそれぞれの`noise_seed`に対応する抽選値が設定されていること。
  - [ ] AC-3: Given seed型mappingの入力名がprimary/fallbackのいずれでもnodeに存在しない, When batchを準備する, Then ComfyUIへのPOST前に説明付きで失敗し、graphへ未使用の入力キーを追加しないこと。
  - [ ] AC-4: Given primary `seed`を実際に持つ既存workflow node, When fixedまたはrandomのseed型生成を行う, Then 従来どおりその`seed`入力に値が適用されること。
  - [ ] AC-5: Given 生成が成功したseed型item, When prompt metadata/history recordを確認する, Then 記録された実使用値が送信graphの解決済みseed入力値と一致すること。
- **Inferred points**:
  - ComfyUIのHTTPログはPOST本文を保持せず、generation_jobsのgraph_jsonは成功後に消去されるため、診断可能性の改善は設計時に検討する。Incident reportに今回観測できたDB値、prompt ID、POST status、およびこの制約を記録した。
  - 現在の再現では各seed型のmetadata値は異なっていた。ComfyUI native UIにも同一画像が保存されることはユーザーが確認した。
