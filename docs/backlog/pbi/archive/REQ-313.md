### REQ-313: Prompt Surgeon: FuguMT翻訳エンジンの高度化（文末分割・強度タグ正規化・Danbooru辞書引き統合）

- **Type**: feature
- **Status**: done (2026-10-03)
- **Current step**: none
- **Priority**: P1
- **Surface**: 画像生成プロンプトにおいて、複数文の自然文での訳抜け、強調構文（重み括弧）の翻訳スキップや推論阻害、アニメ・Danbooru特有タグの直訳・誤訳を解消するため、仕様書 (`tmp/fugumt_sentence_split_and_danbooru_dict_spec.html`) に従って、文末ピリオド分割・強度タグアンパック・Danbooru日英対訳辞書（`tmp/danbooruTagCompleteCsv_v1020250919.zip`）先行照会・再パックパイプラインを統合したい。
- **5 Whys / Root Cause**:
  1. なぜ変更が必要か: プロンプト和訳において、ピリオドで区切られた複数文の後半が丸ごと脱落し、強調タグ（`((smile:1.2))`等）が未翻訳になるか記号混入で推論が乱れ、`ahoge` や `cat_ears` などの特有語彗が不自然に直訳されるため。
  2. なぜ複数文の脱落や構文乱れが起きるのか: FuguMT（Marian-NMT）が文単位モデルであるにもかかわらずピリオド連結文を1チャンクとして入力していること、強調括弧・コロン数値の前処理が未対応であること、Danbooru特有のオタク語彗・アンダースコア結合語の対訳知識を汎用機械翻訳モデルが持たないため。
  3. なぜそれがユーザー体験を阻害するのか: プロンプト全文翻訳やタグチップ確認時に意図と異なる訳や構文破壊が生じ、長文プロンプトの後半が消えることで画像生成の意図確認・プロンプト修正の試行錯誤体験を著しく損ねるため。
  4. なぜ文末分割・強度アンパック・Danbooru辞書引きのパイプラインが有効か: 翻訳処理を「構文退避 → 文分割 → 強度アンパック → 辞書引き → FuguMT推論 → 再パック」に体系化することで、オタク語彗の即座（0ms）確定、複数文の確実な並行推論、構文整合性の維持を両立できるため。
  5. 根本原因: 画像生成プロンプト特有のメタ構文（重み・多重括弧・アンダースコア結合）と専門ドメイン辞書の協調パイプラインが未実装であることに起因する。
- **UX Classification**:
  - **Information Design (情報設計)**: 英語プロンプトから日本語訳（UI表示・理解用）を導出する和訳パイプラインにおいて、タグチップ和訳カードでは強度記号を除去した明瞭な純粋日本語を表示し、プロンプト全文和訳では元の強度構文・文末ピリオド構造を維持して再パックする出力整合性。Danbooru辞書定訳（オタク語彗）とFuguMT（自然文）の明確な役割分担。
  - **Interaction (インタラクション)**: 頻出Danbooruタグ照会時はFuguMT推論をスキップして即座（0ms）に和訳を確定・返却し、複数文の自然文プロンプトも文単位の確実な並行推論で訳抜けのないレスポンスを提供。
  - **Visual (視覚デザイン)**: タグカードおよびプロンプト入力欄において、記号混じりのノイズを排した可読性の高い日本語訳表示。
- **Requirement**:
  - **1. 文末ピリオド・句点チャンク分割と空白正規化**:
    - 重み小数の数値（:1.2 等）や三点リーダー（...）を誤分割せず、「直後が空白または文字列終端であるピリオド」、カンマ、改行、句読点（、, 。）、感嘆符・疑問符（!?）で適切に文・チャンク単位に分割する。
    - 連続する区切り記号によって生じる空文字列（空チャンク）は除外し、推論エラーやマージ破綻を防止する。
  - **2. 強度タグのアンパックと再パック**:
    - 入力チャンクから外側の強調括弧群（任意の重ねを含む ( [ {）およびコロン数値（:1.2）を抽出し、アンダースコアを空白に置換した上で連続空白を1つに正規化したクリーンなコア文字列を生成する。
    - 出力用途に応じて、タグチップ用には純粋なコア日本語訳を返し、プロンプト置換用には元の強度括弧と重み数値を再付与（再パック）して復元する。
  - **3. Danbooru 日英対訳辞書のロードと先行照会**:
    - 	mp/danbooruTagCompleteCsv_v1020250919.zip 内の danbooru_translations_jp.csv（Tag -> Japanese 対訳形式）または展開ファイル（	mp/danbooru_translations_jp.csv, 	mp/danbooru_ja.csv 等）を検索・ロードし、インメモリ辞書に保持する。文字コードは UTF-8 （エラー時 CP932 フォールバック）で安全に読み込む。
    - クリーン化されたコア英単語が辞書に存在する場合、FuguMT推論を行わずに即時定訳を採用する（0ms 応答・CPU負荷削減）。
  - **4. FuguMT バッチ推論と結果マージ**:
    - 辞書に未登録のタグや自然文のみを FuguMT（CTranslate2）の並行バッチ推論に渡し、辞書ヒット結果と統合して順序通りにマージする。
  - **5. メタ構文の保護と Graceful Degradation**:
    - <lora:...>, embedding:... 等のメタ構文は翻訳前に退避し、翻訳後に無傷で復元する。
    - 辞書ファイルが未配置または読み込み不能な場合でもシステムエラーとせず、FuguMT のみの単独推論へ安全にフォールバックする。
- **Acceptance criteria**:
  - [ ] AC-1: Given ピリオドを含む複数文の自然文プロンプト（例: A girl smiles. She reads a book.）が入力されたとき, When 翻訳パイプラインを実行した際, 重み小数や三点リーダー（...）を誤分割することなく文単位に分割され、空チャンクは排除され、FuguMT によりすべての文が訳抜けなく正しく翻訳されること。
  - [ ] AC-2: Given 強調・重み指定タグ（例: ((cat_ears:1.2)) や [smile]）が入力されたとき, When アンパック処理が行われた際, 外側の括弧群とコロン重み数値が分離され、アンダースコアが空白化され連続空白が単一空白に正規化されたクリーンなコア文字列（例: cat ears）が翻訳処理に渡されること。
  - [ ] AC-3: Given Danbooru 日英対訳辞書（danbooru_translations_jp.csv / zip配置）が利用可能なとき, When 英語アニメ特有タグ（例: hoge や cat_ears）が照会された際, FuguMT 推論をスキップして辞書内の日本語定訳（例: アホ毛, 猫耳）が即時採用されること。
  - [ ] AC-4: Given Danbooru 辞書に未登録の語彗または自然文が含まれるとき, When 翻訳パイプラインを実行した際, 辞書未登録分のみが FuguMT バッチ推論に送られ、辞書ヒット結果と元の順序を保ってマージされること。
  - [ ] AC-5: Given 強調・重み指定タグの和訳結果を出力するとき, When タグチップ和訳カード表示用では強度括弧を除いたクリーンな日本語（例: 猫耳）が返され、プロンプト全文和訳用では元の強度括弧と重み数値が再パックされた文字列（例: ((猫耳:1.2))）が返されること。
  - [ ] AC-6: Given 辞書ファイルが存在しない、または読み込みに失敗した場合, When 翻訳パイプラインを実行した際, エラーでクラッシュすることなく FuguMT のみで全タグ・自然文の推論を継続する Graceful Degradation が動作すること。
  - [ ] AC-7: Given メタ構文（<lora:...>, embedding:... 等）を含むプロンプトが入力されたとき, When 翻訳パイプラインを実行した際, メタ構文が退避・復元され、構文破壊されることなくそのまま維持されること。
- **Inferred points**:
  - 辞書ファイルは `tmp/danbooruTagCompleteCsv_v1020250919.zip` 内の `danbooru_translations_jp.csv`（tag, translation形式）を最優先とし、`tmp/danbooru_ja.csv` や `tmp/danbooru.csv` への展開ファイルもサポートする。
  - バックエンド `translation_service.py` の内部パイプライン改修であり、既存フロントエンドとのAPI通信契約（プロンプト全文翻訳・タグ翻訳エンドポイント）の下位互換性を維持する。
