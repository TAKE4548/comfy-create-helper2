### REQ-207: グローバル状態管理（useGenerationStore）の責務分離・スライス化およびWebSocketライフサイクルの疎結合化
- **Type**: refactor
- **Status**: done (2026-08-30)
- **Current step**: Phase 1: Requirement Analysis
- **Priority**: P1
- **Surface**:
  - `frontend/src/store/useGenerationStore.ts` が1,700行を超える単一の巨大ストアとなっており、WebSocket通信・ジョブキュー管理・バイパスプロファイル・パラメータ同期グループ・マルチセット管理・LocalStorage永続化など、無関係な責務が強結合している。
  - ストアモジュール直下に定義されたミュータブルなシングルトン変数（`let ws`, `let isInitializing`, `let reconnectTimer`, `activeSubmissionPromise` 等）がZustandの状態ツリー外に存在し、再初期化時やテスト実行時、高速な画面遷移時に競合状態（Race Condition）やメモリリークを引き起こす潜在デグレリスクが存在する。
  - `bypassProfiles` と `bypassProfilesCache`、`paramSyncGroups` と `paramSyncGroupsCache`、`sets` と `localStorage` の二重状態管理が行われており、APIエラーや部分更新時にキャッシュとの不整合が発生しやすい。
- **Root Cause**:
  - **Architecture Design (Monolithic Store Anti-Pattern)**: 機能追加（Bypass Profiles, Param Sync, Multi-Set, Batch Jobs）ごとに単一の `useGenerationStore` に直接状態とアクションを追加し続けた結果、関心の分離（Separation of Concerns）が破綻し、AIエージェントのコンテキスト読解時にも認知的過負荷を生じさせている。
  - **State Machine Leakage**: WebSocketの接続ライフサイクル管理が状態ストアと直接癒着し、モジュールグローバル変数として保持されているため、状態の決定論的制御・テスト容易性が損なわれている。
- **Requirement**:
  - `useGenerationStore` を Zustand のスライスパターン（Slices Pattern）または独立したサブストア（WebSocket/Connection Slice, Bypass Slice, ParamSync Slice, GenerationSets Slice, JobQueue Slice）へ分割し、各ドメインの凝集度を高めること。
  - モジュール直下のシングルトン変数を廃止し、WebSocketクライアントのライフサイクルを明示的なサービスクラスまたはストア内管理にカプセル化すること。
  - キャッシュとローカル状態の二重管理を解消し、TanStack Queryのキャッシュまたは正規化された単一の真実の源泉（SSoT）へ整理すること。
  - 既存の公開API（外部から呼び出されるアクションや状態プロパティ）に対する完全な後方互換性を維持し、各スライスのユニットテストを独立して記述・実行可能にすること。
- **Acceptance criteria**:
  - [ ] AC-1: `useGenerationStore` のロジックが各ドメインスライス（`connectionSlice`, `bypassSlice`, `paramSyncSlice`, `multiSetSlice`, `jobQueueSlice`）に分割され、各ファイルの行数が適切な規模（300行以内）に収まっていること。
  - [ ] AC-2: `ws`, `reconnectTimer` 等のモジュール外シングルトン変数が排除され、ライフサイクル管理が安全にカプセル化されていること。
  - [ ] AC-3: `bypassProfilesCache` や `paramSyncGroupsCache` の二重管理が整理され、状態更新時にキャッシュ不整合やStale表示が発生しないこと。
  - [ ] AC-4: 既存の全テストスイート（`npm test`）が修正なし、またはより堅牢なスライステストによってすべてパスすること。
