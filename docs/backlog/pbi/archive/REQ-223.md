### REQ-223: サーバ再起動時におけるTagChipEditorプロンプト消失バグ解消

- **Type**: defect
- **Status**: done (2026-09-06)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - サーバをrebootすると、req222のアクティブ入力欄からプロンプトが消失する不具合が再発している。コピペの不具合は再発していない。
- **Root Cause**:
  - `TagChipEditor` の初回マウント時、ローカル state が空チップ配列（`[]`）で初期化され、内部通知 Effect により直ちに `onChipsChange?.([])` が親ストアへ通知されてアクティブセットの `promptChips` に空配列が注入される。
  - `multiSetSlice.loadPresetData` において、`s.promptChips && Object.keys(s.promptChips).length > 0 ? s.promptChips : initialPromptChips` の判定が空配列 `{ [role]: [] }` を「既存チップあり」と誤認し、DBからパースされた有効な `initialPromptChips` を破棄してしまう。
  - その後、`TagChipEditor` が空チップ状態のまま `onChange?.("")` を発火して親の `paramValues` を空文字で上書きし、自動保存 Effect によりバックエンドDBまで空文字で上書き保存されてプロンプトが恒久的に消失する。
- **Requirement**:
  - サーバ再起動、画面リロード、または初期マウント時において、アクティブプリセットに保存されているプロンプト文字列およびタグチップが消失せず、正確に入力欄に復元・表示されること。
  - 初期化前の空チップ状態が親ストアの有効なプロンプトを上書き破壊しないこと。
- **Acceptance criteria**:
  - [ ] AC-1: プロンプトが保存されたプリセットがアクティブな状態でサーバ再起動または画面リロードを行っても、入力欄（TagChipEditor）のプロンプトおよびタグチップが消失せず、正常に表示されること。
  - [ ] AC-2: `TagChipEditor` の初回マウント時やデータ読み込み待ちの過渡状態において、未同期の空チップ状態によって親のプロンプト平文（`paramValues`）が空文字で上書きされないこと。
  - [ ] AC-3: `loadPresetData` において、各 role のチップ配列が空である場合に誤って既存チップとして採用されず、プリセットの `param_values` から正しくパースされたチップ（`initialPromptChips`）が復元されること。
  - [ ] AC-4: プリセット切替機能およびセクションコピペ機能（REQ-222で解消した機能）が退行せず、引き続き正常に動作すること。
  - [ ] AC-5: 関連する自動テストがすべてパスすること。
- **Design doc**: docs/design/REQ-223.md
