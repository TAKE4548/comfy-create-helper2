### REQ-296: セリフ一括生成のVLM非JSON応答とLM Studioアンロード誤判定を修正

- **Type**: bug
- **Status**: done (2026-09-30)
- **Priority**: P1
- **Incident report**: `docs/incident_report.md`
- **Description**: セリフ一括生成の初段階で、VLM が HTTP 200 で返した非 JSON の画像説明を JSON として解析し、HTTP 500 になる。JSON 生成を求める system 指示と画像説明を求める user 指示が競合しており、同じモデル・指示・出力上限の制御再現で同じ JSONDecodeError を確認した。また後処理で LM Studio 未対応の `POST /v1/models/unload` に空 JSON を送信し、LM Studio の HTTP 200 をアンロード成功と誤判定する。2件を一体のバグとして修正し、生成結果と VRAM 解放状態をそれぞれ正しく扱う。
- **Scope**: VLM への指示・出力契約、応答検証とエラー処理、LM Studio アンロード契約、関連 SSoT、局所回帰テスト。既存の2系統参照選定やUIフローは維持する。

#### Acceptance Criteria (AC)
- [x] AC-1（JSON生成）: Given セリフ一括生成で画像と2系統参照をVLMに送るとき、When リクエストを構築して推論すると、Then system/user の指示が同じセリフ生成タスクを要求し、対応するモデル設定では `scene_interpretation` 文字列と1件以上の `items` 配列からなるJSON Schemaを適用する。各itemは `role` (`main`/`sub`/`se`)、`speaker` 文字列、`text` 文字列、`position` (`top_right`/`center_right`/`center`/`top_left`/`bottom_left`) のみを持ち、既存吹き出しへ変換して下流へ渡す。
- [x] AC-2（異常応答）: Given VLM が空本文、非JSON、スキーマ不一致、出力途中終了、拒否、choices欠落のいずれかを返したとき、When 応答を処理すると、Then `vlm_empty`、`vlm_invalid_json`、`vlm_schema_invalid`、`vlm_truncated`、`vlm_filtered`、`vlm_response_shape_invalid` の原因コードで分類した安全な診断情報を残し、ユーザーへ制御された失敗を返す。応答全文や画像内容をログへ漏らさず、未処理例外による HTTP 500 を出さない。
- [x] AC-3（アンロード成功）: Given 推論に使うLM Studioモデルインスタンスが未ロード、ロード済み、またはload応答が不明のとき、When 取得/ロード後に推論と後処理を行うと、Then list/unload要求は各4秒、load要求と処理全体は最大120秒で待つ。loadのReadTimeout/期限超過後は最大20秒・1秒間隔で一覧を再照会し、同一モデルの単一 `instance_id` を回収できた場合はそのIDを推論とアンロードの両方に使う。Chat Completionsが厳密にHTTP 400 `{"error":"Model is unloaded."}` を返したときだけ、同じID・同じrequestを最大90秒・1秒間隔で再試行する。readiness retry中の各POST timeoutは最大60秒を残り期限でcapし、同window中のReadTimeout後も期限内で再試行する。loadは再送しない。他の400/Readiness sentinel前の通信失敗は再試行しない。成功した場合は解放状態を再照会し、対象IDの消失を確認してから解放成功と報告する。非2xx unload応答でも一覧で対象IDの不在を確認できた場合は解放済みとみなし、残存/照会不能なら失敗とする。
- [x] AC-4（アンロード失敗）: Given LM Studio が未対応エンドポイントへHTTP 200を返す、unload応答が不正または非2xx、対象IDが残存、または状態照会に失敗するとき、When 後処理すると、Then 対象IDの消失を有効なロード一覧で確認した場合だけ解放済みと扱い、それ以外は成功にせず、生成エラーを保って安全に診断する。
- [x] AC-5（仕様と回帰）: Given REQ-291 の既存 SSoT と実装があるとき、When 本PBIを完了すると、Then アンロード API・インスタンス識別・成功判定の仕様が更新され、非 JSON 応答の制御再現、正常 JSON 応答、生成失敗時の後処理、アンロード成功/失敗の局所テストが通る。
