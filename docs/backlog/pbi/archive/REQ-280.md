### REQ-280: プロンプト編集オートセーブ競合（OCC）誤発火およびポーリングタイマーリセット遅延の解消

- **Type**: bug
- **Status**: done (2026-09-21)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - `frontend/src/pages/GeneratePage/hooks/usePresetState.ts`
  - `tmp/Prompt_Surgeon_Prompt_Edit_Conflict_and_Autosave_Analysis.pdf`
  - `docs/incident_report.md`
- **Background & Context**:
  - 単一クライアントでプロンプト編集やパラメータ調整を行っている際に、他端末が関与していないにもかかわらず「他セッションで更新されました」という競合モーダル（`PresetConflictModal`）が頻発する。
  - さらに、定期ポーリング（5秒間隔）を受信するたびにオートセーブのデバウンスタイマーが不意にクリア・延命され、1秒待った直後の生成で旧パラメータが採用される遅延要因となっている。
  - これらは「競合モーダル誤発火（直接要因①: In-flight二重送信による409、直接要因②: キー順序や空白差分による偽のisDirty残留）」と「保存遅延（別問題: useEffectのpresets依存）」という2つの独立した課題である。

- **Requirement (是正方針)**:
  1. **オートセーブ直列化 (In-flight ガード)**:
     - `updatePresetMutation.isPending` 中は新規 PUT リクエストを待機させ、前回の完了レスポンス（最新 `updated_at`）を受領した後に最新差分を1回だけ送信する。これにより通信中の多重送信による古い `base_updated_at` での 409 Conflict を物理的に根絶する。
  2. **差分判定の適正化 (キー順序非依存)**:
     - `usePresetState.ts` 内の `isStateEqual` で `JSON.stringify` を廃止し、キー順序に依存しない浅い比較（`isRecordEqual`）に切り替え、スプレッド構文や辞書シリアライズ順のズレによる偽の未保存判定（`isDirty = true`）を根絶する。
  3. **テキストモード送信時正規化**:
     - textarea 入力中は生テキストを許容し、オートセーブ送信時（または onBlur 時）に正規化した文字列（`chipsToString(parseToChips(...))`）で保存および手元キャッシュに反映させ、末尾空白等のズレによる `isDirty` 誤認を防止する。
  4. **タイマー制御からの presets 依存分離**:
     - オートセーブ用 `useEffect` の依存配列から `presets` を除外し、`presetsRef.current` を参照することで、5秒ごとのポーリング受信時にタイマーがリセット延命される現象を解消する。

- **Acceptance criteria**:
  - [ ] AC-1: タイピングやパラメータ変更を連続して行っても、In-flight ガードにより HTTP 409 Conflict が発生せず、最新の値が正常に単一セッションで保存されること。
  - [ ] AC-2: オブジェクトのキー順序が入れ替わっても `isStateEqual` が正常に一致判定され、偽の `isDirty` が残留しないこと。
  - [ ] AC-3: テキストモードで末尾空白を含む文字列を入力しても、オートセーブ後に手元状態とキャッシュが一致し、ポーリング受信時に競合モーダルが誤発火しないこと。
  - [ ] AC-4: 5秒ごとの定期ポーリングが発生しても、オートセーブの1秒デバウンスタイマーが不意にリセットされず、入力停止後1秒で正しく保存がトリガーされること。
  - [ ] AC-5: 既存の他端末編集時の正常な競合検知（真の 409 Conflict）および手動保存（`flushAutoSave`）の動作が破壊されていないこと。
