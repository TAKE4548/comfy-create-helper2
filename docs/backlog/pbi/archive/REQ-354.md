### REQ-354: Workflow取得APIがSeed fallback aliasを返さず生成を事前拒否する

- **Type**: bug
- **Status**: done (2026-10-13)
- **Priority**: P1
- **Surface**: backend/app/routers/workflows.py; frontend/src/utils/seedBatch.ts; frontend/src/utils/seedInputResolver.ts
- **Incident report**: [docs/incident_report_REQ-353-fallback-regression.md](../../../incident_report_REQ-353-fallback-regression.md)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: workflow 69のRough/Detail samplerで`noise_seed`へseed値を適用すべきだが、Generate時にseed入力がない旨で事前拒否され、ComfyUI queueへ届かない。
  2. なぜその課題が発生するか: master 4には`fallback_param_names=["noise_seed"]`が保存されている一方、稼働中`GET /api/workflows/69`はseed mappingのfallbackを`null`で返す。
  3. なぜ現状の仕組みで不十分か: FEのSeed resolverはworkflow API応答の`param_name`と`fallback_param_names`だけを使うため、応答からfallbackが欠落すると`seed`だけを探し、実nodeの`noise_seed`へ到達できない。
  4. なぜこのアプローチを採用するか: workflow取得APIの実行環境を現行契約へ揃え、登録済aliasをFEへ返す必要がある。推測で別inputを選ぶと誤ったgraph keyを生成し得る。
  5. 根本原因: 稼働中BEのworkflow取得応答が保存済みfallback aliasを失っている。workspace sourceでは伝搬実装が存在するため、古いプロセスまたは別の実行コードが読み込まれている可能性がある。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - mapping masterに登録されたfallbackがworkflow応答にも維持され、設定とGenerateの挙動が一致する。
  - **Interaction (インタラクション)**:
    - `noise_seed`のみを持つSamplerCustom nodeでseedバッチ検証を通過し、ComfyUIへqueueされる。解決不能な場合は現在どおりPOST前に拒否する。
  - **Visual (視覚デザイン)**:
    - UIの見た目変更は要求しない。
- **Requirement**:
  - **1. Workflow API alias伝搬**:
    - WorkflowMappingのprimary/fallback metadataを有効masterから返し、persisted fallback aliasをnullへ落とさない。実行中プロセスが現行sourceを使用していることも確認する。
  - **2. Generate前検証**:
    - FEの初期値取得、seed batch validation、graph注入で登録済fallbackを同じ順序で解決し、`noise_seed`へSeed値を適用する。
  - **3. 安全な拒否維持**:
    - primaryと全fallbackがnodeにない場合、未登録inputを作らずComfyUI POST前に説明付きで拒否する。
- **Acceptance criteria**:
  - [x] AC-1: Given mapping masterの`param_name=seed`と`fallback_param_names=[noise_seed]`、workflow nodeに`noise_seed`のみがある, When `GET /api/workflows/{id}`を呼ぶ, Then response mappingに`fallback_param_names=[noise_seed]`が含まれること。
  - [x] AC-2: Given AC-1のmappingと稼働中FE/BE, When Generateでseed batchを準備する, Then seed検証が`noise_seed`を解決し、ComfyUIへのqueue要求に進むこと。
  - [x] AC-3: Given random seed値が既知の3件, When 3件のgraph payloadを確認する, Then 各graphの`noise_seed`にそれぞれの値が入り、余分な`seed` keyが追加されないこと。
  - [x] AC-4: Given primary/fallbackのどちらもnodeにないmapping, When Generateする, Then ComfyUIへPOSTせず、候補を含むエラーで拒否すること。ユーザー承認によりT3自動回帰を受入証拠とし、HTTP POST件数は未計測。
- **Inferred points**:
  - master 4の個別APIは`fallback_param_names=[noise_seed]`、workflow 69の7 seed mappingのworkflow API応答はfallback null。Rough/Detail nodes 1260:1398/1260:1396は`noise_seed`のみを持つ。
  - 現行sourceのworkflow routerはfallback伝搬実装を含むが、稼働runtimeの応答と一致しない。PBIは実行環境のコード更新・再起動/正しいruntimeの特定を含めて調査する。
