### REQ-190: ComfyUIジョブ削除・キュー投入のレスポンス遅延解消と通信オーケストレーション最適化
- **Type**: bugfix
- **Status**: in_progress
- **Current step**: Phase 2: Detailed Design
- **Priority**: P1
- **Surface**: ComfyUIのサーバを起動してから何度か生成を繰り返していると、キュー投入・job削除のレスポンスが悪くなり、特にjob削除が顕著に遅くなる。
- **Root Cause**:
  1. 【Store/不要通信と直列待機】`useGenerationStore.ts` の `cancelJob` / `clearPendingQueue` / `cancelAllJobs` において、待機中ジョブ（Pending）に対する不要な `deleteHistory` の呼び出し、および ComfyUI の WebSocket `status` 通知と重複する末尾の `fetchQueue()` 直列同期待ち（計3往復の直列 HTTP 通信）により、UIスレッドが数秒〜十数秒ブロックされる。
  2. 【Store/履歴フェッチの重複と肥大化】ジョブ完了時（`executing: node=null`, `executed`, `execution_complete`）に `fetchHistory`（`GET /api/comfy/history?max_items=100`）が高頻度で多重発火し、ComfyUI およびバックエンドプロキシの通信帯域・イベントループを圧迫している。
  3. 【Store/楽観的UI更新の欠落】ジョブ削除ボタン押下時にローカル状態（`queuePending`）が即時更新されず、全 HTTP リクエストが完了するまでモーダル上の表示が残るため、体感遅延が増幅されている。
- **Requirement**: ジョブ削除・一括クリア・中断処理における不要な API 呼び出しと冗長な `fetchQueue` 同期待ちを排除し、楽観的UI更新および `fetchHistory` のデバウンス/間引きを導入することで、生成を繰り返した後でもキュー投入・ジョブ削除が即座（数十〜数百ミリ秒以内）に応答するよう通信オーケストレーションを最適化する。
- **Acceptance criteria**:
  - [ ] AC-1: 待機中ジョブ（Pending）の削除（`cancelJob`）時、不要な `deleteHistory` を呼び出さず、かつ末尾の直列 `fetchQueue` 同期待ちを排除して WebSocket 駆動および楽観的更新により即座に UI から削除されること
  - [ ] AC-2: 「キューのみクリア（`clearPendingQueue`）」および「すべて中断（`cancelAllJobs`）」においても、冗長な末尾 `fetchQueue` 同期待ちを排除し、非同期に即座に応答すること
  - [ ] AC-3: ジョブ完了時における `fetchHistory` の重複呼び出しを整理・間引きし、不要な多重履歴フェッチによる ComfyUI / バックエンドの負荷集中を防止すること
  - [ ] AC-4: 単体生成・バッチ生成・セット一括生成のキュー投入（`queuePrompt`）において、既存の進捗表示・生成完了ハンドリング・中断機能にデグレーションが発生しないこと
