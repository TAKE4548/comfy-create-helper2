### REQ-277: パラメータ変更後の即時生成における最新値未反映およびセット間不整合の根本解消

- **Type**: defect
- **Status**: done (2026-09-19)
- **Current step**: Phase 1 (Design)
- **Priority**: P1
- **Surface**:
  - 生成画面（Generate ページ）において、ステップ数、スケジューラ、CFG、Denoise、アスペクト比などのパラメータを変更しても、ページをリロード（F5）しないと生成結果に反映されない（前回の古い値のままキュー投入される）。
  - ページをリロードした後は、変更後の値で正常に生成される。
  - パラメータ変更後1秒以上待ってオートセーブが完了した後に生成しても、リロードしないと反映されない。
  - プロンプト側（`Prompt_Pose_Action` など）はリロードなしでも変更が即座に生成へ反映されている。
  - 画面に表示されているパラメータの入力値自体は巻き戻っておらず、変更後の最新値が表示され続けている。
- **Root Cause**:
  - **根本原因 1: `usePresetState.flushAutoSave` のクロージャ参照による古い値の上書き**:
    - `handleGenerateSets` の呼び出し直前に先行実行される `options.onBeforeGenerate`（`presetState.flushAutoSave`）が、フックレンダリング時のクロージャ変数 `paramValues`（古い値）を参照して `currentState` を構築し、`updateActiveSet(currentState)` や `updatePresetMutation.mutate` を呼び出すため、直前に入力された最新パラメータが古い値でインメモリ上書きされていた。
  - **根本原因 2: プロンプト（`promptChips`）とパラメータ（`paramValues`）の合成経路の非対称性**:
    - プロンプト項目は `TagChipEditor` の変更契機で `promptChips`（タグ構造体）が更新され、最終ペイロード生成時に `getEffectiveParamValues` で `promptChips` から平文が再生成されて強制上書きされるため、`paramValues` が古くても最新値が反映されていた。
    - 一方、パラメータ項目（ステップ数、CFG、スケジューラ、アスペクト比など）は `promptChips` を持たないため 100% `itemParams`（`paramValues`）に依存しており、上記クロージャ上書きや同期ズレの影響を直撃して旧値のまま投入されていた。
  - **根本原因 3: テスト検証パイプラインの重大な偽陽性（不備）**:
    - 従来のテスト（`useGenerateAction.test.ts`）は、ComfyUI 投入ワークフロー（第1引数 `wfJson`）を一切検査せず、保存用メタデータ（第2引数）のみを検証していた。さらにテスト用ワークフローに mapping が存在しないため、実際のパラメータ注入パイプラインが形骸化していた。
- **Requirement**:
  - 生成ボタンが押下された瞬間に、画面上で編集・表示されている最新のパラメータ値（`paramValues`）が、ページのリロード有無やオートセーブの完了待ちに関わらず、100% 確実に ComfyUI 投入ペイロード（`wfJson` の各ノード inputs）へ反映されること。
  - `flushAutoSave` および `usePresetState` において、クロージャ変数による古い `paramValues` の書き戻しを完全に排除し、Zustand ストアの最新状態を一元参照すること。
  - 単一セット時や複数セット時を問わず、アクティブに編集中の画面パラメータが確実に反映され、プロンプトとパラメータの反映挙動に一切の齟齬が生じないこと。
- **Acceptance criteria**:
  - [x] AC-1: ステップ数、スケジューラ、CFG、Denoise、アスペクト比等の任意のパラメータ変更後、ページをリロードすることなく即時（1秒未満）に生成ボタンを押下した場合でも、変更後のパラメータが 100% 確実に ComfyUI ペイロード（`wfJson` の各ノード inputs）に反映されてキュー投入されること。
  - [x] AC-2: パラメータ変更後 1 秒以上待機（オートセーブ完了後）してからリロードなしで生成ボタンを押下した場合でも、変更後のパラメータが 100% 確実に `wfJson` に反映されてキュー投入されること。
  - [x] AC-3: 単一セット運用時および複数セット運用時のいずれにおいても、現在アクティブに編集しているセットの画面パラメータが確実にジョブ（`wfJson` inputs）へ適用され、非アクティブセットの個別パラメータは保持されること。
  - [x] AC-4: テスト計画（抜け道防止 5 大ルール AL-1〜AL-5）に基づき、`queuePrompt` の第1引数 `wfJson` の各ノード `inputs` および先行オートセーブ協調・初期値乖離を検証する自動テストスイートが整備され、すべて PASS すること。
  - [x] AC-5: `useGeneratePageState` のフック結合テストを含め、既存・新規の全テストスイート（Vitest）がすべて PASS すること。
