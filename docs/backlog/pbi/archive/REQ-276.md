### REQ-276: 生成パラメータ変更直後の反映不全およびプリセット誤再同期（巻き戻り）の根本解消

- **Type**: bugfix
- **Status**: done (2026-09-18)
- **Current step**: Phase 2 (Detailed Design)
- **Priority**: P1
- **Surface**:
  - 生成画面（Generate ページ）において、アスペクト比（`aspect_ratio`）などの生成パラメータを変更した直後に「生成」ボタンを押しても、変更が ComfyUI に反映されず前回の値のまま生成される。
  - 複数回生成を繰り返していると、遅れて変更後のアスペクト比で生成されることがある。
- **Root Cause**:
  - **根本原因 1: `updated_at` のシリアライズ形式不一致による不要なプリセット再同期（主因）**:
    - `backend/app/routers/presets.py` では `datetime.now(timezone.utc)` を設定し、レスポンスでは UTC ISO 文字列（末尾 `Z` 付き）を返す。
    - 一方、`GET /api/workflow-presets` 取得時は SQLite から naive datetime として読み出されるため、末尾に `Z` のない文字列としてシリアライズされる。
    - `frontend/src/pages/GeneratePage/hooks/usePresetState.ts` の `presetUpdatedAtRef.current[activePreset.id] !== activePreset.updated_at` による文字列比較が「末尾 Z の有無」により常に TRUE となり、オートセーブ直後のクエリ無効化やポーリング時にサーバー側の古い値でフロントのストアが上書きされる。
  - **根本原因 2: オートセーブ（1秒デバウンス）と即時生成のタイミング競合**:
    - パラメータ変更後 1 秒以内の生成押下時に、オートセーブ未完了のままプロンプトが送信されたり、ポーリングで旧値に巻き戻される。
  - **根本原因 3: ロール名リネームとプリセットキーの構造的分断 & 旧キー混在**:
    - `mapping_master` の更新 API（`PUT /api/mapping-masters/{id}`）がロール名変更時にプリセットデータをカスケード更新しないため、過去の17文字切り捨て旧キー（`Resolution Selecto`）が DB 内に残存し、初期値フォールバックが誘発されていた。
- **Requirement**:
  - `usePresetState.ts` における `updated_at` の日時比較を正規化（ミリ秒比較・1秒未満の端数同一判定）し、同一日時の形式差異による不要な `loadPresetData` を完全に防止すること。
  - 自端末のオートセーブ成功時に不要な全件自己再フェッチ（`invalidateQueries`）を発火させず、キャッシュ直接更新のみで整合性を保つこと。
  - オートセーブのデバウンス時間（1秒）は維持しつつ、生成ボタン押下時に未保存パラメータを即時フラッシュ（保存）し、最新の UI 編集値が確実に ComfyUI 投入ペイロードに反映されること。
  - `mapping_master` のロール名変更・タイポ修正時に、DB 内の全プリセット JSON キーを自動追従させる「カスケード置換」を導入すること。
  - 既存 DB 内の 636 件の旧キー `'Resolution Selecto'` を正規キー `'Resolution Selector'` に一括正規化すること。
  - フロントエンドのロード時にも、旧キーを正規キーへ自動読み替えする「自己修復（Self-Healing）」を設けること。
- **Acceptance criteria**:
  - [ ] AC-1: アスペクト比変更後、1秒以内の即時生成であっても変更後のアスペクト比で確実に ComfyUI にキュー投入されること。
  - [ ] AC-2: `updated_at` の形式差異（末尾 Z の有無）による不要なプリセット再同期（パラメータ巻き戻り）が発生しないこと。
  - [ ] AC-3: マッピングマスターのロール名を更新した際、DB 内の関連プリセットの `param_values` 内のキーが自動的にカスケード置換されること。
  - [ ] AC-4: DB 内のプリセットデータにおいて `'Resolution Selecto'` の旧キーが正規キー `'Resolution Selector'` に一括正規化されること。
  - [ ] AC-5: 他端末でプリセットが更新された場合（5秒ポーリング）、これまで通り正常に更新検知（未保存時は競合モーダル、未編集時は自動反映）されること。
  - [ ] AC-6: 回帰テスト（ユニットテスト・API テスト等）がすべて PASS すること。
