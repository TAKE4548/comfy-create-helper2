### REQ-386: 生成中ステップ進捗（個別プログレスバー）の停止および次画像完了までのプレビュー表示遅延の解消

- **Type**: bug
- **Status**: done (2026-10-20)
- **Priority**: P1
- **Surface**: Desktop / Mobile Generate UI, Generation State & Progress Synchronization
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: 画像生成中に個別のノード/ステップ進捗（個別プログレスバー）が停止したまま動かず、さらに生成された画像のプレビューが次の画像の生成完了タイミングまで表示されない（または大幅に遅延する）ため。
  2. なぜその課題が発生するか:
     - 個別プログレスバー: WebSocket等で配信されるステップ進捗（progress）のイベントがUIコンポーネント（個別プログレス表示部）へ正確に伝播・バインドされていないか、表示対象ノード/ジョブのID不一致により更新がスキップされているため。
     - プレビュー遅延: バッチ生成等において、直前の画像生成完了（succeeded）契機の最新画像URL・ステート更新が即座にプレビュー表示（auto-follow）に反映されず、次のジョブのイベント発生時（または次ジョブ完了時）になって初めて前の画像がレンダリングされているため。
  3. なぜ現状の仕組みで不十分か: REQ-385でComfyUIの完了検知（executing node: null）を修正したが、バッチ処理中の各ジョブのリアルタイムステップ進捗通知や、各ジョブ完了ごとの即時プレビュー切替がエンドツーエンドで担保されていないため。
  4. なぜこのアプローチを採用するか: 個別プログレスバーを現在実行中ノードのステップ進捗と確実に同期させ、各画像が生成完了した瞬間に次ジョブの処理を待たずに即時プレビュー更新（および自動追従）を行うため。
  5. 根本原因: ステップ進捗イベント（node/step progress）の配信・UIステートバインディングの脱落またはID不一致、および連続生成時におけるプレビュー自動追従の更新トリガーが直前ジョブ完了時に正しく発火していない（次ジョブのステート変化まで反映が保留される）こと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 実行中ジョブのステップ進捗（step / total_steps）を個別プログレスバーへ正確に反映し、全体プログレス（完了ジョブ数 / 全ジョブ数）と明確に分離して表示する。
    - バッチ生成の各ジョブ完了時に、該当画像が完了済みとして即時にUIへ提供される。
  - **Interaction (インタラクション)**:
    - 画像が生成完了した際、次の画像生成の完了を待つことなく、1秒以内（即時）に最新画像がプレビュー領域へ自動表示（auto-follow）される。
    - 個別プログレスバーがサンプリングの進捗に合わせてリアルタイムかつスムーズに進捗表示される。
  - **Visual (視覚デザイン)**:
    - 個別プログレスバーが0%のまま固まらず、実行中であることを視覚的にフィードバックする。
    - 生成完了時にプレビュー画像が即座に切り替わり、古い画像やローディング表示が次画像完了まで残存しない。
- **Requirement**:
  - **1. 個別プログレスバーのリアルタイム進捗同期**:
    - 画像生成実行中、現在サンプリング中のステップ進捗イベントを受信し、個別プログレスバー（ノード/ステップ進捗）をリアルタイムに0%から100%まで進行表示する。
  - **2. 各画像完了時のプレビュー即時表示（Auto-follow）**:
    - 連続生成（バッチ等）において、各画像の生成が完了した契機で、次の画像完了を待つことなく即時（1秒以内）に最新生成画像がプレビューおよびギャラリー最新位置へ反映される。
- **Acceptance criteria**:
  - [ ] AC-1: Given 画像生成が実行中である, When 各サンプリングステップが進む（progressイベント発生）, Then 個別プログレスバーが停止したままにならず、現在のステップ進捗率（現在のステップ/総ステップ数）に応じてリアルタイムに更新されること。
  - [ ] AC-2: Given 複数枚のバッチ生成を実行中である, When 1枚目の画像生成が完了する, Then 2枚目の画像生成完了を待つことなく、1秒以内に1枚目の画像がプレビュー領域に即時表示（auto-follow）されること。
  - [ ] AC-3: Given 単体または複数生成が完了した直後, When 全ジョブが完了する, Then 全体プログレスバーおよび個別プログレスバー双方が完了（100%）状態となり、最新画像がプレビュー表示された状態となること。
- **Inferred points**:
  - 個別プログレスバーは現在実行中ノード（サンプラーノード等）のステップ進捗を示し、全体プログレスバーはバッチ内のジョブ完了数（完了ジョブ / 総ジョブ数）を示す（SPEC_GENERATE.mdの二重進捗仕様）。
  - 「次生成画像の完了タイミングくらいで前の画像がプレビューされる」という現象は、バッチ生成時や連続ジョブ投入時に、完了通知またはフロントエンドのステート再描画トリガーが直前の完了イベントではなく次ジョブの完了やステート変更時に押し出されている可能性がある。
  - デスクトップ表示・モバイル表示（最上部固定ステータスヘッダー等）の双方において、同様に進捗同期とプレビュー表示が即時反映される必要がある。
