### REQ-226: 不具合解析・AI自律分析のためのログ永続化と1週間ローテーション機構
- **Type**: enhancement
- **Status**: done (2026-09-07)
- **Current step**: Phase 1: Requirement Analysis
- **Priority**: P2
- **Surface**:
  - 「不具合が起きた時の解析、改善実装時の状況確認を効率化する為のログ機構を追加したい。1週間分程度のログをロールするように残したい。人も見るが、AIの自律分析での活用を主と考えている。」
  - 「人が見る部分は二の次で大丈夫。必要であればログviewerとかを要望するので、AI解析への最適化を優先したログ設計でいい。」
  - 現状はFE・BEともにログの永続化機構が存在せず、ターミナルやブラウザのDevToolsコンソールをリアルタイムに開いていない限り、発生したエラーやコンテキストが消失して事後分析ができない。
- **Root Cause**:
  - **Information Design / Missing Auditability**:
    - システムの稼働状況や異常発生時のコンテキスト（スタックトレース、リクエスト情報、画面エラー等）を蓄積・保持する設計になっておらず、障害解析や実装改善時の事後検証が属人的・リアルタイム依存になっている。
- **Requirement**:
  - バックエンドおよびフロントエンドで発生したエラーや重要な動作記録をローカルログファイルとして永続化する。
  - ログファイルは約1週間（7日間分）を保持し、古いログを自動破棄するローテーション機構を備える。
  - **AIによる自律分析・抽出に最優先で最適化**し、機械可読性の高い構造化ログ形式（1行1レコードのJSON Lines等：タイムスタンプ、ログレベル、モジュール、エラー詳細、スタックトレース、リクエスト/クライアント情報等を網羅）を採用する。
  - フロントエンド側の致命的エラー（未処理例外や画面クラッシュ）もバックエンドへ連携し、一元的に追跡できるようにする。
- **Acceptance criteria**:
  - [x] AC-1: バックエンドの動作ログおよびエラーがファイルに永続化され、約1週間（7日分）のログが自動ローテーションによって安全に保持・管理されること。
  - [x] AC-2: ログがAIエージェントによる機械解析に最適化された構造（JSON Lines等の構造化フォーマットで、タイムスタンプ、ログレベル、発生箇所、メッセージ、スタックトレースやリクエスト情報等のコンテキストを漏れなく保持）で一貫して記録されること。
  - [x] AC-3: バックエンドで未処理の例外やAPIエラーが発生した際、リクエスト概要とスタックトレースが漏れなくログファイルに記録されること。
  - [x] AC-4: フロントエンドで発生した未補足のエラーやコンポーネントクラッシュが検知され、ログ記録対象としてバックエンドへ送信・永続化されること。
  - [x] AC-5: ログ出力の導入後も既存のシステム機能やテストスイートが正常に動作すること。
