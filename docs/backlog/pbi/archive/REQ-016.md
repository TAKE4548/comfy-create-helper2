### REQ-016: タグチップエディタのLLM連携オプション

- **Type**: enhancement
- **Status**: done (2026-08-30)
- **Current step**: none
- **Priority**: P2
- **Surface**: LLM連携関連の部分は、オプション的な扱いで別のPBIとしたい
- **Root Cause**: タグチップエディタにおいて、日本語や自然言語での手動入力を画像生成モデル用の英語タグに変換する手間を省き、過去の履歴に最適化されたタグ候補をLLMで提示するためには、LLM連携オプションが必要である。
- **Requirement**: `TagChipEditor` にLLM補完オプション（入力確定時の自動補完、手動によるLLM変換トリガー、キュー管理）と、過去の生成履歴に基づく類似プロンプト検索を組み合わせたタグサジェスト機能を実装する。
- **Design doc**: docs/spec_tag_chip_editor.md (Section 10, 11)

#### Acceptance Criteria (AC)
##### 1. 自動補完オプション
- [x] AC-1-1: 補完オプション（`llmCompletion.enabled === true`）のとき、タグ入力確定時にバックエンドAPI/LLMサーバーへ変換リクエストを送信し、変換中はスピナー付きプレースホルダーチップを表示すること。
- [x] AC-1-2: 変換が完了した際、スピナーチップが自動で変換後の英語タグチップに差し替わること。

##### 2. 個別チップの手動変換
- [x] AC-2-1: 補完OFFで作成したチップ等の個別メニュー（右クリック等）から「LLMで変換」を手動トリガーできること。
- [x] AC-2-2: 手動変換も `ChipAction` の `CONVERT` アクションとして記録され、Undo（元に戻す）の対象となること。

##### 3. 変換キュー管理
- [x] AC-3-1: 複数チップの同時変換（ペーストによる一括生成など）時、ローカルLLMへの負荷を軽減するため、同時実行数1のキュー（`useChipQueue.ts`）で順次処理を行うこと。
- [x] AC-3-2: 変換待ち中にユーザーがダブルクリック等でインライン編集を開始した場合、変換が完了してもその編集内容を上書きせず、変換結果を破棄すること。

##### 4. 履歴ベースのタグサジェスト
- [x] AC-4-1: 現在のプロンプト構成に基づき、過去の生成履歴（SQLiteの類似プロンプト）からタグ重複率（60%閾値）ベースのマッチングで候補タグ集合をバックエンドから取得すること。
- [x] AC-4-2: バックエンドから取得した候補タグ集合と現在のプロンプトをLLMサーバーへ送り、絞り込んだ提案（3〜5件）を取得して候補チップとして提示すること。
- [x] AC-4-3: エディタマウント後の初回フォーカス時、およびチップ確定（追加）のたびに自動でサジェスト再計算を行うこと。また、前の未完了リクエストは `AbortController` でキャンセル（abort）されること。
