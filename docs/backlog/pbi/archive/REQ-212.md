### REQ-212: バックエンドDBセッション管理の統一（DI化/リーク防止）および非同期バッチ処理（speech_batch）の排他制御・メモリ解放
- **Type**: refactor
- **Status**: done (2026-08-30)
- **Current step**: Phase 3: Task Decomposition
- **Priority**: P1
- **Surface**:
  - `backend/app/services/llm_service.py` や `backend/app/routers/speech_batch.py` 内部で `SessionLocal()` を手動でインスタンス化して使用しており、FastAPIの依存性注入（`Depends(get_db)`）やセッションスコープ管理から逸脱している。
  - 高負荷時や例外発生時にDBセッションが閉じられず、コネクションプールの枯渇やトランザクションロックを引き起こすリスクが高い。
  - `speech_batch.py` において、`_batch_jobs`（辞書）および `_job_tasks`（Task辞書）がモジュールレベルのプレーンな変数として保持されており、スレッドセーフでないため競合状態（Race Condition）が発生しやすく、完了したタスクがクリーンアップされずにメモリリークとなる。
  - `speech_batch.py` の非同期エンドポイント内で同期的なディスクI/OやDBクエリを実行し、FastAPIイベントループをブロックしている。
- **Root Cause**:
  - **Implicit Session Lifecycle**: DBセッションの生成・破棄が共通レイヤに統制されておらず、非同期タスク内部でアドホックに `SessionLocal()` が生成されている。
  - **In-Memory Global State Anti-Pattern**: 長時間ジョブの状態管理をスレッドセーフな構造やDB永続化に委ねず、モジュール内グローバル辞書に放置している。
- **Requirement**:
  - すべてのサービスおよび非同期タスクにおけるDBアクセスを、コンテキストマネージャ（`with SessionLocal() as db:`）またはDIに統一し、例外時でも確実にセッションが破棄される構造に改修すること。
  - `speech_batch.py` におけるグローバル状態操作を `asyncio.Lock()` による排他制御化、またはDBベースのジョブ管理へ移行し、完了・キャンセル済みタスクの自動クリーンアップ機構を導入すること。
  - 同期I/O操作（ファイル読み書きや重い同期DB処理）を `asyncio.to_thread` で非同期ラップし、イベントループのブロッキングを防止すること。
- **Acceptance criteria**:
  - [ ] AC-1: `llm_service.py` および `speech_batch.py` における手動 `SessionLocal()` 呼び出しがコンテキストマネージャまたはDIに安全に統一されていること。
  - [ ] AC-2: `speech_batch.py` のジョブ管理において、並行実行時の競合が発生せず、完了タスクがメモリ上に残留しないこと。
  - [ ] AC-3: 非同期ルート内での同期ブロッキングI/Oが解消され、高並行リクエスト時にもイベントループが滞留しないこと。
  - [ ] AC-4: `test_speech_batch.py` および既存の全バックエンドテストがパスすること。
