### REQ-069: LoraStackの編集がワークフローに反映されない（キャラLoRAが変更されない）不具合
- **Type**: defect
- **Status**: done (2026-08-30)
- **Current step**: none
- **Priority**: P1
- **Surface**: LoraStackの編集がワークフローに反映されていないかも？ キャラLoRAを入れ替えてみても、アップロード時に設定されていたキャラの特徴が強く残る。
- **Root Cause**: パラメータインジェクション時に、ComfyUIの `easy loraStack` ノードが認識しないフィールド（`lora_count`, `lora_name_X`等）でJSONに書き込もうとしていたため、ComfyUI側で変更が完全に無視され、アップロード時の初期値が適用され続けていた。
- **Requirement**: ワークフロー内のLoRAスタックノード（`easy loraStack`など）に対して、ComfyUIが想定する正しい入力キー（`num_loras`, `lora_X_name`, `lora_X_strength`, `lora_X_model_strength`, `lora_X_clip_strength`）でパラメータが反映・インジェクトされること。
- **Acceptance criteria**:
  - AC-1: `easy loraStack` 型ノードのパラメータ取得時（初期値設定）および送信・保存時に、`num_loras`, `lora_X_name`, `lora_X_strength` 等の正しいキー名で読み書きされること。
  - AC-2: UI上で編集されたLoRAスタック構成が、画像生成時（Queue Prompt）に正しくComfyUIのワークフローJSONへインジェクトされ、変更後のLoRAで画像生成が実行されること。
  - AC-3: 使用していない残りのLoRAスロット名には `'None'` が設定され、強度が初期化されること。
- **Design doc**: docs/design/REQ-069.md
