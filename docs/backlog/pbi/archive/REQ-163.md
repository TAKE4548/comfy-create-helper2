# REQ-163: プリセット別プロンプト・パラメータのSSoT確立とデバイス間・セッション間同期の修正

- **Type**: defect
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**:
  - デバイス間（PCとスマホなど）の切り替え時やページリロード時に、直近に編集したプリセットのプロンプトが別のプリセットのプロンプトに勝手に置き換わってしまったり、バックエンドDBのデータが誤った内容で上書き保存されてしまう。
- **Root Cause**:
  1. `useWorkflowParams.ts` および `useGenerationStore.ts` で、プロンプト/パラメータをプリセット単位ではなく「ワークフロー単位の単一キー (`prompt-surgeon-params-wf-${workflowId}`)」でLocalStorageに保持・上書きしており、プリセット間でのデータ混同・汚染が発生している。
  2. マウント時・ワークフロー読み込み時に、バックエンドDBのプリセット一覧よりも先に上記単一キーのLocalStorageからプロンプトを読み込み、現在アクティブなプリセットに注入してしまう。
  3. `useGeneratePageState.ts` のオートセーブ機能（1秒デバウンス）が、上記で汚染された `paramValues` を現在アクティブなプリセットIDに対して `PUT /api/workflow-presets/{id}` で送信し、バックエンドDBのデータを破壊的に上書き保存してしまう。
- **Requirement**:
  - プロンプトおよびパラメータのマスターデータはバックエンドDBの `workflow_presets` を絶対的なSSoT（Single Source of Truth）として扱い、プリセットごとに独立して管理されること。
  - ワークフロー単位の単一LocalStorageキーによるプロンプト復元ロジックを廃止/プリセット単位に分離し、他プリセットのデータや古いローカルデータが誤ってアクティブプリセットに混入しないこと。
  - ページ初期化時・他デバイスアクセス時・リロード時に、バックエンドDBから取得したアクティブプリセットの最新プロンプトが確実に表示されること。
  - オートセーブ機能において、初期同期中やプリセット切り替え時の競合・誤送信を防止し、現在編集中のプリセット固有のデータのみが正しいIDに対して保存されること。
- **Acceptance criteria**:
  - AC-1: 端末Aで「Set 1」のプロンプトを編集して保存後、「Set 2」に切り替えて別のプロンプトを編集しても、端末B（またはページリロード後）で「Set 1」を開いた際に「Set 1」の最新プロンプトが正確に表示されること。
  - AC-2: プリセット切り替え時や初期化時に、異なるプリセットのプロンプトが混入・反映されたり、オートセーブによって別プリセットのDBレコードに上書き保存されないこと。
  - AC-3: ワークフロー単位の単一LocalStorageキー (`prompt-surgeon-params-wf-${workflowId}`) によるプロンプトの一括上書き・競合が解消され、プリセットごとの独立性が担保されること。
  - AC-4: プリセットの編集（プロンプト・LoRA等のパラメータ変更）がバックエンドDBの該当プリセットに正しくオートセーブされ、デバイスを跨いでも最新の編集内容が保持されること。
