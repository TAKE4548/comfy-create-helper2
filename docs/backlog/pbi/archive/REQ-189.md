### REQ-189: 画像生成中プログレスバーの実行中ノード名Unknown表示の解消とキュー情報フォールバック対応
- **Type**: bugfix
- **Status**: done
- **Current step**: Phase 3: Walkthrough & SSoT Sync
- **Priority**: P2
- **Surface**: 生成中のプログレスバーに実行ノード名が出るが、unknownになることが多い。自セッションでも関係なくノード名が分からない。
- **Root Cause**: 
  1. 【Store/状態保存不備】セット一括生成（`handleGenerateSets`）において全投入ジョブに `isBatchIntermediate: true` が指定されているため、`queuePrompt` 内で `currentWorkflow: workflow` の保存がスキップされ、`currentWorkflow` が常に `null` のままとなりノード名が引けない。
  2. 【Store/過剰リセット】WebSocket `executed` イベント受信時に `state.activeBatch` が未設定または完了判定された際に `currentWorkflow: null` が即時設定され、同一ジョブの後続ノード実行時や通常バッチの後続生成時にワークフロー情報が消失する。
  3. 【Store/フォールバック欠落】他セッションや画面リロード時など `currentWorkflow` がローカルメモリに存在しない場合に、ComfyUI のキュー情報（`queueRunning[0][2]` 内の `prompt_json`）からノード定義を参照するフォールバック処理が存在せず、即座に `'Unknown'` にフォールバックする。
- **Requirement**: 自セッション（単体・バッチ・セット一括生成）および他セッション・画面リロード後において、画像生成中のプログレスバーに現在実行中のノード名（タイトルまたはノード種別）が正確に表示されるようにし、ワークフロー情報のライフサイクル管理とキュー情報（`queueRunning`）によるノード名解決フォールバックを実装する。
- **Acceptance criteria**:
  - [x] AC-1: セット一括生成（Sets生成）の実行中、各ノードの実行（KSampler、CheckpointLoaderSimple等）に伴って正しいノード名がプログレスバーに表示されること（`Unknown` にならないこと）
  - [x] AC-2: 単体生成および通常バッチ生成において、画像出力ノード（`executed`）完了後の後続ノードや2枚目以降の生成中にもノード名が正しく表示され続けること
  - [x] AC-3: 他端末/他セッションでの生成中、または生成中に画面をリロードした場合でも、ComfyUI キュー情報（`queueRunning`）からノード定義を参照して実行中ノード名が正しく表示されること
  - [x] AC-4: 既存のバッチ進捗、ノード進捗%、経過時間/ETA表示、およびキャンセル/中断処理にデグレーションが発生しないこと
