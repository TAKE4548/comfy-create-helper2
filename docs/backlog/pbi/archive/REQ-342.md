### REQ-342: Fix Node Candidate Label Missing Title and Class Type in Workflow Registration and Remapping

- **Type**: bug
- **Status**: done (2026-10-11)
- **Priority**: P1
- **Surface**: frontend/src/components/RescanModal.tsx, frontend/src/components/UploadWorkflowModal.tsx, frontend/src/pages/DatasetStudioPage/components/NodeRemapModal.tsx, frontend/src/utils/workflowNodeUtils.ts
- **Incident Report**: docs/incident_report.md
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: ワークフロー登録時やノードリマッピング時のドロップダウンで候補ノードのタイトル・クラス情報が欠落し、ユーザーが対象ノードを識別・選択できないため。
  2. なぜその課題が発生するか: RescanModalで先頭1件しか持たないnodeTitleMapを参照しており、2件目以降の候補でタイトルが取得できずIDのみ表示されるため。
  3. なぜ現状の仕組みで不十分か: RescanModalが手元のworkflowJsonを使わずscanResultから取得しようとし、かつUploadWorkflowModalでも_meta.title以外のフォールバックがないため。
  4. なぜこのアプローチを採用するか: ワークフローJSONからノードIDの表示ラベル（タイトルとクラス名）を解決する堅牢な共通関数を用意し、全リマップ・登録モーダルで共通利用するため。
  5. 根本原因: モーダル間でノードラベル生成ロジックが個別実装されており、RescanModalでの不完全なキャッシュ実装およびメタデータフォールバック不足に起因する。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - ワークフロー内ノード候補のセレクトボックス選択肢において、常に「ID - [タイトル] (クラス名)」の形式で一貫したメタデータを併記表示する。
  - **Interaction (インタラクション)**:
    - 候補ノード選択時、タイトル未設定ノードであってもクラス名等でフォールバックされ、直感的に目的のノードを識別可能にする。
  - **Visual (視覚デザイン)**:
    - 空の角括弧 [] や余計な空括弧 () を排除し、整ったラベル書式で視認性を向上させる。
- **Requirement**:
  - **1. 共通ノードラベル解決関数の整備**:
    - getNodeLabel(id: string, workflowJson?: Record<string, any>): string を作成し、_meta.title、node.title、class_type、type を段階的にフォールバックして ${id} - [] () を生成する。
  - **2. RescanModal の改修**:
    - 不完全な nodeTitleMap を廃止し、workflowJson から共通関数を用いて全候補ノードのラベルを正確に表示する。マスターロール名ではなくノードのクラス名を表示する。
  - **3. UploadWorkflowModal & NodeRemapModal の統一**:
    - 共通関数を用いて候補ノードの表示を統一し、未設定タイトルの空ブラケットや情報欠落を防止する。
- **Acceptance criteria**:
  - [ ] AC-1: RescanModal において、複数候補が存在するロール（duplicated や複数 candidate_node_ids）のドロップダウン選択肢すべてに、ノードID・ノードタイトル・ノードクラス（ロール名ではなくclass_type）が ${id} - [] () の形式で正しく表示されること。
  - [ ] AC-2: UploadWorkflowModal において、候補ノード選択肢に _meta.title だけでなく node.title や class_type がフォールバックされ、${id} - [] () のような空ブラケットや情報欠落が生じないこと。
  - [ ] AC-3: NodeRemapModal において、パラメータマッピング選択肢およびプロンプトノード選択肢で一貫したノード情報フォーマットが表示されること。
  - [ ] AC-4: 既存テストおよび新規追加されるノードラベル解決テストがすべてグリーン（PASS）であること。
- **Inferred points**:
  - ワークフローJSONがUIフォーマット（nodes配列形式）またはAPIプロンプトフォーマット（オブジェクト辞書形式）の双方でID引き当てができるように考慮する。
