### REQ-279: パラメータ変更直後のインメモリ同期的確定とジョブ投入先行競合の是正

- **Type**: defect
- **Status**: done (2026-09-19)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - パラメータ変更直後にオートセーブ完了を待たずに「生成」を実行すると、1回目のジョブ投入で古いパラメータ値が ComfyUI に送信され、リロードなしの2回目になって初めて最新パラメータが反映される。
  - 複数セット存在時や `activeSetId` が未確定の場合に、インメモリ同期処理がガードで弾かれ空振りする。
- **Root Cause**:
  - **要因 1: `usePresetState.ts` および `multiSetSlice.ts` のインメモリ即時確定ガード落ち**:
    - `usePresetState.ts` (L1016–L1023) の `flushAutoSave` および `multiSetSlice.ts` (L456–L461) の `updateActiveSet` において、`targetActiveId` が `null` かつ `currentStore.sets.length > 1`（複数セット存在時）の場合に早期 `return` され、ジョブ発行直前のインメモリ `sets` 更新が空振りする。
  - **要因 2: ジョブ発行と非同期サーバー通信の競合（Race Condition）**:
    - `useGenerateAction.ts` (L132) の `handleGenerateSets` において、`options?.onBeforeGenerate?.()`（`flushAutoSave`）を同期関数として呼び出すが、内部のサーバー更新 `updatePresetMutation.mutate`（非同期 HTTP 通信）の完了を待たずに次行の ComfyUI ジョブ投入ループが先行して実行される。
  - **要因 3: 下流 `useGenerateAction.ts` における `isActive` 判定落ちおよびプロパティ未同期**:
    - `useGenerateAction.ts` (L190–L202) において、`checkedSets.length > 1` かつ `currentActiveSetId === null` の場合に `isActive` が `false` と判定され、画面の `currentParamValues` がマージされず古い `setItem.paramValues` が 100% 採用される。さらに、`batchSize` や `seed` (L211–L227) も画面の最新状態ではなく `setItem` の旧値が参照されている。
- **Requirement**:
  - ComfyUI へのジョブ生成（キュー投入）が非同期 HTTP 通信の完了に一切依存せず、画面上の最新インメモリ状態（`paramValues`, `appliedAssets`, `batchSize`, `seedMode`, `seed` 等）が同期的・確実にストアへ確定された上でジョブペイロードに反映されるアーキテクチャを確立すること。
  - `flushAutoSave` および `updateActiveSet` において、`activeSetId` が未確定でもアクティブセット（または先頭セット）を確実に特定してインメモリ同期を完遂すること。
  - `useGenerateAction.ts` において、`resolvedActiveSetId` を安全に特定し、アクティブセットに対して画面の最新パラメータ・バッチサイズ・シードを確実に適用すること。
  - 非同期レスポンス到達前の即時生成および複数セット時のアクティブ判定を検証する自動テストシナリオを整備し、偽陽性を防止すること。
- **Acceptance criteria**:
  - [x] AC-1: パラメータ変更後、オートセーブタイマー満了前（100ms以内）に即時生成を実行した場合でも、非同期通信の完了を待たずに 1 回目のジョブ投入ペイロードに変更後の新値が 100% 確実に反映されること。
  - [x] AC-2: 複数セットが存在し `activeSetId` が未確定（`null`）の状況下では、他の非アクティブセットに画面値が誤反映されず、各セット固有の値が安全に保護・投入されること（ユーザー指示合意）。
  - [x] AC-3: バッチサイズやシード値の変更直後に即時生成を実行した場合でも、最新のバッチサイズに応じた回数分、最新のシード設定でジョブがキュー投入されること。
  - [x] AC-4: 非同期 HTTP 保存（`PUT /api/workflow-presets/:id`）の通信状態（待機・成功・遅延）に関わらず、ブラウザ上のインメモリ状態から ComfyUI への投入値が一貫して即時反映されること。
  - [x] AC-5: 偽陽性を防ぐ自動テスト（非同期レスポンス前のジョブペイロードインターセプト検証等）が配備され、全テストが PASS すること。
