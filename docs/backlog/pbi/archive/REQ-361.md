### REQ-361: Frontend レガシーテストファイルのドメイン再配置とチケット名完全全廃

- **Type**: refactor
- **Status**: done (2026-10-15)
- **Priority**: P1
- **Surface**: frontend/src
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: REQ-356 において Backend のテスト再構成および多層防護基盤が完了したが、Frontend 側に 44 件のチケット名テストファイルが残存しているため。
  2. なぜその課題が発生するか: 過去の PBI 開発で機能ごとのコロケーションではなく req334*.test.ts や e2e_req*.test.tsx などのチケット名でテストが量産されたため。
  3. なぜ現状の仕組みで不十分か: チケット名テストファイルが分散していると、SPEC-TESTING v2.1 のドメイン別コロケーション規約に反し、テスト衛生リンターで 44 件の違反が残り続けるため。
  4. なぜこのアプローチを採用するか: 各テストファイルを対象コンポーネント・Hook・API の隣接 __tests__/ ディレクトリへ移動・リネームし、テストケース名に [REQ-xxx/AC-n] を付与することで、ファイル名のチケット番号を完全排除しつつ逆引きトレーサビリティを 100% 確立するため。
  5. 根本原因: テストファイル配置規則が統一される前に蓄積した Frontend 側のテスト技術的負債。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - frontend/src/ 配下のテストファイルをドメイン・コンポーネント構造と 1:1 に一致させ、テストの責務と所在を直感的に把握可能にする。
  - **Interaction (インタラクション)**:
    - 開発者が特定のコンポーネントを変更した際、隣接する __tests__/ のテストが Vitest watch で即座に実行される快適な DX を実現。
  - **Visual (視覚デザイン)**:
    - 特になし（テスト基盤リファクタ）。
- **Requirement**:
  - **1. Frontend チケット名ファイルの全廃**:
    - frontend/src/ 配下の全 44 件のチケット名テストファイル（req334PreviewApis.test.ts, e2e_req*.test.tsx, *.req334.test.tsx 等）を、モジュール・機能名由来のファイル名へリネームし、対応するコンポーネント・API・Hook の隣接 __tests__/ へ再配置する。
  - **2. テストケース名の規約化**:
    - 89 件の未規約テストケース名に [REQ-xxx/AC-n] プレフィックスを付与し、grep -rn "REQ-xxx" での逆引きを完全担保する。
  - **3. テストの非破壊・回帰ゼロ**:
    - リネーム・移動後も Frontend 全 231 ファイル / 2,182 テストが 100% PASS し、型検査（TypeScript）が 0 errors であること。
  - **4. 厳格命名検証の合格**:
    - python scripts/verify_test_naming.py --strict および python scripts/workflow_validator.py test-hygiene が違反 0 件（終了コード 0）で合格すること。
