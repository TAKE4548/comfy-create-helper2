### REQ-394: テストスイート実行時間の劣化（FE vitest 約134秒 / BE pytest 並列40秒）の解消と性能予算の仕様化

- **Type**: bug
- **Status**: ready
- **Priority**: P2
- **Surface**: テスト基盤（frontend/vite.config.ts、pytest.ini、backend/tests、tests/unit）、docs/specs/SPEC_TEST_ARCHITECTURE.md
- **Incident report**: [docs/incident_report_test-performance.md](../../../incident_report_test-performance.md)（Type B: Specification Gap、2026-10-25 計測）
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: Gate 2 の実測が SPEC_TEST_ARCHITECTURE.md の実績値を大きく上回る（FE 134〜136秒 vs ~38秒、BE並列 40.0秒 vs ~30秒、BE逐次 118.9秒 vs ~89秒）。
  2. なぜその課題が発生するか: FE は全247ファイルを pool:'forks'（isolate 既定、maxForks 既定=15）かつ jsdom で実行し、累計で environment 1041秒・collect 367秒・prepare 151秒・setup 150秒と、テスト本体 193秒を大きく上回るファイル単位のオーバーヘッドが発生している。BE は WS テストが監視間隔 2.5秒を待つこと、ルート pytest.ini に testpaths が無く db/ 等を走査すること、個別の重いテストが主因。
  3. なぜ現状の仕組みで不十分か: テスト環境の選択方針・並列度・実行時間の上限が仕様上の規範として定義されておらず、劣化を検知・抑止できない。
  4. なぜこのアプローチを採用するか: 計測で寄与が確認できた要因（環境初期化、プロセス過剰並列、固定待ち、収集範囲）を個別に是正し、再計測で効果を確かめられるため。
  5. 根本原因: テスト性能予算と環境選択方針の仕様欠落（Type B）。詳細はインシデントレポートを参照。
- **Requirement**:
  - **1. FE テスト実行オーバーヘッドの削減**:
    - DOM 不要のテストを node 環境で実行する（environmentMatchGlobs または @vitest-environment）。
    - ワーカー数・pool・isolate の設定を計測比較で決定する（isolate 無効化は状態リーク検証とセット）。
    - 上位の遅いテスト（residualHistoryRestore、queryCachePersister、apiCacheStorage 等）の待ち要因を確認する。
  - **2. BE テスト実行時間の削減**:
    - WS 系テストで ResourceMonitorService の監視間隔待ち（約2.8秒/件）を解消する。
    - ルート pytest.ini に testpaths を定義し、リポジトリ直下からの収集で db/ 等を走査しない。
    - FuguMT 実モデル読込、4,001ファイル作成、Hypothesis 再帰プロパティの各テストのコストを見直す（マーカー分離・閾値の monkeypatch・max_examples 明示等）。
  - **3. 仕様の同期**:
    - SPEC_TEST_ARCHITECTURE.md の実績時間を再計測値に更新し、性能予算（時間上限・ワーカー数・環境選択方針）を規範として定義する。
- **Acceptance criteria**:
  - [ ] AC-1: Given 本PBI適用後のリポジトリ, When `cd frontend; npm test` を実行する, Then 全テストが PASS し、所要時間が設計で合意した予算以内であり、Duration 内訳（environment/collect/tests）が計測記録として残されていること
  - [ ] AC-2: Given 本PBI適用後のリポジトリ, When リポジトリ直下で `backend\.venv\Scripts\python -m pytest -n auto` を実行する, Then 収集テスト数が変更前（774件）から意図しない増減なく全 PASS し、所要時間が設計で合意した予算以内であること
  - [ ] AC-3: Given リポジトリ直下, When `pytest --collect-only` を実行する, Then db/・docs/・frontend/ 配下を走査せず、収集時間がパス指定時と同等であること
  - [ ] AC-4: Given WS 系テスト（test_ws.py、test_vram_guard の WS ブロードキャスト）, When 実行する, Then 監視間隔 2.5秒の待ちが発生せず、検証内容（SYSTEM_STATS の型・フォールバック等）が維持されていること
  - [ ] AC-5: Given SPEC_TEST_ARCHITECTURE.md, When 本PBIをクローズする, Then 再計測した実績時間と性能予算・環境選択方針が規範として記載されていること
- **Inferred points**:
  - FE 実績値「~38秒」の計測条件は未確認で、基準コミット時点の再計測は未実施（基準 1cc9196 時点 231ファイル → 現在 247ファイル）。予算値は設計フェーズで計測に基づき決定する。
  - 計測環境: 16論理/10物理コア、計測時CPU負荷15%、空きメモリ約9GB（常駐アプリあり）。
