### REQ-307: 生成キュー投入失敗時に失敗理由をトーストで示す

- **Type**: feature
- **Status**: done (2026-10-02)
- **Surface**: 生成操作でキュー投入に失敗すると失敗トーストは表示されるが、理由が分からず、ユーザーは設定・接続・ワークフロー等のどこを確認すべきか判断できない。
- **Desired outcome**: 失敗通知を見た時点で、判明している失敗理由を読み、次に確認すべき対象を判断できる。
- **UX Classification**:
  - **Information Design**: 「投入失敗」という結果と、その失敗について判明している理由を同じ通知内で対応づけて示す。
  - **Interaction**: 通知を受けたユーザーが、理由に応じて設定や接続状況を確認し、修正後に生成を再試行できる。
- **5 Whys Analysis**:
  1. なぜ困るか：生成キュー投入の失敗理由がトーストに出ず、修正箇所を判断できないため。
  2. なぜ修正箇所を判断できないか：失敗したという結果だけでは、入力、ワークフロー、接続などのどれを確認すべきか区別できないため。
  3. なぜ区別が必要か：原因に応じて確認や修正の対象が変わるため。
  4. なぜその場で知る必要があるか：生成作業中に原因を把握できないと、再試行に向けた次の行動を選べないため。
  5. 根底の業務ニーズ：失敗した生成を、理由を手掛かりに自力で修正・再開できること。
- **Requirement**:
  - 単一生成および複数セット・バッチ生成で、キュー投入に失敗した際のトーストに、失敗したことと、その失敗について返された説明可能な理由を併記する。理由の例は「ワークフローのノード X が無効」「ComfyUI に接続できない」「応答がなく時間切れになった」など、失敗ごとに確認対象を区別できる内容とする。
  - 理由が返されない、または返された内容だけでは理由を特定できない場合は、その旨を表示し、推測した原因を事実として表示しない。技術的な状態番号だけを理由の説明として扱わない。
  - 複数件の投入で一部または全部が失敗した場合、失敗した各生成と対応する理由を取り違えずに確認できるようにする。
  - REQ-141 が規定する複数セット投入時の失敗対象表示を維持し、本要件はその通知内容が理由として読めることを明確にする。
- <inferred_points>
  - 対象は「生成ボタン操作後、生成ジョブをキューへ投入できなかった」事象と解釈した。投入成功後の生成実行中エラーや、翻訳など別操作の失敗は対象外と仮定する。
  - 単一生成と複数セット・バッチ生成の両方を対象と仮定する。既存の複数セット失敗通知には対象を示す要件（REQ-141）があるため、それを維持する。
  - 失敗理由はその失敗時に判明した説明を指す。理由が得られない場合に診断や修正方法を捏造しない。
  - 長い理由も失敗トースト内で全文を読めることを期待する。具体的な表示方法と表示時間は後続の設計で決める。
  </inferred_points>

#### Acceptance Criteria (AC)

- [ ] **AC-1（理由の併記）**
  - **Given**: 生成キュー投入が失敗し、失敗理由として「ワークフローのノード X が無効」が返されている。
  - **When**: 失敗トーストが表示される。
  - **Then**: 同じトースト内に投入失敗の表示と「ワークフローのノード X が無効」が読める形で表示される。
- [ ] **AC-2（理由が不明な場合）**
  - **Given**: 生成キュー投入が失敗し、具体的な失敗理由が返されていない、または技術的な状態番号だけが返されている。
  - **When**: 失敗トーストが表示される。
  - **Then**: 失敗したことに加えて「理由を特定できませんでした」と表示され、状態番号だけを理由として表示せず、原因を断定しない。
- [ ] **AC-3（複数件での対応づけ）**
  - **Given**: 複数セットまたはバッチの生成投入で、セット A の 1/2 件目は理由「ノード X が無効」、セット B の 2/2 件目は理由「接続できない」で失敗し、他の件は成功した。
  - **When**: 失敗トーストを確認する。
  - **Then**: それぞれの失敗対象（セット名とバッチ内の順番）と対応する理由が同じ通知内で読め、セット A とセット B の理由が入れ替わらない。
- [ ] **AC-4（全件失敗時）**
  - **Given**: 複数セットまたはバッチの生成投入で全件が失敗し、各件の理由が判明している。
  - **When**: 失敗トーストを確認する。
  - **Then**: 各失敗対象と各理由の対応が読め、成功したかのような通知は表示されない。
- [ ] **AC-5（長い理由）**
  - **Given**: キュー投入失敗時に、トーストの一行幅を超える長さの理由が返されている。
  - **When**: 失敗トーストを確認する。
  - **Then**: 理由の全文をトーストから読める。
