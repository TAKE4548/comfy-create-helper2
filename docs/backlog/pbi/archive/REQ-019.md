### REQ-019: メイン生成ページのプレビューサイズ調整および履歴切り替え機能の改善

- **Status**: done (2026-08-26)
- **Type**: enhancement
- **Priority**: P2
- **Current step**: none
- **Surface**: メイン生成ページの、プレビュー表示と履歴表示のサイズ感を調整したい。メインプレビューは今の7割くらいのサイズ感で大丈夫。また、現行は上辺が画面端についていてパディングもないので、画像の末端なのかスクロールの余地があるのか分かりにくいため、メインプレビュー部のパディングや枠取りなども合わせてしたい。さらに、現行は履歴をクリックすることでしかメインプレビューに表示できないが、メインプレビューの左右にボタンを設け、クリック・キーボード操作で履歴の画像を切り替えながらメインプレビューに表示させたい。
- **Root Cause**:
  1. メインプレビュー表示エリアのレイアウトにおいて、周囲（特に上辺）のパディングやマージンが確保されておらず、画像の末端やスクロール可能な領域かどうかの視覚的境界が曖昧になっている。
  2. メインプレビューが最大サイズでレンダリングされ、画面の大部分を占めており、他の操作パネルとのバランスが偏っている。
  3. 生成された画像履歴のプレビュー表示変更が、履歴リストのサムネイルクリックのみに制限されている。プレビュー自体にフォーカスして手軽にキーボード（左右キー）や左右のホバーボタンで画像遷移する仕組みがないため、画像の比較検討時の操作コストが高い。
- **Requirement**:
  - **メインプレビューのサイズ調整と装飾**: プレビューエリア内の画像表示サイズを現在の約70%程度に抑える。周囲に適切なパディングを設定して余白を作り、外枠（ボーダー）や影（ボックスシャドウ）を付加してカード状に浮き上がったリッチなデザインに変更する。
  - **左右切り替えボタンの設置**: メインプレビュー内にマウスホバーまたはフォーカス時に表示される左右ナビゲーションボタンを設け、クリックすることで履歴の前後画像へ切り替えられるようにする。
  - **フォーカス時のキーボード切り替え**: メインプレビューがクリックまたはフォーカスされている場合のみ、左右矢印キー（`←` で新しい履歴へ、`→` で古い履歴へ）で画像を切り替えるショートカットをサポートする。プロンプト入力等の入力操作を阻害しないよう、プレビュー部がフォーカスされている時のみイベントを検知する。
  - **対象の履歴範囲**: 対象のセッションで生成された履歴（メインプレビュー下に表示されているリストなど）のすべてを切り替え巡回の対象とする。
- **Acceptance criteria**:
  - [ ] AC-1: メインプレビュー画像の表示サイズが現在の約70%（縦横比維持）に調整され、画面幅・高さに対して余裕のあるサイズになること。
  - [ ] AC-2: メインプレビューエリアの周囲にパディング（余白）が追加され、画像の上辺が画面の上端に密着しないレイアウトになること。
  - [ ] AC-3: メインプレビューエリアに枠線（ボーダー）および影（ボックスシャドウ）が付与され、背景から浮き上がって見えるカード風のコンテナデザインが適用されること。
  - [ ] AC-4: メインプレビュー画像の上にホバーするか、プレビューエリアにフォーカスがあるとき、画像の左右両端に切り替え用のアローボタンが表示され、クリックで前後の画像へ切り替えできること。
  - [ ] AC-5: 左ボタン（またはフォーカス中の左矢印キー `←`）を押すと「直前（より新しい）の履歴画像」が表示され、右ボタン（またはフォーカス中の右矢印キー `→`）を押すと「直後（より古い）の履歴画像」が表示されること。
  - [ ] AC-6: キーボードの矢印キーによる切り替えは、プレビューコンテナにフォーカスがあるときのみ動作し、テキストエリア（プロンプト等）の入力中には動作しないこと。
  - [ ] AC-7: セッション履歴内のすべての画像が切り替え対象となり、履歴の端（最新または最古）に達した際に適切に表示・非活性制御が行われること（あるいは巡回ループがスムーズに動作すること）。
- **Design doc**: none
