### REQ-266: 非アクティブ放置時のComfyUI接続切断防止と自動再接続・復帰の保証

- **Type**: defect
- **Status**: done (2026-09-16)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - ビルドしたFEで、非アクティブ状態でしばらくするとcomfyUIとの接続が切れる。リロードすれば再接続されるが、明示的なリロードしないと切れたままになっている。viteのFEで運用してた頃はこの問題は見られなかった。
- **Root Cause**:
  - **Keepalive & Heartbeat Omission in Single-Process Hosting**:
    - Vite 開発サーバー環境では Vite の HMR クライアントによる約30秒周期のハートビート通信によってブラウザタブおよび TCP 接続が活性維持されていたが、本番ビルド（FastAPI 単一プロセス配信）では WebSocket が直接 ComfyUI（Port 8188）へ接続される上、アプリケーション層での Ping / キープアライブ送信機構が存在しないため、長時間の無通信により OS や Chromium の省電力・アイドルタイムアウトによって TCP 接続が切断される。
  - **Inadequate Reconnection Lifecycle & Error Handling**:
    - `connectionSlice.ts` において、`onError` 時に再接続タイマーがスケジュールされず、かつ切断時の再接続が単一の固定3秒タイマーに依存しているため、バックグラウンドでのタイマースロットリングや再試行失敗時にリトライループが喪失し、未接続状態のまま膠着する。
  - **Missing Tab Visibility / Focus Recovery Trigger**:
    - `useGenerateDisplayState.ts` の `visibilitychange` / `focus` ハンドラにおいて REST API（`fetchQueue`, `fetchHistory`）のみが呼ばれ、WebSocket 接続状態の確認（`isConnected`）および再接続初期化（`initialize`）がトリガーされないため、タブ復帰後もリロードするまで切断状態が継続する。
- **Requirement**:
  - 単一プロセス配信（ビルド後本番環境）において、非アクティブ状態が継続しても ComfyUI との接続が不用意に切断されないよう、定期的なキープアライブ（ハートビート）を送信すること。
  - 切断が発生した場合、エラー（`onError`）や切断（`onClose`）のいずれの契機であっても、指数バックオフを伴う堅牢な自動再接続ループにより自律的に再接続を継続試行すること。
  - ブラウザタブが再度アクティブ（`visibilitychange` が `visible`、または `window focus`）になった際、WebSocket が未接続状態であれば即座に再接続をトリガーし、最新のキュー・履歴状態を復元すること。
  - ユーザーが明示的な画面リロード（F5）を行わなくても、バックグラウンド放置やスリープからの復帰時に自動的に ComfyUI 接続が回復し、生成操作が即座に再開可能であること。
- **Acceptance criteria**:
  - [x] AC-1: ComfyUI との WebSocket 接続確立中、一定間隔（例: 20〜30秒）でキープアライブ Ping または定期疎通が送信され、非アクティブ放置時における無通信アイドル切断が防止されること。
  - [x] AC-2: WebSocket 通信でエラー（`onError`）または切断（`onClose`）が発生した場合、切断状態（`isConnected: false`）へ遷移し、後続の自動再接続処理が確実にスケジュールされること。
  - [x] AC-3: 再接続処理は指数バックオフ（または堅牢なリトライ間隔制御）によって ComfyUI 復帰まで継続的に試行され、1回のリトライ失敗で再接続ループが停止・膠着しないこと。
  - [x] AC-4: ブラウザタブが非アクティブからアクティブ（`visibilityState === 'visible'` または `focus`）に復帰した際、WebSocket が未接続（`!isConnected`）であれば即座に再接続初期化がトリガーされること。
  - [x] AC-5: 再接続が成功した際、インジケーターが即座に接続中（緑色）へ復帰し、キューおよび生成履歴が同期され、生成ボタンが利用可能状態になること。
  - [x] AC-6: ユーザーによる明示的なブラウザリロード（F5）を必要とせず、非アクティブ放置からの復帰時に自動的に再接続・復旧が完了すること。
