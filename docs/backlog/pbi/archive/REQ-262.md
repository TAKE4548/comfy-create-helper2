### REQ-262: フロントエンドビルド成果物のuvicorn内包配信と単一プロセス配布

- **Type**: enhancement
- **Status**: done (2026-09-16)
- **Current step**: none
- **Priority**: P2
- **Surface**:
  - FEをdevで運用してるが、ビルドしてuvicornに内包して配布するようにしたい
- **Root Cause**:
  - **Interaction & Workflow Design**:
    - フロントエンドとバックエンドが分離起動を前提とした開発構成（Node.js dev server + uvicorn）のまま運用されており、配布・一般利用時にも2プロセスの起動・管理が必要という運用負荷・配布摩擦が生じている。
    - 単一のサーバー（uvicorn）プロセス起動のみでバックエンドAPIとフロントエンドUI（SPA）の両方を提供可能な統合配信機構およびビルド・配布導線が未整備である。
    - また、Server Manager（自動起動バッチ・タスクスケジューラ常駐サービス）が 3 プロセス固定前提であり、外部アクセスに必要なファイアウォール設定（Port 8000）や、エージェント用ビルドコマンド（`/build`）も未整備である。
- **Requirement**:
  - フロントエンドの静的ビルド成果物をuvicorn（FastAPI等のASGIサーバー）側で内包し、単一プロセスの起動でUIおよびAPIの両方を提供・配布可能とすること。
  - 通常の開発環境においては既存のフロントエンド開発サーバー（ホットリロード等）による開発体験を維持し、配布・本番実行時においてビルド済み静的ファイルが配信されること。
  - フロントエンドのSPAルーティングに対応し、APIエンドポイント以外のパスへのアクセスにおいて適切にフロントエンドのメイン画面（index.html）へフォールバック配信されること。
  - `tools/server-manager`（起動バッチ・Webマネージャー・常駐サービス）において手動設定切替なしで、普段は ComfyUI + Backend の 2 プロセスで軽量起動し、必要な時だけワンクリックで Vite 開発サーバーを個別起動できること。
  - 配布・他PCからのアクセス向けに Port 8000 の Windows ファイアウォール許可手段を提供すること。
  - リポジトリ向けエージェント用スラッシュコマンド `/build` を配備し、ワンアクションでフロントエンドのビルドと成果物検証を実行可能とすること。
- **Acceptance criteria**:
  - [ ] AC-1: フロントエンドのビルド成果物（静的ファイル群）が存在する場合、uvicorn起動のみでWeb UIがブラウザから正常に表示・操作できること。
  - [ ] AC-2: APIリクエスト以外のパス（SPAルーティングのURL）に直接アクセスまたはリロードした際、404にならず正常にUI画面（index.html）がフォールバック配信されること。
  - [ ] AC-3: 既存のフロントエンド開発環境（devサーバーを用いた開発フローやAPIプロキシ設定等）が損なわれず、開発時は引き続きホットリロード等の利便性が維持されること。
  - [ ] AC-4: 配布・デプロイ向けにフロントエンドをビルドしてuvicorn配信対象ディレクトリへ配置する手順（またはビルドスクリプト）が定義されていること。
  - [ ] AC-5: `tools/server-manager` において設定切替不要の自動判別が機能し、普段は ComfyUI + Backend の 2 プロセスで正常起動・監視され、オンデマンドで Vite を個別起動できること。
  - [ ] AC-6: 外部アクセス・配布向けに Port 8000 の Windows ファイアウォール許可スクリプト（`allow_firewall_8000.bat`）が用意され、管理者権限で実行できること。
  - [ ] AC-7: エージェント向けビルドスラッシュコマンド `/build`（`.agents/skills/build/SKILL.md`）が配備され、フロントエンドのビルドと Uvicorn 配信準備検証が自動実行できること。
