# REQ-165: プロンプト翻訳機能の外部APIプロキシ化・チャンクキャッシュおよび手動反映UI/UXの刷新

- **Type**: enhancement
- **Status**: done (2026-08-30)
- **Priority**: P2
- **Surface**:
  - 現行のプロンプトエリア内翻訳機能において、日英相互変換時にユーザーが意図・確認する前に翻訳結果が入力欄へ自動反映・上書きされてしまう事故が発生する。
  - ローカルLLMを用いた翻訳処理では、画像生成中に別プロファイルのプロンプトを調整・翻訳しようとするとVRAM枯渇や処理競合が発生し、画像生成と翻訳の双方に著しいパフォーマンス低下やエラーを引き起こす。
- **Root Cause**:
  - フロントエンド側で翻訳結果を入力フィールドへ即時双方向バインド/同期する設計になっており、プレビュー・確認と適用が分離されていない。
  - 翻訳エンジンとしてローカルLLMを同一マシンリソース（GPU VRAM）上で共有利用しており、画像生成プロセスとのリソース競合を回避する仕組み（外部API利用＋バックエンドプロキシ）になっていない。
  - プロンプトのタグ単位での重複リクエストを抑止・再利用するキャッシュ層（プロキシ）が存在しない。
- **Requirement**:
  - **外部APIプロキシ & チャンクキャッシュ (Backend)**:
    - Google Translation API等の外部翻訳APIを利用し、フロントエンドからバックエンド（`POST /api/translate/prompt` 等）を経由して呼び出すプロキシ構成とすること。
    - バックエンド側でプロンプトをカンマ・改行単位でチャンク分割し、LoRA構文（`<lora:...>`）や重み付け構文（`(tag:weight)`）等の特殊構文を保護・退避した上で、未翻訳チャンクのみを外部APIへバッチ送信するキャッシュ機構（In-Memory / SQLite等）を実装し、API文字消費とレスポンス遅延を削減すること。
  - **プレビュー確認 & 手動反映UI/UX (Frontend)**:
    - 各プロンプト入力エリアの翻訳ボタンを維持しつつ、主用途である「入力中プロンプトの翻訳（英→日）と内容確認（プレビュー表示）」を安全に行えること。
    - 「日→英」翻訳モードへ切り替え可能とし、ユーザーが自由に入力した日本語テキストを英訳できる入力領域/モードを提供すること。
    - 翻訳結果のプロンプト入力エリアへの反映は一切自動で行わず、ユーザーが明示的に「反映」または「追記反映」ボタンを押下した時のみ安全に適用されること。
- **Acceptance criteria**:
  - AC-1: 各プロンプト入力欄に配置された翻訳ボタンから、現在の英語プロンプトを日本語へ翻訳し、入力欄を破壊・上書きすることなくプレビュー領域で確認できること。
  - AC-2: 日→英モードへの切り替えが可能であり、自由入力された日本語テキストを英語プロンプト（カンマ区切りタグ等）へ翻訳できること。
  - AC-3: 日→英の翻訳結果は自動入力されず、ユーザーが「反映」または「追記」等の明示的なアクションを実行した場合にのみ、対象のプロンプト入力欄へ安全に反映されること。
  - AC-4: バックエンドプロキシにより外部翻訳APIが実行され、画像生成実行中であってもGPU VRAMを消費せず、並行して高速・安定に翻訳が完了すること。
  - AC-5: バックエンド側でLoRA構文や重み付け構文が保護され、タグ単位の分割キャッシュにより同一タグの重複リクエストが抑止（API消費文字数が削減）されること。
