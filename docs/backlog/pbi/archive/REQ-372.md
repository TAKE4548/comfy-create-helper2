### REQ-372: モバイルGenerate：常駐プレビューを廃止し、履歴グリッド・画像シート・全画面ビューアで画像を確認できるようにする

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: モバイルGenerate（幅767px以下）の画像確認導線（現行の常駐プレビュー、履歴サムネイル、フルモーダルプレビュー）
- **Reference**:
  - docs/design/mobile-ui-redesign/mobile-generate-redesign-proposal.md（§2〜§4、§6 AC-01/04/05、§9.4）
  - docs/design/mobile-ui-redesign/mobile-common-ui-redesign-proposal.md（COMMON-05 / COMMON-06 / COMMON-07）
  - docs/specs/SPEC_GENERATE.md（§2-9 メインプレビュー＆キュー管理、§3 モバイルレイアウト）
  - docs/specs/SPEC_COMMON.md（§1-4 共通モーダルとレスポンシブ境界）
  - 比較モック: Baseline `/?ui=baseline` ／ Proposal `/?ui=proposal`（prototype/ui-review）
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: モバイルGenerateは常駐プレビューが縦面積を占有し、プロンプト入力に使える面積が狭いため。
  2. なぜその課題が発生するか: 画像確認（プレビュー）と入力編集が同じ縦スクロール面に同居し、履歴サムネイルも横一列で画面切替操作と競合するため。
  3. なぜ現状の仕組みで不十分か: プレビューは約105px〜220pxに留まり、画像の確認にも入力にも不十分な中途半端な面積になっている。
  4. なぜこのアプローチを採用するか: 画像確認を「履歴→ボトムシート→全画面」の明示的な導線へ分離し、入力面積を広げる方向をユーザーがモックで評価した。
  5. 根本原因: 画像確認と入力編集という目的の異なる作業が、狭いモバイル画面で同じ面積を取り合う情報設計になっていること。
- **UX Classification**:
  - **Information Design (情報設計)**: 画像確認を入力から分離する。履歴を3列の一覧とし、画像は段階的に拡大する。
  - **Interaction (インタラクション)**: サムネイル→シート→全画面→戻る、の導線。閉じる方法を複数用意する。
  - **Visual (視覚デザイン)**: 正方形トリミングの3列サムネイル、黒背景の全画面表示。
- **Requirement**:
  - **1. 常駐プレビューの廃止（モバイルのみ）**: プロンプト入力の面積を広げる。
  - **2. 履歴を3列の縦スクロールグリッドにする**。
  - **3. 画像確認の導線**: サムネイルのタップで大きなボトムシート、シート内の画像タップで全画面ビューア。
  - **4. 既存機能の継承**: 常駐プレビューが担っていた機能（進捗・ETA表示、自動追従／固定、ダウンロード、スナップショット保存、画像エラー表示、複数選択）を、機能対応表に基づき移行先で利用可能にする。機能を無断で削除しない。
  - **5. 非対象**: PC表示、Baseline、バックエンド／API、Wake Lock／Fullscreenに対応しない環境での代替機能の新設。
- **Acceptance criteria**:
  - [ ] AC-1: Given 幅767px以下のGenerate, When 画面を表示する, Then プロンプト入力の上方に常駐する画像プレビュー領域が存在せず、PC（768px以上）では従来のプレビューが維持されること。
  - [ ] AC-2: Given 履歴に複数枚の画像がある, When 履歴セクションを開く, Then サムネイルが3列の正方形トリミングで表示され、ページの縦スクロールで全件に到達でき、履歴の横一列スクロールが存在しないこと。
  - [ ] AC-3: Given 履歴グリッド, When サムネイルをタップする, Then 下端起点のボトムシートが開き、選択した画像が元の縦横比で表示されること。
  - [ ] AC-4: Given ボトムシートが開いている, When シート内の画像をタップする, Then 背景が黒の全画面ビューアに切り替わり、画像は縦横比を維持し、シートのヘッダー・ハンドル・フッターは非表示になり、利用環境が対応していればブラウザのFullscreen表示（ブラウザUIの非表示）になること。
  - [ ] AC-5: Given 全画面ビューア, When 画像をタップする、または右上の閉じる操作を行う、またはOSの戻る操作・Escapeでブラウザ側のFullscreenが解除される, Then ボトムシートに戻り、Fullscreen表示が解除されていること。
  - [ ] AC-6: Given ボトムシート, When 閉じる操作・背面タップ・Escapeのいずれかを行う, Then 履歴グリッドに戻り、グリッドのスクロール位置が保たれること。
  - [ ] AC-7: Given 履歴が0枚, When 履歴セクションを開く, Then 既存の空状態が表示され、存在しない画像は表示されないこと。
  - [ ] AC-8: Given 設計で作成した「常駐プレビュー機能対応表」, When 全項目を確認する, Then 各機能（進捗・ETA表示、自動追従／固定、ダウンロード、スナップショット保存、画像エラー表示、複数選択）に移行先または明示的な廃止承認が記録され、移行先でそれぞれ従来どおり操作できること。
  - [ ] AC-9: Given 画像生成中および完了直後, When モバイルGenerateを操作する, Then バッチ／ノード進捗とETA、完了の事実が、常駐プレビュー廃止後も画面上で確認でき、新しい画像へ到達する手段があること。
  - [ ] AC-10: Given 履歴の画像を長押しして選択モードに入る, When 個別選択・全選択・選択解除を行う, Then 選択状態と件数が従来どおり更新され、選択モード中にサムネイルのタップが画像シートを開かないこと。
  - [ ] AC-11: Given 幅360px、セーフエリアあり／なし、画面回転、画像の読込失敗、縦長・横長画像, When AC-2〜AC-6を実行する, Then レイアウトが崩れず、すべての閉じる操作が利用できること。
  - [ ] AC-12: Given 全画面ビューアを表示している, When 操作せずに画面の自動消灯・自動ロックまでの時間を超えて表示し続ける, Then 利用環境が対応していれば画面の自動消灯とロック画面への移行が起きず、ビューアを閉じる・シートに戻る・アプリが非表示になる・タブが切り替わるといった時点で抑止が解除されること。
  - [ ] AC-13: Given Fullscreen表示または自動ロック抑止に対応しない環境、またはユーザー操作により拒否された状態, When 全画面ビューアを開く, Then ブラウザ表示領域の全面表示（100dvh）で画像が表示され、閉じる操作が使え、エラー表示や操作不能にならないこと。
  - [ ] AC-14: Given 幅768px以上、Baseline、他ページ、本番API, When 操作する, Then 本PBI前から表示と挙動が変化しないこと。
- **Inferred points**:
  - 前提: REQ-378（モバイルUI共通規約のSPEC_COMMON反映）の完了後に設計に着手する。
  - 本PBIはモバイルGenerateの「画像確認」に限定する。タブのスタイル、スワイプ、余白、スクロール末尾はREQ-373で扱う。REQ-373はREQ-372の完了後の着手を推奨する（履歴セクションとスワイプ対象が確定してから）。
  - 現行仕様（SPEC_GENERATE §2-9, §3）は「モバイルの105px／220pxトグルプレビュー」「sticky status header（進捗・ETA）」「Auto-Follow／Lock」を定義している。本PBIはこれらの置換にあたるため、完了時にSPEC_GENERATEの更新が必要。
  - **確定（ユーザー回答 2026-10-18）**: 「全画面」はFullscreen表示を想定する。可能な場合は、全画面表示中にロック画面への自動移行（自動消灯・自動ロック）を抑止したい。
  - 対応状況はブラウザ／OSで異なる（例：iPhoneのSafariは任意要素のFullscreen表示に未対応の場合がある）。対応しない環境では、ブラウザ表示領域の全面表示（100dvh）へ縮退する（AC-13）。実機での対応状況は設計フェーズで調査し、結果をPBIに反映する。
  - 自動ロック抑止は、全画面ビューア表示中に限る。履歴グリッドやシート表示中は抑止しない。バッテリー消費への配慮として、解除条件をACで規定した（AC-12）。
  - モックの履歴画像（12枚の架空データURL）やDOM後処理・CSS上書きは本番方式として採用しない。表示は状態駆動で実装する（設計フェーズで具体化）。
  - 生成完了の通知方法（AC-9）は、常駐プレビュー撤去後に履歴への移動頻度が過大にならないかを含め、具体的な導線を設計で決定する。
  - 画像シートは共通Modalの「ボトムシート」とは別用途の画像閲覧シートであり、REQ-367（共通Modalのフォーカス／Escape制御）の影響を確認する。
