### REQ-358: ノードマッピング候補の確度表示と編集安定化・無効化設定

- **Type**: feature
- **Status**: done (2026-10-14)
- **Priority**: P2
- **Surface**: ワークフロー登録、リマッピング、Settings の対応付け・ノードマッピングマスタ管理
- **5 Whys / Root Cause**:
  1. 候補選択に時間がかかるのは、ロールとの適合度が一覧から分からないため。
  2. 適合度が分からないのは、クラス・タイトル・パラメータの一致根拠を区別して確認できないため。
  3. 手動修正が負担になるのは、入力・削除の途中で行が移動し入力箇所を探し直すため。
  4. 修正負担が繰り返されるのは、ワークフローで不要なロールとステージの組合せを保存できないため。
  5. 運用上のニーズは、候補の根拠を判断でき、編集位置を維持し、不要な対応付けを繰り返さず登録と修正を完了できること。申告からの推定であり実装分析ではない。
- **UX Classification**:
  - **Information Design**: 確度順の候補・根拠、未使用と無効、ワークフロー設定とマスタ既定の区別。
  - **Interaction**: 全ノードの選択、入力位置・フォーカス維持、無効化・再有効化と永続化。
  - **Visual**: スマート置換と意味が共通の確度バッジ、空欄行の減光表示、文字での状態識別。
- **Requirement**:
  - **1. 共通候補順位**: 登録・リマッピング・Settings の対応付けで同じ判定を用いる。候補は下表の区分順に各1回だけ表示し、全ノードを手動選択できる。複数の区分に該当する場合は最上位の区分を採用する。

| 順位 | 条件 | 確度区分 | 推奨 |
| :-- | :-- | :-- | :-- |
| 1 | 登録クラスのいずれかに一致し、登録タイトルのいずれかに完全一致 | 確定相当 | はい |
| 2 | 登録クラスのいずれかに一致し、タイトルが表記ゆれ一致 | 有力 | はい |
| 3 | クラス一致のみでタイトルに該当なし | クラス候補 | いいえ |
| 4 | クラス不一致で、ロール対象パラメータ名のいずれかを持つ | パラメータ候補 | いいえ |
| 5 | 上記以外（クラス不一致のタイトル一致だけも含む） | その他 | いいえ |

  - **2. 表記ゆれの境界**: 英字の大文字小文字・空白・アンダースコア・ハイフンの差のみを無視した一致。Main Sampler / MainSampler / main_sampler / main-sampler は一致する。綴り誤り、翻訳、類義語は推定しない。
  - **3. ステージ適合（2026-10-14改訂）**: 完全一致・表記ゆれ一致を同じ推奨グループとして、現在stageとノードtitleの近似度を優先してスコアと順位に反映する。表記ゆれを正規化した全文包含を最も高く評価し、共有する文字の連なりも部分適合として評価する。FaceDetailer stageに対するFace DetailerはHand Detailerより高いが、後者にもDetailer部分の近似を反映する。クラス候補・パラメータ候補・その他の順序と推奨境界は維持する。stage近似はクラス候補にも反映する。空のstage名は照合対象外、同点はID文字列昇順。元の完全一致/表記ゆれのtier判定は一致根拠として保持する。
  - **4. 確度バッジ（2026-10-14改訂）**: 長い確定/有力ラベルを0〜100%の適合スコア表示へ変更する。スコアはクラス・title・parameter・stage近似の規則による一致度であり、登録・リマッピング・Settingsで共通化する。バッジは短い百分率、詳細な一致根拠とstage適合は候補の補足またはtooltipで確認できる。
  - **5. 安定した編集（2026-10-14改訂）**: マッピング済み/未検出の2エリア方式を廃止する。空欄は未割当として同じ行に残し、編集できる。ロール名を主表示、ステージ名をその下位情報として読み取れる文字サイズで表示する。選択中ノードのID・title・class・スコアをセレクタ欄内に表示する。入力・消去で行位置、フォーカス、入力文字列を失わない。チェックはそのslotの利用許可を示し、空欄と明示的無効を別状態として文字表示する。値の有無で明示的状態を上書きしない。
  - **6. ワークフローの無効化**: role×stage を個別に無効化・再有効化でき、ステージ単位で全組合せを一括変更できる。保存後、再表示・リマッピング・アプリ再起動で復元し他ワークフローに波及しない。無効化しても対応付けを保持し再有効化時に復元する。無効な組合せは必須・未検出件数・生成入力欄の対象に含めない。ComfyUI 内のノード削除や実行経路変更は対象外。
  - **7. マスタの基本無効**: ロールを削除せず基本無効・再有効化でき、定義を保持する。基本無効ロールは新規ワークフローのマッピング行に出さない。既存ワークフローの保存済み対応付けと有効/無効状態は変更しない。既存ワークフローで新たなロールを初めて取り込む場合はマスタの既定を適用する。無効化情報のない従来ワークフローの既存ロールは有効とみなす。
  - **8. 状態の独立性と操作境界**: 候補確度は並び順とバッジだけに影響し、保存済み対応付けを削除・上書き・無効化しない。クラスとパラメータの両方が一致してもタイトル一致がなければクラス候補である。ワークフローの無効行は対応付け画面内に無効の文字表示と再有効化操作を残し、対応付け欄は再有効化するまで読み取り専用とする。stage一括チェックは全slot有効／全slot無効／一部有効を区別して表示し、部分状態を全有効と誤認させない。空欄であることだけで明示的無効にしない。マスタ基本無効は既定だけであり、既存ワークフロー内の行は隠さない。対応先ノードが失われても保存済み識別子を自動消去せず、対応付け画面で参照先なしと表示する。入力位置維持は同一画面内の入力・消去に対する要件であり、ブラウザーのフォーカス移動・離脱に対する新たな自動保存要件は含めない。

### 最終操作・性能補足

- Settings Stage復帰で以前OFFの組合せまでONになる件は利用者指示で別PBI REQ-360へ切り出す。REQ-358内でその復元仕様を追加実装しない。
- 有効チェックOFFの組合せは減光・入力不可。生成側では未割当と同じく対象外にし、保存済み割り当てを保持して再有効化に備える。「利用許可」の新しい説明を廃止し、有効チェックとして表示する。
- 横長のselector欄は全領域をクリックして候補を開ける。IDは先頭1回だけ、後方はtitle/class/score。直接ID編集・選択後focus維持は保持。
- チェック変更で全slot stateや全候補scoreの重複計算を繰り返さず、HTTPを発生させない。保存中の初期化effectによるediting復帰を防ぎ、保存1クリックはPUT1回、応答待ちは操作不可とする。実所要時間と再計算/通信回数を測定する（T35/T36）。

- B2はSettings Stage ManagerのActive操作で配下role×stageが戻らない件、および再スキャンの一括無効保存→再表示で勝手に有効へ戻る件。
- B3はSeedだけでなく全slotの有効/無効と入力値の独立性。保存往復・非同期取得・旧形式variant未指定を再現対象にする。
- Stage ManagerのActive=false→trueは配下variantを一括trueへ戻す。name更新やtrue→trueでは個別状態を変更せず、workflow mappingとslot状態は保持する。全slot一括有効化であり、以前の個別無効履歴を戻す操作ではない（I-5）。
- T32=状態保持、T33=適合スコア/欄内情報、T34=Stage Active復帰。ユーザーの修正指示と継続自律作業の許可を承認として扱う。browser実証は未完了。
