### REQ-141: バッチ生成におけるpending即時描画とComfyUI逐次投入エラーハンドリング・キュー数リアルタイム補正

- **Type**: bugfix
- **Status**: done (2026-08-30)
- **Current step**: none
- **Priority**: P1
- **Surface**: バッチ・複数プリセット生成実行時に、ComfyUIのVerify待機と逐次投入ループ内での配列伸縮（16件→1件→2件...）による全画面再レンダリングが連続発生し、体感描画レスポンスが悪化する。またComfyUI側でNG応答（バリデーションエラー等）が返った際にどのプリセット・バッチで失敗したかが不明瞭で、キュー進捗数が実態と乖離する。
- **Root Cause**:
  1. handleGenerateSets において、初期枠 initialBatch（N件）をセットした直後に各ジョブ完了毎に setActiveBatch([...newBatch]) を呼び出し、配列サイズが縮小・拡大（State Thrashing）して不要な全画面再レンダリングが連続発生している。
  2. ComfyUIへの逐次投入時にNG（HTTP 400等のエラー）が返却された場合、失敗したプリセット名やバッチインデックス（例: SetA (2/4)）の明示的なエラー通知が行われていない。
  3. NGとなったジョブが activeBatch や進捗追跡から除外・補正されず、キュー件数表示との整合性が損なわれる。
- **Requirement**:
  1. 生成ボタン押下時に全件（プリセット×バッチ数）の initialBatch（pending状態）を即座にUIへ反映し、0msの体感レスポンスを確保する。
  2. ComfyUIへの投入は順序（FIFO）を維持した逐次送信としつつ、投入ループ内での不要な全画面再レンダリングや配列伸縮を排除し、各ジョブの promptId をインプレースに確定させる。
  3. ComfyUI側からNG（エラー）が返ってきた場合、どのプリセットの何番目のバッチがNGだったかを特定したエラーメッセージ（トースト）を表示する。
  4. NGとなったジョブは activeBatch 上で failed 状態へ遷移または総数から除外し、画面のキュー件数・進捗総数から即座に減算（補正）してリアルタイムな整合性を担保する。

#### Acceptance Criteria (AC)

##### 1. pending状態の即時描画と逐次投入の描画負荷最適化
- [ ] AC-1-1: バッチ・複数プリセット生成ボタン押下時、全件の pending 枠が 0ms で即座にUI上に描画され、進捗バーが即時表示されること。
- [ ] AC-1-2: 逐次投入ループの進行中に配列サイズの伸縮（State Thrashing）や無駄な全画面再レンダリングが発生せず、順序（FIFO）を保ったままスムーズに ComfyUI へ投入されること。
- [ ] AC-1-3: 各ジョブの ComfyUI 登録完了（Verify完了）に伴い、該当する pending 枠の実 promptId がチラつきなくスムーズに確定・同期されること。

##### 2. ComfyUI NG応答時のエラー特定通知とキュー数リアルタイム補正
- [ ] AC-2-1: ComfyUI からバリデーションエラー等のNG応答（HTTP 400/500等）が返却された際、「[プリセット名] の X/Y 件目でエラーが発生しました: [エラー詳細]」のように該当箇所を特定したエラーメッセージ・トーストが表示されること。
- [ ] AC-2-2: NGとなったジョブが activeBatch 上で適切に failed または除外として処理され、画面の総キュー数および進捗パーセンテージがリアルタイムに補正・反映されること。
- [ ] AC-2-3: 一部のジョブがNGとなっても、後続のジョブ（キャンセルされていない場合）の逐次投入処理が安全に継続または適切にハンドリングされること。

##### 3. リグレッション防止
- [ ] AC-3-1: 既存のジョブキャンセル（単一・一括）機能が正常に動作し、投入中の中断シグナルが正しく機能すること。
- [ ] AC-3-2: 通常モード（デスクトップ）およびモバイルモードの双方において、生成進捗表示および履歴反映が正常に動作すること。
