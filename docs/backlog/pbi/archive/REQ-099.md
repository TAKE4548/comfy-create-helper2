### REQ-099: アルバムページおよびページ遷移のロード高速化と最適化

- **Type**: enhancement
- **Status**: ready
- **Current step**: none
- **Priority**: P1
- **Surface**: ページ切替時のロードが重い。サーバと同一端末のPCだとそこまででもないが、端末を跨ぐと気になるレベルで重い。特にアルバムページに遷移した時に大分時間がかかる印象。キャッシュや部分ロードとかが効率的に使えてないのではないか？
- **Root Cause**: 端末間ネットワーク経由（Androidスマホ/iPadのVivaldiブラウザ等）でのデータ転送（特にアルバムページの画像等）において、画像サイズ最適化・キャッシュ処理・Lazy Loading（遅延ロード）などの部分的な最適化が不足している、または非同期での読み込みが不十分であるため、遷移時の通信量が多く同期的な読み込み負荷が高い。
- **Requirement**: ネットワーク経由であっても、アルバムページ等の遷移時に必要なデータのみが優先的にロード（スクロール等に応じた遅延ロード）され、ブラウザキャッシュが効果的に活用されることで、体感速度および実際の表示完了時間が大幅に改善されていること。
- **Acceptance criteria**:
  - [ ] AC-1: アルバムページにおいて、すべての画像を一括で同期ロードするのではなく、初期表示に必要な分のみを先行して読み込み、残りはスクロールに応じて遅延ロード（Lazy Loading）されること。
  - [ ] AC-2: 画像データが不要に過大な解像度・サイズのまま転送されないよう、サーバー側で適切なサムネイル生成やサイズ圧縮、またはクライアント側での画像ロード最適化が適用されていること。
  - [ ] AC-3: ページ遷移時およびコンテンツロード時に、Skeleton Loaderやローディングスピナーなどの視覚的フィードバックが直ちに表示され、体感的な待ち時間が軽減されること。
  - [ ] AC-4: APIレスポンスおよび静的アセットに対するキャッシュ戦略（ブラウザキャッシュ、メモリキャッシュ等）が適切に機能し、2回目以降のアクセス時にロードが瞬時に完了すること。
- **Design doc**: none
