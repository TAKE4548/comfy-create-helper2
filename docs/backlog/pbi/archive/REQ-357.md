### REQ-357: TagChipの削除・ドラッグ・強度操作がクリック後に機能しない

- **Type**: bug
- **Status**: done (2026-10-13)
- **Priority**: P2
- **Surface**: frontend/src/components/TagChipEditor/TagChip.tsx; TagChipEditor chip-mode interactions
- **Incident report**: [docs/incident_report.md](../../../incident_report.md)
- **Observed symptoms**: チップをクリックすると沈む動作が追加されて以降、ドラッグ移動・削除アイコンが機能しない。サブメニューは開くが、強度設定などのボタンも反応しない。テキストモードでは編集可能。
- **Triage finding**: `TagChip.tsx:243` の全面を覆う `::before` 疑似要素がドラッグ/削除操作を遮る構造。サブメニュー強度ボタンの直接原因は未隔離。詳細な根拠と再現上の限界は incident report を参照。
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: チップモードで削除・並び替え・強度編集が使えず、編集体験が大きく損なわれている。
  2. なぜ操作できないか: 全面の押下用疑似要素がチップ内操作要素より前面に描画される構造がある。
  3. なぜ既存テストで防げなかったか: 子要素への直接click検証だけでは、ブラウザのCSSヒット判定や押下中の座標変化を確認できない。
  4. なぜ既存の見た目を保つ設計にするか: コンパクトなヒット領域拡張と押下フィードバックは維持しつつ、編集操作を優先して到達可能にするため。
  5. 根本原因: 疑似要素の重なり順とメニュー表示中の親チップ縮小が、内側操作のヒット標的や座標に影響し得る。強度操作の直接原因はブラウザ確認まで未確定。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 変更なし。既存のチップ・メニュー構成と操作内容を保つ。
  - **Interaction (インタラクション)**:
    - ドラッグ、削除、強度調整、有効切替をチップモードから確実に操作できるようにする。
  - **Visual (視覚デザイン)**:
    - コンパクトな外縁ヒット領域とチップ本体の押下フィードバックを維持する。
- **Requirement**:
  - **1. チップ内操作の復旧**:
    - 疑似要素を使ったヒット領域と押下フィードバックを維持し、ドラッグハンドル・チップ本文・削除ボタンが正しい標的となること。メニュー表示中は押下による親チップの縮小で子メニューや翻訳カードの操作位置がずれないこと。
- **Acceptance criteria**:
  - [ ] AC-1: 複数チップがあるとき、ドラッグハンドルをマウスで8px超、タッチで5px超移動してドロップすると、チップ順と親の出力順が一致すること。
  - [ ] AC-2: チップの×中央をクリックまたはタップすると、対象チップだけが削除され、メニューが誤って開かないこと。
  - [ ] AC-3: メニューで強度ステップ、数値入力のEnter/Blur、有効切替を行うと、本文と状態が既存の書式規則に従って更新されること。
  - [ ] AC-4: 閉じたチップ本体の押下フィードバックと約2pxのコンパクトなヒット領域拡張が維持され、内側の操作要素や隣接チップを遮らないこと。
  - [ ] AC-5: メニューや翻訳カードが開いている間、操作中に親チップの縮小で座標基準が変化せず、メニュー・カード内の操作と外側クリック境界が機能すること。
- **Inferred points**:
  - ACの8px/5px閾値と既存の強度値処理は現行実装に合わせた設計提案。実ブラウザでの座標ヒットテストが終わるまで各ACは未確認とする。
  - SPEC_COMMONのスライダー記述と現行の段階ボタン・数値範囲の差異は本PBIの変更対象外。
