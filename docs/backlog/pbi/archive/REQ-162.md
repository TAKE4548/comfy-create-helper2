# REQ-162: ComfyUI通信プロキシ集約・複数セッション同期・確実な一括Abortの実装

- **Type**: defect
- **Status**: done (2026-08-30)
- **Current step**: Step 5（実装・検証完了）
- **Priority**: P1
- **Surface**:
  1. モバイル端末からのキュー投入失敗が頻発する（Bypassプロファイル適用時のobject_infoタイムアウトによるノード配線破損、comfyUrl初期化遅延）
  2. モバイルとPCなどの複数セッション間で進捗情報や生成履歴が同期しない（ComfyUI WebSocketの個別クライアント配信仕様および自セッションフィルタ隔離）
  3. Abortのレスポンスが悪く、一括削除をしても他セッションのジョブや投入中キューが除外され部分的なAbortになり、何度も一括削除を実行しなければならない
- **Root Cause**:
  1. `useGeneratePageState.ts` での `/object_info` 取得が3秒タイムアウト（`retry: false`）し、`comfyObjectInfo` が空の状態で `applyBypass` が走ると必須入力を誤って削除しComfyUIバリデーションエラーとなる。
  2. ComfyUIはジョブ投入時の `client_id` にのみ詳細進捗・完了イベントを送信するが、クライアント側で端末ごとに異なる `clientId` を持ち、`fetchHistory` も自セッションのみを抽出しているため他端末の生成情報が同期しない。
  3. `cancelAllJobs` が `filterOwnSession` 有効時に他端末のジョブIDを削除対象から除外して空の削除リクエストを送り、実行中1件の割り込み後に後続ジョブが即座に開始されてしまう。またバッチ投入中のキュー未同期によるID欠損が発生する。
- **Requirement**:
  - モバイル端末から待ち時間やエラーなくBypassプロファイルを含むキュー投入に成功すること。
  - ComfyUIとの通信・スキーマキャッシュ・ジョブ管理をバックエンドに集約・プロキシし、同一ComfyUIに接続する全セッション間で進捗・履歴が同期されること。
  - ジョブ管理からの「一括キャンセル」が、セッションや投入状態にかかわらず1回の実行で確実にComfyUIの待機キュー全削除と中断を完了すること。
- **Acceptance criteria**:
  - AC-1: Bypassプロファイルが有効なワークフローにおいて、モバイル端末・PC端末問わず、初回アクセス時および通信遅延環境下でもComfyUIバリデーションエラー（Required input is missing）が発生せずキュー投入が成功すること。
  - AC-2: /object_info がバックエンド側でキャッシュまたは安全にフォールバックされ、フロントエンドでの3秒タイムアウトによる破壊的ノード削除が発生しないこと。
  - AC-3: PCから投入したジョブの進捗（または完了後の生成画像・履歴）が、同一サーバーに接続しているモバイル側のギャラリー（フィルムストリップ）および履歴一覧に自動同期・反映されること。
  - AC-4: 複数件のバッチジョブが待機中・実行中の状態でジョブ管理の「一括キャンセル」を実行した際、他セッションから投入されたジョブを含め、ComfyUIの全待機キューが即座にクリアされ、後続ジョブが自動開始されることなく1回の操作で完全に停止すること。
  - AC-5: queuePrompt 実行時に comfyUrl が未初期化であってもサイレント失敗せず、正しく解決されてジョブが投入されること。
