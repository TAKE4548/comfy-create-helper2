### REQ-209: ワークフローパラメータ解析・注入（LoRAスタック/バイパス）ロジックの共通化と二重実装排除
- **Type**: refactor
- **Status**: done
- **Current step**: Phase 3: Walkthrough & SSoT Sync
- **Priority**: P1
- **Surface**:
  - `useWorkflowParams.ts`（デフォルト値保存時のJSON構築: `handleSaveDefaultParams`）と `useGenerateAction.ts`（生成リクエスト送信時のJSON構築: `injectParams`）において、`easy loraStack` および標準 `loraStack` のスロット解析・パラメータ注入・余剰キー削除ロジック（約50行）が完全に二重実装されている。
  - 一方のファイルで修正が行われた際に他方への反映漏れが起きやすく、保存されるデフォルト値と実際の生成ペイロードの間で不整合（デグレ）が発生する深刻なリスクがある。
  - `bypassUtils.ts` において、`JSON.parse(JSON.stringify())` による重いディープクローンや、直列に接続された複数ノードをバイパスする際の順序依存性、ノード情報未定義時のリンク削除による不透明なComfyUIエラーのリスクが存在する。
- **Root Cause**:
  - **Code Duplication (DRY Violation)**: ワークフローJSONを操作するロジックが専用のドメイン層ユーティリティとして抽出されず、個別のカスタムフック内部にアドホックにインライン実装されたこと。
- **Requirement**:
  - ワークフローパラメータ解析・注入の単一責務を持つ純粋関数モジュール（`workflowParamInjector.ts`）を新設し、パラメータ注入・LoRAスタック展開・シード注入を完全に一元化（Single Source of Truth化）すること。
  - `useWorkflowParams.ts` および `useGenerateAction.ts` から二重化されたコードを排除し、新設モジュールを呼び出す構成にリファクタリングすること。
  - `bypassUtils.ts` におけるトポロジカルソート（依存順序考慮）の強化と、安全なフォールバック機構を導入すること。
- **Acceptance criteria**:
  - [x] AC-1: `easy loraStack` および標準 `loraStack` のパラメータ展開・整形ロジックが一元化され、`useWorkflowParams.ts` と `useGenerateAction.ts` 間の重複コードが完全に排除されていること。
  - [x] AC-2: パラメータ注入モジュールに対する包括的な単体テスト（各種LoRAスタック形式、通常パラメータ、シード値等の境界値検証）が実装されていること。
  - [x] AC-3: `bypassUtils.ts` で複数連続ノードのバイパスが指定された場合でも、接続リンクが破壊されず安全にバイパス処理が完結すること。
  - [x] AC-4: 既存の `useWorkflowParams.test.ts`, `useGenerateAction.test.ts`, `bypassUtils.test.ts` がすべて正常にパスすること。
