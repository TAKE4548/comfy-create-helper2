### REQ-284: usePresetState の責務分離と一括パッチサービスの純粋関数化

- **Type**: refactoring
- **Status**: done (2026-09-25)
- **Current step**: none
- **Priority**: P3
- **Surface**: usePresetState.ts (1,379行) はカスタムフックでありながら、プリセットCRUD、オートセーブ、Undo/Redoスタック、409競合解決、Zustand同期、および320行に及ぶ一括パラメータ置換ロジックが同居しており、状態遷移の追跡が困難である（リファクタ計画 PBI-REF-03）。
- **Root Cause**: 単一カスタムフック内に複数の直交する関心事（履歴管理、通信競合ハンドリング、タイマー監視、グローバル同期、データ変換パッチ）が集約され、SRP（単一責任原則）が形骸化していること。
- **Requirement**:
  - `handleBulkEditApply` の一括パッチ処理を独立した純粋関数サービス（`services/presetBulkPatcher.ts`）として外出しし、単体テストを充実させる。
  - Undo/Redo、409競合解決、オートセーブ、Zustand同期をそれぞれ独立したサブフックへ分離し、`usePresetState.ts` はそれらを束ねる軽量な統合ファサードフックとする。
  - 【目標構成】:
    ```
    frontend/src/pages/GeneratePage/
    ├─ hooks/
    │  ├─ usePresetState.ts       # 統合ファサードフック（約150行に集約）
    │  ├─ usePresetHistory.ts     # Undo/Redoスタック & Ctrl+Z/Yリスナー（約200行）
    │  ├─ usePresetConflict.ts    # 409競合検知 & 3-way解決ハンドラ（約80行）
    │  ├─ usePresetAutoSave.ts    # オートセーブタイマー & Dirty判定（約60行）
    │  └─ usePresetStoreSync.ts   # サーバーPresetとZustand(sets)同期（約250行）
    └─ services/
       └─ presetBulkPatcher.ts    # handleBulkEditApply純粋関数（約320行）
    ```
- **Acceptance criteria**:
  - [x] AC-1: プリセットのオートセーブ、409競合解消モーダル、Undo/Redo、一括編集の既存挙動が100%維持されること。
  - [x] AC-2: 【REQ-278 同期的フラッシュ維持】`usePresetAutoSave.ts` 切り出し時、`flushAutoSave` 内の「ジョブ投入前にインメモリの sets へ最新値を同期的・即時反映する処理」を100%維持し、生成開始時のパラメータ巻き戻りを発生させないこと。
  - [x] AC-3: 【REQ-276 キー順序非依存比較維持】`isRecordEqual` によるオブジェクト差分判定を維持し、プロパティの順序違いによる不要なオートセーブ多重送信（未保存マークの誤点灯）を防止すること。
  - [x] AC-4: 【409 OCC 競合制御維持】サーバー側との更新衝突（409 Conflict）発生時に、競合解消モーダルが正常に起動・手動マージできること。
