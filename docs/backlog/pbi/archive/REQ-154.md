### REQ-154: 生成キュー投入・進捗管理・Abort制御の不具合修正

- **Type**: bug
- **Status**: ready
- **Priority**: P1
- **Surface**: 生成画面におけるバッチ投入、中断（Abort）、追加投入、進捗カウント、およびキュー残数表示の動作不良。
- **Root Cause**:
  1. `cancelJob` の実行中判定がポーリング配列 `queueRunning` のみに依存しており、未反映時に `POST /interrupt` ではなく無効な `POST /queue (delete)` が送信される。また単体生成 `handleGenerate` に AbortController がない。
  2. `handleGenerateSets` 開始時に既存の `activeBatch` を破棄して新規投入分のみで上書きしている。
  3. `totalQueueCount` が ComfyUI のサーバー側 `/queue` のみを集計しており、クライアント側の `POST /prompt` 送信中・検証中ジョブ（pending）が除外されている。
  4. 全体進捗表示で完了数（`0〜`）をそのまま `n/m 枚目` の `n` にバインドしており、現在生成中の番号と1つずれている（Off-by-one）。
- **Requirement**:
  1. Abort操作時に確実に `/interrupt` を送信し、単体生成・バッチ投入ループを即座に安全中断できるようにする。
  2. 生成中に追加投入した際、既存の未完了ジョブと新規ジョブをマージして進捗母数 `m` を正しく合算・維持する。
  3. ComfyUIでのワークフロー検証中・投入中ジョブもキュー残数カウントまたはステートに適切に反映する。
  4. 全体進捗表示の `n/m 枚目` を「現在生成中のインデックス（1-indexed）」に補正する。

#### Acceptance Criteria (AC)

##### 1. Abort制御の確実化と即時中断
- [ ] AC-1-1: `cancelJob` 実行時、対象が `currentPromptId` または `queueRunning` のいずれかに一致する場合、確実に `POST /interrupt` が発行されて実行中生成が中断されること。
- [ ] AC-1-2: `handleGenerate`（単体バッチ生成）および `handleGenerateSets`（セットバッチ生成）の投入ループ中に中断が要求された場合、`AbortController` により後続のキュー投入が直ちにキャンセルされること。

##### 2. 追加投入時のバッチ母数(m)合算
- [ ] AC-2-1: 生成実行中・待機中に新規セットを追加投入（Generate Batch）した場合、既存の未完了ジョブ（実行中・待機中）と新規ジョブが結合され、全体進捗の母数 `m` が合算値となること。
- [ ] AC-2-2: 追加投入後も既存ジョブのステータス（completed/generating/pending）が保持され、進捗パーセンテージが正常に計算されること。

##### 3. ComfyUI検証中(Verify)および投入中ジョブのキュー反映
- [ ] AC-3-1: `POST /prompt` 送信中（ComfyUI側バリデーション中）のジョブがキュー残数表示（`Queue: X`）または投入中ステータスに適切に反映されること。

##### 4. 進捗表示の助数詞（枚目）補正
- [ ] AC-4-1: 1枚目生成中の表示が「全体進捗: 1/m 枚目」となり、現在生成中の枚数番号（1-indexed）が正しく表示されること。
- [ ] AC-4-2: 全件完了時は「全体進捗: m/m 枚目」（または100%完了表示）となること。
