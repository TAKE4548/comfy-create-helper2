### REQ-195: 生成キュー投入および生成進行時のUI応答性・パフォーマンス改善（巨大履歴取得・描画ループストレージアクセスの最適化）

- **Type**: bugfix
- **Status**: active
- **Current step**: Phase 1: Dev Design
- **Priority**: P1
- **Surface**: 生成キュー投入時および生成進行中において、体感できるレベルで画面の操作を受け付けない時間（UIフリーズ）が発生する。ComfyUI起動直後は軽快だが、生成回数を重ねるにつれて投入待ちおよびUIフリーズが長時間化する。
- **Root Cause**:
  - `frontend/src/store/useGenerationStore.ts` において、ジョブ完了・ノード完了（`executing` (nodeId=null)、`executed`、`execution_complete`）のたびに `fetchHistory()`（`comfyApi.getHistory(100)`）が重複呼び出しされている。
  - ComfyUIの履歴データには各生成時の完全なワークフロー定義JSONが含まれており、生成回数が増えて100件蓄積されると10MB〜50MB以上の巨大JSONとなる。これをComfyUI側でシリアライズする間にComfyUIのイベントループがブロックされてキュー投入が待たされ、さらにフロントエンドのメインスレッドで同期パース・ソートを行うためブラウザのUIがフリーズする。
  - `frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts` の `getSetNameForImage` が、ギャラリーサムネイル（最大50枚）ごとに `localStorage.getItem` と `JSON.parse` を同期実行しており、進捗更新（WebSocket `progress`）による高頻度再レンダリング時に毎秒数百回の同期ストレージアクセスが発生してメインスレッドを圧迫している。
- **Requirement**:
  - 生成回数を重ねてもキュー投入の遅延およびUIフリーズが発生しないよう、通信およびステート更新・描画処理を最適化する。
  - 履歴取得における不要な重複呼び出しを削減し、必要なデータのみを軽量に取得する仕組みに見直す。
  - ギャラリーサムネイル表示等のレンダリングパスにおける同期 `localStorage` / `JSON.parse` 走査をインメモリキャッシュ化し、メインスレッドのブロッキングを排除する。
- **Acceptance criteria**:
  - [x] AC-1: 生成進行中および完了時（`executing` / `executed` / `execution_complete`）において、`fetchHistory` の過剰な重複呼び出しが解消され、必要な画像情報のみが効率的に反映されること。
  - [x] AC-2: ComfyUIからの履歴取得処理において、巨大なワークフローJSONを含む全件取得が最適化され、メインスレッドへの高負荷なパース処理が抑制されること。
  - [x] AC-3: ギャラリーサムネイル表示時のセット名解決（`getSetNameForImage`）において、毎レンダリング時の同期 `localStorage.getItem` および `JSON.parse` が排除され、インメモリキャッシュ等によりメインスレッド負荷が最小化されること。
  - [x] AC-4: 生成回数が増加（数十回以上連続生成）した場合でも、生成キュー投入（`POST /prompt`）時の待ち時間増大およびUIフリーズ（クリック・入力不応）が発生しないこと。
  - [x] AC-5: 既存の生成機能、バッチ生成、プロファイル/セット別バッチ管理、リアルタイム進捗表示、生成画像プレビューおよび履歴表示にデグレーションが発生しないこと。
