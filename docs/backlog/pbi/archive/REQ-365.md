### REQ-365: Settings画面再設計：2ペイン適応・情報密度最適化およびモバイルエルゴノミクス対応

- **Type**: feature
- **Status**: done
- **Priority**: P2
- **Surface**: frontend/src/pages/SettingsPage (SettingsPage.tsx, components/WorkflowConnectionSection.tsx, components/MappingMasterSection.tsx, components/BaseModelSection.tsx, components/LlmSettingsSection.tsx, components/SpeechToneSection.tsx, components/BubbleDetectionSection.tsx, components/TranslationSettingsSection.tsx, components/ServiceConnectionCard.tsx, components/VramGuardSection.tsx, components/ThumbnailSettingsSection.tsx)
- **Reference**:
  - Prompt Surgeon — Settings 画面再設計仕様書 & インタラクティブモック (SPEC_SETTINGS_V3.3)
  - docs/specs/SPEC_SETTINGS.md (現行 v2.6 → v3.0改訂)
  - docs/specs/SPEC_COMMON.md (AppShell / Mobile Nav 契約)
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: 現行のSettings画面は大画面（>=1280px）で全幅ストレッチによる情報の間延びが発生し、モバイル（<768px）では複雑なテーブルが圧縮・はみ出してタップ操作が困難になるという両極端な解像度でのUI/UX破綻を抱えているため。
  2. なぜその課題が発生するか: 13セクションから5タブ構成へ集約されたものの、プロンプト全文やマスタ定義などの高密度要素がインラインに常時展開され、デスクトップ前提の単一グリッドや多列テーブルがviewportの変化に適応できていないため。
  3. なぜ現状の仕組みで不十分か: 単純なCSSメディアクエリの追加だけでは、テーブルの横スクロール発生、小さなタッチターゲット（<44px）、ウルトラワイド画面での2ペインの余白ギャップ（Row-span崩れ）、プロンプト種別とLLMパラメータの非連動といった情報設計・インタラクション上の根本課題を解決できないため。
  4. なぜこのアプローチを採用するか: 「Density by Default, Depth on Demand（初期密度重視・オンデマンド展開）」、「Adaptive Dual-Pane（大画面2ペイン適応）」、「Mobile-First Ergonomics（モバイルカード変換・44pxタッチ・ボトムシート）」の3原則に基づき、既存のAPI・DB保存契約を100%維持したままフロントエンドUI構造を外科的に刷新するため。
  5. 根本原因: 解像度に応じた情報階層の分離（大画面向け2カラム並列配置、小画面向けカード変換・ボトムシート）と、詳細設定のオンデマンド隠蔽（モーダル・アコーディオン化）という適応型情報設計（Adaptive Information Architecture）が欠落していたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 大画面（>=1280px）でのAdaptive Dual-Pane（2カラムグリッド配置。タブ1ではワークフロー+BaseModelカード vs MappingMasterカード、タブ2ではプロンプト本文 vs 専用モデルパラメータ等の左右連動）。
    - 不要な常時露出を排除し、ParamTypeMasterおよびBaseModelマスタ定義を専用モーダルへ分離。
    - 6種類のプロンプト（最適化/タグ提案/品質評価/翻訳/スタイル/ネガティブ）と推論パラメータ（モデル/Temp/MaxTokens）を「統合型エディタ」として1箇所に集約し、種別選択に連動させる。
    - サムネイル表示比率を複数ボタンから1行ドロップダウンへコンパクト化。
  - **Interaction (インタラクション)**:
    - モバイル（<768px）におけるスワイプ可能な水平スクロールタブバー（snap-x snap-mandatory、短縮名「① モデル」「② 呪文」等）。
    - MappingMasterおよびCheckpointマッピングの多列テーブルをモバイル用超スリムカード（.settings-mobile-table）へ自動変換。操作ボタンを右端へ固定ピン留めし、Target Node列をモバイルで隠蔽。
    - モバイルでのモーダル表示を画面下部からせり上がる「ボトムシート」形式（ドラッグハンドル付き、max-height 85vh）へ適応。
    - VRAMガード上限閾値スライダーの操作にリアルタイム連動（フロントエンドState即時バインド）して、VRAMリアルタイムメーター上の黄色い閾値インジケーター線および警告状態が同期。
    - 各サービス（Supervisor, Backend, ComfyUI）行の「ログ ▼」タップによるインライン・アコーディオンログ展開。
    - 口調プリセット選択に連動したリアルタイム書き換えテスト実行機能。
  - **Visual (視覚デザイン)**:
    - すべてのボタン・セレクト・入力・スイッチのタップ領域をモバイルで最小44×44px保証。
    - ターゲットノードの複数クラス（+N classes）およびバリアント（+N stages）のコンパクトバッジ表現。
    - 端末セーフエリア（env(safe-area-inset-bottom)）およびボトムナビゲーション（高さ54px）との干渉を防ぐコンテンツ最下部余白（pb-[calc(6rem+env(safe-area-inset-bottom))]）。
- **Requirement**:
  - **1. 大画面向け2ペイン適応（Adaptive Dual-Pane）とRow-Span余白解消**:
    - >=1280px（xl）では左右2カラムグリッド（タブ1: 左上=ワークフロー、左下=BaseModel、右=MappingMaster）。各カードは独立コンポーネントとして余白なく整列。
    - 1カラム時（<1280px）は順序を「①ワークフロー → ②MappingMaster → ③BaseModel」へCSS（order）で適応リオーダリング。
  - **2. モバイル向けエルゴノミクス（スワイプタブバー、44pxターゲット、ボトムシート、ボトムナビ回避余白）**:
    - タブバーの水平スワイプスクロール（snap-x snap-mandatory）と短縮ラベル表示。
    - すべてのUIコントロールのタップ最小領域44×44px保証。
    - モーダルのボトムシート変形（上端角丸16px、ドラッグハンドル配置、max-height 85vh）。
    - ボトムナビゲーションと重ならない下部パディング pb-[calc(6rem+env(safe-area-inset-bottom))] の設定。
  - **3. マスタ管理のオンデマンド分離（ParamTypeMaster / BaseModelマスタのモーダル化、行アクション集約）**:
    - MappingMasterヘッダーの「カスタム型マスタ」ボタンから独立モーダルでParamTypeMasterを管理。
    - BaseModelセクションの「モデルマスタ管理」ボタンから独立モーダルでBaseModel定義を管理。
    - ワークフロー一覧の行アクション（リネーム、差分、ロールバック、削除、エクスポート）を右端「︙」メニューへ集約。
  - **4. プロンプト支援の統合型エディタ化（種別連動・モデルパラメータ2ペイン）**:
    - プロンプト種別セレクター（最適化/タグ提案/品質評価/翻訳/スタイル/ネガティブ）を単一エディタ上部に配置。
    - 左ペイン（プロンプト本文）と右ペイン（推論モデル・Temp・MaxTokens）が種別切り替えに即座に同期。
  - **5. サービス管理のオンデマンドログ展開とVRAMメーター閾値線リアルタイム連動**:
    - Supervisor（8899）、Backend（8000）、ComfyUI（8188）の死活ランプおよび「ログ ▼」アコーディオン展開。
    - VRAMメーター上にガード上限閾値を示すインジケーター縦線（黄色）を重畳表示。
    - 右ペインのVRAMガード上限閾値スライダーとクライアントStateでリアルタイム連動し、超過・接近時にメーター色を警告色（赤/黄）へ切り替え。
  - **6. MappingMasterおよびCheckpointテーブルのモバイル超スリムカード変換**:
    - theadを非表示にし、1レコードを2行固定グリッドのカード（.settings-mobile-table）として描画。
    - Role/表示名を1行目左側、アクションボタンを1行目右端に固定ピン留め。
    - 2行目に型バッジ・バリアントバッジを配置。ターゲットノード列はモバイルで非表示化しつつ、a11y用aria-labelでコンテキストを保持。
- **Acceptance criteria**:
  - [ ] AC-1: Given 画面幅1280px以上のデスクトップ環境でSettingsを開いている, When 「① ワークフロー・モデル」タブを表示する, Then ワークフロー管理とBaseModelマッピングが左カラム、MappingMasterが右カラムの2カラム並列グリッドで配置され、不要な空隙なく隙間なく描画されること。
  - [ ] AC-2: Given 画面幅768px未満のモバイル環境でSettingsを開いている, When タブバーを表示する, Then タブバーが水平スクロール可能で短縮ラベル（「① モデル」「② 呪文」「③ セリフ」「④ 翻訳」「⑤ システム」）が表示され、各操作要素のタップ領域が最小44×44px以上確保されていること。
  - [ ] AC-3: Given 画面幅768px未満のモバイル環境でSettingsのMappingMasterを表示している, When テーブルを描画する, Then theadが非表示となり1レコードがカードとして描画され、ターゲットノード列が非表示化され、編集ボタンがカード右端に固定ピン留めされ、a11y用aria-labelにターゲットノード情報が保持されていること。
  - [ ] AC-4: Given 「① ワークフロー・モデル」タブでMappingMasterセクションを表示している, When 「カスタム型マスタ」ボタンを押下する, Then ページ内常時展開ではなく独立したモーダルダイアログ（モバイルではボトムシート）としてParamTypeMaster管理画面が展開されること。
  - [ ] AC-5: Given 「② プロンプト支援」タブを表示している, When プロンプト種別セレクターで「① プロンプト最適化」から「② タグ提案」へ切り替える, Then プロンプト本文のテキストエリアと右ペインのLLM推論パラメータ（モデル、Temperature、Max Tokens）が選択種別専用の値へ即座に連動して切り替わること。
  - [ ] AC-6: Given 「③ セリフ支援」タブを表示している, When 口調プリセット一覧から任意の口調を選択しテスト入力にテキストを入力して「テスト実行」を押下する, Then 選択中の変換プロンプトに基づくプレビュー出力結果が右ペインに表示されること。
  - [ ] AC-7: Given 「⑤ システム・一般」タブを表示している, When サービス管理一覧でSupervisor/Backend/ComfyUIの各サービス行の「ログ ▼」を押下する, Then 対象サービス行の直下に直近ログがアコーディオンパネルとしてインライン展開されること。
  - [ ] AC-8: Given 「⑤ システム・一般」タブを表示している, When 右ペインの「VRAM ガード上限閾値」スライダーを操作する, Then クライアント側Stateバインドにより左ペインのVRAMリアルタイムメーター上の閾値インジケーター縦線の位置および閾値表示タグがドラッグに即座に追従して連動移動すること。
  - [ ] AC-9: Given 画面幅768px未満のモバイル環境でSettingsの任意のモーダル（カスタム型マスタ等）を開く, When モーダルが表示される, Then 画面中央固定ダイアログではなく画面下部からせり上がるボトムシート形式（ドラッグハンドル付き、角丸上端16px）で表示されること。
  - [ ] AC-10: Given Settings画面の表示状態を変更する, When ユーザーがタブを切り替えるかVRAMガード上限値を変更する, Then LocalStorageキー prompt-surgeon-settings-active-tab および prompt-surgeon-vram-guard-limit に最新の状態が同期・永続化されること。
- **Inferred points**:
  - 状態管理スキーマ: prompt-surgeon-settings-details-expanded-v2 のスキーマ定義 { prompt: boolean, dialogue: boolean } は現行仕様（SPEC_SETTINGS §3）を完全維持し、詳細プロンプト・口調エディタの開閉状態のみを管理する。ParamTypeMasterおよびBaseModelマスタ管理モーダルは一時的なUIダイアログであり、この永続化キーには含めない。
  - リアルタイム同期境界: AC-8の「スライダーとメーター線のリアルタイム連動」はフロントエンドのローカルReact状態（ドラッグ中のローカルState更新）による即時描画であり、バックエンドへのWebSocket/HTTP負荷は発生しない。バックエンドからの実測VRAM値取得（ポーリング/WebSocket）は既存の更新周期を維持する。
  - レイアウト独立性: ワークフロー、MappingMaster、BaseModelの3カードはそれぞれ独立したカードコンポーネントであり、内部行同士のデータ依存・Row-Span依存関係は存在しない。大画面時の2カラム配置（左: ワークフロー・BaseModel、右: MappingMaster）および小画面時の順序変更（ワークフロー → MappingMaster → BaseModel）は純粋なCSS（Grid / Flex order）による視覚的適応であり、バックエンドAPIペイロードやデータ順序には一切影響を与えない。
  - アクセシビリティ（a11y）: モバイル表示（<768px）においてTarget Node列を非表示とする際は、アクセシビリティを担保するため各カードの編集ボタンに aria-label="[Role名] のマッピング設定を編集" 等の説明属性を動的付与する。
  - 安全領域（Safe Area）: 下部余白は固定ボトムナビ（高さ54px + env(safe-area-inset-bottom)）に隠れないよう、Settingsで 768px未満に pb-[calc(6rem+env(safe-area-inset-bottom))] を確保（768px以上は md:pb-5 で解除）し、画面要素の隠蔽を防ぐ。
  - 排他モーダル設計: 各モーダル（ParamTypeMaster、BaseModelマスタ）は相互に排他的な独立ダイアログとして動作し、モーダルのネスト（多重重なり）は発生させない。
