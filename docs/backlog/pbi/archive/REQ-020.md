### REQ-020: プロンプト入力欄の個別折り畳み・展開機能

- **Status**: done (2026-08-26)
- **Type**: enhancement
- **Priority**: P2
- **Current step**: none
- **Surface**: プロンプト入力欄をそれぞれの枠毎に折り畳み・展開できるようにしたい
- **Root Cause**:
  - 複数のプロンプト入力欄（ポジティブ、ネガティブ、各種アセット入力等）が常にすべて展開された状態で表示されており、入力内容が多くなると画面内の縦スクロール量が増え、視認性が低下する。
  - 試行錯誤中であまり変更しないプロンプト枠を非表示にしておき、現在集中して編集したい入力欄だけを表示するスペース制御の仕組みがないため、不要な表示領域によるインタラクションコストや注意散漫が発生している。
- **Requirement**:
  - **個別折り畳み・展開トグル**: 各プロンプト入力枠（セクション）を個別に折り畳み（非表示）、展開（表示）できるトグルUIを導入する。
  - **前回の状態復元**: 各入力欄の折り畳み状態をブラウザのキャッシュ（localStorage等）に保存し、次回ロード時に前回の折り畳み・展開状態を自動で復元する。
  - **折り畳み時の表示制御**: 折り畳み時には入力エリアを非表示とし、タイトル部分のみをシンプルな形で表示する。入力済みのプロンプトの冒頭プレビューや文字数などは不要とし、情報密度を最小化する。
  - **特定トリガーによる自動展開**: 
    - 「add asset（アセット追加）」などのトリガーによって該当の入力欄に何かしらのデータが追加された場合、自動的にその枠を展開する。
    - 「テキスト入力モード切替（Text mode toggle）」等の切替ボタンが押下された場合も、自動的にその枠を展開する。
  - **対象のプロンプト入力欄**: ジェネレーター画面等にあるプロンプト入力欄（セクション）のすべてを対象とする。
- **Acceptance criteria**:
  - [ ] AC-1: すべてのプロンプト入力欄（セクション）ごとに、折り畳みおよび展開を行うトグルボタン（またはクリック可能なヘッダー）が設置されていること。
  - [ ] AC-2: 折り畳み状態のとき、入力フィールドやオプション要素は非表示となり、セクションタイトルのみが表示されて縦方向の占有スペースが最小化されること。
  - [ ] AC-3: 各セクションの折り畳み・展開状態が localStorage 等のブラウザ保存領域に格納され、ページをリロードした際にも直前の折り畳み状態が正しく復元されること。
  - [ ] AC-4: アセット追加（add asset）によってプロンプト枠にデータが追加されたとき、該当セクションが自動で「展開」状態になり、追加内容が視認・編集できること。
  - [ ] AC-5: テキスト入力モード切替ボタンが押下されたとき、該当セクションが自動で「展開」状態になること。
  - [ ] AC-6: 折り畳み状態から展開したとき、入力済みのテキストや設定情報が欠損・リセットされることなく、そのまま保持されて表示されること。
- **Design doc**: none
