### REQ-037: WebSocket生成完了時のプレビュー・履歴自動更新バグ修正

- **Type**: defect
- **Status**: ready
- **Current step**: none
- **Priority**: P1
- **Surface**: 生成完了時にプレビューエリア・履歴エリアに生成完了した画像が表示されず、リロードすると表示される。本来は、生成完了をwebsocketで受け取り、当該画像を自動的に表示・履歴への追加をしたい。
- **Root Cause**: WebSocket受信直後に `/history` APIを呼び出すことによるタイミング問題（レースコンディション）、全体履歴 `comfyHistoryImages` に対する直接更新処理の不足、UUID形式のキーを `Number` キャストしてソートしている処理の不備、およびWebSocket切断時のクリーンアップ・再接続制御の不備。
- **Requirement**: 生成完了（WebSocketのイベント受信）時に、画面をリロードすることなく、生成画像がプレビューおよび履歴にリアルタイムで追加・表示されること。WebSocket接続が切断された場合に、正常に復旧できること。
- **Acceptance criteria**:
  - [ ] AC-1: 画像生成が完了した際に、リロードを行うことなく、生成された画像がメインプレビューエリアおよび履歴エリア（サムネイル一覧）に即座に表示されること。
  - [ ] AC-2: サムネイル履歴一覧の画像が、生成された日付（最新順）に則って正しい順序でソートされて表示されること。
  - [ ] AC-3: WebSocket接続が予期せず切断された後も、再度接続を開始（またはリロード等）した際に、接続が正常に復旧すること。
  - [ ] AC-4: 自身が生成した画像のみを表示するフィルタ（filterOwnSession）の有効・無効に関わらず、生成された画像がそれぞれ適切なエリアに反映されること。
- **Design doc**: none
