### REQ-198: プリセット・プロンプト編集のオートセーブおよび一括編集における状態同期・OCC競合解消（過去帰り・未反映防止）
- **Type**: bugfix
- **Status**: active
- **Current step**: Phase 1: Intake & Triage (Completed)
- **Priority**: P1
- **Surface**:
  - 生成画面でプロンプトを編集しても保存されず、ブラウザのリロードや別画面からの復帰時に過去の状態に戻ってしまうことがある。
  - プリセット管理モーダルから一括編集を複数回実行すると、未反映の項目が出たり、以前の変更が古いデータで上書きされて巻き戻ることがある。
- **Root Cause**:
  - `updatePresetMutation` 成功時に React Query キャッシュを同期更新（`setQueryData`）せず `invalidateQueries` による非同期再取得のみを行っているため、連続入力時に古い `base_updated_at` が送信されてバックエンドで `409 Conflict` が発生し、変更が DB に保存されない。
  - 409 Conflict 発生時にエラーが握りつぶされ、フロントエンドの `lastSavedStateRef` と DB 実態が乖離し、リロード時に DB の過去データへ巻き戻る。
  - プリセット一括編集（`handleBulkEditApply`）において、コンポーネント内の古い `presets` クロージャを参照して変更を適用しているため、連続実行時に古い値ベースで DB を上書きしてしまう。またアクティブプリセット更新時のステート同期不整合によりオートセーブが誤発火して 409 競合を引き起こす。
- **Requirement**:
  - 生成画面におけるプロンプト・パラメータ編集のオートセーブが確実に DB へ保存され、連続入力時やリロード時にも編集内容が過去の状態へ巻き戻らないこと。
  - プリセット更新成功時に React Query キャッシュ（`workflow-presets`）を即座に同期更新し、最新の `updated_at` を保持して OCC（409 Conflict）の誤検知を防ぐこと。
  - プリセット一括編集を連続実行した場合でも、常に最新のプリセット状態に基づいて変更が計算・適用され、過去データによる上書きが発生しないこと。
  - 一括編集後のアクティブプリセットの状態（`lastSavedStateRef`、タイムスタンプ等）を正確に同期し、不要なオートセーブや競合を防止すること。
- **Acceptance criteria**:
  - [x] AC-1: 生成画面でプロンプト入力欄を連続編集・更新した際、409 Conflict を起こさずに正しく DB へ保存され、ブラウザをリロード（F5）しても最新の編集内容が保持されること。
  - [x] AC-2: プリセット更新 API 実行時に、返却された最新の `updated_at` を即時にフロントエンドのキャッシュおよび状態へ反映し、後続のオートセーブに最新の `base_updated_at` が付与されること。
  - [x] AC-3: プリセット管理モーダルから一括編集を複数回連続して実行した場合でも、直前の編集内容を維持した上で正しく差分・変更が累積反映されること。
  - [x] AC-4: 一括編集でアクティブなプリセットが変更された際、ローカルステート（`paramValues`, `appliedAssets`, `lastSavedStateRef`, `updated_at`）が即時に整合性をもって同期されること。
