### REQ-345: 原画が消失した生成試行を履歴から除外し再取得を抑止する

- **Type**: feature
- **Status**: done (2026-10-12)
- **Priority**: P2（仮置き）
- **Surface**: 生成ページの未保存試行履歴
- **Operational need**: 閲覧不能な画像の再選択と反復取得をなくす。
- **5 Whys / 業務上の課題整理**（ユーザー報告からの要約。実装原因の断定ではない）:
  1. 原画が消えてもサムネが残り閲覧可能と誤認する。
  2. ComfyUI再起動後にtmp原画とサムネの寿命が異なる。
  3. サムネの有無だけで原画の可否を判断できない。
  4. 消失した試行を除外すれば不要な再選択と取得を避けられる。
  5. 履歴表示と原画の取得可能性が一致していないことが業務上の課題である。
- **UX Classification**: Information Design / Interaction
- **Requirement**:
  - 用語: 原画はComfyUIのtmpにある未保存の生成結果画像を指し、生成入力画像ではない。消失確定は対象原画について上流の404が確認された状態であり、サムネイル404や一時エラーは含まない。履歴除外はFE非表示でありDBレコード削除ではない。
  - 既存SPEC_GENERATEの原画availability契約を維持し、サムネイル成功でも原画消失が分かる場合の表示取りこぼしを解消する。自動削除期限は変更・延長しない。
  - 原画不在が確定した未保存試行のみをFE履歴から除外し、欠損確定後の自動再取得を抑止する。
  - BEのサムネ/メタデータ自動削除と保存Snapshotの仕様を維持する。
  - ページ再読み込み時は復元済みの表示履歴をBEの残存履歴と比較し、BEが把握する未表示試行のうち原画presentを確認したものだけ追加する。全履歴を無条件に読み直して表示配列を置換しない。
  - 「表示済み履歴」は復元済みの全履歴/自sessionの表示cacheと対応storeから作る未保存試行の論理集合。viewport、選択中タブ、sort、現在のsession filterに依存しない。Snapshotは含めない。identityはfilename/subfolder/type、hostとtの違いは同一画像とする。
  - 新規候補のunknownは追加保留、missingは追加しない。既存表示のunknownはAC-4に従い保持する。応答中に到着した画像とも再比較し重複追加を防ぐ。既存の表示順・URL・選択を維持し、追加分はBEの確定順で先頭へ、昇順表示は全体の逆順とする。
- **Acceptance criteria**:
  - [ ] AC-1: Given 残存サムネがある未保存試行Aと取得可能な原画を持つ試行B, When ComfyUIだけを再起動しAの原画について上流404が確認されて履歴更新する, Then Aを表示せずBを表示すること。
  - [ ] AC-2: Given 消失確定した試行A, When 履歴再描画と別試行の選択を行う, Then Aの原画への自動取得要求が0件であること。
  - [ ] AC-3: Given 復元履歴に原画消失Aと取得可能B、BEだけが把握する未表示の取得可能C・消失D・通信不明Eがある, When ページを再読み込みして残存履歴差分同期と初期表示需要の確認を完了する, Then Aを除外、Bを保持、Cだけを1件追加し、D/Eを追加せず、Aの原画取得を反復しないこと。
  - [ ] AC-4: Given サムネ失敗または原画確認の503・通信失敗・timeoutのみ, When 履歴更新する, Then 消失確定として履歴除外しないこと。
  - [ ] AC-5: Given 自動削除期限前の試行Aのサムネとメタデータ, When Aの消失確定で履歴除外する, Then 当該サムネとメタデータを即時削除しないこと。
  - [ ] AC-6: Given 保存済みSnapshot, When 未保存試行の欠損を処理する, Then Snapshotの表示・画像・保存パラメータが保持されること。
  - [ ] AC-7: Given Bは旧host/t違いのURLで表示済み、Cは応答待ち中に実行完了で表示へ到着し、同filenameでsubfolder/typeが異なるFがある, When 残存差分を適用する, Then B/Cを重複追加せずFを別画像として追加し、既存B/CのURL・相対順・主/複数選択を維持すること。
  - [ ] AC-8: Given persist復元と初回Generation同期が非同期、Snapshotタブまたは自session filterが有効, When ページを再読み込みする, Then 有効canonical identityの非空persist baselineを復元し初回同期後に1回の論理差分同期を開始し、baselineなしでは差分要求を0件に抑え、GET /api/comfy/history とhistory-fetched全件置換は再読込経路で0回、未表示候補だけをBEで確認し、known/examined identityの再確認は0回、再描画・StrictMode・filter/sort・focusで同同期を再開しないこと。
  - [ ] AC-9: Given 残存差分APIの503/timeout/通信失敗/不正本文、未確認sessionの候補、または実page離脱後の応答, When 差分同期する, Then 既存履歴・選択・Snapshot・metadataを保持し、自動全件取得fallback/自動retryは0回、未知sessionの画像は全履歴のみへ追加し、自sessionへは既存session IDと一致した画像だけ追加し、離脱後の書込は0回であること。
