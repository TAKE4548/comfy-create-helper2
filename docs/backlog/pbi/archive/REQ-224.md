### REQ-224: プリセット一括編集におけるパラメータタブLoRA適用不具合解消およびLoRA適用機能の重複整理

- **Type**: defect
- **Status**: done (2026-09-06)
- **Priority**: P1
- **Surface**:
  - 生成プリセットの一括編集（`ProfileBulkEditModal`）での、パラメータタブのLoRA適用が機能しない。
  - LoRA専用のタブがあるが、パラメータタブのLoRA適用機能と重複している（なお、アセット追加はトリガータグのプロンプト反映が目的であり別役割）。
- **Root Cause**:
  - `ProfileBulkEditModal.tsx` において、`m.input_type === 'lora_stack'` 描画時に個別有効化チェックボックスが欠落しており、`enabledParams` に登録されない。
  - `buildPayload()` 内のパラメータ抽出ロジックが `enabledParams` の完全一致キー（`paramPatch[role]`）のみを走査するため、`LoraStackEditor` が生成する接頭辞付きスロットキー（`${role}_lora_count`, `${role}_lora_name_*`, `${role}_lora_wt_*` 等）がすべて除外される。
  - プロンプトへのタグ反映を担う「アセットの追加（`AddAssetModal`）」とは別に、「LoRAモデル・強度等を指定してプリセットに適用する機能」が「パラメータ」タブ（`LoraStackEditor`）と「LoRA」タブ（単一LoRA指定等）の双方に存在し、機能が重複してUI導線が二重化している。
- **Requirement**:
  - パラメータタブの `LoraStackEditor` からLoRAを追加・変更・削除した際、対象プリセットに対してLoRAスロットパラメータが正しく一括適用・保存されること。
  - 「LoRA自体の適用設定」に関する重複導線を整理・一元化し、プロンプトへのタグ反映を担うアセット追加（`AddAssetModal`）と混同しない明確なUI構造にすること。
- **Acceptance criteria**:
  - [ ] AC-1: `ProfileBulkEditModal` のパラメータタブにおいて、`lora_stack` パラメータ（LoRA Stack）の編集および一括適用の有効化が正しく行えること。
  - [ ] AC-2: パラメータタブでLoRAを追加・変更して一括編集を適用した際、選択したプリセットの `param_values` にLoRAスロットパラメータ（`${role}_lora_count`, `${role}_lora_name_*`, `${role}_lora_wt_*`, `${role}_model_str_*`, `${role}_clip_str_*`）が正確に反映・保存されること。
  - [ ] AC-3: 「LoRA自体の適用設定」が重複していた問題が解消され、ユーザーが迷わずLoRAの一括編集を行えるUI構造に整理されていること。
  - [ ] AC-4: プロンプトへのトリガータグ反映を担う「アセット追加（`AddAssetModal`）」機能およびプロンプトタブ・既存パラメータ編集機能が退行せず、正常に動作すること。
  - [ ] AC-5: 関連するコンポーネントテスト（`ProfileBulkEditModal.test.tsx` 等）が追加・更新され、すべてパスすること。
