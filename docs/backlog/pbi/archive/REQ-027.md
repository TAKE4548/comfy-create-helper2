### REQ-027: フロントエンドテスト環境(Vitest)の導入とタグチップエディタのテスト実装

- **Status**: done (2026-08-26)
- **Type**: enhancement
- **Priority**: P2
- **Current step**: none
- **Surface**: FEのテストフレームワークを導入したい。リファクタ・機能追加でのデグレが心配。ユニット・コンポーネントテストとして Vitest を選択。対象はタグチップ化のロジック、コンポーネント。
- **Root Cause**:
  - 現在、フロントエンドに自動テスト環境が存在せず、コードのリファクタリングや機能追加（タグチップエディタなど複雑なUIロジックを含む部分）の際にデグレーション（先祖返りやバグの混入）が発生するリスクが高い。
  - 手動での回帰テストは時間がかかり、漏れが発生しやすいため、開発スピードと品質の維持に課題がある。
- **Requirement**:
  - **テスト環境の構築**:
    - Viteの構成と統合された高速なテストランナーとして `Vitest` を導入する。
    - ReactコンポーネントのDOM操作テストやレンダリング検証のため `React Testing Library` (`@testing-library/react` 等) を導入する。
    - DOM要素に対するアサーション用に `@testing-library/jest-dom` 等の拡張アサーションを設定する。
    - テスト実行環境（happy-dom または jsdom）を設定する。
    - `npm run test` コマンドでテストを実行可能にし、またウォッチモードやカバレッジレポートの出力ができるようにする。
  - **タグチップエディタのテスト実装**:
    - タグチップ化ロジックを担当するカスタムフック (`useChipParser.ts` や `useChipHistory.ts`) に対するユニットテストを実装する。
    - タグチップ表示・入力コンポーネント (`TagChip.tsx`, `TagInput.tsx`, `TagChipEditor/index.tsx`) の描画、インタラクション（入力、変換、削除、履歴機能など）に対するコンポーネントテストを実装する。
- **Acceptance criteria**:
  - [ ] AC-1: `Vitest` および `React Testing Library` が `frontend` パッケージに正しくインストールされ、設定ファイルでテスト用環境（jsdom/happy-dom等）が設定されていること。
  - [ ] AC-2: `frontend/package.json` に `test`（テスト実行）、`test:watch`（ウォッチモードでのテスト実行）、`test:coverage`（カバレッジの測定）のスクリプトが追加され、正常に実行できること。
  - [ ] AC-3: `useChipParser` のパースロジック（文字列からタグへのパース等）に関して、様々な入力値に対する検証テストが実装され、期待通り動作すること。
  - [ ] AC-4: `useChipHistory` の履歴管理ロジック（履歴の追加・取り消し・やり直し等）に関して、ユニットテストが実装され、期待通り動作すること。
  - [ ] AC-5: `TagChip.tsx` および `TagInput.tsx` / `TagChipEditor` コンポーネントに関して、レンダリング、ユーザー入力、チップの追加・削除のインタラクションをテストするコンポーネントテストが実装され、期待通り動作すること。
- **Design doc**: none
