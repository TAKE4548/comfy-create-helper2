### REQ-331: Dataset Studio におけるパラメータ編集・ノードバイパス機能およびロールフィルタ付きノードマッピングの統合（部品共用・セクション折畳対応）

- **Type**: feature
- **Status**: done (2026-10-08)
- **Priority**: P2
- **Surface**: frontend/src/pages/DatasetStudioPage/components/MatrixGenerationStep.tsx, frontend/src/pages/DatasetStudioPage/components/NodeRemapModal.tsx, frontend/src/pages/DatasetStudioPage/useStudioStore.ts, docs/specs/SPEC_DATASET_STUDIO.md
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: Dataset Studio (Step 1: MatrixGenerationStep) でマトリクス画像生成・直接投入を行う際、Steps, CFG, Sampler, Scheduler, LoRA Stack などのパラメータ編集や、FaceDetailer/Upscaler 等のノード bypass（無効化）設定が行えず、また入力項目増加に伴う視認性・操作性の低下を防ぐ必要があるため。
  2. なぜその課題が発生するか: Dataset Studio の Step 1 には生成ページ（GeneratePage）で提供されている ParamPanel や BypassSettingsModal が組み込まれておらず、初期固定値のまま投入される仕様となっていたため。また、入力項目が増えることで画面の縦スクロールが増大し作業効率が落ちるリスクがあるため。
  3. なぜ現状の仕組みで不十分か: 生成パラメータの微調整や不要ノードのバイパスを行うために生成ページへ移動してワークフロー自体を変更する必要があり、Studio 画面内で完結したデータセット生成・試行ができないため。また、全入力欄が常時展開されていると目的の操作へのアクセス性が悪化するため。
  4. なぜこのアプローチを採用するか: 生成ページ（GeneratePage）の機能部品（ParamPanel, BypassSettingsModal, マッピング編集基盤）を重複実装せず、アダプター設計により共通部品として共用（Component Sharing）することで保守性と一貫性を担保できるため。さらに、各入力欄をセクション別のアコーディオン／折り畳み（Collapsible Sections）として構成することで、画面の情報密度を整理し高い操作性を維持できるため。
  5. 根本原因: Dataset Studio のワークフロー実行系が生成ページのパラメータ管理・バイパス制御・ノードマッピング基盤と疎結合なまま個別の最小実装にとどまっており、かつ増加する入力欄を整理・集約する UI コンポーネント構造が整っていなかったこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - Dataset Studio Step 1 に選択中ワークフローのパラメータ入力項目（共用 ParamPanel: Steps, CFG, Sampler, Scheduler, Denoise, LoRA Stack 等の非 textarea マッピング項目）およびバイパス状態表示を統合。
    - プロンプト因子入力、ネガティブプロンプト、パラメータ入力パネル等をセクション別に分割し、各セクションの開閉状態（折り畳み）を視覚的に明示。
    - ノードマッピングモーダルにおいて、全パラメータロールを表示しつつ、Studio 独自のマトリクスプロンプトと重複する汎用プロンプト入力欄ロール（textarea）をホワイトリスト方式（Positive/Negative に限定）で整理して表示。
  - **Interaction (インタラクション)**:
    - 生成ページと共通の機能部品（Props 経由で Studio ストアと疎結合に接続）を用いたパラメータ値のインライン編集、Bypass 設定モーダルでのノード有効/無効切り替え。
    - 各セクションヘッダーのクリックによるワンタップ折り畳み・展開トグル動作（作業コンテキストに応じた表示整理）。
    - リマッピングモーダルでの各ロールとノードの対応付け・更新。
    - マトリクス生成投入（ComfyUI への一括投入）時に、編集した共通パラメータ値およびバイパス状態が ComfyUI プロンプトペイロードに正確に注入・反映されること。
  - **Visual (視覚デザイン)**:
    - Dataset Studio のダークテーマ（#0F0F11, #18181C）に統一された、セクション折り畳みアコーディオン（アコーディオンアイコン、開閉アニメーション、境界ボーダー）。
    - パラメータ入力パネルおよびバイパストグルの一貫した視覚スタイル。
- **Requirement**:
  - **1. 生成ページとの機能部品共用設計（Component Sharing & Adapter Pattern）**:
    - 生成ページ（GeneratePage）で利用されている既存コンポーネント（ParamPanel, BypassSettingsModal, マッピング編集ロジック）を Studio 固有に二重再実装せず、Props やハンドラを介して useStudioStore と接続する共用設計とする。
  - **2. UI 入力欄のセクション別折り畳み機構（Collapsible Sections）**:
    - Studio Step 1 において、増加する入力項目（マトリクス因子プロンプト、Negative プロンプト、生成パラメータ、マッピング／バイパス情報等）をセクションごとにアコーディオン形式で折り畳み／展開可能にし、画面の圧迫を防ぎ操作性を維持する。
  - **3. ロールフィルタ付きノードマッピング機能の統合**:
    - 生成ページのノードマッピング（RescanModal 等の共通基盤）をベースに流用し、数値や選択肢などの各種パラメータロールはそのまま利用可能としつつ、Studio のプロンプト合成と干渉する汎用プロンプト入力欄ロールのみをフィルタリング（Studio が扱う Positive/Negative 注入先のみ残し他を除外）して表示・変更可能にする。
  - **4. ComfyUI 投入ペイロードへのパラメータおよびバイパス状態の反映**:
    - Studio から ComfyUI へマトリクス画像をバッチ投入する際、共用 ParamPanel で編集されたパラメータ値（Steps, CFG, Sampler, LoRA 等）およびバイパス設定を全20件の各ジョブペイロードに確実に反映する。
  - **5. プロジェクト状態としてのパラメータ・バイパス設定の永続化**:
    - 編集したパラメータ値およびバイパス設定が Studio プロジェクトの下書き（sessionStorage）およびサーバー永続化データに保存・復元されること（SPEC_DATASET_STUDIO 準拠）。
- **Acceptance criteria**:
  - [x] AC-1: Given ユーザーが Dataset Studio (Step 1) でワークフローを選択したとき, When 画面上のパラメータ入力エリアを確認した際, 生成ページと共用された ParamPanel 部品により動的入力項目（Steps, CFG, Sampler, Scheduler, Denoise, LoRA Stack 等）が表示され、値を編集できること。
  - [x] AC-2: Given ユーザーが Dataset Studio (Step 1) でノードバイパス設定を行いたいとき, When Bypass 設定ボタンを押下した際, 生成ページと共用された BypassSettingsModal が開き、ノードのバイパス（無効化/有効化）を切り替えて保存・反映できること。
  - [x] AC-3: Given ユーザーが Dataset Studio (Step 1) でノードマッピングの確認・再設定を行いたいとき, When ノードマッピング編集ボタンを押下した際, 生成ページと共用基盤を持つマッピングモーダルが開き、Studio 独自プロンプトと重複する汎用プロンプト入力欄ロールは適切に除外フィルタされつつ、Positive/Negative 注入先およびパラメータ関連の全ロール（数値、選択肢、LoRA、バイパス等）が表示されノード再割当・保存ができること。
  - [x] AC-4: Given パラメータ編集およびノードバイパス設定が完了した状態で, When 「ComfyUIに20件直接投入」（またはマトリクス画像生成投入）を実行した際, 編集された共通パラメータ値およびバイパス設定が全20件の各プロンプトペイロードに正しく反映・注入されて ComfyUI へ投入されること。
  - [x] AC-5: Given プロジェクトの保存および再読み込み（リロード・再訪）を行ったとき, When 保存された Dataset Studio プロジェクトを開いた際, 設定したパラメータ値およびバイパス状態が正しく復元されること。
  - [x] AC-6: Given ユーザーが Dataset Studio (Step 1) の入力画面を操作するとき, When 各入力セクション（プロンプト枠、パラメータ枠等）の折り畳みトグルをクリックした際, 該当セクションのアコーディオンがスムーズに開閉し、作業領域のスクロール負荷を軽減して高い操作性が維持されること。
- **Inferred points**:
  - 生成ページと機能部品を共用するにあたり、Studio 固有のコンテキスト（マトリクス投入、プロジェクト単位の永続化）を Props やアダプター経由で柔軟に注入できるクリーンなインターフェース設計とする。
  - ロールフィルタリングは、非 textarea ロール（全パラメータ）＋ Studio 必須の Positive/Negative ロールをホワイトリストとして抽出し、不要な汎用 textarea ロールを安全に非表示化する。
  - セクションの開閉状態は、ユーザーの編集操作を妨げないようデフォルトで主要セクションを展開しつつ、ローカル UI 状態として軽快にトグルできるようにする。
