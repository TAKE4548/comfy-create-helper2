### REQ-275: Web Manager経由のサービス再起動(reboot-service)におけるタイムアウト(504)および起動失敗の解消

- **Type**: bugfix
- **Status**: done (2026-09-17)
- **Current step**: Step 1 (Requirement Finalized)
- **Priority**: P1
- **Surface**:
  - Web Manager（http://localhost:8899）からサービスの再起動（reboot-service / restart）を実行した際、HTTP 504 Gateway Timeout が返却され、画面上でエラーとなる。
  - 再起動指示後にバックエンドが正常に再起動せず、STOPPED 状態のまま停止してしまう。
  - Web Manager のログ画面（Backend タブ）に表示される内容が過去のエラー（22:35時点等）で停止したまま更新されず、最新の起動・稼働ログが `tools/server-manager/logs/backend.log` に反映されない。
- **Root Cause**:
  - **Interaction & Workflow Friction (Timeout Mismatch, Synchronous Wait Cascading, and Broken Background Log Redirection)**:
    - Web Manager API（`server_api.py`）の `/api/action` エンドポイントにおいて、PowerShell サブプロセス呼び出しのタイムアウトが 15秒（`timeout=15`）に固定されている。
    - 一方、`server-manager.ps1` の `reboot-service` は「停止待機（最大5秒）」＋「起動後ポート待機（最大15秒）」を直列に同期実行するため、合計最大20秒を要し、15秒超過により `server_api.py` が 504 Gateway Timeout を返却してプロセス通信を遮断してしまう。
    - また、PowerShell のバックグラウンド起動処理（`Start-BackendProcess`）において、`Start-ProcessNoWindow` で `cmd.exe /c run_server.bat ... > backend.log 2>&1` を実行する際のリダイレクト記述やプロセス起動待機の不備により、停止後のバックグラウンド起動が途中で失敗する、あるいは最新ログが `backend.log` に正しく出力・更新されず古いログが固定表示されてしまう。
- **Requirement**:
  - Web Manager API（`server_api.py`）において、再起動（`restart`, `reboot-service`）などの停止＋起動を伴う長時間アクションに対して適切なタイムアウト（または非同期受付・進捗通知）を設定し、HTTP 504 タイムアウトエラーが発生しないようにすること。
  - `server-manager.ps1` の再起動ロジックおよびバックグラウンドプロセス起動（`Start-BackendProcess` 等）を安定化し、再起動後に確実にポート（8000等）が LISTEN 状態へ復帰すること。
  - バックエンドのバックグラウンド起動時および稼働中の標準出力・エラー出力が `tools/server-manager/logs/backend.log` に確実にリアルタイム追記され、Web Manager の UI から最新のバックエンドログを閲覧できるようにすること。
  - Web Manager UI から「再起動」をクリックした際に、正常に完了レスポンスが得られ、サービスが稼働再開することを担保すること。
- **Acceptance criteria**:
  - [ ] AC-1: Web Manager API（`server_api.py`）の `/api/action` に対し、`reboot-service`（backend）を POST した際に HTTP 504 タイムアウトとならず、正常（200 OK）にレスポンスが返却されること。
  - [ ] AC-2: `server-manager.ps1 -Action reboot-service -Service backend -Background` の実行後、バックエンドが停止状態から自動的に再起動し、ポート 8000 が LISTEN 状態に復帰すること。
  - [ ] AC-3: バックエンド起動・再起動時に `tools/server-manager/logs/backend.log` が正しく更新・追記され、Web Manager（`/api/logs?service=backend`）から最新ログが取得できること。
  - [ ] AC-4: 既存の `server_status.py` および Web Manager からのステータス取得（`/api/status`）において、再起動後のバックエンドが正常に `[RUNNING]` (status: `LISTEN`) として認識されること。
  - [ ] AC-5: 回帰テスト（既存の `tests/unit/test_server_manager_*.py` 等）がすべて PASS すること。
