### REQ-419: REQ-417の3層マッピング設計に合わせたマッピングマスタ設定UIの再構成と判定プレビュー

- **Type**: feature
- **Status**: in-progress
- **Priority**: P2
- **Surface**: Frontend（Settings: MappingMaster一覧、MappingMasterEditModal、StageManagerModal、判定プレビューUI）、Backend（判定プレビュー用の非永続スキャンAPIが必要な場合のみ。要否は設計で判断）
- **Related**: REQ-417（3層分離・スキャン刷新、done）、REQ-418（variant_id参照移行、done）
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: REQ-417でデータモデルとスキャン判定がMaster／Variant／判定定義（BindingRuleSet・NodeSelector）の3層へ刷新されたが、設定UIには旧MappingMasterの考え方（Master単位の対象クラス・パラメータ名・フォールバック・タイトルパターン入力欄、`+N classes` バッジ、ステージ検索語）が残っており、画面と実際の判定構造が一致していないため。
  2. なぜそれが問題か: 利用者が画面上の項目を編集しても、それが新構造のどの定義（どのVariantのRuleSetやNodeSelector）に効くのかが分からず、意図しないステージ・roleへ影響する設定ミスや「どちらが効いているのか分からない」二重入力（StageMaster.search_keywords と NodeSelector パターン）が発生するため。
  3. なぜ現状のUI分割では不十分か: REQ-417のUI分割は判定定義を編集可能にしたが、Masterを起点に「ステージごとのVariant → そのRuleSet／NodeSelector」を一望・編集する導線になっておらず、設定結果がワークフロー上でどのノードに当たるかを事前に確認する手段もないため。
  4. なぜこのアプローチか: Master起点でステージ別Variantを並べ、各Variantに判定定義を明示的に紐づけて表示・編集し、共有定義の変更は影響範囲を示して利用者に選ばせ、登録済みワークフローへの判定プレビューで結果を保存前に確認できれば、画面と判定構造が一致し、設定ミスを保存前に発見できるため。
  5. 根本原因: データモデル刷新（REQ-417）に対して、設定UIの情報構造（入力項目・一覧表示・ステージ管理）が旧モデルのまま部分的に残り、判定結果を可視化する手段が設計されていなかったこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - Master＝値の意味と型、Variant＝ステージ単位のrole、RuleSet＝どの入力か、NodeSelector＝どのノードか、という3層の関係をMaster編集画面上の階層表示で明示する。
    - 旧モデル由来の入力欄・バッジ・ステージ検索語を画面から除き、タイトル判定条件の編集箇所をNodeSelectorに一本化する。
  - **Interaction (インタラクション)**:
    - Master起点でVariantごとにRuleSet／NodeSelectorを選択・新規作成・編集できる。
    - 共有定義の編集保存時は参照元role一覧を示し「共有定義を更新」か「複製してこのVariantだけ変更」を選ばせる。
    - 登録済みワークフローを選び、未保存の編集内容で判定結果（段階・候補・確定ノード・入力名・警告）をプレビューする。保存済みデータは変更しない。
    - モバイル（ボトムシート）でもデスクトップと同等の編集操作を行える。
  - **Visual (視覚デザイン)**:
    - 一覧カードのバッジを新構造（Variant数等）を表す表示に置き換える。
    - プレビューでは段階（完全一致／部分一致／セレクタなし）と警告（duplicated／not_found）を区別して表示する。
- **Requirement**:
  - **1. Master編集画面の再構成（Master起点）**:
    - Master単位ではMasterの値定義（名称・入力型など）のみを編集し、旧モデルの判定入力欄（対象クラス一覧、param_name、fallback_param_names、title_patterns 等）を表示しない。
    - ステージ（`StageMaster.sort_order` 順）ごとのVariant行に、role（読み取り専用）、有効状態、参照RuleSetとそのEntry（class_type × param_name、priority順）、参照NodeSelectorとそのパターン（exact／contains、priority順。未設定は「セレクタなし」）を表示する。
    - Variant行からRuleSet／NodeSelectorの選択切替・新規作成・編集ができる。
    - 一意性制約（同一Master内の同一ステージ重複、同一Master内の同一NodeSelector重複）に反する編集は、保存前に該当Variant行へエラーを示し保存しない。NodeSelector未設定（セレクタなし）のVariantは同一Master内で複数共存できる（REQ-417 AC-7）。
  - **2. 共有定義の編集時の影響確認**:
    - 他のroleからも参照されているRuleSet／NodeSelectorを編集して保存する際、参照元role一覧を表示し、「共有定義を更新」または「複製してこのVariantだけ変更」を選択させる。選択するまで保存しない。
  - **3. Settings一覧表示の更新**:
    - MappingMaster一覧カードから旧概念のバッジ（`+N classes` 等）を除き、Variant数など新構造を表すバッジを表示する。
  - **4. ステージ管理の整理**:
    - ステージ管理画面からスキャンのタイトル判定に使う検索語（`search_keywords`）の入力欄を除き、ノード判定のタイトル条件はNodeSelectorでのみ編集できるようにする。
  - **5. 判定プレビュー**:
    - Master編集画面から登録済みワークフローを1件選び、編集中（未保存を含む）の定義でスキャン判定を実行した結果を、Variantごとに表示する（確定ノードID・ノードタイトル・input_name・判定段階・候補一覧・duplicated／not_found 警告）。
    - プレビューは保存済みのマッピング定義・ワークフローマッピング・スロット状態を一切変更しない。
  - **6. モバイル同等性**:
    - 画面幅768px未満ではボトムシート表示とし、要件1・2・5の操作をデスクトップと同等に行える。UI 6大ハード不変条件（SPEC_COMMON §1-5）を満たす。
  - **7. 一括保存（部分反映なし）**:
    - Master編集画面の1回の保存操作（Master値定義、Variantの定義切替・有効状態、共有定義の更新または複製）は、すべて反映されるか、まったく反映されないかのどちらかとする。途中で失敗した場合はエラーを表示し、編集内容を画面に保持する（2026-11-07 設計レビューでのユーザー決定）。
  - **8. 判定・候補・ステージ検出の3層定義への一本化**:
    - スキャン判定、判定プレビュー、ワークフロー登録・リマッピング・配線画面の候補順位付けとステージ自動検出は、RuleSetのEntryとNodeSelectorのパターンだけに基づいて行い、旧フィールド（`StageMaster.search_keywords`、Masterの `expected_class_types`／`param_name`／`fallback_param_names`／`title_patterns` 等）を判定に使わない（2026-11-07 設計レビューでのユーザー決定）。保存済みマッピングへの値注入（`seedBatch`／`seedInputResolver`／`workflowParamInjector`）は本PBIの範囲外とする。
- **Acceptance criteria**:
  - [ ] AC-1: Given 3層構造のMasterが登録されている状態で, When Settingsから当該Masterの編集画面を開いたとき, Then Master単位の入力欄として対象クラス一覧・param_name・fallback_param_names・title_patterns が表示されず、Master単位で編集できる項目は名称・入力型などMasterの値定義のみであること
  - [ ] AC-2: Given 2つ以上のステージにVariantを持つMasterがある状態で, When そのMasterの編集画面を開いたとき, Then Variant行がStageMaster.sort_order順に並び、各行にrole（編集不可）、有効状態、参照RuleSet名とそのEntry（class_type と param_name の組、priority順）、参照NodeSelector名とそのパターン（exact／contains の区別、priority順）が表示され、NodeSelector未設定のVariantには「セレクタなし」と表示されること
  - [ ] AC-3: Given Master編集画面でVariant行を操作できる状態で, When あるVariantの参照RuleSetまたはNodeSelectorを別の既存定義へ切り替える、または新規作成した定義を割り当てて保存したとき, Then 編集画面を開き直すと当該Variant行に切替後の定義名とEntry／パターンが表示され、他のVariantの参照先は変わっていないこと
  - [ ] AC-4: Given 2つ以上のroleから参照されているRuleSetまたはNodeSelectorがある状態で, When Master編集画面からその定義の内容を変更して保存操作を行ったとき, Then 参照元role一覧と「共有定義を更新」「複製してこのVariantだけ変更」の選択肢が表示され、いずれかを選ぶまで保存されないこと
  - [ ] AC-5: Given AC-4の選択が表示された状態で, When 「複製してこのVariantだけ変更」を選んだとき, Then 変更内容を持つ新しい定義が作成されて編集中のVariantだけがそれを参照し、他の参照元roleが参照する元の定義の内容は変わらないこと。また「共有定義を更新」を選んだときは、すべての参照元roleの編集画面で変更後の内容が表示されること
  - [ ] AC-6: Given Master編集画面で、同じMaster内の別Variantと同一のステージ、または同一の（未設定以外の）NodeSelectorを指定する編集をした状態で, When 保存操作を行ったとき, Then 該当Variant行にエラーが表示され、保存は行われず保存済みの定義が変化しないこと。ただし「セレクタなし」（NodeSelector未設定）のVariantは同一Master内で複数あってもエラーとならず保存できること
  - [ ] AC-7: Given Settingsのワークフロータブを表示している状態で, When MappingMaster一覧が描画されたとき, Then 各カードに `+N classes` バッジが表示されず、そのMasterのVariant数を示すバッジが表示されること
  - [ ] AC-8: Given ステージ管理画面を開いた状態で, When ステージの作成・編集フォームを表示したとき, Then スキャンのタイトル判定用の検索語（search_keywords）入力欄が表示されず、Master編集画面のNodeSelector以外にタイトル判定条件を入力できる画面要素が存在しないこと
  - [ ] AC-9: Given 登録済みワークフローが1件以上ありMaster編集画面で未保存の変更がある状態で, When 判定プレビューで登録済みワークフローを選んで実行したとき, Then 未保存の変更を反映した判定結果としてVariantごとに確定ノードID・ノードタイトル・input_name・判定段階（完全一致／部分一致／セレクタなし）・候補一覧が表示され、候補が複数で確定できない場合は duplicated、候補がない場合は not_found の警告が表示されること。また、同じMasterの別Variantのセレクタにのみ一致するノード（REQ-417の段階4）は、そのVariantの確定ノードにも候補一覧にも表示されないこと
  - [ ] AC-10: Given AC-9の判定プレビューを実行する前後で, When マッピング定義（Master／Variant／RuleSet／NodeSelector）・ワークフローマッピング・mapping_slot_states を取得して比較したとき, Then プレビュー実行によってそれらの保存内容が一切変化していないこと
  - [ ] AC-11: Given 画面幅375pxのモバイル表示で, When Master編集画面を開き、AC-3のVariant定義切替、AC-4・AC-5の共有定義の選択、AC-9の判定プレビューを操作したとき, Then 編集画面はボトムシートで表示され、各操作がデスクトップと同じ結果で完了し、操作対象のタップ領域が44×44px以上でページ全体の横スクロールが発生しないこと
  - [ ] AC-12: Given Master編集画面でMaster値定義の変更、2つ以上のVariantの定義切替、および共有定義の「共有定義を更新」または「複製してこのVariantだけ変更」を含む編集をした状態で, When 保存操作の処理途中で失敗が発生したとき, Then エラーが表示されて編集内容が画面に保持され、Master・Variant・RuleSet・NodeSelectorの保存内容が保存操作前と完全に一致し（「複製してこのVariantだけ変更」による新しい定義は保存操作の中で作成されるため、失敗時には残っていない）、失敗が発生しない場合はそれらの変更すべてが1回の保存操作で反映されていること
  - [ ] AC-13: Given NodeSelector未設定のVariantを持つMasterがあり、ワークフローに (a) Masterの旧フィールド（expected_class_types／fallback_param_names）には一致するがRuleSetのどのEntry（class_type と param_name の組）にも一致しないノードと、(b) RuleSetのEntryに一致し、タイトルがステージの search_keywords または旧 title_patterns にだけ一致する（NodeSelectorのパターンには一致しない）ノードが含まれる状態で, When そのワークフローに対してスキャン、判定プレビュー、ワークフロー登録・リマッピング・配線画面の候補表示、およびステージ自動検出を行ったとき, Then (a) のノードは確定ノード・推奨候補・検出ステージのいずれにもならず、(b) のノードはREQ-417の段階3（セレクタなし）として扱われ、search_keywords や旧 title_patterns への一致によって判定段階・候補順位・検出ステージが変わらないこと
- **Inferred points**:
  - role は REQ-417 で永続化・一意化された値であり、本PBIでは表示のみとし編集機能は追加しない（利用者が要望しなかったため）。
  - `StageMaster.search_keywords` は REQ-417 で NodeSelector の contains パターンへ移行済みとみなし、本PBIでは入力欄を画面から除く。設計で、スキャン処理とフロントの候補・ステージ検出が現在も旧フィールドを参照していることを確認したため、要件8・AC-13により判定への使用を廃止する。DB列の削除は本PBIの必須範囲としない。
  - 判定プレビューは登録済みワークフローのみを対象とし、未登録ワークフローJSONの貼付け・読込は範囲外とする。未保存の定義でスキャンを試行する手段（非永続のdry-run API等）の要否と方式は設計で決める。
  - 共有定義の一覧管理画面（定義ライブラリ起点の画面）は本PBIの範囲外とする。共有定義の更新はMaster編集画面からの「共有定義を更新」で行う。
  - SPEC_SETTINGS.md §4-1 の MappingMaster データモデル記述は旧構造のままであり、本PBIのクローズ時に3層構造と新UIに合わせて同期する。
  - 判定の段階4（他Variantのセレクタにのみ一致）は除外扱いのため、プレビューでは確定・候補として表示しない。
