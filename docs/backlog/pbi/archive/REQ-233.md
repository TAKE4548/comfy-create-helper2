### REQ-233: server-manager: ComfyUIポート開放待ちタイムアウトのconfig化とリトライ機構の導入
- **Type**: bugfix / enhancement
- **Status**: done (2026-09-09)
- **Current step**: Phase 3: Walkthrough & SSoT Sync
- **Priority**: P2
- **Surface**:
  - `tools/server-manager/server-manager.ps1`: `Wait-For-Port` 関数および各サービス起動・再起動時の呼び出し箇所で、待機タイムアウト時間 `10` 秒がハードコードされている。
  - `tools/server-manager/config.json`: ポート待機タイムアウト秒数やリトライ回数を定義するプロパティが存在しない。
- **Root Cause**:
  - ComfyUI の起動所要時間（PyTorch、CUDA/ROCm初期化、ノード読込等による10秒超過）に対する許容値の不足。
  - 待機時間がコード内にハードコードされており、環境差や負荷に応じた調整ができない。
  - 単一の待機ループのみで、失敗時のリトライ・再試行メカニズムが存在しないことによる堅牢性の欠如。
- **Requirement**:
  1. `config.json` において、サービス全体またはサービス個別（ComfyUI, Backend, Frontend）でポート待機タイムアウト（秒）およびリトライ回数・リトライ間隔を設定可能にする。
  2. `server-manager.ps1` の `Wait-For-Port` において、`config.json` の設定値を反映し、タイムアウト時に指定回数リトライを試みる堅牢な待機処理を実装する。
  3. 各起動・再起動呼び出し箇所（`Start-AllServices`, `Restart-ServiceByName`, 各サービス単体 `start`）でハードコードされた `10` を撤廃し、設定駆動とする。
  4. Web Manager（`server_api.py`）経由での起動・ステータス更新においても正常に動作することを確認する。
- **Acceptance criteria**:
  - [x] AC-1: `config.json` で ComfyUI を含む各サービス（または全体共通）のポート待機タイムアウト秒数とリトライ回数が指定可能であること。
  - [x] AC-2: `server-manager.ps1` のポート待機処理が `config.json` のタイムアウト・リトライ設定に従って動作し、10秒以上かかる起動でも適切に待機・判定できること。
  - [x] AC-3: 初回待機でポート未開放だった場合でも、設定された回数のリトライが行われ、途中でポート開放が検知された場合は正常に起動完了（LISTEN）と判定されること。
  - [x] AC-4: 設定ファイルに項目が存在しない場合でも、適切なデフォルト値（後方互換性）で安全に動作すること。
  - [x] AC-5: `server-manager.ps1` の CLI メニュー、個別起動コマンド、Web Manager UI からの起動操作で正常に動作すること。
