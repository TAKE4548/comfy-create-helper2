### REQ-283: ProfileBulkEditModal のドメイン計算分離と 2 タブ階層化・セクション化

- **Type**: refactoring
- **Status**: done (2026-09-25)
- **Current step**: none
- **Priority**: P2
- **Surface**: 複数プリセットの一括編集モーダル（ProfileBulkEditModal.tsx, 1,338行）に、タグ重み計算、2タブUI（共通タグ調整・LoRAスタック・型別入力）、確認ダイアログがすべて同居しており、保守性およびテストが著しく困難になっている（リファクタ計画 PBI-REF-02）。
- **Root Cause**: 純粋なドメイン計算ロジック（タグ重みパース・共通タグ抽出など）とモーダル枠・タブUI・各入力フィールドのJSXレンダリングが1つの巨大コンポーネントに混載されていること。
- **Requirement**:
  - 純粋計算関数（タグ重みパース、共通タグ・LoRA計算）を `utils.ts` へ外出しし単体テストを作成する。
  - Prompt編集タブとParam編集タブを独立ディレクトリへ階層化し、各UIセクション（共通タグ、LoRAスタック、パラメータ制御）を部品化する。
  - 1ファイルあたりの最大行数を250行以下に抑制する。
  - 【目標構成】:
    ```
    frontend/src/components/ProfileBulkEditModal/
    ├─ index.tsx                  # モーダル枠・タブ切替・フッター（約150行）
    ├─ types.ts                   # BulkEditPayload 等の型定義
    ├─ utils.ts                   # タグ重みパース・共通タグ/LoRA計算純粋関数
    ├─ BulkEditConfirmView.tsx    # 反映前の確認プレビュー画面（約50行）
    └─ tabs/
       ├─ PromptBulkEditTab/
       │  ├─ index.tsx               # Promptタブ統合（約80行）
       │  ├─ CommonTagsSection.tsx   # 共通タグチップ表示・強度/削除調整（約120行）
       │  ├─ PromptOperationForm.tsx # 検索置換 / 追加 / 上書きフォーム（約100行）
       │  └─ TargetFieldsSelector.tsx# 対象フィールド（positive等）選択（約40行）
       └─ ParamBulkEditTab/
          ├─ index.tsx               # Paramsタブ統合（約90行）
          ├─ LoraStackSection.tsx    # LoRAスタック（差分/上書き）（約230行）
          ├─ ParamFieldControl.tsx   # 型別パラメータ行（約140行）
          └─ BatchSizeSection.tsx    # バッチ数設定（約35行）
    ```
- **Acceptance criteria**:
  - [x] AC-1: 検索置換、共通タグ強度変更・削除、LoRAスタック差分編集、パラメータパッチの一括適用が正常動作すること。
  - [x] AC-2: `utils.ts` のタグパース・共通計算に対する単体テスト（Vitest）が作成され 100% PASS すること。
  - [x] AC-3: 1ファイルあたりの最大行数が 250 行以下に抑制されること。
  - [x] AC-4: `cd frontend && npm run typecheck`（tsc -b --noEmit）がエラー0件でPASSすること（REQ-001の型検査Gate 1）。
  - [x] AC-5: `cd frontend && npx vitest run` で既存テストが全件PASSすること。
