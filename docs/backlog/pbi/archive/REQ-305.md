### REQ-305: デスクトップ生成画面におけるグローバルヘッダー全幅昇格および左ペインツールバー順序整理

- **Type**: improvement
- **Status**: done (2026-10-02)
- **Current step**: none
- **Priority**: P2
- **UX Classification**:
  - **Information Design**: 画面全体の垂直構造の適正化。左ペイン内に取り残されていた本来のヘッダー（Generateタイトル・ワークフロー選択等）を画面最上部（全幅）へ昇格させ、①Global Header → ②Full-Width Preset Tabs Bar → ③左右2ペイン（左: ツールバー＋入力、右: プレビュー）の直感的な情報階層を確立。
  - **Interaction Design**: ワークフロー選択等のシステム全体設定を最上部ヘッダーへ配置し、左ペイン最上部にはプリセット操作群を「プリセット名 → Undo/Redo → Add Set → 管理」の順序で左寄せ連続配置（justify-start）。視線・マウス移動の無駄を排除した一貫した操作導線を実現。
  - **Visual Design**: 全幅ヘッダー・全幅タブバー・左右2ペインの境界線（border-b）と背景トーンの統一。各バーの高さ（ヘッダー約48px、タブバー約40px、左ペインツールバー約40px）をコンパクトに保ち、コンテンツ領域の有効高さを最大限保護。ドロップダウンやモーダルが埋もれないz-indexスタッキングの確立。
- **Surface**:
  - 現状のデスクトップ生成画面において、プリセットタブバーのみが全幅で画面最上部に配置されており、本来のヘッダー（「Generate」タイトル、ワークフロー選択プルダウン、Settingsボタン等）が左ペインのトップに残ってしまっている。
  - このため、画面の最上部にタブバーが来て、その下の左ペインの中にタイトルやワークフロー選択があるという、構造的・視覚的に不自然な逆転現象が生じている。
  - 本来あるべき画面構造として、最上部に「Generate」タイトル等を含むヘッダーを画面全幅で配置し、その直下に全幅のプリセットタブバーを配置したい。
  - さらに、その直下の左右2ペインのうち、左ペインの最上部ツールバー内の操作ボタンについて、左から順に「プリセット名」「Undo/Redo」「Add Set」「管理」の順序で左寄せ連続配置したい。
- **5 Whys Analysis**:
  1. *Why*: 現在の画面レイアウトで違和感があるのはなぜか？
     → タブバーだけが全幅で画面最上部にあり、本来の画面全体のヘッダー（Generateタイトルやワークフロー選択）が左ペインの内部に押し込められているため。
  2. *Why*: なぜそのような不自然な逆転が起きていたのか？
     → REQ-300においてプリセットタブバーを親階層に昇格させた際、既存のヘッダー要素が左ペインの内部に残存したままになっていたため。
  3. *Why*: 本来あるべき階層はどうあるべきか？
     → 最上部に画面全体のグローバルヘッダー（タイトル・ワークフロー・接続状態）、その直下に画面全体のプリセットタブ一覧（全幅）、その下に左右ペイン（左: 各プリセットの編集・操作、右: プレビュー）というトップダウンの構造であるべき。
  4. *Why*: 左ペインのツールバー内の並び順はどうあるべきか？
     → 「現在のプリセット名」→「その内容に対する直前復元（Undo/Redo）」→「新規セット追加（Add Set）」→「プリセット全体管理（管理）」という、対象のスコープが自然に広がる左寄せの順序であるべき。
  5. *Why*: 根本原因（Root Cause）は何か？
     → 【Information Design】グローバルヘッダー要素が左右スプリットペインの子要素（左ペイン）内に誤って閉じ込められていたこと。【Interaction Design】左ペインツールバーの要素が左右両端に分散し、自然な左寄せの操作順序になっていなかったこと。

  - デスクトップ生成画面（DesktopLayout）において、左ペイン内部に含まれていたグローバルヘッダー要素（「Generate」タイトル、接続インジケーター、ワークフロー選択プルダウン #workflow-select、Anima特化トグル #anima-mode-toggle、Settingsボタン #settings-toggle-btn）を画面最上部の独立した親コンテナ（画面全幅 100%、
elative z-20 flex-shrink-0）へ移動・配置すること。
  - プリセットタブ一覧（#desktop-preset-tabs-bar）は、画面最上部のグローバルヘッダー直下、かつ左右2ペイン（ResizableSplitLayout）の直上の位置に画面全幅（

  - 左ペイン最上部のツールバー（#left-pane-toolbar）において、justify-between を廃止して左寄せ配置（justify-start、lex-nowrap、gap-2）とし、以下の順序で要素を配置すること：
    1. アクティブプリセット名表示バッジ（ctiveSet 存在時、max-w-[110px] truncate）
    2. Undo / Redo ボタングループ（#undo-btn, #redo-btn、ctiveSet 存在時、lex-shrink-0）
    3. Add Set ボタン（#add-set-btn、lex-shrink-0）
    4. プリセット管理ボタン（#manage-presets-btn、lex-shrink-0）
  - 各種コントロール（ワークフロー選択、接続状態、Settings、タブ切り替え、Undo/Redo、Add Set、管理モーダル等）の既存機能・コールバック・テストID・イベントハンドラーが完全に維持されること。
  - 各上部固定バー（ヘッダー・タブバー）には lex-shrink-0、スプリット領域には lex-1 min-h-0 overflow-hidden を適用し、不要な二重スクロールバーやコンテンツ領域の押し出されを防止すること。
  - モバイルレイアウト（MobileLayout）には影響を与えず、既存の構成・操作性を維持すること。
- **Acceptance criteria**:
  - [ ] AC-1 (グローバルヘッダーの画面最上部全幅配置):
    - **Given**: デスクトップ生成画面（DesktopLayout）が表示されている。
    - **When**: 画面最上部のヘッダー配置と内容を確認する。
    - **Then**: 左ペイン内ではなく画面最上部全体（全幅100%）にグローバルヘッダーが配置され、「Generate」タイトル、接続インジケーター、ワークフロー選択（#workflow-select）、Settingsボタン（#settings-toggle-btn）等が描画されている。
  - [ ] AC-2 (プリセットタブバーの全幅・ヘッダー直下配置):
    - **Given**: ワークフローが選択され、1つ以上のプリセットタブが存在する状態。
    - **When**: プリセットタブバー（#desktop-preset-tabs-bar）の配置位置を確認する。
    - **Then**: 画面最上部ヘッダーの直下、かつ左右2ペイン（ResizableSplitLayout）の直上に画面全幅で配置され、多数のタブが存在する場合はタブバー固有の横スクロール（overflow-x: auto）で移動可能である。
  - [ ] AC-3 (左ペインツールバーの左寄せ連続配置と順序):
    - **Given**: 左ペインが表示され、プリセットが選択されている状態。
    - **When**: 左ペイン最上部ツールバー（#left-pane-toolbar）内の要素配置を確認する。
    - **Then**: 左から順に、①プリセット名バッジ、②Undo/Redoボタングループ、③「Add Set」ボタン、④「管理」ボタンの順序で左寄せに連続配置（justify-start）されている。
  - [ ] AC-4 (リサイズ時の近接維持と折り返し防止):
    - **Given**: デスクトップ生成画面が表示されている。
    - **When**: 左ペイン幅を広げる（420pxから600px以上へ変更）、または最小幅（380px）へ縮小する。
    - **Then**: 左ペインツールバー内の各ボタンが右端へ引き離されずUndo/Redoに隣接した位置（gap-2）を維持し、縮小時にもボタン群が2段に折り返されることなく横一列の配置が保たれる。
  - [ ] AC-5 (各ボタン・機能の完全維持と未選択時安全性・重なり順序):
    - **Given**: 新レイアウトが適用されたデスクトップ生成画面。
    - **When**: ワークフロー選択、タブ切り替え、Undo/Redo、Add Set、管理モーダル起動、Settingsポップオーバー開閉を検証する。
    - **Then**: すべての既存コールバックとモーダルが正常に動作し、ドロップダウンやモーダルがヘッダーやタブバーによって隠蔽されず、activeSet が未選択の場合でもクラッシュすることなく安全にAdd Setおよび管理ボタンがクリック可能である。
  - [ ] AC-6 (モバイルレイアウト非干渉):
    - **Given**: モバイル画面幅（MobileLayout）で表示する。
    - **When**: モバイル画面のヘッダー・タブ・操作バーを確認する。
    - **Then**: デスクトップ専用の全幅ヘッダー昇格およびツールバー順序変更による影響を受けず、モバイル専用UIが維持される。
  - [ ] AC-7 (品質検証 - 型安全性とテスト通過):
    - **Given**: 実装完了後のリポジトリ。
    - **When**: cd frontend; npm run typecheck および npm test を実行する。
    - **Then**: 型チェックエラーおよびテスト失敗が0件である。
- **Inferred points & Assumptions**:
  - 本来のヘッダー要素（タイトル、ワークフロー選択、接続状態、Settings）を左ペインからルート全幅ヘッダーへ完全に移動し、左右2ペインの親コンテナより上位に配置する。
  - 全体の垂直順序は「最上部ヘッダー（全幅）」→「プリセットタブバー（全幅）」→「左右2ペイン（左ペイントップにプリセット名・Undo/Redo・Add Set・管理）」となる。
