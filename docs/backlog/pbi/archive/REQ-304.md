### REQ-304: FuguMT軽量和訳エンジン導入とドラッガブルタグチップ和訳プレビュー

- **Type**: feature
- **Status**: done (2026-10-02)
- **Current step**: none
- **Priority**: P2
- **UX Classification**:
  - **Information Design**: タグチップサブメニューにおける和訳アクションの整理、個別タグおよび自然文プロンプトの和訳情報提示、長文訳文の独立スクロールおよびコピーインターフェース、入力文字列正規化によるキャッシュ効率化
  - **Interaction**: サブメニュー内「翻訳」ボタンによる和訳プレビューの開閉、Pointer Eventsによるヘッダー掴みドラッグ移動（モバイル時ページスクロール抑止）、ビューポート境界内への移動クランプ、本文スクロールとヘッダードラッグの操作分離、エラー/タイムアウト時の適切な状態通知、複合トリガーによるカードクローズ
  - **Visual**: サブメニュー幅の360pxへの拡張（モバイル時ビューポート制限対応）、フローティング和訳カードの階層表現・ドラッグハンドル表示・ダークテーマ調和
- **Surface**:
  - プロンプトの翻訳において、従来のローカルLLM（LM Studio経由等）ではモデルのロード待機時間（コールドスタート）や、画像生成（ComfyUI / Anima等）実行時のVRAM競合・アンロード遅延が大きなボトルネックとなっていた。
  - プロンプト入力・編集時にタグや情景描写の意味を日本語で素早く確認したいが、画像生成処理（GPU / VRAM）を一切阻害せずにCPU常駐・ミリ秒単位で高速に応答する和訳手段が存在しない。
  - 特にAnimaなどの自然言語指向モデルでは長文の情景タグが増加しており、従来の狭いサブメニュー（min-w-[220px]）では情報が窮屈であり、訳文が長文になってもプロンプト編集を妨げず自由に動かせるドラッガブルな和訳プレビューが求められている。
- **Root Cause**:
  - **Information Design (和訳提示領域とサブメニュー構造の制約)**:
    - 従来のタグサブメニュー幅が狭く、自然文タグや翻訳結果を表示する領域設計になっておらず、タグの意味を確認するための情報導線が欠如していた。
  - **Interaction Design (固定ポップオーバーによる視認性阻害とドラッグ操作の欠如)**:
    - 固定配置のツールチップやメニューでは、訳文確認時に背後のタグやプロンプト入力欄が隠れてしまい、PCマウスとモバイルタッチの双方で自由に退避・移動できるドラッグ機構がなかった。
  - **Architecture Constraint (GPUリソース競合)**:
    - 英日翻訳にLLMを用いていたため、画像生成側のComfyUIとVRAMを取り合い、翻訳実行によるモデルスワップや生成遅延が発生していた。
- **Requirement**:
  - **CPU常駐・低遅延の英日翻訳エンジン（FuguMT / CTranslate2）の導入**:
    - バックエンド側で staka/fugumt-en-ja（CTranslate2 int8形式）を利用したCPU常駐型の高速和訳エンジンを構築し、ComfyUIのGPU VRAMを一切消費（0MB）せずにミリ秒単位（20〜30ms目標）で英日翻訳を提供すること。
    - 翻訳API（POST /api/translate/prompt）において、単一タグ・自然文フレーズ・プロンプト全体の翻訳に対応し、入力文字列の正規化（前後の空白トリム等）を行ってからインメモリキャッシュ（SHA256ハッシュキー）を照会・格納することで重複翻訳を防止すること。未キャッシュ部分の一括バッチ翻訳をサポートし、既存APIとの後方互換性を100%維持すること。
    - 翻訳処理のタイムアウトや例外発生時にもAPIおよびUIがクラッシュせず、適切なエラーメッセージまたはフォールバックを返却すること。
  - **タグチップサブメニューの幅拡張**:
    - タグチップをクリックして開くサブメニューの幅を、従来の狭い幅（min-w-[220px]）から w-[360px]（画面幅超過防止のため最大幅 max-w-[calc(100vw-24px)]）へ拡張し、タグ名入力欄とアクションボタン群をゆったり操作できるようにすること。
    - サブメニューヘッダーに、タグ名入力欄と並んで和訳プレビューを開くための [翻訳] ボタンを配置すること。
  - **ドラッガブル・フローティング和訳カード（TagChipTranslationCard）の実装**:
    - サブメニューの [翻訳] ボタン押下により、サブメニュー直下（画面下部にはみ出す場合は直上）に独立したフローティング和訳カードを表示すること。
    - ヘッダー（タイトルバー）をドラッグハンドルとし、Pointer Events（onPointerDown, onPointerMove, setPointerCapture 等）を用いてPCマウスドラッグとモバイルタッチドラッグの双方で滑らかにカードを任意位置へ移動できること。
    - ヘッダー部にはドラッグ専用スタイル（touch-action: none 等）を適用してモバイルでの背面スクロール誤発火を抑止し、訳文本文領域ではテキスト選択や縦スクロールがドラッグと干渉せずに独立して行えること。
    - カードが画面外へ見失われないよう、移動可能範囲をビューポート境界（上下左右）内にクランプすること。
    - 訳文の1クリッククリップボードコピー機能とコピー完了フィードバックを提供すること。
    - 閉じるボタン [✕]、Escキー押下、カード外クリック、親サブメニューを閉じた際の連動によりカードがスムーズに閉じること。
- **Acceptance criteria**:
  - [ ] AC-1: Given: バックエンドサーバーが起動している / When: POST /api/translate/prompt に英語の単語、自然文フレーズ、またはプロンプトが送信された / Then: GPU VRAMを消費することなくCPU常駐エンジン（CTranslate2 / FuguMT）により日本語訳が返却され、入力文字列正規化後の同一ハッシュに対する再リクエスト時はインメモリキャッシュから即時返却されること。
  - [ ] AC-2: Given: タグチップエディタ上で任意のタグチップをクリックした / When: タグチップサブメニューが表示された / Then: サブメニューの横幅が360px（モバイル時は calc(100vw - 24px) を上限）で表示され、ヘッダー行にタグ名入力欄と [翻訳] ボタンが配置されていること。
  - [ ] AC-3: Given: タグチップサブメニューが開いている / When: ユーザーが [翻訳] ボタンをクリックした / Then: フローティング和訳カード（TagChipTranslationCard）が表示され、翻訳取得中はローディング表示、取得完了後はタグの日本語訳が表示されること。
  - [ ] AC-4: Given: 翻訳APIでエラーまたはタイムアウトが発生した / When: フローティング和訳カードが結果を取得しようとした / Then: アプリケーションがクラッシュすることなく、カード内にエラー状態が表示されること。
  - [ ] AC-5: Given: フローティング和訳カードが表示されている / When: ユーザーがカードのヘッダー領域をマウスまたはタッチ操作でドラッグした / Then: ポインタに追従してカードが移動し、画面端（上下左右）で適切にクランプされビューポート外に飛び出さず、タッチ端末で不要なページスクロールが発生しないこと。
  - [ ] AC-6: Given: 長文の自然文タグに対する和訳が表示されている / When: ユーザーが訳文本文領域でスクロールまたはテキスト選択を行った / Then: カードのドラッグ移動が誤発火せず、本文領域の縦スクロールとテキスト選択が正常に行えること。
  - [ ] AC-7: Given: フローティング和訳カードに日本語訳が表示されている / When: ユーザーがカード内のコピーボタンをクリックした / Then: 訳文テキストがクリップボードにコピーされ、コピー完了を示す視覚的フィードバック（チェックマーク等）が一時表示されること。
  - [ ] AC-8: Given: フローティング和訳カードが表示されている / When: ユーザーがカードの [✕] ボタンをクリックするか、Escキーを押下するか、カード外領域をクリックするか、または親サブメニューを閉じた / Then: フローティング和訳カードが即座に閉じられること。
- **Inferred points & Assumptions**:
  - staka/fugumt-en-ja モデルデータは初回実行時またはセットアップ時に所定のローカルディレクトリに配置され、推論スレッド数はCPUコア構成（Intel Core i5-13400FのPコア数に合わせた intra_threads=6 推奨）に最適化される。
  - 既存のプロンプト全文和訳（usePromptTranslation）も同一のバックエンド翻訳エンドポイント（POST /api/translate/prompt）を利用可能であり、タグ単位の和訳と全体和訳でキャッシュを共有できる。
  - 日⇒英のプロンプト生成・タグ化はLLM側の役割として維持し、本機能の軽量翻訳エンジンは英⇒日のタグ・プロンプト意味確認を用途とする。
