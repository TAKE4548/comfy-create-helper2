# REQ-164: 複数セッション間における生成進捗・キュー情報・生成履歴の同期および可視化の改善

- **Type**: defect
- **Status**: done (2026-08-30)
- **Priority**: P1
- **Surface**:
  - 他セッション（例: PC）で生成を実行中、別端末（例: モバイル）で「他セッションで生成中...」というバッジは表示されるものの、キュー数が0になり、プログレスバーが表示されず「Ready | 0%」のままとなる。
  - 他端末で生成されたバッチの生成画像がフィルムストリップ（履歴一覧）にリアルタイムで反映されず、明示的にリロードしても全件反映されない（偶発的に1〜2枚しか出ない）。
- **Root Cause**:
  1. `filterOwnSession: true`（自セッションのみ表示）が有効な場合、`totalQueueCount`（キュー数集計）、`isGeneratingHere`（プログレスバー描画フラグ）、`displayImages` / `fetchHistory`（履歴画像集計）がすべて自端末の `clientId` のみに絞り込まれ、他端末の実行中・待機中ジョブおよび生成完了画像が完全に除外される。
  2. ComfyUI WebSocket の仕様上、`progress`（ステップ進捗%）および `executed`（生成完了画像）イベントがジョブ投入元の `client_id` にのみ個別送信されるため、他端末の WebSocket では % 進捗が更新されず完了イベントも受信できない。
  3. `useGenerationStore.ts` の `reconcileState` がリロード時に実行中だった単一の `promptId` のみを取得するため、バッチ内の他のジョブが `filterOwnSession` で除外され、1〜2枚程度しか履歴に現れない。
  4. UIコンポーネント（`DesktopLayout` / `MobileLayout`）が自セッション生成中と完全アイドルの2値しか想定しておらず、他セッション生成中の進捗（実行中ノード、全体キュー数）を表示するステート設計が不足している。
- **Requirement**:
  - 他セッションでジョブが実行・待機中である場合、別端末の画面上でも全体キュー数（Running + Pending）および実行中のノード情報が明確に表示されること。
  - 他セッションで生成完了したバッチ画像が、リアルタイムまたはリロード/ポーリング時にフィルムストリップ（履歴一覧）へ確実に全件反映・表示されること。
  - 自セッションフィルタ（`filterOwnSession`）が有効であっても、他セッションの稼働状況や全体キューが把握でき、必要に応じて全セッション履歴へ容易に切り替えまたは同期されること。
- **Acceptance criteria**:
  - AC-1: PCからバッチジョブを投入中、同一ComfyUIに接続しているモバイル端末上で、実行中・待機中のジョブ数（全体キュー数）が正確に表示されること。
  - AC-2: 他セッション生成中（`isGenerating && activeClientId !== clientId`）において、モバイル端末のプログレス領域に実行中ノード（`currentNode`）および他セッション生成中である旨のステータスが表示されること。
  - AC-3: 他セッションで生成完了した画像が、リアルタイム（WebSocket `status` / `executing` 契機等の `fetchHistory` 連携）またはページリロード時に、モバイル側のフィルムストリップ（履歴一覧）に漏れなく全件反映されること。
  - AC-4: 自セッションフィルタ（`filterOwnSession`）のON/OFF切り替えが正しく機能し、OFF時は全セッションのキューおよび履歴画像が表示され、ON時でも他セッションの稼働状況が完全に隠蔽されず適切に案内・表示されること。
