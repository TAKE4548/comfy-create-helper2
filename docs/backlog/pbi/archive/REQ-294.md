### REQ-294: Prompt Surgeon 2系統参照型セリフ生成 UI完全統合 & バックエンド更新

- **Type**: enhancement
- **Status**: done (2026-09-29)
- **Current step**: none
- **Priority**: P1
- **Surface**:
  1. セリフ付与のトリガ後、進捗状況が見えず、エラー停止すら判別できない
  2. Rev16設計書の同キャラ候補「類似度 高・中・低」分散抽出ルールが未反映
  3. 現状ボタンのみで、仕様書(v3.7)に定義された全モーダルステートが未実装
- **Root Cause**:
  - REQ-291 Rev.16（詳細設計書）が確定しているにもかかわらず、それに対応するUI（シーン一括生成モーダルの4ステート）とバックエンド（高・中・低分散抽出アルゴリズム / リファレンススイッチ API / VLM画像圧縮）が実装されていない。
  - ユーザーは✨ボタン押下後の処理フローを一切視認できないため、処理中なのか・エラーなのか・完了しているのかを区別できない（Interaction Design欠落）。
- **Requirement**:
  - 詳細仕様書: tmp/Prompt_Surgeon_シーン一括生成_UI完全統合仕様書_v3_7_完全版_高中文選定＆リファレンススイッチ.html および tmp/REQ-291-Rev16_高中文選定＆リファレンススイッチ確定版.md を SSoT として、以下3フェーズで実装する。
  - T1 (Backend): 生PNG→1024px JPEG圧縮 / 400エラー透過 / 系統A高中低分散抽出(ToneSampleItem) / 系統BTop-3候補返却＆override再推論
  - T2 (Frontend Modal): PC/モバイル両対応 / 全4ステート(Progress/Onboarding/Error/Review) / 系統A・B UI表示 / モバイル全パラメータ設定
  - T3 (Frontend Hook): 並行オンボーディングRef同期 / モバイル完了後setActiveMobileTab('preview')自動発火
- **Acceptance criteria**:
  - [ ] AC-1 (進捗可視化): ✨ボタン押下後、State 1(プログレス)が即時表示され、各ステップ（参照抽出→VLM推論→スタイル割当→VRAM解放）の状態と経過秒数が確認できること
  - [ ] AC-2 (エラー可視化): LM Studio 400エラー / 接続拒否 / タイムアウト等のエラー発生時に State 1-Error が表示され、エラー種別・原因・再試行ボタンが提供されること
  - [ ] AC-3 (系統A 高中低): VLMレスポンスに tone_samples として similarity_tier が high / mid / low の各1件・計3件（異なるスナップショット）が含まれること
  - [ ] AC-4 (系統B Top-3 & スイッチ): candidate_similar_scenes に Top-3候補が返却され、2位/3位選択後の再生成リクエストで override_similar_scene_snapshot_id が正しく渡り、指定シーンで再推論されること
  - [ ] AC-5 (State 2 レビュー画面): セリフ/SE ごとにチェックボックスで選択し、選択分のみキャンバスへ反映できること（PC/モバイル両対応）
  - [ ] AC-6 (モバイル機能パリティ): モバイルのオンボーディング画面(State 1-Onboarding)でフォント・文字方向・配色3点・枠幅の全パラメータが設定可能なこと
  - [ ] AC-7 (モバイル自動タブ遷移): モバイルで生成完了後、自動的にプレビュータブへ切り替わること
  - [ ] AC-8 (3-Gate): Gate 1 typecheck / Gate 2 全テスト / Gate 3 手動確認がすべて PASS すること
