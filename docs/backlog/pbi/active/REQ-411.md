### REQ-411: プリセット管理および一括編集UIの適正化・ステージ情報表示

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: 生成画面（`GeneratePage`）のプリセット管理モーダル（`PresetManagerPanel`）、およびプリセット一括編集モーダル（`ProfileBulkEditModal`）のプロンプト一括編集タブ（`PromptBulkEditTab`）とパラメータ一括編集タブ（`ParamBulkEditTab`）。
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: パラメータ一括編集時に同名パラメータが複数ステージ（Base/Upscale等）に存在する場合にどのステージのものか判別できず誤設定リスクがあるほか、プリセット管理モーダルに使われない保存欄や操作しづらい導線が残り、プロンプト・共通タグの一括編集でも手戻り（引用不可・タグ編集不可・重複状況の把握困難）が発生して作業効率を損ねているため。
  2. なぜその課題が発生するか: パラメータ編集の表示ラベルにステージ所属情報が付与されておらず、プリセット管理側でも画面設定の上書き/別名保存が下部ドックに常駐し、複数選択モード切り替えも専用ボタンの手動トグルに依存しているため。さらに一括編集内の置換・追加・共通タグUIがプリセット群の実データを活かした設計になっていないため。
  3. なぜ現状の仕組みで不十分か: 複数ステージワークフローの普及に伴い同一パラメータ（steps, cfg, denoise等）の識別が不可欠となり、また日常のプリセット運用では画面全体設定ではなく既存プリセットの複製（クローン）が主用途であり、プロンプトの一括調整でも部分置換や重複タグの頻度別整理など高度なバッチ操作が求められているため。
  4. なぜこのアプローチを採用するか: パラメータにステージ名を表示し、不要な上書き欄を廃止して各行にコピー別名保存を配置、Ctrl/Shiftクリックやロングタップによる自動複数選択、生成用/一括操作用の全選択の明確な分離、置換文字列の引用、置換後タグの再編集、追加モードの統合、共通タグの重複頻度順グルーピングを導入することで、直感的かつ誤操作のない一貫したUXを実現できるため。
  5. 根本原因: プリセット管理と一括編集のUI設計が初期の単一ステージ・単発保存・固定一覧表示の前提で構成されており、複数ステージのワークフロー構成や、ユーザーの高速な探索・複製・段階的タグ置換の実運用ワークフローに最適化されていなかったため。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - パラメータ一括編集一覧において、各パラメータ名に所属ステージ名/ステージ情報を明記（例: `[Stage名] パラメータ名`）し、複数ステージで同名パラメータが存在しても一意に識別可能にする。
    - 共通タグ編集において、選択中のプリセット群におけるタグの重複度（出現頻度：例: 全N件共通、N-1件共通など）順にグルーピングしてタグ一覧を列挙し、どのプリセット群に多く含まれているかを視覚的に把握・選択可能にする。
    - 置換する文字列（検索対象）の入力欄において、選択されたプリセット群の既存プロンプトテキストから引用可能な候補一覧を提供し、プリセット名および対象フィールド（ポジティブ/ネガティブ/役割）による絞り込みを可能にする。
    - プリセット管理モーダルにおいて、「生成対象の全選択・全解除」と「複数選択（一括操作対象）の全選択・全解除」のラベルおよび表示エリアを明確に分離・区別する。
  - **Interaction Design (インタラクション)**:
    - プリセット管理モーダルの下部ドックから「現在の設定の上書き保存欄」を削除。
    - プリセット一覧の各行に「コピーして別名保存」アクションを配置し、クリック時に新規プリセット作成（AddPreset）フローを起動して対象プリセットの内容が事前設定された状態にする。
    - 「生成対象にする全選択・全解除」ボタンを下部ドックから一覧上部（またはアクセスしやすい近接位置）へ移動し、2つのボタンを隣接配置して素早くアクセスできるようにする。
    - 専用の複数選択ON/OFFボタンを廃止し、PCではCtrl+クリックまたはShift+クリック、モバイル・タッチではロングタップやドラッグにより自動的に複数選択モードへ遷移させる。解除は「×」ボタン等の明示的クローズ操作でシンプルに終了する。
    - 複数選択モード時に右端に追加されていたチェックボックスを廃止し、既存の枠線ハイライト（緑枠等）のみで選択状態を表現する。
    - 置換後の文字列において、確定してタグチップ化された文字列をクリック/タップして直接再編集できるようにする。
    - プロンプト一括編集のモードにおいて、「先頭に追加」「末尾に追加」を「追加」という1つの大項目に統合し、その内部で「先頭」または「末尾」を選択できるようにする。
  - **Visual Design (視覚デザイン)**:
    - プリセット管理モーダル下部ドックの整理とスリム化。
    - 複数選択状態の枠線ハイライトの視認性維持とチェックボックス削除による行レイアウトのシンプル化。
    - パラメータ一覧および共通タググルーピング一覧におけるバッジ・インデント・視覚階層の統一。
- **Requirement**:
  - **1. パラメータ一括編集のステージ情報明示**:
    - 複数ステージに同名パラメータが存在する場合でも、どのステージのパラメータかを判別できるようステージ情報をラベルまたはバッジで明示する。
  - **2. プリセット管理モーダルのUI適正化と導線整理**:
    - 不要な「現在の設定の上書き保存欄」を削除する。
    - 「別名で保存」は現在の画面設定からではなく、各プリセット行から直接複製できる「コピーして別名保存」アクションとして提供し、AddPresetの仕組みを流用してコピー元データが事前選択された状態で起動する。
    - 「生成対象にする全選択・全解除」ボタンを一覧上部のアクセスしやすい位置に互いに隣接して配置する。
    - 複数選択モードは専用ボタンでの手動トグルを廃止し、PCではCtrl/Shiftクリック、モバイルではロングタップやドラッグによる自動遷移とする。解除は「×」ボタンでシンプルに行い、選択状態は緑枠等の枠線ハイライトで視認できるため右端のチェックボックスは削除する。複数選択用の全選択・全解除と生成用の全選択・全解除が混同しないよう独立して配置する。
  - **3. 一括編集モーダルのプロンプト・共通タグ編集機能強化**:
    - 置換する文字列（検索対象）に、選択したプリセット群のプロンプト入力欄から文字列を引用できる候補ピッカーを設け、プリセットや対象フィールドで絞り込み可能にする。
    - 置換後の文字列でタグチップ化された後でも、クリック/タップから直接再編集できるようにする。
    - プロンプト編集の「先頭に追加」「末尾に追加」を「追加」大項目に統合し、内部で「先頭」か「末尾」かを選択できるようにする。
    - 共通タグ編集において、選択されたプリセット群の中で重複（出現頻度）が多い順にタグをグルーピングして列挙し、そこから選択・編集できるようにする。
- **Acceptance criteria**:
  - [ ] AC-1 (パラメータ一括編集におけるステージ情報表示):
    - **Given**: プリセット一括編集モーダルのパラメータ一括編集画面を開いている。
    - **When**: ワークフロー内の異なるステージに同一名称のパラメータ（例: Stage AのstepsとStage Bのsteps）が存在する状態でパラメータ一覧を表示する。
    - **Then**: 各パラメータ項目の表示ラベルに所属するステージ名またはステージ情報が付与され、どのステージのパラメータであるかが一意に識別できること。
  - [ ] AC-2 (プリセット管理モーダルの上書き保存欄削除):
    - **Given**: 生成画面でプリセット管理モーダルを開いている。
    - **When**: モーダル下部のアクションエリアを表示する。
    - **Then**: 「現在の設定の上書き保存」関連の入力欄および保存ボタンが存在しないこと。
  - [ ] AC-3 (各プリセット行からのコピー別名保存):
    - **Given**: プリセット管理モーダルのプリセット一覧にプリセット行が表示されている。
    - **When**: 特定のプリセット行の「コピーして別名保存」操作（行内アクションボタン等）を実行する。
    - **Then**: プリセット作成フローが起動し、対象プリセットのパラメータ・プロンプト設定が複製元として事前適用された状態で新規別名保存ダイアログが開くこと。
  - [ ] AC-4 (生成対象の全選択・全解除ボタンの再配置・近接化):
    - **Given**: プリセット管理モーダルを開いている。
    - **When**: モーダルヘッダーまたはプリセット一覧上部エリアを表示する。
    - **Then**: 「生成対象の全選択」および「生成対象の全解除」ボタンが一覧上部のアクセスしやすい位置に互いに隣接して配置されていること。
    - **And**: いずれかのボタンを押下した際、プリセット一覧の生成対象チェック状態が全選択または全解除されること。
  - [ ] AC-5 (複数選択モードの自動遷移・解除・視覚表現):
    - **Given**: プリセット管理モーダルが通常表示状態（複数選択モード未起動）である。
    - **When**: PC環境においてCtrlキーまたはShiftキーを押しながらプリセット行をクリックするか、タッチ環境において行をロングタップまたはドラッグする。
    - **Then**: 専用の起動ボタンを押すことなく自動的に複数選択モードへ遷移し、該当プリセットが選択状態になること。
    - **And**: 選択されたプリセット行は枠線ハイライト（緑枠等）で視認可能となり、行右端に独立した複数選択用チェックボックスは表示されないこと。
    - **When**: 複数選択バーまたはヘッダーの解除ボタン（「×」アイコン等）を押下する。
    - **Then**: 複数選択モードが終了し、選択状態がすべてクリアされること。
  - [ ] AC-6 (生成用全選択・全解除と複数選択用全選択・全解除の分離):
    - **Given**: プリセット管理モーダルで複数選択モードが有効になっている。
    - **When**: 複数選択バーの全選択・全解除操作と、生成対象チェックの全選択・全解除操作を確認する。
    - **Then**: それぞれ異なるUI領域（複数選択操作用ツールバー vs 生成対象制御ボタン）として独立して配置・ラベリングされ、互いの選択状態（一括操作対象リスト vs 生成チェックリスト）に干渉しないこと。
  - [ ] AC-7 (置換元文字列のプリセット入力欄からの引用・絞り込み):
    - **Given**: プリセット一括編集モーダルのプロンプトタブで「置換」モードを選択している。
    - **When**: 「置換する文字列」入力欄の引用機能（候補ピッカー）を開く。
    - **Then**: 複数選択されたプリセット群のプロンプト入力欄に含まれる既存文字列・タグの一覧が引用候補として表示され、選択によって検索入力欄に反映できること。
    - **And**: 引用候補はプリセット別および対象フィールド別（ポジティブ/ネガティブ等）に絞り込み可能であること。
  - [ ] AC-8 (置換後文字列のタグチップ再編集):
    - **Given**: プロンプト一括編集の置換機能で、置換後の文字列入力欄にタグチップが追加・生成されている。
    - **When**: 生成されたタグチップをクリックまたはタップする。
    - **Then**: タグチップを削除することなく、タグ文言をその場で直接再編集（インプレース編集または編集サブメニュー）できること。
  - [ ] AC-9 (プロンプト追加項目の統合):
    - **Given**: プリセット一括編集モーダルのプロンプト編集画面を表示している。
    - **When**: 編集モードの選択肢を確認する。
    - **Then**: 「先頭に追加」と「末尾に追加」が大項目として分離されておらず、「追加」という1つの大項目に統合されていること。
    - **And**: 「追加」を選択した状態で、追加位置として「先頭」または「末尾」を指定する切り替え操作（トグル/セレクト等）が提供されていること。
  - [ ] AC-10 (共通タグ編集における重複頻度順グルーピング表示):
    - **Given**: 複数プリセットを選択した状態でプリセット一括編集モーダルの共通タグ編集を表示している。
    - **When**: 共通タグ一覧を確認する。
    - **Then**: 選択されたプリセット群全体における各タグの出現数（重複頻度）が多い順にグルーピング（例:「全N件に共通」「N-1件に共通」など）されて表示されること。
    - **And**: ユーザーは各グループから対象のタグを選択して一括削除または編集の対象に指定できること。
- **Inferred points**:
  - `PresetManagerPanel` の下部固定ドックから「現在の設定の上書き保存」を削除することでドックの高さが大幅に削減され、一覧の視認領域が広がる。
  - コピー別名保存は、既存の新規追加（AddPreset）モーダル/ダイアログのProps（初期値パラメータ・プロンプト・名前サフィックス「(Copy)」等）を流用することで、新規実装コストを最小化できる。
  - 共通タグ編集の「重複頻度順グルーピング」は、従来の「全選択されたプリセットの積集合（100%共通）のみ表示」から、「頻度順にグルーピングされた全タグリスト（部分共通タグも含む）」へと一覧表示を拡充することを想定。
