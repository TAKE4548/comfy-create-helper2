### REQ-013: スナップショットのメタデータ紐づけとアルバム保存

- **Status**: ready
- **Type**: enhancement
- **Priority**: P2
- **Current step**: none
- **Surface**: スナップショットがフラットに保存され整理しにくく、どのアセットを使ったか逆引きできない。スナップショット保存時に適用中LoRA/タグセットのリレーションをDBに保存する。また既存のアルバム（フォルダ）概念のベースを活かし、保存時に直接アルバム指定・作成を可能にする。
- **Root Cause**: 現行の `snapshots` テーブルは生成画像のパスと汎用パラメータのJSON文字列のみを保持しており、「どのアセット（LoRAやタグセット）が適用されていたか」というIDリレーションを持たないため、特定アセットを使用した画像を逆引き・整理するクエリが不可能である。また、生成完了画像をアルバム（フォルダ）に整理するために、一度スナップショットとしてフラットに保存した後にアルバム管理UIに移動して仕分ける必要があり、保存と整理の体験が分断されている。
- **Requirement**:
  - スナップショット保存時に、適用中のアセット（LoRA ID、適用強度、タグセットID等）の関連情報を中間テーブル（または Snapshot のメタデータ構造）を介してDBに保存し、アセット側から逆引き可能なリレーションシップを形成する。
  - 生成画面からスナップショットを保存する際のモーダルダイアログに、保存先アルバムを既存リストから選択するドロップダウン、および「新規アルバム作成」入力フィールドを統合し、保存と同時にアルバムの整理（および必要に応じた新規アルバム作成）が行えるようにする。
- **Acceptance criteria**:
  - [ ] AC-1: スナップショットのデータベーススキーマに、適用されたLoRAモデル（LoRA ID、適用強度）およびタグセット（タグセットID）とのリレーション（中間テーブル `snapshot_loras`, `snapshot_tag_sets` 等）が定義され、保存API（`POST /api/snapshots`）がこれらの情報を受け取ってDBに保存すること。
  - [ ] AC-2: 生成画面でのスナップショット保存モーダルにおいて、既存のアルバム一覧から追加先アルバムを1つ選択するドロップダウンが表示されること。
  - [ ] AC-3: 保存モーダルに「新規アルバム名」の入力フィールドが表示され、既存にないアルバム名を直接入力して保存すると、新規にアルバムが作成され、そのアルバムにスナップショットが即座に紐づくこと。
  - [ ] AC-4: アルバムへ追加されたスナップショットは、`album_items` テーブルの `sequence_order` に末尾のインデックスが自動設定され、アルバム内での並び順が正しく整合すること。
- **Design doc**: none
