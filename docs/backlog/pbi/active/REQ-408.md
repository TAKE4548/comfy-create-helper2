### REQ-408: モバイル: ボトムシートのスワイプダウンによる閉じるジェスチャー操作

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: frontend/src/components/common/Modal.tsx (共通モーダル・ボトムシートUI), docs/specs/SPEC_COMMON.md
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: モバイル表示時のボトムシートを閉じる際、明示的な閉じるボタンや背景タップに頼っており、片手操作時の操作導線が遠く不便であるため。
  2. なぜその課題が発生するか: ボトムシートの閉じるボタンやキャンセルボタンが親指の届きにくい位置にある場合、持ち替えが必要となり、シートを素早く片手で閉じる直感的なジェスチャー操作が提供されていないため。
  3. なぜ現状の仕組みで不十分か: ボトムシート上部にシートハンドル（`modal-sheet-handle`）等の視覚要素が存在するものの、ドラッグやスワイプダウンによる閉じるジェスチャーが実装されておらず、視覚的アフォーダンスと実際の振る舞いに乖離があるため。
  4. なぜこのアプローチを採用するか: ボトムシートのハンドル部や上端領域からのスワイプダウン（下方向へのドラッグ／フリック）でシートをスムーズに閉じられるようにすることで、ネイティブアプリ同等の片手操作性と素早い情報確認・離脱を実現できるため。
  5. 根本原因: モバイル向けモーダルをボトムシートUIへ移行した際、外観（下部固定・角丸・ハンドル表示）のみが先行し、ボトムシートの物理メタファーに沿ったタッチジェスチャー（スワイプダウンによる閉じる）のインタラクション設計と内部縦スクロールとの競合回避機構が未導入であったため。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 既存の閉じるボタン（ヘッダーの閉じるボタン、フッターのキャンセルボタン等）、バックドロップタップ、およびEscキーによる代替経路を完全に維持し、ジェスチャー限定の操作に孤立させない（MUI-10準拠）。
    - シート内に編集中の未保存変更がある場合の誤破棄防止方針を明確化する。
  - **Interaction (インタラクション)**:
    - モバイル画面幅（768px未満）で開いたボトムシートにおいて、ハンドル部または上端境界からの下方向スワイプ／ドラッグ操作を検知する。
    - 下方向への移動量が規定の閾値を超えた場合、または十分な下向き速度でフリックされた場合にシートの閉じる処理（`onClose`）を発火する。
    - 閾値未満でドラッグが終了した場合は、元の表示位置にスナップ復帰する。
    - ボトムシート内部の縦スクロールコンテンツ（`overflow-y-auto`）において、スクロール位置が最上部（`scrollTop === 0`）以外にある状態での下向きドラッグはコンテンツのスクロールを優先し、意図しないシートの即時閉鎖を防止する。
    - デスクトップ表示（768px以上の中央モーダル）では下向きドラッグによる閉じる操作は無効化され、既存のマウスクリック／キーボード操作を維持する。
  - **Visual (視覚デザイン)**:
    - ドラッグ中、ボトムシートが指の移動に追従して下方向へ移動（transform: translateY）し、操作感をフィードバックする。
    - 指を離して閾値未満でキャンセルされた際は、スムーズなアニメーション（トランジション）で元の位置に戻る。
    - 閾値を超えて閉じる際、画面下端へ滑らかにスライドアウトしてオーバーレイがフェードアウトする。
- **Requirement**:
  - **1. ボトムシートのスワイプダウン閉じるジェスチャー**:
    - モバイル表示時（幅768px未満）、ボトムシートの上部ハンドルまたはヘッダー領域を下方向へドラッグ／フリックして閉じる操作を可能にする。
  - **2. 内部スクロールとの調停**:
    - ボトムシート内にスクロール可能なコンテンツがある場合、コンテンツ最上部（`scrollTop === 0`）以外での下スクロール操作とスワイプ閉じる操作が競合しないよう調停する。
  - **3. デスクトップ非破壊・アクセシビリティ維持**:
    - デスクトップ表示（中央モーダル）の既存振る舞いおよび、既存の閉じるボタン／Escキー／バックドロップクリックによる閉じる経路を損なわない。
- **Acceptance criteria**:
  - [ ] AC-1: Given モバイル表示（画面幅768px未満）でボトムシートモーダルが表示されている, When ユーザーがシート上部のハンドルまたはヘッダー領域を下方向へ規定の閾値以上ドラッグ（スワイプダウン）して指を離す, Then ボトムシートが閉じられ、モーダルの閉じるコールバック（onClose）が実行されること
  - [ ] AC-2: Given モバイル表示（画面幅768px未満）でボトムシートモーダルが表示されている, When ユーザーがシートを下方向へドラッグした移動量が規定の閾値未満の状態で指を離す, Then ボトムシートは閉じられず、元の表示位置に復帰すること
  - [ ] AC-3: Given モバイル表示（画面幅768px未満）でスクロール可能なコンテンツを持つボトムシートが表示され、コンテンツが下方向にスクロールされている（scrollTop > 0）, When ユーザーがコンテンツ領域内で下方向へスワイプする, Then ボトムシートは閉じられず、内部コンテンツの上方向へのスクロールが優先されること（最上部 scrollTop === 0 に達した状態からのみスワイプダウン操作が有効となる）
  - [ ] AC-4: Given モバイル表示（画面幅768px未満）でボトムシートモーダルが表示されている, When ユーザーが明示的な閉じるボタン、キャンセルボタン、またはバックドロップ（背景領域）をタップする, Then スワイプジェスチャーを使用しなくても、既存のタップ操作によってボトムシートを正常に閉じることができること（MUI-10準拠）
  - [ ] AC-5: Given デスクトップ表示（画面幅768px以上）でダイアログモーダルが表示されている, When モーダルヘッダーやコンテンツ上でマウスまたはタッチによる下方向ドラッグ操作を行う, Then スワイプダウンによるモーダルの閉鎖は発火せず、中央モーダルの配置と既存の操作性が維持されること
- **Inferred points**:
  - スワイプ判定閾値: 移動距離としてシート高さの一定割合（例: 25〜30%）または一定ピクセル値（例: 80〜100px）、および下方向のフリック速度（velocity）を考慮して設計する。
  - 上方向ドラッグの抑制: シートを上方向に引っ張った場合は、ゴムバンド効果または移動量0でクランプし、上方向への過度な突き破りを防ぐ。
  - フォーム・未保存変更の扱い: 入力フォーム等の未保存データ保護が必要なモーダルに対して、スワイプダウンによる即時クローズを無効化（opt-out）できるプロパティ、または確認ダイアログとの連携を考慮する。
