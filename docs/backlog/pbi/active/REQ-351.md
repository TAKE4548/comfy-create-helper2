### REQ-351: ParamSyncで同一ロールの別ステージを個別選択して同期する

- **Type**: feature
- **Status**: ready
- **Priority**: P2（仮置き）
- **Surface**: 生成ページのParamSync設定と入力
- **Operational need**: 必要な工程だけ追従させ独立調整と別ロール連動を両立する。
- **5 Whys / 業務上の課題整理**（ユーザー報告からの要約。実装原因の断定ではない）:
  1. 同じロールの別ステージを同期先に選べない。
  2. 代表ロール選択でその別工程も候補から除外されるように見える。
  3. 同じパラメータを工程ごとに毎回編集する手間がある。
  4. 同期先をロール×工程単位で選べば不要な工程を除外できる。
  5. 同期対象の識別粒度が多段編集単位と揃っていないことが課題である。
- **UX Classification**: Information Design / Interaction
- **Requirement**:
  - 代表と同じロールの別ステージをサブ候補に含め個別選択できる。
  - 同一型の別ロール同期を維持し未選択ステージを変更しない。
- **Acceptance criteria**:
  - [ ] AC-1: Given Main/StepsとRough/Steps、Detail/Steps、同一型Rough/OtherSteps, When Main/Stepsを代表に選ぶ, Then 他の3つがステージ名付きでサブ候補に表示されること。
  - [ ] AC-2: Given Main/Stepsを代表に選択, When サブ候補を表示する, Then 代表そのもののMain/Stepsは選べないこと。
  - [ ] AC-3: Given Main=20、Rough=30、Detail=40でRoughだけSteps同期先, When Mainを50へ変更する, Then Roughは50でDetailは40を保持すること。
  - [ ] AC-4: Given 同一型Rough/OtherStepsをMain/Stepsの同期先に選択, When Main/Stepsを60へ変更する, Then Rough/OtherStepsが60になること。
  - [ ] AC-5: Given RoughとDetailを同期先に選択, When Detailだけ解除して代表を70へ変更する, Then Roughは70でDetailは解除時の値を保持すること。
  - [ ] AC-6: Given 代表と同期先を保存済み, When 同じワークフローのParamSyncを再表示する, Then 選択したロール×ステージが復元されること。
- **Reference docs**:
  - SPEC_GENERATE.md §2-8
  - REQ-336
- **Inferred points**:
<inferred_points>
- 別ロール候補は現行の同一型条件を維持する。異なる型間同期は含まない。
- 自己参照を禁止しグループ間競合・循環の既存規則は変更しない。
</inferred_points>

- **BA contradiction audit**: 2026-10-11監査完了、条件付き承認（明確化推奨）。監査直後のunload成功。証跡: [監査証跡](../../ba-audit/REQ-351.md)
- **BA audit response**: モデルはMain/Rough/Detailをロールと仮定したが、既存REQ-336はロール×ステージの2軸を定義している。またREQ-336はParamSyncを対象外と明示しており、本PBIとの重複指摘は該当しない。解除時の値保持は代表変更による自動同期を止める意味で、手動編集を永久禁止する意味ではない。自己参照・循環・競合の既存規則維持は推論点に記載済み。設定が後で無効になる場合の従来処理と保存整合は設計で確認し、新たな工程作成等の追加仕様は含めない。条件付き評価を保持する。
- **Human review gate**: 2026-10-11にユーザーが本PBIをOKと明示承認。承認済みとしてreadyへ変更する。ユーザー指示に従い開発への引継ぎは行わない。
