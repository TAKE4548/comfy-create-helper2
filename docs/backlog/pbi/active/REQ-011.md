### REQ-011: 編集ノードのマッピングマスタ設定（CRUD追加）

- **Status**: ready
- **Type**: enhancement
- **Priority**: P2
- **Current step**: none
- **Surface**: 現在DB直接操作などに依存しているマッピングマスタを、設定ページ等からUI経由で追加・編集・削除できるようにする。
- **Root Cause**: ノードIDマッピングマスタ（`mapping_master`）テーブルに対するCRUD APIはバックエンド（`mapping_masters.py`）に実装されているものの、フロントの設定画面（`SettingsPage.tsx`）からこれをUI経由で追加・編集・削除するための操作パネルが提供されておらず、結果としてマスタ情報の管理にDB直接操作やSwagger UI等の裏口利用が必要になっており、エンドユーザーや開発者にとって運用のハードルが高い。
- **Requirement**: 設定画面（SettingsPage）に、ノードマッピングマスタのCRUD（一覧取得、新規作成、編集、削除）を行える直感的な管理UIを追加する。
- **Acceptance criteria**:
  - [ ] AC-1: 設定画面において、登録されているマッピングマスタ（Role, expected_class_types, param_name, input_type, display_name, title_patterns）の一覧がテーブルまたはカード形式で表示され、各設定情報が視認できること。
  - [ ] AC-2: 「マスタの新規追加」フォーム（またはダイアログ）が提供され、必須項目（Role, param_name, input_type, display_name等）およびJSON配列項目（expected_class_types, title_patterns）を適切に入力して新規登録できること。
  - [ ] AC-3: 既存のマスタに対して「編集」操作が行え、入力済みの設定値をフォーム上で編集して変更内容をDBに反映できること。
  - [ ] AC-4: 既存のマスタに対して「削除」操作が行え、誤操作防止のための確認ダイアログ（Confirmation）を挟んでDBから物理削除できること。削除時、カスケードされる関連マッピングが存在する場合の警告メッセージが表示されること。
- **Design doc**: none
