### REQ-260: ComfyUI生成開始前の他プロセスVRAM競合防止と待機通知

- **Type**: enhancement
- **Status**: ready
- **Current step**: none
- **Priority**: P2
- **Surface**:
  - 生成開始前にComfyUIのサーバ側で、他のプロセスがVRAMを使っていて溢れそうな場合、待つようにしたい。現状、溢れてしまうとサーバ自体がフリーズしてしまうことがあるので、運用で気を付けているが、システム的にも防止しておきたい。長時間待つ可能性があるので、ユーザへの通知も行いたい。
- **Root Cause**:
  - **Interaction & Information Design**:
    - 生成投入前のVRAM残量に対する安全ガード機構が存在せず、他プロセス（ローカルLLMや別モデル等）がVRAMを消費している状態で生成を実行するとVRAM枯渇（OOM）によりシステムフリーズが発生するリスクがある。
    - ユーザーが安全なタイミングを手動で見極めて運用せざるを得ず、また待機が必要となった場合のフィードバック（待機理由、状況、長時間待機時の通知、待機中断手段）が欠如している。
- **Requirement**:
  - 生成リクエスト開始前にGPUの空きVRAM状態を自動検証し、他プロセスの使用により枯渇の恐れがある場合は即座に実行せず、空きが回復するまで安全に待機すること。
  - 待機状態になった場合はユーザーにその旨を明示し、長時間に及ぶ場合は通知を発行するとともに、ユーザーが待機をキャンセルできるようにすること。
  - 安全な空き容量が確保された後は、自動的に生成処理を再開・開始すること。
- **Acceptance criteria**:
  - [ ] AC-1: 生成リクエスト投入前において、GPU空きVRAMが安全基準値を下回っている場合、生成投入を一時停止して待機状態に遷移すること。
  - [ ] AC-2: 待機状態となった際、生成進行UI上に「VRAM解放待ち（他プロセスの終了待機中）」の専用ステータスおよび状況が表示されること。
  - [ ] AC-3: 待機状態が一定時間継続した場合、画面上（トーストまたはバナー等）でユーザーに対してVRAM待機中である旨の通知が行われること。
  - [ ] AC-4: 待機状態の継続中、ユーザーはいつでも待機をキャンセル（生成リクエストの取り消し）して安全にアイドル状態に戻せること。
  - [ ] AC-5: 他プロセスの終了等により安全な空きVRAMが確保された場合、待機が自動的に解除され、保留されていた生成処理が正常に開始されること。
- **Design doc**: none
