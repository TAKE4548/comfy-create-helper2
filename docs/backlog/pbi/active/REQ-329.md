### REQ-329: Prompt Surgeon: backend/app/main.py ルーターのドメイン階層別集約

- **Type**: refactoring
- **Status**: ready
- **Current step**: none
- **Priority**: P3
- **Surface**: `tmp/refactoring_analysis_and_roadmap.html` の REF-05 (Task 3.2) に基づき、現在 `backend/app/main.py` にフラットに 27 個以上 include されている APIRouter 群を、ドメイン別サブルーター（例: `routers/lora_studio/`, `routers/settings/` 等）へと階層的に集約する。
- **5 Whys / Root Cause**:
  1. なぜ変更が必要か: `main.py` に 27 個以上のルーターがフラットに並んでおり、エントリポイントの凝集度が下がり全体構造が把握しづらいため。
  2. なぜフラットに並んだのか: 機能追加のたびに `main.py` へ `app.include_router` を 1 行ずつ追記していったため。
  3. なぜサブルーター化するのか: ドメインごとにルーティングと OpenAPI タグ体系を整理し、保守性と見通しを改善するため。
  4. 根本原因: ドメイン単位のサブルーター集約設計が行われていなかったため。
- **UX Classification**:
  - **Information Design / API Documentation**:
    - OpenAPI (Swagger UI) ドキュメント上のタグ体系の整理
    - ルーティング定義の可読性とドメイン境界の明確化

#### Acceptance Criteria (AC)

- [ ] **AC-1**: Given 27 個以上のルーターがフラットに include されている `main.py` において、When 関連するドメイン（例: LoRA Studio 関連のデータセット・学習・評価、設定関連等）がサブルーターに集約された場合、Then `main.py` 内の `app.include_router` 行数が大幅に削減され、責務ごとに整理されること。
- [ ] **AC-2**: Given ドメイン別サブルーターへの集約後において、When 各 API エンドポイントのパスプレフィックス（URL）および HTTP メソッドを検証したとき、Then 既存のすべてのエンドポイントの URL 構造および OpenAPI スキーマが一切変更されず、完全な後方互換性が維持されること。
- [ ] **AC-3**: Given リファクタリング後において、When `mypy backend` および `pytest`（バックエンド全テスト）を実行したとき、Then 型エラー 0、テスト失敗 0 件で通過すること。
