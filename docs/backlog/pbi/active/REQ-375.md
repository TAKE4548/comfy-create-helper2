### REQ-375: モバイル複数選択UIの再設計（History一覧・アルバム詳細・Generate履歴）

- **Type**: feature
- **Status**: ready
- **Priority**: P3
- **Surface**: モバイルのHistoryスナップショット一覧、アルバム詳細、Generate履歴の複数選択（幅767px以下）。共通 `MultiSelectToolbar` / `useMultiSelect` と関連
- **Reference**:
  - docs/design/mobile-ui-redesign/mobile-history-generate-selection-design-draft.md（§4〜§8、AC-04〜AC-10）
  - docs/design/mobile-ui-redesign/mobile-common-ui-redesign-proposal.md（§8、COMMON-11、C-AC-09〜13）
  - docs/design/mobile-ui-redesign/mobile-generate-redesign-proposal.md（§11、AC-18〜22）
  - docs/specs/SPEC_COMMON.md（§5 複数選択UIパターン）
  - docs/specs/SPEC_HISTORY.md（§2、§3）
  - docs/specs/SPEC_GENERATE.md（§3）
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: HistoryとGenerateで複数選択の見た目と操作階層が異なり、大きな色付き背景や同格のボタンが並んで情報階層が散漫なため。
  2. なぜその課題が発生するか: 選択状態の表示と対象への操作が同じ場所に混在し、画面ごとに独自の表現が積み重なったため。
  3. なぜ現状の仕組みで不十分か: SPEC_COMMON §5は画面上部のツールバーを定義するが、モバイルのタッチ操作やボトムナビとの関係までは定めていない。
  4. なぜこのアプローチを採用するか: 上部は選択状態、下部は対象への操作に分離する共通パターンを、ユーザーがモックで評価した。
  5. 根本原因: 選択状態（何件・終了・補助選択）と一括操作（何をするか）の役割がモバイルUIで分離されていないこと。
- **UX Classification**:
  - **Information Design (情報設計)**: 上部を状態、下部を操作に分離する。選択件数を主情報にする。
  - **Interaction (インタラクション)**: 長押しで開始、タップで選択、上部「×」で終了。下部ドックから一括操作。
  - **Visual (視覚デザイン)**: 緑・紫の大きな状態背景を減らし、既存のダークテーマに揃える。
- **Requirement**:
  - **1. 上部の選択状態バー**: 「×」＋「N件（N枚）選択中」を主情報とし、「すべて選択」「選択解除」は補助操作とする。
  - **2. 下部の一括操作ドック**: 選択中のみ、ボトムナビの直上に固定表示し、選択終了・画面離脱時に取り除く。
  - **3. 画面別の一括操作**: History一覧＝ダウンロード／アルバムへ追加／削除、アルバム詳細＝ダウンロード／削除、Generate履歴＝スナップショットに保存。それぞれ既存の処理・確認フローに接続する。
  - **4. 非対象**: 共通React部品（`MultiSelectToolbar` 等）の統合・置換の可否（設計で利用箇所を調査し、別途承認を得る）、PC表示、他ページの選択ツールバー、API。
- **Acceptance criteria**:
  - [ ] AC-1: Given 幅767px以下のHistory一覧・アルバム詳細・Generate履歴, When 画像を長押しする, Then 選択モードに入り、長押しした画像が選択され、以降は画像のタップで選択／解除できること。
  - [ ] AC-2: Given 選択モード, When 画面上部を確認する, Then 「×」と「N件（Generateは「N枚」）選択中」が主情報として表示され、件数が選択数と一致し、「×」のアクセシブルな名前が「選択モード終了」であること。
  - [ ] AC-3: Given 選択モード, When 「×」をタップする, Then 選択が解除され、選択モードが終了して通常表示に戻ること。
  - [ ] AC-4: Given 選択モード, When 「すべて選択」をタップする, Then 対象が全選択され、「選択解除」をタップすると選択0件に戻り、選択モード自体は継続すること（0件時に無効となる操作は無効表示になる）。
  - [ ] AC-5: Given 選択モード, When 画面下部を確認する, Then 一括操作ドックがボトムナビの直上に隙間・重なりなく固定表示され、「×」のタップまたは別画面への遷移の直後にドックが消えて残留せず、透明なタップ領域も残らないこと。
  - [ ] AC-6: Given History一覧で1件以上選択, When 下部ドックの「ダウンロード」「アルバムへ追加」「削除」を押す, Then それぞれ従来の一括ダウンロード、アルバム追加、一括削除の処理が起動し、削除では従来の確認手順が省略されないこと。
  - [ ] AC-7: Given アルバム詳細で1件以上選択, When 下部ドックを確認し操作する, Then 「ダウンロード」「削除」のみが表示され（アルバムへ追加は新設しない）、それぞれ従来の処理が起動すること。
  - [ ] AC-8: Given Generate履歴で1件以上選択, When 下部ドックの「スナップショットに保存」を押す, Then 既存のスナップショット保存モーダル／処理が開き、未選択時は無効であり、Historyの「ダウンロード」と異なるラベル・動作として区別されること。
  - [ ] AC-9: Given 各画面で選択0件・1件・複数件・全選択・選択解除・終了を順に操作する, When 状態遷移を確認する, Then 件数表示とドックの有効／無効、進行中状態が実際の選択状態と常に一致し、押せない操作や重複表示が発生しないこと。
  - [ ] AC-10: Given 選択カード, When 画面を確認する, Then 選択中のカードにチェックマークと輪郭が表示され（色の違いだけに依存せず）、各操作の有効タップ領域が44×44px以上であること。
  - [ ] AC-11: Given 幅360px、セーフエリア、画面回転、ソフトウェアキーボード、拡大表示、スクリーンリーダー, When AC-1〜AC-8を実行する, Then レイアウトと操作が破綻しないこと。
  - [ ] AC-12: Given 幅768px以上、Baseline、他ページの `MultiSelectToolbar` 利用箇所（LoRAs・Tags・Settings等）, When 操作する, Then 本PBI前から表示と挙動が変化しないこと。
- **Inferred points**:
  - **確定（ユーザー回答 2026-10-18）**: アルバム詳細の専用「選択モード」ボタンは非表示とし、長押しのみで開始する。発見可能性の低下は許容する。
  - **仕様の差異**: SPEC_COMMON §5-2は上部スライド表示の共通ツールバー（件数／全体件数、全選択、解除、終了、画面固有ボタン）を定義しており、画面固有ボタンを下部に分離する本PBIは仕様の改訂を伴う。モバイルのみ適用の範囲を設計で明記し、完了時にSPEC_COMMON／HISTORY／GENERATEを更新する。
  - モックの下部ナビ高さ54px＋セーフエリアは現行仕様（SPEC_COMMON §2-4）と一致するが、共通トークンではない。ドック位置は現行ナビ実装に追従させる。
  - 前提: REQ-378（モバイルUI共通規約のSPEC_COMMON反映）の完了後に設計に着手する。
  - REQ-372と同じGenerate履歴を扱うため、REQ-372の完了後の着手を推奨する。HistoryのACはREQ-374と独立して進められるが、カード上の「⋯」と選択モードの競合は共同で確認する。
  - モック固有の回避策（架空SVG画像用の長押し補正、DOM後処理による疑似ボタン）は本番要件に含めない。選択状態とアクションを状態駆動でレンダリングする。
  - 共通部品（`MultiSelectToolbar` / `useMultiSelect`）の統合は利用箇所の調査と別途承認を要する。本PBIは承認なしに共通部品の挙動を変更しない。
