### REQ-409: タブレット・タッチ環境におけるDnD操作とOS標準ジェスチャーの競合防止

- **Type**: feature
- **Status**: ready
- **Priority**: P2
- **Surface**: docs/specs/SPEC_COMMON.md, frontend/src/components/common/ (DnD・ジェスチャー制御)
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: タブレット端末等のタッチ操作環境において、レスポンシブデザインのデスクトップ/タブレット表示下でドラッグ＆ドロップ（DnD）操作（タグ並び替え、LoRAスロット並び替え等）を行う際、ホールドタップ（長押し）やスワイプがブラウザやOS標準ジェスチャー（Pull-to-refreshによるページ再読み込み、3本指Undo/Redo、スワイプ進む/戻る等）と競合し、作業中の状態消失や意図しないナビゲーションが発生するため。
  2. なぜその課題が発生するか: タブレット解像度（768px〜1023px）は画面幅に基づくブレークポイントではモバイル専用UI（ボトムシート等）ではなく通常/デスクトップUIのレスポンシブ範囲となるが、入力デバイスはタッチスクリーンであり、ドラッグ操作が長押し＆スワイプ動作になるため。
  3. なぜ現状の仕組みで不十分か: 既存のDnD（@dnd-kit/sortable等）はマウス操作を前提とした移動量判定や汎用的なイベント監視を行っており、ドラッグ要素や操作領域に対するタッチジェスチャーの分離指定（`touch-action: none` / `touch-action: pan-y`）やコンテナの `overscroll-behavior: contain`、タッチ開始判定（長押しディレイと移動トレランス）の調停が不完全で、OS/ブラウザのネイティブジェスチャーが優先発火してしまうため。
  4. なぜこのアプローチを採用するか: ページ全体や通常状態のOSジェスチャーを一括禁止するのではなく、DnD要素の長押しドラッグ操作中（アクティブ時）に限定して局所的にブラウザジェスチャー抑止（`touch-action: none` や適切なイベント調停）を適用し、長押し時間（delay）や移動許容値（tolerance）を最適化することで、OSジェスチャーの誤発火を遮断しつつ通常のリストスクロールやOS標準ジェスチャーとの完全な両立を実現するため。
  5. 根本原因: 画面幅によるレスポンシブ判定と入力デバイス特性（タッチ入力）の考慮が分離されておらず、タブレット幅で動作するDnDコンポーネントにおいてタッチ長押し・ドラッグ時のネイティブジェスチャー干渉防御機構およびタッチセンサー設定が不足していたため。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - タッチ操作環境でDnDによる並び替えが困難な場合に備え、ボタン操作（上下移動ボタン等）によるアクセシブルな並び替え手段の併存または代替経路を確保する。
    - 誤操作によるページ再読み込み等でのデータ喪失を防ぐため、未保存プロンプトや設定の保護方針を整合させる。
  - **Interaction (インタラクション)**:
    - タブレット・タッチ環境（タッチ入力デバイス）において、DnD対象要素（タグチップ、LoRAカード、ドラッグハンドル等）をホールドタップ（長押し）してドラッグ開始した際、ドラッグ操作中に限りブラウザのPull-to-refresh（引っ張って更新）、進む/戻るスワイプ、OSの3本指Undo/Redoジェスチャーが誤発火しないよう局所的に `touch-action: none` 等で調停する。
    - ページ全体（`html`, `body` 等）に対する大域的なジェスチャー禁止は厳禁とし、ドラッグ操作中以外の通常状態（DnD領域外の操作、または長押しを伴わない通常スワイプ・スクロール時）では、OS・ブラウザ標準のジェスチャー機能（進む/戻る、Pull-to-refresh、Undo/Redo、縦横スクロール）を完全に維持する。
    - タッチ用DnDセンサー（TouchSensor等）において、適度なホールド時間（例: 200〜250ms）と移動トレランス（例: 5〜8px）を設定し、タップ操作（選択やクリック）およびスクロール操作との誤判定を防止する。
    - マウス操作環境（`pointer: fine`）では、既存のマウスドラッグ（クリック即時または8px移動でのドラッグ開始）の操作性を一切損なわないこと。
  - **Visual (視覚デザイン)**:
    - タッチ操作でのホールド（長押し）認識時、ドラッグ準備完了状態を示す視覚的アフォーダンス（微小なスケールアップ、シャドウ/エレベーションの変化、ゴースト表示、またはアクティブリング）を提示し、ユーザーにドラッグ可能となったことを明示する。
    - ドラッグ中、要素が指の移動に追従して滑らかに移動し、指先の下でターゲットが隠れない適切なオフセットまたは半透明表示を行う。
- **Requirement**:
  - **1. タブレット・タッチ環境におけるDnD操作時の局所的OS/ブラウザジェスチャー競合防止**:
    - タッチデバイス上でDnD可能要素（タグチップ、LoRAスロット等）を長押し・ドラッグする際、ドラッグ操作中（アクティブ時）に限定して `touch-action: none` および `overscroll-behavior: contain` 等によりブラウザ標準の Pull-to-refresh や履歴ナビゲーションスワイプ、OSジェスチャーの誤発火を局所的に抑止する。
  - **2. 通常状態におけるOS標準ジェスチャーおよびスクロール操作の完全維持**:
    - ドラッグ操作中以外の通常状態では、ブラウザおよびOSの標準ジェスチャー（進む/戻るスワイプ、Pull-to-refresh、Undo/Redo、リストやページの縦横スクロール）を一切阻害せず維持する。大域的なジェスチャー無効化を行わない。
  - **3. デスクトップ（マウス）操作の非破壊・互換性維持**:
    - マウス入力環境では既存のドラッグ＆ドロップ動作、クリック、ダブルクリック、キーボード操作の互換性を完全に維持する。
- **Acceptance criteria**:
  - [ ] AC-1: Given タブレット等のタッチ操作環境（画面幅768px以上かつタッチ入力）でDnD可能な要素が表示されている, When ユーザーが要素のドラッグ領域をホールドタップ（長押し）してドラッグ操作を開始する, Then ドラッグ操作中のみブラウザのPull-to-refresh（引っ張って更新）や進む/戻るナビゲーションスワイプ、OSジェスチャーが局所的に抑止され、要素のドラッグ並び替え操作が正常に実行されること
  - [ ] AC-2: Given タブレット等のタッチ操作環境でDnD可能な要素を含むスクロール可能なリストが表示されている, When ユーザーが長押しを行わずに要素上を上下にスワイプ（スクロールジェスチャー）する, Then ドラッグ操作は開始されず、リストコンテナの通常の縦スクロールが実行されること
  - [ ] AC-3: Given タッチ操作環境でDnD可能な要素が表示されている, When ユーザーが要素をタップ（短時間のホールドなしタップ）する, Then ドラッグ操作は開始されず、要素固有のタップ動作（タグの選択、詳細表示、トグル等）が正常に発火すること
  - [ ] AC-4: Given タッチ操作環境でDnD可能な要素を長押しする, When ドラッグ可能状態の閾値時間に達した時, Then 要素にドラッグ準備完了を示す視覚的フィードバック（拡大・浮き上がり・半透明ゴースト等）が表示され、OSの長押しテキスト選択メニュー等の表示が抑止されること
  - [ ] AC-5: Given デスクトップ環境（マウス操作）でDnD可能な要素が表示されている, When ユーザーがマウスでクリックおよびドラッグ操作を行う, Then タッチ向けホールドディレイの影響を受けず、既存のマウス操作閾値（8px移動等）に基づき即座にドラッグ並び替えが実行できること
  - [ ] AC-6: Given タブレット等のタッチ操作環境において画面が表示されている, When ユーザーがDnDドラッグ操作を行っていない通常状態（画面の非ドラッグ領域、またはドラッグ終了後）で画面端スワイプ（進む/戻る）やPull-to-refresh、OSのUndo/Redoジェスチャーを行う, Then これらのOS・ブラウザ標準ジェスチャーが阻害されることなく正常に機能すること（大域的なジェスチャー禁止の禁止）
- **Inferred points**:
  - ホールド時間（delay）: タッチ環境での長押しディレイは短すぎるとスクロールと誤認し、長すぎると操作テンポを損なうため、200ms〜250ms程度を推奨値として検証・調整する。
  - ポインタ判定方式: CSSの `@media (pointer: coarse)` や `@dnd-kit` の PointerSensor / TouchSensor のセンサー登録順序・アクティベーション制約（`activationConstraint: { delay: 250, tolerance: 5 }`）の併用を想定する。
