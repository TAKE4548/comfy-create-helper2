### REQ-215: スナップショット/ComfyUIルーターのサービス層分離とトランザクション整合性・エラー伝播の適正化
- **Type**: refactor
- **Status**: ready
- **Current step**: Phase 1: Requirement Analysis
- **Priority**: P2
- **Surface**:
  - `backend/app/routers/snapshots.py` (256行) に、画像のディスク保存、WebP圧縮変換、サムネイル作成、関連LoRA/TagSet/Albumの多対多リレーション作成、DBトランザクションコミットが一体化して記述されている。画像保存成功後にDB書き込みが失敗した場合、またはその逆のケースで、ディスク上の孤立ファイル（Orphan Files）やDB不整合が発生するリスクがある。
  - `backend/app/routers/comfy.py` において、アップストリーム（ComfyUIサーバー）との通信エラー発生時に例外をキャッチして空の辞書 `{}` を返却しているため、ComfyUIダウン時にフロントエンド側でエラーが検知できず、サイレントに壊れたUI状態になる。
  - `comfy.py` の `_client` シングルトン管理において、FastAPIのライフサイクルに応じた適切な接続プール再利用・切断管理が行われていない。
- **Root Cause**:
  - **Fat Router Anti-Pattern**: ルーター関数内にHTTPエンドポイントの定義だけでなく、ファイルシステム操作・外部API通信・DBトランザクションが混載している。
  - **Silent Error Swallowing**: エラーハンドリングにおいて、適切なHTTPステータスコード（502 Bad Gateway / 500 Internal Server Error）をクライアントへ返却せず、空データを返してしまっている。
- **Requirement**:
  - `snapshots.py` のファイルI/Oおよびトランザクション処理を `snapshot_service.py` へ完全移譲し、ファイル生成とDB保存のロールバック整合性を保証すること。
  - `comfy.py` において、ComfyUI通信失敗時に適切なエラーログ記録と `HTTPException(status_code=502, detail="ComfyUI unreachable")` の送出を行うこと。
  - `httpx.AsyncClient` のライフサイクルを FastAPI の lifespan コンテキストで安全に管理すること。
- **Acceptance criteria**:
  - [ ] AC-1: `routers/snapshots.py` のビジネスロジックが `snapshot_service.py` に集約され、ルーターがHTTPリクエスト/レスポンスの責務に純化されていること。
  - [ ] AC-2: 画像保存失敗時にDBレコードが残らず、またDB失敗時に生成済み画像ファイルがクリーンアップされるロールバック機構が備わっていること。
  - [ ] AC-3: `routers/comfy.py` がComfyUIダウン時に空辞書ではなく適切なHTTP 502エラーを返却し、フロントエンド側でエラー検知可能になっていること。
  - [ ] AC-4: `test_snapshots.py` および `test_comfy_proxy.py` を含む全テストがパスすること。
