### REQ-158: FEキャッシュ設計の最適化：冗長なBEアクセスの削減とレスポンス向上

- **Type**: enhancement
- **Status**: done
- **Priority**: P1
- **Surface**: 画像保存時のアルバム名表示ラグ（IDはキャッシュされているが名称取得にBEアクセスが必要）を筆頭に、FEが同一セッション内で不要なBEアクセスを繰り返している箇所が複数存在する。これによりUIの応答性が低下し、モーダル・ページ切替時に視認できるフリッカー・ラグが発生している。
- **Root Cause**:
  1. **React Queryバイパス**: 複数コンポーネントが `useQuery` を使わず `useEffect + raw fetch` で直接APIを呼び出しており、既存のReact Queryキャッシュを無視して重複HTTPリクエストが発生している。
  2. **staleTime 過小設定**: グローバルデフォルト `staleTime: 30,000ms`（30秒）が、事実上不変なデータ（フォント、ベースモデル、カテゴリ、LLMプロンプト設定等）に対しても適用されており、不必要な再フェッチが頻発している。
  3. **アルバム名マッピング欠如**: `lastSaveAlbumId`（localStorage）でアルバムIDはキャッシュしているが、ID→アルバム名のマッピングが保持されておらず、表示時に毎回BEアクセスが必要になる。
  4. **ワークフロー別データのキャッシュ欠如**: `bypassProfiles` / `paramSyncGroups` がZustandで配列保持のみで、ワークフロー切替時に前のワークフローのデータが破棄され、同一ワークフローに戻った際に再フェッチが発生する。
- **Requirement**:
  1. アルバムID→アルバム名のマッピングテーブルをFE側で保持し、アルバム名の即時表示を実現する。適切なタイミング（ページロード、アルバム作成・編集・並び替え後）でBEと同期する。
  2. React Queryをバイパスしている全コンポーネントを `useQuery` ベースに統一し、キャッシュの共有・重複排除を徹底する。
  3. 静的・準静的データ（フォント・ベースモデル・カテゴリ・コンフィグ等）の `staleTime` をデータ変化頻度に応じて適切な値に延長する。
  4. `bypassProfiles` / `paramSyncGroups` を `workflowId` をキーとするMap形式でキャッシュし、ワークフロー切替コストを削減する。
  5. `/config` エンドポイントへの重複呼び出し（現状3箇所）を単一の共通Hookに統一する。

#### Acceptance Criteria (AC)

##### 1. アルバム名マッピングキャッシュ（ユーザー事例対応）

- [x] AC-1-1: アプリ起動時（またはHistoryPage/AddSnapshotToAlbumModal初回表示時）に `GET /albums` の結果から `albumId → albumName` のマッピングテーブルをメモリ内に構築し保持すること。
- [x] AC-1-2: `lastSaveAlbumId` を表示する箇所（保存モーダルのデフォルト選択等）で、アルバム名をBEへの追加リクエストなしに即時表示できること。
- [x] AC-1-3: アルバムの新規作成・名称変更・削除・並び替え操作が完了した後、マッピングテーブルが自動的に再同期（invalidate → refetch）されること。
- [x] AC-1-4: ページリロード時にマッピングテーブルが新鮮なBEデータで再構築されること。

##### 2. React Queryバイパス解消

- [x] AC-2-1: `SpeechBubbleEditorModal` の `albumsApi.list()` / `fontsApi.list()` が `useQuery({ queryKey: ['albums'] })` / `useQuery({ queryKey: ['fonts'] })` に移行され、2回目以降のモーダル開閉でBEリクエストが発生しないこと（staleTime内）。
- [x] AC-2-2: `SpeechBubbleControls` の `speechBubblePresetsApi.list()` が `useQuery` に移行され、モーダル再表示時にBEリクエストが重複しないこと。
- [x] AC-2-3: `BaseImageSelectModal` の全API呼び出しが `useQuery` に移行され、他ページ・コンポーネントとのキャッシュが共有されること。
- [x] AC-2-4: `SettingsPage`（削除確認ダイアログ）内の `Promise.all` フェッチが `useQuery` キャッシュ参照に置き換えられること。

##### 3. `GET /config` の統一Hook化

- [x] AC-3-1: `src/hooks/useConfig.ts` として専用Hookを新規作成し、`queryKey: ['config']`、`staleTime: Infinity` で設定を返すこと。
- [x] AC-3-2: `useComfyWebSocket.ts`、`useGenerationStore.ts`（初期化処理）、`SettingsPage.tsx` の3箇所が全て `useConfig()` Hookを通じてコンフィグを取得するよう統一されること。
- [x] AC-3-3: config保存時（SettingsPage保存アクション）に `queryClient.invalidateQueries(['config'])` が実行され、全利用箇所が更新されること。
- [x] AC-3-4: アプリ起動時の `/config` へのHTTPリクエストが1回のみであることをネットワークログで確認できること。

##### 4. 静的データのstaleTime最適化

- [x] AC-4-1: 以下のエンドポイントの `staleTime` が規定値以上に設定されること：

  | Endpoint | 推奨 staleTime |
  |---|---|
  | `GET /fonts` | `Infinity` |
  | `GET /config` | `Infinity` |
  | `GET /base-models` | `10 * 60 * 1000` (10分) |
  | `GET /lora-categories` | `10 * 60 * 1000` (10分) |
  | `GET /tagset-categories` | `10 * 60 * 1000` (10分) |
  | `GET /llm-prompts` | `10 * 60 * 1000` (10分) |
  | `GET /param-type-masters` | `5 * 60 * 1000` (5分) |
  | `GET /mapping-masters` | `5 * 60 * 1000` (5分) |
  | `GET /speech-bubble-presets` | `5 * 60 * 1000` (5分) |
  | `GET /snapshots/:id` (詳細) | `5 * 60 * 1000` (5分) |

- [x] AC-4-2: 上記エンドポイントを参照するmutation（保存・削除等）が完了した後に `invalidateQueries` が実行され、古いキャッシュが残存しないこと。

##### 5. BypassProfiles / ParamSyncGroups のワークフロー別キャッシュ

- [x] AC-5-1: `useGenerationStore` の `bypassProfiles` の保持方法が `BypassProfile[]`（配列）から `Map<workflowId, BypassProfile[]>` 相当の構造に変更され、ワークフロー切替時に既取得済みのデータが再利用されること。
- [x] AC-5-2: 同様に `paramSyncGroups` もワークフロー別キャッシュ構造となること。
- [x] AC-5-3: bypass profilesの更新・削除後にキャッシュが正しくinvalidateされること。
- [x] AC-5-4: 同一ワークフローに再度切り替えた際にBEへのHTTPリクエストが発生しないこと（キャッシュヒット）。

##### 6. キャッシュ設計のコード標準化（非機能）

- [x] AC-6-1: `src/hooks/useConfig.ts`、および `src/constants/staleTimes.ts`（staleTime定数ファイル）が新規作成され、全コンポーネントから参照されること。
- [x] AC-6-2: 新たにReact Queryを使用するhookはTypeScriptの型安全が確保されること。
- [x] AC-6-3: 既存のテスト（`src/hooks/__tests__`、`src/store/__tests`）がリファクタリング後も全てpassすること。

#### 実装除外スコープ（Out of Scope）

- `GET /comfy/queue`（ComfyUI WebSocket連動のリアルタイムデータ）：キャッシュ不適
- `GET {comfy}/history`（生成後リアルタイム取得）：キャッシュ不適
- `GET /snapshots`（フィルター付き一覧）：動的データのため現行維持
