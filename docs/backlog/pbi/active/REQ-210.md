### REQ-210: 吹き出し描画サブシステム（SpeechBubbleControls/Renderer）の幾何計算・組版・Canvas描画パイプラインの分離
- **Type**: refactor
- **Status**: ready
- **Current step**: Phase 1: Requirement Analysis
- **Priority**: P2
- **Surface**:
  - `SpeechBubbleControls.tsx` (2,008行), `SpeechBubbleEditorModal.tsx` (1,553行), `speechBubbleRenderer.ts` (1,500行) と、吹き出し関連コードが合計5,000行超の巨大サブシステムとなっている。
  - `speechBubbleRenderer.ts` 内に、ベジエ曲線・円弧軌道の幾何学計算（Geometry Math）、縦書き/横書き・フォントメトリクス等の文字組版（Typography Layout）、Canvas 2Dコンテキスト操作（Canvas Rendering）、変形マトリクス・正規化座標（0..1）と実ピクセル座標の変換が混在している。
  - プレビュー表示（低解像度）と高解像度エクスポート時、または画像アスペクト比が変更された際に、手動計算された座標変換の丸め誤差やクリッピングが発生しやすい構造的デグレリスクがある。
- **Root Cause**:
  - **Lack of Pipeline Abstraction**: 吹き出し描画処理がレイヤ化（幾何モデル -> レイアウト計算 -> レンダリングコマンド実行）されず、命令型のCanvas手続きとして1つのファイルに集積されたため。
- **Requirement**:
  - `speechBubbleRenderer.ts` を「幾何演算（`bubbleGeometry.ts`）」「文字組版レイアウト（`bubbleTypography.ts`）」「描画実行（`bubbleCanvasRenderer.ts`）」の3層パイプラインに責務分離すること。
  - 座標系変換（正規化座標、ビューポート座標、エクスポート座標）を管理する `TransformContext` を導入し、手動の座標乗除・丸め処理を一元化すること。
  - `SpeechBubbleControls.tsx` 内のUI制御ロジックと描画更新トリガーを整理し、コード行数を大幅に削減すること。
- **Acceptance criteria**:
  - [ ] AC-1: `speechBubbleRenderer.ts` が幾何計算、テキスト組版、Canvasレンダラーにモジュール分割され、単一ファイルの責務が明確化されていること。
  - [ ] AC-2: 座標系変換が一元化され、異なる解像度やアスペクト比でのプレビュー/エクスポート時にも位置ずれやフォント欠けが発生しないこと。
  - [ ] AC-3: `speechBubbleRenderer.test.ts`, `SpeechBubbleControls.test.tsx`, `SpeechBubbleEditorModal.test.tsx` の既存全テストがパスすること。
