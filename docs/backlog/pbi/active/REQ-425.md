### REQ-425: プロンプト構造テンプレートによる分割入力とノード別任意結合送信

- **Type**: feature
- **Status**: new
- **Priority**: P2
- **Surface**: Generate 画面（PC / モバイルのプロンプト入力パネル・アセット追加導線・プリセット）、ワークフロー設定 / マッピング設定（出力結合グループ管理）、プロンプト構造テンプレート管理 UI、生成履歴・スナップショット詳細表示
- **5 Whys / Root Cause**:
  1. なぜ新設が必要か: ComfyUI ワークフロー側に分割用の `CLIPTextEncode` / `PrimitiveStringMultiline` や結合ノードを先に用意する方式では、画像ごとに増減するキャラクター（Repeat 部分）への汎用対応が難しく、使わない入力欄が残ったりワークフロー自体の変更が必要になるため。
  2. なぜ現行のプロンプト入力構造では不十分か: 現行の Generate 画面はワークフローの物理ノードマッピング（`textarea`）ごとに 1 対 1 で入力欄を生成するため、Anima 推奨構造のように多数の項目や複数キャラクターを含む長大なプロンプトを単一欄内で管理せざるを得ず、構造化と入力整理が困難なため。
  3. なぜ単一入力欄での管理や一律の全結合だけでは不十分か: 生成の主工程（例: `Main`）では全ブロックの結合プロンプトが必要である一方、後段工程（例: `Upscale` や `FaceDetailer`）では顔・髪・表情のみや背景・質感のみなど一部のブロックだけを抽出して送信したいケースがあり、用途に応じた部分結合が求められているため。
  4. なぜハードコードではなくテンプレート・任意グルーピングが必要か: Anima 推奨構造は標準テンプレートとしてすぐ使えるようにしつつ、利用モデルやワークフローの好み・ノード構成に応じてブロック構成やキャラクター繰り返し、結合グループと送信先ノードの対応付けをユーザーが柔軟に増減・編集できる必要があるため。
  5. 根本原因: プロンプトの論理的な構成単位（`[]` ブロック分割およびキャラクター等の繰り返し構造）と、ComfyUI ワークフロー上の物理プロンプトノード（Positive / Negative の `CLIPTextEncode` / `PrimitiveStringMultiline` 等）への送信構成が密結合していたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 汎用的なプロンプト構造テンプレート（および初期搭載の「Anima 標準テンプレート」）により、繰り返し可能なセクション（キャラクター等）と全体セクション、および各 `[...]` 相当の入力ブロックを明確に階層構造化する。
    - ワークフロー単位の「結合出力グループ」定義により、どの入力ブロックをどの順序で結合し、繰り返しセクションについてどのインスタンス（全インスタンスまたは指定番号インスタンス）を対象としてどのワークフロー側プロンプトノードへ送るかをハードコードなしに明示・管理できるようにする。
    - プリセット、生成メタ情報、スナップショットにおいて、結合後の単一文字列だけでなく分割された入力構造のまま保存・識別・確認できるようにする。
  - **Interaction (インタラクション)**:
    - テンプレートの作成・編集・削除（セクション、繰り返し可否、入力ブロックの追加・順序変更・削除）が行える。
    - ワークフロー単位で結合出力グループを任意に追加・編集・削除し、含める入力ブロックの複数選択・結合順指定・繰り返しセクションの対象インスタンス指定（全インスタンス／特定番号指定）・ワークフロー側プロンプトノードへの紐付けが行える。Positive / Negative の区別なく共通の仕組みとして扱え、運用上 Negative を 1 欄のまま割り当てる構成にも対応する。
    - Generate 画面では選択中ワークフローの設定に応じて分割入力欄を表示し、キャラクター等の繰り返しインスタンスの動的追加・削除、既存 `TagChipEditor` 操作、任意入力欄への TagSet / LoRA（アセット）追加、および生成時の空欄・無効チップ除外＋カンマ（`, `）結合送信を実行できる。
  - **Visual (視覚デザイン)**:
    - 項目数が多いテンプレート（Anima 標準構造等）でも入力が破綻しないセクション／ブロック整理（折りたたみ・空欄時の視覚的整理）を提供し、PC・モバイル双方で既存のデザインシステム（`SPEC_COMMON.md` の UI 6 大不変条件・44×44px タップ領域・`min-w-0` 等）に準拠する。
- **Requirement**:
  - **1. 汎用プロンプト構造テンプレート管理と Anima 標準テンプレート**:
    - 特定の BaseModel に限定されない汎用機能として、プロンプト構造テンプレートを任意に追加・編集・削除できること。
    - テンプレートには通常の非繰り返しセクションおよび繰り返し可能（Repeat）なセクションを定義でき、各セクション内に名前付き入力ブロック（Anima 構造における `[...]` 単位に相当）を複数設定・並び替え・削除できること。
    - 初期状態で **Anima 標準テンプレート** が用意されていること。Anima 標準テンプレートは、キャラクター毎の Repeat セクション（`character name`, `series name`, `@artist name if needed`, `skin / ears / horns / halo / wings`, `hair color`, `hair length`, `hair style`, `eye color`, `eye shape`, `pupils`, `expression`, `body features`, `headwear / eyewear`, `neckwear`, `upper clothes`, `lower clothes`, `legwear`, `shoes`, `accessories / tail / wings` の 19 項目）と、全体セクション（`pose`, `hand position`, `leg position`, `action`, `camera distance`, `camera angle`, `lens`, `focus`, `composition`, `background`, `time`, `weather`, `scene objects`, `lighting`, `depth`, `effects`, `after details` の 17 項目）を備えること。
    - Positive / Negative で機能差を設けず同一の仕組みとして利用可能とし、Negative Prompt は運用上 1 欄構成（テンプレート内 1 ブロックまたは従来の単一ノードマッピング）としてそのまま割り当てられること。
  - **2. ワークフロー単位の結合出力グループ定義とノードマッピング**:
    - ワークフロー単位の設定として、使用するプロンプト構造テンプレートの紐付けと、任意の数の結合出力グループ（名称・対象ブロック・結合順・Repeat 対象インスタンス指定・割当先ワークフローノード）の追加・編集・削除ができること。`Main` / `Upscale` / `FaceDetailer` 等の固定グループをハードコードしないこと。
    - 各結合出力グループでは、テンプレート内のどの入力ブロックを含めるかを任意に複数選択でき、選択したブロック間の結合順序を指定できること。さらに繰り返し（Repeat）セクションに属するブロックを含む場合、結合対象とするインスタンス範囲を「全インスタンス（既定）」または「指定番号のインスタンス（例: 1 番目のみ、2 番目のみ等の 1 始まりインデックス指定）」から選択・保存できること。各結合出力グループは互いに独立して設定ブロックを結合する（グループ間での重複除去は行わない）。
    - 各結合出力グループは、対象ワークフローにマッピングされたプロンプト入力ノード（`CLIPTextEncode` や `PrimitiveStringMultiline` 等）へ割り当てられること。出力グループ専用の追加テキスト入力欄は設けない。
    - 結合出力グループに割り当てられていないワークフロー側プロンプトノード（例: 1 欄で運用する Negative や未設定ノード）は、従来の単一入力欄としてそのまま表示・送信されること。
  - **3. Generate 画面での分割入力・Repeat 操作・既存アセット連携**:
    - 分割設定されたワークフローを Generate 画面で開いた場合、結合出力グループに紐づくノードの個別入力欄の代わりに、テンプレートに基づく分割入力欄を表示すること。
    - 繰り返し（Repeat）セクションでは、Generate 画面上でインスタンスの追加・削除・並び順維持を行えること。削除時は対象インスタンス枠と内部の入力値のみを取り除き、空のインスタンス枠（不要な空欄）を残さず残存インスタンスを詰めて保持すること（他インスタンスや保存済みアセット定義には影響しない）。
    - 各分割入力欄は既存の `TagChipEditor` 操作を備え、Repeat インスタンスごとに独立して入力値を保持すること。どの入力欄からでも既存の TagSet / LoRA 追加導線を利用でき、操作対象とした単一のブロック入力欄にのみ追加されて他インスタンスへ波及しないこと。
  - **4. ComfyUI 送信前の結合処理（空欄除外・カンマ結合・Repeat 展開）**:
    - 画像生成の実行時（ComfyUI へ送信する前段階。結合処理を FE / BE のどちらで担うかは設計に委ねる）、各結合出力グループに対して割り当て先ノードへ送る文字列を生成すること。
    - 各結合出力グループは他グループと独立して評価され、同一入力ブロックを複数グループへ重複して含めることができる（他グループへの割当によって自グループから除外されない）。
    - グループ内の連続する同一 Repeat セクションのブロック群は、当該結合出力グループに設定された Repeat 対象インスタンス指定（「全インスタンス」または「指定番号のインスタンス」）に合致し、かつ Generate 画面上に実在するインスタンスを登録順（例: 全インスタンス時は キャラ 1 → キャラ 2、指定番号時は合致する番号のインスタンスのみ）に抽出し、各インスタンス内で指定ブロック順に展開したうえで、前後の非繰り返しブロックと指定順で連結する。指定されたインスタンス番号が Generate 画面上のインスタンス数を超えて存在しない場合は、エラーや余分なカンマを発生させず当該 Repeat 部分をスキップすること。
    - 各ブロックから有効チップのみを抽出し、空文字・空白のみ・有効チップ 0 件のブロックをスキップして **`, `（カンマ＋スペース）** で連結すること。先頭・末尾の余分なカンマや連続カンマ（`, ,`）を発生させないこと。
  - **5. 分割状態のメタ情報保持と既存ワークフロー互換**:
    - ワークフロープリセットでは結合結果へ丸めず、テンプレート・Repeat インスタンス・各ブロック入力値および無効チップ状態を保持・復元でき、復元後も無効チップを無効状態のまま再有効化・編集できること。
    - 生成履歴メタ情報およびスナップショットでは、テンプレート・Repeat インスタンス・各ブロック単位の有効入力を分割状態のまま保持・表示し、復元時は対応する分割入力欄へ再配置すること（`SPEC_GENERATE.md` §2-3 に従い、無効化済みチップは生成メタ情報・送信ペイロードへ混入させない）。
    - プロンプト構造テンプレートを適用しない既存ワークフローおよび既存のプリセット／スナップショットは、PC・モバイル双方で変更前と同等に動作・保持されること。

- **Inferred points**:
  - 結合文字列の構築処理は「ComfyUI 送信前に結合する」要件であるため、フロントエンドのペイロード構築時またはバックエンドのワーカー注入時のいずれで実行するかは設計フェーズで整合性（プリセット一括編集・メタ情報保存・キュー再投入等との相性）を踏まえて決定する。
  - `SPEC_GENERATE.md` §2-3 の「マッピング済み `textarea` のみ入力欄を生成する」規約に対して、本機能は分割設定済みワークフローで割り当てられたマッピングノードをテンプレート由来の分割欄として展開・集約する拡張となる（未設定ワークフローおよび未割当ノードは従来契約を維持）。
  - 既存の `SPEC_GENERATE.md` §2-3（「無効タグは生成payloadや生成metadataに混入しない」）に基づき、編集用ワークフロープリセットでは無効化済みチップ（`enabled: false`）を含めた分割状態を保持・復元し、生成メタ情報・スナップショットでは無効タグを除外した有効な分割入力状態を保持する仕様として定義している。
  - 結合出力グループの Repeat 対象インスタンス指定は、既定を「全インスタンス」とし、特定番号指定において単一番号指定と複数番号指定（例: 1, 2 番目）のどちらの UI 表現・設定形式を採るかは設計フェーズで決定する（未指定の既存グループは「全インスタンス」として扱う）。
  - Anima 標準テンプレートの `@artist name if needed` はユーザー提示構造に従いキャラクター Repeat セクション内に含めるが、テンプレート編集機能によりユーザー自身で全体セクションへ移動・複製・改変できる。
  - 結合時はブロック間を `, ` で連結する。個々のブロック内でのチップ区切りや `isAnimaMode`（ピリオド区切り等）は既存の `TagChipEditor` 挙動をそのまま維持し、ブロック末にユーザーが手入力した末尾カンマの重複除去等は設計時に正規化規則を明確化する。
  - LLM 支援機能（`SceneGeneratorModal` の自動分解・`AuditPanel` の分割構造専用診断）およびプリセット一括編集モーダル（`ProfileBulkEditModal`）でのブロック個別指定編集は本 PBI の必須対象外とし、既存ワークフローの動作非破壊を保証する範囲で設計時に扱いを確認する。また結合先ノード専用の追加プロンプト入力欄は設けない。
  - ワークフローが参照中のテンプレートを削除・編集した場合の保護・整合性（削除確認・既存プリセット/メタ情報の表示保全）は設計フェーズで定義する。
