### REQ-349: LoRAStack型のマッピングマスタをパラメータ名なしで設定可能にする

- **Type**: feature
- **Status**: ready
- **Priority**: P2（仮置き）
- **Surface**: Settingsのマッピングマスタ作成・編集
- **Operational need**: 複合LoRAロールを単一パラメータ名の制約で妨げず設定する。
- **5 Whys / 業務上の課題整理**（ユーザー報告からの要約。実装原因の断定ではない）:
  1. LoRAStackマスタを保存できない。
  2. 単一パラメータ名を必須としている。
  3. LoRAStackは選択・複数強度・LoRA数をまとめて扱う。
  4. 専用型では不要入力を無効化すれば設定できる。
  5. 一般パラメータの必須項目が複合ロールにも適用されることが課題である。
- **UX Classification**: Information Design / Interaction
- **Requirement**:
  - LoRAStack選択時はパラメータ名欄を無効化し空欄で作成・更新できる。
  - 一般型の従来必須条件は維持する。
- **Acceptance criteria**:
  - [ ] AC-1: Given マスタ作成画面, When LoRAStack型を選択する, Then パラメータ名欄が無効になり入力できないこと。
  - [ ] AC-2: Given LoRAStack型でパラメータ名が空、他の必須項目が有効, When 保存する, Then パラメータ名必須エラーなしに作成されること。
  - [ ] AC-3: Given LoRAStackマスタ, When パラメータ名が空のまま編集保存して再表示する, Then 変更内容とLoRAStack型が保持されること。
  - [ ] AC-4: Given LoRAStack型でパラメータ名が空, When パラメータ名を必要とするfloat型へ変更する, Then パラメータ名欄が入力可能になること。
  - [ ] AC-5: Given float型でパラメータ名が空, When 保存する, Then 必須エラーが表示され保存されないこと。
- **Reference docs**:
  - SPEC_SETTINGS.md §4-1
  - SPEC_GENERATE.md §2-5
- **Inferred points**:
<inferred_points>
- 既存LoRAStack型を対象としLoRA数・強度・選択機能は変更しない。
- 型変更時の旧パラメータ名保持/クリアは設計事項。
</inferred_points>

- **BA contradiction audit**: 2026-10-11監査完了、CONDITIONAL PASS。監査直後のunload成功。証跡: [監査証跡](../../ba-audit/REQ-349.md)
- **BA audit response**: 監査はパラメータ名をマスタ名や一意識別子と混同している。既存SPEC_SETTINGSにid・role・display_nameとparam_nameが別々に定義されており、識別不能という指摘は該当しない。空欄はNULL保存を指定する意味ではなく、利用者が名前を入力しなくても保存できるという要件である。保存契約との整合は設計で検証し、SQL・UUID・migration等の具体的実装指定は採用しない。型変更後の空欄保存拒否はAC-5に定義済み。監査の条件付き評価を保持する。
- **Human review gate**: 2026-10-11にユーザーが本PBIをOKと明示承認。承認済みとしてreadyへ変更する。ユーザー指示に従い開発への引継ぎは行わない。
