### REQ-299: 競合確認モーダルの差分視認性向上（スクロール同期・インライン差分強調・セクション順整合）

- **Type**: improvement
- **Status**: new (2026-10-01)
- **Priority**: P2
- **UX Classification**:
  - **Interaction Design**: 左右ペイン（サーバー最新版とこの端末の編集）のスクロール同期および項目行単位（Row-level）の高さ自動整列による、同一比較項目の常時水平対照表示
  - **Visual Design**: プロンプト欄などのテキスト・タグ内容におけるトークン単位のインライン差分ハイライト（追加・削除・変更されたタグや単語の視覚的強調表示）
  - **Information Design**: モーダル内セクション表示順序の生成画面レイアウト（プリセット基本情報 → プロンプト → アセット/LoRA → パラメータ）への整合・統一
- **Surface**:
  - 競合検知した際に出る差分確認モーダル（PresetConflictModal）において、左右ペインのスクロールが連動せず、プロンプトの長さの違いによって後続項目の縦位置がズレてしまい比較がしづらい。
  - 差分がある欄にバッジは付くが、プロンプト欄などで具体的にどこが変更されたのかを目視で探す必要があり、パッと見で内容差分がわからない。
  - モーダル内のセクション並び順が生成画面（GeneratePage）と異なっており、認知負荷が高い。
- **5 Whys Analysis**:
  1. *Why*: 競合確認モーダルで左右の差異を確認・比較しにくいと感じるのはなぜか？
     → スクロールや縦位置が左右で揃っておらず、プロンプト欄の変更箇所を目視で探す必要があり、セクションの並び順も生成画面と異なっているため。
  2. *Why*: なぜ左右で項目の縦位置がズレてしまうのか？
     → 左右カラムが独立してスクロールされるか、またはプロンプト欄の行数・文字数差によって一方のカラムの高さが伸び、後続のパラメータ項目等の開始位置が左右で食い違うため。
  3. *Why*: なぜプロンプト欄の差分を目視で探さなければならないのか？
     → 現状の差分表現が「項目カード全体に差分バッジを付与する」単位にとどまり、テキスト内部の追加・削除・変更されたタグや単語をインラインでハイライトする機能がないため。
  4. *Why*: なぜセクション並び順に違和感（認知負荷）があるのか？
     → モーダル内のセクション順序が、ユーザーが普段操作している生成画面（GeneratePage）の視覚的ヒエラルキー（プリセット基本情報 → プロンプト → アセット/LoRA → パラメータ）と整合していないため。
  5. *Why*: 根本原因（Root Cause）は何か？
     → 【Interaction Design】2ペイン比較ビューにおける行単位の垂直アライメント・スクロール同期の欠如、【Visual Design】長文テキスト・タグに対する粒度の細かいインライン差分ハイライトの欠如、【Information Design】操作画面と確認モーダル間での情報階層・並び順の不整合。
- **Requirement & Edge Case Specifications**:
  - **左右ペインの行単位整列とスクロール同期**:
    - モーダルのデスクトップ表示（`md` ブレークポイント以上）において、各項目（プロンプト、各パラメータ）を同一行（Row）の左右セルとしてレイアウト、または行の高さを左右の最大値に自動追従させる。
    - 単一の共通スクロール領域内でコンテンツ全体がスクロールされる（または左右のスクロール位置が遅延なく1:1連動する）ことで、スクロール速度差による位置ドリフトを排除し、常に同一項目が水平に並んだ状態を維持する。
    - 一方の項目が空（未設定）の場合でも、他方のコンテンツ高さに合わせた行高さを確保し（「（未設定）」等のプレースホルダー表示）、後続行の垂直位置を崩さない。
  - **プロンプト内容のトークン単位インライン差分強調**:
    - プロンプト欄などのテキスト内容について、カンマや単語境界を考慮したトークン単位の差分抽出を行う。
    - サーバー側にのみ存在する要素（ローカルで削除されたタグ）には削除スタイル（赤系背景・取り消し線など）、ローカル側にのみ存在する要素（新規追加されたタグ）には追加スタイル（緑系背景など）、変更された要素には変更スタイルを適用する。
    - 差分のない共通タグ・単語は通常スタイルで描画し、どこが変更されたか一目で視認できるようにする。長大プロンプト（多数のタグ）でも描画パフォーマンスを維持する。
  - **セクション並び順の生成画面整合**:
    - モーダル内のセクション順序を、生成画面（GeneratePage）のレイアウト順（1. プリセット基本情報 → 2. プロンプト入力［Positive, Negative 等の定義順］ → 3. アセット・LoRA → 4. パラメータ群［サンプラー、ステップ、CFG、Seed、Batch Size 等］）と一致させる。
  - **レスポンシブ（モバイル）対応**:
    - モバイル幅（`md` 未満）ではタブ切替（「サーバー最新版」/「この端末の編集」）を維持しつつ、セクション並び順とインライン差分強調表示を適用し、横スクロール破綻を防ぐ。
  - **既存機能の非破壊性**:
    - 既存の3つの解決アクション（サーバー最新採用、この端末で上書き、別名保存）や複数競合時のタブ切り替え機能に干渉・破壊しないこと。
- **Acceptance criteria**:
  - [ ] AC-1 (行単位の水平アライメントと空状態保護):
    - **Given**: デスクトップ表示（左右2カラム）で競合比較モーダルが表示されている。
    - **When**: 一方のプロンプト欄等の文字数・行数が他方と異なる、または片方が空（未設定）である。
    - **Then**: 該当行の高さが左右の最大コンテンツに合わせて同一に整列され、空の側にはプレースホルダーが表示され、後続の全項目（他のプロンプトやパラメータ等）の開始縦位置が左右で完全に一致する。
  - [ ] AC-2 (共通スクロールによる完全同期・ドリフト防止):
    - **Given**: コンテンツ全体の高さがモーダル表示領域を超えている競合比較モーダルが表示されている。
    - **When**: ユーザーがスクロール操作を行う。
    - **Then**: 共通スクロールまたは完全連動スクロールにより、左右ペインの対応項目がズレることなく同時にスクロールし、常に同一項目が横並びの水平関係を維持する。
  - [ ] AC-3 (トークン単位のインライン差分強調表示):
    - **Given**: 左右ペインでプロンプト内容に差異が存在する。
    - **When**: 競合モーダルが表示される。
    - **Then**: 項目枠の差分バッジに加え、プロンプトテキスト内の追加タグ・単語（追加スタイル）、削除タグ・単語（削除スタイル/取り消し線）、変更タグ・単語がインラインで視覚的に強調され、一致する共通部分は通常表示される。
  - [ ] AC-4 (セクション並び順の生成画面整合):
    - **Given**: 競合比較モーダルが表示されている。
    - **When**: モーダル内のセクション表示順序を確認する。
    - **Then**: セクションが生成画面（GeneratePage）の並び順に従い、「プリセット基本情報」→「プロンプト入力（Positive / Negative 等）」→「アセット・LoRA」→「パラメータ（サンプラー、ステップ、CFG、Seed、Batch Size 等）」の順序で整列して配置される。
  - [ ] AC-5 (モバイル表示における整合と操作性維持):
    - **Given**: モバイル画面幅（タブ切替モード）で競合モーダルが表示されている。
    - **When**: 「サーバー最新版」タブおよび「この端末の編集」タブを切り替えて閲覧する。
    - **Then**: 生成画面と同一のセクション並び順で表示され、インライン差分強調が視認可能であり、レイアウト崩れを起こさない。
  - [ ] AC-6 (解決アクションボタンおよび既存機能の維持):
    - **Given**: 競合比較モーダルが表示されている。
    - **When**: 「サーバー最新版を採用」「この端末の編集で上書き」「別名で両方保存」のいずれかのアクションボタンをクリックする。
    - **Then**: 各解決アクションが正常に実行され、複数競合時のタブ切り替え機能も正常に動作する。
  - [ ] AC-7 (品質検証 - 回帰防止):
    - **Given**: 実装完了後のリポジトリ。
    - **When**: `cd frontend; npm run typecheck` および `npx vitest run src/components/__tests__/PresetConflictModal.test.tsx` を実行する。
    - **Then**: 型エラーおよびテスト失敗が0件である。
