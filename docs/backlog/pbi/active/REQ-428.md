### REQ-428: 共通Modalでフォーカスがダイアログ内にあるときEscapeキーで閉じられない不具合の修正

- **Type**: bug
- **Priority**: P2
- **Surface**: 共通 Modal（`frontend/src/components/common/Modal.tsx`）を使用する全画面（Settings・Generate・プロファイル一括編集内の参照画像ピッカー等。影響範囲は AC-6 で確定）
- **5 Whys / Root Cause**:
  1. なぜ修正が必要か: 共通Modalは「Escape/backdrop/キーボードでの退避を担保する」ことが UI 6大ハード不変条件（#3 Mobile Modals、SPEC_COMMON §1-5）で求められているが、通常の操作状態（フォーカスがダイアログ内）で Escape を押してもモーダルが閉じず、キーボードのみの利用者や外付けキーボード利用者がダイアログから退避できないため。
  2. なぜその課題が発生するか: REQ-427 の実ブラウザ（Chromium）検証で、プロファイル一括編集モーダルから開いた参照画像ピッカー（共通Modal）が、フォーカスがダイアログ内にある状態で Escape を押しても閉じず、重なっている一括編集モーダルも閉じなかった。フォーカスを外した（blur した）後の Escape では閉じる。つまり閉じられるかどうかがフォーカス位置に依存している。
  3. なぜ現状の仕組みで不十分か: 共通Modalのダイアログ内でのキー入力処理は Escape の伝播を止める一方、モーダル自身の閉じる処理は `window` のキー入力で受けているため、フォーカスがダイアログ内にある通常状態では閉じる処理に Escape が到達しない。さらに REQ-427 の E2E は「Escape の前に blur する」回避手順で通過しており、通常状態の不具合が自動検証で検出されていない。
  4. なぜこのアプローチを採用するか: 共通Modalは全利用箇所で共有されるため、共有側で一度修正すれば全利用箇所へ反映でき、個別モーダルごとの回避策（REQ-427 の E2E の blur 手順など）を不要にできる。同時に、重なって開いた場合に最前面のモーダルだけが閉じる既存のネスト挙動（SPEC_COMMON §1-4、REQ-427 一括編集モーダルのガード）は維持する必要がある。
  5. 根本原因: 共通Modalのダイアログ内キー処理（Escape の伝播停止）と、モーダルの閉じる処理（`window` での受付）が整合しておらず、フォーカスがダイアログ内にあるとき Escape が閉じる処理へ到達しない（REQ-408 の Modal 変更以降に存在。REQ-427 では変更されていない既存不具合）。影響する他の共通Modal利用箇所は未確認。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 該当なし（表示情報・構造の変更はない）。ただし SPEC_COMMON の共通Modal Escape 契約の記述を修正後の挙動に合わせる（AC-9）。
  - **Interaction (インタラクション)**:
    - フォーカスがダイアログ内にある通常状態での Escape による閉じる操作、ネスト時に最前面のみが閉じる挙動、Escape 無効指定モーダルの非閉鎖
  - **Visual (視覚デザイン)**:
    - 該当なし（見た目の変更はない）
- **Requirement**:
  - **1. フォーカス位置に依存しない Escape 閉鎖**:
    - 共通Modalが開いている間、フォーカスがダイアログ内（入力欄・ボタン・ダイアログ本体等）にあってもなくても、Escape キーでそのモーダルが閉じること。Desktop・Mobile（768px 未満のボトムシート）の双方で成立すること。
  - **2. ネスト時の挙動維持**:
    - 共通Modalが重なって開いている場合（例: プロファイル一括編集モーダル上の参照画像ピッカー、MappingMasterEditModal 上の WorkflowNodePicker）、Escape は最前面のモーダルのみを閉じ、背面のモーダルは開いたままであること。
  - **3. 既存の Escape 無効指定の維持**:
    - Escape での閉鎖を無効指定している共通Modal利用箇所（例: ネスト時の外側モーダル）は、引き続き Escape で閉じないこと。
  - **4. 影響範囲の調査と回帰防止**:
    - 共通Modalの全利用箇所を調査して一覧化し、各利用箇所で Escape 閉鎖の可否を実ブラウザで検証する。REQ-427 の E2E が用いている blur 回避手順を不要にする。
  - **5. 仕様書の同期**:
    - 共通Modalの Escape 契約を SPEC_COMMON（§1-4 ほか関連記述）へ反映し、REQ-427 で追記された「`window` の keydown で Escape を処理する既存の共有挙動」の記述が修正後の実挙動と矛盾しない状態にする。
- **Acceptance criteria**:
  - [ ] AC-1: Given 共通Modalが開いており、フォーカスがダイアログ内の要素（入力欄・ボタン・ダイアログ本体のいずれか）にある状態（Desktop 幅 1280x800 および Mobile 幅 375x667）, When Escape キーを 1 回押す, Then そのモーダルが閉じ、ダイアログが DOM から消えること。
  - [ ] AC-2: Given 共通Modalが開いており、ダイアログ内の要素からフォーカスを外した（blur した）状態, When Escape キーを 1 回押す, Then そのモーダルが従来どおり閉じること（回帰なし）。
  - [ ] AC-3: Given プロファイル一括編集モーダル上に参照画像ピッカー（共通Modal）が重なって開いており、フォーカスがピッカー内にある状態, When Escape キーを 1 回押す, Then ピッカーだけが閉じて一括編集モーダルは開いたままであり、続けて Escape キーを 1 回押すと一括編集モーダルが閉じること。
  - [ ] AC-4: Given MappingMasterEditModal 上に WorkflowNodePicker（共通Modal）が重なって開いており、フォーカスが WorkflowNodePicker 内にある状態, When Escape キーを 1 回押す, Then WorkflowNodePicker だけが閉じて MappingMasterEditModal は開いたままであること。
  - [ ] AC-5: Given Escape での閉鎖を無効にした共通Modal（例: ネスト時の外側モーダル、または Escape 無効指定のモーダル）が開いている状態, When フォーカスがダイアログ内にある状態で Escape キーを押す, Then そのモーダルは閉じないこと。
  - [ ] AC-6: Given 共通Modalを使用している全ての画面・コンポーネント, When 利用箇所を網羅的に調査する, Then 設計記録 `docs/design/REQ-428.md`（または検証記録）に、「利用箇所」「Escape 閉鎖の有無の指定」「フォーカスがダイアログ内にある状態での実ブラウザでの Escape 閉鎖結果」を列とする一覧が全利用箇所分作成されること。一覧で「閉じない」結果の利用箇所はすべて AC-1 の挙動に修正されていること（調査対象から外した利用箇所がある場合は理由が一覧に記録されていること）。
  - [ ] AC-7: Given REQ-427 の参照画像ピッカーとプロファイル一括編集モーダルの E2E, When Escape の直前に blur 操作を行わない形に変更して実行する, Then ピッカーが閉じる検証とネスト時の最前面のみ閉じる検証が成功すること。
  - [ ] AC-8: Given 修正後の候補, When Frontend の全テスト（`npm test`）と E2E 全件（`scripts/run_e2e.py`）を実行する, Then 既存テストが回帰せず成功すること。Escape 以外のキー操作（Tab 移動・Enter・文字入力）の挙動が修正前と変わらないこと。
  - [ ] AC-9: Given 修正後, When SPEC_COMMON の共通Modal Escape に関する記述（§1-4 のモーダル規約、および REQ-427 追記の §5-4 プロファイル一括編集モーダルの「Escape」項＝画像ピッカー表示中は一括編集モーダルが閉じずピッカーのみ閉じる旨の記述）を確認する, Then 記述が AC-1〜AC-5 の挙動と矛盾せず、§5-4 の「共通 `Modal` は `window` の keydown で Escape を処理する既存の共有挙動」という記述が修正後の実挙動に合わせて更新されていること。
- **Inferred points**:
  - 不具合の再現確認は REQ-427 検証時の Chromium 実機確認（ピッカー・一括編集モーダルとも Escape で閉じない）のみで、本 PBI 起票時点で再現手順の独立確認は行っていない。
  - REQ-427 で一括編集モーダルが閉じなかった事象は、フォーカスがピッカー内にあったため Escape が背面にも到達しなかった結果と推定する（一括編集モーダル自体の Escape 処理の不具合かは未確認）。レガシー `.modal-backdrop` モーダル（共通Modalでないもの）で自身にフォーカスがある場合の Escape 挙動は本 PBI の対象外とし、AC-6 の調査で気付いた問題は別 PBI 候補として記録する。
  - 他の共通Modal利用箇所が影響を受けるかは未確認であり、AC-6 の全利用箇所調査で確定する。調査で影響が確認されなければ、AC-1 の修正は全利用箇所に適用されても副作用が生じないことを AC-8 で担保する。
  - 日本語入力中（IME 変換中）の Escape は変換取消を意図した操作のため、モーダルを閉じるかどうかは設計フェーズで既存挙動との整合を確認して決める（現状挙動を変えない前提）。
  - 検証幅は Desktop 1280x800・Mobile 375x667 を代表とする（設計フェーズで SPEC_COMMON の検証幅に合わせて調整可）。
  - 優先度は P2 とする。キーボード退避は UI 不変条件に関わるが、マウス・タップ・backdrop・ボタンでは閉じられるため業務停止には至らない。
