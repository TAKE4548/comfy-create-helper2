### REQ-302: 未統一オーバーレイの前面化と不要なナビ回避余白の解消

- **Type**: improvement
- **Status**: ready
- **Priority**: P2
- **Current step**: none
- **Surface**: 現在の共通Modalより低い/同順位の独自モーダル・画像確認シート、および共通CSSに残る不要なボトムナビ回避余白。対象を棚卸しして、現行の重なり順・共通Modal・レスポンシブ契約へ統一する。
- **UX Classification**: Information Design（モーダルとナビの階層）、Interaction（背面操作の遮断と確定/取消への到達）、Visual（不要余白と見切れの解消）。
- **現状確認（2026-10-26、コード読取）**:
  - AppShellのボトムナビは--z-mobile-nav=50、共通.modal-backdropは--z-modal=100。共通Modalの前面化は実装済みであり、全画面が未対応とは扱わない。
  - 下表の独自overlayにはz-50が残り、ナビより前面にする共通契約への未統一がある。実際の遮蔽・タップ抜けは未再現で、親のstacking contextと実画面のhit targetを設計・検証時に確認する。
  - index.css基底.modal-backdropにはnav高+1rem+safe-areaの下余白がある。768〜1023pxの補正はrole=dialogの共通Modalとflex-colのHistoryModalPreviewを除外するため、ナビ非表示でも旧回避余白が残る条件がある。

- **Requirement**:
  - 上表を起点として本番から到達する対象と呼出経路を確定し、モーダル/シート本体とbackdropをボトムナビより前面へ統一する。未参照コード、通常のtooltip/メニュー、親modal内だけのz-50を同一の不具合として一括変更しない。
  - 通常の独自モーダルは既存の共通Modalを再利用する方向で整理し、768px未満の下部シート、以上の中央配置、幅/高さ上限、focus・Escape/backdropと復帰を現行契約に合わせる。画像確認シート・全画面ビューアは画像閲覧の既存例外を維持し、通常Modalへ機械的に置換しない。
  - 共通の重なり順トークンと実際のstacking contextで前面化を保証する。開いている間、背面ナビにタップ・キーボードフォーカスが抜けず、意図しない画面遷移を起こさない。
  - ナビ回避だけを目的とする余白を除去する。特に768〜1023pxでのnav非表示状態を含め、共通Modalと履歴プレビューを確認する。画面本体がナビに隠れないための余白、safe-area、通常のパネル内余白まで削除しない。
  - 短い画面・長い内容・ソフトキーボード表示時も必要なアクションへ到達でき、safe-areaに重ならない。raw 100vhへの変更や画面全高の強制で解決しない。
  - モーダルは原則排他であり、一覧→確認等は現行共通規則に沿う切替とする。ネストを一般要件にしない。SPEC_COMMONで明示されたMappingMasterEditModal内WorkflowNodePickerの例外だけは、既存の最前面操作とEscape制御を維持する。
  - PCの既存レイアウト・保存/取消/削除/閲覧の意味を維持する。REQ-299の差分改善、REQ-301の置換確認改善、REQ-367の共通アクセシビリティを本PBIだけで完了扱いにしない。

### 旧REQ-302: モバイル・レスポンシブ表示時におけるモーダル／ボトムシートのボトムナビゲーション前面オーバーレイ化

- **Type**: improvement
- **Status**: new (2026-10-01)
- **Priority**: P2
- **UX Classification**:
  - **Information Design**: モーダルダイアログおよびボトムシート（一時的・タスク集中コンテキスト）をグローバルな画面遷移ナビゲーション（ボトムメニュー）の上位レイヤーとして明確に位置づけ。展開中はボトムメニューを前面オーバーレイで覆うことで、ユーザーの注意をモーダル／シート内の操作・入力に集中させ、表示可能領域を画面下端まで最大化する。
  - **Interaction Design**: モーダルおよび最新UI仕様（UI 6大不変条件: 画面幅768px未満の下部ボトムシート統一）に基づくボトムシートにおいて、下部に配置される主要アクション（確定・保存・キャンセル・閉じる等）がボトムメニューによって隠蔽または押下不能になる問題を解消し、快適なタップ操作を保証する。また、展開中に背面のボトムメニュー項目が誤って反応しないよう操作を遮断しつつ、端末セーフエリア（ホームインジケーター）との適正なクリアランスを維持する。
  - **Visual Design**: モーダルおよびボトムシートの背景バックドロップ（半透明オーバーレイ・ブラー効果）を画面最下部まで均一に広げ、ボトムメニューとの不自然な隙間や分断感を排除する。ダイアログおよび下部シート全体が画面の高さを広々と活用できる視覚的安定感を提供する。
- **Surface**:
  - レスポンシブ表示やモバイルビューにおいて、ボトムメニューが表示されている状態で各種モーダルおよびボトムシートを開いた際、下部がボトムメニューの裏に隠れてしまったり、確定・保存・キャンセルなどのアクションボタンが押せない事象が発生している。
  - モーダル・ボトムシートは特定の操作に付随して一時的に表示されるものであるため、ボトムメニューを避けるために高さを過剰に縮小したり下部オフセット（余白）を設けるのではなく、ボトムメニュー自体を覆うように前面オーバーレイ表示することで、限られたモバイル画面を広く使えるようにする。
- **5 Whys Analysis**:
  1. *Why*: モバイルやレスポンシブ表示でモーダル／ボトムシート下部のボタンが隠れたり押せなくなるのはなぜか？
     → モーダルやボトムシートがボトムナビゲーションメニューの背面に潜り込んでしまうか、あるいはボトムナビを回避するために大きな下部余白が設定され、ダイアログ／シート表示領域が上下に圧迫されてフッター要素が見切れてしまうため。
  2. *Why*: なぜボトムナビゲーションを回避するような余白やレイヤー設定が残っていたのか？
     → 過去の改修において、モーダルとボトムメニューの重なりを防ぐ目的で「ボトムメニューの高さ分モーダルの下部パディングを空けて避ける」という回避策が採用されていたため。
  3. *Why*: なぜボトムナビゲーションを避ける方式では不都合なのか？
     → モバイル端末の画面縦幅は限られており、ボトムナビの高さ（約64px〜80px）＋セーフエリア分の余白を一律に差し引くと、ボトムシートやモーダルの最大高さが極端に縮小され、スクロールしても下部ボタンが操作困難になるため。
  4. *Why*: モーダル・ボトムシート表示中にボトムナビゲーションが見えなくなっても問題ないのか？
     → モーダルおよびボトムシートは特定の作業（設定、タグ編集、確認等）を完了またはキャンセルするために開かれるモーダル（排他的）タスクであり、表示中にボトムメニューで別画面へ遷移することはUX上想定されず、むしろ背景操作として無効化・遮蔽されるべきであるため。
  5. *Why*: 根本原因（Root Cause）は何か？
     → 【Information Design】モーダル／ボトムシートタスクとグローバルナビゲーションの視覚的・構造的ヒエラルキーが逆転または同一階層扱いとなっており、前面で覆う全画面・下部集中タスクとして設計されていなかったこと。【Interaction Design】フッターの重要アクション（保存・送信など）の到達性が、不要なボトムナビ回避オフセットによって著しく損なわれていたこと。
- **Requirement**:
  - モバイルおよびレスポンシブ表示時（ボトムナビゲーションが表示される画面幅・画面状態）において、開かれたすべてのモーダルダイアログ、下部ボトムシート（768px未満のMobile Modals不変条件準拠）、およびその背景バックドロップが、ボトムナビゲーションよりも前面にオーバーレイ（重畳）表示されること。
  - モーダル・ボトムシート下部に不要なボトムナビゲーション回避用のオフセット（過剰な下部パディング等）を設けず、ビューポート縦方向全体（100dvh）を有効活用できること。
  - 最下部アクションエリア（確定・保存・キャンセル・閉じる等のボタン群）が、ボトムメニューに覆われたり見切れたりすることなく、完全に視認・操作可能であること。
  - 展開中、背後のボトムメニューのタップ操作（画面遷移等）が完全に遮断され、誤操作が発生しないこと。OS標準のシステムジェスチャー（ホームバー操作等）は阻害しないこと。
  - モーダル／ボトムシート内で確認ダイアログ等の二次モーダル（Nested Modal）が開かれた場合でも、上位のダイアログがさらに最前面に表示され、階層順序（二次モーダル ＞ 一次モーダル／ボトムシート ＞ ボトムナビゲーション）が維持されること。
  - 展開時のアクセシビリティ（Escキー押下による終了、フォーカスが背景ナビゲーションへ漏れ出さないこと）を担保すること。
  - モバイル端末のセーフエリア（iOSのホームインジケーター等）への配慮を維持し、フォールバックを含む適切なセーフエリアクリアランスが確保されること。
  - デスクトップ表示（サイドバーナビゲーション時）におけるモーダルの既存挙動・レイアウトおよび表示品質にデグレが発生しないこと。
- **Acceptance criteria**:
  - 旧AC-1 (ボトムナビゲーション前面へのモーダル／ボトムシートオーバーレイ):
    - **Given**: モバイルまたはレスポンシブ幅でボトムナビゲーションが表示されている画面。
    - **When**: 任意のモーダルまたはボトムシート（アセット追加、プリセット管理、タグセット編集、ワークフロー管理、履歴プレビュー、確認ダイアログ等）を開く。
    - **Then**: モーダル／ボトムシート本体および背景バックドロップがボトムナビゲーションよりも前面に展開され、ボトムナビゲーションの表示がオーバーレイによって覆われる。
  - 旧AC-2 (画面縦幅の最大活用と下部ボタンの完全な操作性):
    - **Given**: モバイル画面幅で多数の入力項目またはリストを持つ縦長モーダルまたは下部ボトムシートが開かれている状態。
    - **When**: フッター領域および最下部のアクションボタン（保存、確定、閉じる等）を確認・スクロール操作する。
    - **Then**: ボトムナビゲーション回避のための過剰な下部余白によって高さが不当に縮小されることなく、ビューポートの高さを最大限に活用した表示が行われ、最下部ボタンが隠蔽・見切れすることなく完全に視認およびタップ操作できる。
  - 旧AC-3 (背面ボトムナビゲーションの操作遮断とモーダル操作):
    - **Given**: モバイル画面幅でモーダルまたはボトムシートが開かれている状態。
    - **When**: 画面下部のボトムナビゲーションが配置されていたエリアをタップする、またはキーボード操作（Escキー等）を行う。
    - **Then**: 背面のボトムナビゲーションのリンク/ボタンは反応せずページ遷移は発生しない。バックドロップタップでクローズ可能なモーダル／シートではそれが閉じ、Escキー押下時も正しく閉じる。
  - 旧AC-4 (ネストされたモーダルの重なり順序の整合性):
    - **Given**: モーダルまたはボトムシートが開かれている状態から、削除確認や警告などの二次モーダルが開かれた状態。
    - **When**: 重なり順序および操作対象を確認する。
    - **Then**: 二次モーダルが一次モーダル／ボトムシートおよびボトムナビゲーションよりも前面に表示され、背後の操作は遮断され、二次モーダルでの操作（OK/Cancel）が最前面で完結できる。
  - 旧AC-5 (セーフエリアクリアランスの維持とフォールバック):
    - **Given**: セーフエリア（ホームインジケーター）を持つモバイル端末またはエミュレーション環境でモーダルまたはボトムシートが開かれている状態。
    - **When**: 最下部領域の配置を確認する。
    - **Then**: 端末下端のセーフエリア（env(safe-area-inset-bottom) およびその未対応環境向けフォールバック余白）に応じた安全なクリアランスが確保され、操作ボタンが端末のシステム操作領域と重複しない。
  - 旧AC-6 (デスクトップ環境への影響皆無):
    - **Given**: デスクトップ画面幅（サイドバーナビゲーション表示）でアプリケーションを開いている状態。
    - **When**: 各種モーダルを開いて表示および操作を行う。
    - **Then**: デスクトップ表示におけるモーダルのセンタリング、最大幅・高さ、操作性、およびバックドロップ表示に何らのレイアウト崩れやデグレが発生しない。
