### REQ-302: モバイル・レスポンシブ表示時におけるモーダルのボトムナビゲーション前面オーバーレイ化

- **Type**: improvement
- **Status**: new (2026-10-01)
- **Priority**: P2
- **UX Classification**:
  - **Information Design**: モーダルダイアログ（一時的・タスク集中コンテキスト）をグローバルな画面遷移ナビゲーション（ボトムメニュー）の上位レイヤーとして明確に位置づけ。モーダル展開中はボトムメニューを前面オーバーレイで覆うことで、ユーザーの注意をモーダル内の操作・入力に集中させ、表示可能領域を画面下端まで最大化する。
  - **Interaction Design**: モーダル下部に配置される主要アクション（確定・保存・キャンセル・閉じる等）がボトムメニューによって隠蔽または押下不能になる問題を解消し、快適なタップ操作を保証する。また、モーダル展開中に背面のボトムメニュー項目が誤って反応しないよう操作を遮断しつつ、端末セーフエリア（ホームインジケーター）との適正なクリアランスを維持する。
  - **Visual Design**: モーダルの背景バックドロップ（半透明オーバーレイ・ブラー効果）を画面最下部まで均一に広げ、ボトムメニューとの不自然な隙間や分断感を排除する。ダイアログ全体が画面の高さを広々と活用できる視覚的安定感を提供する。
- **Surface**:
  - レスポンシブ表示やモバイルビューにおいて、ボトムメニューが表示されている状態で各種モーダルを開いた際、モーダルの下部がボトムメニューの裏に隠れてしまったり、確定・保存・キャンセルなどのアクションボタンが押せない事象が発生している。
  - モーダルは特定の操作に付随して一時的に表示されるものであるため、ボトムメニューを避けるためにモーダル高さを過剰に縮小したり下部オフセット（余白）を設けるのではなく、ボトムメニュー自体を覆うようにオーバーレイ表示することで、限られたモバイル画面を広く使えるようにしたい。
- **5 Whys Analysis**:
  1. *Why*: モバイルやレスポンシブ表示でモーダル下部のボタンが隠れたり押せなくなるのはなぜか？
     → モーダルがボトムナビゲーションメニューの背面に潜り込んでしまうか、あるいはボトムナビを回避するために大きな下部余白が設定され、ダイアログ表示領域が上下に圧迫されてフッター要素が見切れてしまうため。
  2. *Why*: なぜボトムナビゲーションを回避するような余白やレイヤー設定が残っていたのか？
     → 過去の改修において、モーダルとボトムメニューの重なりを防ぐ目的で「ボトムメニューの高さ分モーダルの下部パディングを空けて避ける」という回避策が採用されていたため。
  3. *Why*: なぜボトムナビゲーションを避ける方式では不都合なのか？
     → モバイル端末の画面縦幅は限られており、ボトムナビの高さ（約64px〜80px）＋セーフエリア分の余白をモーダル下部から一律に差し引くと、フォームやリストを含むモーダルの最大高さが極端に縮小され、スクロールしても下部ボタンが操作困難になるため。
  4. *Why*: モーダル表示中にボトムナビゲーションが見えなくなっても問題ないのか？
     → モーダルは特定の作業（設定、タグ編集、確認等）を完了またはキャンセルするために開かれるモーダル（排他的）タスクであり、モーダルが開いている最中にボトムメニューで別画面へ遷移することはUX上想定されず、むしろ背景操作として無効化・遮蔽されるべきであるため。
  5. *Why*: 根本原因（Root Cause）は何か？
     → 【Information Design】モーダルタスクとグローバルナビゲーションの視覚的・構造的ヒエラルキーが逆転または同一階層扱いとなっており、モーダルがボトムナビを前面で覆う全画面タスクとして設計されていなかったこと。【Interaction Design】モーダルフッターの重要アクション（保存・送信など）の到達性が、不要なボトムナビ回避オフセットによって著しく損なわれていたこと。
- **Requirement**:
  - モバイルおよびレスポンシブ表示時（ボトムナビゲーションが表示される画面幅・画面状態）において、開かれたすべてのモーダルダイアログおよびその背景バックドロップが、ボトムナビゲーションよりも前面にオーバーレイ（重畳）表示されること。
  - モーダル下部に不要なボトムナビゲーション回避用のオフセット（過剰な下部パディング等）を設けず、ビューポート縦方向全体を有効活用できること。
  - モーダル内の最下部アクションエリア（確定・保存・キャンセル・閉じる等のボタン群）が、ボトムメニューに覆われたり見切れたりすることなく、完全に視認・操作可能であること。
  - モーダル展開中、背後のボトムメニューのタップ操作（画面遷移等）が完全に遮断され、誤操作が発生しないこと。OS標準のシステムジェスチャー（ホームバー操作等）は阻害しないこと。
  - モーダル内で確認ダイアログ等の二次モーダル（Nested Modal）が開かれた場合でも、上位のダイアログがさらに最前面に表示され、階層順序（二次モーダル ＞ 一次モーダル ＞ ボトムナビゲーション）が維持されること。
  - モーダル展開時のアクセシビリティ（Escキー押下によるモーダル終了、フォーカスが背景ナビゲーションへ漏れ出さないこと）を担保すること。
  - モバイル端末のセーフエリア（iOSのホームインジケーター等）への配慮を維持し、フォールバックを含む適切なセーフエリアクリアランスが確保されること。
  - デスクトップ表示（サイドバーナビゲーション時）におけるモーダルの既存挙動・レイアウトおよび表示品質にデグレが発生しないこと。
- **Acceptance criteria**:
  - [ ] AC-1 (ボトムナビゲーション前面へのモーダルオーバーレイ):
    - **Given**: モバイルまたはレスポンシブ幅でボトムナビゲーションが表示されている画面。
    - **When**: 任意のモーダル（アセット追加、プリセット管理、タグセット編集、ワークフロー管理、履歴プレビュー、確認ダイアログ等）を開く。
    - **Then**: モーダルの背景バックドロップおよびダイアログ本体がボトムナビゲーションよりも前面に展開され、ボトムナビゲーションの表示がオーバーレイによって覆われる。
  - [ ] AC-2 (画面縦幅の最大活用と下部ボタンの完全な操作性):
    - **Given**: モバイル画面幅で多数の入力項目またはリストを持つ縦長モーダルが開かれている状態。
    - **When**: モーダルのフッター領域および最下部のアクションボタン（保存、確定、閉じる等）を確認・スクロール操作する。
    - **Then**: ボトムナビゲーション回避のための過剰な下部余白によってダイアログ高さが不当に縮小されることなく、ビューポートの高さを最大限に活用した表示が行われ、最下部ボタンが隠蔽・見切れすることなく完全に視認およびタップ操作できる。
  - [ ] AC-3 (背面ボトムナビゲーションの操作遮断とモーダル操作):
    - **Given**: モバイル画面幅でモーダルが開かれている状態。
    - **When**: 画面下部のボトムナビゲーションが配置されていたエリアをタップする、またはキーボード操作（Escキー等）を行う。
    - **Then**: 背面のボトムナビゲーションのリンク/ボタンは反応せずページ遷移は発生しない。バックドロップタップでクローズ可能なモーダルではモーダルが閉じ、Escキー押下時もモーダルが正しく閉じる。
  - [ ] AC-4 (ネストされたモーダルの重なり順序の整合性):
    - **Given**: モーダルが開かれている状態から、削除確認や警告などの二次モーダルが開かれた状態。
    - **When**: 重なり順序および操作対象を確認する。
    - **Then**: 二次モーダルが一次モーダルおよびボトムナビゲーションよりも前面に表示され、一次モーダルやボトムナビゲーションの操作は遮断され、二次モーダルでの操作（OK/Cancel）が最前面で完結できる。
  - [ ] AC-5 (セーフエリアクリアランスの維持とフォールバック):
    - **Given**: セーフエリア（ホームインジケーター）を持つモバイル端末またはエミュレーション環境でモーダルが開かれている状態。
    - **When**: モーダルダイアログの最下部領域の配置を確認する。
    - **Then**: 端末下端のセーフエリア（env(safe-area-inset-bottom) およびその未対応環境向けフォールバック余白）に応じた安全なクリアランスが確保され、操作ボタンが端末のシステム操作領域と重複しない。
  - [ ] AC-6 (デスクトップ環境への影響皆無):
    - **Given**: デスクトップ画面幅（サイドバーナビゲーション表示）でアプリケーションを開いている状態。
    - **When**: 各種モーダルを開いて表示および操作を行う。
    - **Then**: デスクトップ表示におけるモーダルのセンタリング、最大幅・高さ、操作性、およびバックドロップ表示に何らのレイアウト崩れやデグレが発生しない。
- **BA Audit Outcome**:
  - Model: qwen3.5-9b-claude-4.6-highiq-thinking-heretic-uncensored (Domain: reasoning)
  - Result: APPROVED WITH CONDITIONS
  - Observations & Mitigations:
    - 重なり順（z-index / Stacking Hierarchy）: ボトムナビゲーション（基底ナビ）＜ 一次モーダル ＜ 二次確認モーダルの階層順序を明確化（AC-1, AC-4）。
    - 画面幅・ブレークポイント依存の排除: 画面幅数値のみに依存せず、ボトムナビゲーション要素自体の重なり関係として前面オーバーレイを保証。
    - アクセシビリティ・キーボード操作: モーダル展開中のEscキーハンドリング、背景ナビへのフォーカス遮断を明記（AC-3）。
    - 端末セーフエリアのフォールバック: env(safe-area-inset-bottom) とともに標準余白フォールバックを規定し、古い環境やシステム操作領域との衝突を防止（AC-5）。
    - 既存の回避余白（Legacy Offsets）の撤廃: ボトムナビ回避用の過剰な下部パディングを一掃し、全高活用とボタン視認性を保証（AC-2）。
