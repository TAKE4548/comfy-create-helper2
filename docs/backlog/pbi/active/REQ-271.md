### REQ-271: 新規登録時重複検知およびカード統合アシスタント（Phase 3）

- **Type**: enhancement
- **Status**: ready
- **Current step**: none
- **Priority**: P3
- **Surface**:
  - 過去の運用によりモデル別に別カードとして作成されてしまった既存データ（例: キャラA (Anima) と キャラA (Illustrious)）を、1枚の論理カードの複数バリアントへと手作業なしにワンクリックで統合したい。
  - 一過性の統合移行機能に留めず、今後新規登録する際にも重複検知として恒久活用し、重複の疑いがあれば既存カードのバリアントとして統合するかを問い合わせる仕様としたい。
  - 統合アシスタントUIはボタン起動のモーダル形式とし、恒久的には能動的利用頻度が落ち着くため、ボタンへの導線はメイン画面のトップバーを占有せず、新規登録（New）モーダル内経由（またはSettings等）とする。
- **Root Cause**:
  - **Interaction & Information Design (Lack of Proactive Ingestion Guard & Library Drift)**:
    - 過去の重複カードの一括整理だけでなく、新規登録時に類似・同名の論理カードが存在するかを能動的に検知する仕組みがないため、運用を続けるうちに再度モデル別の別カードが重複作成されてしまうリスクが存在する。
    - また、一過性の移行ツールが主画面の主要アクションバーに恒久配置されると認知負荷を高めるため、登録モーダル等のコンテキストに応じた適切な補助導線が求められる。
- **Requirement**:
  - **新規登録時のリアルタイム重複検知と統合サジェスト**:
    - 新規作成モーダル（`AddTagSetModal`, `AddLoRAModal` 等）での名前入力時、既存のカード群（名前の完全一致、正規化一致、モデル名サフィックス一致等）を自動検知すること。
    - 重複・類似の疑いがある場合、インラインまたはダイアログで「既存のカード『〇〇』が見つかりました。このカードの新規バリアントとして追加しますか？それとも別カードとして新規作成しますか？」とユーザーに選択を促すこと。
    - 「バリアントとして追加」を選択した場合、既存の論理カードを編集対象とし、現在の入力内容をそのカードの新規BaseModelバリアントとしてシームレスに統合保存できること。
  - **統合アシスタントモーダル（恒久メンテナンス導線）**:
    - ボタン押下で起動するモーダル形式の「カード統合アシスタント」を提供すること。
    - 恒久的な利用頻度を考慮し、主画面の主要アクションバーを占有せず、新規登録モーダル内（またはSettings等のサブ導線）から起動可能とすること。
    - モーダル内ではライブラリ全体の重複・類似候補をスキャンし、代表カードへのバリアント統合・旧重複カードの整理を安全に実行できること。
  - **安全な統合処理とプレビュー**:
    - 候補グループごとに、統合後の代表名、代表サムネイル、代表カテゴリ、統合されるバリアントの対応関係がプレビュー表示され、必要に応じてユーザーが代表値を選択変更できること。
    - ユーザーの確認承認に基づき、対象カード群の設定が1つの論理カード内の複数バリアントとして集約され、重複していた旧カードが安全に整理・削除されること。
- **Acceptance criteria**:
  - [ ] AC-1: タグセットおよびLoRAの新規登録モーダルにおいて、カード名入力時に既存カードとの重複・類似を自動検知し、重複の疑いがある旨が明示されること。
  - [ ] AC-2: 重複検知時、ユーザーが「既存カードのバリアントとして追加・統合する」か「独立した新規カードとして作成する」かを明示的に選択できること。
  - [ ] AC-3: 「既存カードのバリアントとして統合」を選択した場合、既存の論理カードに新しいBaseModelバリアントとして設定が追加され、二重カードの発生が防止されること。
  - [ ] AC-4: 新規登録モーダル内等からアクセス可能なモーダル形式の「統合アシスタント」が提供され、ライブラリ内の重複候補カードを一覧プレビュー・統合できること。
  - [ ] AC-5: 統合実行時には代表カード名・代表サムネイル・移行されるバリアントの対応関係がプレビュー確認でき、誤操作による意図しない統合が防止されること。
  - [ ] AC-6: 統合処理完了後、旧重複カードが安全に整理・削除され、関連データ（プリセット等）の整合性が維持されること。
