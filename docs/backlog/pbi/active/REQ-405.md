### REQ-405: 画面を移って戻っても生成画面のプロンプトが保たれるようにする

- **Type**: feature
- **Status**: frontmatter の `status` を参照（状態の正本）。
- **Priority**: P2（編集内容の消失を防ぐ利便性・安全性の改善。仮置き）
- **Surface**: 生成画面のプロンプト入力欄（デスクトップ・モバイル共通）と、生成画面から LoRAs などほかの画面へ移動して戻る操作。
- **利用者ニーズ**: 生成画面でプロンプトを編集している途中に、LoRA や TagSet を確認するためほかの画面へ移動しても、戻ったときに編集中の内容がそのまま残っていてほしい。
- **課題の整理（観測）**: 生成画面でプロンプトを編集し、別の画面（LoRAs など）へ移って戻ると、入力が初期状態に戻る。REQ-309（初回 JS の遅延読込）より前（baseline）からの挙動で、REQ-309 では範囲外とした。そのため不具合の修正ではなく、新しい要望として扱う。なお、テキストモードの選択（`roleTextModes`）は、同じ SPA 内の移動では保たれるが、再読込では保たれない。
- **5 Whys**:
  1. なぜ起票するか: 画面を移って戻るとプロンプトの入力が初期状態に戻り、編集をやり直す必要があるため。
  2. なぜやり直しが負担か: プロンプトは長いタグ列や複数 role に及び、再入力に手間がかかるうえ、元の内容を正確に再現できないことがあるため（推定）。
  3. なぜ画面を移る必要があるか: 使うLoRA・TagSet を確認・選択する作業が別の画面にあり、生成画面の編集と行き来するため（推定）。
  4. なぜ今まで残らなかったか: 画面の移動で生成画面の入力状態が引き継がれる契約が仕様書になく、プリセットの切替や開閉に対する保持だけが定められているため（SPEC_GENERATE §2-3）。
  5. 根本原因: 同じタブ内で画面を移って戻ったときの編集中プロンプトの扱いが、要件として定められていない。
- **UX Classification**: Interaction（画面間を行き来する操作の連続性）と Information Design（編集中の状態を戻ったときも同じ内容で提示すること）。Visual（見た目の変更）は含めない。
- **Requirement**: 同じブラウザータブの中で、生成画面からほかの画面へ移動して生成画面に戻ったとき、移動前に編集していたプロンプトが保たれていること。

## 範囲

- 対象: 同じタブ内の画面遷移（生成画面から別画面へ移り、生成画面へ戻る）での、編集中プロンプトの保持。デスクトップ・モバイルの両方。
- 対象外（要確認事項。下記 inferred_points 参照）: ブラウザーの再読込、タブを閉じて開き直す、別のブラウザータブ・別端末をまたぐ場合の保持。プロンプト以外の入力（パラメータ、シード、チェックポイント選択、適用アセットなど）の保持。
- 対象外: プリセットの保存・自動保存・競合解決の契約の変更。

## Acceptance Criteria

- [ ] AC-1: 画面を移って戻ってもプロンプトが保たれる
  - Given 生成画面でプロンプトを編集している（保存の有無は問わない）
  - When LoRAs 画面へ移動し、同じタブ内で生成画面へ戻る
  - Then 移動前に表示していたプロンプトと同じ内容が入力欄に表示され、初期状態に戻っていないこと
- [ ] AC-2: 複数のプロンプト欄すべてが保たれる
  - Given 生成画面で複数の role（例: 背景・構図・表情）のプロンプト欄を編集している
  - When ほかの画面へ移動して生成画面へ戻る
  - Then すべての欄が移動前と同じ内容で表示されること
- [ ] AC-3: 無効にしたタグの状態も保たれる
  - Given プロンプトのタグの一部を無効（`enabled: false`）にしている
  - When ほかの画面へ移動して生成画面へ戻る
  - Then 有効・無効の状態と並び順が移動前と同じで表示されること
- [ ] AC-4: 複数の画面を経由しても保たれる
  - Given 生成画面でプロンプトを編集している
  - When LoRAs 画面、Tags 画面の順に移動し、同じタブ内で生成画面へ戻る
  - Then 移動前と同じ内容が表示されること
- [ ] AC-5: 複数プリセットのタブごとのプロンプトが保たれる
  - Given 複数のプリセットタブを開いており、タブごとに異なるプロンプトを編集している
  - When ほかの画面へ移動して生成画面へ戻る
  - Then 各タブのプロンプトが移動前と同じで、アクティブなタブも移動前と同じであること
- [ ] AC-6: デスクトップとモバイルの両方で保たれる
  - Given デスクトップ幅とモバイル幅のそれぞれでプロンプトを編集している
  - When ほかの画面へ移動して生成画面へ戻る
  - Then どちらの表示でも AC-1 と同じ結果になること
- [ ] AC-7: 戻った後に生成要求へ使われる内容が表示と一致する
  - Given AC-1 の状態で生成画面へ戻った
  - When 生成を実行する
  - Then 生成要求に含まれるプロンプトが、画面に表示されている有効なタグの内容と一致すること
- [ ] AC-8: 保存状態の表示が移動前と矛盾しない
  - Given 未保存の編集がある状態、または保存済みの状態でほかの画面へ移動した
  - When 生成画面へ戻る
  - Then 未保存・保存済みの状態の表示が移動前と同じで、保存済みの内容を未保存の編集が無断で上書きしていないこと
- [ ] AC-9: テキストモードの選択は従来どおり保たれる
  - Given role ごとのテキストモードを選択している
  - When ほかの画面へ移動して生成画面へ戻る
  - Then テキストモードの選択が移動前と同じであること
- [ ] AC-10: ワークフロー・プリセットの明示的な切替では従来の規則に従う
  - Given 生成画面でプロンプトを編集している
  - When 利用者が別のワークフローまたは別のプリセットへ明示的に切り替える
  - Then 切替先のプロンプトの表示は従来の切替規則に従い、移動前のプロンプトが切替先へ持ち越されないこと
- [ ] AC-11: 明示的な消去・初期化の操作は従来どおり働く
  - Given AC-1 の状態でプロンプトが保たれている
  - When 利用者がプロンプトの消去またはリセットの既存操作を行う
  - Then 入力が消去・初期化され、その後ほかの画面へ移動して戻っても消去した内容が復活しないこと
- [ ] AC-12: 別のブラウザータブの編集に影響しない
  - Given 2 つのブラウザータブで生成画面を開き、それぞれ異なるプロンプトを編集している
  - When 一方のタブでほかの画面へ移動して生成画面へ戻る
  - Then 他方のタブの入力内容が変化せず、戻ったタブにも他方のタブの内容が入り込まないこと

## Inferred points

<inferred_points>
- 利用者の明示要望は「同じタブ内で画面を移って戻っても、編集中のプロンプトが保たれること」。AC-12（別タブへ影響しない）は「同じタブ内」の限定を検証可能にするための BA の提案で、レビューで確認する。
- 要確認事項（再読込）: ブラウザーを再読み込みした後もプロンプトを保つか。現状、テキストモードの選択は再読込で保たれない。再読込で保つ場合は、保存済みのプリセット内容との優先関係を定める必要があり、別の要件になりうる。本 PBI では保つことを要求しない前提で書いた。
- 要確認事項（タブ・端末をまたぐ）: タブを閉じて開き直した場合、別のブラウザータブ、別端末で保持するか。本 PBI では要求しない前提。
- 要確認事項（保持の範囲）: プロンプト以外（パラメータ、シード、チェックポイント選択、適用アセット、バッチ枚数）も画面を移って戻ったときに保つか。現状どうなっているかは未確認で、本 PBI はプロンプトのみを必須とした。
- 要確認事項（自動保存との関係）: SPEC_GENERATE §2-6 の自動保存・Dirty 認識型同期がある中で、画面を移って戻ると入力が初期状態に戻る現象が、どの条件（保存済み・未保存・プリセットの有無）で起こるかは未確認。AC-1 と AC-8 は保存の有無を問わず保持を求める。
- 要確認事項（他画面での変更）: 移動先の画面で、保持されたプロンプトが参照する LoRA や TagSet が削除・名称変更された場合の戻り時の扱いは未定。本 PBI の AC は含めておらず、設計で扱いを決めて必要なら別 PBI とする。
- 要確認事項（保持の期間）: 同じタブ内で、どれだけの間保持するか（セッション中は無期限、メモリ上限、ワークフロー切替時の破棄など）は未確認。
- 「移動」は SPA 内の画面遷移（ナビゲーション操作、ブラウザーの戻る・進む）を想定する。ブラウザーの戻る・進むも含めるかは要確認。
- 要件取りまとめ時点では実装コードは未調査。保持の方式は設計で決める（AC は保持の結果のみを求める）。
</inferred_points>

## 関連仕様・維持契約

- [SPEC_GENERATE §2-3 / §2-6](../../../specs/SPEC_GENERATE.md): `promptChips` の保持規則（アコーディオン開閉、モバイルのタブ切替、Multi-Set 切替・追加・複製で無効タグを破棄しない）、自動保存、Dirty 認識型同期、競合保護を維持する。本 PBI は保持規則に「同じタブ内の画面遷移」を追加する。
- [SPEC_COMMON §2-4](../../../specs/SPEC_COMMON.md): 全ページ共通のルーティングと URL・ナビ構成を変更しない。
- [REQ-309](../archive/REQ-309.md): 範囲外とした baseline からの挙動。REQ-309 の AC を後退させない。
