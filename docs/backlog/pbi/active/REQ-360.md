### REQ-360: SettingsのStage再有効化で個別の有効状態を復元する

- **Type**: feature
- **Status**: new（レビュー待ちの草案。REQ-358の修正と分離し、今は実装しない）
- **Priority**: P3
- **Surface**: SettingsのロールとStage管理
- **Origin**: REQ-358のブラウザ確認で、Stageを再有効化すると元々有効でなかったロール×StageまでActiveになるとのユーザ報告。利用頻度が低いため別PBIへの切り出しを明示依頼。
- **5 Whys / Root Cause**:
  1. Stageを再有効化した後、不要なロール×StageまでActiveになる。
  2. 利用者が個別に選んだ構成を再度手作業で戻す必要がある。
  3. Stageの一時的な利用停止と、個別構成の変更が利用者にとって別の操作だからである。
  4. 復帰時に不要な組合せが増えると、既存構成を信頼して再利用できない。
  5. 必要な運用上の性質は、Stageの一時停止と再開をしても個別の選択を失わないこと。内部原因は未調査。
- **UX Classification**:
  - **Interaction**: Stageの停止・再開を可逆な操作にする。
  - **Information Design**: Stage全体の有効状態と、各ロール×Stageの個別設定を区別する。
  - **Visual**: このPBIで新たな外観変更の要求はない。
- **Requirement**:
  - SettingsでStage全体を無効化しても、各ロール×Stageの個別設定・定義を保持する。
  - 再有効化では、無効化直前に個別に有効だった組合せのみActiveへ戻す。個別に無効だった組合せや未定義の組合せをActiveにしない。
  - 未定義とは利用者がまだ作成していない組合せを指す。Stageの再有効化だけで新たなロール×Stage定義を作成しない。
  - 再開後の個別設定変更は通常どおり可能で、次の停止・再開ではその最新設定を復元対象とする。
  - 保存してSettingsを再表示した後もこの復元ができる。
  - 対象外: ワークフローごとの無効状態、再スキャンモーダルの操作性・性能、スコアバッジ。REQ-358側で扱う。
- **Acceptance criteria**:
  - [ ] AC-1: Given Stage Sが有効で、ロールA×Sは個別に有効、ロールB×Sは個別に無効、ロールC×Sは未定義である, When Sを無効化してから再有効化する, Then A×SのみActiveになり、B×Sは無効、C×Sは未定義のままであること。
  - [ ] AC-2: Given AC-1の構成でSを無効化して保存した状態, When Settingsを閉じて再表示しSを再有効化して保存・再表示する, Then A×SはActive、B×Sは無効、C×Sは未定義であること。
  - [ ] AC-3: Given AC-1の構成, When Sの無効化・再有効化を連続3回行う, Then 各回の再有効化後、A×SはActive、B×Sは無効、C×Sは未定義であること。
  - [ ] AC-4: Given Sと別のStage Tがあり、Sを無効化済みである, When Tの個別設定を変更して保存した後Sを再有効化する, Then Sの各組合せはS無効化直前の個別設定に戻ること。
  - [ ] AC-5: Given Sの定義とロール×Sの設定が保存済みであり、ワークフローWにノード割り当てとワークフロー固有の無効設定が保存されている, When SettingsでSを無効化・再有効化して保存する, Then Wに保存されている割り当てとワークフロー固有の無効設定は操作前と一致すること。
  - [ ] AC-6: Given AC-1の構成を停止・再開した後、有効なSでA×Sを個別に無効、B×Sを個別に有効へ変更し保存した状態, When Sを再度無効化して再有効化する, Then 最新の選択を反映し、A×Sは無効、B×SはActive、C×Sは未定義であること。
- **Inferred points**:
  - 「元々つけてなかったStage」は、ロール×Stageが未定義または個別に無効の双方を含むと仮定する。
  - Stage全体が無効な間は、そのStageの組合せは利用対象外となる。個別設定は再開時のために保持する。
  - 個別設定を変えずにStageを停止・再開したい、という運用上の必要性をユーザ報告から推定した。
  - 既存データで停止直前の個別設定が失われ、履歴を復元できない場合の扱いは未決定。AC-1〜AC-6は個別設定が分かる構成から開始する。履歴不明データの移行方針は実装着手前のレビューで確定する。
  - Stage停止中の個別編集や新規定義追加はこの草案の対象外。必要ならレビューで追加する。
  - ACは同時編集がない単一利用者の順次操作を前提とする。複数利用者の競合解決は対象外。
