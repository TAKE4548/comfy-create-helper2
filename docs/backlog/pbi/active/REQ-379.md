### REQ-379: ComfyUIへの原画確認処理の完全廃止とBE自立キャッシュへの仕様整合

- **Type**: bug (Type B: Specification Gap)
- **Status**: ready
- **Priority**: P1
- **Surface**: backend/app/routers/comfy.py, frontend/src/services/trialImageAvailability.ts, frontend/src/pages/GeneratePage, docs/specs/SPEC_COMMON.md, docs/specs/SPEC_GENERATE.md
- **Incident Report**: docs/incident_report.md
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: REQ-362でゼロプローブ化およびフルサイズWebPキャッシュが導入された後も、Galleryサムネイル表示時にComfyUIへの原画確認プローブ通信（GET /api/comfy/image-availability）が発生し続けているため。
  2. なぜその課題が発生するか: REQ-362で廃止されたのは画像配信エンドポイント（/thumbnail, /view）内のプローブのみであり、REQ-333/345で規定されたGallery試行履歴の原画実在確認（trialImageAvailability）の仕様と実装が残存しているため。
  3. なぜ現状の仕組みで不十分か: BEが最新200件のWebPフルサイズキャッシュとSQLiteメタデータを自立保持しているため、ComfyUI側の元PNGが存在しなくてもプレビュー・閲覧・ワークフロー復元は完結可能であるにもかかわらず、ComfyUI側のファイル掃除等で404になるとBEにキャッシュがある画像まで履歴から消えてしまう不整合が生じるため。
  4. なぜこのアプローチを採用するか: Gallery表示時の原画確認処理およびBE側のavailability確認エンドポイントを全廃し、SSoT（SPEC_COMMON, SPEC_GENERATE）を「BE保持のキャッシュおよびメタデータを正とする」規約へ整合させることで、不要通信の完全根絶と自立キャッシュの整合性を両立できるため。
  5. 根本原因: REQ-362のキャッシュ自立化に伴い不要となった旧世代（REQ-333/345）の原画監視仕様の改定・削除がスコープ外として見送られ、仕様・コード・デッドコード（_check_comfy_exists）が取り残されていたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 試行履歴（Gallery）の表示判定をComfyUIのファイルシステム依存から脱却させ、BE手元のWebPキャッシュおよびメタデータの保持状態を一意の正本（SSoT）とする。
  - **Interaction (インタラクション)**:
    - サムネイル読み込みに伴うバックグラウンドHTTPプローブ（GET /api/comfy/image-availability）を完全撤廃し、無駄なネットワーク負荷や競合をゼロ化。
  - **Visual (視覚デザイン)**:
    - ComfyUI側の出力ディレクトリ掃除後も、BEにキャッシュが存在する直近200件の履歴画像が不意に消えることなく安定して表示され続ける。
- **Requirement**:
  - **1. SSoT（SPEC_COMMON, SPEC_GENERATE）の改定**:
    - 試行履歴サムネイル表示契機での原画実在確認（availability probe）規定を削除し、BE自立キャッシュ（最新200件）を正とする仕様へ改定する。
  - **2. フロントエンド原画確認処理の完全廃止**:
    - `GenerationGallerySection` におけるサムネイルロード契機の原画監視（`observeThumbnail` / `trialAvailability.observe`）および `trialImageAvailability.ts` コントローラーを廃止・整理する。
    - `generationApi.imageAvailability` の呼び出しを撤廃する。
  - **3. バックエンド原画確認エンドポイントおよびデッドコードの撤廃**:
    - `backend/app/routers/comfy.py` の `get_comfy_thumbnail` 内に残存する未使用関数 `_check_comfy_exists` を削除する。
    - `/api/comfy/image-availability` および `probe_image_availability` の不要となった原画プローブ処理を整理する。
- **Acceptance criteria**:
  - [x] AC-1: Given Galleryタブで生成履歴サムネイルが表示・ロードされる, When 画面描画が行われる, Then ComfyUIへの原画確認リクエスト（GET /api/comfy/image-availability）が一切発生しないこと。
  - [x] AC-2: Given ComfyUI側の出力フォルダから元PNG画像が削除されているがBEのWebPキャッシュが存在する状態, When Gallery履歴を表示する, Then 画像が404/missingとして履歴から勝手に除外されることなく正常にプレビュー表示できること。
  - [x] AC-3: Given `backend/app/routers/comfy.py` を静的解析・テストする, When routerコードを検査する, Then 未使用のローカル関数 `_check_comfy_exists` が完全に除去されていること。
  - [x] AC-4: Given `docs/specs/SPEC_COMMON.md` および `docs/specs/SPEC_GENERATE.md`, When 仕様書を照合する, Then サムネイルload/error契機のComfyUI原画実在確認規定がBE自立キャッシュ仕様へ整合して更新されていること。
- **Inferred points**:
  - 保存済みSnapshotについては元々原画確認対象外であったため、本改修による影響はない。
  - BEキャッシュ（200件）からパージされた過去画像についてオンデマンド取得（/view）を試みてComfyUIが404を返した場合は、従来の画像404フォールバック表示がそのまま機能する。
- **Design doc**: docs/design/REQ-379.md
