### REQ-413: ノードマッピングマスタで無効化（is_enabled=false）したステージバリアントがリマッピング画面に表示されないままパラメータ枠に表示・生成注入され続ける不具合

- **Type**: bug (Type A: Implementation Defect)
- **Status**: ready
- **Priority**: P1
- **Surface**: Frontend (`workflowMappingState.ts`, `useWorkflowManagement.ts`, `mappingStageGroups.ts`), Docs (`SPEC_GENERATE.md`, `SPEC_SETTINGS.md`)
- **Incident Report**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. なぜマスタで無効化したステージバリアント（例: BboxThreshold, UpscaleModel, Upscale, FaceDetailer 等の通常/Main無効）が生成画面のパラメータ枠に表示され生成時にも注入されるか: ワークフローの生成用マッピング選別関数 `generationWorkflow` がワークフロー個別の `mapping_slot_states` のみを参照し、マスタ側のバリアント有効フラグ `variant.is_enabled` を確認していないため。
  2. なぜリマッピング画面や配線画面で該当スロットが表示されず、解除もできないか: `useMasterMappingRows`、`RescanModal`、`wiringStageGroups` は `variant.is_enabled !== false` でスロット自体を非表示にし、かつ `useMasterMappingRows.getMappings()` が非表示スロットの既存マッピングを全定義存在チェックのみで無条件に引き継ぎ再保存するため。
  3. なぜ既存ワークフローに無効バリアントのマッピングレコードが残存しているか: V2マッピング移行（step_029）やバリアント無効化前のスキャン保存によりDB（`workflow_mappings`）にレコードが作成された後、マスタ側でバリアントが無効化されてもワークフロー側の `mapping_slot_states` は未設定（`None`）または `true` のままであり、マスタ定義の変更が自動的に生成側マッピング選別へ伝播しないため。
  4. なぜ既存の無効化仕様（REQ-358）でこの問題が防げなかったか: REQ-358はワークフロー個別無効化（`mapping_slot_states`）およびマスタ基本無効（`MappingMaster.default_enabled`）を導入したが、マスタのステージバリアント無効（`MappingVariant.is_enabled`）を `generationWorkflow` や `groupMappingsByStage` の生成・表示用マッピング選別に連携させる契約が欠落していたため。
  5. 根本原因: 生成用マッピング選別（`generationWorkflow` / `useWorkflowManagement`）およびステージグループ分類（`groupMappingsByStage`）におけるマスタ側バリアント有効フラグ（`variant.is_enabled`）の評価欠落、およびリマッピングUIでの非表示と引き継ぎ保存の不整合。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - マスタで無効化されたバリアントに紐づくロールを生成画面のパラメータ枠・プロンプト枠から確実に除外し、リマッピング画面との整合性を確立する。
  - **Interaction (インタラクション)**:
    - リマッピング画面およびSettings配線画面での非表示と、生成画面での非表示が一致し、ユーザーの意図しないマッピングが幽霊のように残り続ける事態を根絶する。
  - **Visual (視覚デザイン)**:
    - パラメータ入力枠（ParamPanel）に無効化済みバリアントが表示されなくなる。
- **Requirement**:
  - **1. SlotDefinition へのマスタ側バリアント有効フラグ連携**:
    - `SlotDefinition` に `variantEnabled?: boolean` を追加し、`useWorkflowManagement` で `mappingMasters` から各バリアントの `is_enabled !== false` を渡す。
  - **2. generationWorkflow における無効バリアントの除外**:
    - `generationWorkflow` で `mapping_slot_states` に加え、対応する `SlotDefinition` が `variantEnabled === false` のマッピング（および解決先バリアントが `variantEnabled === false` のレガシーマッピング）を生成用 mappings から除外する。
  - **3. groupMappingsByStage における無効バリアントの除外**:
    - `groupMappingsByStage` で解決されたバリアントが `is_enabled === false` のマッピングをステージグループ表示および ParamSync 候補から除外する。
  - **4. SSoT 同期**:
    - `docs/specs/SPEC_GENERATE.md` および `docs/specs/SPEC_SETTINGS.md` に、マスタ側で無効化されたバリアント（`is_enabled = false`）の生成用マッピング選別および表示除外契約を追記する。
- **Acceptance criteria**:
  - [ ] AC-1: Given マスタで無効化（`is_enabled = false`）されたステージバリアント（例: 通常/Main の FaceDetailer Steps 等）のマッピングを含むワークフロー, When `useWorkflowManagement` でワークフローを読み込んだとき, Then `workflow.mappings`（`generationWorkflow` による選別後）から当該バリアントのマッピングが除外され、パラメータ入力枠（`paramMappings`）に表示されないこと
  - [ ] AC-2: Given マスタで無効化（`is_enabled = false`）されたステージバリアントのマッピングを含むワークフロー, When 生成処理（`handleGenerateSets` / `injectWorkflowParams`）を実行したとき, Then 当該バリアントに対応するパラメータやプロンプトが ComfyUI ワークフロー JSON へ注入されないこと
  - [ ] AC-3: Given マスタで有効（`is_enabled = true`）なステージバリアントのマッピング, When ワークフローの `mapping_slot_states` で明示的に無効化（`false`）されていないとき, Then 従来通り `workflow.mappings` に保持されパラメータ枠に正常表示されること
  - [ ] AC-4: Given レガシー形式（`variant_id == null`）のマッピングを持つワークフロー, When マスタの対応バリアントが `is_enabled = false` のとき, Then 当該レガシーマッピングも `generationWorkflow` から安全に除外されること
  - [ ] AC-5: Given マスタで無効化（`is_enabled = false`）されたステージバリアントのマッピング, When `useMappingStageGroups` / `groupMappingsByStage` を呼び出したとき, Then 当該マッピングがステージグループ表示および ParamSync 候補に含まれないこと
- **Inferred points**:
  - DB 上の `workflow_mappings` レコード自体は削除せず保持し、マスタ側でバリアントが再有効化された場合には即座に復元・表示されるようにする（REQ-358 / REQ-369 の永続化方針との整合）。
- **Design doc**: docs/design/REQ-413.md
