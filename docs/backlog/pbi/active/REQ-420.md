### REQ-420: SPEC_COMMON.md §1-4 の WorkflowNodePicker 例外記述を現行実装に同期

- **Type**: chore
- **Status**: new
- **Priority**: P3
- **Surface**: docs/specs/SPEC_COMMON.md §1-4
- **Origin**: REQ-419 クローズ時の後続対応事項
- **5 Whys / Root Cause**:
  1. なぜ必要か: SPEC_COMMON.md §1-4 に「唯一の例外は MappingMasterEditModal 内の WorkflowNodePicker で共通Modalをネストし、外側は closeOnEsc={!isNodePickerOpen}」という記述が残っている。
  2. なぜ発生したか: REQ-419 で編集モーダル内の WorkflowNodePicker 利用を撤去し SPEC_SETTINGS §3-2 からは例外を削除したが、SPEC_COMMON.md は REQ-419 の設計対象外だった。
  3. なぜ不十分か: SPEC_SETTINGS §3-1-1 が「詳細は SPEC_COMMON §1-4」と参照しており、正本仕様間で矛盾する（REQ-419 文書レビュー F-1）。
  4. なぜこのアプローチか: 仕様の文言を現行実装に合わせる文書同期のみで解消でき、コード変更を要しない。
  5. 根本原因: 横断仕様（SPEC_COMMON）の参照元が設計時の影響範囲から漏れた。
- **UX Classification**:
  - Information Design: 開発者が読む正本仕様の整合性（ユーザー画面への変化なし）
- **Requirement**:
  - **1. ネスト例外記述の削除・更新**:
    - §1-4 L56 の「唯一の例外は MappingMasterEditModal 内の WorkflowNodePicker」とその Esc 制御（closeOnEsc={!isNodePickerOpen}）の記述を削除し、Settings からのモーダルは例外なくネストしないと記述する。
  - **2. モーダル列挙の確認**:
    - §1-4 L53 のモーダル列挙のうち、現行の Settings 関連コードから到達しないモーダル（WorkflowNodePicker を含む）は列挙から削除する。
- **Acceptance criteria**:
  - [ ] AC-1: Given REQ-419 後の SPEC_COMMON.md §1-4, When モーダルのネスト規則を読む, Then MappingMasterEditModal 内で WorkflowNodePicker をネストして開くという例外記述が存在しないこと
  - [ ] AC-2: Given SPEC_COMMON.md §1-4 のモーダル列挙, When 列挙された各モーダルを確認する, Then 現行の Settings 関連コードから到達しないモーダルが列挙に含まれていないこと
  - [ ] AC-3: Given SPEC_SETTINGS §3-1-1 と §3-2 および SPEC_COMMON §1-4, When モーダルのネスト可否を比較する, Then 3箇所の記述が矛盾しないこと
- **Inferred points**:
  - これらの更新により、SPEC_COMMON §1-4 と SPEC_SETTINGS §3-1-1・§3-2（REQ-419 で例外を削除済み）の記述が一致する。
  - WorkflowNodePicker.tsx 自体の削除（未参照コンポーネントの整理）は本 PBI の対象外とし、必要なら別途扱う。
  - SPEC_SETTINGS frontmatter related_paths の WorkflowNodePicker.tsx（文書レビュー F-4）も同時に整理してよい。
