### REQ-410: 任意ノードのComfyUIセレクタ動的取得型カスタムパラメータ対応

- **Type**: feature
- **Status**: frontmatter の `status` を参照（状態の正本）。
- **Priority**: P2
- **Surface**: 設定画面のカスタム型マスタ管理モーダル（`ParamTypeMasterManagerModal`, `ParamTypeMasterModal`）および生成画面のパラメータ入力パネル（`ParamPanel`）。
- **利用者ニーズ**: チェックポイントやモデル等のセレクタの選択肢をComfyUIからリアルタイムに動的取得したい。個別ノード専用のビルトイン型をコードにハードコードしなくても、設定画面で任意のノードを選択して動的に選択肢を取得するセレクタ型を自由に追加・利用できるようにしたい。
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: チェックポイントやカスタムノードのモデル等の選択肢がComfyUI側で変更（追加・削除）されても、静的保存された `combo_options` では自動追従されず、毎回手動で設定画面を開いて再保存しなければ古い選択肢のままになるため。
  2. なぜ静的保存になっているのか: 設定画面のAuto-Fill機能が、設定時点のComfyUI `/object_info` から取得した選択肢リストを固定文字列（`combo_options`）としてDBに保存しているため。
  3. なぜ既存のビルトイン動的型（`select_sampler`, `select_scheduler`）の追加では不十分なのか: ComfyUIには多様なノード（`CheckpointLoaderSimple`, `VAELoader`, `CLIPLoader`, 各種カスタムノード等）が存在し、それぞれに対して個別のビルトイン型をコードへハードコードすると保守負荷が増大し、任意のノードに柔軟に対応できないため。
  4. なぜ設定画面で任意ノードを選択してセレクタ型を追加するアプローチを採用するのか: ユーザーが利用するワークフローに合わせて、設定画面から「どのノードクラス・パラメータから選択肢を動的に取得するか」を指定したカスタムパラメータ型を登録できるようにすることで、コード改修なしで任意のセレクタをComfyUIとリアルタイム同期できるため。
  5. 根本原因: カスタムパラメータ型（`ParamTypeMaster`）に「ComfyUIから実行時に選択肢を動的取得するセレクタ」を表現するメタデータと、生成画面での動的取得・フォールバック機構が存在せず、静的配列の保持またはコードへの個別ビルトイン型ハードコードに依存していたこと。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - カスタムパラメータ型における動的取得属性（対象ノードクラス型、パラメータ名、動的フラグ等）の定義。
    - 設定画面一覧・編集フォームでの動的セレクタ型と静的セレクタ型の識別表示（対象ノード情報の可視化）。
    - 生成画面での動的取得ドロップダウンの選択肢表示、およびオフライン時フォールバック状態の明示。
  - **Interaction (インタラクション)**:
    - 設定画面（`ParamTypeMasterModal`）で、ノードとパラメータを選択して動的セレクタ型を作成・編集・保存する操作。
    - 生成画面（`ParamPanel`）で、動的セレクタ型パラメータ描画時にComfyUIから最新選択肢を取得してドロップダウンに反映する操作連動。
    - ComfyUI未接続（オフライン）時や取得失敗時に、クラッシュせず安全にフォールバック表示する操作性。
  - **Visual (視覚デザイン)**:
    - 設定一覧での動的セレクタであることを示すバッジやノード名の明瞭な視覚表現。
    - 生成画面ドロップダウンでの読み込み中（ローディング）およびオフライン時の適切なフィードバック。

## 範囲

- **対象**:
  - 設定画面における「任意のComfyUIノードのパラメータから選択肢を動的取得するセレクタ型」の作成・編集・削除・一覧表示。
  - 生成画面における動的セレクタ型パラメータの最新選択肢の動的取得・ドロップダウン表示。
  - ComfyUI未接続（オフライン）時・取得失敗時のフォールバック保護。
  - 選択値のプリセット保存・自動保存・ComfyUI生成投入への正常伝播。
- **対象外**:
  - ComfyUIの `/object_info` 以外の独自外部APIからの選択肢取得。
  - 既存の静的 `combo_options` 型や既存ビルトイン型（`select_sampler`, `select_scheduler`, `seed` 等）の廃止（共存して後方互換性を維持する）。
  - ノード自体の実行グラフ構造やバイパス設定の変更。

## 要件詳細

1. **設定画面での動的セレクタ型定義**:
   - `ParamTypeMaster` の作成・編集において、ComfyUIノードのクラス型（`class_type`）およびパラメータ名（`param_name`）を紐づけた動的セレクタ型を登録・更新できること。
   - 既存のAuto-Fill操作から、検出されたノード・パラメータ情報を利用して動的取得設定を容易に行えること。
   - 従来の静的選択肢（手動入力の `combo_options`）型も引き続き作成・編集・保持できること。
2. **生成画面での動的取得と表示**:
   - ワークフローにマッピングされたパラメータが動的セレクタ型の場合、生成画面描画時にComfyUIの最新情報（`/object_info` 等）から対象ノード・パラメータの選択肢一覧を取得してドロップダウンに表示すること。
   - ComfyUI側でチェックポイントやモデル等の選択肢ファイルが追加・削除された場合、設定画面を再保存しなくても、生成画面の再読込や画面遷移で最新選択肢が反映されること。
3. **オフライン・取得失敗時のフォールバック保護**:
   - ComfyUIがオフライン、接続不能、または対象ノード情報が取得できない場合でも、UIがエラーでクラッシュせず、フォールバック選択肢（静的キャッシュ値等）を表示して操作を継続できること。
   - 選択肢取得中または失敗時に、プリセット等に保存済みの既存パラメータ値が勝手にクリア・上書きされないこと。
4. **互換性と既存契約の維持**:
   - 既存のビルトイン型（`select_sampler`, `select_scheduler` 等）および静的カスタム型の動作を維持すること。
   - 選択された値は既存のパラメータ値として正常にプリセット保存・生成投入されること。

## Acceptance Criteria

- [ ] AC-1: 設定画面でノードを指定した動的セレクタ型を作成・保存できる
  - Given 設定画面のカスタム型マスタ作成モーダルを開いている
  - When 任意のノードクラス（例: `CheckpointLoaderSimple`）と対象パラメータ（例: `ckpt_name`）を指定し、動的セレクタ型として保存する
  - Then 新規カスタムパラメータ型が動的取得設定（ノードクラス型とパラメータ名）を保持して保存され、一覧に正しく表示されること
- [ ] AC-2: 設定画面のAuto-Fillから動的セレクタ型を設定できる
  - Given カスタム型マスタ編集モーダルでAuto-Fill機能を使用している
  - When comboパラメータを持つノードを選択してAuto-Fillを実行する
  - Then 検出されたノード情報をもとにComfyUI動的取得型として設定・保存できること
- [ ] AC-3: 既存の静的セレクタ型（手動combo_options）の作成・編集が維持される
  - Given カスタム型マスタ作成・編集モーダルを開いている
  - When 動的取得を指定せず、従来どおり改行区切りの固定テキスト（`combo_options`）を入力して保存する
  - Then 従来の静的セレクタ型として正常に保存・更新され、一覧および生成画面で固定選択肢が表示されること
- [ ] AC-4: 生成画面で動的セレクタパラメータにComfyUIの最新選択肢が表示される
  - Given 動的セレクタ型（例: チェックポイント選択）がマッピングされたパラメータを持つワークフローが選択されている
  - When 生成画面を表示する
  - Then ドロップダウンにComfyUIから動的に取得された最新の選択肢一覧が表示されること
- [ ] AC-5: ComfyUI側のモデル・ファイル増減が設定再保存なしで反映される
  - Given 動的セレクタ型パラメータが生成画面に表示されている
  - When ComfyUI側で新しいモデルやファイルが追加された状態で生成画面を再読み込みまたは表示更新する
  - Then 設定画面での再保存やコード変更を行わなくても、追加された最新の選択肢がドロップダウンに現れること
- [ ] AC-6: ComfyUIオフライン・未接続時に安全にフォールバックする
  - Given ComfyUIサーバーがオフラインまたは未接続である
  - When 動的セレクタ型パラメータを含む生成画面を表示する
  - Then 生成画面がエラーでクラッシュせず、フォールバック選択肢（キャッシュまたは直近保存値）が安全に表示されること
- [ ] AC-7: 動的セレクタで選択した値がプリセット保存および生成投入に正常に反映される
  - Given 生成画面で動的セレクタから特定の値を選択している
  - When プリセット保存および生成実行を行う
  - Then 選択された値がプリセットのパラメータ値として正常に保存され、ComfyUIへの生成投入パラメータとして正常に送信されること
- [ ] AC-8: 選択肢の非同期取得時に既存の保存済み値が破棄されない
  - Given 既存のプリセットに有効な値が保存されている状態で生成画面を開く
  - When 動的セレクタの選択肢がComfyUIから非同期に取得・更新される
  - Then 取得完了前後で、プリセットで選択済みの値が未選択や空値に勝手にリセットされないこと
- [ ] AC-9: 既存ビルトイン型および既存静的カスタム型との後方互換性が保たれる
  - Given 既存のビルトイン型（`select_sampler`, `select_scheduler`, `seed` 等）または既存の静的カスタム型がマッピングされている
  - When 設定画面および生成画面でそれぞれのパラメータを操作・保存・生成する
  - Then 従来の表示・選択・保存・生成動作が損なわれず正常に機能すること

## Inferred points

<inferred_points>
- データモデル拡張の仮定: `ParamTypeMaster` に動的取得元のノード情報（例: `dynamic_class_type?: string`, `dynamic_param_name?: string`、または `is_dynamic: boolean` 等）を保持するスキーマ拡張が必要と想定される。具体的なカラム設計やDBマイグレーションの仕様は dev-design フェーズで策定する。
- 動的取得元APIの仮定: ComfyUIの `/object_info` から `object_info[class_type].input.required[param_name][0]`（または optional）の配列を取得する方式を基本想定とする。フロントエンドで既存の `comfyApi.getObjectInfo` またはバックエンドプロキシ経由でキャッシュ活用しながら取得することが期待される。
- オフライン時のフォールバック方針: Auto-Fill時または直近取得成功時の選択肢を `combo_options` カラム等に保持しておき、ComfyUIオフライン時にはそのキャッシュをフォールバックとしてドロップダウンに表示する設計が安全なUXとして想定される。
- ユーザーによる任意指定の範囲: ComfyUIの `/object_info` に存在する任意のノードクラスおよび入力comboパラメータを対象とする。標準ノード（CheckpointLoaderSimple, VAELoader, CLIPLoader等）だけでなく、ユーザーが導入している任意のカスタムノード（ControlNet, IP-Adapter, UpscaleModel等）も同一の仕組みで対応可能とする。
- UI表示の識別性: 設定画面の型マスタ一覧において、どの型が静的でどの型がどのノードから動的取得するものかをユーザーが容易に判別できるよう、バッジやノード名の表示を設けることが推奨される。
</inferred_points>
