### REQ-297: プリセット一括編集モーダルの利便性向上 (入力クリア・自動閉じ抑止・サブセット抽出・対象排他制御・パラメータ検索・タグ操作統一)

- **Type**: enhancement
- **Status**: new (2026-09-30)
- **Priority**: P2
- **Surface**: 生成画面のプリセット一括編集モーダルにおいて、連続編集時の自動クローズ、前回の入力・選択状態の残留による手動リセットの煩わしさ、複数入力欄への意図しない上書き事故リスク、大量パラメータからの探索コスト、共通タグのサブセット抽出不可およびタグ編集操作の不整合により、一括編集作業の効率と操作性が低下している。
- **5 Whys Analysis**:
  1. *Why*: プリセット一括編集モーダルでの作業効率が悪いのはなぜか？
     → 入力欄や選択のクリア、対象プリセットの絞り込み、目当てのパラメータ探索に多数の手動ステップを要し、一度適用するとモーダルが閉じてしまうため。
  2. *Why*: なぜ手動ステップが増えてしまうのか？
     → プロンプト入力欄にワンクリッククリアがなく、パラメータ編集では適用後も選択チェックが残り続け、プロンプト対象欄も全選択がデフォルトになっているため。
  3. *Why*: なぜ適用後にモーダルが閉じてしまうのか？
     → 単発の適用完了でタスク終了とみなす前提で設計されており、プロンプト・パラメータ・共通タグを連続して段階的に編集するワークフローに対応していないため。
  4. *Why*: なぜ共通タグ編集で最初の全選択から外せないのか？
     → 共通タグ抽出ロジックがモーダル起動時の外部選択状態（全選択）に強く依存しており、モーダル内部で対象プリセットを動的にサブセット化するUI/状態管理がないため。
  5. *Why*: なぜ共通タグのクリック操作がプロンプト欄と異なっているのか？
     → タグクリックが単純な削除トグルとして実装されており、プロンプト欄のタグチップで提供されているサブメニュー（強度調整・文言編集・削除等の一元管理）が再利用されていないため。
- **UX Classification**:
  - **Interaction Design**:
    - [プロンプト編集] 入力欄のワンクリック「クリア」ボタン提供（前回の入力値保持は維持しつつ明示的クリアを可能に、空欄時は非活性/非表示）
    - [パラメータ編集] 一括編集の適用成功時におけるパラメータ選択状態（チェックボックス）の自動全解除
    - [モーダル共通] 適用実行後の自動モーダルクローズ抑止（ユーザーの明示的操作でのみ閉じる）
    - [プロンプト編集] 編集対象欄の排他・複数選択制御（「置換」モードのみ複数選択可能、それ以外の「上書き」「追加」等は単一排他選択。複数選択状態から単一モードへ切り替えた際は先頭1件にフォールバック）
    - [共通タグ編集] タグチップのクリック操作統一（削除トグル廃止、クリック/タップでプロンプト同様のサブメニュー展開・編集・強度調整。削除はチップ上の削除アイコンまたはサブメニュー内の削除操作に一元化）
  - **Information Design**:
    - [共通タグ編集] モーダル内での対象プリセットサブセット選択UI（動的な共通タグ再集計・反映）
    - [パラメータ編集] パラメータ一覧上部のインクリメンタル検索ボックス（パラメータ表示名またはキーの部分一致フィルタリング、該当なし時の空メッセージ表示）
  - **Visual Design**:
    - クリアボタン・検索ボックス・サブセット選択UIの直感的な配置とレイアウト統一
- **Scope & Section Boundaries**:
  - 本モーダルは明確に「プロンプト一括編集」「共通タグ編集」「パラメータ一括編集」のセクションに責務が分離されている。
  - 各機能のスコープ境界：
    1. プロンプト入力クリアボタン: プロンプト編集タブ内の各入力欄にスコープ限定（他タブや検索欄には影響しない）。
    2. パラメータ検索欄: パラメータ編集タブ内の項目表示フィルタリングにスコープ限定（チェック状態の有無には影響せず、適用はチェックが入っている全パラメータに対して実行される）。
    3. 共通タグサブセット選択: 共通タグ編集タブ内でのみ対象プリセットの絞り込みを行い、共通タグの再集計と適用対象を決定する。
    4. 共通タグ削除とサブセットの独立性: サブセット選択は「どのプリセットを対象にするか」の母集団決定であり、タグチップの削除アイコン/メニュー操作は「対象プリセットからそのタグを削除する」編集操作である。
- **Acceptance criteria**:
  - [ ] AC-1 (プロンプト入力クリア):
    - **Given**: プロンプト編集欄にテキストまたはタグが入力されている。
    - **When**: 該当入力欄の「クリア」ボタンを押下する。
    - **Then**: 該当入力欄の入力内容が即座に空になる。
    - **And**: クリアを押さずにモーダルを閉じ再度開いた場合は、前回入力値が保持されている。
  - [ ] AC-2 (パラメータ選択の自動解除):
    - **Given**: パラメータ編集画面で1つ以上の項目にチェックが入っている。
    - **When**: 「一括適用」を実行し正常終了する。
    - **Then**: すべてのパラメータ項目の選択状態（チェックボックス）が未選択（解除）状態に自動リセットされる。
  - [ ] AC-3 (適用後のモーダル維持):
    - **Given**: プロンプト編集、パラメータ編集、または共通タグ編集のいずれかの画面。
    - **When**: 「一括適用」を実行し正常終了する。
    - **Then**: モーダルは閉じずに開いた状態を維持し、適用成功のトーストまたは通知が表示される。
    - **And**: モーダルは閉じるボタン（×）、キャンセルボタン、またはESCキー押下でのみ閉じる。
  - [ ] AC-4 (共通タグのサブセット抽出):
    - **Given**: 共通タグ編集画面で複数のプリセットが初期選択されている。
    - **When**: プリセットサブセット選択UIで特定のプリセットのチェックを外す。
    - **Then**: 現在チェックされているサブセットのプリセット群に共通するタグのみが即座に再抽出されて表示される。
    - **When**: 共通タグ編集を適用する。
    - **Then**: チェックされているサブセットのプリセット群に対してのみタグ編集が反映される。
  - [ ] AC-5 (プロンプト対象欄のモード別排他制御):
    - **Given**: プロンプト編集画面。
    - **When**: 編集モードが「置換」の場合、対象入力欄（ポジティブ/ネガティブ等）を複数同時に選択できる。
    - **When**: 編集モードが「上書き」「先頭に追加」「末尾に追加」のいずれかの場合、対象入力欄は排他的（単一選択ラジオ動作）となり、同時に1つしか選択できない。
    - **And**: 複数選択状態で単一選択モードへ切り替えた場合、選択状態は先頭の1件のみが維持される。
  - [ ] AC-6 (パラメータ検索フィルタ):
    - **Given**: パラメータ編集画面。
    - **When**: パラメータ検索ボックスに文字列を入力する。
    - **Then**: パラメータの表示名またはキーに部分一致する項目のみにリアルタイムで絞り込まれる（該当なし時はメッセージ表示）。
    - **When**: 検索ボックスの入力を空にする。
    - **Then**: すべてのパラメータ項目が再表示される。
    - **And**: 検索フィルターの状態はパラメータの選択（チェック）状態や適用対象の判定には影響しない。
  - [ ] AC-7 (共通タグのサブメニュー編集統一):
    - **Given**: 共通タグ編集画面に共通タグチップが表示されている。
    - **When**: タグチップの本体（削除アイコン以外）をクリック/タップする。
    - **Then**: タグ編集サブメニューがポップオーバー表示され、タグ文言の編集および強度変更（連続/ステップ指定）が行える。
    - **And**: タグチップ本体クリックで削除トグルは発生せず、削除はタグチップ上の独立した削除アイコンまたはサブメニュー内の削除操作でのみ実行される。
  - [ ] AC-8 (品質検証):
    - **Given**: 実装完了後のリポジトリ。
    - **When**: cd frontend; npm run typecheck および 
pm test を実行する。
    - **Then**: 型エラーおよびテスト失敗が0件である。
