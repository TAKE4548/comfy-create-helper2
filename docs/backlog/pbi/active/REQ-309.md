### REQ-309: フロントエンド初回読み込み量の削減

- **Type**: refactor
- **Status**: ready
- **Surface**: 本番ビルドで初回表示に使われる JavaScript が 1,261.71 kB（gzip 335.43 kB）となり、Vite の 500 kB 超警告が出ている。これは表示速度の実測値ではなく、初回読み込み量が大きいことを示す兆候である。
- **Desired outcome**: 利用者が最初の画面を開く際の読み込み量を減らし、画面遷移後も既存の操作を継続できる。
- **UX Classification**:
  - **Interaction**: 初回表示に必要なデータだけで操作を始められ、別画面へ移ったときも必要な画面を正常に操作できる。
- **5 Whys Analysis**:
  1. なぜリファクタが必要か：本番ビルドで JavaScript の大きさに関する警告が出ているため。
  2. なぜ大きさが問題か：初回表示前に取得・処理する量が増え、環境によって操作開始が遅くなる可能性があるため。
  3. なぜ操作開始への影響を減らしたいか：最初の画面を開くたびに不要な待ち時間があると、日常の生成作業の開始を妨げるため。
  4. なぜ警告だけを消すのでは足りないか：ファイルの分割だけで初回に全て取得すれば、利用者の読み込み量は減らないため。
  5. 根底の業務ニーズ：生成作業に入るまでの待ちを短くし、必要な画面を引き続き利用できること。
- **Requirement**:
  - 本番ビルドの初回画面で取得する JavaScript の総量を、現状のビルドより減らす。
  - 各画面は利用時に正常に表示・操作でき、プロンプト編集、チェックポイント選択、生成、履歴閲覧、設定操作の既存の動作を維持する。
  - ビルド時の 500 kB 超警告を、警告閾値の引き上げや警告の非表示に頼らず解消する。ただし、警告の消失だけを初回読み込み量削減の代わりとしない。
- <inferred_points>
  - ユーザーの「リファクタとしてPBIにしておいて」は、直前に説明した JavaScript バンドルサイズ警告の改善を指すと解釈した。
  - 遅さの体感報告や実測値はない。性能改善は初回に取得する JavaScript の総量で判定し、表示時間の改善を保証する要件にはしない。
  - 基準値は今回のビルドの 1,261.71 kB（gzip 335.43 kB）の JavaScript とする。初回取得量の比較は同じブラウザ設定・空キャッシュ・同じ初期画面・同じ計測条件で行う。
  - 対象はフロントエンドの本番配布物であり、API応答時間や画像データの最適化は対象外と仮定する。
  </inferred_points>

#### Acceptance Criteria (AC)

- [ ] **AC-1（初回取得量）**
  - **Given**: 改修前後の本番ビルドを同じブラウザ設定、空キャッシュ、同じ初期画面で開く。
  - **When**: 初期画面のプロンプト入力欄が編集可能になるまでにブラウザのネットワーク記録で取得した JavaScript の転送量の合計を比較する。
  - **Then**: 改修後の JavaScript 転送量の合計は、改修前の合計より小さい。
- [ ] **AC-2（ビルド警告）**
  - **Given**: フロントエンドの本番ビルドを実行する。
  - **When**: ビルドが完了する。
  - **Then**: ビルドは成功し、警告閾値を引き上げたり警告を非表示にしたりせず、500 kB 超の JavaScript チャンクに関する警告が表示されない。
- [ ] **AC-3（初期画面の編集）**
  - **Given**: 改修後の本番配布物を空キャッシュで開く。
  - **When**: 利用者が初期画面でプロンプトを編集する。
  - **Then**: 編集した内容が入力欄に保持される。
- [ ] **AC-4（チェックポイント選択と生成）**
  - **Given**: 改修後の本番配布物を開き、生成可能な設定が揃っている。
  - **When**: 利用者がチェックポイントを選択して生成を開始する。
  - **Then**: 選択したチェックポイントで生成が開始される。
- [ ] **AC-5（履歴画面）**
  - **Given**: 改修後の本番配布物で初期画面を開いている。
  - **When**: 利用者が履歴画面を開く。
  - **Then**: 履歴画面が表示され、既存の履歴項目を閲覧できる。
- [ ] **AC-6（設定画面）**
  - **Given**: 改修後の本番配布物で初期画面を開いている。
  - **When**: 利用者が設定画面を開く。
  - **Then**: 設定画面が表示され、既存の設定項目を閲覧できる。

- **BA Audit Outcome**: 2026-10-02 の初回監査は ComfyUI の VRAM 使用により `VRAM_GUARD_BUSY` で中止。2026-10-03 に監査を再試行し、指摘を反映して再監査まで完了。各回の直後にモデルをアンロードして VRAM 解放を確認した。初回の有効な監査が指摘した AC-1 の判定点と AC-2 の警告抑止による見かけ上の解消は、プロンプト入力欄の編集可能時点と警告設定を変えない条件で解消した。再監査では要件の論理矛盾は指摘されなかった。500 kB 警告はビルド出力の非圧縮チャンクサイズに対するものとし、335.43 kB は同じ出力の gzip サイズである。再監査の DOMContentLoaded 指標への変更、圧縮方式・HTTPプロトコルの固定、動的importの必須化、ComfyUIのVRAM対策は、初回操作までの転送量という受入目的に直結しないため採用しない。PBI はユーザーレビュー待ちの draft とする。
