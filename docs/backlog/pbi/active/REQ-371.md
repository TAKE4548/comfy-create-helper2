### REQ-371: モバイルGenerate：テキスト層による生成ボタンの被覆修正と固定方法の見直し

- **Type**: bug
- **Status**: ready
- **Priority**: P2
- **Surface**: モバイルGenerate（幅767px以下）のテキスト・プロンプト編集領域と生成ボタン領域。固定方法、スクロール領域、重なり順、共通 `TagChipEditor` が関与する可能性を設計フェーズで調査する
- **Reference**:
  - docs/design/mobile-ui-redesign/mobile-generate-redesign-proposal.md（§10 追加修正対象）
  - docs/design/mobile-ui-redesign/mobile-common-ui-redesign-proposal.md（COMMON-03 / COMMON-07 / C-AC-03）
  - docs/specs/SPEC_GENERATE.md（§3 モバイルレイアウト：アクションバー維持・下部余白）
  - docs/specs/SPEC_COMMON.md（§3 TagChipEditor、§1-5 モバイル アンチパターン）
- **5 Whys / Root Cause**:
  1. なぜ修正が必要か: モバイルGenerateでプロンプト欄をスクロールすると、チップに限らずテキストのレイヤが画面下部の固定生成バーのボタンに被って描画され、生成・保存・キューのボタンが見えない／押しにくいため（ユーザーによる実画面での報告）。
  2. なぜその課題が発生するか: テキスト・編集領域と生成ボタン領域の重なりが適切に制御されていないため。ボタン領域の固定方法にも問題がある可能性があるが、原因は未特定であり、DOM・CSS・スクロール構造を調査する。
  3. なぜ現状の仕組みで不十分か: 既存仕様は「固定バーに内容が隠れない下部余白」を定めるが、テキスト層の被覆防止と、固定方法・スクロール領域・ボトムナビとの組合せの妥当性が十分に確認されていない。
  4. なぜこのアプローチを採用するか: 生成操作は主要導線であり、重なり順の不具合は操作不能に直結するため、UI全面刷新（REQ-372/373）とは独立して先行修正できる単位にする。
  5. 根本原因: 未特定。実画面・DOM・CSSの照合で設計フェーズに特定する（BAはコード非参照のため断定しない）。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 固定操作（生成・保存・キュー）が常に視認できる階層を保つ。
  - **Interaction (インタラクション)**:
    - 固定バーのタップを背面のテキスト・編集領域やタグチップが奪わない。タグ編集サブメニュー・ドラッグ・入力を維持する。
  - **Visual (視覚デザイン)**:
    - スクロール中の重なり順（固定バーが手前）。
- **Requirement**:
  - **1. 生成ボタン領域の視認性と操作性**: テキスト、入力・選択表示、通常・選択中・ドラッグ中のタグチップなどの背面コンテンツは生成ボタン領域を覆わず、ボタンの表示とタップを妨げない。
  - **2. 既存機能の維持**: タグ編集サブメニュー、ドラッグ並べ替え、入力、ソフトキーボード表示中の挙動を維持する。
  - **3. 共通部品の扱い**: 原因が共通 `TagChipEditor` やドラッグ／ポップオーバー基盤にある場合は、Generate専用の無根拠な例外を作らず、他の利用画面（Tag Set作成・編集など）を含めて影響を確認する。
  - **4. ボタン領域の固定方法の見直し**: 重なり順だけに原因を限定せず、配置先・包含要素・スクロール領域・固定位置・背景・必要な下部余白を調査し、現行デザインルールに沿って見直す。具体的なCSS方式は設計で決定し、主要操作へのアクセス、ボトムナビ、セーフエリア、ソフトキーボードとの整合を保つ。
- **Acceptance criteria**:
  - [ ] AC-1: Given 幅767px以下のGenerateでテキスト・入力表示・タグチップを含むプロンプト欄に生成ボタン領域の位置まで届く量の内容がある, When プロンプト領域を上下にスクロールし、各テキスト層・入力表示・チップの描画領域の一部が生成ボタン領域に入る位置を通過させる, Then 背面コンテンツの文字や装飾がボタンに被らず、生成・保存・キューの各ボタンが全面視認できること。
  - [ ] AC-2: Given AC-1と同じ状態, When 固定生成バーの各ボタン（生成・保存・キュー）の上をタップする, Then タップは常にそのボタンが受け取り、背面のテキスト・入力・タグチップの操作は発火しないこと。
  - [ ] AC-3: Given タグチップをドラッグ中, When ドラッグ中のチップを移動し、チップの描画領域の一部が固定生成バーの領域に入る位置まで持っていく, Then ドラッグ中のチップが固定生成バーの前面に描画されず、ドラッグ並べ替えは従来どおり完了できること。
  - [ ] AC-4: Given 固定生成バーの近くにあるタグチップ, When チップのサブメニュー編集を開く, Then サブメニューの操作項目が固定生成バーに隠れて押せなくなることがなく、従来どおり編集・削除・入力フォーカス・ソフトキーボード表示中の入力ができること。
  - [ ] AC-5: Given 幅360px、セーフエリアあり、ボトムナビ表示の状態, When AC-1〜AC-4を実行する, Then 同じ結果になり、見直した生成ボタン領域とボトムナビの配置が現行仕様（SPEC_COMMON §2-4 / SPEC_GENERATE §3）に整合し、相互の被覆・操作不能・不要な隙間や二重の下部余白が生じないこと。
  - [ ] AC-6: Given 修正が共有の `TagChipEditor` またはドラッグ／ポップオーバー基盤に及ぶ, When Tag Set作成・編集画面を開く, Then チップの表示・サブメニュー編集・ドラッグ・削除・入力・折返しが従来と同等に動作し、影響した画面の一覧が設計に記録されていること。
  - [ ] AC-7: Given 幅768px以上（PC）またはGenerate以外の画面, When 同様に操作する, Then 表示と操作が修正前から変化しないこと。
  - [ ] AC-8: Given 見直した生成ボタン領域を表示したモバイルGenerate, When ページ・編集領域を上下および末尾までスクロールし、ソフトキーボードの表示・非表示を切り替える, Then 各状態で主要ボタンが現行デザインルールに沿って到達・操作可能であり、テキスト層の被覆、ボトムナビとの重複、入力末尾の到達不能がないこと。固定方法とその採用理由、スクロール領域との関係を設計に記録すること。

## 個別レビュー決定（2026-10-26）

- ユーザーから「現在もチップというか、テキストのレイヤがボタンに被っている」と現行の実画面報告があり、その修正として継続する判断を受けた。チップ限定の旧表題と対象をテキスト層全般へ見直した。
- 「ボタン部分の固定の仕方が不適切かもしれないので、それの見直しも」との指示を受け、固定方法・包含要素・スクロール構造等の調査と必要な見直しを要求4・AC-8へ追加した。固定方法が原因と確定したわけではなく、特定のCSS方式は指定しない。
- P2・readyを維持。現行ACは8件。既存のチップ編集・ドラッグ・共通部品・PCの非回帰要求を維持し、AC-1/2をテキスト層へ拡張、AC-5を見直し後の配置整合へ更新した。
- 今回は要求整理のみ。エージェントによる現行実装調査・実ブラウザでの再現・テスト・新規監査は未実施。過去のISSUES_FOUNDと、その指摘を設計で扱う既存承認は継続し、新たな監査PASSとはしない。
