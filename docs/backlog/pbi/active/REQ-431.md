### REQ-431: モバイル生成プレビューの左右スワイプ画像送りおよびボトムシートのスワイプダウン閉じる対応

- **Type**: feature
- **Priority**: P2
- **Surface**: Generate ページのモバイルレイアウト（画面幅 768px 未満）における画像ボトムシート（`MobileImageSheet`、SPEC_GENERATE §3-4）および全画面ビューア（SPEC_GENERATE §3-5）、ならびに履歴3列グリッド（`GenerationGallerySection`、SPEC_GENERATE §3-3）
- **5 Whys / Root Cause**:
  1. なぜ新設・改修が必要か: モバイル表示（幅768px未満）の生成プレビュー（画像ボトムシートおよび全画面ビューア）で複数の生成画像を比較・確認する際、毎回シートを閉じて別のサムネイルをタップし直す必要があり手間がかかる。また、他のボトムシート（REQ-408準拠）と同様にプレビュー用ボトムシートを下方向スワイプで閉じようとしても閉じられないため。
  2. なぜその課題が発生するか: REQ-372 で常駐プレビューを撤去して「3列サムネイル → 画像ボトムシート → 全画面ビューア」のフローを導入した際、ボトムシートおよび全画面ビューアは単一画像の拡大表示のみを想定して定義され、スワイプによる前後画像送りが未定義だった。また、共通Modalには REQ-408 でスワイプダウン閉じるジェスチャーが導入されたが、画像ボトムシートは独自シート構造のため同ジェスチャーが備わっていない。
  3. なぜ現状の仕組みで不十分か: モバイルで複数の生成結果を素早く見比べる操作ができず、PCの連続横スクロールリールに相当する軽快な閲覧体験が欠けている。加えて、ボトムシートの閉じる操作が閉じるボタン・バックドロップタップ・Escキーに限られ、アプリ内の他ボトムシートと操作感が一貫していない。
  4. なぜこのアプローチを採用するか: ボトムシートおよび全画面ビューアの両方に左右スワイプによる画像送り（左スワイプで1つ古い画像へ、右スワイプで1つ新しい画像へ移動し、端で停止）を追加し、ダウンロード・スナップショット保存および閉じた後の履歴選択状態を切り替え後の画像に同期させる。さらに、ボトムシートに REQ-408 と同等のスワイプダウン閉じるジェスチャー（下方向移動量80px以上または速いフリックで閉じ、閾値未満は元に戻る、上方向は0にクランプ）を適用し、横スワイプと下スワイプが誤競合しない方向判定を行う。
  5. 根本原因: モバイル画像確認シート（SPEC_GENERATE §3-4 / §3-5）が単一画像表示前提で定義されており、複数画像間のスワイプ遷移契約および REQ-408 準拠のスワイプダウン閉じるジェスチャー契約が欠落していること。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 該当なし（表示する画像情報や現在位置インジケーター等の新規情報要素は追加しない）
  - **Interaction (インタラクション)**:
    - ボトムシート表示時および全画面ビューア表示時の左右スワイプによる前後画像送り（左スワイプで過去画像、右スワイプで新しい画像、先頭・末尾ではループせず停止）。
    - 画像送りに連動したアクション対象（ダウンロード・スナップショット保存）の更新と、シートクローズ後の履歴グリッド選択状態の同期。
    - ボトムシート表示時の下方向スワイプ／フリックによる閉じるジェスチャー（REQ-408 準拠：閾値未満はスナップ復帰、横方向スワイプと下方向スワイプの意図を分離）。
  - **Visual (視覚デザイン)**:
    - スワイプダウン中のシート追従移動（`translateY`）と閾値未満離脱時の滑らかなスナップ復帰（`translateY: 0`）、および左右スワイプ時の画像切替表示。デスクトップ（幅768px以上）や既存のレイアウト構造には影響を与えない。
- **Requirement**:
  - **1. モバイル生成プレビューの左右スワイプ画像送り（ボトムシート・全画面ビューア共通）**:
    - Generate ページのモバイル画像ボトムシートおよび全画面ビューアの両方において、左右スワイプ操作で履歴画像列を切り替えられること。
    - 履歴画像列の時系列（最新画像を先頭 index 0 とし、index が増えるほど古い画像）に従い、左スワイプで1つ古い（過去の）画像へ、右スワイプで1つ新しい画像へ切り替えること。
    - 先頭（最新画像）での右スワイプ、および末尾（最古画像）での左スワイプではループせず現在の画像に留まること。
  - **2. アクション連動および履歴選択状態の同期**:
    - スワイプで画像を切り替えた状態において、ボトムシートヘッダーのダウンロードボタン（`#download-btn-mobile`）およびスナップショット保存ボタンは、現在表示中の画像を対象に動作すること。
    - ボトムシートを閉じた後、背後の履歴3列グリッドの選択状態が、直前にプレビュー上で表示していた画像に同期していること。
  - **3. ボトムシートのスワイプダウン閉じるジェスチャー（REQ-408 統一）**:
    - モバイル表示（幅768px未満）の画像ボトムシートにおいて、上部ハンドルまたはコンテンツ領域からの下方向スワイプ／ドラッグでシートを閉じられること。
    - 下方向移動量が規定閾値（80px以上）またはフリック速度（> 0.5px/ms かつ移動量 > 30px）に達した際にシートを閉じること。
    - 閾値未満で離された場合は閉じず、元の表示位置（`translateY: 0`）へ滑らかにスナップ復帰すること。上方向ドラッグは移動量 0 にクランプすること。
    - 内部コンテンツに縦スクロールがある場合に `scrollTop > 0` の状態ではスクロールを優先し、最上部（`scrollTop === 0`）からのみスワイプダウン閉じるを有効とすること。
    - スワイプダウンによるシート閉じジェスチャーはボトムシート表示時のみ有効とし、全画面ビューア表示中は下方向スワイプによるボトムシートのクローズを無効化して誤作動を防止し、既存の全画面解除操作（画像タップ・右上閉じるボタン・Esc・OS戻る）でボトムシートへ復帰できること。
    - 横方向スワイプ（画像送り）と下方向スワイプ（シート閉じ）は操作初動の主方向で排他判定し、誤競合しないこと。既存の閉じる導線（閉じるボタン・バックドロップタップ・Escキー）も維持すること。
- **Acceptance criteria**:
  - [ ] AC-1: Given モバイル表示（幅767px以下）の Generate ページで履歴に複数枚（3枚以上）の生成画像があり、先頭・中間・末尾のいずれかの画像で画像ボトムシートを開いている状態（先頭 index 0 が最新画像、末尾が最古画像）, When ボトムシート表示中に左方向または右方向へスワイプする, Then 中間では左スワイプ時に1つ古い（過去の）画像へ切り替わり右スワイプ時に1つ新しい画像へ切り替わること。先頭（最新画像）での右スワイプおよび末尾（最古画像）での左スワイプではループせず現在の画像に留まること。
  - [ ] AC-2: Given モバイル画像ボトムシートから画像をタップして全画面ビューアを開いている状態, When 全画面ビューア表示中に画像送りのため左方向または右方向へスワイプする, Then ボトムシート時と同じ順序（左スワイプで1つ古い画像、右スワイプで1つ新しい画像、先頭・末尾ではループせず停止）で表示画像が切り替わること。また、全画面ビューアを解除してボトムシートへ復帰した際も切り替え後の画像が表示され続けること。
  - [ ] AC-3: Given モバイル画像ボトムシート上で左右スワイプにより別の画像へ切り替えた状態、または全画面ビューア上で左右スワイプにより別の画像へ切り替えてボトムシートへ復帰した状態, When ボトムシートヘッダーのダウンロードボタン（`#download-btn-mobile`）またはスナップショット保存ボタンを押下する, Then 押下された操作が切り替え後の現在表示中画像を対象として処理されること。
  - [ ] AC-4: Given モバイル表示（幅767px以下）で画像ボトムシートを開いている状態, When シート上部ハンドルまたはコンテンツ領域から下方向へ閾値以上（80px以上、または移動量30px超かつ速度0.5px/ms超のフリック）ドラッグして離す, Then ボトムシートが閉じ、背後の履歴グリッドのスクロール位置が維持されること。閾値未満で離した場合は閉じず元の位置（`translateY: 0`）へ復帰し、上方向ドラッグは移動量0にクランプされること。
  - [ ] AC-5: Given 画像ボトムシートから移行した全画面ビューアを表示している状態, When 画面上で下方向へスワイプする, Then 下方向スワイプによるボトムシートのクローズは無効であり、既存の全画面解除操作（画像タップ・右上閉じるボタン・Esc・OS戻る）でボトムシートへ復帰できること。また、ボトムシート表示時の既存閉じる操作（閉じるボタン・Backdropタップ・Esc）も維持されること。
  - [ ] AC-6: Given モバイル画像ボトムシートを開いている状態, When タッチまたはポインター移動開始時の方向判定において水平移動量が垂直移動量より大きい（`|deltaX| > |deltaY|`）横方向スワイプ、垂直下方向移動量が水平移動量より大きい（`deltaY > |deltaX|`）縦下方向スワイプ（`scrollTop === 0` および `scrollTop > 0`）、または上方向ドラッグを行う, Then 横方向スワイプでは画像送りのみが有効となりシート閉じ追従が起動しないこと、`scrollTop === 0` での縦下方向スワイプではシート閉じ追従のみが動作し画像送りが発生しないこと、上方向ドラッグ時は移動量0にクランプされて閉じる処理・画像送りが起動しないこと、および `scrollTop > 0` の内部縦スクロール中はコンテンツスクロールのみが優先されスワイプダウン閉じも画像送りも起動しないこと。
  - [ ] AC-7: Given モバイル画像ボトムシート上または全画面ビューア経由で左右スワイプにより別の画像へ切り替えた状態, When ボトムシートを閉じる, Then 背後の履歴3列グリッドにおいて、閉じる直前にプレビュー表示していた画像が選択状態になること。
- **Inferred points**:
  - 対象画面はユーザーの「モバイルモードでの生成プレビュー」「ボトムシートでのプレビュー」という表現、および仕様書（`SPEC_GENERATE.md` §3-4 / §3-5）に基づき、Generate ページの `MobileImageSheet`（ボトムシートおよび全画面ビューア）を対象としている。History ページ等の別モーダルは対象外。
  - スワイプで画像送りした際の自動追従トグル（`previewAutoFollow`）の扱い（手動閲覧中に生成完了が来た場合の追従／固定仕様との整合）の詳細は、設計フェーズで `SPEC_GENERATE.md` §2-9 / §3-7 に沿って定義する。
  - 履歴画像が1枚のみの場合、左右スワイプによる画像切り替わりは発生しない。
