### REQ-312: Prompt Surgeon: リソースモニタ HUD の重複解消と 3 行レイアウト統合

- **Type**: enhancement
- **Status**: new
- **Current step**: none
- **Priority**: P2
- **Surface**: Prompt Surgeon プレビューエリア右上のリソースモニタ HUD において、CPU/GPU 表示で数値が重複しており、縦幅がプレビューを圧迫しているため、モックアップ (`tmp/resource_monitor_layout_mockup.html`) 案1に沿って 3 行にスリム化したい。
- **5 Whys / Root Cause**:
  1. なぜ変更が必要か: リソースモニタ HUD の CPU と GPU で中央列と右端列に同じパーセント値が重複表示され、縦 4 行（約 102px）を占有してプレビュー右上を遮っているため。
  2. なぜ重複表示されるのか: RAM/VRAM と同じ 3 列レイアウト（ラベル・詳細・%）を適用した結果、容量指標（GB）を持たない CPU/GPU は詳細列にも使用率 % が入ってしまい二重表示になっていたため。
  3. なぜ縦幅を圧迫するのか: 単一メトリクスごとに 1 行ずつ縦積みした 4 行構成をとっていたため。
  4. なぜ CPU/GPU の横並び統合が有効か: CPU と GPU はともに「使用率（%）」のみを扱う同質のメトリクスであり、2 カラム（左右分割）で 1 行に集約することで重複を完全に排除しつつ省スペース化できるため。
  5. 根本原因: メトリクス特性（単一使用率 vs 容量+使用率）に応じた情報設計の最適化がなされておらず、全指標を一律の 3 列行で縦積みしていたこと。
- **UX Classification**:
  - **Information Design (情報設計)**: CPU/GPU の重複パーセント表示を排除し、使用率のみの指標（CPU/GPU）と容量＋使用率の指標（RAM/VRAM）で階層と表示構造を最適化。
  - **Visual (視覚デザイン)**: 4 行構成（約 102px）から 3 行構成（約 82px / 約 20% スリム化）へコンパクト化。1 行目を左右 2 分割グリッド（中央ボーダー区切り）とし、プレビュー画像へのオーバーレイ侵食を低減。
  - **Interaction (インタラクション)**: 既存のリアルタイム値更新および閾値カラーリング（通常・警告 >=85%・危険 >=95%）を維持。
- **Requirement**:
  - **1行目: CPU / GPU の横並び統合**:
    - リソースモニタ HUD の 1 行目を左右 2 カラム構成（grid-cols-2）とし、左列に CPU、右列に GPU を配置する。
    - 各カラムにはラベル（CPU / GPU）と使用率 % のみを表示し、重複表示を廃止する。
    - 左右のカラム間には視認性を保つための境界線（ボーダー）を設ける。
  - **2行目・3行目: メモリ指標（RAM / VRAM）の維持**:
    - 2行目には RAM、3行目には VRAM を配置する。
    - ラベル、詳細（使用量 GB / 総容量 GB）、およびパーセンテージ（%）の 3 要素構成を維持する。
  - **ステータス連動カラーリング & フォールバック**:
    - 各メトリクス値（四捨五入した整数 %）に応じて、通常・警告（>=85%）・危険（>=95%）のカラー表示を適切に適用する。
    - 値が null または取得不能な場合は、グリッド崩れを起こさず安全にフォールバック (`--`) を表示し、画面がクラッシュしないこと。
- **Acceptance criteria**:
  - [ ] AC-1: Given Prompt Surgeon のプレビューエリアにリソースモニタ HUD（ResourceGaugeHUD）が表示されているとき, When HUD の 1 行目をレンダリングした際, CPU と GPU が左右 2 分割で横並びに配置され、それぞれのラベル（CPU / GPU）と使用率 % が 1 回ずつ表示され、中央列の重複表示が存在しないこと。
  - [ ] AC-2: Given リソースモニタ HUD が表示されているとき, When HUD の 2 行目および 3 行目をレンダリングした際, 2 行目に RAM（ラベル、使用量/総容量 GB、使用率 %）、3 行目に VRAM（ラベル、使用量/総容量 GB、使用率 %）が表示されていること。
  - [ ] AC-3: Given 各メトリクス値（CPU, GPU, RAM, VRAM）が更新されたとき, When 四捨五入された整数パーセンテージ値に基づき、使用率が 85% 以上 95% 未満の場合は警告カラー（amber/warn）、95% 以上の場合は危険カラー（red/danger）、85% 未満の場合は通常カラー（zinc/normal）が該当メトリクスの数値に適用されること。
  - [ ] AC-4: Given メトリクスデータが未取得または null のとき, When リソースモニタ HUD がレンダリングされた際, グリッド構造が崩壊することなくラベルを維持し、エラーでクラッシュすることなく数値部分にプレースホルダー (`--`) が表示されること。
  - [ ] AC-5: Given リソースモニタ HUD にCPU/GPU/RAM/VRAMのみを表示する構成である, When HUD の行数および全体高さを確認した際, CPU/GPUの統合により従来の4行構成から3行構成に削減され、プレビュー画像を遮る縦専有面積がスリム化されていること。REQ-317などで必要な指標を追加する場合は全体3行固定を要求せず、指標追加に伴う行数増加を許容する。
- **Inferred points**:
  - モックアップ案1 (`tmp/resource_monitor_layout_mockup.html`) のデザイン・構造仕様をベースに要件化。
  - 既存の Zustand ストア (`useGenerationStore` / `systemStats`) から提供されるデータ構造を変更することなく、HUD 表示コンポーネント側のレイアウト調整のみで完結可能と想定。
- **Design doc**: `tmp/resource_monitor_layout_mockup.html`

#### ユーザーによる要件補足（2026-10-05）

- 目的は余分な表示や重複を削ってスリム化すること。「3行」は既存4指標に対する配置案であり、モニタ全体の恒久的な行数上限ではない。
- REQ-317のlocalStorage/sessionStorage使用量表示など、必要な項目の追加によって表示行が増えることは許容する。タイトル・Surface・Visual・Requirementの3行記述もこの条件で解釈する。
- CPU/GPUの重複排除、既存指標の参照、更新・カラーリング・フォールバックの意図は維持する。
