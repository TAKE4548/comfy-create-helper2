### REQ-312: リソースモニターの透過表現を維持した文字の視認性改善

- **Type**: enhancement
- **Status**: ready
- **Current step**: none
- **Priority**: P2
- **Surface**: 現在のリソースモニターの文字表示。PCの資源チップ・ホバー詳細、およびモバイルのVRAMピル・展開表示を対象とする。
- **ユーザー報告（2026-10-26）**:
  - 当初の旧HUDの表示整理はもう不要。現在は背景の透過エフェクトで文字が見づらい。
  - 透過エフェクト自体は残し、文字類の視認性を上げたい。
- **現状と原因の扱い**:
  - `ResourceHoverMonitor.tsx`には透過・ぼかし背景、小さい文字サイズ、暗めの文字色を使う表示がある。これはコード上の確認であり、背景との合成結果や視認性を実画面で検証したものではない。
  - 透過度だけを原因と断定しない。文字色・太さ・大きさ・文字背面の明度を含め、透過表現を残した状態で改善方法を設計する。
- **UX Classification**: Visual（文字と背景の判別性）、Information Design（ラベル・数値・単位・状態の識別）。
- **Requirement**:
  - 透過・ぼかしの表現を維持する。読みやすさのための透過度調整は許容するが、全面を不透明化して表現を廃止する対応はしない。
  - 明るい画像・暗い画像・細かい模様の背後でも、表示対象のラベル・数値・単位・補足文を判読できるようにする。
  - 通常・警告・危険・取得不能の識別を維持し、淡い文字や色付きの文字が背景に埋もれないようにする。
  - 現在提供する情報、リアルタイム更新、PCのホバーとモバイルの展開・閉じる操作、配置・重なり順を維持する。
  - 対象はリソースモニターに限定する。アプリ全体の透過表現や共通メニューの見た目を一括変更せず、旧HUDの3行化を再導入しない。
- **Acceptance criteria（2026-10-26レビュー後の現行AC）**:
  - [ ] AC-1: Given 現在のリソースモニターが表示されている, When PCのホバー詳細とモバイルの展開表示を確認する, Then 透過・ぼかしの表現が維持され、視認性改善のために透過度を調整しても効果自体は廃止されていないこと。
  - [ ] AC-2: Given 明るい画像・暗い画像・細かい模様の各背景がモニターの背後にある, When 対象となるチップ・ピル・詳細表示の文字を確認する, Then 表示されるラベル・数値・単位・補足文のすべてを判読でき、背景への埋没、文字の重なり、欠けがないこと。
  - [ ] AC-3: Given 通常・警告・危険・取得不能の各状態, When リソースモニターに表示する, Then 既存の状態の意味と判定条件を維持し、各状態の文字・数値・プレースホルダーが背後の明暗や模様に埋もれず識別できること。
  - [ ] AC-4: Given PCとモバイルの対象表示, When モニターを開閉して監視値を更新し、画面幅を変更する, Then 既存情報とリアルタイム更新が保たれ、ホバー・展開・閉じる操作、パネル配置と重なり順が維持され、文字の改善による見切れや操作妨害がないこと。
- **設計・検証への引継ぎ**:
  - 色・太さ・文字サイズ・透過度等の具体値、および再現可能な背景fixtureと判読性の測定・目視確認基準は、設計・テスト計画で具体化してレビューする。
  - 実ブラウザで背景との合成・文字の判読性を確認する。クラス名やDOMの存在だけで視認性の受入PASSとはしない。
  - `ResourceGaugeChips.tsx`を記す旧仕様と、現在のヘッダーの`ResourceHoverMonitor.tsx`の利用箇所・表示範囲を設計で照合する。不要な旧HUDの復活や情報削除は行わない。

#### 旧要求の履歴（現行の実装指示・受入条件として適用しない）

- **旧タイトル**: Prompt Surgeon: リソースモニタ HUD の重複解消と 3 行レイアウト統合

- **Type**: enhancement
- **旧Status（履歴）**: new
- **Current step**: none
- **Priority**: P2
- **Surface**: Prompt Surgeon プレビューエリア右上のリソースモニタ HUD において、CPU/GPU 表示で数値が重複しており、縦幅がプレビューを圧迫しているため、モックアップ (`tmp/resource_monitor_layout_mockup.html`) 案1に沿って 3 行にスリム化したい。
- **5 Whys / Root Cause**:
  1. なぜ変更が必要か: リソースモニタ HUD の CPU と GPU で中央列と右端列に同じパーセント値が重複表示され、縦 4 行（約 102px）を占有してプレビュー右上を遮っているため。
  2. なぜ重複表示されるのか: RAM/VRAM と同じ 3 列レイアウト（ラベル・詳細・%）を適用した結果、容量指標（GB）を持たない CPU/GPU は詳細列にも使用率 % が入ってしまい二重表示になっていたため。
  3. なぜ縦幅を圧迫するのか: 単一メトリクスごとに 1 行ずつ縦積みした 4 行構成をとっていたため。
  4. なぜ CPU/GPU の横並び統合が有効か: CPU と GPU はともに「使用率（%）」のみを扱う同質のメトリクスであり、2 カラム（左右分割）で 1 行に集約することで重複を完全に排除しつつ省スペース化できるため。
  5. 根本原因: メトリクス特性（単一使用率 vs 容量+使用率）に応じた情報設計の最適化がなされておらず、全指標を一律の 3 列行で縦積みしていたこと。
- **UX Classification**:
  - **Information Design (情報設計)**: CPU/GPU の重複パーセント表示を排除し、使用率のみの指標（CPU/GPU）と容量＋使用率の指標（RAM/VRAM）で階層と表示構造を最適化。
  - **Visual (視覚デザイン)**: 4 行構成（約 102px）から 3 行構成（約 82px / 約 20% スリム化）へコンパクト化。1 行目を左右 2 分割グリッド（中央ボーダー区切り）とし、プレビュー画像へのオーバーレイ侵食を低減。
  - **Interaction (インタラクション)**: 既存のリアルタイム値更新および閾値カラーリング（通常・警告 >=85%・危険 >=95%）を維持。
- **Requirement**:
  - **1行目: CPU / GPU の横並び統合**:
    - リソースモニタ HUD の 1 行目を左右 2 カラム構成（grid-cols-2）とし、左列に CPU、右列に GPU を配置する。
    - 各カラムにはラベル（CPU / GPU）と使用率 % のみを表示し、重複表示を廃止する。
    - 左右のカラム間には視認性を保つための境界線（ボーダー）を設ける。
  - **2行目・3行目: メモリ指標（RAM / VRAM）の維持**:
    - 2行目には RAM、3行目には VRAM を配置する。
    - ラベル、詳細（使用量 GB / 総容量 GB）、およびパーセンテージ（%）の 3 要素構成を維持する。
  - **ステータス連動カラーリング & フォールバック**:
    - 各メトリクス値（四捨五入した整数 %）に応じて、通常・警告（>=85%）・危険（>=95%）のカラー表示を適切に適用する。
    - 値が null または取得不能な場合は、グリッド崩れを起こさず安全にフォールバック (`--`) を表示し、画面がクラッシュしないこと。
- **旧Acceptance criteria（履歴・適用終了）**:
  - 旧AC-1: Given Prompt Surgeon のプレビューエリアにリソースモニタ HUD（ResourceGaugeHUD）が表示されているとき, When HUD の 1 行目をレンダリングした際, CPU と GPU が左右 2 分割で横並びに配置され、それぞれのラベル（CPU / GPU）と使用率 % が 1 回ずつ表示され、中央列の重複表示が存在しないこと。
  - 旧AC-2: Given リソースモニタ HUD が表示されているとき, When HUD の 2 行目および 3 行目をレンダリングした際, 2 行目に RAM（ラベル、使用量/総容量 GB、使用率 %）、3 行目に VRAM（ラベル、使用量/総容量 GB、使用率 %）が表示されていること。
  - 旧AC-3: Given 各メトリクス値（CPU, GPU, RAM, VRAM）が更新されたとき, When 四捨五入された整数パーセンテージ値に基づき、使用率が 85% 以上 95% 未満の場合は警告カラー（amber/warn）、95% 以上の場合は危険カラー（red/danger）、85% 未満の場合は通常カラー（zinc/normal）が該当メトリクスの数値に適用されること。
  - 旧AC-4: Given メトリクスデータが未取得または null のとき, When リソースモニタ HUD がレンダリングされた際, グリッド構造が崩壊することなくラベルを維持し、エラーでクラッシュすることなく数値部分にプレースホルダー (`--`) が表示されること。
  - 旧AC-5: Given リソースモニタ HUD にCPU/GPU/RAM/VRAMのみを表示する構成である, When HUD の行数および全体高さを確認した際, CPU/GPUの統合により従来の4行構成から3行構成に削減され、プレビュー画像を遮る縦専有面積がスリム化されていること。REQ-317などで必要な指標を追加する場合は全体3行固定を要求せず、指標追加に伴う行数増加を許容する。
- **Inferred points**:
  - モックアップ案1 (`tmp/resource_monitor_layout_mockup.html`) のデザイン・構造仕様をベースに要件化。
  - 既存の Zustand ストア (`useGenerationStore` / `systemStats`) から提供されるデータ構造を変更することなく、HUD 表示コンポーネント側のレイアウト調整のみで完結可能と想定。
- **Design doc**: `tmp/resource_monitor_layout_mockup.html`

#### ユーザーによる要件補足（2026-10-05）

- 目的は余分な表示や重複を削ってスリム化すること。「3行」は既存4指標に対する配置案であり、モニタ全体の恒久的な行数上限ではない。
- REQ-317のlocalStorage/sessionStorage使用量表示など、必要な項目の追加によって表示行が増えることは許容する。タイトル・Surface・Visual・Requirementの3行記述もこの条件で解釈する。
- CPU/GPUの重複排除、既存指標の参照、更新・カラーリング・フォールバックの意図は維持する。
