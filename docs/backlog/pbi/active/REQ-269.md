### REQ-269: タグセット・LoRAのカテゴリセクション化とセクション内スコープ並び替え（Phase 1）

- **Type**: enhancement
- **Status**: ready
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - LoRA・タグセットの並び替え・整理をしやすくするため、カテゴリセクション化およびBaseModelマルチバリアント構想に基づくデータモデルおよびUIの見直しを行いたい。
  - 検索クエリやカテゴリ・BaseModelフィルタ適用時にD&D並び替えが無効化される制約や、単一フラットリストによるソート順衝突・カテゴリ跨ぎの順序破綻を解消したい。
  - カテゴリフィルタは残し、フィルタ適用でセクション自体の表示・非表示を切り替えるようにする。
  - それに伴いカテゴリフィルタはOR設定可能（複数選択）にし、カテゴリ未設定（その他）も1項目としてフィルタ対象に含める。
- **Root Cause**:
  - **Information Design (Flat List & Missing Category Scope Boundary)**:
    - 現行のタグセット・LoRA管理は全カードが単一のフラットな順序列（`sort_order`）として管理されており、カテゴリごとの独立したソート境界（スコープ）が存在しない。
    - フィルタ適用時にフラットなインデックス再計算を行うと、フィルタ外のカードと順序番号が重複・衝突するため、D&Dを一律無効化（`isDndActive = false`）せざるを得ない制約が生じていた。
  - **Interaction Design (Rigid Filtering & Inefficient Organization Navigation)**:
    - カテゴリフィルタが単一選択かつフラットリストのカード絞り込みに閉じており、必要な複数カテゴリのみを並べて俯瞰・整理する柔軟性がなかった。
    - 「未分類（カテゴリ未設定）」のアイテムを明示的にフィルタリングして集中的にトリアージする導線が不足していた。
- **Requirement**:
  - **カテゴリ別アコーディオンセクション表示**:
    - `TagsPage` および `LoRAsPage` のカード一覧を単一のフラットグリッドから、カテゴリごとの独立したアコーディオンセクション表示に刷新すること。
    - 各セクションヘッダーには「カテゴリ名」「登録カード件数」「展開/折りたたみトグル」を表示すること。
    - セクションの開閉状態は `localStorage` に保持し、ページ再訪時にも状態が復元されること。
    - カテゴリが未設定のカード（`category_id` が null または未割当）は最下部の「未分類（その他）」セクションに集約して表示すること。
    - 登録アイテム数が0件のカテゴリはヘッダーに「(0件)」と表示し、カードのドロップ先として受け入れ可能とすること。
  - **カテゴリフィルタによるセクション表示・非表示制御（OR条件・複数選択）**:
    - カテゴリフィルタを維持し、フィルタ選択されたカテゴリに対応する「セクション自体の表示・非表示」を切り替える方式とすること。
    - カテゴリフィルタは複数選択（OR条件）に対応し、ユーザーが選んだ複数のカテゴリセクションのみを画面上に並べて表示・比較・整理できること（全解除時は全セクションを表示）。
    - カテゴリフィルタの選択肢に「未分類（その他）」を独立した1項目として含め、未分類セクションのみの表示や、特定カテゴリと未分類の同時表示を可能にすること。
  - **カテゴリ内スコープでの安全な並び替え（D&D）**:
    - 表示中の各セクション内でのドラッグ＆ドロップ（D&D）による並び替えをサポートすること。
    - 並び替え更新時、他カテゴリのカードの `sort_order` に一切影響を与えず、対象カテゴリのカードのみをスコープとして順序を更新すること。
    - バックエンドの `/reorder` API（`/api/tag-sets/reorder`, `/api/loras/reorder`）を拡張し、`category_id` を指定した局所的な順序更新に対応させること（既存のDBスキーマは変更せず維持）。
    - ネットワーク通信失敗時には楽観的更新をロールバックし、エラー通知を表示してデータの不整合を防止すること。
  - **セクション間ドラッグ＆ドロップ（カテゴリ移動）**:
    - カードを別カテゴリのセクションへドラッグ＆ドロップした際、移動先カテゴリへの `category_id` 更新および挿入位置に応じた `sort_order` の再計算が即時実行されること（失敗時は元のカテゴリ位置へロールバック）。
  - **BaseModelフィルタおよび検索適用時の整合性維持**:
    - BaseModelフィルタやテキスト検索適用時でもセクション構造を維持し、表示中セクション内で該当するカードを絞り込み表示しつつ、論理的な順序関係が破綻しないこと。
- **Acceptance criteria**:
  - [ ] AC-1: `TagsPage` および `LoRAsPage` において、カード一覧がカテゴリごとのアコーディオンセクションに分割して縦スクロール表示されること。
  - [ ] AC-2: 各カテゴリセクションヘッダーに「カテゴリ名」「セクション内の登録件数」「展開/折りたたみトグル」が表示され、トグル操作によって開閉状態が切り替わること。
  - [ ] AC-3: セクションの開閉状態が `localStorage` に保存され、ページをリロードまたは再訪問した際にも直前の開閉状態が正確に復元されること。
  - [ ] AC-4: カテゴリ未設定のカード（`category_id` が null）が存在する場合、最下部に「未分類（その他）」セクションとして独立して一覧表示されること。
  - [ ] AC-5: カテゴリフィルタが複数選択（OR条件）に対応し、選択されたカテゴリに対応するセクションのみが表示され、未選択カテゴリのセクションが非表示となること（全未選択時は全セクション表示）。
  - [ ] AC-6: カテゴリフィルタの選択肢に「未分類（その他）」が含まれており、未分類カードのセクションを単独または他カテゴリと併せてフィルタ表示できること。
  - [ ] AC-7: カテゴリフィルタ適用下においても表示中の各セクション内でドラッグ＆ドロップによる並び替えが可能であり、その並び順更新が対象カテゴリ内のみにスコープされ、他カテゴリの `sort_order` を破壊・変更しないこと。
  - [ ] AC-8: カードを別カテゴリセクションへドラッグ＆ドロップして移動した場合、モーダル編集を経ることなくカードの所属カテゴリ（`category_id`）および移動先の並び順が即時反映されること。また通信失敗時は移動前の状態にロールバックされること。
  - [ ] AC-9: BaseModelフィルタや検索クエリを適用している状態でも、表示中のセクション構造を維持したまま対象カードの絞り込み・視認が行え、順序の整合性が担保されること。
  - [ ] AC-10: 既存のDBスキーマおよび過去の登録データとの後方互換性が完全に維持され、データ欠落やマイグレーションエラーが生じないこと。
