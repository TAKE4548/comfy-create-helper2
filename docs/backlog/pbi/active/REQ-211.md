### REQ-211: 設定ページ・履歴ページのモノリス構造解体と非同期エラーリカバリ・プログレス管理の堅牢化
- **Type**: refactor
- **Status**: ready
- **Current step**: Phase 1: Requirement Analysis
- **Priority**: P2
- **Surface**:
  - `SettingsPage.tsx` (1,689行) に音声トーンプリセット、マスタマッピング、カテゴリ管理、サムネイル設定、翻訳設定、モデル設定などの独立した6系統の設定ロジックが1ファイルに同居しており、個別の設定機能改修時に予期せぬ他セクションへの影響が発生しやすい。
  - `HistoryPage.tsx` (1,564行) において、一括ダウンロード（Bulk Download）やアルバム追加処理などの長時間非同期処理において、エラー発生時の状態リセット（`isDownloading` 等の解除）や再試行機構が不完全であり、通信切断時にUIがフリーズまたは操作不能になるリスクがある。
  - 非同期エフェクト内のクリーンアップ不備による競合状態（Race Condition）や、古い状態（Stale Closures）の参照が散見される。
- **Root Cause**:
  - **Monolithic Page Component Anti-Pattern**: ページ単位のコンポーネントにドメインごとのステート・API呼出・UIテンプレートを直接フラットに記述し続けたことによる肥大化。
- **Requirement**:
  - `SettingsPage.tsx` を各設定ドメインごとの自己完結型セクションコンポーネント（すでに一部存在する `BaseModelSection` 等と同様のパターン）へ完全に分割し、メインページをそれらを束ねるルーティング・レイアウトのみにスリム化すること。
  - `HistoryPage.tsx` の一括操作・ダウンロードロジックをカスタムフック（`useBulkDownload`, `useAlbumOperations`）として抽出し、エラーバウンダリおよび確実な `finally` ブロックでの状態リセット・プログレス通知を完備すること。
- **Acceptance criteria**:
  - [ ] AC-1: `SettingsPage.tsx` の行数が300行程度に削減され、各設定セクションが独立したコンポーネントとして分割・管理されていること。
  - [ ] AC-2: `HistoryPage.tsx` の一括ダウンロード等の非同期処理でネットワークエラーや例外が発生した場合でも、ローディング状態が確実に解除され、ユーザーにリトライ可能な通知が表示されること。
  - [ ] AC-3: `SettingsPage.test.tsx` および `HistoryPage.test.tsx` の全テストが正常にパスすること。
