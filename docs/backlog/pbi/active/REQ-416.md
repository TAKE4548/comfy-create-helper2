### REQ-416: 新規ワークフロー追加時のノードマッピング初期選択が候補スコア順と連動せず空欄または非推奨ノードになる不具合

- **Type**: bug (Type B: Specification Gap)
- **Status**: new
- **Priority**: P2
- **Surface**: Frontend (`UploadWorkflowModal.tsx`, `useMasterMappingRows.ts`), Backend (`workflow_scanner.py`), Docs (`REQ-358.md`, `SPEC_SETTINGS.md`)
- **Incident Report**: `docs/incident_report.md`
- **5 Whys / Root Cause**:
  1. なぜ初期選択がスコア通りになっていないか: 新規ワークフロー追加モーダル（UploadWorkflowModal）表示時、スロット初期値（node_id）が候補一覧のスコア最上位ノードではなく、空欄や低スコアノードに設定されるため。
  2. なぜ空欄や低スコアノードが初期値になるか: `useMasterMappingRows.initFromScan` がバックエンドAPI（`/api/workflows/scan`）の返却結果（`scanDefaults`）から直接初期値を設定しているため。
  3. なぜバックエンドのスキャナ結果とフロントエンドの候補スコアが乖離するか: バックエンド（`workflow_scanner.py`）はノードID昇順（`candidates.sort(key=lambda x: int(x[0]))`）で候補をソートしており、正規化タイトルや文字バイグラム類似度によるステージ親和性スコアリングを持たず、不完全一致時にID最小ノード選択や `not_found`（空欄）となるため。
  4. なぜフロントエンドの候補スコア（rankWorkflowNodeCandidates）が初期値選定に反映されていないか: REQ-358設計時に「候補一覧の順位・スコア算出（AC-8〜14）」は規定されたが、「新規登録・未割り当てスロットの初期選択（Auto-assignment）として推奨候補（スコア1位）を自動採用する」制約が仕様から欠落していたため。
  5. 根本原因: SSoT（REQ-358およびSPEC_SETTINGS）における初期選択選定ルール（スコア最上位ノードの初期自動適用）の仕様欠落（Specification Gap）。
- **UX Classification**:
  - **Information Design (情報設計)**:
    - 候補ドロップダウン内の適合スコア（0〜100%）と、スロットの初期選択ノードの一貫性を担保し、ユーザーが「スコア1位のノードが選ばれている」ことを自然に認知できるようにする。
  - **Interaction (インタラクション)**:
    - 新規ワークフロー追加時（UploadWorkflowModal）および未割り当てスロットにおいて、推奨ノード（スコア1位）が存在する場合は自動的に初期選択され、手動選択の手間を削減する。
    - 候補が存在しない場合や推奨レベルに達しない場合は未割当（空欄）を維持し、誤ったマッピングを防止する。
  - **Visual (視覚デザイン)**:
    - 自動補完されたノードに対しても既存の適合度バッジ（緑・推奨）を初期表示し、セレクタ欄内で即座に確認可能にする。
- **Requirement**:
  - **1. SSoT仕様改定（REQ-358 / SPEC_SETTINGS.md）**:
    - 新規ワークフロー登録時および未割り当てスロットにおいて、候補スコア最上位（推奨フラグ付き、または基準スコア以上の最上位ノード）が存在する場合、そのノードIDをスロットの初期選択値として自動補完する仕様を明文化する。
  - **2. フロントエンド初期値選定ロジックの改修（UploadWorkflowModal / useMasterMappingRows）**:
    - 新規ワークフロー追加時において、バックエンドの旧ID昇順スキャナ結果に依存せず、`rankWorkflowNodeCandidates` で算出されたスコア1位の推奨ノードを初期値（`node_id`）として適用する。
  - **3. リマップ・未割り当てスロットとの整合性**:
    - 保存済みマッピングが存在する場合はそれを最優先で維持しつつ、未割り当てスロットや新規追加スロットにおいて推奨候補がある場合の自動サジェスト挙動を統一する。
- **Acceptance criteria**:
  - [ ] AC-1: Given 新規ワークフロー追加時（UploadWorkflowModal）において、特定のスロットに対してスコア最上位（推奨）の候補ノードが存在する状態, When モーダルを開いてノードマッピング行を表示したとき, Then そのスロットの初期選択値（node_id）としてスコア最上位のノードが自動選択されていること
  - [ ] AC-2: Given 同一スロットに複数の候補ノード（例: スコア95%とスコア75%）が存在する状態, When 初期表示されたとき, Then スコアが最も高いノード（95%）が初期選択されており、ドロップダウン内の最上位ノードと一致していること
  - [ ] AC-3: Given スロットに対して推奨ノードが存在せず、低スコア（その他ノード等）のみが存在する場合, When 初期表示されたとき, Then 誤った自動選択を避け、初期値は空欄（未割当）のままであること
  - [ ] AC-4: Given 既存ワークフローの保存済みマッピングが存在するスロット, When 編集画面やリマップ画面を表示したとき, Then スコア順位に関わらず既存の保存済みノードIDが初期値として維持されること
- **Inferred points**:
  - 推奨ノードの判定基準は `candidate.recommended === true`（tier 0 または 1）または `score >= 75` を基本とし、低信頼度ノードの誤選択を防ぐ。
- **Design doc**: docs/design/REQ-416.md
