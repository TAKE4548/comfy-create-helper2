### REQ-376: モバイルLoRA／Tag Set：一覧カードの情報整理と縦スクロールの一本化

- **Type**: feature
- **Status**: ready
- **Priority**: P3
- **Surface**: モバイルLoRAs（`/loras`）・Tag Sets（`/tags`）の一覧（幅767px以下）。カード、カテゴリ見出し、ページ縦スクロール
- **Reference**:
  - docs/design/mobile-ui-redesign/mobile-lora-tagset-redesign-proposal.md（§1〜§3、§6、§8 AC-01〜AC-05、AC-11〜AC-13）
  - docs/design/mobile-ui-redesign/mobile-common-ui-redesign-proposal.md（COMMON-02 / 06 / 08、§3 `ImageCarousel`）
  - docs/specs/SPEC_LORAS.md（一覧カード、カード寸法）／docs/specs/SPEC_TAGS.md（§3 レイアウト、カード寸法）
  - docs/specs/SPEC_COMMON.md（§4-2 ImageCarousel）
  - 比較モック: `/loras?ui=baseline|proposal`、`/tags?ui=baseline|proposal`
- **5 Whys / Root Cause**:
  1. なぜ改修が必要か: モバイルの一覧で、カード右上の編集・削除ボタンが重なり、カード下部の独立スクロールがページのスクロールを妨げ、Stickyなカテゴリ見出しが不自然に離れるため。
  2. なぜその課題が発生するか: 固定高さのカードに、カテゴリバッジ・タグチップ・トリガーワード・強度・パス等を詰め込み、はみ出しを内部スクロールで逃がしているため。
  3. なぜ現状の仕組みで不十分か: 一覧でカードごとの識別に必要な情報（タイトル・説明・対象Base Model）が、補助情報に埋もれて読みづらい。
  4. なぜこのアプローチを採用するか: 一覧は識別に必要な情報へ絞り、詳細データは詳細画面で確認する方向を、ユーザーがモックで評価した。
  5. 根本原因: 一覧カードに詳細情報まで載せる情報設計と、入れ子スクロールで情報を収める構造。
- **UX Classification**:
  - **Information Design (情報設計)**: カード下部をタイトル・Description・対象Base Modelの3項目に限定する。カテゴリは見出しに集約する。
  - **Interaction (インタラクション)**: カード内の独立スクロールを廃止し、ページ全体のスクロールを優先する。編集・削除を重ならない位置に整理する。
  - **Visual (視覚デザイン)**: カード高さを固定し、画像フレームを中央に配置する。
- **Requirement**:
  - **1. カードの固定高さ**: モバイルのカード高さを320pxに揃える（現行仕様の寸法を維持）。
  - **2. 下部情報の限定**: ①タイトル（最大2行）、②Description（最大2行）、③対象Base Model（1行、下端に揃えて省略）。タグチップ、トリガーワード、強度、パス、サブセット、タグ数は一覧から除外し、詳細で確認する。
  - **3. カテゴリ**: カード内のカテゴリバッジをなくし、既存のカテゴリ見出しへ集約する。
  - **4. スクロール**: カード内の独立スクロールをなくし、ページの縦スクロールに統合する。Stickyカテゴリ見出しはスクロール領域の上端に接する。
  - **5. 操作**: 編集・削除ボタンを重ならない位置へ整理し、サムネイルの画像フレームを中央に合わせる。並べ替え、複数選択、画像閲覧、カードタップの既存機能を維持する。
  - **6. 非対象**: PC表示、詳細・編集シート（REQ-377）、共通 `ImageCarousel` のグローバルな変更。
- **Acceptance criteria**:
  - [ ] AC-1: Given 幅767px以下のLoRAs／Tag Sets一覧に長短さまざまなデータがある, When 一覧を表示する, Then すべてのカードの外形が高さ320pxで揃い、はみ出しやカード同士の重なりがないこと。
  - [ ] AC-2: Given 一覧カード, When 下部の情報を確認する, Then 表示がタイトル・Description・対象Base Modelの3項目のみで、この順序で、タイトルと説明が各最大2行、モデルが1行で省略され、モデル行がカード下端側に揃うこと。
  - [ ] AC-3: Given 3行以上のタイトル・説明、長いモデル名, When 一覧を表示する, Then 超過部分は省略され、カードの外にはみ出さず、全文は詳細で確認できること。
  - [ ] AC-4: Given 一覧カード, When カード上で縦方向にスクロール操作を行う, Then カード内部の独立スクロールは存在せず、ページ全体が縦にスクロールし、途切れないこと。
  - [ ] AC-5: Given カテゴリが複数ある一覧をスクロールする, When カテゴリ見出しがSticky表示になる, Then 見出しがスクロール領域の上端に接し、不自然な空隙やカードへの重なりがなく、カード内にカテゴリバッジが重複表示されないこと。未分類は未分類セクションに表示されること。
  - [ ] AC-6: Given 各カード, When 編集・削除・並べ替えハンドル・複数選択・カードタップ・画像閲覧を操作する, Then 編集と削除のボタンが重ならず、各操作の有効タップ領域が44×44px以上で、相互に操作が競合せず、従来の機能が動作すること。
  - [ ] AC-7: Given サムネイル, When 一覧を表示する, Then 画像フレームがカードの中央に配置され、現行のサムネイル比率設定が保持されて画像の切れ・歪みがないこと。
  - [ ] AC-8: Given LoRA一覧／Tag Set一覧, When 一覧から除外した項目（トリガーワード、強度、ファイルパス、タグ、サブセット、コピー）を確認する, Then 各項目が詳細画面で従来どおり確認・コピーできること。
  - [ ] AC-9: Given 対象Base Modelが複数のデータ, When 一覧を表示する, Then 設計で決定した表示形式で1行内に収まり、全件を確認する導線が提供されること。
  - [ ] AC-10: Given 検索、カテゴリ／Base Modelフィルター、カテゴリの折りたたみ、並べ替え、複数選択・一括操作, When 操作する, Then 従来の機能が失われないこと。
  - [ ] AC-11: Given 幅360px、極端な長文、画像なし、画像の読込失敗、カテゴリ多数、少数／大量データ、縦長・横長画像, When 一覧を表示する, Then レイアウトが破綻しないこと。
  - [ ] AC-12: Given 幅768px以上、Baseline、`ImageCarousel` を利用する他画面, When 操作する, Then 本PBI前から表示と挙動が変化しないこと。
- **Inferred points**:
  - **仕様の差異**: SPEC_LORAS／SPEC_TAGSは一覧カードにBaseModelバッジ、トリガーワード（ホバーでコピー）、推奨強度、ファイルパス（ホバーのツールチップ）等を定義し、画像領域をカード高の約55〜60%としている。本PBIはモバイルのみ一覧を3項目へ絞る仕様改訂を伴う。PC側の定義は維持し、モバイルとの差を仕様へ追記する。
  - **確定（ユーザー回答 2026-10-18）**: 一覧からのトリガーワード／タグの単体コピー導線がなくなり、詳細でのコピーのみとなることを許容する。
  - 前提: REQ-378（モバイルUI共通規約のSPEC_COMMON反映）の完了後に設計に着手する。
  - 320px、2行／2行／1行は比較用の候補値（ユーザーは方向性を評価）。設計で最終値を確定する。
  - 対象Base Modelが複数の場合の表示形式（AC-9）は最終設計で決定する未確定事項。
  - 画像の中央配置は、共有の `ImageCarousel` を変更せず、ページ側で調整する方針。`ImageCarousel` への変更が必要となる場合は、影響画面を調査し別途承認を得る。
  - 「不要項目のCSS隠蔽」ではなく、表示モデル／コンポーネントの整理を検討する（モックはDOM追加とCSS上書き）。実装方式は設計で決定する。
  - 現行仕様のカード寸法式（SPEC_LORAS／SPEC_TAGS：画像面積58%）との整合を設計で確認する。
  - REQ-377とは独立に着手できる。両者で一覧と詳細が一貫して動作することを、最終確認として共同で行う。
  - テスト規約: テスト名に `[REQ-376/AC-n]` を付与し、ファイル名・パスにチケット番号を含めない。
