### REQ-298: タグチップのドラッグ並び替え判定位置を重なり判定に改善

- **Type**: improvement
- **Status**: new
- **Current step**: none
- **Priority**: P2
- **UX Classification**:
  - **Interaction Design**: ドラッグ＆ドロップ時の衝突・並び替え（ソートスロット）判定ロジックの改善（要素中心点距離判定から要素重なり判定への最適化、境界領域チャタリング防止閾値、ポインタ/タッチ操作両対応）
  - **Visual Design**: ドラッグ中の半透明ゴースト表示および移動先スロットへのスムーズなシフトプレビュー（60fps追従）
- **Surface**:
  - タグチップの並び替えをドラッグハンドルで行えるが、掴んで持っていった後の入れ替え判定位置が直感的ではない。
  - 移動させたい先のタグチップの上に重ねただけで、自然に入れ替え（目的のスロットへの並び替えプレビュー）が判定されるようにしたい。
- **5 Whys Analysis**:
  1. *Why*: タグチップのドラッグ並び替えにおいて、移動先判定が直感的でないと感じるのはなぜか？
     → 移動先のタグチップの上に持っていっても、目的の入れ替え位置に即座に反映されず、移動先チップの中心を大きく超えたり特定の位置まで深く運ぶ必要があるため。
  2. *Why*: なぜ移動先チップの中心を超えるまで判定されないのか？
     → 並び替えの衝突・ヒット判定が「要素の中心点間の近さ」等を基準にしており、タグチップの文字数や重み表記によって横幅が不均一な場合、直感と判定タイミングにズレが生じるため。
  3. *Why*: なぜそれが操作ストレスになるのか？
     → ユーザーは視覚的に「入れ替えたいチップの上」を狙って運ぶため、視覚的にチップ上に重ねているのに反応しないと、有効な判定位置を探してマウスを彷徨わせる必要があるため。
  4. *Why*: 「シンプルに重なっていたら入れ替え判定」という挙動が求められるのか？
     → 「持っていきたいチップの上に重ねれば、そのスロットに自然に収まる（入れ替わる）」という空間的なメンタルモデルと、UIのリアクションを一致させるため。
  5. *Why*: 根本原因（Root Cause）は何か？
     → 【Interaction Design】並び替えの衝突判定基準がユーザーの直感的なメンタルモデル（対象要素とのバウンディングボックス/矩形の重なり）に合致しておらず、直感的な入れ替えインタラクションを提供できていない。
- **Requirement**:
  - ドラッグハンドルでタグチップをドラッグした際、移動先候補となるタグチップの矩形領域上にドラッグ中のチップ（またはポインタ）が重なった時点で、即座にその位置へのスロット挿入・並び替えプレビューが発火すること。
  - チップの横幅や長さに左右されず、移動先チップの上に重ねる（20%以上の面積重複またはポインタ直下侵入）だけで直感的に入れ替え対象として認識されること。角の微小な接触での誤発火を防止する閾値を設ける。
  - 隣接チップの境界付近に重なった場合でも、小刻みな振動（チャタリング/ジッター）を起こさず、重なり面積の大きい（またはポインタ直下の）チップが一意かつ安定して判定されること（境界判定のイプシロン閾値制御）。
  - ドラッグ並び替え方式は「対象スロットへの挿入・シフト移動」とし、目的のチップ位置にドラッグ中チップが収まり、周囲のチップが自然に移動するプレビューを提示すること。
  - マウス操作およびタッチ操作（スマートフォン・タブレット）の双方で同等の判定挙動が保証されること。
  - 編集中（インライン編集やサブメニュー展開中）のチップが存在する場合、ドラッグ開始時に安全に編集内容を確定（Commit）または終了し、状態の競合やデータ消失を起こさないこと。
  - チップが1件のみ（N=1）または空の場合はドラッグしても順序変更は発生せず、エラーを起こさないこと。
  - ドラッグキャンセル時（Escapeキー押下やドロップ可能領域外へのリリース）は、ドラッグ前の元の並び順へ安全に復帰すること。
  - 既存のタグチップ操作（テキストクリックでのサブメニュー表示、強度変更、削除、インライン編集等）に干渉・誤発火しないこと。
- **Acceptance criteria**:
  - [ ] AC-1 (重なりによる即時スロット並び替えプレビュー):
    - **Given**: 複数のタグチップ（チップA, チップB, チップC）が並んでいる。
    - **When**: ユーザーがドラッグハンドルでチップAをドラッグし、チップBの表示領域上に重ねる（重複面積20%以上またはポインタがチップBの領域内に進入）。
    - **Then**: チップBの中心点を越える前であっても、領域の重なりが検知された時点でチップBのスロットへの並び替えプレビュー（チップBがシフトしてチップAの収まるスペースが形成される）が即座に反映される。
    - **And**: ドラッグ中のチップAは半透明（ゴースト）等で視覚的に識別される。
  - [ ] AC-2 (ドロップによる順序確定):
    - **Given**: チップAをドラッグしてチップBの上に重ね、並び替えプレビューが表示されている。
    - **When**: マウスボタンを離す、またはタッチを終了してドロップする。
    - **Then**: プレビューされた並び順（チップBの位置にチップAが配置された順序）でタグチップ列の順序が確定・反映される。
  - [ ] AC-3 (境界領域におけるチャタリング防止):
    - **Given**: 隣接する2つのタグチップ（チップBとチップC）の境界付近にチップAをドラッグ移動する。
    - **When**: チップAがチップBとチップCの両方に同時に重なる。
    - **Then**: 重なり面積の大きい方（またはポインタ直下のチップ）が一意かつ安定して選択され、プレビュー表示が小刻みに振動・チラつくことなくスムーズに追従する。
  - [ ] AC-4 (キャンセル操作および範囲外ドロップによる復帰):
    - **Given**: チップAをドラッグして別のチップ上に重ね、入れ替えプレビューが表示されている。
    - **When**: ドロップ前にEscapeキーを押下する、またはチップ一覧の有効なドロップ領域外へドラッグして離す。
    - **Then**: 並び替え操作がキャンセルされ、ドラッグ開始前の元のチップ並び順に復帰する。
  - [ ] AC-5 (単一チップおよび編集状態との競合防止):
    - **Given**: タグチップが1件のみ表示されている、またはいずれかのタグチップでインライン編集やサブメニューが開いている。
    - **When**: ドラッグ操作を開始する。
    - **Then**: 1件のみの場合は順序変更やUI破綻が発生せず、編集中のチップが存在する場合は編集内容が安全に確定・終了されてからドラッグが進行する。
  - [ ] AC-6 (既存のチップ操作への非干渉):
    - **Given**: タグチップ一覧が表示されている。
    - **When**: ドラッグハンドル以外の部分（タグ名テキスト、削除ボタン、強度入力欄等）をクリック・タップ・操作する。
    - **Then**: ドラッグ並び替えが誤発火することなく、サブメニュー展開、強度変更、タグ削除等の既存操作が正常に行える。
