### REQ-246: Server Manager スクリプト群（PowerShell / Python）の責務分離とモジュール化

- **Type**: refactor
- **Status**: ready
- **Current step**: none
- **Priority**: P1
- **Surface**:
  - `tools/server-manager/server-manager.ps1` が直近の改修（REQ-233 ポート待機設定化、REQ-238 Vite EPERM解消、REQ-239 WSL2ポート検知、REQ-241 停止再起動競合バグ、REQ-242 ターミナル非表示＆タブ別コンソール出力、REQ-243 Manager再起動バッチ）によって単一ファイル（700行超）として肥大化している。
  - プロセスライフサイクル制御（taskkill / conhost / cmd）、WSL2 bashコマンド発行、ポート監視・ソケット解放待機、コンソールログ収集・ファイル書き出し、文字コード変換が1つのスクリプトに手続き型で混載している。
  - `server_api.py`（Python Web API）と `server-manager.ps1` の間でサービス識別子の表記（fe/be/comfy vs frontend/backend/comfy）や引数マッピングが二重管理されており、改修時の不整合リスクが高い。
- **Root Cause**:
  - (Monolithic Script Anti-Pattern / システム構造): 機能追加や不具合修正ごとに対処療法的な引数分岐やインラインスクリプトを追加し続けた結果、関心の分離（SoC）が崩れ、テスタビリティおよび変更時の影響範囲追跡が困難になっている。
- **Requirement**:
  - `server-manager.ps1` を責務別に関数・モジュール（プロセス起動停止 `process.ps1`、ポート監視 `network.ps1`、ログストリーム `logger.ps1` 等）へ分割し、メインファイルを簡潔なディスパッチャ（200行以内）に純化すること。
  - または、長期的な保守性を高めるため、状態判定・ポート監視・プロセス監視の主要ロジックを Python 側（`server_api.py` 内部）へ段階的に集約し、PowerShell は OS プリミティブ実行レイヤに限定すること。
  - サービス識別子を `config.json` を SSoT として統一し、Python / PowerShell 間のハードコードされた引数マッピングを排除すること。
- **Acceptance criteria**:
  - [ ] AC-1: `server-manager.ps1` のメインロジックが200行程度にスリム化され、プロセス制御・ポート監視・ログ収集の各責務がモジュール分割されていること。
  - [ ] AC-2: Web Manager（ポート8899）および対話型コンソールメニュー（`server_menu.bat`）からの全操作（start/stop/restart/status/console）が既存と同等以上に正常動作すること。
  - [ ] AC-3: サービス識別子の不整合による処理漏れや「Unknown service」エラーが再発しない構造になっていること。
  - [ ] AC-4: WSL2 ComfyUI、Windows Backend、Windows Frontend の各環境差分を吸収する抽象化が行われ、Windows側のポートプロキシを誤爆終了しない安全性が維持されていること。
