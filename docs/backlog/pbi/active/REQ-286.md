### REQ-286: HistoryPage のビュー分離（ギャラリー vs アルバム詳細）

- **Type**: refactoring
- **Status**: ready
- **Current step**: none
- **Priority**: P3
- **Surface**: HistoryPage.tsx (842行) には、アルバム未選択時の「全スナップショット一覧ギャラリー」と、選択時の「アルバム詳細・並び替えビュー（Dnd並び替え、一括操作）」の実質2つの独立画面が同居しており、状態とJSXの肥大化を招いている（リファクタ計画 PBI-REF-05）。
- **Root Cause**: 履歴画面において、ギャラリーブラウズ用途とアルバム編集管理用途という異なるユースケースのUI・状態が1つのページコンポーネント内で条件分岐レンダリングされていること。
- **Requirement**:
  - Dnd-kitによるアルバム内並び替え制御を専用カスタムフック（`useAlbumDndOrder.ts`）に分離する。
  - 全スナップショット一覧を `SnapshotGalleryView.tsx`、アルバム詳細・編集画面を `AlbumDetailView.tsx` として独立したビューコンポーネントに分離する。
  - 親の `HistoryPage/index.tsx` は共通クエリとルーティング/表示切替に特化させる。
  - 【目標構成】:
    ```
    frontend/src/pages/HistoryPage/
    ├─ index.tsx                  # ページエントリ・共通クエリ定義（約120行）
    ├─ hooks/
    │  └─ useAlbumDndOrder.ts     # Dnd-kitによるアルバム内並び替え制御（約90行）
    └─ views/
       ├─ SnapshotGalleryView.tsx # 全件一覧ビュー（検索フィルタ・無限スクロール）（約320行）
       └─ AlbumDetailView.tsx     # アルバム詳細ビュー（Dnd並び替え・一括操作）（約220行）
    ```
- **Acceptance criteria**:
  - [ ] AC-1: スナップショットの無限スクロール、検索フィルタリング、アルバム内並び替えが既存通り正常に動作すること。
  - [ ] AC-2: `cd frontend && npm run typecheck`（tsc -b --noEmit）がエラー0件でPASSすること（REQ-001の型検査Gate 1）。
  - [ ] AC-3: `cd frontend && npx vitest run` で既存テスト（`HistoryPage.test.tsx` 含む）が全件PASSすること。
