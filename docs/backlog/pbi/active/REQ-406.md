### REQ-406: SPEC_SUMMARY §6 のエンティティ一覧を実装の整合性制約に合わせる

- **Type**: chore（文書）
- **Status**: frontmatter の `status` を参照（状態の正本）。
- **Priority**: P3（仕様書の正確性の改善。仮置き）
- **Surface**: `docs/specs/SPEC_SUMMARY.md` の「6. DB 設計 & 外部キー制約（SQLite）」内「エンティティ一覧 & 整合性制約」の表。
- **利用者ニーズ**: 設計・実装・レビューを行う開発者が、仕様書のエンティティ一覧を信頼して、テーブル名・一意制約・外部キーを判断できるようにしたい。
- **課題の整理（事実）**: 一覧が backend の実際のモデルと食い違っている。以下はユーザーから受領した事実で、この PBI の作成時に実装は再調査していない。
  - (a) `llm_prompts` は「`key` 主キー一意制約」と書かれているが、実際は `key` が UNIQUE で、主キーは `id`。
  - (b) `speech_bubble_presets` は「`name` 一意」と書かれているが、実際は (`name`, `orientation`) の複合一意。
  - (c) `speech_bubble_presets` の外部キー（`tag_set_id` -> `tag_sets.id` `SET NULL`、`tone_preset_id` -> `speech_tone_presets.id` `SET NULL`）が載っていない。
  - (d) 表名 `mapping_master` は、実際は `mapping_masters`。
  - (e) 表に載っていないテーブル: `mapping_group_masters`, `stage_masters`, `mapping_variants`, `workflow_history`, `lora_example_images`, `prompt_metadata`, `generation_jobs`, `app_settings`, `dataset_projects`, `dataset_items`, `outfit_master_presets`, `lora_training_jobs`。
- **5 Whys**:
  1. なぜ起票するか: 仕様書の一覧が実装と異なり、読んだ人が誤った制約を前提にするおそれがあるため。
  2. なぜ誤りが問題か: 例えば `speech_bubble_presets` を `name` 単独で一意と読むと、向き違いの同名プリセットを不正と誤判定し、設計・テスト・検証が実装とずれるため（推定）。
  3. なぜ食い違いが生じたか: テーブルやカラムが追加・変更されても、完了時の仕様書同期が §6 まで及ばなかったため（推定）。
  4. なぜ見過ごされてきたか: 一覧がどの範囲のテーブルを載せるかの方針が書かれておらず、欠落を欠落として検出できないため。
  5. 根本原因: §6 の記載範囲と、実装との照合の手順・責任が定められていない。
- **UX Classification**: N/A（開発者向けの仕様書の正確性の改善であり、製品利用者向けの Information Design / Interaction / Visual には当たらない）。
- **Requirement**: §6 のエンティティ一覧が、backend の実際のモデル（テーブル名、一意制約、主キー、外部キーと削除時の動作）と一致していること。一覧に載せる範囲の方針が文書に明記されていること。

## 範囲

- 対象: `docs/specs/SPEC_SUMMARY.md` の §6 の表と、その記載範囲の説明。上記 (a) から (e) の是正。
- 対象外: backend のモデル、マイグレーション、API の変更（仕様書を実装に合わせるのであり、実装を仕様に合わせない）。§6 以外の節の再構成。
