### REQ-403: テスト名の検査が追跡ファイルを書き換えないようにする

- **Type**: chore
- **Status**: frontmatter の `status` を参照（状態の正本）。
- **Priority**: P3（開発者向けの検証手順の安全性改善。仮置き）
- **Surface**: 開発者・検証担当が実行するテスト名検査（`scripts/verify_test_naming.py`）と、git で追跡されている `docs/design/REQ-356-test-mapping.md`。利用者向け画面には影響しない。
- **利用者ニーズ**: 検査（検証）を実行しただけでリポジトリの追跡ファイルが変わらないようにしたい。検査のたびに手で元へ戻す手間と、変更の混入を防ぎたい。
- **課題の整理（事実）**: `python scripts/verify_test_naming.py --strict` を実行するたびに、追跡対象の `docs/design/REQ-356-test-mapping.md` が書き換わる。REQ-309 では実行のたびに `git checkout --` で戻す必要があった。このファイルは生成物で、どこからも使われておらず、REQ-356 は done である。
- **5 Whys**:
  1. なぜ起票するか: 検査を実行するたびに追跡ファイルに差分が出て、毎回手で戻す必要があるため。
  2. なぜ手で戻す必要があるか: 検証の実行が作業ツリーを汚し、そのままだと担当外の差分が候補・コミット範囲に混入しうるため。
  3. なぜ差分が出るか: 検査の実行に伴い、完了済みの REQ-356 の生成物が追跡パスへ出力されるため（推定。実装は調査していない）。
  4. なぜ放置されてきたか: 生成物は誰にも参照されず、REQ-356 完了後に見直す契機がなかったため（推定）。
  5. 根本原因: 検査（読み取り専用であるべき検証）が、不要な生成物を追跡対象へ書き出す副作用を持っている。
- **UX Classification**: N/A（開発者向けの検証基盤の改善であり、利用者向けの Information Design / Interaction / Visual のいずれにも当たらない）。
- **Requirement**: テスト名の検査を実行しても、git の追跡ファイルが変わらず、実行後に残る不要な生成ファイルがないこと。

## 範囲

- 対象: 検査の実行が作業ツリーに与える副作用の除去と、不要な生成ファイルの整理。
- 対象外: 検査が報告する既存の規約違反 18 件の解消（`--strict` は現状 exit 1）。検査の判定基準（ファイル名規約、`[REQ-xxx/AC-n]` 規約）の変更。

## Acceptance Criteria

- [ ] AC-1: 検査実行で追跡ファイルが変わらない
  - Given 作業ツリーに未コミットの変更がない
  - When `python scripts/verify_test_naming.py --strict` を実行する
  - Then 実行後も `git status` に追跡ファイルの変更が現れないこと
- [ ] AC-2: `--strict` なしでも追跡ファイルが変わらない
  - Given 作業ツリーに未コミットの変更がない
  - When `python scripts/verify_test_naming.py` を `--strict` なしで実行する
  - Then 実行後も `git status` に追跡ファイルの変更が現れないこと
- [ ] AC-3: 繰り返し実行しても作業ツリーが変わらない
  - Given 作業ツリーに未コミットの変更がない
  - When 同じ検査を続けて 2 回実行する
  - Then 1 回目の後と 2 回目の後で `git status` の内容が同じで、いずれも空であること
- [ ] AC-4: 不要な生成ファイルを残さない
  - Given 本 PBI の完了後のリポジトリ
  - When 検査を実行する
  - Then 検査の実行によって新しい未追跡ファイルが作られず、`docs/design/REQ-356-test-mapping.md` が追跡対象に残らないこと
- [ ] AC-5: 参照切れを生じさせない
  - Given `docs/design/REQ-356-test-mapping.md` の扱いを変更した
  - When リポジトリ内の文書・設定・スクリプトからそのファイル名への参照を検索する
  - Then 参照が残っていないこと、または参照先が更新されていること
- [ ] AC-6: 検査の判定結果が変わらない
  - Given 本 PBI の着手前と同じ既存違反（命名違反 18 件）がある状態
  - When 検査を `--strict` で実行する
  - Then ファイル名違反件数、テスト名違反件数、exit code（1）が着手前と同じで、違反の解消または増減をこの PBI で行わないこと
- [ ] AC-7: 手順書から復元手順が不要になる
  - Given 検査を含む検証手順を読む開発者がいる
  - When 手順どおり検査を実行する
  - Then 検査後に `git checkout --` などで追跡ファイルを戻す手順を必要とせず、手順書にもその記述が要求されていないこと

## Inferred points

<inferred_points>
- 「生成物でどこからも使われていない」はユーザーから受領した事実で、本 PBI の作成時に実装・全文書を再調査していない。AC-5 の参照検索は設計時の再確認として置く。
- 「不要な生成ファイルを残さない」を、(a) 生成ファイル `docs/design/REQ-356-test-mapping.md` を追跡対象から外す（削除する）こと、(b) 検査が今後そのような出力を行わないこと、の両方と解釈した。ファイルの削除を許容するか、履歴として残すか（アーカイブ配置など）は要確認。
- 対応表を出力する機能を、利用者が明示的に求めたときだけ使える形で残すか、廃止するかは要確認（現状は誰も使っていない前提で、廃止を想定）。

- 既存違反 18 件は REQ-309 の着手前（HEAD `37f16e7`）で確認された件数。着手時に件数が異なる場合は、AC-6 を「着手前の基準値と同じ」として読み替える。
- 要件取りまとめ時点では実装コードは未調査。
