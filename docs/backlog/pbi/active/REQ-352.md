### REQ-352: ヘッダーの状態変化で隣接アクションの位置が動かない幅を確保する

- **Type**: feature
- **Status**: ready
- **Priority**: P2（仮置き）
- **Surface**: 共通ヘッダーの状態バッジと隣接アクション
- **Operational need**: 状態変化中も同じ位置のボタンを狙い誤操作を避ける。
- **5 Whys / 業務上の課題整理**（ユーザー報告からの要約。実装原因の断定ではない）:
  1. 状態変化で隣の操作領域が動き押しづらい。
  2. 状態文字数によって幅が変わる。
  3. クリック前に位置が動くと狙いが外れる。
  4. 定義済み状態に必要な幅を確保すれば位置を安定させられる。
  5. 固定状態定義に対して領域が状態ごとに伸縮することが課題である。
- **UX Classification**: Interaction / Visual
- **Requirement**:
  - 全定義済み状態を表示できる一定幅を状態領域へ確保する。
  - 状態変化だけで隣接操作の位置が変わらず状態全文を表示する。
- **Acceptance criteria**:
  - [ ] AC-1: Given ページ・タイトル・画面幅・アクション構成が一定, When 定義済み全状態を順に表示する, Then 隣接アクション領域と各ボタンの左端座標が各状態で等しいこと。
  - [ ] AC-2: Given 同一表示条件, When 最短と最長の状態を切り替える, Then 状態領域の幅が等しいこと。
  - [ ] AC-3: Given 定義済み最長状態, When ヘッダーを表示する, Then 状態全文が省略・欠落・隣接操作との重なりなく表示されること。
  - [ ] AC-4: Given 対応対象各ページのdesktop/tablet/mobile幅, When そのページの全状態を順に表示する, Then 同じ表示条件内で位置を維持し各操作を押下できること。
- **Reference docs**:
  - SPEC_COMMON.md 共通ヘッダー
  - SPEC_GENERATE.md §2-1
- **Inferred points**:
<inferred_points>
- 必要幅はページ・タイトル・状態定義・対応画面幅の組み合わせで定義する。画面幅やページ変更後まで同一座標を求めない。
- ページ追加・文言変更時は幅の見直し対象。固定px値や計算方法は設計に委ねる。
</inferred_points>

- **BA contradiction audit**: 2026-10-11監査完了。結論はoverflow/画面幅の明確化推奨。監査直後のunload成功。証跡: [監査証跡](../../ba-audit/REQ-352.md)
- **BA audit response**: 対象は現在定義済みの状態であり、未定義の動的文言は仮定しない。ページ追加・文言変更時の見直し、表示条件ごとの必要幅、幅変更後まで同一座標を求めない条件は推論点に明記済み。対応各画面幅はAC-4で検証する。既知の全文が収まる幅と位置固定は両立可能で、省略を導入するモデル提案は今回の方針へ追加しない。実際の必要幅・レスポンシブ配置は設計で確認し、監査の明確化推奨を保持する。
- **Human review gate**: 2026-10-11にユーザーが本PBIをOKと明示承認。承認済みとしてreadyへ変更する。ユーザー指示に従い開発への引継ぎは行わない。
