# REQ-418-T3: プリセット API と workflow copy

Subsystem: backend (API). Role: engineer. This Card is the sole semantic specification for the task. Run commands from the repository root `repo root`. Prerequisites: T1 (`variant_keys`, `VariantRef`) and T2 (models) are complete.

### 1. Purpose and scope

Preset parameter values move from the JSON text column `workflow_presets.param_values` to rows in `workflow_preset_values` (FK to `mapping_variants`). The API stays backward compatible: responses still expose `param_values` keyed by the CURRENT role (resolved through the variant FK, so a role/display-name change is reflected immediately, AC-4), plus the additive `variant_param_values` and `variants`. (Note: AC-1 preset migration is implemented in REQ-418-T2; AC-2 snapshot restoration is implemented in REQ-418-T4; AC-3 sync groups and AC-4 sync-group list are implemented in REQ-418-T5 and REQ-418-T6.)

Completion: `GET/POST/PUT /api/workflow-presets` and workflow copy use the value table; the cases in section 5 pass; existing preset tests still pass.

### 4. Implementation logic

- [ ] Build `VariantIndex.from_session(db)` once per request (not per preset). Read path: assemble `stored = {encode_variant_key(r.variant_id, r.sub_key): r.value for r in preset.values}` merged with the reserved JSON dict (`json.loads(preset.param_values)`, tolerate empty/invalid as `{}`); call `expand_stored_params(index, stored, owner_label=f"workflow_preset {preset.id}")`; `param_values = role_keyed` (cast values to `str`), `variant_param_values` = the `v:`-prefixed entries of `variant_keyed`. Rows whose variant no longer exists are skipped by the resolver (it logs a warning); the endpoint must still return 200. Fill `variants` from `MappingVariant` + `master` for the referenced ids in one query for the whole list (avoid per-preset queries).
- [ ] Write path (create and update when `payload.param_values is not None`): `normalize_params(index, payload.param_values)`; each name in `unresolved` -> one `logger.warning` containing the preset id (or `new`) and the key, then it is dropped; replace `preset.values` entirely with new `WorkflowPresetValue` rows from `entries`; set `preset.param_values = json.dumps(reserved, ensure_ascii=False)`. For `update`, when `param_values` is omitted do not touch values. Keep `preset.updated_at = datetime.now(timezone.utc)` and the existing 409 `base_updated_at` logic EXACTLY as is.
- [ ] `create_preset`: create the preset (flush for its id), then add value rows; response built by the same read path.
- [ ] `copy_workflow`: copy each preset's `param_values` text AND its `values` rows (same `variant_id`, `sub_key`, `value`); copy each sync group's `master_role`, `slave_roles`, `is_enabled` AND `master_variant_id` and member rows (same variant ids). Do not touch anything else in `workflows.py`.
- [ ] Do not change `applied_assets` handling, ordering, reorder/bulk-delete endpoints, or response status codes.
- [ ] If an existing test in `test_presets.py` posts role strings that have no variant (they are now dropped), rewrite its fixture to create real variants (allowed, section Delegation). If an existing test OUTSIDE your owned files (e.g. `test_workflows.py` copy tests) fails because of your change, do not edit it; stop and escalate with the failing test id.
