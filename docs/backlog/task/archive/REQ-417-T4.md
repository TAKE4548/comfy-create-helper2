# REQ-417-T4: フロントエンド値適用処理のinput_name直接使用化

## 1. 概要と目的
ワークフロー実行時およびプレビュー時において、`WorkflowMapping.input_name` を直接使用してパラメータを注入するように `workflowParamInjector.ts`, `seedInputResolver.ts`, `seedBatch.ts` を改修する。これにより、実行時における曖昧なフォールバック探索処理（ノード入力辞書に対するカンマ区切りパラメータ名のループ検索等）を廃止し、決定論的なパラメータバインドを実現する。

## 2. ターゲット識別
- **対象ファイル**:
  - `frontend/src/utils/workflowParamInjector.ts`
  - `frontend/src/utils/seedInputResolver.ts`
  - `frontend/src/utils/seedBatch.ts`
  - `frontend/src/utils/__tests__/workflowParamInjector.test.ts`
- **対象シンボル**: `injectWorkflowParams`, `getInitialParams`, `resolveSeedInputKey`, `injectGeneralParam`

## 3. 密閉コンテキスト (Hermetic Context)
<hermetic_context>
### 3.1 `input_name` 直接適用コードスニペット (`frontend/src/utils/workflowParamInjector.ts`)
```ts
// 一般パラメータの注入処理
workflow.mappings.forEach((m) => {
  if (!m.role || !m.node_id) return
  const node = wfJson[m.node_id] as WorkflowNode | undefined
  if (!node) return
  if (!node.inputs) node.inputs = {}

  if (m.input_type === 'lora_stack') {
    injectLoraStackParams(node.inputs, m.role, paramValues, node.class_type)
  } else if (m.input_type === 'seed') {
    const prepared = preparedSeeds.get(m)
    if (!prepared) throw new Error(`${m.display_name || m.role}: seed入力の準備に失敗しました`)
    node.inputs[prepared.key] = prepared.seed
  } else if (m.role !== 'Sampler_Seed' || !seedOptions) {
    // input_name が存在する場合は最優先で直接使用
    const targetParam = m.input_name || m.param_name || 'value'
    const rawVal = paramValues[m.role] !== undefined ? paramValues[m.role] : defaultParams[m.role]
    injectGeneralParam(node.inputs, targetParam, m.input_type, rawVal)
  }
})
```
</hermetic_context>

## 4. 実装要件 (Implementation Logic)
- [ ] `frontend/src/utils/seedInputResolver.ts` において、`m.input_name` が定義されている場合はフォールバック解決を行わず直ちに `m.input_name` を返すよう更新する。
- [ ] `frontend/src/utils/workflowParamInjector.ts` の `getInitialParams` および `injectWorkflowParams` において、`m.input_name` を直接使用してノードの inputs スロットに値を注入する。
- [ ] `frontend/src/utils/seedBatch.ts` における seed 解決処理でも、`m.input_name` を優先参照するよう改修する。
- [ ] 後方互換性として `m.input_name` が空または未定義のレガシーデータに対してのみ、既存のフォールバックロジックで安全に解決するガードを残す。
- [ ] `frontend/src/utils/__tests__/workflowParamInjector.test.ts` に `[REQ-417/AC-4]` テストケースを追加し、`input_name` 直接注入が正常に機能することを検証する。
