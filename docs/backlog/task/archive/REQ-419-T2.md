# REQ-419-T2: 原子的保存API・判定プレビューAPI・Variant読み取りのインライン定義

## 1. 目的
(a) Master 編集の1回の保存（Master 値定義＋定義の作成/更新＋Variant の作成/更新/参照付替え）を **単一トランザクション** で適用し、どの失敗でも全件ロールバックする `POST /api/mapping-masters/{master_id}/atomic-save`。(b) 未保存定義で登録済みワークフローを判定する非永続 `POST /api/mapping-masters/scan-preview`。(c) フロントの候補ランク付け・ステージ検出用に `MappingVariantRead` へ参照定義の Entry/パターンを読み取り専用で含める。担当 AC: AC-2(c)、AC-3、AC-5、AC-6、AC-9、AC-10、AC-12（原子性）、AC-13（プレビューの旧フィールド不使用）。

### 4-1. 原子的保存スキーマ（`schemas/mapping.py`）

### 4-2. サービス `services/mapping_master_save.py`
```python
class MasterSaveValidationError(Exception):
    def __init__(self, errors: list[dict]): ...   # 各 {scope, index, ref, row_key, field, message}
def validate_atomic_save(db: Session, master: models.MappingMaster, req: MasterAtomicSaveRequest) -> list[dict]
def apply_atomic_save(db: Session, master: models.MappingMaster, req: MasterAtomicSaveRequest) -> None  # commit しない
```
検証（全件を集めてから返す。DB は読むだけ）:
- master: `name` 空、`group_id` 不在。
- rule_sets/selectors: `ref` 重複、update の `id` 欠落・不在、create/update 後の名前が既存（自分以外）や同一要求内と衝突、rule_sets に patterns / selectors に entries、match_type は schema で 422。
- variants: `id` がこの Master の Variant でない（`field="id"`）、stage 不在、最終状態で同一 stage_id が2件以上（id なし item が既存 Variant の stage を使う場合を含む）、最終状態で同一の非 null セレクタが2件以上（null は除外）、`DefinitionRef` の id 不在・ref 未定義（`field="rule_set"`/`"selector"`）、新規 Variant の role（`master.base_key + stage.suffix`）が他 Variant（全 Master）と重複（`field="role"`）。
適用順（全て同一セッション・未コミット）: ①Master 値定義を更新（`display_name=name`、`role`・`base_key`・旧列は変更しない）→ ②定義 create を `db.add`、update は name と entries/patterns を全置換 → `db.flush()` で ref→id を解決 → ③セレクタが変わる既存 Variant の `node_selector_id` を一旦 None にして `flush()` → ④各 Variant に `binding_rule_set_id`/`node_selector_id`/`is_enabled` を設定、id なしは新規作成（role は上記、`sort_order=stage.sort_order`、`extra_title_patterns="[]"`）→ `flush()`。

### 4-3. ルーター（`mapping_masters.py`）
```python
@router.post("/{master_id}/atomic-save", response_model=MappingMasterV2Read)
def atomic_save_master(master_id: int, payload: schemas.MasterAtomicSaveRequest, db: Session = Depends(get_db)):
    mm = ...  # 無ければ 404
    errors = validate_atomic_save(db, mm, payload)
    if errors: raise HTTPException(422, detail={"code": "MASTER_SAVE_VALIDATION_FAILED", "errors": errors})
    try:
        apply_atomic_save(db, mm, payload)
        db.commit()
    except IntegrityError:
        db.rollback(); raise HTTPException(409, detail={"code": "MASTER_SAVE_CONFLICT", "message": "..."})
    except Exception:
        db.rollback(); raise
    db.refresh(mm); return _to_schema_v2(mm)
```
`commit` は1回のみ。既存 `update_master`（PUT）・`create_master` は変更しない。

### 4-5. Variant 読み取りのインライン定義（`mapping_masters.py` 現 L365-382 `_to_variant_schema`）

def _to_variant_schema(v: models.MappingVariant) -> MappingVariantRead:
