## 3. 実装要件 (Implementation Logic)

### 3.1 タブ構成の2タブ化と旧LoRAタブの完全削除 (`ProfileBulkEditModal.tsx`)
- `Tab` 型を `'prompt' | 'params'` に変更。
- タブバーを「プロンプト」「パラメータ」の2ボタンのみに変更。
- 旧LoRAタブのレンダリングブロック（L999-L1122）および不要となったState（`loraFilename`, `loraRole`, `loraMode`, `loraStrength`）を削除。
- プロンプトタブ内の「アセットを追加」ボタンおよび `assetOps` はプロンプト用アセット注入機能としてそのまま維持。

### 3.2 共通LoRA抽出純粋関数の実装 (`computeCommonLoras`)
- `computeCommonLoras(presets: WorkflowPreset[], role: string): CommonLoraItem[]` を実装。
- 各プリセットの `param_values` から `${role}_lora_name_*` を抽出し、全選択プリセットで共通するLoRA（積集合）を特定してリスト化。

### 3.3 パラメータタブ内の LoRA Stack UI（個別チェックボックス、モード切替、差分編集／完全上書き）
- `m.input_type === 'lora_stack'` の描画時、他のパラメータ型と同様のラッパー `<div className="p-3 bg-[#1F1F25]/60 border border-[rgba(255,255,255,0.06)] rounded-lg space-y-3">` で囲み、チェックボックス `<input type="checkbox" checked={isEnabled} onChange={() => toggleParamEnabled(m.role)} />` を提供。
- チェックOFF時は全体を非活性（`opacity-40 pointer-events-none`）表示。
- チェックON時、編集モード切替ボタンを表示:
  - **「差分編集（共通確認・追加・削除）」** (デフォルト)
  - **「完全上書き」**
- **差分編集モード**:
  - `computeCommonLoras` で抽出した共通LoRA一覧を表示。
  - 各共通LoRAに削除ボタン（ゴミ箱アイコン）および強度編集フィールドを配置。削除押下時は取消線スタイルにし、`action: 'remove'` として追跡。
  - 新規追加スロット領域を設け、「+ LoRAを追加」でスロット（LoRA選択、強度）を追記可能に。
- **完全上書きモード**:
  - `LoraStackEditor` を配置し、プリセットの既存LoRAを全置換する新スロット群を設定可能に。

### 3.4 `buildPayload` における `loraStackOps` の生成
- `enabledParams.has(role)` かつ `mapping.input_type === 'lora_stack'` の場合:
  - 差分編集モード時: `loraStackOps = [{ role, mode: 'differential', commonOps, addSlots }]`
  - 完全上書きモード時: `loraStackOps = [{ role, mode: 'overwrite', slots }]`
  - ペイロードに `loraStackOps` を設定。

### 3.5 `usePresetState.ts` における `loraStackOps` の適用
- `handleBulkEditApply` 内で `payload.loraStackOps` を走査:
  - `mode === 'overwrite'`: 既存全スロット削除後、新スロットを登録。
  - `mode === 'differential'`:
    - 当該プリセットの既存スロットから `commonOps` で `action === 'remove'` のLoRAを除外し、`action === 'update'` の強熱を更新。
    - `addSlots` のLoRAを末尾に追加（最大10スロットでクランプ）。
    - `${role}_lora_count` および各スロットキーを `newParamValues` に再構築。
