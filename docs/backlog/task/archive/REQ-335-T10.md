## 3. 変更内容

### 3.1 F-1: L552（行内の1箇所置換）
置換前（部分）:
```
`unconfirmed` のjobは確認済み終了（`already_terminal`）として扱わず、待機・生成中・進捗の母数から分離して「状態未確認」と表示する。
```

置換後:

```
`unconfirmed` のjobは確認済み終了（`already_terminal`）として扱わず、待機・生成中の表示とせず、通常生成の進捗母数からも分離して「状態未確認」と表示する（Studioの進捗母数の扱いは `SPEC_GENERATE.md` の規定に従い、状態未確認はStudioの母数に残る）。
```

### 3.2 F-2: L553 の末尾（`解除記録は通常のterminal保持とは別に最大1000件（古い順）を保持する。` の直後、同じ行の末尾に追記）
```
解除の対象は状態未確認（`unconfirmed`）の記録だけで、呼び出し側が明示した `job_ids` のjobだけが影響を受け、それ以外のjobの状態は変更しない。結果の `outcome` は、`released`（今回の操作で解除した）、`already_released`（解除済みで変更なし）、`not_released`（状態未確認ではない、または解除前の上流照合で進行・終了を確認して状態を更新したため解除せず、解除記録も作らない）、`rejected`（該当する記録がない）を表し、いずれも上流の取消・成功・失敗の確認を意味しない。
```
根拠（設計書§6.4、`backend/app/services/generation_service.py` `_release_one` L352付近 の読取りで確認済み）: 該当なし→`rejected`／`status=released`→`already_released`／`status≠unconfirmed`→`not_released`／照合後に状態が動いた・CAS 失敗→`not_released`／解除成功→`released`。
