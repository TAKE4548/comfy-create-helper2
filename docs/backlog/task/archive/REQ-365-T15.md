## テストケース
各viewportで `await page.setViewportSize({width, height: 900}); await page.goto('/settings#workflows')`。
1. `[REQ-365/AC-1] 1280px: dual pane` — `settings-card-workflow` と `settings-card-basemodel` の `boundingBox().x` が同一（左）、`settings-card-mapping` はそれより右。`settings-card-basemodel.y >= settings-card-workflow.y + height` かつ差が <= 24px（左カラム内に空隙なし）。`settings-card-mapping.y` ≒ `settings-card-workflow.y`（上端揃い、±2px）。
2. `[REQ-365/AC-1] 1279px: single column order` — 3カードの `x` が同一、`y` の順序が workflow < mapping < basemodel。
3. `[REQ-365/AC-2] 767px: horizontal swipe tablist with numbered compact labels` — `role=tablist` の `scrollWidth > clientWidth` もしくは `overflow-x` が auto、タブ文言が `① モデル`…`⑤ システム`、`getComputedStyle(tablist).scrollSnapType` に `x` と `mandatory`。
4. `[REQ-365/AC-2] 768px: grid tabs with long labels` — `display: grid`、長い表示名が見える、`md` 余白(`padding-bottom` が 20px)。
5. `[REQ-365/AC-2] 375px: interactive controls are >=44px` — `.req314-settings` 内の可視 `button, select, input:not([type=checkbox]):not([type=radio]), [role=tab]` の全`boundingBox`について `height >= 44`（アイコンボタンは `width >= 44` も）。違反要素を列挙して失敗メッセージに出す（RT-9）。
6. `[REQ-365/AC-3] 375px: mapping master cards` — `.settings-mobile-card` の `display` が `grid`、`__target-node` が `display:none`、`__actions` が行の右端（カード右端との差 <= 16px）。`thead` が可視でない。
7. `[REQ-365/AC-9] 375px: param type manager opens as bottom sheet` — 「カスタム型マスタ」クリック → `role=dialog` の下端が viewport 下端±1px、上端左右の `border-top-left-radius` が 16px、`modal-sheet-handle` が可視、`maxHeight` <= 85% viewport。
8. `[REQ-365/AC-9] 768px: same dialog is centered, not a sheet` — dialog の下端 < viewport下端 かつ水平中央±2px。
9. `[REQ-365/AC-2] 375px: content bottom padding clears the bottom nav` — `#settings-panel-system` までスクロールし、最終要素の下に `>= 54px(nav) + safe-area` の余白（スクロール末尾の最後の要素とviewport下端の差 >= 54px）。
