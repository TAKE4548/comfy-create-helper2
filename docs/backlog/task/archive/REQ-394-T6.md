# REQ-394-T6: pool / isolate の明示（AC-1）

## 実行境界

- 役割は engineer / dev-task。FE のコマンドは `cd frontend` してから実行する。
- 所有ファイルは `frontend/vite.config.ts` だけ。`test` ブロック以外（`cleanBrokenViteDeps`、`server`、`plugins`）は変更しない。テストファイル、製品コードは変更しない。
- 前提: T4 が完了していること。コーディネーターが設計承認を確認し、exact-ID で in-progress へ遷移済みであること。状態更新・QA・commit は担当外。
- UI 制約: 該当なし（テスト設定のみ）。

## 決定（計測済み。設計 §2.1、§4-4）

- pool は `forks` のまま、maxForks は既定のまま。6/8/10、threads の比較は負荷変動（±20%）に埋もれ、有意差がない。
- **`isolate: false` は不採用**: node 環境化後に forks 8 + isolate=false で実行すると、ファイル間の状態リークで `No queryFn was passed ...` が無限に出力されてハングした（ログ `docs/logs/REQ-394/fe-exp-E7-node43-noisolate-forks8.txt`）。
- vmThreads / vmForks は不採用: 21 ファイルが失敗（msw の `WritableStream` 未定義、`location` 再定義不可など）。
- 値を変えず、現在の既定を明示してコメントで根拠を残す（将来の `isolate:false` 化を防ぐ）。

## 変更箇所

現状（`frontend/vite.config.ts` の `test` ブロック）:

```ts
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: './src/test/setup.ts',
    pool: 'forks',
    include: ['src/**/*.{test,spec}.{ts,tsx}'],
    exclude: ['**/node_modules/**', '**/dist/**', 'e2e/**'],
  },
```

変更後（`pool: 'forks',` の行に続けて追加。他の行は変えない。型は `tsc -p tsconfig.node.json --noEmit` で通ることを scratch で確認済み）:

```ts
    pool: 'forks',
    // REQ-394: keep isolate:true. isolate:false hung the run (cross-file state leak, endless refetch
    // logging) and vmThreads/vmForks break msw/location. Files that need no DOM opt in to the node
    // environment with a "// @vitest-environment node" first line; everything else stays on jsdom.
    poolOptions: { forks: { isolate: true } },
```
