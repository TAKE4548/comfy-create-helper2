# TASK-REQ-152-01: バッチ生成キュー登録時の不要オーバーヘッド削減およびキャンセル時状態復活デグレの修正

## 1. タスク概要

バッチ生成キュー投入時の以下4つの不具合を修正する。

| Issue | 説明 |
|-------|------|
| **Issue 1** | `handleGenerateSets` の `finally` 句がキャンセル後にも無条件で `setActiveBatch` を上書きし生成状態が復活する |
| **Issue 2** | `queuePrompt` の `fetch('/prompt')` に `AbortSignal` が連動しておらず、通信中キャンセルでもComfyUI投入が完了してしまう |
| **Issue 3** | 逐次投入ループ各イテレーションでの不要な重い `set()` とWS経由 `fetchQueue()` 多重発火によるUI応答悪化 |
| **Issue 4** | `fetchQueue` の自動クリアロジックが `activeBatch` 中のfake `pending-...` IDをComfyUIキューで検索→未ヒット→ `activeBatch: null` を誤セットし投入途中でバッチが消える |

### 4-2. `useGenerateAction.ts` の `handleGenerateSets` 修正

```typescript
const handleGenerateSets = async () => {
  if (!workflow) return
  const checkedSets = sets.filter((s) => s.checked)
  if (checkedSets.length === 0) return

  const abortController = new AbortController()
  setSubmissionAbortController?.(abortController)
  setIsBatchSubmitting?.(true)   // ← 追加 (Issue 4): fetchQueue自動クリア抑止

  // REQ-141維持: 全件 pending 枠を即時初期化
  const initialBatch: BatchJob[] = []
  checkedSets.forEach((setItem) => {
    for (let i = 0; i < setItem.batchSize; i++) {
      initialBatch.push({ promptId: `pending-${setItem.name}-${i}-${Date.now()}`, setName: setItem.name, status: 'pending' })
    }
  })
  setActiveBatch(initialBatch)
  const currentBatch: BatchJob[] = [...initialBatch]  // REQ-141維持: 固定長配列

  // ... mappings, bypass, currentIdx など前処理 ...

  try {
    for (const setItem of checkedSets) {
      for (let i = 0; i < setItem.batchSize; i++) {
        if (abortController.signal.aborted) { return }   // 既存: ループ先頭チェック

        // ... wfJson構築 ...

        let promptId: string | null = null
        try {
          promptId = await queuePrompt(
            wfJson,
            { paramValues: syncedParamValues, appliedAssets: setItem.appliedAssets },
            {
              skipQueueFetch: true,
              signal: abortController.signal,   // ← 追加 (Issue 2)
              isBatchIntermediate: true,         // ← 追加 (Issue 3)
            }
          )
        } catch (err) {
          console.error(`Failed to generate set ${setItem.name} (batch index ${i}):`, err)
        }

        // ← 追加 (Issue 1/2): queuePrompt 完了後のキャンセルチェック
        if (abortController.signal.aborted) { return }

        if (promptId) {
          mappings[promptId] = setItem.name
          // REQ-141維持: インプレース更新（配列サイズ不変）
          currentBatch[currentIdx] = { ...currentBatch[currentIdx], promptId, status: 'pending' }
          setActiveBatch([...currentBatch])
        } else {
          const errorMsg = `[${setItem.name}] (${i + 1}/${setItem.batchSize}) のキュー投入に失敗しました`
          setErrorToast?.({ message: errorMsg, type: 'error' })
          // REQ-141維持: failed に遷移
          currentBatch[currentIdx] = { ...currentBatch[currentIdx], status: 'failed' }
          setActiveBatch([...currentBatch])
        }
        currentIdx++
      }
    }
  } finally {
    setIsBatchSubmitting?.(false)   // ← 追加 (Issue 4): 必ずリセット
    localStorage.setItem('prompt-surgeon-prompt-to-set-map', JSON.stringify(mappings))

    // Issue 1 修正: キャンセル中断時は setActiveBatch 上書きと fetchQueue を抑止
    if (!abortController.signal.aborted) {
      setActiveBatch([...currentBatch])
      await fetchQueue?.()
    }
  }
}
```

## 5. REQ-141 維持要件（デグレ防止チェックリスト）

実装後、以下が従来通り動作することを確認すること：

| # | 維持要件 | 実装箇所 |
|---|----------|---------|
| M-1 | ボタン押下直後に全件 `pending-...` 枠が `setActiveBatch(initialBatch)` で即時表示（0ms表示） | `handleGenerateSets` ループ前 |
| M-2 | 各ジョブ投入完了時に `currentBatch[currentIdx]` を実 `promptId` でインプレース更新（配列サイズ不変・State Thrashing防止） | ループ内 `setActiveBatch([...currentBatch])` |
| M-3 | NG応答時（`promptId: null`）は `status: 'failed'` に遷移し個別エラートーストを表示 | `else` ブロック |
