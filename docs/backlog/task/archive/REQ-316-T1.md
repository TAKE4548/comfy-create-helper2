### Import・transport・保存データ契約
- `PromptMetadataRead` と `promptMetadataApi` は `frontend/src/api/client.ts` のnamed export。`frontend/src/utils/promptRecord.ts` から `../api/client` をimportする。`get(promptId)` は `Promise<PromptMetadataRead>` 相当でGET `/prompt-metadata/${encodeURIComponent(promptId)}`。応答は `prompt_id:string`, `workflow_id:number|null`, `param_values:Record<string,any>`, `applied_assets:Record<string,any>|null`, `created_at:string`。GETの404/rejectionは呼出元がcatchしnullとして扱えるようutilityからrejectしない。
- localStorage keyは `prompt-surgeon-meta-${promptId}`。現在の値はJSON object `{paramValues: Record<string,unknown>, appliedAssets: Record<string,unknown>, timestamp:number}`（`timestamp`は`Date.now()` epoch ms）。保存元 `frontend/src/store/slices/jobQueueSlice.ts:140-154`。現在のreader `frontend/src/components/HistoryModalPreview.tsx:168-183`。
- server write payloadは `{prompt_id, workflow_id?, param_values, applied_assets?}`。保存元は同jobQueueSliceで非同期。server `created_at`はメタデータ保存時刻、local `timestamp`は端末保存時刻として識別し、生成完了時刻と呼ばない。`ResolvedMetadata`はlocal優先、破損/旧local時だけserverへfallback、prompt IDを照合して同一ソースのparams/assetsを返す。local-only metadataにはserver時刻を捏造しない。
- `GenerationMetadataPanelProps` の構造は `REQ-316-T14.md` を参照し、utility側からcomponentをimportしない。fieldsは `REQ-316-T15.md` の `PromptFieldView` と構造互換（`key/name/role/nodeId/recorded/value/status`）。parameters/extras/assetsは `{key,name,recorded,value:JsonValue,role?,status?}`。T4がMetadataViewからT14/T15へ接続する。
- `loraRows`は新recordの `parameters` から、`input_type === 'lora_stack'` の記録値のみ読む。`class_type === 'easy loraStack'` または`inputs.num_loras`/`inputs.lora_1_name`があるeasy形式と、`lora_count`/`lora_name_N`があるstandard形式を既存 `frontend/src/utils/workflowParamInjector.ts:35-73,102-144` に合わせる。件数は`num_loras`優先、次に`lora_count`、いずれもなければname slot 1〜10の最大index。nameは`lora_N_name`優先/fallback `lora_name_N`、weightは`lora_N_strength`/`lora_wt_N`、modelは`lora_N_model_strength`/`model_str_N`、clipは`lora_N_clip_strength`/`clip_str_N`。model/clipを統合せず各欄を値のまま提示し、空/0を欠落扱いしない。class_type/input keyを別形式へ推定しない。旧flat値は実投入値へ昇格しない。

## 実装
generationRecord型はT9からimport。妥当recordをparseし全fields/parameters/通常JSON値を表示modelへ。complete+未記録/重複ID/未知versionは完全扱いしない。旧データは全JSON通常キーをキー名で表示（scalar限定を撤回）、actual seed/workflow名へ昇格しない。false/0/null/配列/辞書/空値を保持。除外は2予約キーだけ。getMetadataViewは現在入力/master/workflowを受け取らない。fieldsはT15 propsに合わせnodeId/keyを持ち、非string textareaを未記録として扱う。actualSeedは新recordのsubmitted Sampler_Seedだけ。loraRowsは記録されたstackのclass_type/inputsからモデルと各強度を別々に抽出、旧flat値は保存値として別表示し実投入へ昇格しない。resolveはv1 local優先、旧/破損localでserver照会、prompt ID照合、params/assets同一ソース、assets欠落は{}。saved empty paramsの補完はしない。source timestampsはキュー記録/DB保存の意味を添える。
