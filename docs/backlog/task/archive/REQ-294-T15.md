# REQ-294-T15（設計レビュー待ち）

Hookの `generateDraftApi` 注入契約を `(payload: SceneDraftRequest, options?: SceneSpeechStreamOptions) => Promise<SceneDraftResponse>` に拡張する。`SceneSpeechStreamOptions` は `../api/types` からimportし、既存 `SceneSpeechModalState` は `../components/SpeechBubbleEditorModal/sections/SceneSpeechModalState` から使う。開始直後に4工程を表示し、referenceのみactive、他はpending。以後T14が渡す実イベントだけでstatusを更新する。Onboarding表示中も最新進捗を保持し、保存/スキップ後に戻す。キャンセル/再試行/参照切替は旧AbortControllerをabortし、既存generationIdで遅延イベントも無視する。`result` は全工程終了後にReviewへ進め、`error` は分類して再試行可能なErrorへ。上記2ファイルのみ、300行以下目安。

検証: frontendで `npm run typecheck`、`npx vitest run src/hooks/__tests__/useSceneSpeechGeneration.test.ts`。実イベント順、遅延イベント、Onboarding両完了順、abort、errorを制御Promiseで検証し、タイマーで擬似遷移させない。

## 密封コンテキスト: Hookの既存変更点

`SceneSpeechStreamOptions` と `SceneSpeechProgressEvent` を `../api/types` からimport。既存 `SceneSpeechModalState` は `../components/SpeechBubbleEditorModal/sections/SceneSpeechModalState`。T8の `ProgressStep` key/status型に合わせ、ラベルは `参照抽出`, `VLM推論`, `スタイル割当`, `VRAM解放`。

```typescript
interface UseSceneSpeechGenerationParams {
  snapshotId: number
  primaryTagSetId?: number | null
  setBubbles: React.Dispatch<React.SetStateAction<any[]>>
  generateDraftApi: (
    payload: SceneDraftRequest,
    options?: SceneSpeechStreamOptions,
  ) => Promise<SceneDraftResponse>
  applyPresetToBubbles: (bubbles: GeneratedSpeechBubbleRead[], presetId: number | null) => any[]
  setActiveMobileTab?: (tab: 'preview' | 'controls') => void
}
```

現状は `const initialProgress = ... steps: []`、`handleBatchGenerateClick` 内で `setModalState(initialProgress())`、`const result = await generateDraftApi(payload)`、`onModalCancel` で `++generationIdRef.current` している。変更後は `steps` 4件でreference activeを即時表示し、進捗callbackが同じ `generationId` のときのみ該当stepを更新する。`AbortController` は新しい生成開始前に古いものをabortし、`onModalCancel` でもabort。Onboarding中は別の進捗Refに更新を保持し、保存/スキップで最新値を復元する。`AbortError` はキャンセル操作として扱い、誤ったError画面を出さない。

T13のstream error_kindは6値 (`lm_studio_400`, `connection_refused`, `timeout`, `invalid_request`, `vram_unload_failed`, `unknown`)。T14の `SceneSpeechStreamError` は `../api/client` からimportする。現行 `SceneSpeechModalState` のerrorKindは4値のため、`invalid_request` と `vram_unload_failed` は `unknown` に写すが、サーバーmessageは省略せず Error画面へ出す。`lm_studio_400` / `connection_refused` / `timeout` は既存labelへ直接写す。
