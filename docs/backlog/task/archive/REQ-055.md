## 3. 実装要件 (Implementation Logic)

### 3.1 ストア (`useGenerationStore.ts`) の改修
- [x] `GenerationSet` インターフェースの追加。
- [x] `sets` (デフォルト空配列) および `activeSetId` (初期値 `null`) を状態に追加。
- [x] 既存の `setSelectedWorkflowId` 内で、選択されたワークフローIDに応じたセット情報をローカルストレージ (`prompt-surgeon-sets-wf-{id}`) から読み込むように実装。
  - 存在しない場合は、デフォルトとして「Set 1」という名前のセットを1つ作成して初期設定とする。
- [x] 各パラメータのセッター（`setParamValues`, `setBatchSize`, `setSeed`, `setSeedMode`, `setAppliedAssets` 等）において、現在のアクティブセット (`activeSetId`) の対応プロパティへ状態を同期し、かつ `localStorage` に保存する処理を追加。
- [x] `addSet`, `removeSet`, `renameSet`, `toggleSetChecked`, `setAllSetsChecked` のCRUDおよび選択制御アクションの実装。

### 3.2 生成ロジック (`useGenerateAction.ts`) の改修
- [x] 従来の `handleGenerate` に加え、複数セットの一括生成用メソッド `handleGenerateSets` を追加または `handleGenerate` 自体を一括生成対応に拡張。
- [x] チェックされたセット群 (`sets.filter(s => s.checked)`) を取得し、それらを順次シーケンシャルに生成。
- [x] 生成時には、各セット個別の `paramValues`, `appliedAssets`, `batchSize`, `seed`, `seedMode` をワークフローJSONへ注入。
- [x] キュー投入（`queuePrompt`）後、WebSocketから完了（`execution_complete` / `executed`）またはエラー（`execution_error`）のイベント通知を受けるまで待機する仕組みを構築。
- [x] エラー発生時（`execution_error` または投入失敗時）は例外をキャッチしてログ出力し、処理を止めずに次のセットの生成処理へスキップして移行。

### 3.3 UI表示 (`GeneratePage.tsx`) の改修
- [x] プロンプト入力パネル (`PromptPanel`) の上部に、軽量なセットチップを表示するタブバーコンポーネントを実装（デスクトップ表示時のみ適用）。
- [x] 各セットチップには以下のUI要素を配置：
  - 生成対象に含めるかどうかのチェックボックス。
  - セットの切り替えクリック。
  - テキストダブルクリックで編集可能なセット名インプット。
  - セットの削除ボタン (X) ※セット数が1つの場合は非表示または非活性。
- [x] タブバーの右端等に「+ 新規セット」ボタン、および「全選択」「全解除」ボタンを配置。
- [x] 生成履歴サムネイルの左上等に、生成元のセット名（`promptIdToSetNameMap` から参照）を示す小さなバッジを表示。
