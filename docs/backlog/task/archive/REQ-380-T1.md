## Required contracts

- 新moduleは標準ライブラリだけで実装する。公開signature: get_comfy_execution_state(port: int, timeout: float = 2.0) -> dict[str, object]、request_comfy_memory_free(port: int, timeout: float = 5.0) -> None。HTTP status/timeoutを呼出し元が区別できる例外型を宣言する。
- targetは127.0.0.1 + config.json既存wsl.port（1〜65535のint、bool拒否）。新しい接続先設定やURL引数をbrowserから受け取らない。redirect追跡を無効にする。
- GET /queueのJSON objectにqueue_running/queue_pending両方の配列を要求する。running非空=executing、pendingのみ非空=queued、双方空=idle。timeout2秒/受信2MiB上限、不正/失敗はunknown + counts=null + execution_error。配列の要素内容は解釈しない。
- get_server_statusのcomfyへexecution_state（idle/executing/queued/unknown）、queue_running/queue_pending（int|null）、任意execution_errorを加える。TCP停止時はGETしない。fe/beの値をqueue障害へ巻き込まない。既存2秒cacheと7秒読取予算を維持する。
- POST /api/action {action:'free-memory',service:'comfy'}のみ新actionとして受ける。他serviceは400。既存Origin/body検証→_active_action確保→TCPとuncached queue再確認→POST /free {unload_models:true,free_memory:true}の順。native空本文200を成功とする。subprocess、stop/restartへ到達しない。
- 200: status=ok/action=free-memory/outcome=accepted。400 wrong target、409 another action/executing/queued、503 stopped/unknownはstatus=error/request_sent=falseと明確なcode/error。上流非2xx/redirectは502、POST timeout/切断は504/status=timeout/outcome=unconfirmed。自動再送しない。finallyで_active_action解除とcache無効化。
- Manager dashboard: ComfyUI行にメモリ解放ボタンと隣接理由、常時見える結果status領域を追加。LISTEN+idle+操作なしのみ有効。isActionPending（同期guard）と直近status snapshotを保持し、renderServicesによるDOM再生成・finally後にもdisabled条件を再計算する。status.action_in_progressを反映する。res.ok/body.statusを確認して受付・拒否・未確認を区別する。
- UI分類はForms & Controls/Shell。44×44pxの有効域、touch-action:manipulation、flex-wrapと長いerror折返し、11px以上を局所指定。既存のstart/stop/restart/log/config機能を維持する。
- /queueと/freeは非原子的。外部新規投入との完全排他を保証しない。成功は要求受付で、解放完了・解放量を表示しない。

## Response and recovery boundaries

ブラウザーUIはSettings/Managerの両方とも8899の既存/api/actionを使い、Managerが常にJSONを返す。ComfyUIネイティブ/freeだけが空本文HTTP200を返し得る。Managerはこのnative応答を{status:ok,action:free-memory,outcome:accepted}のJSONへ包む。外部localツールのloopback8188直接利用は別consumerで、Managerのguardを経由しない。通常のLANブラウザー/スマートフォンへ8188接続を要求しない。

UIは応答直後に『解放要求を受け付けました。空き容量は監視値で確認してください』というacknowledgementを表示する。『完了』『解放成功』とは表示しない。解放後にも古い/高いVRAM測定値が残り得るため、数値は監視で取得した測定値として表示し、低下を検出して完了を宣言する永続的なcompletion detectorは追加しない。応答後はfresh GET statusが既知idleかつcounts0/0と確認できる場合だけ再有効化する。unknownはdisabledのまま、後続GETで既知idleへ回復した場合だけ解除する。古いidle cacheでunknownを上書きして操作可能にしない。

同一タブはクリック直後のbusyRef/isActionPending、別タブはManager共通_active_action lockで排他する。先行actionの実行中に別タブactionが到達した場合はHTTP409、code=ACTION_BUSY、request_sent=falseを必ず返す。キューイングしない。試験では異なる2clientから同時要求し、2件目409/ACTION_BUSYとnative POST1件をassertする。

自動再送禁止は操作POSTだけ。background status/VRAM GET pollとWS再接続は継続し、操作POSTを再生しない。WS切断時はGET statusとVRAM refreshだけ行う。実ComfyUIの/free処理とGET /queueの間は外部clientの新規投入に対して非原子的であり、完全な外部排他は保証しない。

試験のCONFIG_FILEはtest-owned TemporaryDirectory内の新規JSONを使う。production pathを先に保存し、temp_path.resolve()!=production_path.resolve()をassertしてから、testプロセス内でserver_api.CONFIG_FILEをtemp_pathへbindする。production configのbytes/hashを試験前後で確認し、書込み・rename・backup・restoreを一切しない。fixtureの全HTTPはephemeral loopback port、サービス起動停止要求は0とする。テスト失敗時もtemp以外をcleanupしない。

compile command前にPowerShellで $env:PYTHONPYCACHEPREFIX=(Join-Path (Get-Location) 'docs/logs/REQ-380/pycache') と $env:PYTHONDONTWRITEBYTECODE='1' を設定する。コマンドは記載argvとして実行し、shellは環境変数設定と起動にだけ使う。対象環境は現行Windows PowerShell、cross-OSやCI互換は本Cardの主張に含めない。
