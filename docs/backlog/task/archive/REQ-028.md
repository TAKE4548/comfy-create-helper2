### 2.2 実装要件
1. **複数回送信処理とシードの制御**:
   `handleGenerate` 関数において、`batchSize` 回数分ループして `queuePrompt` を送信します。
   * シードモードが `random` の場合、ループごとに `Math.floor(Math.random() * 2 ** 32)` をセットする。
   * シードモードが `fixed` の場合、ループごとに `seed + i` (ここで `i` は 0 から始まるループインデックス) をセットする。
   * ※オブジェクトのディープコピーが必要になる点に注意。毎回 `workflow.json_body` のコピーを生成し、パラメータをインジェクトした上で `queuePrompt` に渡す必要があります。

2. **生成ボタンの無効化解除**:
   生成ボタンの無効化条件を変更し、自セッション生成中によるロックを解除します。
   * 修正対象箇所: モバイル版 (L1053) および デスクトップ版 (L1682)
   * 修正条件: `disabled={!selectedWorkflowId || !isConnected}`

3. **ボタン表記の統一**:
   自セッション生成中であってもキュー追加が可能になるため、`isGenerating` が `true` の期間はスピナーなどの表示を省略し、一貫して `Generate Batch (キュー追加)` と表示します。
   * モバイル版:
     * `isGenerating` が `true` の場合: `<Zap size={16} /> Generate Batch (キュー追加)`
     * `isGenerating` が `false` の場合: `<Zap size={16} /> Generate Batch`
   * デスクトップ版:
     * `isGenerating` が `true` の場合: `<Zap size={16} /> Generate Batch (キュー追加)`
     * `isGenerating` が `false` の場合: `<Zap size={16} /> Generate Batch`
