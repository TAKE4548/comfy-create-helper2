## 3. 実装要件 (Implementation Logic)
- [x] **1. 全体履歴への即時ローカル反映 (executed時)**:
  - `executed` イベント処理内で、バッチ生成されたすべての画像（`images` 配列の要素すべて）に対して `viewUrl` を構築する。
  - `set` 内で、これらの新しいURLを `batchImages` の先頭にプレピンドするだけでなく、`comfyHistoryImages` にも先頭にプレピンドして直接更新する。
  - 最新の最初の生成画像 `selectedImg` と `previewImage` に設定する。
  - `fetchHistory()` の呼び出しを `setTimeout` で `500ms` 遅らせる。
- [x] **2. 履歴取得のディレイ処理 (execution_complete時)**:
  - `execution_complete` イベント処理内でも、`fetchHistory()` の呼び出しを `setTimeout` で `500ms` 遅らせる。
- [x] **3. 履歴ソートロジックの修正 (UUID対応)**:
  - `fetchHistory` 内で `Object.keys(data).sort(...)` を廃止。
  - `Object.entries(data)` の結果を明示的に `[string, ComfyHistoryItem][]` 型にキャストし、各アイテムの `prompt[0]` (Sequential prompt index, `number`) の値を用いて降順でソートする。
  ```typescript
  const entries = Object.entries(data) as [string, ComfyHistoryItem][]
  const sortedEntries = entries.sort(([, itemA], [, itemB]) => {
    const indexA = itemA.prompt ? itemA.prompt[0] : 0
    const indexB = itemB.prompt ? itemB.prompt[0] : 0
    return indexB - indexA
  })
  ```
- [x] **4. WebSocket切断クリーンアップと自動再接続**:
  - モジュールレベルの変数として `let reconnectTimer: any = null` を定義する。
  - `initialize` 処理の開始時、または `setComfyUrl` 処理内で既存 of `reconnectTimer` があれば `clearTimeout` し、`reconnectTimer = null` にクリアする。
  - `ws.onclose` イベント発生時:
    - 状態の `isConnected: false` を設定する。
    - `ws = null` を設定する。
    - `reconnectTimer` が null の場合、`setTimeout`（3000ms）で `get().initialize()` を実行して再接続を試みるタイマーを設定する。
  - `ws.onerror` イベント発生時:
    - 状態の `isConnected: false` を設定する。
    - `ws` が存在する場合は `ws.close()` を呼び出し、`ws = null` を設定する。
