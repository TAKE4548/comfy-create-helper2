## Hermetic Contract

HTTP期限は既存comfy.pyから継承: connect5秒、prompt10秒、queue/interrupt/history-delete5秒、history read15秒（既定15秒）。history削除は既存Comfy APIとproxyに合わせ `POST /history` JSON `{delete:[prompt_ids...]}`。上流WSは旧ComfyWebSocketServiceの再接続1秒開始/最大15秒/0〜499ms jitterを移す。submit/interruptは結果未確認でも自動再送しない。client用SystemWsServiceの1〜10秒とは別の既存挙動であり、新期限/SLAを設定しない。

以下は承認対象の新contract。scopeとproject、上流client IDと利用者sessionは別。clientから完了状態を送らない。
受付はDB commit後202。上流POST結果不明はunconfirmed、自動再送なし。BE再起動完全復元を追加しない。
通常Nはcancelled除外、F=succeeded+failed。Studio各batch独立。別scope待機優先、他session待機はfilter ONだけ。
snapshotはepoch/revisionでatomic置換、eventも同じ形の全状態dataを使い部分mergeを避ける。SYSTEM_STATS/VRAM_RECOVEREDのtype/data・2.5秒周期保持。
既存30local/1000server metadata、Snapshot独立、Studio750ms/draft競合、画像aspectを保持。

### History/event wire shape

`queue()` returns normalized `{running:[{prompt_id,client_id}],pending:[{prompt_id,client_id}]}` for the T5 service contract. `history(prompt_id)` returns the standard Comfy mapping, not a new normalized bridge DTO:
`{prompt_id:{outputs:{node_id:{images:[{filename,subfolder,type}]}},status:{completed,status_str,messages}}}`.
Event callbacks preserve the upstream JSON `type/data` and carry the prompt_id when present. The service associates ID-less progress/preview only after verifying the current upstream running prompt; an executed image event alone does not prove completion. `execution_success` causes the service to fetch this history and save outputs before publishing terminal state. `execution_interrupted` is not a generic failure signal; only a known cancel operation may treat it as cancellation.

Comfy binary preview header is BIG-ENDIAN: decode two uint32 words as `>II` (format,width/height fields as specified by the upstream wire frame). A test fixture must independently pack `>II`; truncated headers and unknown formats are safely ignored, without changing unrelated events. Do not infer endianness from the implementation under test.
History image `node_id/index` are ImageView fields, not query parameters for the view/thumbnail routes. Existing URL queries remain filename/subfolder/type, with the optional `t=prompt_id` metadata key preserved. Original availability starts unknown until the original availability endpoint confirms it.
The bridge keeps only the latest preview frame per prompt_id and releases it at terminal; `get_preview(prompt_id)` is the HTTP preview route's source. Frame bytes/MIME never enter persisted metadata or `GenerationSnapshot`; T5 preview callback only advances state revision.
The existing proxy's interrupt call had no prompt_id. The bridge now sends `POST /interrupt` with JSON `{prompt_id}` after an exact queue preflight. Older handlers may ignore the extra key, so this is a compatible targeting hint, not an atomic guarantee; preserve conservative barriers and disclose the race. `interrupt_all()` remains global without target. The bridge is the live upstream health source: successful/failed HTTP queue/history/probe calls update `http_ready`; WS open/close updates `ws_connected`. `failure_since` is the first HTTP failure timestamp and remains until a later HTTP success resets it to null. `get_upstream_state()` returns `{http_ready,ws_connected,failure_since}` for T5 snapshot overlay. Do not infer HTTP health from queue contents or add an independent T10 health source/SLA.

### Cancellation Compatibility Contract (D7)

一括scopeはall|normal、mode=single|queued|allとは別軸。既定scope=allを維持。singleは選択job_id/prompt_id一方だけ、scopeを選択させずallのみ。表示filterは対象決定へ使わない。
all scope: queuedは全BE受付済み未投入＋全上流pendingをglobal clear:true、running保持。mode allは同clear後global interrupt、Studio/全session/legacyを含む。per-job loopへ縮小しない。
normal scope: 全sessionのDB job.scope=normalかつcutoff前commit済み未投入、またはDB prompt_idに正に対応付いた上流normal pendingだけ対象。削除はdelete:[確定ID群]、clear:true禁止、Studio/unknown legacyは触らない。推測client_id/表示行/残数からnormalを判定しない。
accept/dispatch/cancelを同じBE lockで直列化。normal allはID削除後に最新queueを再取得し、running又は上流pendingにStudio/unknownが1件でもある、queue照合不能、対象normalがrunningと確認不能ならinterruptを送らない。upstream_interrupt=skipped、messageで「Studio/未分類を保護するため通常実行中を維持」等の理由、正常終了前ならnot_cancelledを返す。全取消完了と表示しない。normal queuedはrunningに関係なく上記確定待機取消を行う。
最新queueが全件known normal、対象running一致、lock保持の場合だけnormal-running interruptを試行可能。直前一致検査を行うが、上流はexpected IDを受けず、外部legacy投入/上流自律切替/遅延到達とのTOCTOUを原子的に防げない。Studio保護の絶対保証と称さず、競合・timeoutはunconfirmedで明示、自動再送しない。既知保護対象がある場合は常に見送るという保守条件を優先。
未投入はlock下の取消commit、上流投入済みは正常ack＋queue/history/terminal照合で確認。queue不在/旧HTTP200 status:errorだけを証拠にしない。成功/失敗先行は終端を優先。normal Nはconfirmed cancelledのみ除外し重複減算なし、操作のfailed/unconfirmed/skippedをjob失敗へ変換しない。cutoff後の新BE受付は次集合、上流global clearは実行時集合、分散atomicではない。
Studio batch F=成功+失敗、取消非加算、12成功+8取消は12/20停止。cancelled終端でrunning flags解除、Step移動/auto-advanceなし。confirmed cancelに失敗トーストなし。running履歴cleanupは取消確認後best effort、先行完了履歴/保存Snapshotを消さずcleanup失敗で取消を戻さない。

### Submit Outcome Clarification

上流の明確なprompt検証拒否は結果不明と区別する。submitだけはHTTP400/422とerror JSONを捕捉し、
`{'error': <upstream error or message>, 'node_errors': ...}` のdictを返す。T5既存error分岐がfailedへ記録する。
HTTP400/422の非JSONも明確な拒否messageをerrorへ返す。timeout/接続切断/曖昧5xxは例外でunconfirmed、再POSTしない。
HTTP200で非空のprompt_idが得られた場合は、部分node_errorsの有無にかかわらず確定IDとして返す。
一部outputの検証エラーと全prompt拒否を混同せず、実際のhistory終端で成否を確定する。
node_errors単独/IDなしで拒否が明示されていればerror dict、IDも明確な拒否もない応答はunconfirmed例外。
局所試験は400error→error dict、200prompt_id+node_errors→同ID、timeout→例外/送信1回を観測する。
