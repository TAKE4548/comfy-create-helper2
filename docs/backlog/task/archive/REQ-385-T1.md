# REQ-385-T1: GenerationService.on_eventのexecuting(node: null)即時完了ハンドリング

## 1. 概要と目的
ComfyUIがプロンプト完了時に送信する `{"type": "executing", "data": {"node": null, "prompt_id": prompt_id}}` イベントを検知し、即時に upstream history を照会してジョブを `succeeded` / `failed` / `cancelled` へ遷移させてスナップショットを配信する（2.5秒ポーリング待ちを解消）。

## 2. ターゲット識別
- **対象ファイル**: `backend/app/services/generation_service.py`
- **対象シンボル**: `GenerationService.on_event`
- **行番号目安**: L288-L365 付近

## 4. 実装要件 (Implementation Logic)
- [ ] `GenerationService.on_event` において、`event_type == "executing"` かつ `data.get("node") is None` の場合、即時完了ルートを実行する。
- [ ] 完了ルートでは `await self.bridge.history(prompt_id)` を照会し、以下を判定：
  - `status.status_str == "success"` または `messages` に `execution_success` が含まれる場合：
    - `job.job_id in self._cancel_requested` であれば `cancelled`、そうでなければ `succeeded` に遷移し outputs を保存、`_eager_cache_outputs` をスケジュール。
  - `execution_interrupted` が含まれる場合：`self._cancel_requested` に応じて `cancelled` または `unconfirmed` に遷移。
  - `execution_error` または `status_str == "error"` の場合：`failed` に遷移。
- [ ] 処理後に `self._frozen_graphs.pop(job.job_id, None)` を行い、`await self._publish_snapshot()` を発行する。
- [ ] `event_type == "execution_success"` の既存ブロックも同様の共通完了ロジックを共有する。
