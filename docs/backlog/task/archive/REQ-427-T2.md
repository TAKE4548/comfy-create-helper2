# REQ-427-T2: image 型の永続化と ref_image 初期定義

## 1. 目的
1. 標準 `input_type: 'image'` が MappingMaster API で作成・更新・再取得後も保持されることを保証する（AC-1 の BE 側）。`mapping_masters.input_type` は自由文字列列のため実装変更は不要で、テストで固定する。
2. 汎用参照画像ロール `ref_image`（`input_type: 'image'`）と `LoadImage`×`image` の RuleSet・main Variant を起動時 seed で冪等に追加し、新規登録・再スキャン時に `LoadImage` ノードが候補として検出・保存できるようにする（AC-2）。
3. seed の role が別 Master の Variant と `UNIQUE(role)` で衝突する DB でも起動が失敗しないガードを入れる。
4. プリセット・Snapshot に参照トークン文字列が欠落なく往復することをテストで固定する（AC-8 の BE 側）。

## 4. 共有契約（参照のみ）
- 参照トークン（C1）: `^refimg:([0-9a-f]{64})\.(png|jpg|webp)$`。本カードでは文字列として扱うのみ（実体ストアは T1 の責務）。テストでは例 `"refimg:" + "a"*64 + ".png"` を使う。
- プリセット保存は `VariantIndex` による role→variant 正規化を通り、**未解決 role は破棄される**（`backend/app/routers/presets.py` L134-137）。したがって `ref_image` role の値を保存するには seed された `ref_image` Variant が必要。

### 5.3 走査器の判定（参照のみ、`backend/app/services/workflow_scanner.py`、変更禁止）
- 候補は Variant の RuleSet Entry（`class_type` 一致かつ `param_name` をノード入力に持つ）で抽出。セレクタパターン不一致でも、同 Master に一致 Variant が無ければ「段階 3（セレクタなし）」で候補に残る。最小ノード ID が確定、同段階に複数あれば `duplicated` 警告と全 `node_ids`。
- `POST /api/workflows/scan` 本文 `{"json_body": {...}}` → `ScanResult{matched:[{master_id, variant_id, role, node_id, node_title, input_name, status, node_ids}], warnings:[...]}`。
