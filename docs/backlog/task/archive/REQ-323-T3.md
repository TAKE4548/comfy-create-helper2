# REQ-323-T3: デバウンス・オートセーブフック (useStudioAutosave) と復元ロジックの実装

## 1. 概要と目的
Dataset Studio で編集中のフォーム入力をデバウンス（750ms）後に自動永続化し、入力中は即時 `sessionStorage` へ下書きを同期し、再訪時にはタイムスタンプ比較によって未保存下書きを自動復元するカスタムフック `useStudioAutosave` を実装する。

## 2. 密閉コンテキスト (Hermetic Context)

### 2.1 型定義
```typescript
import type { DatasetProject } from '../../../api/types'
import type { DatasetStudioDraft } from '../utils/studioDraftStorage'

export interface StudioFormData {
  name: string
  character_trigger: string
  outfit_trigger: string
  workflow_id: number
  prompt_meta: string
  prompt_physical: string
  prompt_exclusive_outfit: string
  prompt_negative: string
  selected_alt_outfits: string
}

export interface UseStudioAutosaveProps {
  activeProject: DatasetProject | null
  formData: StudioFormData
  onProjectUpdated?: (project: DatasetProject) => void
  onDraftRestored?: (draft: DatasetStudioDraft) => void
  debounceMs?: number // デフォルト 750ms
}

export interface UseStudioAutosaveReturn {
  saveStatus: 'idle' | 'unsaved' | 'saving' | 'saved' | 'error'
  hasConflict: boolean
  flushAutoSave: () => Promise<void>
  resolveConflictWithDraft: () => Promise<void>
  resolveConflictWithServer: () => void
  isRestoredFromDraft: boolean
  clearDraftStatus: () => void
}
```

### 2.2 既存 API シグネチャ (`frontend/src/api/client.ts`)
```typescript
datasetApi.updateProject: (projectId: number, data: DatasetProjectUpdate) => Promise<DatasetProject>
```

## 3. 実装要件 (Implementation Logic)
1. **`frontend/src/pages/DatasetStudioPage/hooks/useStudioAutosave.ts` の新規作成**:
   - 初期ロード / `activeProject` 変更時:
     - `loadStudioDraft(activeProject.id)` を取得。
     - **競合判定**: 下書きに `base_server_updated_at` が存在し、`activeProject.updated_at` と異なる場合:
       - `hasConflict = true` とし、自動上書きを停止 (Red Team 5)。
     - 競合がない場合で、`draft && new Date(draft.updated_at).getTime() > new Date(activeProject.updated_at).getTime()` の場合:
       - `onDraftRestored(draft)` を発火し `isRestoredFromDraft = true` とする (AC-4, Red Team 4)。
   - **競合解消メソッドの実装**:
     - `resolveConflictWithDraft`: 下書きデータで `datasetApi.updateProject` を強制送信。成功時に `markStudioDraftSynced(id, res.updated_at)` を呼び `hasConflict = false` に復帰。
     - `resolveConflictWithServer`: `clearStudioDraft(id)` を実行し、サーバー側データでフォームを更新し `hasConflict = false` に復帰。
   - `formData` 変更時:
     - `hasConflict` が false かつ `activeProject` が存在する場合、直ちに `saveStudioDraft` を呼び出し `base_server_updated_at: activeProject.updated_at` と共に `sessionStorage` に書き込む (AC-3)。
     - ストアおよび内部ステータスを `'unsaved'` に設定。
     - デバウンスタイマー（750ms）をスケジュール。
     - タイマー満了時: ステータスを `'saving'` に変更し、`datasetApi.updateProject(activeProject.id, formData)` を実行。
     - 成功時: ステータスを `'saved'` に更新し、`markStudioDraftSynced(activeProject.id, res.updated_at)` を実行し、`onProjectUpdated(res)` を発火 (AC-2, AC-5)。
     - 失敗時: ステータスを `'error'` に更新し、下書きは保持する (AC-2, Red Team 2)。
   - `flushAutoSave`: デバウンス待ちタイマーをキャンセルし、即座に `datasetApi.updateProject` を実行して完了を await できる関数。
2. **単体テスト `frontend/src/pages/DatasetStudioPage/hooks/__tests__/useStudioAutosave.test.ts` の新規作成**:
   - `vi.useFakeTimers()` を用いて、入力直後に `sessionStorage` に書き込まれ、750ms 経過後に `datasetApi.updateProject` が発行されることを検証。
   - API 成功時の `'saved'` 遷移と `markStudioDraftSynced` の検証。
   - API エラー時の `'error'` 遷移と下書き保持の検証 (Red Team 2)。
   - サーバー更新日時より新しい下書きが存在する場合の自動復元、および古い下書き時の復元スキップを検証 (AC-4, Red Team 4)。
   - `base_server_updated_at !== activeProject.updated_at` 時の競合検知 (`hasConflict: true`)、自動保存抑止、および `resolveConflictWithDraft` / `resolveConflictWithServer` の動作検証 (Red Team 5)。

## 4. 完了条件と検証
- [ ] フォーム変更後 750ms でオートセーブが送信されること (AC-2)。
- [ ] デバウンス待ちの間もリアルタイムに `sessionStorage` に退避されること (AC-3)。
- [ ] 画面再訪時に新しい下書きから自動復元されること (AC-4)。
- [ ] 保存成功時に同期マークが行われ、失敗時に下書きが保持されること (AC-5, Red Team 2)。
- [ ] 別セッションによる更新があった場合に競合検知と手動解消が行えること (Red Team 5)。
