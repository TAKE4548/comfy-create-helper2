### 1. Purpose and scope

Create the pure, DB-free key-classification layer used by every later REQ-418 Card. Presets, snapshots and sync groups currently key parameters by the role string. After REQ-418 they are keyed by `mapping_variants.id`. This module is the single place that decides what a key means, so migration code (T2, AC-1) and runtime APIs (T3/T4/T5, AC-2/AC-3/AC-4) never diverge. (Note: AC-1 DB migration is implemented in REQ-418-T2; AC-2 snapshot restoration is implemented in REQ-418-T4; AC-3 sync groups are implemented in REQ-418-T5 and REQ-418-T6; AC-4 latest Variant responses are implemented in REQ-418-T3 and REQ-418-T5.)

Completion: every symbol in section 3 exists with exactly these signatures, the unit tests in section 5 pass, and no DB write happens anywhere in the module.

### 3. Shared contract (fixed; do not change signatures)

```python
# backend/app/services/variant_keys.py
RESERVED_PREFIX = "__"
class KeyKind(str, Enum):
    RESERVED = "reserved"; VARIANT = "variant"; ROLE = "role"
    DERIVED_ROLE = "derived_role"; UNRESOLVED = "unresolved"

@dataclass(frozen=True)
class ClassifiedKey:
    kind: KeyKind
    key: str
    variant_id: int | None   # None for RESERVED / UNRESOLVED
    sub_key: str             # '' for plain value; e.g. 'lora_count', 'lora_name_3' for derived keys

def encode_variant_key(variant_id: int, sub_key: str = "") -> str   # 'v:12' or 'v:12:lora_count'
def decode_variant_key(key: str) -> tuple[int, str] | None          # None if not matching the wire form

class VariantIndex:
    def __init__(self, roles_by_id: Mapping[int, str]) -> None
    @classmethod
    def from_session(cls, db: Session) -> "VariantIndex"           # SELECT id, role FROM mapping_variants
    def role_of(self, variant_id: int) -> str | None
    def classify(self, key: str) -> ClassifiedKey
    def role_key(self, variant_id: int, sub_key: str = "") -> str | None  # '<role>' / '<role>_<sub_key>'; None if id unknown

@dataclass
class NormalizedParams:
    entries: dict[tuple[int, str], str]   # (variant_id, sub_key) -> value (string)
    reserved: dict[str, Any]
    unresolved: list[str]                 # sorted

@dataclass
class ExpandedParams:
    role_keyed: dict[str, Any]            # current role names (sorted-key construction)
    variant_keyed: dict[str, Any]         # 'v:<id>[:sub]' keys
    missing: list[str]                    # unresolved original keys, sorted

def normalize_params(index: VariantIndex, params: Mapping[str, Any]) -> NormalizedParams
def expand_stored_params(index: VariantIndex, stored: Mapping[str, Any], *, owner_label: str, warn: bool = True) -> ExpandedParams
def to_storage_params(index: VariantIndex, params: Mapping[str, Any]) -> tuple[dict[str, Any], list[str]]
    # -> ({'v:<id>[:sub]' or reserved key: ORIGINAL value, ...}, unresolved keys sorted)
```

### 4. Implementation logic

- [ ] Classification order is FIXED: (1) key starts with `__` -> RESERVED; (2) matches `^v:(?P<id>\d+)(?::(?P<sub>[A-Za-z0-9_]+))?$` -> VARIANT if the id exists in the index, otherwise UNRESOLVED (the variant was deleted); (3) key equals a role exactly -> ROLE; (4) matches `^(?P<base>.+)_(?P<sub>lora_count|(?:lora_name|lora_wt|model_str|clip_str)_\d+)$` AND `base` equals a role exactly -> DERIVED_ROLE (sub_key = the `sub` group); (5) otherwise UNRESOLVED. An exact role always beats the derived pattern (a role may itself end with `_lora_count`).
- [ ] `encode_variant_key(id, sub)` / `decode_variant_key` must round-trip for every `id >= 0` and every `sub` matching `[A-Za-z0-9_]*`.
- [ ] `normalize_params`: iterate in sorted key order; process ROLE/DERIVED_ROLE keys first and VARIANT keys second so an explicit `v:` key wins on collision. Non-`str` values are stored with `json.dumps(value, ensure_ascii=False)`; `str` values unchanged. No logging, no exceptions for unknown keys.
- [ ] `expand_stored_params`: same ordering rule. RESERVED keys appear unchanged in BOTH output dicts. Resolved keys appear in `role_keyed` under `index.role_key(...)` (the CURRENT role) and in `variant_keyed` under the `v:` form, with the original (unmodified) value. UNRESOLVED keys go to `missing`. When `warn` and `missing` is non-empty emit exactly one `logging.getLogger(__name__).warning(...)` whose message contains `owner_label` and every missing key (e.g. `"%s: unresolvable parameter keys skipped: %s"`).
- [ ] `to_storage_params`: same classification; output keys are `encode_variant_key(...)` or the reserved key; values are the ORIGINAL values (not stringified); unresolved keys are returned sorted and are NOT included in the output dict.
- [ ] All functions are deterministic and never raise for arbitrary `str` keys (including `""` and Unicode).
