### REQ-340-T1: Backend: MappingMaster fallback_param_names モデル拡張・DBマイグレーション・Scannerフォールバック解決

#### 1. 目的とスコープ
`MappingMaster` に `fallback_param_names`（JSON配列文字列）カラムを追加し、Pydanticスキーマ（Read/Create/Update）の受託、DBマイグレーションの冪等実行、および `workflow_scanner.py` におけるプライマリ名非存在時の順次フォールバック解決ロジックを実装する。

#### 2. 型定義・シグネチャ
```python
# backend/app/models.py
class MappingMaster(Base):
    ...
    fallback_param_names: Mapped[Optional[str]] = mapped_column(Text, nullable=True)  # JSON array

# backend/app/routers/mapping_masters.py
class MappingMasterV2Read(BaseModel):
    ...
    fallback_param_names: Optional[list[str]] = None

class MappingMasterUpdate(BaseModel):
    ...
    fallback_param_names: Optional[list[str]] = None

class MappingMasterCreatePayload(BaseModel):
    ...
    fallback_param_names: Optional[list[str]] = None
```

#### 3. 変更箇所のサージカルスニペット
```python
# backend/app/services/workflow_scanner.py (_find_candidate_nodes / scan_workflow)
# 既存の param_name に加え、fallback_param_names を順次評価
param_names = []
if master and getattr(master, "param_name", None):
    param_names.append(master.param_name.strip().lower())
fallback_list = _safe_parse_json_list(getattr(master, "fallback_param_names", None), master_id, "fallback_param_names")
for fb in fallback_list:
    if isinstance(fb, str) and fb.strip():
        param_names.append(fb.strip().lower())
```
