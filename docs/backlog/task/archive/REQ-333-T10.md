## Hermetic Contract

snapshot()はread-only。DB read/serialize失敗は503、FEは前回のvalid状態を保持して同期失敗表示、部分payloadは適用しない。受付transaction未commitならrollbackして202なし。commit済みなら後続snapshot取得/通知失敗で受付を拒否扱いに戻さず、commitしたjob IDs/epoch/revisionから202を返す。request lookupを受付根拠とし、state取得失敗でmutationを再送しない。

version=1をruntime検証。未知version/不正な項目は適用せずlast valid状態とSYSTEM_STATS購読を保持。同epochの未知versionについて自動state再取得は最大1回、なお非対応なら再読込を案内する同期非対応状態にし、連続refetch/自動reload/reconnectを起こさない。手動操作または対応するpayloadに復帰した時に解除する。

以下は承認対象の新contract。scopeとproject、上流client IDと利用者sessionは別。clientから完了状態を送らない。
受付はDB commit後202。上流POST結果不明はunconfirmed、自動再送なし。BE再起動完全復元を追加しない。
通常Nはcancelled除外、F=succeeded+failed。Studio各batch独立。別scope待機優先、他session待機はfilter ONだけ。
snapshotはepoch/revisionでatomic置換、eventも同じ形の全状態dataを使い部分mergeを避ける。SYSTEM_STATS/VRAM_RECOVEREDのtype/data・2.5秒周期保持。
既存30local/1000server metadata、Snapshot独立、Studio750ms/draft競合、画像aspectを保持。
カード外ファイルや公開contract変更が必要なら設計へ差し戻す。

from typing import Any, Literal, Protocol
from pydantic import BaseModel
Scope = Literal['normal','studio']
JobStatus = Literal['queued','submitting','running','succeeded','failed','cancelled','unconfirmed']
class BatchItem(BaseModel):
    graph: dict[str, Any]
    workflow_id: int | None = None
    param_values: dict[str, Any]
    applied_assets: dict[str, Any] | None = None
    set_name: str | None = None
class BatchRequest(BaseModel):
    request_id: str
    session_id: str
    scope: Scope
    project_id: int | None = None
    items: list[BatchItem]
class GenerationPort(Protocol):
    async def submit(self, graph: dict[str, Any]) -> dict[str, Any]: ...
    async def queue(self) -> dict[str, Any]: ...
    async def history(self, prompt_id: str | None = None) -> dict[str, Any]: ...
    async def interrupt(self, prompt_id: str) -> None: ...
    async def clear_queue(self) -> dict[str, Any]: ...
    async def delete_queue(self, prompt_ids: list[str]) -> dict[str, Any]: ...
    async def interrupt_all(self) -> dict[str, Any]: ...
    async def delete_history(self, prompt_ids: list[str]) -> None: ...
class RepositoryPort(Protocol):
    def accept_batch(self, payload: BatchRequest) -> dict[str, Any]: ...
    def snapshot(self) -> dict[str, Any]: ...
    def transition(self, job_id: str, status: JobStatus, **fields: Any) -> dict[str, Any]: ...
# UUID、空items禁止、studio project必須をvalidatorで検査。

CancelResultは{job_id:string|null,prompt_id:string|null,status:JobStatus|null,outcome:cancelled|not_cancelled|already_terminal|unconfirmed|rejected,message:string}。CancelOperationは{scope:all|normal,message:string,mode:single|queued|all,items:CancelResult[],upstream_clear/upstream_interrupt:confirmed|unconfirmed|failed|not_requested|skipped,epoch:string,revision:number}。single targetはID一方のみ、scope=all。一括modeはtargetなし、scope省略all。upstream_clearはnormal時に指定ID削除の結果を表す。上流未知件数を0件成功へ換算しない。T2/T8がこの公開型を所有する。

### Cancellation Compatibility Contract (D7)

一括scopeはall|normal、mode=single|queued|allとは別軸。既定scope=allを維持。singleは選択job_id/prompt_id一方だけ、scopeを選択させずallのみ。表示filterは対象決定へ使わない。
all scope: queuedは全BE受付済み未投入＋全上流pendingをglobal clear:true、running保持。mode allは同clear後global interrupt、Studio/全session/legacyを含む。per-job loopへ縮小しない。
normal scope: 全sessionのDB job.scope=normalかつcutoff前commit済み未投入、またはDB prompt_idに正に対応付いた上流normal pendingだけ対象。削除はdelete:[確定ID群]、clear:true禁止、Studio/unknown legacyは触らない。推測client_id/表示行/残数からnormalを判定しない。
accept/dispatch/cancelを同じBE lockで直列化。normal allはID削除後に最新queueを再取得し、running又は上流pendingにStudio/unknownが1件でもある、queue照合不能、対象normalがrunningと確認不能ならinterruptを送らない。upstream_interrupt=skipped、messageで「Studio/未分類を保護するため通常実行中を維持」等の理由、正常終了前ならnot_cancelledを返す。全取消完了と表示しない。normal queuedはrunningに関係なく上記確定待機取消を行う。
最新queueが全件known normal、対象running一致、lock保持の場合だけnormal-running interruptを試行可能。直前一致検査を行うが、上流はexpected IDを受けず、外部legacy投入/上流自律切替/遅延到達とのTOCTOUを原子的に防げない。Studio保護の絶対保証と称さず、競合・timeoutはunconfirmedで明示、自動再送しない。既知保護対象がある場合は常に見送るという保守条件を優先。
未投入はlock下の取消commit、上流投入済みは正常ack＋queue/history/terminal照合で確認。queue不在/旧HTTP200 status:errorだけを証拠にしない。成功/失敗先行は終端を優先。normal Nはconfirmed cancelledのみ除外し重複減算なし、操作のfailed/unconfirmed/skippedをjob失敗へ変換しない。cutoff後の新BE受付は次集合、上流global clearは実行時集合、分散atomicではない。
Studio batch F=成功+失敗、取消非加算、12成功+8取消は12/20停止。cancelled終端でrunning flags解除、Step移動/auto-advanceなし。confirmed cancelに失敗トーストなし。running履歴cleanupは取消確認後best effort、先行完了履歴/保存Snapshotを消さずcleanup失敗で取消を戻さない。

AC-36/FC15–19: default all、normal指定ID削除、Studio/unknown running/pending barrier interrupt0、known-normal限定試行、skipped非完了、scope/結果型parityを局所検査する。
