## Implementation Logic

新しいutility責務。v:<id>/m:<id>を正本、hook v_<id>/m_<id>は境界変換。既存state(空欄含む)→従来mapping証拠(true)→新規取り込み時master.default_enabled!==false。新規基本無効slotは取込集合から除外。全取込slotのtrue/falseを保存し後で空欄も既存判定可能。unknown過去キーは保持。

`setStageEnabled`のslotsは呼出し元が確定した表示対象・取込済みslot集合。`slot.stageId === stageId`の全件の`slotKey(slot.masterId, slot.variantId)`だけをenabledへ変更し、新state objectを返す。対象キーが未保存でも追加する。他stage、stageId未設定、slotsにない既存/unknownキーを全て保持。defaultEnabledや過去の個別falseによる例外を設けず、再有効化なら対象全件true。対象0件でも新objectを返し、states/slots/slot recordを変更しない。

`generationWorkflow`は`{...raw, mappings: 新配列}`の浅いclone。各mappingについて`raw.mapping_slot_states?.[slotKey(mapping.master_id, mapping.variant_id)] === false`の場合だけ新配列から除外する。状態省略、キー欠落はtrue相当。master/stage一覧やdefaultEnabled、node_idの有無を追加のfilter条件にしない。variant_idがnull/省略ならm:<master_id>、それ以外はv:<variant_id>。
raw自体、raw.mappings、そのrecord、mapping_slot_states（unknownキー込み）とその他fieldを変更しない。保持mappingは元順序・元record参照、state object・json_body・その他fieldは元参照/値を維持。除外0件でもworkflow object/mappings配列は新参照。これは深いcloneではなく、派生先から共有recordを変更する権限を与えない。T17が生成入力/注入の統合を担当。
