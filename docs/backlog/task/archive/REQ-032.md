## 3. 実装要件 (Implementation Logic)

### 3.1 `UploadWorkflowModal.tsx` の新規作成
1. `RescanModal.tsx` のマッピング確認・編集ロジックを参考にしつつ、以下の機能を持つ `UploadWorkflowModal` を実装する。
2. モーダル起動時に `workflowsApi.scan` を呼び出し、結果を編集可能なテーブル/リストとして表示する。
3. モーダルの上部にワークフロー名を入力するテキストフィールドを追加する。
   - 初期値はファイル名（拡張子なし）。空欄の場合は「登録」ボタンを無効化する。
4. マッピング（ matched 及び warnings ）の調整・追加・削除ができるようにする。
5. 保存時に `workflowsApi.create` を使用して `POST /api/workflows` を呼び出す。
   - すでに同名のワークフローが存在する場合は、APIから409エラーが返されるため、それをキャッチして「すでに同名のワークフローが存在します」という警告をモーダル内に赤字で表示し、モーダルは閉じない。
   - 保存成功時には、APIレスポンスの `WorkflowSummary`（`id` や `name` など）を `onSaved(newWorkflowId)` コールバックに引き渡してモーダルを閉じる。

### 3.2 `GeneratePage.tsx` の修正
1. デスクトップ版・モバイル版のワークフロー選択ドロップダウン（`#workflow-select`, `#workflow-select-mobile`）のデフォルト項目（value="" のプレースホルダー）を、`Select workflow…` から `+ 新しいワークフローを追加 (Upload New...)` に変更する。
2. `selectedWorkflowId` が `null` または未選択（かつ `new` または `""` の状態）の場合、左ペイン（パラメータフォームが表示される領域）に、点線の枠線やドラッグゾーンの文言、アップロード用のアイコン等を含んだドロップゾーン（`UploadZone`）をフル幅で表示する。
3. ドロップゾーンには、ドラッグ＆ドロップ（`onDragOver`, `onDrop`）およびクリックでローカルの `.json` ファイルを選択できるファイル入力をバインドする。
4. ファイル選択時に `FileReader` を用いてファイルをパースし、JSONオブジェクトとして保持して、`UploadWorkflowModal` を表示させる。
5. モーダルの `onSaved` コールバックにて以下を実行する：
   - `['workflows']` クエリのキャッシュを無効化してリロード。
   - `selectedWorkflowId` を新しく登録されたワークフローIDに変更する（これにより、左ペインがドロップゾーンから該当ワークフローの入力パラメータ欄に自動で切り替わる）。
