## 背景・目的

`JobManagementModal` を開くと画面が真っ黒になるバグを修正する。

**根本原因**: React Rules of Hooks 違反。`useMemo` × 2 が `if (!isOpen) return null`（L20）より後に置かれているため、`isOpen: false → true` の遷移時にフック呼び出し数が変わり React がクラッシュする。

---

## 実装指示

### 対象ファイル

`frontend/src/components/JobManagementModal.tsx`

### 変更内容

**Step 1**: L23 の `filterJob` ヘルパー関数を削除する（インライン化するため不要）

**Step 2**: L25–26 の `useMemo` × 2 ブロックを `useGenerationStore()` の直後、`if (!isOpen) return null` の**前**に移動する

**Step 3**: `filterJob` 関数の参照部分を各 `useMemo` 内でインライン式に置換する

### 変更前（現状コード L10–L28）

```tsx
export const JobManagementModal: React.FC<JobManagementModalProps> = ({ isOpen, onClose }) => {
  const {
    queueRunning,
    queuePending,
    clientId,
    filterOwnSession,
    cancelJob,
    cancelAllJobs,
  } = useGenerationStore()

  if (!isOpen) return null

  // フィルター処理
  const filterJob = (job: any) => !filterOwnSession || job[3]?.client_id === clientId

  const visibleRunning = useMemo(() => queueRunning.filter(filterJob), [queueRunning, filterOwnSession, clientId])
  const visiblePending = useMemo(() => queuePending.filter(filterJob), [queuePending, filterOwnSession, clientId])

  const totalJobsCount = visibleRunning.length + visiblePending.length
```

### 変更後（修正コード）

```tsx
export const JobManagementModal: React.FC<JobManagementModalProps> = ({ isOpen, onClose }) => {
  const {
    queueRunning,
    queuePending,
    clientId,
    filterOwnSession,
    cancelJob,
    cancelAllJobs,
  } = useGenerationStore()

  // [FIX REQ-049] useMemo を早期リターンより前に移動（React Rules of Hooks 準拠）
  const visibleRunning = useMemo(
    () => queueRunning.filter((job: any) => !filterOwnSession || job[3]?.client_id === clientId),
    [queueRunning, filterOwnSession, clientId]
  )
  const visiblePending = useMemo(
    () => queuePending.filter((job: any) => !filterOwnSession || job[3]?.client_id === clientId),
    [queuePending, filterOwnSession, clientId]
  )

  if (!isOpen) return null

  const totalJobsCount = visibleRunning.length + visiblePending.length
```

### 重要な注意事項

- `totalJobsCount`（L28）、`handleCancelJob`、`handleCancelAll`、`formatPromptId` は通常の変数・関数でありフックではないため、`if (!isOpen) return null` の後に残したままでよい
- JSX（L45以降）は変更不要
- `useMemo` の deps 配列は変更前と同一（filterJob をインライン化しても依存値は `queueRunning/queuePending, filterOwnSession, clientId` で変わらない）
