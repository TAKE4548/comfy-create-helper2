# REQ-385-T3: GenerationService._cancel_singleのinterrupt発行とキャンセル完了連携最適化

## 1. 概要と目的
実行中ジョブの単一キャンセル操作（`_cancel_single`）において、ComfyUI `/interrupt` POST 前に `_cancel_requested` へ確実に先行登録し、イベントハンドラ（`on_event`）との競合なく即座に `cancelled` へ遷移・スナップショット配信できるように連携を最適化する。

## 2. ターゲット識別
- **対象ファイル**: `backend/app/services/generation_service.py`
- **対象シンボル**: `GenerationService._cancel_single`
- **行番号目安**: L599-L613 付近

## 3. 密閉コンテキスト (Hermetic Context)

# backend/app/services/generation_service.py:599-613
        if any(item.prompt_id == job.prompt_id for item in queue.running):
            self._cancel_requested.add(job.job_id)
            try:
                await self.bridge.interrupt(job.prompt_id)
            except Exception as exc:
                return [self._result(job.job_id, job.prompt_id, job.status, "unconfirmed", f"interrupt outcome unknown: {exc}")], "not_requested", "unconfirmed", "interrupt outcome unknown"
            changed = await self._reconcile_cancel_state({job.job_id})
            current = self._find_job(changed, job.job_id)
            if current is not None and current.status == "cancelled":
                return [self._result(job.job_id, job.prompt_id, "cancelled", "cancelled", "history confirmed cancellation")], "not_requested", "confirmed", "target cancellation confirmed"
            if current is not None and current.status in {"succeeded", "failed"}:
                return [self._result(job.job_id, job.prompt_id, current.status, "already_terminal", "job completed before cancellation was confirmed")], "not_requested", "unconfirmed", "job was already terminal"
            return [self._result(job.job_id, job.prompt_id, current.status if current else job.status, "unconfirmed", "interrupt was acknowledged but cancellation is not confirmed")], "not_requested", "unconfirmed", "interrupt target outcome is unconfirmed"
        return [self._result(job.job_id, job.prompt_id, job.status, "unconfirmed", "job is absent from queue but terminal state is unknown")], "not_requested", "unconfirmed", "queue absence does not confirm cancellation"

## 4. 実装要件 (Implementation Logic)
- [ ] `_cancel_single` において、実行中ジョブに対する `interrupt` 呼び出し前に `self._cancel_requested.add(job.job_id)` が確実に実行される状態を維持する。
- [ ] `_reconcile_cancel_state` による確認が行われた後、もし即時に `cancelled` が確認できなかった場合でも、後続の WebSocket イベント（`execution_interrupted` または `executing` (node: null)）が届いた際に `_cancel_requested` に基づき即座に `cancelled` 状態へ確定・配信されるよう、`_cancel_requested` の破棄タイミングや状態整合を担保する。
- [ ] 既存の `cancel_operation` の契約（戻り値構造、ActionOutcome）を一切壊さず、例外発生時の安全なフォールバックを維持する。
