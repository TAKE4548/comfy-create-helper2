## Implementation Logic

- [ ] 候補は保持済み成功job出力とComfy history(max_items=200)の和集合。Snapshot DB/metadata/thumbnailを走査しない。managed session優先、legacy client_id fallback、不明null。
- [ ] managedをfinished_at降順/null末尾・job_id/node_id/index昇順、legacyのみprompt[0]降順・prompt_id/node_id/index昇順。identity重複はmanaged優先、先頭200画像を候補窓とする。
- [ ] known/examinedをprobe前に除外。先頭10identity、active<=2、既存probeを利用。結果presentだけitems、missing/unknownはrejected。has_moreは未検査候補の有無。
- [ ] 全候補を事前probeしない。同identity1probe/1論理同期。表示済みidentity0probe、1page最大10、subfolder/type別、host/t非送信。
- [ ] 上流不通/非2xx/不正JSONは503 ErrorEnvelope、入力不正422。原画HTTP errorのmissing判定は既存probe本文に従い、元recordのavailabilityを存在根拠にしない。
- [ ] DB/サムネ/metadataを変更しない。pytestではfake bridge/service/HTTP clientでAPIstatus/順序/セッション/probe件数/並行数/二page/unknown/missingを確認する。
