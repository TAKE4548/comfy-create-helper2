## 6. 画面仕様
### 6-1. 作成モード（`master === null`）
値定義（表示名・入力型・グループ・基本有効）＋「初期RuleSetのパラメータ名」（placeholder `例: text, steps, cfg`、必須）。Variant 行・プレビューは出さず「保存後にステージ別Variantを編集できます」と表示。保存 payload は `{ name, display_name: name, param_name, input_type, default_enabled, group_id }`（旧判定フィールドは送らない）。既存 `MappingMasterEditModal.seed.test.tsx` と `GeneratePage/__tests__/dedicatedSeedIntegration.test.tsx` を無変更で PASS させること（作成モードの `onSave` 引数は従来の `MappingMasterV2Create` 形）。

### 6-2. 編集モード
1. 値定義セクション（AC-1）。param_name・Class Types・fallback・title_patterns・Role上書きの入力は出さない。
2. 「ステージ別Variant」セクション（AC-2）: `sortVariantDrafts` の順に `VariantRow`。末尾に「Variantを追加」→ ステージ select（全ステージを選択肢に出す。使用済みでも選べる）付きの新規行。新規行の role 表示は `${master.base_key}${stage.suffix}`。
3. 「判定プレビュー」セクション（AC-9）: `ScanPreviewPanel`。`buildRequest` は `validateVariantDrafts` にエラーがあれば null（理由を `disabledReason` に表示）、なければ `buildScanPreviewRequest(state, wid)`。`rowLabels` は `${stageName} / ${role}`。

## 8. 保存フロー（編集モード `handleSubmit`）
1. `validateVariantDrafts` → エラーがあれば行に表示して終了（API 呼び出し 0）。
2. `pendingSharedChoices` が空でなければ先頭を `SharedDefinitionChoice` で表示して終了（API 0）。選択されたら `choices[defKey]` を設定し 1 から再実行。「戻る」は何もしない。
3. `buildAtomicSaveRequest(state, {name, input_type, group_id, default_enabled}, 既存定義名)` → `await onSave(request)`（API 呼び出しは呼び出し側の `atomic-save` 1回のみ）。
4. 例外時: `mapServerValidationErrors` が非 null なら `rows` を行エラー、`general` を本文上部へ。それ以外（409・ネットワーク断等）は本文上部 `role="alert"` に「保存に失敗しました。変更は保存されていません」。サーバは全件ロールバックするため、下書きをそのまま保持し再保存できる。保存中は「マスターを保存」を無効化（二重送信防止）。
5. 成功時のクエリ無効化（`mapping-masters`・`binding-rules`・`node-selectors`）は呼び出し側（T6）が行う。
