# REQ-401-T3: SPEC_COMMON / SPEC_GENERATE への上流消失時 unconfirmed 遷移契約の明文化

## 1. 実行境界

- 役割は doc-editor / doc-task。workspace はリポジトリルート（Git root）。所有ファイルは `docs/specs/SPEC_COMMON.md` および `docs/specs/SPEC_GENERATE.md` のみ。
- 前提: コーディネーターが設計承認を確認し、本 Card を exact-ID で in-progress へ遷移済みであること。状態更新・独立検証・commit は担当外。
- UTF-8（BOMなし）/ LF を厳守する。既存の他機能契約・不変条件を損なわず、整合性を保って記述する。
- 仕様判断の疑義が生じた場合は ESCALATE_TO_DESIGN とする。

## 2. 変更位置と追記内容

### 2.1 `docs/specs/SPEC_COMMON.md` (L551-L555 付近)
- **対象箇所**: 「待機jobは取消前にpendingであること...」「`unconfirmed` のjobは確認済み終了として扱わず...」の箇条。
- **追記内容**:
  1. `prompt_id` が確定したアクティブジョブ（`status IN ('queued', 'submitting', 'running')`）が上流 ComfyUI の queue（`running`/`pending`）に不在かつ上流 `history` 照会成功時に実行履歴が存在しない（空である）場合、上流で消失したと判定し DB 上のステータスを `unconfirmed` に遷移させる契約を明記する。
  2. 単件取消・待機取消において上流 queue 照会エラーまたは queue 不在により取消が未確認となる場合、API 応答の `outcome="unconfirmed"` と同期して DB 上のジョブステータスを `unconfirmed` に更新する契約を明記する。
  3. 上記により `unconfirmed` となったジョブは `_ACTIVE_STATUSES` から外れ、`normal_group_id` を開いたままにせず、手動解除（`release`）の対象となる契約を明記する。

### 2.2 `docs/specs/SPEC_GENERATE.md` (L214-L218 付近)
- **対象箇所**: 「ジョブ割り込み / キャンセル」節の取消仕様箇条。
- **追記内容**:
  1. 一括取消（`mode=all|queued`, `scope=all|normal`）において、上流キューに実在しない prompt_id 保持 active ジョブも未確認項目として走査・回収し、DB 上のステータスを `unconfirmed` に更新した上で取消応答 `items` に `outcome="unconfirmed"` として含め、HTTP 202 Accepted を返却する契約を明記する。
  2. 上流 ComfyUI クラッシュ・再起動後の reconcile または取消操作によって `unconfirmed` に遷移した記録は、ジョブ管理モーダルの「状態未確認の記録」から直ちに手動解除（`/api/generation/release`）可能となり、待機・実行中・未確認の全表示から安全に除去できる出口契約を明記する。
