# REQ-424-T2: JobManagementModalの単一キャンセル即時実行と3秒間アンドゥUI統合

## 1. 概要と目的
本タスクは `JobManagementModal` において、待機中ジョブ（`visiblePending`）の単一キャンセル時に存在していた旧3秒事前ディレイロジック（`reserveQueuedCancel`）を撤廃し、押下と同時に即時キャンセル（`cancelQueuedJobWithUndo`）を実行するよう改修する。さらに、キャンセル直後に「取り消し」ボタンと残り有効時間表示を伴うアンドゥ通知UIを表示し、3秒以内の復元（`restoreCancelledJob`）および自然確定・手動消去（`dismissQueuedCancelUndo`）を統合・検証する。本カードが唯一の意味的仕様書である（dev-task Step 1）。

### 3.2 修正対象のコード設計（JobManagementModal.tsx）
```tsx
// frontend/src/components/JobManagementModal.tsx
// 旧 reserveQueuedCancel（3秒事前ディレイ）を廃止し、即時キャンセルハンドラに置換
const handleQueuedCancel = async (promptId: string, e: React.MouseEvent) => {
  e.stopPropagation()
  if (busyRef.current) return
  await cancelQueuedJobWithUndo(promptId)
}

// 待機ジョブ一覧の削除ボタン（事前ディレイを挟まず即時キャンセルを発行）
```

## 4. 実装要件 (Implementation Logic)
1. **旧事前ディレイロジックの撤廃 (`JobManagementModal.tsx`)**:
   - `queuedReservation` ステートおよび `cancelTimer` ref の旧事前ディレイ（3秒 setTimeout）をクリーンアップ。
   - `handleQueuedCancel(promptId: string, e: React.MouseEvent)` を新設:
     - `e.stopPropagation()` を実行。
     - ユーザーのボタン押下操作と同時に（3秒事前ディレイを挟まず）、イベントハンドラ内で直ちに `cancelQueuedJobWithUndo(promptId)` を呼び出し、レスポンス待ちなしでUI上の待機ジョブ一覧から該当ジョブを即座に除外（即時キャンセル実行）する ([REQ-424/AC-1])。
     - ストア側でバックエンドAPI（`generationApi.cancelJob`）発行およびキュー再取得（`fetchQueue`）が直ちに実行され、サーバーステートと同期する。
2. **事後3秒間アンドゥ通知UIの統合 ([REQ-424/AC-2], [REQ-424/AC-4])**:
   - `useGenerationStore` から `queuedCancelUndo`, `restoreCancelledJob`, `dismissQueuedCancelUndo` を購読。
   - `queuedCancelUndo` が存在する場合、待機キュー一覧の上部に非ブロッキングな通知バナーを表示:
     - **残り有効時間タイマー開始と表示仕様 ([REQ-424/AC-2])**:
       - 単一キャンセル直後、3秒間（3000ms）の有効期限タイマーを開始する。
       - 通知バナー内に残り時間インジケーター（3秒から0秒へ進行するプログレスバーアニメーション、および「3秒以内なら取り消せます」等の残り時間テキスト表示）を常時表示し、ユーザーに視覚的フィードバックを提供する。
     - **「取り消し」ボタン ([REQ-424/AC-3])**: クリックで `restoreCancelledJob()` を呼び出し、`CancelledJobSnapshot` に退避されたワークフロー（`workflow`）およびプロンプト・パラメータメタデータ（`metadata`）を完全にマッピング・復元してキューへ即座に再投入し、通知バナーを消去する。
     - **「×」ボタン（または閉じる） ([REQ-424/AC-4])**: クリックで `dismissQueuedCancelUndo()` を呼び出し、通知UIを即座に非表示にしてキャンセルを確定する。
     - **3秒経過による自然消去 ([REQ-424/AC-4])**: 3秒（3000ms）タイマーが満了した時点で自動的に通知UIを非表示とし、キャンセル確定状態を維持する。
3. **既存動作の保護 ([REQ-424/AC-5])**:
   - **実行中ジョブ緊急停止**: 実行中ジョブ（running）の「緊急停止」ボタン押下時は、既存の確認モーダル（`confirmRunningCancel`）の表示を経て即時中断APIが発行されるフローを完全維持。単一待機キューUndoロジックは一切干渉しない。
   - **一括全件キャンセル**: 一括キャンセル操作時（「待機中の全キューをキャンセルしますか？」確認ダイアログ）の表示タイミングやボタン活性制御はそのまま維持。ユーザーが確認ダイアログで「OK」を承認した時点でストアの `clearPendingQueue()` が呼び出される。
   - **競合回避ロジック**: 一括キャンセル実行時や緊急停止モーダル承認時は、Undo通知が表示されていてもストア側で保留中の `queuedCancelUndo` スロットおよびタイマーが直ちに自動破棄され、確認ダイアログの表示制御やAPI呼び出し順序が阻害されず完全に独立して正常機能する。
4. **コンポーネントテストの更新 (`JobManagementModal.test.tsx`)**:
   - 旧「3000ms後に一度だけキャンセルが呼ばれる」テストを「押下直後に `cancelJob` が即時呼ばれる」テストに更新（`[REQ-424/AC-1]`）。
   - キャンセル直後にUndo通知UIが表示されることを検証（`[REQ-424/AC-2]`）。
   - 3秒以内に「取り消し」をクリックするとジョブ復元が実行されることを検証（`[REQ-424/AC-3]`）。
   - 3秒経過または閉じるボタン押下で通知が閉じ、キャンセル確定となることを検証（`[REQ-424/AC-4]`）。
   - 一括キャンセルや実行中ジョブ中断が阻害されないことを検証（`[REQ-424/AC-5]`）。
