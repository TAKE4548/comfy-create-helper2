## 追記する内容（意味を変えずに日本語の仕様文として整える）

1. **snapshot の配信窓**: snapshot（WS配信と `GET /api/generation/state`）の `jobs` は、次の和集合の job 全件とする。「全状態」とはこの配信窓の全状態を指し、一体性（epoch/revision と部分 merge 禁止）は維持する。
   - 非終端job（queued / submitting / running / unconfirmed）全件
   - 非終端jobを1件以上含む batch の全job
   - 現在の `normal_group_id` に属する全job
   - 直近20個の batch（受付時刻の新しい順）の全job
   - session ごとに直近10件の解除済み（released）job
   batch と group は単位ごとに欠けず含まれるので、通常生成・Studio batch の N/F と、解除済み直近10件の表示は全件時と同じになる。`batches` は窓内 job の batch だけを含む。
2. **窓外 job の扱い**: 取消・記録解除・プレビュー取得・画像 availability などの job 単位操作は、配信窓に含まれない job も job_id / prompt_id で照会して従来どおり判定する（終端済みは already_terminal 等、存在しなければ not found）。
3. **非機能制約**: バックエンドは Generation 状態の取得で、イベントループを全件 DB 読込・全件 JSON 解析で占有してはならない。状態取得は revision が変わらない限り再計算しない。プレビューフレーム受信時は generation_jobs の全件再読込を行わない。
4. **上流不通時のログ**: ComfyUI 不通で reconcile が連続して失敗する間、詳細な例外（stack trace）付きの記録は失敗開始時の1回に限り、その後は間隔を空けた要約記録とする。回復時に回復した旨を1回記録する。
5. **SQLite 接続設定**: バックエンドの SQLite 接続は WAL モードと busy_timeout（5秒）を設定する。WAL の `-wal` / `-shm` ファイルは DB 本体と一体のデータであり、キャッシュとして削除しない。
6. **保持方針**: DB 上の終端 job 記録の保持上限（REQ-333 の 1000件方針）は変えない。配信窓は DB の保持件数と独立に有界である。
