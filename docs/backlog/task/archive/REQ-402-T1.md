## History Preservation Context Repair
- 参照元: usePresetHistory.tsの既存signatureは `undo(presetId:string|number):void`、`redo(presetId:string|number):void`、`recordHistory(presetId,previousState:HistoryState):void`。usePresetStateはraw undo/redoをそのまま返す。引数省略でactive IDへfallbackする契約はない。
- 履歴はsessionStorageの `prompt-surgeon-history-${id}` に `{past:HistoryState[],future:HistoryState[]}`。fixtureは各case前にsessionStorage.clearも行い、他case履歴を引き継がない。canUndo/canRedoはactiveSetIdの履歴を参照するが、undo/redoは渡したIDの履歴を参照する。
- recordHistoryはpreviousStateをpastへpushしfutureを空にする。undo(id)は現在のrenderのcurrentStateをfutureへpush、past末尾をpopしてonApplyState(previous)を呼ぶ。redo(id)は現在stateをpastへpush、future末尾をpopしてonApplyState(next)を呼ぶ。
- usePresetStateのonApplyStateは **global Zustand editor** のsetParamValues/setAppliedAssets/setBatchSize/setSeedMode/setSeedを呼ぶ。history hook内のlocal currentState変数を書換える処理ではない。currentStateはstore再renderから再構成されるため、redoはundo反映後の最新result.currentから呼ぶ。
- HistoryStateはparamValues/appliedAssets/batchSize/seedMode/seedの5field。promptChipsとsets自体は履歴snapshotのfieldではない。undo直後の同期履歴契約にsetsやpromptChipsの直接置換を要求せず、editorの5fieldを観測する。flush時のsets同期保証は別assertする。
- 実INTのactive103でbaseline H0=`{paramValues:{prompt:'server-103'},appliedAssets:{},batchSize:1,seedMode:'random',seed:42}`。draft H1はparamValues={prompt:'flush-draft'},seed=77で他3fieldはH0と同じ。sessionStorage空→初回GET/sync完了→actでH1をstoreへ反映→最新hook render→flushAutoSave→deferred PUT受信を待つ。flushはH0をhistoryへ記録し、setsへH1を同期。canUndo=trueだけでなくpast末尾H0/editor H1を確認する。

## Required Behavior
1. 表示順=setsをString正規化open IDsでfilterしdedupe。workflowなし/無効triggerはnull、空target no-op。A B C D EのC: left A B、right D E、others A B D E。Cは対象外。元activeがtargetならtriggerへ、残るなら維持。

3. usePresetStateのmutateAsync境界にqueue。既存単一pendingSaveArgsRef/onSettled dispatchを置換し、異IDを上書きしない。同ID同snapshotはPromise dedupe。異snapshotは順序保持、先行失敗後後続は保留して利用者へ戻す。void performUpdatePreset wrapperでrejection処理。
4. production入口autosave、handleUpdatePreset、競合overwrite callbackを同adapterへ集約。返却updatePresetMutationの互換性維持し、onMutate/onSettledでもin-flight/世代追跡。create/rename/delete/reorder/bulk適用のbusy中はbarrier開始拒否、途中開始はclose世代無効化。
5. lastSavedStateRefは初回GET/明示load/成功PUT ACKの確認済snapshot。AutoSave成功前代入を除く。初期StoreSyncで全preset baseline、後続GETはClean非activeだけreconcile。Dirty/pending/失敗draftをACKと誤認しない。初期同期後Clean closeは可能にする。
6. base_updated_atは直前成功ACKから取得、409自動force/rebase retry禁止。既存競合UI/明示再操作へ。既存flushAutoSave():voidと同期updateActiveSet、生成payloadの最新性を維持。
7. Barrier: timer停止→active bufferをsets同期（active対象外でも）→対象全件snapshot→既存in-flight待機→dirty対象を順次保存ACK待ち。初期sync未完/baseline不明/preset欠落/対象の未解決競合は中止と原因通知。
8. active snapshotはeditor、inactiveは各set。部分server保存成功後に後続失敗しても全target open、失敗/未送信draft保持、成功済server書込rollbackはしない。
9. commit直前にworkflow/mount世代、plan表示順/open/active、全target内容と対象外active bufferを再照合。編集/並び/新規tab/active変更は中止・再操作、勝手にtarget再計算しない。
10. workflow切替/unmountで世代無効化。後着ACKのcloseなし。job query keyをcaptured workflowに固定、新workflowへ旧ACK混入なし。送信済HTTP取消保証はしない。重複一括操作はpending中拒否、finallyは当該世代のみ解除。
