### 2.2 APIクライアント（frontend/src/api/client.ts）

```typescript
export const lorasApi = {
  list: (category_id?: number) => request(`/loras${category_id ? `?category_id=${category_id}` : ''}`),
  create: (data: unknown) => request('/loras', { method: 'POST', body: JSON.stringify(data) }),
  update: (id: number, data: unknown) => request(`/loras/${id}`, { method: 'PUT', body: JSON.stringify(data) }),
  delete: (id: number) => request(`/loras/${id}`, { method: 'DELETE' }),
}
```

### 2.3 バックエンドAPI仕様

**PUT /api/loras/{lora_id}**
- Request Body: `LoraCreate`（全フィールドを毎回送信。trigger_word_setsは全削除後に再作成）
- Response: `LoraRead`
- 過去の `snapshots.params` への影響なし（params はリクエスト送信時の値を直接格納）

## 3. 実装要件 (Implementation Logic)

### State追加
- `editLora` state (`Lora | null`): 編集対象LoRAを保持（nullで編集モーダル非表示）
- `editForm` state: 編集フォームの値（登録フォームと同じ型）

### 編集ボタン追加（LoRAカードのホバー領域）
- 削除ボタン（`lora-delete-${lora.id}`）の左側に編集ボタンを追加
- `id="lora-edit-${lora.id}"`
- アイコン: `Pencil` (lucide-react、`size={13}`)
- クリック時: `editLora` に対象LoRAをセット、`editForm` に既存値をプリセット
  - `words` は `tws.words.join(', ')` でカンマ区切り文字列に変換
- スタイル: 削除ボタンと同様の `absolute top-2 right-8` に配置（削除ボタンは `right-2`）

### 編集モーダル追加
- 登録モーダルと同じ構造・スタイルを流用
- タイトル: `"Edit LoRA Model"`
- 閉じる動作: `editLora` を null にリセット
- フォームフィールド: 登録モーダルと同一（Model Name/Path、Description、Strength Min/Max、Category）
- trigger_word_sets のUIは今回のスコープ外（PBIには含まれない）
- 「保存」ボタン: `id="save-edit-lora-btn"` → `updateLora.mutate()` を呼ぶ

### useMutationの追加
```typescript
const updateLora = useMutation({
  mutationFn: () => lorasApi.update(editLora!.id, {
    ...editForm,
    trigger_word_sets: editForm.trigger_word_sets.map((t) => ({
      name: t.name,
      words: t.words.split(',').map((w) => w.trim()).filter(Boolean),
    })),
  }),
  onSuccess: () => {
    qc.invalidateQueries({ queryKey: ['loras'] })
    setEditLora(null)
  },
})
```
