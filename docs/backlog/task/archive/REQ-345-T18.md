# REQ-345-T18 復元待ち・残存同期待ちでfull history GETを抑止する

## Ownership and Atomicity

Write only the listed hook and its residual test file, with at most 100 changed lines total. Preserve other shared edits.

## Failure Evidence

The user performed the reload check. `tools/server-manager/logs/backend.log` records `GET /api/comfy/history` at 2026-10-12 04:59:28.565, followed by `POST /api/generation/history/residual` at 04:59:31.188. During persisted query restoration, the focus/visibility handler can run while the residual record is still `waiting`, causing a bounded but unnecessary full history fetch before differential reconciliation.

## Implementation Contract

- In the `useGenerateDisplayState` visibility/focus refresh path, do not call `store.fetchHistory()` while the residual record is `waiting` or `checking`.
- Continue refreshing the queue when the page becomes visible.
- Preserve existing focus history refresh after residual reconciliation reaches a terminal state (`complete`, `partial`, or `error`) and when no-baseline reconciliation completes immediately.
- Add a regression test with persisted baseline and Query restoration still active: dispatch focus/visibility while status is `waiting`; assert `fetchHistory` is not called. After restoration settles and residual sync completes, assert normal later focus can refresh history.
- Do not change the residual request, examined/known identities, merge behavior, or store history action semantics.
