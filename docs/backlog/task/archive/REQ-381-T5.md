## T0 Draft registry integration

T0の `useSettingsDraftRegistration(resourceId,{cancelQueued,discardLocal})` は `{update(risk),clear()}` を返す。riskは `{dirty,invalid,failed,queued,inFlight}:boolean`。unique instance ID/resourceで登録し、raw値をregistryへ渡さない。edit/commit/ack/errorで同期updateし、cleanup/成功baseline一致/明示cancelで適切にclearする。mobile/desktopとも登録する。

Cancel navigationはdraft/queueを変えない。確認中inflight保存は通常完了するが、Leaveは全persist inFlight==falseまでdisabled。explicit Leave時だけ未送信queueを同期停止しlocal draftを破棄するcallbackを提供し、remote successのrollbackやautomatic retryをしない。同Settings hash/query切替とresizeだけでは破棄しない。previewなど非persist要求は保存inFlightに数えない。

SpeechTonePresetModalのname/prompt/description/sortOrderをinitial値と比較しdirtyを登録。isPendingはpersist inFlight、親create/update mutation errorは必要な局所propsで同じfile内から渡しfailedへ反映する。preview inFlightは含めない。Cancel/Save成功baselineのみclear、navigation CancelでonCloseを呼ばない。

## Exact T0 Registration Signature

`SpeechToneSection.tsx` の所在から `../context/SettingsDraftContext.tsx` が実在moduleへ解決することを確認済み。次は実exportの型契約であり、新しいAPIを追加しない。

```ts
import {
  useSettingsDraftRegistration,
  type SettingsDraftRisk,
  type SettingsDraftControls,
} from '../context/SettingsDraftContext'

export type SettingsDraftRisk = {
  dirty: boolean; invalid: boolean; failed: boolean; queued: boolean; inFlight: boolean
}
export type SettingsDraftControls = {
  cancelQueued: () => void; discardLocal: () => void
}
export function useSettingsDraftRegistration(
  resourceId: string,
  controls: SettingsDraftControls,
): { update: (risk: SettingsDraftRisk) => void; clear: () => void }
```

SpeechTonePresetModal内の利用例（型宣言をsourceへ重複定義しない）:

```tsx
const controls: SettingsDraftControls = {
  cancelQueued: () => {}, // toneは明示Saveであり未送信autosave queueを持たない
  discardLocal: onClose, // 明示Leave時だけ既存close経路でmodal draftを破棄
}
const { update, clear } = useSettingsDraftRegistration(
  `speech-tone:${mode}:${initial?.id ?? 'new'}`,
  controls,
)
const publishRisk = (risk: SettingsDraftRisk) => update(risk)
// edit/submit/ack/errorでpublishRisk、成功Saveまたは実際のmodal取消でclear。
```

hook自身が `useLayoutEffect` で登録し、unmount/resourceId変更時に自動unregisterする。consumerに別の登録解除処理を重複実装しない。navigationのCancelはblocker.resetのみで、ここでのonClose/clearを呼ばずdraftを保持する。risk算出とpersist pending/errorの扱いは直前の承認済み契約を維持する。

## Real Client / MSW Test Method

既存owned `SpeechToneSection.test.tsx` はAPI clientとReact Query全体をglobal mockしている。新ACの受入ではこのmockを外し、同じowned testを実QueryClient＋MSWへ移行する。旧caseの意図は保持し、mutation spy期待を実HTTP method/body/応答後UIの期待へ置き換え、query/保存応答はawaitする。別test fileやmodule-cache/unmockによる混在harnessを追加しない。内部handler/registry/React Queryはmockしない。

実clientは `frontend/src/api/domains/speech.ts` の `speechTonePresetsApi`、`core/base.ts` の `BASE_URL='/api'`。実requestは次のHTTPへ到達する。

| 操作 | path/method | payload / 応答 |
|---|---|---|
| list | GET `/api/speech-tone-presets` | SpeechTonePreset[] |
| create | POST `/api/speech-tone-presets` | `{name,prompt,description?,sort_order?}` → SpeechTonePreset |
| update | PUT `/api/speech-tone-presets/:id` | 任意のname/prompt/description/sort_order → SpeechTonePreset |
| rewrite | POST `/api/speech-tone-presets/rewrite` | `{text,tone_prompt?,preset_id?}` → `{rewritten_text:string}` |
| delete | DELETE `/api/speech-tone-presets/:id` | 応答204 |

SpeechTonePreset応答は `{id,name,prompt,description?,sort_order,created_at}`。実modal submitはname/promptをtrim、description空はundefined、sort_orderをnumberとして送る。Sectionのcreate/update成功callbackはqueryをinvalidateしmodalを閉じる。503/422は成功responseに偽装せずdraft/errorを確認する。認証/秘密値はfixture不要。

既存 `src/test/mocks/server.ts` が `setupServer(...handlers)` をexportするが自動listenはしない。`src/test/setup.ts` はjest-dom importのみ。owned test側で既存serverを起動する（既存 `src/test/msw.test.ts` と同じ契約）。

```tsx
import { http, HttpResponse } from 'msw'
import { server } from '../../../../test/mocks/server'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { createMemoryRouter, RouterProvider } from 'react-router-dom'
import { SettingsDraftBoundary } from '../SettingsDraftBoundary'

beforeAll(() => server.listen({ onUnhandledRequest: 'error' }))
afterEach(() => { cleanup(); server.resetHandlers() })
afterAll(() => server.close())
// 各testは返されたrouter.dispose()/client.clear()もfinally等で実施。
const preset = { id: 17, name: '丁寧', prompt: '口調',
  description: '説明', sort_order: 2, created_at: '2026-01-01T00:00:00Z' }
beforeEach(() => server.use(http.get('/api/speech-tone-presets', () => HttpResponse.json([preset]))))
// create/update caseは同pathのhttp.post/http.putでrequest.json()を捕捉し、
// HttpResponse.json({...preset,...submitted})を返す。失敗caseはstatus:503/422。

function mountRealTone() {
  const client = new QueryClient({ defaultOptions: {
    queries: { retry: false }, mutations: { retry: false },
  } })
  const router = createMemoryRouter([
    { path: '/settings', element: <SettingsDraftBoundary>
      <SpeechToneSection isExpanded onToggle={() => {}} />
    </SettingsDraftBoundary> },
    { path: '/other', element: <p>移動先</p> },
  ], { initialEntries: ['/settings'] })
  const view = render(<QueryClientProvider client={client}>
    <RouterProvider router={router} />
  </QueryClientProvider>)
  return { ...view, router, client }
}
```

具体的な `[REQ-381/AC-8]` caseはmount→GET完了後の実「編集」button→実preset名inputへ未保存値を入力→`await act(async () => { await router.navigate('/other') })`→`findByRole('dialog',{name:'未保存の設定'})`→そのdialog内のCancelを押す。`router.state.location.pathname==='/settings'`、実tone modalのinputに未保存値が残ること、create/update HTTPが0件であることを確認する。これは実SpeechToneSection/Modal/client/registryと実data-routerの統合で、T0のdummy probeのみを受入証拠へ流用しない。両modalに同名Cancelがあるので必ずdialogをscopeする。

追加で実POST/PUTを503/遅延にして、失敗draft保持・persist pending中Leave disabled・preview要求をpersist扱いしないことを検証する。cleanupは自分のrouter/client/MSW handlerだけを破棄し、shared sourceや他Card/testを変更しない。既存全caseを保持するため局所case-filterに加え同SpeechToneSection.test.tsx全体も実行する。

## Constraints / UI archetypes

- mobileは<768px、desktopは>=768px。desktopの既存操作/Save/配置を保持。生vh、global font floor、一括padding overrideを追加しない。文字は11px以上、重要なerror/未保存はtruncateしない。
