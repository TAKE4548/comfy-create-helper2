## 3. 実装要件 (Implementation Logic)
- [x] `useGenerationStore.ts` に `activeBatch` 状態および `setActiveBatch` / `updateBatchJobStatus` アクションを追加する。
- [x] `useGenerationStore.ts` の WebSocket メッセージハンドラーにおいて、`activeBatch` が存在する場合は各イベント（`execution_start`, `executed`, `execution_complete`, `execution_error`）受信時に `updateBatchJobStatus` を通じて該当ジョブのステータスを更新する。`activeBatch` 内のすべてのジョブが完了または失敗状態に達した時点で `isGenerating` を `false` に変更する。
- [x] `useGenerationStore.ts` の `fetchQueue` アクションを拡張し、`activeBatch` に残っている `pending` / `generating` なジョブが ComfyUI キュー（`queueRunning` および `queuePending`）から消失している場合に、キューのクリア（キャンセル）が発生したと判定し、`activeBatch: null`, `isGenerating: false` にリセットする。
- [x] `useGenerationStore.ts` の `cancelJob` / `cancelAllJobs` アクション内でも `activeBatch = null` による状態クリアを適切に行う。
- [x] `useGenerateAction.ts` の `handleGenerateSets` において、`waitForPrompt` による同期待機処理を完全に削除する。選択（`checked`）された各セットのバッチ総数のループを即座に実行して `queuePrompt` を呼び出し、取得した `promptId` のリストを用いて `activeBatch` 状態を初期化する。
- [x] `GeneratePage.tsx` の進捗表示領域（Progress Line / Status bar）において、`activeBatch` に基づく `"Generating (m/n Complete)..."` という表示をサポートし、プログレスバーの進捗率も全体の完了割合（$m/n$ に実行中ジョブの端数 progress を足した比率）を基準に算出する。生成中もパラメータの入力フィールドは一切ロックしないこと（AC-5）。
