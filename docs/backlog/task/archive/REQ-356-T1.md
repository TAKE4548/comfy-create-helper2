# REQ-356-T1: [Tool/Governance] 既存テスト検証項目対応表の抽出ツールおよびテスト名形式検証スクリプト作成

## 1. 概要と目的
再構成前の既存全テスト（Backend 約757件、Frontend 約80ファイル）が担保している検証項目一覧（対応表 `docs/design/REQ-356-test-mapping.md`）を自動抽出し、非破壊リファクタ（AC-10/AC-13）の比較基準を確立する。
同時に、AC-15 で要求されるテスト名形式検証スクリプト `scripts/verify_test_naming.py` を作成し、PBI紐づきテストが `[REQ-xxx/AC-n]` 形式を満たしていること、ファイル名に `req\d+` が含まれていないこと（AC-1）を機械判定できるようにする。

## 2. ターゲット識別
- **対象ファイル**: `scripts/verify_test_naming.py`, `docs/design/REQ-356-test-mapping.md`
- **対象シンボル**: `verify_test_naming()`, `extract_test_mapping()`

### 3.2 判定正規表現とロジック
```python
import re

PBI_PATTERN = re.compile(r"\[(REQ-\d+)/(AC-\d+)\]")
FORBIDDEN_FILENAME_PATTERN = re.compile(r"req\d+", re.IGNORECASE)

def validate_test_name(name: str) -> bool:
    if "REQ-" in name or "req" in name.lower():
        return bool(PBI_PATTERN.search(name))
    return True  # PBI紐づけなしテストは許容
```
