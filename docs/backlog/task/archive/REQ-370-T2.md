# REQ-370-T2: residualHistory FIFO スロット上限計算と差分画像の先頭側挿入位置補正

## 1. 概要と目的
残存履歴（`residual-history`）の同期処理において、既存保持件数が 200 件に達していると新規差分候補が全件切り捨てられる問題（事前空き枠計算の不整合）を解消し、新規差分候補を受け入れた上で全体を 200 件に制限する FIFO 方式へ改修する（`AC-2`）。また、初回差分マージ時に画像が配列最末尾（最古画像の後ろ）に挿入されて時系列が逆転する欠陥を是正し、配列先頭側へ挿入する（`AC-3`）。

## 3. 実装制約と設計上の注意事項
- `candidates` に対する事前 `slice(0, allSlots)` を行わず、`allMerged.slice(0, 200)` で事後スライスすること。
- `priorKeys` が一致した場合は既存の `insertAt + 1` の動作を厳密に維持すること（後続ページが正しく前ページの後ろに連鎖する）。
