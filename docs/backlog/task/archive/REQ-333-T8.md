## Hermetic Contract

以下は承認対象の新contract。scopeとproject、上流client IDと利用者sessionは別。clientから完了状態を送らない。
受付はDB commit後202。上流POST結果不明はunconfirmed、自動再送なし。BE再起動完全復元を追加しない。
通常Nはcancelled除外、F=succeeded+failed。Studio各batch独立。別scope待機優先、他session待機はfilter ONだけ。
snapshotはepoch/revisionでatomic置換、eventも同じ形の全状態dataを使い部分mergeを避ける。SYSTEM_STATS/VRAM_RECOVEREDのtype/data・2.5秒周期保持。
既存30local/1000server metadata、Snapshot独立、Studio750ms/draft競合、画像aspectを保持。
カード外ファイルや公開contract変更が必要なら設計へ差し戻す。

## Local Verification

共有decoder具体化: 完全nested検証を行う `decodeGenerationSnapshot(value:unknown):GenerationSnapshot` をexport。
`decodeGenerationEnvelope(value:unknown):GenerationEnvelope` もexportし、type/version/epoch/revisionとdataの一致を検証。
HTTP getStateとWS consumer T15が同じ検証を再利用する。未知version/壊れたnested payloadはthrow、部分stateを返さない。
単件cancel helperは `cancelJob(jobId:string, onlyUnsubmitted?:boolean):Promise<CancelResult>`。
true時だけ既存単件cancel URLへ `?only_unsubmitted=true` を付加。VRAM待機取消用で、既存default経路はそのまま。

実装時補足: availability(jobId)はGET `/api/generation/images/{jobId}/availability`、応答はImageView[]。
各出力のavailabilityはpresent/missing/unknown。原画確認が確定404の時だけmissing、502/timeout/判定不能はunknown。
API自体の404/503をFEで全画像missingへ変換せずtyped errorとして返す。Snapshot画像へ適用しない。
imageAvailability(identity)は別のGET `/api/comfy/image-availability`、filename/subfolder/type queryでUUID不要。
StateSnapshot.jobsはmanagedのみの非nullable JobView。legacyのnullable job_id/statusはCancelResultだけに適用する。
