# REQ-394-T4: FE の node 環境化（AC-1）

- 役割は engineer / dev-task。workspace はリポジトリルート。FE のコマンドは `cd frontend` してから実行する。
- 所有範囲は下記 43 ファイルの**先頭 1 行の追加のみ**と、2 ファイルへのカナリア各 1 件の追加。製品コード、`frontend/vite.config.ts`（T6 の所有）、`frontend/src/test/setup.ts` は変更しない。

## 背景（計測済み）

vitest 1.6.1 は pool=forks・isolate 既定で、全 247 ファイルを jsdom で実行する。jsdom の import は fork 1 つあたり約 1.1s で、environment の累計が 1038s（Duration 内訳）。`.test.ts` 95 件に `--environment node` を CLI で当てると 43 件が全 PASS（52 件は DOM 必須）。43 件に docblock を付けると全体 wall は約 134s から約 113s になる（scratch 上で 2607 件全 PASS を確認済み）。

vitest 1.6.1 は `@vitest-environment` の記述をファイル内容から正規表現 `/@(?:vitest|jest)-environment\s+?([\w-]+)\b/` で検出する。位置は問われないが、規約として 1 行目に置く。

### 要確認の 4 ファイル

次の 4 件は DOM 関連の語を含む。本文を読み、`window`/`navigator`/`localStorage` を `vi.stubGlobal` や `Object.assign` でスタブしているだけ、または fake-indexeddb を使うだけで、実 DOM（jsdom の挙動）を検証根拠にしていないことを確認する。実 DOM を根拠にしているものは jsdom に残し（docblock を付けない）、報告に理由を書く（その場合の対象は 42 件以下になり、設計の件数・予算の見込みは変わらない）。

- `src/components/common/header/__tests__/headerMenuPlacement.test.ts`（テスト名に "jsdom getBoundingClientRect" を含む）
- `src/store/__tests__/usePromptClipboardStore.test.ts`
- `src/utils/__tests__/browserStorageUsage.test.ts`
- `src/utils/__tests__/queryCachePersister.test.ts`

## 2. カナリア 2 件（FE の収集件数 2607 → 2609）

docblock の効きと既定環境の維持を恒久的に検知する。既存ファイルの最後の `});`（describe の終端）の直前に追加する。

```

cd frontend; (Get-ChildItem -Recurse src -Filter *.test.ts | Select-String -Pattern "@vitest-environment node" -List).Count
```

`--sequence.shuffle` で 2 回実行して全 PASS・ハングなし。2 つ目の件数が採用ファイル数（43、または確認で外した分だけ少ない数）と一致する。`@vitest-environment` を含む他のファイルが無い。

`--sequence.shuffle` で既存テストの順序依存による失敗が出た場合は、shuffle なしで同じファイルが PASS することを確認して報告し、docblock 起因でないことを示す（docblock を外して同じ失敗が出るなら既存の順序依存であり、ESCALATE_TO_DESIGN）。
