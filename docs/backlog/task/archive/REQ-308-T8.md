# REQ-308-T8: Workflow mapping 到着時に clean active preset を再同期

## Impacted Files
- `frontend/src/pages/GeneratePage/hooks/usePresetStoreSync.ts`
- `frontend/src/pages/GeneratePage/hooks/__tests__/usePresetStoreSync.test.ts`

## Hermetic Context
`usePresetStoreSync` effect depends on `workflow`. First sync may run with `workflow === undefined`, compute `promptRoles = []`, and call `loadPresetData`. On the next render with textarea mappings, `isFirstSync` is false; the current clean-snapshot path calls `loadPresetData` only when `activePreset.updated_at` changes. Therefore the prompt chips remain empty when mapping arrival does not change the preset timestamp.

T1 adds `currentStore.promptRoleAllowlist` and `loadPresetData(preset, defaults, promptRoleAllowlist)`. `HistoryState` and `isStateEqual` compare editable parameter values/assets/batch/seed, so clean active state can be checked before rehydration.

## Implementation
- Detect that active preset is clean and the available textarea role allowlist differs from the store allowlist.
- Re-call `loadPresetData(activePreset, defaultParams, promptRoles)` to reparse only mapped prompts when mapping arrives.
- Preserve dirty local edits; do not rehydrate over them. Avoid repeated resets when the role allowlist is unchanged.
- Add rerender tests: load before mapping then mapping arrives and prompts are rehydrated; mapping arrival after local edits preserves those edits.
