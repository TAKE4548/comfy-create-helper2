# REQ-427-T3: 生成時の参照画像供給

## 1. 目的
生成用 graph のノード入力に含まれる参照トークン `refimg:<sha256>.<ext>` を、バックエンド生成 worker が ComfyUI 上流 `POST /prompt` の直前に解決する。ストアの原本を ComfyUI `POST /upload/image` へ供給し、返却された参照名（`<subfolder>/<name>`）へ置換して投入する。トークンが無い graph は従来どおり（AC-6）。受付時はトークンのストア実在を検証し、欠落なら 422 で全体拒否する。

## 4. 前提契約（T1 が提供、変更禁止）
```python
# backend/app/services/ref_image_store.py
REF_TOKEN_RE  # ^refimg:([0-9a-f]{64})\.(png|jpg|webp)$
def parse_ref_token(value: object) -> str | None      # 完全一致なら ref_id "<sha>.<ext>"
class RefImageError(Exception): status: int; code: str; message: str
class RefImageStore:
    @classmethod
    def default(cls) -> "RefImageStore"
    def save_bytes(self, data: bytes) -> StoredRefImage  # テストでの事前投入に使用
    def exists(self, ref_id: str) -> bool
    def read(self, ref_id: str) -> tuple[bytes, str]     # 無ければ RefImageError(404)
    def claim(self, ref_ids: Iterable[str]) -> list[str] # ストアロック下で存在確認＋mtime 更新(touch)を原子的に実施し、欠落 ref_id を返す
```
- 背景: T1 の GC は「どこからも参照されず、原本 mtime が 72 時間より古い」画像を定期削除する。受付時に `claim` で touch することで、受付〜DB commit の間に GC が対象画像を削除しないことが保証される（GC はロック下で mtime を再確認してから削除する）。

### 5.3 `GenerationService` 統合（C6）
- コンストラクタに **キーワード引数** `ref_image_supplier: RefImageSupplier | None = None` を末尾追加（既存引数の位置・意味は不変）。`None` のとき `isinstance(bridge, RefImageUploadPort)` なら `RefImageSupplier(RefImageStore.default(), bridge)` を生成、そうでなければ `self._ref_supplier = None`。
- `LiveBridgePort` / `GenerationPort` Protocol は変更しない（`FakeBridge` 等の既存実装との互換と mypy のため）。
- **accept**: `async with self._lock:` 内で `previous` 判定後、`replay` でない場合に限り、全 item の `collect_ref_ids(item.graph)` を調べ、トークンがあるのに `self._ref_supplier is None`、または `claim_refs` の欠落が非空なら、
  `raise HTTPException(status_code=422, detail=ErrorDetail(code="ref_image_not_found", message=..., outcome="failed", request_id=payload.request_id, job_id=None).model_dump(mode="json"))`
  （`from starlette.exceptions import HTTPException`、`ErrorDetail` は `app.schemas.generation`）。`repository.accept_batch` を呼ぶ前に送出し、何も commit しない。router 側は既存の `except HTTPException → _http_error` で 422 envelope を返す（router 変更不要）。
- **worker**: `submitting` 遷移・publish の後、`bridge.submit` の前に `collect_ref_ids(item.graph)` が非空なら `graph = await self._ref_supplier.resolve(item.graph)`（supplier が `None` なら供給不能として失敗扱い）。
  - 成功: `response = await self.bridge.submit(graph)`（以降は既存処理）。
  - `RefImageSupplyError`（および supplier 不在）: `repository.transition(job_id, "failed", failure={"reason": str(e), "outcome": "failed"}, finished_at=self._now())` → `await self._publish_snapshot()` → `continue`。`submit` は呼ばない。
  - `asyncio.CancelledError`: `failed`（reason「上流投入前にサービスが停止しました」）へ遷移して再送出。
  - トークン無し: 一切呼ばない（既存挙動・既存テスト不変）。
