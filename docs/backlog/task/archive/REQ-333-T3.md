## Hermetic Contract

以下は承認対象の新contract。scopeとproject、上流client IDと利用者sessionは別。clientから完了状態を送らない。
受付はDB commit後202。上流POST結果不明はunconfirmed、自動再送なし。BE再起動完全復元を追加しない。
通常Nはcancelled除外、F=succeeded+failed。Studio各batch独立。別scope待機優先、他session待機はfilter ONだけ。
snapshotはepoch/revisionでatomic置換、eventも同じ形の全状態dataを使い部分mergeを避ける。SYSTEM_STATS/VRAM_RECOVEREDのtype/data・2.5秒周期保持。
既存30local/1000server metadata、Snapshot独立、Studio750ms/draft競合、画像aspectを保持。
カード外ファイルや公開contract変更が必要なら設計へ差し戻す。

### Persisted Column Contract (Implementation Clarification)

2026-10-10、承認済みD3/API項目の物理型を明確化。所有対象・公開動作は変更しない。
ORMは既存Mapped/mapped_column形式。次の列名・SQLAlchemy型・nullableをmigrationと一致させる。

| Column | Type | Nullable / default |
|---|---|---|
| job_id | String | false、primary key。repositoryがUUID文字列を指定 |
| request_id | String | false |
| item_index | Integer | false、request内0始まり |
| payload_hash | String | false、同request全jobで同じcanonical SHA256 |
| prompt_id | String | true、unique。未投入はNULL、複数NULL許容 |
| session_id | String | false |
| scope | String | false、normal/studioをschemaで検証 |
| batch_id | String | false、repository指定UUID |
| normal_group_id | String | true、StudioはNULL |
| project_id | Integer | true、Studioは受付で必須。新FK/cascadeを追加しない |
| set_name | String | true |
| status | String | false、ORM/server default queued |
| graph_json | Text | true、受付graph、terminal整理でNULLへ解放可能 |
| metadata_json | Text | false、ORM/server default '{}' |
| outputs_json | Text | false、ORM/server default '[]' |
| node_json | Text | true、進捗NodeProgressまたはNULL |
| accepted_at | DateTime | false、ORM utc_now、server CURRENT_TIMESTAMP |
| started_at | DateTime | true |
| finished_at | DateTime | true |
| failure_json | Text | true、JobFailureまたはNULL |
| cancel_requested | Boolean | false、ORM/server default false |

request_id/item_indexにnamed UniqueConstraint、prompt_idにuniqueを付与。
batch_id、normal_group_id、statusに通常index、追加index/保持SLAは設けない。
JSONはUTF-8相当のText、ensure_ascii=Falseでdict/listをjson.dumps/loads。binary/base64は保存しない。
metadata_jsonは凍結BatchItemのgraph以外（workflow_id,param_values,applied_assets,set_name）。
revision/epochの状態はT4 repositoryの責任で既存AppSetting等を使用し、このカードで別entityを増やさない。
migration027は既存step構造に登録。未存在時のみ表とindexを作成し、再実行で既存行を更新/削除しない。
実DBへ適用せず専用SQLite testでempty/既存旧行/二度適用/unique/multiple NULLを検証する。
