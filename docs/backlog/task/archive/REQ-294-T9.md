# REQ-294-T9: Gate 1 既存ベースライン修復

REQ-294の全体検証で、変更外の3箇所に起因する `mypy backend` 失敗を検出した。対象ファイルはHEADと同一。承認済みの機能コードを変更せず、型スタブ依存と `scripts` のパッケージ境界を最小限に補正する。上記2ファイルのみリポジトリ変更可。別PBI変更を保全し、コミットしない。

## 入力証拠

- `backend/app/services/bubble_detector.py:1 [import-untyped]`: cv2 に型情報がない。
- `backend/app/services/resource_monitor.py:9 [import-untyped]`: psutil stub がない。
- `backend/scripts/migrate_images_to_webp.py`: `migrate_images_to_webp` と `scripts.migrate_images_to_webp` の重複モジュール。
- `backend/requirements.txt` には `opencv-python-headless` と `psutil>=5.9.0` がある。`backend/scripts/__init__.py` は現状存在しない。`backend/tests/test_migrate_images_to_webp.py` は `from scripts.migrate_images_to_webp import migrate_images` を使用する。
- 現在の `mypy` は環境の `mypy` コマンド（または仮想環境内の `mypy`）。

## 実装

1. `backend/requirements.txt` に cv2 と psutil 用の実在する型スタブ依存を追加し、型検査を実行する環境にも導入する。環境導入が不可能なら理由を報告し、エラー無視設定で通過させない。
2. 空の `backend/scripts/__init__.py` を追加し、既存 import を package として一意にする。
3. `mypy backend` を再実行し、追加の型エラーが出た場合は正確な箇所・内容を返して次の原子的カードへの分割を依頼する。カード外の source を直接変更しない。

## 検証

- ルートから `mypy backend`、期待: exit 0 / 0 errors。
- backend ディレクトリから `.\venv\Scripts\python -m pytest tests/test_migrate_images_to_webp.py -q`（実際の venv が `.venv` なら `.\.venv\Scripts\python`）、期待: PASS。
- 変更前後の型検査出力を報告する。
