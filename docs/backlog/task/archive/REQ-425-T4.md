# REQ-425-T4: Frontend 生成画面の分割入力UI・Repeat操作・プリセット無効チップ保持・生成送信・履歴表示/復元統合

## Goal
生成画面（デスクトップ `DesktopLayout.tsx`・モバイル `MobileLayout.tsx`）にプロンプト構造テンプレートに基づく分割入力エディタ（`PromptTemplateSplitEditor.tsx`）を導入し、Repeat インスタンスの動的な追加・削除、分割ブロック単位でのタグチップ編集・アセット追加・翻訳・クリップボード操作、出力グループ未割り当てプロンプト欄（Negative Prompt 等）の単一入力欄維持、プリセット保存/読込時の無効化チップ（`enabled: false`）完全保持、生成送信時の出力グループ別結合と無効チップ除外、および生成履歴/スナップショット詳細での分割値表示と有効値のみの復元を統合する。

## Context & Surgical Snippets

### 1. 分割プロンプト入力コンポーネント (`PromptTemplateSplitEditor.tsx`)
```typescript
import type {
  Lora,
  PromptOutputGroup,
  PromptTemplateStructure,
  TagSet,
  WorkflowPromptTemplateConfig,
} from '../../../api/types'
import type { AppliedAsset } from '../../../store/useGenerationStore'

export interface PromptTemplateSplitEditorProps {
  config: WorkflowPromptTemplateConfig
  structure: PromptTemplateStructure
  paramValues: Record<string, string>
  setParamValues: (values: Record<string, string>) => void
  loras?: Lora[]
  tagSets?: TagSet[]
  activeBaseModelId?: number | null
  addAppliedAsset: (role: string, asset: Omit<AppliedAsset, 'id' | 'enabled'>) => void
  onOpenTranslation?: (targetKey: string, currentValue: string, onApplyText?: (newText: string) => void) => void
  onOpenSaveAsTagSet?: (label: string, currentValue: string) => void
}
```
- **状態同期と `PROMPT_TEMPLATE_STATE_KEY` (`__prompt_template_state_v1`)**:
  - `parsePresetState(paramValues[PROMPT_TEMPLATE_STATE_KEY], structure, paramValues, config.output_groups)` で現在の分割状態（各セクションの `instances` と各ブロックの `TagChip[]`、無効化チップ `enabled: false` を含む）を取得する。
  - ユーザーが任意のブロックでチップを追加・削除・編集・有効/無効トグル（`enabled: true/false`）した際、または Repeat セクションで `[+ インスタンスを追加]` / `[インスタンス削除]` した際：
    1. 新しい `PromptTemplatePresetState` を構築し、`serializePresetState(nextState)` を `nextParamValues[PROMPT_TEMPLATE_STATE_KEY]` に格納する（これによりプリセット保存・AutoSave・Undo/Redo で `enabled: false` のチップが完全保持される、`AC-7`）。
    2. 同時に `computeAllOutputGroupValues(structure, nextState, config.output_groups)` を呼び出し、各 `group.target_role` の結合文字列（`enabled: true` のチップのみを結合し、空ブロックをスキップしてカンマ正規化した文字列）を `nextParamValues[group.target_role]` に書き込む（`AC-5`, `AC-6`, `AC-10`）。
    3. `setParamValues(nextParamValues)` を呼び出す。
- **UI 機能**:
  - セクション単位の折りたたみ、および「空ブロックを折りたたむ」表示フィルタトグル。
  - `section.is_repeatable === true` のセクションでは、ヘッダーに `[+ インスタンスを追加]` ボタンと、各インスタンス（`#1`, `#2`, ...）のカードおよび削除ボタン（インスタンス数 > 1 の場合）を表示する（`AC-4`, `AC-6`）。
  - 各ブロックに `TagChipEditor`（`chips` と `onChipsChange` を直接バインドして無効化チップ `enabled: false` を保持）、`PromptSectionClipboardMenu`、および `[+ アセット]` ボタンを配置する。
  - ブロックの `[+ アセット]` ボタンから `AddAssetModal` を開いた際：
    - 選択された TagSet タグまたは LoRA トリガーワードは、当該ブロック（特定インスタンスの該当ブロック）の `TagChip[]` に `enabled: true` チップとして追加する。
    - 選択された LoRA 本体は、当該ブロック ID を含む出力グループの `target_role` に対して `addAppliedAsset(targetRole, ...)` を呼び出す。
  - 折りたたみ可能な「出力グループ別結合プレビュー」アコーディオンを用意し、各出力グループ（例: 全体プロンプト、FaceDetailer #1 等）に現在結合されている送信文字列を確認できるようにする。

### 2. `DesktopLayout.tsx` および `MobileLayout.tsx` への組み込み (`AC-4`, `AC-9`)
- `workflow?.prompt_template_config` が有効（`isWorkflowTemplateActive(workflow?.prompt_template_config)` が `true`）な場合：
  - `assignedTargetRoles = new Set(workflow.prompt_template_config.output_groups.map(g => g.target_role).filter(Boolean))` を算出する。
  - プロンプト領域の先頭に `<PromptTemplateSplitEditor ... />` を描画する。
  - `textMappings`（`input_type === 'textarea'` のマッピング一覧）のうち、`!assignedTargetRoles.has(mapping.role)` である**未割り当てロール（例: Negative Prompt 等）のみ**を、従来通りの単一 `TagChipEditor` セクションとしてその下に描画する（`AC-4`）。
- テンプレート未適用ワークフロー（`isWorkflowTemplateActive` が `false`）の場合は、従来通りすべての `textMappings` を単一 `TagChipEditor` として描画する（`AC-9`）。

### 3. 生成送信パイプライン (`useGenerateAction.ts`) (`AC-5`, `AC-6`, `AC-7`, `AC-8`)
- `getEffectiveParamValues`（または `handleGenerate` / `handleGenerateSets` 内）において：
  - ワークフローに `prompt_template_config` が設定され `paramValues[PROMPT_TEMPLATE_STATE_KEY]` が存在する場合、`computeAllOutputGroupValues` で最新の結合文字列を各 `target_role` へ確定反映した上で、既存のアセットタグ付与を実行する。
- `cleanParams` の作成時（`useGenerateAction.ts` 165〜168行および 353〜356行付近）：
  - `buildGenerationRecord` には `PROMPT_TEMPLATE_STATE_KEY` を含む `setParams` を渡して `GenerationRecord.prompt_template`（有効値のみのサニタイズ済み分割記録）を構築させた後、**送信用・保存用の `cleanParams` からは `delete cleanParams[PROMPT_TEMPLATE_STATE_KEY]` でプリセット用生ステート（無効チップ含む）を確実に除去**する（`AC-7`, `AC-8`）。

### 4. スナップショット復元 & 履歴メタデータ表示 (`useWorkflowParams.ts` & `GenerationMetadataPanel.tsx`) (`AC-8`)
- `useWorkflowParams.ts` の `loadSnapshotParams`（112〜166行付近）：
  - スナップショットの `params[PROMPT_RECORD_KEY]`（`__prompt_surgeon_metadata_v1`）をパースし、`record.prompt_template`（`SanitizedPromptTemplateRecord`）が存在する場合、`restorePresetStateFromSanitizedRecord(record.prompt_template)` を呼び出して有効チップのみから成る `PromptTemplatePresetState` を生成し、`cleanedParams[PROMPT_TEMPLATE_STATE_KEY] = serializePresetState(restoredState)` を設定する。これにより、スナップショットから生成画面へ読み込んだ際、有効だった値のみが分割入力欄へ復元され、無効化チップは復元されない（`AC-8`）。
- `GenerationMetadataPanel.tsx`：
  - `props.promptTemplate`（`getMetadataView` から渡される `SanitizedPromptTemplateRecord | null`）が存在する場合、結合送信された `GenerationPromptFields` に加えて「分割プロンプト構造（テンプレート記録）」セクションを表示し、各セクション・各 Repeat インスタンス（`#1`, `#2`...）・各非空ブロックのラベルと有効プロンプト値を一覧表示する（`AC-8`）。
