## Coordinator dispatch contract: reusable collection selection

Implement new useCollectionSelection<ID extends number|string,T extends {id:ID}>({items:T[]}): return isMultiSelectMode:boolean, selectedIds:Set<ID>, enterMultiSelectMode(firstId?:ID), exitMultiSelectMode(), handleItemClick(id,event:React.MouseEvent), toggleItem(id), selectAll(), clearSelection(), isSelected(id), getLongPressHandlers(id). Long press handlers support onMouseDown/onMouseUp/onMouseLeave/onTouchStart/onTouchEnd/onTouchCancel/onContextMenu. Fixed mobile long-press activation is 500ms; moving cancels activation (15px touch threshold), release/cancel/unmount clears timers/listeners. Suppress following synthetic click so selection is not toggled off. Ctrl/meta enters mode and toggles item; Shift uses latest displayed items order, selects inclusive anchor-to-target range, and normal clicks outside mode remain available for opening a card. Clear keeps selection mode active; exit clears and leaves mode. Prune removed/filtered-out IDs when items change to prevent destructive operations on stale IDs.

HistoryPage currently queries snapshotsApi.list({workflow_id,lora_id,tag_set_id}) into snapshots (complete filtered result), derives sortedSnapshots (current date order), and slices sortedSnapshots only for visual pagination. Therefore full filtered IDs already reside in memory even when cards are not yet rendered. Replace its snapshotMultiSelect useMultiSelect with useCollectionSelection({items:sortedSnapshots}); albumItemMultiSelect receives sortedAlbumItems.map(i=>({id:i.snapshot_id})) (complete collection). Existing History useMultiSelect return interface matches the fields above, and views consume these callbacks. Do not modify the existing useMultiSelect hook outside ownership. Reuse the new hook later in LoRA/TagSet cards. C1 History full-ID selection is confirmed by existing complete list query, not a new endpoint requirement.
