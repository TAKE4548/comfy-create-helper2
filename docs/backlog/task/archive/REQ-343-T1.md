# REQ-343-T1: バックエンド /api/workflows/scan のバリアント対応およびマッピング永続化の改修

## 1. 概要と目的
バックエンドの `/api/workflows/scan` エンドポイントが `scan_workflow_variants` を呼び出し、各ステージ・バリアント情報（`variant_id`, `stage_id`, `stage_key`）を含むマッチング結果を返却するようにする。
また、`WorkflowMappingCreate` および `WorkflowMappingRead` に `variant_id` を追加し、ワークフロー作成・更新・複製・ロールバック・取得時に `variant_id` を正確にDB永続化および復元・返却する。

## 2. ターゲット識別
- **対象ファイル**:
  - `backend/app/schemas/workflow.py`
  - `backend/app/routers/workflows.py`
  - `backend/tests/test_req343_workflow_variant_scan.py` (新規テスト)
- **対象シンボル**:
  - `ScanMatchedItem`, `ScanWarningItem`, `WorkflowMappingCreate`, `WorkflowMappingRead`
  - `scan_workflow_json`, `create_workflow`, `update_workflow`, `get_workflow`, `rollback_workflow`

## 4. 実装要件 (Implementation Logic)
- [ ] `backend/app/schemas/workflow.py`: `ScanMatchedItem`, `ScanWarningItem`, `WorkflowMappingCreate`, `WorkflowMappingRead` に `variant_id`, `stage_id`, `stage_key` を追加する。
- [ ] `backend/app/routers/workflows.py`:
  - `scan_workflow_json`: `MappingVariant` をクエリし、存在する場合は `scan_workflow_variants(payload.json_body, variants)` を実行する（フォールバックとして `scan_workflow`）。

  - `get_workflow`: `WorkflowMappingRead` 生成時に `variant_id=m.variant_id` および `role=(m.variant.computed_role if m.variant and m.variant.computed_role else (m.master.role if m.master else None))` を反映する。

  - `/api/workflows/scan` でステージキーワードに合致するノードが variant_id, stage_key 付きで返却されるテスト。
