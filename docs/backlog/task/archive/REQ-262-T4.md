## 3. 実装要件 (Implementation Logic)
- [x] `tools/server-manager/server-manager.ps1`:
  - `frontend/dist/index.html` の存在判定ヘルパーを定義。
  - `Start-AllServices`:
    - `frontend/dist/index.html` が存在する場合、`Start-FrontendProcess` の呼び出しおよび Port 5173 の待機を自動スキップし、「[3/3] Frontend is bundled into Backend (Port 8000) - Skipping dev server」を表示。
    - `frontend/dist/index.html` が存在しない場合は、従来通り Vite（Port 5173）を起動。
    - 既存の個別起動コマンド（`-Action start -Service frontend`）は変更せず、いつでも Vite を起動可能に維持。
  - `Get-StatusObject`:
    - Port 5173 が LISTEN の場合:
      - `status = "LISTEN"`, `name = "React FE (Dev: 5173)"`, `running = $true`
    - Port 5173 が停止しており `frontend/dist/index.html` が存在する場合:
      - `status = "BUNDLED"`, `name = "React FE (Bundled on 8000)"`, `running = $beRunning`（Backend稼働に連動）
    - いずれでもない場合:
      - `status = "STOPPED"`, `running = $false`
  - `Show-Status`:
    - `status == "BUNDLED"` の場合、緑色（Green）で表示し、正常扱いとする。
- [x] `tools/server-manager/server_api.py`:
  - `renderServices`:
    - `status == "BUNDLED"` の場合、バッジを緑色（`badge-running`）で描画。
    - カード内に「▶ Vite 起動（開発用）」ボタンを表示し、クリック時にいつでも `triggerAction('start', 'fe')` で Vite を個別起動できるようにする。
    - Vite 稼働中（`status == "LISTEN"`）は「⏹ Vite 停止」「🔄 再起動」ボタンを表示。

## 4. 検証手順 (AC)
- [x] AC-1: `frontend/dist/index.html` が存在する状態で `powershell -ExecutionPolicy Bypass -File tools/server-manager/server-manager.ps1 -Action status -Json` を実行し、Vite 未起動時に `fe.status` が `"BUNDLED"` であること。
- [x] AC-2: Web Manager 上で `React FE (Bundled on 8000)` が緑色バッジで表示され、起動ボタンから Vite が個別起動できること。
