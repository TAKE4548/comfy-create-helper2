## 3. 実装要件 (Implementation Logic)
1. **新規プリセット作成の同期・アトミック化 (全キャッシュ層連携)**:
   - `createPresetMutation.onSuccess` での個別の `setActiveSetId` および `setParamValues` 呼び出しを撤廃。
   - `loadPresetData(newPreset, defaultParams)` を呼び出し、Zustand の L2 (`sets`) への追加、`activeSetId` の切り替え、および L1 パラメータ展開を単一のアトミック更新で行う。
   - 既存の `autoSaveTimerRef.current` が存在すれば `clearTimeout` してリセット（直前プリセットのタイマー誤発火を遮断）。
   - L4 キャッシュ同期: `presetUpdatedAtRef.current[newPreset.id] = newPreset.updated_at` を即時登録。
   - L4 キャッシュ同期: `lastSavedStateRef.current[newPreset.id]` に初期保存状態を即時記録。
   - L3 クエリキャッシュ同期: React Query の `['workflow-presets', selectedWorkflowId]` キャッシュに `newPreset` を楽観的に追加（`qc.setQueryData`）した上で `invalidateQueries` を実行。
   - L5 ストレージ同期: `localStorage` の `activeSetId` および `openPresetIds` を即時保存。
2. **`updatePresetMutation` のパラメータ混入防止ガード**:
   - `updatePresetMutation.mutationFn` において、`args.id` が現在アクティブなプリセットでない場合、グローバルな `paramValues`（アクティブプリセットの値）へフォールバックすることを禁止。
   - `args.id` が非アクティブな場合は、`storeRef.current.sets` から該当プリセットのパラメータを取得するか、明示指定されたパラメータのみを送信する。
3. **`handleUpdatePreset` の安全性強化**:
   - `id` が `activeSetId` の場合は現在の設定値を使用し、`base_updated_at: presetUpdatedAtRef.current[id]` を付与して更新を呼び出す。
   - 非アクティブな `id` が渡された場合はストア内の該当プリセットのパラメータを送信する。
