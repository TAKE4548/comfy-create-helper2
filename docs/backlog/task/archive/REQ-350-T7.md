## Implementation Requirements

- handleGenerate/handleGenerateSets の両方で seedBatch.prepareSeedBatch を呼び、各item.seedsBySlotをinjectWorkflowParams.resolvedSeedsへ渡す。legacy seedOptions は現行のset別global値で維持する。
- 全対象セットのseed設定を凍結しvalidation後にrequestを構築、全検証完了まで setActiveBatch/setIsBatchSubmitting を更新せず submitGenerationBatch を呼ばない。捕捉エラーはset名/欄名と原因を既存toastへ表示してreturnする。
- 最初のgetLatestState直後にcurrentParamValues=cleanParams(freeze(state.paramValues))とし、sets/workflow/syncはdeep freeze-copyする。snapshot後のUI変更は次回の生成へ適用し、進行中要求はgraph/recordで当初の実使用値を確認できる。
- まず各セットのPrepareSeedBatchOptionsを凍結して一覧化し全件validateSeedBatchする。その後だけprepareSeedBatchで各itemを確定する二段階構築とする。
- applyParamSyncは専用seed roleを一般数値同期から除外（seedBatchでモードも含め同期する）。seed以外のparam syncは既存順序を保持。
- アクティブセットは画面のparamValues（metadata含む）を優先、他セットは自身のparamValuesを使う。batch indexは各セット0から。最初の送信待ち中に入力変更してもすべてのitemは凍結値のまま。
- item.param_values は ResolvedSeedItem.actualParamValues を基礎とし、buildGenerationRecord を実注入graph・最終graphから生成。基準Seedでなく実使用Seedを記録。history metadataも一致させる。
- AC-3/4/5/6、混在mode、random親子同期1抽選、global Seed非干渉、後続セットoverflowで全体送信ゼロ、runtime metadata破損・9枚以上拒否・既存idempotency replay時同request同graphをテストする。
