# REQ-380-T5: AC5のVRAM fallback反映期限を検証する

ユーザーは、REQ-380-T2の追加3回目の再作業としてAC-5の最大5秒以内反映期限をテストで証明する例外を明示承認した（2026-10-24、回答 `ok`）。この補助カードは、完了済みT2を再オープンせず、同一PBI・同一ACの承認範囲を試験1件だけで補完するための実行IDである。既定の最大2回再作業の履歴を隠したり、ACを拡張したりしない。

対象は既存の `frontend/src/pages/SettingsPage/components/__tests__/VramGuardSection.test.tsx` 一ファイルだけ。通常のWebSocket接続中のSYSTEM_STATSを維持し、WS断時のGET fallbackで次のサーバーVRAM測定値が最大5,000ms以内に画面へ反映されることを検証する。実GPU測定、物理解放完了、閾値/age判定、完了タイマーは追加しない。製品コードは変更しない。要件違反する製品動作を再現した場合のみ、修正案を報告して停止する。

- 実 `VramGuardSection`、TanStack Query、generation store、settings API/query関数を通し、外部HTTP/fetchだけをテストfixtureで制御する。内部業務関数のpatchで結果を製造しない。
- controlled clock/fake timersで `systemWsConnected=true` の間にfallback GETが実行されないことを確認する。
- WS断へ切り替え、fallback queryが現在値を返した後、次の2500ms設定pollで新しい実測fixture値を返す。前値のまま待つ時間と、次値へ反映する時間をcontrolled clockで測り、断検知から最大5000ms以内に次値（例: `vram_free_gb` 6→9）がUIに現れることをassertする。

- 2500msより前のpollを求めない。モデル提案の±50ms、30秒stale閾値、`STALE_DATA` code、低水準タイマーSLAを追加しない。
