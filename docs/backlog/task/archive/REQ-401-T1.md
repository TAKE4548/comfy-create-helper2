## 2. 現状コードスニペットと問題点

### 2.1 `backend/app/services/generation_service.py` L1285-L1295 (`_reconcile_locked`)
```python
            try:
                history = await self.bridge.history(prompt_id)
            except Exception:
                logger.debug("History lookup unavailable for %s", prompt_id, exc_info=True)
                continue
            record = history.get(prompt_id) if isinstance(history, dict) else None
```

**問題点**: prompt_id 保持ジョブが ComfyUI queue に不在かつ history 照会で空（record is None）の場合、何もしないで `continue` するため DB 上で `running`/`queued` のまま恒久残留する。

## 3. 実装契約

1. **Reconcile 消失検知 (`_reconcile_locked`)**:
   `record = history.get(prompt_id) if isinstance(history, dict) else None` の後、`if not isinstance(record, dict):` のブロックで：
   ```python
   self._mark_unconfirmed(job, "upstream execution completed or lost without recorded history")
   self._cancel_requested.discard(job.job_id)
   changed = True
   continue
   ```
   ※例外発生時の `except Exception:` では `continue`（保守的ガード）を維持し、誤検知を防ぐ。

2. **待機取消の DB 同期 (`cancel_queued`)**:
   `outcome="unconfirmed"` を返す2箇所（queue 照会エラー時、queue.pending 不在時）で：
   ```python
   self._mark_unconfirmed(job, "upstream queue unavailable or job missing from pending queue")
   publish = True
   ```
   を呼んでから `CancelResult` を返す。

3. **単件取消の DB 同期 (`_cancel_single`)**:
   `outcome="unconfirmed"` を返す2箇所（queue 照会エラー時、queue 不在時）で：
   ```python
   self._mark_unconfirmed(target, "upstream queue unavailable or job missing from upstream queue")
   ```
   を呼んで DB を `unconfirmed` に更新してから `CancelResult` を返す。

4. **WS 再接続最適化 (`on_event`)**:
   `on_event` 内で `event_type == "status"` または WS 再接続イベント時に `self._wake.set()` を呼び出し、再接続後の即時 reconcile を促進する。

## 4. テスト契約

- `backend/tests/integration/legacy/test_generation_service.py`:
  - `test_req401_ac1_reconcile_upstream_lost_job_transitions_to_unconfirmed_and_closes_normal_group`:
    - Given: prompt_id を持つ running/queued ジョブが存在し、上流 queue は空、history も空。
    - When: `_reconcile_locked` を実行。
    - Then: ジョブの status が `unconfirmed` に遷移し、後続の通常バッチ投入で新しい `normal_group_id` が払い出される。
  - `test_req401_ac2_single_and_queued_cancel_when_upstream_lost_transitions_to_unconfirmed`:
    - Given: prompt_id を持つ running ジョブが存在し、上流 queue に不在。
    - When: `cancel_queued` および `_cancel_single` を実行。
    - Then: 戻り値が `outcome="unconfirmed"` であり、かつ `job["status"] == "unconfirmed"` となる。
  - `test_req401_ac4_unconfirmed_transitioned_job_can_be_released`:
    - Given: 上記で `unconfirmed` になったジョブ。
    - When: `service.release_unconfirmed(...)` を実行。
    - Then: status が `released` に遷移し、`_unconfirmed_leftovers` からも除外される。
- `backend/tests/integration/legacy/test_generation_api.py`:
  - `test_req401_ac2_single_cancel_updates_db_status_to_unconfirmed`:
    - POST `/api/generation/jobs/{id}/cancel` を呼び、202 outcome='unconfirmed' とともに `repository.snapshot()` でジョブ status が `unconfirmed` であることを検証。
