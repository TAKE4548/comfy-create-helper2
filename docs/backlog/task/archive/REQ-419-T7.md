## 5. シナリオ仕様
専用ヘルパー `stubMasterEditApi(page)` をブロック内に定義し、状態を持つモック（配列を更新し GET に反映）を用意する:
- `GET /api/stage-masters` → main(id1, sort_order 1, suffix '') / rough(id2, sort_order 2, suffix '_rough')
- `GET /api/mapping-masters` → Master id 2 `steps`（variants: id21 main role `steps`、id22 rough role `steps_rough`、両方 `binding_rule_set_id: 5`、id21 `node_selector_id: null`、id22 `node_selector_id: 7`）
- `GET /api/binding-rules` → id5 `Steps RuleSet`（entries KSampler×steps priority1、`referenced_roles: ['steps','steps_rough','cfg_other']`）、id6 `Alt RuleSet`
- `GET /api/node-selectors` → id7 `Rough Selector`（patterns contains `rough`）
- `POST /api/mapping-masters/2/atomic-save` → 本文を記録し、要求どおりに状態（masters/rule sets/selectors）を更新して `MappingMasterV2` を返す（`rule_entries`/`selector_patterns` も更新）
- `/api/binding-rules*`・`/api/node-selectors*` への POST/PUT/DELETE と `PUT /api/mapping-masters/2` → 記録のみ（呼ばれたら失敗として扱う）
- `GET /api/workflows` → `[{id:1,name:'wf-e2e',...}]`
- `POST /api/mapping-masters/scan-preview` → 本文を記録し、client_key ごとに ok/duplicated/not_found の固定応答
記録した呼び出し列（method・path・本文。id/name の自動採番は正規化）を返す。

ケース（ケース名は必ず `[REQ-419/AC-11]` で始める）:
1. `[REQ-419/AC-11] [REQ-419/AC-12] 375px: master edit sheet supports variant switch, shared choice and preview`
   - `setViewportSize(375, 667)` → `/settings#workflows` → `MASTER_CARD` の `steps` 編集ボタン（name `/^Steps のマッピング設定を編集/`）をタップ。
   - dialog `/マッピングマスター編集/` がボトムシート（dialog の bottom が viewport 下端±2px、幅 ≥ 375-2）。
   - AC-3: Rough 行の NodeSelector select（`aria-label="Rough のNodeSelector"`）で「セレクタなし」を選ぶ。
   - AC-4/5: Rough 行で RuleSet 編集を開き Entry を1件追加 → 「マスターを保存」→ `role="alertdialog"` に `cfg_other` と `steps` が列挙され「共有定義を更新」「複製してこのVariantだけ変更」が見える。この時点で POST/PUT 記録が 0 件（atomic-save も未送信）。→「複製してこのVariantだけ変更」。
   - 記録: 保存操作で送信されたのは `POST /api/mapping-masters/2/atomic-save` の **1件のみ**。本文の `rule_sets` に `op: "create"`・名前 `Steps RuleSet (steps_rough)` があり、id5 の `op: "update"` が無い。`variants` の id22 は `rule_set: {ref: ...}`・`selector: null`、id21 は `rule_set: {id: 5}`。定義 API への POST/PUT は 0 件。
   - AC-9: シートを開き直し（またはそのまま）判定プレビューで `wf-e2e` を選び「プレビュー実行」→ 各 Variant 結果ブロックに段階ラベル・duplicated/not_found 警告が表示。
   - 操作した各要素（編集ボタン、select、編集・保存・選択・プレビュー実行ボタン）の有効タップ領域 ≥ 44×44（`box()` の width/height。Hit-Slop を使う要素は `getComputedStyle(el, '::before')` の inset を加味してよい）。
   - `document.documentElement.scrollWidth <= document.documentElement.clientWidth` を各操作後に確認。
2. `[REQ-419/AC-11] 1280px: same operations send the same requests`
   - 同じ手順を 1280px で行い、正規化した呼び出し列がケース1と一致（ケース1の列はテスト内で再取得して比較するか、両ケースを1つの `test` 内でビューポートを変えて2回実行してもよい）。ダイアログは中央配置（ボトムシートでない）。
