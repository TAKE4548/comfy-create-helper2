### REQ-164-T1: useGenerationStore の複数セッション WebSocket・履歴同期・起動復元の改修

#### 目的
他セッションから投入されたジョブの実行中ノード遷移（`executing`）や完了検知（`node: null`）、および `status` イベント受信時に `fetchHistory()` / `fetchQueue()` を適切に連動させ、全セッションの生成履歴・キュー状態がリアルタイムおよび起動・リロード時に確実に復元・同期されるようにする。

#### 対象ファイル
1. `frontend/src/store/useGenerationStore.ts`
2. `frontend/src/store/__tests/useGenerationStore.test.ts`

#### ストアアーキテクチャと完全な型定義 (Complete Context Types & Schemas)

本プロジェクトでは **Zustand (`create<GenerationState>((set, get) => ({ ... }))`)** を状態管理として採用しています。
`set` は Zustand の state 更新関数 (`(partial: Partial<GenerationState> | ((state: GenerationState) => Partial<GenerationState>)) => void`)、`get` は現在の state 参照関数 (`() => GenerationState`) です。

#### 実装指示 (Implementation Steps)

1. **WebSocket メッセージハンドリング (`useGenerationStore.ts`)**:
   - `case 'executing'`:
     ```typescript
     case 'executing': {
       const nodeId = data.node !== undefined ? (data.node as string | null) : null
       const promptId = data.prompt_id as string | undefined
       if (nodeId) {
         const nodeInfo = get().currentWorkflow?.[nodeId]
         const nodeName = nodeInfo
           ? (nodeInfo._meta?.title || nodeInfo.class_type || 'Unknown')
           : 'Unknown'
         
         const running = get().queueRunning
         const activeJob = running.length > 0 ? running[0] : null
         const jobClientId = activeJob?.[3]?.client_id || get().activeClientId

         set({
           isGenerating: true,
           currentPromptId: promptId || get().currentPromptId,
           activeClientId: jobClientId,
           currentNode: { id: nodeId, name: nodeName },
           nodeProgress: {
             value: 0,
             max: 100,
             percentage: 0,
             nodeId,
             nodeName,
           },
         })
       } else {
         // nodeId === null は 1 つのジョブの実行完了
         set({
           currentNode: null,
           nodeProgress: null,
         })
         get().fetchHistory()
         get().fetchQueue()
       }
       break
     }
     ```
   - `case 'status'`:
     ```typescript
     case 'status':
       get().fetchQueue()
       get().fetchHistory()
       break
     ```

2. **起動時整合性復元 (`reconcileState`)**:
   - 単一 `currentPromptId` が存在しても、その1件の画像取得で `return` せず、`/queue` と `/history` の全件ロード・同期を確実に実行する。
   - `reconcileState` の最後に `get().fetchHistory()` および `get().fetchQueue()` を呼出し、他端末で生成された履歴を漏れなく `comfyHistoryImages` に復元する。

3. **`fetchHistory()` のマージロジック**:
   - ComfyUI の `/history`（`comfyApi.getHistory()`）から取得した全画像は常に `comfyHistoryImages`（最新50件）にセット。
   - `filterOwnSession: false` の場合、`batchImages` にも `allImages` をマージして `localStorage.setItem(LS_KEYS.BATCH_IMAGES, JSON.stringify(mergedBatchImages))` を更新。
   - `filterOwnSession: true` の場合は `ownImages` をマージ。

4. **単体テスト作成 (`useGenerationStore.test.ts`)**:
   - **Test 1**: 他セッションのジョブ実行時、WS `executing`（`node: "3"`）を受信した際に `isGenerating: true`、`currentNode.id: "3"` が設定されること。
   - **Test 2**: 他セッションのジョブ完了時、WS `executing`（`node: null`）を受信した際に `fetchHistory` および `fetchQueue` が呼び出されること。
   - **Test 3**: `reconcileState` 実行時に ComfyUI の全セッション履歴が `comfyHistoryImages` にロードされること。
