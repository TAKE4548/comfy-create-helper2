# REQ-419-T10: 呼び出し側の候補定義・ステージ検出をVariant単位の3層定義へ切替

## 1. 目的
`UploadWorkflowModal`・`RescanModal`・`AdaptiveWorkflowWiring` の候補ランク付け入力を、Master 単位の旧列から **Variant 単位** の `candidateDefinitionForVariant(variant)` に切り替える。`WorkflowConnectionSection` のステージ検出を NodeSelector パターンに切り替える。担当 AC: AC-13（登録・リマッピング・配線画面の候補表示とステージ自動検出）、AC-1。

## 5. 変更箇所
### 5-1. `UploadWorkflowModal.tsx`（現 L37-56）
```tsx
  const candidateCache = useMemo(() => {
    const stages = masters.flatMap(master => 'variants' in master ? master.variants.map(v => v.stage_name) : [])
    const cache = new Map<string, ReturnType<typeof rankWorkflowNodeCandidates>>()
    for (const master of masters) {
      const v2 = 'base_key' in master ? master : undefined
      const variants = v2?.variants ?? []
      const definition = {
        expectedClassTypes: master.expected_class_types ?? [],
        titlePatterns: [...(v2?.base_title_patterns ?? master.title_patterns ?? []), ...variants.flatMap(v => v.extra_title_patterns ?? [])],
        paramNames: [master.param_name, ...(v2?.fallback_param_names ?? [])].filter((value): value is string => Boolean(value)),
      }
      const activeVariants = variants.filter(v => v.is_enabled !== false)
      const slots = activeVariants.length ? activeVariants.map(v => ({ key: `v_${v.id}`, stage: v.stage_name || 'Main' }))
        : variants.length ? variants.map(v => ({ key: `v_${v.id}`, stage: v.stage_name || 'Main' }))
          : [{ key: `v_${master.id}`, stage: 'Main' }]
      for (const slot of slots) cache.set(slot.key, rankWorkflowNodeCandidates(workflowJson, definition, slot.stage, stages))
```
変更: Master 単位の `definition` を削除し、slot ごとに対応 Variant の `candidateDefinitionForVariant(v)` を使う（Variant の無い slot は `candidateDefinitionForVariant(null)`）。slot の選び方・キー・`stages` は不変。
### 5-2. `RescanModal.tsx`（現 L46-60）
同じ形の `candidateCache` を同様に変更（slot キー `v_${v.id}` / `m_${master.id}` は不変）。**未割当スロットの保持ロジック（REQ-369／REQ-413 の禁止範囲）には触れない**。
### 5-3. `AdaptiveWorkflowWiring.tsx`（現 L84-99 `workflowNodesByRank`）
```tsx
      const master = mappingMasters.find((item) => item.id === slot.masterId)
      const expectedClassTypes = master?.expected_class_types ?? []
      const patterns = 'base_title_patterns' in (master ?? {}) ? ... : ...
      const fallbackParams = master && 'fallback_param_names' in master ? master.fallback_param_names ?? [] : []
      return [slot.slotKey, rankWorkflowNodeCandidates(workflow?.json_body, { expectedClassTypes, titlePatterns: [...], paramNames: [slot.paramName, ...fallbackParams].filter(Boolean) }, group.info.stage.name, stageNames)] as const
```
変更: `slot.variantId` に一致する Variant（`master.variants`）を探し、`candidateDefinitionForVariant(variant ?? null)` を渡す。旧列の読み取りを全て削除。
### 5-4. `WorkflowConnectionSection.tsx`（現 L222-227）
```tsx
    const masters = stageMasters.length > 0 ? stageMasters : [ { id: 1, key: 'main', ..., search_keywords: null, ... } as StageMaster ]
    const detected = detectActiveStages(configWorkflow?.json_body, masters)
```
変更: `detectActiveStages(configWorkflow?.json_body, masters, buildStageSelectorPatterns(mappingMasters as Array<{ variants?: MappingVariant[] }>))`。`useMemo` の依存配列に `mappingMasters` を追加。フォールバック StageMaster の `search_keywords: null` リテラルは型のため残してよい（検出には使われない）。必須ステージの補完ロジック（L227-238）は不変。

## 6. テスト
- `WorkflowModalMultiStage.test.tsx`: 新規 `[REQ-419/AC-13] [REQ-419/AC-1] upload and rescan rank candidates per variant from rule entries` — 同一 Master の main/rough Variant に異なる `rule_entries`/`selector_patterns` を与え、各 slot の推奨（tier 0〜1）ノードが Variant ごとに異なり、Master の `expected_class_types`/`title_patterns` だけに一致するノードは推奨にならない。
- `WorkflowModalMultiStage.test.tsx`: 新規 `[REQ-419/AC-13] upload rescan and wiring ignore legacy-only and keyword-only nodes`（(a)(b) を明示）: セレクタなし Variant で、(a) 旧列にだけ一致し Entry 不一致のノードは Upload・Rescan のどちらでも推奨グループに出ない。(b) Entry 一致でタイトルが search_keywords／旧 title_patterns にだけ一致するノードは、旧一致の無い同 Entry 一致ノードと同じ順位帯（推奨グループ外の class 候補）に並ぶ。`AdaptiveWorkflowWiring` でも同じことを `WorkflowAdaptiveStaging.test.tsx` で確認する。
- `WorkflowAdaptiveStaging.test.tsx` または `WorkflowConnectionSection.test.tsx`: 新規 `[REQ-419/AC-13] settings wiring shows stages detected by selector patterns` — (b) `search_keywords` にだけ一致するタイトルのノードしか無いステージは表示されず（必須ステージ補完の対象外の場合）、(a) 旧列にだけ一致するノードでステージが検出されない。selector パターンが一致するステージは表示される。
- 既存ケースの扱い: Master 旧列で推奨ノードを期待していたケースは、同等の `rule_entries`（class_type×param_name）と `selector_patterns`（exact/contains）を fixture に追加して意図を維持する。期待値の変更は「旧列だけに依存した推奨」が消える箇所に限り、変更したケース名と理由を完了報告に列挙する。`GeneratePage.test.tsx` は fixture 追記のみで通らなければ編集をやめて報告する。
