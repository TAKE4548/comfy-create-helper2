# REQ-333-T29: Generate接続設定popoverの上流正本表示

## Purpose and Ownership

端末localComfyUrl編集が通信先を変えたと誤認されないよう、BE COMFY_URL読取表示と設定systemへの導線に変更。既存workflow/default params/model操作を保持。旧store props signatureは移行中互換を保ち直接通信へ復活させない。

受入対応: AC-10/C3既存設定互換。設計レビュー承認後に実施。所有する変更対象は下記だけ（テスト/依存宣言込み）。他担当の変更を巻き戻さず、共通ファイル変更は調整役が直列化する。

## Hermetic Contract

旧挙動はURL inputのonChangeでsetLocalComfyUrl(value)とsetComfyUrl(value)を即呼出し、closeでsetIsSettingsOpen(false)を呼ぶ。改修後は上流URLをuseConfig().data.comfy_urlのread-only表示へ移し、URL callbackをmount/変更/closeで呼ばない。旧propsは型互換として受け取れるが保存/通信の副作用を起こさない。config未取得は「取得不可/読込み中」とし古いlocalComfyUrlをBE正本として表示しない。close、workflow/default params保存/reset/model操作のcallbackは従来通り。これはC3の明示アーキ差分であり、旧URL編集挙動を維持すると称さない。

以下は承認対象の新contract。scopeとproject、上流client IDと利用者sessionは別。clientから完了状態を送らない。
受付はDB commit後202。上流POST結果不明はunconfirmed、自動再送なし。BE再起動完全復元を追加しない。
通常Nはcancelled除外、F=succeeded+failed。Studio各batch独立。別scope待機優先、他session待機はfilter ONだけ。
snapshotはepoch/revisionでatomic置換、eventも同じ形の全状態dataを使い部分mergeを避ける。SYSTEM_STATS/VRAM_RECOVEREDのtype/data・2.5秒周期保持。
既存30local/1000server metadata、Snapshot独立、Studio750ms/draft競合、画像aspectを保持。
カード外ファイルや公開contract変更が必要なら設計へ差し戻す。
