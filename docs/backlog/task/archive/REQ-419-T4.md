# REQ-419-T4: 判定プレビューパネル（ScanPreviewPanel）

## 1. 目的
Master 編集画面内に置く、登録済みワークフローを1件選んで未保存の下書きで判定を実行し、Variant ごとの結果を表示するパネルを作る。保存系 API は呼ばない。担当 AC: AC-9（表示）、AC-10（UI 側の非永続）。

```ts
import { workflowsApi } from '../../api/domains/workflows'          // list(): Promise<WorkflowSummary[]>  ({id,name,created_at})
```

型の要点: `ScanPreviewVariantResult { client_key, variant_id, stage_id, stage_key, role, is_enabled, status: 'ok'|'duplicated'|'not_found'|'disabled', confirmed: ScanPreviewCandidate|null, candidates: ScanPreviewCandidate[] }`、`ScanPreviewCandidate { node_id, node_title, class_type, input_name, stage_rank, stage_label, entry_priority, pattern_priority }`。

## 5. コンポーネント契約
```tsx
export interface ScanPreviewPanelProps {
  /** 実行時点の下書きから要求を作る。null を返したら実行しない（例: 検証エラー）。 */
  buildRequest: (workflowId: number) => ScanPreviewRequest | null
  /** client_key -> 行の表示名（例: "Rough / steps_rough"） */
  rowLabels: Record<string, string>
  disabledReason?: string | null
}
export function ScanPreviewPanel(props: ScanPreviewPanelProps): JSX.Element
```
振る舞い:
- 見出し「判定プレビュー」、説明「保存前の内容で判定します。保存済みデータは変更しません。」。
- ワークフロー選択 `<select aria-label="プレビュー対象ワークフロー">`（`useQuery(['workflows'], workflowsApi.list)`）。0件なら select を無効化し「登録済みワークフローがありません」。
- 「プレビュー実行」ボタン。実行中は無効化し「判定中...」。`buildRequest` が null なら実行しない。
- 古い応答の破棄: 実行ごとに連番を振り、最新の連番以外の応答・エラーは捨てる。ワークフロー選択を変えたら表示中の結果をクリアする。
- 結果は `results` の順で Variant ごとに1ブロック（`data-testid="scan-preview-result-<client_key>"`）:
  - 見出し: `rowLabels[client_key]`（無ければ role）。
  - `status==='disabled'`: 「無効（判定対象外）」のみ。
  - `confirmed` あり: 確定ノードID、ノードタイトル、input_name、段階ラベル `STAGE_LABELS[confirmed.stage_label]`。
  - 警告バッジ: `duplicated` →「duplicated: 候補が複数あり確定できません」、`not_found` →「not_found: 候補がありません」。色だけで区別しない（テキスト必須）。
  - 候補一覧（`<ul>`）: 各候補の node_id・node_title・class_type・input_name・段階ラベル。0件なら「候補なし」。
- エラー: 失敗時は `role="alert"` で「プレビューに失敗しました（<要約>）」。404 は「ワークフローが見つかりません」。下書き（親の state）には触れない。
- 保存系（POST/PUT/DELETE で scan-preview 以外）を一切呼ばない。

## 6. UI 制約（Archetype 2: Tabs/Chips/Grids を内包する Generic パネル、モーダル内に配置）
<constraints>
- ボタン・select は `min-h-[44px] md:min-h-0 touch-manipulation`。小さいアイコン操作は `relative before:absolute before:-inset-2`。
- 段階・警告バッジは `shrink-0 whitespace-nowrap`。横並び行は `flex flex-wrap`、テキスト要素は `min-w-0`。
- node_id・role・警告文は `truncate` しない（折返し `break-all`/`break-words` を使う）。
- 文字サイズは 11px 未満にしない（`text-[11px]` 以上）。生の `vh` 禁止。パネル自身に固定高さ・内側スクロールを作らない（モーダル本文のスクロールに任せる）。
- グローバルセレクタでの font-size 変更禁止。
</constraints>

## 7. テスト（`ScanPreviewPanel.test.tsx`、`it('[REQ-419/AC-n] ...')`）
- `[REQ-419/AC-9] preview renders per-variant result with stage labels and warnings`: MSW 応答に ok(exact)、duplicated(no_selector, 候補2件)、not_found、disabled を含め、各表示を検証。
- `[REQ-419/AC-9] preview sends the unsaved draft`: `buildRequest` の戻り値と MSW で受けた本文が一致し、選択した workflow_id を含む。
- `[REQ-419/AC-9] preview failure keeps draft and ignores stale responses`: 500 と `HttpResponse.error()` でアラート表示。1回目を遅延させ2回目を先に返すと、1回目の結果が表示されない。
- `[REQ-419/AC-9] preview is disabled when no workflow is registered`
- `[REQ-419/AC-10] preview never calls persistence endpoints`: MSW の `request:start` で全リクエストを記録し、POST/PUT/DELETE は `/api/mapping-masters/scan-preview` のみ。
