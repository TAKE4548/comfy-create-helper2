## 4. 変更内容

### 4.1 `FakeMonitor`
- `configure_comfy_stats(self, provider: Any) -> None`（同期）: 受け取った provider を記録する（例: `self.comfy_stats_provider = provider` と、呼び出し履歴のリスト `self.configured.append(provider)`）。`__init__` で provider を `None`、履歴を空リストに初期化する。
- `async def sample_guard_status(self) -> dict[str, Any]`: `self.status` から導出し、本番 C5 の返却キーと互換の dict を返す。呼び出しのたびに `self.status` を読み直す（テストが途中で `status["vram_free_gb"]` を書き換えるため、値をキャッシュしない）。
  ```python
  status = dict(self.status)
  free = status.get("vram_free_gb")
  minimum = status.get("vram_min_free_gb")
  return {
      "vram_guard_enabled": status.get("vram_guard_enabled"),
      "vram_min_free_gb": minimum,
      "vram_free_gb": free,
      "vram_total_gb": status.get("vram_total_gb"),
      "vram_guard_free_gb": status.get("vram_guard_free_gb", free),
      "vram_own_residual_gb": status.get("vram_own_residual_gb"),
      "vram_hold_reason": status.get("vram_hold_reason"),
      "vram_measure_source": status.get("vram_measure_source"),
      "vram_safe": status.get("vram_safe", ...),  # 下記
  }
  ```
  - `vram_guard_free_gb` は `status` に明示値が無ければ `vram_free_gb` を既定値とする。これにより worker の `_is_vram_blocked` は従来どおり `vram_free_gb < vram_min_free_gb` で判定し、既存テストの挙動（初期値 free 1.0 < min 2.0 で保留、4.0 に上げると投入）が変わらない。
  - `vram_safe` は `status` に明示値があればそれを使う。無ければ、ガード無効なら `True`、`free` と `minimum` がともに数値なら `free >= minimum`、それ以外は `True` とする（本番 C1 と同じ等号側の規則）。
  - `vram_hold_reason` は既定 `None` でよい（worker は保留判定に使わず、10 秒警告ログの文言にだけ使う）。
- 既存の `status`、`started`、`stopped`、`broadcast`、`get_vram_status`、`start`、`stop` は変更しない。

### 4.2 `FakeBridge`
- `async def system_stats(self) -> dict[str, Any] | None`: `None` を返す（本番 C3 では「取得失敗」を表し、monitor はホストフォールバックになる。本ファイルの monitor は FakeMonitor なので値は使われない）。呼び出し回数を数える属性を追加してもよい。
- 理由: `main.py` L81 の `resource_monitor.configure_comfy_stats(bridge.system_stats)` は、引数の `bridge.system_stats` を評価する時点で属性が必要になる。FakeMonitor だけを直すと、次は `'FakeBridge' object has no attribute 'system_stats'` で同じ 13 件が ERROR になる。

### 4.3 待機上限の調整（`test_committed_work_continues_after_request_without_browser_connection`）
- T2 以降、`main.py` は `vram_recheck_seconds=1.0` を注入する。保留中のジョブは前回のプローブから 1.0 秒経過するまで再評価されない（worker のポーリング周期 `_POLL_SECONDS=0.2` が加わる）。現在の待機は `range(100)` × `time.sleep(0.01)` で約 1.0〜1.6 秒しかなく、投入が間に合わずに失敗する競合がある。
- 待機を時間ベースの上限 3.0 秒に変える（例: `deadline = time.monotonic() + 3.0` まで `time.sleep(0.01)` で `api["bridge"].submissions` を待つ）。`assert api["bridge"].submissions` 以降の assert は変更しない。
- この変更は待機上限の拡大だけで、テストの意味（ブラウザ接続なしでも受付済みジョブが投入される）は変わらない。

class FakeMonitor:
