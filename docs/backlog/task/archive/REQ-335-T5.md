### 3.3 同ファイル 新アクション（`clearPendingQueue` の後、`cancelAllJobs` の前か直後）
```ts
    releaseUnconfirmed: async (jobIds: string[]) => {
      // 上流の取消/中断は行わない。submission の abort もしない（解除は記録のみ）。
      const ids = Array.from(new Set(jobIds)).filter((id) => id.length > 0)
      const snapshot = get().generationSnapshot
      const merged: ReleaseOperation = { items: [], epoch: snapshot?.epoch ?? '', revision: snapshot?.revision ?? 0 }
      for (let index = 0; index < ids.length; index += 50) {
        const operation = await generationApi.releaseJobs({ job_ids: ids.slice(index, index + 50), session_id: get().clientId })
        merged.items.push(...operation.items)
        merged.epoch = operation.epoch
        merged.revision = operation.revision
      }
      await get().fetchQueue()
      return merged
    },
```
`import type { ... ReleaseOperation }` を既存の generation import（L5）に追加。

## 5. 追加するテスト
**`jobQueueSlice.test.ts`**
- `it('[REQ-335/AC-1] projectQueue does not place unconfirmed jobs in queuePending and exposes upstream items of unconfirmed prompts')`: `projectQueue`（import 可）に unconfirmed(prompt_id 有り)＋上流 pending 同 prompt を与え、pending に managed 行が無く外部項目が1件。released も同様。
- `it('[REQ-335/AC-2] cancelJob propagates unconfirmed outcome without treating it as success')`: `generationApi.cancelJob` が `{outcome:'unconfirmed'}` を返す → `cancelJob` の戻り値が同じで、`getState` 再取得後も当該 job が unconfirmed 集合に残る。
- `it('[REQ-335/AC-3] releaseUnconfirmed sends only given ids then refetches state')`: `releaseJobs` 呼出が重複除去済みIDのみ、`session_id=clientId`、`getState` が1回呼ばれる。空配列は API 非呼出。51件で2回に分割。
- `it('[REQ-335/AC-4] fetchQueue does not keep activeBatch open for an unconfirmed item')`: activeBatch に pending 項目＋unconfirmed 項目 → unconfirmed のみ残る状態で `activeBatch === null` かつ `isGenerating === false`。
- `it('[REQ-335/AC-5] unconfirmed that gains a prompt_id and becomes running moves from the unconfirmed list to the running queue')`: 連続2 snapshot（revision+1）で queueRunning に現れる。
**`connectionSlice.test.ts`**
- `it('[REQ-335/AC-1] unconfirmed-only snapshot yields isGenerating=false and no active prompt')`（`applyGenerationSnapshot` 経由）。
- `it('[REQ-335/AC-3] transition to released raises neither failure toast nor auto-follow image')`。
**`generationQueueSync.test.ts`**（既存 `makeJob`/`makeSnapshot`/`publishSnapshot` を再利用）
- `it('[REQ-335/AC-4] new generation proceeds while an unconfirmed record exists and queued clear does not touch it')`: snapshot に unconfirmed(prompt_id=null) と新規 queued→running→succeeded を流し、新規が完了表示（selectedImg 追従）まで進み、`clearPendingQueue()` 後も unconfirmed の status は不変。既存 Scenario 2 の偽 BE（`['queued','submitting','unconfirmed']`）は実 BE 仕様に合わせ `['queued','submitting']` へ更新してよい。
