## 3. 実装要件 (Implementation Logic)

### 3.1 バックエンド側
1. **`backend/app/schemas.py`の修正**:
   - `WorkflowMappingRead` の `role`, `param_name`, `input_type`, `display_name` フィールドを `Optional[str] = None` に変更します。
   - `WorkflowUpdate` スキーマをファイル末尾等に定義します。
2. **`backend/app/routers/workflows.py`の修正**:
   - `get_workflow` エンドポイントにおいて、`m.master` が `None` の場合に属性エラーにならないように、三項演算子等を使用して以下のように安全にマッピング情報を構築します。
     ```python
     role=m.master.role if m.master else None,
     param_name=m.master.param_name if m.master else None,
     input_type=m.master.input_type if m.master else None,
     display_name=m.master.display_name if m.master else None,
     ```
   - `PUT /api/workflows/{workflow_id}` エンドポイントを実装します。
     - 指定された `workflow_id` のワークフローが存在しない場合は `404 Not Found` エラーを返却します。
     - `payload.mappings` が提供された場合、該当ワークフローに紐づく既存の `WorkflowMapping` をすべて削除した上で、提供された新しいマッピングを追加（インサート）します。

### 3.2 フロントエンド API クライアント側
1. **`frontend/src/api/types.ts`の更新**:
   - `WorkflowMapping` の各プロパティを `string | null` に変更し、`WorkflowUpdate` 型を追加します。
2. **`frontend/src/api/client.ts`の更新**:
   - `workflowsApi` のオブジェクト内に `update: (id: number, data: unknown) => request(...)` メソッドを追加します。

### 3.3 フロントエンド UI 側
1. **`frontend/src/pages/GeneratePage.tsx`の更新**:
   - `mappingMastersApi.list()` を呼び出して、すべての `MappingMaster` 定義をロードします（`mappingMasters`）。
   - ロードした `workflow` の `mappings` から、有効なマッピング（`role !== null`）と無効なマッピング（`role === null`）をフィルタリングして分離します。
     ```typescript
     const validMappings = workflow?.mappings.filter((m) => m.role !== null && m.role !== undefined) ?? []
     const invalidMappings = workflow?.mappings.filter((m) => m.role === null || m.role === undefined) ?? []
     ```
   - パラメータ列（左カラム）の最上部、LLM Audit パネルの上などに、無効なマッピング（`invalidMappings.length > 0`）が検出された場合の警告 UI（Alert）を表示します。
   - 警告 UI 内で、エラーが発生している各ノード（`node_id`）について：
     - ノード ID と、そのノードが何であるか（クラス名やマスタ情報など）を表示します。
     - 正しいマッピング（Role）を選択するためのドロップダウン（`<select>`）を表示します。ドロップダウンの選択肢には `mappingMasters` のすべてのマスタ定義を表示します（例：`Character LoRA Model` 等）。
     - 各エラー項目に「修正する」ボタン（または警告UI全体の最下部に「マッピングを一括修正する」ボタン）を設置します。
     - ボタンクリック時、有効なマッピング情報の一覧と、ユーザーがドロップダウンで選択・紐付け直した新しいマッピング情報を合成した配列を構築し、`workflowsApi.update(selectedWorkflowId, { mappings: updatedMappings })` を呼び出します。
     - 更新完了時に React Query の `workflows` / `workflow` クエリデータを無効化（`invalidateQueries`）し、画面を自動更新します。これにより無効なマッピングがなくなり、入力欄が正しく動的生成されます。
