## Implementation and Acceptance

1. schemaへoptional属性とfield_validatorを追加する。json文字列はdecodeし、壊れたJSON/非配列はschema検証で拒否する。None/nullと[]は区別する。

2. routerのWorkflowMappingRead組立へeffective_masterのfallback_param_namesを渡す。primary/input_typeと同じmaster選択を使う。DB変更や他routerのsource変更は行わない。

3. 新規test_req353_seed_mapping_api.pyをmemory SQLite/TestClientで作成する。既存test_req350_seed_mapping_api.pyと同じget_db overrideを復元する。通常master・variant付きmapping、noise_seed配列順・null/[]・404、schema malformed値を検証する。

4. variant付きfixtureでは既存WorkflowMappingCreateのmaster_idとvariant_idをともに指定する。既存応答のmaster_id契約を変更しない。
