## 背景（確認済み）

`stubApi()` は `page.route` で HTTP の `/api/*` だけをスタブしている。`page.route` は WebSocket を捕捉しないため、アプリ（`frontend/src/store/services/systemWsService.ts:26`）の `ws://localhost:5173/api/ws` が Vite proxy（`ws: true`、target `http://127.0.0.1:8000`）経由で稼働中の実バックエンドへ届く。実データのスナップショットが HTTP スタブを上書きし、[REQ-372] AC-3/4/5/7 が失敗する。スクラッチ複製で `routeWebSocket` を 1 行足すと 8 件すべて PASS することを確認済み。

## 1. 変更箇所 A: stubApi（現状、81〜112 行付近）

```ts
// Stub only backend API calls (pathname starts with /api/); never Vite module requests like /src/api/*.
async function stubApi(page: Page, isEmpty = false): Promise<void> {
  await page.route((url) => url.pathname.startsWith('/api/'), async (route) => {
    const req = route.request()
    const path = new URL(req.url()).pathname.replace(/^\/api/, '')
    const json = (body: unknown) =>
      route.fulfill({ status: 200, contentType: 'application/json', body: JSON.stringify(body) })

    if (req.method() !== 'GET') return json({})
    if (path === '/workflows') return json(WORKFLOW_LIST)
    // ... (他の分岐は変更しない)
    return json([])
  })

  // Mock ComfyUI /view requests for generated images
  await page.route((url) => url.pathname === '/view', async (route) => {
    await route.fulfill({ /* 1x1 PNG（変更しない） */ })
  })
}
```

変更:
1. シグネチャを `async function stubApi(page: Page, isEmpty = false): Promise<string[]>` にする。
2. 関数の先頭（最初の `page.route` の前）に次を追加する:
   ```ts
   const wsUrls: string[] = []
   // Sever the app WebSocket: page.route does not intercept WebSockets, and the Vite proxy would
   // forward /api/ws to a live backend whose snapshot overrides the HTTP stub (REQ-395).
   await page.routeWebSocket((url) => url.pathname === '/api/ws', (ws) => {
     wsUrls.push(ws.url())
   })
   ```
   handler 内で `ws.connectToServer()` を呼ばないこと（呼ぶと実バックエンドへ中継される）。照合は pathname `/api/ws` の完全一致にする（Vite HMR の WS を捕捉しないため）。
3. 関数の末尾（`/view` の route の後）に `return wsUrls` を追加する。
4. HTTP スタブの分岐・`/view` のモックは 1 文字も変えない。
