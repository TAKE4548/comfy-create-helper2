### 2.1 BaseModel Table Schema Definition
```python
class BaseModel(Base):
    __tablename__ = "base_models"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String, nullable=False, unique=True)
    description: Mapped[Optional[str]] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)

class CheckpointMapping(Base):
    __tablename__ = "checkpoint_mappings"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    checkpoint_name: Mapped[str] = mapped_column(String, nullable=False, unique=True)
    base_model_id: Mapped[int] = mapped_column(ForeignKey("base_models.id", ondelete="CASCADE"), nullable=False)
    created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow)
    
    base_model: Mapped["BaseModel"] = relationship()
```

## 3. 実装要件 (Implementation Logic)

### T1: データベースマイグレーション
- `models.py` に `BaseModel`, `CheckpointMapping` および中間テーブルを追加。
- `Workflow` モデルに `target_base_model_id` カラムを追加。
- Alembic マイグレーションファイルを作成し、マイグレーション中にデフォルトベースモデル（"Illus", "Noob", "Anima"）をシードする。
- 既存のすべての LoRA レコードに対し、マイグレーション時に「Illus」ベースモデルとのリレーションを一括追加する。

### T2: Backend REST APIs
- `base_models.py` ルーターを作成し、`GET/POST/PUT/DELETE /api/base-models` を実装。
- `GET/POST/DELETE /api/checkpoint-mappings` エンドポイントを実装。
- `GET /api/comfy/checkpoints` エンドポイントを実装（ComfyUIの `/api/models/checkpoints` をフェッチ）。

### T3 & T4: LoRA / TagSet 複数紐づけとフィルタ
- Pydantic スキーマに `target_base_model_ids: list[int]` を追加。
- `loras.py`, `tag_sets.py` の一覧取得エンドポイントで `base_model_ids` クエリパラメータによる OR 絞り込みフィルタを実装。
- カード作成・更新時に中間テーブルを介してリレーションを永続化する。

### T5: ワークフローベースモデル＆自動判定
- ワークフローモデルに `target_base_model_id` を追加。
- `workflow_scanner.py` にチェックポイントローダー検知と、マッピングに基づく完全一致・部分一致によるベースモデル推定ロジックを追加。

### T6 & T7: フロントエンド UI の統合
- 設定画面に「ベースモデル設定」タブを追加し、CRUD・マッピング管理を実装。
- アセット（LoRA/タグセット）登録モーダルに対象ベースモデル選択チェックボックスを追加。
- 生成画面でのアセット追加モーダルにて、現在のアクティブワークフローのベースモデルでの自動フィルタリングを適用。
