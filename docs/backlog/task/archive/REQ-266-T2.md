## 1. 目的とスコープ
`connectionSlice` における接続初期化および再接続スケジューリングを刷新する：
1. **多重接続・死活ソケットの厳格判定**: `initialize(options?: { force?: boolean })` において `readyState` が OPEN / CONNECTING の既存ソケットを保護し、CLOSED / CLOSING または `force: true` 時に安全に再初期化する。
2. **統一された再接続スケジューラ**: `onClose` および `onError` の双方から呼び出される `scheduleReconnect()` を導入し、指数バックオフ遅延（`comfyWsService.getReconnectDelay()`）を適用する。
3. **接続成功時のリセット**: `onOpen` でリトライカウントをリセットし、キュー状態を即時照会する。

## 4. 実装要件・手順
1. **`types.ts` の型拡張**:
   - `ConnectionActions` の `initialize` を `(options?: { force?: boolean }) => void` に更新。
2. **`connectionSlice.ts` の `scheduleReconnect` 共通化**:
   - 再接続スケジュール関数を定義：
     ```ts
     const scheduleReconnect = () => {
       set({ isConnected: false });
       if (!comfyWsService.getReconnectTimer()) {
         const delay = comfyWsService.getReconnectDelay();
         comfyWsService.incrementRetryCount();
         const timer = setTimeout(() => {
           comfyWsService.setReconnectTimer(null);
           get().initialize();
         }, delay);
         comfyWsService.setReconnectTimer(timer);
       }
     };
     ```
   - `onClose`: `scheduleReconnect()` を呼び出す。
   - `onError`: `scheduleReconnect()` を呼び出す。
   - `onOpen`: `comfyWsService.resetRetryCount()` を呼び出し、リトライ間隔を初期化。
3. **`initialize` ガードの改善**:
   - 引数 `options?: { force?: boolean }` を受け付ける。
   - `options?.force` が指定された場合は `comfyWsService.disconnect()` を実行して既存ソケットを切断・破棄。
   - 非 force 時は `comfyWsService.getIsInitializing()` チェックに加え、既存ソケットの `readyState` が `WebSocket.OPEN` または `WebSocket.CONNECTING` の場合のみ early return する。
