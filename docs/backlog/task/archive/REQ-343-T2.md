# REQ-343-T2: フロントエンド型定義の更新および設定画面（WorkflowConnectionSection）のバリアント配線整合

## 1. 概要と目的
フロントエンドのAPI型定義（`WorkflowMapping`, `WorkflowCreate`, `WorkflowUpdate`, `ScanMatchedItem`, `ScanWarningItem`）に `variant_id` を反映する。
さらに、`WorkflowConnectionSection.tsx` の設定検証関数 `validateConfig` で同一 `master_id` の複数バリアント共存を許容し、配線保存・JSONエクスポート/インポート時に `variant_id` が破棄されず正しく保持されるようにする。

## 2. ターゲット識別
- **対象ファイル**:
  - `frontend/src/api/types.ts`
  - `frontend/src/pages/SettingsPage/components/WorkflowConnectionSection.tsx`
  - `frontend/src/pages/SettingsPage/components/__tests__/WorkflowConnectionSection.config.test.ts` (新規テスト)
- **対象シンボル**:
  - `WorkflowMapping`, `WorkflowCreate`, `WorkflowUpdate`, `ScanMatchedItem`, `ScanWarningItem`
  - `validateConfig`, `handleSaveLinks`, `saveWorkflowConfig`, `setConfigMappings`

function validateConfig(value: unknown, masterIds: number[], modelIds: number[]): ConfigDraft {
  if (!record(value) || value.format !== 'prompt-surgeon-workflow-config' || value.version !== 1) throw new Error('形式またはバージョンが正しくありません')
  if (typeof value.name !== 'string' || !record(value.json_body) || !graphNodeIds(value.json_body).length || !Array.isArray(value.mappings)) throw new Error('ワークフロー名・グラフ・対応付けが不正です')
  const nodes = graphNodeIds(value.json_body)
  const seen = new Set<string>()
  const mappings = value.mappings.map((m: any) => {
    if (!record(m) || !Number.isInteger(m.master_id) || m.master_id <= 0 || !masterIds.includes(m.master_id) || typeof m.node_id !== 'string' || !nodes.includes(m.node_id)) throw new Error('対応付けのマスターID・ノードIDが不正です')
    const key = m.variant_id ? `${m.master_id}_${m.variant_id}` : `${m.master_id}`
    if (seen.has(key)) throw new Error('対応付けが重複しています')
    seen.add(key)
    return { master_id: m.master_id, node_id: m.node_id, variant_id: m.variant_id ?? null }
  })

## 4. 実装要件 (Implementation Logic)
- [ ] `frontend/src/api/types.ts`: `WorkflowMapping`, `WorkflowCreate`, `WorkflowUpdate`, `ScanMatchedItem`, `ScanWarningItem` に `variant_id` を追加する。
- [ ] `frontend/src/pages/SettingsPage/components/WorkflowConnectionSection.tsx`:
  - `ConfigDraft` の `mappings` 要素に `variant_id?: number | null` を定義。
  - `validateConfig`: 重複判定を `seenKey = m.variant_id ? `${m.master_id}_${m.variant_id}` : `${m.master_id}`` に変更し、同一 `master_id` で異なる `variant_id` を許容する。
  - `handleSaveLinks`: `mappingsToSave.map(m => ({ master_id: m.master_id, node_id: m.node_id, variant_id: m.variant_id }))` として `variant_id` を維持。
  - `setConfigMappings`（L155およびL623）: `configWorkflow.mappings` や `onChangeMappings` から `variant_id` を欠落させず設定。
  - エクスポートJSON・インポートプレビューで `variant_id` を正しく保持。
- [ ] `frontend/src/pages/SettingsPage/components/__tests__/WorkflowConnectionSection.config.test.ts`:
  - 同一 `master_id` で異なる `variant_id` を持つマッピングが `validateConfig` をPASSすることの検証。
  - 同一 `variant_id` の重複時はエラーとなることの検証。
  - レガシー（`variant_id` なし）JSONも正常にPASSすることの検証。
