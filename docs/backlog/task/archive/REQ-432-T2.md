# REQ-432-T2: 生成 worker の判定直前 VRAM プローブと結線

## 1. 概要と目的
生成 worker が ComfyUI へ投入する直前の VRAM 判定を、2.5 秒周期のキャッシュ値（`resource_monitor.get_vram_status`）から、判定のたびに新規に取得する非同期プローブ（`resource_monitor.sample_guard_status`）へ切り替える。判定では自セッション残留を除いた判定用空き（`vram_guard_free_gb`）を使う。保留理由をログで区別し、`main.py` で T1 の API を結線する。

### C6（本カードで実装）
```python
def __init__(
    self,
    repository: RequestRepositoryPort,
    bridge: LiveBridgePort,
    clock: Callable[[], Any],
    vram_status: Callable[[], dict[str, Any]],
    publish: Callable[[dict[str, Any]], Any] | None,
    *,
    ref_image_supplier: RefImageSupplier | None = None,
    vram_probe: Callable[[], Awaitable[dict[str, Any]]] | None = None,
    vram_recheck_seconds: float = 0.0,
) -> None: ...
```
- **判定値の取得**: `vram_probe` があれば `await self.vram_probe()`、なければ従来どおり `self.vram_status()`。例外時は従来どおり warning ログを出して `{}`（保留しない）。`Awaitable` は `collections.abc` または `typing` から import する。
- **再評価間隔**: 同一ジョブが保留中（`_vram_wait_started` に存在）で、前回判定から `vram_recheck_seconds` 未満であれば、プローブを呼ばずに `continue` する。間隔の計測には `asyncio.get_running_loop().time()`（単調時計）を使い、`self.clock` は使わない（テストの固定 clock の影響を受けないため）。初回判定は即時。`vram_recheck_seconds=0.0`（既定）では毎ループ判定する（既存テストの 0.25〜0.35 秒の期待を維持）。前回判定時刻は既存の `_vram_wait_started.pop(...)` がある全箇所（L291 付近、L317 付近、L460 付近、L726 付近）で一緒に破棄する。
- **`_is_vram_blocked(status)`**: ガード無効 → False。`vram_guard_free_gb` が数値（bool を除く）ならそれを、そうでなければ `vram_free_gb` を `vram_min_free_gb` と比較し、`free < minimum` で True。数値が欠ければ False。
- **10 秒警告ログ**: `logger.warning("Generation %s is waiting for the configured VRAM threshold (reason=%s, guard_free_gb=%s, min_free_gb=%s, source=%s)", ...)`。`vram_hold_reason` が無い場合（従来形式の status）は `reason=unattributed` とする。
- **`main.py`**: `bridge` 生成後に `resource_monitor.configure_comfy_stats(bridge.system_stats)` を呼ぶ。`GenerationService(..., vram_status=resource_monitor.get_vram_status, publish=..., vram_probe=resource_monitor.sample_guard_status, vram_recheck_seconds=1.0)` とする。シャットダウン時に `resource_monitor.configure_comfy_stats(None)` を呼ぶ（bridge 停止後に古い bridge を参照しないため。既存の finally 節の中で bridge.stop の前後どちらでもよい）。

## 5. 現行コード抜粋

### `generation_service.py` L712-L727
```python
                try:
                    status = self.vram_status()
                except Exception:
                    logger.warning("VRAM status is unavailable; the generation guard cannot block submission", exc_info=True)
                    status = {}
                if self._is_vram_blocked(status):
                    now_seconds = self._clock_seconds()
                    started = self._vram_wait_started.setdefault(item.job_id, now_seconds)
                    if now_seconds - started >= 10.0 and item.job_id not in self._vram_warned:
                        logger.warning("Generation %s is waiting for the configured VRAM threshold", item.job_id)
                        self._vram_warned.add(item.job_id)
                    continue
                self._pending.popleft()
                self._pending_ids.discard(item.job_id)

                self._vram_warned.discard(item.job_id)
```

### `generation_service.py` L1602-L1609
```python
    def _is_vram_blocked(self, status: dict[str, Any]) -> bool:
        if not status.get("vram_guard_enabled"):
            return False
        free = status.get("vram_free_gb")
        minimum = status.get("vram_min_free_gb")
        if isinstance(free, (int, float)) and isinstance(minimum, (int, float)):
            return free < minimum
        return False
```

## 6. テストケース（`test_generation_service.py` へ追記）
各テストに `@pytest.mark.asyncio`、`@getattr(pytest.mark, "REQ-432")`、`@getattr(pytest.mark, "AC-n")` を付け、docstring 先頭を `[REQ-432/AC-n]` にする。`MemoryRepository`、`FakeBridge`、`_payload`、`_wait_until` を再利用する。probe は status dict を返す async 関数（呼び出し回数と時刻を記録）とする。

- AC1-I-2 `test_own_residual_only_does_not_hold_dispatch`: probe=`{"vram_guard_enabled": True, "vram_min_free_gb": 6.0, "vram_free_gb": 5.3, "vram_guard_free_gb": 13.5, "vram_hold_reason": None, "vram_measure_source": "comfyui", "vram_safe": True}` → 1 秒以内に `bridge.submissions` が 1 件。
- AC1-S-1 `test_consecutive_generations_with_resident_model_never_wait`: job1 投入・完了後（既存テストの完了手順を流用）、同じ残留 probe のまま job2 を受け付け、job2 が投入され、`service._vram_wait_started` に job2 が残らない。
- AC2-I-3 `test_external_hold_logs_reason_and_remains_cancellable`: probe=`{..., "vram_free_gb": 2.0, "vram_guard_free_gb": 2.5, "vram_hold_reason": "external", "vram_safe": False}`、clock は可変（受付後に 11 秒進める）→ submissions 0、`caplog` に `reason=external` を含む警告 1 件、`cancel(job_id)` が `cancelled` で上流 POST 0。
- AC4-I-3 `test_dispatch_uses_probe_value_at_decision_time`: `vram_status` は保留値（`vram_free_gb=1.0, min=2.0`）、probe は安全値 → 投入される。同期 `vram_status` の呼び出し回数が 0。
- AC4-I-4 `test_held_job_rechecks_fresh_probe_at_bounded_interval`: `vram_recheck_seconds=0.3`、probe は保留値を返し続ける。約 1.0 秒間の probe 呼び出し間隔が全て 0.3 秒以上（許容誤差 0.05 秒）。その後 probe を安全値へ切り替えると、次の再評価で投入され、さらに 0.5 秒待っても submissions は 1 件のまま。
- AC4-I-5 `test_probe_failure_does_not_block_dispatch`: probe が `RuntimeError` を送出 → 投入される（従来の判定不能方針）、warning ログ 1 件以上。

モック禁止: `_is_vram_blocked`、`_run_worker`、`_clock_seconds` のパッチ。差し替えは probe・`vram_status`・`FakeBridge`・`MemoryRepository`（既存の注入点）のみとする。
