# REQ-345-T19 baseline確認済みページのfocusでfull history GETを抑止する

## Ownership and Atomicity

Write only the listed hook and its residual test file, with at most 100 changed lines total. Preserve other shared edits.

## Failure Evidence

After T18, the user reloaded. `tools/server-manager/logs/backend.log` still records `/api/comfy/history` full-fetch requests at 05:03:50.566, 05:03:53.126 upstream, and 05:03:56.519 upstream; a residual POST returned 200 at 05:03:53.660. This middleware log aggregates requests and cannot correlate them to one browser tab, but confirms full-history fetches remain during the same live verification window.

## Implementation Contract

- Track on the shared residual record whether a nonempty displayed baseline was observed after Query restoration.
- Once a nonempty baseline is observed, never call `store.fetchHistory()` from the focus/visibility refresh handler during that document lifetime. Continue queue refresh. Residual sync remains responsible for reconciling that baseline.
- If no displayed baseline exists, preserve the existing focus-triggered full history fetch so a fresh/empty page can populate its initial history.
- Preserve T18's waiting/checking suppression and do not change residual request, merge, or retry semantics.
- Tests: with a persisted baseline, dispatch focus/visibility before and after residual completion and assert zero history fetches plus queue refresh; without a baseline, assert the terminal-state focus path still fetches history.
