### REQ-163-T1: バックエンド: WorkflowPresetのupdated_at管理と楽観的ロック（OCC）の実装

#### 目的
`WorkflowPreset` モデルに `updated_at` タイムスタンプを追加し、`PUT /api/workflow-presets/{id}` での楽観的並行性制御（OCC）によって、他セッションで先行更新されたレコードへの古いデータによる上書きを `409 Conflict` で防止する。

#### 対象ファイル
1. `backend/app/models.py`
2. `backend/app/schemas/preset.py`
3. `backend/app/routers/presets.py`
4. `backend/app/main.py`

#### 実装仕様詳細

1. **`backend/app/models.py`**:
   - `WorkflowPreset` クラスに `updated_at` カラムを追加:
     ```python
     updated_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
     ```

2. **`backend/app/schemas/preset.py`**:
   - `WorkflowPresetRead`: `updated_at: datetime` を追加。
   - `WorkflowPresetUpdate`: `base_updated_at: Optional[datetime] = None` を追加。

3. **`backend/app/routers/presets.py`**:
   - `_preset_to_schema`: `updated_at=preset.updated_at or preset.created_at` を設定。
   - `update_preset`:
     ```python
     if payload.base_updated_at is not None and preset.updated_at is not None:
         # タイムスタンプ比較（DBの方が新しい場合は409 Conflict）
         if preset.updated_at > payload.base_updated_at:
             raise HTTPException(
                 status_code=status.HTTP_409_CONFLICT,
                 detail="Preset was updated by another session. Please reload to get the latest changes."
             )
     ```
     更新時に `preset.updated_at = datetime.utcnow()` を明示更新。

4. **`backend/app/main.py`**:
   - `run_migrations()` に `workflow_presets` の `updated_at` カラム追加処理を実装。

#### 完了条件
- `PUT /api/workflow-presets/{id}` が古い `base_updated_at` による更新を `409 Conflict` でブロックし、正常更新時は新しい `updated_at` を返却すること。
