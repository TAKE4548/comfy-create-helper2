## Hermetic Contract

以下は承認対象の新contract。scopeとproject、上流client IDと利用者sessionは別。clientから完了状態を送らない。
受付はDB commit後202。上流POST結果不明はunconfirmed、自動再送なし。BE再起動完全復元を追加しない。
通常Nはcancelled除外、F=succeeded+failed。Studio各batch独立。別scope待機優先、他session待機はfilter ONだけ。
snapshotはepoch/revisionでatomic置換、eventも同じ形の全状態dataを使い部分mergeを避ける。SYSTEM_STATS/VRAM_RECOVEREDのtype/data・2.5秒周期保持。
既存30local/1000server metadata、Snapshot独立、Studio750ms/draft競合、画像aspectを保持。
カード外ファイルや公開contract変更が必要なら設計へ差し戻す。

## Local Verification

受入状態表（設計具体化、旧ラベルを追加しない）:

| 前提 | 総合ラベル |
|---|---|
| Supervisor/本体/Comfy稼働、端末接続と生成基盤応答正常 | READY |
| Comfy起動準備中、又は端末接続再試行中 | CONNECTING |
| Supervisor/本体稼働、Comfy TCP稼働、HTTP応答失敗が30秒超連続 | STUCK |
| Supervisor/本体稼働、Comfy停止 | STOPPED |
| 本体/Comfy接続正常、Supervisorのみ停止 | OFFLINE |

優先順: initial managerLoading→CONNECTING、確認済Manager unavailable→OFFLINE、
manager欠落/be.running=false→CONNECTING、comfy/backend/beのstart/restart/reboot-service進行中→CONNECTING、
known comfy.running=false→STOPPED、comfy稼働+http_ready=false+valid failure_since>30秒→STUCK、
reconnecting又はupstream欠落/HTTP不通/WS不通→CONNECTING、残りREADY。
30秒ちょうどはCONNECTING。devFE running/statusとdevFE actionは配布版READYへ影響させない。
reconnectingはbackend generationSyncing（初期化/切断/再同期）であり、devFEではない。
PageHeaderはinitial refetch settlementをlocalに持ちmanagerLoadingを渡せる。共有T13 refetchが重複を抑える。
本体8000停止時の新規画面表示は保証しない。8899既存FEで復旧する。

状態表5行、30秒境界/reset、devFE切替、Manager downで生成可、進捗が止まるだけでSTUCKなし。
