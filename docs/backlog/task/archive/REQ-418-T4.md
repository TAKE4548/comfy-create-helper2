# REQ-418-T4: スナップショット保存の variant_id 化と旧 role キー復元リゾルバ

Subsystem: backend (API / service). Role: engineer. This Card is the sole semantic specification for the task. Run commands from `repo root`. Prerequisite: T1 (`variant_keys`, `VariantRef`).

### 1. Purpose and scope

Snapshots store `params` as a JSON string in `snapshots.params`. On save/update, convert parameter keys to `v:<variant_id>[:sub]` (plus reserved keys `__*`). On read/list, resolve stored `v:` keys and legacy `role` keys back to the current `role` via `expand_stored_params`, logging a `logger.warning` and omitting any unresolvable key so the frontend leaves unmapped form fields unset (AC-2, AC-4). (Note: AC-1 preset migration is in REQ-418-T2; AC-3 sync groups and AC-4 preset/sync-group list APIs are in REQ-418-T3, REQ-418-T5, and REQ-418-T6.)

Completion: `schemas/snapshot.py`, `services/snapshot_service.py`, `routers/snapshots.py` updated; all AC-2 tests in section 5 pass; existing snapshot tests pass.

Wire contract (C3): `SnapshotRead` and `SnapshotSummary` gain `variant_params: dict[str, Any] = {}` (`v:`-prefixed entries of `variant_keyed`, excluding `__*` keys) and `variants: list[VariantRef] = []` (variants referenced by this snapshot, with latest `role` and `master.display_name`). `params` remains keyed by the current `role` (+ derived keys + reserved keys).

### 4. Implementation logic

- [ ] **Write path (`SnapshotService.create_snapshot` and `update_snapshot`)**:
  - In `create_snapshot`: build `index = VariantIndex.from_session(db)`; call `storage_dict, unresolved = to_storage_params(index, payload.params or {})`. If `unresolved` is non-empty, log `logger.warning("snapshot create: unresolvable parameter keys skipped: %s", unresolved)`. Store `params=json.dumps(storage_dict, ensure_ascii=False)`.
  - In `update_snapshot`: when `payload.params is not None`, normalize via `to_storage_params(index, payload.params)`, warn if `unresolved` is non-empty (include `snapshot_id`), and set `s.params = json.dumps(storage_dict, ensure_ascii=False)` (preserving `ASSOCIATIONS_KEY` if `payload.lora_trigger_sets` was updated in the same call).
- [ ] **Read path (`routers/snapshots.py`: `list_snapshots`, `get_snapshot`, `create_snapshot`)**:
  - Build `VariantIndex.from_session(db)` once per request, and batch-load `MappingVariant` (with `master`) for referenced variant IDs to build `VariantRef(id=v.id, role=v.role, display_name=v.master.display_name if v.master else None)`.
  - For each snapshot `s`: parse `raw = json.loads(s.params) if s.params else {}` (tolerate invalid/non-dict as `{}`). Call `expanded = expand_stored_params(index, raw, owner_label=f"snapshot {s.id}", warn=True)`.
  - Set `params = expanded.role_keyed` (`None` on `SnapshotSummary` only if `s.params` is empty/None), `variant_params = {k: v for k, v in expanded.variant_keyed.items() if not k.startswith("__")}`, and `variants` for the referenced variant IDs. Unresolvable keys emit `logger.warning` and are omitted from `params` so unmapped form fields remain unset (AC-2).
- [ ] **Existing tests in owned files**: In `test_snapshots.py` and `test_snapshot_service.py`, seed matching `MappingVariant` rows where existing tests assert non-reserved `params` keys.
