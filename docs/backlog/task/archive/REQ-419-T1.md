### 4-3. 新関数 `scan_master_variants_detailed`
`scan_workflow_variants`（現 L460-568）の Master グループ処理を抽出した関数を追加し、`scan_workflow_variants` はこれを使って**従来と同一の戻り値**（`matched`/`warnings` の各 dict キー・値・順序）を組み立てる。
```python
STATUS_DISABLED = "disabled"

def scan_master_variants_detailed(workflow_json: dict, mapping_variants: list) -> list[dict]:
    """Return one result per input variant (including disabled ones).

    Keys: variant (the input object), status ('ok'|'duplicated'|'not_found'|'disabled'),
    confirmed (candidate dict or None), candidates (list of candidate dicts sorted by
    _candidate_sort_key after excluding nodes confirmed by earlier variants of the same master).
    Candidate dict keys: node_id, numeric_id, stage_rank, entry_priority, pattern_priority,
    input_name, node_title, class_type. stage_rank 4 never appears.
    Order: grouped by master in first-seen order; within a master by _variant_stage_sort_key;
    disabled variants are placed by the same key with status 'disabled' and do not consume nodes.
    """
```
- 有効 Variant の処理は既存ロジック（`_evaluate_candidate_stages`、`confirmed_nodes`/`confirmed_pairs` による除外、`_candidate_sort_key`、先頭段階の候補が2件以上で `duplicated`）をそのまま使う。`duplicated` でも `confirmed` は先頭候補。
- `workflow_json` が dict でない場合は全 Variant を `not_found`（無効は `disabled`）とし例外を出さない。
- `scan_workflow_variants` 側: `status=="disabled"` は出力しない。Master グループの出力順は従来どおり「有効 Variant の初出順」とする（無効 Variant の位置でグループ順が変わらないこと）。`not_found` は従来の warning dict、`ok`/`duplicated` は従来の matched dict（`status: "ok"`、`node_ids` は候補 node_id 一覧）＋ `duplicated` のとき従来どおり warning を先に追加。role 解決ロジック（`role` → `computed_role` → override → base_key+suffix）は共通ヘルパーへ移して両関数で使う。
