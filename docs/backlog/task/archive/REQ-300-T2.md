### REQ-300-T2: デスクトップ全幅タブバーおよび左ペイン操作ボタンの単体・統合・Red Teamテスト実装

- **Status**: done
- **Subsystem**: frontend
- **Depends On**: [`REQ-300-T1`]
- **Impacted Files**:
  - `frontend/src/pages/GeneratePage/components/__tests__/DesktopLayout.tabs.test.tsx`

#### Context & Purpose
REQ-300 で再構成されたデスクトップレイアウトの全幅プリセットタブバー、左ペインツールバー（Add Set、管理、Undo/Redo）、および Red Team 境界値（空プリセット、多数タブ、タブ削除）を包括的に検証するテストを作成する。

#### Verification Specifications
1. **AC-1 / Layout Hierarchy**:
   - `DesktopLayout` をレンダリングし、`#desktop-preset-tabs-bar` が存在すること、およびその親階層が左右2ペイン（`ResizableSplitLayout`）の上位にあることを検証。
2. **AC-2 / Multiple Presets**:
   - 複数プリセット（3つ以上）が登録されている状態で、全タブが `#desktop-preset-tabs-bar` 内に描画され、`overflow-x-auto` クラスを持つコンテナ内に収まっていることを検証。
3. **AC-3 / Left Pane Toolbar**:
   - `#add-set-btn` と `#manage-presets-btn` が `#left-pane-toolbar` 内に配置されていること、およびクリック時に所定のモーダル表示コールバック／状態更新がトリガーされることを検証。
4. **AC-4 / Interactions**:
   - タブクリックで `handleSelectPresetTab` が発火し、アクティブスタイルが適用されること。
   - チェックボックス切り替え、タブ削除（✕ボタン）、Undo/Redo ボタンのクリックが正常に動作すること。
5. **Red Team Boundary Cases**:
   - プリセットが 0 件または `activeSet` が null の場合でもクラッシュせず `#left-pane-toolbar` が描画されること。

cd frontend; npx vitest run src/pages/GeneratePage/components/__tests__/DesktopLayout.tabs.test.tsx
