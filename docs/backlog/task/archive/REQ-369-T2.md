# REQ-369-T2: フロントエンド useMasterMappingRows の孤立マッピング除外と既存ワークフロー未割当スロット保持

## 1. 概要と目的
- `useMasterMappingRows` において、現行の `allDefinitions`（有効・無効すべての実在マスタ/バリアント定義）に存在しない削除済み `master_id` や不整合 `variant_id` の孤立マッピングを初期化時・`getMappings` 出力時の双方で除外し、実在する無効バリアント/マスタのマッピングのみを保持する（`AC-1`）。
- 既存の有効なマッピングが存在するワークフロー（`savedMappings.length > 0`）を `initFromScan` で初期化する際、未割当のスロットに `scanDefaults` を自動セットせず空文字（`''`）のまま維持する。一方、新規ワークフロー登録時（`savedMappings.length === 0`）は従来通り `scanDefaults` で自動初期化する（`AC-2`, `AC-3`）。

## 2. ターゲット識別

## 4. 実装要件 (Implementation Logic)
- [ ] `frontend/src/hooks/useMasterMappingRows.ts` に以下のヘルパー関数を定義する：
  ```typescript
  const isValidSavedMapping = (mapping: SlotMapping, definitions: readonly SlotDefinition[]): boolean => {
    if (mapping.variant_id != null) {
      return definitions.some(d => d.masterId === mapping.master_id && d.variantId === mapping.variant_id)
    }
    const resolvedKey = mappingSlotKey(mapping, definitions)
    return definitions.some(d => canonicalSlotKey(d.masterId, d.variantId) === resolvedKey && d.masterId === mapping.master_id)
  }
  ```
- [ ] `useMasterMappingRows` 内で：
  - `const saved = useMemo(() => storedMappings.current.filter(m => isValidSavedMapping(m, allDefinitions)), [storedMappings.current, allDefinitions])` のように `allDefinitions` で有効性が確認されたマッピングのみを参照する。
  - `initFromScan` 内で `const rawSavedMappings = existingMappings ?? options.existingMappings ?? []` から `const savedMappings = rawSavedMappings.filter(m => isValidSavedMapping(m, allDefinitions))` を作り、`storedMappings.current = savedMappings` とする。
  - `initFromScan` 内で `if (savedMappings.length > 0)` の分岐にある未割当スロットの `else` 節（バリアントあり L393-395、バリアントなし L429-432）において、`scanDefaults` を使わず `initial[slotKey] = ''`（バリアントなしは `initial[\`m_${master.id}\`] = ''` / `initial[String(master.id)] = ''`）を設定する。さらに L466-469 の `for (const mapping of savedMappings)` ループで、単一バリアントやレガシー role 一致によって `v_<variantId>` へ解決されたキー以外（例：`m_${master.id}` に旧 `mapping.node_id` を上書きして複数バリアントの 2 番目以降や primary 以外の挙動を乱さないよう）整合性を保つ。
  - `getMappings` 内のループ（L482-487）で `if (isValidSavedMapping(saved, allDefinitions) && !knownKeys.has(mappingSlotKey(saved, slotDefinitions(true))))` とし、削除済みマスタ/バリアントの孤立マッピングが絶対に `results` に混入しないようにする。
- [ ] `frontend/src/hooks/__tests__/useMasterMappingRows.test.ts` を更新・追加する：
  - L521 の `[REQ-358/AC-23][REQ-358/AC-34]` テストは既存マッピング（`master_id: 10, variant_id: null, node_id: 'main'`）が存在するため、未割当の `v:102` は自動割当されず `node_id: ''`（`getMappings` は `[{ master_id: 10, variant_id: 101, node_id: 'main' }]` のみ）となることを検証するよう更新する。
  - `[REQ-369/AC-1]`, `[REQ-369/AC-2]`, `[REQ-369/AC-3]` の各ユニットテストを追加する。
- [ ] `frontend/src/components/__tests__/WorkflowModalMultiStage.test.tsx` を更新・追加する：
  - L500 のテストを更新し、削除済みマスタ（`master_id: 999`）の孤立マッピングは除外される一方、実在する無効バリアント（`is_enabled: false`）や `default_enabled: false` のマスタに紐づく既存マッピングは保持されること（`[REQ-358/AC-29][REQ-369/AC-1]`）、および既存ワークフローの `RescanModal` で未割当ステージが勝手に保存されないこと（`[REQ-369/AC-2]`）、新規登録 `UploadWorkflowModal` ではスキャン結果が自動セットされること（`[REQ-369/AC-3]`）を検証する。
