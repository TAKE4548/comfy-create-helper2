## 設計改訂（2026-10-16・R4: AC-6 の読み。人間決定 (b)。着手中のため本文どおり反映する）
実測（本カードの先行実行）で、Generate の実ルートは **768px を境に Desktop／Mobile レイアウトへ切り替わり、`WorkflowActionsMenu` が再マウントされて開いたメニューが閉じる**ことが判明した（1280×800 → 375×360 で `[role="menu"]` が 0 件）。人間決定: これを**仕様として受容**し、「境界を跨いでも開いたままにする」は**却下**。AC-6 は次のとおり読み、検証を 2 本に分ける（検証項目 5a／5b）。**実装（本番コード）は変更しない**。実装を弱めて合格させない（同一レイアウト内でメニューが閉じたら FAIL）。
- 5a 同一レイアウト内の resize（Desktop 内、Mobile 内）: 開いたまま、上端＝ヘッダー下端＋6px、最後の項目が押下可。
- 5b レイアウト境界（768px）を跨ぐ resize: メニューは閉じる（`[role="menu"]` 0 件）のが正常。新サイズで**開き直すと**最後の項目が押下可。
- 境界跨ぎ後もメニューが開いたままだった場合は想定外（レイアウト入替が起きていない）。テストを緩めず、実測値を添えて設計へ escalate する。

## 前提情報（実コードから確認済み）
- Generate (`/`) の選択ワークフローは `localStorage['prompt-surgeon-workflow-id']`（`LS_KEYS.WORKFLOW_ID`）に永続化される。`page.addInitScript(() => localStorage.setItem('prompt-surgeon-workflow-id', '1'))`。
- ワークフロー API: `GET /api/workflows` → `WorkflowSummary[]`（`[{ id: 1, name: 'W1', created_at: '2026-01-01T00:00:00Z' }]`）、`GET /api/workflows/1` → `Workflow`（`{ id: 1, name: 'W1', json_body: {}, mappings: [], target_base_model_id: null, created_at: '2026-01-01T00:00:00Z' }`。`created_at` は型上必須）。`WorkflowActionsMenu` は `workflowId` と `workflow` が揃うと表示される（どちらかが無いと `null`）。他の `GET` は `[]`／`{}` を返す。WebSocket (`/api/ws`) は接続不可のままでよい。
- 要素: ワークフロー設定トリガー `#workflow-actions-btn`、メニュー `[role="menu"]`、最終項目 `#workflow-actions-rescan`、ヘッダー本体は `h1`（テキスト `Generate`）の祖先 `border-b` div（`xpath=ancestor::div[contains(@class,"border-b")][1]`）。ケバブ `[data-testid="header-kebab-menu-button"]`／`header-kebab-dropdown`／最終項目 `header-settings-link`。モバイル幅では `#nav-generate-mobile` 等の固定ボトムナビが存在する。
- Generate の Mobile レイアウト（768px未満）はルート `div.overflow-y-auto`（`h-[100dvh]`）内にヘッダーを含み、ページスクロールでヘッダーが動く。Desktop（768px以上）は `DesktopLayout` の `#desktop-preset-tabs-bar`（`relative z-10`）がヘッダー直下にある。

## 検証内容（`headerMenuRoutes.spec.ts`）
幅×高さ: `1280×800`, `1024×768`, `768×1024`, `375×667`, 追加 `375×360`。
1. `[REQ-346/AC-1] Generate: workflow settings menu bottom is below the header bottom and its top is the header bottom + 6px (all widths)`: 開く→ `[role=menu]` bbox.bottom > ヘッダー bbox.bottom、`|menu.y - (header.bottom + 6)| <= 1`（ヘッダーに重ならない）。同じ検証をケバブ（`header-kebab-dropdown`）と、375／639 幅のピル展開（`mobile-resource-overlay`）にも行う（ピルは折り返しヘッダーの 2 行目より下＝`header.bottom + 6` に出ること）。ヘッダー高さ・`document.documentElement.scrollHeight` が開閉前後で 1px 以内の差（サブピクセル丸めのみ許容）。
2. `[REQ-346/AC-2] Generate: clicking 名前を変更 (below the header) runs the action`: 項目 bbox.y > ヘッダー下端、クリックでメニューが閉じ（`WorkflowManageModal` が開く等の既存挙動に追従。モーダルの詳細まで断定せずメニュー閉鎖を assert）。
3. `[REQ-346/AC-3] Generate: last item (ノード再スキャン) is reachable on a short viewport (375×360)`: パネルが `maxHeight` 内（`panel.bottom <= vh - 8 + 0.5`）に収まり、必要なら（あふれていれば）パネルを末尾までスクロール（あふれていなくてもよい。`scrollHeight > clientHeight` は assert しない）→ `elementFromPoint` が最終項目、固定ボトムナビに隠れず、`click({ trial: true })` 成立。
4. `[REQ-346/AC-5] Generate/Settings: kebab dropdown and (<640px) VRAM overlay stay inside the viewport and are not covered by the preset tab bar, progress line or bottom navigation`: パネル左上＋(10,10) と末尾項目の `elementFromPoint` がパネル内。
5a. `[REQ-346/AC-6] Generate (same layout): resize while the workflow menu is open keeps it open and the last item reachable @<from>-><to>`（同一レイアウト内。`for` で生成）:
   - Desktop: `1280×800 → 1024×768`（いずれも 768px 以上）。
   - Mobile: `700×900 → 375×667`、続けて `375×667 → 375×360`（いずれも 768px 未満）。
   - 手順: `openGenerate(page, from.w, from.h)` → `openWorkflowMenu` → `page.setViewportSize(to)` → `expect.poll` で (i) `[role="menu"]` が可視 1 件（**閉じたら FAIL＝退行**）、(ii) `|panel.y − (header.bottom + 6)| <= 1`（`headerRoot(page)` の bbox.bottom を resize 後に読み直す）、(iii) 最後の項目 `#workflow-actions-rescan` が（必要ならパネル内 `scrollIntoView({ block: 'nearest' })` 後に）ビューポート内で `describeAt` が `workflow-actions-rescan` を含み、`click({ trial: true })` 成立、Mobile では固定ボトムナビ（`#nav-generate-mobile` 等）に隠れない（最終項目の中心点の `elementFromPoint` がパネル内）。
   - 失敗メッセージに実測値を残す: resize 前後のビューポート、`[role="menu"]` の件数、`header.bottom`、パネル rect、最終項目 rect、`describeAt` の結果（class／testid）。
5b. `[REQ-346/AC-6] Generate (layout boundary 768px): crossing the boundary closes the menu and re-opening at the new size makes the last item reachable @<from>-><to>`（`for` で生成）:
   - `1280×800 → 375×360`（Desktop→Mobile）、`375×667 → 1280×800`（Mobile→Desktop）。
   - 手順: `openGenerate(page, from.w, from.h)` → `openWorkflowMenu` → `page.setViewportSize(to)` → `await expect(page.locator('#workflow-actions-btn')).toBeVisible()`（再マウント後のトリガー）→ `expect.poll` で `[role="menu"]` が **0 件**（孤立パネルが残らない。**閉じるのが正常**）→ トリガーをクリックして開き直す（`openWorkflowMenu`）→ `[role="menu"]` が 1 件、`|panel.y − (header.bottom + 6)| <= 1`、最後の項目が 5a (iii) と同じ基準で押下可（`describeAt` 一致・`click({ trial: true })` 成立）。
   - 閉じずに開いたままだった場合: テストを緩めて通さず、resize 前後のビューポートと `[role="menu"]` の件数を添えて設計へ escalate（想定外。設計 §4 HEO-7・§9 T-17）。
6. `[REQ-346/AC-4] Generate: toggling the trigger twice closes the menu`。
7. Red Team: Mobile でメニューを開いたままルートをスクロールしてヘッダーが動いた場合、メニューは**ヘッダー下端に追従して `|panel.y - (header.bottom + 6)| <= 1` を保つ**か、トリガーが画面外（トリガー bbox.bottom < 0）になったら閉じる（浮遊・ヘッダーへの重なりなし）。スクロール量は 20px と 60px の 2 通りで、追従（window の `scroll` capture 経由）を判定する。
8. 実装前の疑い（設計 §2-2 A2/A3 の重なり順）の実測値を、失敗時のメッセージとコンソール出力（`elementFromPoint` の結果要素の class/testid）に残す。
9. `[REQ-346/AC-5] Generate Desktop (1280×800, 1024×768, 768×1024): A4 hover card is not covered by the preset tab bar`: `[data-testid="resource-hover-monitor"]` を `hover()` → `[data-testid="resource-hover-card"]` の bbox.bottom > ヘッダー下端、`#desktop-preset-tabs-bar`（`relative z-10`）が存在する幅で、カード左上+(10,10) と中心の `elementFromPoint` がカード内。実測値（class/testid）を失敗メッセージに残す。375×667（640px 未満）ではカードが可視にならず `[data-header-menu-bridge]` も 0 件であることを確認（A3 のピルが担う）。**追加（R1）**: Generate Mobile の折り返しヘッダー（`700×900`。768px 未満＝MobileLayout で `actions` が 2 行目、A4 は 640px 以上で可視）で、カード上端＝ヘッダー下端＋6px（±1px。トリガーとの間隔は約80〜90px）、`resource-hover-monitor` から `page.mouse.move(cardCenterX, card.y + 12, { steps: 20 })` でカードへ移動してもカードが開いたまま（`[data-header-menu-bridge]` が 1 件、トリガー下端〜カード上端を被覆）、ブリッジ中点の `elementFromPoint` がブリッジ、離脱（(5, vh−5)）で閉じる。
