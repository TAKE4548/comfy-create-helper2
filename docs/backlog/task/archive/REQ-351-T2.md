# REQ-351-T2: 生成時 ParamSync の回帰テスト（AC-3 / AC-4 / AC-5）

## 1. 概要と目的

- 種別: change_kind = code、subsystem = frontend、実行ロール = engineer（init-task スキャフォールドのフロントマターにこれらのキーがないため本文に記載する）。

設計調査では、生成時の同期は role 文字列キーで動くため、ステージ付き role（`computed_role`）でも既存実装のまま AC を満たす見込みである。本 Card は既存テストファイルにケースを追加して挙動を固定する（characterization）。

- AC-3: Main=20、Rough=30、Detail=40 で Rough だけ同期先。Main を 50 へ変更→Rough は 50、Detail は 40 を保持。
- AC-4: 同一型 Rough/OtherSteps を Main/Steps の同期先に選択。Main を 60 へ→Rough/OtherSteps が 60。
- AC-5: Rough と Detail を同期先に選択。Detail だけ解除して代表を 70 へ→Rough は 70、Detail は解除時の値を保持。
  - 「解除時の値」= Detail を同期先から外した時点で Detail 自身の入力欄にある値、つまりストア `paramValues['Sampler_Steps_Detail']`（DB の値ではない）。
  - 例: Main=20、Rough=30、Detail=40 で Rough・Detail を同期先にし、Main=60 で生成→送信は Rough=60、Detail=60。ストアは Rough=30、Detail=40 のまま（`applyParamSync` は送信用コピー `merged` だけを上書きし、ストアへ書き戻さない）。Detail を外して Main=70 で生成→送信は Rough=70、Detail=40。Detail が 60 や 70 なら不合格。

観測点: 送信グラフ（`mockStore.queuePrompt.mock.calls[n][0]`）の各ノード `inputs.steps`、およびストアの `paramValues` が書き換わらないこと。

### 3.2 既存の対象コード
`frontend/src/pages/GeneratePage/hooks/useGenerateAction.ts` L157-L177:
```ts
  const applyParamSync = (
    paramValues: Record<string, string>,
    groups: ParamSyncGroup[] = [],
    workflowMappings: Workflow['mappings'] = []
  ): Record<string, string> => {
    const activeGroups = (groups || []).filter((g) => g.is_enabled)
    if (activeGroups.length === 0) return paramValues
    const merged = { ...paramValues }
    const seedRoles = new Set(workflowMappings.filter((mapping) => mapping.input_type === 'seed' && mapping.role).map((mapping) => mapping.role as string))
    activeGroups.forEach((g) => {
      if (seedRoles.has(g.master_role) || g.slave_roles.some((role) => seedRoles.has(role))) return
      const masterVal = merged[g.master_role]
      if (masterVal !== undefined) {
        g.slave_roles.forEach((slaveRole: string) => {
          merged[slaveRole] = masterVal
        })
      }
    })
    return merged
  }
```
