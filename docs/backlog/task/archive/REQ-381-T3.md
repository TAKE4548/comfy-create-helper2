## 目的と受入

AC7:mobileのLLM5数値はraw draftを編集中保持、number blur/Enter、range pointerup/keyboard keyup/blurで確定保存。pointercancelは不発、同値重複0。通常の数値Saveをmobileだけ除く。AC8:長文prompt/Playgroundは既存明示Save/previewのまま。AC12:desktop数値Save、group/key/draft保護を保持。

### 後続へ供給する確定interface

```ts
export type CommitPhase = 'idle'|'dirty'|'invalid'|'saving'|'saved'|'error'
export type CommitState = { phase: CommitPhase; revision: number; error: string|null }
export function useSettingsCommit(options: {
  save: (key:string, snapshot:string)=>Promise<void>
}): {
  stage:(key:string,snapshot:string|null)=>void
  commit:(key:string)=>void
  retry:(key:string)=>void
  acceptServer:(key:string,snapshot:string)=>void
  getState:(key:string)=>CommitState
}
```

- resource keyごとに1 in flight、後続の確定snapshotは最新1件へcoalesce、別key独立。nullはinvalidで送信不可。stageだけでは送信しない。invalid/dirtyは保持、成功ackはsubmitted revisionだけ。
- 古いack/refetchは新draftやdirtyを上書きしない。savedはmatching ack後のみ約2秒、通常はidle、pendingは控えめ、error/未保存を常設。失敗時queue停止、手動retryまで自動network再送なし。結果不明は成功にしない。
- save callbackは既存 `llmPromptsApi.update(key,{content:snapshot})` のawait、server contract PUT /api/llm-prompts/{key} は `{content:string}`→LlmPrompt。`snapshot=JSON.stringify(LlmParams)`。endpoint/schema変更なし。
- LlmParams: temperature/top_p/max_tokens/presence_penalty/frequency_penalty:number。既存PARAM_FIELDSのmin/max/stepを保持。空/NaN/Infinity/範囲外rawは0へ変換せずvalidation+未保存、未送信。numeric rawは別stateで保持。
- T1 `useSettingsMobile()`を使用。resizeだけでcommitしない。mobile→desktopでpending/draftを捨てずmanual Saveへ戻す。既存model即時change、prompt種別切替draft、6prompt制約、previewのlatest-request保護を維持。
- 新hookのsequence/PBTは外部save I/OだけMSWで制御。stage/commit/ack/fail任意列でmax1/key・invalid0送信・旧ack上書き禁止・failure後retry待ちを検証。旧module-mockケースを新統合証拠にしない。
- 説明infoの適用はT4と混ぜない（T2と並行可能にする）。既存重要model/error表示を削除しない。

## T0 Draft registry integration

T0の `useSettingsDraftRegistration(resourceId,{cancelQueued,discardLocal})` は `{update(risk),clear()}` を返す。riskは `{dirty,invalid,failed,queued,inFlight}:boolean`。unique instance ID/resourceで登録し、raw値をregistryへ渡さない。edit/commit/ack/errorで同期updateし、cleanup/成功baseline一致/明示cancelで適切にclearする。mobile/desktopとも登録する。

Cancel navigationはdraft/queueを変えない。確認中inflight保存は通常完了するが、Leaveは全persist inFlight==falseまでdisabled。explicit Leave時だけ未送信queueを同期停止しlocal draftを破棄するcallbackを提供し、remote successのrollbackやautomatic retryをしない。同Settings hash/query切替とresizeだけでは破棄しない。previewなど非persist要求は保存inFlightに数えない。

useSettingsCommit内部の各keyをaggregateして1つのregistrationへ反映する。LLM長文promptは保存済みbaselineとeditsを比較する別registration。manual prompt/model/params mutationの実persist pending/errorも登録し、ack revisionが最新draftに一致しなければdirtyを消さない。desktop manual Save draftも登録する。
