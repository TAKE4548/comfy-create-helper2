# REQ-423-T3: マッピング行構築および配線保持におけるinput_name属性の維持・復元

## 1. 概要と目的
本タスクは **AC-1 のマッピング行構築および配線保持** を担当する（AC-2 の UI 保存処理は T4、AC-2 バックエンドは T1、AC-3/AC-4 は T2/T5 が担当）。
`useMasterMappingRows.ts` の `getMappings` において、返却されるマッピング配列要素から `input_name` が除外されていたため、スキャン結果（`latestScan.current`）や既存保存マッピング（`savedByKey` / `storedMappings`）から合致した `input_name` を抽出・保持して返却するように改修する。また既存 DB の `input_name` が空であっても、再スキャンのマッチ結果から `input_name` を自動補完（ヒーリング）する。
併せて `AdaptiveWorkflowWiring.tsx` および `wiringStageGroups.ts` の `WiringMappingItem` に `input_name?: string` を定義し、配線変更時や保存時に `input_name` を欠落させないよう保持する。

### 3.2 既存の対象コードスニペット
```typescript
// frontend/src/hooks/useMasterMappingRows.ts (L487-517)
  const getMappings = (mainRows: MasterMappingRow[], notFoundRows: MasterMappingRow[]) => {
    const results: { master_id: number; node_id: string; variant_id?: number; input_name?: string }[] = []
    const inputRows = [...mainRows, ...notFoundRows]
    const knownKeys = new Set(inputRows.flatMap(r => r.stageSlots?.length
      ? r.stageSlots.map(s => canonicalSlotKey(s.masterId, s.variantId))
      : [canonicalSlotKey(r.master.id)]))
    for (const saved of storedMappings.current) {
      if (isValidSavedMapping(saved, allDefinitions) && !knownKeys.has(mappingSlotKey(saved, slotDefinitions(true)))) {
        const { variant_id, ...legacy } = saved
        results.push(variant_id == null ? legacy : { ...saved, variant_id })
      }
    }
    for (const r of inputRows) {
      if (r.stageSlots && r.stageSlots.length > 0) {
        for (const slot of r.stageSlots) {
          if (slot.node_id && slot.node_id.trim() !== '') {
            const saved = savedByKey.get(canonicalSlotKey(slot.masterId, slot.variantId))
            results.push({
              master_id: slot.masterId,
              node_id: saved?.node_id === slot.node_id ? saved.node_id : slot.node_id.trim(),
              ...(slot.variantId !== undefined ? { variant_id: slot.variantId } : {}),
            })
          }
        }
      } else if (r.node_id && r.node_id.trim() !== '') {
        const saved = storedMappings.current.find(m => m.master_id === r.master.id && m.variant_id == null)
        results.push({ master_id: r.master.id, node_id: saved?.node_id === r.node_id ? saved.node_id : r.node_id.trim() })
      }
    }
    return results
  }
```

## 4. 実装要件 (Implementation Logic)
- [ ] `frontend/src/hooks/useMasterMappingRows.ts`:
  - `StageSlotItem` および `MasterMappingRow` に `input_name?: string` を追加。
  - `buildRows` 内で、スロット構築時に `slotMatched?.input_name` または `saved?.input_name` を抽出し、スロットオブジェクトの `input_name` に設定。
  - `getMappings`:
    - 各スロットおよびマスター行について、`input_name` を安全に解決：
      1. `latestScan.current?.matched` に該当スロットまたはノードの合致があり `input_name` が存在する場合はそれを優先（再スキャンでの自動ヒーリング）。
      2. スキャンにない場合は `saved?.input_name`（既存値）。
      3. いずれもない場合は `slot.input_name` または空。
    - 返却する各マッピングオブジェクトに `...(input_name ? { input_name } : {})` を付与して返却。
- [ ] `frontend/src/components/AdaptiveWorkflowWiring.tsx` & `frontend/src/utils/wiringStageGroups.ts`:
  - `WiringMappingItem` 型に `input_name?: string` を追加。
  - `mappingsMap` の生成・更新ループで `m.input_name` を保持。
  - `handleNodeChange` でスロット更新時、`prev?.input_name` を引き継ぐ。
- [ ] `frontend/src/hooks/__tests__/useMasterMappingRows.test.ts`:
  - `[REQ-423/AC-1]` `getMappings` がスキャン結果から正しく `input_name: "noise_seed"` を含めて返却することを検証。
  - `[REQ-423/AC-1]` 既存マッピングが `input_name: ""` の場合でも、スキャン結果によって補完・修復されることを検証。
- [ ] `frontend/src/pages/SettingsPage/components/__tests__/WorkflowAdaptiveStaging.test.tsx`:
  - `[REQ-423/AC-1]` `AdaptiveWorkflowWiring` でノード変更や保存を実行した際、`input_name` が破棄されず渡されることを検証。
