# REQ-308-T1: Store の chip 読込・上書きを prompt role に限定

## Hermetic Context
```ts
export function getEffectiveParamValues(
  paramValues: Record<string, string>,
  promptChips: Record<string, TagChip[]>,
  isAnimaMode?: boolean
): Record<string, string> {
  const effective = { ...paramValues }
  for (const [role, chips] of Object.entries(promptChips || {})) {
    if (chips && chips.length > 0) effective[role] = chipsToString(chips, isAnimaMode)
  }
  return effective
}
```
`loadPresetData(preset, defaultParams)` currently iterates all merged roles and calls `parseToChips(val, isAnimaMode)`. Its current action signature is `loadPresetData: (preset: WorkflowPreset, defaultParams: Record<string, string>) => void;`. `Workflow.mappings` item shape in `frontend/src/api/types.ts`: `role: string | null`, `input_type: string | null`. Canonical allowlist: mappings where `role` exists and `input_type === 'textarea'`.

## Implementation
- Add the prompt role allowlist to store state/action arguments needed for preset loading and effective value construction; default missing mapping to empty (fail closed).
- In `loadPresetData`, create/preserve chips only for allowed roles. Keep every original `paramValues` value.
- In effective serialization, ignore stray chips for non-prompt roles, including stale persisted chips.
- Tests: dotted checkpoint and LoRA values survive load/serialization; a prompt chip still serializes; empty allowlist preserves all raw values.
