# REQ-394-T7: identity root_files に pytest.ini を追加（承認ゲート付き）

## 実行境界

- 役割は engineer / dev-task。workspace・cwd はリポジトリルート。
- 所有ファイルは `.agents/verification.json` だけ。ほかのキー（`gates`、`input_dirs`、`excluded_*`、`endpoints`）は変更しない。
- **この Card は検証契約そのものの変更であり、高リスク範囲（verification）に当たる。コーディネーターが人間レビューで明示承認した場合のみ実行する。承認がなければ実行せず、Card を外す（T9 の depends_on からも外す）。** 承認済み（2026-10-25、`docs/logs/REQ-394/approval-design.json`、回答「3_T7: 実施する」）。承認の沈黙や既定値は承認ではない。
- 前提: コーディネーターが設計承認と本 Card 個別の承認を確認し、exact-ID で in-progress へ遷移済みであること。状態更新・QA・commit は担当外。

## 理由

`identity` は候補（確定したレビュー対象）のハッシュ対象を `input_dirs` と `root_files` で決める。ルートの `pytest.ini` はどちらにも含まれていない。したがって T1 が変更する `pytest.ini`（AC-3 の中核）を変更しても候補の同一性が変わらず、tester の「凍結候補」に反映されない（追跡入力の検知漏れ）。`frontend/vite.config.ts` は `frontend` ディレクトリ配下なので既に対象。

## 変更箇所

現状（`.agents/verification.json` の `identity`）:

```json
  "identity": {
    "input_dirs": [
      "backend",
      "frontend",
      "scripts",
      "tests",
      "docs",
      "tools/server-manager"
    ],
    "root_files": [
      "README.md",
      ".gitignore",
      ".gitattributes"
    ],
```

変更後（`root_files` の末尾に 1 要素。整形・インデント・他の行は変えない）:

```json
    "root_files": [
      "README.md",
      ".gitignore",
      ".gitattributes",
      "pytest.ini"
    ],
```

## 完了条件・検証コマンド

```
backend\.venv\Scripts\python -c "import json,pathlib; d=json.loads(pathlib.Path('.agents/verification.json').read_text(encoding='utf-8')); print(d['identity']['root_files']); assert d['identity']['root_files'][-1]=='pytest.ini'; assert d['schema_version']==1"
git diff --numstat -- .agents/verification.json
```

期待: 1 つ目が `['README.md', '.gitignore', '.gitattributes', 'pytest.ini']` を出力して終了コード 0。2 つ目が追加 2 行・削除 1 行（`.gitattributes` 行へのカンマ追加と `pytest.ini` 行）。それ以上の差分は ESCALATE。ファイルは UTF-8（BOM なし）、LF。`gates.fixed_commands` は 1 バイトも変えない。
