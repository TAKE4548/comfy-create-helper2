# REQ-424-T1: 生成キューの即時キャンセルとUndoスナップショット管理の実装

## 1. 概要と目的
本タスクは `useGenerationStore`（`JobQueueSlice`）において、待機中ジョブ（queued）の単一キャンセルを事前ディレイなく即時実行し、直後3秒間のアンドゥ（復元）に必要なジョブ情報スナップショットの退避・タイマー管理・復元再投入（`queuePrompt`）ロジックを実装・ユニット検証する。本カードが唯一の意味的仕様書である（dev-task Step 1）。

### 3.2 既存の対象コード（キャンセル・一括キャンセル・再投入周辺）
```typescript
// frontend/src/store/slices/jobQueueSlice.ts (L371-384)
// 既存の単一ジョブキャンセル（汎用・実行中ジョブ中断用）: そのまま維持し、単一待機キュー専用の cancelQueuedJobWithUndo と並行共存
cancelJob: async (id: string) => {
  get().abortSubmission()
  const active = comfyWsService.getActiveSubmissionPromise()
  if (active) { try { await active } catch {} }
  const job = get().generationSnapshot?.jobs.find((item) => item.job_id === id || item.prompt_id === id)
  let result: CancelResult
  if (job) result = await generationApi.cancelJob(job.job_id)
  else {
    const operation = await generationApi.cancel({ mode: 'single', scope: 'all', target: { prompt_id: id } })
    result = operation.items[0] ?? { job_id: null, prompt_id: id, status: null, outcome: 'rejected', message: operation.message }
  }
  await get().fetchQueue()
  return result
},

// 既存の一括全件キャンセル: Undo状態が存在する場合でも即時クリアし、全件キャンセル処理を一切阻害せず正常実行 ([REQ-424/AC-5])
clearPendingQueue: async () => {
  if (get().queuedCancelUndo) {
    get().dismissQueuedCancelUndo()
  }
  await generationApi.cancel({ mode: 'all', scope: 'pending' })
  await get().fetchQueue()
},
```

## 4. 実装要件 (Implementation Logic)
1. **型定義追加 (`types.ts`)**:
   - `CancelledJobSnapshot` を定義し、`JobQueueState` および `JobQueueActions` に各プロパティ・メソッドを追加。
2. **初期状態とUndo管理 (`jobQueueSlice.ts`)**:
   - 初期状態 `queuedCancelUndo: null` を設定。
   - **単一キャンセルのトリガーと使い分け ([REQ-424/AC-1])**:
     - UI層（`JobManagementModal`）の待機ジョブ一覧のごみ箱ボタン押下時、単一待機キュー専用アクションとして `cancelQueuedJobWithUndo(promptId)` がディスパッチされる。
     - 既存の `cancelJob(id)` は実行中ジョブ中断や汎用キャンセル用としてそのまま維持し、単一待機ジョブのキャンセルには事後Undoスロット武装を行う本アクションを明確に使い分ける。
   - `cancelQueuedJobWithUndo(promptId: string)` ([REQ-424/AC-1], [REQ-424/AC-2]):
     - 既存の進行中タイマーがあれば解除（`clearTimeout`）。
     - 対象ジョブのメタデータ（`localStorage.getItem('prompt-surgeon-meta-' + promptId)` や `prompt-surgeon-meta-` + jobId、および `get().currentWorkflow`）を取得・退避。
     - 事前ディレイを挟まず即座に `generationApi.cancelJob(promptId, false, true)` を実行して待機キューから除外 ([REQ-424/AC-1])。
     - キャンセル成功後、`queuedCancelUndo` にスナップショットを保存し、直ちに3000ms後に `dismissQueuedCancelUndo()` を呼び出すタイマーを開始 ([REQ-424/AC-2])。
     - `await get().fetchQueue()` を実行。
   - `restoreCancelledJob()` ([REQ-424/AC-3]):
     - `queuedCancelUndo` を取得。存在しない場合は `null` を返却。
     - タイマーを解除し、退避していた `workflow` および `metadata` を用いて `get().queuePrompt(workflow, metadata)` を呼び出しキューに再投入。
     - `set({ queuedCancelUndo: null })` でUndo状態をクリア。
     - 再投入されたジョブIDを返却。
   - `dismissQueuedCancelUndo()` ([REQ-424/AC-4]):
     - 3秒タイマー満了時または明示的閉じる操作時にタイマーを解除し、`set({ queuedCancelUndo: null })` でスナップショットを破棄してキャンセル確定とする。
3. **ユニットテスト拡充 (`jobQueueSlice.test.ts`)**:
   - `[REQ-424/AC-1]` 即時キャンセル呼び出し（ディレイなし）の検証。
   - `[REQ-424/AC-2]` Undoスナップショットの生成と3秒タイマーの起動検証。
   - `[REQ-424/AC-3]` `restoreCancelledJob` による元のワークフロー・メタデータでのキュー復帰検証。
   - `[REQ-424/AC-4]` タイマー満了または明示破棄でUndoスロットがクリアされることの検証。
   - `[REQ-424/AC-5]` 一括キャンセル・他操作共存検証: `cancelQueuedJobWithUndo` 呼出直後（Undo通知武装中）に `cancelAllJobs` または `clearPendingQueue` を実行した場合、タイマーが解除されUndoスロットがクリアされること、および一括キャンセル機能自体のロジック（API呼び出しやキュー更新）が阻害されず全件キャンセルが正常実行されることの両方を検証。
