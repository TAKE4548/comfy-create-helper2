## Verification Commands and Gates

frontend cwd。コマンドは各1回のみ。tools.exec_commandでsessionを開始し、
coordinatorがclockでwall時間を監視する。120秒上限に達した診断/対象は当該sessionを停止。
正常終了codeが得られなければINCONCLUSIVE。case timeoutを120秒に設定しない。
長いblocking waitを行わず、停止後ログと最後の完了caseを保存し再実行しない。

### 1. Focused diagnostic (one run)

```powershell
$env:VITE_REQ344_QUERY_DIAGNOSTICS = '1'
try {
  npx vitest run src/pages/__tests__/GeneratePage.test.tsx --testNamePattern 'REQ-161: Generate button follows workflow load state' --reporter=verbose *> ../docs/design/REQ-344-followup-diagnostic.log
  $req344DiagnosticExit = $LASTEXITCODE
  Get-Content -LiteralPath '../docs/design/REQ-344-followup-diagnostic.log' -Tail 35
} finally {
  Remove-Item Env:VITE_REQ344_QUERY_DIAGNOSTICS -ErrorAction SilentlyContinue
}
exit $req344DiagnosticExit
```

期待: 正常完了・focused2case PASS、No queryFn/Missing queryFn0、
両caseのkey/queryFn function/mock参照一致/observer総数の記録。
未処理例外、collection障害、証拠不足なら停止して親へ返す。
filterで除外した他caseは受入や対象全件のPASSに数えない。
警告消失だけで歴史的flakyの原因を確定しない。

失敗/停止時はread-only静的解析と改訂レビューへ戻す。再実行しない。

### 3. Acceptance batch (after target gate)

既定npm testを同じ実装で最大5回、1バッチのみ。各run wall600秒を外側で監視する。
具体的loopはtest planのFollow-up Acceptance Batch節。
ログはREQ-344-followup-suite-N.log、JSONはREQ-344-followup-suite-results.json。
target FAIL/timeout/警告再発/例外/出力不足ならバッチ停止。
EPERM（特にsetup.ts realpath/collection）が再発したら別の環境障害として停止し、
raw例外/path/収集数を残す。対象PASS行があっても環境ゲート充足としない。
未実行回はNOT-RUN。cache/ACL/setup/実行権限/worker変更やその場の再実行は禁止。

## Output and Decision

- [ ] Attempt Evidence: SHA256/開始終了/実行code/wall停止/最後のcase/生ログを記す。
- [ ] Diagnostic Evidence: 警告数・snapshot・静的3consumerとの対応・未観測事項。
  個別observer ownerは不明ならそのまま記載。
- [ ] Target Result: 全件の件数/状態、過去13/13結果との区別。
- [ ] Acceptance Table: 5行、実行済み結果とNOT-RUN、全体終了code、対象判定、
  EPERM collection・その他FAILの分類。失敗回を捨てない。
- [ ] Next Decision: 対象5回PASS＋環境ゲート充足＋追加修正不要の親判断ならT4。
  対象失敗/警告/証拠不足は静的解析と人の改訂レビュー、
  EPERMは環境read-only調査と親レビュー。ここでは追加修正/再試行しない。
