## Trigger and Exit Conditions

このTaskの切替評価は常に一度行う。次のいずれかなら静的解析を実施する:
1. T1/T2の局所検証で対象失敗/未処理非同期例外が残る。
2. 既定全体最大5回の検証バッチで対象FAIL/timeout/対象関連の未処理例外が残る。
3. 対象5回PASSでも、変更前失敗→非同期/共有状態の仕組み→修正で遮断される経路を
   具体的な観測とファイル:行で説明できない。再現しなかった、候補を列挙しただけも該当する。

対象5回PASSかつ具体的な説明が揃う場合は「解析不要」と根拠を同じ出力へ記録する。
成功だけを歴史的flakyの原因確定としない。対象5回PASSで解析後も原因未確定の場合は、
追加修正不要/必要を証拠で判断して親へ返す。説明できるまで調査を繰り返さない。
追加修正が必要なら改訂設計へ返す。T4は5回PASS＋追加修正不要の親判断後に実行する。

## Static Analysis and Output Requirements

reportは次の順で作成する。各結論にファイル:行と観測ログまたは未観測の記載が必要。
解析不要の場合も5見出しを置き、Attempt Evidence/Next Decisionへ根拠を記載し、
解析用の表/経路/仮説は「未実施（解析不要判定）」と明示する。6分類の詳しい解析は実施時に必須。
- [ ] Attempt Evidence: 候補修正1回の内容、バッチの実行/中断条件、対象PASS/FAIL、
  関連しない全体FAIL、解析trigger、解析版を記録する。
- [ ] Lifecycle Matrix: 以下6分類を一行以上ずつ、owner/start/settle-or-cleanup/
  case間共有/証拠/未確定事項で整理する。
  async: query/deferred開始、resolve/reject、await、unmount後更新。
  timer: debounce/polling/query通知/gc、作成/clear、real↔fake、effect再実行。
  mock: factory/default/one-shot、reset/restore、欠落API、spy実装の寿命。
  store: snapshot identity、subscribe/unsubscribe、immutable setter、fresh nested state。
  query: client/key/enabled/retry/poll/gc、cancel/clear、Promiseと通知のタイミング。
  boundary: import/collectとrender/effectの分離、閉じたmodalと実layout/hookの境界。
- [ ] Causal Paths: 失敗箇所から候補機構へ、promise/timer/query/store/componentの辺を
  辿り、修正で遮断された辺/残った辺を示す。コード上の可能性を実際の発生事実と混同しない。
- [ ] Hypotheses: 各候補を修正済み/残存/根拠により否定/未確定に分類し、
  支持証拠、反証、未観測項目、次に必要な最小検証を列記する。
- [ ] Next Decision: 対象5回PASSで追加修正不要ならT4へ。残存失敗または具体的な
  修正必要性があれば、最小変更対象・提案検証・trade-offを親へ返して改訂設計へ。
  静的解析でCPU競合や所要時間を確定しない。根拠不十分な断定を避ける。
