## Scroll Root and Focus Contract

rootの検出は `target.closest('[data-stage-scroll-root]')` のみ。rootの属性/classは `data-stage-scroll-root=""` / `stage-input-scroll-root`。T2はStageInputGroup.tsxから `./StageInputGroup.css` を静的importし、同CSSへ `.stage-input-scroll-root[data-stage-scroll-root] { scroll-padding-top:44px; }` を定義する。rootのDOM接続はT4がDesktopLayout.tsxの `#desktop-prompt-scroll` と `#desktop-controls-scroll`、T7がAdaptiveWorkflowWiring.tsxの `#settings-mapping-scroll` を所有。T2はこれら外部ファイルを編集しない。T5のParamPanelはcontrols root内の利用側で、独自rootを追加しない。

section/heading/bodyのclassは `stage-input-group` / `stage-input-group__heading` / `stage-input-group__body`。headingはheight36px/box-sizing:border-box/sticky top0/opaque/z10。section内の `input, textarea, select, button, [tabindex], [contenteditable="true"]` に各selectorをsectionでscopeしscroll-margin-top44pxを同CSSに定義。44=36px＋8pxの余白であり通常のpadding-topは増やさない。

focus captureの対象は `event.target` のHTMLElement。own section内にありrootがsectionを含むことを確認しown heading refを使う。root欠落、portal等のsection外対象、高さ0の矩形はno-op。root viewport topはrootRect.top+clientTop、bottomはtop+clientHeight。visibleHeaderTop=max(viewportTop,headerRect.top)、visibleHeaderBottom=min(viewportBottom,headerRect.bottom)。この範囲が正で、targetRect.top<visibleHeaderBottomかつtargetRect.bottom>visibleHeaderTopの時だけ `root.scrollBy({top:targetRect.top-(visibleHeaderBottom+8),behavior:'auto'})` を1回実行。露出済みの対象はscrollしない。固定44pxの閾値、scrollIntoView、window/別root/sectionのscrollやfocus/value変更は使わない。browserのclamp後の実非遮蔽はBR-3で確認する。
