# REQ-394-T8: 最終構成の再計測（AC-1〜AC-4、AC-5 の入力）

## 実行境界

- 役割は engineer / dev-task。workspace・cwd はリポジトリルート。`PYTHONDONTWRITEBYTECODE=1`。
- **ソース・テスト・設定は一切変更しない**。書くのは `docs/logs/REQ-394/final-*` のみ（git 管理外）。
- 前提: T1〜T6 が完了していること。コーディネーターが exact-ID で in-progress へ遷移済みであること。状態更新・QA・commit は担当外。
- この計測は tester の独立検証の代替ではない（独立 QA は別途 Gate 1〜3 を新規実行する）。T9（SPEC 同期）が引用する再計測値の出典である。
- 常駐アプリ（Antigravity、LM Studio、ブラウザ）の状態を変えない。他のワークロードを止めない。

## 計測プロトコル

各計測の前後で CPU 負荷を記録する:

```
powershell -NoProfile -Command "(Get-CimInstance Win32_Processor).LoadPercentage"
```

負荷が計測前後の平均で 60% を超えた計測は**無効**として破棄し、再計測する（無効の記録も残す）。有効な 3 回を揃える。

## 手順

1. FE を 3 回: `cd frontend; npm test > ..\docs\logs\REQ-394\final-fe-<n>.txt 2>&1`（n=1,2,3）。wall は `Measure-Command` か開始/終了時刻で測る。各ログの `Test Files`・`Tests`・`Duration`（transform/setup/collect/tests/environment/prepare）を転記する。
2. BE 並列を 3 回: `backend\.venv\Scripts\python -m pytest -n auto -q -p no:cacheprovider --durations=15 > docs\logs\REQ-394\final-be-n-auto-<n>.txt 2>&1`。wall と末尾の件数行を転記する。
3. BE 逐次を 1 回（参考）: `backend\.venv\Scripts\python -m pytest -q -p no:cacheprovider --durations=15 > docs\logs\REQ-394\final-be-seq.txt 2>&1`。
4. 収集の比較（AC-3）。それぞれ 2 回:
   - `backend\.venv\Scripts\python -m pytest --collect-only -q -p no:cacheprovider`（ルート。末尾の `collected in X s` を記録）
   - `backend\.venv\Scripts\python -m pytest backend/tests tests --collect-only -q -p no:cacheprovider`（パス指定）
   ルートの出力のノードID（`::` を含む行）をソートして `docs/logs/REQ-394/final-be-collect-ids.txt` に保存する。
5. ノードID差分: `docs/logs/REQ-394/be-collect-baseline-ids.txt`（774 件、設計時の baseline）と `final-be-collect-ids.txt` を比較する。**増分は T1 の新規 3 件（`test_root_pytest_ini_declares_testpaths_for_backend_and_tests` と `test_collection_without_args_skips_db_docs_frontend_dirs` の 2 パラメータ）だけ**で、欠落は 0 であること。ルートとパス指定のノードID集合が同一であること。
6. FE テスト一覧の差分: `cd frontend; npx vitest run --reporter=json --outputFile=..\docs\logs\REQ-394\final-fe-tests.json` を 1 回実行し、`docs/logs/REQ-394/fe-baseline-tests.json`（2607 件）と比較する。欠落 0・失敗 0、増分は T4 のカナリア 2 件だけ。
7. WS（AC-4）: `backend\.venv\Scripts\python -m pytest backend/tests/integration/legacy/test_ws.py backend/tests/governance/test_vram_guard.py --durations=0 -q > docs\logs\REQ-394\final-be-ws.txt 2>&1`。WS 系 7 件が各 1.5s 未満。
8. `docs/logs/REQ-394/final-summary.md` に表でまとめる（FE: 3 回の wall と Duration 内訳、中央値、最大 / BE: 3 回の wall、中央値、最大、逐次 / 収集時間 root vs paths / 件数 FE 2609・BE 777 / ノードID差分 / WS 各件の秒数 / 各計測の CPU 負荷前後 / 予算との照合）。

## 予算との照合（設計 §3）

| 項目 | 予算 |
| --- | --- |
| FE `npm test` wall | 中央値 ≤ 125s、最大 ≤ 140s |
| BE `pytest -n auto` wall | 中央値 ≤ 36s、最大 ≤ 42s |
| ルート収集（pytest 内計時） | パス指定の 1.25 倍以内 |
| 件数 | FE 2609 / 247 ファイル、BE 777、skipped・xfail 0 |

超過した場合は予算を緩めず、結果をそのまま報告する（暗黙の緩和は禁止。設計へ戻す判断はコーディネーター）。
