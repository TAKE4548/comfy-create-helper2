## 2. 現状コードスニペットと問題点

### 2.1 `backend/app/services/generation_service.py` L858-L880 (`_cancel_global`)
```python
        if before is not None:
            for upstream in before.pending:
                queued_job = jobs_by_prompt.get(upstream.prompt_id)
                if queued_job is not None and queued_job.status not in _CONFIRMED_TERMINAL:
                    self._cancel_requested.add(queued_job.job_id)
                result_targets.append((queued_job.job_id if queued_job else None, upstream.prompt_id))
```
**問題点**: 上流キュー（`before.pending` および `before.running`）に実在するジョブのみを走査しているため、上流クラッシュ等で上流キューに不在となった DB 上の active ジョブ（`status in {"queued", "submitting", "running"}` かつ `prompt_id is not None`）が走査から完全に脱落し、DB 状態が更新されず `results` にも含まれない。

### 2.2 `backend/app/services/generation_service.py` L1149-L1155 (`_cancel_normal`)
```python
        pending_normal = [item.prompt_id for item in queue.pending if item.prompt_id in known_normal]
        result_targets: list[tuple[str, str]] = []
        if pending_normal:
            result_targets.extend((jobs_by_prompt[prompt_id].job_id, prompt_id) for prompt_id in pending_normal)
```
**問題点**: `known_normal` に属する active ジョブであっても、`queue.pending` や `queue.running` に不在のジョブは `pending_normal` / `running_targets` に入らず、DB 上の `running`/`queued` のまま放置される。

## 3. 実装契約

1. **`_cancel_global` での上流不在 active ジョブの回収**:
   対象スコープの全 active ジョブ（`job.status in {"queued", "submitting", "running"}` かつ `job.prompt_id is not None`）のうち、上流 `before.pending` および `before.running` に存在しないジョブ（または上流 queue 照会失敗時）を特定する。
   それらのジョブに対し：
   ```python
   self._mark_unconfirmed(job, "job missing from upstream queue during global cancel")
   results.append(self._result(job.job_id, job.prompt_id, "unconfirmed", "unconfirmed", "job was missing from upstream queue during bulk cancellation"))
   ```
   を実行し、DB を確実に `unconfirmed` に遷移させるとともに `results` に追加する。

2. **`_cancel_normal` での上流不在 active ジョブの回収**:
   `known_normal` かつ active なジョブのうち、上流 queue（`queue.pending` および `queue.running`）に不在のジョブを特定する。
   それらのジョブに対し：
   ```python
   self._mark_unconfirmed(job, "job missing from upstream queue during normal cancel")
   results.append(self._result(job.job_id, job.prompt_id, "unconfirmed", "unconfirmed", "normal job was missing from upstream queue during bulk cancellation"))
   ```
   を実行する。

3. **HTTP 202 と `items` の一貫性**:
   上記により DB 状態が `unconfirmed` に更新されることで、末尾の `_unconfirmed_leftovers()` や `any(item.outcome == "unconfirmed" for item in items)` と自然に整合し、API レスポンスは 202 Accepted となり、全未確認ジョブが `items` に含まれる。

## 4. テスト契約

- `backend/tests/integration/legacy/test_generation_integration.py`:
  - `test_req401_ac1_integration_reconcile_upstream_lost_job_releases_normal_group`:
    - Given: 実 SQLite DB 環境。通常バッチを投入し prompt_id が確定した active ジョブが存在する。上流 ComfyUI の queue/history が消失（空）。
    - When: バックエンドの reconcile ループまたは明示的 reconcile が走行する。
    - Then: ジョブ status が `unconfirmed` へ更新され、次に投入される通常バッチには新しい `normal_group_id` が割り当てられる（グループが解放されている）。
  - `test_req401_ac3_integration_bulk_cancel_transitions_upstream_lost_jobs_to_unconfirmed`:
    - Given: 実 SQLite DB 環境。prompt_id 確定済みの active ジョブが複数存在し、上流 queue には不在。
    - When: POST `/api/generation/cancel`（mode=all または mode=queued）を実行。
    - Then: HTTP 202 が返却され、レスポンスの `items` に全消失ジョブが `outcome="unconfirmed"` として含まれ、DB snapshot 上の status もすべて `unconfirmed` に更新されている。
  - `test_req401_ac4_integration_released_unconfirmed_job_is_cleared`:
    - Given: 上記で `unconfirmed` になったジョブ。
    - When: POST `/api/generation/release` を実行。
    - Then: HTTP 200 が返却され、DB snapshot 上の status が `released` となり、アクティブジョブ一覧から除外される。
