## 3. 実装要件 (Implementation Logic)
- [x] 1. **動的なisMobile状態追従**:
  - `useEffect` を用い、`resize` イベントリスナーを追加して `window.innerWidth < 768` (スマホ) またはパス名 `/mobile` の時、`isMobile` を `true` に更新、それ以外は `false` にする。
- [x] 2. **アクティブなプロンプトタブの状態管理**:
  - `useState` で `activePromptTab` を定義。初期値は空文字列。
  - `useEffect` で `workflow`（マッピング定義）がロードされた際、`textMappings` の最初の要素の `role` (例: `m.role`) を `activePromptTab` の初期値として設定する。
- [x] 3. **スマホ専用1カラムレイアウトの実装**:
  - `isMobile === true` のとき、全体を縦並びの 1カラム (`flex flex-col h-full overflow-y-auto pb-20`) でレンダリングする。
  - デスクトップの右カラムにあった「画像プレビューエリア」および「履歴サムネイルストリップ」を上部に配置する（プレビューがはみ出さないように CSS のアスペクト比調整や `max-h-[300px]` などを考慮する）。
  - 中段に、「横スクロール対応のプロンプトタブ」を配置する。
    - `textMappings.map(m => ...)` を用い、タブとしてボタンを並べる。
    - コンテナは `flex overflow-x-auto whitespace-nowrap gap-2 py-2 px-1 border-b border-[rgba(255,255,255,0.06)]` 等とする。
    - 選択中のタブ（`activePromptTab === m.role`）はエメラルドグリーン（`#3ecf8e`）などでハイライトする。
  - プロンプト入力欄として、1つの `textarea` のみを配置する。
    - 選択中のマッピングに対する内容（`paramValues[activePromptTab] ?? ''`）を表示・編集可能とする。
    - アセット追加チップスも、現在アクティブな `activePromptTab` に紐づくもののみをその下に表示する。
  - 下部にパラメータ設定やLLM Auditを縦並びで配置する。
  - 画面最下部（sticky/fixed bottom-0）に「アクションバー（Generate Batch、Save Snapshot）」を固定表示する。
- [x] 4. **PC用レイアウトとの条件分岐**:
  - `isMobile` の状態に基づいて、`isMobile ? (スマホレイアウト) : (デスクトップレイアウト)` で分岐させる。
