# REQ-346-T10: A4（hover 型）の実ブラウザ検証 (AC-1〜6。AC-2/AC-4 は設計 §8-2 の読み替え)

## 設計改訂（2026-10-16・実ブラウザ所見 R1。未着手のため本文どおり実装する）
人間決定により A4 のカード上端は**ヘッダー下端＋6px**（トリガー下端＋6px ではない。設計 §4 HEO-2）。ヘッダー下端の基準は `[data-page-header-root]`（`Settings` の `h1` の祖先 `border-b` div と同一）の bbox.bottom。トリガー（`resource-hover-monitor`）下端〜カード上端の間隔は `/settings` の 1 行ヘッダーで約20px（固定6pxではない）に広がるため、ホバー継続ブリッジは**プリミティブ（`HeaderDropdown` の `hoverBridge`）が `body` 直下に描画する固定要素 `[data-testid="resource-hover-card-bridge"]`（`[data-header-menu-bridge]`）**で、高さは「トリガー下端〜カード上端＋1px」の可変（旧: モニタ内の固定7px `resource-hover-bridge` は廃止）。**前提: T11〜T14 が完了していること。** 以下の本文のうち、旧記述（トリガー下端基準・7px ブリッジ）は本節が優先する。

## 前提情報（実コードから確認済み。T5 実装後の想定構造）
- 右クラスタは `PageHeader` の `ml-auto ... shrink-0`（`overflow-*` なし）。モニタ `[data-testid="resource-hover-monitor"]`（`relative flex items-center`）は ≥640px でチップ行（`hidden sm:flex`）を表示し、`onMouseEnter`/`onMouseLeave` でホバー状態を持つ。
- ホバー時: ポータルのカード `[data-testid="resource-hover-card"]`（`role="tooltip"`、`w-[250px]`、`position: fixed`、`data-header-menu-panel`、**`top = ヘッダー下端 + 6`**、`align=end`）と、`body` 直下の固定透明ブリッジ `[data-testid="resource-hover-card-bridge"]`（`aria-hidden`、水平＝モニタの左右範囲、垂直＝モニタ下端〜カード上端＋1px）。カードの `maxHeight = vh − top − 8`（96px 未満になると自動で閉じる）。< 640px ではカードは `hidden`（`display: none`）。
- ヘッダー本体: `h1`（テキスト `Settings`）の祖先 `xpath=ancestor::div[contains(@class,"border-b")][1]`。
- ポインター位置はレイアウト変化（`setViewportSize`）で要素の外へ出得る。resize 後の判定は**各 resize 後にモニタへ再 `hover()`** してから行う（再 hover までの間にカードが閉じること自体は仕様 HEO-9(b) で、本カードの検証対象ではない）。

## 検証内容（`headerHoverCard.spec.ts`）
幅×高さ（設計 §7。≥640 のみ）: `640×800`, `768×1024`, `1024×768`, `1280×800`。`for (const v of VIEWPORTS)` でケースを生成（ケース名末尾に `@WxH`）。共通ヘルパー（spec 内）: `openSettings(page, w, h)`（`stubApi`＋`setViewportSize`＋`goto('/settings#workflows')`＋`h1` 可視待ち）、`headerBottom(page)`、`hoverMonitor(page)`（先にポインターを (5, 窓高−5) へ退避して `mouseenter` を確実に再発火させてから、モニタに `hover()`→カード可視待ち。同座標への `hover()` は移動イベントを生まないため）、`layoutSnapshot(page)`（ヘッダー高さ、`document.documentElement`／`body` の `scrollHeight`）、`pointInside(page, locator, dx, dy)`（座標の `document.elementFromPoint` がロケータ要素またはその子孫か）。

1. `[REQ-346/AC-1] A4 hover card opens below the header bottom without pushing the layout @WxH`: ホバー前後で `layoutSnapshot` の各値の差が 1px 以内（サブピクセル丸めのみ許容。押し広げは数px以上の差として検出される）。カード bbox.y >= モニタ bbox.bottom、**`|card.y - (headerBottom + 6)| <= 1`**、カード bbox.bottom > ヘッダー下端、カードの親が `document.body`。
2. `[REQ-346/AC-2] A4 hover continuity: moving the real pointer from the monitor through the gap into the card keeps it open @WxH`: モニタ下端付近（カード中心 x をモニタ幅内にクランプした座標）から `page.mouse.move(cardCenterX, card.y + 12, { steps: 15 })` でカードへ移動 → カードが可視のまま、カード内の `GPU:` 行が可視。さらにカード上で `page.mouse.wheel(0, 40)` を行ってもカードが閉じない。ブリッジが隙間を被覆していることの実証（弱めて通さない: 失敗時は `elementFromPoint` の結果要素の class/testid を失敗メッセージへ出す）: ホバー中に `[data-header-menu-bridge]` の bbox が「上端≈モニタ下端（±1px）」「下端≥カード上端」「左右＝モニタの左右範囲」を満たし、隙間の中点（モニタ中心 x、`y = (monitor.bottom + card.y) / 2`）の `elementFromPoint` がブリッジ自身であること。
3. `[REQ-346/AC-3] A4 hover card scrolls inside the viewport-capped height and the last row is reachable @1024`: 1024×768 で**ヘッダー下端 `hb`** を実測（R1: モニタ下端ではない）→ 高さ `H = ceil(hb + 6 + 100 + 8)`（`maxHeight` ≈ 100px、閾値 96px 超）で `setViewportSize({ width: 1024, height: H })` → モニタへ再 hover → `parseFloat(card.style.maxHeight)` が 96 以上 100 付近、`card.scrollHeight > card.clientHeight`（内容が高さ上限を超える）。ポインターをカード上へ移動して `page.mouse.wheel(0, 400)` → `card.scrollTop > 0`（実スクロール。ホバー継続が前提）。`GPU:` 行の bbox が `0 <= y` かつ `y+height <= H`、`pointInside` がカード内。内容がスクロール不要（`scrollHeight <= clientHeight`）なら `H` を 10px ずつ下げる（`maxHeight` が 96 未満にならない範囲）。それでも不能なら設計へ escalate（検証を弱めない）。
4. `[REQ-346/AC-4] A4 closes when the pointer leaves, when pressing outside, and has no click toggle @WxH`: (a) ポインターを (5, h−5) へ移動 → カード非表示。(b) 再 hover → `document.body` へ `pointerdown`（`page.evaluate(() => document.body.dispatchEvent(new PointerEvent('pointerdown', { bubbles: true })))`）→ カード非表示。(c) 再 hover → モニタを `click()` してもカードは可視のまま（トグル無し）。
5. `[REQ-346/AC-5] A4 hover card stays inside the viewport and is not covered @WxH`: カード bbox の `x >= 0`、`x+width <= vw`、`y+height <= vh`（高さ上限内）、カード左上+(10,10) と中心の `pointInside` が true（他要素に隠れない）。`role="tooltip"` を確認。
6. `[REQ-346/AC-6] A4 recomputes after resize while hovered and is hidden below 640px @1280`: 1280×800 でホバー → `setViewportSize(800, 400)`→ 再 hover → カード可視・viewport 内・`parseFloat(maxHeight)` が `400 − top − 8` に ±1px で一致。→ `1024×768` でも同様。→ `639×667` に縮め再 hover → カードは非表示（`toBeHidden`）かつ `[data-header-menu-panel]` が可視 0 件（孤立しない）。
7. `[REQ-346/AC-1] A4 is not shown at 639px (A3 pill is responsible)`: 639×667 で `resource-hover-monitor` に hover してもカードは非表示、`[data-header-menu-bridge]` も 0 件（カード非描画時はブリッジを出さず他要素のヒットテストを奪わない）、`mobile-vram-pill` は可視。
8. Red Team（合否判定する）:
   - `[REQ-346/AC-3] A4 auto-closes when the remaining height is below 96px`: `H = ceil(hb + 6 + 90 + 8)`（`maxHeight` ≈ 90 < 96。`hb` はヘッダー下端）でホバー → カード非表示（HEO-7）。
   - `[REQ-346/AC-4] rapid hover in/out ten times leaves no orphan panel`: モニタ上と (5, h−5) を 10 往復 → 最後に離脱した状態で `[data-header-menu-panel]` が 0 件、ホバー状態で 1 件以下。
   - `[REQ-346/AC-4] opening the header menu while the A4 card is open leaves only one body-level panel`: ホバー（カード可視）→ `[data-testid="header-kebab-menu-button"]` をクリック → `[data-header-menu-panel]` が 1 件（ケバブの `header-kebab-dropdown`）。
