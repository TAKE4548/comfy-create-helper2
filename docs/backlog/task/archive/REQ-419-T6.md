# REQ-419-T6: 一覧カードのVariant数バッジ・原子的保存ミューテーション・ステージ管理の検索語不在

## 1. 目的
Settings ワークフロータブの MappingMaster 一覧カードから旧概念 `+N classes` を除き Variant 数バッジを出す（AC-7）。編集時の保存を単一トランザクションの `atomic-save` 1回に切り替え、モーダルが結果を待てるよう `onSave` を Promise 化する（REQ-419-T5 の契約）。ステージ管理画面に検索語入力が無く、送信にも含まれないことをテストで固定する（AC-8）。

## 4. 変更仕様

### 4-1. カード（`MappingMasterSection.tsx` 現 L81-170 付近、`SortableMasterCard` 相当）
現状（抜粋）:
```tsx
  const displayName = master.name || master.display_name || ''
  const classes = master.expected_class_types ?? []
  const variants = master.variants ?? []
  ...
          aria-label={`${displayName} のマッピング設定を編集（対象ノード: ${master.param_name}${classes.length ? ' / ' + classes.join(', ') : ''}）`}
  ...
      <div className="settings-mobile-card__badges flex flex-wrap items-center gap-1.5">
        <span className="shrink-0 whitespace-nowrap ...">{master.input_type}</span>
        {classes.length > 1 && (
          <span className="shrink-0 whitespace-nowrap ...">+{classes.length - 1} classes</span>
        )}
        {variants.length > 0 ? ( ...stage chips... +{variants.length - 1} stages ... ) : (<span>-</span>)}
```
変更:
- `classes` と `+N classes` バッジを削除。
- Variant 数バッジを input_type バッジの直後に追加: テキスト `Variant ${variants.length}`、`data-testid="master-variant-count"`、`aria-label="Variant数 ${variants.length}"`、クラス `shrink-0 whitespace-nowrap px-2 py-0.5 rounded bg-zinc-800 text-zinc-400 text-[11px] font-mono`。0件でも `Variant 0` を表示。
- 編集ボタンの aria-label を `${displayName} のマッピング設定を編集（Variant ${variants.length}件）` に変更。
- 既存のステージチップ・`+N stages`（モバイル）・「新規マッピングで基本無効」バッジ・`.settings-mobile-card__target-node` 要素は維持（E2E が `.settings-mobile-card:has(.settings-mobile-card__target-node)` に依存）。

### 4-2. 原子的保存ミューテーションと Promise 化（現 L350-380、L478-485）
現状:
```tsx
  const updateMaster = useMutation({
    mutationFn: ({ id, data }: { id: number; data: MappingMasterV2Update }) =>
      mappingMastersApi.update(id, data),
    onMutate: startDraftMutation, onError: failDraftMutation, onSettled: settleDraftMutation,
    onSuccess: () => { qc.invalidateQueries({ queryKey: ['mapping-masters'] }); ... setShowEditModal(false) ... },
  })
  const handleSaveMaster = (data: MappingMasterV2Create | MappingMasterV2Update) => {
    if (selectedMaster) {
      updateMaster.mutate({ id: selectedMaster.id, data })
    } else {
      createMaster.mutate(data as MappingMasterV2Create)
    }
  }
```
変更:
- `updateMaster` の `mutationFn` を `mappingMastersApi.atomicSave(id, data as MasterAtomicSaveRequest)` に置換（REQ-419-T3 提供）。1回の保存で呼ぶ API はこの1回のみ（定義 API を呼ばない）。
- `onSuccess` で `['mapping-masters']` に加え `['binding-rules']`・`['node-selectors']` を無効化。既存の draft リスク管理・モーダルを閉じる処理は維持。
- `handleSaveMaster` を `async (data: MappingMasterV2Create | MasterAtomicSaveRequest) => Promise<void>` にし、`mutateAsync` を `await` する（失敗は reject で呼び出し側＝モーダルへ伝える）。作成は従来どおり `createMaster`。`isPending` の渡し方は不変。

### 4-3. StageManagerModal（AC-8）
現状、作成フォーム（キー・ステージ名・接尾辞）と編集フォーム（ステージ名・接尾辞・有効）に検索語入力は無い。`createStage.mutationFn` は `{ key, name, suffix }`、`updateStage` は `Partial<StageMaster>` を送る。変更不要ならコードは触らない。編集保存時に既存 `search_keywords` を送信しているなら送らないよう修正する（値の削除はしない）。

## 5. 共有コントラクト
- T5 との契約: `MappingMasterEditModal` の `onSave: (data: MappingMasterV2Create | MasterAtomicSaveRequest) => Promise<void> | void`。本カードは Promise を返し、atomic-save の失敗（422/409/ネットワーク断）で reject する。
- T3 提供: `mappingMastersApi.atomicSave(id, req)`、型 `MasterAtomicSaveRequest`。T2 提供: `POST /api/mapping-masters/{id}/atomic-save`（失敗時は全件ロールバック）。
- T7（E2E）が依存: `data-testid="master-variant-count"`、編集ボタン aria-label の接頭辞 `<名称> のマッピング設定を編集`。
