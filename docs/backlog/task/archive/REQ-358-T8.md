## Implementation Logic

### Row Identity and Order

`rows`は取込対象のマスタごとに1件のMasterMappingRowを返す単一配列。順序は呼出し元から受けたmasters配列順、各stageSlotsはそのmasterのvariants配列順（既存is_enabled filter後）。hook内でstage名/status/候補数/node_id/有効状態によるsortや別配列への移動をしない。master wrapperのReact keyはrowKey=m_<master.id>、各input keyはv_<variant.id>/legacy m_<master.id>。配列index、status、node_idをkeyにしない。object/配列の参照同一性は保証せず、identity/key/相対順序を保証する。
取込集合はhydrate前の保存stateのown key（true/falseどちらも）または保存mappingを既存証拠にし、初取込だけmaster.default_enabled!==falseを適用する。T7 hydrateSlotStatesはfalseの新規slotにもstateを作るため、返されたstateだけから取込済みを判定しない。master基本無効の未取込slotはrows/state snapshotへ追加しない。既存空欄state=true/falseも保持。表示不能な旧定義/unknownキーとmappingは送信時も保持する。現行のvariant.is_enabled選別とlegacy fallbackは維持する。
初回`scanResult===null`時は既存buildRows互換の空3配列を返す。scanが一度届いた同一hook sessionでは最新scanを保持し、refetch中の一時nullでrowsを消さない。行の初期化はmastersとscanが揃った時点で一度だけ。initFromScanの明示existingMappings/workflowJson引数は初回だけoptionsより優先、省略ならoptionsを使う。初期化後の再呼出しでdraft/stateをresetしない。mastersに新しい基本有効slotが追加されたときはそのslotだけ初取込の既定で補完し、既存draftを再初期化しない。再open/workflow切替は呼出し元T12/T13がhookをunmount/remountするsession境界であり、新reset引数は追加しない。
`mainRows/notFoundRows`は従来status分類の互換viewとして残す。新UIの入力描画・順序はrowsを使い、getMappingsの2引数には(rows, [])を渡せる。有効件数はstageSlotsまたはlegacy slotを単位にenabled===trueだけで数え、無効は必須/未検出件数から除く。multi-stage wrapperのprimary fieldだけで全slotの件数を判断しない。

### Value Precedence and Missing Reference

初回値は保存mappingのnode_id（存在するなら空文字もそのまま）→保存stateだけで既存と分かる未対応slotの''→初取込slotだけscan default→''。保存IDのtrim・候補への所属・class一致・推奨度で別IDへ置換しない。初期化済み値はupdateNodeId/updateSlotNodeId/clearSlotなど利用者の明示操作だけで変更し、scanの再応答、graph変更、masters同内容refetch、再度initFromScanがdirty draftを上書きしない。rowStateのown keyの''は確定した空欄であり、undefinedのscan fallbackと分ける。
`reference_missing`は現在node_idが非空、scanのmatched/warningsのnode_id/node_idsにもなく、提供されたworkflowJsonの実node集合にもない場合true。それ以外はfalse。graph未提供時は参照の不存在を断定せずfalse。実node集合はAPI dictのown node key、{nodes:dict}のown key、UI nodes[]のString(node.id)を使う。T8は順位計算を呼ばずT6依存を追加しない。不在の判定でnode_idは変更せず、graph再追加でflagだけfalseへ戻る。row/slotのstatusは既存scan enumのまま、UIは独立flagを「参照先なし」と表示する（T12/T13）。空欄を参照先なしにしない。非推奨でもgraph内にあればflag=false。
`getMappings(rows, [])`は有効/無効・参照先なし・非推奨に関係なく非空IDを保持し、保存済み未知slotのmappingも落とさない。保存IDは元文字列を保持する。利用者が入力したdraftの保存時trimは既存契約、空欄化の明示操作はそのslotのmappingを除去する。既存mappingをslot identityでmergeし、既知slotだけdraftで置換/削除、未知slotと追加metadataは保持する。variant null/省略はlegacy。1有効variantへのlegacy mapping fallbackは従来互換を維持し、二重送信しない。

### Enabled State Operations

`setSlotEnabled(editorSlotKey, enabled):void`は表示・取込済みslotのv_<id>/m_<id>のみ受理し、T7 slotKeyでcanonical v:<id>/m:<id>へ変換してfunctional state updateで1keyだけ変更する。他slot/unknownキーを保持、新state objectを返す。非表示/未知keyはno-opで新slotを取り込まない。node_id/rowState/mismatch/candidates/row順序を変更しない。
hookの`setStageEnabled(stageId, enabled):void`はT7 utilityを別名importし、現在の表示・取込済みSlotDefinition集合と最新stateを渡す。stageId完全一致だけ変更、再trueは対象全true、他stage/未指定stage/unknownキー保持、対象0件でもcloneというT7契約をそのまま使う。個別/一括toggleは編集操作としてdirtyにする。
enabled=falseならinputはreadonly、候補選択/clear/updateによる値変更もhookでno-opとし、再有効化toggleは使える。enabled=trueでnode_id===''はunused=trueかつ編集可。無効な空欄もunused=trueを保持するが表示は「無効」を優先する。再有効化で元IDと未使用状態をそのまま復元する。
