## Implementation Requirements

- 新規 seedModel.ts に SeedMode、SeedSettings、SEED_MODES_KEY='__seed_modes_v1'、UINT32_MAX=4294967295 を公開する。input_type==='seed' のみを専用型として判定し、カスタム名・float/int を推定しない。
- 値は paramValues[m.role] の10進整数文字列、モードは paramValues[SEED_MODES_KEY] に JSON.stringify({version:1,modes:{[slotKey]:'random'|'fixed'}}) で保存。slotKey は `master:${m.master_id}:variant:${m.variant_id ?? 'legacy'}`。同じ master の別 variant は別スロット。
- 予約キーがない旧データは fixed とする。未編集の数値を保持する。未知version、JSON破損、不正modeを含む現在使用するスロットは検証エラーとして扱い、暗黙randomにしない。削除済みスロットのmodeは使用しない。
- 整数は /^[0-9]+$/ と Number.isSafeInteger、0..UINT32_MAX で判定。空文字、負値、小数、指数表記、NaN/Infinityは生成前エラー。UIでは途中の空文字を保持できるが生成不可。
- setSeedModeForMapping は対象modeのみ更新し他欄・他スロットを保持。parseSeedValue のエラーには表示欄名を含める。slotKey/role/実書込先の重複・予約role衝突を確認する共有validationを用意する。
- resolveSeedSyncRoots は完全roleでseedの親を解決し、複数段でもroot slotKeyへ収束させる。seedが関係する混在型・複数親・循環は拒否。T3 plannerとT5表示はこの同じ関数を使う。
