## 3. 実装要件 (Implementation Logic)
1. **タブ切替時の即時フラッシュ保存 (`flushAutoSave`)**:
   - 保留中のオートセーブを即座に API 実行する共通関数 `flushAutoSave` を定義。
   - `handleSelectPresetTab(nextId)` の冒頭で、現在の `activeSetId` が存在し、かつ `nextId` と異なる場合に `flushAutoSave()` を実行。
   - L1 のデバウンスタイマーをクリアし、直ちに `performUpdatePresetRef` を同期発火して L6（サーバーDB）へ保存し、L4 (`lastSavedStateRef`) を更新。
2. **切替先プリセットのサーバー同期判定**:
   - `handleSelectPresetTab` で切替先プリセット（`nextId`）が他端末で更新されているか判定。
   - クリーン（未編集）であれば `loadPresetData(serverPreset, defaultParams)` によりサーバー最新版をロードし、L1/L2/L4 を同期。
   - ダーティ（自端末でも編集中）であれば `setConflictData` により競合解消ダイアログを表示。
3. **Dirty 状態に基づく L3 ⇄ L2 SSoT 再同期**:
   - ポーリング同期（`rawMappedSets`）において、ローカルインメモリ値の無条件スプレッド（`...(existingSet?.paramValues || {})`）を撤廃。
   - プリセットごとにダーティ（未保存編集があるか）を判定：
     - **Clean な場合**: サーバーの DB 値（`p.param_values` 等）を SSoT として採用。`mappedSets` (L2) と `lastSavedStateRef` (L4) を更新。
     - **Dirty な場合**: ローカル編集差分を保持。サーバーの `updated_at` が前進していれば競合として記録。
4. **全プリセットの L4 タイムスタンプ追跡**:
   - ポーリング受信時、クリーンなプリセットについては `presetUpdatedAtRef.current[p.id] = p.updated_at` を同期更新し、タイムスタンプ情報の欠落を解消する。
5. **Undo / Redo の L4 ベースライン保護**:
   - `undo` および `redo` において、`lastSavedStateRef.current[presetId]` を直接書き換える処理を撤廃。
   - 履歴展開によるパラメータ変更のみを Zustand/UI に適用し、真のサーバー保存ベースライン（`lastSavedStateRef`）との差分によってオートセーブが正しく発火・保存されるようにする。
