# REQ-351-T1: ParamSyncModal のロール×ステージ単位のサブ候補

## 1. 概要と目的

- 種別: change_kind = code、subsystem = frontend、実行ロール = engineer（init-task スキャフォールドのフロントマターにこれらのキーがないため本文に記載する）。
- AC-1: 代表 Main/Steps 選択時、Rough/Steps・Detail/Steps・同一型 Rough/OtherSteps がステージ名付きでサブ候補に出る。
- AC-2: 代表そのもの（Main/Steps）はサブ候補に出ない。
- AC-4（候補側）: 同一型の別ロール Rough/OtherSteps を同期先に選べる。
- AC-6（表示側）: 保存済みのステージ付き同期先が再表示時にチェック済みで復元される。代表変更時もステージ付き同期先を誤って落とさない。

原因（設計調査の推定）: `WorkflowMapping.role` はステージ接尾辞付きの `computed_role`（例 `Sampler_Steps_Rough`）だが、モーダルは型判定にマスターの legacy `role`（基底ロール）をキーとする `roleMasterMap` を使うため、ステージ付き role が `!m` で除外される。

## 4. 実装要件 (Implementation Logic)

### 4.1 `buildParamSyncCandidates` の規則
- [ ] `groupMappingsByStage(mappings, masters, stages)` の返却順（グループ順→グループ内の mapping 順）で走査する。
- [ ] role が null・空なら除外。同じ role は最初の1件だけ（`paramValues` と同期設定は role 文字列キーなので、同じ role の mapping は1つの入力値を共有する。通常は接尾辞で role が分かれるため、同じロールの別ステージは別候補になる。role が同じになる上書き設定時だけ1候補にまとまり、最初のステージ名を使う）。
- [ ] `stageName` はグループに `stageId` がある場合だけ `group.stageName`、ない場合は null。入力を変更しない。

### 4.2 `ParamSyncModal.tsx` の変更
- [ ] 1. 同じ useEffect で `stageMastersApi.list(true)`（`import { stageMastersApi } from '../api/domains/stageMasters'`）を取得して state に保持。失敗は `console.error`、stages は空配列のまま。型の受け方は `frontend/src/hooks/useMappingStageGroups.ts` と同じにする。
- [ ] 2. `candidates = buildParamSyncCandidates(activeWorkflow?.mappings ?? [], mappingMasters, stages)`。
- [ ] 3. `resolveType(role) = candidates の該当.inputType ?? roleMasterMap.get(role)?.input_type ?? null`。`name(role) = candidates の該当.displayName ?? roleMasterMap.get(role)?.display_name ?? role`。
- [ ] 4. `masterInputType = resolveType(currentMasterRole)`。サブ候補 = `candidates` のうち `role !== currentMasterRole` かつ型が非 null で代表と一致するもの。
- [ ] 5. `handleMasterChange`: `validSlaves = slave_roles.filter(r => r !== newMaster && resolveType(r) !== null && resolveType(r) === resolveType(newMaster))`。
- [ ] 6. ラベル: stageName があれば `{stageName} / {name}`、なければ `name`。2行目 `Role: {role}` は維持。代表選択の2つの `<select>`（L218-L222、L356-L360）の option も候補順・同ラベル＋` ({role})` にする。key は role（重複排除済み）。
- [ ] 7. 変更しない: `handleSlaveToggle`、`checked = activeGroup.slave_roles.includes(role)`、新規作成の初期代表 `workflowMappedRoles[0]`、グループ一覧（L253 の `masterDisp` 含む）・改名・削除・有効切替、モーダルのレイアウトクラス。
