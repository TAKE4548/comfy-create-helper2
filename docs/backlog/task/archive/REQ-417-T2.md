# REQ-417-T2: スキャン判定ロジック刷新（辞書式ソート・Entry照合）とinput_name永続化

## 1. 概要と目的
点数加算方式の古いスキャン処理を廃止し、Entry（`class_type` × `param_name`）一致を足切り必須条件とする辞書式判定アルゴリズム（段階1〜4、Entry priority、Pattern priority、node_id昇順）へ刷新する。複数ステージ間でのセレクタ競合解消（完全一致 ＞ 部分一致、部分一致同士ならより長いパターン文字列）を実装し、確定した `(node_id, input_name)` をスキャン結果および `WorkflowMapping` の永続化データとして返却する。`mapping_service.py` も新スキーマの role を用いたカスケード処理に適合させる。

## 2. ターゲット識別
- **対象ファイル**:
  - `backend/app/services/workflow_scanner.py`
  - `backend/app/services/mapping_service.py`
  - `backend/tests/integration/legacy/test_workflow_scanner.py`
  - `backend/tests/integration/legacy/test_workflow_scanner_property.py`
- **対象シンボル**: `scan_workflow_variants`, `_match_binding_entries`, `_evaluate_candidate_stages`, `_resolve_multi_stage_conflicts`

### 3.1 辞書式判定キー構造 (`backend/app/services/workflow_scanner.py`)
```python
# 段階の定義 (Stage 1: 完全一致, Stage 2: 部分一致, Stage 3: セレクタなし/不一致, Stage 4: 他セレクタ一致=除外)
STAGE_EXACT_MATCH = 1
STAGE_CONTAINS_MATCH = 2
STAGE_NO_SELECTOR = 3
STAGE_OTHER_SELECTOR = 4

def _candidate_sort_key(candidate: dict) -> tuple[int, int, int, int, str]:
    """
    辞書式ソートキー:
    1. stage_rank (1=自セレクタ完全一致, 2=自セレクタ部分一致, 3=セレクタなし/不一致)
    2. entry_priority (小さい値が高優先)
    3. pattern_priority (小さい値が高優先)
    4. numeric_node_id (小さいノードID優先)
    5. raw_node_id (安定比較用)
    """
    return (
        candidate["stage_rank"],
        candidate["entry_priority"],
        candidate["pattern_priority"],
        candidate["numeric_id"],
        candidate["node_id"],
    )
```
</hermetic_context>

## 4. 実装要件 (Implementation Logic)
- [ ] `backend/app/services/workflow_scanner.py` に `BindingRuleEntry` に基づく候補ノード抽出（class_type かつ input_name が存在）を実装する。Entry に不一致のノードは候補から即座に足切り除外する。
- [ ] 各候補ノードを自セレクタおよび同一 Master の他 Variant セレクタと照合し、段階1〜4の判定を行う：
  - 段階1: Entry一致 ＋ 自セレクタ `exact` パターン一致
  - 段階2: Entry一致 ＋ 自セレクタ `contains` パターン一致
  - 段階3: Entry一致 ＋ セレクタ未設定またはどのセレクタにも不一致
  - 段階4: Entry一致 ＋ 同一 Master の他 Variant セレクタにのみ一致（候補から除外）
- [ ] 同一ノードが複数ステージのセレクタに一致した際の競合解消を実装する：
  - 完全一致（exact） ＞ 部分一致（contains）
  - 部分一致同士の場合は、より長いパターン文字列（specificity）を持つステージを優先
- [ ] 同一 Master の Variant を `StageMaster.sort_order` 順に確定させ、確定した `(node_id, input_name)` を残りの Variant の候補プールから除外する。
- [ ] スキャン結果辞書に `input_name` を含め、1件自動確定時は `input_name` をセット、競合時は `duplicated` 警告を付与する。
- [ ] `backend/app/services/mapping_service.py` のカスケード同期処理を Variant の永続化 `role` カラムを参照するように改修する。
- [ ] `backend/tests/integration/legacy/test_workflow_scanner.py` に `test_req417_ac2_...`, `test_req417_ac3_...` を追加し、`test_workflow_scanner_property.py` に辞書式決定性の PBT（Hypothesis）を追加する。
