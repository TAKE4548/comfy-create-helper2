## 3. 実装要件 (Implementation Logic)
1. **`usePresetState.ts`**:
   - `useQuery` に `refetchInterval: 5000` および `refetchOnWindowFocus: true` を設定。
   - `lastSavedStateRef` の更新を `updatePresetMutation.onSuccess` 内に移動し、通信失敗時に未保存状態（`isDirty`）が維持されるようにする。
   - `rawMappedSets` の構築で、サーバーから取得した `p` の各属性（`param_values`, `applied_assets`, `batch_size`, `seed_mode`, `seed`）を直接正としてマッピング。
   - サーバーの `activePreset.updated_at` が前回の `presetUpdatedAtRef` から更新された場合：
     - `!isDirty`（ローカル未編集）: `currentStore.loadPresetData(activePreset, defaultParams)` を呼び出して即時同期。
     - `isDirty`（ローカル未保存編集あり）: 勝手に上書きせず、`conflictData`（`{ serverPreset, localDraft }`）をセットして競合状態へ遷移。
   - `updatePresetMutation.onError` で 409 Conflict を受信した場合も `conflictData` をセットして競合モーダルを起動可能とする。
   - 競合解決ハンドラ（`handleResolveConflictUseServer`, `handleResolveConflictOverwrite`, `handleResolveConflictSaveAsNew`）を定義・エクスポート。
2. **`multiSetSlice.ts`**:
   - `loadPresetData` において、`mergedParamValues` から生成した最新の `initialPromptChips` を `promptChips` に適用。
