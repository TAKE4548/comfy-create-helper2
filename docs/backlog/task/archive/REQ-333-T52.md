# REQ-333-T52

BE再起動失敗のread-only調査: PS stop close5s→retry close5s→start ready最低20s→ShowStatus5s＋overheadに対しAPI timeout35s。停止未確認とreadiness falseを無視し、古いlistenで成功扱いする経路がある。適正な再起動とは旧service停止が確認され、新serviceの起動確認が成功したこと。停止確認不能ならlaunchしないでnonzero、起動確認不能もnonzero。PS actionの例外は非zeroにしてAPIが明確な失敗として返す。既存background/menuの使用感・対象port・指定service範囲を維持し、他サービスを巻き込まない。既存kill方式の権限を勝手に拡大しない。

API時間予算はPS停止retry・設定ready待ち・状態確認と十分な余裕を含める。BE restartのdefaultは60秒を最低予算とし、Comfy restart50秒、all90秒等との整合を保つ。設定によるready待ちを使う場合はその予算も考慮し、固定35秒で切らない。FE T50のaction待機は120秒。成功ACKだけでrunningを捏造しない。

## Impacted Files
- tools/server-manager/server-manager.ps1
- tools/server-manager/server_api.py
- tests/unit/test_server_manager_timeout.py
