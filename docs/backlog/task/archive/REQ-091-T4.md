# TASK-REQ-091-T4: Frontend Zustand Store State & Send Bypass Integration

## 1. ターゲット識別
- **対象ファイル**:
  - `frontend/src/store/useGenerationStore.ts`
  - `frontend/src/pages/GeneratePage/hooks/useGenerateAction.ts`
- **対象シンボル**:
  - `GenerationState` (ステート定義)
  - `bypassProfiles` (新規ステート)
  - `errorToast` (新規ステート)
  - `queuePrompt` (エラーハンドリング強化)

## 2. 密閉コンテキスト (Hermetic Context)
<hermetic_context>
`queuePrompt` 実行時の HTTP POST レスポンスのハンドリング部分。
</hermetic_context>

## 3. 実装要件 (Implementation Logic)
- **`useGenerationStore.ts`**:
  - `bypassProfiles: BypassProfile[]`（デフォルト `[]`）および `errorToast: { message: string; type: 'error' | 'success' } | null`（デフォルト `null`）をステートに追加。
  - アクション `fetchBypassProfiles(workflowId)`、`createBypassProfile(workflowId, name, nodeIds)`、`updateBypassProfile(profileId, data)`、`deleteBypassProfile(profileId)` を追加（FastAPI バックエンドのAPIエンドポイントを呼び出す）。
  - `setErrorToast` アクションを追加。
  - `queuePrompt` で ComfyUI POST 時にエラー（HTTP 4xx/5xx 等）をキャッチした場合、レスポンス JSON の詳細（`error.message` や `error.details` 等）を抽出し、`setErrorToast` でエラーをセットする。
- **`useGenerateAction.ts`**:
  - 送信前の `wfJson` をディープコピーし、`bypassProfiles` のうち `is_enabled === true` となっているプロファイルの `bypassed_node_ids` の和集合を取得。
  - 和集合が空でなければ、`applyBypass(wfJson, activeBypassNodeIds, comfyObjectInfo)` を呼び出してバイパスされたワークフローJSONを生成し、それを `queuePrompt` に渡す。
