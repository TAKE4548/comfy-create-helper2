## 変更内容
1. **キー追加**（`localStorageKeys.ts`）: `VRAM_GUARD_LIMIT: 'prompt-surgeon-vram-guard-limit',`。既存キー・コメントは変更しない。
2. **読み出し純粋関数**（`VramGuardSection.tsx` に export）:
```ts
export const VRAM_LIMIT_MIN = 2.0
export const VRAM_LIMIT_MAX = 14.0
export const VRAM_LIMIT_DEFAULT = 4.0
export function readStoredVramLimit(raw: string | null): number  // 非数/空/null→4.0、数値は 2.0..14.0 にclamp
```
3. **永続化（write-through ミラー）**: `useState(() => readStoredVramLimit(safeGetItem(LS_KEYS.VRAM_GUARD_LIMIT)))`。`minFreeGb` が変化するたび `localStorage.setItem(LS_KEYS.VRAM_GUARD_LIMIT, String(minFreeGb))`（try/catch、例外は無視して画面継続）。サーバ取得値は従来どおり「dirtyでなければ」state上書き（サーバ値が正）→その結果もミラーされる。保存成功時の `dirtyRef` 解除・`noNewerEdits` 判定など**既存の競合制御ロジックは変更しない**（保存成功後はdirty=falseとなりサーバ応答値が採用され、LSも同値へ同期される）。スライダーとnumber入力のどちらの操作でも同期される（`updateDraft`経由）。
4. **2ペイン**: 設定本体（ローディング後ブロック）を `grid grid-cols-1 gap-4 lg:grid-cols-2` にし、**左ペイン=ステータス＋VRAMメーター、右ペイン=閾値入力（number・range・目盛り）とガード有効トグル**。保存ボタン/トースト/エラーのヘッダは全幅で現行維持。
5. **閾値インジケーター**: 縦線を **黄色**（`bg-amber-400`）にし `data-testid="vram-threshold-line"`、位置 `left: clamp(minFreeGb/totalGb*100, 0, 100)%`。閾値タグ `data-testid="vram-threshold-tag"` に `閾値: {minFreeGb.toFixed(1)} GB`（既存の「閾値:」表示を流用）。**スライダー操作の即時（保存前）に追従**し、HTTP/WS呼出は保存ボタン押下時のみ。
6. **警告色**: `free < limit` → 赤（`bg-red-500/70`、タグ`閾値未満 (警戒)`は赤系）、`limit <= free < limit + 1.0` → 黄（`bg-amber-500/70`、`接近`バッジ `閾値に接近`）、それ以外 → 緑。`currentFreeGb == null` は従来どおり状態不明。`totalGb`/`free` が null/0 でも NaN を描画しない（RT-8）。
7. スライダー/数値入力/トグルの操作領域を44px化（`min-h-11`、range は `h-11` の透明ヒット領域＋`touch-action: pan-y`で縦スクロールを阻害しない）。トグルの `label` は入力に限定した判定（広域クリックを避ける）。
