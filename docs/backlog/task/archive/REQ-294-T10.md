## 調査の起点

- `TestVramGuardAPI.clean_settings` autouse fixture は `get_db_context()` でDELETEするが、先に `AppSetting` テーブルの存在を保証しない。
- `backend/app/main.py` の `models.Base.metadata.create_all(bind=engine)` は lifespan 内。失敗テストは `TestClient(app)` を context manager なしで作る。
- `backend/tests/conftest.py` は DB pool leak を検出するが、テーブル作成はしない。
- DB順序依存を独立実行と全体実行で再現・確認し、fixtureのDB準備を最小限で修正する。共用DBを `drop_all` しない。Production router/service は変更しない。
