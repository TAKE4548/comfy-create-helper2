# REQ-412-T1: ComfyUIメモリ解放ロジックの共有フック抽出とSettingsの移行

## 1. 概要と目的

Settings system 欄（`ServiceConnectionCard.tsx`）に閉じている ComfyUI メモリ解放の有効条件・理由文言・送信処理を、新規の共有フック `frontend/src/hooks/useComfyFreeMemory.ts` へ抽出する。同一タブ内の Manager 操作ロックをモジュール共有ストアにし、Settings とヘッダー（後続 T2）のどちらから押しても二重送信にならないようにする。Settings の既存の振る舞い（REQ-380）は、未確認文言の先頭に「要求結果未確認: 」が付く点を除き変えない。

## 4. 実装コンテキスト

### 4.1 共有契約（そのまま実装すること）

```ts
// frontend/src/hooks/useComfyFreeMemory.ts
import { useSyncExternalStore } from 'react'
import { ManagerActionOutcomeUnknownError, systemManagerApi } from '../api/domains/systemManager'
import type { ManagerStatus } from '../api/domains/systemManager'
import { useManagerStatus } from './useManagerStatus'

export const FREE_MEMORY_OPERATION_KEY = 'comfy:free-memory'
export const FREE_MEMORY_MESSAGES = {
  pending: '解放要求を送信中',
  accepted: '解放要求を受け付けました。空き容量は監視値で確認してください',
  unconfirmed: '要求結果未確認: 解放要求の結果を確認できません。状態を再取得します。操作は再送しません。',
  failedPrefix: '解放要求に失敗しました: ',
} as const

export type FreeMemoryFeedbackKind = 'none' | 'pending' | 'accepted' | 'unconfirmed' | 'failed'
export interface FreeMemoryFeedback { kind: FreeMemoryFeedbackKind; message: string }
export interface FreeMemoryGuardInput { status: ManagerStatus | null; available: boolean; localOperation: string | null }
export interface FreeMemoryGuard { enabled: boolean; reason: string }

export function deriveFreeMemoryGuard(input: FreeMemoryGuardInput): FreeMemoryGuard
export function tryBeginManagerOperation(key: string): boolean // 既に取得済みなら false（同期・即時）
export function endManagerOperation(key: string): void          // 現在の key と一致する時だけ解放
export function useManagerOperation(): string | null
export function resetManagerOperationStoreForTests(): void      // operation=null, feedback={kind:'none',message:''}
export interface UseComfyFreeMemoryOptions { onAccepted?: () => Promise<unknown> | void }
export interface UseComfyFreeMemoryResult extends FreeMemoryGuard {
  pending: boolean            // operation === FREE_MEMORY_OPERATION_KEY
  feedback: FreeMemoryFeedback // モジュール共有（全インスタンスで同じ最新結果）
  run: () => Promise<FreeMemoryFeedback | null> // 不成立・ロック失敗時は送信せず null
}
export function useComfyFreeMemory(options?: UseComfyFreeMemoryOptions): UseComfyFreeMemoryResult
```

**ガード（既存 L35-L41 と同一の条件・優先順）**: `managerAvailable = available && status !== null`、`busy = status?.action_in_progress != null || localOperation !== null`。
`enabled = managerAvailable && !busy && comfy.status === 'LISTEN' && comfy.execution_state === 'idle' && comfy.queue_running === 0 && comfy.queue_pending === 0`。
理由（enabled なら `''`）: 未接続 `Manager状態を確認できません。` → busy `別のサービス操作中です。` → 非 LISTEN `ComfyUIが停止中または状態不明です。` → executing `ComfyUIで生成中です。` → queued または件数≠0 `ComfyUIのキューが空ではありません。` → その他 `ComfyUIの実行状態が不明です。`

**`run()` の手順**（既存 `runFreeMemory` と同一順序）:
1. 最新のガードが不成立、または `tryBeginManagerOperation(FREE_MEMORY_OPERATION_KEY)` が false なら `null` を返す（POST しない）。
2. feedback を `{kind:'pending', message: pending}` にする。
3. `await systemManagerApi.freeMemory()`。成功 → `accepted`、続けて `await options.onAccepted?.()`。`ManagerActionOutcomeUnknownError` → `unconfirmed`。その他 → `failed`（`failedPrefix + (error instanceof Error ? error.message : String(error))`）。
4. finally: `try { await refetch(); await refetch() } finally { endManagerOperation(FREE_MEMORY_OPERATION_KEY) }`。
5. 最終 feedback を返す。`onAccepted` の例外は握りつぶさず既存と同じく finally を通す（既存は `invalidateQueries` を try 内で await）。
