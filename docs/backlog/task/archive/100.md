## 3. 実装要件 (Implementation Logic)
### 3-1. Zustandストア (`useGenerationStore.ts`) の修正
1. **`openPresetIds` 状態とアクションの追加:**
   - 状態 `openPresetIds: (string | number)[]` を追加する。
   - `openPreset(id)` / `closePreset(id)` アクションを追加し、`localStorage`（キー: `prompt-surgeon-open-presets-{workflowId}`）へ書き込み保存する。
2. **`initSets` の修正:**
   - 読み込み時に `localStorage` から `openPresetIds` を取得し、なければ `[initialSet.id]` とする。
3. **`addSet` の修正:**
   - 新規作成したセットのIDを `openPresetIds` に追加する。
4. **`removeSet` の修正 (タブを閉じる):**
   - DBからの実削除は行わず、`closePreset(id)` を呼び出す（`openPresetIds` から除外し `localStorage` を更新）。
   - アクティブだったタブを閉じた場合、残りの `openPresetIds` の最初の要素、または空なら null を `activeSetId` にセットする。

### 3-2. 状態フック (`useGeneratePageState.ts`) の修正
1. **アクティブプロファイルの強制 (未選択防止):**
   - プリセット同期の `useEffect` 内で、`activeSetId` が無効（null、または `openPresetIds` に含まれない）かつ `presets` が存在する場合、自動的に `openPresetIds[0]` または `presets[0].id` をアクティブにする。
   - `presets` が空の場合、デフォルトプロファイルを作成する処理を実行する。
2. **Undo/Redo履歴管理スタックの実装:**
   - プロファイルIDごとに `past` / `future` の `HistoryState[]` を保持するメモリ上オブジェクト `historyMap` を Zustand またはフック内に実装する。
   - パラメータ値の変更デバウンスのタイミングで、変更前の状態を `past` にプッシュする（直近と変化がない場合はプッシュしない）。
   - `undo(presetId)` / `redo(presetId)` アクションを実装し、状態を復元した際に自動保存が走るようにする。
