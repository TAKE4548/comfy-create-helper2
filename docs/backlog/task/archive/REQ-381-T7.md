## T0 Draft registry integration

T0の `useSettingsDraftRegistration(resourceId,{cancelQueued,discardLocal})` は `{update(risk),clear()}` を返す。riskは `{dirty,invalid,failed,queued,inFlight}:boolean`。unique instance ID/resourceで登録し、raw値をregistryへ渡さない。edit/commit/ack/errorで同期updateし、cleanup/成功baseline一致/明示cancelで適切にclearする。mobile/desktopとも登録する。

Cancel navigationはdraft/queueを変えない。確認中inflight保存は通常完了するが、Leaveは全persist inFlight==falseまでdisabled。explicit Leave時だけ未送信queueを同期停止しlocal draftを破棄するcallbackを提供し、remote successのrollbackやautomatic retryをしない。同Settings hash/query切替とresizeだけでは破棄しない。previewなど非persist要求は保存inFlightに数えない。

T0 guardを実production画面で確認する。LLM/Bubble/Translation/toneなど実draftを作りNavLink PUSH/戻るPOP→Cancelで値/errorを保持、Leaveでtargetへ一度移動。保存遅延中Leave disabled・success/fail後も自動遷移なし、直前blur送信race、同Settings hash/query維持、clean不発、native reload beforeunload dialog、767/768両幅を追加。REPLACEはT0の実data-router testで検証。historyやhandlerのmonkey patchを使わない。

### 通信失敗・離脱・swipeの実施方法

PUT Aをtransportで保留中にBを実fieldへ編集/確定し、同resource最大1要求/最終B、古いack/refetchがBを上書きしないこと。503/422はHttpResponse body相当のJSON errorで返し「未保存/失敗」保持・自動再送0・明示再試行後だけrequest増加を確認。timeout/rejectは結果不明をsuccessにせず観測する。empty/範囲外rawは0PUT、invalid表示。localStorage拒否はbrowser sandboxの保存I/O境界だけに注入し、内部save logicをpatchしない。

離脱は実nav `#nav-history-mobile`（desktopは#nav-history）、confirm dialog名「未保存の設定」内Cancel→path/最新draft/error維持、Leave→targetへ一度。tone dialogにもCancelがあるのでconfirm内へscope。inflight中Leave disabled、settle後も自動移動なし。POPは先にHistory→実Settings navでSPA履歴を作ってからpage.goBack。reload前にnative beforeunload dialog handlerを登録しdismiss、browserの取消abortと真のerrorを区別する。

swipeはtouch対応のcase専用browser context/pageを使い、既存desktop caseのcontext設定を一括変更しない。Chromium CDP `Input.dispatchTouchEvent` のtouchStart→touchMove→touchEnd（複数move/pointで縦先行/多点）などnative入力を利用し、DOMに合成pointer eventを注入しない。非interactive開始点は本文card間余白のrectから選び、elementFromPointを観測してinput/button/横scrollでないことを確認する。tab aria-selected、URL hash、panel可視、scrollTopをbefore/afterで観測。mouse swipeでtouch対応PASSを主張しない。
