## Purpose

POST残存差分APIをGeneration既存clientへ追加し、不正応答を表示へ混ぜない。

## Hermetic Context

Exact endpoint contract: backend route is `POST /api/generation/history/residual`. The existing frontend `call()` helper already supplies the `/api` base, so pass `/generation/history/residual` to `call()`; do not include `/api` twice and do not add a GET fallback.

~~~ts
interface ImageIdentity { filename: string; subfolder: string; type: string }
interface ResidualHistoryRequest { known: ImageIdentity[]; examined: ImageIdentity[] }
interface ResidualHistoryItem {
  identity: ImageIdentity; view_url: string; session_id: string | null; availability: 'present'
}
interface ResidualHistoryResponse {
  items: ResidualHistoryItem[]
  rejected: Array<{ identity: ImageIdentity; availability: 'missing' | 'unknown' }>
  has_more: boolean
}
~~~
~~~ts
generationApi.residualHistory(body: ResidualHistoryRequest,
 signal?: AbortSignal): Promise<ResidualHistoryResponse>
export function decodeResidualHistoryResponse(value: unknown): ResidualHistoryResponse
~~~

## Implementation Logic

- [ ] 型をexportし、新APIをcall<unknown>のPOST/body/AbortSignal付きで呼び厳格decoderへ渡す。
- [ ] itemsはpresentのみ、identityと同一origin /api/comfy/viewまたは正規化/view URL一致を検証。host任意URL/identity不一致/重複identity/不正availability/空page+has_more=trueをreject。
- [ ] items/rejected合計<=10、identity正規化の型、session_id null|string、has_more booleanを検証。HTTP404/503/timeoutをmissingへ変換しない。
- [ ] unitでbody/headers/signal、known host/tなし、不正本文、422/503例外、no fallbackを確認。
