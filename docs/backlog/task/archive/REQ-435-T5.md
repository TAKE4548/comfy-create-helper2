# REQ-435-T5: Generate MobileLayout の余白整理・単一進捗バー化・メニュー統合配線・パラメータステージグループ化

> 本 Task Card は本タスクの唯一の意味仕様書（sole semantic specification）である。実装時の追加調査が必要な場合は dev-task の有界調査規則に従い、未解決事項は推測せずエスカレーションすること。

## 1. 概要と目的
`MobileLayout` および `PromptSectionClipboardMenu` に対し、(1) セクションタブ・プロファイル行・プロンプトタブ・プロンプトツールバーの視覚外形スリム化＋非重複 Hit-Slop ≥ 44×44px、(2) プリセットタブ統合メニューの「このタブを閉じる」配線、(3) 生成中の進捗バーを上部ステータスヘッダーの実行中 job 1 本に統合＋全体進捗 `n/m` 文字表示、(4) Mobile `ParamPanel` のステージグループ化＆折り畳み有効化を実装する。

## 2. ターゲット識別（Impacted Files）
- `frontend/src/pages/GeneratePage/components/MobileLayout.tsx`（L480–881）
- `frontend/src/pages/GeneratePage/components/PromptSectionClipboardMenu.tsx`（L80–104）

### 4.1 単一進捗バー＋`n/m` 文字表示（`MobileLayout.tsx` L480–570）
```tsx
import { isActiveJobStatus, selectMobileOverallProgress, selectProgress, selectUnconfirmedJobs, selectWait } from '../../../utils/generationSelectors'
// ...
const mobileOverallProgress = selectMobileOverallProgress(normalProgress, activeBatch, isGeneratingHere)

// mobile-sticky-status-header (画面上唯一の生成中進捗バー):
<div data-testid="mobile-sticky-status-header" data-test-progress-line="true" className="sticky top-0 z-40 h-6 min-h-6 bg-surface-2/95 backdrop-blur border-b border-white/5 px-3 flex items-center justify-between gap-2 text-[11px] font-mono text-zinc-300">
  <span className="truncate flex-1 min-w-0" data-testid="mobile-progress-line">
    {displayProgressActive ? displayNodeName : vramWaitStatus?.isWaiting ? 'VRAM解放待ち' : (generationSnapshot ? Boolean(normalWait?.kind === 'session') : isOtherSessionGenerating) ? '他セッションで生成中' : '待機中'}
  </span>
  {displayProgressActive && mobileOverallProgress && (
    <span data-testid="mobile-overall-progress-text" className="shrink-0 font-semibold text-accent-green ux-numeric">
      {mobileOverallProgress.label}
    </span>
  )}
  {showCompletionNav && (
    <button type="button" data-testid="mobile-completion-nav-btn" ...>生成完了: 最新画像を表示</button>
  )}
  <span className="shrink-0 ux-numeric">{displayProgressActive ? `${Math.round(displayNodePercentage)}%` : '—'}</span>
  <span className="shrink-0 ux-numeric">ETA {displayProgressActive ? (eta === null ? '未取得' : `${eta}秒`) : '未取得'}</span>
  {displayProgressActive && (
    <span
      data-testid="mobile-running-job-progress-bar"
      role="progressbar"
      aria-label="実行中ジョブ進捗"
      aria-valuenow={Math.round(displayNodePercentage)}
      aria-valuemin={0}
      aria-valuemax={100}
      className="absolute bottom-0 left-0 h-0.5 bg-accent-green transition-all duration-200"
      style={{ width: `${displayNodePercentage}%` }}
    />
  )}
</div>

// mobile-progress-section (displayProgressActive 時は進捗バーを描画せず、経過・残り・Queue の1行のみ描画):
```

## 5. 実装要件
- [ ] `MobileLayout.tsx`:
  - 上部ステータスヘッダーの進捗バーを実行中 job 進捗（`displayNodePercentage`）1 本にし、`data-testid="mobile-overall-progress-text"` で `n/m` を表示。`mobile-progress-section` の生成中 2 本バーを削除し、経過時間・ETA・Queue 導線の 1 行のみ表示する（AC-7, AC-8）。Ready 状態も余分な 0% バーを削除しスリム化する。
  - セクションタブ・プロファイル行・プリセットタブ列・プロンプトタブ・プロンプトツールバーに `<constraints>` の Hit-Slop と余白整理を適用（AC-1, AC-2）。
  - `PresetTabItem` から `onRemove` を削除、`PresetTabCloseMenu` に `onCloseSingle` を接続（AC-4, AC-5, AC-6）。
  - `<ParamPanel>` に `stageGrouping={true}` と `workflowId={selectedWorkflowId}` を渡す（AC-13, AC-14, AC-15, AC-16, AC-17）。Mobile プロンプト欄にはステージ折り畳みを追加しない。
- [ ] `PromptSectionClipboardMenu.tsx`:
  - コピーボタン・メニューボタンに `data-tap-target-exempt` とモバイル Hit-Slop（`md:before:hidden`）、ラッパー `gap-4 md:gap-1` を適用（AC-1, AC-2）。Desktop 外観は維持。
- [ ] `MobileLayout.test.tsx`:
  - `[REQ-435/AC-1]`, `[REQ-435/AC-4]`, `[REQ-435/AC-6]`, `[REQ-435/AC-7]`, `[REQ-435/AC-8]`, `[REQ-435/AC-13]`, `[REQ-435/AC-14]`, `[REQ-435/AC-17]` のテストを追加（進捗バーが 1 本のみ、`n/m` の進行、経過/ETA/Queue/完了導線維持、パラメータステージグループ＆折り畳み、値保持）。
