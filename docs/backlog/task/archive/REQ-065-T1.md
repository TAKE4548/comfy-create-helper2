## 3. 実装要件 (Implementation Logic)

### 3.1 並び替えロジックの改善
- `LoRAsPage.tsx` と `TagsPage.tsx` の `handleDragEnd` において：
  - `isMultiSelectMode` の時、`over.id` が `selectedIds` に含まれている場合は何もせずに `return` する（グループ内へのドロップによる先頭誤ジャンプを防止）。
  - `insertAt` の決定方法を改善する：
    - `items` 配列における `active.id` のインデックス (`activeIdx`) と `over.id` のインデックス (`overIdx`) を比較。
    - 下方向への移動（`overIdx > activeIdx`）の場合、`nonSelected.findIndex(i => i.id === over.id) + 1` を挿入インデックスとする。
    - 上方向への移動（`overIdx < activeIdx`）の場合、`nonSelected.findIndex(i => i.id === over.id)` を挿入インデックスとする。

### 3.2 一括編集のマージ対応
- `LoRAsPage.tsx` の `bulkUpdateLoras` において：
  - `selectedIds` 内の各 `id` について、`items` から既存の `lora` オブジェクトを特定する。
  - 送信する `updatedLora` オブジェクトを構築する：
    - `model_name` などの必須フィールドは既存のものを使用。一括編集値（`values`）に含まれる値があれば上書き。
    - `trigger_word_sets` は既存の `words` を `{ name: tws.name, words: tws.words }` 形式にマッピングする。
  - `lorasApi.update(id, updatedLora)` を呼び出す。
- `TagsPage.tsx` の `bulkUpdateTagSets` において：
  - 各 `id` について `items` から既存の `tagSet` を特定する。
  - 同様に `values` で既存データをマージした完全なオブジェクトを作成し、`tagSetsApi.update(id, updatedTs)` を呼び出す。
