### 2.1 型定義とパーサー (`useChipParser.ts`)
```typescript
export type TagChip = {
  id: string;
  text: string;
  enabled: boolean;
};
export type TagChipType = TagChip;

export const chipsToString = (chips: TagChip[]): string => {
  return chips
    .filter((chip) => chip.enabled)
    .map((chip) => chip.text)
    .join(', ');
};

export const parseToChips = (text: string): TagChip[] => {
  if (!text) return [];
  return text
    .split(',')
    .map((s) => s.trim())
    .filter(Boolean)
    .map((t, idx) => ({ id: `${Date.now()}-${idx}`, text: t, enabled: true }));
};
```

## 3. 実装要件 (Implementation Logic)

1. **マウント時親通知の完全遮断 (流入防止)**:
   - `isMountedRef` または `isInitialMountRef` を導入し、コンポーネント初回マウント時の内部通知 Effect において `onChipsChange` や `onChange` を呼び出さない（マウントは表示初期化であり変更ではない）。未同期時の `{ [role]: [] }` 逆流を構造的に根絶する。

2. **親通知の上り通信を「ユーザー直接操作」のみに限定**:
   - `const userEditedRef = useRef(false);` を新設。
   - ユーザーが手動で行った操作（タグ追加、削除、トグル、編集、ドラッグ並べ替え、テキスト入力、モード切替確定）のハンドラ内でのみ `userEditedRef.current = true;` をセットする。
   - 内部通知 Effect (`useEffect([state, ...])`) において:
     - `isExternalUpdateRef.current === true` の場合はフラグを落として return（下り更新の打ち返し遮断）。
     - `userEditedRef.current === false` の場合は、親への `onChange` / `onChipsChange` を呼び出さない（親からの値到着等の下り同期を「変更」と誤認して親へ打ち返す自己破壊ループを完全根絶）。
     - `userEditedRef.current === true` の場合（ユーザーによる明示的操作）のみ親へ通知し、通知完了後に `userEditedRef.current = false;` にリセットする。

3. **下り方向同期（親/BE → 子）の自己修復**:
   - `chipsProp !== undefined` かつ `chipsProp.length === 0` であっても、外部 `value` が非空（`value && value.trim() !== ""`）である場合は、空チップで潰さず `parseToChips(value)` によりチップを自律復元する。
   - REQ-222で対応した `value` 外部変更同期（セクションコピペ等）を維持する。

4. **単体テスト拡充 (`TagChipEditor.test.tsx`)**:
   - **Case 5**: 初回マウント時に `onChipsChange` が空配列で呼ばれないこと、および親からの遅延 `value` 到着時に `onChange("")` が発火せず正常にチップが表示されることを検証。
   - **Case 6**: `chips=[]` かつ `value="cat ears, tail"` が渡された場合、チップが自律復元されることを検証。
   - **Case 7**: ユーザーが明示的にタグチップを全削除した場合にのみ、正しく `onChange("")` が発火することを検証。
