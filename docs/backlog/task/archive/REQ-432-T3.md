# REQ-432-T3: VRAM 解放待ち表示の保留理由区別

## 1. 概要と目的
Backend は `SYSTEM_STATS` に保留理由（`vram_hold_reason`）と判定用空き（`vram_guard_free_gb`）を追加する（T1 で実装。本カードでは契約として凍結済み）。Backend は自セッション残留（ComfyUI 保持分）を判定から除外するため、保留が起きるのは外部占有（`external`）か占有元を判別できない場合（`unattributed`。ComfyUI 値が取得できずホスト値で判定したとき）だけである。待機表示で理由を区別し、「空き」には判定に使った値を表示する。

## 4. 契約と表示規則

### C4（Backend 配信、凍結済み）
`SYSTEM_STATS.data` に追加される任意フィールド（旧 Backend では欠落しうる）:
| キー | 型 | 意味 |
|---|---|---|
| `vram_guard_free_gb` | number\|null | 判定用空き（自セッション残留を除外済み） |
| `vram_own_residual_gb` | number\|null | 自セッション残留（ComfyUI torch 予約量） |
| `vram_hold_reason` | `'external'`\|`'unattributed'`\|null | 保留理由（保留中のみ非 null） |
| `vram_measure_source` | `'comfyui'`\|`'host'`\|null | 判定値の取得元 |
`vram_safe` の型は不変（意味は判定用空き ≥ 閾値）。`vram_free_gb` は物理空きのまま。

### C7（本カードで実装）
```ts
export interface VramWaitStatus {
  isWaiting: boolean;
  freeGb: number | null;
  requiredGb: number;
  waitDurationSec: number;
  reason?: 'external' | 'unattributed';
}
export interface SystemStats {
  // 既存フィールドは維持し、以下を追加
  vram_guard_free_gb?: number | null;
  vram_own_residual_gb?: number | null;
  vram_hold_reason?: 'external' | 'unattributed' | null;
  vram_measure_source?: 'comfyui' | 'host' | null;
}
```
`reason` は任意フィールドとする（既存テストのフィクスチャは `reason` なしで型が通ること）。

### 表示規則
- `useGenerateAction.update`: `lastFreeGb = stats.vram_guard_free_gb ?? stats.vram_free_gb ?? lastFreeGb`。`reason = stats.vram_hold_reason ?? undefined`（`'external'`/`'unattributed'` 以外は undefined）。`nextWaitStatus` に `reason` を含め、差分比較にも `reason` を加える。
- 10 秒トースト: `reason === 'unattributed'` のときだけ `'VRAM解放待ちが継続しています。占有元を判別できません（キャンセル可能）'`。それ以外は既存文言 `'VRAM解放待ちが継続しています。他プロセスの終了待機中（キャンセル可能）'` のまま。
- Desktop ステータスバー見出し: `unattributed` → `VRAM解放待ち（占有元を判別できません）`。それ以外（`external`・未定義）→ 既存 `VRAM解放待ち（他プロセスの終了待機中）`。
- Mobile バナー見出し: `unattributed` → `VRAM解放待ち（占有元未確認）`。それ以外 → 既存 `VRAM解放待ち（待機中）`。
- 数値表示行（空き / 必要 / 秒数）の書式は変更しない。
