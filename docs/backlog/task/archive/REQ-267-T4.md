## 1. 目的とスコープ
1. **保存失敗時の FE エラー通知（UX 防御）**:
   `useSnapshotActions.ts` の `saveSnapshot` （`useMutation`）に `onError` ハンドラを追加し、BE から HTTP 502 等のエラーが返却された際に `useGenerationStore.setErrorToast` でユーザーに「スナップショットの保存に失敗しました」と画面上に明確に通知する。
2. **履歴表示の防御的プロキシフォールバック**:
   `HistoryPage.tsx` および関連ビューにおいて、万一サムネイルが生成されていない古いスナップショットや外部 ComfyUI URL を含むレコードが存在した場合でも、直接到達不能なポート 8188 を直接参照せず、バックエンドのサムネイル・画像プロキシを介して表示できる防御的フォールバックを施す。
3. **フロントエンド単体テストの拡充**:
   エラーハンドリングおよびフォールバック描画のテストを追加する。

## 4. 実装要件・手順
1. **`useSnapshotActions.ts` のエラーハンドリング追加**:
   - `useGenerationStore` から `setErrorToast` を取得。
   - `saveSnapshot` mutation に `onError: (error: any) => void` を追加：
     - `setErrorToast({ type: 'error', message: 'スナップショットの保存に失敗しました。画像の取得エラーが発生しました。' })` を実行。
     - モーダルは閉じる、または維持して再試行可能にし、ボタンのローディング状態を解除。
2. **サムネイル URL 解決の防御的強化**:
   - `HistoryPage.tsx`（および `AlbumDetailView.tsx`）のサムネイル描画箇所において、`toThumbnailUrl` ヘルパーを適用：
     - `src={snap.thumbnail_path || toThumbnailUrl(snap.image_path)}`
     - これにより、万一 `thumbnail_path` が欠落していても、ComfyUI `/view` 形式であれば `/api/comfy/thumbnail?...` 経由で安全に画像が表示される。
3. **モーダルプレビューの画像 URL 解決**:
   - `lightboxImages` の算出時、外部 ComfyUI URL（`/view?`）が含まれる場合はバックエンドプロキシ `/api/comfy/view?...` を利用できるようフォールバック対応。
4. **フロントエンド単体テストの拡充**:
   - `useSnapshotActions.test.ts` に保存失敗時の `setErrorToast` 呼び出しテストを追加。
   - `HistoryPage.test.tsx` に通常相対パスおよびフォールバック画像の描画テストを追加。
