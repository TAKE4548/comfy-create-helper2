## REQ-068-T1: WorkflowPreset に sort_order 追加 + DB マイグレーション

**対象ファイル**:
- `backend/app/models.py`
- `backend/app/schemas/preset.py`
- `backend/scripts/migrate_preset_sort_order.py`（新規）

**実装内容**:

```python
# models.py — WorkflowPreset クラスに追加
sort_order: Mapped[int] = mapped_column(Integer, nullable=False, default=0)
```

```python
# schemas/preset.py — WorkflowPresetBase に追加
sort_order: int = 0
```

```python
# migrate_preset_sort_order.py（新規マイグレーションスクリプト）
# SQLite に sort_order カラムを追加し、既存レコードに id 昇順で sort_order を振り直す
import sqlite3, os
DB_PATH = os.environ.get("DB_PATH", "db/prompt_surgeon.db")
con = sqlite3.connect(DB_PATH)
try:
    con.execute("ALTER TABLE workflow_presets ADD COLUMN sort_order INTEGER NOT NULL DEFAULT 0")
except:
    pass  # 既に存在する場合は無視
rows = con.execute("SELECT id FROM workflow_presets ORDER BY id ASC").fetchall()
for i, (pid,) in enumerate(rows):
    con.execute("UPDATE workflow_presets SET sort_order = ? WHERE id = ?", (i, pid))
con.commit(); con.close()
print("Migration complete.")
```

また `routers/presets.py` の `list_presets` のソート順を変更:
```python
# 変更前
q.order_by(models.WorkflowPreset.id.desc())
# 変更後
q.order_by(models.WorkflowPreset.sort_order.asc())
```

**AC 対応**: AC-6（並び替え永続化の前提）

## REQ-068-T2: POST /api/workflows/{id}/copy エンドポイント追加

**対象ファイル**:
- `backend/app/routers/workflows.py`
- `backend/app/schemas/workflow.py`

**新規スキーマ**:
```python
# schemas/workflow.py に追加
class WorkflowCopyRequest(BaseModel):
    name: str
```

**ルーター追加**:
```python
# routers/workflows.py に追加
@router.post("/{workflow_id}/copy", response_model=schemas.WorkflowSummary, status_code=status.HTTP_201_CREATED)
def copy_workflow(workflow_id: int, payload: schemas.WorkflowCopyRequest, db: Session = Depends(get_db)):
    src = db.query(models.Workflow).filter(models.Workflow.id == workflow_id).first()
    if not src:
        raise HTTPException(status_code=404, detail="Workflow not found")
    existing = db.query(models.Workflow).filter(models.Workflow.name == payload.name).first()
    if existing:
        raise HTTPException(status_code=409, detail="Workflow name already exists")
    new_wf = models.Workflow(
        name=payload.name,
        json_body=src.json_body,
        default_applied_assets=src.default_applied_assets,
    )
    db.add(new_wf)
    db.flush()
    for m in src.mappings:
        db.add(models.WorkflowMapping(workflow_id=new_wf.id, master_id=m.master_id, node_id=m.node_id))
    for p in src.presets:
        db.add(models.WorkflowPreset(
            workflow_id=new_wf.id, name=p.name,
            param_values=p.param_values, applied_assets=p.applied_assets,
            batch_size=p.batch_size, seed_mode=p.seed_mode, seed=p.seed,
            sort_order=p.sort_order,
        ))
    # Snapshot は複製しない（AC-4, AC-5）
    db.commit()
    db.refresh(new_wf)
    return new_wf
```

**重要**: `/{workflow_id}/copy` は `/scan` と同じ非-ID パスパターン衝突の懸念あり。FastAPI のルーター順序を `copy` を `/{workflow_id}` より前に登録することで解消。ただし `workflow_id` が整数型なので通常は問題なし。

**AC 対応**: AC-4, AC-5, AC-5（スナップショット除外）

## REQ-068-T3: PUT /api/workflow-presets/reorder エンドポイント追加

**対象ファイル**:
- `backend/app/routers/presets.py`
- `backend/app/schemas/preset.py`

**新規スキーマ**:
```python
# schemas/preset.py に追加
class WorkflowPresetReorder(BaseModel):
    ordered_ids: list[int]
```

**ルーター追加**:
```python
# routers/presets.py に追加（既存の PUT /{preset_id} より前に登録すること）
@router.put("/reorder", status_code=status.HTTP_204_NO_CONTENT)
def reorder_presets(payload: schemas.WorkflowPresetReorder, db: Session = Depends(get_db)):
    for i, pid in enumerate(payload.ordered_ids):
        db.query(models.WorkflowPreset).filter(models.WorkflowPreset.id == pid).update({"sort_order": i})
    db.commit()
```

**注意**: `/reorder` を `/{preset_id}` より前にルーター定義すること（FastAPI のパス解決順序）。

**AC 対応**: AC-6（並び替え永続化）

## REQ-068-T9: Settings Page — ワークフロー管理セクション実装

**対象ファイル**:
- `frontend/src/pages/SettingsPage.tsx`
- `frontend/src/components/SettingsComponents.tsx`

**変更内容**:
1. `SettingsPage.tsx` に `useQuery(['workflows'])` を追加し、ワークフロー一覧を取得
2. 各ワークフロー行に「名前変更」「コピー」「プロファイル管理」「削除」ボタンを配置
3. 「名前変更」「コピー」→ `WorkflowManageModal`（T5）を呼び出し
4. 「プロファイル管理」→ `PresetManagerPanel`（T6）をインライン展開パネルとして表示
5. 「削除」→ `WorkflowDeleteConfirmDialog` を開く

**WorkflowDeleteConfirmDialog の仕様**（SettingsComponents.tsx に追加）:
```
┌─────────────────────────────────────────────────────────────────┐
│ ⚠ ワークフロー「{name}」を削除しますか？                           │
│                                                                 │
│ 以下のデータがすべて削除されます（取り消し不可）:                   │
│ ・ノードマッピング: {mappings.length} 件                          │
│ ・プロファイル: {presets.length} 件                              │
│ ・生成履歴（スナップショット）: {snapshots_count} 件              │
│                                                                 │
│ [✓] 上記の内容を理解しました                                     │
│                                                                 │
│ [キャンセル]               [🗑 削除する（赤ボタン）]              │
└─────────────────────────────────────────────────────────────────┘
```

**snapshots_count の取得**: `GET /api/snapshots?workflow_id={id}` または `WorkflowRead.snapshots` のカウントをバックエンドから取得（既存 `GET /api/workflows/{id}` では snapshot 数は未返却のため、確認ダイアログ開示時に `GET /api/workflows/{id}` をフェッチし mapping/preset 数を表示。スナップショット数は `GET /api/snapshots?workflow_id={id}` で個別取得）。

**AC 対応**: AC-2（Settings 内全操作）, AC-3（2段階削除確認）
