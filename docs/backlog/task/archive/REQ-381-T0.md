## Draft registry contract（後続Cardへ供給）

```ts
export type SettingsDraftRisk = {
  dirty:boolean; invalid:boolean; failed:boolean; queued:boolean; inFlight:boolean
}
export type SettingsDraftControls = {
  cancelQueued:()=>void; discardLocal:()=>void
}
export function useSettingsDraftRegistration(
  resourceId:string, controls:SettingsDraftControls
): { update:(risk:SettingsDraftRisk)=>void; clear:()=>void }
export function SettingsDraftBoundary(props:{children:React.ReactNode}):React.JSX.Element
```

context moduleがregistry/providerとregistration hook、components moduleがuseBlocker/Modal/beforeunloadを所有。unique instance ID（useId等）＋resource識別で登録し、同keyの別componentを上書きしない。registryはflagsとcallbackのみ保持し、raw prompt/credential/秘密値を保存・ログ出力しない。consumer不在時のisolated component testはno-op contextで既存renderを維持し、production Settingsがboundary下であることはApp routing testで保証する。

riskは5flagのOR。updateはedit/commit/ack/errorのhandlerから同期的にregistry refへ反映し、blurとnavigationが同イベント内でも古いcleanを見ない。描画notifyは安全にbatchする。登録/cleanup/StrictModeは重複を残さない。registryはsnapshot状態を返せる内部関数でLeave直前に再確認する。

T3はcommit engine全resource＋LLM長文prompt、T4はBubble/VRAM/翻訳provider+credential/debounce/workflow config/BaseModel form、T5はtone create/edit、T2は変更済みmaster formを登録。自動保存queued/inFlightもriskであり、成功値のidleとは区別する。入力を元値へ戻してexact baseline一致ならcleanへ戻せる。親がraw stateを持たないmaster modalはinput capture後、成功Saveまたは取消まで保守的にdirty扱い（変更後に元へ戻しても確認が出ることを許容し、差分未検知をcleanと断定しない）。

## Navigation / Cancel / Leave

- mobile/desktop両方で有効。useBlocker関数は現在path `/settings`、次pathが異なり、riskがある場合だけtrue。同Settingsのhash/query/カテゴリ切替はunmountしないため許可しdraftを保持する。
- router PUSH/REPLACE/POP（NavLink/useNavigate/戻る進む）を対象とする。blocked時は共通Modalで「設定に未保存の変更があります」「キャンセル」「変更を破棄して移動」を表示。Cancel→blocker.reset、元Settingsに留まり全draft/validation/error/queueを保持。確認中も通常のinflight要求は自然に完了し、保存済み状態への反映は既存revision規則に従う。
- persist要求inFlightが1件でもあればLeaveをdisabledにし「保存処理の完了を待っています」を常時表示。queuedのみならLeave可。応答成功/失敗/timeout後も自動proceedしない。利用者が改めてLeaveを選ぶ。
- Leave handlerは最新registryを再取得しinFlightがなければ同期的にunsent queueを停止、ローカルdraftを破棄し、blocker.proceedを一度だけ実行。check→cancelQueued→discard→proceedにawaitを入れず新送信のraceを防ぐ。処理中はbutton二重操作を防ぐ。すでに成功した保存をrollbackしない。timeoutで結果不明の過去要求がserverで無効になったとは言わない。
- blocked中の追加navigation/連打/POP/保存完了/viewport resizeでdraftを喪失せず、Cancelは現在のblockerをreset、Leaveは現在のblocker.locationに対して1回だけproceed。destinationを独自history replayしない。
- reload/close/同tab cross-documentにはrisk時だけnative beforeunload（preventDefault/returnValue）を登録する。独自文言/非同期flush/確実なmobile OS強制終了防止を約束しない。browser判断で離脱された場合にinflight要求の成功を捏造しない。新tab/modified clickは現在documentを失わず、draftを消費しない。
