## Implementation Requirements

- 本カードは既存保存経路の契約テストのみ。setParamValues が値とJSON mode文字列を activeSetへ渡すこと、autosave が param_values のmetadataを失わないこと、プリセット保存/再取得/再読込で値・modeが復元することを確認する。
- metadataなし旧セットとmetadataあり新セットを切り替えて、画面・非アクティブセットの設定が独立して保たれることを確認する。固定→ランダム→固定で基準値を失わない。
- バックエンド PUT/GET workflow-presets の param_values:Record<string,string> に JSON文字列を載せて完全往復する。DB列追加なし。実DBや実ComfyUIを使用しないfixtureを採用する。
- stage suffix cascade は既存role数値を更新し、modeがmaster/variantのslotKeyでそのまま復元できることをテストする。予約JSONがrole名で勝手に改名されないことも確認。
- 既存経路の欠陥が露呈した場合は実装sourceを本カードへ追加せず、coordinatorへFAILとして返し、修正カードを再設計して人間reviewへ戻す。
