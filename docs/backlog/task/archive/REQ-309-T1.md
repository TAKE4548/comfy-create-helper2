## Encapsulated Contracts（新規 API。実装はこの型に従う）
```tsx
import { Component, lazy, Suspense, type ComponentType, type ReactNode } from 'react'

/** route 要素の Suspense fallback。AppShell 内の main 領域に収まり、ナビは隠さない。 */
export function RouteLoadFallback(): React.JSX.Element
//  <div role="status" aria-live="polite" className="flex min-h-0 flex-1 items-center justify-center p-8 text-xs text-zinc-400">画面を読み込み中…</div>

export type LazyModalMode = 'latch' | 'while-open'
export interface LazyModalHostProps<P extends object> {
  isOpen: boolean
  /** latch: 初回 isOpen=true で初めて mount し、以後は閉じても mount を維持（現行「常時 mount・isOpen で null」型）。
   *  while-open: isOpen の間だけ mount、閉じれば unmount（現行「条件 render」型）。 */
  mode: LazyModalMode
  /** モジュール定数の loader。例: () => import('../../components/JobManagementModal').then((m) => ({ default: m.JobManagementModal })) */
  load: () => Promise<{ default: ComponentType<P> }>
  /** latch 型のモーダルは isOpen を含めて渡す（ホストは注入しない）。while-open 型は含めない/含めてもよい（呼び出し側の現行 props に合わせる） */
  modalProps: P
  /** 取得失敗の局所エラーで「閉じる」を押したときに呼ぶ（親の open 状態を閉じる） */
  onClose: () => void
  /** 利用者向け名称。例: 'ジョブ管理' */
  label: string
}
export function LazyModalHost<P extends object>(props: LazyModalHostProps<P>): React.JSX.Element | null
```
実装規則:
- `lazy(load)` は **`load` 関数をキーとするモジュールレベル `WeakMap` にキャッシュ**し、ホスト再 mount（Desktop/Mobile 切替）で再 Suspend しない。
- latch の判定: `const [latched, setLatched] = useState(isOpen); if (isOpen && !latched) setLatched(true)`（render 中の派生 state 更新）。`mounted = mode === 'latch' ? latched || isOpen : isOpen`。`!mounted` なら `null`。
- 描画: `<ModalLoadBoundary label isOpen onClose><Suspense fallback={isOpen ? <ModalLoadFallback label/> : null}><Lazy {...modalProps}/></Suspense></ModalLoadBoundary>`。fallback は **開いている間だけ**（読込中に閉じた後に遅れて出ない）。
- `ModalLoadBoundary`（class）: chunk 取得失敗だけを局所処理する。`isChunkLoadError(error)` = `error.name === 'ChunkLoadError'` または message が `/Failed to fetch dynamically imported module|Importing a module script failed|error loading dynamically imported module|Failed to load module script/i` に一致。**該当しないエラー（モーダル内部の描画例外）は `render()` で再 throw** して従来どおり外側（`GeneratePageErrorBoundary`/route/`GlobalErrorBoundary`）へ伝える。該当時は `isOpen` の間だけ局所 UI を出す:
```tsx
<div role="alert" className="fixed inset-x-3 bottom-3 z-[70] mx-auto flex max-w-md min-w-0 flex-col gap-2 rounded-xl border border-red-500/40 bg-surface-2 p-4 text-xs text-zinc-200 shadow-2xl">
  <p className="min-w-0 break-words">{label}を読み込めませんでした。ページを再読み込みすると回復する場合があります。</p>
  <div className="flex justify-end gap-2">
    <button type="button" onClick={onClose} className="relative min-h-11 rounded-lg px-3 text-zinc-300 hover:bg-white/5 before:absolute before:-inset-2 before:content-['']">閉じる</button>
    <button type="button" onClick={() => window.location.reload()} className="relative min-h-11 rounded-lg bg-[#7C6FDD] px-3 font-medium text-white before:absolute before:-inset-2 before:content-['']">ページを再読み込み</button>
  </div>
</div>
```
  `componentDidCatch` で `logClientError(error, { component: 'LazyModalHost', context: { label } })`（`../../utils/logger`、`GlobalErrorBoundary.tsx` と同じ呼び方）。自動再試行・自動 reload は実装しない（`React.lazy` は reject を cache するため、回復手段は reload）。閉じた後に再 open した場合も同じ局所エラーが再表示される（無限 spinner にならない）。
- `ModalLoadFallback`: `<div role="status" aria-live="polite" className="pointer-events-none fixed bottom-4 left-1/2 z-[70] -translate-x-1/2 rounded-lg bg-surface-2 px-4 py-2 text-xs text-zinc-300 shadow-lg">{label}を読み込み中…</div>`（入力をブロックしない）。

Archetype 1 (Modals & Overlays) + Generic。Hit-Slop は上記ボタンの `before:absolute before:-inset-2`、文字は 11px 未満禁止（`text-xs`=12px 以上）、生の `vh` 禁止、`min-w-0`/`break-words` で長い label を許容。中央モーダルは作らない（モバイル 768px 未満で下部配置）。SSoT: `docs/specs/SPEC_COMMON.md` §1-5。`verify_ui_invariants.py` が PASS すること。

## テスト（LAZY = `LazyBoundary.test.tsx`）
タイトルは `[REQ-309/AC-n] <case-id>`、case 冒頭で `({ task }) => { Object.assign(task.meta, { acIds: [...], layer: 'unit', caseId }) }`。loader は制御可能な Promise（deferred）を返す `vi.fn()`、対象モーダルは本ホストの契約を見る最小の実コンポーネント（内部 state にカウンタを持つ）。ホスト/React/境界はモックしない。
| case-id | AC | 期待 |
|---|---|---|
| `latch-not-loaded-until-open` | AC-1 | `isOpen=false` の間 `load` は 0 回・DOM なし。初めて true で 1 回 |
| `latch-keeps-mounted-after-close` | AC-3 | 開く→カウンタ操作→閉じる→再 open でカウンタが保持され、`load` は 1 回のまま |
| `while-open-unmounts-on-close` | AC-3 | 閉じると unmount、再 open で state が初期化。`load` は 1 回（cache） |
| `close-while-loading` | AC-3 | 読込中に `isOpen=false` にすると fallback が消え、後で resolve しても何も表示されない |
| `rapid-toggle` | AC-3 | open/close を連打しても `load` 1 回、モーダルは 1 つ |
| `load-failure-local-alert` | AC-3 | reject（message に `Failed to fetch dynamically imported module`）で `role=alert`、親の兄弟要素（入力欄）は残る。「閉じる」で `onClose`、「ページを再読み込み」で `window.location.reload` が呼ばれる。閉じた後の再 open で再度 alert |
| `non-chunk-error-propagates` | AC-3 | モーダル内部の描画例外は外側のテスト用 boundary に到達（局所 alert は出ない） |
| `host-state-machine-properties` | AC-3 | `fast-check` で open/close/resolve/reject/re-open の列を生成。不変条件: latch は一度 mount したら unmount されない、while-open は閉じたら DOM 無し、fallback は open 中のみ、reject 後も親要素が残る。seed と最小反例の path を失敗ログに出す |
