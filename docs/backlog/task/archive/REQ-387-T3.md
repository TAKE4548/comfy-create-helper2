## 2. `_find_job` のフォールバック（L983-987）

```python
    @staticmethod
    def _find_job(state: StateSnapshot, job_id: str | None) -> JobView | None:
        if job_id is None:
            return None
        return next((job for job in state.jobs if job.job_id == job_id), None)
```

→ instance method にする。state 内になければ `self.repository.get_job(job_id)` を `JobView.model_validate` して返す（preview_url は None のまま）。新設 `def _find_job_by_prompt(self, state: StateSnapshot, prompt_id: str | None) -> JobView | None` も同様にし、`find_job_by_prompt` へフォールバックする。公開ラッパー `def find_job(self, job_id: str) -> JobView | None`（`self._find_job(self._snapshot(), job_id)`）を追加する。

prompt で探す箇所を `_find_job_by_prompt` へ置き換える。

- `cancel_queued`（L249-251）:
  ```python
            job = self._find_job(state, identifier)
            if job is None:
                job = next((item for item in state.jobs if item.prompt_id == identifier), None)
  ```
- `_cancel_single`（L718-723）: `target.job_id` があれば `_find_job`、なければ `_find_job_by_prompt(state, target.prompt_id)`。

`on_event`（L433）と `on_preview`（L548）の prompt 検索は state 内だけのままにする（窓外は終端で、従来も無視している）。

## 3. on_preview の再読込削減（L544-555 と L1406-1412）

```python
    async def on_preview(self, prompt_id: str, frame: bytes, mime: str) -> None:
        del frame, mime
        async with self._lock:
            state = self._snapshot()
            job = next((candidate for candidate in state.jobs if candidate.prompt_id == prompt_id), None)
            if job is None or job.status in _TERMINAL:
                return
            self._preview_revisions[job.job_id] = self._preview_revisions.get(job.job_id, 0) + 1
            self._advance_wire_revision()
        await self._publish_snapshot()

    def _advance_wire_revision(self) -> None:
        state = self._snapshot()
        self._wire_revision = max(self._wire_revision, state.revision) + 1
        signature_data = state.model_dump(mode="json")
        signature_data.pop("revision", None)
        self._wire_signature = signature_data
```

`_advance_wire_revision(self, state: StateSnapshot | None = None)` にする。引数がなければ従来どおり `_snapshot()` を呼ぶ。ただし preview_revisions の更新後の URL を signature に反映する必要があるので、on_preview からは `self._advance_wire_revision()` のまま呼ぶ。これで on_preview の `_snapshot()` は合計3回のままだが、T2 のキャッシュにより DB の jobs 読込は0回になる。呼出回数を減らせる場合は、更新後 state を `_snapshot()` で1回だけ再取得し、それを `_advance_wire_revision(state)` に渡す。既存テスト `test_preview_url_changes_only_for_received_frames_and_never_persists_or_survives_terminal` の期待を保つこと。

## 4. reconcile 失敗ログ抑制（`_run_worker` L605-609）

```python
                    try:
                        changed = await self._reconcile_locked()
                        if changed:
                            await self._publish_snapshot()
                    except Exception:
                        logger.warning("Generation reconciliation failed", exc_info=True)
```

→ `self._reconcile_failures: int` を `__init__` に追加する。
- 例外時はカウンタを +1 する。純関数 `_should_log_reconcile_failure(count: int) -> bool` が真の場合だけ記録する。
  - count == 1: `logger.warning("Generation reconciliation failed", exc_info=True)`
  - count ∈ {24, 48, 96, 192} または (count > 192 かつ (count - 192) % 240 == 0): `logger.warning("Generation reconciliation still failing (%d consecutive)", count)`（exc_info なし）
  - それ以外: `logger.debug(..., exc_info=True)`
- 成功時にカウンタ > 0 なら `logger.info("Generation reconciliation recovered after %d failures", n)` を出して0に戻す。
- 周期 2.5秒換算で約60s/120s/240s/480s、以降10分毎になる。

## テスト（`backend/tests/integration/legacy/test_generation_service.py` を拡張）

- `test_req387_ac2_preview_frame_reads_snapshot_once_and_advances_revision`: MemoryRepository の `snapshot` 呼出回数を数える（MemoryRepository 自身にカウンタ属性を追加する）。1フレームで呼出が3回以下、preview_url の revision が +1、publish が1回であることを確認する。
- `test_req387_ac4_cancel_and_release_for_out_of_window_jobs_keep_results`: `hidden_job_ids` で終端/released job を窓外にし、次の結果が窓内のときと同一であることを確認する。
  - `cancel_unsubmitted`、`cancel_queued`（job_id と prompt_id）、`cancel_operation`（単件 target job_id/prompt_id）
  - `release_unconfirmed`（released 済み → already_released）
  - 存在しない ID → rejected "job not found"
- `test_req387_ac6_reconcile_failure_logs_once_then_backoff_and_recovery`: `_should_log_reconcile_failure` の 1..500 の真値集合を検証する。さらに FakeBridge の `queue_error` を設定して worker を回し、caplog で exc_info 付き WARNING が1件だけであること、`queue_error=None` に戻した後に recovered INFO が1件出ることを確認する。worker 周期の待ちは既存テストの手法（`service._last_reconcile` を0に戻して `_wake.set()`）に合わせる。
