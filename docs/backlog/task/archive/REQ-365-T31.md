# REQ-365-T31: D-R3-1 修正 (BaseModelSection のバックドロップ 24px ずれ) (AC-9)

**人間の設計レビュー承認後に着手。** 検証レポート `docs/design/REQ-365-verification-report-r3.md` の D-R3-1 が根拠。

## 原子性
2ファイル、変更は約15行（JSX の包み替えのみ。ロジック・クラス・文言は不変）。`export function BaseModelSection()`（propsなし）不変。

## 原因（設計時に実ファイルで確認済み）
`Modal`（`frontend/src/components/common/Modal.tsx:131`）は portal を使わず、自身の位置に `<div class="modal-backdrop ...">`（`position: fixed; inset: 0`、`index.css:290`）を描画する。`BaseModelSection` は `return ( <div className="space-y-6"> ... <Modal/> x3 </div> )`（`BaseModelSection.tsx:119-120`）で、3つの `Modal`（:202 管理, :284 作成/編集, :342 マッピング追加）が `space-y-6` の2番目以降の子になる。Tailwind の `space-y-6` は `> :not([hidden]) ~ :not([hidden]) { margin-top: 1.5rem }` を生成するため、`position: fixed; inset: 0` の backdrop にも `margin-top: 24px` が効き、backdrop が (0,24,W,H-24) になる。上端24pxが未ディム・操作可能。

## 修正（最小・堅牢）
ルートを `<div className="space-y-6">` から Fragment に変え、既存の本体を `<div className="space-y-6">…</div>`（モーダル以外）に包み、3つの `Modal` をその**兄弟**として Fragment 直下に置く。親ラッパーが `space-y` でなくなるため、将来 Modal が増えても同じ欠陥が起きない。`!mt-0` 等の対症は使わない（各 Modal に `className` を上書きする方式は再発防止にならず、`!important` 規制・UI不変条件にも反する）。

現状（`BaseModelSection.tsx` 119-121 行付近、概略）:
```tsx
  return (
    <div className="space-y-6">
      {/* Checkpoint Mappings Management */}
      <div className="space-y-4"> ... </div>
      {/* Model Master Manager Modal */}
      <Modal isOpen={showModelManager} ...> ... </Modal>
      {/* Model Create / Edit Modal */}
      <Modal isOpen={showModelModal} ...> ... </Modal>
      {/* Mapping Create Modal */}
      <Modal isOpen={showMappingModal} ...> ... </Modal>
    </div>
  )
```
変更後:
```tsx
  return (
    <>
      <div className="space-y-6">
        {/* Checkpoint Mappings Management */}
        <div className="space-y-4"> ... </div>
      </div>
      {/* Modals are siblings of the space-y wrapper: space-y margin must never reach .modal-backdrop (D-R3-1). */}
      <Modal isOpen={showModelManager} ...> ... </Modal>
      <Modal isOpen={showModelModal} ...> ... </Modal>
      <Modal isOpen={showMappingModal} ...> ... </Modal>
    </>
  )
```
- 実ファイルで、Modal 以外に `space-y-6` 直下の兄弟ブロックが他に無いか確認する（ある場合は `space-y-6` の中に残す）。`<div className="space-y-6">` を残すのは見た目差分ゼロのため。
- 親 `SettingsPage.tsx:114` は `<div className="p-4 border-t ..."><BaseModelSection /></div>`（`space-y` なし）。Fragment 化後も Modal の親に `space-y`/`divide-*` は無い。**SettingsPage.tsx は編集しない。**
- Modal の props（`ariaLabel`, `size`, `sheetMaxHeightClass`, `onClose`, `isOpen`）は不変。dialog の role/name/排他遷移は不変。

## テスト（既存 `BaseModelSection.test.tsx` に追記。新規ファイル禁止。ケース名 `[REQ-365/AC-9]`）
既存 `expectSheet` 付近（約86-108行）と同じ `render(<BaseModelSection />)` / `openManager` を使う。
```tsx
  it('[REQ-365/AC-9] dialogs are not rendered inside a space-y/divide wrapper (backdrop must not receive a margin)', () => {
    const { container, unmount } = render(<BaseModelSection />)
    const expectBackdropUnmargined = (name: string) => {
      const backdrop = screen.getByRole('dialog', { name }).parentElement as HTMLElement
      expect(backdrop).toHaveClass('modal-backdrop')
      // No ancestor up to (and including) the render container may apply sibling margin.
      for (let el: HTMLElement | null = backdrop.parentElement; el; el = el.parentElement) {
        expect(el.className).not.toMatch(/(^|\s)(space-[xy]-|divide-[xy])/)
        if (el === container) break
      }
      expect(backdrop.parentElement).toBe(container) // Fragment root: backdrop is a direct child of the container
    }
    openManager()
    expectBackdropUnmargined('ベースモデルマスタ管理')
    fireEvent.click(screen.getByRole('button', { name: /モデル追加/ }))
    expectBackdropUnmargined('ベースモデル作成')
    unmount()
    render(<BaseModelSection />)
    fireEvent.click(screen.getByRole('button', { name: /マッピング追加/ }))
    expectBackdropUnmargined('チェックポイントマッピング追加')
  })
```
- `container` は RTL 既定の `div`（className 空）。`getByRole('dialog',{name}).parentElement` が `.modal-backdrop` であることは `Modal.tsx:131-153` で保証される。2回目の `render` の `container` は別オブジェクトなので、2回目の検証でも同ヘルパーが参照する `container` は1回目のもの。2回目は `const { container: c2 } = render(...)` として `expectBackdropUnmargined` に container を引数で渡す形にしてよい（実装時に整える）。
- RED 確認: 修正前は `backdrop.parentElement` が `div.space-y-6` で失敗することを先に確認してから修正する。
- 実ブラウザでの margin 実測は T32（E2E）が担う（jsdom は Tailwind CSS を評価しないため構造検証のみ）。
