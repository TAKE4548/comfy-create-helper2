## 既存型のimport先・具体的な定義
変更先 `frontend/src/utils/generationRecord.ts` からの相対importは以下。型宣言元は参照専用でありT9では変更しない。`WorkflowMapping` は `Workflow.mappings` の要素型で、helperに直接注釈が必要な場合だけimportする。
```ts
import type { Workflow, WorkflowMapping } from '../api/types';
import type { AppliedAsset } from '../store/types';

type CaptureAssetInput = AppliedAsset & {
  triggerSetId?: number | null;
  triggerSetName?: string | null;
};
// builderのassets引数はRecord<string,CaptureAssetInput[]>を使える。
// 基底AppliedAsset[]はoptional追加のみなので構造互換。
// T10のstore/types.ts変更を待たず型チェック可能。
```

## 実装
record型とbuilderを新utilityへ。全textareaは注入graphの実string+submitted/bypassed/missing、全その他mapping（roleなし含む）はsubmitted graphのJsonValue/recorded/class_type/graph-reference。空/0/false/nullと未記録を区別。seedはinjector先と同じkeyの実値、再乱数化/現在値補完なし。lora_stack inputsを丸ごと保持しmodel/clip別値を失わない。生成時name/order/asset snapshotをclone。optional trigger provenanceはCaptureAssetInput構造型で受けるのでT10以前にもcompile可能。default null=none、undefined=unknown、known ID=trigger。予約キー衝突はthrow、completeは全prompt文字列/IDが妥当なときだけ。queued_atはnullでT3がstamp。
