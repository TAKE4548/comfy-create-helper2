# REQ-394-T2: WS テストの INTERVAL 待ち解消（AC-4）

## 実行境界

- 役割は engineer / dev-task。workspace・cwd はリポジトリルート。`PYTHONDONTWRITEBYTECODE=1`。Python は `backend\.venv\Scripts\python`。
- 所有ファイルは上記 2 つだけ。**`backend/app/**`（`resource_monitor.py` を含む）は変更しない。** `backend/tests/conftest.py` も変更しない（共有フィクスチャ。各ファイルのローカル fixture で足りる）。
- 前提: コーディネーターが設計承認を確認し、本 Card を exact-ID で in-progress へ遷移済みであること。状態更新・QA・commit は担当外。
- **アサーションは削除も緩和もしない**（SYSTEM_STATS の型・値域・GPU フォールバック・VRAM 項目の検証を維持する）。テスト件数は増減しない。

## 原因（計測済み）

`ResourceMonitorService._run` は lifespan 開始直後に 1 回送信（接続クライアントはまだ無い）し、`await asyncio.sleep(self.INTERVAL)`（`INTERVAL: float = 2.5`、クラス属性）の後の 2 回目でクライアントに届く。そのため WS テスト 7 件が各 2.8〜2.9s。`INTERVAL` を 0.05 にすると各 0.37〜0.5s（`INTERVAL` は `self.INTERVAL` として毎周期読まれるため、TestClient 起動前に差し替えれば最初の sleep から効く）。

```python
# backend/app/services/resource_monitor.py（参照のみ）
class ResourceMonitorService:
    INTERVAL: float = 2.5
    ...
    async def _run(self, broadcast_fn):
        while True:
            data = await self._collect()
            await broadcast_fn(json.dumps({"type": "SYSTEM_STATS", "data": data}))
            ...
            await asyncio.sleep(self.INTERVAL)
```
