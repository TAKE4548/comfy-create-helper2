## Encapsulated Contract

| 項目 | 必須の意味 |
|---|---|
| アプリ経路 | Settings systemのComfyUI行とWeb Managerで「メモリ解放」。既存 `POST http://<現在のホスト名>:8899/api/action`、JSON `{ "action": "free-memory", "service": "comfy" }`。8000 proxyを新設しない。 |
| upstream | Managerは固定host127.0.0.1と既存`wsl.port`のComfyUIへHTTP送信。プロセス停止/再起動なし。 |
| status | `execution_state`（`idle` / `executing` / `queued` / `unknown`）、`queue_running` / `queue_pending`（numberまたはnull）、任意`execution_error`。TCP死活と区別する。 |
| queue | `GET /queue` のrunning非空=executing、pendingのみ非空=queued、双方空=idle。取得失敗・不正応答・停止=unknown。 |
| 有効条件 | LISTEN + idle + 操作なしのみ。生成中/待機/停止/不明/要求中は非活性と理由。受付後も最新状態のidle確認まで非活性を保つ。Managerもglobal action lock後、uncached `/queue` を直前確認する。 |
| 解放本文 | idle時のみ `POST /free` に `{ "unload_models": true, "free_memory": true }`。ComfyUIネイティブの空本文HTTP200も成功受付とし、Managerは `/api/action` のJSON応答に包んでUIへ返す。 |
| 拒否 | 400=対象service不正、409=busy/queued/executing、503=停止/queue不明は`request_sent:false`。502=upstream非2xx。504/通信断は送信成否不明。 |
| 通知 | 成功は「解放要求受付」の意味で、物理解放完了・全GPUメモリ解放を断定しない。応答不明は結果未確認→状態再取得。同じaction POSTとupstream `/free` POSTは再送しない。 |
| 監視 | POST再送を行わず、通常のGET状態/VRAM取得・ポーリングとWS監視を継続する。既存2.5秒周期WS監視（5秒以内）で実VRAM空き容量を同期し、WS断時はSettingsのVRAM再取得、取得失敗は監視エラー通知。受付直後の古い値/高い使用量だけで物理解放完了・失敗を断定したりPOSTを再送したりしない。 |
| 外部運用 | 送信元が `http://127.0.0.1:8188/queue` のidleを確認し、`http://127.0.0.1:8188/free`へ上記JSONを直接POST。本ツール8000/8899に依存しない。本ツールのUI/Manager guardは適用されない。 |
| 取引 | モデル解放後の次回生成はモデル再ロードを要する。物理解放量は状態に依存し保証しない。 |
