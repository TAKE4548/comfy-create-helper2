# REQ-412-T3: ヘッダーからのComfyUIメモリ解放に関する仕様書同期

## 1. 概要と目的

T1（共有フック `useComfyFreeMemory` と Settings の移行）と T2（ヘッダーのリソース詳細パネルへのボタン配置）で確定した振る舞いを、SSoT の仕様書 4 件へ矛盾なく反映する。コード・テストは変更しない。

## 2. ターゲット識別

- `docs/specs/SPEC_COMMON.md` §4-4-1「対象アクション」表（hover 型行 `role=tooltip`、モバイル VRAM ピル行）
- `docs/specs/SPEC_GENERATE.md` L398 付近（リソースホバーモニター段落）
- `docs/specs/SPEC_SETTINGS.md` L109-L111、L121 付近（ComfyUI 行のメモリ解放）
- `docs/specs/server_manager_guide.md` L128、L138-L146 付近（「ComfyUIのメモリ解放要求」）

## 3. Delegation & Boundaries

本カードが本タスクの唯一の意味仕様（Semantic Specification）である。

- **責務・スコープ・完了条件**: §4 の内容を各仕様書へ追記・更新し、§5 の確認で矛盾・参照切れがないこと。
- **依存関係**: `REQ-412-T1`、`REQ-412-T2`（実装後の最終差分で文言・DOM 契約を確認して反映するため）。着手時に T1/T2 の最終差分を読み返し、§4 と食い違う場合は推測で書かず Coordinator へ報告する。
- **隣接カードの所有ファイル（編集禁止）**: `frontend/` 配下の全ソース・テスト（T1/T2 所有）。
- **共有契約（反映対象）**:
  - ボタン名「ComfyUI メモリ解放」（ヘッダー）、「ComfyUIのメモリ解放」（Settings。不変）
  - 有効条件・理由文言は Settings と共通（Manager 接続、LISTEN、`execution_state=idle`、queue 0/0、他操作なし、要求中でない）
  - 同一タブ内のローカル Manager 操作ロックを Settings とヘッダーで共有（どちらかの操作中は双方とも無効）
  - 未確認時の文言は「要求結果未確認: 解放要求の結果を確認できません。状態を再取得します。操作は再送しません。」、受付文言は既存どおり
  - ホバーカードは `role=tooltip` を持たず、内容を `role=group`・`aria-label="リソース詳細"` で包む。ボタン群（`data-testid="resource-free-memory"`）は各パネルの末尾
  - Manager API（`POST /api/action {"action":"free-memory","service":"comfy"}`）、Manager 側 lock、§4-4-1 の配置・高さ・開閉契約は不変
- **AC と検証**: AC-1/AC-2/AC-7 → SPEC_COMMON・SPEC_GENERATE の記述、AC-3〜AC-6 → SPEC_SETTINGS・server_manager_guide の記述。doc-verify 観点で確認（コード AC の PASS はこのカードでは閉じない）。
- **委譲する判断**: 文の言い回し、追記位置（同一節内）。
- **変更禁止**: §4-4-1 の契約表（配置・高さ・重なり順・開閉・非目標）の既存行の意味、他 PBI の記述、仕様書以外のファイル。

- [ ] SPEC_GENERATE リソースホバーモニター段落: 両パネルの末尾にメモリ解放操作があり、条件・文言・送信経路は SPEC_SETTINGS の system 欄と共通である旨を、SPEC_SETTINGS への相対リンク付きで追記。
- [ ] SPEC_SETTINGS メモリ解放段落: 共通ヘッダーのリソース詳細パネルからも同じ guard・送信経路で操作できること、同一タブ内ロックの共有、未確認文言の先頭が「要求結果未確認」であることを追記。
