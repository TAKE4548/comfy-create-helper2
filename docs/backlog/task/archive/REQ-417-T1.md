# REQ-417-T1: DB新テーブル定義とマイグレーション・制約付与

## 1. 概要と目的
Master / Variant / 判定定義の3層分離を実現するため、新テーブル（`binding_rule_sets`, `binding_rule_entries`, `node_selectors`, `node_selector_patterns`）を新設し、`mapping_variants`（`role`, `binding_rule_set_id`, `node_selector_id`）および `workflow_mappings`（`input_name`）に必要な列を追加・整理する。既存データを無損失で変換するマイグレーションステップを追加し、SQLiteテーブル再作成により物理的な `UNIQUE(role)`, `UNIQUE(master_id, stage_id)`, `UNIQUE(master_id, node_selector_id)` 制約を付与する。初期シードデータも新構造へ更新する。

## 2. ターゲット識別
- **対象ファイル**:
  - `backend/app/models.py`
  - `backend/app/migrations/steps.py`
  - `backend/app/seed_data.py`
  - `backend/app/seeder.py`
  - `backend/tests/integration/models/test_migrations.py`
- **対象シンボル**: `BindingRuleSet`, `BindingRuleEntry`, `NodeSelector`, `NodeSelectorPattern`, `MappingVariant`, `WorkflowMapping`, `step_033_...`

## 4. 実装要件 (Implementation Logic)
- [x] `backend/app/models.py` に `BindingRuleSet`, `BindingRuleEntry`, `NodeSelector`, `NodeSelectorPattern` を定義する。
- [x] `MappingVariant` に `role NOT NULL`, `binding_rule_set_id NOT NULL`, `node_selector_id Optional[int]` を追加し、リレーションを定義する。
- [x] `WorkflowMapping` に `input_name NOT NULL` を追加し、不要となった `master_id` 列への直接依存を整理する。
- [x] `backend/app/migrations/steps.py` に新規マイグレーションステップを追加し、以下を実行する：
  1. 新テーブル作成。
  2. 既存マスタの `expected_class_types`, `param_name`, `fallback_param_names` から `BindingRuleSet` / `BindingRuleEntry` を生成。
  3. 既存マスタの `base_title_patterns` / `MappingVariant.extra_title_patterns` / `StageMaster.search_keywords` から `NodeSelector` / `NodeSelectorPattern` を生成。
  4. 既存の `computed_role` を `mapping_variants.role` に永続化。
  5. SQLite テーブル再作成により、`mapping_variants` に `UNIQUE(role)`, `UNIQUE(master_id, stage_id)`, `UNIQUE(master_id, node_selector_id)` 制約を付与。
- [x] `backend/app/seed_data.py` および `seeder.py` を新構造（RuleSet / NodeSelector）に対応させる。
- [x] `backend/tests/integration/models/test_migrations.py` に `test_req417_ac1`, `test_req417_ac6`, `test_req417_ac7` を追加・検証する。
