## 4. 現行記述（抜粋）と更新内容
### §3-1-1（L150 付近）
現行: 「2行目はバッジ（`+N classes` / `+N stages`）とする。Target Node情報は画面表示せず、編集ボタンの `aria-label`「<名称> のマッピング設定を編集（対象ノード: …）」に保持する。」
更新: バッジは入力型・`Variant N`（Variant 数）・ステージ（モバイルは先頭＋`+N stages`）・基本無効。`+N classes` は表示しない。aria-label は「<名称> のマッピング設定を編集（Variant N件）」。モーダル一覧から WorkflowNodePicker を外す（MappingMasterEditModal から到達しなくなったため）。
### §3-1-2
追記: 375px の Master 編集シートで Variant 行の定義切替・共有定義の選択・判定プレビューをデスクトップと同じ結果で行える。操作対象 44×44px 以上、ページ横スクロールなし（REQ-419 AC-11）。
### §3-2（L162-164）
現行: 「ただし MappingMasterEditModal 内の WorkflowNodePicker は共通Modalのネスト例外で、Esc は内側のみを閉じる。」
更新: このネスト例外を削除。MappingMasterEditModal の共有定義の影響確認はモーダル内の行内パネル（`role="alertdialog"`）で行い、表示中の Esc はパネルのみを閉じる。判定プレビューもモーダル内セクションでありネストしない。
### §4-1（L178-206）
現行の `interface MappingMaster { id; role; expected_class_types; param_name; input_type; display_name; title_patterns; default_enabled; sort_order }` を、次の3層の説明へ置換する（`ParamTypeMaster` と `select_sampler`/`select_scheduler` の記述、末尾の wire 表示の段落は維持）:
- Master（`mapping_masters`）: 値の意味と型（`base_key`, `name`, `input_type`, `group_id`, `default_enabled`, `sort_order`）。旧列 `param_name`/`expected_class_types`/`base_title_patterns`/`title_patterns`/`fallback_param_names` は DB に残るが画面で編集せず、スキャン判定・フロントの候補ランク付け・ステージ検出にも使わない（作成時の `param_name` は初期 RuleSet の生成にのみ使う）。
- Variant（`mapping_variants`）: ステージ単位の role（永続・一意、画面は読み取り専用）、`is_enabled`、`binding_rule_set_id`（必須）、`node_selector_id`（NULL＝セレクタなし）。`UNIQUE(role)`、`UNIQUE(master_id, stage_id)`、`UNIQUE(master_id, node_selector_id)`（NULL は複数可）。
- BindingRuleSet/Entry（どの入力か: `class_type` × `param_name`、priority）、NodeSelector/Pattern（どのノードか: `exact`/`contains`、priority）。複数 role で共有でき、参照中は削除不可。
- 判定段階: 1=自セレクタ完全一致、2=部分一致、3=セレクタなし／どのセレクタにも不一致、4=同 Master の別 Variant のセレクタにのみ一致（除外）。順位は段階→Entry priority→パターン priority→ノードID。`StageMaster.search_keywords` は判定に使わない（DB 列・API フィールドは残存、画面に入力欄なし）。
- 編集画面: Master 値定義のみ＋ステージ（`sort_order` 順）別 Variant 行。共有定義の内容変更保存時は他の参照元 role を示し「共有定義を更新」または「複製してこのVariantだけ変更」を選ばせる。一意性違反は保存前に行エラーとし保存しない。
### §4-1-1（L208-219 付近、tier 表のみ）
現行: 「| 0 | 登録classと登録titleの生文字完全一致 | はい | … | 3 | class不一致だが登録parameter名を持つ | …」。
更新: 「登録class」「登録title」「登録parameter名」の出典を Variant 単位の3層定義に置き換える。tier 0 = RuleSet Entry 一致（class_type 一致かつ param_name をノード入力に持つ）かつ NodeSelector の exact パターンとタイトル生文字一致、tier 1 = Entry 一致かつ（exact の表記ゆれ一致 または contains パターンを正規化タイトルが含む）、tier 2 = Entry 一致のみ、tier 3 = Entry の param_name をノード入力に持つ（class 不一致）、tier 4 = その他。Master の旧列（expected_class_types / title_patterns / base_title_patterns / fallback_param_names）・Variant の extra_title_patterns は使わない。Settings 配線のステージ表示は各ステージの有効 Variant の NodeSelector パターンで検出し、`search_keywords` を使わない（ビルトイン／main は常時表示）。score 帯・正規化規則・未割当スロット保持の段落は変更しない。
### §6（API 表）
追加行: 「マッピングマスタ原子的保存 | `POST /api/mapping-masters/{id}/atomic-save` | `{ master, rule_sets[], selectors[], variants[] }`。1トランザクションで適用し、失敗時（422 `MASTER_SAVE_VALIDATION_FAILED`／409）は全件ロールバック」。追加行: 「マッピング判定プレビュー（非永続）| `POST /api/mapping-masters/scan-preview` | `{ workflow_id, variants: [{ client_key, variant_id?, stage_id, role, is_enabled, entries, patterns|null }] }`。保存データを変更しない」。既存「マッピングマスタ一覧・管理」行の補足に「Variant には参照定義の `rule_entries`・`selector_patterns`（読み取り専用）を含む」。BindingRuleSet・NodeSelector の CRUD 行（`/api/binding-rules`, `/api/node-selectors`）を追加。path 数の記述（117 path）は `docs/openapi.yaml` の実数に合わせて更新する。
