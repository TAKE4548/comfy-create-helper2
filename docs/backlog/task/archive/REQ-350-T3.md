## Implementation Requirements

- prepareSeedBatch を純粋関数として追加。各 input_type:'seed' mapping ごとに readSeedSettings を読み、セット内0始まりindexで fixed=base+index、random=既存 Math.floor(Math.random()*2**32) を適用。
- seed 値と batchSize の整数・有限値・範囲を全スロットで先に検証。fixed+batchSize-1>UINT32_MAX はバッチ全体を拒否する。エラー時ネットワーク呼出しなし。random の偶然一致は許容する。
- dedicated seedが存在する場合はbatchSizeを1..8（現行UI上限）に制限する。9/10000000/Infinityを抽選前に拒否。seed不在のlegacy生成に新たな枚数制限を追加しない。
- 抽選はindexごとに同期root slotだけを列挙して行い、resolved root値を子slotへコピーする。子でrandomUint32を再呼出ししない。
- validateSeedBatch を公開し抽選前validationを共有する。呼出側T7は全対象セットにvalidateSeedBatchを実施してからprepareSeedBatchする。seed同期rootはT1共有関数から取得する。
- paramSyncGroups は master_role/slave_roles の現在の完全roleに従う。seed->seed 同期では親のモード・基準値・実使用値を共有し、random の親1回の抽選を子へコピーする。無同期なら各欄で独立抽選。
- seed が関係する混在型同期、複数親、循環、同一role/slotKey/実書込先の競合、欠損node/roleを検出し欄名付きエラーで拒否。通常パラメータだけの既存同期には手を加えない。
- item.actualParamValues は original paramValues を保ち、当該 item の seed role のみ実数値文字列へ置換。元のparamValues/metadata/graphを変更しない。未使用の古いmodeスロットは無視。
- 数値を注入するキーは param_name が node.inputs にあればそれ、なければ既存 value、さらに無ければ param_name||'value'。同じキーに別mappingが書く場合は競合として拒否。graph-reference(Array) の Seed 入力は直接数値に変換せず生成不可を表示。
