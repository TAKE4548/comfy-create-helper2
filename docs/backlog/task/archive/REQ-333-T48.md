# REQ-333-T48

現ManagerはFE LISTENなのにaction_in_progress fe/startが残り、全管理操作が409/disabled。read-only調査でPSのFE起動はport readiness後returnするが長寿命childが親capture_output pipeを保持する経路を確認。Windows subprocess.runのtimeout cleanupも子孫のpipe EOF待ちに戻るため、finallyまで到達しない場合がある。現processのhandle継承は未検証、稼働中旧Managerを勝手に停止しない。

## Impacted Files
- tools/server-manager/server_api.py
- backend/tests/test_manager_origin_req333.py
- tests/unit/test_server_manager_timeout.py

## Correction

Manager actionの有限launcher outputはPIPE capture_outputを使わずregular temporary filesへstdout/stderrを別々に収集する。subprocess.runはfile対象で待機しtimeoutと終了code判定を維持。終了後file sizeのsnapshotを上限に有限readし、従前stdout+stderrのoutput返却を維持。encodingは以前のtext modeと同じローカル規約を使い、decode errorは応答全体を落とさない。file contextを必ずclose。Origin境界、action409排他、cache無効化、nonzero502/timeout504/finally busy解除を維持。生存しているlauncherをready表示だけで完了扱いにしない。非対象Comfy/processの停止や一括taskkillなし。

## Verification Command
```powershell
backend/.venv/Scripts/python.exe -m pytest backend/tests/test_manager_origin_req333.py tests/unit/test_server_manager_timeout.py -q
backend/.venv/Scripts/python.exe -m mypy backend
```

TDDでstdout/stderrがPIPEではないregular file、有限output回収、成功/nonzero/timeout時のbusy解除と既存timeout回帰を確認。既存mockはfileへ出力する実際のsubprocess規約に合わせ、終了codeなどのassertは弱めない。現Managerの更新反映はCoordinatorが別途扱う。所有外編集禁止、他担当変更を巻き戻さない。
