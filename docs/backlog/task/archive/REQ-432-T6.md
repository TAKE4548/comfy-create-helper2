# REQ-432-T6: VRAMガード閾値のフォールバック既定値を 6.0 GB に揃える

## 1. 概要と目的
`VramGuardSection.tsx` の `VRAM_LIMIT_DEFAULT = 4.0` は、localStorage の閾値ミラー（`prompt-surgeon-vram-guard-limit`）が空・数値でない場合の初期表示値である。Backend の既定値（`ResourceMonitorService._min_free_gb = 6.0`）と、改訂済み SPEC_GENERATE §5-4 の「`vram_min_free_gb`、既定 6.0GB。`resource_monitor` の初期値と一致」と食い違っている。サーバー応答前の初期表示と、未保存の閾値が 4.0 として扱われる余地をなくすため、6.0 に揃える（SPEC 整合の是正。承認済みの手戻り範囲）。

## 2. ターゲット識別

- テスト: `frontend/src/pages/SettingsPage/components/__tests__/VramGuardSection.test.tsx`（L208 の調整と、新規ケースの追記）

grep 確認結果（設計時）: 4.0 フォールバックを固定値で前提にするテストは L208 のみである。`SettingsPage.test.tsx`、`SettingsAutosave.integration.test.tsx`、`TranslationSettingsSection.test.tsx`、`api/__tests__/client.test.ts` の `vram_min_free_gb: 4` は、サーバー応答のモック値であり、フォールバック既定値には依存しない。これらは変更しない（所有外）。

## 5. 現行コード抜粋

export const VRAM_LIMIT_MIN = 2.0
export const VRAM_LIMIT_MAX = 14.0
export const VRAM_LIMIT_DEFAULT = 4.0
export const VRAM_APPROACH_MARGIN_GB = 1.0

export function readStoredVramLimit(raw: string | null): number {
  if (raw == null || raw.trim() === '') return VRAM_LIMIT_DEFAULT
  const n = Number(raw)
  if (!Number.isFinite(n)) return VRAM_LIMIT_DEFAULT
  return Math.min(VRAM_LIMIT_MAX, Math.max(VRAM_LIMIT_MIN, n))
}
