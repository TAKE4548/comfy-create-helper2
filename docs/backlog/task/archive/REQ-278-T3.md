# Task Card: REQ-278-T3

## 1. 目的
静的解析レポート（`tmp/REQ-276_277_Static_Analysis_Report.pdf`）で判明したテストギャップ（REQ-277 のテストコードがストアへ直接手動代入したため、`useEffect` による上書き破壊を検知できなかった偽陽性問題）を恒久解消する。
プリセット再同期サイクル（`presets` 更新契機の `rawMappedSets` マッピング）においてローカル編集値が保持されること、およびリロードなしでの即時生成で最新パラメータが `wfJson` ノード inputs に確実に渡ることを検証する自動テストを整備する。

## 2. 対象ファイル
- `frontend/src/pages/GeneratePage/hooks/__tests__/useGenerateAction.test.ts`
- `frontend/src/pages/GeneratePage/hooks/__tests__/useGeneratePageState.test.tsx`

## 3. 実装仕様

### 3.1 `rawMappedSets` インメモリ保持テスト（`useGeneratePageState.test.tsx` または結合テスト）
プリセットの再取得が発生したシナリオにおいて：
1. 編集前のプリセット（Steps=20）をロード。
2. ユーザー操作により Steps=40 に変更。
3. サーバーから DB 値（Steps=20）を持つプリセットデータが再同期された際、インメモリのセットが Steps=40 を維持することを検証。

### 3.2 リロードなし即時生成と連続編集生成テスト（`useGenerateAction.test.ts`）
1. 初期値（Steps=20）から Steps=35 に変更し、リロードなしで生成実行 -> `wfJson` inputs の steps が 35 であることをアサート。
2. その後、さらに Steps=50 に変更し、再度リロードなしで生成実行 -> `wfJson` inputs の steps が 50 であることをアサート（実機第5現象の再発防止）。

## 4. 完了条件
1. 抜け道防止ルール（AL-1〜AL-4）に準拠したテストが追加され、手動直代入による偽陽性が完全に排除されていること。
