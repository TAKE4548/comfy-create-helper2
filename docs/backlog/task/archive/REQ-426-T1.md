# REQ-426-T1: step_035_variant_id_references の未解決キー救済と統合テスト

## 1. 概要と目的
実 DB の `workflow_presets` および `param_sync_groups` に残存する未解決 `role` キー（ゴーストキー）により `step_035_variant_id_references` が毎回ロールバックする不具合を解消する。前提テーブル欠如時の中断は維持しつつ、データ内の未解決キーは `logger.warning` を出力してスキップし、解決可能なデータの移行と `master_variant_id` 列追加を完了させる。

## 4. 実装要件 (Implementation Logic)
- [ ] `step_035_variant_id_references` 冒頭の `audit_role_references` による `ValueError` 送出（L1299-1302）を削除し、前提テーブル（`mapping_variants` および `role` 列）チェックのみ維持する。
- [ ] `workflow_presets` 移行ループ（L1336-1360）において:
  - JSON パース失敗または `dict` 以外の場合は `logger.warning` に `preset id` を記録してスキップする。
  - `norm = normalize_params(index, data)` 実行後、`norm.unresolved` が空でなければ `logger.warning` に `preset id` と未解決キー一覧を記録する。
  - 解決済み `norm.entries` を `workflow_preset_values` へ `INSERT OR IGNORE` し、`workflow_presets.param_values` を `json.dumps(norm.reserved, ensure_ascii=False)` で更新する（再実行時の冪等性確保）。
- [ ] `param_sync_groups` 移行ループ（L1362-1388）において:
  - `master_role` が解決できない（`cls_master.variant_id is None`）場合は `logger.warning` に `sync_group id` と `master_role` を記録し、`master_variant_id` は `NULL` のまま更新しない。
  - `slave_roles` の要素のうち解決できないキーまたは非文字列は `logger.warning` に `sync_group id` とキーを記録してスキップし、解決可能な `variant_id` のみ `param_sync_group_members` へ `INSERT OR IGNORE` する。
- [ ] `backend/tests/integration/models/test_migrations.py` の旧仕様テスト（`test_variant_ref_ac1_unresolved_row_rolls_back_all_unchanged`, `test_variant_ref_ac1_unresolved_error_lists_all_keys`）を `[REQ-426/AC-1]` 仕様（警告ログ出力＋解決分のみ移行＋`master_variant_id` 列追加＋不正 JSON 耐性＋再実行冪等性）のテストへ更新・拡充する。
