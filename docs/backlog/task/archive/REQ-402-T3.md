## Normative Changes
- §2-6へ右click/500mslongtap/通常tapのellipsis入口と3項目を記述。A B C D EのCでleft=A B、right=D E、others=A B D Eを閉じ、Cは必ず残すと明示。
- 左右はsets由来の表示順、画面外を含む。menuだけでselect/入力を変えない。target0は無効。外側/Escapeでcancel。通常select/check/単件close/横scrollを維持。
- 保存ACK待ち、全targetが安全な場合だけclose。保存失敗/409/通信断は全tab/draft保持と既存復旧経路。部分server保存成功をrollbackすると記載しない。
- activeが残れば維持、閉じるならtriggerを選択。閉じるは非表示でプリセット削除ではない。open/active再訪復元、管理から再表示。
- §2-6の「同期実行…サーバーへ確実にフラッシュ永続化」と§5-3の「非同期PUT完了を待たず」の両編集箇所を照合し、既存flushAutoSaveの同期保証はtimer取消・最新draftのメモリ即時反映・保存要求開始であり、PUT ACK待機ではないと明確化。既存の生成直前メモリ反映と最新生成payload保証を弱めず、今回一括closeのみawaitable barrierでACKまで待つことを区別。dirty/clean pollと競合3経路を維持。
- 構成一覧へ実際に追加されたPresetTabItem/PresetTabCloseMenu/presetTabCloseの責務を同期。未実装の名称を完成事実として記載しない。
- 完成実装との名称/閾値差異は独断で仕様を変えず親へ返す。承認済契約を拡張しない。
