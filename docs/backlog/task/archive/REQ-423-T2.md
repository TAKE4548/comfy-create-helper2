# REQ-423-T2: パラメータ注入およびメタ情報記録のフォールバック堅牢化

## 1. 概要と目的
`workflowParamInjector.ts` において、`seedNode.input_name` が指定されている場合はそれを優先してノードの入力へ注入し、空・未設定の場合でも `node.inputs` に実在するシード関連キー（`noise_seed`, `seed`, `value` 等）を自動探索して解決するフォールバックを実装する。これにより、ノード（KSamplerAdvanced等）に実在しない `node.inputs["seed"]` が誤生成され、本来の `noise_seed` が未更新のまま ComfyUI に送信される不具合を防止する。
併せて `generationRecord.ts` の `capture` においても、`mapping.input_name` および実在するシードキーから正確に記録対象キーを解決し、UI表示・履歴メタデータと実送信グラフの完全一致を担保する。

```typescript
function capture(mapping: WorkflowMapping, injected: Record<string, unknown>, submitted: Record<string, unknown>): CapturedField {
  const prompt = mapping.input_type === 'textarea'
  const raw = (prompt ? injected : submitted)[mapping.node_id]
  const node = object(raw) ? raw : undefined
  const inputs = node && object(node.inputs) ? node.inputs : undefined
  const resolvedSeedKey = mapping.input_type === 'seed' ? resolveSeedInputKey(mapping, inputs) : null
  const key = resolvedSeedKey ?? (inputs && mapping.param_name != null && inputs[mapping.param_name] !== undefined
    ? mapping.param_name : inputs && inputs.value !== undefined ? 'value' : mapping.param_name || (mapping.role === 'Sampler_Seed' ? 'seed' : 'value'))
```

## 4. 実装要件 (Implementation Logic)
- [ ] `frontend/src/utils/workflowParamInjector.ts`:
  - `seedOptions` の注入処理において、シードキー `seedKey` の解決順序を以下のように堅牢化：
    1. `seedNode.input_name` が非空文字列で、`node.inputs[seedNode.input_name.trim()] !== undefined` の場合はそのキーを採用。
    2. もし `seedNode.input_name` が指定されているが `node.inputs` にまだ存在しない場合でも、`seedNode.input_name.trim()` を最優先キーとする（スキャンで決定された明示的キー）。
    3. `seedNode.input_name` が空・未設定の場合（レガシーマッピング等）:
       - 候補配列 `[seedNode.param_name, ...(seedNode.fallback_param_names ?? []), 'noise_seed', 'seed', 'value'].filter(Boolean)` を順に検査し、`node.inputs` に実在する最初のキーを解決する。
       - いずれも実在しない場合のみ `seedNode.param_name || 'seed'` にフォールバックする。
  - これにより、KSamplerAdvanced（`noise_seed`）に対して `node.inputs["seed"]` が誤注入されることを完全に防止する。
- [ ] `frontend/src/utils/generationRecord.ts`:
  - `capture` 関数において、`configuredKey` として `typeof mapping.input_name === 'string' && mapping.input_name.trim().length > 0 ? mapping.input_name.trim() : null` を認識。
  - `configuredKey` がある場合は優先し、未設定で `mapping.role === 'Sampler_Seed'` の場合は `inputs` 内の実在キー（`noise_seed`, `seed`, `value` 等）を検出して記録する。
- [ ] `frontend/src/utils/__tests__/workflowParamInjector.test.ts`:
  - `[REQ-423/AC-3]` サンプラーノード（KSamplerAdvanced: `inputs: { noise_seed: 0 }`）に `input_name: "noise_seed"` のマッピングと `seedOptions: { seed: 12345, seedMode: 'fixed' }` を指定したとき、`inputs.noise_seed === 12345` となり `inputs.seed === undefined` であることを検証。
  - `[REQ-423/AC-4]` レガシーマッピング（`input_name: ""`）のサンプラーノードに対し、`node.inputs.noise_seed` が自動検出されて注入され、`inputs.seed` が生成されないことを検証。
  - `[REQ-423/AC-4]` レガシーマッピング（`input_name: ""`）の PrimitiveNode（`inputs: { value: 0 }`）に対し `value` へ注入されることを検証。
- [ ] `frontend/src/utils/__tests__/generationRecord.test.ts`:
  - `[REQ-423/AC-3]` `noise_seed` を持つノードの注入後グラフから `buildGenerationRecord` を実行した際、記録されるフィールドのキーおよび値が `noise_seed` と完全に一致することを検証。
