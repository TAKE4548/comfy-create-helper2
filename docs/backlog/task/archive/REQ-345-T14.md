# REQ-345-T14 App統合と既存E2E fixtureのavailability契約更新

## Ownership and Atomicity

Write only the two listed test files, with at most 180 changed lines total. Shared codebase: preserve other edits and assertions.

## Failure Evidence

The full frontend suite fails in `App.generationIntegration.test.tsx` because a `GenerationGallerySection` fixture omits `state.trialAvailability` and throws on `getIdentity`. The existing `e2e_req339_preview_layout.test.tsx` also has a pre-contract fixture.

## Implementation Contract

- Keep Gallery, display cache listener, and user-visible assertions intact.
- In `App.generationIntegration.test.tsx`, do not create a second unrelated controller for the manually assembled state. Change the gallery harness so it calls `useGenerateDisplayState({ selectedWorkflowId: null })` and passes that same returned `trialAvailability` and `sortedDisplayImages` into `GenerationGallerySection`, with only the existing UI-only state fields supplied by the fixture. The missing-image assertion must exercise the controller owned by the real hook so it can update both query caches and the store.
- In `e2e_req339_preview_layout.test.tsx`, use a complete `createTrialAvailabilityController(async () => ({ availability: 'present' }))` when rendering layout-only Gallery state.
- Keep the App integration fixture URL in the real application form `/api/comfy/view?...`; the controller contract accepts this path as equivalent to `/view`.
- Do not replace the controller with a partial object; it must provide the full controller API including `getIdentity`, `getStatus`, observation and ownership methods, `adopt`, `check`, `refreshVisible`, `subscribe`, and `dispose`.
- Dispose controllers during test cleanup where the fixture owns their lifetime.
- Do not change production files or suppress the failing assertions.
