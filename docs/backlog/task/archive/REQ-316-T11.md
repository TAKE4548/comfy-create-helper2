### 既存型・予約payload・不変関係
- `SnapshotTagSetCreate` は `backend/app/schemas/snapshot.py:25-27` の既存 `{tag_set_id:int, role:str='positive'}`。`SnapshotUpdate` は同:63-68、schemas packageより `schemas.SnapshotUpdate` として service/router が使用する。新 `SnapshotTriggerAssociation` は同ファイルに置き、既存 `schemas/__init__.py` からの追加exportは不要（SnapshotUpdate内だけで参照）。`role` は空白だけでない文字列を必須とする。
- `Snapshot.params` は `backend/app/models.py:178-198` のTEXT JSON object。`SnapshotRead.params` はdictでGET `/api/snapshots/{snapshot_id}` は `backend/app/routers/snapshots.py:40-69`。PATCH `/api/snapshots/{snapshot_id}` (`:102-104`) は更新後 `SnapshotRead` を返す。新PATCHは `tag_sets` と `lora_trigger_sets` を使い、legacy caller向け `tag_set_ids`/`lora_ids`/`params` は残す。新`tag_sets`とlegacy `tag_set_ids`の同時指定は400。各list省略は保持、空配列はそのrelationを空にする。
- `params['__metadata_associations_v1']` の値自体もJSON string: `{"version":1,"lora_trigger_sets":[{"lora_id":int,"trigger_set_id":int,"role":str}]}`。他の `params` キー、`__prompt_surgeon_metadata_v1` の完全な文字列、通常値、順序のあるtrigger listを保持し、このkeyだけ更新する。壊れた/未知versionは編集不能として維持または400、空trigger listへ初期化して保存しない。duplicate identityはgeneric `(tag_set_id, role)`、trigger `(lora_id, trigger_set_id, role)`。新規trigger IDは `models.LoraTriggerWordSet` (`backend/app/models.py:263-273`) の存在と親`lora_id`一致を両方検証。異なるTagSet/trigger ID名前空間を混同しない。
- `models.SnapshotLora` は `backend/app/models.py:328-340`、一意制約 `(snapshot_id,lora_id,role)` と `strength`/`role` を持つ。新規triggerは、`LoraTriggerWordSet` のparent `lora_id` が対象Snapshotに同IDで関連済みか検証する。trigger roleはそのSnapshotLoraのroleと一致する必要はなく、association-only選択を許可する。更新中に既存 `SnapshotLora` 行を削除/再生成しないため、そのrole・strengthは不変にする。`SnapshotTagSet` は同342-355、関連更新は `(snapshot_id,tag_set_id,role)` を維持する。
- service entry point は `SnapshotService.update_snapshot(db: Session, snapshot_id: int, payload: schemas.SnapshotUpdate) -> models.Snapshot` (`backend/app/services/snapshot_service.py:226+`)。404/400条件を先に全件検証し、validation pass後に関係とparamsを変更、単一commitを試み、例外時rollbackして再raiseする。既存DBに保存済みのtrigger参照がmasterから消えた場合は、変更前と同じtupleのみ維持/削除可；新規追加/role変更で不存在tupleを再生成しない。

## 実装
SnapshotUpdateに2追加フィールド、旧tag_set_ids同時指定400。先にsnapshot存在/全新ID/trigger所属LoRA/role nonempty/重複を検証。tag_setsは(id,role)を維持し関係全置換、省略維持/[]全削除。triggerはparamsのASSOCIATIONS_KEYだけ現DB辞書にmerge、generation record/通常params/lora関係/image/album/created_at不変。検証と変更を単一transaction、失敗rollback。一度保存済みの欠落trigger参照は同一行保持/削除可能、新規不正参照は不可。旧PATCH契約は残すが新UIはlora_ids/paramsを送らない。nested classはsnapshot.py内で利用しschema package export変更不要。
