## 4. 実装要件 (Implementation Logic)
既存の1行は残し、下に箇条書きで次を追加する:
- [ ] 1. 同期の単位はワークフロー mapping の role（REQ-336 のロール×ステージ。バリアントがあれば `computed_role`）。代表（マスター）と同期先は role 文字列で保存する。
- [ ] 2. サブ候補は、代表と同じロールの別ステージと、同じ `input_type` の別ロール。代表自身は候補に出さない。異なる `input_type` 間の同期は扱わない。
- [ ] 3. 候補はステージ名付きで表示する（T1 で確定したラベル形式を書く。例: `Rough / Steps`）。ステージを解決できない mapping は表示名だけ。
- [ ] 4. 型判定は mapping の `input_type` を優先し、ない場合はマスター一覧の legacy role で補う（T1 の実装結果に合わせる）。
- [ ] 5. 同期は生成時に実効値へ適用し、ストアの入力値は書き換えない。未選択の同期先、および解除した同期先は代表の変更に追従せず、自身の保存値を使う。無効グループは適用しない。Seed は REQ-353 の専用経路で扱う。
- [ ] 6. 保存した代表と同期先は、同じワークフローで ParamSync を再表示したときに復元される。
- [ ] 7. 自己参照の禁止以外の競合・循環規則は従来どおり（本変更で追加しない）。

T2 で `applyParamSync` の修正が入った場合は、その内容と矛盾しないよう 5 を調整する。T1〜T3 の完了報告に書かれた事実だけを記述し、未実装の挙動を書かない。
