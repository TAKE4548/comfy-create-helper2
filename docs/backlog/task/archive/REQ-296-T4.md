## 実装契約

- モデルキー確定後、取得→推論→解放検証を同じモデル単位の排他区間へ入れる。`instance_id = await acquire_model_instance(vlm_model)` とし、`call_scene_vlm(image_base64, prompt, instance_id)` のpayload `model` と `unload_model_instance_with_retry(instance_id)` の本文に同じIDを渡す。取得失敗時は推論を開始しない。ID指定がLM Studioに拒否されたらモデルキーへ再試行せず制御エラーとし、保持したIDの解放を試みる。
- 元の推論例外をアンロード例外で置換しない。解放失敗は安全な分類ログと進捗 `vram:error` に残し、正常生成時の `vram_unloaded=false` を返す。streamは既存の `vram_unload_failed` を返す。
- LM Studio listの`loaded_instances`は`id/config`しか返さずreadinessを示さない。Chat Completionsが厳密にHTTP 400 `{"error":"Model is unloaded."}` を返した場合のみ、T1の同一payload・同じ `instance_id` の最大90秒・1秒間隔再試行に委ねる。各後続要求は最大60秒を残りdeadlineでcapし、readiness retry中のReadTimeoutも期限内に再試行する。別の400、最初のreadiness sentinel前の通信失敗は再試行しない。枯渇時の `LM_STUDIO_INSTANCE_NOT_READY` を保持し、finallyで対象ID cleanupを行う。
- unload非2xx後に状態照会して、正確な対象 `instance_id` が不在なら解放済みと認める。対象残存または状態照会不能は `vram_unloaded=false`。正常2xxでも応答本文不正/ID不一致は解放成功にしない。
- キャンセル時も解放完了まで待ち、既存のprogress通知失敗が解放を阻害しない特性を維持する。インスタンスIDはログで伏せるか安定したハッシュにし、生のモデル本文を出さない。
