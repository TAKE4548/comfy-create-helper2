# REQ-309-T6

## Scope
T5 の本番検証が PASS し、coordinator が実装結果を確認した後に実行する文書カード。**実装結果（実際に確定した境界・文言）と矛盾する記述を入れない**。計測の数値（kB・byte）は仕様書に書かない（環境依存の履歴値であり、正本は PBI/検証ログ）。画面 URL・機能・API・離脱保護の契約（block 条件・callback）は変更しない。意味・矛盾・適用範囲・参照・AC シナリオの確認を行い、コード用の API/型/TDD は要求しない。
**AC 分担**: コード AC の受入には寄与しない（文書の同期のみ）。AC-1〜AC-6 のコード側の合否は T0〜T5 と独立 tester が判断し、本カードの PASS でコード AC を閉じない。

## 追記内容
1. **SPEC_SUMMARY.md §5（`## 5. ページ構成`）**: 現行表（Generate / History / LoRAs / Tags / Settings の 5 行）には `/studio`（Dataset Studio、`pages/DatasetStudioPage/index.tsx`、詳細は `SPEC_DATASET_STUDIO.md`）が欠けているため行を追加する。表の直後（※ スマホ… の次）に次の趣旨を追記: 「6 画面はすべて route 単位の遅延読込（`React.lazy` + `Suspense`）。初期表示 route で他画面のコードを取得せず、訪問時に取得する。`AppShell`・Data Router・`errorElement`・`PersistQueryClientProvider` は静的。chunk 取得失敗は既存の `GlobalErrorBoundary` に到達する」。ディレクトリ構成の `App.tsx # ルーティング定義` 注記に「(各ページは遅延読込)」を足す。
2. **SPEC_GENERATE.md**: §7（`## 7. コンポーネント & フック構成`）に「モーダルの読込条件」を追記。常時 mount 型（`AddSnapshotToAlbumModal`・`HistoryModalPreview`・`JobManagementModal`・`ProfileBulkEditModal`・`PresetConflictModal`・`PromptTranslationModal`）は初回に開くまで取得せず、初回オープン後は mount を維持する（内部 state の寿命は従来どおり）。条件 render 型（`RescanModal`・`UploadWorkflowModal`・`WorkflowManageModal`・`PresetManagerPanel`・`SceneGeneratorModal`・`BypassSettingsModal`・`ParamSyncModal`・`SaveAsTagSetModal`）は開いている間だけ取得・mount。読込中は開いている間だけ局所の読込表示、取得失敗は局所の `role="alert"`（「閉じる」「ページを再読み込み」）でページ全体・入力済みプロンプトを失わない。`DesktopLayout`/`MobileLayout` は遅延化しない。コピー作成ダイアログと通知は静的。
3. **SPEC_SETTINGS.md**: 離脱保護の節（`【承認済み追加設計】Settings限定の離脱保護…` を含む段落の直後）に 1 段落。「`/settings` route 要素は `SettingsDraftBoundary`（静的）の内側で Settings 本体を遅延読込する。blocker と `beforeunload` は Settings chunk の取得前から有効で、登録は Settings 本体の mount 後に行われる。block 条件・`cancelQueued`/`discardLocal` の契約は不変」。
4. **SPEC_COMMON.md §2-4**: 「全ページで同一のルーティング（…）を共有」の箇条書きの末尾に「各 route は遅延読込だが URL・ナビ構成・初期表示は不変」を追記（新しい高さや CSS 値は定義しない）。
5. **SPEC_TEST_ARCHITECTURE.md**: §5.1 の `frontend/e2e/` の記述付近に `frontend/e2e/prod/`（本番バンドル専用。`playwright.prod.config.ts` で収集、既定 Gate 3 の `playwright.config.ts` は `testIgnore` で対象外。圧縮なしの静的サーバで配信した本番 build を対象に、初回 JS 転送量・chunk 構成・全 route・chunk 取得失敗を検証）を追記。
