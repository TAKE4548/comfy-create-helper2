### 2.1 useSnapshotActions.ts 内の保存処理
```typescript
      const allApplied = Object.values(appliedAssets).flat()
      const activeLoras = allApplied
        .filter((a) => a.type === 'lora' && a.enabled)
        .map((a) => {
          let strength = 1.0
          if (a.loraPromptString) {
            const parts = a.loraPromptString.replace(/[<>]/g, '').split(':')
            if (parts.length >= 3) strength = parseFloat(parts[2]) || 1.0
          }
          return { lora_id: a.assetId, strength }
        })
      const activeTagSets = allApplied
        .filter((a) => a.type === 'tagset' && a.enabled)
        .map((a) => ({ tag_set_id: a.assetId }))
```

## 3. 実装要件 (Implementation Logic)
- [x] `frontend/src/pages/GeneratePage/hooks/useSnapshotActions.ts`
  - `saveSnapshot` 実行時、適用アセットの属する `role` (ポジティブ/ネガティブ等の入力エリア) も保存できるように、送信データに `role` を含める。
  - `activeLoras` に `role` フィールドを追加 (例: `lora_id: a.assetId, strength, role`)。
  - `activeTagSets` に `role` フィールドを追加 (例: `tag_set_id: a.assetId, role`)。
  - ※ `allApplied` をフラットにする前の段階で、`appliedAssets` は `Record<role, AppliedAsset[]>` の構造を持っているため、各 `role` キーを活かして `role` 情報を含めたオブジェクトをマップする。
- [x] `frontend/src/pages/GeneratePage.tsx`
  - `handleLoadSnapshot` 実行時、全件リストからの参照ではなく、`snapshotsApi.get(id)` API を呼び出してスナップショットの「詳細情報」（`loras` と `tag_sets` の各紐づけリストと `role`）を非同期で取得する。
  - 取得した `loras` と `tag_sets` の適用情報から、フロントで読み込み済みの全LoRA (`loras` リスト) / 全タグセット (`tagSets` リスト) の中から該当のIDを検索し、`AppliedAsset` の配列を再構築する。
  - 再構築した `appliedAssets` (構造: `Record<string, AppliedAsset[]>`) を、Zustand store (新設アクション `setAppliedAssets` または既存 store API) を使用して設定・復元する。また、LocalStorage のワークフロー個別キーにも書き込む。
