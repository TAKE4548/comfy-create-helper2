公開シグネチャは `export function GeneratePage()`、内部状態は `const state = useGeneratePageState()`、レスポンシブ判定は `state.isMobile`。既存モーダルは `isOpen` prop を持つものと、条件付き render のものが混在する。

## 実装の境界
`DesktopLayout` / `MobileLayout` を `isMobile` に応じて片方のみ取得する。読み込み待ちはレイアウト領域に限定する。未表示のモーダルは lazy import と開状態での mount を組み合わせる。特に常時 mount の `AddSnapshotToAlbumModal`、`HistoryModalPreview`、`JobManagementModal`、`ProfileBulkEditModal`、`PresetConflictModal` は `isOpen=false` でも JS が取得される設計を解消する。閉じた後に必要な状態が失われる場合は状態の置き場を維持する。`PresetManagerPanel` など既に条件付き表示のものも import を遅延化する。PC/モバイルの生成入力状態を保つ。

## 完了条件と検証
空キャッシュ初期 `/` で未使用レイアウトと未開モーダルの chunk が取得されない。各モーダルの初回開閉・再開、PC/モバイル切替、プロンプト編集と checkpoint 選択を維持する。読込失敗時は既存エラー境界の再読み込み導線を確認し、未保存入力が失われる場合は T4 に記録する。

**検証コマンド**: `cd frontend; npm run typecheck`、`cd frontend; npx vitest run src/pages/__tests__/GeneratePage.test.tsx`。本番 Network 判定は T4。
