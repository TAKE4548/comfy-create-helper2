# REQ-330-T1: MatrixGenerationStep における ComfyUI 直接 fetch を comfyApi.queuePrompt に置き換え

## 1. 概要と目的
Dataset Studio Step 1（`MatrixGenerationStep`）でマトリクス計算後のプロンプト一括投入時、ブラウザから直接 `fetch('http://127.0.0.1:8188/prompt')` している箇所を `comfyApi.queuePrompt` に置き換えます。
これにより、バックエンドプロキシ（`/api/comfy/prompt`）経由で通信を行い、ブラウザのCORS拒絶（`Failed to fetch`）を解消します。また、BA監査の指摘に基づき、ComfyUI内部エラー検知（`res.error`）と途中失敗時のエラー通知を堅牢化し、単体テストをモックに追従させます。

  queuePrompt: (data: { prompt: Record<string, any>; client_id?: string }) =>

## 4. 実装要件 (Implementation Logic)
- [ ] `MatrixGenerationStep.tsx`: `import { datasetApi, workflowsApi, workflowPresetsApi, comfyApi } from '../../../api/client'` に変更する。
- [ ] `handleSubmitBatch`:
  - `const comfyUrl = 'http://127.0.0.1:8188'` を削除する。
  - `clientId` をより衝突しにくい形式に変更（例: `'lora-studio-' + Date.now() + '-' + Math.random().toString(36).slice(2, 7)`）。
  - ループ内の `await fetch(...)` を以下に変更する:
    ```typescript
    const res = await comfyApi.queuePrompt({
      prompt: payload,
      client_id: clientId,
    })
    if (res?.error) {
      const errorMsg = typeof res.error === 'string' ? res.error : (res.error.message || JSON.stringify(res.error))
      throw new Error(errorMsg)
    }
    ```
  - エラー発生時は既存の通り `setStatusMessage({ type: 'error', text: \`ComfyUI直接投入エラー: \${err.message || '接続に失敗しました'}\` })` で通知し、`isSubmitting` を解除する。
- [ ] `MatrixGenerationStep.test.tsx`:
  - `comfyApi.queuePrompt` をモック化し、`mockItems` の20件に対して呼び出されることを検証する。
  - `globalThis.fetch` のモックを撤廃する。
  - 異常系テストを追加: `comfyApi.queuePrompt` がエラー（または `error` プロパティを含むレスポンス）を返した際にエラーメッセージが表示され、`isSubmitting` が解除されることを検証する。
