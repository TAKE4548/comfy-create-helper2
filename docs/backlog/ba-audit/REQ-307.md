## 初回監査

## 改訂版監査

終了コード 0。監査判定は **Conditional Approval with Refinements**。意図は論理的に妥当と評価された。残る指摘は次のとおり。

- 長い理由の全文表示と、トーストの表示領域・読みやすさの両立。受入条件 AC-5 の実現方法を設計で具体化する。
- 多数のバッチ失敗が同時に起きた際の通知件数と読みやすさ。AC-3/4 で対象と理由の対応を維持し、表示量の扱いを設計で決める。
- 通信タイムアウトや応答確認不能を「キュー投入失敗」とみなす境界。
- 理由が空文字・空白の場合の AC-2 適用。
- バッチで一部成功・一部失敗した際の通知の優先度。
- REQ-141 の既存通知要件との整合確認。REQ-307 は理由の読みやすさを明確化する目的であり、対象表示を維持する。

監査は一部で API 形式や実装方式を推定している。これらの推定を要件の事実とは扱わない。上記のうちユーザーの要望からは決めきれない範囲は、ドラフトのレビューまたは後続設計で確認する。改訂版監査直後の `unload` は終了コード 0。
