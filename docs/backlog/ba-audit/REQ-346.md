# Business Analyst Reasoning Gate Analysis: REQ-346

## 1. Executive Summary
REQ-346 proposes a UI modification for the "Generated Header Workflow Settings Menu" to improve accessibility and operability by expanding the dropdown downwards with full height visibility, rather than constraining it within the header bounds. The requirement is logically sound regarding standard dropdown behavior but contains ambiguous phrasing regarding layout interaction ("above page content") that requires clarification during implementation to prevent regression in layout stability or z-index conflicts.

## 2. Logical Consistency & Contradiction Audit

### 2.1 Positioning Ambiguity
*   **Requirement Text:** "ページ内容の上へ表示する" (Display above page content) vs. "ヘッダー下へせり出して展開する" (Protrude downwards from header).
*   **Analysis:** These phrases are technically consistent if interpreted as Z-index layering (overlay), but could be misinterpreted by developers as a layout shift requirement. If the menu pushes content down, it violates the intent of "not pushing height."
*   **Resolution:** The implementation must ensure `position: fixed` or `absolute` with high z-index to overlay without affecting document flow.

### 2.2 Height Constraints
*   **Requirement Text:** "ヘッダー高さで切り詰めない" (Do not cut off by header height).
*   **Analysis:** This is consistent with AC-1 ("Menu bottom displays below header bottom"). However, if the viewport is smaller than the menu content + header, the user must scroll. The requirement implies internal scrolling (AC-3), which resolves this but requires careful CSS handling (`max-height` + `overflow-y`).

### 2.3 Interaction Logic
*   **Requirement Text:** "展開ボタンを再度押す...メニューが閉じる" (Press expand button again... menu closes).
*   **Analysis:** This is standard toggle behavior. However, if the user clicks *outside* the menu while it is open, does it close? AC-4 only specifies clicking the button. Standard UX dictates closing on outside click to prevent accidental trapping of focus or interaction.

## 3. Edge Case Analysis

### 3.1 Mobile & Touch Targets (AC-5)
*   **Scenario:** On a mobile device in portrait mode, the header might take up ~60px. If the menu has 20 items at 48px each, total height is ~960px.
*   **Risk:** AC-3 ensures scrolling works, but touch targets must remain tappable without accidental scroll interference. The scrollbar itself should not be interactive (clicking it shouldn't close the menu).

### 3.2 Screen Resizing & Layout Shift (AC-6)
*   **Scenario:** User opens menu, then resizes browser window rapidly.
*   **Risk:** If the menu is fixed to the header position and the viewport shrinks below the menu height, the user might lose track of where they are in the scroll list. The requirement implies persistence ("continuously reach"), which suggests the scroll position should be preserved or the menu should re-render smoothly without jumping.

### 3.3 Accessibility & Focus
*   **Gap:** AC-4 mentions closing on button press but does not specify focus management.
*   **Risk:** When closed, focus must return to the trigger element (the expand button) for keyboard users. Without this, a keyboard-only user might lose their place in the workflow.

### 3.4 Z-Index Conflicts
*   **Scenario:** If other modals or tooltips exist on the page.
*   **Risk:** The requirement does not define a specific z-index value. If another UI element has a higher z-index, REQ-346's menu could be obscured.

## 4. SSoT Integrity & Context Check

### 4.1 Reference Documentation
*   **Citations:** `SPEC_GENERATE.md §2-1` and `SPEC_COMMON.md`.
*   **Integrity Status:** The requirement relies on external specs for the "existing cache menu" behavior (Reference). If those specs are outdated, REQ-346 might inherit legacy bugs. It is recommended to verify that the referenced "cache menu" implementation matches the desired overlay behavior before coding.

### 4.2 Audit History Consistency
*   **Observation:** The audit log mentions a previous contradiction regarding AC-1's height condition ("inverted citation").
*   **Resolution:** The current text clarifies this by explicitly stating the menu should protrude *below* the header bottom (AC-1). This resolves the previous ambiguity.

### 4.3 Status & Readiness
*   **Status:** Draft / User Approval Pending.
*   **Gate Check:** The "Human Review Gate" is active ("Not ready for change/design/dev handoff"). This requirement passes the initial logical gate but requires a technical review regarding CSS implementation details (overflow handling) before moving to "Ready".

## 5. Recommendations & Action Items

1.  **Clarify Z-Index:** Explicitly define the z-index in the design doc or implementation notes to ensure it overlays correctly without being hidden by other UI components.
2.  **Add Outside Click Closure:** Update AC-4 to include closing behavior when clicking outside the menu area, preventing interaction traps.
3.  **Focus Management:** Add an acceptance criterion for keyboard users (e.g., "AC-7: When closed via button press, focus returns to the trigger element").
4.  **Scrollbar Interaction:** Ensure that using the scrollbar does not inadvertently close the menu or shift the layout.
5.  **Verify External Specs:** Cross-reference `SPEC_GENERATE.md §2-1` to ensure the "existing cache menu" behavior is fully understood before implementing the new protrusion logic.

**Final Verdict:** Logically consistent with standard UI patterns but requires technical clarification on overlay mechanics and accessibility focus management before implementation.

## 1. Logical Contradiction Analysis

### 1.1 AC-5 vs AC-6 Reachability Conflict

```
AC-5: "画面内で到達して押下できる" (reachable within screen)
AC-6: "引き続き到達して押下できる" (continue to reach while resizing)

**Issue**: These create a tension between static and dynamic reachability. If AC-5 requires all items visible at once, AC-6 becomes impossible for long menus during resize.

**Recommendation**: Clarify that AC-5 allows scrolling within the menu container, not full visibility of all items simultaneously.

### 1.2 Height Treatment Ambiguity

```
Requirement: "ヘッダー高さで切り詰めない" (don't cut off by header height)
AC-1: "メニュー下端がヘッダー下端より下に表示される" (menu bottom below header bottom)

**Issue**: The requirement prohibits cutting, but AC-1 only mandates display position. A menu could still be partially obscured if it extends beyond viewport.
