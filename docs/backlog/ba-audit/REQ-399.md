## 監査結果と方針転換（ユーザー協議後）

### 根本原因の再定義
- 当初ドラフトにあった「遅延テスト側の一時的遅延注入」は、プロダクトコードの汚染や戻し忘れ、自動受入検証との不整合の観点から危険・不適切と判断。
- 散発 FAIL の真因は `scripts/run_full_suite.py` で BE (`pytest -n auto`) と FE (`vitest`) が同時に全コアを占有して CPU 100% 飽和（Starvation）を引き起こしていることにある。
- 対策方針を「`scripts/run_full_suite.py` の並列度・ワーカー数制御による CPU 飽和防止」へ全面的に見直し。

### 主な指摘事項と反映
1. **並列度制御の定量的制約 (AC-2)**:
   - 「適切に制御」から、「BE `pytest -n` のワーカー数を論理コア数の 75% 以下（または `max(1, os.cpu_count() - 2)`）を上限とする」と定量的制約を明記。
2. **検証能力の保持 (AC-3)**:
   - 個別テストのアサーション閾値（150ms / 300ms）を緩和・変更・削除せず 100% 維持することを明記。
3. **実行時間予算の遵守 (AC-4)**:
   - 並列度制限を適用しても、フルスイート全体が 150 秒以内に完了することを明記。
