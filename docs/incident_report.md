# インシデントレポート: スマートフォン等からのスナップショット画像非表示問題

## 1. 現象・症状
スマートフォンや外部端末から IP アドレス経由で本アプリケーションにアクセスした際、過去のスナップショット画像がリンク切れ（表示できない状態）になります。

## 2. 再現手順
1. ホストPCにてバックエンド（FastAPI）、フロントエンド（Vite）、ComfyUI を起動する。
2. 同一ネットワーク上のスマートフォン等のデバイスから、ホストの IP アドレス経由でフロントエンド（例: `http://192.168.X.X:5173`）にアクセスする。
3. 過去のスナップショット画像を表示しようとすると、画像がリンク切れとなり表示されない。

## 3. 原因究明 (Root Cause Isolation)
調査の結果、以下の実装上の不備（二重のバグ）が判明しました。

1. **データベース保存値の問題 (URL のローカルホスト依存)**
   - フロントエンドで画像生成を行うと、ComfyUI の出力画像 URL（例: `http://localhost:8188/view?filename=...`）が生成されます。
   - スナップショット保存時、フロントエンドから送られてきたこの `localhost` を含むフル URL が、そのままデータベースの `snapshots.image_path` に格納されていました。
   - スマートフォンなどからアクセスすると、画像の URL が `localhost:8188` を指すため、スマートフォン自身に接続を試みてしまい、画像が取得できません。

2. **画像ファイル保存ロジックおよび配信設定の未実装**
   - プロジェクト設計方針（`SKILL.md` の「重要な設計方針 3」）では「**スナップショット画像は `db/snapshots/` にファイル保存**」と指定されていましたが、バックエンドの `POST /api/snapshots` において、画像をダウンロードして保存する処理が未実装でした。
   - バックエンド（FastAPI）側で `db/snapshots` ディレクトリを静的ファイルとしてマウント・配信する設定も存在しませんでした。

## 4. 対策方針 (Proposed Solution)
本インシデントは **Type A (Implementation Bug: 実装バグ)** に分類されます。以下の修正を行うことで解決します。

1. **バックエンドでの画像保存処理の追加**
   - `POST /api/snapshots` API において、リクエストされた `image_path` が外部 URL（`http://` または `https://` で始まる場合）であれば、バックエンド側でその画像をダウンロードして `db/snapshots/` にユニークなファイル名で保存する。
   - データベースの `image_path` には、ローカル静的ファイル配信用の相対パス（例: `/api/snapshots/images/filename.png`）を保存する。

2. **静的ファイル配信用マウントの設定**
   - バックエンドの FastAPI アプリ（`backend/app/main.py`）において、`db/snapshots` ディレクトリを `/api/snapshots/images` パスへ静的ファイルディレクトリとしてマウントし配信する。
   - これにより、フロントエンド側はオリジン（IP アドレス）に依存しない相対パスで画像をロードできるようになり、Vite の API プロキシ経由でどの端末からでも画像が表示可能になります。
