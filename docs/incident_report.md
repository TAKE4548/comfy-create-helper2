# 障害調査報告書 (Incident Report)

## 障害概要
スマホモード（画面幅 767px 以下、または `/mobile` パス）において、PC向けの2カラムレイアウト（左側設定入力、右側プレビュー・実行ボタン）がそのまま適用されてしまい、以下の問題が発生しています。
1. 幅が `w-[420px]`（デスクトップ用の固定幅）の左カラムが画面全体を占有、またははみ出す。
2. その結果、右カラムにある画像プレビューエリアや「Generate Batch（生成ボタン）」「Save Snapshot（スナップショットボタン）」が画面外に押し出され、表示されず押せなくなる。
3. 本来、スマホ専用画面（`/mobile`）として提供されるべき「プロンプト入力欄をタブで切り替える共用テキストエリア方式」や、進捗プレビュー・操作ボタンを1カラムに収めた専用レイアウトが実装されておらず、デスクトップ向けのレイアウトを無理に表示しようとしている。

## 再現手順
1. ブラウザでアプリの生成画面（`/`）を開く。
2. 開発者ツールでデバイスツールバーを有効にし、画面幅をスマホサイズ（例：375px または 768px 未満）にする。
3. 設定入力部分のみが表示され、プレビュー画像や生成ボタンのある右側エリアが右側にはみ出て見えなくなる、あるいはボタンが押せなくなることを確認する。

## 根本原因 (Root Cause Analysis)
15: 1. **レイアウトのレスポンシブ未対応**:
16:    [GeneratePage.tsx](../frontend/src/pages/GeneratePage.tsx) において、レイアウト構造全体が `flex h-full overflow-hidden` で囲まれており、画面幅に関わらず左右2カラムが横並びになる実装になっています。
17: 2. **スマホ専用設計（/mobile 相当）の実装漏れ**:
18:    [Prompt Surgeon フロントエンド デザイン・実装仕様書.md](../Prompt%20Surgeon%20FE%E3%83%87%E3%82%B6%E3%82%A4%E3%83%B3%E3%83%BB%E5%AE%9F%E8%A3%85%E4%BB%95%E6%A7%98%E6%9B%B8.md) の「レスポンシブ・マルチデバイス対応」に記載されている、スマホ向け（〜767px）の専用設計レイアウト（プレビュー表示、タブ切り替え＋プロンプト共用テキストエリアなど）が [GeneratePage.tsx](../frontend/src/pages/GeneratePage.tsx) に実装されていません。
19: 3. **`isMobile` 判定の不整合**:
20:    [GeneratePage.tsx](../frontend/src/pages/GeneratePage.tsx#L52) の `isMobile` 判定条件が `window.innerWidth < 1024` となっており、本来スマホ（〜767px）とタブレット（768px〜）で分けるべきブレークポイントと乖離しています。また、ウィンドウリサイズ時に `isMobile` が動的に追従する仕組み（イベントリスナー等）も存在しません。

## 障害分類
* **分類**: **Type A (Implementation Bug / 実装バグ・実装漏れ)**
  * 仕様書（`Prompt Surgeon フロントエンド デザイン・実装仕様書.md`）にスマホ専用設計の画面仕様（タブ切り替え＋共用テキストエリア、およびレイアウト）が定義されているにもかかわらず、フロントエンドの実装（`GeneratePage.tsx`）がそれに追従していないため。

## 対策案（※本フェーズでは実装は行いません）
1. `GeneratePage.tsx` 内で、スマホモード判定（ブレークポイント 768px 未満、または `/mobile` パス）のレスポンシブ状態を検知するカスタムフック、または `resize` イベントリスナー付きの React state を導入する。
2. スマホモード検知時、PC向けの2カラムレイアウトではなく、スマホ専用の1カラムレイアウトに切り替える。
3. スマホ用レイアウトでは、仕様書通り「複数のプロンプト欄を横スクロールタブで切り替える共用テキストエリア」を構築し、その下に進捗プレビューエリア、サムネイル履歴、および生成・スナップショット保存ボタンなどのアクションエリアを縦に並べる。
