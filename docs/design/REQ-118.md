# REQ-118 設計書: 生成済み画像へのセリフ付与機能

## 1. 機能概要

スナップショット一覧から画像を選択し、画像内の吹き出し（セリフ領域）を自動検出して任意のテキストを重畳・保存する機能。
自動検出の誤認識補正、及び VLM/LLM による AI セリフ下書き生成（拡張機能）を含む。

---

## 2. アーキテクチャ概要

```
Frontend (React/TypeScript)
  └── SpeechBubbleEditorModal
       ├── Canvas Layer (konva.js or fabric.js — or HTML5 Canvas API)
       │    ├── Image レイヤー
       │    ├── BoundingBox オーバーレイ（自動 or 手動補正矩形）
       │    └── テキスト重畳レイヤー
       ├── セリフ入力テキストエリア
       ├── 「ドラフト生成」ボタン
       └── 「保存」ボタン

Backend (FastAPI / Python)
  └── /api/snapshots/{id}/detect-bubble  [NEW] POST
       └── bubble_detector.py (OpenCV contour detection)
  └── /api/snapshots/{id}/detect-bubble-roi [NEW] POST
       └── 矩形ROI内での輪郭再検出
  └── /api/llm-prompts/speech-draft      [NEW] POST
       └── VLM → LLM 2段階呼び出し
  └── /api/snapshots                     [既存] POST
       └── 加工後画像をスナップショットとして保存
  └── /api/snapshots/upload              [既存] POST
       └── 加工後画像ファイルのアップロード
```

---

## 3. データフロー

### 3-1. 吹き出し自動検出フロー
1. フロントエンドがスナップショット選択 → Modal を開く
2. `POST /api/snapshots/{id}/detect-bubble` を呼び出す
3. バックエンドがスナップショットの `image_path` から画像を読み込み、OpenCV で吹き出し領域のバウンディングボックス `{x, y, w, h, confidence}` を返す
4. フロントエンドが Canvas 上に BoundingBox を描画し、テキスト描画エリアを初期化する

### 3-2. 手動補正フロー (ROI指定)
1. ユーザーが Canvas 上でドラッグ → 矩形 ROI を指定
2. `POST /api/snapshots/{id}/detect-bubble-roi` に `{roi: {x, y, w, h}}` を送信
3. バックエンドが ROI 内で輪郭抽出 → BoundingBox を再計算して返す
4. フロントエンドが BoundingBox を更新する

### 3-3. AI セリフ下書き生成フロー
1. ユーザーが「ドラフト生成」ボタンを押下
2. `POST /api/llm-prompts/speech-draft` に `{snapshot_id}` を送信
3. バックエンドが:
   a. スナップショットの `image_path` から画像をBase64エンコード
   b. VLM モデル (LM Studio multimodal API) に画像を送信 → 概要テキスト取得
   c. スナップショットの `params` から生成時プロンプトを抽出
   d. LLM に「{VLM概要} + {生成時プロンプト}」でセリフドラフト生成を依頼
   e. セリフドラフトテキストを返す
4. フロントエンドがセリフ入力エリアにドラフトを自動反映

### 3-4. 加工画像保存フロー
1. フロントエンドが Canvas を画像として export (Blob/DataURL)
2. `POST /api/snapshots/upload` でアップロード → `image_path` 取得
3. `POST /api/snapshots` で元スナップショットの `workflow_id` と `params` を引き継いだ新規スナップショットを作成

## 4. 新規 API エンドポイント定義

### POST /api/snapshots/{snapshot_id}/detect-bubble
**Request:** (body なし)
**Response:**
```json
{
  "bounding_box": { "x": 120, "y": 50, "w": 300, "h": 80 },
  "confidence": 0.92
}
```
`bounding_box` が null の場合は吹き出し未検出。

### POST /api/snapshots/{snapshot_id}/detect-bubble-roi
**Request:**
```json
{ "roi": { "x": 100, "y": 30, "w": 350, "h": 120 } }
```
**Response:** detect-bubble と同一スキーマ（ROI 内で最大の吹き出しを返す）

### POST /api/snapshots/{snapshot_id}/detect-bubble-debug
**Request:**
```json
{ "roi": { "x": 100, "y": 30, "w": 350, "h": 120 } } or { "roi": null }
```
**Response:**
```json
{
  "candidates": [
    {
      "id": 1,
      "x": 120, "y": 50, "w": 300, "h": 80,
      "area": 24000,
      "aspect_ratio": 3.75,
      "mean_brightness": 245.2,
      "status": "PASS"
    },
    {
      "id": 2,
      "x": 10, "y": 20, "w": 15, "h": 15,
      "area": 225,
      "aspect_ratio": 1.0,
      "mean_brightness": 120.0,
      "status": "FAIL_AREA"
    }
  ]
}
```

### POST /api/llm-prompts/speech-draft
**Request:**
```json
{ "snapshot_id": 42 }
```
**Response:**
```json
{ "draft": "生成されたセリフドラフトテキスト" }
```

## 5. バックエンド実装詳細

### 5-1. bubble_detector.py (新規サービス)
- 使用ライブラリ: `opencv-python-headless`, `numpy`
- アルゴリズム:
  1. カラー白マスク抽出方式: BGRの全チャンネルが `min_brightness` 以上のピクセルを `255`、それ以外を `0` に二値化したカラー白マスクを作成（グレースケール・Cannyエッジ処理を廃止）。これにより中の文字に干渉されずに外枠の面を一発で捉え、明るい肌色等との同化を防ぐ。
  2. 輪郭抽出 (`findContours(..., RETR_EXTERNAL, ...)`): 最も外側の輪郭のみを対象にする。
  3. 面積の `w * h` 化: 輪郭面積（`cv2.contourArea`）の代わりに、見た目の面積に一致する外接矩形（Bounding Box）の面積 `w * h` を `area` と判定。
  4. パラメータフィルタ: 面積（`min_area`）、ROI位置（中心座標がROI内か）、アスペクト比を検証。
  5. `detect_bubble` は最良（最大面積）の合格候補を1つ返却。
  6. `detect_bubble_candidates` (デバッグ用) は、OK/NGすべての候補を判定ステータス（`PASS`, `FAIL_AREA`, `FAIL_ROI`, `FAIL_ASPECT`）付きのリストとして返却。
  7. ROI 指定時は、画像全体で抽出された輪郭の中心座標がROI範囲内に含まれているかを判定してフィルタリング。

### 5-2. speech_draft_service.py (新規サービス)
- VLM 呼び出し: `call_llm_vision(image_base64, prompt)` を追加
  - LM Studio の `/chat/completions` エンドポイントに `image_url` (base64) を含む messages を送信
- LLM 呼び出し: 既存 `call_llm()` を使用
- LLM/VLM のモデルとシステムプロンプトは `llm_prompts` テーブルから取得
  - キー: `speech_draft_vlm_model`, `speech_draft_vlm_prompt`, `speech_draft_llm_model`, `speech_draft_llm_prompt`

### 5-3. Snapshot モデルの変更
- `snapshots` テーブルに `source_snapshot_id` カラム追加（派生元スナップショットIDの参照、nullable）
- `main.py` の `run_migrations()` に ALTER TABLE を追記

## 6. フロントエンド実装詳細

### 6-1. SpeechBubbleEditorModal (新規コンポーネント)
- `frontend/src/components/SpeechBubbleEditorModal.tsx`
- 内部状態:
  - `boundingBox: {x,y,w,h} | null` — 現在選択/適用中の吹き出し
  - `showDebugPanel: boolean` — 候補リストデバッグパネルの表示状態
  - `candidates: BubbleCandidate[]` — APIから返されたすべての候補輪郭
  - `filterStatus: 'all' | 'pass' | 'fail'` — 候補リストの判定フィルタ（初期値: `'pass'` - OKのみ）
  - `sortBy: 'area_desc' | 'area_asc' | 'brightness_desc' | 'distance_center' | 'id'` — リストの並び順（初期値: `'area_desc'`)
  - `lastUsedROI: {x,y,w,h} | null` — 直近に使用したROI座標の記録
- Canvas 描画:
  - 選択中 (`boundingBox`) の吹き出しは緑枠でハイライトし、入力テキストを内部に重畳表示。
  - デバッグON時は、合格候補を薄い緑の破線、不合格候補を薄い赤の破線でオーバーレイ表示。
  - マウスホバー中の候補はオレンジ色の太枠でハイライト。
- 候補リスト・フィルタ・ソートコントロール:
  - 判定フィルタによる絞り込み、および各種条件（面積順、輝度順、ID順、ROI中心距離順）での並び替え。
  - **ROI自動ソート連動**: ユーザーがROIをドラッグ指定した瞬間、`sortBy` が自動的に `'distance_center'` に切り替わり、指定の中心に最も近い候補がリストの最上位に並びます。
  - 候補行をクリックまたは「適用」ボタン押下で、該当座標を `boundingBox` に適用。
- ドラフト生成: `POST /api/llm-prompts/speech-draft` — VLM/LLMによる自動下書き生成。
