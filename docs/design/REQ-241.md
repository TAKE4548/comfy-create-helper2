# 設計書: REQ-241 Web Appからのサービス停止・再起動の不整合および競合バグの解消

## 1. 設計概要 (Architecture Overview)

本設計は、Prompt Surgeon のサービスマネージャー（`tools/server-manager/server_api.py` および `server-manager.ps1`）において、Web UI（ポート 8899）からのサービス停止・再起動操作が不安定になる以下の 5 つの課題を根本解決し、あわせてモバイル等の同一 LAN 端末からのアクセスを可能にする。

1. **個別操作時のサービス識別子の不一致**: Web UI（`fe`, `be`, `comfy`）と PowerShell（`frontend`, `backend`, `comfy`）間の識別子表記ゆれを解消する。
2. **Web サーバーの同期ブロッキングと連打・ポーリング競合**: `server_api.py` を `ThreadingMixIn` でマルチスレッド化し、UI に操作中ロック（`disabled`）を導入して多重リクエストを防止する。
3. **再起動時のポート解放待ち抜け (Race Condition)**: `Stop-AllServices` で全ポート（8188, 8000, 5173）の `Wait-For-Port-Closed` を義務化し、古いプロセスの残留による `Test-PortOpen` 誤判定・起動スキップを防止する。
4. **Web 経由起動時の `-Background` フラグ欠落**: Web API から PowerShell を呼び出す際、`start`, `restart`, `reboot-service` の場合は常に `-Background` を付与し、非対話環境でのハングを防ぐ。
5. **WSL2 ComfyUI 停止時のホストプロキシ誤爆保護**: ComfyUI は Linux VM 内部プロセスであるため、Windows 側ポート 8188 の所有プロセス（WSL プロキシ）への `taskkill` を廃止し、WSL ネットワーク仲介を保護する。
6. **同一 LAN からの Web Manager アクセス対応**: サーバー起動時に PC のローカル IP（`192.168.x.x`）を自動検出し、コンソール起動ログおよび Web UI ヘッダーにモバイル接続用 URL を明示。またポート 8899 の Windows ファイアウォール許可バッチを提供する。

## 2. アーキテクチャ変更点 (Architectural Changes)

```
[Web UI (Browser / Mobile)]
   │
   ├─ (ボタン押下) ──> UI全体を disabled ロック
   │
   ├─ (POST /api/action) ──> [ThreadedTCPServer (0.0.0.0:8899)]
   │                             │ (別スレッドで実行)
   │                             └─> powershell.exe -Action ... -Background
   │                                    │
   ├─ (GET /api/status) ────> 並行処理でブロックされず即座に応答
   │
   ├─ (GET /api/info) ──────> ホスト名・ローカルIPアドレス返却
   │
   └─ (アクション完了) ───> UIロック解除 (disabled = false) & ログ出力
```

## 3. モジュール別詳細設計 (Detailed Module Design)

### 3.1 `tools/server-manager/server-manager.ps1`

#### A. サービス識別子の正規化関数 (`Get-NormalizedServiceName`)
```powershell
function Get-NormalizedServiceName ([string]$name) {
    switch ($name.ToLower()) {
        { $_ -in "fe", "frontend" } { return "frontend" }
        { $_ -in "be", "backend" } { return "backend" }
        { $_ -in "comfy", "wsl" } { return "comfy" }
        default { return "" }
    }
}
```
- `Action` が `start`, `stop`, `restart`, `reboot-service` の場合、`$Service` または `$name` を `Get-NormalizedServiceName` を通して正規化し、`frontend`, `backend`, `comfy` のいずれかで統一判定する。

#### B. `Stop-AllServices` のポートクローズ待機義務化
- `Stop-AllServices` の末尾において、3 サービスすべてのポートクローズを明示的に待機する。
```powershell
function Stop-AllServices {
    Write-Host "Stopping all services..." -ForegroundColor Yellow
    Stop-ComfyUIProcess
    Stop-BackendProcess
    Stop-FrontendProcess

    Write-Host "Waiting for ports to close..." -ForegroundColor Gray
    Wait-For-Port-Closed -port $cfg.wsl.port -timeoutSec 5 -serviceName "WSL ComfyUI" | Out-Null
    Wait-For-Port-Closed -port $cfg.backend.port -timeoutSec 5 -serviceName "Backend" | Out-Null
    Wait-For-Port-Closed -port $cfg.frontend.port -timeoutSec 5 -serviceName "Frontend" | Out-Null
}
```

#### C. `Stop-ComfyUIProcess` の Windows 側プロセスキル誤爆廃止
- ComfyUI 停止処理において、`Stop-PortProcesses $cfg.wsl.port "ComfyUI"` の呼び出しを削除する。
- WSL 内部の `pkill -f 'python.*main.py'` および `pkill -9` フォールバック、さらに Windows 側のタイトル一致 `cmd.exe` 回収のみで安全に停止を完結させる。

### 3.2 `tools/server-manager/server_api.py`

#### A. マルチスレッド HTTP サーバー (`ThreadedTCPServer`)
```python
class ThreadedTCPServer(socketserver.ThreadingMixIn, socketserver.TCPServer):
    daemon_threads = True
    allow_reuse_address = True
```
- `run_server()` で `ThreadedTCPServer` を使用。
- これにより、10〜30秒かかる重いアクション実行中であっても、5秒間隔の `/api/status` リクエストが別スレッドで並行処理され、UI の応答性が維持される。

#### B. `-Background` フラグの自動付与
- `do_POST` の `/api/action` ハンドラ内：
```python
cmd = ["powershell.exe", "-ExecutionPolicy", "Bypass", "-File", str(PS_SCRIPT), "-Action", action]
if action in ["start", "restart", "reboot-service"]:
    cmd.append("-Background")
if service:
    cmd += ["-Service", service]
```

#### C. フロントエンド UI の二重送信防止ロック
- `HTML_TEMPLATE` 内の JavaScript に `setControlsDisabled(disabled)` 関数を追加：
```javascript
function setControlsDisabled(disabled) {
  const buttons = document.querySelectorAll('button');
  buttons.forEach(btn => {
    btn.disabled = disabled;
  });
}
```
- `triggerAction` の `try ... finally` ブロックで確実にボタンの活性／非活性を制御。
- 実行中はコンソールログにローディング文言を表示。

#### D. ローカル LAN IP 検出と UI ヘッダー表示
```python
def get_local_ip():
    try:
        with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as s:
            s.connect(("8.8.8.8", 80))
            return s.getsockname()[0]
    except Exception:
        try:
            return socket.gethostbyname(socket.gethostname())
        except Exception:
            return "127.0.0.1"
```
- 起動時にコンソールへ `http://localhost:8899` と `http://<local_ip>:8899` の両方を出力。
- Web UI の HTML ヘッダー部に LAN アクセス用 URL バッジを表示。

### 3.3 `tools/server-manager/allow_firewall_8899.bat` (新規)
- Windows Defender ファイアウォールにおいて、ポート 8899（TCP 受信）の通信を許可するルールを追加する管理者権限付きワンクリックバッチ。
```cmd
@echo off
title Prompt Surgeon - Allow Port 8899 in Firewall
net session >nul 2>&1
if %errorLevel% neq 0 (
    echo Administrator privileges required. Requesting elevation...
    powershell -Command "Start-Process '%~f0' -Verb RunAs"
    exit /b
)
powershell -Command "New-NetFirewallRule -DisplayName 'Prompt Surgeon Web Manager (8899)' -Direction Inbound -LocalPort 8899 -Protocol TCP -Action Allow -Profile Any -ErrorAction SilentlyContinue"
echo Firewall rule added for Port 8899.
pause
```
