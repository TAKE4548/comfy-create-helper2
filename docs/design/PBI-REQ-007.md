# 設計書 - REQ-007: タグセット一覧画面のカード型レイアウト化

## 1. 目的と概要
現在、タグセット一覧画面（TagsPage）はリスト形式で実装されていますが、LoRA管理画面（LoRAsPage）のカード型レイアウトとデザインの一貫性がありません。
また、タグセットの情報量が増えた際に画面の有効活用ができておらず、タグセットを詳細に確認したり、すばやく編集したりする操作性にも改善の余地があります。

本設計では、タグセット一覧画面をレスポンシブなカード型（グリッドレイアウト）に変更し、ビジュアルおよび操作性をLoRA管理画面に近づけます。

主な変更点：
- **カード型レイアウトへの移行**: リスト形式から、画面幅に応じて複数カラムに並ぶグリッドレイアウトに変更します。
- **テキスト主体のデザイン**: サムネイル画像は配置せず、テキストとタグチッププレビューを中心としたデザインにします。
- **詳細モーダル表示**: カード自体をクリックした際に、含まれるすべてのタグを表示する詳細モーダルを追加します。
- **インライン・サブアクション**: カード上に直接「編集」および「削除」のサブボタンを配置します。
- **タグセット編集機能の追加**: 既存の作成フォームを再利用（または類似フォームの実装）し、登録済みのタグセットを直接編集・更新できるようにします。

## 2. アーキテクチャ設計

### 2.1 フロントエンド（React + TypeScript）

#### 1. 状態管理（TagsPage.tsx）
- `selectedTagSetForDetail` (TagSet | null): 詳細モーダルに表示する対象のタグセット。
- `editTagSet` (TagSet | null): 編集モーダルに表示・編集する対象のタグセット。
- `editForm` (form state): 編集時の入力フォーム状態（`name`, `description`, `category_id`, `tags`）。
- 既存の `showModal` (boolean): 新規作成モーダルの表示制御。

#### 2. API連携
- 更新時には `tagSetsApi.update(id, data)` を使用してバックエンドに `PUT /api/tag-sets/{id}` リクエストを送信します。
- 成功時は `useQueryClient` を用いて `tag-sets` クエリキャッシュを無効化（`invalidateQueries`）し、一覧を再取得します。

## 3. UI/UX デザイン設計

### 3.1 カード型レイアウト（デスクトップ時：grid-cols-2〜4程度）
```
+------------------------------------+
| [Tag-Icon]  セット名        [Edit] |  <- タイトル行 ＋ サブボタン（編集・削除）
| (Category / 12 tags)        [Trash]|  <- カテゴリ名やタグ数のサブ情報
+------------------------------------+
|  #tag1  #tag2  #tag3  #tag4        |  <- タグ一覧のプレビュー（チップ形式）
|  #tag5  ...                        |
+------------------------------------+
```
- カードをクリックすると、詳細モーダルが開きます。
- 編集ボタン（Pencilアイコン）または削除ボタン（Trash2アイコン）をホバー時または常時（モバイル時含む）カード右上に配置します。
- デスクトップ環境では `grid grid-cols-2 md:grid-cols-3 lg:grid-cols-4 xl:grid-cols-5 gap-4` のようにレスポンシブ対応を行います。

### 3.2 詳細モーダル（Detail Modal）
カードクリックで開き、タグセット名、説明文、所属カテゴリ、およびタグセットに含まれる全タグをコピー可能な形式で一覧表示します。

### 3.3 編集モーダル（Edit Modal）
編集ボタンをクリックした際に、フォームに既存の値をロードした状態でモーダルを起動します。
入力内容：
- セット名 (Name)
- 説明 (Description)
- カテゴリ (Category)
- タグ一覧 (Tags - カンマ区切りのテキストエリア)
保存ボタン押下で `updateTagSet` mutation が実行されます。
