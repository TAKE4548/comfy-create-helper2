# REQ-144 詳細設計書: セリフ編集のベース画像差し替えにおける全履歴対応・履歴フィルタおよびアルバム選択機能

## 1. 概要 (Overview)
REQ-143 で実装された `BaseImageSelectModal` は、セリフ編集画面から別の生成画像へベース画像を差し替える機能を提供しています。
しかし、現状の実装では以下の課題があります：
1. **全履歴の未表示 / ワークフロー制限**: モーダル呼び出し時の単一 `workflowId` で `snapshotsApi.list({ workflow_id })` を呼び出しているため、他ワークフローのスナップショットや全履歴を俯瞰して選択することができず、またページネーション/無限スクロールがないため大量スナップショットへのスケーラビリティに欠けている。
2. **検索・フィルタリング手段の欠如**: 履歴ページと同等のワークフロー選択、LoRAフィルタ、TagSetフィルタ、並び順切り替え（新しい順/古い順）が存在しないため、目的の画像を素早く特定できない。
3. **アルバムからの選択が不可能**: ユーザーが Albums（アルバム）機能で整理・分類したコレクションから直接ベース画像を選択できない。

本設計では、`BaseImageSelectModal` を大幅に強化し、以下の機能を提供します：
- **全履歴対応と無限スクロール**: ワークフローの制限なく全スナップショットを取得・閲覧可能にし、IntersectionObserver による段階的ロード（+24件ずつ）を導入。
- **履歴同等のフィルタ・ソート**: ワークフロー、LoRA、TagSet フィルタ、および新しい順/古い順のソート機能をモーダル上部に統合。
- **アルバム選択タブ**: 「履歴 (Snapshots)」と「アルバム (Albums)」のタブ切り替えを追加し、アルバム一覧およびアルバム内アイテムから直接ベース画像を選択可能にする。

## 3. 詳細設計 (Detailed Design)

### 3.1 `BaseImageSelectModal` コンポーネント構造

```tsx
export interface BaseImageOption {
  id: number
  image_path?: string | null
  thumbnail_path?: string | null
}

export type CloseCallback = () => void
export type SelectSnapshotCallback = (snapshot: BaseImageOption) => void

export interface BaseImageSelectModalProps {
  workflowId?: number
  currentSnapshotId: number
  onClose: CloseCallback
  onSelect: SelectSnapshotCallback
}
```

### 3.2 状態管理 (State Management)
- `activeTab`: `'snapshots' | 'albums'`
- **Snapshots Tab State**:
  - `selectedWorkflowId`: `number | null` (初期値: props の `workflowId` または `null`)
  - `selectedLoraId`: `number | null`
  - `selectedTagSetId`: `number | null`
  - `sortOrder`: `'desc' | 'asc'`
  - `snapshotLimit`: `number` (初期値: 24, スクロール時に +24)
- **Albums Tab State**:
  - `selectedAlbumId`: `number | null`
  - `albumSortBy`: `'custom' | 'date-asc' | 'date-desc'`
  - `albumItemLimit`: `number` (初期値: 24, スクロール時に +24)

### 3.3 データフェッチ (API Integration)
- `workflowsApi.list()` -> ワークフロードロップダウン
- `lorasApi.list()` -> LoRA ドロップダウン
- `tagSetsApi.list()` -> TagSet ドロップダウン
- `snapshotsApi.list({ workflow_id, lora_id, tag_set_id })` -> スナップショット一覧
- `albumsApi.list()` -> アルバム一覧
- `albumsApi.get(selectedAlbumId)` -> 選択されたアルバムの詳細・アイテム一覧

### 3.4 UI レイアウト設計
1. **Header**:
   - 左側: アイコン + タイトル「ベース画像を差し替え」
   - 中央/右側: タブ切り替えボタン [履歴 (Snapshots)] / [アルバム (Albums)]
   - 右端: 閉じるボタン (`X`)
2. **Snapshots View**:
   - フィルタバー:
     - ワークフロー選択 (`history-workflow-filter`)
     - LoRA 選択 (`history-lora-filter`)
     - TagSet 選択 (`history-tagset-filter`)
     - ソート順切り替え（新しい順 / 古い順）
     - 取得件数バッジ
   - スナップショットグリッド:
     - サムネイル画像
     - 現在のベース画像には「現在」バッジ表示
     - スナップショットID (`#ID`) 表示
     - 無限スクロール用センチネル要素 (`snapshotSentinelRef`)
3. **Albums View**:
   - **アルバム未選択時**:
     - アルバムカード一覧（アルバム名、画像枚数、先頭画像のサムネイルカバー）
     - クリックで `selectedAlbumId` をセット
   - **アルバム選択時**:
     - サブヘッダー: 戻るボタン (`ArrowLeft`)、アルバム名、枚数、ソートセレクター (`custom` | `date-asc` | `date-desc`)
     - アルバム内アイテムグリッド:
       - サムネイル画像、`#snapshot_id` 表示、「現在」バッジ
       - クリックで `onSelect({ id: item.snapshot_id, image_path: item.image_path, thumbnail_path: item.thumbnail_path })` を実行
       - 無限スクロール用センチネル要素 (`albumItemSentinelRef`)

## 4. UI/UX 仕様
- **シームレスな画像切り替え**: 履歴またはアルバムから画像を選択すると、モーダルが即座に閉じ、セリフ編集画面上のキャンバスに新しいベース画像が展開されます。
- **既存セリフの保持**: ベース画像切り替え時、ユーザーがすでに配置・編集した吹き出し（テキスト、座標、サイズ、フォント・色スタイル等）は完全に維持されます。
- **直感的な操作感**: 履歴ページおよびアルバムページと一貫したフィルタ・ソートUIを踏襲し、ユーザーが迷わず操作できるように設計します。
