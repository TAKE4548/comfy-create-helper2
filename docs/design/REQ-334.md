# REQ-334 Full Scope Design

## Source Comparison and Decisions

- Phase 1（項目1〜5）: split/Queue/二段進捗/取消安全性/global shortcut/保存/全画面視覚/複数選択。
- Phase 2（項目6〜10）: 全高Fit並列2〜4枚/N枚送り/Tablet/portrait cards/単語copy/専用drag/拡大比較。
- Phase 3（項目11〜16）: Mobile画像/24px進捗/segment状態保持/Steps1・CFG0.1・Denoise0.01・LoRA0.05/sheets/LoRA rich editor/AddAsset tray/TagSet parser。
- Phase 4（項目17〜20）: Studio新規承認・caption工程と評価/Albums/設定5タブ/import-export/Playground/感度preview/辞書/health/logs/save状態。
- AC-38/39は3000msの待機取消予約。Undoは予約解除であり取消後復元ではない。開始済みjobにinterruptを送らないようbackendのqueued-only原子guardが必要。
- AC-32/67はLoRA0.05刻みを要求。旧0.1を維持する案は廃止し、有効範囲を維持しつつUI刻みだけ0.05へ変更。
- AC-42は新規完了画像だけAPPROVED。既存REJECTED/再訪画像を上書きしない。
- AC-46は生成→選別→キャプション→学習の4段階。学習後4軸評価は独立導線として保持。従来step3/4の意味を黙って再利用しない。
- AC-11は未ロードを含む絞込み全件選択。画面DOMの件数ではなくAPIの全ID集合を正本にする。
- AC-13は選択中D&D禁止。従来group moveと矛盾する部分はこの要求の明示変更として正本同期する。
- AC-03/04/06/08は全対象modal/画面に適用。common Modalだけ・aliasだけに限定する旧案は廃止。
- AC-90/91/95/97は新しい保存/API経路の候補契約を別文書で定義し、未確認依存を可視化する。機能を延期として扱わない。

## Trade-off Disclosure

全範囲を維持するため旧10task案よりカード数・実装工数が増える。3秒取消予約はjob開始を停止しないのでqueued-only guardが必須。全件選択はAPIのID取得を待つが誤った件数で破壊操作を行わない。既存group D&Dを選択中に禁止する要求変更がある。caption工程追加でstage状態を明示変換する。Playground/辞書/import-exportにはBE契約確認と保存の原子性を必要とする。全画面視覚値の移行は対象surfaceごとのカードへ分割する。

## AC-70 契約確認漏れの補正（T106〜T112）

復旧PBIの「各サブセットのタグと画像」は、親TagSet画像だけでは満たさない。設計担当の再照合で、親画像のみとする承認済み例外は存在しないことを確認した。各TagSubsetにnullable `thumbnail_path`を追加し、親画像と独立して保存する。登録済み028migrationは旧データを保持して画像列を追加し、二重適用を許容する。

PUTは既存のサブセット全置換契約を維持する。各送信サブセットで省略はnull、明示null/空文字は解除、非空パスは設定。クライアントは編集・一括カテゴリ変更でも保存済みサブセットと画像を明示して送信し、意図しない削除を防ぐ。アップロード/クロップは既存snapshots/uploadを再利用し、安定した編集対象識別によって遅延応答を別サブセットへ割り当てない。取消・失敗は元画像を保持する。

T106モデル/スキーマ/型、T107migrationは根タスク。T106完了後にT108 API、T109フォームを並列実行。T109後T110保存/詳細/一括保持、T112失敗・競合テスト、T110後T111再訪テスト。最終SSoT/OpenAPIは親が同期する。既に承認されたACを満たす補正として扱い、要件を親画像だけへ緩めない。
