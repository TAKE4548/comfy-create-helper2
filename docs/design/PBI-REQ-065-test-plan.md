# REQ-065 実行可能テスト計画

## 1. 自動テスト (CLI Verification)
- 並び替えやAPI呼び出しロジックはフロントエンドの画面操作がメインとなるため、今回は主に手動によるブラウザ検証を実施します。
- 必要に応じて、一括編集時のデータマージ処理に関するフロントエンドの単体テストを導入します。

## 2. ブラウザ検証 (Browser Agent Verification)
- **対象URL**: `http://localhost:5173/` (フロントエンド開発サーバー)

### 2.1 LoRA / Tagセットの複数選択並び替えテスト
1. LoRA または Tag セットページに移動する。
2. アイテムを複数選択する（例: A, B）。
3. 選択した A をドラッグし、別の非選択アイテム C の直前にドロップする。
   - **期待値**: A と B の両方が C の直前に正しく移動し、順序が保存されること。
4. 選択した A をドラッグし、同じく選択中である B の上にドロップする。
   - **期待値**: リスト最前面に勝手に移動したりクラッシュしたりせず、移動がキャンセルされるか正常に動作すること。

### 2.2 一括編集機能のテスト
1. LoRA または Tag セットページで複数のアイテムを選択し、「一括編集」をクリックする。
2. カテゴリなどのフィールドを変更し、「適用する」をクリックする。
   - **期待値**: モーダルが正常に閉じ、選択した全てのアイテムに変更内容が反映され、再ロード後も維持されること（422バリデーションエラーが発生しないこと）。

### 2.3 マッピングマスタ複数選択時の並び替えテスト
1. 設定ページ (`SettingsPage`) を開く。
2. マッピングマスタの一覧を行長押しなどで複数選択モードにする。
   - **期待値**: 各行の左側にチェックボックスとグリップアイコンが並んで表示されること。
3. グリップアイコンをドラッグ＆ドロップして並び替える。
   - **期待値**: 複数選択中であっても、グリップアイコンを使って行の並び替えができること。
