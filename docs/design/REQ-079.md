# REQ-079: モバイルモードのタブ・プロファイル同期およびコピー作成対応

## 1. 概要
本設計書は、画像生成画面における「セット（タブ）」と「プロファイル（プリセット）」の概念を1:1で統合し、モバイル端末での操作性向上と端末・セッション間でのデータ同期を実現するための設計を定義します。

### 1.1 現状の課題と改善方針
1. **モバイルUIの不足**:
   - モバイル版UI（`MobileLayout`）にセット切り替え・管理用のUIが存在しない。
   - 対策: モバイル版にもスクロール可能なタブバーおよびセット操作用のUIを追加する。
2. **データの端末・セッション間での非同期**:
   - セット（タブ）データがブラウザのLocalStorageに保存されているため、別端末や別ブラウザで同期されない。
   - 対策: ローカルの `sets` 状態を廃止し、バックエンドの `workflow_presets`（プリセット）と完全に統合する。タブ＝プロファイルとして扱い、サーバー側でデータを永続化する。
3. **プロファイル編集とコピー作成の使い勝手の維持**:
   - プロファイルを柔軟にコピーして新しいタブを作成できるようにする。
   - 対策: 新規タブ追加時に、ベースとする既存プロファイル（またはワークフローのデフォルト設定）を選択してコピー作成できるダイアログを実装する。

---

## 2. システムアーキテクチャ・設計詳細

### 2.1 データモデルの統合 (プロファイル ＝ タブ)
現行の `sets`（フロントエンドのローカル状態）を廃止し、バックエンド of `WorkflowPreset` を「タブ」のデータソースとして直接使用します。

| 現行概念 | 新概念 | 永続化先 |
| :--- | :--- | :--- |
| タブ (GenerationSet) | プロファイル (WorkflowPreset) | サーバーDB (`workflow_presets` テーブル) |
| アクティブタブID (`activeSetId`) | アクティブプロファイルID (`activePresetId`) | LocalStorage (端末ごとに独立させるため) |
| タブ選択状態 (`checked`) | プロファイル選択状態 (`checked`) | LocalStorage (`prompt-surgeon-checked-presets`) *※スキーマ変更を避けるため* |

#### チェック状態 (`checked`) の管理方針
DBスキーマ変更とマイグレーションの複雑化を避けるため、各プロファイルの「一括生成対象チェック状態」は LocalStorage で管理します。
- キー名: `prompt-surgeon-checked-presets-{workflowId}`
- 値: `{ [presetId: number]: boolean }` のJSON文字列

### 2.2 API連携と自動保存 (オートセーブ)
タブ（プロファイル）の内容が変更された際、サーバーに自動保存されるようにします。

1. **自動保存のトリガー**:
   - パラメータ値の変更 (`paramValues` の更新)
   - 適用アセットの変更 (`appliedAssets` の更新)
   - バッチサイズ・シードモード・シードの変更
2. **自動保存の制御 (Debounce)**:
   - 変更のたびに即座に API を呼び出すとサーバー負荷が高くなるため、変更後 **1秒間** 操作がない場合に `updatePresetMutation` を実行するデバウンス処理を導入します。

### 2.3 コピー新規作成のUIフロー
新規タブ（プロファイル）の追加時、以下のダイアログを表示します。

1. **入力項目**:
   - プロファイル名 (テキスト入力、デフォルトは「プロファイル N」)
   - コピー元 (セレクトボックス)
     - オプション1: 「ワークフローのデフォルト」(新規作成時の初期値)
     - オプション2: 既存のプロファイル一覧 (各プロファイル名を表示)
2. **作成処理**:
   - コピー元が「ワークフローのデフォルト」の場合: ワークフロー定義から初期パラメータを取得して新規プリセットを作成。
   - コピー元が「既存のプロファイル」の場合: 選択されたプロファイルの設定値（パラメータ、アセット等）をコピーして新規プリセットを作成。

### 2.4 モバイルUIレイアウト (`MobileLayout.tsx`)
モバイル表示時、メインプレビューとプロンプト入力エリアの間に、スクロール可能なタブバーを配置します。

```
+-----------------------------------+
|  Generate (Header)                |
+-----------------------------------+
|  Main Preview                     |
+-----------------------------------+
| [Set 1] [*Set 2] [Set 3]  [+ Add]  | <-- スクロール可能なタブバーを追加
+-----------------------------------+
|  Active Prompt Input              |
|  ...                              |
+-----------------------------------+
```

## 3. 懸念点・トレードオフ (Trade-off Disclosure)

### 3.1 オートセーブによるネットワークトラフィック
- **懸念**: パラメータ変更のたびにAPIリクエストが発生するため、ネットワーク接続が遅い環境で遅延が発生する可能性がある。
- **対策**: フロントエンド側で十分なデバウンス時間（1000ms）を設け、連続入力中の不要なリクエストを抑制します。

### 3.2 同時編集の競合
- **懸念**: 複数端末で同じプロファイルを開いて同時にパラメータを編集した場合、後に保存した側で上書きされるラストライターウィン（Last-Writer-Wins）仕様になります。
- **対策**: 個人開発および小規模チームでの利用を想定しているため、現状はラストライターウィンを許容します。将来的に競合検知が必要な場合は楽観的ロックを検討します。
