# 設計書 - REQ-001: メインの生成画面でのワークフロー読込エラー回避およびマッピング手動修正機能

## 1. 目的と概要
移行データの不備等により、マッピングマスタ（`mapping_master`）に存在しない無効な `master_id` を持つレコードが `workflow_mappings` に含まれている場合、バックエンドAPI `/api/workflows/{id}` が500 Internal Server Errorを返却し、画面側で入力欄が生成されなくなる問題を解決します。
さらに、無効なマッピングが存在する場合にフロントエンド画面上で警告を表示し、どのノードが問題であるかを知らせるとともに、ユーザーが正しいマッピングへ紐付け直すための手動修正UIを構築します。

## 2. アーキテクチャ設計

### 2.1 バックエンド（FastAPI）
- **Pydantic スキーマ (`backend/app/schemas.py`)**
  - `WorkflowMappingRead` の `role`, `param_name`, `input_type`, `display_name` フィールドを `Optional` に変更し、マスタ定義が存在しない場合でもシリアライズ可能にします。
  - `WorkflowUpdate` スキーマを追加し、ワークフローのマッピング情報等を更新できるようにします。
- **ルーター (`backend/app/routers/workflows.py`)**
  - `GET /api/workflows/{workflow_id}` エンドポイントにおいて、`m.master` が `None` の場合に属性エラーにならないよう、`m.master.role if m.master else None` のように安全なアクセスに修正します。
  - `PUT /api/workflows/{workflow_id}` エンドポイントを追加し、ワークフローのマッピングの更新を受け入れ、古いマッピングをクリアした上で新しいマッピングを保存できるようにします。

### 2.2 フロントエンド（React + TypeScript）
- **API クライアント (`frontend/src/api/`)**
  - `client.ts` の `workflowsApi` に `update` メソッドを追加します。
  - `types.ts` の `WorkflowMapping` インターフェースを更新し、`role`, `param_name`, `input_type`, `display_name` が `string | null` になり得るようにします。
  - `types.ts` に `WorkflowUpdate` インターフェースを追加します。
- **UI コンポーネント (`frontend/src/pages/GeneratePage.tsx`)**
  - 現在のワークフローから、有効なマッピング（`role !== null`）と無効なマッピング（`role === null`）を分離します。
  - 有効なマッピングのみを入力欄（プロンプト・パラメータ）の生成対象とします。
  - 無効なマッピングが検出された場合、パラメータ列（左カラム）の最上部に警告を表示します。
  - 警告エリア内において、エラーが発生しているノード（node_id）ごとに、利用可能な `MappingMaster` の一覧（`mappingMastersApi.list()` から取得）をドロップダウン（select）で表示し、正しい役割（Role）を選択して保存（更新APIの呼び出し）を行えるようにします。

## 3. API 仕様

### 3.1 ワークフロー更新 API
- **パス**: `PUT /api/workflows/{workflow_id}`
- **リクエストボディ (WorkflowUpdate)**:
  ```json
  {
    "mappings": [
      { "master_id": 1, "node_id": "6" },
      { "master_id": 5, "node_id": "12" }
    ]
  }
  ```
- **レスポンス (WorkflowSummary)**:
  ```json
  {
    "id": 1,
    "name": "portrait_v3",
    "created_at": "2026-06-05T12:00:00Z"
  }
  ```

## 4. UI/UX デザイン設計
警告パネルは、視認性の高いオレンジ、もしくは赤のボーダーラインと背景色を使い、他のパラメータセクションと区別しやすい位置に配置します。

```
+-------------------------------------------------+
| ! マッピングエラーの検出                        |
| 以下のノードのマッピング先が無効になっています。|
| 正しい役割を選択して紐付けを修正してください。  |
|                                                 |
| [ノード ID: 334]                                 |
| 役割: [ キャラクター Lora (Model)          v]   |
| [ マッピングを修正する ]                         |
+-------------------------------------------------+
```
マスタの一覧から正しい役割を選択し、「マッピングを修正する」をクリックすると、API経由でデータベースが更新され、画面が自動でリロードされて該当ノードの入力欄が生成されます。
