## Existing Contracts and Feasibility
- React18 / Zustand5 / TanStack Query5 / Vitest1.6 / Playwright。新dependencyなし。
- 両layoutは `sets.filter(openPresetIds)` 順。左右はopenPresetIds配列順でなくこの表示順。
- storeのclosePresetはopen IDs除去だけ、removeSetは単件close後の選択を先頭へfallback。連続呼出しでは今回の基準タブ選択規則と原子的画面更新を満たさない。
- flushAutoSave():voidは保存開始要求でACK待ちではない。現状は成功前にlastSavedStateRefへ代入し、pendingSaveArgsRefは単一slot。このままflush→closeすると保存失敗と複数タブを保護できない。

## Target Selection and Commit
- 新規 `frontend/src/store/presetTabClose.ts` に `PresetTabCloseMode='others'|'left'|'right'` と純粋plannerを追加。ID比較はString正規化し、返却IDは元型を維持。sets順でopen IDsとの交差を取る。
- `createPresetTabClosePlan(input,triggerId,mode):PresetTabClosePlan|null`。inputはselectedWorkflowId/sets/openPresetIds/activeSetId。planはworkflowId/triggerId/mode/orderedOpenIds/targetIds/activeSetId/nextActiveId。重複除去、無効trigger・workflowなしはnull、targetなしはno-op。
- A B C D EのC起点: left target=A B、right target=D E、others target=A B D E。Cは全modeで対象外。
- メニュー表示中のdisabled/countは最新列に追従。確定クリック時にplanを凍結。保存中の並び変更に合わせて閉じる対象を再計算しない。
- storeへ `applyPresetTabClose(plan):boolean`。workflow/表示順/open集合/active/triggerを再照合し、変化時は何も閉じずfalse。
- sets/checked/chips/historyは保持。open IDsだけからtargetを除き、旧activeが残れば維持、閉じるならtriggerへ。paramValues/appliedAssets/promptChips/batchSize/seedMode/seedも一回のsetで同期する。
- 既存open presetsとACTIVE_SET_PREFIXのlocalStorage keysを更新。プリセットDELETEは呼ばない。管理から再open可能。
- WebStorageは2キーtransactionではない。例外時はメモリcloseを行わず旧値へ復旧を試み、失敗を通知する。恒久storage障害を完全にtransaction化する変更は範囲外。

## Acknowledged Save Barrier
- T1はusePresetState内のupdatePresetMutation.mutateAsyncに狭いadapterを導入。backend契約・query cache全体・保存UI全体の刷新はしない。
- private `enqueuePresetSave(args:UpdatePresetArgs):Promise<void>` とin-flight/queued jobsを持つ。既存performUpdatePresetのvoid口は維持し、rejectionは処理する。
- 同ID・同snapshotは既存Promiseへdedupe。異IDpendingを単一slotで上書きしない。異snapshotは順序を保ち、先行失敗後の後続を無条件に保存しない。
- base_updated_atはjob直前の成功ACKで得た値を使う。409の自動force/rebase retryはしない。既存競合解決操作または利用者の再操作へ戻す。
- lastSavedStateRefはサーバー確認済snapshot（初回GET/明示loadと成功PUT ACK）のみ。初回GET時の既存StoreSync初期化で全presetのbaselineを作り、Cleanな非activeの後続GETだけを既存reconcileに従って更新する。Dirty/pending/失敗中のlocal snapshotをGETでACK扱いしない。AutoSaveの成功前代入を除き、必要なStoreSync調整はT1が所有する。通常のClean一括closeは初期同期完了後に可能。
- production保存入口はautosaveのperformUpdatePreset、handleUpdatePreset、競合overwriteのonUpdatePresetを同adapterへ集約。returned updatePresetMutationを使う既存呼出しとの互換性を残し、そのonMutate/onSettledでもin-flight/世代を追跡する。管理のcreate/rename/delete/reorder/bulk適用が進行中ならbarrier開始を断り、途中開始ならoperation世代変化でcloseを中止する。backendや一般管理UIは改造しない。
- `preparePresetTabsClose(plan):Promise<boolean>`: 重複close拒否、timer停止、active UI bufferをsetsへ同期、対象全件snapshotをclone。activeが対象外でもbufferを同期し最新編集を守る。
- active対象は最新editor、inactive対象は各sets snapshot。ACKとの差分をdirtyとする。初期同期未完・ACK未知・preset欠落は安全側に中止し通知。
- 既存in-flightを待ち、dirty targetを同adapterで順次保存。targetの未解決競合・保存失敗ではcloseを中止し、既存競合モーダル/エラートーストと再操作を案内する。
- 一部server保存成功後に後続失敗しても全targetは開いたまま。成功済server書込のrollbackは主張しない。失敗/未送信snapshotはローカル保持しACKと誤記録しない。
- 完了直前にworkflow/mount世代、planの表示順/open/active、全target内容と対象外active bufferを再確認。drift時はcloseせず再操作。scope外の新規tabを閉じない。
- workflow切替/unmountで世代token無効化。後着ACKは旧操作のcloseを発火させない。送信済HTTP取消/server rollbackは保証しない。jobのquery keyはcaptured workflowで固定し、新workflow cacheへ混入させない。
- usePresetStateが返す `handleClosePresetTabs(triggerId,mode):Promise<boolean>` と `isPresetTabsClosing:boolean` を双方layoutから使う。既存useGeneratePageStateのspreadで伝わるため追加配線変更は不要。

## UI and Interaction
- GeneratePage/componentsに共有PresetTabItem/PresetTabCloseMenuを追加し、desktop局所SetTabItemとmobile inlineを置換。
- 外枠は非interactive group。選択button・checkbox・単件close・ellipsisは兄弟としbuttonを入れ子にしない。
- 通常tap入口は各tabの常設 `…`（aria-label=`${name}のタブ操作`）。非activeでもmenuを開くだけではselectしない。
- 選択領域の右contextmenuとtouch/pen500ms長押しで同じmenu。controls起点は長押し対象外。8px超移動/scroll/up/cancel/2本目pointer/unmountでtimer解除。
- pointerdown時はpreventDefaultもpointer captureも行わず、横scrollを維持する。長押し成立後だけ発生するcontextmenuをpreventDefaultし、続くsynthetic clickを一度消費する。native contextmenu重複はdedupeし、通常tapへ抑止を持ち越さない。
- 3項目は「他のタブを閉じる」「左のタブをすべて閉じる」「右のタブをすべて閉じる」。target0はdisabled表示。
- 768px以上はbody portal fixed menuをviewport内に補正。未満は既存BottomSheetをreuseし中央modalを追加しない。見出しに対象tab名。
- desktop menu/menuitemでArrow/Home/End/Enter/Space/Escape。mobileはdialog内通常buttons、feature側でfocus循環を補う。初期focusは有効項目、全disabledなら閉じるへ。
- outside/backdrop/Escapeはmenuのみ閉じ、背景click-throughを防ぐ。focusは起点controlへ、消失時は残るactiveへ戻す。
- 保存開始でmenuを閉じ、pending中は二重close無効。menu閉鎖と保存取消を混同しない。global input lockはせず、変更があればbarrierの再検証で中止。
- Tabs/Chips+Overlays+Controls: min-w-0/truncate、shrink-0/nowrap、overflow-x-auto、44px操作領域、最低11px、dvh、sheet overscroll-contain。tab列はpan-x pan-y/manipulationで横scroll維持、一律pan-yを強制しない。

## Trade-offs and Review
- ACK待ちでclose遅延、保存中変更で再操作が必要。global input lockは採用しない。
- 常設ellipsisはtab幅を使うが通常tap代替と発見性を満たす。
- 単一pending slot/成功前markerの改修は既存flush/競合/履歴/pollへ影響するため全FE discoveryと維持scenario必須。一般保存system全体の刷新はしない。
