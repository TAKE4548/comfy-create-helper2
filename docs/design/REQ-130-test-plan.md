# テスト計画書: REQ-130 (Add Set 実行時の新規セット自動アクティブ化)

## 1. 概要
REQ-130 の修正に対するテスト計画。自動テスト（Vitest）および手動検証手順を定義する。

## 2. 自動テスト計画 (Automated Tests)

### テストコマンド
```bash
npx vitest run frontend/src/pages/GeneratePage/hooks/__tests__/useGeneratePageState.test.tsx
```

### 検証項目
1. `handleCreatePreset` 呼び出し成功時に `setActiveSetId` が新セットの ID で呼び出されること。
2. `presets` 配列更新時、`localStorage` のアクティブIDが最優先で `activeSetId` に反映されること。

## 3. 手動検証計画 (Manual Test Plan)

### テストケース TC-1: 新規セット作成時の自動アクティブ化
1. 開発サーバー (`npm run dev`) を起動し、ブラウザで生成画面を開く。
2. ワークフローを選択し、Set 1 がアクティブになっていることを確認する。
3. 「+ Add Set」ボタンをクリックし、新規プロファイル作成モーダルを開く。
4. プロファイル名に「Set 2」と入力して「作成」ボタンを押下する。
5. **判定基準**:
   - Tabバーで「Set 2」が選択状態（アクティブ）になること。
   - 画面のパラメーターエリアに「Set 2」の設定値が反映されていること。

### テストケース TC-2: ページ再読み込み・タブ切り替えの回帰確認
1. TC-1 に引き続き、画面をリロード (F5) する。
2. **判定基準**: リロード後も「Set 2」がアクティブな状態を保持していること。
3. 「Set 1」タブをクリックして切り替える。
4. **判定基準**: 「Set 1」がアクティブになり、正常にタブ切替ができること。
