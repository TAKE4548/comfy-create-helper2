# REQ-262: フロントエンドビルド成果物のuvicorn内包配信と単一プロセス配布 詳細設計書

## 1. 背景と課題

Prompt Surgeon では、開発時にフロントエンド（Vite 開発サーバー: ポート 5173）とバックエンド（FastAPI / Uvicorn: ポート 8000）を別プロセスとして起動・運用している。
しかし、一般ユーザーや他環境への配布・運用時においては、Node.js の常駐や 2 つのターミナル・プロセスの管理が大きな運用負荷・摩擦（Deployment Friction）となっている。
また、現行の `tools/server-manager`（一括起動バッチ、タスクスケジューラ常駐サービス）も ComfyUI + Backend + Frontend (npm run dev) の 3 プロセス固定で起動する設計となっており、Port 8000 のファイアウォール開放、内包配信時のスマート運用連動、およびエージェント自身がビルドを実行・検証できる専用スラッシュコマンド（`/build`）が未整備であった。

### 解決すべき要件
1. **単一プロセスでの Web UI 提供**: フロントエンドのビルド成果物（`frontend/dist`）が存在する場合、Uvicorn（FastAPI）が静的ファイルを配信し、ブラウザから `http://localhost:8000/` でアプリケーション全機能を利用可能とする。
2. **SPA ルーティング・フォールバック対応**: React Router によるクライアントサイドルーティング（例: `/generate`, `/presets`, `/settings` 等）への直接アクセスやページリロード時、404 エラーとならず `index.html` を正常にフォールバック配信する。
3. **API・静的アセットの保護**:
   - `/api/...` 配下の未定義エンドポイントは、HTML へフォールバックせず正規の JSON 404（`{"detail": "Not Found"}`）を返却する。
   - 存在しない JS / CSS / 画像などの静的ファイル（拡張子付きパス）は、MIME タイプの不一致によるスクリプトパースエラーを防ぐため正規の 404 を返却する。
4. **開発体験（Dev Server）の完全維持**: Vite 開発サーバーによるホットリロードやプロキシ設定は一切変更せず、開発時は引き続き独立して快適に開発できる構成とする。
5. **Server Manager のスマート連動（設定切替不要）**:
   - 一括起動時（`Start-AllServices` / `start_servers.bat` 等）: `frontend/dist` が存在する場合、自動的に ComfyUI + Backend の **2 プロセスのみを軽量起動**（Node.js 不要）。
   - Vite の個別起動: 設定ファイルの書き換えを必要とせず、Web Manager のボタンや CLI メニューから **いつでもワンクリックで Vite（Port 5173）を個別起動・停止可能**。
   - 状態表示:
     - Vite 停止中: `React FE: BUNDLED (内包配信: Port 8000)`（正常・Green）＋「▶ Vite 起動」ボタン
     - Vite 稼働中: `React FE: DEV ACTIVE (Port 5173)`（正常・Green）＋「⏹ Vite 停止」「🔄 再起動」ボタン
6. **Windows ファイアウォール許可**:
   - 他 PC や LAN 内からのアクセスを可能にするため、Port 8000 の受信を許可する管理者スクリプト `allow_firewall_8000.bat` を新設。
7. **エージェント向けビルドスラッシュコマンド (`/build`)**:
   - リポジトリ専用のスキル `.agents/skills/build/SKILL.md` を配備し、チャット入力欄から `/build` を実行することで、フロントエンドビルドの実行・成果物整合性検証・バックエンドパス解決確認をワンアクションで完結させる。

## 3. 詳細モジュール設計

### 3-1. `backend/app/config.py`
- `frontend_dist_dir: str = "../frontend/dist"` 設定項目を追加。
- `frontend_dist_path: Path` プロパティを追加（`backend/` 相対およびリポジトリルート相対の両方を安全に解決）。

### 3-2. `backend/app/main.py`
- `SPAStaticFiles(StaticFiles)` クラスの実装:
  - 404 送出時、`/api/` プレフィックスは `JSONResponse(status_code=404, content={"detail": "Not Found"})` を返却。
  - 拡張子なし（`not Path(norm_path).suffix`）のパスは `index.html`（SPA フォールバック）を返却。
  - 拡張子ありの静的アセット欠損は 404 を送出。
- アプリケーション末尾でマウント処理:
  - `(frontend_dist / "index.html").exists()` の場合、`app.mount("/", SPAStaticFiles(...))` を登録。
  - 存在しない場合はマウントをスキップし、`GET /` でビルド手順と `/docs` への案内を返却。

### 3-3. `backend/tests/test_spa_static.py`
- 疑似ビルド環境を用いたルーティング統合テストスイート（ルート 200, 静的アセット 200, SPA フォールバック 200, 未定義 API 404 JSON, 欠損アセット 404）。

### 3-4. `tools/build_dist.bat` & `.agents/skills/build/SKILL.md`
- `tools/build_dist.bat`:
  - `cd frontend && npx vite build` を実行し、成果物を生成。
- `.agents/skills/build/SKILL.md`:
  - スラッシュコマンド `/build` を提供。
  - 1. ビルド実行（`npx vite build` または `tools/build_dist.bat`）
  - 2. `frontend/dist/index.html` および assets の検証
  - 3. Backend `settings.frontend_dist_path` の解決検証
  - 4. 結果レポート（バンドルサイズ、Uvicorn 起動コマンド案内）

### 3-5. `tools/server-manager/server-manager.ps1`
- `Start-AllServices`:
  - `frontend/dist/index.html` が存在する場合、`npm run dev`（Port 5173）の起動を自動スキップし、ComfyUI + Backend の 2 プロセスで軽量起動。
  - `frontend/dist/index.html` が存在しない場合は、従来通り Vite（Port 5173）を起動。
  - いずれの場合も、`-Action start -Service frontend` による個別起動はいつでも実行可能。
- `Get-StatusObject`:
  - Port 5173 が LISTEN の場合: `status = "LISTEN"`, `name = "React FE (Dev: 5173)"`, `running = $true`。
  - Port 5173 が停止しており `frontend/dist/index.html` が存在する場合: `status = "BUNDLED"`, `name = "React FE (Bundled on 8000)"`, `running = $beRunning`。
  - いずれでもない場合: `status = "STOPPED"`, `running = $false`。

### 3-6. `tools/server-manager/server_api.py`
- `status == "BUNDLED"` の場合にバッジを正常稼働（緑色・`badge-running`）として描画し、カード内に「▶ Vite 起動（開発用）」ボタンを表示。

### 3-7. `tools/server-manager/allow_firewall_8000.bat`
- 管理者権限昇格を行い、Windows ファイアウォールに `Prompt Surgeon Backend & UI (8000)` の TCP 受信許可ルールを追加するバッチスクリプトを作成。

## 4. テスト戦略

1. **自動テスト (Pytest)**:
   - `pytest tests/test_spa_static.py -v`: 6つの検証項目を実行。
   - `pytest tests/test_config.py`: 設定読み込み回帰テスト。
2. **結合・E2E検証**:
   - スラッシュコマンド `/build` を実行し、`frontend/dist` が生成され、検証ステップが正常完了することを確認。
   - `server-manager.ps1 -Action start -Background`: ComfyUI と Backend の 2 プロセスのみが起動し、Frontend（5173）が不要に起動しないことを確認。
   - Web マネージャー（`http://localhost:8899`）から「React FE」カードの起動ボタンを押下し、いつでも Vite（Port 5173）が起動できることを確認。
3. **Red Teaming (境界値・異常系)**:
   - 未定義 API（`/api/nonexistent`）が JSON 404 を返し、HTML を返さないこと。
   - 欠損 JS アセット（`/assets/missing.js`）が 404 を返し、MIME パースエラーが発生しないこと。
   - `allow_firewall_8000.bat` の二重実行時にエラーなく冪等に完了すること。

## 5. トレードオフとリスク開示 (Trade-off Disclosure)

- **トレードオフ**: 設定ファイルによる手動モード切替を排除し、`frontend/dist` の物理的な存在有無による自動判別を採用。さらにリポジトリ内にエージェント向け `/build` スラッシュコマンドを整備することで、UI 修正後のビルド・検証を最小手順で自動実行可能にしている。
- **リスクと対策**:
  - *ファイアウォールリスク*: Port 8000 を開放するとローカルネットワーク内の全端末からアクセス可能となるため、本番運用時は信頼できるプライベートネットワーク環境下でのみ利用することを推奨し、ドキュメントに明記する。
