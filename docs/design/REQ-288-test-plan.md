# REQ-288 テスト計画

## Gate 1: 静的型検査

```bash
cd frontend && npm run typecheck
```
- **合格条件**: `tsc -b --noEmit` がエラー 0 件で終了すること。
- **対象ファイル**: 追加/変更した全TS/TSXファイル

---

## Gate 2: 自動テストスイート (回帰)

### バックエンド

```bash
cd backend && python -m pytest tests/test_ws.py -v
```

| テストID | 内容 | 期待結果 |
|---------|------|---------|
| BE-01 | `/api/ws` エンドポイントに WebSocket 接続できる | 接続成功 101 |
| BE-02 | 接続後 2.5s 以内に `SYSTEM_STATS` メッセージを受信できる | JSON 受信 |
| BE-03 | `cpu_pct`, `ram_pct` が 0-100 の数値であること | 型検証 PASS |
| BE-04 | AMD SMI 不可環境 (`rocm-smi` モック失敗) で `gpu_pct=null` になること | null |
| BE-05 | クライアント切断時にメモリリーク・例外が発生しないこと | 正常終了 |
| BE-06 | 複数クライアント同時接続時に全員がブロードキャストを受信する | 全クライアント受信 |

### フロントエンド

```bash
cd frontend && npx vitest run
```

- 既存テストスイートが全件 PASS すること（回帰ゼロ）
- `useSystemStats.test.ts`: フック初期化・切断クリーンアップを確認

---

## Gate 3: シナリオ & レッドチーミング

### E2E シナリオ

| シナリオID | 内容 | 検証方法 |
|-----------|------|---------|
| E2E-01 | フロントエンド起動 → HUD に CPU/RAM/GPU/VRAM が表示される | ブラウザ目視確認 |
| E2E-02 | デスクトップ: プレビューエリア右上に半透明HUDが重なって表示される | レイアウト確認 |
| E2E-03 | モバイル: 2段目ヘッダーにチップが横並びで表示される | レスポンシブ確認 |
| E2E-04 | RAM 85%超でチップが amber 色に変わる | 閾値カラー確認 |
| E2E-05 | バックエンドサーバー停止 → 自動再接続 (1s→2s→4s→8s→10s) | タイムアウト観測 |
| E2E-06 | タブ非アクティブ時に WS 接続が切断されること | DevTools確認 |

### レッドチーミング (境界/失敗シナリオ)

| RT-ID | シナリオ | 期待挙動 |
|-------|---------|---------|
| RT-01 | `rocm-smi` がタイムアウト (>2s) した場合 | null フォールバック、サーバークラッシュなし |
| RT-02 | 100 クライアント同時接続時のメモリ使用量 | ConnectionManager がリーク増大しないこと |
| RT-03 | フロントエンドが WS 受信中に React コンポーネントがアンマウントされる | タイマー二重実行なし、メモリリークなし |
| RT-04 | `visiblitychange` イベントが高頻度 (< 500ms) で発火する | 再接続ループにならないこと (debounce 検討) |
| RT-05 | ComfyUI 生成中に systemWsService が切断される | comfyWsService には無影響、生成継続 |
| RT-06 | `SYSTEM_STATS` ペイロードに未知フィールドが含まれる | フロントエンドがクラッシュせず無視する |
