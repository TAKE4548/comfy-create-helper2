# Design Document: REQ-101 モバイル表示におけるモーダル・ページ下部要素の被り防止

## 1. Summary
本ドキュメントは、モバイル表示（低解像度画面、画面幅1024px未満）において、画面下部に固定配置されるメニューバー（ボトムナビゲーションバー）が、ページ最下部のコンテンツや各種モーダル（特にアセット追加モーダルなどの縦長ダイアログ）の操作領域（フッターの適用・キャンセルボタン等）と重なり、クリック/タップ等の操作ができなくなる問題を解消するためのレイアウト設計を定義します。

## 2. Design Principles & Changes

### 2-1. 重ね合わせ順序（z-index）の修正
- **現状**:
  - `AppShell.tsx` のボトムナビゲーションバー: `z-50`
  - モーダル各種の外枠コンテナー（backdrop）: `z-50`
  - 同一 z-index であるため、スタッキングコンテキストとDOM順により、ボトムナビゲーションバーがモーダルの上に重なって表示される。
- **変更点**:
  - すべてのモーダル（`AddAssetModal.tsx` および `frontend/src/components/` 配下のモーダルコンポーネント群）の backdrop 外枠の z-index を `z-[100]` に引き上げる。これにより、モーダルがボトムナビゲーションバー（`z-50`）より常に手前に描画され、イベントを奪われないようにする。

### 2-2. モーダルのモバイル表示用余白（padding）および最大高（max-height）の動的調整
- **現状**:
  - `AddAssetModal` などのモーダルは `fixed inset-0` をベースに `flex items-center justify-center` で中央配置され、`max-h-[85vh]` の最大高さ制限を持つ。
  - モバイル時は画面全体の 85% の高さがボトムナビの領域（高さ 64px + セーフエリア）に被るため、中央に配置されたモーダルの最下部ボタンがボトムナビと干渉する。
- **変更点**:
  - モーダルの外枠コンテナーにモバイル用の下部パディングを設定し、モーダルの描画範囲（最大高さ）を「画面の全高からボトムナビ + セーフエリア + マージンを引いた範囲」に制限する。
  - 具体的には、backdrop コンテナーのクラスに `pb-[calc(4rem+env(safe-area-inset-bottom)+1rem)] lg:pb-4` などのパディングを設定する。これにより、`flex items-center justify-center` 内でモーダル自体が自動的に上にシフトし、最大高さ（`max-h`）もパディングを差し引いた領域内で計算されるため、ボトムナビの上端より上の領域に綺麗に収まる。

### 2-3. メインページ最下部パディングのセーフエリア対応
- **現状**:
  - `AppShell.tsx` 内の `<main>` タグに `pb-16 lg:pb-0` が設定されている。
  - ボトムナビゲーションバーは `pb-safe` が設定されているため、ホームインジケーターのあるiPhone等の端末では `64px + env(safe-area-inset-bottom)` の高さになり、メインコンテンツがボトムナビと被って隠れる。
- **変更点**:
  - `<main>` タグの下部パディングを `pb-[calc(4rem+env(safe-area-inset-bottom))] lg:pb-0` に修正する。これにより、セーフエリアのある端末でもページ最下部コンテンツが完全にボトムナビの上に露出する。

### 2-4. モーダルの固定フッターとスクロール領域の構造維持
- **現状**:
  - `AddAssetModal.tsx` や `BulkEditModal.tsx` 等はすでに `flex flex-col` 構造で、ヘッダー/フッターは固定、コンテンツ領域（アセットリスト、フォーム）が `overflow-y-auto` となっている。
- **変更点**:
  - この固定フッター構造（`flex flex-col overflow-hidden`）を維持し、上記 2-2 での外枠 padding 制限によってモーダルが縮小された場合でも、フッター位置が固定されたまま、中身だけがスクロール可能であることを保証する。

## 3. UI/UX Changes
- **モバイル表示時のモーダル表示位置**:
  - 画面の最下部（ボトムナビゲーションバーがある位置）より上方に浮き上がった位置にモーダルダイアログが描画される。
  - モーダルが縦長になっても、ボトムナビと重なることがなく、フッターの「追加」「キャンセル」ボタンが完全に見える状態で下に固定配置される。
- **メインページ**:
  - スクロールを最下部までを行った際、ボトムナビの裏にコンテンツが潜り込むことなく、余白を含めて綺麗に表示される。

## 4. Impact Range & Risks
- **デスクトップ表示（1024px以上）への影響**:
  - モバイル用のメディアクエリ（`lg:pb-4` や `lg:pb-0`）を使用することで、デスクトップ側での従来のレイアウトやモーダルの配置（完全に中央寄せされる状態）には影響を与えない。
- **影響範囲の広いコンポーネント**:
  - 修正対象のモーダルが複数存在するため、各コンポーネントの構造が崩れないように一貫した Tailwind CSS クラス（`fixed inset-0 z-[100] flex items-center justify-center p-4 pb-[calc(4rem+env(safe-area-inset-bottom)+1rem)] lg:pb-4` 等）を適用し、検証する。
