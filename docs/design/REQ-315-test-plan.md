# REQ-315 テスト計画

## 判定の前提

`TagChip` と `TagChipTranslationCard` の結合を主対象とする。翻訳 API は `translateApi.translatePrompt` をモックして、結果の到着順、失敗、無応答を決定的に制御する。実 API との接続は Gate 3 で既存の英日翻訳経路を一度確認する。タグ本文の正本は親から渡る `text` で、`wordInput` は未確定値とする。取得元のテキスト、カード状態、`onEdit` の呼び出しをそれぞれ観測する。

## 結合・E2E 受入経路

| 経路 | 操作と観測 | AC |
| --- | --- | --- |
| 初回 | 英語タグを開き、翻訳ボタン操作前にカードと取得中表示が出る。API 引数が確定タグ本文・英日・`repack:false` で、応答後に日本語訳が出る | 1, 9 |
| Enter 確定 | 入力途中の各 `change` では API 回数が増えず旧訳が残る。Enter で `onEdit` が呼ばれ、親が更新した `text` の取得中を経て新訳が出る | 2, 4, 9 |
| blur 確定 | 入力欄から強度入力欄またはカードへ移動し、確定後もカードを開いたまま新訳が出る。Enter 後の blur で二重取得しない | 3 |
| 取消 | 入力後 Escape でサブメニューを閉じ、親タグは元の値。再度開くと元の本文が取得され、取消文言は一度も API に渡らない | 5 |
| 訳の取得失敗 | 新本文を確定して API を失敗させる。本文は新値で、旧訳は表示されず、失敗表示と再試行で復旧する | 6, 9 |
| 順序逆転 | A→B と短時間に確定し、B の応答を先に解決後 A の応答を解決する。B の訳のみ表示し、ローディングも旧要求の `finally` に消されない | 7 |
| タグ切替 | タグ A の取得中に閉じてタグ B を開き、A を後から解決する。B のカードの状態と訳に A が混入しない | 8 |
| 空応答・無応答 | 空白だけの訳、空応答、10秒無応答を個別に与え、訳を表示できない状態またはタイムアウトを示す。後着した結果は無視し、再試行できる | 10 |

## Gate 3 境界・異常系

1. 重みタグ `(cat_ears:1.2)` では表示用本文 `cat_ears` を翻訳し、重みだけ変更した場合は再取得しない。Anima モードの文章末尾ピリオドは既存 `parseTagWeight` / `formatTagWeight` の規則を維持する。
2. 入力が空白のみなら既存のタグ編集規則で元の本文へ戻し、空文字の API リクエストを送らない。前後空白を含む入力は trim 後の確定値だけ翻訳する。
3. 真の外側クリックではサブメニューとカードが閉じる。サブメニュー内の入力欄、強度入力欄、コピーボタン、カード内操作ではカードが閉じない。Esc とカードの閉じるボタンは各導線どおり動く。
4. 連続再試行時は最後の要求だけ採用する。失敗中に本文を変えた場合、旧本文の再試行結果は現在の訳として表示しない。アンマウント後の完了で React 状態更新や表示の復活が起こらない。
5. CPU 翻訳 API が遅延・拒否・空 payload を返しても、タグ編集の確定とプロンプト文字列は保たれる。ネットワーク要求数は初回と本文確定時に限られ、タイピング回数に比例しない。
6. PC/モバイルの Generate のタグチップ、カードのドラッグ・本文スクロール・コピー・画面端クランプが `REQ-304` の既存動作を維持する。

## 実装後の検証コマンドと証拠

設計段階ではテストを実行しない。実装中の局所確認は `cd frontend; npx vitest run src/components/TagChipEditor/__tests__/TagChipTranslationCard.test.tsx src/components/TagChipEditor/__tests__/TagChip.test.tsx`。最終 Gate 1 は `cd frontend; npm run typecheck`、Gate 2 は全テストの `cd frontend; npm test`。Gate 3 は上記の結合シナリオをブラウザで確認し、必要に応じて同じ 2 ファイルに回帰テストを追加する。失敗を再現した場合は入力値、確定値、API 呼び出し順、カード表示状態を記録する。
