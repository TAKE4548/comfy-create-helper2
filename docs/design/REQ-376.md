# REQ-376 設計ドキュメント
# モバイルLoRA／Tag Set：一覧カードの情報整理と縦スクロールの一本化

---

## 1. 概要 (Overview)

本ドキュメントは、PBI REQ-376に基づき、モバイル環境（画面幅767px以下）におけるLoRA一覧（`/loras`）・Tag Set一覧（`/tags`）のカード情報整理とページ縦スクロールの一本化に関する詳細設計を定める。

### 1.1 背景と課題
1. モバイル画面において、カード右上の編集・削除ボタンのタップ領域が重なり、誤操作が発生しやすい。
2. カード下部の独立縦スクロール（`overflow-y-auto`）がスワイプ操作を奪い、ページ全体の縦スクロールを阻害している。
3. 一覧カード内にカテゴリバッジ・タグチップ・トリガーワード・強度・パスなどの詳細情報が詰め込まれ、識別に必要な基本情報（タイトル、説明、対象Base Model）の可読性が著しく低下している。
4. Sticky指定されたカテゴリ見出しの上にスクロールコンテナのパディングによる不自然な空隙が生じる。
5. サムネイル画像フレームがカード左側に寄っており、視覚的バランスを欠いている。

### 1.2 解決方針 (Preserved / Modified)
- **Modified (モバイル < 768px)**:
  - カード外形は320px固定（`h-[320px]`）を維持。
  - カード下部情報領域は「①タイトル（最大2行）」「②Description（最大2行）」「③対象Base Model（1行、下端揃え）」の3項目のみに限定。
  - カード内部の独立スクロールを全廃し、`overflow-hidden` でスクロール奪取を防止、ページ縦スクロールに一本化。
  - カード内カテゴリバッジを非表示化し、Stickyカテゴリ見出しに集約。
  - 編集・削除ボタンの配置を整理し、相互のタップ可能領域（44×44px以上）の重なりを解消。
  - 共有コンポーネント `ImageCarousel` の本体コードを変更せず、ページ側のクラス指定によりサムネイル画像フレームを中央配置。
  - カテゴリスクロール領域の `padding-top` を調整し、Sticky見出しがスクロール領域上端に自然に接するようにする。
- **Preserved (PC >= 768px / 既存機能)**:
  - PC（デスクトップ）表示時のレイアウト・カード内スクロール・トリガーワードコピー・タグチップ表示は従来仕様（Baseline）を完全維持。
  - 並べ替えD&D、複数選択モード、カードタップによる詳細モーダル表示、画像閲覧（カルーセルスワイプ）などの機能・操作を維持。
  - 共有コンポーネント（`ImageCarousel`）の他画面向けグローバル変更は行わない。

## 2. アーキテクチャ設計・レイアウト設計

### 2.1 UI 4大アーキタイプ分類と外科的制約 (UI Archetypes & Surgical Constraints)
本改修対象コンポーネントは以下のアーキタイプに分類される：
- **Archetype 2: Tabs / Chips / Grids (カードグリッド・サムネイル)**
  - 制約: カード高 `h-[320px] min-h-[320px] max-h-[320px]` 固定。
  - 制約: モバイル下部情報エリアは `overflow-hidden`。
  - 制約: タイトル `line-clamp-2 break-words`、説明 `line-clamp-2 break-words`、Base Model `truncate whitespace-nowrap mt-auto`。
  - 制約: 11pxフロア準拠（最小フォントサイズ11px：`text-[11px]`）。
- **Archetype 3: Forms & Controls (操作ボタン・ドラッグハンドル)**
  - 制約: 編集・削除・ドラッグハンドルは各44×44px以上のヒットスロップ（`min-h-[44px] min-w-[44px] flex items-center justify-center`）。
  - 制約: 編集ボタンと削除ボタンのクリアランスを確保（重なり防止）。
  - 制約: ドラッグハンドルは `touch-action: none`、カード面は `touch-action: pan-y` を維持し、縦スクロールとジェスチャーの競合を防止。
- **Archetype 4: Shell & Page Layout (スクロールコンテナ・Sticky見出し)**
  - 制約: スクロールコンテナは `pt-0 md:pt-5` とし、Sticky見出しが上端に密着（空隙排除）。
  - 制約: 見出し背景は不透明または `bg-surface/95 backdrop-blur` を指定し、スクロール通過要素の透過重なりを防止。

### 2.2 カード内レイアウト構造 (LoRAsPage & TagsPage)

カード全体はレスポンシブクラスを用いて、モバイル用とPC用で分離する。

```tsx
<div className="group relative rounded-xl border overflow-hidden ... flex flex-col h-[320px] min-h-[320px] max-h-[320px]">
  {/* 複数選択チェックボックス */}
  {isMultiSelectMode && ( ... )}

  {/* 並べ替えハンドル (D&D有効時) */}
  {!isMultiSelectMode && isDndActive && ( ... )}

  {/* サムネイル画像領域 (ImageCarousel) */}
  <ImageCarousel
    thumbnailPath={...}
    snapshotPaths={...}
    alt={...}
    className="w-full shrink-0 flex justify-center max-md:[&>[data-testid=image-carousel-frame]]:left-1/2 max-md:[&>[data-testid=image-carousel-frame]]:-translate-x-1/2 max-md:[&.justify-start]:justify-center"
    imageAspectRatio={numericRatio}
    imageAreaFraction={0.58}
  >
    {/* 編集ボタン: モバイルはtop-1 right-[50px] (44x44px)、PCはtop-2 right-8 */}
    <button
      id={`...-edit-${id}`}
      className="absolute top-1 right-[50px] min-h-[44px] min-w-[44px] flex items-center justify-center md:top-2 md:right-8 md:min-h-0 md:min-w-0 md:p-1 rounded-md bg-surface/80 text-zinc-400 hover:text-white transition-opacity"
    >
      <Pencil size={13} />
    </button>
    {/* 削除ボタン: モバイルはtop-1 right-1 (44x44px)、PCはtop-2 right-2 */}
    <button
      id={`...-delete-${id}`}
      className="absolute top-1 right-1 min-h-[44px] min-w-[44px] flex items-center justify-center md:top-2 md:right-2 md:min-h-0 md:min-w-0 md:p-1 rounded-md bg-surface/80 text-red-400 hover:text-red-300 transition-opacity"
    >
      <Trash2 size={13} />
    </button>
  </ImageCarousel>

  {/* モバイル表示 (< 768px): 3項目固定・内部スクロールなし */}
  <div className="flex md:hidden flex-1 min-h-0 flex-col p-2.5 overflow-hidden justify-between">
    <div className="space-y-1 min-w-0 overflow-hidden">
      {/* 1. タイトル (最大2行) */}
      <p className="text-xs font-semibold text-zinc-200 line-clamp-2 break-words" title={titleText}>
        {titleText}
      </p>
      {/* 2. 説明文 (最大2行) */}
      <p className="text-[11px] text-zinc-400 line-clamp-2 break-words" title={descText}>
        {descText}
      </p>
    </div>
    {/* 3. 対象Base Model (1行、下端揃え) */}
    <p className="text-[11px] text-zinc-500 truncate mt-auto pt-1 whitespace-nowrap" title={baseModelTooltip}>
      {baseModelCaption}
    </p>
  </div>

  {/* デスクトップ表示 (>= 768px): 従来の詳細・スクロール表示 (Baseline完全維持) */}
  <div className="hidden md:flex p-3 flex-1 min-h-0 overflow-y-auto custom-scrollbar flex-col justify-start gap-2">
    {/* 従来のタイトル、カテゴリバッジ、トリガーワード、強度、タグチップ、パス等 */}
  </div>
</div>
```

### 2.3 対象Base Modelの複数件表示仕様 (AC-9)
- **0件**: `"対象モデル未設定"`（文字色: `text-zinc-500`）
- **1件**: `"{ModelName}"`（例: `"SD 1.5"`）
- **複数件**: `names.join(' · ')`（例: `"SD 1.5 · SDXL · Illustrious"`）
  - スタイル: `truncate whitespace-nowrap` により1行に強制収容。横幅超過時は末尾が `…` に自動省略される。
  - ツールチップ: `title={names.join(', ')}` により長文時も全体を確認可能。
  - 全件確認導線: カード自体をタップすることで詳細モーダル（`selectedLoraForDetail` / `selectedTagSetForDetail`）が開き、全モデル名および詳細パラメータを確認できる。

### 2.4 サムネイル画像フレームの中央配置仕様 (AC-7)
- `ImageCarousel.tsx` の内部実装は変更せず、`className` 経由でTailwind任意セレクタを適用：
  `className="... max-md:[&>[data-testid=image-carousel-frame]]:left-1/2 max-md:[&>[data-testid=image-carousel-frame]]:-translate-x-1/2 max-md:[&.justify-start]:justify-center"`
- これにより、`absolute left-0` で左寄せされていた画像フレームがモバイル時のみ中央（`left: 50%; transform: translateX(-50%)`）に配置される。画像なしの `No Preview` プレースホルダー（Flexbox）も中央配置される。
- PC表示（`md:` 以上）では本クラスが無効化され、従来のレイアウトが維持される。

### 2.5 Stickyカテゴリ見出しの空隙解消 (AC-5)
- スクロール親コンテナのクラスを `className="flex-1 overflow-y-auto custom-scrollbar p-5 pt-0 md:pt-5"` に改修。
- 見出しボタン `id={`category-section-header-${catKey}`}` は `sticky top-0 z-20 min-h-[44px] bg-surface/95 backdrop-blur py-2` を確保。
- これによりスクロール時にコンテナ上端と見出しの間の20pxの空隙が解消され、スクロールされたカードが見出しの下へ綺麗に潜り込む。

## 3. テスト Seam Map (Test Seam Map [MUST [W-DD-SEAM]])

### 3.1 統合レイヤー (Integrated - Real Production Code)
- `LoRAsPage` および `TagsPage` コンポーネント全体。
- React hooks (`useState`, `useRef`, `useMemo`, `useQuery`)。
- `@dnd-kit/core` および `@dnd-kit/sortable` の並べ替えコンテキスト・ドラッグ属性の伝播。
- レスポンシブクラス（`md:hidden`、`hidden md:flex`、Tailwind line-clamp、truncate）のDOM出力とスタイル属性。
- イベントハンドラー（タップによる詳細モーダル起動、編集・削除ボタンクリック時のイベントバブリング抑止 `e.stopPropagation()`）。

### 3.2 切断境界 (Severed - External I/O Boundary)
- **API通信レイヤー**: `frontend/src/api/client.ts` の `lorasApi`, `tagSetsApi`, `loraCategoriesApi`, `tagsetCategoriesApi`, `baseModelsApi` を Vitest モック（`vi.mock('../../api/client')`）により切断。実際のHTTPリクエストは一切発行しない。
- **クリップボード**: `navigator.clipboard.writeText` をモック関数で隔離。

### 3.3 モックレベル (Mock Level)
- コンポーネント内部のロジックやヘルパーのモンキーパッチは厳格に禁止。
- モックはネットワークトランスポート層（`client.ts`）およびブラウザ環境（`window.innerWidth`, `navigator.clipboard`）のみに限定する。

### 3.4 PBT (Property-Based Testing) 決定
- **適用対象**: Base Model 複数件結合文字列生成ロジックおよびテキスト省略安全性。
- `fast-check` を用い、Base Modelの件数（0〜50件）、名称（空文字・極端な長文・特殊文字・絵文字・マルチバイト文字）のランダム生成に対し、生成文字列が常に例外を投げず、期待されるフォーマット（` · ` 結合、または未設定文字列）を出力することを検証する。

### 3.5 フォールト注入・異常系シナリオ (Fault Injection)
- `description` が `null` / 空文字のカード。
- `target_base_model_ids` が空配列または未解決IDを含むカード。
- タイトルや説明文が改行を含む極端な長文（1000文字以上）。
- `thumbnail_path` が空（画像なし `No Preview`）または無効パス。
- カテゴリ未分類データ（未分類セクションの表示とカード内バッジ非表示の整合）。
