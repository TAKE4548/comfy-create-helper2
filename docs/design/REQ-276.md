# REQ-276: 生成パラメータ変更直後の反映不全およびプリセット誤再同期（巻き戻り）の根本解消 設計書

- **PBI**: REQ-276
- **作成日**: 2026-09-18（改訂版）
- **作成者**: Architect
- **ステータス**: 設計完了 (Detailed Design Finalized)

---

## 1. 概要 & 目的

生成画面（Generate ページ）において、アスペクト比などの生成パラメータを変更した直後に「生成」ボタンを押しても反映されず、複数回生成を繰り返すうちに遅れて反映される事象、およびパラメータが意図せず直前値に巻き戻る事象を根本解消する。  
さらに、将来マッピングマスターのロール名でタイポや改名が発生した場合でも、プリセット内のキーが取り残されない恒久的な防御機構（カスケード置換＆自己修復マッピング）を組み込む。

---

## 2. 根本原因と設計方針

### 2.1 原因分析
1. **`updated_at` のシリアライズ形式不一致による不要なプリセット再同期**:
   - バックエンド更新時: `datetime.now(timezone.utc)` を設定し、レスポンスでは UTC ISO 文字列（末尾 `Z`）を返却。
   - バックエンド一覧取得時: SQLite から naive datetime として読み出されるため、末尾に `Z` のない文字列としてシリアライズ。
   - フロントエンド `usePresetState.ts`: `activePreset.updated_at !== prevUpdatedAt` で単純文字列比較を行っているため、オートセーブ直後のクエリ無効化（`invalidateQueries`）や 5秒ポーリング時に**常に他者更新ありと誤判定**される。
   - `!isDirty` 時に `currentStore.loadPresetData` が発火し、サーバーの古い値でローカルストアが強制上書きされる。
2. **オートセーブ（1秒デバウンス）と即時生成のタイミング競合**:
   - 変更後 1 秒以内の生成押下時、オートセーブ未完了のままプロンプトが送信されたり、ポーリングで旧値に巻き戻る。
3. **ロール名変更時のデータ構造的分断（キー孤立）**:
   - `mapping_master.role` の更新時に `workflow_presets.param_values` の JSON キーがカスケード更新されないため、過去の17文字切り捨て旧キー（`Resolution Selecto`）が DB 内に残存し、初期値フォールバックが誘発されていた。

### 2.2 設計方針
1. **バックエンド**: 
   - `_preset_to_schema` において、`created_at` および `updated_at` が naive datetime の場合は明示的に `tzinfo=timezone.utc` を付与し、常に UTC ISO8601 文字列（`...Z`）としてシリアライズする。
   - `PUT /api/mapping-masters/{master_id}` において、`role` 名が変更された場合に `workflow_presets` の `param_values` 内の旧キーを単一 SQL `replace` で即座にカスケード置換（実測 35ms）する恒久防壁を実装。
2. **フロントエンド**: 
   - `usePresetState.ts` に堅牢なタイムスタンプ比較ヘルパー（`isTimestampDifferent`）を導入。文字列の末尾 `Z` 補正とミリ秒単位のエポックタイム比較（1秒未満の端数は同一と判定）を行い、同一更新の誤検知を完全に排除。他端末からの更新（5秒ポーリング）は引き続き正常に検知。
   - 自端末のオートセーブ成功時は `qc.setQueryData` でキャッシュ直接更新を行い、不要な自己再フェッチ（`invalidateQueries`）を抑止。
   - デバウンス時間は現行の「1秒（1000ms）」を維持し、生成ボタン押下時に未保存パラメータの即時フラッシュ（保存）および UI 最新値の確実なペイロード採用を行う。
3. **データベース & レジリエンス**:
   - DB 内の既存 636 件の `'Resolution Selecto'` を正規キー `'Resolution Selector'` に一括正規化するマイグレーションを実行。
   - `useWorkflowParams.ts` においても、ロード時に旧キーが存在していれば正規キーへ自動昇格する自己修復（Self-Healing）を導入。

## 3. コンポーネント別詳細仕様

### 3.1 バックエンド (`backend/app/routers/presets.py`)
- `_preset_to_schema(preset)` の修正:
  ```python
  def _ensure_utc(dt: Optional[datetime]) -> Optional[datetime]:
      if dt is None:
          return None
      if dt.tzinfo is None:
          return dt.replace(tzinfo=timezone.utc)
      return dt

  def _preset_to_schema(preset: models.WorkflowPreset) -> schemas.WorkflowPresetRead:
      raw_updated = preset.updated_at or preset.created_at
      return schemas.WorkflowPresetRead(
          id=preset.id,
          workflow_id=preset.workflow_id,
          name=preset.name,
          param_values=json.loads(preset.param_values) if preset.param_values else {},
          applied_assets=json.loads(preset.applied_assets) if preset.applied_assets else {},
          batch_size=preset.batch_size,
          seed_mode=preset.seed_mode,
          seed=preset.seed,
          created_at=_ensure_utc(preset.created_at),
          updated_at=_ensure_utc(raw_updated),
          sort_order=preset.sort_order,
      )
  ```

### 3.2 バックエンド (`backend/app/routers/mapping_masters.py`)
- `update_master` におけるカスケード置換処理:
  ```python
  @router.put("/{master_id}", response_model=schemas.MappingMasterRead)
  def update_master(master_id: int, payload: schemas.MappingMasterCreate, db: Session = Depends(get_db)):
      mm = db.query(models.MappingMaster).filter(models.MappingMaster.id == master_id).first()
      if not mm:
          raise HTTPException(status_code=404, detail="MappingMaster not found")
      
      old_role = mm.role
      new_role = payload.role
      
      # ロール名が変更された場合、既存の全プリセット内の JSON キーを一括カスケード置換 (実測 35ms)
      if old_role and new_role and old_role != new_role:
          old_key_pattern = f'"{old_role}":'
          new_key_pattern = f'"{new_role}":'
          db.query(models.WorkflowPreset).filter(
              models.WorkflowPreset.param_values.contains(old_key_pattern)
          ).update(
              {
                  models.WorkflowPreset.param_values: func.replace(
                      models.WorkflowPreset.param_values, old_key_pattern, new_key_pattern
                  )
              },
              synchronize_session=False
          )
      
      mm.role = new_role
      mm.expected_class_types = json.dumps(payload.expected_class_types) if payload.expected_class_types else None
      mm.param_name = payload.param_name
      mm.input_type = payload.input_type
      mm.display_name = payload.display_name
      mm.title_patterns = json.dumps(payload.title_patterns) if payload.title_patterns else None
      db.commit()
      db.refresh(mm)
      return _to_schema(mm)
  ```

### 3.3 フロントエンド (`frontend/src/pages/GeneratePage/hooks/usePresetState.ts`)
- タイムスタンプ比較ヘルパー:
  ```typescript
  export function normalizeTimestamp(ts?: string | null): number {
    if (!ts) return 0
    const trimmed = ts.trim()
    const hasTz = trimmed.endsWith('Z') || trimmed.includes('+') || (trimmed.includes('-') && trimmed.lastIndexOf('-') > 10)
    const normalized = hasTz ? trimmed : `${trimmed}Z`
    const ms = new Date(normalized).getTime()
    return isNaN(ms) ? 0 : ms
  }

  export function isTimestampDifferent(a?: string | null, b?: string | null, thresholdMs = 1000): boolean {
    if (!a && !b) return false
    if (!a || !b) return true
    const msA = normalizeTimestamp(a)
    const msB = normalizeTimestamp(b)
    return Math.abs(msA - msB) >= thresholdMs
  }
  ```
- オートセーブ成功時（`onSuccess`）:
  - `qc.setQueryData` でローカルキャッシュを更新。
  - 不要な `qc.invalidateQueries` を削除（5秒ポーリングとフォーカス復帰による正規同期は維持）。
- 即時フラッシュ関数 `flushAutoSave`:
  - タイマーをクリアし、現在のダーティ状態を即座に `updatePresetMutation.mutate` する関数を提供。

### 3.4 フロントエンド (`frontend/src/pages/GeneratePage/hooks/useWorkflowParams.ts` & `useGenerateAction.ts`)
- `useWorkflowParams.ts`:
  - 初期ロード時に `'Resolution Selecto'` があれば `'Resolution Selector'` に自動読み替え。
- `useGenerateAction.ts`:
  - `handleGenerateSets` 開始時に `flushAutoSave?.()` を呼び出し、UI 上の最新 `currentParamValues` が確実に採用されることを担保。
