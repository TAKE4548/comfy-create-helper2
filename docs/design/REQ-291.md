# REQ-291: Prompt Surgeon: 2系統参照型セリフ・SE一括自動生成 詳細設計書 (Rev.14 最終確定版)

## 1. 背景と課題意識 (Conceptual Architecture)

Prompt Surgeonのセリフ付与機能において、ゼロショット生成ではキャラらしさや場面の熱量が安定せず、また1画像内に主役・モブ・SEが混在する実態に対応しきれていなかった。さらにローカル環境（16GB VRAM）において、ComfyUI画像生成とVLM推論のGPUメモリ競合を回避し、推論完了後に即座にVRAMを全量返却する厳格なライフサイクル管理が求められていた。

- **VRAMリソースの排他制御**: ComfyUIのバッチ生成とVLMが同時にVRAMを専有するとOOMや速度低下を招く。VLMは推論完了直後に即時アンロード（解放）する必要がある。
- **文章力・演技力モデルの選定**: 数学的な推論（Thinking）モデルではなく、Claude蒸留の豊かな文章力と無修正（Uncensored）の自由な台詞表現を持つモデル（Qwen3.5-9B-Claude-4.6）が最適。
- **1:N 混在と会話の噛み合い**: 吹き出し単独の推論では、相手の言葉と主役の返答、SEが噛み合わず、漫画らしい掛け合いが成立しない。

### コアコンセプト: 「Claude蒸留VLM × 即時解放 × 2系統リファレンス」
| 要素 | アプローチ | ユーザー体験（UX）と提供価値 |
|---|---|---|
| **頭脳 (VLM)** | Qwen3.5-9B-Claude-4.6 (推論直後即時アンロード) | ・文学的・情緒的なセリフ回しと漫画的掛け合いの成立<br>・ComfyUI画像生成とのVRAM競合ゼロ（生成直後に16GB全量返却） |
| **文脈参照** | 2系統リファレンス (系統A: 口調 ＋ 系統B: 演出) | ・系統A: 過去確定セリフからキャラ特有の口調（一人称・語尾）を完全再現<br>・系統B: 全キャラ横断で最類似シーンから会話構成・SEを借用 |
| **初期配置** | 80点ハイブリッド配置 (VLM粗判定 ＋ BE座標変換) | ・AIに100点のピクセル座標を求めず、視覚的な空き方角（右上/左上等）を判定<br>・BEが1024px実ピクセルに変換。顔遮蔽なしでキャンバスへ一発展開 |
| **キャラ初出** | 並行オンボーディング (非同期Fork ＆ レース防止同期) | ・初出キャラでも待ち時間ゼロ。色選びの裏で推論を先行実行<br>・Ref参照同期により完了順序不問（キャンセル時も救済展開）で合流 |

## 2. データモデル構造とDB拡張設計 (MAJ-04, REQ-285整合)

### 2-1. 主要エンティティの関係
- `snapshots.params['speech_bubbles']`: JSON内に格納される吹き出し配列。各要素に `speaker_tag_set_id` (話者FK相当) と `is_se` (効果音フラグ) を保持。構造は `position`(x,y,w,h実px), `tail`(direction,tip), `style`(shape,textColor,backgroundColor等) の完全階層構造（REQ-285 / MAJ-01 準拠）。
- `speech_bubble_presets`: キャラクター（`tag_set_id`）に紐づく外見スタイル。`is_default: bool` カラムを新設し、1キャラに衣装別等の複数プリセットを許容しつつ、自動適用用のデフォルトを唯一決定可能（MAJ-04）。
- `tag_sets`: キャラクターおよび衣装等のタグ集合（SSoT）。`name` はVLM出力の `speaker` 文字列（sub話者）の同定キーとしても機能（CRIT-02）。
- `speech_tone_presets`: キャラクターの口調定義。過去セリフが未蓄積のコールドスタート時に系統Aの第1フォールバック例文として活用される。

### 2-3. 過去データ一括バックフィルスクリプト (`backend/tools/migrate_speech_speakers.py`)
正規表現構文エラーを解消し、`([!?！？〜～ッっ…・]|^[ァ-ヴーぁ-ん]{2,6}$)` によりオノマトペカタカナを精密判定。
```python
import json, re, logging
from app.database import get_db_context
from app.models import Snapshot, TagSet

logger = logging.getLogger(__name__)

def migrate_existing_bubbles(color_to_tagset_id_map: dict[str, int]):
    """過去の snapshots.params['speech_bubbles'] を検査し、文字色からキャラID付与 & SE厳格判定"""
    with get_db_context() as db:
        snapshots = db.query(Snapshot).all()
        updated_count = 0
        for s in snapshots:
            if not s.params: continue
            try:
                params_dict = json.loads(s.params) if isinstance(s.params, str) else s.params
            except Exception: continue
            bubbles = params_dict.get('speech_bubbles', [])
            if not bubbles: continue
            changed = False
            for b in bubbles:
                text = b.get('text', '').strip()
                is_shape_none = b.get('shape') == 'none'
                # 正規表現構文修正 (感嘆符類 または 2〜6文字のカタカナ/ひらがなオノマトペ)
                is_short_se = (b.get('tail') is None and len(text) <= 6 and
                               bool(re.search(r'([!?！？〜～ッっ…・]|^[ァ-ヴーぁ-ん]{2,6}$)', text)))
                is_se = is_shape_none or is_short_se
                b['is_se'] = is_se
                # キャラクターID付与 (SE以外かつ未付与時)
                if not is_se and 'speaker_tag_set_id' not in b:
                    txt_color = b.get('style', {}).get('textColor') or b.get('textColor', '')
                    if txt_color in color_to_tagset_id_map:
                        b['speaker_tag_set_id'] = color_to_tagset_id_map[txt_color]
                        changed = True
            if changed:
                params_dict['speech_bubbles'] = bubbles
                s.params = json.dumps(params_dict, ensure_ascii=False)
                updated_count += 1
        db.commit()
        logger.info(f'Migrated {updated_count} snapshots successfully with safe SE detection.')
```

## 3. REST API & Pydantic スキーマ詳細仕様 (CRIT-03, CRIT-04, MAJ-01, MAJ-02)

### 3-1. エンドポイント一覧
1. **`POST /api/speech/scene-draft`**:
   - リクエスト: `SceneDraftRequest(snapshot_id, target_tag_set_id, explicit_preset_id, scene_hint)`
   - レスポンス: `SceneDraftResponse(scene_interpretation, bubbles, vram_unloaded, reference_tone_char, reference_scene_prompt)`
   - 責務: 2系統リファレンスからVLM推論し、Preset適用済み `GeneratedSpeechBubbleRead[]` を返却。推論直後に即時アンロード発火（`vram_unloaded: true`）。
2. **`GET /api/speech-bubble-presets/by-tagset/{id}`**:
   - パス引数: `id` (`tag_set_id`, int)
   - レスポンス: `Optional[SpeechBubblePresetRead]`
   - ★CRIT-04準拠: 未登録時は 404 例外ではなく **HTTP 200 OK (ボディ null)** を返却。

## 4. バックエンド推論・アンロード・配置アルゴリズム (`app/services/speech_scene_service.py`)

### 4-1. 2系統リファレンス選定
- **系統A（同キャラ口調選定）**: SQLiteの `snapshots` を `created_at DESC` で直近50件走査。`speaker_tag_set_id == target_tag_set_id and not is_se` の確定セリフを最大3件抽出。0件時は `SpeechTonePreset.prompt` または抽象口調へフォールバック。
- **系統B（全キャラ類似シーン選定）**: `Snapshot.positive_prompt`（または `params` 内プロンプト）から SnowballStemmer で名詞・動詞トークンを抽出。全スナップショット群とのトークン一致数（重み: 感情語+5, 状況語+2）をスコア計算し、スコア2点以上のTop-1シーンを抽出。

### 4-2. VRAM即時解放プロトコル（REQ-296改訂）

LM Studio REST API の `GET /api/v1/models` で推論対象モデルの `loaded_instances[].id` を取得する。未ロードなら `POST /api/v1/models/load` の返却 `instance_id` を保持する。複数インスタンス等で対象が曖昧なときは推論開始前に制御された失敗とする。保持したIDをChat Completionsの `model` に指定し、推論の正常・異常・キャンセル後、同じIDを `POST /api/v1/models/unload` の本文 `{"instance_id": "..."}` に指定する。応答IDの一致と `GET /api/v1/models` による対象ID消失の双方を確認した場合だけ `vram_unloaded=true` とする。失敗は1回再試行し、元の推論エラーを解放エラーで上書きしない。`/v1/models/unload` と空JSONは現行契約ではない。OpenAI互換APIが別名instance IDを受け付けるかはREQ-296の実機確認事項とする。

セリフ一括生成のVLM呼び出しではsystem/user双方を同じJSON生成タスクに揃え、対応モデルへ `response_format.json_schema` を指定する。空本文・非JSON・スキーマ不一致・出力途中終了を分類して制御された失敗へ変換する。詳細は `docs/design/REQ-296.md` を参照。

### 4-3. 80点ハイブリッド配置変換マッピング (1024px実ピクセル)
| VLM指定 `position` | 1024px基準絶対座標 (x, y, w, h) | 典型的な配置意図と対象要素 |
|---|---|---|
| `top_right` | `x: 700px, y: 90px, w: 230px, h: 110px` | 相手（モブ）の呼びかけ・きっかけ（日本の漫画の1コマ目の定石位置） |
| `center_right` / `center` | `x: 550px, y: 350px, w: 160px, h: 75px` | SE（効果音・動揺の擬音・漫符）。相手と主役の間・身体の脇に配置 |
| `top_left` | `x: 120px, y: 120px, w: 240px, h: 120px` | 主役キャラクターのセリフ（リアクション・オチ）。主役の頭上余白に配置 |
| `bottom_left` | `x: 140px, y: 700px, w: 240px, h: 120px` | 座りポーズや画面下部に主役がいる場合のセリフ配置 |

### 4-4. スタイル解決ロジック (`resolve_bubble_style`)
- **main話者**: `explicit_preset_id` または `tag_set_id` の `is_default=True` プリセットを適用。
- **sub話者**: `item.speaker` 文字列を `TagSet.name` と完全一致検索。一致するプリセットがあれば適用、なければ汎用白黒（`backgroundColor='#FFFFFF'`, `textColor='#1A202C'`）を適用。
- **se要素**: `is_se=True`, `shape='none'`, `backgroundColor='transparent'`, `borderColor='transparent'`, `textColor='#FFCC00'`（枠なし・黄色テキスト）に強制適用。

## 5. フロントエンド並行オンボーディング設計 (`src/hooks/useSceneSpeechGeneration.ts`)

初出キャラ時の待ち時間をゼロにするため、プリセット作成モーダル表示と同時に推論を非同期Fork発火。
3つのRef（`createdPresetIdRef`, `pendingDraftResultRef`, `isCancelledRef`）により合流レースを完全防止：
1. **モーダル先行確定**: ユーザーが色を決定してモーダル確定した後に推論完了した場合、保存された `createdPresetIdRef.current` を適用して即時描画。
2. **推論先行完了**: モーダル操作中に推論が先に返った場合、`pendingDraftResultRef.current` にドラフトを保管し、モーダル確定コールバック（`onPresetCreatedAndApply`）で即時描画。
3. **先行キャンセル救済**: モーダルがキャンセル（Close）された後に推論が返った場合、または推論返却後にキャンセルされた場合、`isCancelledRef.current = true` を検知して標準スタイル（白背景・黒文字）で救済描画し、セリフ消失を完全防止。
