# REQ-073: LoRA・タグセット適用時のスナップショット保存メタデータ不整合問題 - テスト計画書

## 1. 自動テスト (Unit Tests)
今回の機能変更箇所は Zustand ストアのデータ保存・読み込みロジックおよびカスタムフックの副作用がメインとなるため、Vitest を用いたユニットテストを新規追加・実行して挙動を検証します。

### 1-1. テスト作成方針
- `frontend/src/store/__tests/useGenerationStore.test.ts` に、`queuePrompt` 実行時に `localStorage` にメタデータがキャッシュされることを検証するテストケースを追加。
- メタデータの最大200件のクリーンアップ（プルーニング）が正常に機能することを検証するテストケースを追加。
- キャッシュメタデータに基づき `useSnapshotActions` が正しくアセット情報を復元することを検証するテストケースを追加。

### 1-2. テスト実行コマンド
```bash
cd frontend
npm run test -- --run
```

## 2. 手動テスト (Manual Verification)
本番環境やローカル環境におけるUIを通じた手動検証手順は以下の通りです。

### 2-1. 単一・複数 Set 生成時のメタデータ整合性の検証
1. フロントエンド (`npm run dev`) とバックエンド (`uvicorn app.main:app`) を起動します。
2. アプリの生成ページを開き、任意のワークフローを選択します。
3. **Set 1** を作成し、Add Asset から任意の LoRA（例: `LoRA-A`）とタグセットを追加します。
4. **Set 2** を作成し、別のアセット（例: `LoRA-B`）を追加します。
5. 両方の Set にチェックを入れ、一括生成を行います。
6. 生成が完了してサムネイルが表示されたら、UI 上のアクティブなプロファイルを「Set 2」に切り替えます。
7. 「Set 1」の生成結果画像のサムネイルを選択し、スナップショットとして保存（新規アルバムまたは既存アルバムに保存）します。
8. 履歴画面に遷移し、保存されたスナップショットのメタデータ（詳細ビュー）を開きます。
9. 登録されているアセットが「Set 2 (LoRA-B)」ではなく、実際に画像を生成した **「Set 1 (LoRA-A)」** であることを確認します。

### 2-2. キャッシュが存在しない場合の互換性検証
1. ブラウザのデベロッパーツール（F12）の Application -> Local Storage から、`prompt-surgeon-meta-` で始まるキーをすべて手動削除します（またはシークレットウインドウで実行）。
2. 保存済みのサムネイル画像（すでにキャッシュが存在しない状態）を選択し、スナップショット保存を行います。
3. スナップショットがエラーなく保存され、現在 UI で選択されているアセット（フォールバック）が正しく適用されて保存されることを確認します。
