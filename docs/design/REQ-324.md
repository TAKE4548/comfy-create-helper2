- **PBI ID**: REQ-324

- **Status**: in-progress

## 1. Background & Architectural Intent

Prompt Surgeonの機能急拡大に伴い、2大フロントエンドモジュールが肥大化し技術的負債となっていた：
1. `frontend/src/api/client.ts` (約700行 / 35KB):
   - 通信基盤（HTTP `request<T>`, BASE_URL, 共通例外）
   - NDJSON/SSE ストリーミング処理（`SceneSpeechStreamError`, `parseSceneSpeechEvent`, `sceneSpeechApi.generateStream`）
   - 27個以上のAPIリソースオブジェクト（workflows, snapshots, loras, dataset, training, etc.）
   - 大量の型再エクスポート
   これらが単一ファイルに集中し、複数PBI並行時のマージ競合、コード可読性の低下、型循環リスクを生んでいた。
2. `frontend/src/components/HistoryModalPreview.tsx` (約420行):
   - 全画面プレビュー／タップ・スワイプ・キーボードナビゲーション制御
   - ヘッダーダウンロードボタン群・自動追従トグル
   - スナップショットおよび一時メタデータのフェッチと正本解析
   - メタデータパネル・アルバム所属・タグ関連付けエディタ
   全ロジックが単一コンポーネントに同居し、タブ切替やコントロールタイマーの更新でモーダル全体が無駄に再レンダリングされていた。

本設計では、**後方互換性100%維持**（呼び出し側の既存コード変更ゼロ）を最重要制約とし、Clean Architecture / Atomic Design に基づく責務分離を実施する。

## 2. To-Be Component & Module Architecture

### 2.1 API Layer Modularization

```
frontend/src/api/
├── core/
│   ├── base.ts          # HTTP request<T>, BASE_URL, 共通ヘッダー・エラーハンドリング
│   └── stream.ts        # SceneSpeechStreamError, parseSceneSpeechEvent, abortError, NDJSON reader
├── domains/
│   ├── workflows.ts     # workflowsApi, workflowPresetsApi, bypassProfilesApi, paramSyncGroupsApi, mappingMastersApi, paramTypeMastersApi
│   ├── snapshots.ts     # snapshotsApi, albumsApi, promptMetadataApi
│   ├── tags.ts          # tagSetsApi, tagsetCategoriesApi
│   ├── loras.ts         # lorasApi, loraCategoriesApi, baseModelsApi, checkpointMappingsApi
│   ├── loraStudio.ts    # datasetApi, trainingApi, benchmarkApi
│   ├── speech.ts        # sceneSpeechApi, speechBatchApi, speechBubblePresetsApi, speechTonePresetsApi, fontsApi
│   ├── translation.ts   # translateApi
│   └── settings.ts      # settingsApi, configApi, auditApi, comfyApi
├── client.ts            # 【SSoT Re-export Hub】core & domains & types の完全な再エクスポート
└── types.ts             # 既存の型定義集約
```

#### 2.1.1 依存方向と循環参照ゼロ保証 (DAG Isolation)
- `core/base.ts`: 外部依存なし（ブラウザ標準 fetch / FormData）
- `core/stream.ts`: `types.ts` の型のみ参照
- `domains/*.ts`: `core/base.ts` (request), `core/stream.ts` (ストリーム型), `types.ts` を参照。**ドメイン間相互参照は禁止**。
- `client.ts`: `core/*`, `domains/*`, `types.ts` を集約再エクスポート。
- **循環参照検査**: TypeScript 型解決およびモジュール境界で循環ゼロ（Cycle = 0）を担保。

#### 2.1.2 呼び出し側の透過性（Transparent Re-export）
既存のすべてのインポート元（例: `import { snapshotsApi } from '@/api/client'`, `import type { PromptMetadataRead } from '../api/client'`）は、1行も変更することなく同一の型・インスタンス・シグネチャを享受する。

### 2.2 HistoryModalPreview Component Decomposition

```
frontend/src/components/
├── HistoryModalPreview.tsx              # オーケストレータ（状態管理・キーボード/スワイプハンドラ・レイアウト合成）
└── history/
    ├── PreviewHeader.tsx                # ダウンロードメニュー、自動追従トグル、閉じるボタン (React.memo)
    ├── PreviewImageViewer.tsx           # 画像表示、前後送り矢印、全画面切替、インジケータ (React.memo)
    └── SnapshotMetadataTab.tsx          # メタデータパネルコンテナ、ローディング状態、GenerationMetadataPanel連携 (React.memo)
```

#### 2.2.1 責務分離
1. `PreviewHeader.tsx`:
   - スナップショットダウンロード（WebP/PNG/JPEG）、一時画像直接ダウンロード
   - `previewAutoFollow` トグルボタン
   - 閉じるボタン
2. `PreviewImageViewer.tsx`:
   - 画像コンテナ、object-contain / 全画面拡大
   - 前後ナビゲーションボタン（`<`, `>`）
   - カルーセル枚数インジケータ（`currentIndex + 1 / total`）
   - 情報表示（`Info` / `Maximize2`）切替ボタン
3. `SnapshotMetadataTab.tsx`:
   - メタデータ読み込み状態（`Loader2` スピナー）
   - `GenerationMetadataPanel` のマウント
   - タグ関連付け・アルバム所属の表示・編集連携
4. `HistoryModalPreview.tsx` (親):
   - 全画面API監視（`fullscreenchange`）
   - タイマー制御（3秒無操作コントロールフェード）
   - スワイプ・キーボードショートカット
   - 編集／保存中ロック状態（`lockedTarget`, `isEditing`, `isSaving`）

#### 2.2.2 メモ化とレンダリング最適化 (Performance)
- 各サブコンポーネントを `React.memo` でラップ。
- コールバック（`onClose`, `onChangeIndex`, `onToggleAutoFollow`）を `useCallback` で安定化。
- タイマーによる `showControls` のトグル時に、重たい `SnapshotMetadataTab` 内部のDOMツリー再計算を抑制。
