# REQ-120 設計仕様書: 吹き出しセリフの縦書き化・フォントサイズ自動調整・サーバーフォント選択機能

## 1. 目的と背景
現在の吹き出しセリフ編集機能では、入力したテキストが横書きで描画されるため、日本のマンガ表現（縦書き）として不自然です。また、フォントサイズを手動スライダーで調整する必要があり、文章量や吹き出し領域（Bounding Box）のサイズに合わせて調整するのが複雑でした。
本設計では、セリフの描画方向を縦書き（上から下、右から左へ改行）に変更し、吹き出しサイズに合わせてフォントサイズを自動計算・最適化して常に領域内に収まるようにします。
さらに、サーバー（バックエンド）にインストールされている日本語システムフォント（MSゴシック、メイリオ、遊ゴシックなど）の一覧を取得し、フロントエンドのCanvas上で選択したフォントをロードして描画できるように拡張します。

## 3. 詳細設計

### 3-1. サーバーフォント取得・ダウンロードAPI (Backend API)
- **GET /api/fonts**
  - レスポンス: `[{"name": "ＭＳ ゴシック (MS Gothic)", "file_name": "msgothic.ttc"}, ...]`
  - OS（Windows/macOS/Linux）に応じたフォントディレクトリ（例: `C:\Windows\Fonts`）を走査し、存在する日本語フォント（または主要なTTF/OTF/TTCフォント）の一覧を返却します。
- **GET /api/fonts/{font_filename}**
  - レスポンス: フォントファイルデータ（`FileResponse`）
  - 指定されたフォントファイルをバイナリストリームとしてクライアントへ返却します。

### 3-2. フロントエンドでのフォント動的ロードと適用
1. モーダル起動時に `GET /api/fonts` を呼び出し、利用可能なフォント一覧を取得。
2. ユーザーがフォントを選択すると、ブラウザの `FontFace` API を用いて動的にフォントをロード・登録します。
   ```typescript
   const fontId = `server-font-${fontFileName.replace(/\./g, '-')}`;
   const fontFace = new FontFace(fontId, `url(/api/fonts/${fontFileName})`);
   await fontFace.load();
   document.fonts.add(fontFace);
   ```
3. ロード完了後、キャンバスを再描画します。

### 3-3. 縦書き (Tate-gaki) レイアウトアルゴリズム
Canvasで縦書きテキストを描画するため、文字を1文字ずつ縦方向に並べる処理を実装します。
1. **テキストの分解**:
   - 入力されたテキストを改行コード (`\n`) で分割し、段落ごとの配列を作成します。
2. **縦書き列へのパース (`layoutVerticalText`)**:
   - 各段落について、文字を上から下へ追加していきます。
   - 1列の高さが吹き出しの最大許容高さ（`maxHeight`）を超える場合、または改行された場合、新しい列（左隣の列）へ折り返します。
   - 縦書き特有の記号変換（長音符 `ー` を縦線 `｜` に変換、カッコ類 `（` `）` `「` `」` を縦書き用 `︵` `︶` `﹁` `﹂` に変換）を行います。

### 3-4. フォントサイズ自動計算ロジック
吹き出し領域（幅 `W`, 高さ `H`）およびパディング `P` から、有効な描画可能領域 `maxWidth = W - 2*P`、`maxHeight = H - 2*P` を算出します。
1. **フォントサイズ探索（ステップダウン方式）**:
   - 最大フォントサイズ `maxFontSize = 36` から最小フォントサイズ `minFontSize = 8` まで、1px刻みでループ処理を行います。
   - 各フォントサイズについて、`layoutVerticalText` を呼び出し、必要な縦書き列の数を算出します。
   - 列数 $N$ に対し、予測される総幅 `totalWidth = N * (fontSize * 1.3)` を計算します。
   - `totalWidth <= maxWidth` となる最大のフォントサイズを決定し、適用します。

### 3-5. Canvas への描画と配置
- **水平方向のセンタリング**:
  - 複数列からなるテキストブロック全体の幅 `totalWidth` を算出し、吹き出しの中心 $X$ に配置します。
  - 右から左へ向けて列を描画するため、第0列（右端）の描画開始座標は `startX = boxCenterX + (totalWidth / 2) - (fontSize * 1.3) / 2` となります。
- **垂直方向のセンタリング**:
  - 各列に含まれる文字数 $C$ に応じた列の高さ `colHeight = C * fontSize` を算出します。
  - 吹き出しの中心 $Y$ に配置するため、描画開始座標は `startY = boxCenterY - colHeight / 2` となります。

### 3-6. UIの変更
- `SpeechBubbleEditorModal.tsx` にフォント選択用のドロップダウンメニューを追加します。
- フォントサイズ調整スライダー（`fontSize` ステートとスライダーUI）を削除し、完全に自動調整化します。

## 4. 設計上のトレードオフとリスク (Trade-off-Disclosure)

### 縦書き記号の変換精度
- **リスク**: Canvas標準のフォント描画（`ctx.fillText`）では、縦書き専用のグリフ配置（句読点や小文字の右寄せなど）が完全には再現されず、簡易的な文字置換（`ー` → `｜` 等）にとどまるため、厳密な写植レベルのフォント配置からは若干のズレが生じる可能性があります。
- **対策**: プロトタイプ段階として簡易変換マップ（`ー` や括弧類）を導入し、十分な視認性とレイアウト整合性を確保します。

### フォントファイルのサイズとネットワーク転送
- **リスク**: 日本語フォントファイル（例: メイリオ `meiryo.ttc` や遊ゴシック `yugothm.ttc` など）は通常 10MB 〜 20MB 近くあり、初回ロード時にネットワーク転送の遅延が発生し、テキスト描画までにタイムラグが生じる可能性があります。
- **対策**:
  1. フロントエンドでフォント読み込み中はインジケーター（またはローディング状態）を表示し、非同期のロード完了後にCanvasを即座に再描画（再トリガー）します。
  2. ブラウザの `document.fonts.check` やキャッシュ機構を活用し、同じフォントの重複ダウンロードを回避します。
