# 設計書: REQ-245 アプリケーション全体における画像・サムネイル表示パフォーマンス最適化

## 1. 設計概要 (Architecture Overview)

本設計は、モバイル端末（iPad、スマートフォン等）から Wi-Fi 経由でホスト PC にアクセスして Prompt Surgeon を利用する際のパフォーマンス課題（履歴ストリップの読み込み遅延・フリーズ、LoRAs/Tags グリッドのカクつき、端末負荷）を根本解消するための包括的アーキテクチャ最適化を定義する。

具体的には以下の 3 つの柱で水平展開を行う：
1. **バックエンド動的サムネイル API & インメモリ LRU キャッシュ**:
   - ComfyUI の出力画像をオンデマンドで 256px WebP (15〜30KB) に変換・配信する API (`GET /api/comfy/thumbnail`) を新設。
   - 最大 500 件のインメモリ LRU キャッシュおよび HTTP `Cache-Control: public, max-age=604800, immutable` による即時配信。
2. **フロントエンド全域の遅延ロード (loading="lazy") & 非同期デコード (decoding="async") 標準化**:
   - Generate 画面の履歴/スナップショットストリップ、LoRAs/Tags のカードカルーセル (`ImageCarousel`)、一括漫画化モーダル (`BatchSpeechTransformModal`)、History/Album 一覧等に一括適用し、ブラウザの同時接続枠（最大6本）の枯渇を防止。
3. **アセット管理におけるサムネイルパス保存の是正**:
   - LoRA / TagSet の画像クロップアップロード時に、元画像パス (`image_path`) ではなく軽量 300px WebP サムネイルパス (`thumbnail_path`) を優先保存するように修正。

## 2. 課題と解決アプローチ (Problem & Solution Approach)

### 2.1 ComfyUI フル解像度 PNG 配信による帯域枯渇と初期フリーズ
- **現状の課題**:
  - Generate 画面の履歴ストリップでは、ComfyUI の出力したフル解像度 PNG 画像（1枚 3〜8MB）を数十〜200枚そのまま配信している。
  - 弱 Wi-Fi (10Mbps 程度) 上で 100〜400MB 超の通信が集中し、30秒〜数分のロード待ちやタイムアウトが発生。
- **解決アプローチ**:
  - バックエンドに `GET /api/comfy/thumbnail` を新設。
  - フロントエンドでストリップ表示用 URL を `toThumbnailUrl(img)` により `/api/comfy/thumbnail?...` に透過的変換。
  - メイン拡大プレビューやダウンロード時のみフル解像度 URL を取得する分離設計とし、ストリップ通信量を 99% 以上削減（200MB → 約1MB、画面内表示分は 80KB 程度）。

### 2.2 全面的な遅延ロード欠落によるブラウザ接続枠飽和（コネクション詰まり）
- **現状の課題**:
  - 画面外（スクロール先）の画像を含めてマウント時に一括リクエストが走る。
  - ブラウザの同一ホスト向け同時接続枠（約6本）が飽和し、画面内に見えている先頭サムネイルすら通信待ちで真っ白になる。
- **解決アプローチ**:
  - すべてのサムネイル要素に `loading="lazy"` および `decoding="async"` を適用。
  - 画面内に進入した画像のみが優先的にダウンロード・非同期デコードされるようにし、接続枠飽和とメインスレッドのカクつきを解消。

### 2.3 LoRA / TagSet クロップ画像のサムネイルパス不整合
- **現状の課題**:
  - `/api/snapshots/upload` は `{ image_path, thumbnail_path }` を返却しているが、フロントエンドの `uploadImage` 関数が `return data.image_path` と元画像パスを保存している。
- **解決アプローチ**:
  - `LoRAsPage`, `TagsPage`, `LoraModals`, `TagSetModals` 内の画像アップロード処理を `return data.thumbnail_path || data.image_path` に修正。

## 3. モジュール別詳細設計 (Detailed Module Design)

### 3.1 バックエンド: ComfyUI 動的サムネイル API (`backend/app/routers/comfy.py`)

- **エンドポイント**: `GET /api/comfy/thumbnail`
- **クエリパラメータ**:
  - `filename`: `str` (必須) - 画像ファイル名
  - `subfolder`: `str` = "" (任意) - サブフォルダ名
  - `type`: `str` = "output" (任意) - 出力種別 ("output", "temp", "input")
  - `size`: `int` = 256 (任意, 32 <= size <= 1024) - サムネイル長辺ピクセル数
  - `quality`: `int` = 80 (任意, 10 <= quality <= 100) - WebP 品質
- **キャッシュ設計**:
  - `_thumbnail_cache: OrderedDict[str, bytes] = OrderedDict()`
  - キャッシュキー: `f"{type}:{subfolder}:{filename}:{size}:{quality}"`
  - 容量上限: 500 件。上限超過時は FIFO/LRU (`popitem(last=False)`) で退避。
  - レスポンスヘッダー: `Cache-Control: public, max-age=604800, immutable`, `Content-Type: image/webp`
- **画像取得・リサイズ処理**:
  ```python
  client = get_comfy_client()
  params = {"filename": filename, "subfolder": subfolder, "type": type}
  resp = await client.get(f"{settings.comfy_url}/view", params=params, timeout=10.0)
  if resp.status_code != 200:
      raise HTTPException(status_code=resp.status_code, detail="ComfyUI view error")
  
  img = Image.open(io.BytesIO(resp.content))
  if img.mode not in ("RGB", "RGBA"):
      img = img.convert("RGBA")
  img.thumbnail((size, size))
  buf = io.BytesIO()
  img.save(buf, format="WEBP", quality=quality)
  webp_bytes = buf.getvalue()
  ```

### 3.2 フロントエンド: サムネイル URL 変換ヘルパー (`frontend/src/utils/thumbnailUrl.ts`)

- **シグネチャ**:
  ```typescript
  export function toThumbnailUrl(url: string | null | undefined, size: number = 256): string
  ```
- **ロジック**:
  - 空文字列や null/undefined の場合は空文字返却。
  - URL に `/view?` または `/view/` が含まれる場合、URL パラメータ（`filename`, `subfolder`, `type`）を抽出。
  - `filename` が存在する場合、`/api/comfy/thumbnail?filename=...&subfolder=...&type=...&size=256` を返却。
  - スナップショット等の画像パス（`/api/snapshots/images/...`）やその他通常 URL はそのまま返却。

### 3.3 フロントエンド: Generate 画面履歴・スナップショットストリップ (`DesktopLayout.tsx`, `MobileLayout.tsx`)

- **履歴サムネイル**:
  ```tsx
  <img
    src={toThumbnailUrl(img)}
    alt={`Generated ${i + 1}`}
    loading="lazy"
    decoding="async"
    className="w-full h-full object-cover pointer-events-none select-none"
    style={{ WebkitTouchCallout: 'none' }}
  />
  ```
- **スナップショットサムネイル**:
  ```tsx
  <img
    src={snap.thumbnail_path || snap.image_path!}
    alt="Snapshot"
    loading="lazy"
    decoding="async"
    className="w-full h-full object-cover"
  />
  ```
- **メインプレビュー**:
  - `previewImage || selectedImg` はそのまま（フル解像度 URL）を維持し、高精細表示とダウンロードの品質を担保。

### 3.4 フロントエンド: LoRA / TagSet サムネイルパス保存是正 & ImageCarousel 最適化

- **対象ファイル**:
  - `frontend/src/pages/LoRAsPage.tsx`
  - `frontend/src/pages/TagsPage.tsx`
  - `frontend/src/components/LoraModals.tsx`
  - `frontend/src/components/TagSetModals.tsx`
- **修正内容**:
  ```typescript
  const uploadImage = async (blob: Blob): Promise<string> => {
    const formData = new FormData()
    formData.append('file', blob, 'cropped.jpg')
    const res = await fetch('/api/snapshots/upload', {
      method: 'POST',
      body: formData,
    })
    if (!res.ok) {
      throw new Error('Upload failed')
    }
    const data = await res.json()
    return data.thumbnail_path || data.image_path
  }
  ```
- **ImageCarousel (`frontend/src/components/ImageCarousel.tsx`)**:
  ```tsx
  <img
    src={images[activeIndex]}
    alt={`${alt} preview ${activeIndex + 1}`}
    loading="lazy"
    decoding="async"
    className="w-full h-full object-cover transition-all duration-300 pointer-events-none select-none"
  />
  ```

### 3.5 フロントエンド: モーダルおよび一覧表示の遅延・非同期ロード化

- **`BatchSpeechTransformModal.tsx`**:
  - 選択スナップショットの `<img>` に `loading="lazy"` および `decoding="async"` を付与。
- **`HistoryPage.tsx` / `AlbumDetailView.tsx`**:
  - 既存の `loading="lazy"` に `decoding="async"` を追加付与。

## 5. リスクとトレードオフ (Risks & Trade-offs)

### 5.1 トレードオフの開示
1. **初回サムネイル生成時の CPU 負荷**:
   - 初回リクエスト時にバックエンドで Pillow によるリサイズ・WebP エンコードが走るため、短時間の CPU 使用率上昇が発生する。
   - **対策**: インメモリ LRU キャッシュ（最大500件）とブラウザ側 HTTP キャッシュ (`max-age=604800, immutable`) により、同一画像の2回目以降のアクセスは 1ms 未満で返却される。
2. **メモリ消費量**:
   - 500件のサムネイルキャッシュをメモリ上に保持するため、約 10MB〜15MB のメモリを消費する。
   - **対策**: `OrderedDict` を用いた厳密な上限制御（500件超過時は即座に古いキャッシュを破棄）により、無制限なメモリ肥大化を確実に防止。
3. **ComfyUI 未起動・通信切断時の挙動**:
   - ComfyUI 停止中に `/api/comfy/thumbnail` を叩いた場合、HTTP 502/503 または 404 が返る。
   - **対策**: フロントエンドの `img` onerror で過剰なアラートを出さず、必要に応じてプレースホルダー表示を維持する。
