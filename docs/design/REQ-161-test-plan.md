# REQ-161 手動テスト計画: モバイルGenerate Batch修正

## 前提条件
- モバイル端末（iOS Safari または Android Chrome）が開発PCと同じLANに接続済み
- Vite dev server が `http://192.168.x.x:5173` でモバイルからアクセス可能
- ComfyUI が `http://localhost:8188` で起動中
- 少なくとも1つのワークフローとプリセットが登録済み

---

## MT-001: ボタン非活性チェック（AC-1対応）

- **前提条件**: モバイル端末でアプリのURLをまだ開いていない新規タブ
- **手順**:
  1. モバイル端末のブラウザを新規タブで開く
  2. アプリURL（`http://192.168.x.x:5173`）をアドレスバーに入力してEnter
  3. ページ表示直後（1〜2秒以内）にGenerate Batchボタンの状態を目視確認
  4. Generate Batchボタンをタップする
- **期待結果**:
  - ページロード直後はGenerate Batchボタンがグレーアウト（半透明）されてタップ不可
  - タップしてもキュー投入は発生しない（エラートーストも出ない）
  - workflowロード完了後にボタンが緑色（活性）に変わる
- **関連AC**: AC-1

---

## MT-002: 2回目アクセスでのキャッシュ効果確認（AC-2対応）

- **前提条件**: MT-001完了後（同じモバイル端末・同じタブ）
- **手順**:
  1. ブラウザのリロードボタンを押す（または Pull to Refresh）
  2. ページが表示された直後（1秒以内）のGenerate Batchボタンの状態を確認
  3. Generate Batchボタンをタップする
- **期待結果**:
  - MT-001の初回アクセス時と比べてボタンが明らかに素早く活性化する（またはリロード直後から活性化している）
  - ボタンをタップするとキュー投入が成功し、エラートーストが表示されない
  - ComfyUI側でキューに追加されていることを確認できる
- **関連AC**: AC-2

---

## MT-003: PCブラウザでの退行チェック（AC-3対応）

- **前提条件**: PCブラウザ（Chrome）でアプリにアクセス
- **手順**:
  1. PCブラウザで `http://localhost:5173` を開く
  2. ワークフローを選択し、Generate Batchボタンをクリックする
  3. キュー投入の成否を確認する
- **期待結果**:
  - キュー投入が成功する（エラートーストが表示されない）
  - ComfyUI側でキューに追加されていることを確認できる
  - 従来と同等の速度でキュー投入が完了する
- **関連AC**: AC-3

---

## MT-004: localStorageキャッシュサイズ確認（AC-4対応）

- **前提条件**: PCブラウザ（Chrome）でアプリにアクセスし、Generate Batchを1回実施後
- **手順**:
  1. Chrome DevToolsを開く（F12）
  2. Application タブ → Storage → Local Storage → `http://localhost:5173` を選択
  3. キー `prompt-surgeon-rq-cache` を探してクリック
  4. 値の文字数（＝概ねバイト数）を確認する
  5. 値のJSON内に `comfy-object-info` キーが含まれていないことを確認する
- **期待結果**:
  - `prompt-surgeon-rq-cache` キーが存在する
  - 値のサイズが5MB（約5,000,000文字）未満である
  - JSON内に `comfy-object-info` や `snapshots` のクエリデータが含まれていない
- **関連AC**: AC-4

---

## MT-005: 10分後のキャッシュ無効化確認（境界条件）

- **前提条件**: モバイル端末で一度アプリにアクセス済み
- **手順**:
  1. モバイル端末でアプリにアクセスし、完全ロード完了を確認
  2. そのまま10分間放置する（画面スリープ可）
  3. モバイルブラウザを再度アクティブにしてリロードする
  4. Generate Batchボタンの状態を観察する
- **期待結果**:
  - キャッシュがmaxAge（10分）超過で無効化されているためAPIフェッチが走る
  - `workflow`ロード完了までボタンがdisabled状態になる（MT-001と同様の動作）
  - ロード完了後にキュー投入が正常に成功する
- **関連AC**: AC-1, AC-2
