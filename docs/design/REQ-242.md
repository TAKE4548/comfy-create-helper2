# 設計書: REQ-242 Service Manager ターミナルバックグラウンド起動とタブ別コンソール出力表示

## 1. 設計概要 (Architecture Overview)

本設計は、Prompt Surgeon のサービスマネージャー（`tools/server-manager/`）において、Web UI（ポート 8899）からサービスを起動した際に 3 つの外部ターミナルウィンドウ（Backend, Frontend, ComfyUI）が前面にポップアップして残り続ける問題を根本解決し、あわせてマネージャー画面内に各サービス（Backend, Frontend, ComfyUI, Manager Action）のコンソールログ出力をタブ切り替えでリアルタイムに確認・監視できるダッシュボード環境を提供する。

### 課題と解決アプローチ

1. **3つのターミナルが開きっぱなしで残り続ける現象**:
   - **根本原因**:
     - 従来の `server-manager.ps1` 内のバックグラウンド起動において `Start-Process -FilePath "conhost.exe" ... -WindowStyle Hidden` が使用されていた。Windows において `conhost.exe` はコンソールウィンドウそのものをホストするプログラムであるため、`-WindowStyle Hidden`（`SW_HIDE`）を指定してもウィンドウ生成自体は抑制されず、有効なウィンドウ（`MainWindowHandle`）が生成されて表示されてしまう。
     - その内部で `uvicorn`（Backend）、`npm run dev`（Frontend）、`wsl python main.py`（ComfyUI）という**終了しない常駐プロセス**が動作するため、ウィンドウが閉じずに画面上に 3 つ残り続ける結果となっていた。
     - また、非バックグラウンド時も `cmd.exe /k` により明示的に 3 つのウィンドウを開いて常駐させる分岐になっていた。
   - **解決策**:
     - `conhost.exe` の呼び出しを完全に廃止し、.NET の `System.Diagnostics.ProcessStartInfo`（`CreateNoWindow = $true`, `UseShellExecute = $false`）を用いた完全非表示起動ヘルパー `Start-ProcessNoWindow` を導入。
     - 実機検証（`scratch/test_nowindow.ps1`）により、`MainWindowHandle: 0`（ウィンドウ生成数 0）でプロセスが完全バックグラウンド常駐することを実証済み。
     - さらに `server_api.py` の `subprocess.run` 実行時にも `creationflags=subprocess.CREATE_NO_WINDOW` を指定し、外部ウィンドウの生成・割り込みを 100% 抑止する。

2. **ComfyUI ログの消失**:
   - **原因**: ComfyUI のバックグラウンド起動時に stdout/stderr のファイルリダイレクトが行われておらず、ログがファイルに残らない。
   - **解決**: ComfyUI 起動コマンドに `> "$logFile" 2>&1` を付与し、`tools/server-manager/logs/comfy.log` に確実に記録する。

3. **コンソールログの閲覧手段の欠如**:
   - **原因**: 既存 Web UI には各サービスのログを配信する API および UI 表示エリアが存在せず、実行結果テキストのみが表示されていた。
   - **解決**:
     - `server_api.py` に `GET /api/logs?service=<name>&tail=<lines>` エンドポイントを新設。
     - Web UI に「Backend」「Frontend」「ComfyUI」「Manager 実行ログ」の 4 つを切り替えるタブ別コンソールビューアを実装。
     - 自動更新（ポーリング）、自動スクロール追従、フォールバックエンコーディング（UTF-8 / CP932）に対応。

## 3. モジュール別詳細設計 (Detailed Module Design)

### 3.1 `tools/server-manager/server-manager.ps1`

#### A. 完全非表示プロセス起動関数 (`Start-ProcessNoWindow`)
```powershell
function Start-ProcessNoWindow ([string]$filePath, [string]$arguments, [string]$workingDirectory = "") {
    $psi = New-Object System.Diagnostics.ProcessStartInfo
    $psi.FileName = $filePath
    $psi.Arguments = $arguments
    if ($workingDirectory) {
        $psi.WorkingDirectory = $workingDirectory
    }
    $psi.WindowStyle = [System.Diagnostics.ProcessWindowStyle]::Hidden
    $psi.CreateNoWindow = $true
    $psi.UseShellExecute = $false
    return [System.Diagnostics.Process]::Start($psi)
}
```
- 従来の `conhost.exe` 経由の起動を完全に廃止し、`Start-ProcessNoWindow` を通じて `cmd.exe /c ...` を直接起動。
- `CreateNoWindow = $true` かつ `UseShellExecute = $false` により、Windows Console Host ウィンドウの生成そのものが抑止され、`MainWindowHandle` が 0 となるため、前面への 3 つのターミナル出現・残存が完全に根絶される。

#### B. 各サービス起動処理の更新
1. **WSL ComfyUI (`Start-ComfyUIProcess`)**:
   - バックグラウンド時：`$logFile = Join-Path $LOGS_DIR "comfy.log"` を設定し、`Start-ProcessNoWindow "cmd.exe" "/c wsl $($wslPrefix)bash -c `"$cmdStr`" > `"$logFile`" 2>&1"` を実行。
2. **Backend (`Start-BackendProcess`)**:
   - バックグラウンド時：`Start-ProcessNoWindow "cmd.exe" "/c run_server.bat > `"$logFile`" 2>&1" $beDir` を実行。
3. **Frontend (`Start-FrontendProcess`)**:
   - バックグラウンド時：`Start-ProcessNoWindow "cmd.exe" "/c $($cfg.frontend.start_cmd) > `"$logFile`" 2>&1" $feDir` を実行。

#### C. ログ表示処理 (`Show-Logs`)
- `comfy` 指定時に `$LOGS_DIR/comfy.log` が存在すれば優先して表示し、未生成の場合は WSL 内 `~/comfyui.log` にフォールバック。

### 3.2 `tools/server-manager/server_api.py`

#### A. サブプロセス呼び出しの非表示化
- `subprocess.run` 実行時、Windows 環境では `creationflags=subprocess.CREATE_NO_WINDOW`（`0x08000000`）を付与。
- これにより、Web Manager が powershell.exe を実行する際のコマンドプロンプトポップアップを防止。

#### B. ログ取得エンドポイント (`GET /api/logs`)
- **リクエスト**:
  - `GET /api/logs?service=backend&tail=200`
  - `GET /api/logs?service=frontend&tail=200`
  - `GET /api/logs?service=comfy&tail=200`
  - `GET /api/logs?service=manager&tail=200`
- **処理ロジック**:
  1. `service` パラメータを正規化（`backend`/`be`, `frontend`/`fe`, `comfy`/`wsl`, `manager`）。
  2. 対象ログファイル（`backend.log`, `frontend.log`, `comfy.log`, `web_manager.log`）を特定。パス走査（ディレクトリトラバーサル）を防止するため、ファイル名を固定ホワイトリストで制限。
  3. ファイルが存在する場合：末尾 `tail` 行（既定 200 行、最大 1000 行）を読み込み。エンコーディングは UTF-8 を試行し、失敗時は CP932 (Shift-JIS) でフォールバック読み込み。
  4. ファイルが存在しない場合：`"ログファイルはまだ生成されていません（サービス未起動）"` を返却。
- **レスポンス形式**:
  ```json
  {
    "service": "backend",
    "filename": "backend.log",
    "exists": true,
    "lines": 120,
    "content": "INFO:     Started server process [1234]\nINFO:     Waiting for application startup..."
  }
  ```

#### C. タブ別コンソール UI 実装
- **タブ構成**:
  - 🖥️ `Backend (Win BE)`
  - 🌐 `Frontend (React FE)`
  - ⚡ `ComfyUI (WSL2)`
  - 📋 `Manager 実行ログ`
- **UI 構成要素**:
  - **タブヘッダー**: 各サービス名のタブボタン。アクティブタブはハイライト表示。各サービスの状態（稼働中緑/停止中赤）を示す小型ステータスドットを表示。
  - **コントロールバー**:
    - 「🔄 ログ自動更新」チェックボックス（既定: ON、2秒間隔）
    - 「⬇ 最新へスクロール」チェックボックス（既定: ON）
    - 表示行数セレクト（50 / 100 / 200 / 500 行）
    - 「🔄 今すぐ更新」ボタン
  - **コンソール表示部**:
    - 黒背景（`#050914`）、monospace フォント、高さ 360px、縦スクロール可能。
    - ユーザーが上方にスクロールした場合は自動スクロールを一時抑制し、閲覧を邪魔しない設計。最下部に到達すると自動追従が再開。
    - アクション（起動・停止・再起動）実行時の出力は「Manager 実行ログ」タブに記録され、かつ該当サービスタブへ切り替えることで起動過程のログがリアルタイムに確認可能。
