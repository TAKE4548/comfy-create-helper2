# PBI-REQ-035 実行可能テスト計画

## 1. 自動テスト (CLI Verification)
- **ビルド検証コマンド**:
  ```bash
  cd frontend
  npm run build
  ```
- **判定基準**: ビルドプロセスがエラー（Exit Code 0 以外）なしで終了し、コンソール出力にエラーメッセージが含まれないこと。ビルド生成物（`dist` ディレクトリ等）が作成されること。

## 2. ツール主導監査 (Tool-Driven Audit)
- **コード監査**: `local_model_adapter.py arch-audit .` を実行し、設計整合性の客観的証明を得ること。
- **バリデータ実行**:
  ```bash
  python ${GLOBAL_SCRIPTS}\artifact_linter.py docs/backlog/task/active/
  ```
- **判定基準**: 出力に `VALIDATION_FAILED` や `ERROR` が含まれず、`<status>PASS</status>` となっていること。

## 3. ブラウザ検証 (Browser Agent Verification)
- **対象URL**: `http://localhost:5173/` (Frontend開発用URL)
- **前提条件**:
  - バックエンドサーバー (`http://localhost:8000`) が起動していること。
  - ComfyUI サーバー（またはモック）が起動していること。
- **操作手順 & 判定基準 (Assertion)**:
  1. 生成ページにてシード設定を「Shuffle」（サイコロアイコン）にする。
  2. Batch Size を `3` に設定して画像生成を実行する（これにより、ランダムなシード値を持つ3つの独立したリクエストが送信されます）。
  3. ブラウザのデベロッパーツール（F12）の「ネットワーク」タブにて、ComfyUIの `/prompt` エンドポイントへ送信される3回のリクエストのJSONデータを確認し、それぞれのシード値 `s1`, `s2`, `s3` を抽出する。
  4. **厳密な数値検証（ランダムモード）**:
     - `s1 > 0` かつ `s2 > 0` かつ `s3 > 0` (すべて正の整数) であること。
     - `s1 != s2` かつ `s2 != s3` かつ `s1 != s3` (3つの値がすべて互いに異なること) であること。
  5. 次に、シード設定を「Lock」（固定値キーアイコン）にし、シード入力欄に `1000` を設定する。
  6. Batch Size を `3` に設定して画像生成を実行する。
  7. 同様に送信される3回のリクエストのシード値 `s1`, `s2`, `s3` を確認する。
  8. **厳密な数値検証（固定値モード）**:
     - 送信されたシード値が順に `s1 = 1000`, `s2 = 1001`, `s3 = 1002` であること。
- **必須エビデンス**: デベロッパーツールのネットワークタブで送信されたJSON（シード値部分）のスクリーンショットを `.gemini/` ディレクトリに保存すること。
