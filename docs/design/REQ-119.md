# REQ-119: ROI範囲指定時の吹き出し検出不具合の修正 - 設計仕様書

## 1. 目的と背景
フロントエンドのスナップショット編集画面でROI（関心領域）を指定して吹き出しを自動検出する際、検出に失敗する不具合が発生していました。
原因は、バックエンドの画像処理ロジックにおいて、指定されたROIで事前に画像をクロップしてから輪郭抽出・面積判定を行っていたため、以下の問題が生じていたことです：
1. クロップ後の狭い領域における吹き出しの面積が1000画素未満になり、ノイズ除去フィルタで除外される。
2. クロップ境界で吹き出しのエッジが途切れ、閉じた輪郭として抽出できなくなる。

本設計では、検出処理は常に画像全体に対して実行し、抽出された吹き出し候補（輪郭）がROIに含まれるか否かで後からフィルタリングする方式に変更します。

## 2. 影響を受けるコンポーネントとファイル
- **バックエンド**:
  - `backend/app/services/bubble_detector.py` ([bubble_detector.py](../../backend/app/services/bubble_detector.py)): `detect_bubble` 関数の検出・ROIフィルタリングロジック of 修正。

## 3. 詳細設計

### 3-1. `detect_bubble` 関数のアルゴリズム変更

変更前のアルゴリズム：
1. ROI指定がある場合、入力画像を `roi["x"], roi["y"], roi["w"], roi["h"]` で切り出す。
2. 切り出した画像に対してグレースケール化、平滑化、Cannyエッジ検出、輪郭抽出を実行する。
3. 各輪郭の面積が `1000` 未満の場合は除外する。
4. 輝度やアスペクト比でフィルタリングし、最大面積のものを選択。
5. 選択された輪郭の座標にROIのオフセットを足して画像全体の座標に変換して返却。

変更後のアルゴリズム：
1. **画像全体を対象**としてグレースケール化、平滑化、Cannyエッジ検出、輪郭抽出（`cv2.findContours`）を実行する。これにより、エッジが画像の端で切れて閉まらなくなる問題と、面積が1000画素未満になって除外される問題を根本的に解決する。
2. 検出された各輪郭に対して、面積が `1000` 未満のものを除外（画像全体での面積判定となるため、正常に動作する）。
3. **ROIフィルタリングの適用**:
   - `roi` パラメータが指定されている場合、各輪郭のバウンディングボックス（`x2, y2, w2, h2`）が、指定された `roi` 範囲に合致するか判定する。
   - 判定基準：**輪郭 of bounding box の中心座標 `(x2 + w2/2, y2 + h2/2)` が、指定された `roi` の範囲内 `[x, x+w]`, `[y, y+h]` に含まれていること**。これにより、ユーザーがドラッグで囲んだ領域の内側にある吹き出しのみを正確に抽出する。
4. アスペクト比判定および内部の平均輝度判定を行う。
5. 最大面積のものを選択し、その座標をそのまま返却する（オフセット加算は不要）。
6. **確信度（Confidence）の計算**:
   - 分母となる面積（`denom_area`）は、ROI指定時は `roi_w * roi_h`、未指定時は画像全体の面積とする。
   - `confidence = min(best_area / denom_area * 10, 1.0)` として計算し、少数第2位で丸める。

---

## 4. 設計上のトレードオフとリスク (Trade-off Disclosure)

### 画像全体に対する処理負荷
- **リスク**: 画像全体に対してエッジ検出や輪郭抽出を実行するため、ROIで切り取ってから処理するよりも計算負荷がわずかに増加します。
- **対策**: 対象画像はスナップショット（通常はWebUIの生成画像、1〜2MB程度）であり、OpenCV of contour detection (Canny + findContours) は数ミリ秒〜十数ミリ秒で完了するため、実用上のパフォーマンス低下やユーザー体験への影響はありません。

### ROI境界付近での判定の厳密さ
- **リスク**: ユーザーが吹き出しを囲む際、吹き出しの大部分は囲んでいるが中心点がわずかにROIから外れてしまう極端なドラッグ操作を行った場合、検出から除外される可能性があります。
- **対策**: 通常、ユーザーは吹き出しの中心付近を含めてドラッグするため、中心点判定が最も誤検知が少なく直感的です。また、もし中心点判定で不足がある場合は「交差領域の面積が50%以上」といった判定基準を組み合わせることも可能ですが、シンプルさと堅牢性を考慮し、まずは中心点判定をプライマリとして実装します。
