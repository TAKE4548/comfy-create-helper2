# REQ-148 詳細設計書: 生成画面およびセリフ編集画面における前回保存先アルバムの個別管理とアルバム選択モーダルのサイズ拡張

## 1. 概要 (Overview)
生成画面（スナップショット保存）とセリフ編集画面（セリフ追加・編集後の保存）におけるアルバム保存ワークフローに関して、以下の課題を解決します：
1. **保存先アルバム記憶の共有によるコンテキスト汚染**:
   現在は両方の画面で同一のストレージキー（`LS_KEYS.LAST_SAVE_ALBUM_ID`）を参照・更新しているため、生成画面で素材用アルバムを選択するとセリフ編集側の前回保存先が上書きされ、逆にセリフ編集画面で完成品アルバムを選択すると生成画面側の前回保存先が上書きされてしまう。
2. **アルバム選択モーダルの縦サイズ制限**:
   保存先アルバムを選択するモーダル（`AddSnapshotToAlbumModal`）のドロップダウンリストや全体の高さが `max-h-60`（約240px）等で小さく、アルバム数が多い場合にスクロールが窮屈で選択しづらい。

本設計では、以下を実装します：
- **画面別ストレージキーの分離**:
  - 生成画面用: `LS_KEYS.LAST_SAVE_ALBUM_ID_GENERATE`
  - セリフ編集画面用: `LS_KEYS.LAST_SAVE_ALBUM_ID_SPEECH`
- **保存先アルバム選択モーダルのサイズ・視認性拡張**:
  - `AddSnapshotToAlbumModal` のモーダル幅・縦高さを拡張（`max-w-lg`, ドロップダウン `max-h-96` / 384px 等）。

```typescript
  // ...既存のキー

  LAST_SAVE_ALBUM_ID_GENERATE: 'prompt-surgeon-last-save-album-id-generate',
  LAST_SAVE_ALBUM_ID_SPEECH: 'prompt-surgeon-last-save-album-id-speech',
```


### 3.3 `SpeechBubbleEditorModal.tsx`
```tsx
const [targetAlbumId, setTargetAlbumId] = useState<number | 'new' | ''>(() => {
  try {
    const saved = localStorage.getItem(LS_KEYS.LAST_SAVE_ALBUM_ID_SPEECH)
    if (saved && !isNaN(Number(saved)) && Number(saved) > 0) {
      return Number(saved)
    }
  } catch {}
  if (initialAlbumId !== undefined) return initialAlbumId
  return 'new'
})

// 保存処理内
if (targetAlbumId === 'new') {
  const createdAlbum = await albumsApi.create({
    name: newAlbumName.trim(),
    snapshot_ids: [savedSnapshotId],
  })
  try {
    localStorage.setItem(LS_KEYS.LAST_SAVE_ALBUM_ID_SPEECH, String(createdAlbum.id))
  } catch {}
} else if (typeof targetAlbumId === 'number') {
  await albumsApi.addItems(targetAlbumId, [savedSnapshotId])
  try {
    localStorage.setItem(LS_KEYS.LAST_SAVE_ALBUM_ID_SPEECH, String(targetAlbumId))
  } catch {}
} else {
  try {
    localStorage.setItem(LS_KEYS.LAST_SAVE_ALBUM_ID_SPEECH, '')
  } catch {}
}
```

## 4. トレードオフ・リスク開示 (Trade-offs & Constraints)
- **過去の localStorage キーの移行**:
  過去の単一キー `LAST_SAVE_ALBUM_ID` から移行する際、ユーザーがすでに保存していた過去値は新キー未設定時のフォールバックとして参照可能にするか、初回のみフォールバックさせることが可能です。今回は独立性を最優先し、新キー未設定時は通常初期値（またはフォールバック値）を適用します。
