# REQ-216: モバイルモードにおけるセリフ一括変換モーダル下部被り解消および履歴ヘッダーレスポンシブレイアウト修正 詳細設計書（根本対策導入版）

## 1. 概要・背景
本改修は、モバイル端末（画面幅 < 1024px、および 375px〜414px）におけるセリフ一括変換モーダルの下部メニュー被り、および履歴ヘッダーでのボタンはみ出し事象の解消とともに、**「今後の改修・新機能追加で同様のレイアウト破綻や z-index / パディング不整合を再発させない根本対策」** を組み込んだアーキテクチャ刷新である。

---

## 2. 根本対策アーキテクチャ設計

### 2.1 共通 `<Modal>` コンポーネントの導入 (`frontend/src/components/common/Modal.tsx`)
- **目的**: 各コンポーネントでの `fixed inset-0 z-50` などの独自記述を排除し、プロジェクト標準のモーダル Backdrop・スタッキング規約を単一コンポーネントで強制する。
- **仕様**:
  - **Backdrop**: 常に `.modal-backdrop` クラス（`z-index: var(--z-modal)` [100]、モバイル下部ナビゲーション分のセーフエリアパディング `calc(var(--mobile-nav-height) + 1rem + env(safe-area-inset-bottom))`）を自動適用。
  - **ダイアログサイズ**: `size` props ('sm' | 'md' | 'lg' | 'xl' | '5xl' | 'full' 等) に応じて安全な最大幅を設定。高さは `max-h-full` または `max-h-[88vh]` でビューポート内に安全に収める。
  - **共通振る舞い**:
    - 背景クリック時の `onClose` 呼び出し（`closeOnBackdropClick` で制御可能）。
    - ダイアログ内部クリック時の `e.stopPropagation()` を自動適用。
    - `Esc` キー押下によるクローズハンドリング（`closeOnEsc` で制御可能）。
  - **セリフ一括変換モーダルへの適用**: `BatchSpeechTransformModal.tsx` で共通 `<Modal>` コンポーネントを使用し、下部被りを完全解消。

### 2.2 共通 `<PageHeader>` コンポーネントの導入 (`frontend/src/components/common/PageHeader.tsx`)
- **目的**: ページヘッダーで要素追加時にモバイル幅で横幅オーバーフローが発生するのを防ぐ。
- **仕様**:
  - 親コンテナに `flex flex-wrap items-center justify-between gap-2.5 px-4 sm:px-5 py-3 sm:py-4 border-b border-[rgba(255,255,255,0.06)]` を標準適用。
  - 右側アクション領域に `flex flex-wrap items-center gap-2` を標準適用。
  - モバイル画面幅（375px〜414px）でも、新設ボタンや既存ボタンが自動的・安全に折り返され、右端のボタンが画面外にはみ出る事象を構造的に防ぐ。
  - **履歴ページへの適用**: `HistoryPage.tsx` で共通 `<PageHeader>` を使用。

### 2.3 UI ガードレールテストの導入 (`frontend/src/__tests__/ui_guardrail.test.ts`)
- **目的**: 今後の新規モーダル追加やヘッダー改修時に、非推奨な独自クラス（`fixed inset-0 z-50` 等）の直書きや `flex-wrap` 漏れを CI/テストで静的に検出する。

## 4. トレードオフと設計判断 (Trade-off Disclosure)
- **個別修正 vs 共通コンポーネント導入**:
  - 当面のバグ修正だけであれば `BatchSpeechTransformModal` と `HistoryPage` のクラス名書き換えのみでも対応可能だが、将来の改修や新画面追加時に同様のミスが再発するリスクが高い。共通 `<Modal>` / `<PageHeader>` コンポーネントを導入することで、規約をコンポーネントレベルで強制し、長期的な保守性と品質を担保する。
