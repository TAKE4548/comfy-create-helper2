# REQ-322: Fix LoRA Studio API Path Double Prefix (405 Method Not Allowed)

## 1. 概要 (Overview)
- **PBI ID**: REQ-322
- **ステータス**: in-progress
- **対象サブシステム**: `frontend` (`frontend/src/api/client.ts`, `frontend/src/api/__tests__/client.test.ts`)
- **関連ドキュメント**: [`docs/incident_report.md`](docs/incident_report.md), [`docs/backlog/pbi/active/REQ-322.md`](docs/backlog/pbi/active/REQ-322.md)

## 2. 背景と課題 (Background & Problem Analysis)
Dataset Studio (LoRA Studio) において、直交マトリクス再計算やプロジェクト作成・更新などの操作を行った際、APIリクエストが `405 Method Not Allowed` で失敗するインシデントが発生した。

### 根本原因 (Root Cause)
1. `frontend/src/api/client.ts` の内部共通リクエスト関数 `request<T>(path: string, options: RequestInit)` は、定数 `BASE_URL = '/api'` を定義し、`fetch(\`${BASE_URL}${path}\`, ...)` としてエンドポイントURLを組み立てる仕様である。
2. 他のAPI（`workflowsApi`, `mappingMastersApi`, `snapshotsApi` 等）は相対パス（例: `'/workflows'`, `'/mapping-masters'`）を渡しており、正常に `fetch('/api/workflows')` 等が発行される。
3. しかし、`settingsApi`, `datasetApi`, `trainingApi`, `benchmarkApi` の各メソッドにおいて、パス引数に誤ってプレフィックス `/api` を含めた文字列リテラル（例: `'/api/settings/vram'`, `'/api/dataset/projects'`）が指定されていた。
4. この結果、ブラウザから `fetch('/api/api/dataset/projects/...')` が発行されていた。
5. FastAPI 側には `/api/api/...` にマッチするルーティングが存在せず、フォールバックの `SPAStaticFiles` (GET/HEAD のみ対応) に到達するため、POST/PUT/PATCH/DELETE リクエストに対して `405 Method Not Allowed` が返送されていた。

## 3. SSoT インパクト分析 (SSoT Impact Analysis)
- `doc_mapper.py` による調査結果: 直接マッピングされた仕様書 (`docs/specs`) は存在しない。
- バックエンド側のルーティング定義（SSoT）:
  - `backend/app/routers/settings.py`: `router = APIRouter(prefix="/api/settings", ...)`
  - `backend/app/routers/dataset_router.py`: `router = APIRouter(prefix="/api/dataset", ...)`
  - `backend/app/routers/training_router.py`: `router = APIRouter(prefix="/api/training", ...)`
  - `backend/app/routers/benchmark_router.py`: `router = APIRouter(prefix="/api/benchmark", ...)`
- バックエンドの各ルーターはすべて `/api/<subsystem>` をプレフィックスとしてFastAPIにマウントされているため、フロントエンドの `request` 関数（`BASE_URL = '/api'`）に渡すべきパスは先頭が `/settings`, `/dataset`, `/training`, `/benchmark` で始まる相対パスである必要がある。

## 4. 詳細設計 (Detailed Design)

### 4.1 `frontend/src/api/client.ts` 修正仕様
各APIオブジェクトの呼び出し先パスから、先頭の余分な `/api` を除去する。

#### `settingsApi`
- `getVram`: `request<VramSettings>('/settings/vram')`
- `updateVram`: `request<VramSettings>('/settings/vram', { method: 'PUT', body: JSON.stringify(data) })`

#### `datasetApi`
- `getProjects`: `request<DatasetProject[]>('/dataset/projects')`
- `getProject`: `request<DatasetProject>(`/dataset/projects/${projectId}`)`
- `createProject`: `request<DatasetProject>('/dataset/projects', { method: 'POST', body: JSON.stringify(data) })`
- `updateProject`: `request<DatasetProject>(`/dataset/projects/${projectId}`, { method: 'PUT', body: JSON.stringify(data) })`
- `deleteProject`: `request<{ message: string; id: number }>(`/dataset/projects/${projectId}`, { method: 'DELETE' })`
- `getOutfitMasters`: `request<OutfitMasterPreset[]>(`/dataset/outfits${qs}`)`
- `calculateMatrix`: `request<DatasetItem[]>(`/dataset/projects/${projectId}/matrix`, { method: 'POST' })`
- `updateItem`: `request<DatasetItem>(`/dataset/items/${itemId}`, { method: 'PATCH', body: JSON.stringify(data) })`
- `exportDataset`: `request<DatasetExportResponse>(`/dataset/projects/${projectId}/export`, { method: 'POST', body: data ? JSON.stringify(data) : undefined })`

#### `trainingApi`
- `createJob`: `request<LoraTrainingJob>('/training/jobs', { method: 'POST', body: JSON.stringify(data) })`
- `getJob`: `request<LoraTrainingJob>(`/training/jobs/${jobId}`)`
- `startJob`: `request<{ status: string; job_id: number; pid?: number }>(`/training/jobs/${jobId}/start`, { method: 'POST' })`
- `stopJob`: `request<{ status: string; job_id: number }>(`/training/jobs/${jobId}/stop`, { method: 'POST' })`
- `getJobStatus`: `request<{ is_training_active: boolean }>('/training/status')`

#### `benchmarkApi`
- `generatePrompts`: `request<GenerateStressTestPromptsResponse>('/benchmark/generate-prompts', { method: 'POST', body: JSON.stringify(data) })`
- `evaluate`: `request<EvaluateBenchmarkResponse>('/benchmark/evaluate', { method: 'POST', body: JSON.stringify(data) })`

### 4.2 `frontend/src/api/__tests__/client.test.ts` テスト追加仕様
`settingsApi`, `datasetApi`, `trainingApi`, `benchmarkApi` を `client.ts` からインポートし、モックされた `fetch` が期待通り `/api/...` にリクエストを発行していることを検証するテストケース群を追加する。
- `settingsApi`:
  - `getVram`: `/api/settings/vram` への GET リクエスト検証
  - `updateVram`: `/api/settings/vram` への PUT リクエスト・ボディ検証
- `datasetApi`:
  - `getProjects`: `/api/dataset/projects` への GET
  - `getProject`: `/api/dataset/projects/:id` への GET
  - `createProject`: `/api/dataset/projects` への POST
  - `updateProject`: `/api/dataset/projects/:id` への PUT
  - `deleteProject`: `/api/dataset/projects/:id` への DELETE
  - `getOutfitMasters`: `/api/dataset/outfits` およびクエリパラメータ `/api/dataset/outfits?category=xxx` の検証
  - `calculateMatrix`: `/api/dataset/projects/:id/matrix` への POST
  - `updateItem`: `/api/dataset/items/:id` への PATCH
  - `exportDataset`: `/api/dataset/projects/:id/export` への POST
- `trainingApi`:
  - `createJob`: `/api/training/jobs` への POST
  - `getJob`: `/api/training/jobs/:id` への GET
  - `startJob`: `/api/training/jobs/:id/start` への POST
  - `stopJob`: `/api/training/jobs/:id/stop` への POST
  - `getJobStatus`: `/api/training/status` への GET
- `benchmarkApi`:
  - `generatePrompts`: `/api/benchmark/generate-prompts` への POST
  - `evaluate`: `/api/benchmark/evaluate` への POST

## 5. 移行・互換性・破壊的変更への影響 (Compatibility & Migration)
- 本修正はクライアントコードのプレフィックス過剰付与バグの修正であり、FastAPI側のルーティングおよびデータスキーマには一切の変更を加えない。
- 既存のコンポーネントテスト（`e2e_req319_lora_studio.test.tsx`, `OutfitMasterModal.test.tsx`, `MatrixGenerationStep.test.tsx`, `CuratorGrid.test.tsx` 等）は `client.ts` のエクスポート関数を直接モックしているため、本修正による後方互換性破壊やテスト破損は発生しない。
