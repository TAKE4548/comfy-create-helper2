# 検証計画書: REQ-039 生成ジョブのキャンセル機能

> [!IMPORTANT]
> **AIエージェントへの指示**:
> 本計画書に基づく検証を行う際、コードの論理構造から「正常に動作するはず」と推測して検証を合格（Pass）させてはならない（脳内テストの禁止）。
> 各検証ステップで指定された具体的なエビデンス（`performance.now()` や `Date.now()` による計測数値、終了コード数値、コンソールログ出力、開発者ツールのキャプチャ内容、実際のAPIレスポンスペイロードなど）を必ず数値・文字列で報告に含めること。
> 数値が基準を満たさない場合や、指定されたエビデンスが出力できない場合は、論理的な理由付けなしに即座に「Fail」と判定すること。

## [重要] データ取得規則 (Global Rule)
本検証では、すべての計測数値は実行中の JavaScript コード変数または開発者ツールの出力から直接取得すること。
- `performance.now()`: クリックイベントハンドラー開始時または直後に記録する変数を使用。
- API レスポンス: `fetch` の `.then(res => res.json())` 内でパースしたオブジェクトのキー値を使用。
- タイミング差分: `(終了時刻変数 - 開始時刻変数)` を計算し、その結果を報告すること。浮動小数点比較のブレを防ぐため、`Math.round(T_diff)` を使用し、整数値で判定すること。

## 1. 自動テスト（フロントエンド単体）
**目的**: ビルドプロセスおよび型チェックが正常に通ることを確認する。
**実行コマンド**:
```bash
cd frontend && npm ci && npm run build
```
**判定基準 (Pass/Fail ロジック)**:
- [ ] **Exit Code Verification**: コマンドの実行結果から取得した終了コード（Exit Code、シェルでは `$?`）を数値で確認し、**厳密に `0` に等しいこと**。
  - **Fail条件**: 終了コードが `0` 以外の場合、またはエラーメッセージが出力された場合、即座に Fail と判定しその数値を報告すること。
- [ ] **No Errors in Output**: ビルド出力ログに `error:` または `ERR_` で始まる文字列が含まれていないこと。
  - **Fail条件**: エラー文字列が含まれている場合は即座に Fail と判定し、該当ログ部分を報告すること。
- [ ] **Type Check Passed**: ビルド前の `tsc` 静的解析エラーがないこと。
- [ ] **Artifact Integrity Check**: ビルド完了後、`dist/index.html` および `dist/assets/` 配下にサイズが 0 バイトより大きい JS/CSS ファイルが正しく出力されていること。

## 2. 手動検証（ブラウザによる確認手順）

### 事前準備
1. **バックエンド起動**: `cd backend && .venv\Scripts\uvicorn app.main:app --reload` を実行してサーバーを起動する。
2. **フロントエンド起動**: `cd frontend && npm run dev` を実行し、開発サーバーを起動する。
3. ブラウザで `http://localhost:5173/` にアクセスする。
4. 接続設定で正常に動作している ComfyUI の URL を設定する。
5. **コンテキスト準備（必須）**: 
   - テストブラウザの別ウィンドウまたはシークレットウィンドウを開き、異なる `clientId` （別ユーザー）でアクセスする。
   - **確認ステップ**: 両方のウィンドウからそれぞれジョブを生成し、メイン画面の「Queue: X」表示が合計件数（自 + 他）を正しく反映していることを確認してからテストを開始すること。

### 検証項目詳細

#### AC-1 & AC-2: ジョブ管理モーダルの表示と一覧表示
**操作手順**:
1. 画面上の進捗表示エリアにある「Queue: X」というラベルをクリックする。
2. 開いたモーダルをブラウザの開発者ツール（Elements タブ）でインスペクトする。

**判定基準**:
- [ ] **DOM Presence**: クリック後、`document.querySelector('.fixed.inset-0.bg-black\\/60.backdrop-blur-sm')` の実行結果が `null` でないこと（DOM要素の存在を確認し、結果の真偽値を報告すること）。
  - **Fail条件**: 返り値が `null` の場合、即座に Fail と判定すること。
- [ ] **Style Verification**: `window.getComputedStyle(document.querySelector('.fixed.inset-0.bg-black\\/60.backdrop-blur-sm')).backdropFilter` の値（文字列）を取得し、`"blur(4px)"` (または同等) が適用されていることを確認し、その出力されたスタイル文字列を報告すること。
  - **Fail条件**: スタイル文字列に `"blur"` または同等の表記が含まれていない場合、即座に Fail と判定すること。
- [ ] **Timing Check**: ラベルをクリックした時刻（T1 = `performance.now()`）とモーダル要素がDOMにマウントされた時刻（T2 = `performance.now()`）をミリ秒単位で計測し、その差分 `T_diff = Math.round(T2 - T1)` が `200`（ミリ秒）以下であること。計測した ms 数値を報告すること。本検証では、動作環境による差異やネットワーク遅延を考慮し、100ms の許容誤差を含めた 200ms を基準とする。
  - **Fail条件**: `T_diff > 200` の場合、取得した数値を報告し即座に Fail と判定すること。
- [ ] **List Count Sync**: モーダル内のリスト表示件数と、ComfyUI 側が返す実際のキュー件数を数値で比較し、完全に一致すること。

#### AC-3: 個別キャンセルアクション
**操作手順**:
1. 複数のジョブを生成してキューを溜める。
2. 待機中（Pending）の特定のジョブの右側にあるゴミ箱アイコンボタンをクリックする。
3. 実行中（Running）のジョブの右側にあるゴミ箱アイコンボタンをクリックする。

**判定基準**:
- [ ] **Pending Job**: 
    - ボタンをクリックした時刻（T_click = `performance.now()`）と該当ジョブのDOM要素が親コンテナから削除された時刻（T_remove = `performance.now()`）を計測し、`T_diff = Math.round(T_remove - T_click)` が `1000`（ミリ秒）以下であること。計測した ms 数値を報告すること。
      - **Fail条件**: `T_diff > 1000` の場合、取得した数値を報告し即座に Fail と判定すること。
    - メイン画面の「Queue 待機数」カウンターが 1 つ減ることを数値で確認すること。
- [ ] **Running Job**: 
    - 中断ボタンをクリックした時刻（T_click = `performance.now()`）から、ネットワークタブで ComfyUI の `/interrupt` POST リクエストに対するレスポンスが完了した時刻（T_confirm = `performance.now()`）を計測し、`T_diff = Math.round(T_confirm - T_click)` が `5000`（ミリ秒）以下であること。計測した ms 数値を報告すること。
      - **Fail条件**: `T_diff > 5000` の場合、取得した数値を報告し即座に Fail と判定すること。
    - 中断リクエストに対するレスポンスステータスコード（例: `200`）を数値で報告すること。

#### AC-4: 一括キャンセルアクション
**操作手順**:
1. 別ユーザーのジョブ（`client_id` が異なるもの）を1つ以上、自ユーザーのジョブを2つ以上キューに溜める。
2. モーダル内の「自セッションのジョブのみを表示（`filterOwnSession`）」のON/OFFを切り替えてテストする。
3. まず `filterOwnSession` をONにし、「一括キャンセル」ボタンをクリックし、ポップアップ確認ダイアログで「OK」をクリックする。
4. 次に `filterOwnSession` をOFFにし、「一括キャンセル」ボタンをクリックする。

**判定基準**:
- [ ] **自セッションのみ一括削除 (`filterOwnSession` が有効な場合)**:
  - 自セッションのジョブは全てキューからクリアされ、リストから消失する（最大 3秒以内）。
  - ネットワークタブで `/queue` POST リクエストを確認し、リクエストペイロード（`delete` 配列）を JSON パースする。
    - **Pass条件**: JSON パースした `delete` 配列の要素数（`length`）が自セッションのジョブ数と一致し、配列内に他ユーザーのジョブ ID が含まれていないこと。
    - **Fail条件**: 他ユーザーのジョブ ID が含まれているか、配列長が一致しない場合。
    - パースした `delete` 配列の内容（文字列配列）を報告すること。
- [ ] **全削除 (`filterOwnSession` が無効な場合)**:
  - 実行中・待機中を問わず、全てのセッションのジョブがキューからクリアされること。

#### AC-5 & AC-6: 履歴非保持と状態の即時更新
**操作手順**:
1. ジョブの個別キャンセルおよび一括キャンセルを行う。
2. キャンセル後に履歴一覧（History など）を確認する。

**判定基準**:
- [ ] **API Verification**: 
    - キャンセル直後（1 秒以内）、ブラウザの開発者ツール（Network タブ）で `/history` POST (delete) のレスポンスを確認する。
    - `/history` 取得 API の応答データ JSON をパースし、**キャンセル対象の `promptId` が配列に含まれていないことを検証**する。
      - **Pass条件**: 対象 ID が配列に存在しないこと。
      - **Fail条件**: 対象 ID が配列に含まれている場合、またはパースエラーが発生した場合。
      - 取得された `history` 配列の長さ（件数）を数値で報告すること。
- [ ] **UI State Sync**: 
    - キャンセル実行直後、モーダル内のリスト表示およびメイン画面の「Queue」カウンターが遅滞なく（1秒以内）同期され最新件数を反映すること（`performance.now()` 計測値 `T_diff` が 1000ms 以下であること）。計測した ms 数値を報告すること。
      - **Fail条件**: `T_diff > 1000` の場合、即座に Fail と判定すること。

#### AC-7: エラー時の挙動（異常系テスト）
**操作手順**:
1. ネットワーク接続を切断（または ComfyUI サーバーの接続設定を無効なものに変更）した状態で、キャンセルボタンをクリックする。

**判定基準 (Pass/Fail ロジック)**:
- [ ] **UI Stability**: 
    - キャンセル操作後、`document.querySelector('.fixed.inset-0.bg-black\\/60.backdrop-blur-sm')` の実行結果が `null` でないこと（DOM要素が生存していること）。
    - 画面がクラッシュ（真っ白になるなど）しないことを確認し、実行結果の真偽値を報告すること。
- [ ] **Error Handling Verification**: 
    - **Pass条件**: 
      1. Network タブで `/interrupt` または `/queue` リクエストに対するレスポンスの HTTP ステータスコードが `400` から `599` の範囲内であること。
      2. または、ネットワークオフライン等のためリクエストが送信されずステータスコードが得られない場合、ブラウザの Console タブに `"Failed to fetch"` または `"NetworkError"` という文字列のエラーログが出力されていること。
    - **報告内容**: 取得できたステータスコード数値（4xx/5xx）、または確認できた Console のエラーログ文字列を報告すること。
    - **Fail条件**: ステータスコードが `2xx` であるか、もしくは Console に `"Failed to fetch"` / `"NetworkError"` の文字列がどちらも検出されない場合。および、モーダルの DOM 要素が消失（`null`）した場合。
