# REQ-286 詳細設計書: HistoryPage のビュー分離（ギャラリー vs アルバム詳細）

## 1. 概要と背景
`HistoryPage.tsx` は 840 行を超え、全スナップショット一覧（検索フィルタ、無限スクロール、一括操作、Lightbox、セリフ編集）と、アルバム詳細・並び替え（Dnd-kit、グループ移動、昇順降順、一括削除スコープ）という 2 つの異なる責務が一体化しており、状態管理とレンダリングロジックの肥大化（AI-Context Bloat）を招いている。
本改修では、PBI-REF-05 に従い、以下のディレクトリ構造へ物理的に責任分離を行う。

```
frontend/src/pages/HistoryPage/
├─ index.tsx                  # ページエントリ・共通クエリ定義（約120行）
├─ hooks/
│  ├─ useAlbumDndOrder.ts     # Dnd-kitによるアルバム内並び替え制御（約90行）
│  ├─ useAlbumOperations.ts   # 既存
│  └─ useBulkDownload.ts      # 既存
├─ components/
│  ├─ AlbumListView.tsx       # 既存
│  └─ AlbumDetailView.tsx     # リファクタ（Dnd並び替えロジックのフック分離）
└─ views/
   ├─ SnapshotGalleryView.tsx # 全件一覧ビュー（検索フィルタ・無限スクロール・カード描画）
   └─ AlbumDetailView.tsx     # components/ から views/ への再配置またはエイリアス
```

また、`frontend/src/pages/HistoryPage.tsx` は `export * from './HistoryPage/index'` を再エクスポートするか、直接 `frontend/src/pages/HistoryPage/index.tsx` へ移設し、外部（`App.tsx` 等）のインポートパス後方互換性を保証する。

---

## 2. アーキテクチャと責務分担

### 2.1 `useAlbumDndOrder.ts`（Dnd 並び替え制御カスタムフック）
- **責務**:
  - Dnd-kit のドラッグ＆ドロップイベントハンドリング（単一アイテム並び替えおよび複数選択グループ並び替えの挿入位置計算）。
  - `albumSortDirection`（'asc' | 'desc'）を考慮した新 snapshotIds 配列の生成。
  - `updateAlbumOrder.mutate` の呼び出し。
- **インターフェース**:
  ```typescript
  export interface UseAlbumDndOrderProps {
    albumId: number | null
    sortedAlbumItems: Album['items']
    sortDirection: 'asc' | 'desc'
    multiSelect: {
      isMultiSelectMode: boolean
      selectedIds: Set<number>
    }
    onUpdateOrder: (params: { id: number; snapshotIds: number[] }) => void
  }

  export function useAlbumDndOrder({
    albumId,
    sortedAlbumItems,
    sortDirection,
    multiSelect,
    onUpdateOrder,
  }: UseAlbumDndOrderProps): {
    handleAlbumItemDragEnd: (activeId: number, overId: number) => void
  }
  ```

### 2.2 `SnapshotGalleryView.tsx`（全スナップショット一覧ビュー）
- **責務**:
  - ワークフロー、LoRA、タグセットのフィルタバー、新旧ソート順切替。
  - スナップショットグリッド描画（カード、長押し選択、個別アクションボタン：セリフ編集、ダウンロード、削除）。
  - 無限スクロール用 sentinel DOM および IntersectionObserver 監視。
- **Props**:
  ```typescript
  export interface SnapshotGalleryViewProps {
    snapshots: SnapshotSummary[]
    workflows: { id: number; name: string }[] | undefined
    loras: Lora[] | undefined
    tagSets: TagSet[] | undefined
    selectedWorkflowId: number | null
    setSelectedWorkflowId: (id: number | null) => void
    selectedLoraId: number | null
    setSelectedLoraId: (id: number | null) => void
    selectedTagSetId: number | null
    setSelectedTagSetId: (id: number | null) => void
    sortOrder: 'desc' | 'asc'
    setSortOrder: (order: 'desc' | 'asc') => void
    snapshotLimit: number
    setSnapshotLimit: React.Dispatch<React.SetStateAction<number>>
    aspectRatioStyle: React.CSSProperties
    multiSelect: UseMultiSelectReturn<SnapshotSummary>
    onOpenPreview: (index: number) => void
    onOpenSpeechModal: (snapshot: SnapshotSummary) => void
    onDeleteSnapshot: (id: number) => void
  }
  ```

### 2.3 `AlbumDetailView.tsx`（アルバム詳細ビュー）
- **変更内容**:
  - `HistoryPage.tsx` に直書きされていた `handleAlbumItemDragEnd` のアルゴリズムを `useAlbumDndOrder` に移譲。
  - Props または内部フックとして `useAlbumDndOrder` を利用し、コードの複雑性を低減。

### 2.4 `HistoryPage/index.tsx`（親コンテナ・ルーティング）
- **責務**:
  - React Query（`workflows`, `loras`, `tagSets`, `snapshots`, `activeBatchJob`, `albums`, `album`）の呼び出しとキャッシュ管理。
  - モーダル群（`HistoryModalPreview`, `AddSnapshotToAlbumModal`, `SpeechBubbleEditorModal`, `BatchSpeechTransformModal`, スナップショット一括削除モーダル、アルバムアイテム削除スコープモーダル）のオーケストレーション。
  - `view === 'snapshots'` のときは `SnapshotGalleryView`、アルバム選択時は `AlbumDetailView`、アルバム一覧時は `AlbumListView` をレンダリング。

## 3. インポート・エクスポート後方互換性
- `frontend/src/pages/HistoryPage.tsx` から `HistoryPage`、`toSafeImageUrl`、`toThumbnailUrl` をエクスポートしているため、新規 `HistoryPage/index.tsx` に配置した上で、`frontend/src/pages/HistoryPage.tsx` はそれを re-export するか、`frontend/src/pages/HistoryPage/index.tsx` からエクスポートしてルートレベルの `HistoryPage.ts(x)` からエイリアスを提供する。
- これにより既存テスト（`HistoryPage.test.tsx`）およびルーティング（`App.tsx`）への破壊的変更を完全に防止する。
