# 設計書 - REQ-099: アルバムページおよびページ遷移のロード高速化と最適化

## 1. 目的と概要
端末を跨いだネットワーク経由での利用時（iPadやAndroidスマホのVivaldiブラウザなど）に、ページ遷移やアルバム表示のロードが著しく低速になる問題を解消します。
主な原因は以下の3点です：
1. 画像アセット（生成された高解像度画像）に対するブラウザキャッシュが効いておらず、画面遷移のたびに再リクエストが発生している。
2. グリッド表示において、画面外にある大量の画像を一括で同期ロードしようとするため、ネットワーク帯域が逼迫している。
3. 履歴リスト（Snapshots）やアルバム内アイテム（Album Items）の全件を一度にDOM描画・画像ロードしている。

本設計では、API/静的ファイルへの強力なキャッシュ制御の追加、フロントエンドでの画像遅延読み込み（Lazy Loading）、およびスクロール位置に応じた自動追加読み込み（無限スクロール / 遅延リストロード）を導入し、体感および実際のロード時間を大幅に高速化します。

## 2. アーキテクチャ設計

### 2.1 バックエンド（FastAPI / Python）

#### 1. 静的アセット（画像）のキャッシュ制御
FastAPIの `StaticFiles` を拡張し、レスポンスヘッダーに `Cache-Control: public, max-age=31536000, immutable` を付与します。
生成されるスナップショット画像はファイル名に UUID が含まれており不変（immutable）であるため、ブラウザに永続キャッシュさせることで、2回目以降の表示速度を極限まで高めます。

### 2.2 フロントエンド（React + TypeScript）

#### 1. 画像のネイティブ Lazy Loading の適用
`HistoryPage.tsx` 内の `<img />` タグ（スナップショット一覧、アルバム一覧のサムネイル、アルバム詳細のグリッド画像）に対し、`loading="lazy"` 属性を付与します。
これにより、ブラウザは画面外にある画像の読み込みを自動的に遅延させ、スクロール等で画面内（または近く）に入った時点でのみネットワークリクエストを走らせます。

#### 2. IntersectionObserver を用いた自動遅延読み込み (Auto Lazy/Infinite Scroll)
スナップショット一覧およびアルバム詳細の画像グリッドにおいて、表示領域の下部に配置した監視ターゲット（センチネル要素）が画面内に入ったことを `IntersectionObserver` で検知し、表示件数の上限（`limit`）を自動的に段階増加（+24件ずつ）させる仕組みを導入します。
これにより、ボタン操作を必要とせず、ユーザーがスクロールするだけでシームレスに次の画像群が表示・ロードされます。

## 3. UI/UX 設計とインタラクション

### 3.1 スケルトンローダー/スピナーの表示
データ取得中（React Query の `isLoading` / `isFetching` 時）に、画面が白くフリーズしたように見えないよう、適切なプレースホルダー（Skeleton Loader）またはローディングスピナーを表示し、ユーザーに即時フィードバックを提供します。

### 3.2 遅延ロード中のプレースホルダー
画像がロードされるまでの間、アスペクト比を維持したグレーのプレースホルダー（または `ImageOff` アイコン）を表示し、画像のロード完了に伴うレイアウトシフト（ガタツキ）を防止します。
