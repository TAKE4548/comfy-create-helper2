# PBI-162: ComfyUI通信プロキシ集約・複数セッション同期・確実な一括Abortの実装

## 1. 概要 (Overview)
本設計は、ComfyUIとの全通信（ジョブ投入、キュー管理、割り込み中断、履歴取得、ノードスキーマキャッシュ）をFastAPIバックエンドにプロキシ集約し、フロントエンドのバイパス配線安全性向上、複数端末（PC・モバイル）間の進捗・履歴自動同期、および確実な一括Abortを実現するためのアーキテクチャ設計である。

---

## 2. アーキテクチャ設計 (Architecture Design)

### 2.1 通信経路の刷新 (Backend-Proxy Architecture)

```
【ブラウザ（PC / モバイル）】
      │
      ├─► [1] DB・プリセット・設定 API ────────► FastAPI バックエンド (:8000)
      │
      ├─► [2] /api/comfy/* (プロキシ＆キャッシュ) ──► FastAPI バックエンド (:8000) ──► ComfyUI (:8188)
      │       - /api/comfy/object_info (キャッシュ)
      │       - /api/comfy/prompt
      │       - /api/comfy/queue, /api/comfy/interrupt
      │       - /api/comfy/history
      │
      └─► [3] WebSocket (プレビュー/リアルタイム進捗) ─► Vite (:5173/comfy/ws) ──► ComfyUI (:8188/ws)
```

---

## 3. バックエンド設計 (Backend Specifications)

### 3.1 `backend/app/routers/comfy.py` エンドポイント拡張

1. **`GET /api/comfy/object_info`**:
   - **キャッシュ機構**: サーバー起動時または初回リクエスト時に `settings.comfy_url/object_info` から全ノードスキーマを取得し、メモリ内にキャッシュ（`_object_info_cache`）。
   - **高速応答**: キャッシュが存在する場合は即座（< 5ms）に応答し、モバイル端末でのダウンロード遅延（数MB〜数十MB）による3秒タイムアウトを根絶。
   - **耐障害性**: ComfyUI未起動時は `{}` を返しエラーで落とさない。

2. **`POST /api/comfy/prompt`**:
   - **リクエスト**: `{ "prompt": {...}, "client_id": string }`
   - **プロキシ処理**: ComfyUIの `POST /prompt` へ転送。
   - **エラーハンドリング**: ComfyUIがバリデーションエラー（400）を返した際、エラーJSON（`node_errors`, `error`）をそのままクライアントへ中継。

3. **`GET /api/comfy/queue`**:
   - ComfyUIの `GET /queue` をプロキシし、`queue_running` / `queue_pending` を返却。

4. **`POST /api/comfy/queue`**:
   - リクエスト: `{ "delete": string[] }` または `{ "clear": true }`
   - ComfyUIの `POST /queue` に転送し、指定キューIDの削除または全キューのパージを実行。

5. **`POST /api/comfy/interrupt`**:
   - ComfyUIの `POST /interrupt` へ転送し、現在実行中のジョブを即座に割り込み中断。

6. **`GET /api/comfy/history`**:
   - ComfyUIの `GET /history` をプロキシし、履歴マップを返却。

7. **`POST /api/comfy/history`**:
   - リクエスト: `{ "delete": string[] }` または `{ "clear": true }`
   - ComfyUIの `POST /history` に転送し履歴を削除。

## 4. フロントエンド設計 (Frontend Specifications)

### 4.1 `frontend/src/api/client.ts`
- `comfyApi` オブジェクトを新設し、バックエンドの `/api/comfy/*` に対する各メソッド（`getObjectInfo`, `queuePrompt`, `getQueue`, `deleteQueue`, `interrupt`, `getHistory`, `deleteHistory`）を定義。

### 4.2 `frontend/src/utils/bypassUtils.ts` (安全なフォールバック)
- `comfyObjectInfo` が万が一取得できていない場合でも、`otherNode.inputs[inputSlot]` を `delete` して必須入力を欠損させない防御的フォールバックを実装。
- `nodeInfo` が存在する場合は、既存通り出力インデックスと入力スロットの型マッチングを行ってバイパス配線を安全に再構築。

### 4.3 `frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts`
- `comfyObjectInfo` の取得を `comfyApi.getObjectInfo()` に切り替え、極端に短いタイムアウト（3秒）や `retry: false` を廃止。
- プリセット初期チェック状態の欠損防止: `checkedPresetsRaw === null`（初回アクセス時）に、デフォルトで全プリセット（または先頭プリセット）を `checked: true` に設定。

### 4.4 `frontend/src/store/useGenerationStore.ts`
1. **確実な一括Abort (`cancelAllJobs`)**:
   - `abortSubmission()` を呼び出し、クライアント内のバッチ投入ループを即座に停止。
   - `filterOwnSession` の値にかかわらず、ComfyUIの待機キューを全削除（`clear: true` または最新サーバーキューの全ID削除）するよう修正。
   - `POST /api/comfy/interrupt` を発行し実行中ジョブを停止。
   - これにより、他セッション投入ジョブを含め、キューに残ったジョブが自動開始されることなく1回の操作で完全停止する。
2. **複数セッション間の履歴同期 (`fetchHistory`)**:
   - WebSocketで `status` イベントを受信した際（キュー残数変化時）、キューが減少したタイミングで `fetchHistory()` を自動トリガー。
   - これにより、別端末（PC）で生成が完了した際、モバイル側でも自動的に最新画像がギャラリーおよび履歴に反映される。
3. **`queuePrompt` の安定化**:
   - バックエンドプロキシ経由（`/api/comfy/prompt`）で送信するため、`comfyUrl` 未初期化による即時 `null` 失敗を根絶。

## 5. 移行・互換性計画 (Migration & Compatibility)
- 既存のDBスキーマ変更は不要（SQLiteテーブルへの影響なし）。
- 既存のViteプロキシ設定はWebSocketプレビュー用（`/comfy/ws`）および直接画像表示用として維持しつつ、API通信はすべて `/api/comfy` 経由に統一。
