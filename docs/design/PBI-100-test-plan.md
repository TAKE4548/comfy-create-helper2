# PBI-100 実行可能テスト計画

## 1. 自動テスト (CLI Verification)
- **コマンド**: `npm run test` または `vitest` によるフロントエンド単体テスト。特に Zustand ストアのアクション（`removeSet` の挙動変更）および Undo/Redo ロジックの検証コードを追加し、それを実行する。
- **期待値**: 追加したテストケース（タブ非表示テスト、Undo/Redo履歴スタックテストなど）の PASS。

## 2. ツール主導監査 (Tool-Driven Audit)
- **コード監査**: `python ${GLOBAL_SCRIPTS}\artifact_linter.py .` を実行し、アーティファクトの構造や形式に不整合がないか確認する。

## 3. ブラウザ検証 (Browser Agent Verification)
- **対象URL**: `http://localhost:5173/` (フロントエンド開発サーバー)
- **検証項目と操作手順**:
  1. **タブの「閉じる」挙動の確認**:
     - 任意のタブの「×」ボタンをクリックする。
     - タブが画面上から消えることを確認する。
     - リロードしてもそのタブが表示されないことを確認する。
     - プロファイル選択ドロップダウンを開き、閉じたプロファイルを選択し、タブが再表示されることを確認する。
  2. **プロファイル未選択状態防止の確認**:
     - すべてのタブを「×」で閉じる。
     - 自動的に新規のデフォルトプロファイル（例: `Default`）が作成されてアクティブ状態になる（パラメータ入力が未選択状態で放置されない）ことを確認する。
  3. **自動セーブの確認**:
     - プロンプト入力やパラメータの値を編集する。
     - 手動保存ボタンを押さずに、画面をリロードする。
     - リロード後も編集した内容が維持されている（自動保存されている）ことを確認する。
  4. **Undo/Redo機能の確認**:
     - パラメータの値を複数回変更する。
     - Undoボタン（↩）をクリックするか、`Ctrl+Z` を入力して、前回の値に戻ることを確認する。
     - Redoボタン（↪）をクリックするか、`Ctrl+Y` を入力して、戻した変更が再度適用されることを確認する。
     - タブAで変更を行い、タブBに切り替え、再度タブAに戻ってUndoができる（履歴がタブごとに独立して残っている）ことを確認する。
- **必須エビデンス**: `.gemini/evidence_req_100_verification.png` などの検証時スクリーンショット。
