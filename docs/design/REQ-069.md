# REQ-069 設計書: LoraStackの編集がワークフローに反映されない（キャラLoRAが変更されない）不具合

## 1. 概要

本不具合は、ComfyUIのカスタムノード `easy loraStack` 等のLoRAスタックノードにおいて、フロントエンドが想定するノード入力名（`lora_name_X`, `lora_wt_X` 等）と、実際のノードが想定する入力名（`lora_X_name`, `lora_X_strength` 等）に不一致があるため、編集結果が画像生成時に無視されてしまう現象を解決するものである。

この不整合を解消するため、フロントエンドのパラメータ初期化およびパラメータインジェクション処理（`useWorkflowParams.ts` / `useGenerateAction.ts`）にて、対象ノードの入力構造を動的に判定し、正しいキーに対して書き込み/読み込みを行うようにデュアルサポート（二重対応）を実装する。

---

## 2. システム設計

### 2-1. パラメータ変換の定義
Zustandストア内およびローカルストレージに保持する `paramValues` のキー構造は現状のままとし、ComfyUI ワークフロー JSON との間で双方向マッピングを行う際に変換を実施する。

| UI/Zustandストア内キー | 標準キー (ComfyUI) | easy loraStackキー (ComfyUI) |
|---|---|---|
| `${role}_lora_count` | `lora_count` | `num_loras` |
| `${role}_lora_name_${i}` | `lora_name_${i}` | `lora_${i}_name` |
| `${role}_lora_wt_${i}` | `lora_wt_${i}` | `lora_${i}_strength` |
| `${role}_model_str_${i}` | `model_str_${i}` | `lora_${i}_model_strength` |
| `${role}_clip_str_${i}` | `clip_str_${i}` | `lora_${i}_clip_strength` |

### 2-2. 判定ロジック
対象ノード (`node.inputs`) が `easy loraStack` 形式であるかどうかの判定：
```typescript
const isEasyLoraStack = 
  node.inputs['num_loras'] !== undefined || 
  node.inputs['lora_1_name'] !== undefined ||
  node.class_type === 'easy loraStack';
```

## 3. 詳細ロジック設計

### 3-1. ワークフロー初期化時 (`useWorkflowParams.ts` の `getInitialParams`)
`easy loraStack` 形式と標準形式の双方からパラメータを読み出せるようにフォールバックロジックを構成する。

1. **LoRA数の取得**:
   - `node.inputs['num_loras']` が存在すれば数値化。
   - なければ `node.inputs['lora_count']` を参照。
   - どちらもなければ、`lora_${i}_name` または `lora_name_${i}` が定義されている最大インデックス `i` (1〜10) をカウント。
2. **各スロットの値の取得 (1〜loraCount)**:
   - **モデル名**: `lora_${i}_name` 優先、なければ `lora_name_${i}`
   - **ウェイト**: `lora_${i}_strength` 優先、なければ `lora_wt_${i}`
   - **モデル強度**: `lora_${i}_model_strength` 優先、なければ `model_str_${i}`
   - **CLIP強度**: `lora_${i}_clip_strength` 優先、なければ `clip_str_${i}`

### 3-2. デフォルト保存時・生成実行時 (`useWorkflowParams.ts` / `useGenerateAction.ts`)
1. **`easy loraStack` 形式の場合**:
   - `num_loras` にカウントを書き込む。
   - `1` から `loraCount` までのスロットに `lora_${i}_name` 等の形式で書き込む。
   - 未使用のスロット（`loraCount + 1` から `10` まで）について、名前を `'None'`、ウェイト・強度を `1.0` に設定して無効化する。
   - 重複を防ぐため、ノードから不要な `lora_name_X` などの標準キーを削除する。
2. **標準形式の場合**:
   - `lora_count` にカウントを書き込む。
   - `1` から `loraCount` までのスロットに `lora_name_${i}` 等の形式で書き込む。
   - `loraCount` を超える余剰な `lora_name_X` 等の標準キーを削除する。
   - 重複を防ぐため、ノードから不要な `lora_X_name` などの `easy loraStack` キーを削除する。

## 4. 変更対象ファイル

| ファイルパス | 変更種別 | 内容 |
|---|---|---|

| `frontend/src/pages/GeneratePage/hooks/useGenerateAction.ts` | MODIFY | `injectParams` にて、上記と同様のデュアルキー対応と未使用スロットのリセット・サニタイズ処理を実装。 |

## 5. 影響範囲とリスク
- **既存の動作への影響**: 判定ロジックが安全にフォールバックされるため、標準形式のLoRA Stackノードを利用しているワークフローへの影響はありません。
- **データ移行**: `localStorage` や データベース内の `paramValues` は既存のキー形式をそのまま維持するため、移行作業は不要です。
