# Architectural Design Document: REQ-321

## 1. Overview & Context

In LoRA Dataset Studio (/dataset-studio), users configure workflow prompt injection nodes via NodeRemapModal.
Currently, when a workflow has unmapped roles (e.g. neither Main_Positive_Prompt nor Negative_Prompt exists in workflow.mappings), changing the node selection and clicking "マッピングを保存" fails to persist the new mapping.
Furthermore, after workflowsApi.update succeeds, the modal creates an incomplete local state without re-fetching the updated Workflow entity (including generated mapping IDs and master details) from workflowsApi.get, causing desynchronization with the parent component (MatrixGenerationStep).

This design specifies the architectural solution to ensure deterministic mapping persistence, SSoT re-synchronization, and immediate visual badge updates.

---

## 2. Root Cause & Architectural Breakdown

### 2.1 Missing Master Resolution for Unmapped Roles
- In NodeRemapModal.tsx, mapping creation relied on positiveMapping?.master_id and negativeMapping?.master_id.
- If the current workflow has no existing mappings matching the target roles, positiveMapping and negativeMapping are undefined.
- In handleSave, the conditional if (!posHandled && positiveMapping) evaluated to false, omitting the new mapping from the payload sent to workflowsApi.update.

### 2.2 SSoT Desynchronization & Optimistic Incompletion
- Upon save completion, NodeRemapModal synthesizes an optimistic updatedWf by mapping over existingMappings.
- Newly added mappings are completely absent from this locally synthesized object.
- onSaved passed this incomplete object to MatrixGenerationStep, leaving currentWorkflow.mappings empty or stale.
- workflowsApi.get(workflow.id) was not called to retrieve the canonical WorkflowRead model from the backend.

---

## 3. Detailed Component Design

### 3.1 NodeRemapModal Enhancement (NodeRemapModal.tsx)

#### 3.1.1 Fetching & Resolving Mapping Masters
- NodeRemapModal will retrieve available mapping masters via mappingMastersApi.list().
- Identify the target master for Positive and Negative roles using strict matching first:
  - posMaster: matching canonical role `m.role === 'Main_Positive_Prompt'` (fallback: `m.role.toLowerCase().includes('positive')`)
  - negMaster: matching canonical role `m.role === 'Negative_Prompt'` (fallback: `m.role.toLowerCase().includes('negative')`)
- Priority for master resolution:
  1. positiveMapping?.master_id (if existing mapping exists)
  2. posMaster?.id (from mapping masters table)

#### 3.1.2 Deterministic Payload Construction in handleSave
- Validate that selected node IDs are non-empty.
- Build updatedMappingsList:
  - Preserve any existing mappings that do not correspond to Positive or Negative prompts.
  - If existing mapping matches Positive or Negative role/master, update its node_id to selected node.
  - If Positive role was not present in existing mappings and posMaster was resolved, append { master_id: posMaster.id, node_id: selectedPositiveNodeId }.
  - If Negative role was not present in existing mappings and negMaster was resolved, append { master_id: negMaster.id, node_id: selectedNegativeNodeId }.
- Execute await workflowsApi.update(workflow.id, { mappings: updatedMappingsList }).

#### 3.1.3 Authoritative SSoT Re-fetch
- After workflowsApi.update resolves:
  Fetch fresh workflow from backend via workflowsApi.get(workflow.id).
  Pass fresh authoritative workflow to onSaved(freshWorkflow) and close modal.
  If get() fails, display an error banner to notify the user rather than passing an incomplete locally synthesized object (preventing state corruption).

### 3.2 MatrixGenerationStep Synchronization (MatrixGenerationStep.tsx)

- MatrixGenerationStep receives the authoritative updatedWorkflow in onSaved:
  - setCurrentWorkflow(updatedWorkflow)
  - setWorkflows((prev) => prev.map((w) => (w.id === updatedWorkflow.id ? updatedWorkflow : w)))
- Because currentWorkflow is updated with complete mappings, the node badges immediately re-render:
  - positive-node-badge: #<pos.node_id> <title>
  - negative-node-badge: #<neg.node_id> <title>
- Subsequent ComfyUI batch generation consumes the updated mappings seamlessly.

## 4. Error Handling & Red Teaming

| Scenario | Behavior | Expected Outcome |
| :--- | :--- | :--- |
| Mapping Masters API Failure | Network error or 500 when fetching mapping masters | Modal displays clear error banner; save button disabled or error caught gracefully. |
| Workflow Update Failure | Server-side validation error or DB lock | Modal remains open, error state displayed to user, no state mutation in parent. |
| Partial Mapping | User re-maps only Positive prompt, Negative node left as-is | Existing Negative mapping is preserved intact; only target node is altered. |
| Initial Empty Mappings | Workflow has 0 mappings configured | Both Positive and Negative mappings are newly inserted with appropriate master IDs. |
