# PBI-166: ジョブ管理におけるキュー削除と全ジョブ中断の機能・UIボタン分離および中断状態同期の堅牢化

## 1. 概要 (Overview)

本設計は、画像生成時のジョブ管理モーダル（`JobManagementModal`）および状態管理ストア（`useGenerationStore`）において、
1. **「待機キューのみクリア（現在生成中の1枚は最後まで継続）」**
2. **「すべて中断（実行中も含めて全ジョブを即座に完全停止）」**

の2つのユースケースに応じた処理とUIボタンを明確に分離し、ComfyUIの中断処理（`/interrupt`）およびWebSocketイベントとの状態同期の堅牢化を行う。また、操作完了時にジョブ管理モーダルを自動的に閉じる仕様を定める。

---

## 2. 課題とアーキテクチャ方針 (Problem & Architectural Strategy)

### 2.1 現状の課題
1. **単一ボタンによる機能の混同**:
   - 現在の `JobManagementModal` のフッターには「一括キャンセル」ボタンが1つしかなく、待機キューのみを空にしたい場合でも `/interrupt` を呼ぼうとする（あるいは全中断したいのに生成中が停止しない）という曖昧さが発生していた。
2. **ComfyUIの協調型割り込みと状態不整合**:
   - ComfyUIの `/interrupt` はノード内チェックポイントで停止する仕様のため、フロントエンド側が即時リセットしても、直後に届く WebSocket イベント（`progress`, `executing`, `executed`）によってフロントエンド状態が勝手に「生成中」に復帰してしまう。
3. **WebSocket `execution_interrupted` イベントの未ハンドリング**:
   - ComfyUIから届く中断完了イベント（`execution_interrupted`）がストアのメッセージハンドラに登録されておらず、中断処理の確定状態が管理できていなかった。
4. **操作完了後のモーダル維持**:
   - 一括処理完了後もモーダルが開いたままとなり、ユーザーが手動で「閉じる」を押す必要があった。

### 2.2 アーキテクチャ方針

```
【ユーザー操作: ジョブ管理モーダル】
   ├── [キューのみクリア] ──► store.clearPendingQueue()
   │                               ├── comfyApi.deleteQueue({ clear: true }) (待機キューのみ削除)
   │                               ├── 実行中ジョブ (queue_running) はそのまま継続・完了
   │                               └── 完了後にモーダルを自動クローズ (onClose())
   │
   └── [すべて中断]       ──► store.cancelAllJobs() / abortAllJobs()
                                   ├── store.abortSubmission() (投入ループの中断)
                                   ├── comfyApi.deleteQueue({ clear: true }) (待機キュー全クリア)
                                   ├── comfyApi.interrupt() (ComfyUI実行中断)
                                   ├── comfyApi.deleteHistory({ delete: allIds })
                                   ├── 中断フラグ・ステートリセット
                                   ├── ComfyUI WebSocket (execution_interrupted) のハンドリング
                                   └── 完了後にモーダルを自動クローズ (onClose())
```

## 3. 詳細設計仕様 (Detailed Specifications)

### 3.1 状態管理ストアの改修 (`frontend/src/store/useGenerationStore.ts`)

1. **新アクション: `clearPendingQueue(): Promise<void>`**:
   - 待機キューのみを削除する専用アクション。
   - 処理内容:
     ```ts
     clearPendingQueue: async (): Promise<void> => {
       get().abortSubmission()
       try {
         const pendingIds = get().queuePending.map((j) => j[1])
         await comfyApi.deleteQueue({ clear: true })
         if (pendingIds.length > 0) {
           await comfyApi.deleteHistory({ delete: pendingIds })
         }
         
         // activeBatch の待機中ジョブのみ failed / 削除に更新
         const activeBatch = get().activeBatch
         if (activeBatch) {
           const updatedBatch = activeBatch.filter(
             (job) => job.status === 'generating' || job.status === 'completed'
           )
           set({ activeBatch: updatedBatch.length > 0 ? updatedBatch : null })
         }
         await get().fetchQueue()
       } catch (e) {
         console.error('Failed to clear pending queue:', e)
       }
     }
     ```

2. **改善: `cancelAllJobs(): Promise<void>`**:
   - 実行中ジョブも含めて確実に完全中断するアクション。
   - 処理内容:
     - 投入 AbortController の停止 (`abortSubmission()`)
     - 待機キューのクリア (`comfyApi.deleteQueue({ clear: true })`)
     - ComfyUI への割り込みリクエスト (`comfyApi.interrupt()`)
     - 履歴削除 (`comfyApi.deleteHistory({ delete: allIds })`)
     - 中断ターゲット ID の記録（またはタイムスタンプ管理）により、直後の不要な `progress` / `executing` イベントによる再活性化をガード。
     - ステート初期化 (`isGenerating: false`, `activeBatch: null`, `currentPromptId: null` など)

3. **WebSocket メッセージハンドラへの `execution_interrupted` 追加**:
   - ComfyUI の `execution_interrupted` イベントを受信した際の確実な状態確定:
     ```ts
     case 'execution_interrupted': {
       const promptId = data.prompt_id as string
       set({
         isGenerating: false,
         progress: null,
         currentPromptId: null,
         activeClientId: null,
         currentNode: null,
         nodeProgress: null,
         activeBatch: null,
       })
       localStorage.removeItem(LS_KEYS.CURRENT_PROMPT_ID)
       get().fetchQueue()
       window.dispatchEvent(new CustomEvent('comfy-job-event', { detail: { type: 'execution_interrupted', promptId } }))
       break
     }
     ```

### 3.2 ジョブ管理モーダルのUI改修 (`frontend/src/components/JobManagementModal.tsx`)

1. **フッター領域のボタン構成と自動クローズ**:
   - **「キューのみクリア」ボタン**:
     - 表示条件: `visiblePending.length > 0`
     - スタイル: `bg-amber-500/10 hover:bg-amber-500/20 border border-amber-500/30 text-amber-400 hover:text-amber-300`
     - アイコン: `Eraser` または `ListX`
     - 確認ダイアログ: `待機中のキュー（${visiblePending.length}件）をクリアしますか？\n※現在生成中の1枚は中断せず最後まで生成されます。`
     - アクション: `await clearPendingQueue(); onClose();`
   - **「すべて中断」ボタン**:
     - 表示条件: `totalJobsCount > 0`（実行中または待機中が存在する場合）
     - スタイル: `bg-red-500/15 hover:bg-red-500/25 border border-red-500/30 text-red-400 hover:text-red-300`
     - アイコン: `Square` または `Trash2`
     - 確認ダイアログ: `実行中の生成を中断し、待機中のすべてのジョブを削除しますか？`
     - アクション: `await cancelAllJobs(); onClose();`
   - **「閉じる」ボタン**: モーダルクローズ (`onClose()`)

2. **リスト内個別操作のツールチップ・視覚表現統一**:
   - 実行中ジョブ（Active Job）のゴミ箱ボタン: `title="中断（生成を停止）"`
   - 待機中ジョブ（Pending Job）のゴミ箱ボタン: `title="キューから削除"`

## 5. 受け入れ基準 (Acceptance Criteria)

- **AC-1**: ジョブ管理モーダルのフッターに「キューのみクリア」と「すべて中断」の2つのボタンが独立して表示されること（待機キューが存在するときに「キューのみクリア」が活性化）。
- **AC-2**: 「キューのみクリア」を実行した場合、待機中ジョブ（`queue_pending`）のみが削除され、実行中のジョブ（`queue_running`）は中断されずに生成が完了すること。
- **AC-3**: 「すべて中断」を実行した場合、待機中ジョブがクリアされ、かつ実行中ジョブに `/interrupt` が発行されて即座に中断されること。
- **AC-4**: 中断実行後、ComfyUIからの残余 WebSocket イベントによってフロントエンドが勝手に「生成中」ステートに戻らないこと。
- **AC-5**: 各アクション実行前に明確な確認メッセージが表示され、ユーザーが誤操作なく意図した操作を選択できること。
- **AC-6**: 「キューのみクリア」または「すべて中断」の完了後、ジョブ管理モーダルが自動的に閉じること。
