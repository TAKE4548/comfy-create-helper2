# Design Document: REQ-100 生成画面におけるプロファイルの自動保存とタブ管理の改善およびUndo/Redo機能の実装

## 1. 概要
本ドキュメントは、生成画面におけるプロファイル（WorkflowPreset）の保存方式の改善、タブ管理の挙動修正、およびプロファイルごとのUndo/Redo機能の設計を定義します。これにより、編集内容の消失防止、タブ操作の一貫性確保、および直感的な操作性の向上を実現します。

## 2. 設計方針と変更内容

### 2-1. タブ管理とプロファイル操作の分離 (AC-1)
* **表示状態の管理:**
  * 「開いているタブ（プロファイルID）」を管理するため、Zustandストアおよび `localStorage` 上に `prompt-surgeon-open-presets-{workflowId}`（以下 `openPresetIds`）というキーで数値型の配列を保持します。
  * `presets`（DBから読み込んだ全プリセット）のうち、`openPresetIds` に含まれるものだけを `sets`（画面に表示するタブ）としてマッピングします。
* **タブを閉じる (×):**
  * `removeSet(presetId)` アクションの挙動を変更し、DBからの削除（DELETEリクエスト）は行わず、単に `openPresetIds` から当該IDを除外し、Zustandストアおよび `localStorage` を更新します。
* **プロファイル削除 (DB削除):**
  * プリセットマネージャー（Preset Manager）等のプロファイル管理モーダルにおいてのみ、実削除（DELETE `/api/workflow-presets/{id}`）を可能にします。
* **プロファイルの再表示:**
  * 生成画面上部に配置されている「プロファイル選択リスト（ドロップダウン等）」において、閉じられたものも含めてDB上のすべてのプロファイルを表示します。
  * 閉じられているプロファイルが選択された場合、それを `openPresetIds` に追加し、アクティブ状態とすることで、タブとして再表示させます。

### 2-2. プロファイル未選択状態での編集防止 (AC-2)
* **アクティブプロファイルの強制:**
  * ワークフローロード時、あるいは `presets` 取得時の同期処理において、`activeSetId` が無効（null、または `openPresetIds` に含まれない等）である場合、以下の優先順位で自動的にアクティブ状態を設定します。
    1. `openPresetIds` の最初のID
    2. DB上の `presets` の最初のID
  * もしDB上にプリセットが1つも存在しない場合、デフォルト設定から新規プリセット（例: `Default`）を即座に自動生成してDBに登録し、それを `activeSetId` に割り当てます。
  * これにより、ユーザーは常に何らかのアクティブなプロファイルを選択した状態でしか編集できないよう制御します。

### 2-3. 自動セーブの徹底 (AC-3)
* **手動上書きの廃止:**
  * ユーザーのパラメータ編集操作（パラメータ値、適用アセット、Batch Size、Seed、Seed Mode等）は、すべてアクティブなプロファイルに対する自動セーブ（debounceを挟んだDB更新）の対象とし、手動上書き保存用のアクションはUIから廃止または自動セーブを促す挙動に変更します。

### 2-4. タブ（プロファイル）ごとのUndo/Redo機能 (AC-4)
* **履歴の永続化 (sessionStorageの活用):**
  * 各プロファイルIDごとに独立した履歴スタックを管理するオブジェクトを、ブラウザの `sessionStorage`（キー: `prompt-surgeon-history-{presetId}`）にJSON文字列として保存します。これにより、ページのリロードを挟んでもUndo/Redo履歴がクリアされずに維持されます。
    ```typescript
    interface HistoryState {
      paramValues: Record<string, string>
      appliedAssets: Record<string, AppliedAsset[]>
      batchSize: number
      seedMode: 'random' | 'fixed'
      seed: number
    }
    
    // プロファイルごとの履歴（sessionStorageに永続化されるオブジェクトの型定義）
    interface HistoryStack {
      past: HistoryState[]
      future: HistoryState[]
    }
    ```
  * タブを切り替えて戻ってきた際、およびページをリロードした際にも、この `sessionStorage` から履歴オブジェクトが復元されるため、切り替え前・リロード前の状態に対するUndo/Redoが可能です。
  * パラメータ変更完了後（デバウンス時など）に、新たな状態を `past` にスタックし、`sessionStorage` に保存します（直前状態と同じ場合はスキップ）。
  * UI上にUndo/Redoを実行できる矢印ボタンを配置し、またキーボードショートカット（Ctrl+Z / Ctrl+Y）もサポートします。


### 2-5. モバイルレイアウト・デバイス間同期 (AC-5)
* モバイルレイアウト（`/mobile`）でもデスクトップ同様の状態管理ロジック（Zustandストア）を利用するため、自動セーブ、未選択状態の防止、Undo/Redo機能が同一に機能します。
* 編集内容は即座にバックエンドDBへ自動セーブされるため、端末を切り替えても最新のパラメータ状態がDBからロードされ、無意識のデバイス間同期が実現されます。

## 3. UI/UXの変更点
* **デスクトップ画面:**
  * タブ右側の「×」アイコンをクリックした際、「プリセットは削除されず、タブが閉じられます」といったツールチップまたは静的なニュアンスを表現。
  * ワークフロー選択やプロファイル選択エリア付近に、Undo/Redo実行用のボタン（↩ / ↪）を追加配置。
* **モバイル画面:**
  * デスクトップと同様、タブ選択肢およびUndo/Redo操作を行える簡易ボタンを配置し、操作の一貫性を保持します。

## 4. 影響範囲とリスク
* 自動セーブの頻度上昇によるデータベース書き込み負荷の可能性。デバウンス時間（現状1000ms）を適切に調整し、不要な短時間での連続リクエストを抑制します。
* Undo/Redoによる一時的な画面表示とDB状態のズレ。履歴からの復元処理においても自動セーブが走るように統一します。
