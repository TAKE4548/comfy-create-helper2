# PBI-REQ-115 実行可能テスト計画

## 1. 静的検証 & ビルドテスト (Linter & Build Verification)
- **ビルド確認**:
  - コマンド: `npm run build` (ディレクトリ: `frontend/`)
  - 期待値: TypeScriptのコンパイルおよびViteビルドがエラーなしで成功すること。
- **リンター確認**:
  - コマンド: `npm run lint` (ディレクトリ: `frontend/`)
  - 期待値: ESLintルール違反がないこと。

## 2. 自動テスト (Vitest Verification)
- **テスト実行**:
  - コマンド: `npm run test` (ディレクトリ: `frontend/`)
  - 期待値: 既存のテストスイートがすべてパスすること。

## 3. ブラウザ検証 (Manual Browser Verification)
- **検証手順**:
  1. アプリケーション（フロントエンドとバックエンド）を起動する。
  2. ブラウザで生成画面 (`http://localhost:5173/`) を開く。
  3. パラメータパネル内、またはLoRA Stack設定からLoRALoader（LoRA選択ドロップダウン）をクリックして開く。
  4. ドロップダウン上部に固定ヘッダ（検索入力、ベースモデルフィルタ、カテゴリフィルタ）が表示されていることを確認する。
  5. 以下の操作を行い、リストが動的に絞り込まれることを確認する：
     - **フリーワード検索**: `description` または `file_path` や `model_name` に含まれる文字列を入力し、対応するLoRAのみに絞り込まれること。
     - **ベースモデルフィルタ**: 特定のベースモデル（例: SD1.5, SDXLなど）を選択した際、対象のベースモデルIDを持つLoRAに絞り込まれること。
     - **カテゴリフィルタ**: 特定のカテゴリを選択した際、対象のカテゴリに登録されているLoRAに絞り込まれること。
  6. ドロップダウンリストをスクロールした際、検索・フィルタヘッダが最上部に固定され、スクロールに追従しないことを確認する。
  7. 絞り込まれたリストからLoRAを選択した際、正しくドロップダウンの値が更新され、設定値が反映されることを確認する。
