# REQ-207 設計仕様書: グローバル状態管理（useGenerationStore）の責務分離・スライス化およびWebSocketライフサイクルの疎結合化

## 1. 概要
本仕様書は、1,700行を超えるモノリシックなグローバル状態ストア `frontend/src/store/useGenerationStore.ts` を、Zustand のスライスパターン（Slices Pattern）およびカプセル化されたWebSocketサービスクラスへ分離・再設計するアーキテクチャを定義する。

## 2. アーキテクチャ設計

### 2.2 WebSocket ライフサイクルのカプセル化 (`services/comfyWebSocketService.ts`)
モジュールレベルのグローバル変数（`let ws`, `let isInitializing`, `let reconnectTimer`, `activeSubmissionPromise`, `activeFetchHistoryPromise`）を排除し、専用の `ComfyWebSocketService` クラスインスタンスへカプセル化する。

```typescript
export interface ComfyWebSocketCallbacks {
  onOpen: () => void;
  onClose: () => void;
  onError: () => void;
  onBlobMessage: (blob: Blob) => void;
  onJsonMessage: (type: string, data: Record<string, unknown>) => void;
}

export class ComfyWebSocketService {
  private ws: WebSocket | null = null;
  private reconnectTimer: ReturnType<typeof setTimeout> | null = null;
  private isInitializing: boolean = false;
  private activeSubmissionPromise: Promise<string | null> | null = null;
  private activeFetchHistoryPromise: Promise<void> | null = null;
  private comfyUrl: string | null = null;

  public connect(url: string, clientId: string, callbacks: ComfyWebSocketCallbacks): void;
  public disconnect(): void;
  public resetForTesting(): void;
  public getComfyUrl(): string | null;
  public setComfyUrl(url: string): void;
  public getActiveSubmissionPromise(): Promise<string | null> | null;
  public setActiveSubmissionPromise(p: Promise<string | null> | null): void;
  public getActiveFetchHistoryPromise(): Promise<void> | null;
  public setActiveFetchHistoryPromise(p: Promise<void> | null): void;
}
export const comfyWsService = new ComfyWebSocketService();
```

### 2.3 Zustand スライスパターン設計
各スライスは `StateCreator<GenerationState, [], [], SliceInterface>` を用いて定義され、他スライスの状態やアクションへ `get()` / `set()` を通じてアクセス可能とする。

1. **`createConnectionSlice`**:
   - WebSocketメッセージ受信時の状態ディスパッチ（`progress`, `executing`, `executed`, `execution_complete`, `execution_error`, `execution_interrupted`）
   - `previewImage` の blob URL 生成および破棄（`URL.revokeObjectURL`）
   - `reconcileState` による起動時/再接続時のジョブ復旧

2. **`createJobQueueSlice`**:
   - `queuePrompt`: AbortSignal 制御、Prompt ID 永続化、メタデータ保存・古いキャッシュ間引き
   - `cancelJob` / `clearPendingQueue` / `cancelAllJobs`: 楽観的更新、ComfyUI API 呼び出し、履歴クリーンアップ
   - `fetchHistory` / `fetchQueue`: 自セッション / 他セッションの画像分離とキュー監視

3. **`createMultiSetSlice`**:
   - `sets`, `activeSetId`, `openPresetIds` の LocalStorage 同期
   - `addAppliedAsset`, `removeAppliedAsset`, `toggleAppliedAsset` とプロンプト文字列（`addAssetToPrompt`, `removeAssetFromPrompt`）の連動更新
   - プリセット読み込み・一括チェック・名前変更・削除

4. **`createBypassSlice` & `createParamSyncSlice`**:
   - `bypassProfilesCache` / `paramSyncGroupsCache` の管理と API CRUD 操作
   - 単一の真実の源泉（SSoT）としてのキャッシュ更新

### 2.4 後方互換性の担保 (`useGenerationStore.ts`)
既存コンポーネントおよびテストスイートに対する破壊的変更をゼロにするため、以下を `useGenerationStore.ts` から完全に re-export する:
- 型定義 (`GenerationState`, `GenerationSet`, `AppliedAsset`, `BatchJob`, `ComfyProgress`, `NodeProgress` 等)
- ヘルパー関数 (`resolveNodeTitle`, `addAssetToPrompt`, `removeAssetFromPrompt`)
- テスト用関数 (`_resetWebSocketForTesting` -> `comfyWsService.resetForTesting()` を呼び出す)

## 3. 非機能要件 & 品質基準
- **ファイルサイズ上限**: 各スライスファイルは 300行以内 に収めること（AC-1）。
- **テスト網羅率**: 既存の448テスト全件が修正なし、または同等以上のテストで 100% 通過すること（AC-4）。
- **メモリ安全性**: WebSocket接続や blob URL が再初期化時・アンマウント時に確実に破棄されること（AC-2）。
