# REQ-364: FE環境切替（開発/本番）・ライフサイクル制御（起動/停止）およびヘッダーステータス稼働モニタ表示 設計書

## 1. 概要と目的

Vite 開発サーバーと FastAPI 本番ホスティングの稼働環境を一目で識別可能にし、ブラウザアドレスバーの手動書き換えを行わずに、現在のパス・クエリ・ハッシュを100%保持したままワンクリックで環境間を相互移動できるクイック導線を提供する。
さらに、以下の2つの高度要件を充足する設計とする:
1. **動的ポート追従**:
   将来的なポート変更（例: 5173 -> 5174, 8000 -> 8080 等）が発生した場合でも、固定ポート表示の矛盾を防ぎ、`window.location` や環境変数から実態に動的追従する。
2. **開発サーバーのライフサイクル制御（起動/停止要求）**:
   単なるページ遷移だけでなく、本番環境閲覧時に開発サーバーが停止していれば「▶ 開発起動」ボタンで ServerManager (`/api/action`) へ起動要求を発行可能とし、開発環境閲覧時には「■ 開発停止」または「本番へ戻り停止」で不要になった開発サーバーを安全にシャットダウンできる運用導線を提供する。

## 2. アーキテクチャとSeam Map設計 [MUST [W-DD-SEAM]]

### 2-1. Seam Map

| レイヤー | 区分 | 境界・責務 | 実装/テスト方針 |
|---|---|---|---|
| **SystemStatusBadge** | Integrated (実コード) | ステータス集約、動的DEVタグ表示、稼働モニタPopover展開、起動/停止UIトリガー | 実Reactコンポーネントとして実行・検証 |
| **systemManagerApi** | Integrated (実コード) | ServerManager APIクライアント（`ManagedServiceName` に `'frontend'` / `'fe'` を追加） | 型定義およびAPI呼び出しインターフェース |
| **HeaderDropdown** | Integrated (実コード) | Popoverの配置計算、外部クリック閉止、ESCキー押下閉止 | 実Portal/Popoverとして実行・検証 |
| **buildSwitchUrl** | Integrated (実コード) | パス・クエリ・ハッシュを安全に合成する純粋関数 | 単体テスト・境界値テストで完全検証 |
| **ServerManager API (I/O)** | Severed (外部I/O切断) | `/api/action` へのプロセス制御HTTP POST | `systemManagerApi.action` のモック/スパイで切断 |
| **ブラウザURL遷移** | Severed (外部I/O切断) | `window.location.assign` による実際のページ再読込 | ナビゲーション境界関数で切断しスパイ検証 |

### 2-2. モック境界方針
- コンポーネント内部のビジネスロジックやポート計算ロジック（`resolveSystemStatus`, `buildSwitchUrl`）のモンキーパッチは厳格に禁止。
- 画面遷移は `navigateTo(url: string)` または `onNavigate` コールバック/スパイにより transport 境界でのみ切断する。
- ライフサイクルアクションは `systemManagerApi.action` をスパイし、`{ status: 'ok', action: 'start' }` 等のレスポンスをシミュレートする。
- 状態値およびポート設定は `SystemStatusBadgeProps`（`isDev`, `currentPort`, `backendPort`, `comfyPort`, `managerPort` 等）経由で純粋に注入・制御可能とする。

### 2-3. Property-Based / Table-Driven Testing 決定
- `buildSwitchUrl` は任意の pathname, search, hash, targetPort を受け取るため、複雑なクエリ（複数パラメータ、日本語エンコード、特殊文字、ハッシュフラグメント）を網羅するテーブル駆動テストおよびプロパティテストを `SystemStatusBadge.test.tsx` に配置する。
- ポート番号の動的追従性（5173/8000以外の任意ポート 5174/8080/8288/8999等）においても表示と遷移先が完全に一致することを検証する。

### 2-4. フォールトインジェクション方針
- 開発サーバー起動要求エラー（HTTP 500 / タイムアウト）: エラーハンドリングとローディング解除の検証。
- Manager サービス停止時（`managerAvailable: false`）: 起動/停止ボタンが非活性となり、Manager 行が `offline (:${managerPort})` と表示されること。
- ComfyUI サービス停止時（`comfy.running: false`）: ComfyUI 行が `stopped (:${comfyPort})` と表示されること。

## 3. コンポーネント設計とUI Archetypes

### 3-1. UI Archetype 分類
- **SystemStatusBadge トリガー**: `Archetype 3: Forms & Controls`
  - クリック可能なバッジボタン。キーボードアクセシビリティ（Enter / Space）、`aria-expanded`, `aria-haspopup="dialog"` を付与。
- **システム稼働モニタ Popover**: `Archetype 1: Modals & Overlays`
  - `HeaderDropdown` を用いたアンカー配置ドロップダウン。外側クリックおよび ESC キー押下での閉止に対応。
- **Frontend環境切替 & ライフサイクル制御ボタン**: `Archetype 2: Tabs / Chips / Grids` + `Archetype 3: Forms & Controls`
  - Frontend 行ラベル直横にインライン配置されるコンパクトなピルボタン群（[▶ 開発起動] / [⇄ 開発用] / [⇄ 本番用] / [■ 停止]）。
- **共通ヘッダー統合 (PageHeader)**: `Archetype 4: Shell & Page Layout`
  - デスクトップ表示（md以上）では `DEV :${port}` タグバッジをインライン表示し、モバイル表示（md未満）ではコンパクトドット（dot variant）としてタグを抑制。

### 3-2. サージカルUI制約
- **Hit-Slop**: タッチ操作時のミスタッチ防止および 44x44px ターゲット確保（モバイルでは `touch-manipulation`）。
- **Scroll**: Popover コンテナに `overscroll-contain` を付与し、背面のスクロール連鎖を遮断。
- **Chips/Pill**: `shrink-0 whitespace-nowrap` によりピルボタンやステータスラベルの意図せぬ折り返しを防止。
- **Truncation/Alignment**: 行内の右側ステータス列に `ml-auto shrink-0 font-mono text-[11px]` を指定し、ラベルの長さやボタン数に関わらず右端のドット＋テキストを全行で垂直整列。
- **Action State**: アクション実行中は `animate-spin` 付きのスピナーまたは `disabled` 属性で二重クリックを防止。

## 4. 詳細仕様

### 4-1. DEV環境判定および動的DEVインジケータータグ表示（AC-1, AC-2）
- **環境判定ロジック**:
  - `isDevMode = props.isDev ?? (typeof import.meta !== 'undefined' && import.meta.env?.DEV)`
- **現在ポートの解決**:
  - `resolvedCurrentPort = props.currentPort ?? (typeof window !== 'undefined' ? (window.location.port || (window.location.protocol === 'https:' ? '443' : '80')) : '5173')`
- **表示条件**:
  - `isDevMode === true` かつ `variant !== 'dot'`（デスクトップの `slim` / `full` バリアント）。
- **スタイル & 表示文言**:
  - クラス: `inline-flex shrink-0 items-center rounded border border-amber-500/40 bg-amber-500/10 px-1.5 py-0.5 text-[10px] font-mono font-medium text-amber-400 select-none`
  - テキスト: `DEV :${resolvedCurrentPort}`（例: `DEV :5173`, `DEV :5174`）
- **本番モード時（isDevMode === false）**:
  - タグバッジは一切描画されない（DOMに存在しない）。

### 4-2. システム稼働モニタ Popover の構造化と動的ポート整列（AC-3, AC-4）
- 開閉トリガー: ステータスバッジのクリックで開閉トグル。ESCキーまたは外側クリックで閉止。
- 各サービスの動的ポート解決:
  - **Frontend**: ポート `resolvedCurrentPort`、状態 `${props.manager?.fe.running ? 'running' : 'stopped'} (:${resolvedCurrentPort})`
  - **FastAPI (BE)**: ポート `props.backendPort ?? (!isDevMode ? resolvedCurrentPort : (import.meta.env?.VITE_PROD_PORT || import.meta.env?.VITE_BACKEND_PORT || '8000'))`、状態 `${beStatus} (:${resolvedBackendPort})`
  - **ComfyUI**: ポート `props.comfyPort ?? (import.meta.env?.VITE_COMFY_PORT || '8188')`、状態 `${comfyStatus} (:${resolvedComfyPort})`
  - **Manager**: ポート `props.managerPort ?? (import.meta.env?.VITE_MANAGER_PORT || '8899')`、状態 `${managerStatus} (:${resolvedManagerPort})`
- 整列仕様: 全サービス行の右端ステータス要素を `ml-auto flex items-center gap-1.5 font-mono text-[11px]` で統一し、垂直整列を保持。

### 4-3. Frontend行の環境切替 & ライフサイクル制御ボタン（AC-3, AC-5, AC-6, ライフサイクル）
- **本番アクセス時（!isDevMode）**:
  - 開発サーバー停止時（`props.manager?.fe.running === false`）:
    - 表示ボタン: `▶ 開発起動`（`systemManagerApi.action('start', 'frontend')` を呼び出し）
    - スタイル: `border-amber-500/40 bg-amber-500/10 text-amber-300 hover:bg-amber-500/20`
    - 起動処理中: スピナー表示 + 非活性化
  - 開発サーバー稼働時（`props.manager?.fe.running === true`）:
    - 表示ボタン: `⇄ 開発用`（押下で現在のパス・クエリ・ハッシュを保持し開発ポートへ遷移）
- **開発アクセス時（isDevMode）**:
  - 表示ボタン 1: `⇄ 本番用`（押下で本番ポートへURLを保持して遷移）
  - 表示ボタン 2: `■ 停止して本番へ`（または `■ 停止`）:
    - 押下で `systemManagerApi.action('stop', 'frontend')` を呼び出し、本番ポートへ安全に遷移。

### 4-4. URL遷移生成ロジック (`buildSwitchUrl`)
```typescript
export interface LocationParts {
  protocol: string
  hostname: string
  pathname: string
  search: string
  hash: string
}

export function buildSwitchUrl(
  targetPort: string,
  loc: LocationParts = typeof window !== 'undefined'
    ? window.location
    : { protocol: 'http:', hostname: 'localhost', pathname: '/', search: '', hash: '' }
): string {
  const portPart = targetPort ? `:${targetPort}` : ''
  return `${loc.protocol}//${loc.hostname}${portPart}${loc.pathname}${loc.search}${loc.hash}`
}
```
