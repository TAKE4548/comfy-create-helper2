# REQ-407 設計書: Gate 3 の E2E 実行手順を、手順書どおりに実行して成立するよう直す

## 1. 概要と背景

### 1.1 現状の課題と原因分析 (5 Whys)
リポジトリ内の主要手順書（`.agents/context.md`、`docs/specs/SPEC_TEST_ARCHITECTURE.md` §6、`README.md`）において、Gate 3（実ブラウザ E2E）の実行手順として `cd frontend; npx playwright test` が案内されていた。
しかし、本プロジェクトの `frontend/playwright.config.ts` には `webServer` 定義が存在せず、`http://localhost:5173` への接続を前提としている。
そのため、開発者や検証エージェントが手順書に書かれたコマンドをそのままクリーンな環境（dev server 未起動）で実行すると、全 340 件中 338 件のテストが `net::ERR_CONNECTION_REFUSED`（接続拒否）により大量失敗し、環境起因の失敗かテスト自体の不具合かの切り分けに混乱を生じさせていた。

1. **なぜ失敗するか**: 手順書のコマンド（`npx playwright test`）は dev server（ポート 5173）が起動済みであることを前提としているが、その前提条件が手順書に明記されていないため。
2. **なぜ前提が必要か**: `playwright.config.ts` に `webServer` 自動起動設定がなく、Playwright 単体では Vite dev server を起動しないため。
3. **なぜ前提が抜けたか**: 初期（REQ-356 時点）の E2E テスト（`stickyHeader.spec.ts`、2件）は `page.route` によるインライン HTML 注入で完結しており dev server 不要で動作していたが、その後の機能拡張（REQ-346, REQ-365 等）で Vite dev server を読み込む本番コンポーネントテストが約 340 件まで拡充された際、手順書の記述が更新されなかったため。
4. **正式な Gate 3 はどう実行されているか**: `.agents/verification.json` に定義された正式な Gate 3 コマンドは `backend\.venv\Scripts\python.exe scripts/run_e2e.py` である。このラッパースクリプトが Vite dev server（ポート 5173）を自律起動し、ポート待機後に Playwright を実行し、完了後にサーバープロセスを確実にクリーンアップする設計となっている。
5. **根本原因**: 正式な Gate 3 コマンド（`scripts/run_e2e.py`）と、直接実行時（`npx playwright test`）に必要な前提条件（ポート 5173 事前起動）が、手順書間で一貫して整理・記載されていなかった。

### 1.2 本改修の解決方針 (AC-1〜AC-7 の達成)
本 PBI は文書のみの改修（chore・document）として実施し、以下の 3 文書の記述を相互に矛盾なく是正する：
- **正式な実行方法の一本化と自律成立性明記 (AC-1, AC-2, AC-4)**:
  `.agents/context.md`、`docs/specs/SPEC_TEST_ARCHITECTURE.md` §6、`README.md` の 3 文書において、正式な Gate 3 実行コマンドとして `backend\.venv\Scripts\python scripts/run_e2e.py`（または `python scripts/run_e2e.py`）を明記する。これにより、dev server 未起動の環境でもスクリプト経由で自律的に E2E が成立することを明記する。
- **直接実行時の前提条件と失敗理由の併記 (AC-2, AC-3, AC-5)**:
  `npx playwright test` を直接実行するコマンドを掲載する箇所には、必ず「正式な Gate 3 ではないこと」「Vite dev server（ポート 5173）の事前起動が必須であること」「未起動時は接続拒否（`net::ERR_CONNECTION_REFUSED`）で失敗すること」を同一箇所に併記する。
- **現行文書の全件網羅調査と誤記根絶 (AC-5)**:
  現行文書全域を `npx playwright test` で検索し、見つかったすべての箇所（上記 3 文書）を是正対象とすることで、リポジトリ内に誤解を招く単独の直接実行コマンドが残らないようにする。
- **検証対象・収集件数・設定ファイルの維持 (AC-6, AC-7)**:
  Playwright の設定ファイル（`playwright.config.ts`）、`scripts/run_e2e.py`、`.agents/verification.json`、およびテストコードは一切変更しない。本番バンドル専用 E2E（`playwright.prod.config.ts`）は既定 Gate 3 の対象外のままとし、テスト収集件数（340 件 / 8 ファイル）を完全に維持する。

### 1.3 着手前 Baseline エビデンス (Gate 3 収集件数の事前測定)
本 PBI の着手前における Gate 3 の状態を以下の通り事前に実測し、不変条件の基準値として記録する：
- **実行コマンド**: `cd frontend; npx playwright test --list`
- **実測結果**: `Total: 340 tests in 8 files`（8 ファイル: `generateMobileGallery.spec.ts`, `generatePresetTabs.spec.ts`, `headerHoverCard.spec.ts`, `headerMenuOverlay.spec.ts`, `headerMenuRoutes.spec.ts`, `presetManagementModal.spec.ts`, `settingsResponsive.spec.ts`, `stickyHeader.spec.ts`）
- **本番専用 E2E の状態**: `frontend/e2e/prod/`（`playwright.prod.config.ts` 対象）は `playwright.config.ts` の `testIgnore: ['**/prod/**']` により既定 Gate 3 から除外されており、収集件数に含まれないことを確認済み。

## 4. 文書間の整合性と用語定義

### 4.1 用語定義
- **正式な Gate 3 (Official Gate 3)**:
  `scripts/run_e2e.py`（または `backend\.venv\Scripts\python scripts/run_e2e.py`）を用いた E2E 実行。Vite dev server（ポート 5173）のライフサイクル管理（事前起動チェック・自律起動・ポート開放待機・テスト実行・自動終了）を内包し、`.agents/verification.json` に登録された正規コマンド。
- **直接実行 (Direct Execution)**:
  `cd frontend; npx playwright test` による Playwright CLI の直接呼出。Vite dev server の自律起動を行わないため、実行前にポート 5173 で dev server が稼働していることが必須条件となる。
- **本番バンドル専用 E2E (Prod Bundle E2E)**:
  `frontend/e2e/prod/` 配下の E2E テスト群。`playwright.prod.config.ts` で実行され、ビルド成果物（`frontend/dist/`）を静的配信して検証する。既定の Gate 3（`playwright.config.ts`）では `testIgnore: ['**/prod/**']` により対象外として維持される。

### 4.2 優先順位・参照関係
1. 機械検証・自動実行の正本: `.agents/verification.json`
2. テスト設計・規約の正本: `docs/specs/SPEC_TEST_ARCHITECTURE.md`
3. エージェント環境設定・実行コマンド参照: `.agents/context.md`
4. 人間向けリポジトリ開発ガイド: `README.md`

改修後は上記 4 つのすべての定義において「Gate 3 の正式実行 = `scripts/run_e2e.py`」で完全一致し、矛盾が 0 件となる。
