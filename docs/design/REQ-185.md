# REQ-185: 履歴・アルバム画面の表示・操作性向上 詳細設計書

## 1. 概要と背景
履歴（Snapshots）およびアルバム（Albums）画面において、以下の課題が存在していました：
1. **サムネイルバッジの配置不一致 & ホバー依存**: スナップショット一覧とアルバム詳細でバッジ（セリフ編集、ダウンロード、削除）の並びや配置方法が異なり、またホバー表示前提であるためタッチデバイス等で不可視のまま操作せざるを得ない。
2. **アルバムソート機能の制限**: ソート基準（カスタム順 / 登録日時）とソート方向（昇順 / 降順）が直交しておらず、カスタム順での昇順・降順切り替えなどができない。
3. **レスポンシブ崩れ・溢れ**: 画面幅が狭い場合、フィルタ・ソートバーや複数選択ツールバーの要素が画面外にはみ出して操作不能になる。
4. **履歴複数選択時の削除導線の不足**: 履歴一覧で複数選択時に一括ダウンロードやアルバム追加はあるが一括削除ができず、また安全のための2段階確認が必要。
5. **アルバム削除時の操作粒度**: アルバムから削除する際、「アルバムの登録解除のみ」と「元画像の実体削除」の選択肢がなく、ユーザーの意図に応じた削除ができない。

本設計では、これらの課題を解消し、表示の一貫性、タッチ操作性、レスポンシブ対応、柔軟なソートおよび安全なデータ管理を実現します。

---

## 2. アーキテクチャ・UI設計詳細

### 2.1 サムネイルバッジ統一＆常時表示化
- **対象**: `frontend/src/pages/HistoryPage.tsx`
- **変更内容**:
  - スナップショット一覧およびアルバム詳細一覧のサムネイル右上に統一された flex コンテナを配置：
    `className="absolute top-2 right-2 flex items-center gap-1 z-20"`
  - ボタン順序を統一：
    1. セリフ編集 (`MessageSquarePlus`): `id="snap-speech-edit-${id}"` / `id="item-speech-edit-${id}"`
    2. ダウンロード (`Download`): `id="snap-download-${id}"` / `id="item-download-${id}"`
    3. 削除 (`Trash2`): `id="snap-delete-${id}"` / `id="item-delete-btn-${id}"`
  - スタイル統一：
    `p-1.5 rounded-md bg-black/60 hover:bg-black/80 text-zinc-300 transition-colors shadow-sm`
  - 常時表示化：
    `opacity-0 group-hover:opacity-100` を撤廃し、常時表示（`opacity-100`）とする。複数選択モード時は選択チェックボックスのみ表示し、バッジ群は非表示。

### 2.2 アルバムソート（基準・方向の分離）
- **対象**: `frontend/src/pages/HistoryPage.tsx`
- **状態管理**:
  - `albumSortCriterion`: `'custom' | 'date'` (カスタム順 / 登録日時)
  - `albumSortDirection`: `'asc' | 'desc'` (昇順 / 降順)
- **ソートロジック**:
  - `albumSortCriterion === 'custom'`:
    - `asc`: `a.sequence_order - b.sequence_order`
    - `desc`: `b.sequence_order - a.sequence_order`
  - `albumSortCriterion === 'date'`:
    - `asc`: `dateA - dateB`
    - `desc`: `dateB - dateA`
- **DnD並び替え**:
  - `albumSortCriterion === 'custom' && albumSortDirection === 'asc'` の場合に有効化。
- **UI表示**:
  - 基準選択 (`カスタム順` / `登録順`) と 方向選択 (`昇順` / `降順`) を独立したボタングループとして提供。

### 2.3 レスポンシブ対応・折り返し制御
- **対象**:
  - `frontend/src/components/MultiSelectToolbar.tsx`
  - `frontend/src/pages/HistoryPage.tsx`
- **変更内容**:
  - `MultiSelectToolbar`: `flex-wrap gap-2.5 px-3 sm:px-6 py-2 sm:py-3` を適用し、選択情報・操作ボタン・終了ボタンが狭小画面でも縦に自然に折り返して画面内に収まるようにする。
  - スナップショットのフィルタバー: `flex-wrap gap-2 px-3 sm:px-5 py-2.5` を適用し、ワークフロー/LoRA/タグセット選択およびソートボタンが画面幅に応じて折り返す。
  - アルバム詳細・一覧のヘッダー: `flex-wrap justify-between gap-3` を適用。

### 2.4 履歴画面の複数選択一括削除＆2段階操作
- **対象**: `frontend/src/pages/HistoryPage.tsx`
- **変更内容**:
  - 履歴スナップショット複数選択時の `MultiSelectToolbar` actions に「一括削除」ボタン（赤系スタイル）を追加。
  - クリック時に削除確認モーダルを表示（ステップ1）。
  - モーダル上で「選択した ○ 件のスナップショットを完全に削除しますか？」と警告し、確認確定ボタンをクリックすることで一括削除を実行（ステップ2）。
  - `snapshotsApi.delete(id)` を実行後、クエリキャッシュを無効化し複数選択モードを終了。

### 2.5 アルバム画面削除時のスコープ選択モーダル
- **対象**: `frontend/src/pages/HistoryPage.tsx`
- **変更内容**:
  - アルバム内での単一アイテム削除および複数選択一括削除のトリガー時、削除スコープ選択モーダルを表示。
  - 選択肢：
    1. **「アルバムから削除」**: アルバム内の登録解除のみ（`albumsApi.deleteItems`）。元画像・履歴は保持。
    2. **「元画像ごと削除」**: アルバムから解除し、かつ元画像（Snapshot実体）も削除（`albumsApi.deleteItems` + `snapshotsApi.delete`）。
    3. **「キャンセル」**: モーダルを閉じる。
