# REQ-386 詳細設計書: 生成中ステップ進捗（個別プログレスバー）の停止および次画像完了までのプレビュー表示遅延の解消

## 1. 概要と目的

画像生成中の個別プログレスバー停止問題、および次画像完了までプレビュー表示が遅延する問題を解消する。

### 1.1 解決する課題
1. **個別プログレスバーの停止 (AC-1)**:
   - ComfyUI `progress` 受信時に `prompt_id` が欠落し、高頻度のHTTP照会でイベントが脱落していた。
   - `data.get("node")` の型不一致（数値型）や、サンプラーノードへの紐付け脱落が存在した。
   - フロントエンドで `displayNodePercentage` がストアの `nodeProgress` にフォールバックできず0%で停止していた。
2. **プレビュー表示の遅延 (AC-2, AC-3)**:
   - `connectionSlice.ts` で直前ジョブの中間プレビューが残存し、完了原画が覆い隠されていた。
   - `DesktopLayout.tsx` で履歴クエリ反映までの時間差に旧画像（先頭画像）が表示されていた。

### 1.2 目的と解決方針 (AC-1, AC-2, AC-3)
1. **個別進捗のリアルタイム同期 (AC-1)**:
   - バックエンドで `prompt_id`/`node_id` の型を正規化し、アクティブジョブへの紐付けとサンプラー自動補完を行う。
   - フロントエンドで `nodeProgress` への安全な二重フォールバックを行い、リアルタイムに進捗を表示する。
2. **完了時プレビュー即時表示 (AC-2)**:
   - 直前ジョブ完了時に中間プレビューを即時解除し、最新完了画像を先頭に合成して1秒以内に自動追従表示する。
3. **バッチ完了時の100%整合 (AC-3)**:
   - 全ジョブ完了時に全体・個別プログレスバーを双方100%に揃え、最新生成画像のプレビューを維持する。

## 2. アーキテクチャと詳細設計

### 2-1. バックエンド `GenerationService.on_event` の progress 配信強化
- **ファイル**: `backend/app/services/generation_service.py`
- **対象**: `GenerationService.on_event`
- **改修内容**:
  1. **prompt_id の確実な解決とフォールバック**:
     `prompt_id` が `event` や `data` から取得できない場合、直ちに HTTP `/queue` を呼ぶ前に、リポジトリ内のアクティブ実行中ジョブ（`status == "running"` かつ `prompt_id` が存在するジョブ）が単一であれば、その `prompt_id` にバインドする。これにより高頻度の progress パケットでHTTPラウンドトリップによる遅延・脱落を防止する。
  2. **node_id の型正規化**:
     `raw_node = data.get("node")` に対し、`node_id = str(raw_node) if raw_node is not None else None` として数値型IDを吸収する。
  3. **サンプラーノードへの自動フォールバック**:
     `node_id is None` かつ `job.node is None` の progress イベントにおいて、`self._frozen_graphs.get(job.job_id, {})` から `KSampler` / `KSamplerAdvanced` などのサンプラーノードを探索し、存在すればそのノードIDを自動補完する（見つからない場合は `"sampler"` にフォールバック）。
  4. **スナップショット配信**:
     `_node_progress` により算出された `NodeView` を `repository.transition(job.job_id, status, **fields)` で保存し、`_publish_snapshot()` を発行する。

### 2-2. フロントエンド `connectionSlice.ts` の完了時プレビュー解除
- **ファイル**: `frontend/src/store/slices/connectionSlice.ts`
- **対象**: `applyGenerationSnapshot`
- **改修内容**:
  1. `autoFollowImage !== null`（画像生成完了契機）の場合、無条件に `previewImage = null` とし、直前ジョブの中間プレビューフレームを完全に破棄して完了原画（`selectedImg`）を表示可能にする。
  2. `runningJob?.preview_url` が存在する場合のみ新しいプレビューフレームを設定し、存在しない場合は `autoFollowImage` が発生した時点で前フレームの持ち越し（`previousPreview`）を停止する。

### 2-3. フロントエンド `useGenerateDisplayState.ts` の自動追従確実化
- **ファイル**: `frontend/src/pages/GeneratePage/hooks/useGenerateDisplayState.ts`
- **対象**: `handleJobEvent`, モーダル自動追従 effect
- **改修内容**:
  1. `pendingAutoFollowUrlRef.current` は、`sortedDisplayImages.indexOf(targetUrl) !== -1` で実際にリスト内に存在することを確認したタイミングで初めて `null` に消費する。描画タイミングのズレで新画像が即時リストに見つからない場合でも、次レンダリングで確実に追従できるようにする。

### 2-4. フロントエンド `DesktopLayout.tsx` & `MobileLayout.tsx` の表示統合
- **ファイル**:
  - `frontend/src/pages/GeneratePage/components/DesktopLayout.tsx`
  - `frontend/src/pages/GeneratePage/components/MobileLayout.tsx`
- **改修内容**:
  1. **個別プログレスバーの安全なフォールバック**:
     `managedNodePercentage`（`normalRunningJob?.node` の進捗率）が正しく取得できている場合はそれを優先し、取得できない場合（`normalRunningJob` が null、または `max <= 0`）はストアの `nodeProgress?.percentage` または `progress?.percentage` へ安全にフォールバックする。
     実行中ノード名（`displayNodeName`）も同様に `normalRunningJob?.node?.name` → `nodeProgress?.nodeName` → `currentNode?.name` → `'準備中...'` の順でフォールバックする。
  2. **メインプレビューの即時表示担保**:
     `DesktopLayout.tsx` において、`selectedImg` が `currentDisplayImages` の先頭に未反映の場合、一時的に合成した `effectiveDisplayImages`（`[selectedImg, ...currentDisplayImages]`）を供給する。
     これによりクエリ反映ラグを解消し、完了した瞬間に `selectedImg` をプレビュー領域へ1秒以内（即時）に表示する。
  3. **完了時の100%表示維持**:
     全ジョブ完了時、全体・個別プログレスが完了状態（100%）を反映し、最新画像が表示された状態を維持する。

## 3. Seam Map (設計義務 [MUST [W-DD-SEAM]], AC-1, AC-2, AC-3)

本節は AC-1（進捗同期）、AC-2（プレビュー即時表示）、AC-3（完了時表示）を検証するためのテスト境界を定義する。

1. **Integrated (本物のコード)**:
   - `backend/app/services/generation_service.py`
   - `backend/app/services/generation_repository.py`
   - `frontend/src/store/slices/connectionSlice.ts`
   - `frontend/src/pages/GeneratePage/hooks/useGenerateDisplayState.ts`
   - `frontend/src/pages/GeneratePage/components/DesktopLayout.tsx`
   - `frontend/src/pages/GeneratePage/components/MobileLayout.tsx`
2. **Severed (外部I/Oのみ・トランスポート層)**:
   - ComfyUI HTTP API (`/queue`, `/history`, `/prompt`) — `httpx.AsyncClient` トランスポートモック
   - ComfyUI WebSocket (`/ws`) — `_FakeSocket` による進捗イベントストリーム注入
   - ブラウザ WebSocket (`/api/ws`) — `wsHelpers` によるスナップショット受信検証
3. **Mock Level**:
   - 内部ビジネスロジック・ヘルパー関数の monkey-patch は禁止。
   - バックエンド: `FakeBridge` またはモックトランスポート経由でイベントを注入。
   - フロントエンド: `applyGenerationSnapshot` または `ws.message` を通じてスナップショットを注入。
4. **PBT Decision**:
   - 進捗パーセンテージ計算（`Math.min(100, Math.max(0, ...))`）および `runningFraction` は 0〜100% の範囲外（NaN、負値、無限大、max=0のゼロ除算）に対して安全である必要があり、境界値テストおよび範囲アサーションを明記する。
5. **Fault Injection**:
   - ComfyUIから `progress` イベント受信時に `prompt_id` が存在しないケース。
   - `node` が数値型 `10` や `None` で送られるケース。
   - `value > max` や `max == 0` の異常進捗データが送られたケース。
   - 画像生成完了直後に後続ジョブが未初期化（preview_url: null）の状態で snapshot が届くケース。

## 4. UI Archetype 分類 & 制約設計 (AC-1, AC-2, AC-3 UI Invariants)

本節は AC-1（進捗バー視覚維持）、AC-2（プレビュー領域タッチ操作）、AC-3（完了時表示安定）のUI不変条件を定義する。

### 4-1. コンポーネント分類
- `DesktopLayout.tsx` / `MobileLayout.tsx`: `Archetype 4: Shell & Page Layout`（ステータスヘッダー、進捗バー領域、メインペイン配置）
- `GenerateParallelPreview.tsx`: `Archetype 2: Tabs / Chips / Grids`（プレビュー画像表示・カルーセル・ページング）

### 4-2. Surgical Constraints
- **Universal Safety**:
  - 最低フォントサイズ 11px（`text-[11px]`、`text-[10px]` は補助表示のみ・アクセシビリティ考慮）
  - raw `vh` の使用禁止（`h-full` または `dvh` を使用）
  - 二重パディングの排除
- **Truncation**:
  - ノード名およびステータス文字列表示部: `min-w-0 flex-1 truncate`
- **Hit-Slop & Gesture**:
  - プレビュー操作ボタン・ナビゲーション: `before:absolute before:-inset-2`
  - モバイルタッチ: `touch-action: pan-y / manipulation`
- **Backend Zero-Contamination Guardrail**:
  - `subsystem: backend` のタスク（REQ-386-T1）には UI CSS、Tailwind クラス、タッチ制約を一切混入させない。
