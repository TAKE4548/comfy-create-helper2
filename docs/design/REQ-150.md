# REQ-150 詳細設計書: プロファイル新規作成時のコピー元選択に基づく名称自動補完（サフィックス連番付与）

## 1. 概要 (Overview)
プロファイル新規作成（Add Set）時、既存のプロファイルをコピー元として指定した場合に、新しいプロファイルの名前を「コピー元のベース名 + サフィックス連番（最大値+1）」で自動補完する機能を実装する。

### 課題と背景
- 同一シーンの差分生成やバリエーション展開を行う際、既存のプロファイルを複製して微修正を加えるユースケースが多い。
- 従来はコピー元を選択してもプロファイル名欄は「Set N」のまま、または手動でベース名をすべて入力し直す必要があった。
- コピー元を選択したタイミングで、同名グループの中で最大の数値サフィックスを算出して +1 した名前をプレフィルすることで、手動入力の手間を大幅に削減する。

### 基本方針
- **名称の解析と連番生成ユーティリティ (`frontend/src/utils/profileUtils.ts`)**:
  - コピー元名称から末尾の区切り文字（スペース、アンダースコア、ハイフンなど）および数値を正規表現で分解し、ベース名・区切り文字・現在の数値を抽出。
  - 既存の全プロファイル名リストを走査し、同一ベース名を持つプロファイルのサフィックス数値の最大値 `maxNum` を特定。
  - `maxNum + 1` を付与した新しいプロファイル名を生成する。
- **UIとの連携 (`DesktopLayout.tsx`, `MobileLayout.tsx`)**:
  - 新規作成モーダル（`showCopyModal`）内の「コピー元 (ベース設定)」セレクトボックスの `onChange` イベントにおいて、選択されたプロファイル名をもとに `generateNextProfileName` を呼び出し、プロファイル名入力状態（`newSetName`）を自動更新する。
  - 「ワークフローのデフォルト設定 (`default`)」が選択された場合は、「Set N」または Set グループの連番名にフォールバックする。
  - 自動補完後もユーザーは自由に入力欄を編集でき、作成実行時は入力欄の文字列がそのまま正式名称として使用される。

## 3. 詳細ロジック設計 (Detailed Logic)

### 3.1 名称パーサー & 連番生成アルゴリズム (`profileUtils.ts`)

```typescript
export interface ParsedProfileName {
  baseName: string;
  separator: string;
  num: number | null;
}

export function parseProfileName(name: string): ParsedProfileName {
  const trimmed = name.trim();
  const match = trimmed.match(/^(.*?)([\s_-]*)(\d+)$/);
  if (match) {
    const baseName = match[1].trim();
    if (!baseName) {
      return { baseName: trimmed, separator: ' ', num: null };
    }
    const separator = match[2] || '';
    const num = parseInt(match[3], 10);
    return { baseName, separator, num };
  }
  return { baseName: trimmed, separator: ' ', num: null };
}

export function generateNextProfileName(sourceName: string, existingNames: string[]): string {
  if (!sourceName || !sourceName.trim()) {
    return 'Set 1';
  }

  const { baseName, separator, num } = parseProfileName(sourceName);
  const sep = separator !== '' ? separator : ' ';

  const escapedBase = baseName.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
  const pattern = new RegExp(`^${escapedBase}(?:[\\s_-]*(\\d+))?$`, 'i');

  let maxNum = num ?? 1;

  for (const name of existingNames) {
    const m = name.trim().match(pattern);
    if (m) {
      if (m[1]) {
        const n = parseInt(m[1], 10);
        if (!isNaN(n) && n > maxNum) {
          maxNum = n;
        }
      }
    }
  }

  const nextNum = maxNum + 1;
  return `${baseName}${sep}${nextNum}`;
}
```

### 3.2 振る舞い例
| コピー元プロファイル名 | 既存プロファイル一覧 | 自動生成される名称 | 備考 |
|---|---|---|---|
| `SceneA` | `['SceneA']` | `SceneA 2` | 元を1とみなし2を生成 |
| `SceneA 1` | `['SceneA 1']` | `SceneA 2` | 最大値1 + 1 |
| `SceneA 1` | `['SceneA 1', 'SceneA 3']` | `SceneA 4` | 同名グループ内最大値3 + 1 |
| `Scene_1` | `['Scene_1', 'Scene_2']` | `Scene_3` | アンダースコア区切りを維持 |
| `Scene-01` | `['Scene-01']` | `Scene-2` | ハイフン区切りを維持 |
| `Char (Hero)` | `['Char (Hero)']` | `Char (Hero) 2` | 特殊文字入り |
| `default` | `['Set 1', 'Set 2']` | `Set 3` | デフォルトフォールバック |

## 4. トレードオフとリスクの開示 (Trade-offs & Risks)
- **手動編集後の再選択挙動**: ユーザーがプロファイル名を手動でカスタム入力した後にコピー元を変更した場合、名称は新しく選択されたコピー元に応じた連番名で上書きされます。これは「コピー元を選んだ時点での自動補完」という仕様に沿った標準的な挙動ですが、再選択時は上書きされる点に注意が必要です。
- **区切り文字の統一性**: 数値のみで区切り文字がない名称（例: `Scene1`）の場合、元のフォーマットに従い `Scene2` を生成します。区切り文字が存在しない場合はスペースなし、スペースがある場合はスペース付きでサフィックスを付与します。
