# REQ-053 設計書: 全画面表示のクラッシュ修正およびモバイル表示時のレイアウト修正

## 1. 概要

1. `HistoryModalPreview.tsx` における `getParamValue` 関数内の Temporal Dead Zone (TDZ) 参照エラー（`ReferenceError`）を修正する。これにより、履歴スナップショット画像をクリックして拡大プレビューを開いた際、React がクラッシュして画面がフリーズ（真っ黒）になる問題を解決する。
2. `AppShell.tsx` において、モバイル等のレスポンシブ表示（画面幅 1024px 未満）時にボトムメニューバーがメインコンテンツと重なる問題を解決するため、下部に適切なパディングを追加する。

## 2. 変更対象

| ファイル | 変更種別 | 内容 |
|---|---|---|
| `frontend/src/components/HistoryModalPreview.tsx` | MODIFY | `getParamValue` 関数内のコールバック関数の戻り値を修正し、TDZ 参照を排除する。 |
| `frontend/src/components/layout/AppShell.tsx` | MODIFY | メインコンテンツ (`main`) コンテナにモバイル表示時用のボトムパディング (`pb-20 lg:pb-0` 等) を追加する。 |

**バックエンド変更**: なし  
**API 変更**: なし  
**SSoT 文書更新**: なし（UI/レイアウト不具合修正のみ）

## 3. 変更前後の比較

### 3-1. HistoryModalPreview.tsx (全画面表示クラッシュ)

#### Before (バグのあるコード)
```tsx
  const getParamValue = (keys: string[], excludeKeys: string[] = []): string => {
    if (!snapshot?.params) return ''
    const matchKey = Object.keys(snapshot.params).find((key) => {
      const k = key.toLowerCase()
      const matchesInclude = keys.some((target) => k.includes(target.toLowerCase()))
      const matchesExclude = excludeKeys.some((target) => k.includes(target.toLowerCase()))
      return matchKey ? String(snapshot.params[matchKey]) : '' // ⚠️ find内での未宣言/未初期化変数 `matchKey` の参照
    })
    return matchKey ? String(snapshot.params[matchKey]) : ''
  }
```

#### After (修正コード案)
```tsx
  const getParamValue = (keys: string[], excludeKeys: string[] = []): string => {
    if (!snapshot?.params) return ''
    const matchKey = Object.keys(snapshot.params).find((key) => {
      const k = key.toLowerCase()
      const matchesInclude = keys.some((target) => k.includes(target.toLowerCase()))
      const matchesExclude = excludeKeys.some((target) => k.includes(target.toLowerCase()))
      return matchesInclude && !matchesExclude // ✓ 条件合致時の真偽値を返す
    })
    return matchKey ? String(snapshot.params[matchKey]) : ''
  }
```

- **変更点の説明**: `find` コールバックは探索条件を満たすかどうかを表す `boolean` を返す必要があります。修正前は条件に関わらず未初期化の `matchKey` に応じて文字列を返そうとしたためエラーが発生していました。正しく条件分岐の論理式 `matchesInclude && !matchesExclude` を返すように変更します。

---

### 3-2. AppShell.tsx (モバイルボトムパディング)

#### Before
```tsx
      {/* Main Content */}
      <main className="flex-1 flex flex-col min-w-0 overflow-hidden">
        <Outlet />
      </main>
```

#### After (修正コード案)
```tsx
      {/* Main Content */}
      <main className="flex-1 flex flex-col min-w-0 overflow-hidden pb-16 lg:pb-0">
        <Outlet />
      </main>
```
※ モバイルボトムナビゲーションの高さは約 `56px`〜`64px` のため、`pb-16` (64px) を設定します。安全のため `pb-20` (80px) または iOS の safe area を考慮したパディング (`pb-[calc(4rem+env(safe-area-inset-bottom))]`) にするのも有効です。

- **変更点の説明**: デスクトップ表示（`lg`以上）ではサイドバーが横に表示されるため `pb-0` とし、モバイル表示（`lg`未満）では下部メニューがオーバーレイするため `pb-16` 以上のパディングを付与してメインコンテンツの最下部が隠れないようにします。

## 4. リスク評価

| リスク | 評価 | 対策 |
|---|---|---|
| `getParamValue` の挙動変化 | 低 | 本来のロジックに合わせた修正であり、表示されるメタデータの妥当性に影響はありません。 |
| モバイルパディングによるレイアウト変化 | 低 | デスクトップ表示（`lg`）への影響を排除しており、モバイルでのみスクロール余白ができる正当なレイアウト修正です。 |
