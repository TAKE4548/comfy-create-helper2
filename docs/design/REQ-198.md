# 設計書: REQ-198 プリセット・プロンプト編集のオートセーブおよび一括編集における状態同期・OCC競合解消（過去帰り・未発生防止）

## 1. 概要 (Overview)
本設計は、生成画面（`GeneratePage`）でのプロンプト・パラメータ編集時のオートセーブ失敗（409 Conflict による巻き戻り）およびプリセット管理モーダルからの一括編集（`ProfileBulkEditModal`）連続実行時の未反映・データ破壊（過去帰り）を根本解消するための設計である。

保存成功時に返却される最新のタイムスタンプ（`updated_at`）をフロントエンドの手元（`presetUpdatedAtRef` および React Query キャッシュ）へ即座に更新・反映し、送信直前のタイミングで常に最新のベースタイムスタンプを参照して送信するアーキテクチャを採用する。

---

## 2. 課題とメカニズム分析 (Root Cause & Failure Mechanics)

### (1) オートセーブ時の OCC タイムスタンプ遅延競合 (Issue 1)
- **現状の挙動**:
  1. ユーザーがプロンプトを入力 -> デバウンス 1000ms 後に `updatePresetMutation.mutate` が発火。
  2. バックエンドでプリセットが更新され、DB 上の `updated_at` が新しい時刻（$T_2$）になる。
  3. `updatePresetMutation.onSuccess` は `qc.invalidateQueries` を呼ぶのみで、返却された最新タイムスタンプを手元に即座に反映しない。
  4. ユーザーが連続して文字入力を行い、再取得完了前に次のオートセーブが発火すると、フロントエンドの `presets` に残る古いタイムスタンプ（$T_1$）が `base_updated_at` として送信される。
  5. バックエンドは $T_2 > T_1$ を検知して `409 Conflict` を返却する。
  6. フロントエンドの `onError` は 409 を受けて再取得を呼ぶが、`lastSavedStateRef` はすでに更新済みとみなされているため、DB との不整合が発生し、ブラウザリロード（`isFirstSync`）時に古い DB 値へ巻き戻る。

### (2) 一括編集の連続実行におけるクロージャ参照・クエリ非同期の競合 (Issue 2)
- **現状の挙動**:
  1. `handleBulkEditApply` がコンポーネントスコープの古い `presets` 変数を参照して演算を実行。
  2. 連続して一括編集モーダルを操作した場合、React Query の再取得が完了する前に前回の編集前の古い `presets` をベースに更新処理が実行され、1回目の編集結果が上書き消失する。
  3. アクティブプリセットに対して一括編集が行われた際、`lastSavedStateRef` や最新タイムスタンプが同期されないため、直後にオートセーブが旧タイムスタンプで余計に発火して 409 競合を引き起こす。

### (3) タイムスタンプ精度（マイクロ秒 vs ミリ秒）の不一致による偽 409
- バックエンド（Python/SQLite）の `datetime.utcnow()` がマイクロ秒精度である一方、フロントエンド（JavaScript）の `toISOString()` はミリ秒精度でシリアライズされるため、同一タイムスタンプであってもマイクロ秒の差異によって $T_{\text{db}} > T_{\text{base}}$ と判定されるリスクが存在する。

## 3. 詳細設計 (Detailed Architecture)

### 3-1. フロントエンド: 保存成功後のタイムスタンプ即時更新と送信直前取得 (`useGeneratePageState.ts`)

#### ① タイムスタンプ管理用 Ref（`presetUpdatedAtRef`）の導入
- 各プリセットの最新 `updated_at` を保持する Ref を用意し、クエリ初期取得時および保存成功時に即時同期する。

```typescript
const presetUpdatedAtRef = useRef<Record<number, string>>({})

// 初回およびクエリ更新時に Ref を同期
useEffect(() => {
  if (presets) {
    presets.forEach(p => {
      if (p.updated_at) {
        presetUpdatedAtRef.current[p.id] = p.updated_at
      }
    })
  }
}, [presets])
```

#### ② `updatePresetMutation` の `onSuccess` での即時更新
- API レスポンスで返却された `updatedPreset.updated_at` を `presetUpdatedAtRef` および React Query キャッシュへ即座に反映する。

```typescript
const updatePresetMutation = useMutation({
  mutationFn: (args: ...) => workflowPresetsApi.update(args.id, args),
  onSuccess: (updatedPreset) => {
    if (updatedPreset?.id) {
      // 1. タイムスタンプ参照を即時更新（次回の送信で即座に利用可能）
      presetUpdatedAtRef.current[updatedPreset.id] = updatedPreset.updated_at
      // 2. React Query キャッシュを同期更新
      qc.setQueryData<WorkflowPreset[]>(['workflow-presets', selectedWorkflowId], (old) => {
        if (!old) return old
        return old.map((p) => (p.id === updatedPreset.id ? updatedPreset : p))
      })
    }
    qc.invalidateQueries({ queryKey: ['workflow-presets', selectedWorkflowId] })
  },
  onError: (err: any, variables) => {
    // 409 Conflict 時は lastSavedStateRef をクリアして再同期可能にする
    if (err?.message?.includes('409') || err?.status === 409) {
      delete lastSavedStateRef.current[variables.id]
      qc.invalidateQueries({ queryKey: ['workflow-presets', selectedWorkflowId] })
    }
  }
})
```

#### ③ オートセーブ送信直前のタイムスタンプ取得
- デバウンスタイマー発火時（送信の直前の瞬間）に `presetUpdatedAtRef.current[activePreset.id]` から最新タイムスタンプを取得して送信する。

```typescript
const timer = setTimeout(() => {
  const currentLastSaved = lastSavedStateRef.current[activeSetId]
  if (currentLastSaved && isStateEqual(currentLastSaved, currentState)) {
    return
  }

  // ★ 送信直前の瞬間に Ref から最新のベースタイムスタンプを取得
  const latestBaseUpdatedAt = presetUpdatedAtRef.current[activePreset.id] || activePreset.updated_at

  if (currentLastSaved) {
    const hist = getHistory(activeSetId)
    hist.past.push(currentLastSaved)
    hist.future = []
    saveHistory(activeSetId, hist)
  }
  lastSavedStateRef.current[activeSetId] = currentState

  updatePresetMutation.mutate({
    id: activePreset.id,
    name: activePreset.name,
    param_values: currentState.paramValues,
    applied_assets: currentState.appliedAssets,
    batch_size: currentState.batchSize,
    seed_mode: currentState.seedMode,
    seed: currentState.seed,
    base_updated_at: latestBaseUpdatedAt,
  })
}, 1000)
```

#### ④ プリセット一括編集（`handleBulkEditApply`）のステート同期
- `presets` state の代わりに `qc.getQueryData<WorkflowPreset[]>(['workflow-presets', selectedWorkflowId]) || presets` から最新のプリセットリストを取得して演算を行う。
- `Promise.all` による各プリセットの更新完了後、返却された全更新プリセットのタイムスタンプを `presetUpdatedAtRef` に格納し、`qc.setQueryData` で一括同期する。
- アクティブなプリセットが含まれていた場合、Zustand ストア、`lastSavedStateRef`、`presetUpdatedAtRef` を最新状態に同期する。

### 3-2. バックエンド: タイムスタンプ比較の許容誤差と OCC ロジック安全化 (`backend/app/routers/presets.py`)

- `base_updated_at` と DB の `updated_at` を比較する際、ミリ秒以下の丸め誤差（クライアント側 ISO 文字列変換等）による誤検知を防ぐため、10ミリ秒（0.01秒）以上の有意な差がある場合のみ 409 Conflict を送出する。

```python
if payload.base_updated_at is not None and preset.updated_at is not None:
    db_updated_at = preset.updated_at.replace(tzinfo=None) if preset.updated_at.tzinfo else preset.updated_at
    base_updated_at = payload.base_updated_at.astimezone(timezone.utc).replace(tzinfo=None) if payload.base_updated_at.tzinfo else payload.base_updated_at
    # 許容誤差 10ms (0.01s) を考慮した OCC 比較
    if (db_updated_at - base_updated_at).total_seconds() > 0.01:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT,
            detail="Preset was updated by another session. Please reload to get the latest changes."
        )
```

## 5. トレードオフ・リスクの開示 (Trade-offs & Constraints)

1. **タイムスタンプRefのメモリ管理**:
   - `presetUpdatedAtRef` はメモリ上の Ref として保持するため、画面遷移を行ってもワークフロー内でのタイムスタンプは維持される。
2. **タイムスタンプ比較の許容誤差 (10ms)**:
   - 10ms 未満の極めて微小な競合を許容することになるが、同一ミリ秒内のマルチデバイス同時書き込みは現実的に存在せず、ISOシリアライズ丸めによる偽 409 を防止するメリットが勝る。
