# REQ-377: モバイルLoRA／Tag Set：詳細・編集シートの再構成とTag Set編集入口・Subsetsの統一 詳細設計書

## 1. 概要・背景・設計方針

### 1.1 課題と目的
モバイル端末（ビューポート幅 767px 以下）における LoRA および Tag Set の詳細モーダルおよび編集画面において、以下の UI/UX 課題が存在している：
1. **巨大画像・一覧による本文圧迫**: 常駐するアスペクト比固定の巨大プレビュー画像と Related Snapshots グリッドが画面上部の大半を占有し、メタデータやフォーム入力欄が画面外に押し出される。
2. **アクションボタンの到達不能・配置不整合**: 決定・保存（Edit/Save/Close/Cancel）ボタンが本文の最下部にあり、長いスクロールを行わないと操作できない。また、閲覧状態（Edit/Close）と編集状態（Cancel/Save）で左右の配置順序（戻る＝左、進む・確定＝右）が揃っていない。
3. **Tag Set 編集入口の多重化・不整合**: カード右上の編集アイコンから開く画面（`TagSetEditModal`）と、詳細モーダル内の Edit ボタンから開く画面（`TagSetDetailModal` 内の編集ステート）が別々のモーダルコンポーネントに分岐しており、操作感やレイアウトが一致しない。
4. **Subsets の入れ子スクロール障害**: `TagSetFormFields` 内の Subsets 一覧に `max-h-[160px] overflow-y-auto` による独立スクロールが設定されており、親コンテナのスクロールと競合してモバイルで操作しにくい。

本設計では、これらの課題を解消し、`SPEC_COMMON` §1-6（モバイルUI共通規約: MUI-02, MUI-03, MUI-04, MUI-05, MUI-06, MUI-07, MUI-09）に準拠したボトムシート構造、固定アクションフッター、小型 Cover 導線、および編集入口・Subsets スクロールの一元化を実現する。デスクトップ表示（768px 以上）および Baseline 動作は 100% 保持する（Baseline-Preserving 原則）。

## 2. 変更境界と Seam Map [MUST [W-DD-SEAM]]

### 2.1 Seam Map 定義
1. **Integrated (real code)**:
   - 対象: `LoraDetailModal.tsx`, `TagSetDetailModal.tsx`, `TagSetFormFields.tsx`, `TagsPage.tsx`, `LoRAsPage.tsx`
   - 責務: React State、イベントハンドラ、ボトムシートレイアウト、固定フッター、小型Cover行、ギャラリーサブビュー、Subsets自然展開を本番コードで結合実行する。
2. **Severed (external I/O)**:
   - 対象: `/api/loras`, `/api/tag-sets`, `/api/base-models`, `/api/snapshots/upload`
   - 責務: バックエンド API 通信と画像アップロード通信はトランスポート層（`client.ts` の API 関数および `fetch`）で切断し、完全インメモリ（Zero-GPU）でテスト実行する。
3. **Mock Level**:
   - 規約: 内部ビジネスロジックや React フックへの monkey-patch を禁止。`baseModelsApi.list` や `fetch` のトランスポート層のみをモック化する。
4. **PBT Decision**:
   - 規約: タグ文字列分割・正規化ロジック (`parseTagSetTokens`, `appendTagSetPaste`) は既存の Fast-Check PBT を維持し、境界値に対する不変性を担保する。
5. **Fault Injection**:
   - 規約: 画像欠損、空スナップショット、画像ロード失敗、逆転強度値などの異常系シナリオを注入し、レイアウト破綻と不正保存を防止する (AC-3, AC-7, AC-11)。

## 3. UI/UX 構造設計

### 3.1 モバイルボトムシートの基本構造 (幅 767px 以下)
`LoraDetailModal` および `TagSetDetailModal` は、幅 767px 以下のモバイル環境において共通の 3 層ボトムシート構造を採用する：

- **最外層 Backdrop**: `modal-backdrop items-end md:items-center p-0 md:p-4`
- **シートコンテナ**: `relative mt-auto md:my-auto w-full max-w-full bg-surface rounded-t-2xl rounded-b-none border border-[rgba(255,255,255,0.08)] shadow-2xl overflow-hidden max-h-[90dvh] flex flex-col md:max-w-4xl md:rounded-2xl md:max-h-[85vh]`
- **上端ドラッグハンドル**: `aria-hidden="true" className="mx-auto mt-2 h-1 w-10 rounded-full bg-zinc-600 md:hidden"`
- **固定ヘッダー**: `flex items-center justify-between px-5 py-4 border-b border-[rgba(255,255,255,0.06)] flex-shrink-0`
- **単一縦スクロール本文**: `flex-1 overflow-y-auto overscroll-contain p-5 space-y-4`
- **固定アクションフッター**: `flex-shrink-0 border-t border-[rgba(255,255,255,0.06)] px-5 py-3 bg-surface flex gap-3 pb-[calc(0.75rem+env(safe-area-inset-bottom,0px))]`

### 3.2 アクションフッターの配置規約 (MUI-04)
- **閲覧モード (View Mode)**:
  - 左: `Close` ボタン（二次アクション: 枠線スタイル、グレー）
  - 右: `Edit` ボタン（一次アクション: アクセントグリーン、強調）
- **編集モード (Edit Mode)**:
  - 左: `Cancel` ボタン（二次アクション: 変更を破棄して閲覧モードへ戻る）
  - 右: `Save` ボタン（一次アクション: アクセントグリーン塗り、保存実行。保存中は `Saving…` と無効化）
- **固定性**:
  - `flex-shrink-0` かつ本文の外側に配置し、本文のスクロール位置（最上部〜最下部）に関係なく常時タップ可能。
  - セーフエリア対応として `pb-[calc(0.75rem+env(safe-area-inset-bottom,0px))]` を適用。
  - 最小タップターゲット 44×44px（Hit-Slop `before:absolute before:-inset-2`）を担保（MUI-06）。

### 3.3 本文上部の小型 Cover プレビューと画像ギャラリー導線 (MUI-05, AC-5, AC-6)
- **常時表示 (本文先頭)**:
  - 幅 767px 以下では巨大なカルーセルや 5 列グリッドを排除。
  - 高さ 64px 程度のコンパクトなバナー行を配置：
    - 小型サムネイル（48×48px または 56×56px、`rounded-lg object-cover bg-zinc-900 border`）
    - ラベル情報：「Cover Image」＋「Related Snapshots (N 件)」
    - タップ誘導アイコン（`ChevronRight`）
- **Cover タップ時の画像ギャラリーサブビュー (AC-6)**:
  - 小型 Cover 行をタップすると、同一モーダル内で `isGalleryOpen = true` に遷移（モーダルの多重ネストを回避し排他規約を遵守）。
  - ヘッダーが「← 詳細に戻る」に切り替わり、Related Snapshots の全件一覧と拡大プレビューを展開。
  - **閲覧時**: Read-only でスナップショットを拡大閲覧。
  - **編集中**: 各スナップショットに「Set as Cover」ボタン、ローカル画像アップロードボタン（`ImageCropper` 連携）を表示。
  - **保存・取消タイミング整合**:
    - ギャラリー内で Cover を変更しても、それは `form.thumbnail_path` の編集ステートに反映されるのみ。
    - 編集シートに戻り、フッターの `Save` を押して初めて永続化される。
    - フッターの `Cancel` またはモーダルを閉じた場合、Cover は元の状態へ復元される（AC-6 整合）。

### 3.4 Tag Set 編集入口の統一 (MUI-09, AC-8)
- **現状の二重分岐**:
  - カードの編集ボタン (`#tagset-edit-${id}`) -> `TagsPage` の `openEdit()` -> `TagSetEditModal` 表示。
  - カードクリック -> `TagSetDetailModal` 表示 -> 詳細内の Edit ボタン -> `TagSetDetailModal` 内で `isEditing = true`。
- **統一仕様**:
  - `TagSetDetailModal` に `initialEditing?: boolean` プロパティを追加。
  - `TagsPage.tsx` において、カードの編集ボタンクリック時も `setSelectedTagSetForDetail(item)` を呼び出し、同時に `initialEditing: true` を渡す。
  - これにより、カードの編集アイコンと詳細内の Edit ボタンの双方が、**全く同一のコンポーネント（`TagSetDetailModal`）の編集モード（同一フィールド、同一固定フッター Cancel/Save）** を開く。
  - `TagSetEditModal` は `TagSetDetailModal` への委譲ラッパーまたは非推奨コンポーネントとして整理し、画面による挙動差異を完全撤廃する。

### 3.5 Subsets 独立スクロールの撤廃と親コンテナ統合 (MUI-02, AC-9, AC-10)
- `frontend/src/components/TagSetModals/TagSetFormFields.tsx` の L278：
  - 現行: `<div className="space-y-2 max-h-[160px] overflow-y-auto custom-scrollbar pr-1">`
  - 改修後: `<div className="space-y-2">`
- 内部の `max-h-[160px]` および `overflow-y-auto` を完全撤廃。
- 多数の Subsets（バリエーション）が追加された場合でも、親のモーダル本文スクロールコンテナ（`TagSetDetailModal` の本文、または `TagSetCreateModal` の本文）が一続きで縦スクロールし、入れ子スクロールによるスタックを根絶する。

## 4. `TagSetFormFields` 利用箇所一覧と影響評価 [AC-10]

共有コンポーネントである `TagSetFormFields` のスクロール仕様変更に伴い、以下の全利用箇所について影響を調査・設計に記録する：

| 利用箇所ファイル | 画面・モーダル | スクロールコンテナの構成 | 変更後の影響と対策 |
|---|---|---|---|
| `TagSetDetailModal.tsx` | Tag Set 詳細／編集モーダル | モバイル: 本文単一縦スクロール (`flex-1 overflow-y-auto`)<br>PC: 右ペイン縦スクロール (`overflow-y-auto h-full`) | Subsets が自然に縦伸長し、本文/ペイン全体のスクロールにスムーズに統合される。破綻なし。 |
| `TagSetCreateModal.tsx` | Tag Set 新規作成モーダル | モーダル枠自体が `max-h-full lg:max-h-[85vh] overflow-y-auto` を保持 | Subsets が増えても新規作成モーダル全体が縦スクロールする。フォーム全体の視認性が向上し、破綻なし。 |
| `TagSetEditModal.tsx` | Tag Set 編集モーダル（互換保持） | 右ペイン縦スクロール (`p-6 overflow-y-auto h-full`) | 右ペイン内で自然に縦スクロール。破綻なし。 |
| `TagsPage.tsx` | タグセット管理ページ（本体） | トークン解析関数 `parseTagSetTokens` のインポートのみ | フォームレンダリングへの直接影響なし。 |

## 5. 技術トレードオフと設計判断 (Trade-offs & Risks)

### 5.1 トレードオフ 1: 画像ギャラリーのサブビュー方式 vs インラインアコーディオン
- **案 A (採用: サブビュー切替方式)**:
  - モバイル時は同一モーダル内部で詳細ビューとギャラリービューをステート切替（`isGalleryOpen`）。
  - **メリット**: 本文の縦スクロール領域が画像で圧迫されず、テキスト作業の可読性を最大化できる。モーダルの多重重ね（アンチパターン 1-5-2 #8）を完全に回避できる。
  - **デメリット**: 閲覧中に画像を見るための 1 タップが必要。
  - **判断**: 課題分析（5 Whys）において「常駐の巨大画像が本文を圧迫する」ことが根本原因と特定されており、案 A を採用。
- **案 B (不採用: インライン展開アコーディオン)**:
  - 本文内でアコーディオンを開閉する。
  - **デメリット**: 開いた瞬間に本文スクロールが跳ね上がり、フッターや入力位置を見失いやすい。

### 5.2 トレードオフ 2: Tag Set 編集の統一方式
- **案 A (採用: `TagSetDetailModal` への一本化)**:
  - カード編集ボタンからも `TagSetDetailModal(initialEditing=true)` を起動。
  - **メリット**: コード重複と UI 不整合（ボタン位置、画像導線、Subsets）が完全に解消される。
  - **デメリット**: `TagSetEditModal` を使っていた既存テストのモック調整が必要。
- **案 B (不採用: `TagSetEditModal` の見た目だけを `TagSetDetailModal` に合わせる)**:
  - 2 つのモーダルを保守し続ける。
  - **デメリット**: 将来の機能追加時に再び乖離が発生するリスクが高い。

### 5.3 トレードオフ 3: デスクトップ表示の分離
- デスクトップ（768px 以上）では `md:grid-cols-2` の 2 列分割レイアウト（左に画像プレビュー＆スナップショット一覧、右にメタデータ・フォーム）を完全に維持する。Tailwind のレスポンシブプレフィックス（`hidden md:block` / `block md:hidden` 等）を用いて、モバイルとデスクトップの最適な UX を両立させる。
