# REQ-385 詳細設計書: 生成完了プレビュー表示遅延およびジョブキャンセル処理の遅延解消

## 1. 概要と目的

ComfyUIと連携した画像生成において、生成完了から画面上にプレビュー画像が表示されるまでに約2.5秒の不要な遅延が発生する問題、およびジョブキャンセル操作（実行中中断）の反映が遅い問題を解消する。

### 解決する課題
1. **生成完了後のプレビュー表示遅延**:
   - ComfyUIは完了時にWebSocketで `execution_success` を送信せず、`{"type": "executing", "data": {"node": null, "prompt_id": prompt_id}}` を送信する。
   - `generation_service.py` の `on_event` は `execution_success` のみで完了処理（history取得およびsucceeded遷移）を行っており、`executing` (node: null) を空処理として無視していた。
   - その結果、バックグラウンドの定期ポーリング周期（`_RECONCILE_SECONDS = 2.5` 秒）が満了するまで `succeeded` 状態および出力画像URLがフロントエンドへ配信されなかった。
2. **ジョブキャンセルの遅延**:
   - `comfy_generation_bridge.py` の `interrupt()` において、リクエスト送信前に冗長な `await self.queue()` が連続2回実行されていた。
   - `generation_service.py` の `_cancel_single()` において、`interrupt()` 呼び出し直後にロックを保持したまま `_reconcile_cancel_state()`（多重同期HTTP通信）を実行していたが、サンプラー停止直後は未完了判定（unconfirmed）となり、結局2.5秒ポーリング待ちとなっていた。

---

## 2. アーキテクチャと詳細設計

### 2-1. `GenerationService.on_event` の即時完了判定改修
- `event_type == "executing"` かつ `data.get("node") is None` の場合、ComfyUIのプロンプト実行完了シグナルとして扱う。
- 即時に upstream history（`await self.bridge.history(prompt_id)`）を照会し、以下を実行：
  - `status.status_str == "success"` または messages 内に `execution_success` が存在する場合：
    - ジョブを `succeeded` に遷移させ、`outputs` を設定。
    - `_frozen_graphs.pop(job.job_id, None)`
    - `_eager_cache_outputs(record.get("outputs"))`
    - `_publish_snapshot()` を発行。
  - `status.status_str == "error"` または messages 内に `execution_error` が存在する場合：
    - ジョブを `failed` に遷移。
  - `messages` 内に `execution_interrupted` が存在する場合：
    - `job.job_id in self._cancel_requested` であれば `cancelled`、そうでなければ `unconfirmed` へ遷移。
- `event_type == "execution_success"` の既存ブロックも将来・モック互換性のため維持する（共通処理 `_handle_completion_record` に統合）。

### 2-2. `ComfyGenerationBridge._handle_json_message` の最適化
- `event_type in {"execution_success", "execution_error", "execution_interrupted"}` に加え、`event_type == "executing" and data.get("node") is None` の場合も、当該 prompt_id の一時プレビューキャッシュ `_latest_preview.pop(prompt_id, None)` をクリアする。

### 2-3. キャンセル処理の高速化
- `ComfyGenerationBridge.interrupt(prompt_id)`:
  - 連続した二重 `self.queue()` 呼び出しを1回に整理。
  - ComfyUIの `/interrupt` POST を速やかに実行。
- `GenerationService._cancel_single`:
  - `interrupt(job.prompt_id)` 実行後、`_cancel_requested` に登録されていることを保証した上で、サンプラー停止とComfyUIからの `execution_interrupted` WebSocketイベントをプライマリ待機パスとする。
  - 同期照会 `_reconcile_cancel_state` が即時 confirmed にならなかった場合でも、ComfyUIからの `execution_interrupted` または直後の `executing` (node: null) 受信時に即時 `cancelled` 遷移してスナップショットを配信する。

## 3. Seam Map (設計義務)

1. **Integrated (本物のコード)**:
   - `backend/app/services/generation_service.py`
   - `backend/app/services/comfy_generation_bridge.py`
   - `backend/app/services/generation_repository.py`
2. **Severed (外部I/Oのみ・トランスポート層)**:
   - ComfyUI HTTP API (`/prompt`, `/queue`, `/history`, `/interrupt`) — `httpx.AsyncClient` トランスポートモック
   - ComfyUI WebSocket (`/ws`) — `_FakeSocket` によるイベント注入
3. **Mock Level**:
   - 内部ビジネスロジックの monkey-patch は禁止。BridgeのHTTPハンドラまたはWebSocketイテレータ層で切断する。
4. **PBT Decision**:
   - WebSocketイベントメッセージ辞書パーサーおよび状態遷移は既存の固定スキーマに基づくため、PBTは不要（決定的単体・結合テストで検証）。
5. **Fault Injection**:
   - `executing` (node: null) 受信時に history が一時的に 404/503 を返した場合のフォールバック動作（例外でクラッシュせず、既存のポーリング reconcile で安全に回復すること）。

## 4. UI 不変条件 & 制約 (UI Invariants)

本PBIの主対象はバックエンドのリアルタイムイベント処理（subsystem: backend）であるため、UI Anti-patterns の混入リスクは極小。
- Frontend既存の `JobManagementModal.tsx` は既存の `3000ms` 待機予約仕様（SPEC_GENERATE.md:203規定）を遵守し、勝手な破壊的変更を行わない。
