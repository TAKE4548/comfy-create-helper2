# REQ-025 テスト計画書

## 1. テスト概要
スマホモードへのレスポンシブな自動切り替え、スマホ専用レイアウトの各機能（画像プレビュー、履歴、タブ切り替えプロンプト入力、各種ボタン操作）が正常に動作することを確認します。

## 2. テストケース・検証項目

### 2.1 レスポンシブレイアウトの動的切り替え検証
* **手順**:
  1. PCブラウザでアプリを開き、画面幅を1200pxにする（PC用2カラムレイアウトが表示されることを確認）。
  2. 画面幅を徐々に縮小し、768px未満にする。
* **期待される結果**:
  * 768px未満になった瞬間、リロードなしで自動的にスマホ専用1カラムレイアウトに切り替わること。
  * 画面を再度1024px以上に広げたとき、自動的にPC用2カラムレイアウトに戻ること。

### 2.2 スマホ用レイアウトでの表示検証
* **手順**:
  1. 画面幅をスマホサイズ（例: 375px）にする。
* **期待される結果**:
  * プレビュー画像表示エリアが崩れることなくアスペクト比を維持して表示されること。
  * 「Generate Batch」および「Save Snapshot」ボタンが画面下部（アクションバー）に適切なサイズで表示され、はみ出しや崩れが無いこと。
  * プロンプト入力部が「横スクロール対応タブ ＋ 単一の共用テキストエリア」の構成になっていること。

### 2.3 プロンプト入力タブ切り替え機能の検証
* **手順**:
  1. スマホモードで、ワークフローを選択する（プロンプト入力タブが複数生成される）。
  2. 最初のタブ（例: `Positive_Prompt`）を選択し、テキストエリアに `beautiful landscape` と入力する。
  3. 二つ目のタブ（例: `Negative_Prompt`）をクリックして切り替える。
  4. 二つ目のタブのテキストエリアに `ugly, blurry` と入力する。
  5. 再び最初のタブをクリックして戻る。
* **期待される結果**:
  * タブ切り替え時に、それぞれのプロンプト内容が正しく表示され、入力した内容（`beautiful landscape` や `ugly, blurry`）が保持されていること。

### 2.4 アクションボタンの動作検証
* **手順**:
  1. スマホモードで「Generate Batch」ボタンをクリックする。
  2. 生成中になり、進捗バーが表示されることを確認する。
  3. 生成が完了し、メインプレビュー画像が更新されることを確認する。
  4. 「Save Snapshot」ボタンをクリックし、スナップショット保存モーダルが開くことを確認する。
* **期待される結果**:
  * 各ボタンが正しくタップでき、PC版と同様のAPI呼び出し・WebSocket処理・状態更新がスマホレイアウトから行われること。

## 3. 手動テストの検証方法
* Chromeデベロッパーツール（F12）のデバイスモードで「iPhone 14 Pro（幅 393px）」などを選択して検証を実施する。
