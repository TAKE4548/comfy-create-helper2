# REQ-127 設計ドキュメント: ComfyUI自動取得 combo パラメータ誤認識の修正

## 1. 問題の概要

`ParamTypeMasterModal.tsx` の `paramList` がワークフローJSON の `inputs` の**全キー**を返す仕様のため、リンク接続型パラメータ（`model: ["4", 0]` 等）がリストに混入する。ユーザーがこれを選択すると object_info が `"MODEL"` 等を返し、combo 検出に失敗して `widget_type: 'textarea'` になる。

## 2. 修正方針

### 採用案: **Hybrid アプローチ（object_info 優先 + ワークフロー JSON フォールバック）**

| フェーズ | 挙動 |
|--------|------|
| ノード選択時 | `selectedClassType` が確定したら自動的に `object_info` をフェッチ |
| paramList 構築 | object_info から combo + プリミティブ型のキーのみ取得（接続型を除外） |
| ComfyUI 未接続時 | ワークフローJSON の `inputs` から配列値（リンク接続）を除外してフォールバック |
| パラメータ選択時 | 自動的に型を検出してフォームにプレビュー表示（ボタン不要） |
| ボタン | 明示的な再フェッチ・上書き用として残す |

### 案の比較と選択理由

| 案 | 内容 | 採用 |
|----|------|------|
| A（最小）| `!Array.isArray(value)` でフォールバックのみ | ✗ ComfyUI 接続時も object_info を使わない、UX 改善なし |
| **B（採用）**| object_info 優先 + フォールバック + 自動型検出 | ✅ AC-1/2/3 を網羅、ユーザーの「自動で分かってほしい」ニーズに応える |
| C（重厚）| paramList 全体を object_info リアルタイム取得のみ | ✗ ComfyUI 未接続時に paramList が空になり AC-3 が難しくなる |

## 3. 実装仕様

### 3.1 新規 useQuery: object_info の自動フェッチ

**追加箇所**: 既存の `useQuery` 群の後（L66付近）

```typescript
// Fetch object_info for selected class type (auto-triggered on node selection)
const { data: objectInfoData } = useQuery<ComfyObjectInfo>({
  queryKey: ['comfy-object-info', selectedClassType],
  queryFn: () => comfyApi.getObjectInfo(selectedClassType),
  enabled: showAutoFill && !!selectedClassType,
  retry: false,                   // ComfyUI未接続時はエラーを静かに無視
  staleTime: 5 * 60 * 1000,      // 5分キャッシュ
})
```

### 3.2 paramList の変更

**変更箇所**: `ParamTypeMasterModal.tsx` L82-87

**現在**:
```typescript
const paramList = useMemo(() => {
    if (!selectedNodeId) return []
    const targetNode = nodeList.find((n) => n.nodeId === selectedNodeId)
    if (!targetNode?.inputs) return []
    return Object.keys(targetNode.inputs)           // ← 全キー（リンク接続を含む）
}, [nodeList, selectedNodeId])
```

**修正後**:
```typescript
/** ComfyUI の object_info においてユーザー編集可能とみなす型名 */
const EDITABLE_TYPES = new Set(['INT', 'FLOAT', 'BOOLEAN', 'STRING'])

const paramList = useMemo(() => {
    if (!selectedNodeId) return []

    // ── 優先: object_info ベース (ComfyUI 接続時) ──────────────────
    if (objectInfoData && selectedClassType) {
        const nodeInfo = objectInfoData[selectedClassType]
        if (nodeInfo) {
            const allInputs = {
                ...nodeInfo.input?.required,
                ...nodeInfo.input?.optional,
            }
            return Object.entries(allInputs)
                .filter(([, entry]) => {
                    if (Array.isArray(entry[0])) return true          // combo
                    return EDITABLE_TYPES.has(String(entry[0]).toUpperCase()) // INT/FLOAT/BOOLEAN/STRING
                })
                .map(([key]) => key)
        }
    }

    // ── フォールバック: ワークフロー JSON（ComfyUI 未接続時）──────────
    const targetNode = nodeList.find((n) => n.nodeId === selectedNodeId)
    if (!targetNode?.inputs) return []
    return Object.keys(targetNode.inputs).filter(
        (key) => !Array.isArray(targetNode.inputs![key]) // リンク接続(配列値)を除外
    )
}, [nodeList, selectedNodeId, objectInfoData, selectedClassType])
```

### 3.3 パラメータ選択時の自動型検出

**変更箇所**: `handleAutoFill` ロジックを `applyTypeDetection(paramName)` として抽出し、`selectedParamName` の変化時にも自動呼び出す。

**型検出ロジック抽出**:
```typescript
/** object_info エントリからフォームを更新する共通ロジック */
const applyTypeFromEntry = useCallback((entry: [unknown, Record<string, unknown>?]) => {
    if (Array.isArray(entry[0])) {
        setForm((f) => ({
            ...f,
            widget_type: 'select',
            combo_options_text: (entry[0] as string[]).join('\n'),
        }))
    } else {
        const typeName = String(entry[0]).toUpperCase()
        const config = (entry[1] as Record<string, number>) ?? {}
        if (typeName === 'INT') {
            setForm((f) => ({
                ...f,
                widget_type: 'int',
                min_value: config.min !== undefined ? String(config.min) : '',
                max_value: config.max !== undefined ? String(config.max) : '',
                step: config.step !== undefined ? String(config.step) : '1',
            }))
        } else if (typeName === 'FLOAT') {
            setForm((f) => ({
                ...f,
                widget_type: 'float',
                min_value: config.min !== undefined ? String(config.min) : '',
                max_value: config.max !== undefined ? String(config.max) : '',
                step: config.step !== undefined ? String(config.step) : '0.01',
            }))
        } else if (typeName === 'BOOLEAN') {
            setForm((f) => ({ ...f, widget_type: 'boolean' }))
        } else {
            setForm((f) => ({ ...f, widget_type: 'textarea' }))
        }
    }
}, [])
```

**パラメータ選択ハンドラに自動検出を追加**:
```typescript
const handleParamChange = useCallback((paramName: string) => {
    setSelectedParamName(paramName)
    if (!paramName || !objectInfoData || !selectedClassType) return
    
    const nodeInfo = objectInfoData[selectedClassType]
    if (!nodeInfo) return
    const allInputs = { ...nodeInfo.input?.required, ...nodeInfo.input?.optional }
    const entry = allInputs?.[paramName]
    if (!entry) return
    
    applyTypeFromEntry(entry as [unknown, Record<string, unknown>?])
}, [objectInfoData, selectedClassType, applyTypeFromEntry])
```

**handleAutoFill の更新** (既存ボタンは再フェッチ用として残す):
```typescript
const handleAutoFill = async () => {
    if (!selectedClassType || !selectedParamName) return
    setIsFetchingObjectInfo(true)
    setError(null)
    try {
        const info = await comfyApi.getObjectInfo(selectedClassType)
        const nodeInfo = info[selectedClassType]
        if (!nodeInfo) {
            setError(`ComfyUI から '${selectedClassType}' の定義を取得できませんでした。`)
            return
        }
        const allInputs = { ...nodeInfo.input?.required, ...nodeInfo.input?.optional }
        const entry = allInputs?.[selectedParamName]
        if (!entry) {
            setError(`パラメータ '${selectedParamName}' の定義が見つかりませんでした。`)
            return
        }
        applyTypeFromEntry(entry as [unknown, Record<string, unknown>?])
    } catch (e: any) {
        setError(`ComfyUI データの取得に失敗しました: ${e.message || String(e)}`)
    } finally {
        setIsFetchingObjectInfo(false)
    }
}
```

**select の onChange を `handleParamChange` に切り替え**:
```tsx
// L357
<select
    value={selectedParamName}
    onChange={(e) => handleParamChange(e.target.value)}   // ← 変更
    ...
>
```

## 4. Trade-off Disclosure（トレードオフ）

| 項目 | 内容 |
|------|------|
| **長所** | パラメータ選択だけで型が自動検出される → ボタン操作が不要 |
| **長所** | object_info ベースの paramList が接続型を排除するため、誤選択が原理的にできなくなる |
| **短所** | ノード選択時に `getObjectInfo` API コールが追加で発生（5分キャッシュで軽減） |
| **短所** | ComfyUI 未起動時はフォールバック動作になるため paramList の精度が下がる（リンク接続の除外は機能するが combo 判定はできない） |
| **リスク** | カスタムノードが非標準形式の object_info を返す場合、検出精度が落ちる可能性あり（既存課題と同等） |

## 5. 影響ファイル

| ファイル | 変更種別 | 内容 |
|---------|--------|------|
| `frontend/src/components/ParamTypeMasterModal.tsx` | MODIFY | useQuery追加、paramList修正、自動型検出追加 |

**バックエンド変更なし**: `/api/comfy/object-info/{class_type}` は既存エンドポイントをそのまま利用。

## 6. AC 充足確認

| AC | 対応 |
|----|------|
| AC-1: リンク接続型が paramList に表示されない | ✅ object_info フィルタ + ワークフローJSON フォールバックフィルタで除外 |
| AC-2: combo パラメータ選択で `select` + 選択肢が設定される | ✅ パラメータ選択時自動検出 + ボタン明示フェッチ両方で対応 |
| AC-3: ComfyUI 未起動でも動作 | ✅ retry:false + フォールバック経路で graceful degradation |
