# 設計書 - REQ-097: workflows.pyのコピー空状態・名称重複エラーテストの追加

## 1. 目的と概要
`workflows.py` のAPIである、ワークフローコピー (`POST /api/workflows/{id}/copy`)、ワークフロー更新 (`PUT /api/workflows/{id}`)、およびワークフロー作成 (`POST /api/workflows`) に対して、境界値および例外挙動のテストカバレッジを向上させます。
具体的には、以下の3点についてテストを追加し、予期せぬ例外の発生や不正なデータの混入を防ぎます。
- マッピングやプリセットを持たない空のワークフローをコピーした際に正常に完了すること (AC-1)
- ワークフロー更新時に他の既存ワークフローと同一の名前（重複名）を指定した場合に `HTTP 409 Conflict` エラーが返ること (AC-2)
- 不正な `json_body` (空文字列や無効なJSON型) が渡された場合に入力検証 (FastAPI / Pydantic の Validation Error) によって適切に遮断されること (AC-3)

## 2. 対象コンポーネントと設計

### 2.1 バックエンドテスト (`backend/tests/test_workflows_copy.py` への追加)
既存の `TestWorkflowsCopy` テストクラス内に、要件を満たすテストメソッドを追加します。

#### AC-1: 空のワークフローコピーのテスト
- **手順**:
  1. mappings / presets を一切持たないワークフローをDBに作成する。
  2. そのワークフローの ID に対して `POST /api/workflows/{id}/copy` を呼び出す。
- **検証項目**:
  - ステータスコードが `201 Created` であること。
  - レスポンスに含まれるコピー先のワークフローの mappings / presets が空リスト `[]` であること。
  - DBから新しいワークフローを取得した際、mappings および presets が空であることを確認する。

#### AC-2: 更新時の名称重複テスト
- **手順**:
  1. 異なる名前のワークフローを2つDBに作成する (例: `wf1`, `wf2`)。
  2. `wf2` に対して `PUT /api/workflows/{wf2.id}` を呼び出し、`name` に `wf1` の名前を指定する。
- **検証項目**:
  - ステータスコードが `409 Conflict` であること。
  - レスポンスメッセージに重複エラーが含まれること。

#### AC-3: 不正な `json_body` 入力検証テスト
- **手順 (作成時)**:
  1. `json_body` に `{}` ではない無効なデータ型 (例: 空文字列 `""` や数値 `123`) を指定して `POST /api/workflows` を呼び出す。
  2. HTTPリクエストとして無効なJSONフォーマット（例: 閉じられていない括弧 `{`）を送信する。
- **手順 (更新時)**:
  1. ワークフローを1つ作成する。
  2. そのワークフローに対して、`json_body` に `""` などの不正なオブジェクトを渡して `PUT /api/workflows/{id}` を呼び出す。
- **検証項目**:
  - ステータスコードが `422 Unprocessable Entity` または `400 Bad Request` であること。
  - API側でリクエストが適切にリジェクトされること。
