# REQ-264: 生成プレビューの最新自動追従と固定（ロック）のトグル切り替え 詳細設計書

## 1. 背景と課題

Prompt Surgeon では画像生成完了時、サムネイル履歴リストへの画像追加およびプレビュー表示が行われます。
先行の REQ-240 において、他端末やバックグラウンドでの生成完了時に閲覧中コンテキストが破壊される問題を防ぐため、「モーダルプレビュー表示中は現在閲覧している画像 URL にインデックスを自動補正して固定（ロック）する」保護仕様が導入されました。

しかしながら、この仕様固定により以下の課題が生じています：

1. **連続生成時の反復操作摩擦（特にモバイル）**:
   - モバイル端末等の画面サイズ制約下では、詳細確認のためにフォーカス表示（`HistoryModalPreview`）が必須となる。
   - 連続して生成（Generate Batch）を実行しながら最新画像を順次確認したい場合、生成完了ごとに「モーダルを閉じる → 履歴から新規画像をタップして再フォーカス」という煩雑な手動操作を強いられる。
2. **モード柔軟性の欠如（最新自動追従 vs 特定画像観察）**:
   - ユーザーのタスクには「次々生成される最新画像をリアルタイムでチェックしたい（自動追従）」ユースケースと、「特定の画像をじっくり比較・観察したい（固定/ロック）」ユースケースの双方が存在する。
   - 表示追従動作をワンタップで切り替える手段が UI 上に提供されていない。
3. **イン-ページプレビュー（DesktopLayout）での整合性**:
   - デスクトップのインページプレビュー（`selectedImg`）は自セッション生成時に無条件に先頭更新される一方、モーダル内は固定されるなど、コンテキスト間の動作不整合が存在する。

## 3. アーキテクチャと詳細設計

### 3-1. 状態管理と永続化 (SSoT)

- **状態キー**: `previewAutoFollow: boolean`
- **ストレージキー**: `LS_KEYS.PREVIEW_AUTO_FOLLOW` (`'prompt-surgeon-preview-auto-follow'`)
- **デフォルト値**: `true`（画像生成ツールとして最新画像を表示する期待値に準拠）
  - ※ ユーザーが一度「固定（Lock）」を選択した場合、`localStorage` に `false` が記録され、リロード後もセッションを超えて保持される。
- **操作アクション**:
  - `setPreviewAutoFollow: (autoFollow: boolean) => void`
  - `togglePreviewAutoFollow: () => void`

### 3-2. モーダル表示インデックス制御マトリクス (`useGenerateDisplayState`)

| イベント / アクション | `previewAutoFollow: true` (自動追従) | `previewAutoFollow: false` (固定/ロック) |
|---|---|---|
| **自セッション生成完了** (`isOwn: true`) | `modalPreviewIndex` を最新画像（`sortOrder === 'desc' ? 0 : length - 1`）へ自動更新。<br>`currentModalUrlRef.current` を新画像 URL に更新。<br>`selectedImg` を新画像に更新。 | `currentModalUrlRef.current`（閲覧中画像 URL）の新規インデックスを探して `modalPreviewIndex` を補正（画像表示は不変維持）。<br>`selectedImg` は上書きせず維持。 |
| **他セッション生成完了** (`isOwn: false`) | REQ-240 準拠：作業中コンテキストを保護し、画面ハイジャックを防止するため、閲覧中画像のインデックスを補正して維持。 | 閲覧中画像のインデックスを補正して維持。 |
| **トグル操作（固定 → 自動追従）** | 即座に最新生成画像（インデックス 0 等）へフォーカスおよび `selectedImg` をジャンプ更新。 | — |
| **トグル操作（自動追従 → 固定）** | 現在表示中の画像 URL を `currentModalUrlRef.current` としてロック固定。以後の新規生成では切り替わらない。 | — |
| **手動送り (<, >) / スワイプ** | 選択画像が切り替わり `currentModalUrlRef.current` が更新される。モード自体（追従か固定か）はリセットされず維持される。 | 選択画像が切り替わり `currentModalUrlRef.current` が更新される。 |

### 3-3. UI / UX コンポーネント設計

#### A. フォーカスプレビューモーダル (`HistoryModalPreview`)
- ヘッダー右側（ダウンロードボタン群と閉じる `X` ボタンの間、または左側）にトグルボタンを配置。
- **画像閲覧を邪魔しないアイコン単体UI（再生/一時停止メタファー）**:
  - **自動追従有効時（再生）**:
    - アイコン: `Play`（再生の三角、`text-accent-green fill-accent-green`）
    - スタイル: `p-2 rounded-lg bg-accent-green/10 border border-accent-green/40 hover:bg-accent-green/20 transition-colors`
    - ホバーツールチップ (`title`): `最新画像を自動追従中（クリックで固定）`
  - **固定（ロック）有効時（一時停止）**:
    - アイコン: `Pause`（一時停止の縦2本線、`text-zinc-400 hover:text-white`）
    - スタイル: `p-2 rounded-lg bg-zinc-800/80 border border-zinc-700 hover:bg-zinc-700/80 transition-colors`
    - ホバーツールチップ (`title`): `現在の画像に固定中（クリックで自動追従）`
- モバイル等ではホバーは機能しないが、アイコン単体（グリーン再生三角 ▶ vs 落ち着いた一時停止 ⏸）の視覚的メタファーにより、画像表示領域を圧迫せずにモードを直感的に判別可能。

#### B. デスクトップ & モバイル サムネイルヘッダー (`DesktopLayout` / `MobileLayout`)
- 「自セッションのみ表示」「新しい順 / 古い順」と並列して同一のアイコン単体トグルボタン（ホバーヒント付き）を提供。
- モーダルを開いていない状態でも現在の動作モードを把握・事前設定可能。
