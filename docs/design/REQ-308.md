# REQ-308 設計: プロンプト区切り変換の適用範囲とチップ編集

## 対象と根拠
REQ-303 の Anima 区切り処理と REQ-306 のプリセット復元経路が影響する。事故調査で確認された Type A は、非プロンプト値も `promptChips` に変換し、有効値の再構築時に上書きしていること。Type B は、サブメニューの単語・強度編集で `formatTagWeight` が `isAnimaMode` だけを根拠に末尾ドットを付け直すこと。ユーザー確認ではテキストモードとダブルクリック編集は正常で、サブメニュー入力欄で再現する。

## 設計決定
1. チップ化・チップからの値上書き対象を、選択中 workflow の `mappings` で `input_type === 'textarea'` の role に限定する。プリセット読込、一括更新、`getEffectiveParamValues` のすべてで同じ許可集合を使う。workflow mapping が未ロードの間は空集合として原値を維持し、mapping 到着時に active preset が未編集なら prompt role を再同期する。checkpoint、LoRA、数値など他パラメータは `paramValues` の原値を保つ。
2. `formatTagWeight` は編集前チップに明示されていた末尾ドットだけを保持する。Anima モードはパース／直近のチップ間結合方針を決めるが、編集値への自動付与根拠にはしない。チップ文言からドットが削除された場合は、強度変更後もドットなしを保つ。
3. 既存の `chipsToString` は末尾ドットを有するチップの後を空白、それ以外を `, ` で結合する。通常モード、テキストモード、ダブルクリック編集は現状維持する。

## 影響 SSoT
- `docs/design/REQ-303.md`: Anima のピリオド分割は入力チップの明示的な末尾ピリオドを維持する仕様とし、Anima による自動再付与を削除。
- `docs/design/REQ-306.md`: Anima プリセット復元対象は workflow textarea role のみと追記。
- `docs/specs/SPEC_COMMON.md`: TagChipEditor 対象と末尾ドットによる結合規則を明記。
- OpenAPI/API schema は変更しない。ワークフロー既存 mapping を参照する内部フロントエンド処理。

## 変更境界
フロントエンドの `multiSetSlice`, `usePresetState`, `useChipParser` とそれぞれの近接テストに限定する。各タスクは3ファイル以下。実装者は Task Card の該当スニペットと AC の範囲で作業する。

## トレードオフとリスク
- textarea role の判定を workflow mapping に依存させるため、workflow や mapping が未ロードの間はチップを生成せず、非プロンプト値を保護する。mapping 到着時は sync effect が active preset の汚れ状態を確認し、未編集なら textarea chips を再構築する。編集済みなら現在値を上書きしない。prompt role が mapping に未登録の場合は従来の破壊的な推測変換より安全側に倒す。
- 編集前の末尾ドットを `parseTagWeight` の戻り値で保持するため、重み付きタグと通常タグで保持規則を一本化できる。異常な複数末尾ドットは正規化して1つにする。
- プリセット保存形式・API契約は変更しない。

## BA audit trace and triage
最初の引数なし `ba-audit` は対象本文が空という応答で終わったため評価に含めない。その後 `python C:\Users\audih\.gemini\antigravity\scripts\local_model_adapter.py --unload-after ba-audit docs/design/REQ-308.md` を実行し、exit 0 で監査を完了した。監査モデルは完了後に全モデルを unload し、VRAM 解放を確認した。

監査指摘と対応:
- Mapping 未ロード: 空の allowlist では chips を作らず、送信時も chips を原値へ反映しない。`paramValues` の元文字列を維持し、後から workflow mapping を得た呼出元だけが allowlist を設定する。欠落中に誤変換・誤送信する経路はないため、警告 UI は追加しない。
- ドット意味の整合: 末尾 `.` の有無を同一の明示状態としてパース・編集・強度整形・`chipsToString` が共有する。文末ドットがないチップはカンマ結合となる。小数重みはチップ内のまま扱う。
- 既存 preset: API/保存形式は変えず、保存文字列中の末尾 `.` はユーザーの明示状態として扱う。過去版が自動追加したかを判定できる根拠がないため一括除去や migration は行わない。
- Type A は非textarea値へのチップ変換・上書きの実装不具合、Type B は Anima 自動付与と編集後状態を尊重する仕様の衝突を指し、本設計の「対象と根拠」に記述済み。
- API schema 変更なし: API は既存どおり parameter role ごとの文字列を受け取り、チップ構造はフロントエンドの編集状態に留まる。

以上は設計説明・テスト計画で扱える懸念であり、受入基準を拡張せずに解消した。監査コメントは保存移行を要求する AC 欠陥を示していない。
