# REQ-214: Python 3.12 / Pydantic V2 互換性対応（datetime.UTC標準化・ConfigDict移行）による非推奨警告の一掃

## 1. 背景と目的

現在、Prompt Surgeon バックエンド（Python 3.12 + FastAPI + SQLAlchemy + Pydantic V2）のテストスイート（全212テスト）を実行すると、合計 **414件の非推奨警告（DeprecationWarning / PydanticDeprecatedSince20）** が出力されている。

主な原因は以下の2点である：
1. **Python 3.12 で非推奨となった `datetime.utcnow()` の継続使用**:
   - `app/models.py` の 16 箇所の DateTime カラムデフォルト定義（`default=datetime.utcnow`, `onupdate=datetime.utcnow`）
   - `app/seeder.py`, `app/routers/llm_prompts.py`, `app/routers/presets.py`, `tests/test_req_087.py`, `scripts/migrate_from_v1.py`
   - これにより、SQLAlchemy ORM のスキーマ初期化・INSERT 実行時に 413 件の `DeprecationWarning: datetime.datetime.utcnow() is deprecated and scheduled for removal in a future version. Use timezone-aware objects to represent datetimes in UTC: datetime.datetime.now(datetime.UTC).` が発生している。
   - また、タイムゾーン情報を持たない Naive Datetime と Aware Datetime の混在により、将来の Python 3.13+ アップグレード時のランタイム破損リスクが存在する。

2. **Pydantic V1 スタイルの内部 `class Config:` 残存**:
   - `app/config.py` 内の `Settings` クラスで `class Config: env_file = ".env"` が使用されており、`PydanticDeprecatedSince20: Support for class-based config is deprecated, use ConfigDict instead.` が発生している。

本設計では、コードベース全体の `datetime.utcnow()` を Python 3.12 標準の timezone-aware な UTC 生成（`utc_now` / `datetime.now(timezone.utc)`）へ移行し、`app/config.py` を Pydantic V2 の `model_config = SettingsConfigDict(...)` へ刷新する。これにより、テストスイート実行時の非推奨警告を **414件から 0件** に完全解消し、既存 212 件の全テストの完全通過（リグレッションなし）を保証する。

## 3. 詳細設計

### 3-1. `app/config.py` の Pydantic V2 移行

```python
from pathlib import Path
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    database_url: str = "sqlite:///../db/prompt_surgeon.db"
    snapshot_dir: str = "../db/snapshots"
    llm_base_url: str = "http://localhost:1234/v1"
    llm_model: str = "qwen3.5-9b-sushi-coder-rl"
    comfy_url: str = "http://localhost:8188"
    cors_origins: str = "http://localhost:5173,http://localhost:4173"

    @property
    def cors_origins_list(self) -> list[str]:
        return [o.strip() for o in self.cors_origins.split(",")]

    @property
    def snapshot_path(self) -> Path:
        p = Path(self.snapshot_dir)
        p.mkdir(parents=True, exist_ok=True)
        return p


settings = Settings()
```

### 3-2. `app/models.py` の Datetime 標準化

SQLAlchemy の SQLite ダイアレクトにおいて、カラムデフォルトにラムダ式またはトップレベル関数を渡すことで、挿入・更新毎に動的に現在UTC時刻が生成される。モジュールレベルに関数 `utc_now` を定義することで、可読性向上とピクル化/マイグレーション互換性を確保する。

```python
from datetime import datetime, timezone
from typing import Optional
from sqlalchemy import (
    Integer, String, Text, Float, Boolean,
    ForeignKey, DateTime, UniqueConstraint, Index,
    Table, Column
)
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.database import Base


def utc_now() -> datetime:
    """Return timezone-aware UTC datetime for SQLAlchemy column defaults."""
    return datetime.now(timezone.utc)
```

## 4. リグレッション防止と互換性検証

1. **SQLite と Datetime 型の整合性**:
   - SQLite はネイティブの日時型を持たず、文字列として格納される。
   - SQLAlchemy の `DateTime` は `datetime.now(timezone.utc)` を受け取った場合でも適切にシリアライズし、既存のクエリ（フィルタリング・ソート・OCC排他制御）と 100% 互換性を保つ。
2. **OCC（楽観的排他制御）との整合性**:
   - `presets.py` の OCC 実装（L83-91）は、`db_updated_at` と `base_updated_at` の差分を `replace(tzinfo=None)` して比較しているため、Timezone-aware なオブジェクトを代入してもミリ秒精度の比較に悪影響を与えない。
