# PBI-164: 複数セッション間における生成進捗・キュー情報・生成履歴の同期および可視化の改善

## 1. 概要 (Overview)
本設計は、PCとモバイルなど複数端末・セッション間におけるComfyUI生成状況の同期および可視化を改善し、他端末で投入されたジョブの進捗（ノード進行・キュー数）の把握および生成完了画像のリアルタイム/リロード時同期を確実に実現するための設計である。

---

## 2. 課題とアーキテクチャ方針 (Problem & Architectural Strategy)

### 2.1 現状の課題
1. **ComfyUI WebSocketの配信仕様の差**:
   - `executing`（ノード変更 / 完了）および `status`（キュー状態）は全WebSocketクライアントへブロードキャストされる。
   - `progress`（ステップ進捗%）および `executed`（生成完了画像）はジョブ投入元の `client_id` にのみ個別配信される。
2. **フロントエンドのステート制御の欠落**:
   - `isGeneratingHere` が `filterOwnSession: true` 時や他セッション時に `false` となり、UIが「完全待機（Ready）」にフォールバックして進捗バー領域が非表示になる。
   - `totalQueueCount` が `filterOwnSession` によって自セッション外のジョブを全件除外して `0` になる。
   - `fetchHistory` が `filterOwnSession: true` 時に他セッションの画像を破棄し、リロード時にも `reconcileState` が単一 `promptId` しか復元しないため、バッチ全体の画像が反映されない。

### 2.2 改善アーキテクチャ方針
```
【PC（ジョブ投入元）】                 【ComfyUI】                 【モバイル（監視側）】
        │                                  │                                  │
        ├────── POST /prompt ─────────────►│                                  │
        │       (client_id: PC)            │                                  │
        │                                  ├────── WS: status ───────────────►│ ──► fetchQueue() & fetchHistory()
        │                                  ├────── WS: executing (node_id) ──►│ ──► isGenerating: true, currentNode更新
        ├◄───── WS: progress (%) ──────────┤ (個別配信)                       │     (他セッション生成中UI表示)
        │                                  ├────── WS: executing (node: null)►│ ──► ジョブ完了検知 ──► fetchHistory()
        ├◄───── WS: executed (画像出力) ───┤ (個別配信)                       │
        │                                  │                                  │
        │                                  │◄───── GET /api/comfy/history ────┤ (最新画像全件同期)
```

## 3. 詳細設計仕様 (Detailed Specifications)

### 3.1 ストア改善 (`frontend/src/store/useGenerationStore.ts`)

1. **WebSocket メッセージハンドリングの強化**:
   - `case 'executing'`:
     - `nodeId` が存在する場合:
       - `isGenerating: true` に設定。
       - `currentNode`: `{ id: nodeId, name: nodeName }` を設定。
       - `data.prompt_id` が存在する場合、`currentPromptId` を更新。
       - `queueRunning` からアクティブな `client_id` を抽出し `activeClientId` を設定。
     - `nodeId === null` の場合（ジョブ実行完了）:
       - 1つのジョブが終了した合図であるため、直ちに `get().fetchHistory()` および `get().fetchQueue()` を呼び出して最新画像と残りキューを自動同期。
   - `case 'status'`:
     - `get().fetchQueue()` および `get().fetchHistory()` を呼び出し、最新のキュー状態と生成履歴を即時同期。

2. **起動時・リロード時の整合性復元 (`reconcileState` & `initialize`)**:
   - `reconcileState` において、単一の `currentPromptId` に依存した早期リターンを廃止。
   - ComfyUIの `/queue` および `/history` を確実に取得し、実行中ジョブの有無に応じて `isGenerating` / `activeClientId` / `currentNode` / `comfyHistoryImages` を同期。

3. **`fetchHistory` のマージロジック適正化**:
   - 全履歴（`allImages`）を常に `comfyHistoryImages`（最新50件）に保持。
   - `batchImages` は自セッション画像と直近の表示用画像を適切にマージし、LocalStorageへの保存とステート更新を行う。

---

### 3.2 ページ状態管理の改善 (`frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts`)

1. **セッション状態判定の分離**:
   - `isGeneratingHere`: 自セッションのジョブが実行中（`activeClientId === clientId` または自セッションの `activeBatch` が未完了）。
   - `isOtherSessionGenerating`: 他セッションのジョブが実行中（`store.isGenerating && !isGeneratingHere`）。

2. **キュー集計の二重化**:
   - `ownQueueCount`: 自セッションのキュー数（Running + Pending）。
   - `allQueueCount`: ComfyUI全体のキュー数（Running + Pending）。
   - `totalQueueCount`:
     - `filterOwnSession: true` かつ `ownQueueCount === 0` かつ `allQueueCount > 0` の場合、他セッション稼働中であることをUIに伝えるための情報（`allQueueCount`）を保持・提供。

3. **履歴表示（`displayImages`）の挙動適正化**:
   - `filterOwnSession` が `false` の場合は `comfyHistoryImages`（全セッション履歴）を表示。
   - `filterOwnSession` が `true` の場合でも、他セッションで生成された画像が存在するときはフィルムストリップ上部に「他セッションの履歴が○件あります」等の通知やワンタップ切り替えを可能にする。

---

### 3.3 UIレイアウト改善 (`DesktopLayout.tsx` & `MobileLayout.tsx`)

1. **プログレスバー領域の3態表示**:
   - **態様 1: 自セッション生成中 (`isGeneratingHere`)**:
     - 全体バッチ進捗バー（○/○枚目, %）、詳細ノード進捗バー（%）、経過時間、ETA、Queue数を表示。
   - **態様 2: 他セッション生成中 (`isOtherSessionGenerating`)**:
     - ステータスバッジ: 「他セッションで生成中...」
     - 実行中ノード: 「実行中: {currentNode?.name || '処理中...'}」
     - プログレスバー: インジケーター（シマーアニメーション付きプログレスバー）
     - キュー情報: 「Queue: {allQueueCount}件 (他セッション)」
     - 経過時間: 経過秒数をリアルタイム表示。
   - **態様 3: 完全アイドル (`!isGenerating`)**:
     - 「Ready | Queue: 0」を表示。

2. **フィルムストリップ（生成履歴）の可視性**:
   - リロード時およびリアルタイム完了時に、全セッション表示時は即座に新しいサムネイルが追加される。
   - 自セッションフィルタがONの場合でも、空表示時に「他セッションの履歴を表示（フィルタOFF）」リンクを表示し、ワンタップで全履歴を確認可能にする。

## 5. テスト・検証方針 (Testing Plan)
- 単体テスト（Vitest）:
  - `useGenerationStore.test.ts`: 他セッションの `executing`（ノード指定 / node=null）受信時のステート更新、`fetchHistory` 連携、`reconcileState` の全セッション同期検証。
  - `useGeneratePageState.test.tsx`: `isOtherSessionGenerating`、`allQueueCount`、`displayImages` の切り替え検証。
- 手動検証:
  - ブラウザ2画面（PC幅 / モバイル幅、異なる `clientId`）を開き、PCでバッチ生成投入 $\rightarrow$ モバイル側で進捗バー（実行中ノード・キュー数）が表示され、完了時にサムネイルが自動反映されることを確認。
