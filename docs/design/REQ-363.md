# Detailed Design Document: REQ-363

## 1. Overview & Architectural Context
REQ-363 resolves critical mobile UI layout defects and enhances usability across the mobile interface of comfy-create-helper2. The goal is to provide a seamless image generation workflow on narrow mobile screens (360px - 390px) without disrupting desktop layouts, breaking existing features (like batch preset management and multi-selection), or requiring any backend API/schema modifications.

## 3. Subsystem Breakdown & Surgical Modifications

### 3.1 Item 1 & 2: MobileLayout.tsx (Tabs, Scroll Padding, and Action Bar)
- **Role Tabs**:
  - Apply shrink-0 whitespace-nowrap to each tab button in MobileLayout.tsx.
  - Ensures pills never collapse or overlap on narrow screens and scroll smoothly horizontally.
- **Scroll Padding**:
  - Scroll container padding: pb-[calc(54px+env(safe-area-inset-bottom)+56px+16px)] ensuring bottom chips stay 16px clear of the fixed action bar.
- **Action Bar & Focus Detection (isTextInput)**:
  - Exclude checkboxes, radio buttons, range sliders, and buttons from isTextInput.
  - Prevents Generate Batch action bar from vanishing when checkboxes are tapped.

### 3.2 Item 4: MobileLayout.tsx (Main Preview Compact Default & Tap Toggle)
- **State**:
  - Add const [isCompactPreview, setIsCompactPreview] = useState(true) to MobileLayout.tsx.
- **Layout**:
  - When isCompactPreview: render height as h-[105px] with compact preview badge and download button.
  - When expanded: render standard max-h-[42vh] or h-[220px].
  - Tap on preview toggles isCompactPreview. Accessible via keyboard (role="button", tabIndex=0, onKeyDown Enter/Space, aria-expanded).
  - Starting generation does NOT force-expand preview; preserves current user state so queuing can continue without scroll jumps.
  - Tap on expanded preview or expand button opens full-screen preview modal (handleOpenModalPreview).

## 4. Trade-off Disclosure [MUST [G-03]]
- **Full-screen preview requires 2 taps**: Transitioning from compact preview (105px) to full-screen modal takes 2 interactions (tap to expand to 220px, then tap to modal, or tapping a dedicated expand button). This is an explicit trade-off prioritizing high-frequency prompt editing and queue additions over passive viewing.
- **Fixed max-height on preset bottom sheet (75dvh)**: Limits the visible list of presets to ~4-5 items at once on mobile, but strictly protects against browser address bar truncation on iOS Safari.
- **Select box compact width (125px)**: Some long scheduler/sampler names may be slightly truncated inside the dropdown closed state, but are fully legible once opened. This prevents label collision on 360px viewports.
