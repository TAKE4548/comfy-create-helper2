# Technical Design: REQ-423 マッピング保存時のinput_name属性欠落によるComfyUIへのSeed未伝播不具合の修正と回帰抑止テスト網の構築

## 0. 設計方針とユーザー特別指示への回答

### ユーザー特別指示 (User Special Directive)
> 「今後、デグレに気づけるようにテストの拡充も合わせて設計して」

本設計は、単なる表面的な不具合修正（`input_name` の受け渡し追加）にとどまらず、**「マッピング検出 → フロントエンド各画面での保持・保存 → バックエンドAPI・DB永続化 → パラメータ注入 → ComfyUIペイロード送信 → メタ情報記録」** に至る一連の全データ伝播経路において、今後いかなるリファクタリングや画面改修が入っても `input_name` の欠落や Seed 未伝播を即座に検知できる多層防壁（コロケーション単体・結合・E2E・異常系フォールバック）を網羅的に設計・配備する。

---

## 1. 現状分析と不具合メカニズム (Root Cause Isolation)

### 1.1 不具合の全体像
1. **現象**: 生成画面でSeed値を変更しても、ComfyUIで実行されるサンプラーノード（KSamplerAdvanced等）の `noise_seed` が書き換わらず固定値のままサンプリングされ、画像が変化しない。一方で生成履歴のメタ情報表示には変更後のSeed値が記録・表示されており、見かけ上は成功しているように見える。
2. **根本原因（5 Whys）**:
   - REQ-417にてスキャナーが合致したノード入力名（`input_name`）を検出し、DBの `workflow_mappings.input_name` に永続化して注入に利用する仕様が策定された。
   - しかしフロントエンド側の複数の保存処理（`useMasterMappingRows.ts:getMappings`, `WorkflowConnectionSection.tsx:saveWorkflowConfig`, `RescanModal.tsx:initFromScan`, `useWorkflowManagement.ts:handleUpdateMapping`, `NodeRemapModal.tsx:handleSave`, `AdaptiveWorkflowWiring.tsx:WiringMappingItem`）において、保存ペイロード構築時に `input_name` 属性が除外・欠落し、バックエンドへ送信されなかった。
   - バックエンドDBには `input_name = ""`（空文字列）が保存された。
   - 生成実行時、`workflowParamInjector.ts` の `seedOptions` 処理において `seedNode.input_name` が空であるためマスタ既定の `param_name`（`"seed"`）にフォールバックした。
   - ノード（KSamplerAdvanced等）は `noise_seed` を本来の入力とするため、`node.inputs["seed"]` は存在せず、`node.inputs["value"]` も存在しないため、最終的に `node.inputs["seed"]` という実在しないキーへ値が新規誤注入された。
   - ComfyUIはサンプラー本来の入力である `noise_seed` のみを参照して動作するため、シード変更が無視された。
   - 一方で `generationRecord.ts` は `node.inputs[mapping.param_name]`（`node.inputs["seed"]`）が存在したためそれを「実際のシード」として記録し、UI表示との乖離が発生した。

## 3. アーキテクチャおよび改修設計 (Architecture & Remediation Design)

### 3.1 パラメータ注入および記録のフォールバック堅牢化 (`workflowParamInjector.ts`, `generationRecord.ts`)
1. **`workflowParamInjector.ts` のシード注入ロジック**:
   - `seedNode.input_name` が非空文字列の場合はそれを優先して使用する。
   - `seedNode.input_name` が空・未設定の場合（レガシーワークフロー等）:
     - 候補リスト `[seedNode.param_name, ...(seedNode.fallback_param_names ?? []), 'noise_seed', 'seed', 'value']` を走査し、`node.inputs` に実在する最初のキーを解決する。
     - 実在するキーが存在する場合はそのキーへ注入する。
     - いずれのキーも実在しない場合のみ `configuredKey || 'seed'` にフォールバックする。
     - これにより、`input_name` が欠落した状態であっても KSamplerAdvanced の `noise_seed` や PrimitiveNode の `value` へ正しくシードが注入され、不要な `node.inputs["seed"]` の誤生成を完全に防止する。
2. **`generationRecord.ts` のメタ情報記録ロジック**:
   - `capture` 関数において、`mapping.input_name` が非空文字列の場合は最優先キーとして採用する。
   - `mapping.input_name` が未設定で `mapping.role === 'Sampler_Seed'` の場合、`inputs["noise_seed"]`、`inputs["seed"]`、`inputs["value"]` の実在キーをチェックし、実際に注入されたノード入力値を取得する。

### 3.2 マッピング行構築および配線保持 (`useMasterMappingRows.ts`, `AdaptiveWorkflowWiring.tsx`, `wiringStageGroups.ts`)
1. **`useMasterMappingRows.ts`**:
   - `StageSlotItem` および `MasterMappingRow` に `input_name?: string` を追加。
   - `buildRows`:
     - スキャン結果 `slotMatched?.input_name` または既存保存マッピング `saved.input_name` をスロット・行に保持。
     - スキャンマッチで検出された `input_name` は、既存保存マッピングの `input_name` が空であっても正しく補完（ヒーリング）。
   - `getMappings`:
     - 返却オブジェクト `{ master_id, node_id, variant_id?, input_name?: string }[]` において、`slot.input_name`、`saved?.input_name`、`latestScan.current?.matched` の対応候補から `input_name` を確実に抽出し、空でない限り必ずペイロードに含める。
2. **`AdaptiveWorkflowWiring.tsx` & `wiringStageGroups.ts`**:
   - `WiringMappingItem` インターフェースに `input_name?: string` を追加。
   - `handleNodeChange` や `mappingsMap` の同期処理において、既存マッピングの `input_name` を落とさずに維持する。

### 3.3 UI 保存経路および再スキャン復元 (`WorkflowConnectionSection.tsx`, `RescanModal.tsx`, `useWorkflowManagement.ts`, `NodeRemapModal.tsx`)
1. **`WorkflowConnectionSection.tsx`**:
   - `ConfigDraft.mappings` 型に `input_name?: string` を定義。
   - `useEffect` での `configWorkflow.mappings` から `configMappings` への初期化時、`input_name` を保持。
   - `saveWorkflowConfig` での `snapshot.mappings` マッピング時、`input_name` を保持。
   - `handleSaveLinks` での `mappingsToSave` マッピング時、`input_name` を保持。
   - `validateConfig`（エクスポート/インポート）で `m.input_name` を保持。
   - `onChangeMappings` で `input_name` を保持。
2. **`RescanModal.tsx`**:
   - `initFromScan` への `savedMappings` 渡しにおいて、`input_name` をドロップせず渡す。
   - `saveMutation` は `getMappings(rows, [])` を呼び出すため、修正された `useMasterMappingRows` から完全な `input_name` を受け取ってバックエンドへ送信する。
3. **`useWorkflowManagement.ts`**:
   - `handleUpdateMapping` において、マッピング更新時に対象外マッピングおよび更新対象マッピングの `input_name` を保持。
   - `updateWorkflowMutation` の型定義に `input_name?: string` を追加。
4. **`NodeRemapModal.tsx`**:
   - `handleSave` の `updatedMappingsList` 構築において、`m.variant_id` および `m.input_name` を確実に保持。

### 3.4 バックエンド API 契約と往復検証 (`test_workflows.py`)
- バックエンド（FastAPI `PUT /api/workflows/{id}`, `POST /api/workflows`, `POST /api/workflows/{id}/duplicate`）は既に `input_name` に対応しているが、DB永続化および往復取得（Roundtrip）を担保する回帰テストが存在しなかったため、`backend/tests/integration/api/test_workflows.py` にテストケースを拡充し、API契約の固定化を図る。

## 4. Seam Map [W-DD-SEAM]

1. **Integrated (本物のコードを実行する境界)**:
   - **Frontend**:
     - `workflowParamInjector.ts` の `injectWorkflowParams`, `getInitialParams`
     - `generationRecord.ts` の `buildGenerationRecord`
     - `useMasterMappingRows.ts` の `buildRows`, `getMappings`, `initFromScan`
     - `AdaptiveWorkflowWiring.tsx`, `WorkflowConnectionSection.tsx`, `RescanModal.tsx`, `useWorkflowManagement.ts`, `NodeRemapModal.tsx`
   - **Backend**:
     - `backend/app/routers/workflows.py`
     - `backend/app/schemas/workflow.py`
     - SQLAlchemy ORM モデル `models.WorkflowMapping`
     - テスト用 SQLite インメモリ DB
2. **Severed (外部 I/O の切断境界)**:
   - ComfyUI 外部サーバーへの HTTP リクエスト・WebSocket 通信（`useGenerateAction` のプロンプト送信部分はモックまたは事前ペイロード検証）。
   - ブラウザストレージ（`localStorage` はテスト環境のモック）。
3. **Mock Level**:
   - 内部ビジネスロジック・ヘルパー関数のモンキーパッチは**全面禁止**。
   - 切断はトランスポート層（`workflowsApi` クライアント呼び出し、または FastAPI `TestClient` による HTTP 境界）のみで行う。
4. **PBT Decision (Property-Based Testing 要否)**:
   - `workflowParamInjector` のシード注入ロジックに対し、入力ノードが持つ多様なキーの組み合わせ（`noise_seed`, `seed`, `value`, 未知キー, 複合キー）に対するシード値注入の安全性検証を Vitest パラメタライズドテストおよびアサーション網でカバーする（入力キー空間が有限の代表的ComfyUIノードクラス型に閉起するため、高速かつ確定的なマトリクステストを採用）。
5. **Fault Injection (異常系・境界値テスト)**:
   - `input_name = ""`（空文字列）のレガシーマッピング。
   - `input_name` に指定されたキーがノード `inputs` に存在しないケース。
   - ワークフロー JSON 内に対象 `node_id` が存在しないケース。
   - ノードの `inputs` が空オブジェクト `{}` のケース。
   - サンプラーノード以外のノード（CLIPTextEncode等）に誤ってシードマッピングが紐付けられたケース。

## 6. 回帰抑止テスト網の拡充設計 (Regression Prevention Strategy)

ユーザー特別指示に応え、本改修では以下の**4重の防護ネット**を敷設する：

```
+---------------------------------------------------------------------------------------+
```

## 7. トレードオフとリスク分析 (Trade-offs & Risks)

1. **既存空 `input_name` の自動ヒーリング vs 既存値の温存**:
   - トレードオフ: 再スキャン時に既存 DB に空文字（`""`）が入っていた場合、スキャンマッチした候補の `input_name`（`"noise_seed"` 等）で上書き（補完）する。手動で意図的に空にしたケースは想定されず、REQ-417の実装不備による空文字であるため、再スキャン時に自動修復することがユーザー体験上最も望ましい。
2. **`workflowParamInjector` での探索フォールバック**:
   - 万が一将来新たな保存経路で `input_name` が欠落した場合でも、サンプラーノードの主要キー（`noise_seed`, `seed`, `value`）を走査して自動注入する二重安全装置を備える。これにより、最悪の場合でも ComfyUI への Seed 未伝播は再発しない。
3. **リスク分類**:
   - 変更リスク: **Low**（既存の公開インターフェースやDBスキーマを変更せず、欠落していたフィールドの伝播復元とフォールバックの追加であるため、破壊的変更のリスクは極めて低い）。
   - ただし、生成パイプラインの核心部分であるため、テスト計画において Gate 1/2/3 の完全検証を実施する。
