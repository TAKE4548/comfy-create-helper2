# REQ-082: RescanModal 候補ドロップダウン ラベル改善

## 1. 背景と目的

`RescanModal.tsx`（生成画面のワークフロー選択脇から開く再マッピングモーダル）では、
役割に対する候補ノードを選択する `<select>` にノードID（例: `10`）のみが表示されている。

PBI-081（`UploadWorkflowModal.tsx`）で実装した `getNodeLabel` 関数と同様のロジックを
`RescanModal.tsx` にも適用し、候補ノードのラベルを
`ID - [タイトル] (クラスタイプ)` 形式（例: `10 - [positive] (KSampler)`）に変更する。

## 2. 影響範囲

| ファイル | 変更種別 | 内容 |
|---|---|---|
| `frontend/src/components/RescanModal.tsx` | MODIFY | `getNodeLabel` 関数の追加、`<option>` の表示ロジック変更 |

バックエンド変更: **なし**（`workflowJson` prop はすでに `RescanModal` へ渡されており、ノード情報取得に利用可能）

## 3. 実装詳細

### 3-1. `getNodeLabel` 関数（PBI-081 実装と同一ロジック）

```tsx
const getNodeLabel = (id: string) => {
  const node = workflowJson?.[id] as Record<string, any> | undefined
  if (!node) return id                        // フォールバック: IDのみ表示
  const title = node._meta?.title || ''
  const classType = node.class_type || ''
  return `${id} - [${title}] (${classType})`
}
```

**フォールバック挙動（AC-2）:**
- `workflowJson` にノードが存在しない → `id` のみ返す
- `_meta.title` が欠落 → `''` として扱う（`[](KSampler)` のように表示）
- `class_type` が欠落 → `''` として扱う（`10 - [positive]()` のように表示）
- いずれの場合もクラッシュしない

### 3-2. `<option>` 変更箇所

**Before (RescanModal.tsx L216):**
```tsx
{row.candidates.map((id) => (
  <option key={id} value={id}>{id}</option>
))}
```

**After:**
```tsx
{row.candidates.map((id) => (
  <option key={id} value={id}>{getNodeLabel(id)}</option>
))}
```

> **重要**: `value` 属性は引き続き `id`（ノードID文字列）のみを保持する。
> 表示ラベルのみ変更であり、状態管理・保存ロジックへの影響はない。

## 6. トレードオフと制約

| 観点 | 内容 |
|---|---|
| **利点** | UploadWorkflowModal との UI 一貫性が確保される |
| **制約** | `workflowJson` の型が `Record<string, unknown>` のため、内部アクセス時に `as Record<string, any>` キャストが必要（PBI-081 と同一の型回避策） |
| **リスク** | ノード情報が欠落している場合のフォールバック動作が想定通りに動作しないリスクはあるが、`UploadWorkflowModal` で実績済みのロジックをそのまま転用するため低リスク |
