# REQ-282: GeneratePage レイアウト重複の解消と共通オーバーレイ抽出 詳細設計書

## 1. 背景と課題

Prompt Surgeon の主要画面である `GeneratePage` において、`DesktopLayout.tsx` (1,086行) と `MobileLayout.tsx` (944行) の2つのレイアウトコンポーネントが存在する。
本来この2ファイルは「PC用2カラム分割配置」と「モバイル用縦積み配置」という**画面配置（View Layout）の違いのみ**を担うべきである。

しかし現状は、以下の関心事が両ファイルに完全コピペ重複して実装されている：
1. **共通モーダル・トースト群 (約160行重複)**:
   - 新規プロファイル作成ダイアログ (`showCopyModal`)
   - バイパス設定モーダル (`BypassSettingsModal`)
   - パラメータ同期設定モーダル (`ParamSyncModal`)
   - エラートースト通知 (`errorToast`)
   - プロンプト翻訳モーダル (`PromptTranslationModal`)
   - タグセット保存モーダル (`SaveAsTagSetModal`)
2. **セットタブバー (DesktopLayout 約140行)**:
   - プリセットタブ一覧 (`SetTabItem`)
   - 新規作成・管理ボタン
   - アクティブプリセットのUndo / Redoボタン
3. **生成画像・履歴ギャラリー (約200行重複)**:
   - 履歴 / スナップショットタブ切り替え
   - ソート順切り替え (昇順/降順)
   - プレビュー自動追従トグル (`previewAutoFollow` / REQ-264)
   - 自セッションのみ表示フィルタ (`filterOwnSession`)
   - 複数選択一括保存バー (`isMultiSelectMode`)
   - サムネイルグリッド & スナップショットカード一覧

これにより、片方の修正漏れによる不具合リスク（REQ-264のボタンIDやハンドラ差分など）やコード肥大化（2ファイル合計2,000行超）が発生している。

---

## 2. アーキテクチャ設計と階層構造

```
frontend/src/pages/GeneratePage/
├─ components/
│  ├─ DesktopLayout.tsx           # PC用画面分割配置のみ（約250〜300行に削減）
│  └─ MobileLayout.tsx            # モバイル用縦積み配置のみ（約200〜250行に削減）
└─ sections/
   ├─ GenerateModalsOverlay.tsx   # ★共通モーダル・トースト集約（約160行）
   ├─ SetTabsBar.tsx              # ★セットタブ一覧・追加・Undo/Redo（約140行）
   └─ GenerationGallerySection.tsx # ★生成画像グリッド・スクロール・REQ-264追従（約200行）
```

### 2-1. コンポーネント責務とインターフェース

#### 1. `GenerateModalsOverlay.tsx`
- **責務**: `DesktopLayout` および `MobileLayout` からモーダル・トースト表示JSXを完全に集約・外出しする。
- **入力 Props**:
  - `state: ReturnType<typeof useGeneratePageState>`（または必要な state プロパティ）
- **内包する要素**:
  - `showCopyModal` (新規プロファイル作成ダイアログ)
  - `isBypassSettingsOpen` (`BypassSettingsModal`)
  - `isParamSyncSettingsOpen` (`ParamSyncModal`)
  - `errorToast` (トーストアラート)
  - `promptTranslation` (`PromptTranslationModal`)
  - `saveAsTagSetRole` (`SaveAsTagSetModal`)

#### 2. `SetTabsBar.tsx`
- **責務**: プリセットタブの一覧表示、タブ切り替え、追加・管理導線、Undo/Redo制御を提供する。
- **入力 Props**:
  - `sets: GenerationSet[]`
  - `openPresetIds: (string | number)[]`
  - `activeSetId: string | number | null`
  - `handleSelectPresetTab: (id: string | number) => void`
  - `toggleSetChecked: (id: string | number) => void`
  - `removeSet: (id: string | number) => void`
  - `presets: WorkflowPreset[]`
  - `undo?: (id: string | number) => void`
  - `redo?: (id: string | number) => void`
  - `canUndo: boolean`
  - `canRedo: boolean`
  - `onOpenAddSet: () => void`
  - `onOpenPresetManager: () => void`

#### 3. `GenerationGallerySection.tsx`
- **責務**: 生成履歴・スナップショットのサムネイル表示、ソート、セッションフィルタ、複数選択操作、および REQ-264 のプレビュー自動追従トグルを提供する。
- **入力 Props**:
  - `state: ReturnType<typeof useGeneratePageState>`
  - `isMobile?: boolean` (PCとMobileの微細なスタイリング差分を吸収)
- **REQ-264 プレビュー制御の維持**:
  - トグルボタンの ID（`preview-autofollow-toggle-desktop` / `preview-autofollow-toggle-mobile`）を完全維持
  - `previewAutoFollow`（Play/Pause アイコン）および `handleToggleAutoFollow` のバインドを100%担保

## 3. 分割タスク計画 (Atomicity Audit)

- **REQ-282-T1**: `GenerateModalsOverlay` の抽出と `DesktopLayout` / `MobileLayout` への接続 (Impacted files: 3)
- **REQ-282-T2**: `SetTabsBar` の抽出と `DesktopLayout` への接続 (Impacted files: 2)
- **REQ-282-T3**: `GenerationGallerySection` の抽出と `DesktopLayout` / `MobileLayout` への接続（REQ-264 プレビュー制御維持） (Impacted files: 3)

全タスクが **3ファイル以内** かつ **相互に疎結合** であり、リグレッションを局所化して安全に推進可能。
