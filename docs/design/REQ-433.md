## 1. 実現可能性判定と根本原因分析

### 1.1 実現可能性判定
**実現可能（Feasible）**。既存の Tailwind CSS ユーティリティ、Hit-Slop パターン（`before:absolute before:-inset-*`）、および `index.css` の `data-radius-exempt` / `data-tap-target-exempt` オプトアウト機構を整合させることで、既存機能・アクセシビリティ・UI 6大不変条件を損なうことなく全画面で標準デザインへ統一できる。

### 1.2 根本原因（`frontend/src/index.css`）
モバイル表示（幅 768px 未満 / `@media (max-width: 767px)`）でステータスランプやトグルスイッチ周辺が「角丸正方形」に見える原因は、`frontend/src/index.css` における以下 3 点の一律補正の複合作用である。

1. **`button` セレクタへの無条件角丸上書き（L169–182）**:
   - `@layer utilities` 内で `button` が `:not([data-radius-exempt])` なしに `border-radius: var(--ux-radius-control);`（`8px`）へ強制されている。
   - 同様に `[class~='rounded-full']:not([data-radius-exempt])` も `8px` に上書きされるため、`data-radius-exempt` を持たない `rounded-full` のランプや `<div>` トラックも角丸 `8px` になる。
2. **モバイル時の `min-width: 44px; min-height: 44px` 強制（L387–399）**:
   - `@media (max-width: 767px)` 内で `button:not([data-tap-target-exempt])` および `[role='button']:not(button):not([data-tap-target-exempt])` に `min-width: 44px; min-height: 44px;` が適用されている。
   - この結果、`<button>` で実装されたピル型トグルスイッチ（`w-9 h-5` = 36×20px 等）や `<span role="button">` で実装されたドット型ステータスランプ（`SystemStatusBadge` `w-[7px] h-[7px]`）が 44×44px の正方形に引き伸ばされ、上記(1)の `border-radius: 8px` と相まって **44×44px の角丸正方形** として描画される。
3. **Hit-Slop 分離の未適用**:
   - 外形サイズ（正円ドットやピル型トラック）とタップ判定領域（44×44px 以上）が分離されておらず、かつ各コンポーネントに `data-radius-exempt` / `data-tap-target-exempt` が付与されていない。

### 2.1 `SPEC_COMMON.md` に追加する標準デザイン契約（案）

#### A. ステータスランプ（Status Lamp）標準仕様
- **対象**: 死活監視・接続状態・保存状態・実行中状態を示す円形インジケータドット（文字やバッジ枠を伴うピル型テキストバッジ自体はチップ/バッジ規定に従うが、その内部のランプドットは本仕様に従う）。
- **形状・角丸**:
  - 縦横比 1:1 の**正円**とし、`rounded-full` と `data-radius-exempt` を併用して実効 `border-radius: 9999px`（幅・高さの 50% 以上）を保証する。
  - Flex/Grid コンテナ内での潰れ防止のため `shrink-0`（または `flex-shrink-0`）を必須とする。
  - 標準サイズ: `w-2 h-2`（8×8px）または `w-2.5 h-2.5`（10×10px）。コンパクト領域では `w-1.5 h-1.5`（6×6px）または `w-[7px] h-[7px]`（7×7px）を許容する。
- **状態表現（色のみで伝えない原則）**:
  - 稼働中・正常・完了: `bg-emerald-400` / `bg-accent-green`（`#3ECF8E`）
  - 確認中・待機中・進行中: `bg-amber-400` / `bg-yellow-400` / `bg-indigo-400` / `bg-[#7C6FDD]` / `bg-zinc-500`（必要に応じ `animate-pulse` / `animate-ping`）
  - 停止中・エラー・失敗: `bg-rose-400` / `bg-red-500`
  - **必須併記**: 隣接する名称・状態テキスト（例: `稼働中`、`停止中`、`不明`、`Ready`）または `role="img" aria-label="..."`（操作可能ランプの場合はボタン側の `aria-label`）を必ず併用し、色覚のみに依存しない。
- **モバイル保護・操作領域**:
  - `data-radius-exempt` により `index.css` の一律角丸補正（`8px`）から保護する。
  - ランプ自体が操作対象（`role="button"` 等）を兼ねる場合（例: `SystemStatusBadge` の `variant="dot"`）は、`data-tap-target-exempt` を併用して視覚外形（7×7px 正円）を維持したまま、`before:absolute` による Hit-Slop 拡張で **有効タップ領域 44×44px 以上** を確保する。

#### B. トグルスイッチ（Toggle Switch）標準仕様
- **対象と区分**:
  - **本仕様の対象（ON/OFF トグルスイッチ）**: 2値状態（ON/OFF、有効/無効、boolean）を直接切り替えるスイッチ UI（`ParamPanel`、`ParamFieldControl`、`VramGuardSection`）。
  - **対象外（押しボタン型トグル）**: チップ/テキスト表示切替（`TagChipEditor` / `TagChipViewer`）、アコーディオン開閉、セクション展開ボタン、タブ切替等は押しボタン型トグルとして従来の角丸 8px ボタン（`--ux-radius-control`）を維持する。
- **構造・形状**:
  - **トラック（Track）**: 両端半円のピル型（`rounded-full` + `data-radius-exempt`、実効 `border-radius: 9999px`）。
    - 標準サイズ: `h-5 w-9`（36×20px、`border-2 border-transparent`）
    - コンパクトサイズ（リスト行内用）: `h-4 w-7`（28×16px、`border border-transparent`）
  - **ノブ（Knob）**: 縦横比 1:1 の正円（`rounded-full` + `data-radius-exempt`、`bg-white shadow`）。
    - 標準サイズ用: `h-4 w-4`（16×16px、ON: `translate-x-4` / OFF: `translate-x-0`）
    - コンパクトサイズ用: `h-3 w-3`（12×12px、ON: `translate-x-3` / OFF: `translate-x-0`）
- **状態表現・アクセシビリティ**:
  - **ON**: `bg-accent-green`（`#3ECF8E`、ただし破壊的/警告系 Bypass トグルは `bg-red-500` を維持）、ノブ右端。
  - **OFF**: `bg-zinc-700`、ノブ左端。
  - **Disabled**: `disabled:opacity-40 disabled:cursor-not-allowed`。
  - **ARIA**: `role="switch"` と `aria-checked={isOn}` を必須とし、`aria-label` または関連ラベルで対象項目を識別可能にする。
- **モバイル角丸保護 & 44×44px Hit-Slop 要件**:
  - `index.css` の `button` セレクタを `button:not([data-radius-exempt])` とし、トラック（`<button>` / `<div>`）およびノブ（`<span>`）の双方に `data-radius-exempt` を付与する。
  - `<button role="switch">` には `data-tap-target-exempt` を付与してモバイル時の `min-height: 44px` 引き伸ばし（角丸正方形化）を防ぎつつ、`relative touch-manipulation before:absolute before:content-['']` による Hit-Slop（`h-5 w-9` には `before:-inset-x-2 before:-inset-y-3` で 52×44px、`h-4 w-7` には `before:-inset-x-2 before:-inset-y-3.5` で 44×44px）で **有効タップ領域 44×44px 以上** を確保する。

## 4. トレードオフと設計判断

1. **CSS セレクタ修正 vs `!important` 強制**:
   - `verify_ui_invariants.py` は CSS 内の `!important` を原則禁止（`rule-no-indiscriminate-important`）している。そのため `index.css` では `!important` を使わず、`button:not([data-radius-exempt])` および `[class~='rounded-full'][class*='px-']:not([data-radius-exempt])` として除外属性で制御する。
2. **共通 `<ToggleSwitch>` コンポーネント新設 vs 既存マークアップへの属性・クラス統一**:
   - `VramGuardSection` は `<label><input type="checkbox" className="sr-only peer" />` 構造（既存テストで `getByRole('checkbox')` や `label` クリックに依存する可能性あり）であり、`ParamPanel` / `ParamFieldControl` は `<button>` 構造である。既存テスト・DOM 構造の破壊リスクを抑えるため、本 PBI では既存要素構造を維持しつつ `SPEC_COMMON.md` の標準契約（`data-radius-exempt` + `data-tap-target-exempt` + Hit-Slop + `role="switch"`）へ統一する。将来的な共通コンポーネント化は別リファクタで検討可能。
   - ※ `VramGuardSection` で `<input type="checkbox" role="switch">` にすると ARIA role が `checkbox` から `switch` へ変わるため、既存テスト `VramGuardSection.test.tsx` が `getByRole('checkbox')` を使っていないか Task Card 内で明示確認・更新する。
3. **Hit-Slop の寸法設計**:
   - 従来の `before:-inset-2`（上下左右 +8px）では、`h-5`（20px）のトグルの高さが `20 + 16 = 36px` に留まり 44px 未満となる。そのため `h-5 w-9` には `before:-inset-x-2 before:-inset-y-3`（52×44px）、`h-4 w-7` には `before:-inset-x-2 before:-inset-y-3.5`（44×44px）、`SystemStatusBadge` の 7×7px ドットには `before:-inset-[19px]`（45×45px）を採用する。
