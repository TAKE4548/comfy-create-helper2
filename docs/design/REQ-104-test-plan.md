# PBI-REQ-104 実行可能テスト計画（監査修正版）

## 1. 自動テスト (CLI Verification)
本変更は主に外部ネットワーク接続時の API 解決およびコンポーネントの初期描画に関するものであるため、既存の Vitest テストが壊れていないことを検証する。
- **コマンド**: `npm run test` (または `npx vitest run`)
- **判定基準（Pass/Fail）**:
    - **PASS**: 実行結果として「Test Files: X passed, Y failed」かつ、**Failed の数が 0**であること。
    - **FAIL**: Failed の数が 1 以上ある場合、またはテストがタイムアウト/エラーで終了した場合。

## 2. 手動・ブラウザ検証 (Manual & Browser Verification)
環境: Chrome ブラウザ（モバイルデバイスエミュレーション：iPhone 12 または同等のレスポンシブサイズ）。

### 2.1 ComfyUI 接続成功時の検証
1. **準備**: ローカル ComfyUI を起動し、ブラウザで `http://localhost:5173/` にアクセスして生成画面を開く。
2. **UI 確認（非曖昧化）**: 
    - パラメータパネルの `Scheduler` ドロップダウンを開く。
    - **判定基準**: リスト内に文字列 `"beta"` が**存在する**こと。（存在 = Pass, 不存在 = Fail）
3. **動作確認（厳密なログ参照）**:
    - `beta` を選択し、「Generate」ボタンをクリックする。
    - **判定基準**: 
        - ブラウザコンソール (F12) に、HTTP ステータスコードが **200** であるリクエストログ（または成功メッセージ）が表示されること。
        - かつ、画面下部のキュー表示領域に「1」件のタスクが追加されたこと。
    - **Fail 条件**: コンソールに `4xx` または `5xx` のエラーコードが含まれる場合、またはキューにタスクが追加されない場合。

### 2.2 ComfyUI 接続失敗時の検証（フォールバック）
1. **準備**: ローカルの ComfyUI プロセスを停止し、ブラウザを再読み込みする。
2. **状態確認**: 
    - **判定基準**: UI に「オフライン」または「接続エラー」という明確なテキスト/アイコンが表示されること。（表示 = Pass, 非表示 = Fail）
3. **フォールバック動作確認**:
    - パラメータパネル of `Scheduler` ドロップダウンを開く。
    - **判定基準**: リスト内に文字列 `"beta"` が**存在する**こと（ComfyUI 接続なしでもデフォルトスケジューラーが利用可能であること）。
