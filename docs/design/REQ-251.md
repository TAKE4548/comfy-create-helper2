# REQ-251: セクションタグコピー履歴サブメニューのスクロール表示化と項目潰れ解消

## 1. 背景と課題

GeneratePage の各プロンプトセクション（Positive / Negative 等）に存在する「クリップボード・履歴操作」ボタン（`PromptSectionClipboardMenu`）から展開されるポップオーバーメニューには、プロンプト文字列の「コピー履歴（最大10件）」が表示されます。

しかし、コピー履歴の件数が増加した場合、スクロールバーによる閲覧にならず、各ボタンの縦幅が極端に押し潰されてしまい、ボタン内部のテキストが上下に切れて判読できなくなる問題が発生していました。

---

## 2. 根本原因

`PromptSectionClipboardMenu.tsx` の L176 において、履歴リストコンテナは以下のように定義されています：

```tsx
<div className="max-h-40 overflow-y-auto flex flex-col gap-1 pr-0.5">
  {history.map((item, index) => (
    <button
      key={`${index}-${item.slice(0, 15)}`}
      type="button"
      onClick={() => handleHistoryItemClick(item)}
      className="w-full px-2 py-1.5 rounded bg-[#27272F] hover:bg-[#32323D] text-left text-[11px] text-zinc-300 hover:text-white truncate transition-colors border border-transparent hover:border-[rgba(255,255,255,0.1)]"
      title={item}
    >
      {item}
    </button>
  ))}
</div>
```

1. コンテナに `display: flex; flex-direction: column;` が指定されているが、子要素の `<button>` に `shrink-0`（`flex-shrink: 0`）が指定されていない。
2. そのため、子要素には CSS Flexbox の既定値である `flex-shrink: 1` が適用される。
3. 加えて各ボタンには `truncate`（`overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`）が付与されており、中身のテキストによる縦方向の最小高さ抵抗（min-height）が働かない。
4. 履歴件数が増加（最大10件）して全体の高さが親の `max-h-40`（160px）を超過した際、スクロールを発生させる前に Flexbox が各ボタンの縦幅を均等に押し潰して160px内に収めようとする。
5. この結果、ボタンの高さが数ピクセル程度まで圧縮され、テキストが垂直方向に非表示となって項目が読めなくなる。

---

## 4. 詳細設計

### 4.1 `PromptSectionClipboardMenu.tsx` のスタイリング改善

```tsx
<div className="flex flex-col gap-1.5 pt-1 border-t border-[rgba(255,255,255,0.08)] min-h-0">
  <div className="flex items-center justify-between text-zinc-400 text-[11px]">
    <span className="flex items-center gap-1 font-medium">
      <History size={12} /> コピー履歴 ({history.length})
    </span>
    {history.length > 0 && (
      <button
        type="button"
        onClick={clearHistory}
        className="hover:text-red-400 flex items-center gap-0.5 transition-colors"
        title="履歴を全削除"
      >
        <Trash2 size={11} /> クリア
      </button>
    )}
  </div>

  {history.length === 0 ? (
    <div className="py-2 text-center text-zinc-500 text-[11px]">履歴はありません</div>
  ) : (
    <div className="max-h-40 overflow-y-auto custom-scrollbar flex flex-col gap-1 pr-0.5">
      {history.map((item, index) => (
        <button
          key={`${index}-${item.slice(0, 15)}`}
          type="button"
          onClick={() => handleHistoryItemClick(item)}
          className="w-full shrink-0 px-2 py-1.5 rounded bg-[#27272F] hover:bg-[#32323D] text-left text-[11px] text-zinc-300 hover:text-white truncate transition-colors border border-transparent hover:border-[rgba(255,255,255,0.1)]"
          title={item}
        >
          {item}
        </button>
      ))}
    </div>
  )}
</div>
```

#### 主な変更点:
1. **`shrink-0` の付与**:
   各履歴ボタンに `shrink-0`（`flex-shrink: 0`）を付与。これにより Flexbox の高さ縮小計算から除外され、各ボタンは本来の高さ（`py-1.5` + フォント行高 約28px）を完全に維持する。
2. **`custom-scrollbar` の付与**:
   スクロールバーが表示された際、アプリ共通のダークテーマに適したスリムなスクロールバーデザインを適用。
3. **`min-h-0` の付与**:
   外側の `flex flex-col` 親要素に `min-h-0` を付与し、フレックス子要素内のスクロールコンテナが想定通り縮退して親要素をはみ出さないよう CSS 標準仕様に準拠。

---

## 5. 検証方針 (AC 充足確認)

- **AC-1**: コピー履歴が複数件（最大10件）存在する場合でも、各履歴項目に `shrink-0` が適用され、縦幅が圧縮されずテキストが完全に視認可能。
- **AC-2**: コピー履歴の合計高さが `max-h-40`（160px）を超える場合、`overflow-y-auto custom-scrollbar` によって縦スクロールが可能。
- **AC-3**: スクロールされた状態でも各履歴項目をクリックしてプロンプト入力欄への貼り付けが正常に動作する。
- **AC-4**: `PromptSectionClipboardMenu.test.tsx` の単体テストに「最大10件の履歴展開時にすべてのボタンが `shrink-0` を保持し、クリック貼り付けが動作すること」を検証するテストを追加し、PASS すること。
