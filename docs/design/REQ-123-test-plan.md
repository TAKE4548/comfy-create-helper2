## 2. 手動シナリオテスト

### シナリオ A: クロスデバイス同期 (AC-1)
```
前提: デバイスAとデバイスBで同じバックエンドに接続済み
手順:
  1. デバイスBでプリセット「ProfileA」を開き、promptフィールドを編集
  2. オートセーブ完了を確認（1秒待機、ネットワークタブで PUT /api/workflow-presets/{id} の成功を確認）
  3. デバイスAでページをリロード
期待:
  - デバイスAのUIにデバイスBで入力した内容が表示されること
  - localStorage の古い値で上書きされていないこと
判定: NG の場合は isInitialSyncRef による強制同期が未動作
```

### シナリオ B: 新規タブ作成後の元プロファイル保持 (AC-2)
```
手順:
  1. プリセット「ProfileA」を開く
  2. promptフィールドを編集（例: "cat" → "cat, dog"）
  3. オートセーブを待たずに「ProfileAからコピーして新規作成」を実行
  4. 新規タブが作成されたことを確認
  5. 「ProfileA」タブをクリック
期待:
  - ProfileAに "cat, dog" の編集内容が残っていること
  - （旧動作: 編集前の "cat" に戻ってしまう）
判定: NG の場合は setSets の未保存保護注入が未動作
```

### シナリオ C: 新規タブへのフォーカス (AC-3)
```
手順:
  1. 任意のプリセットを開く
  2. 「コピーして新規作成」を実行
期待:
  - 作成後、新しいプリセットタブがハイライト・選択状態になること
  - （旧動作: 元のプリセットタブに留まったまま）
判定: NG の場合は onSuccess の localStorage 書き込みが未動作
```

### シナリオ D: オートセーブ後の編集保持 (AC-4)
```
手順:
  1. プリセット「ProfileA」を開き編集開始
  2. 1秒以上待機（オートセーブ発火 → invalidateQueries → バックグラウンド再フェッチ）
  3. 別のプリセット「ProfileB」タブをクリック → 「ProfileA」タブに戻る
期待:
  - ProfileAの編集内容が消えていないこと
  - paramValues が再フェッチ前の値のままであること
判定: NG の場合は mappedSets への現在値注入が未動作
```
