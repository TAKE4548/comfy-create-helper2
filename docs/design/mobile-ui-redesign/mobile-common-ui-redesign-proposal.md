# モバイル共通 UI/UX 改修案仕様（レビュー版）

- **状態**：改修案・採用未確定。ここに記載したルールは本番の全画面へ自動適用されない。
- **適用検討範囲**：Generate、LoRA、Tag Set、History のモバイルUI。以後の他ページのレビューでも比較基準として参照可能。
- **画面固有の仕様**：[Generate改修案](./mobile-generate-redesign-proposal.md) ／ [LoRA・タグセット改修案](./mobile-lora-tagset-redesign-proposal.md) ／ [History画面別改修案](./mobile-history-generate-selection-design-draft.md)
- **実装境界**：`prototype/ui-review`・`ui-prototype/` の試案。 `main`、`frontend/`、`backend/` は変更・採用未実施。
- **判断原則**：Baseline-Preserving, Problem-Driven Design。ユーザーの確定判断 ＞ 有効な仕様書 ＞ 現行実装 ＞ 一般設計原則。

## 1. この文書の役割と読み方

本書は画面間の**一貫性を判断する共通UI設計ルール候補**と、その検証・承認条件を集約する。ページ固有のレイアウト、数値、画像操作の詳細は下位文書に置く。

- **共通ルール候補**：複数画面に一貫して適用したい原則。採用可否は未確定。
- **共通コンポーネント変更候補**：共有コード自体の変更を伴う可能性がある事項。依存先を洗い出し、別途承認する。
- **ページ固有実装**：似た見た目でも、同一部品にするとは限らない。
- **確認済み**はコード構造またはユーザーの実画面指摘を指す。**未検証**は視覚・実機・回帰試験が不足している項目。

## 2. 共通UIルール候補

| ID | テーマ | 共通ルール候補 | 各画面への適用 |
|---|---|---|---|
| COMMON-01 | ベースライン維持 | 問題のない色、文字、余白、共通ナビ・操作を維持。デザインの一律刷新をしない | 3画面 |
| COMMON-02 | スクロール | 主要コンテンツの縦スクロールを優先し、無用な入れ子スクロールを作らない。独立スクロールは明確な理由がある場合のみ | Generateの本文／LoRA・Tag Setのカード／Tag SetのSubsets |
| COMMON-03 | 固定操作 | 決定・保存・生成など重要アクションを本文スクロールで失わない。表示階層、底部余白、セーフエリア、キーボードをセットで設計 | Generate固定生成バー／LoRA・Tag Set詳細の固定フッター |
| COMMON-04 | アクション配置 | 同種の詳細シートでは左を戻る・取消（Close/Cancel）、右を進む・確定（Edit/Save）として整合させる | LoRA・Tag Setの詳細／編集。Generateの異用途ボタンには機械的に適用しない |
| COMMON-05 | シート／画像 | 文字作業を主目的とする画面では画像の常時占有を抑制し、拡大・一覧・Cover変更は明確な別導線にする | Generate画像確認／LoRA・Tag SetのCover・Snapshot |
| COMMON-06 | 操作領域 | 主要操作のタップ領域、隣接ボタンとの分離、フォーカス視認性を保つ。寸法を減らす場合は誤タップと操作効率を実機確認 | タブ、削除／編集、チップ、フッター、ドラッグ |
| COMMON-07 | 表示階層 | 通常本文・チップ・ドラッグ対象は固定操作を覆わない。モーダル／シート／ポップオーバーは用途に応じた階層で設計 | Generateのタグと生成バー／両ページのシートや画像ギャラリー |
| COMMON-08 | 情報階層 | 一覧では識別に必要な情報を優先し、詳細データは詳細画面へ。行数制限・省略時は全文確認経路を保持 | LoRA・Tag Setの固定サイズカード。Generateへ同一カードルールは強制しない |
| COMMON-09 | 入口の一貫性 | 同じ編集対象・目的に入る複数導線は、状態・見た目・確定動作を揃える | Tag Setのカード編集／詳細からの編集 |
| COMMON-11 | 複数選択 | 選択時は上部に「×＋選択件数＋補助選択操作」、下部に画面固有の一括操作を表示する。状態とアクションの役割を分離する | History一覧・アルバム詳細、Generate履歴（モバイル） |
| COMMON-10 | ジェスチャー | 横移動、縦スクロール、ドラッグ、チップ操作、入力、支援技術の競合を避ける。タップ操作を代替経路として残す | Generateスワイプ／一覧の並べ替え・選択 |

> **適用の限界**：ここでは「無意味な入れ子スクロールを避ける」「フッターを操作可能にする」等の**原則**を共有する。Generateの3タブ高さ42px、LoRA・Tag Setカード高さ320px、チップのパディング3px/8px等を全画面共通トークンと決めるものではない。

## 3. 共通コンポーネント影響表

| 共有領域／部品 | 確認した利用・関連先 | 共通化／変更の判断 |
|---|---|---|
| `TagChipEditor`・`TagChip` | Generateのプロンプト、Tag Set作成・編集の`TagSetFormFields` | チップ寸法・編集操作の改修はGenerate限定の例外を安易に作らず、両画面で比較する。共通化は採用前に判断 |
| `TagChipInput`・`TagChipViewer` | タグに関する別コンポーネント。詳細で`TagChipViewer`を利用 | 同一実装ではない。視覚仕様を揃える必要性と変更影響を個別に調査 |
| `TagSetFormFields` | Tag Set作成・編集で使用 | Subsetsの内部スクロール廃止は両導線で整合確認。共有部品に変更を加える場合は他の使用箇所も確認 |
| `ImageCarousel` | LoRA・Tag Set一覧ほか | カードの画像中央配置を共通部品へのグローバル変更と短絡しない。他画面への影響を調査 |
| `MultiSelectToolbar`／`useMultiSelect`／Generate履歴の選択バー | Historyでは共通ツールバーを使用。Generateは画面内独自の選択バーを使用 | 視覚・操作パターンを共通候補とするが、React部品の統合は利用箇所を調査して別途承認。モックのDOM後処理を本番へ持ち込まない |
| `PageHeader`／`AppShell` | 複数ページで利用 | 基本維持。固定バーやStickyの問題はまずページ内の配置・親のスクロール構造を調査 |
| 詳細シート／固定フッター | LoRA・Tag Setの類似する詳細UI、Generateの異用途の画像シート | 共通**パターン**を検討するが、共通**コンポーネント**化は別途判断 |
| ドラッグ／ポップオーバー基盤 | カード移動、チップ、画像など | スタッキングコンテキストやイベント競合が基盤側なら利用画面全体を検証 |

この一覧は依存関係の完全な棚卸しではない。本番変更前に検索と画面別回帰確認を追加する。

## 4. 共有してはいけないページ固有の事項

| 画面 | 個別仕様（上位共通仕様へ数値を移管しない） |
|---|---|
| Generate | プロンプト／パラメータ／履歴の3セクション、横スワイプ、3列履歴、常駐プレビュー撤去、生成バー、画像全画面表示 |
| LoRA・Tag Set | 固定320pxカード、タイトル2行／Description2行／対応モデル1行、カテゴリ見出し、カード編集・削除と並べ替え |
| LoRA | 強度、トリガーワード、ファイルパス、モデル固有の編集・コピー |
| Tag Set | タグ、サブセット、作成画面と編集画面、Cover・Snapshotの保存動作 |

## 5. 共通ルール変更の決定フロー

1. 問題を実画面または操作で確認し、コードからの推測だけで決めない。
2. **Preserved／Modified／New** と、ページ固有／共通ルール／共通部品を分類する。
3. 影響する画面・状態・操作を洗い出し、BaselineとProposalを同条件で比較する。
4. フォーカス・タップ・キーボード・タッチ・スクリーンリーダー・スクロール・重なり・回帰を検証する。
5. 共通変更は、適用範囲、利点・不利益、必要なバリアントの理由を示し、ユーザーの**明示的な採否判断**を得る。
6. 採用が確定した部分だけ、`ui-specification.md` の方針に沿って確定仕様に移管する。

## 6. 共通受け入れ条件（未確定の設計ゲート）

- **C-AC-01** 既存の問題のない配色・ナビ・入力・各機能が退行しない。
- **C-AC-02** 本文をスクロールするとき、意図しない子要素の独立スクロールが発生しない。
- **C-AC-03** 固定操作をコンテンツ／タグ／ドラッグ中の要素が覆わず、タップが奪われない。
- **C-AC-04** 同じ用途の操作は入口ごとに別の画面状態へ分岐せず、左右のアクション配置が整合する。
- **C-AC-05** 画像と本文、シート、フッターのレイアウトが狭幅・セーフエリア・キーボード・多量データで破綻しない。
- **C-AC-06** 共有部品変更時はGenerate・Tag Setを含む関連画面の表示・操作回帰を確認する。
- **C-AC-07** CI成功とモック表示は採用確定ではない。未検証を明示し、実画面で評価する。
- **C-AC-08** 共通化によるデザイン例外を作る際は合理的な理由と影響を記録し、ユーザーの判断を得る。

## 7. 現状と引き渡し

- **確認済み**：対象ページの問題はユーザーの実画面レビューに基づく。コード上の独立スクロール、共有フォーム、モーダル構造も確認されている。
- **確認済み**：2026-10-18時点で3画面のProposalは`prototype/ui-review`上に分離され、Baselineと比較可能。
- **未検証**：実機ごとの画像選択・Cover変更、複数モデル／大量サブセット、スクリーンリーダーやフォーカスの網羅的回帰。
- **未確定**：上記共通ルールの正式採用、共有コンポーネント改修、本番反映。両画面の詳細は下位文書の各ACを参照。

## 8. モバイル複数選択の共通デザイン候補（History／Generate）

**対象範囲**：Historyのスナップショット一覧・アルバム詳細、Generateの履歴。共通UI**パターン**の提案であり、アプリ全画面への適用や共通React部品の更新は未確定。

### 8.1 選択状態と終了

- 画像長押しで選択モードに移り、最初の画像を選択する。以降はタップで個別選択・解除する。
- 上部は**「×」＋「N件／N枚選択中」**を主情報として横並びに配置。×はモード終了と選択クリアを行い、アクセシブルな名前「選択モード終了」を持つ。
- 「すべて選択」と「選択解除」は補助操作として維持。後者は選択0件に戻すが、モードは終了しない。
- 大きな緑／紫の状態背景や多段の操作群を避け、既存ダークテーマと整合させる。選択カードにはチェックや輪郭を残す。
- 長押しは既存の選択設定とスクロールを両立する。架空SVG用モック固有のイベント補正や遅延値は本番仕様に含めない。

### 8.2 下部一括操作ドック

- 選択中のみ**モバイルナビゲーションの直上**へ固定表示し、終了・画面離脱時に消す。セーフエリアや固定バーとの隙間・重なりを作らない。
- ボタンは操作結果が分かるラベルを使う。破壊的操作、無効状態、実行中状態、確認ダイアログを各画面の既存処理に連動させる。
- ドックの44px程度のタップ領域、フォーカス、スクリーンリーダー、狭幅・回転時の折り返しを検証する。モックのナビ高さ54pxは固定の共通トークンではない。
- **画面固有アクション**は共通仕様では固定しない。History一覧＝「ダウンロード／アルバムへ追加／削除」、アルバム詳細＝「ダウンロード／削除」、Generate履歴＝「スナップショットに保存」。各画面の下位仕様を参照。

### 8.3 共通受け入れ条件（追加・未確定）

- **C-AC-09** 長押しで選択モード開始、画像タップで選択状態・件数更新が行える。
- **C-AC-10** 上部の×で選択解除・終了でき、「すべて選択」「選択解除」はそれぞれ規定の状態遷移を行う。
- **C-AC-11** 下部操作ドックは既存ナビの直上に表示され、解除・画面離脱後に残留しない。
- **C-AC-12** 各操作の有効／無効・確認動作は実処理に一致し、全画面への共通UI強制による退行がない。
- **C-AC-13** 対象2画面でBaseline／Proposal、狭幅、タッチ、キーボード、アクセシビリティを検証する。CI成功だけで採用確定とはしない。

**検証状況**：ユーザーからHistoryの画像プレビュー復旧、下部バーの隙間解消、Generate履歴の長押し有効化、最新選択UIの肯定的レビューがあった。ただし全ACの実機・自動操作検証および本番共通実装の承認は未完了。
