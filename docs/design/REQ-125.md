# REQ-125 詳細設計書

## 1. 概要
既存ワークフローの再スキャン・リマッピングダイアログ（`RescanModal`）開始時、現在そのワークフローに設定されているマッピング情報（`workflow.mappings`）を初期値として引き継いで編集を開始できるようにする。

万一ワークフローJSONの変更により既存のノードIDが存在しなくなった場合やクラスタイプ不一致（ミスマッチ）が発生した項目については、極力問題ない項目の設定を維持したまま、該当するミスマッチ項目のみ個別に初期スキャン時と同様のデフォルトフォールバック値を適用し、ユーザーへ注意表示（警告メッセージ/バッジ）を行う。

## 2. 影響範囲
- `frontend/src/hooks/useMasterMappingRows.ts`: `initFromScan`関数の拡張、既存マッピングの判定および個別ミスマッチ時のフォールバック処理・ステータス保持を追加。
- `frontend/src/components/RescanModal.tsx`: `existingMappings`プロパティの受け渡し、既存マッピングのフォールバック警告表示を追加。
- `frontend/src/pages/GeneratePage.tsx`: `RescanModal`呼出時に`existingMappings={workflow.mappings}`を渡す。
- `frontend/src/hooks/__tests__/useMasterMappingRows.test.ts`: 既存マッピング保持およびミスマッチフォールバックの単体テストを追加。

## 3. 詳細ロジック設計

### 3.1 `useMasterMappingRows` の拡張
`initFromScan(result: ScanResult, existingMappings?: { master_id: number; node_id: string }[], workflowJson?: Record<string, unknown>)`
1. デフォルトスキャン結果（`result.matched` / `result.warnings`）から各 `master_id` に対する推奨ノードIDマップ `scanDefaults` を算定する。
2. `existingMappings` が渡されている場合:
   - 各 `mapping` (master_id, node_id) について、`workflowJson` またはスキャン候補内に該当 `node_id` が存在しかつ適合するかチェックする。
   - 適合する場合: `initial[master_id] = mapping.node_id` として既存設定を採用する。
   - 適合しない場合（ノード削除/型不一致等のミスマッチ）: `initial[master_id] = scanDefaults[master_id]`（なければ空文字）を採用し、`mismatchMasters` または警告ステータスに登録する。
3. `existingMappings` が存在しない場合（新規アップロード等）:
   - 従来通り `scanDefaults` を `initial` に設定する。

### 3.2 UI警告表示（`RescanModal.tsx`）
- 既存マッピングからのミスマッチフォールバックが発生した項目に対して、ステータスラベル（例: `既存設定無効`）または警告バッジを表示し、自動修正された旨を明確にする。

## 4. テスト設計
- `useMasterMappingRows.test.ts`:
  - 既存マッピングが正常に維持されるケースのテスト
  - 一部ノードが消去された場合に、問題のない項目は維持しつつ消去された項目のみフォールバック初期値が設定されるケースのテスト
