# REQ-309 設計

## 実現可能性と境界

AC-1〜6 は現在の React 18、React Router、Vite 5 の構成で実現可能。API、保存形式、バックエンドは変更しない。`frontend/dist` の現行 `index.html` は単一の JavaScript ファイル `index-BkizodkY.js`（ディスク上 1,286,166 byte）を参照し、直近ビルド報告は 1,261.71 kB / gzip 335.43 kB。これは **編集可能時点までの実転送量の測定値ではない**。実装前に現行配布物を空キャッシュで測り、同じ配信方式・ブラウザ・初期ルート・画面幅で改修後と比較する。

## 依存関係と設計決定

1. `App.tsx` は `/` と `/loras`、`/tags`、`/history`、`/settings` の5画面を静的 import している。画面単位の `React.lazy` と `Suspense` に変え、初期ルートで他4画面のコードを取得しない。ページの named export は維持する。
2. `GeneratePage.tsx` は PC とモバイル両レイアウト、未表示の各種モーダルを静的 import している。`isMobile` に応じて使うレイアウトだけを読み込み、モーダルは開く条件が成立した時に初めて mount して読み込む。特に現状で `isOpen=false` のまま常時 mount される `AddSnapshotToAlbumModal`、`HistoryModalPreview`、`JobManagementModal`、`ProfileBulkEditModal`、`PresetConflictModal` は、遅延 import だけでは初回転送が減らないため開状態による mount 条件も必要。閉じた際のフォーム状態、再オープン、保留中処理の扱いを既存動作と照合する。
3. `GenerateModalsOverlay.tsx` は `BypassSettingsModal`、`ParamSyncModal`、`PromptTranslationModal`、`SaveAsTagSetModal` を静的 import している。親レイアウトのプロンプト欄は先に描画し、これらのモーダル本体だけを開状態で読み込む。コピー作成ダイアログと通知は小さく即時描画を維持する。
4. `Suspense` のフォールバックは画面切替・モーダル表示の対象領域に限定する。ページ全体のフォールバックで既に編集可能なプロンプト欄を隠さない。読み込み失敗は既存 `GlobalErrorBoundary` / `GeneratePageErrorBoundary` の表示と再読み込み導線を確認する。追加の局所復旧が必要かは Gate 3 で判断する。
5. チャンク警告の解消は実際の遅延境界で狙う。`chunkSizeWarningLimit` の変更や警告抑止は行わない。500 kB 以下に収まらない場合はビルド結果の依存グラフを確認し、残った静的 import のうち初回操作に不要なものを追加分割する設計改訂を行う。`manualChunks` による見かけ上の警告解消だけでは AC-1 と判定しない。

## 上流・下流、SSoT

上流は PBI `REQ-309` と `SPEC_SUMMARY.md` のルーティング定義、`SPEC_GENERATE.md` の初期画面仕様。下流は5画面の表示、Generate の PC/モバイル入力、checkpoint/生成、モーダル、履歴、設定、配布物の静的配信。`SPEC_LORAS.md`、`SPEC_TAGS.md`、`SPEC_HISTORY.md`、`SPEC_SETTINGS.md` は機能契約を保持する参照元であり、今回の読み込み方式だけなら本文変更不要。実装後は `SPEC_SUMMARY.md` に画面単位の遅延読込、`SPEC_GENERATE.md` に使用レイアウト・モーダルの読込条件を同期する。OpenAPI の変更はない。

## 計測と判定

- 同一条件の本番配布物を空キャッシュで `/` に開き、Network 記録開始からプロンプト欄が編集可能になる時点までに**取得完了した JavaScript 応答の転送バイト数**を合計する。圧縮、HTTP、キャッシュ条件を前後で一致させ、リクエスト URL とサイズも保存する。`index.html`、CSS、API、画像は合計に含めない。編集可能時点に取得中だった JS は、その時点までに実転送されたバイトを記録できる計測手段を使うか、全取得完了時点を併記して判定の曖昧さをなくす。
- 既存 `dist` の数値はビルド成果物のサイズであり、AC-1 の比較値として代用しない。`/loras` 等への遷移後に読み込む JS は初回合計から除き、初回の先読み・プリロードがある場合は合計に含める。
- `npm run build` の出力で全 JS チャンク 500 kB 以下かつ閾値変更なしを確認する。初回転送量低下と警告消失の両方が必要。

## リスクと代替案

- 画面/モーダルの初回表示は、その時点でコード取得を待つ。対象領域の読み込み表示と失敗時の復旧を検証する。
- 現状常時 mount のモーダルを条件付き mount にすると内部状態の寿命が変わる。開閉の状態保持が必要なら状態を親へ移すか、軽いシェルと重い内容を分ける。
- 画面単位の遅延読込だけでは、初期 Generate の静的依存が大きく、AC-1 や AC-2 に不足する可能性が高い。そのため初期画面内部の境界も独立した Task Card とする。
- 大きい vendor チャンクを機械的に分割する案は警告を消せても初回転送量を減らさないため、最初の対策には採用しない。
