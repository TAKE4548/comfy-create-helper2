# REQ-325: 共通プロンプト構文解析エンジン (PromptTokenEngine) 詳細設計書

## 1. 概要 (Overview) & 背景 (Context)

Prompt Surgeon の機能拡張（タグ翻訳、キャプションデカップリング、LoRAトリガーワード注入など）に伴い、プロンプト構文の解析、重み付け `((tag:1.2))` の展開、カンマや空白の正規化ロジックが各コンポーネント（`TagChipEditor`, `captionDecoupler.ts`, `promptUtils.ts`）に個別実装され、挙動の差異や保守リスクが生じている。
本改修では、`frontend/src/utils/prompt/` 配下に単一責任の `PromptTokenEngine` 基盤を新設し、共通の AST / `PromptToken` モデルによる構文解析・シリアライズ・タグ操作（デカップリング）を統一する。

## 2. SSoT 影響分析 (SSoT Impact Analysis)

- **対象仕様ドキュメント**:
  - `docs/specs/SPEC_DATASET_STUDIO.md`: LoRA Studio キャプションデカップリング（`captionDecoupler.ts`）の基盤ロジックを本エンジンへ透過的に移行。外部インターフェース（`decoupleCaption`）は 100% 後方互換を維持。
  - `docs/specs/SPEC_COMMON.md`: 将来的なプロンプト構文解析共通モジュールとして `PromptTokenEngine` の仕様を追加記録。
- **アーキテクチャ境界**:
  - フロントエンド単体（`frontend/`）内の純粋ユーティリティ層（`src/utils/prompt/`）の新設。
  - バックエンドやDBスキーマへの影響なし（完全分離）。

## 3. ドメインモデル & インターフェース設計 (Interface Design)

### 3.1 `PromptToken` データモデル

```typescript
export type PromptTokenCategory = 'meta' | 'physical' | 'outfit' | 'trigger' | 'general'

export interface PromptToken {
  /** 元のトークン生文字列 (例: "((cat ears:1.2))") */
  raw: string
  /** 余分な括弧・重み付け・空白を除去した正規化タグ本体 (例: "cat ears") */
  text: string
  /** 強度倍率 (未指定時は 1.0) */
  weight: number
  /** 括弧のネスト深度 (例: 2) */
  bracketDepth: number
  /** 有効/無効フラグ (デフォルト true) */
  enabled: boolean
  /** タグカテゴリ分類 (オプション) */
  category?: PromptTokenCategory
}
```

### 3.2 `PromptTokenEngine` クラス

```typescript
export interface DecoupleOptions {
  position?: 'prepend' | 'append'
}

export class PromptTokenEngine {
  /**
   * 平文プロンプト文字列を解析し、PromptToken の構造化配列へ変換する。
   * - 括弧ネスト (), [], {} の深度を追跡し、括弧内のカンマ・ピリオドは分割しない。
   * - 重み付け構文 `(tag:weight)` や `((tag:weight))` をパースし、text / weight / bracketDepth を算出。
   * - 連続カンマ、改行、重複スペースを安全に正規化し、空トークンを除外する。
   */
  static tokenize(promptText: string): PromptToken[]

  /**
   * PromptToken 配列から ComfyUI / SD 構文に準拠したクリーンな平文プロンプトを再構成する。
   * - enabled === false のトークンを除外。
   * - weight !== 1.0 の場合は `(text:weight)` 形式で出力。
   * - weight === 1.0 かつ bracketDepth > 0 の場合は深度分の括弧でラップ。
   * - 余分な連続カンマや前後の空白のない、クリーンなカンマ区切り文字列を出力。
   */
  static serializeToComfyPrompt(tokens: PromptToken[]): string

  /**
   * 特定のタグ配列を除外し、トリガーワードを注入する。
   * - removeTags との一致判定は大文字小文字を区別しない (case-insensitive)。
   * - injectTrigger (単一文字列または配列) が指定された場合、指定位置 (デフォルトは先頭) に注入。
   * - captionDecoupler.ts と等価な振る舞いを担保。
   */
  static decoupleTags(
    tokens: PromptToken[],
    removeTags: string[],
    injectTrigger?: string | string[],
    options?: DecoupleOptions
  ): PromptToken[]

  /**
   * トークンの強度 (weight) を delta 分加算・調整する (0 未満にならないよう保護、小数第2位に丸め)。
   */
  static adjustWeight(token: PromptToken, delta: number): PromptToken
}
```

## 4. 既存モジュール統合設計 (Integration Design)

### 4.1 `captionDecoupler.ts` のリファクタリング

既存の `decoupleCaption(params: DecoupleParams): string` を `PromptTokenEngine` 経由に置き換える：
1. `rawPrompt` を `PromptTokenEngine.tokenize(rawPrompt)` でトークン化。
2. `PromptTokenEngine.decoupleTags(tokens, physicalTags)` で身体タグを除去。
3. `isDefaultOutfit === true` の場合、`exclusiveOutfitTags` を除去し、`[characterTrigger, outfitTrigger]` を先頭に注入。
4. `isDefaultOutfit === false` の場合、`characterTrigger` のみを先頭に注入。
5. `PromptTokenEngine.serializeToComfyPrompt(tokens)` で文字列化して返却。
これにより、従来の `CuratorGrid.test.tsx` および `e2e_req319_lora_studio.test.tsx` のアサーションを 100% 満たす。

## 6. 非機能要件 & トレードオフ

- **パフォーマンス**: 単一プロンプト (数十〜数百タグ) のパース時間を 1ms 未満に抑える線形スキャン ($O(N)$) アルゴリズムを採用。
- **ReDoS 耐性**: 複雑な入れ子正規表現のバックトラッキングを回避し、文字走査と括弧深度カウンタによる堅牢なステートマシンで実装。
- **完全な後方互換性**: 既存関数のシグネチャ・返り値フォーマットは完全に同一を維持。
