# REQ-185 テスト計画書

## 1. 概要
REQ-185（履歴・アルバム画面の表示・操作性向上）に関する検証計画です。

## 2. 自動テスト計画 (Vitest)
以下の項目を検証するユニットテストを `frontend/src/pages/__tests__/HistoryPage.test.tsx` に追加・実行します。

### テストケース
1. **サムネイルバッジ統一＆常時表示**:
   - 履歴一覧およびアルバム詳細において、サムネイル右上にセリフ編集・ダウンロード・削除ボタンが常時表示（`opacity-0` ではない状態）で配置されていること
   - ボタンIDおよびtitle属性が正しく設定され、クリックイベントが正しく発火すること
2. **アルバムソート（基準と昇順/降順の分離）**:
   - 基準（カスタム順 / 登録順）と方向（昇順 / 降順）の独立した切り替えにより、アイテム配列が適切にソートされること
   - カスタム順・昇順時のみDnDが有効化されること
3. **レスポンシブ・ツールバー**:
   - MultiSelectToolbar に `flex-wrap` が適用され、幅狭画面でも要素が折り返されること
4. **履歴画面の複数選択一括削除（2段階操作）**:
   - 複数選択時に一括削除ボタンが表示されること
   - クリックすると確認ダイアログ/モーダルが表示されること
   - 確定時に `snapshotsApi.delete` が各選択IDに対して呼び出されること
5. **アルバム削除時のスコープ選択**:
   - 単一・一括削除時に削除モーダルが表示され、「アルバムから削除」選択時は `albumsApi.deleteItems` のみが呼ばれ、「元画像ごと削除」選択時は `albumsApi.deleteItems` および `snapshotsApi.delete` が呼ばれること

### 実行コマンド
```bash
npx vitest run src/pages/__tests__/HistoryPage.test.tsx
```

## 3. 手動検証計画
1. **バッジ常時表示・配置統一**:
   - ブラウザで History 画面および Album 詳細画面を開き、ホバーせずとも右上に「セリフ編集」「ダウンロード」「削除」アイコンが見えていることを確認
2. **ソート機能**:
   - Album 詳細で「カスタム順 / 登録順」×「昇順 / 降順」を切り替え、正しく並び替わることを確認
3. **レスポンシブ**:
   - ブラウザのDevToolsで画面幅を 375px / 640px / 1024px にリサイズし、フィルタバーや複数選択バーが横スクロールアウトや画面切れを起こさず折り返して操作できることを確認
4. **一括削除・2段階確認**:
   - 履歴画面で複数選択し、「一括削除」をクリックしてモーダルが表示されること、キャンセルで閉じ、確定で削除されることを確認
5. **アルバム削除のスコープ選択**:
   - アルバムから削除する際、モーダルで「アルバムから削除」を選択した場合はスナップショット一覧に残ること、「元画像ごと削除」を選択した場合はスナップショット一覧からも削除されることを確認
