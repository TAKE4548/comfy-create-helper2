# Design Document: REQ-067 同一LoRA/タグセットを複数役割に指定した際のスナップショット保存失敗バグ

## 概要
生成ページにおいて、同一のLoRAやタグセットを複数の役割（例: `positive` と `negative`）に設定して画像を生成した際、その状態のスナップショットの保存がサーバーエラー（500 Internal Server Error）で失敗する問題を修正します。

## 根本原因
- `snapshot_loras` テーブルおよび `snapshot_tag_sets` テーブルのORMモデルおよびデータベースの定義において、それぞれ `(snapshot_id, lora_id)` および `(snapshot_id, tag_set_id)` を対象とするユニーク制約（UNIQUE）が定義されています。
- 最近のアップデートにより、同一の LoRA/タグセット を異なる役割 (`role`) に対して設定してスナップショットに保存することが可能になりましたが、ユニーク制約の対象に `role` カラムが含まれていません。
- これにより、同じ LoRA ID / タグセット ID が1つのスナップショット内で重複して登録された場合に `sqlite3.IntegrityError`（UNIQUE制約違反）が発生し、保存処理全体がロールバックされてしまいます。

## 変更内容

### 1. ORMモデル定義の修正 (`backend/app/models.py`)
- `SnapshotLora` のユニーク制約を `UniqueConstraint("snapshot_id", "lora_id", "role")` に更新します。
- `SnapshotTagSet` のユニーク制約を `UniqueConstraint("snapshot_id", "tag_set_id", "role")` に更新します。

### 2. データベースマイグレーションの追加 (`backend/app/main.py`)
- `run_migrations()` 関数内に、ユニーク制約を更新するマイグレーション処理を追加します。
- SQLAlchemy の `inspector.get_unique_constraints` を使用して、既存の `snapshot_loras` および `snapshot_tag_sets` テーブルのユニーク制約に `role` が含まれているかを判定します。
- `role` カラムが含まれていない場合、SQLiteのテーブル再定義手順に従って以下を実行します：
  1. 新しいユニーク制約 `UNIQUE(snapshot_id, lora_id, role)` / `UNIQUE(snapshot_id, tag_set_id, role)` を持った一時テーブルを作成。
  2. 既存データを移行。
  3. 旧テーブルを削除。
  4. 一時テーブルを本番テーブル名にリネーム。

---

## 懸念事項・トレードオフ
- SQLiteの制限上、`ALTER TABLE` による制約変更がサポートされていないため、テーブルの再作成およびデータコピーの処理が必要です。
- マイグレーションの実行中にデータベース接続が不安定になった場合のリスクを防ぐため、処理全体を `conn.begin()` などのトランザクションブロック内でアトミックに実行します。
- データ量が多い場合は一時テーブルへのコピーに僅かな処理時間がかかりますが、本アプリケーションのスナップショット数（通常数百〜数千件程度）であれば無視できるレベル（ミリ秒単位）です。
