# REQ-304 詳細設計書: FuguMT軽量和訳エンジン導入とドラッガブルタグチップ和訳プレビュー

## 1. 概要と背景
Prompt Surgeonおよびタグチップエディタにおいて、自然文タグや情景描写を含むプロンプトの編集作業が増加している。
しかし、従来の翻訳機能（外部クラウドAPIやローカルLLM）には以下の課題が存在していた：
1. **GPUリソース競合・コールドスタート**: ローカルLLMを用いた和訳では、画像生成側のComfyUIとVRAMを取り合い、翻訳実行に伴うモデルスワップや生成遅延が発生していた。
2. **サブメニューの表示領域制限**: タグチップのサブメニュー幅が `min-w-[220px]` と狭く、長文のタグ名や翻訳情報を表示する導線が欠如していた。
3. **固定ポップオーバーの視認性阻害**: 和訳表示が固定位置であると、編集中の背景タグやプロンプト入力欄が隠れてしまい、退避・移動させながら作業を継続できなかった。

本設計では、以下の改修を行う：
1. **CPU常駐・低遅延の英日翻訳エンジン（FuguMT / CTranslate2）の導入**:
   - バックエンドに `staka/fugumt-en-ja`（CTranslate2 int8形式）を用いたCPU常駐型の高速和訳エンジンを構築。
   - GPU VRAM消費ゼロ（0MB）、高速推論（目標20〜30ms）、およびインメモリSHA256ハッシュキャッシュによる重複翻訳抑止を実現する。
2. **タグチップサブメニューの幅拡張**:
   - サブメニューの横幅を `w-[360px]`（モバイル上限 `max-w-[calc(100vw-24px)]`）へ拡張し、ヘッダーに `[翻訳]` ボタンを新設。
3. **ドラッガブル・フローティング和訳カード（`TagChipTranslationCard`）の実装**:
   - `[翻訳]` ボタン押下により、独立したフローティング和訳プレビューカードを表示。
   - Pointer Events（`onPointerDown`, `onPointerMove`, `setPointerCapture` 等）によるPCマウス/モバイルタッチ両対応のドラッグ移動機構。
   - ヘッダー部の `touch-action: none` によるモバイル背面スクロール抑止、ビューポート境界内への移動クランプ、本文縦スクロール・テキスト選択との操作分離、1クリッククリップボードコピー、Esc/外側クリック等による安全な閉じる処理を提供する。

## 3. アーキテクチャおよびコンポーネント詳細設計

### 3-1. バックエンド FuguMT CPU和訳エンジン設計

```
[Client / UI]
      │
      ▼ POST /api/translate/prompt { prompt, source_lang: "en", target_lang: "ja", provider: "fugumt" }
[routers/translate.py]
      │
      ▼ translate_prompt(...)
[services/translation_service.py]
      ├── 1. sanitize_and_tokenize(prompt)
      ├── 2. normalize_input(chunk) & SHA256 cache lookup (TRANSLATION_CACHE)
      │      ├── Cache Hit  ──► 即時返却 (0ms)
      │      └── Cache Miss ──► 集約リスト作成
      └── 3. services/fugumt_service.py (FuguMTService: CTranslate2 + MarianTokenizer on CPU)
             └── translate_batch(missing_chunks) [intra_threads=6, 0MB VRAM]
```

#### A. `FuguMTService` (`backend/app/services/fugumt_service.py`)
- **責務**: CTranslate2 `Translator` および Hugging Face / MarianTokenizer のライフサイクル管理、CPU推論実行、および入力正規化。
- **シングルトン・遅延ロード**:
  - `get_instance()` によるシングルトン提供。
  - 初回翻訳呼び出し時または明示的な初期化時にモデル（`staka/fugumt-en-ja`）をCPU上にロード。
  - モデルディレクトリ未検出時や依存ライブラリ欠落時は `RuntimeError` をスローし、FastAPI起動自体は阻害しない。
- **CPU最適化設定**:
  - `device="cpu"`
  - `intra_threads=6`（Intel Core i5-13400FのPコア数に合致させた最適化並列スレッド数）
  - `inter_threads=1`
  - `compute_type="int8"`（int8量子化による高速推論と低メモリ消費 ~150-250MB）
- **入力正規化 (`normalize_input`)**:
  - 先頭・末尾の空白トリム、および連続する半角空白の単一空白への縮退。
- **バッチ推論 (`translate_batch(texts: List[str]) -> List[str]`)**:
  - メモリ枯渇・バッファ超過（OOM）防止のため、`MAX_BATCH_SIZE = 100` ごとにチャンク分割して安全に推論を実行。
  - 入力テキストリストをトークナイズ（`tokenizer.encode`）。
  - `translator.translate_batch(source_tokens)` により並列バッチ翻訳を実行。
  - ターゲットトークンをデコードして日本語文字列のリストを返却。

#### B. `translation_service.py` の拡張
- **プロバイダー `fugumt` の統合**:
  - `provider == "fugumt"` 分岐を追加。
  - `FuguMTService.get_instance().translate_batch(missing_chunks_list)` を呼び出し。
- **入力正規化とキャッシュ連携**:
  - チャンクごとに `normalize_input` を適用後、`get_cache_key(normalized_chunk, target_lang, provider)` で照会。
  - キャッシュミス分を一括して `translate_batch` に渡し、翻訳結果を `TRANSLATION_CACHE` に格納。
- **後方互換性**:
  - `google_cloud`, `deepl`, `llm` プロバイダーへの既存処理は一切変更せず互換性を維持。
  - デフォルトプロバイダーの判定ロジックにおいて、`fugumt` を選択可能とする。

#### C. `routers/translate.py` の拡張
- `PromptTranslateRequest` に `provider: Optional[str] = None` を追加。
- `TranslateTestRequest` の `provider` Literal型に `"fugumt"` を追加。

### 3-2. フロントエンド タグチップサブメニュー拡張設計 (`TagChip.tsx`)

#### A. サブメニュー幅の拡張
- サブメニュー外枠クラスを更新:
  - 従来: `min-w-[220px]`
  - 改修後: `w-[360px] max-w-[calc(100vw-24px)]`
- 小さな画面幅（モバイル端末等）での画面はみ出しを防止し、ゆったりとした操作領域を確保。

#### B. ヘッダーアクション行の再構成
- サブメニューヘッダーの要素構成:
  1. `input`: タグ名編集用テキストインプット（`flex-1 min-w-0`）
  2. `button`: クリップボードコピーボタン（`<Copy size={12} />`）
  3. `button`: `[翻訳]` 和訳プレビュー表示切替ボタン（新設）
  4. `button`: 有効/無効トグルボタン（`enabled ? '有効' : '無効'`）
- `[翻訳]` ボタンクリック時:
  - `isTranslationOpen` 状態をトグル反転（`setIsTranslationOpen(prev => !prev)`）。
  - 親サブメニューが閉じた際（`isMenuOpen === false`）、`isTranslationOpen` も自動的に `false` にリセット。

### 3-3. ドラッガブル・フローティング和訳カード設計 (`TagChipTranslationCard.tsx`)

#### A. コンポーネント仕様 (`TagChipTranslationCardProps`)
```typescript
export interface TagChipTranslationCardProps {
  text: string;
  onClose: () => void;
  anchorRect?: DOMRect | null;
}
```

#### B. 初期配置とビューポート境界クランプ
- **初期位置計算**:
  - `anchorRect` が渡された場合:
    - `left`: `Math.max(12, Math.min(anchorRect.left, window.innerWidth - 320 - 12))`
    - `top`: 下部スペースが十分（`anchorRect.bottom + 180 + 8 <= window.innerHeight`）なら `anchorRect.bottom + 8`、不足時は `Math.max(12, anchorRect.top - 180 - 8)`
  - `anchorRect` が未指定の場合:
    - 画面中央付近に配置。
- **ドラッグ中の境界クランプ**:
  - カード幅（320px）、カード高さ（実測または160px〜220px）に基づき、上下左右の移動可能範囲を厳格に制限:
    - `minX = 0, maxX = window.innerWidth - cardWidth`
    - `minY = 0, maxY = window.innerHeight - cardHeight`
    - `newX = Math.max(minX, Math.min(newX, maxX))`
    - `newY = Math.max(minY, Math.min(newY, maxY))`
  - **リサイズ時再クランプ**:
    - `window.addEventListener('resize', ...)` を監視し、ブラウザリサイズ時にも現在位置をビューポート内に即時再クランプ（画面外見失い防止）。

#### C. Pointer Events ドラッグ操作と操作分離
- **ドラッグハンドル（タイトルバー・ヘッダー部）**:
  - `onPointerDown`:
    - `e.currentTarget.setPointerCapture(e.pointerId)` を呼び出してポインタをキャプチャ。
    - ドラッグ開始位置と初期カード座標を記録。
    - ドラッグ状態フラグを `true` に設定。
  - `onPointerMove`:
    - ドラッグ中の場合、差分を算出してクランプされた新座標に更新。
  - `onPointerUp` / `onPointerCancel`:
    - `e.currentTarget.releasePointerCapture(e.pointerId)` を呼び出してキャプチャ解除。
    - ドラッグ状態フラグを `false` に設定し、イベントリークを完全防止。
  - スタイル: `touch-action: none`（`touch-none`）、`cursor-move select-none` を適用し、モバイルでのブラウザスクロール誤発火を確実に抑止。
- **本文領域（訳文表示・スクロール部）**:
  - `onPointerDown={(e) => e.stopPropagation()}` を設定し、本文クリックやスクロール操作がヘッダーのドラッグハンドラに伝播しないよう完全遮断。
  - `select-text`, `touch-action: auto`, `overflow-y-auto max-h-[160px]` を適用し、独立した縦スクロールおよびテキスト範囲選択を保証。

#### D. 和訳データのフェッチと状態表現
- 表示開始時に `translateApi.translatePrompt({ prompt: text, source_lang: 'en', target_lang: 'ja' })` を非同期呼び出し。
- **3つの状態表示**:
  1. **Loading**: スピナーまたは "和訳を取得中..." メッセージ表示。
  2. **Success**: 日本語訳文、クリップボードコピーボタン、文字数・キャッシュ等のメタ情報を表示。
  3. **Error / Timeout**: "和訳の取得に失敗しました" エラーメッセージと [再試行] ボタンの表示（クラッシュ完全防止）。

#### E. クリップボードコピー
- コピーボタン押下時、`navigator.clipboard.writeText(translatedText)` または `usePromptClipboardStore.copyText` を実行。
- コピー完了時、アイコンを `<Check className="text-emerald-400" />` に切り替え、1.5秒後に元に戻すフィードバックを提供。

#### F. 閉じる（Dismiss）トリガーの統合
- タイトルバー右上の `[✕]` ボタン押下。
- `Escape` キー押下（`window.addEventListener('keydown', ...)`）。
- カード外クリック検知（親サブメニュー外をクリックした際も連動）。
- 親サブメニューが閉じられた際のアンマウント連動。

## 4. 非機能要件・安全性・リソース設計

1. **GPU VRAM競合ゼロ (0MB)**:
   - CTranslate2の推論デバイスを `device="cpu"` に固定。ComfyUIの画像生成（Stable Diffusion / Flux / Anima等）とVRAMが競合せず、モデルスワップ遅延が一切発生しない。
2. **高速推論と省メモリ**:
   - `int8` 量子化により、モデルメモリ常駐サイズを約150MB〜250MBに抑制。
   - `intra_threads=6` により、CPU推論遅延 20〜30ms を達成。
3. **ReDoSおよび不正入力防止**:
   - 空文字、スペースのみ、記号連続などの入力に対して例外を発生させず、正規化と早期リターンで安全にガード。
4. **イベント伝播制御とメモリリーク防止**:
   - `document` / `window` のイベントリスナー（`pointermove`, `pointerup`, `keydown`, `click`）は、コンポーネントのアンマウント時に確実にクリーンアップされる。
