# 設計書 - REQ-098: loras.pyのreorderエンドポイントバリデーションテストの追加

## 1. 目的と概要
`PUT /api/loras/reorder` エンドポイントについて、無効なペイロード（空配列、重複ID、存在しないIDなど）が送信された場合のエッジケースおよび例外挙動を検証するテストコードを `backend/tests/test_loras.py` に追加し、APIが安全かつ安定して動作することを保証します。

## 2. テスト設計と例外挙動の定義

### AC-1: `ordered_ids` が空配列の場合のテスト
- **挙動定義**: Pydanticスキーマ `LoraReorder` 自体は空配列 `[]` を許容します。エンドポイント `reorder_loras` は空配列に対してループ処理を行わず、例外を発生させずに `204 No Content` を返却します。
- **検証手順**:
  1. 空のリスト `[]` を `ordered_ids` に持つペイロードを作成し、`PUT /api/loras/reorder` を呼び出す。
  2. レスンステータスコードが `204 No Content` であることを検証する。

### AC-2: 存在しないID・重複するIDが送信された場合のテスト
- **挙動定義 (存在しないID)**: DBに存在しないLoRA ID（例: `9999`）が送信された場合、SQLの `UPDATE` クエリは行の更新を行わず（影響行数 0）、エラーをスローせずに正常終了します。
- **挙動定義 (重複ID)**: 同一のLoRA IDが複数含まれる場合（例: `[1, 1]`）、同一レコードに対して複数回 `UPDATE` が実行され、エラーをスローせずに正常終了します。
- **検証手順 (存在しないID)**:
  1. 存在しないIDを含むリスト `[9999]` をペイロードとして `PUT /api/loras/reorder` を呼び出す。
  2. レスポンスステータスコードが `204 No Content` であることを検証する。
- **検証手順 (重複ID)**:
  1. 重複するIDを含むリスト `[1, 1]` （1は登録済みのLoRA ID）をペイロードとして `PUT /api/loras/reorder` を呼び出す。
  2. レスポンスステータスコードが `204 No Content` であることを検証する。

### AC-3: テスト実行時のデータベース整合性の検証
- **挙動定義**: 無効なペイロードによるリクエスト実行後も、データベース内の既存のLoRAデータや他の関連データ（TriggerWordSetなど）が破損・消失しないこと、および有効なIDに対する更新処理が正しく完了することを確認します。
- **検証手順**:
  1. 複数のLoRA（例: ID `1`, `2`）を事前にDBに作成する。
  2. 存在しないIDと存在するIDが混在するペイロード `[1, 9999, 2]` を送信する。
  3. APIが `204` を返し、かつ存在するLoRAの `sort_order` がそれぞれ期待通り（ID `1` の `sort_order` が `0`、ID `2` の `sort_order` が `2`）に更新されること。
  4. 事前に登録されていたLoRAの他のカラム（`model_name`, `file_path` など）が書き換わっていないことを検証する。
