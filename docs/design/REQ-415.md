# REQ-415 設計書: ノードマッピング編集時のモバイルにおけるタイトル検索パターン追加不能不具合

## 1. 概要と背景

### 1.1 現状の課題と原因分析 (5 Whys)
`MappingMasterEditModal` において、ノードマッピングのタイトル検索パターン（`titlePatterns`）を入力・管理するUIコンポーネントとして `PatternTagInput` が使用されている。
デスクトップ環境では物理キーボードのEnter押下やテキスト貼り付けによりパターンチップを追加・管理できるが、スマートフォンやタブレット（iOS Safari / Android Chrome 等）のモバイル環境において以下の操作不能不具合が発生していた：

1. **Enter押下によるフォーカス誤ジャンプと入力消失**:
   - `PatternTagInput` は `MappingMasterEditModal` の `<form>` 内に配置されている。
   - `PatternTagInput` の `<input>` 直後には、バリアント一覧リストの `custom_role_override`（Role上書き）入力欄がDOM順で並んでいる。
   - モバイル仮想キーボードは、フォーム内 `<input>` のEnterをデフォルトで「次へ (Next)」と判定し、ネイティブフォーカス移動を先行実行する。
   - その結果、Enterを押下してもタグが追加されず、直下の「Role上書き」入力欄へフォーカスが勝手に遷移してしまう。
2. **タップ操作による追加導線の欠落 (MUI-10違反)**:
   - 隣接する `FallbackParamsInput` には「追加」ボタン（`<Plus size={12} />` 付き）が存在するが、`PatternTagInput` にはタップ用ボタンが存在せず、キーボード操作のみに孤立していた。
3. **日本語IME変換確定時の誤動作リスク**:
   - 日本語入力環境において、IME変換中の変換確定Enter（`isComposing = true` または `keyCode === 229`）に対するガードがなく、誤って変換途中の未確定文字列がタグ化されるリスクがあった。
4. **フォーカス離脱 (onBlur) 時の未コミット破棄**:
   - 入力欄に文字列を入力したまま他フィールドや画面外をタップした場合、入力値が確定されず無視されていた。

### 1.2 本改修の解決方針 (AC-1〜AC-5 の達成)
本設計では、以下の改修により全受入基準を完全に達成する：
- **明示的な「追加」ボタンの設置 (`REQ-415-T1`, AC-1, AC-5)**:
  `FallbackParamsInput` とデザインを統一した `<Plus size={12} />` 付きボタン（44×44px Hit-Slop対応）を新設し、タップで `addTag` を実行可能にする。空文字または重複時は非活性（disabled）にする。
- **仮想キーボード制御 (enterKeyHint="done") とEnterフォーム遷移抑止 (`REQ-415-T1`, AC-2)**:
  `<input>` に `enterKeyHint="done"` を付与し、仮想キーボード上で確定アクションを表示させ、Enter押下時の `e.preventDefault()` によりフォーム遷移を完全に抑止する。
- **フォーカス離脱 (onBlur) 時の自動追加フォールバック (`REQ-415-T1`, AC-3)**:
  入力欄に文字列が残った状態でフォーカスが外れた場合、自動的に `addTag` を実行する（空文字・重複時は安全に無視）。
- **日本語IME確定ガード (`REQ-415-T1`, AC-4)**:
  `handleKeyDown` で `e.nativeEvent.isComposing || e.keyCode === 229` の間はタグ追加を抑止し、IME確定後の単独Enterでのみ追加を許可する。
- **SSoT仕様書の同期 (`REQ-415-T2`)**:
  `SPEC_COMMON.md`（MUI-10）および `REQ-340.md`（§3.2）に、モバイル仮想キーボード対応・タップ追加導線の設計契約を明文化する。

## 3. アーキテクチャ & 詳細設計 (Component & Logic)

### 3.1 PatternTagInput Props インターフェース (後方互換性維持)
```typescript
export interface PatternTagInputProps {
  patterns: string[]
  onChange: (patterns: string[]) => void
  placeholder?: string
  disabled?: boolean
}
```

### 3.2 変更点詳細

1. **追加ボタンの配置とUI設計 (`REQ-415-T1`, AC-1, AC-5)**:
   - `PatternTagInput` の入力ボックス（`flex-wrap` コンテナ）内の入力フィールド右側に、「追加」ボタンを配置する。
   - `FallbackParamsInput` と同一のビジュアルスタイルを適用：
     ```tsx
     <button
       type="button"
       onClick={() => addTag(inputValue)}
       disabled={disabled || !inputValue.trim() || patterns.includes(inputValue.trim())}
       aria-label="パターンを追加"
       className="relative before:absolute before:-inset-2 touch-manipulation flex items-center gap-1 px-2.5 py-1 text-xs bg-zinc-800 hover:bg-zinc-700 text-zinc-200 rounded border border-zinc-700 disabled:opacity-40 transition-colors shrink-0"
     >
       <Plus size={12} />
       <span>追加</span>
     </button>
     ```
   - **Hit-Slop & Touch-Safety**: `relative before:absolute before:-inset-2 touch-manipulation` を付与し、最小44×44pxの有効タップ領域を確保する（SPEC_COMMON §1-5-3 Hit-Slop、MUI-06/MUI-10準拠）。
   - **Form Submission Guard**: `type="button"` を明示し、親の `<form>` が誤って送信されることを防止する。

2. **input 要素の属性追加 (`REQ-415-T1`, AC-2, AC-3)**:
   ```tsx
   <input
     type="text"
     enterKeyHint="done"
     placeholder={patterns.length === 0 ? placeholder : 'パターン追加...'}
     value={inputValue}
     onChange={(e) => setInputValue(e.target.value)}
     onKeyDown={handleKeyDown}
     onBlur={() => addTag(inputValue)}
     onPaste={handlePaste}
     disabled={disabled}
     className="bg-transparent text-xs text-zinc-200 outline-none w-full"
   />
   ```
   - `enterKeyHint="done"`: モバイル仮想キーボードに「完了」または「Done」を表示させ、次フィールド（Role上書き）への誤ジャンプを抑制（AC-2）。
   - `onBlur={() => addTag(inputValue)}`: フォーカスが他のフィールドに移動した際、未確定の入力文字列を自動的にチップとして確定する（AC-3）。

3. **日本語IME確定ガード (`REQ-415-T1`, AC-4)**:
   ```typescript
   const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>) => {
     if (e.nativeEvent.isComposing || e.keyCode === 229) {
       return
     }
     if (e.key === 'Enter' || e.key === ',') {
       e.preventDefault()
       addTag(inputValue)
     }
   }
   ```
   - `e.nativeEvent.isComposing || e.keyCode === 229` の判定により、日本語IMEの漢字変換確定時のEnter押下では `addTag` を発火させない。
   - 変換確定後に再度Enterを押下したタイミングで `addTag` が発火し、`e.preventDefault()` によりフォーム送信およびフォーカス遷移を抑止する。

4. **addTag のバリデーション・重複排除 (`REQ-415-T1`, AC-5)**:
   ```typescript
   const addTag = (text: string) => {
     const trimmed = text.trim()
     if (!trimmed) {
       setInputValue('')
       return
     }
     if (!patterns.includes(trimmed)) {
       onChange([...patterns, trimmed])
     }
     setInputValue('')
   }
   ```
   - 空文字または空白のみの場合はタグを追加せず、入力欄をクリアする。
   - 既存パターンに既に含まれている場合は重複追加せず、入力欄をクリアする。

## 4. トレードオフ開示 (Trade-off Disclosure)

本改修における主要な設計上のトレードオフと決定事項は以下の通りである：

1. **追加ボタンの配置構造 (AC-1, AC-5 の達成)**:
   - **採用方針**: インライン入力ボックス（`flex-wrap` コンテナ）内の入力フィールド直後に「追加」ボタンを一体配置する。
   - **メリット**: `FallbackParamsInput` と統一された視覚的一貫性を確保し、モーダルの最大高制限（`max-h-[85dvh]`）内で縦スクロール領域を圧迫しない。
   - **代替案と却下理由**: 独立した専用フッター行を設ける案は、フォーム全体の縦幅が肥大化しモバイル表示時の視認性を損ねるため却下した。
2. **フォーカス離脱（onBlur）時の自動コミットとタップ競合の回避 (AC-3 の達成)**:
   - **採用方針**: `<input>` の `onBlur` イベントで `addTag(inputValue)` を実行し、未確定文字列を自動的にチップ化する。
   - **メリット**: モバイルユーザーが「追加」ボタンを押さずに直下のRole上書き入力欄や別要素をタップした場合でも、入力内容が確実に保存される。
   - **競合対策**: ユーザーが明示的な「追加」ボタンをタップした際、ボタンの `onClick` より先に input の `onBlur` が発火するが、`onBlur` 内で `addTag` が実行されて `inputValue` が空文字にクリアされるため、直後の `onClick` は空文字ガードにより何もしない。二重追加や状態競合は生じず、冪等性が保証される。
3. **日本語IME確定の検知方式 (AC-4 の達成)**:
   - **採用方針**: `e.nativeEvent.isComposing || e.keyCode === 229` のハイブリッド判定を採用する。
   - **メリット**: モダンブラウザ（Safari, Chrome, Firefox）の最新仕様（`isComposing`）と、一部Android端末やWebViewの仮想キーボード（`keyCode === 229`）の双方を確実に検知し、漢字変換候補確定のEnterでの誤発火を完全に抑止する。
   - **代替案と却下理由**: `isComposing` 単体のみの判定は、一部モバイル端末で未確定確定Enter時に `isComposing` が先行して false に落ちるエッジケースに対応できないため却下した。

## 5. Seam Map

本セクションでは、REQ-415におけるテストシーム（結合対象、切断対象、モック境界、Property-Based Testing判定、および障害注入）の境界設計を定義する。
本改修の対象である `PatternTagInput` は、ネットワークやDB永続化などの外部I/Oを持たない純粋なクライアント側プレゼンテーションコンポーネントである。
したがって、テストは本物の React コンポーネントツリーと実イベントハンドラをそのまま実行（Integrated）し、ブラウザの DOM イベントのみをテストランナー（jsdom / Vitest）で供給する方針を採用する。

### 5.1 シーム定義表

| 区分 | 対象 | 契約・方針 |
|---|---|---|
| **Integrated (本物のコード)** | `PatternTagInput.tsx` (React Presentation) | 実コンポーネントコードを実行。`useState`, `useRef`, `handleKeyDown`, `onBlur`, `addTag`, ボタンクリックの全インタラクションを本番コードのまま結合実行する。<br>・「追加」ボタンタップで `addTag(inputValue)` を実行しパターンチップを追加（AC-1）。<br>・`<input>` に `enterKeyHint="done"` を設定し、Enter押下時の `preventDefault()` によりフォーカス遷移を抑止（AC-2）。<br>・フォーカス離脱（Blur）時に未追加文字列を自動コミット（AC-3）。<br>・IME変換中（`isComposing` / `keyCode 229`）のEnterでは追加を抑止（AC-4）。<br>・空文字・重複時はボタンを非活性（disabled）にし、重複追加を防止（AC-5）。 |
| **Severed (切断対象)** | なし (完全ゼロI/O) | `PatternTagInput` は純粋なクライアント状態管理コンポーネントであり、外部ネットワーク・WebSocket・DBトランザクション等の外部I/Oは一切存在しない。 |
| **Mock Level** | DOMイベント層 | Vitest / `@testing-library/react` の `fireEvent` を使用して、input change, keyDown, blur, click イベントを発火。内部ロジックやヘルパーのモンキーパッチは行わない。 |
| **PBT (Property-Based Testing)** | 不採用 (境界値ユニットテストで十分) | `PatternTagInput` は文字列配列の操作およびUIイベントハンドリングであり、複雑な文法解析や巨大な数値計算空間を持たないため、Property-Based Testing (fast-check) は必須とせず、決定論的な境界ケース（空白、重複、カンマ混在、IME入力）をユニットテストで網羅する。 |
| **Fault Injection** | 非該当 | 外部サービス通信が存在しないため、HTTP 503やタイムアウト等の障害注入は対象外。 |

### 5.2 各受入基準のテスト結合方針
1. **AC-1 (ボタン追加)**: 実コンポーネントの「追加」ボタンに対する click イベント発火により、`addTag` の実ロジックが走り `onChange` が期待通り呼ばれることを検証。
2. **AC-2 (Enter制御)**: `<input>` に対する Enter キー押下イベントを発火し、`e.preventDefault()` が呼ばれ `onChange` に反映されることを検証。
3. **AC-3 (Blurフォールバック)**: `<input>` に対する blur イベントを発火し、未確定文字列が自動的に `onChange` で通知されることを検証。
4. **AC-4 (IMEガード)**: `isComposing: true` の Enter イベントで `onChange` が呼ばれないこと、および確定後の通常 Enter で呼ばれることを検証。
5. **AC-5 (非活性・重複排除)**: 空文字時および既存チップと一致する入力時に、ボタンが `disabled` 属性を持つこと、および Enter 押下でも重複が追加されないことを検証。
