# REQ-111: LoRA・タグセット管理のベースモデル使い分け機能 設計仕様書

## 1. 概要
本設計書は、LoRAやタグセットを異なるモデルアーキテクチャ（SDXL系、Anima、Pony、SD1.5等）で使い分けるための「対象ベースモデル」属性の追加、フィルタリング機能、ワークフロー毎のベースモデル紐づけ、およびチェックポイント名からの自動検出機能の実装仕様を定義します。

## 2. データベース設計 (SQLite/SQLAlchemy)

### 2.1. 新規テーブル

#### 2.1.1. `base_models` (BaseModel)
ベースモデル（マスタデータ）を保持します。
- `id`: `Integer`, PK, autoincrement
- `name`: `String`, Unique, Not Null (例: "SDXL", "Noob", "Illus", "Anima")
- `description`: `Text`, Nullable
- `created_at`: `DateTime`, Default `utcnow`

#### 2.1.2. `checkpoint_mappings` (CheckpointMapping)
チェックポイントファイル名とベースモデルのマッピングを保持します。
- `id`: `Integer`, PK, autoincrement
- `checkpoint_name`: `String`, Unique, Not Null (例: "NoobAI-XL-v1.0.safetensors")
- `base_model_id`: `Integer`, FK(`base_models.id`, ondelete="CASCADE"), Not Null
- `created_at`: `DateTime`, Default `utcnow`

#### 2.1.3. `lora_base_models` (中間テーブル)
LoRAカードとベースモデルの多対多リレーション。
- `lora_id`: `Integer`, FK(`loras.id`, ondelete="CASCADE"), PK
- `base_model_id`: `Integer`, FK(`base_models.id`, ondelete="CASCADE"), PK

#### 2.1.4. `tagset_base_models` (中間テーブル)
タグセットカードとベースモデルの多対多リレーション。
- `tag_set_id`: `Integer`, FK(`tag_sets.id`, ondelete="CASCADE"), PK
- `base_model_id`: `Integer`, FK(`base_models.id`, ondelete="CASCADE"), PK

### 2.2. 既存テーブルの拡張

#### 2.2.1. `workflows` (Workflow)
- `target_base_model_id`: `Integer`, FK(`base_models.id`, ondelete="SET NULL"), Nullable

## 3. API エンドポイント設計

### 3.1. ベースモデル CRUD (`/api/base-models`)
- `GET /api/base-models`: ベースモデル一覧の取得
- `POST /api/base-models`: ベースモデルの登録
- `PUT /api/base-models/{id}`: ベースモデルの更新
- `DELETE /api/base-models/{id}`: ベースモデルの削除

### 3.2. チェックポイントマッピング CRUD (`/api/checkpoint-mappings`)
- `GET /api/checkpoint-mappings`: マッピング一覧の取得
- `POST /api/checkpoint-mappings`: マッピングの登録・更新
- `DELETE /api/checkpoint-mappings/{id}`: マッピングの削除

### 3.3. ComfyUI チェックポイントリスト取得
- `GET /api/comfy/checkpoints`: ComfyUIから利用可能なチェックポイントファイル名の一覧を取得する。
  - バックエンドが ComfyUI の `/api/models/checkpoints` または `/api/object_info` からリストをフェッチして返す。
  - ComfyUI未起動時は空リストを返し、エラーにしない（接続警告はフロントで処理）。

### 3.4. 既存APIの拡張

#### 3.4.1. LoRA API (`/api/loras`)
- `GET /api/loras`: `base_model_ids` クエリパラメータによるフィルタリングに対応（複数指定時はOR条件）。レスポンスに `target_base_model_ids: int[]` を追加。
- `POST /api/loras` & `PUT /api/loras/{id}`: リクエストに `target_base_model_ids: int[]` を含め、関連付けを保存・更新可能にする。

#### 3.4.2. タグセット API (`/api/tag-sets`)
- `GET /api/tag-sets`: `base_model_ids` クエリパラメータによるフィルタリングに対応（複数指定時はOR条件）。レスポンスに `target_base_model_ids: int[]` を追加。
- `POST /api/tag-sets` & `PUT /api/tag-sets/{id}`: リクエストに `target_base_model_ids: int[]` を含め、関連付けを保存・更新可能にする。

#### 3.4.3. ワークフロー API (`/api/workflows`)
- `GET /api/workflows` / `GET /api/workflows/{id}`: レスポンスに `target_base_model_id: int | None` を追加。
- `POST /api/workflows` & `PUT /api/workflows/{id}`: リクエストに `target_base_model_id: int | None` を追加。

## 4. チェックポイント自動検出ロジック (Backend)

ワークフローのJSONが送信またはパースされる際、以下のロジックで対象ベースモデルの初期値を検出します。

1. **Checkpoint Loaderノードの特定**:
   - `class_type` が `CheckpointLoaderSimple` または `CheckpointLoader` であるノードを探す。
   - 上記が見つからない場合、ノード名やクラス名に `checkpoint` を含むものをフォールバック探索。
2. **ファイル名 (ckpt_name) の取得**:
   - 該当ノードの `inputs.ckpt_name` を抽出する。
3. **マッピングマッチング**:
   - **完全一致**: 取得したファイル名が `checkpoint_mappings` 内の `checkpoint_name` と完全一致する場合、対応する `base_model_id` を返す。
   - **部分一致 (推定)**: 完全一致しない場合、定義されている `base_model` ごとに、部分一致（大文字小文字を区別せず、ファイル名に含まれているか）を判定する。
   - **検出不能**: いずれも一致しない、またはノードが見つからない場合は `None` を返す。

## 5. フロントエンド設計 (React)

### 5.1. 設定画面 (`SettingsPage`)
「ベースモデル設定」タブを追加します。
1. **ベースモデル（マスタデータ）の管理**:
   - ベースモデルのCRUDグリッド。
2. **チェックポイントマッピング**:
   - マッピングデータテーブル（チェックポイント名 ⇄ ベースモデル）。
   - 新規マッピング登録時、ComfyUIから取得したチェックポイントファイル名リストをセレクトボックスで選択可能とする。

### 5.2. LoRA / タグセット管理画面
- カード登録・編集フォーム（モーダル等）に「対象ベースモデル」の複数選択チェックボックスを追加。
- アセット一覧上部にベースモデルでのフィルタ用チェックボックス（複数選択可能）を設置。

### 5.3. ワークフロー編集・生成画面 (`GeneratePage`)
- ワークフローの設定ポップアップ（またはインフォパネル）に「ターゲットベースモデル」の選択フィールドを追加（手動変更可能）。
- ワークフローインポート/パース時に、ベースモデルが自動判定された場合はそれを初期選択し、自動判定できなかった場合は「ベースモデルを検出できませんでした（ファイル名: {filename}）」という内容のToast/トースター通知を表示する。
- 生成画面の「Add Asset」ボタンで開くモーダルにおいて、アクティブなワークフローのベースモデルに対応するアセットが初期フィルタとして適用されるようにする。

## 6. トレードオフとリスクの開示 (Trade-off Disclosure)

- **ComfyUIの依存度**: チェックポイントファイル名リストはComfyUI API経由で取得するため、ComfyUIが起動していない状態では手動マッピング登録時の選択肢がテキスト直接入力になるか、または空になります。これに対処するため、ファイル名の自由入力も許可します。
- **SQLiteでの多対多テーブルのマイグレーション**: 既存の `loras` および `tag_sets` テーブルには影響を与えず、中間テーブルを追加するアプローチを取るため、データ破損のリスクは極めて低いです。
