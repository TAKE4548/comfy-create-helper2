- **判定**: **実現可能 (Feasible)**
- **背景**:
  - **Type A (実装不備 / AC-1)**: `docs/specs/SPEC_SETTINGS.md` §3-1-1 は「1行目は名称と右端固定のアクション、2行目はバッジ」の超スリムカードを規定している。しかし `SettingsResponsive.css` L159-184 が `768px` 以上で `.settings-mobile-card` を単一行 flex に上書きしており、`xl:grid-cols-2` の半幅カラム内で `MasterRow` のステージ状態バッジ（`shrink-0 whitespace-nowrap`）がタイトルを押し潰して埋没させている。

## 3. アーキテクチャ設計

### 3.1 Type A: MappingMaster 行レイアウト修正 (AC-1)
- `frontend/src/pages/SettingsPage/SettingsResponsive.css`:
  - `.req314-settings .settings-mobile-card` の基本ルール（全画面幅）を 2行 CSS Grid（`grid-template-columns: minmax(0, 1fr) auto`, `grid-template-areas: "title actions" "badges badges"`, `gap: 0.375rem 0.5rem`）に統一し、`>=768px` の単一行 flex によるタイトル圧迫を解消する。
  - 既存の `[REQ-365/AC-3]` テスト契約（`.settings-mobile-card`, `__target-node`, `td[data-cell='target-node']`, `@media (max-width: 767px)`, `grid-template-areas`, `!important` が1箇所のみ）を維持する。
- `frontend/src/pages/SettingsPage/components/MappingMasterSection.tsx`:
  - `MasterRow` のDOM構成（`__title` → `__actions` → `__badges`）は CSS Grid area により 1行目に `__title` + `__actions`（右端固定）、2行目に `__badges`（`flex-wrap`）が配置される。
  - デスクトップでも 2行目バッジが `flex-wrap` で折り返すため、複数ステージ Variant を持つ Master でも 1行目のタイトル幅（`minmax(0, 1fr)`）が確保され埋没しない。

### 3.2 Type B: `xl` 2カラム時の左右ペイン高さ整合・内部スクロール (AC-2)
- **設計方針**:
  - `SettingsPage.tsx` の `settings-workflows-grid` 既存クラス（`xl:grid-cols-2 xl:grid-rows-[auto_1fr] items-start`）は `[REQ-365/AC-1]` 互換のため維持する。
  - `xl`（`window.matchMedia('(min-width: 1280px)')` かつ `workflows` タブ表示中）において、`ResizeObserver` と `useLayoutEffect` を用い、循環計測を避けるため各ペインの**自然高さ（非リスト部分の高さ + リストの `scrollHeight`）**を算出する。
    - 左ペイン自然高さ: `(workflowCardHeight - wfListClientHeight + wfListScrollHeight) + 24 (gap-6) + basemodelCardHeight`
    - 右ペイン自然高さ: `mappingCardHeight - mpListClientHeight + mpListScrollHeight`
    - 基準高さ `targetPaneHeight = Math.min(leftNaturalHeight, rightNaturalHeight)`
  - 長い側のリストにのみ `maxHeight`（最小床 `MIN_SCROLL_LIST_HEIGHT = 240` px で折り畳み時等の潰れを防止）を設定し、短い側は `undefined`（自然高さのまま、スクロールバーなし）とする。
  - `<1280px`（モバイル・タブレット単一カラム）では双方に `undefined` を渡し、`SPEC_SETTINGS.md` §3-1-2 のページ全体縦スクロールを維持する。
- **インターフェース追加**:
  - `WorkflowConnectionSectionProps`: `workflowListMaxHeight?: number` を追加。ワークフロー一覧（`data-testid="workflow-list-scroll"`）に `overflow-y-auto overscroll-contain` および `style={workflowListMaxHeight != null ? { maxHeight: `${workflowListMaxHeight}px` } : undefined}` を適用。
  - `MappingMasterSectionProps`: `listScrollMaxHeight?: number` を追加。Master 一覧（`data-testid="mapping-master-list-scroll"`）に `overflow-y-auto overscroll-contain` および `style={listScrollMaxHeight != null ? { maxHeight: `${listScrollMaxHeight}px` } : undefined}` を適用。

## 4. Seam Map (`[W-DD-SEAM]`)

- **Integrated (real code)**: `SettingsPage`, `WorkflowConnectionSection`, `MappingMasterSection`, `SettingsResponsive.css` の実際の DOM/CSS/レイアウト計算ロジック。
- **Severed (external I/O only)**: API 通信（`workflowsApi`, `mappingMastersApi`, `llmPromptsApi` 等）および WebSocket / `localStorage` は Vitest ではモジュールモック、Playwright E2E では `page.route('/api/...')` でトランスポート層を切断する。内部レイアウト計算ロジックのモンキーパッチは禁止。
- **Mock Level**: トランスポート層（API レスポンススタブ）および JSDOM 未実装のブラウザ API（`ResizeObserver` / `matchMedia`）の境界のみ。
- **PBT Decision**: 不要（入力空間は有限の DOM 寸法・カード配列であり、パーサや数式 DSL を含まない）。
- **Fault Injection**: 異常・境界系として「片側ペインが折り畳まれて極端に低い場合でも最小床 `240px` を下回らない」「`<1280px` で内部スクロール制限が解除される」「`ResizeObserver` 非対応環境で例外を出さずフォールバックする」を検証する。

## 6. トレードオフとリスク (Trade-offs & Risks)

1. **全幅 2行カード化 vs デスクトップ単一行**:
   - トレードオフ: 2行カード化により `MasterRow` 1件あたりの縦幅が約 16〜24px 増えるが、タイトル埋没を完全に防ぎ、`SPEC_SETTINGS.md` §3-1-1 の「1行目=名称＋右端固定アクション、2行目=バッジ」と一貫する。
2. **`ResizeObserver` + 自然高さ算出 vs 固定 `max-h-[60dvh]`**:
   - トレードオフ: 固定 `max-h` だけでは右ペイン（MappingMaster）が長いときに左ペインが無駄に早期スクロールする、または右ペインが短いときに左ペインが突き抜ける問題が残る。自然高さ算出方式は DOM 計測の複雑さがわずかに増すが、AC-2「左右ペインの短いほうの高さに合わせて長いほうが内部スクロール」を正確に満たす。`ResizeObserver` 不在環境（一部テスト環境）では安全にスキップするガードを入れることでリスクを緩和する。
3. **最小床 `240px` の設定**:
   - 片側ペインがアコーディオンで折り畳まれた場合、もう片側が 0px に潰れないよう `240px` を下限とする。これにより折り畳み状態でも一覧の操作性を保つ。
