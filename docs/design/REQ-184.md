# REQ-184: モバイルモード生成画面のセクション順序およびUndo/Redo配置の最適化 詳細設計書

## 1. 概要と背景
モバイルモードの生成画面（`MobileLayout.tsx`）において、現在のセクション順序は上から「プログレスバー/プレビュー → プリセットタブ → 履歴ビュー（サムネイルストリップ） → プロンプトエリア」となっていました。
これにより、生成結果確認（プレビュー/履歴）とプロンプト入力（プリセットタブ/プロンプト）の視覚的・操作的グルーピングが分断されていました。

また、プリセットタブの下部にUndo/Redoボタンが独立行として配置されていたため、不自然な縦方向の余白（隙間）が生じ、モバイルの限られた縦画面領域を圧迫していました。

本設計では、これらを再配置して自然な操作動線と画面領域の最適化を実現します。

---

## 2. アーキテクチャ変更詳細

### 2.1 セクション順序の再配置 (`frontend/src/pages/GeneratePage/components/MobileLayout.tsx`)
JSX内のセクションレンダリング順序を以下のように変更します：
1. **メインプレビュー・プログレスバー** (`{/* Main Preview */}`)
2. **サムネイルストリップ（履歴ビュー・スナップショット）** (`{/* Thumbnail Strip */}`)
3. **Multi-Set Tab Bar（プリセットタブ・プロファイル）** (`{/* Multi-Set Tab Bar (Mobile) */}`)
4. **プロンプト入力エリア** (`{/* Active Prompt Textarea (Mobile) */}`)
5. **設定・パラメータパネル** (`{/* Mobile Settings & Parameters */}`)

### 2.2 Undo/Redo ボタンの配置最適化
- プリセットタブ下部の独立した `flex items-center justify-end` 行（余計な縦余白の原因）を削除。
- `Multi-Set Tab Bar` ヘッダー行の右側領域（`flex items-center gap-2.5`）において、「📑 管理」ボタン（`#manage-presets-btn-mobile`）の左隣の空きスペースに Undo/Redo ボタン群（`#undo-btn-mobile`, `#redo-btn-mobile`）をインライン配置。
- `activeSet` が存在する場合に表示され、クリックイベント (`undo?.(activeSet.id)`, `redo?.(activeSet.id)`) および `disabled` 制御 (`!canUndo`, `!canRedo`) を維持。
