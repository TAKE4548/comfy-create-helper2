# REQ-228: 画像プレビュー表示時のReactフックルール違反によるクラッシュ不具合の修正 - 詳細設計書

## 1. 概要 (Overview)
`frontend/src/components/HistoryModalPreview.tsx` において、モーダルが非表示状態（`isOpen: false`）から表示状態（`isOpen: true`）へと遷移した際に、Reactの「フックのルール（Rules of Hooks）」違反が発生し、`GlobalErrorBoundary` が発火して画面全体がクラッシュする不具合を解消する。

## 2. 背景・問題構造 (Problem Structure)

### 2.1 現行コードのフック配置問題
`HistoryModalPreview.tsx` の現在の実装構造：
```typescript
export function HistoryModalPreview(...) {
  // フック群 1〜26 (useState, useRef, useCallback, useEffect, useQuery, useMemo など)
  ...
  
  // L303: 条件付き早期リターン
  if (!isOpen || images.length === 0) return null

  // L331: 早期リターンの後ろに配置されたフック
  const getParamValue = useCallback((keys: string[], excludeKeys: string[] = []): string => {
    ...
  }, [effectiveParams])

  // L342-350: パラメータ算出
  const positivePrompt = getParamValue(...)
  ...

  return ( ... JSX ... )
}
```

### 2.2 発生メカニズム
- `isOpen === false` のレンダリング時: L303 で `return null` となるため、フックは 26 個のみ実行される。
- `isOpen === true` のレンダリング時: L303 を通過し、L331 の `getParamValue = useCallback(...)`（27個目のフック）が呼び出される。
- React は同一コンポーネントにおけるレンダリング間のフック数の不一致（26個 → 27個）を検知し、`Error: Rendered more hooks than during the previous render.` 例外を送出。
- これがトップレベルの `GlobalErrorBoundary` に捕捉され、画面全体が「システムエラーが発生しました」画面に遷移する。

## 3. 修正設計 (Design Architecture)

### 3.1 フック配置の是正 (Top-Level Execution)
Reactの原則「すべてのフックはコンポーネントのトップレベルで、いかなる早期リターンよりも前に無条件で実行されなければならない」に従い、`getParamValue`（`useCallback`）の定義を L303 の早期リターン（`if (!isOpen || images.length === 0) return null`）の**前**に移動する。

```typescript
export function HistoryModalPreview(...) {
  // 1. すべての useState, useRef, useCallback, useEffect, useQuery, useMemo を定義
  ...
  const loraStacks = useMemo(...)

  // Helper to extract values from params dictionary (早期リターン前に配置)
  const getParamValue = useCallback((keys: string[], excludeKeys: string[] = []): string => {
    if (!effectiveParams) return ''
    const matchKey = Object.keys(effectiveParams).find((key) => {
      const k = key.toLowerCase()
      const matchesInclude = keys.some((target) => k.includes(target.toLowerCase()))
      const matchesExclude = excludeKeys.some((target) => k.includes(target.toLowerCase()))
      return matchesInclude && !matchesExclude
    })
    return matchKey ? String(effectiveParams[matchKey]) : ''
  }, [effectiveParams])

  // 2. すべてのフック宣言が完了した後に、条件付き早期リターンを実行
  if (!isOpen || images.length === 0) return null

  // 3. レンダリング用変数の評価およびJSX返却
  const handleTouchStart = ...
  const handleTouchEnd = ...
  const positivePrompt = getParamValue(...)
  ...

  return ( ... )
}
```

### 3.2 SSoT・依存性への影響分析
- APIコントラクト変更: なし（完全なフロントエンド内部コンポーネントのロジック是正）。
- 他コンポーネントへの波及影響: なし（`HistoryModalPreview` のインターフェース `HistoryModalPreviewProps` や返却JSX構造に変更はない）。
- リファクタリングによる副作用: `getParamValue` は `effectiveParams` に依存するメモ化コールバックであり、早期リターン前に実行されても副作用や不要なオーバーヘッドは発生しない。

## 4. テスト設計 (Test Strategy)

### 4.1 ユニットテスト (`HistoryModalPreview.test.tsx`)
既存のテストは初回から `isOpen: true` でレンダリングされていたため、開閉時のフック不整合を検知できていなかった。以下のテストケースを追加する：
1. **モーダル開閉遷移テスト（Red Teaming / Regression Check）**:
   - `isOpen: false` で初期レンダリングを実行（早期リターンを通過させる）。
   - `rerender` を使用して `isOpen: true` に更新。
   - `Rendered more hooks than during the previous render.` エラーがスローされず、モーダル要素が正常にDOMにマウントされることを検証する。
