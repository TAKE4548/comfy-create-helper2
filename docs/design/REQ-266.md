# 設計書 - REQ-266: 非アクティブ放置時のComfyUI接続切断防止と自動再接続・復帰の保証

## 1. 目的と概要
`npm run build` による本番フロントエンド配信環境（FastAPI 単一プロセスホスティング、Port 8000）において、ブラウザタブを非アクティブ（バックグラウンド化・別ウィンドウ操作・端末スリープ等）にして一定時間（約5分以上）放置すると、ComfyUI との WebSocket 接続が切断され、画面を手動リロード（F5）するまで切断状態のまま膠着する不具合が発生していました。

本設計では、以下の3つの多層防御を導入し、手動リロードを一切必要としない自律的かつ堅牢な接続維持・回復機構を確立します：
1. **定期キープアライブ（Ping）によるアイドル切断防止**:
   - `ComfyWebSocketService` にハートビートタイマー（25秒間隔）を導入し、接続中に定期的な Ping フレームを送信することで、Chromium や OS のアイドルソケット回収および NAT タイムアウトを能動的に防止する。
   - 万が一ハーフオープン（死活検知漏れ）が発生した場合でも、次回の Ping 送信試行時のエラーによって即座に異常切断を能動検知する。
2. **エラー耐性および指数バックオフを備えた自動再接続ループ**:
   - `connectionSlice.ts` において、`onClose` だけでなく `onError` 発生時にも確実に再接続をスケジュールする。
   - 再接続間隔に指数バックオフ（1s → 2s → 4s → 8s → 最大15s）を採用し、一時的なサーバー負荷やネットワーク不安定時でもループが停止せず継続的に再試行する。接続成功（`onOpen`）時にバックオフ間隔をリセットする。
3. **タブ復帰時（VisibilityChange / Window Focus）の即時再接続保証**:
   - `useGenerateDisplayState.ts` のタブ復帰イベントハンドラにおいて、WebSocket が未接続状態（`!isConnected` または socket readyState が OPEN でない）であることを検知した場合、待機タイマーを待たずに即座に `store.initialize({ force: true })` を呼び出して再接続をトリガーする。

## 2. アーキテクチャ設計

### 2.1 レイヤー構成と責務分離
```
[Page / Hook Layer]
  useGenerateDisplayState.ts
    - visibilitychange / focus イベント監視
    - タブ復帰時に !isConnected を検知したら即時 store.initialize({ force: true }) を発火

[Store Layer]
  connectionSlice.ts
    - isConnected, comfyUrl の状態管理
    - initialize(options?: { force?: boolean }): ソケット状態検証と in-flight 排他制御
    - onClose / onError: 指数バックオフ計算と再接続タイマーの統合スケジューリング
    - onOpen: 指数バックオフのリセットと最新キュー照会

[Service Layer]
  comfyWebSocketService.ts (Singleton)
    - WebSocket インスタンス保持とライフサイクル管理
    - ハートビート（25秒間隔 Ping）の起動・停止
    - リトライカウントおよび指数バックオフ遅延の計算管理
```

### 2.2 ハートビート / キープアライブ仕様
- **周期**: 25,000ms（25秒）。一般的なルーター/NAT のアイドルタイムアウト（30〜60秒）より短い間隔で送信。
- **ペイロード**: `JSON.stringify({ type: 'ping' })`
- **動作フロー**:
  - `ws.onopen` 時に `startHeartbeat()` を呼び出し、`setInterval` を開始。
  - `ws.onclose`, `ws.onerror`, `disconnect()` 時に `stopHeartbeat()` を呼び出し、確実にタイマーを解放。
  - 送信時にソケットが `OPEN` 状態でない、または `ws.send()` が例外をスローした場合、安全にキャッチして切断ハンドラへフォールバック。

### 2.3 指数バックオフ再接続仕様
- **基本間隔**: 1,000ms（1秒）
- **増加係数**: 2倍（1s → 2s → 4s → 8s → 15s）
- **最大上限**: 15,000ms（15秒）
- **ジッター**: `Math.random() * 500ms` の揺らぎを付加し、複数クライアントの一斉アクセス競合を緩和。
- **リセット条件**: `ws.onopen` コールバック実行時にリトライカウントを 0 にリセット。

### 2.4 タブ復帰時（VisibilityChange / Focus）の高速回復仕様
- ユーザーがブラウザタブへ復帰した際（`document.visibilityState === 'visible'` または `window.onfocus`）：
  1. `store.isConnected === false`、またはソケットの `readyState !== WebSocket.OPEN` を確認。
  2. 条件を満たす場合、既存の遅延タイマーをクリアし、即座に `store.initialize({ force: true })` を実行。
  3. 続いて REST API によるキュー照会（`store.fetchQueue()`）および履歴照会（`store.fetchHistory()`）を実行し、非アクティブ中に完了した生成結果をシームレスに同期。
