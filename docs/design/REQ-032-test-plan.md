# テスト計画 - REQ-032: 生成画面での新規ワークフローアップロード・登録機能の追加

## 1. 自動テスト / 検証コマンド
フロントエンドのコードビルド及び静的解析（リンター）を実行し、型定義エラーやビルド違反がないことを検証します。

### フロントエンドの検証
```bash
cd frontend
npm run lint
npm run build
```

## 2. 手動検証シナリオ

### シナリオ 1: アップロード用ドロップゾーン（左ペイン）の確認
1. アプリケーションを起動し、ブラウザで生成（Generate）画面を開く。
2. ワークフロー選択ドロップダウンの初期選択項目が「+ 新しいワークフローを追加 (Upload New...)」であることを確認する。
3. 左ペイン（パラメータ入力欄が表示されるエリア）に、ドラッグ＆ドロップ用点線エリア（JSONアイコン等を含むプレミアムなデザイン）が表示されていることを確認する。

### シナリオ 2: ファイルドロップ / クリックでのアップロード動作
1. 以下のいずれかの方法でJSONファイル（例: `sdxl_base.json`）をロードする：
   - ローカルファイルを左ペインのドロップゾーンへドラッグ＆ドロップする。
   - ドロップゾーンをクリックし、立ち上がったファイル選択ダイアログからファイルを選択する。
2. ロード完了後、`UploadWorkflowModal` が自動的に立ち上がることを確認する。
3. モーダル内に自動スキャン結果とワークフロー名入力欄が表示されることを確認する。

### シナリオ 3: マッピング登録と自動切り替え
1. モーダル内のワークフロー名に `sdxl_base` を指定し、「登録」ボタンをクリックする。
2. モーダルが閉じ、ワークフロー選択ドロップダウンの選択が自動的に `sdxl_base` に切り替わっていることを確認する。
3. ドロップゾーンが非表示になり、追加されたワークフローに対応するパラメータ入力欄（プロンプト等）が左ペインに正しく描画されていることを確認する。

### シナリオ 4: 名前の重複エラーの確認
1. 再びドロップダウンで「+ 新しいワークフローを追加 (Upload New...)」を選択し、アップロード画面にする。
2. 同じJSONファイルをロードし、名前 `sdxl_base` のまま登録を試みる。
3. モーダル内に赤字でエラーが表示され、モーダルが閉じないことを確認する。
