# 設計書: REQ-250 プリセット一括編集適用時におけるアクティブプリセットおよび開いているタブセットのプロンプトチップ同期適正化

## 1. 設計概要 (Architecture Overview)

本設計は、Prompt Surgeon の GeneratePage において、プリセットの一括編集（Bulk Edit）実行時に「現在アクティブなプリセット」が含まれていた場合、一括編集完了後に画面上のプロンプト表示（`TagChipEditor`）および画像生成用の有効プロンプト（`getEffectiveParamValues()`）に編集後の最新プロンプトが即時反映されない不具合（インシデント報告 `docs/incident_report.md` 参照）を根本的に解決する。

### 課題と解決アプローチ

1. **アクティブプリセットの `promptChips` 同期欠落**:
   - **課題**: `usePresetState.ts` の `handleBulkEditApply` では `setParamValues`・`setAppliedAssets`・`setBatchSize`・`updateActiveSet` を行っているが、UI表示や生成で優先される `promptChips` のパースおよびストアへの同期（`setPromptChips` / `setAllPromptChips`）が欠落している。
   - **解決策**:
     - `multiSetSlice.ts` および `types.ts` に全ロールのチップを一括更新するアクション `setAllPromptChips: (promptChips: Record<string, TagChip[]>) => void` を新設。
     - `handleBulkEditApply` において、更新されたアクティブプリセットの `param_values` から `parseToChips(val)` を用いて全ロールの `promptChips` を再構築し、`setAllPromptChips` を呼び出す。
     - これにより、Zustand ストアの `promptChips` の参照が更新され、`DesktopLayout` / `MobileLayout` 経由で `TagChipEditor` の `chips` prop の参照変化（`chipsProp !== prevChipsProp.current`）がトリガーされ、コンポーネント内ステートおよびテキストが即時同期される。

2. **開いているタブセットコレクション（`sets`）への更新未伝播**:
   - **課題**: 一括編集で複数プリセットが更新された際、アクティブ以外の開いているタブ（`sets` 内に保持されているプリセット）のメモリ内データ（`paramValues`, `appliedAssets`, `batchSize`, `promptChips`）が更新されない。
   - **解決策**:
     - `handleBulkEditApply` において、`updatedResults` のプリセットマップを作成し、現在開いている `sets` 配列に含まれる各セットについて、更新後の `param_values`・`applied_assets`・`batch_size`・パース済み `promptChips` をマッピングして一括更新（`setSets`）する。
     - これにより、一括編集後に別タブを選択した場合でも、編集前の古い状態が表示されることなく、常に最新の編集結果が反映される。

3. **Autosave / 衝突検知との整合性確保**:
   - **課題**: ローカルステート更新時に `lastSavedStateRef` との差分が生じると、Autosave のタイマー（1000ms）による不要な自動上書きや衝突誤検知が生じる懸念がある。
   - **解決策**:
     - 一括編集適用時に、更新された最新値を用いて `lastSavedStateRef.current[activePreset.id]` を正しく更新し、`isStateEqual` でクリーン判定となる状態を維持する。
     - サーバー側の `updated_at` を `presetUpdatedAtRef` に格納し、SSoT との整合性を担保する。

## 2. アーキテクチャとデータフロー (Architectural Data Flow)

```
[ProfileBulkEditModal]
       │
       │ onApply(payload)
       ▼
[usePresetState.handleBulkEditApply]
       │
       ├─ (1) Promise.all(workflowPresetsApi.update(...)) ──> [Backend DB]
       │
       ├─ (2) 各プリセットの param_values から parseToChips で promptChips を生成
       │
       ├─ (3) sets 配列内の該当プリセット群を一括更新 (setSets)
       │       └─ 複数タブで開かれているプリセットの paramValues & promptChips を最新化
       │
       ├─ (4) 対象に activeSetId が含まれる場合:
       │       ├─ setParamValues(newParamValues)
       │       ├─ setAppliedAssets(newAppliedAssets)
       │       ├─ setBatchSize(newBatchSize)
       │       ├─ setAllPromptChips(newPromptChips)  <── [NEW!]
       │       │    └─ updateActiveSet({ promptChips })
       │       └─ lastSavedStateRef の同期更新
       │
       ├─ (5) TanStack Query キャッシュ更新 (qc.setQueryData, qc.invalidateQueries)
       │
       ▼
[useGenerationStore]
       │
       ├─ promptChips (新規オブジェクト参照)
       │       │
       │       ├─> [DesktopLayout / MobileLayout]
       │       │        │ chips={promptChips?.[role]}
       │       │        ▼
       │       │   [TagChipEditor]
       │       │        │ chipsProp !== prevChipsProp.current 検知
       │       │        └─> setChips(chipsProp, false) & setTextValue(...) ──> [画面に即時反映]
       │       │
       │       └─> getEffectiveParamValues()
       │                └─> 最新の chipsToString(chips) を採用 ──> [画像生成時も最新プロンプト]
       │
       └─ sets (最新の paramValues & promptChips を保持)
               └─> タブ切り替え時も常に最新データを維持
```

## 3. モジュール別詳細設計 (Detailed Module Design)

### 3.1 `frontend/src/store/types.ts`
- `MultiSetActions` インターフェースに `setAllPromptChips` を追加：
```typescript
export interface MultiSetActions {
  // ...既存
  setPromptChips: (role: string, chips: TagChip[]) => void;
  setAllPromptChips: (promptChips: Record<string, TagChip[]>) => void; // NEW
  // ...
}
```

### 3.2 `frontend/src/store/slices/multiSetSlice.ts`
- `createMultiSetSlice` 内に `setAllPromptChips` を実装：
```typescript
    setAllPromptChips: (promptChips) => {
      set({ promptChips })
      get().updateActiveSet({ promptChips })
    },
```
- 既存の `setPromptChips` と同様に、ストアの `promptChips` を更新すると同時に `updateActiveSet({ promptChips })` を呼び出してアクティブセットにも反映する。

### 3.3 `frontend/src/pages/GeneratePage/hooks/usePresetState.ts`
- `parseToChips` を `../../../components/TagChipEditor/useChipParser` からインポート（または既存インポートを確認）。
- `handleBulkEditApply` 内での状態同期を以下のように改修：

```typescript
      const defaultParams = workflow ? getInitialParams(workflow) : {}
      const resultMap = new Map(updatedResults.map((p) => [p.id, p]))

      // 1. 開いている sets 配列内に含まれる更新プリセットを一括同期
      const currentSets = storeRef.current.sets || []
      const updatedSets = currentSets.map((s) => {
        const updatedPreset = resultMap.get(Number(s.id))
        if (!updatedPreset) return s

        const mergedParams = { ...defaultParams, ...(updatedPreset.param_values || {}) }
        const chips: Record<string, TagChip[]> = {}
        for (const [role, val] of Object.entries(mergedParams)) {
          if (val) {
            chips[role] = parseToChips(val)
          }
        }
        return {
          ...s,
          name: updatedPreset.name || s.name,
          paramValues: mergedParams,
          appliedAssets: updatedPreset.applied_assets || {},
          batchSize: updatedPreset.batch_size ?? s.batchSize,
          seedMode: (updatedPreset.seed_mode as 'random' | 'fixed') || s.seedMode,
          seed: updatedPreset.seed !== undefined ? updatedPreset.seed : s.seed,
          promptChips: chips,
        }
      })
      storeRef.current.setSets?.(updatedSets)

      // 2. アクティブプリセットが含まれていた場合、個別ステートおよび promptChips を即時同期
      const activeUpdatedPreset = updatedResults.find(
        (p) => String(p.id) === String(activeSetId)
      )
      if (activeUpdatedPreset) {
        const mergedParams = { ...defaultParams, ...(activeUpdatedPreset.param_values || {}) }
        const initialPromptChips: Record<string, TagChip[]> = {}
        for (const [role, val] of Object.entries(mergedParams)) {
          if (val) {
            initialPromptChips[role] = parseToChips(val)
          }
        }

        lastSavedStateRef.current[activeUpdatedPreset.id] = {
          paramValues: mergedParams,
          appliedAssets: activeUpdatedPreset.applied_assets || {},
          batchSize: activeUpdatedPreset.batch_size ?? 1,
          seedMode: (activeUpdatedPreset.seed_mode as 'random' | 'fixed') || 'random',
          seed: activeUpdatedPreset.seed !== undefined ? activeUpdatedPreset.seed : 42,
        }

        setParamValues(mergedParams)
        setAppliedAssets(activeUpdatedPreset.applied_assets || {})
        if (activeUpdatedPreset.batch_size !== undefined) {
          setBatchSize(activeUpdatedPreset.batch_size)
        }
        if (activeUpdatedPreset.seed_mode) {
          setSeedMode(activeUpdatedPreset.seed_mode as 'random' | 'fixed')
        }
        if (activeUpdatedPreset.seed !== undefined) {
          setSeed(activeUpdatedPreset.seed)
        }

        // 全ロールの promptChips を一括更新
        storeRef.current.setAllPromptChips?.(initialPromptChips)
      }
```

## 4. 影響範囲とリスク分析 (Impact & Trade-offs)

### 4.1 影響範囲
- `frontend/src/store/types.ts`: `MultiSetActions` への型追加（後方互換性あり）。
- `frontend/src/store/slices/multiSetSlice.ts`: `setAllPromptChips` の追加（副作用なし）。
- `frontend/src/pages/GeneratePage/hooks/usePresetState.ts`: `handleBulkEditApply` のローカル同期処理の改善。

### 4.2 トレードオフの開示 (Trade-off Disclosure)
- **計算コスト**: 一括編集適用時に各プリセットのプロンプト文字列を `parseToChips` でパースする処理が加わるが、一括編集は数件〜数十件規模であり、正規表現分割および文字列マッピングは数ミリ秒以下で完了するため、UIのフレームレートや応答性に与える影響は皆無である。
- **TagChip の ID 再生成**: `parseToChips` は各チップにランダムなユニーク ID を新規採番する。一括編集はプロンプト内容自体の置換・追加・削除であるため、チップ ID の再採番は自然であり、`TagChipEditor` の再レンダリング時に正しく新しいチップ群として再構築される。
