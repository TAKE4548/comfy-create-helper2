# REQ-187: アルバム詳細画面におけるカスタム順・降順でのドラッグ＆ドロップ並び替え対応 詳細設計書

## 1. 概要と背景
REQ-185 においてアルバム詳細画面でソート基準（カスタム順 / 登録日時）とソート方向（昇順 / 降順）が独立して設定可能になりましたが、ドラッグ＆ドロップ（DnD）によるアイテム並び替えが「カスタム順・昇順」時のみに制限されていました。
本設計では、ソート方向が「降順」の場合でもカスタム順であれば直感的にドラッグ＆ドロップによる並び替えを可能にし、画面上の表示順序とバックエンドの順序インデックス（`sequence_order`）を双方向で正しく同期・永続化する仕組みを策定します。

---

## 2. アーキテクチャ・UI設計詳細

### 2.1 DnD 有効化条件の緩和
- **対象ファイル**: `frontend/src/pages/HistoryPage.tsx`
- **変更前**:
  ```typescript
  const isDndEnabled = albumSortCriterion === 'custom' && albumSortDirection === 'asc' && !updateAlbumOrder.isPending
  ```
- **変更後**:
  ```typescript
  const isDndEnabled = albumSortCriterion === 'custom' && !updateAlbumOrder.isPending
  ```
- **影響**:
  - ソート基準が「カスタム順（`custom`）」であれば、ソート方向が「昇順（`asc`）」でも「降順（`desc`）」でもアイテムカード上のドラッグハンドル（`GripVertical`）が表示され、`SortableItem` によるドラッグ＆ドロップ操作が可能となる。

### 2.2 降順表示時の順序同期ロジック（`handleDragEnd`）
- **対象ファイル**: `frontend/src/pages/HistoryPage.tsx`
- **データ構造仕様**:
  - バックエンド（DB）の `sequence_order` は `0, 1, 2, ...` の昇順で管理される。
  - フロントエンド表示:
    - 昇順（`asc`）: `a.sequence_order - b.sequence_order`（画面先頭 = `sequence_order` 0）
    - 降順（`desc`）: `b.sequence_order - a.sequence_order`（画面先頭 = `sequence_order` 最大値）
- **並び替え後の永続化ペイロード生成**:
  - ドラッグ＆ドロップによって得られた画面上のアイテム配列を `newItems` とする。
  - バックエンド API `albumsApi.updateOrder(albumId, snapshotIds)` は、渡された配列のインデックス順に `sequence_order = 0, 1, 2, ...` を再付与する仕様である。
  - したがって：
    - `albumSortDirection === 'asc'` の場合:
      `updatedSnapshotIds = newItems.map(item => item.snapshot_id)`
    - `albumSortDirection === 'desc'` の場合:
      `updatedSnapshotIds = newItems.map(item => item.snapshot_id).reverse()`
  - これにより、画面先頭（index 0）に配置されたアイテムが最も大きい `sequence_order`（末尾 index）となり、降順表示を再計算した際にも画面上の見た目通りの順序が完全に維持される。

### 2.3 複数選択モード時のグループ移動
- 複数選択モードにおいて選択されたアイテム群をまとめてドラッグ移動する場合も同様に、画面上の配置順序配列 `newItems` を生成後、`albumSortDirection === 'desc'` の場合は `.reverse()` を適用して API に送信する。

### 2.4 オプティミスティック更新の整合性
- `updateAlbumOrder` の `onMutate` において、`snapshotIds`（常に昇順の `sequence_order` に対応する ID 配列）に基づいて `previousAlbum.items` の `sequence_order` を更新する。
- 画面側の `sortedAlbumItems` は `albumSortDirection` に従って自動再計算されるため、オプティミスティック更新時も画面上の並び順が瞬時に反映され、チラつきなくスムーズに表示が更新される。

---

## 3. 影響範囲とリスク分析 (Trade-off & Risk Disclosure)

### 影響範囲
- `frontend/src/pages/HistoryPage.tsx` のみ（バックエンド API および DB スキーマの変更は不要）。

### トレードオフ・リスク
- **ページネーション/遅延読み込み（`albumItemLimit`）との兼ね合い**:
  - 現在の実装では `visibleAlbumItems`（初期 24 件、スクロールで追加）が表示される。
  - 全アイテムがロードされていない状態で DnD を行う場合、すでに読み込まれているアイテム内での並び替えとなる（これは既存の昇順 DnD と同等の挙動）。全件並び替えを行う場合はスクロールして全アイテムを読み込む必要がある。

## 4. Acceptance Criteria (受入基準)
- [ ] **AC-1**: アルバム詳細画面で「カスタム順」かつ「降順」選択時にも、アイテムカードに並び替えハンドルが表示され、DnD 操作が可能であること。
- [ ] **AC-2**: 「カスタム順」かつ「降順」表示時に単一アイテムをドラッグ＆ドロップで移動した際、画面上の並び順通りに順序が更新・永続化され、再読み込み後も意図した順序が維持されること。
- [ ] **AC-3**: 複数選択モード時（グループ移動）においても、「カスタム順」かつ「降順」で選択アイテム群のドラッグ移動が正常に動作すること。
- [ ] **AC-4**: 「カスタム順・昇順」時の既存の並び替え動作および「登録日時」ソート時の動作にデグレーションが発生しないこと。
