# PBI-163: プリセット別プロンプト・パラメータのSSoT確立とBE楽観的ロック（OCC）による同期修正

## 1. 概要 (Overview)
本設計は、ワークフローごとの単一LocalStorageキーに起因するプロンプト混同・破壊的オートセーブ問題を根本解決し、バックエンドDB（`workflow_presets`）を真のSSoT（Single Source of Truth）として各プリセットのプロンプトおよびパラメータを独立して永続化するとともに、**バックエンド主導の楽観的並行性制御（Optimistic Concurrency Control / 楽観的ロック）** によって、複数デバイス間（PCとスマホなど）の放置・同時編集による過去データ上書き（タイムマシン現象）を確実に防止するためのアーキテクチャ設計である。

---

## 2. アーキテクチャ設計 (Architecture & Data Flow Design)

### 2.1 課題と解決の構造

```
【従来（問題の構造）】
  [Set 1 編集] ──► Zustand paramValues ──► 単一LSキー (prompt-surgeon-params-wf-1) [上書き]
  [Set 2 切替] ──► Zustand paramValues ──► 単一LSキー (prompt-surgeon-params-wf-1) [Set2で上書き]
                                                │
  [他端末/リロード] ◄───────────────────────────┘ (Set 2の内容をSet 1として読み込み)
        │
        └─► オートセーブ発火 (1秒後) ──► PUT /api/workflow-presets/1 (Set 1のDBをSet 2で破壊!)
```

```
【刷新後: BE楽観的ロック（OCC）＋ SSoT確立構造】
  [バックエンドDB (workflow_presets)] ◄───【絶対的な SSoT / 判定基準点】
        │  - updated_at (UTCタイムスタンプ) を保持
        │
        ├─ (1) データ取得 (PC / スマホ):
        │      GET /api/workflow-presets ──► DBから最新データと updated_at (例: T1) を取得
        │      lastSyncedUpdatedAt[presetId] = T1 として保持
        │
        ├─ (2) スマホで編集・保存 (T2時点):
        │      PUT /api/workflow-presets/1 { base_updated_at: T1, param_values: "スマホの変更" }
        │      BE: DBの updated_at (T1) <= base_updated_at (T1) なので更新成功！
        │          DBの updated_at を T2 に更新
        │
        ├─ (3) PC（開きっぱなし・T1のまま放置）が後からオートセーブしようとした場合:
        │      PUT /api/workflow-presets/1 { base_updated_at: T1, param_values: "PCの古いデータ" }
        │      BE: DBの updated_at (T2) > base_updated_at (T1) を検知！
        │          👉 【409 Conflict (競合)】を返却し、古いデータによる上書きを拒否！
        │
        └─ (4) FE (PC) の競合リカバリー:
               409 Conflict を受信すると、React Query の queryClient.invalidateQueries を実行し、
               サーバーの最新データ (T2のスマホ編集分) を自動再取得して画面を安全に最新化。
```

## 3. 詳細コンポーネント設計 (Detailed Component Design)

### 3.1 バックエンド設計 (`backend/app/`)

1. **`models.py` (`WorkflowPreset`)**:
   - `updated_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)` を追加。
2. **`schemas/preset.py`**:
   - `WorkflowPresetRead`: `updated_at: datetime` を追加。
   - `WorkflowPresetUpdate`: `base_updated_at: Optional[datetime] = None` を追加。
3. **`routers/presets.py` (`PUT /api/workflow-presets/{id}`)**:
   - 楽観的ロックの判定ロジック:
     ```python
     if payload.base_updated_at is not None and preset.updated_at is not None:
         if preset.updated_at > payload.base_updated_at:
             raise HTTPException(
                 status_code=status.HTTP_409_CONFLICT,
                 detail="Preset was updated by another session. Please reload to get the latest changes."
             )
     ```
   - フィールド更新後に `preset.updated_at = datetime.utcnow()` をセット。
4. **`main.py` (`run_migrations`)**:
   - SQLiteテーブル `workflow_presets` に `updated_at` カラムが存在しない場合の自動マイグレーションを追加。

---

### 3.2 フロントエンド設計 (`frontend/src/`)

1. **`frontend/src/api/types.ts` & `client.ts`**:
   - `WorkflowPreset` 型に `updated_at: string` を追加。
   - `WorkflowPresetUpdate` 型に `base_updated_at?: string` を追加。

2. **`frontend/src/store/useGenerationStore.ts`**:
   - ワークフロー単位の単一LocalStorageキー (`LS_KEYS.PARAMS_PREFIX`, `LS_KEYS.APPLIED_ASSETS`) への書き込み全廃。
   - `setParamValues`, `addAppliedAsset`, `removeAppliedAsset`, `toggleAppliedAsset`, `setAppliedAssets` を純粋なストアステートおよび `updateActiveSet` の更新処理に簡素化。
   - `setSelectedWorkflowId` およびストア初期化部において、単一LocalStorageからのパラメータ読み込みを削除。

3. **`frontend/src/pages/GeneratePage/hooks/useWorkflowParams.ts`**:
   - マウント時の `useEffect` で `localStorage.getItem(LS_KEYS.PARAMS_PREFIX + workflow.id)` から `paramValues` を上書きしていた処理を削除。
   - ワークフロー定義からのデフォルトパラメータ抽出（`getInitialParams`）に純化。

4. **`frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts`**:
   - **プリセット初期同期**:
     - バックエンドの `presets` クエリ結果をベースに `rawMappedSets` を構築。
     - 初期ロード時はアクティブプリセットのDBデータから確実に `paramValues` 等を初期化。
     - `lastSavedStateRef.current[targetActiveId]` を初期化し、初期同期による不要なオートセーブを抑止。
   - **OCC対応オートセーブ**:
     - 差分検知時のみ1秒デバウンスで実行。
     - `updatePresetMutation` に `base_updated_at: activePreset.updated_at` を付与して送信。
     - **409 Conflict 受信時の処理**: `onError` で 409 を検知した際、`qc.invalidateQueries({ queryKey: ['workflow-presets', selectedWorkflowId] })` を即時実行してサーバーの最新データを取得し、画面を最新化。
   - **プリセット切り替え**:
     - 切り替え先プリセットのデータをロードし、`lastSavedStateRef` を即時更新。

## 5. Trade-off Disclosure (トレードオフとリスク)

1. **BE基準の楽観的ロックによる安全性と端末時計非依存**:
   - サーバーの `updated_at` を比較基準とするため、PCとスマホの端末時計のズレによる誤動作リスクは完全にゼロになります。
2. **競合発生時の挙動（最新サーバーデータの優先）**:
   - PCを開きっぱなしにしてスマホで編集した場合、PCが古いデータで上書き保存しようとすると BE が 409 で安全にブロックし、PC側はスマホの最新データを自動取得します。これにより「意図せぬ過去データへの巻き戻り」が確実に防止されます。
