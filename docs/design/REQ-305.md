# Design Document: REQ-305 デスクトップ生成画面におけるグローバルヘッダー全幅昇格および左ペインツールバー順序整理

## 1. Summary & Background
REQ-300においてプリセットタブバー（`#desktop-preset-tabs-bar`）を左右2ペイン直上の親階層（画面全幅）へ昇格させたが、本来の画面全体のヘッダー（「Generate」タイトル、接続ステータス、ワークフロー選択プルダウン、Settingsボタン等）が左ペイン（`leftPane`）の内部に閉じ込められたままになっていた。
これにより、「タブバーの下にヘッダーがある」という視覚的・階層的逆転現象が発生していた。
また、左ペイン最上部のツールバー（`#left-pane-toolbar`）において、`justify-between` により要素が両端に分散配置されていたため、ペイン幅を広げた際に「Add Set」「管理」ボタンが右端へ引き離され、マウス移動と視線走査の負荷が増大していた。

本設計では以下の2点を構造的に是正する：
1. **Global Header の全幅昇格 (Information Design)**: 左ペインからヘッダー要素をルートコンテナ最上位（画面幅100%）へ移動し、①最上位グローバルヘッダー（全幅） → ②プリセットタブバー（全幅） → ③左右2ペイン（左: ツールバー＋入力、右: プレビュー）の自然なトップダウン階層を確立する。
2. **Left Pane Toolbar の順序整理と左寄せ連続配置 (Interaction Design)**: `justify-between` を廃止し、左から「プリセット名バッジ」→「Undo/Redoボタングループ」→「Add Setボタン」→「管理ボタン」の順序で左寄せ（`justify-start`、`gap-2`、`flex-nowrap`）に配置する。

### 2-2. 視覚的・インタラクション詳細仕様
1. **Global Header (画面最上部)**:
   - ルートコンテナの最初の子要素として配置（`w-full px-5 py-3 border-b border-[rgba(255,255,255,0.06)] bg-surface/50 flex-shrink-0 relative z-20`）。
   - ドロップダウン（`#workflow-select`）やポップオーバー（`#settings-toggle-btn`）が下層のタブバーやペインによって隠蔽されないよう、`z-20` の重なり順序を保証。
2. **Full-Width Preset Tabs Bar (ヘッダー直下)**:
   - ワークフロー選択時（`selectedWorkflowId` 存在時）にグローバルヘッダー直下に配置。
   - `id="desktop-preset-tabs-bar"`、`border-b border-[rgba(255,255,255,0.06)] bg-surface-2/40 px-5 py-2 w-full overflow-hidden flex-shrink-0 relative z-10`。
   - タブ数が多く画面幅を超える場合でも `overflow-x-auto` により独立して水平スクロール可能。
3. **Left Pane Toolbar (左ペイントップ)**:
   - 左ペイン内部の最上部に配置（`id="left-pane-toolbar"`、`border-b border-[rgba(255,255,255,0.06)] bg-surface-2/30 px-4 py-2.5 flex items-center justify-start gap-2 flex-nowrap flex-shrink-0`）。
   - 要素順序：
     1. `activeSet.name` バッジ（`max-w-[110px] truncate flex-shrink-0`）
     2. Undo / Redo ボタングループ（`#undo-btn`、`#redo-btn`、`flex-shrink-0`）
     3. Add Set ボタン（`#add-set-btn`、`flex-shrink-0`）
     4. 管理ボタン（`#manage-presets-btn`、`flex-shrink-0`）
   - `activeSet` が未選択（null）の場合でも、バッジとUndo/Redoが非表示になるのみで、Add Setおよび管理ボタンが左寄せで安全に描画され、クリック可能であることを保証。
4. **MobileLayout への非干渉保証**:
   - モバイル画面（`MobileLayout.tsx`）には変更を加えず、既存のモバイル専用ヘッダー・タブ操作が100%維持される。

## 3. SSoT Specification Impact
- **Impacted Spec**: `docs/specs/SPEC_GENERATE.md`
  - Section 2「デスクトップレイアウト (`DesktopLayout`)」のアスキー図および階層定義を、最上部グローバルヘッダー → 全幅プリセットタブバー → 左右2ペイン（左ペイン上部に左寄せツールバー）の構造へと同期更新する。

## 4. Trade-off & Risk Disclosure
- **Trade-off (垂直スペース)**: ヘッダー（約48px）とタブバー（約40px）が画面上部に2段並ぶため、コンテンツエリアの縦方向が合計約88px消費される。しかし、左ペイン内部から旧ヘッダーが撤廃されるため、左ペイン入力欄自体の縦方向スペースは実質的に差し引きゼロ（むしろ拡大）となり、プレビュー側も全幅タブバーの視認性向上メリットが上回る。
- **Risk (オーバーレイのスタッキング)**: SettingsポップオーバーやWorkflowSelectがタブバーと重なるリスクがあるが、Global Header に `relative z-20`、Tabs Bar に `relative z-10` を明示指定することで解消する。
