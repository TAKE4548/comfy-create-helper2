# Detailed Design Document: REQ-372

- **PBI ID**: REQ-372
- **Title**: モバイルGenerate：常駐プレビューを廃止し、履歴グリッド・画像シート・全画面ビューアで画像を確認できるようにする
- **Status**: in-progress (Design Phase)
- **Target Surface**: モバイルGenerate（画面幅767px以下）の画像確認導線、履歴グリッド、ステータスヘッダー、画像ボトムシート、全画面ビューア

## 1. Overview & Architectural Context (概要と背景目的)

### 1.1 背景と課題
現行のモバイルGenerate画面（幅767px以下）では、画面上部に2:3比率・105px〜220pxの常駐プレビュー領域が配置されている。この常駐プレビューは画像閲覧スペースとしてもプロンプト編集スペースとしても中途半端であり、限られたモバイル画面の縦スクロール面を恒常的に圧迫している。
また、履歴サムネイルが横一列のスクロールレールで表示されているため、画面遷移ジェスチャーや縦スクロールとの競合が発生し、過去画像の俯瞰一覧性が著しく制限されていた。

### 1.2 目的と解決策
本改修（REQ-372）では、ユーザー検証済みモック（Proposal）に基づき、以下の3段階の分離型画像確認アーキテクチャを本番導入する：
1. **常駐プレビューの廃止（モバイルのみ）**: 入力画面上方の固定画像プレビューを撤去し、プロンプト・タグ編集の有効面積を最大化する。
2. **履歴の3列正方形グリッド化**: ページの縦スクロールに従う3列グリッドで履歴画像を一覧表示する。横スクロールレールを撤去。
3. **段階的画像確認導線（サムネイル → ボトムシート → 全画面ビューア）**:
   - サムネイルタップで下端起点のボトムシート（`MobileImageSheet`）が開き、元の縦横比で拡大プレビュー。
   - シート内画像タップで背景が黒のエッジツーエッジ全画面ビューアへ切り替わり、シートのクローム（ヘッダー・ハンドル・フッター）を非表示にして没入閲覧を提供。
   - 全画面表示中は、対応環境であればブラウザのFullscreen表示（ブラウザUI非表示）およびScreen Wake Lock（画面自動消灯・自動ロック抑止）を有効化し、閉じる・戻る・タブ切替時に安全に解除する。
   - Fullscreen API / Wake Lock API 非対応ブラウザ（iOS Safari等）や権限拒否環境では、ブラウザ表示領域の全面表示（100dvh）に優雅に縮退フォールバックする。
4. **既存機能の100%継承**: 常駐プレビューが担っていた機能（進捗・ETA表示、自動追従/固定、ダウンロード、スナップショット保存、画像エラー表示、複数選択）を機能対応表（AC-8）に基づき各移行先へ完全に移設する。

## 2. Seam Map [MUST [W-DD-SEAM]]

- **1. Integrated (実コード実行)**: 対象は `MobileLayout.tsx`, `GenerationGallerySection.tsx`, `useGalleryInteraction.ts`, `MobileImageSheet.tsx`。モバイルGenerateコンポーネントツリー、履歴グリッド描画、ボトムシート・全画面ビューア状態遷移、DOMタッチ/クリックイベントハンドリングを実コードで実行。
- **2. Severed (外部I/O遮断)**: 対象は ComfyUI WebSocket & HTTP API, `navigator.wakeLock`, `document.requestFullscreen`。WebSocket受信、画像読込イベント（onLoad/onError）、Fullscreen/Wake Lock APIのDOM呼び出しをトランスポート/API境界でモック遮断。
- **3. Mock Level**: トランスポートおよびブラウザAPI境界モック。内部ビジネスロジックや状態フックのモンキーパッチは厳禁。navigator.wakeLock.request や Element.prototype.requestFullscreen のDOMインターフェースをスタブ化。
- **4. PBT Decision**: 不採用 (No)。パーサー、数式計算、DSL等の連続入力空間は存在しないため、状態遷移マトリクス・テーブル駆動テストによる網羅的検証を採用。
- **5. Fault Injection (異常系・縮退パス検証)**: 画像読込失敗（img.onErrorフォールバック表示）、Fullscreen例外（未定義・例外時の100dvh全面フォールバック）、Wake Lock拒否（未定義・reject時の非阻害継続）、履歴0枚（空状態表示）。

## 3. モバイル常駐プレビュー撤去と機能移行対応表 (`MobileLayout.tsx`, AC-1, AC-8)

- **常駐プレビュー撤去 (AC-1, AC-14)**:
  画面幅767px以下で `data-testid="mobile-main-preview"` コンテナを撤去しプロンプト入力領域を拡大。PC（768px以上）ではプレビューを維持（AC-14）。
- **常駐プレビュー機能対応表 (AC-8) [MUST [REQ-372/AC-8]]**:
  常駐プレビューが担っていた全6機能の移行先、具体的操作仕様、および判定状況を以下に定義する。すべての機能は移行先で従来通り操作可能であり、無断削除・廃止は一切行わない。

| 機能項目 | 移行先コンポーネント | 具体的操作仕様・UI導線 | 移行判定 |
| :--- | :--- | :--- | :--- |
| 1. 進捗・ETA・キュー数表示 | 最上部固定ステータスヘッダー (`MobileLayout.tsx`) | 24px固定ヘッダー内にリアルタイム描画。生成完了直後に新画像到達導線を表示 | 移行維持 |
| 2. 自動追従 / 固定 | 履歴ツールバー (`GenerationGallerySection.tsx`) | `#preview-autofollow-toggle-mobile` ボタンで新画像自動選択と手動固定をトグル | 移行維持 |
| 3. 画像ダウンロード | 画像ボトムシート (`MobileImageSheet.tsx`) | シートヘッダーの `#download-btn-mobile` ボタンから表示中画像を直接保存 | 移行維持 |
| 4. スナップショット保存 | 画像ボトムシート / 複数選択バー | ボトムシート保存ボタンおよび履歴複数選択バーからスナップショット保存モーダルを起動 | 移行維持 |
| 5. 画像エラー表示 | 履歴サムネイル / ボトムシート / 全画面 | 履歴サムネイルに再試行バッジ、シートおよび全画面に ImageOff アイコンと案内文を表示 | 移行維持 |
| 6. 複数選択モード | 3列履歴グリッド (`GenerationGallerySection.tsx`) | サムネイル長押しで起動。選択モード中はタップでシートを開かず個別トグルを実行 | 移行維持 |

## 4. 固定ステータスヘッダーと生成完了導線 (`MobileLayout.tsx`, AC-9)

- **最上部固定ステータスヘッダーの構造 (AC-9)**:
  画面上部に `data-testid="mobile-sticky-status-header"`（24px高）を常時固定配置する。
- **生成中ステータス表示**:
  ノード進捗バー、全体バッチ進捗バー、経過秒数、ETA、およびキュー数をヘッダー内にリアルタイム描画する。
- **生成完了通知と新画像到達導線**:
  画像生成ジョブが完了した直後、ヘッダー右側に「生成完了: 最新画像を表示」アクション導線を表示する。
- **履歴セグメント自動切替**:
  ユーザーが完了導線をタップすると、アクティブセグメントが自動的に `history`（履歴タブ）へ切り替わり、最新の生成画像を選択・スクロール表示する。

## 5. 履歴3列縦スクロールグリッド (`GenerationGallerySection.tsx`, AC-2, AC-7)

- **横スクロールレールの撤去 (AC-2)**: モバイル時の `overflow-x-auto` 横スクロールレールを完全廃止する。
- **3列縦スクロールグリッド (AC-2)**: `grid grid-cols-3 gap-2 py-2` を採用しページの縦スクロールで全件到達可能とする。
- **正方形サムネイルトリミング (AC-2)**: 各サムネイルを `aspect-square rounded-lg border-2` の正方形とし `object-cover` で描画する。
- **空状態（0枚）の表示 (AC-7)**: 履歴0件時は既存の「履歴はありません」空状態を描画し架空画像を表示しない。

---

## 6. 画像ボトムシート (`MobileImageSheet.tsx`, AC-3, AC-6, AC-11)

- **ボトムシート展開導線 (AC-3)**: 3列グリッドのサムネイルタップで下端起点ボトムシート（`max-h-[88dvh]`）が展開する。
- **元アスペクト比プレビュー (AC-3)**: シート中央の画像コンテナ内で画像を元縦横比（`max-h-[60dvh] object-contain`）で表示する。
- **シートヘッダー操作部 (AC-8)**: タイトル表示、DLボタン（`#download-btn-mobile`）、スナップショット保存ボタン、閉じるボタンを配置。
- **ガイダンスフッター**: 最下部に「画像をタップして全画面で確認」ガイダンスを配置。
- **画像エラーフォールバック (AC-11)**: 画像読込失敗時は ImageOff アイコンと案内文を表示し崩れを防止する。
- **閉じる操作とスクロール位置維持 (AC-6)**: 閉じるボタン・Backdropタップ・Escapeでシートを閉じ履歴グリッドのスクロール位置を維持する。

---

## 7. 全画面ビューア (`MobileImageSheet.tsx`, AC-4, AC-5, AC-11, AC-12, AC-13)

- **全画面ビューア起動 (AC-4)**: ボトムシート内画像タップで背景が黒（`bg-black`）のエッジツーエッジ全画面ビューアへ切り替える。
- **クローム非表示と画像全面表示 (AC-4)**: シートヘッダー・ハンドル・フッターを非表示化し `w-full h-full object-contain` で没入閲覧を提供する。
- **フローティング閉じるボタン (AC-5)**: 右上に safe-area-inset-top を考慮した 44x44px 以上のフローティング閉じるボタンを配置する。
- **Fullscreen API 制御と縮退 (AC-4, AC-13)**: `requestFullscreen()` を実行し、非対応環境や拒否時は CSS 100dvh 全画面へ安全に縮退する。
- **全画面解除とシート復帰 (AC-5)**: 画像タップ・右上閉じる・OS戻る・Escape・fullscreenchange で全画面を解除しボトムシートへ復帰する。
- **Wake Lock 取得条件 (AC-12)**: 全画面ビューア表示中（`isFullscreen === true`）かつフォアグラウンド状態（`document.visibilityState === 'visible'`）の時に `navigator.wakeLock.request('screen')` を取得し画面自動消灯を抑止する。
- **Wake Lock 解除条件 (AC-12)**: ビューア終了時（閉じるボタン・画像タップ・Escape・戻る操作）、シート復帰時、タブ切替時、画面非表示時（`document.visibilityState === 'hidden'`）に直ちに `sentinel.release()` を呼び出し解放する。
- **フォアグラウンド復帰時の再取得 (AC-12)**: 全画面表示中にバックグラウンドから復帰した際（`visibilitychange` イベント）、Wake Lock の再取得を試行する。
- **Wake Lock 非対応・拒否時フォールバック (AC-13)**: 未サポート環境や例外発生時も非阻害で安全に閲覧・操作を継続する。

## 8. 複数選択モードの保護 (AC-10)

- **複数選択モードの起動 (AC-10)**: 3列履歴グリッドのサムネイル長押しで複数選択モードへ入る。
- **サムネイルタップ処理とシート抑止 (AC-10)**: 複数選択モード中はサムネイルタップイベントで画像ボトムシートを開かず、当該画像の選択・解除トグル処理を実行する。
- **選択状態と件数更新 (AC-10)**: 個別選択・全選択・選択解除時にヘッダーの選択件数表示を従来通りリアルタイム更新する。
- **ツールバー操作の維持 (AC-10)**: 選択件数カウント表示、全選択、選択解除、スナップショット一括保存、終了ボタンを完全維持する。

## 9. UI 4大アーキタイプ分類と制約注入 (UI Archetype Constraints)

- **ボトムシート (MobileImageSheet.tsx, Archetype 1: Modals & Overlays)**: `overscroll-contain` で背後ページのスクロール連鎖を完全防止。`rounded-t-2xl max-h-[88dvh]` で上部セーフエリアを侵食しない。閉じる・DLボタンに `min-w-[44px] min-h-[44px]` のHit-Slopを確保。EscapeおよびBackdropタップで閉じる。
- **全画面ビューア (MobileImageSheet.tsx, Archetype 1: Modals & Overlays Fullscreen)**: `fixed inset-0 z-50 bg-black` で画面全面没入。`touch-action: manipulation` でピンチ・ダブルタップズーム暴発を防止。`env(safe-area-inset-top)` で右上閉じるボタンのノッチ回避。
- **履歴グリッド (GenerationGallerySection.tsx, Archetype 2: Tabs / Chips / Grids)**: `grid grid-cols-3 gap-2 py-2` の3列縦スクロール正方形グリッド。`w-full aspect-square object-cover` による歪みのないトリミング。横スクロールレール完全排除。
- **ステータスヘッダー (MobileLayout.tsx, Archetype 4: Shell & Page Layout)**: `sticky top-0 z-30` で画面最上部固定。`min-w-0 flex-1 truncate` によるテキストはみ出し防止。最小フォントサイズ11px（`text-[11px]`）の徹底。

## 10. Technical Trade-offs & Decisions (トレードオフ開示)

- **常駐プレビュー廃止と画像閲覧の2ステップ化**: メリットはプロンプト入力面積が約105〜220px拡大すること。トレードオフは画像確認に「サムネイルタップ（シート表示）」の1操作が必要になること。緩和策としてヘッダーに「最新画像を表示」導線を設置し、Auto-Follow有効時は履歴先頭が自動同期される。
- **Fullscreen API の縮退（CSS 100dvh 全画面）**: iOS Safari等で `requestFullscreen()` が非対応または拒否された場合でも、CSS `fixed inset-0 h-[100dvh] z-50 bg-black` により全面表示を保証する。API対応環境でのみブラウザUI非表示を発火させる。
- **Screen Wake Lock の厳格なライフサイクル管理**: Wake Lockは全画面表示かつフォアグラウンド時のみ取得する。シート復帰、閉じる操作、画面非表示（`visibilitychange`）で直ちに解放する。
