# REQ-240: 別端末で生成した画像の履歴リアルタイム同期 詳細設計書

## 1. 背景と課題

現在、Prompt Surgeon では複数の端末（PC/スマホ/タブレット等）から同一の ComfyUI バックエンドに接続して画像を生成することが可能です。
しかしながら、別端末から投入された生成ジョブが完了した際、以下の挙動・構造的問題が生じています：

1. **手動リロードへの依存**:
   - `connectionSlice.ts` 内の WebSocket `executed` イベント処理において、新規画像は `comfyHistoryImages` に先頭追加されるものの、`selectedImg` が無条件に最新画像（別端末が生成した画像）に強制更新されるか、あるいは画面リロードを行わないと UI 上の整合性が取れない。
2. **UI コンテキスト（選択画像・スクロール・詳細モーダル）の不意な破壊**:
   - 別端末での生成完了時に `selectedImg` が強制的に書き換わってしまうと、ユーザーが現在作業・確認中だった画像フォーカスが強制移動する。
   - `HistoryModalPreview` を開いて過去画像を閲覧中に新規画像が先頭（Index 0）に挿入されると、配列インデックスが +1 ズレて表示対象画像が予期せず別の画像に切り替わってしまう。
   - スクロール位置や入力中のプロンプト（`paramValues`）への波及を防止する境界保証が不足している。
3. **自端末セッション / 別端末セッションの明確な区別と順序保証**:
   - `executed` イベントが届いたジョブが自端末（`activeBatch` または自セッションの `currentPromptId`）によるものか、別端末（他クライアント）によるものかを厳密に判定し、それぞれ最適な UI 反映（自端末ならプレビュー切り替え、別端末なら履歴先頭追加のみで現在の作業コンテキストを不変保持）を行う必要がある。

## 3. アーキテクチャと詳細設計

### 3-1. データフローとセッション判定マトリクス

- 端末B がジョブを投入して ComfyUI で生成完了
- ComfyUI が接続中の全クライアントへ WebSocket イベント `executed` (prompt_id, output.images) をブロードキャスト
- 端末A の `connectionSlice` が `executed` イベントを受信
- セッション判定:
  - `isOwnSession = (prompt_id === currentPromptId) || (activeBatch && activeBatch.some(j => j.promptId === prompt_id))`
  - **自セッションの場合**:
    - `previewImage` を破棄
    - `batchImages` および `comfyHistoryImages` の先頭に新規画像 URL を追加
    - `selectedImg` を新規生成画像に更新
    - バッチ内の残りジョブ状況に応じて `isGenerating` を完了へ
  - **他端末セッションの場合**:
    - `previewImage` や `isGenerating`, `currentNode`, `nodeProgress` 等の自端末生成状態には一切干渉しない
    - `comfyHistoryImages` の先頭に新規画像 URL を追加
    - `selectedImg` は現在の選択をそのまま維持（null の場合のみ初期画像としてセット）
    - `batchImages`（自セッション画像リスト）には混入させない
    - 編集中プロンプト（`paramValues`）、適用アセット（`appliedAssets`）、選択中セット（`activeSetId`）には一切触れない
- `useGenerateDisplayState` が更新された `comfyHistoryImages` を検知:
  - モーダルプレビューが開いている場合、開いていた画像 URL の新しいインデックスを探して `modalPreviewIndex` を追従させ、表示画像の急変を防止。

## 4. 検証計画

### 4-1. 自動テスト
1. **単体テスト**: `frontend/src/store/__tests__/slices/connectionSlice.test.ts`
   - 他セッションの `executed` イベントを受信した際、`comfyHistoryImages` の先頭に画像が追加されること。
   - 他セッションの `executed` 受信時に、自端末の `selectedImg` が変更されず維持されること。
   - 他セッションの `executed` 受信時に、自端末の `previewImage` や `isGenerating` が破壊されないこと。
2. **結合・E2Eテスト**: `frontend/src/test/e2e_req240_multidevice.test.ts`
   - 複数端末並行シナリオの網羅検証（AC-1, AC-2, AC-3, AC-4）。

### 4-2. AC 準拠表

| AC項目 | 判定条件 | 検証手段 |
|---|---|---|
| **AC-1**: リロード不要で先頭に即時自動挿入 | 他端末の `executed` 受信時に `comfyHistoryImages` 先頭に画像が自動追加され UI に即時反映 | `e2e_req240_multidevice.test.ts` |
| **AC-2**: 複数端末並行時の時系列順序整合性 | 連続して投入・完了した複数ジョブの画像が完了順に整列 | `connectionSlice.test.ts` / E2E |
| **AC-3**: スクロール・プレビュー状態の維持 | モーダルプレビュー表示中およびサムネイル選択中に別端末画像が追加されても、表示画像やインデックスが狂わない | `useGeneratePageState.test.tsx` / E2E |
| **AC-4**: 編集中のプロンプト・パラメータの完全保護 | `executed` 同期処理が `paramValues`, `appliedAssets`, `sets` に一切干渉しない | `e2e_req240_multidevice.test.ts` |
