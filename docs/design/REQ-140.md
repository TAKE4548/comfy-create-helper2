# REQ-140 詳細設計書: モバイルモードにおけるバッチ・複数プリセット生成のキュー登録高速化および取り消しレスポンス改善

## 1. 概要 (Overview)
モバイル環境（スマートフォン・狭小ビューポート・Wi-Fi接続等）において、バッチ生成または複数プリセットを選択して生成を実行した際、ComfyUIキューへの登録完了までに著しい遅延が発生し、また生成キャンセル操作を行っても即座に停止せずレスポンスが悪化する問題が発生していました。

本設計では、以下の改修を行い、キュー登録処理の高速化とキャンセル操作の即時中断を実現します：
1. **キュー投入のパイプライン化と不要フェッチ削減**:
   - 複数ジョブ投入時、各ジョブごとの中間 wait fetchQueue()（GET /queue）を抑制し、全ジョブ投入完了後に 1 回のみキュー状態同期を実行。
2. **localStorage メタデータ走査の非同期・遅延化**:
   - queuePrompt 実行毎に同期実行されていた最大200件の localStorage キャッシュ走査・パース処理を非同期化（setTimeout / equestIdleCallback）し、メインスレッドのブロッキングを解消。
3. **キャンセル中断トークン（AbortSignal / キャンセルフラグ）の導入**:
   - useGenerationStore にジョブ投入中断フラグおよび Abort 連携を追加し、ユーザーがキャンセル操作を実行した際は handleGenerateSets の直列投入ループを即座に reak して後続ジョブの再投入を防止。
4. **バッチ状態管理の即時初期化**:
   - バッチ投入開始時点で setActiveBatch を初期化・追跡し、進捗バーとジョブステータスの同期を改善。

## 3. 詳細設計 (Detailed Design)

### 3.1 useGenerationStore.ts の拡張

#### 3.1.1 queuePrompt のオプション対応とメタデータ走査の非同期化
`	s
queuePrompt: async (
  workflow: Record<string, unknown>,
  metadata?: {
    paramValues?: Record<string, string>;
    appliedAssets?: Record<string, AppliedAsset[]>;
  },
  options?: {
    skipQueueFetch?: boolean;
  }
): Promise<string | null> => {
  if (!comfyUrl) return null
  const activeUrl = resolveComfyUrl(comfyUrl)
  try {
    const res = await fetch(${activeUrl}/prompt, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ prompt: workflow, client_id: get().clientId }),
    })
    if (!res.ok) {
      ...
    }
    const data = await res.json()
    const promptId = data.prompt_id ?? null
    set({
      isGenerating: true,
      previewImage: null,
      progress: null,
      currentPromptId: promptId,
      activeClientId: get().clientId,
      currentWorkflow: workflow,
    })
    if (promptId) {
      localStorage.setItem(LS_KEYS.CURRENT_PROMPT_ID, promptId)
      const metaKey = prompt-surgeon-meta-
      const promptMetadata = {
        paramValues: metadata?.paramValues ?? get().paramValues,
        appliedAssets: metadata?.appliedAssets ?? get().appliedAssets,
        timestamp: Date.now()
      }
      localStorage.setItem(metaKey, JSON.stringify(promptMetadata))

      // メタデータの自動クリーンアップを非同期化（メインスレッドブロッキング防止）
      setTimeout(() => {
        try {
          const keys = Object.keys(localStorage).filter(k => k.startsWith('prompt-surgeon-meta-'))
          if (keys.length > 200) {
            const items = keys.map(k => {
              try {
                const val = JSON.parse(localStorage.getItem(k) || '{}')
                return { key: k, timestamp: val.timestamp || 0 }
              } catch {
                return { key: k, timestamp: 0 }
              }
            })
            items.sort((a, b) => a.timestamp - b.timestamp)
            const toDelete = items.slice(0, items.length - 200)
            toDelete.forEach(item => localStorage.removeItem(item.key))
          }
        } catch (e) {
          console.error('Failed to prune prompt metadata:', e)
        }
      }, 0)
    }
    if (!options?.skipQueueFetch) {
      await get().fetchQueue()
    }
    return promptId
  } catch (e: any) {
    ...
  }
}
`

#### 3.1.2 キャンセル中断シグナルの管理
- ストアに submissionAbortController: AbortController | null または isSubmissionCancelled: boolean を保持し、cancelJob / cancelAllJobs 呼び出し時に submissionAbortController?.abort() を実行。

### 3.2 useGenerateAction.ts (handleGenerateSets) の最適化

`	s
const handleGenerateSets = async () => {
  if (!workflow) return
  const checkedSets = sets.filter((s) => s.checked)
  if (checkedSets.length === 0) return

  // 中断用 AbortController の作成
  const abortController = new AbortController()
  setSubmissionAbortController(abortController)

  const initialBatch: BatchJob[] = []
  // 事前に batchJob リストの枠を作成
  checkedSets.forEach((setItem) => {
    for (let i = 0; i < setItem.batchSize; i++) {
      initialBatch.push({
        promptId: pending--,
        setName: setItem.name,
        status: 'pending'
      })
    }
  })
  setActiveBatch(initialBatch)

  const activeBatchJobs: BatchJob[] = []
  const mappingsJson = localStorage.getItem('prompt-surgeon-prompt-to-set-map') || '{}'
  const mappings = JSON.parse(mappingsJson)

  const activeBypassNodeIds = Array.from(
    new Set(
      bypassProfiles
        .filter((p) => p.is_enabled)
        .flatMap((p) => p.bypassed_node_ids)
    )
  )

  try {
    for (const setItem of checkedSets) {
      const syncedParamValues = applyParamSync(setItem.paramValues)
      for (let i = 0; i < setItem.batchSize; i++) {
        if (abortController.signal.aborted) {
          console.log('Batch generation aborted by user.')
          return
        }

        let wfJson = JSON.parse(JSON.stringify(workflow.json_body)) as Record<string, unknown>
        injectParams(wfJson, syncedParamValues, setItem.seedMode, setItem.seed, i)
        if (activeBypassNodeIds.length > 0) {
          wfJson = applyBypass(wfJson, activeBypassNodeIds, comfyObjectInfo)
        }
        
        try {
          const promptId = await queuePrompt(
            wfJson,
            { paramValues: syncedParamValues, appliedAssets: setItem.appliedAssets },
            { skipQueueFetch: true }
          )
          if (promptId) {
            mappings[promptId] = setItem.name
            activeBatchJobs.push({
              promptId,
              setName: setItem.name,
              status: 'pending'
            })
            // activeBatch を更新
            setActiveBatch([...activeBatchJobs])
          }
        } catch (err) {
          console.error(Failed to generate set  (batch index ):, err)
        }
      }
    }
  } finally {
    localStorage.setItem('prompt-surgeon-prompt-to-set-map', JSON.stringify(mappings))
    // 全ループ終了後に 1 回だけキューを最新化
    await fetchQueue()
  }
}
`

## 4. 非機能要件・パフォーマンス・安全性
- **レスポンシブ性**: モバイルブラウザでのUIフリーズを回避し、タッチ・スクロールの追従性を保つ。
- **リグレッション防止**: 単一ジョブ生成（handleGenerate）および PC/タブレットモードの生成動作に悪影響を与えない。
