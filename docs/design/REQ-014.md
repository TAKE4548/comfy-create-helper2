# 設計書: REQ-014 紐づきスナップショットを活用したアセットの自動・複数サムネプレビュー

## 1. 概要
LoRAやタグセットのアセット一覧カードにおいて、ユーザーが手動でサムネイルを登録していない場合でも、適用したワークフローで生成・保存されたスナップショット画像（最大5件）を自動的に取得してサムネイルとして表示します。
また、複数のスナップショットが存在する場合は、カード内でホバー操作によって切り替え可能なカルーセルUIを提供し、カタログとしての視認性を高めます。

## 2. 影響範囲と依存関係
- **backend**:
  - `backend/app/schemas/lora.py`: `LoraRead` に `snapshot_paths` フィールドを追加。
  - `backend/app/schemas/tagset.py`: `TagSetRead` に `snapshot_paths` フィールドを追加。
  - `backend/app/routers/loras.py`: `_lora_to_schema` 内で、該当LoRAの最新5件のスナップショットパスをJOINクエリで取得し設定。
  - `backend/app/routers/tag_sets.py`: `_tagset_to_schema` 内で、該当タグセットの最新5件のスナップショットパスをJOINクエリで取得し設定。
- **frontend**:
  - `frontend/src/api/types.ts`: `Lora` および `TagSet` のTypeScriptインターフェース定義に `snapshot_paths` を追加。
  - `frontend/src/components/ImageCarousel.tsx` (新規): 画像プレビューとホバーカルーセル切り替えをカプセル化するコンポーネ实现。
  - `frontend/src/pages/LoRAsPage.tsx`: LoRAカードの画像表示を `<ImageCarousel>` に置き換え。
  - `frontend/src/pages/TagsPage.tsx`: タグセットカードの画像表示を `<ImageCarousel>` に置き換え。

## 3. 詳細設計

### 3.1. バックエンドデータベースクエリ設計
アセット（LoRA/TagSet）を取得する際、そのアセットが使用されたスナップショットの画像パスを取得します。

**LoRAのスナップショットパス取得 (SQLiteクエリ)**
```sql
SELECT s.image_path 
FROM snapshots s
JOIN snapshot_loras sl ON s.id = sl.snapshot_id
WHERE sl.lora_id = :lora_id AND s.image_path IS NOT NULL
ORDER BY s.created_at DESC
LIMIT 5
```

**TagSetのスナップショットパス取得 (SQLiteクエリ)**
```sql
SELECT s.image_path 
FROM snapshots s
JOIN snapshot_tag_sets sts ON s.id = sts.snapshot_id
WHERE sts.tag_set_id = :tag_set_id AND s.image_path IS NOT NULL
ORDER BY s.created_at DESC
LIMIT 5
```

### 3.2. フロントエンド カルーセルUI設計
`ImageCarousel` コンポーネントは以下の仕様に基づき画像を管理します：
1. **ステート**: `currentIndex` (現在表示している画像インデックス)。
2. **ホバー状態の判定**: 親カードまたはカルーセル領域にカーソルが入った際に、左右のナビゲーションボタン（矢印）を表示。
3. **ナビゲーション操作**: 
   - 矢印クリック時にインデックスを進める/戻す。
   - インデックス移動時、端（最後/最初）に達した場合は循環する（ループ表示）。
   - ナビゲーション矢印のクリックイベントには必ず `e.stopPropagation()` および `e.preventDefault()` を施し、カードクリック（詳細表示等）の親イベント発火を防止する。
4. **インジケーター**: カルーセル下部にドットインジケーターを表示し、現在のインデックスを視覚的に提示。
