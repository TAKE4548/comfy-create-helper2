# REQ-117: LLMパラメータの設定・永続化機能 システム設計書

## 1. 概要
本機能は、LLM呼び出し時の各種ハイパーパラメータ（`temperature`, `top_p`, `max_tokens`, `presence_penalty`, `frequency_penalty`）を、「翻訳」、「シーン生成」、「プロンプト診断」の機能ごとに個別に設定・永続化可能にするものです。

## 2. アーキテクチャとデータフロー

### 2.1 データベース永続化設計
スキーマ拡張（マイグレーション）を伴わないシンプルな実装として、既存の `llm_prompts` テーブルを利用し、JSON形式でシリアライズした文字列を `content` に格納します。

追加するキー：
- `llm_params_translation`: 翻訳機能のパラメータ設定
- `llm_params_scene_generate`: シーン生成機能のパラメータ設定
- `llm_params_audit`: プロンプト診断機能のパラメータ設定

初期値（Seedデータ）は以下の通り定義します：
```json
{
  "temperature": 0.2,
  "top_p": 1.0,
  "max_tokens": 2048,
  "presence_penalty": 0.0,
  "frequency_penalty": 0.0
}
```

### 2.2 バックエンド設計 (API・サービス)
* **`app/services/llm_request.py` の `call_llm` 改修**:
  引数に `llm_params: dict = None` を追加し、呼び出し時に指定されたハイパーパラメータをAPIペイロードに設定します。
* **機能ごとのパラメータ取得と呼び出し適用**:
  - 翻訳API (`/api/llm-prompts/translate`): `llm_params_translation` キーのレコードからJSONを取得・デコードし、`call_llm` に渡す。
  - シーン生成API (`/api/llm-prompts/scene-generate`): `llm_params_scene_generate` キーのレコードからJSONを取得・デコードし、`run_scene_generate` 経由で `call_llm` に渡す。
  - プロンプト診断API (`/api/audit`): `llm_params_audit` キーのレコードからJSONを取得・デコードし、`run_audit` 経由で `call_llm` に渡す。

### 2.3 フロントエンド設計 (UI)
* **設定画面 (`SettingsPage.tsx`) 内に「LLM詳細パラメータ設定」のセクションを追加**:
  - アコーディオンまたは新規セクションを追加し、機能別（翻訳、シーン生成、プロンプト診断）に以下のUI要素を配置します。
    - `temperature`: スライダー (0.0 ~ 1.0, 刻み 0.05)
    - `top_p`: スライダー (0.0 ~ 1.0, 刻み 0.05)
    - `max_tokens`: 数値入力 (空または 1 ~ 8192)
    - `presence_penalty`: スライダーまたは数値入力 (-2.0 ~ 2.0, 刻み 0.1)
    - `frequency_penalty`: スライダーまたは数値入力 (-2.0 ~ 2.0, 刻み 0.1)
  - 「保存」ボタンの押下時に、それぞれの設定を JSON 文字列として `llmPromptsApi.update("llm_params_...", ...)` でバックエンドに保存します。

## 3. 影響範囲 (Impact Scope)
* **バックエンド**:
  - `app/services/llm_request.py`
  - `app/services/llm_service.py`
  - `app/routers/llm_prompts.py`
  - `app/routers/audit.py`
  - `app/seed_data.py`
  - `app/seeder.py`
* **フロントエンド**:
  - `frontend/src/pages/SettingsPage.tsx`
  - `frontend/src/api/client.ts`

## 4. 制約事項・トレードオフ (Trade-off Disclosure)
- **JSONによるテーブル使い回し**: パラメータ用の新規テーブルを作成する代わりに、既存の `llm_prompts.content` に JSON を詰め込む構成とします。これによりマイグレーションのオーバーヘッドを避けられますが、DBスキーマでのデータ型検証が効かないため、更新時にアプリケーションレイヤーでバリデーションを厳密に行う必要があります。
