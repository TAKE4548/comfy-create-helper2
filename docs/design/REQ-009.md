# 設計書 - REQ-009: 生成セッション（WebSocket進捗同期）の維持

## 1. 目的と概要
現在、画像生成の進捗監視およびプレビュー画像の受信は、フロントエンド（React）が ComfyUI の WebSocket に直接接続して行っています。そのため、画面のリロードや他ページ（LoRA管理、設定等）への遷移によってコンポーネントがアンマウントされると WebSocket 接続が切断され、進行中の進捗やプレビュー画像が消失してしまいます。

本設計では、フロントエンド単体で完結しつつ堅牢に同期状態を復帰させる「フロントエンド（FE）再アタッチアプローチ」を採用します。Zustand を用いて WebSocket 接続および生成状態をグローバルに管理し、`localStorage` を活用してリロード時や画面遷移時でも ComfyUI との接続と進行中ジョブの状態をシームレスに復元・同期する仕組みを提供します。

さらに、ComfyUI の仕様（キューや履歴はサーバー側で全セッション共通で管理される特性）を最大限に活かし、複数デバイスや別ブラウザセッションからでも進行中のジョブ進捗や生成履歴を同期できる設計とします。UI上には「セッションフィルター」のトグルスイッチを提供し、基本は「全セッションのジョブ・履歴の共有表示」とし、必要に応じて「自セッションのジョブ・履歴のみ」に絞り込めるように制御します。
なお、他セッションが生成中であっても、ComfyUI 自体がサーバー側でキュー管理（順次実行）を行うため、生成ボタンの無効化などは行わず、自由にキューイング要求を送れるようにします。

## 2. アーキテクチャ設計

### 2.1 Zustand によるグローバル状態管理 (`frontend/src/store/useGenerationStore.ts`)
WebSocket 接続および生成進捗に関わる以下の状態をグローバルストアで管理します：
- `clientId`: WebSocket 接続用のクライアント識別子（`localStorage` に永続化）
- `isConnected`: WebSocket の接続状態
- `isGenerating`: サーバー全体で生成処理が実行中か否か
- `progress`: 現在の生成進捗（進捗率、現在ステップ、最大ステップ）
- `previewImage`: プレビュー画像または最終出力画像のURL
- `currentPromptId`: 現在実行中の ComfyUI プロンプトID
- `activeClientId`: 現在生成を行っているクライアントのID
- `filterOwnSession`: 自セッションのジョブ・履歴のみに絞り込むかどうかのフラグ（デフォルト: `false`）
- `comfyHistory`: ComfyUI の `/history` から取得した履歴データ（クライアントID情報を含む）
- `batchImages`: バッチ生成された画像の履歴リスト（`localStorage` に永続化、blob URL は除外、表示時にフィルター適用）
- `selectedImg`: メインプレビューで選択されている画像URL（`localStorage` に永続化、blob URL は除外）
- `selectedWorkflowId`: 選択中のワークフローID（`localStorage` に永続化）
- `paramValues`: 生成画面の入力パラメータ値（`localStorage` に永続化）
- `batchSize`: バッチサイズ（`localStorage` に永続化）
- `seedMode`: シードモード（`localStorage` に永続化）
- `seed`: シード値（`localStorage` に永続化）

### 2.2 マルチセッション同期およびフィルタリングのロジック
1. **ジョブの監視と進捗同期**:
   - WebSocket から受信する `execution_start`, `progress`, `executed` などのイベントはサーバー全体の進行状態を通知するため、ストアでこれらをすべて補足します。
   - `execution_start` イベント受信時、イベントに含まれる `prompt_id` から該当ジョブがどの `client_id` によって投入されたかを特定します。
   - UIのプログレスバー表示では、`filterOwnSession` が `true` の場合、現在実行中のジョブのクライアントIDが自身の `clientId` と一致するときのみ進捗バーを表示します。`filterOwnSession` が `false` の場合は、他セッションによる生成であっても進捗（「他セッションが生成中...」などの補助表示付き）をリアルタイムに同期表示します。
2. **履歴の取得とフィルタリング**:
   - 起動時および生成完了時に ComfyUI の `GET /history` から全生成履歴を取得します。
   - 履歴アイテムのメタデータ（`prompt[3]["client_id"]` または `extra_data["client_id"]`）を読み取り、各画像の生成元クライアントIDを紐づけてストアにキャッシュします。
   - サムネイル履歴ストリップでは、`filterOwnSession` の値に基づき、自身の `clientId` に一致するもののみ、または全履歴画像を表示するかを切り替えます。

### 2.3 リロード（F5）時の整合性復元（レコンシリエーション）フロー
1. アプリ起動時（またはストア初期化時）、`localStorage` から `clientId` や各種パラメータ、永続化された履歴を読み込みます。
2. 常に同一の `clientId` で ComfyUI WebSocket に接続します。
3. ComfyUI の `GET /queue` および `GET /history` を非同期で取得し、進行中のジョブおよび新規に完了したジョブをスキャンします。
   - **キューにジョブが存在する場合**: 対象ジョブが自身または他人のものであるかを問わず、進行中（`isGenerating = true`）として進捗同期状態に入ります。
   - **履歴に新規ジョブが追加されている場合**: 一時的な通信切断やリロードの間に完了したジョブの画像を自動取得し、履歴およびプレビューに反映します。

## 3. ComfyUI API 仕様

### 3.1 履歴取得 API
- **パス**: `GET <comfy_url>/history` または `GET <comfy_url>/history/{prompt_id}`
- **データ構造におけるクライアントIDの特定**:
  返却される JSON の各エントリーには、キュー投入時のパラメータを含む `prompt` 配列が存在します。
  `prompt[3]`（通常は `extra_data`）または `client_id` フィールドから、生成を要求した `client_id` を照合・特定します。

### 3.2 キュー取得 API
- **パス**: `GET <comfy_url>/queue`
- **データ構造におけるクライアントIDの特定**:
  `queue_running` および `queue_pending` の各要素は `[index, prompt_id, prompt, extra_data, outputs]` などのリスト形式であり、`extra_data` 内またはリスト末尾の要素から `client_id` を取得します。

## 4. UI/UX デザイン設計
生成画面の「Generate Batch」ボタン付近または履歴サムネイルストリップのヘッダー部に、**「全セッションの履歴を表示」/「自セッションのみ」**を切り替えるトグルスイッチ（例: スイッチコンポーネントまたはタブUI）を配置します。

```
+-------------------------------------------------------------+
|  [ ] 自セッションのみ表示                                    |
|  +-------------------------------------------------------+  |
|  | [サムネ1 (自)] [サムネ2 (他)] [サムネ3 (自)] [サムネ4 (他)] |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

他セッションのジョブが実行されている間でも、ComfyUI のキューに順次投入されるため「Generate Batch」ボタンは無効化せず、そのままキューイング可能です。ただし、画面上には「他セッションが生成中...（キュー待ち）」などのガイダンスメッセージを表示して状態を分かりやすく伝える工夫を行います。
