# REQ-298 設計書: タグチップのドラッグ並び替え判定位置の重なり判定改善

## 1. 概要と背景課題

`TagChipEditor` は `@dnd-kit/core` および `@dnd-kit/sortable` を利用してタグチップのドラッグ＆ドロップによる並び替えを実現している。
現状の実装では、衝突判定アルゴリズムとして `@dnd-kit/core` 提供の `closestCenter`（要素中心点間のユークリッド距離判定）が採用されている。

### 現行実装の問題点
1. **幅の不均一なチップでの中心距離判定の不整合**:
   タグ文字列の長さ（例: `1girl` と `(masterpiece, best quality:1.2)`）によって各チップの横幅が大きく異なる。
   中心点距離判定では、ユーザーが視覚的に移動先チップの上にドラッグチップを重ねているにもかかわらず、相手の中心点を越えるまで並び替え判定（スロットシフト）が発火せず、操作者が「反応しない」と感じる原因となっていた。
2. **境界領域でのチャタリング（Jitter / ジッター）**:
   隣接チップの境目付近を通過する際、中心点距離がミリ秒単位で近接逆転し、プレビューのシフトアニメーションが激しく振動する現象が発生しうる。
3. **範囲外ドロップ時の不自然な挙動**:
   `closestCenter` は要素外へ大きくドラッグした場合でも常に「最も中心が近い」いずれかの要素を返してしまうため、有効領域外へ外してキャンセルする直感的操作が行いにくかった。

---

## 2. アーキテクチャおよび詳細設計

### 2.1 重なり判定アルゴリズム (`tagChipCollisionDetection`)

ドラッグ中のチップ（`collisionRect`）と候補チップ（`droppableRects`）との幾何学的重なりをベースとした高精度な衝突判定関数 `tagChipCollisionDetection` を設計・導入する。

```typescript
export interface TagChipCollisionDetectionOptions {
  overlapThreshold?: number; // デフォルト: 0.20 (20%)
  epsilonHysteresis?: number; // デフォルト: 0.05 (5%)
}
```

#### 判定基準とステップ
1. **候補フィルタリング**:
   - `active.id` 自身を除外する（自身との衝突はスロットシフト対象外）。
2. **幾何学的重複（AABB Intersect）およびポインタ含有判定**:
   - 各候補の矩形（`targetRect`）とドラッグ要素矩形（`collisionRect`）の重複領域（幅 `w`、高さ `h`）を計算。
   - `targetOverlap = intersectionArea / targetArea`
   - `activeOverlap = intersectionArea / collisionArea`
   - `maxOverlap = Math.max(targetOverlap, activeOverlap)`
   - `isPointerInside`: ポインタ座標（`pointerCoordinates`）が相手矩形 `targetRect` の内部に存在するかどうか。
3. **発火閾値と微小接触の除外 (AC-1, AC-3)**:
   - 以下のいずれかを満たす場合のみ有効な衝突候補として認定:
     - `isPointerInside === true`（ポインタ直下侵入）
     - または `maxOverlap >= 0.20`（20%以上の面積重複）
   - これにより、角の微小な接触（1〜2%のグレージング接触）による誤発火を確実に除外する。
4. **ヒステリシスによるチャタリング防止 (AC-3)**:
   - 複数の隣接チップ（例: チップBとチップC）に同時に重なった場合:
     1. ポインタが内包されているチップを最優先。
     2. 直前の衝突候補（`lastCollisionId`）が存在する場合、新たな候補の重複スコアが直前の候補のスコアを `EPSILON = 0.05`（5%）以上上回らない限り、直前の候補を維持する（ヒステリシス制御）。
     3. これにより境界線付近でのプレビューの小刻みなチラつき・振動を完全に抑止する。
5. **有効範囲外の検知とキャンセル (AC-4)**:
   - ドラッグチップまたはポインタがタグチップ一覧の有効領域から完全に離脱し、全候補で閾値を下回った場合、衝突結果として空配列 `[]` を返却する。
   - `@dnd-kit` において `over` が `null` となるため、チップは元の並び順へスムーズに復帰し、範囲外ドロップによる安全なキャンセルが実現される。

### 2.2 ドラッグライフサイクル制御 (`TagChipEditor/index.tsx`)

1. **ドラッグ開始時 (`onDragStart`) (AC-5)**:
   - インライン編集中（`<input>` にフォーカス中）のチップが存在する場合、`document.activeElement?.blur()` を呼び出して編集内容を安全に確定（Commit）する。
   - サブメニュー展開中の場合はサブメニューを閉じる。
   - ドラッグ中チップの `activeId` を保持する。
2. **ドラッグキャンセル時 (`onDragCancel`) (AC-4)**:
   - Escapeキー押下や範囲外ドロップ検知時に `activeId` をクリア。
   - チップ配列の状態は変更せず、元の並び順を維持する。
3. **ドラッグ終了時 (`onDragEnd`) (AC-2, AC-5)**:
   - `!over || active.id === over.id` またはチップ数が 1件以下（`state.length <= 1`）の場合は何もしない。
   - `over` が有効な場合、`arrayMove(state, oldIndex, newIndex)` を実行し、`setChips` を介して履歴（Undo/Redo）に反映する。
4. **既存操作への非干渉 (AC-6)**:
   - ドラッグハンドル（`GripVertical`）にのみ `listeners` / `attributes` をバインドし、タグ本体クリック（サブメニュー）、ダブルクリック（インライン編集）、削除ボタン（`X`）のクリック等の既存操作を妨害・誤発火させない。

### 2.3 視覚的フィードバック (AC-1)

- ドラッグ中の要素（`isDragging`）には半透明ゴーストスタイル（`opacity: 0.6`, スケール微増 `scale(1.05)`, ドロップシャドウ）を付与。
- 他のチップは `useSortable` の `transition` に従って 60fps でスムーズにスロットをシフトし、視覚的な挿入先プレビューを形成する。

## 4. リスクとトレードオフ

1. **タッチデバイスでのドラッグ追従性**:
   タッチ操作ではポインタ座標の精度や指の遮蔽があるため、面積重複20%とポインタ侵入の両方をOR条件で判定することで、指先での操作でもストレスなく入れ替えが反応するように配慮。
2. **N=1または空リストでの挙動**:
   1件のみの場合に無駄な判定やシフト計算を行わないよう早期リターンを徹底し、不要なレンダリングや例外を防止。

- **VRAM解放**: 終了コード0、LM Studio上からモデルアンロード完了を確認済み（100% VRAM解放）。
- **指摘事項と設計への反映**:
  1. *ライブラリ（@dnd-kit/core）標準フローとの統合*:
     `tagChipCollisionDetection` は `@dnd-kit/core` の公式 `CollisionDetection` 型シグネチャに完全準拠させ、`<DndContext collisionDetection={tagChipCollisionDetection}>` プロパティへ注入することで、ライブラリの標準ライフサイクル（`over` 解決、`SortableContext` によるスロットシフト）と一切の矛盾なくシームレスに連携させる。
  2. *インライン編集とドラッグの競合（Focus Race Condition）*:
     自身が編集中（`isEditing: true`）のチップはドラッグハンドルへのリスナー付与を除外（`dragProps = {}`）してドラッグ開始を禁止し、他チップのドラッグ開始時（`onDragStart`）には `document.activeElement?.blur()` を呼ぶことで、編集テキストの確定（Commit）を先行させてから並び替えが進行する安全構造を確立。
  3. *ヒステリシス状態の解放（Cleanup）*:
     チャタリング防止のための直前衝突ID（`lastActiveCollisionId`）がドラッグ終了後も残留（Stale State）しないよう、`onDragStart`, `onDragEnd`, `onDragCancel` のすべてのライフサイクル脱出ポイントで `resetCollisionHistory()` を明示的に実行し、完全クリーンアップを保証。
  4. *視覚的重なり感とポインタ判定の優先*:
     単なる面積比率（20%）に依存せず、ポインタ座標直下侵入（`isPointerInside`）を最優先ボーナスとして判定することで、細長いチップや高DPI環境でも直感的なスロット移動が即応する設計とする。
