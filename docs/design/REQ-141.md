# REQ-141 詳細設計書: バッチ生成におけるpending即時描画とComfyUI逐次投入エラーハンドリング・キュー数リアルタイム補正

## 1. 概要 (Overview)
PC（デスクトップ）およびモバイル環境において、複数プリセット・バッチ生成を実行した際、ComfyUI側のワークフロー検証（Verify）待ちとアプリ側の逐次投入ループ内でのReact状態更新の不整合により、画面のレスポンス低下や進捗表示のバタつき（State Thrashing）が発生していました。
また、ComfyUI側からNG（バリデーションエラー等）が返却された場合に、どのプリセットの何番目のバッチが失敗したかが明確でなく、キュー進捗数が実態と乖離する問題がありました。

本設計では、以下の改善を行い、0msの即時体感レスポンスと厳密なエラーハンドリング・キュー同期を実現します：
1. **0ms の即時描画（pending 状態）**: ボタン押下直後に全件の `initialBatch` をセットし、UI のプログレスバーおよびジョブ枠を即時表示。
2. **逐次投入時の配列不変性（No State Thrashing）**: ループ内で配列サイズを縮小・再生成せず、固定長配列の該当要素の `promptId` をインプレースに更新することで、無駄な全画面再レンダリングを抑止し最速ストリーム投入を実現。
3. **ComfyUI NG時の特定エラー通知とキュー数リアルタイム補正**: ComfyUIからバリデーションエラー等のNG応答が返った場合、どのプリセット・バッチ番号（例: `プリセット名 (2/4)`）で失敗したかを明示してトースト通知し、該当ジョブを `failed` として進捗計算を即座に補正。

## 3. 詳細設計 (Detailed Design)

### 3.1 `useGenerateAction.ts` の改善

#### 3.1.1 pending 即時描画とインプレース更新ロジック
```typescript
const handleGenerateSets = async () => {
  if (!workflow) return
  const checkedSets = sets.filter((s) => s.checked)
  if (checkedSets.length === 0) return

  // 中断用 AbortController の作成とストア登録
  const abortController = new AbortController()
  setSubmissionAbortController?.(abortController)

  // 事前に全体の枠を構築して activeBatch を即時初期化 (0ms でUIに全枠を表示)
  const initialBatch: BatchJob[] = []
  checkedSets.forEach((setItem) => {
    for (let i = 0; i < setItem.batchSize; i++) {
      initialBatch.push({
        promptId: `pending-${setItem.name}-${i}-${Date.now()}`,
        setName: setItem.name,
        status: 'pending'
      })
    }
  })
  setActiveBatch(initialBatch)

  const currentBatch: BatchJob[] = [...initialBatch]
  const mappingsJson = localStorage.getItem('prompt-surgeon-prompt-to-set-map') || '{}'
  const mappings = JSON.parse(mappingsJson)

  const activeBypassNodeIds = Array.from(
    new Set(
      bypassProfiles
        .filter((p) => p.is_enabled)
        .flatMap((p) => p.bypassed_node_ids)
    )
  )

  let jobIndex = 0
  try {
    for (const setItem of checkedSets) {
      const syncedParamValues = applyParamSync(setItem.paramValues)
      for (let i = 0; i < setItem.batchSize; i++) {
        const currentIdx = jobIndex++
        
        // キャンセル中断チェック
        if (abortController.signal.aborted) {
          console.log('Batch queueing aborted by user.')
          return
        }

        let wfJson = JSON.parse(JSON.stringify(workflow.json_body)) as Record<string, unknown>
        injectParams(wfJson, syncedParamValues, setItem.seedMode, setItem.seed, i)
        if (activeBypassNodeIds.length > 0) {
          wfJson = applyBypass(wfJson, activeBypassNodeIds, comfyObjectInfo)
        }
        
        try {
          // skipQueueFetch: true で個別フェッチをバイパス
          const promptId = await queuePrompt(
            wfJson,
            { paramValues: syncedParamValues, appliedAssets: setItem.appliedAssets },
            { skipQueueFetch: true }
          )
          if (promptId) {
            mappings[promptId] = setItem.name
            currentBatch[currentIdx] = {
              promptId,
              setName: setItem.name,
              status: 'pending'
            }
            // 配列長を変えずに promptId のみ同期
            setActiveBatch([...currentBatch])
          } else {
            // ComfyUI NG (バリデーションエラー等)
            const errorMsg = `[${setItem.name}] (${i + 1}/${setItem.batchSize}) のキュー投入に失敗しました。`
            console.error(errorMsg)
            setErrorToast?.({ message: errorMsg, type: 'error' })
            currentBatch[currentIdx] = {
              ...currentBatch[currentIdx],
              status: 'failed'
            }
            setActiveBatch([...currentBatch])
          }
        } catch (err: any) {
          const errorMsg = `[${setItem.name}] (${i + 1}/${setItem.batchSize}) でエラーが発生しました: ${err?.message || err}`
          console.error(errorMsg, err)
          setErrorToast?.({ message: errorMsg, type: 'error' })
          currentBatch[currentIdx] = {
            ...currentBatch[currentIdx],
            status: 'failed'
          }
          setActiveBatch([...currentBatch])
        }
      }
    }
  } finally {
    localStorage.setItem('prompt-surgeon-prompt-to-set-map', JSON.stringify(mappings))
    setActiveBatch([...currentBatch])
    // 全ループ終了後に 1 回のみキューを同期
    await fetchQueue?.()
  }
}
```

## 4. テスト方針 (Test Plan)
- **単体テスト (`useGenerateAction.test.ts`)**:
  - `handleGenerateSets` 実行時、即座に全件の pending 枠で `setActiveBatch` が呼ばれること。
  - 各ジョブ投入時に配列長が縮小せず、固定長のまま各インデックスが更新されること。
  - `queuePrompt` が null または例外を返した場合、該当プリセット名・バッチ番号（`Set (1/2)`）のエラーメッセージがセットされ、ジョブステータスが `failed` になること。
- **結合テスト**:
  - 正常系: 複数プリセット・バッチ生成で進捗バーが即時 0/N で立ち上がり、順次完了すること。
  - 異常系: 不正なノード接続等で ComfyUI がエラーを返した際、該当ジョブが failed となり、特定エラーメッセージがトースト表示されること。

## 5. トレードオフ・リスクの開示 (Trade-off Disclosure)
- **逐次投入による通信時間**: FIFO 順序を保つため直列ループ自体は維持されます。ただし、配列伸縮と再レンダリングの削減、および 0ms pending 表示により、体感レスポンスは劇的に向上します。
- **NG発生時の一部継続**: 1件のジョブがNGになっても、後続のジョブの投入は継続されます。これにより、特定のプリセットの不備で全体のバッチが道連れになるのを防ぎます。
