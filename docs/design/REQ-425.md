# REQ-425: プロンプト構造テンプレートによる分割入力とノード別任意結合送信 詳細設計書

## 1. アーキテクチャ概要

本設計は、ワークフロー内の複数プロンプトノード（全体プロンプト、アップスケール用、FaceDetailer用など）間で発生する手動コピペ・二重管理を排除するため、**プロンプト構造テンプレート（Prompt Structure Template）** と **ワークフロー別プロンプト出力グループ（Prompt Output Group）** による分割入力およびノード別任意結合アーキテクチャを導入する。

### コア設計原則
1. **テンプレート定義とワークフロー出力グループの疎結合 (`AC-1`, `AC-2`, `AC-3`)**:
   - プロンプト構造テンプレートは `prompt_structure_templates` テーブルで汎用管理し、システム起動時に初期データとして **「Anima 標準テンプレート」**（繰り返し可能なキャラクターセクション19ブロック＋非繰り返しの全体セクション17ブロック）をシードする。
   - ワークフロー側（`workflows.prompt_template_config` JSON カラムおよび `workflow_history`）には、適用する `template_id`、テンプレート構造スナップショット `template_snapshot`、および任意の個数・名称・送信先 `target_role`・結合対象 `block_ids`・Repeat 対象指定 `repeat_filter` を持つ `output_groups` を保持する。ステージ名（Main/Upscale/FaceDetailer等）のハードコードは一切行わない。
2. **予約キー `__prompt_template_state_v1` によるプリセット完全互換 (`AC-7`)**:
   - バックエンド `variant_keys.py` は `__` プレフィックス（`RESERVED_PREFIX`）を持つキーを `KeyKind.RESERVED` として扱い、`workflow_presets.param_values` および `snapshots.params` に欠落なく保存・展開する。
   - 生成画面での分割入力状態（各ブロック・各 Repeat インスタンスの入力文字列、および `enabled: false` の無効化チップを含む `TagChip[]` リスト）を `paramValues['__prompt_template_state_v1']` に JSON シリアライズして保持するとともに、ブロック変更時に出力グループ毎の有効結合文字列を各 `target_role`（例: `positive_main`, `positive_upscale`）へリアルタイム同期する。
   - これにより、既存のプリセット CRUD・自動保存（`usePresetAutoSave`）・Undo/Redo（`usePresetHistory`）・5秒ポーリング同期（`usePresetStoreSync`）・409 競合解決・タブ閉じバリアと 100% 互換性を保ちつつ、プリセット保存・復元時には無効化チップ（`enabled: false`）を含む分割状態が完全復元される。
3. **生成記録・スナップショットにおける有効値のみの保持と分割復元 (`AC-8`)**:
   - 生成実行（`useGenerateAction.ts` / `generationRecord.ts`）時、`cleanParams` からはプリセット用の `__prompt_template_state_v1`（無効チップ含む）を除外し、代わりに `GenerationRecord`（`__prompt_surgeon_metadata_v1`）内の `prompt_template` フィールドへ **有効なチップ（`enabled: true`）のみから構成されたサニタイズ済み分割状態**（`SanitizedPromptTemplateRecord`）を記録する。
   - 画像詳細（GenerationMetadataPanel / SnapshotMetadataTab）では結合送信されたノード別プロンプトに加え、分割ブロック・Repeat インスタンス単位の有効プロンプトを表示する。スナップショットから生成画面へ読み込む際（`loadSnapshotParams`）は、`GenerationRecord.prompt_template` から有効値のみを分割入力欄へ復元し、無効化チップは引き継がない。
4. **未割り当てプロンプト欄の共存と後方互換 (`AC-4`, `AC-9`)**:
   - ワークフロー内の `textarea` マッピングのうち、`output_groups` のいずれの `target_role` にも割り当てられていないロール（例: Negative Prompt や単独プロンプトノード）、またはテンプレート未適用ワークフローの全 `textarea` ロールは、従来通り1つの `TagChipEditor` 入力欄として表示・送信される。

## 2. PBI 推論箇所（Inferred Points 1〜8）の設計決定

`REQ-425.md` の「推論箇所」8項目に対するアーキテクチャ決定を以下に確定する。

| # | 推論項目 | 設計決定（SSoT） |
|---|---|---|
| **1** | **結合処理の責務配置（FE vs BE）** | **フロントエンドの純粋関数エンジン (`frontend/src/utils/promptTemplateEngine.ts`) を主責務とし、ブロック編集時および `useGenerateAction.ts` のペイロード構築時に各 `output_group.target_role` の結合文字列を算出する**。既存の `injectWorkflowParams`・`applyParamSync`・`buildGenerationRecord` がすべてフロントエンドで ComfyUI 送信用 `graph` と `param_values` を確定させる設計（`SPEC_GENERATE.md`）と完全に整合させるため。バックエンドはテンプレート CRUD とワークフロー設定スキーマ検証を担当する。 |
| **2** | **プロンプト構造テンプレートの永続化スキーマ** | **専用 SQLite テーブル `prompt_structure_templates` を新設（Migration `step_036`）し、`GET/POST/PUT/DELETE /api/prompt-templates` で CRUD 提供する**。各ワークフローの結合設定は `workflows.prompt_template_config`（JSON カラム、`workflow_history` にも保存）に保持し、エクスポート・コピー・ロールバック耐性のため `template_snapshot` も同梱する。 |
| **3** | **Repeat セクションの結合順序規則** | 出力グループが `repeat_filter.mode === 'all'` で複数 Repeat インスタンスを含む場合、**出力グループ内の `block_ids` の並び順において、連続する同一 Repeat セクションのブロック群を「インスタンス 1 の該当ブロック群 → インスタンス 2 の該当ブロック群 → …」の順（インスタンス単位のまとまり）で展開**し、その後に非 Repeat セクション（全体セクション等）の選択ブロック群を結合する（`AC-6` の「1人目のキャラブロック群 → 2人目のキャラブロック群 → 全体ブロック群」と厳密一致）。 |
| **4** | **生成画面における分割入力欄の UI レイアウト** | デスクトップ（`DesktopLayout`）およびモバイル（`MobileLayout` のプロンプトタブ）双方で、**セクション単位の折りたたみ可能なアコーディオンパネル**として描画する。Repeat セクションにはヘッダーに `[+ インスタンス追加]` ボタンとインスタンス切り替え/一覧カード（`#1`, `#2`... と削除ボタン）を配置し、各ブロックにはコンパクトな `TagChipEditor`・翻訳ボタン・クリップボードメニュー・`[+ アセット追加]` ボタンを備える。またヘッダーのトグルで「空欄ブロックを折りたたむ」表示フィルタを提供する。 |
| **5** | **アセット追加（TagSet / LoRA トリガー）の対象スコープ** | **分割ブロック単位（Repeat セクションの場合は `インスタンス index + ブロック ID` の複合スコープキー `tpl_slot:<sectionId>:<instanceIndex>:<blockId>`）でアセット追加・TagSet 保存・翻訳を行える**。LoRA 本体（`<lora:name:strength>` または `lora_stack` への注入）は、当該ブロックを参照する出力グループの `target_role`（複数ある場合は先頭または全対象ロール）へ適用し、トリガーワード／TagSet タグは指定したブロック（特定インスタンスの該当ブロック）のチップ配列へ直接挿入する。 |
| **6** | **プリセットおよびスナップショットの後方互換性** | `__prompt_template_state_v1` が存在しない既存プリセットやスナップショットをロードした場合、テンプレート未適用ワークフローではそのまま従来の単一 `TagChipEditor` へ表示し、テンプレート適用済みワークフローでは既存の `paramValues[target_role]` を先頭ブロック（またはフォールバック表示）に保持しつつ分割編集へ安全に移行できるグレースフル・フォールバックを提供する。 |
| **7** | **プリセット保存時の無効化チップ保持方式** | `paramValues['__prompt_template_state_v1']` の JSON ペイロード内に、各スロットの `chips: TagChip[]`（`enabled: boolean` を含む完全なチップ配列）と `rawText: string`（有効チップのみの結合文字列）を保持する。プリセット保存時は `paramValues` がそのまま `workflow_presets.param_values` に保存されるため、`enabled: false` のチップが DB に完全保存される（`AC-7`）。 |
| **8** | **生成メタデータ・スナップショットの保存粒度** | 生成送信時、`cleanParams` から `__prompt_template_state_v1` を削除し、`buildGenerationRecord` が生成する `__prompt_surgeon_metadata_v1`（`GenerationRecord`）に `prompt_template?: SanitizedPromptTemplateRecord` を追加する。ここには `enabled: true` のチップのみから生成した各ブロック／インスタンスの有効文字列だけを格納し、`enabled: false` チップは一切含めない（`AC-8`）。 |

## 4. プロンプト結合アルゴリズムと状態変換設計 (`promptTemplateEngine.ts`)

### 4.1 状態データ構造
```typescript
export const PROMPT_TEMPLATE_STATE_KEY = '__prompt_template_state_v1'

export interface PromptBlockChipItem {
  id: string
  text: string
  enabled: boolean
  weight?: number
}

export interface PromptTemplateInstanceState {
  instanceId: string // e.g. "inst-1", "inst-2"
  blocks: Record<string, PromptBlockChipItem[]> // blockId -> chips (enabled true/false)
}

export interface PromptTemplatePresetState {
  version: 1
  templateId: number | null
  sections: {
    [sectionId: string]: {
      instances: PromptTemplateInstanceState[] // non-repeatable has length 1
    }
  }
}

export interface SanitizedPromptTemplateRecord {
  version: 1
  template_id: number | null
  template_snapshot: PromptTemplateStructure
  sections: Array<{
    section_id: string
    section_name: string
    is_repeatable: boolean
    instances: Array<{
      instance_index: number // 1-based
      blocks: Array<{
        block_id: string
        block_label: string
        value: string // joined enabled chips only!
      }>
    }>
  }>
}
```

### 4.2 ブロック単体の有効文字列化とカンマ正規化 (`AC-5`, `AC-10`)
1. ブロック内の `chips` から `chip.enabled === true` の要素のみを抽出し、`formatChipText(chip)`（重み付き等の正規化表現）をトリムして空文字を除去する。
2. 各チップ文字列の先頭・末尾に付着した余分なカンマや空白（`/^[\s,]+|[\s,]+$/g`）を除去し、内部の連続カンマも正規化した上で `", "` で結合する。
3. 有効チップが 0 件、または空白・カンマのみのブロックは `""`（空文字）を返し、出力グループ結合時の対象リストから完全にスキップする（空ブロックによる先頭カンマ `, tag`・末尾カンマ `tag, `・連続カンマ `tag1, , tag2` を一切発生させない）。

### 4.3 出力グループ別の結合順序と Repeat インスタンスフィルタリング (`AC-5`, `AC-6`)
出力グループ `group: PromptOutputGroup` の結合文字列 `joinOutputGroup(template, state, group)` は以下の決定的アルゴリズムで算出する：
1. `group.block_ids`（出力グループで選択された順序付きブロックID配列）を走査し、連続する同一セクションのブロック群をチャンク（`(section, blockIds[])`）にまとめる（通常は「キャラクターセクションの選択ブロック群」→「全体セクションの選択ブロック群」）。
2. 各チャンク `(section, chunkBlockIds)` について：
   - **非 Repeat セクション (`!section.is_repeatable`)**:
     - `instances[0]` に対して `chunkBlockIds` の順で各ブロックの有効文字列を取得し、空でないものだけを配列 `segments` に追加する。
   - **Repeat セクション (`section.is_repeatable`)**:
     - `group.repeat_filter.mode === 'index'` かつ `group.repeat_filter.index`（1始まり、例: `1` または `2`）が指定されている場合：
       - `targetInstance = instances[group.repeat_filter.index - 1]` が存在すれば、そのインスタンス内の `chunkBlockIds` を順に評価し、空でない有効文字列を `segments` に追加する。存在しないインデックス（例: インスタンスが1つしかないのに `#2` 指定）の場合は空（スキップ）とする。
     - `group.repeat_filter.mode === 'all'`（全結合）の場合：
       - `instances` を `0, 1, ...`（1人目、2人目…）の順にループし、**各インスタンスごとに `chunkBlockIds` を順に評価**して空でない有効文字列を `segments` に追加する。
3. 収集された全 `segments`（すべて非空・前後カンマ除去済み）を `", "` で結合して返す。

#### ウォークスルー検証 (`AC-6` および `AC-10` 具体例)
- **`AC-6`（重複選択・独立評価・無効チップ/空欄スキップ・登録順展開）**:
  - グループ1 = 全ブロックをノードAへ（`repeat_filter = { mode: 'all' }`）、グループ2 = `['character_name', 'expression']` をノードBへ（`repeat_filter = { mode: 'all' }`）。
  - キャラ1: `character_name = "alice"`, `expression = "smile"`, `upper_clothes = [disabled("shirt")]`（全チップ無効）
  - キャラ2: `character_name = "bob"`, `expression = ""`（空欄）, `upper_clothes = "coat"`
  - 全体: `lighting = "rim light"`
  - 結果:
    - ノードA: `"alice, smile, bob, coat, rim light"`（キャラ1の無効チップとキャラ2の空欄をスキップし、余分なカンマ・連続カンマなし）
    - ノードB: `"alice, smile, bob"`（キャラ2の `expression` 空欄をスキップし末尾カンマなし）
- **`AC-10`（Repeat 対象インデックス指定と未追加インスタンスの安全なスキップ）**:
  - ノードA = 全ブロック（`repeat_filter: { mode: 'all' }`）、ノードB = `['character_name', 'upper_clothes']`（`repeat_filter: { mode: 'index', index: 1 }`）、ノードC = `['character_name', 'upper_clothes']`（`repeat_filter: { mode: 'index', index: 2 }`）。
  - 1人入力時（キャラ1: `character_name = "alice"`, `upper_clothes = "dress"`、2番目のインスタンス未追加）:
    - ノードA: `"alice, dress"`
    - ノードB: `"alice, dress"`
    - ノードC: `""`（存在しない2番目をエラーなくスキップし余分なカンマなし）
  - 2人入力時（キャラ2: `character_name = "bob"`, `upper_clothes = "suit"` を追加後）:
    - ノードA: `"alice, dress, bob, suit"`
    - ノードB: `"alice, dress"`
    - ノードC: `"bob, suit"`
- **`AC-5`（Repeat インスタンス追加・単一ブロックへのアセット追加・削除時の詰め処理）**:
  - キャラ2の `upper_clothes` 欄のみを対象に TagSet / LoRA 追加操作を実行した場合、当該インスタンス・当該ブロック（`sections['character'].instances[1].blocks['upper_clothes']`）にのみタグが追加され、キャラ1や保存済みアセット定義には波及しない。
  - キャラ2を削除した場合、`instances.splice(1, 1)` により対象インスタンス枠と内部の入力値のみが除去され、空のインスタンス枠（不要な空欄）を残さず残存インスタンスを詰めて保持する。

## 5. フロントエンド UI 設計とレスポンシブ・規約準拠

### 5.1 設定画面 (`SettingsPage`)
1. **プロンプト構造テンプレート管理 (`PromptTemplateManagerSection.tsx`)**:
   - `SettingsPage.tsx` の `activeTab === 'workflows'` 内に配置。
   - テンプレート一覧表示（「Anima 標準テンプレート」を含む）、新規作成、編集、複製、削除を提供。
   - セクション追加・削除・並び替え、`is_repeatable`（Repeat可否）トグル、各セクション内のブロック追加・削除・ラベル変更・並び替え（上下移動ボタン）を提供。
2. **ワークフロー別プロンプト出力グループ設定 (`WorkflowPromptOutputGroupsEditor.tsx`)**:
   - `WorkflowConnectionSection.tsx` のワークフロー「対応付け・設定」パネル内に組み込む。
   - 適用するテンプレートの選択ドロップダウン（`未適用 (従来の単一入力)` または登録済みテンプレート一覧）。
   - 出力グループの追加・名称編集・削除。
   - 各出力グループに対する：
     - **送信先プロンプトノード（`target_role`）選択**: 当該ワークフローの `input_type === 'textarea'` マッピング一覧から選択。
     - **Repeat 対象指定 (`repeat_filter`)**: 「全インスタンス結合 (`all`)」または「特定インスタンスのみ (`index`: `#1`, `#2`, ...)」。
     - **結合ブロック選択・順序制御 (`block_ids`)**: セクション別の全選択/解除、チェックボックストグル、選択ブロックの結合順序変更。
   - ワークフロー設定 JSON エクスポート／インポート（`WorkflowConnectionSection.tsx`）にも `prompt_template_config` を含める。

### 5.2 生成画面 (`GeneratePage`)
1. **分割入力コンポーネント (`PromptTemplateSplitEditor.tsx`)**:
   - 選択中ワークフローの `prompt_template_config` に有効な `template_id`（または `template_snapshot`）と 1 件以上の `output_groups` が設定されている場合に、`DesktopLayout.tsx` および `MobileLayout.tsx` のプロンプト領域に描画する。
   - **出力グループに割り当て済みの `target_role`** は `PromptTemplateSplitEditor` が管理し、個別の生 `textarea` ロール欄としては重複表示しない（代わりに折りたたみ可能な「結合プレビュー（出力グループ別送信文字列）」バッジ／アコーディオンで確認可能にする）。
   - **出力グループに未割り当ての `textarea` ロール**（例: `negative_prompt` 等）は、`PromptTemplateSplitEditor` の直下にこれまで通りの単一 `TagChipEditor` として並べて表示する（`AC-4`, `AC-9`）。
   - **Repeat セクション操作**:
     - `[+ インスタンスを追加]` ボタンで新しいキャラクター等のインスタンス（`#2`, `#3`...）を追加。
     - 各インスタンスのヘッダーに `#1`, `#2` バッジと削除ボタン（インスタンスが2個以上の場合に削除可能）を配置。
   - **ブロック別機能**:
     - 各ブロックは `TagChipEditor` を内包し、チップの追加・削除・個別 ON/OFF トグル（`enabled: true/false`）・ドラッグまたは入力編集に対応。
     - ブロック単位の `[+ アセット]` ボタン（押下すると `AddAssetModal` を開き、選択した TagSet や LoRA トリガーワードをそのブロックのチップとして追加し、LoRA 本体は当該ブロックを含む出力グループの `target_role` に登録）、翻訳ボタン、クリップボードメニューを配置。
     - 「空ブロックを隠す」フィルタトグルにより、36ブロックある Anima 標準テンプレートでもスマホ・PC双方で快適に一覧・入力可能とする。

### 5.3 UI 不変条件（Gate 1 静的リンター）遵守
- `scripts/verify_ui_invariants.py` の全規則を遵守する：
  - `100vh` 禁止（`100dvh` または `%` を使用）。
  - グローバル `11px` フォントフロア禁止。
  - 無差別な `!important` 禁止。
  - モバイル操作ボタンの最小タップターゲット `min-h-11` / `min-w-11` を確保。
