# Architectural Design Document: REQ-330

## 1. Overview & Context

In LoRA Dataset Studio (`/dataset-studio`), users calculate an orthogonal matrix of prompts in Step 1 (`MatrixGenerationStep`) and submit 20 generated prompts to ComfyUI for generation.
Currently, `MatrixGenerationStep.tsx` attempts to directly call `fetch('http://127.0.0.1:8188/prompt')` from the browser.
Because ComfyUI does not return CORS headers by default, the browser rejects this cross-origin request with `TypeError: Failed to fetch`.
Furthermore, hardcoding `127.0.0.1:8188` bypasses the user's configured `COMFY_URL` setting and ignores remote server topologies.

In contrast, the standard generation pipeline (`GeneratePage`) and Step 4 (`BenchmarkGrid`) route prompt submissions through the backend proxy (`POST /api/comfy/prompt` via `comfyApi.queuePrompt`), where the server communicates with ComfyUI via Python `httpx` without browser CORS restrictions.

This design aligns `MatrixGenerationStep.tsx` with the existing SSoT architecture (`SPEC_SUMMARY.md`) by replacing direct browser `fetch` calls with `comfyApi.queuePrompt`.

---

## 2. Root Cause & Architectural Breakdown

### 2.1 Direct Client-Side Fetch & CORS Rejection
- In `MatrixGenerationStep.tsx:515-549`:
  - `const comfyUrl = 'http://127.0.0.1:8188'`
  - `await fetch(`${comfyUrl}/prompt`, { method: 'POST', ... })`
- Origin mismatch: Browser is at origin `http://localhost:8000` (or `5173`). Destination is `http://127.0.0.1:8188`.
- ComfyUI does not emit `Access-Control-Allow-Origin: *` headers unless `--enable-cors-header` is explicitly passed.
- Browser blocks the request and surfaces `Failed to fetch`.

### 2.2 SSoT Proxy Inconsistency
- SSoT (`docs/specs/SPEC_SUMMARY.md`) specifies `/api/comfy` as the single unified proxy for ComfyUI communication (`/prompt`, `/queue`, `/history`, etc.).
- Step 4 (`BenchmarkGrid.tsx`) already uses `comfyApi.queuePrompt`.
- `MatrixGenerationStep.tsx` was the lone outlier violating this architectural boundary.

---

## 3. Detailed Component Design

### 3.1 MatrixGenerationStep Enhancement (`MatrixGenerationStep.tsx`)
- Import `comfyApi` from `../../../api/client`.
- In `handleSubmitBatch`:
  - Remove hardcoded `const comfyUrl = 'http://127.0.0.1:8188'`.
  - Retain `clientId` generation: `const clientId = 'lora-studio-' + Math.random().toString(36).slice(2, 9)`.
  - Replace `await fetch(`${comfyUrl}/prompt`, ...)` with:
    ```typescript
    await comfyApi.queuePrompt({
      prompt: payload,
      client_id: clientId,
    })
    ```
  - Maintain progress tracking (`setBatchProgress`) and error handling (`setStatusMessage`).
  - Update button text/tooltip to clean up the hardcoded `(Port 8188)` label to a clean `ComfyUIに20件直接投入`.

### 3.2 Test Suite Modernization (`MatrixGenerationStep.test.tsx`)
- Update mock setup for `api/client`:
  - Ensure `comfyApi.queuePrompt` is properly mocked via `vi.mocked(comfyApi.queuePrompt)`.
- Replace legacy `globalThis.fetch` mocking in test `AC-4` with `comfyApi.queuePrompt` assertion.
- Add Red Team failure verification:
  - Simulate `comfyApi.queuePrompt` rejection/error.
  - Verify error status message `ComfyUI直接投入エラー: ...` is rendered and `isSubmitting` resets to false.

## 4. Architectural Boundaries & SSoT Synchronization
- No changes to backend endpoints (`/api/comfy/prompt` is already fully functional).
- No modifications to database schemas or OpenAPI specifications.
- Restores 100% compliance with `docs/specs/SPEC_SUMMARY.md`.
