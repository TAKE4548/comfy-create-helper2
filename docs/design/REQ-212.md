# REQ-212: バックエンドDBセッション管理の統一（DI化/リーク防止）および非同期バッチ処理（speech_batch）の排他制御・メモリ解放

## 1. 背景と目的

現在、Prompt Surgeon バックエンドにおいて以下のアーキテクチャ上の課題が存在している：
1. **暗黙的・非統制なDBセッションライフサイクル**:
   - `backend/app/routers/speech_batch.py` や `backend/app/services/llm_service.py` 内部で `SessionLocal()` をアドホックに直接インスタンス化して使用しており、例外発生時や並行実行時にセッションが確実に閉じられないリスクがある。
   - コネクションプールの枯渇やトランザクションロックの滞留を引き起こす要因となっている。
2. **グローバル辞書によるインメモリ状態管理と競合・メモリリーク**:
   - `speech_batch.py` のジョブ管理（`_batch_jobs`, `_job_tasks`）が排他制御なしのモジュールレベル辞書として保持されており、複数リクエストからの同時更新（キャンセル、リトライ、完了進捗の加算）で競合状態（Race Condition）が発生しうる。
   - 完了・キャンセル済みジョブの履歴がメモリ上に無制限に蓄積され続け、長時間稼働時にメモリリークを引き起こす。
3. **非同期イベントループ内でのブロッキングI/O実行**:
   - `_process_single_item` や `run_batch_job` 内で同期的なSQLiteクエリや画像ディスク読み込み・Base64エンコード処理がイベントループ上で直接実行され、FastAPIサーバー全体の非同期処理スループットを低下させている。

本設計では、セッション管理のコンテキストマネージャ/DI統一、スレッドセーフな `SpeechBatchManager` 導入による排他制御とメモリクリーンアップ、および `asyncio.to_thread` による同期I/Oオフロードを実施し、バックエンドの堅牢性と並行性能を根本から改善する。

## 3. 詳細設計

### 3-1. DBセッション管理の統一 (`database.py`, `llm_service.py`)

#### (1) セッションコンテキストマネージャの標準化
FastAPIのリクエストスコープ外（バックグラウンドタスクやサービスクラス内部）で安全にDBセッションを生成・破棄できるように、`contextlib.contextmanager` を活用した標準ヘルパーを定義する。

```python
# backend/app/database.py
import contextlib
from typing import Generator
from sqlalchemy.orm import Session

@contextlib.contextmanager
def get_db_context() -> Generator[Session, None, None]:
    """Context manager for DB sessions outside of FastAPI request lifecycle."""
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

#### (2) サービスクラスでの統一
`llm_service.py` や `llm_request.py` では `with get_db_context() as db:` または `with SessionLocal() as db:` を使用し、例外発生時にも `finally` で確実に接続が解放されることを保証する。

### 3-2. スレッドセーフな `SpeechBatchManager` と排他制御 (`speech_batch.py`)

#### (1) クラス構造と状態保護
モジュールレベルのプレーンな辞書 `_batch_jobs`, `_job_tasks` を廃止し、専用のマネージャークラス `SpeechBatchManager` を導入する。

```python
class SpeechBatchManager:
    def __init__(self, max_history: int = 100):
        self._jobs: dict[str, schemas.SpeechBatchJobRead] = {}
        self._tasks: dict[str, asyncio.Task] = {}
        self._lock = asyncio.Lock()
        self._max_history = max_history

    async def create_job(self, payload: schemas.SpeechBatchJobCreate) -> schemas.SpeechBatchJobRead:
        async with self._lock:
            self._prune_old_jobs_locked()
            job_id = uuid.uuid4().hex[:12]
            items = [...]
            job = schemas.SpeechBatchJobRead(...)
            self._jobs[job_id] = job
            task = asyncio.create_task(self._run_batch_job(job_id))
            self._tasks[job_id] = task
            task.add_done_callback(lambda t: self._tasks.pop(job_id, None))
            return job

    async def get_job(self, job_id: str) -> Optional[schemas.SpeechBatchJobRead]:
        async with self._lock:
            return self._jobs.get(job_id)

    async def get_active_job(self) -> Optional[schemas.SpeechBatchJobRead]:
        async with self._lock:
            for job in reversed(list(self._jobs.values())):
                if job.status in ("processing", "pending"):
                    return job
            if self._jobs:
                return list(self._jobs.values())[-1]
            return None

    async def cancel_job(self, job_id: str) -> Optional[schemas.SpeechBatchJobRead]:
        async with self._lock:
            job = self._jobs.get(job_id)
            if not job:
                return None
            task = self._tasks.get(job_id)
            if task and not task.done():
                task.cancel()
            job.status = "cancelled"
            for item in job.items:
                if item.status in ("pending", "processing"):
                    item.status = "cancelled"
            return job

    async def cancel_item(self, job_id: str, item_id: str) -> Optional[schemas.SpeechBatchJobRead]:
        async with self._lock:
            job = self._jobs.get(job_id)
            if not job:
                return None
            for item in job.items:
                if item.id == item_id:
                    item.status = "cancelled"
                    break
            return job

    async def retry_item(self, job_id: str, item_id: str, payload: Optional[schemas.SpeechBatchItemRetryRequest] = None) -> Optional[schemas.SpeechBatchJobRead]:
        async with self._lock:
            job = self._jobs.get(job_id)
            if not job:
                return None
            found = False
            for item in job.items:
                if item.id == item_id:
                    if payload:
                        if payload.revision_instruction is not None:
                            item.previous_rewritten_text = item.rewritten_text
                            item.revision_instruction = payload.revision_instruction
                        if payload.scene_hint is not None:
                            item.scene_hint = payload.scene_hint
                        if payload.include_image is not None:
                            item.include_image = payload.include_image
                    item.status = "pending"
                    item.error = None
                    found = True
                    break
            if not found:
                return None

            if job.status in ("completed", "cancelled", "failed"):
                job.status = "processing"

            task = self._tasks.get(job_id)
            if not task or task.done():
                new_task = asyncio.create_task(self._run_batch_job(job_id))
                self._tasks[job_id] = new_task
                new_task.add_done_callback(lambda t: self._tasks.pop(job_id, None))
            return job

    def _prune_old_jobs_locked(self):
        """保持件数が max_history を超えた場合、完了・キャンセル・失敗済みの古いジョブから削除"""
        if len(self._jobs) >= self._max_history:
            finished_keys = [k for k, v in self._jobs.items() if v.status in ("completed", "cancelled", "failed")]
            excess = len(self._jobs) - self._max_history + 1
            for k in finished_keys[:excess]:
                self._jobs.pop(k, None)
```

### 3-3. 非同期I/OオフロードとDBアクセスの集約 (`speech_batch.py`)

#### (1) 同期処理の `asyncio.to_thread` による分離
- **DBクエリのオフロード**:
  `get_effective_speech_rewrite_system_prompt` や `models.Snapshot` / `models.SpeechTonePreset` のクエリを別スレッドで実行するヘルパーに切り出す。
- **画像読み込み・エンコードのオフロード**:
  `Path.exists()` や `load_image_as_base64()` を `asyncio.to_thread` 内で実行し、巨大画像読み込み時にもイベントループをブロックさせない。

```python
def _sync_fetch_batch_prerequisites(preset_id: Optional[int]) -> Tuple[str, Optional[str]]:
    """DBからシステムプロンプトとトーンプリセットを一括取得（同期実行用）"""
    with get_db_context() as db:
        system_prompt = get_effective_speech_rewrite_system_prompt(db)
        tone_prompt = None
        if preset_id:
            preset = db.query(models.SpeechTonePreset).filter(models.SpeechTonePreset.id == preset_id).first()
            if preset:
                tone_prompt = preset.prompt
        return system_prompt, tone_prompt

def _sync_load_item_image(image_path: Optional[str], snapshot_id: Optional[int]) -> Optional[str]:
    """ディスクおよびDBから画像ファイルを探索しBase64文字列化（同期実行用）"""
    image_file_path = None
    if image_path:
        filename = image_path.split("/")[-1]
        candidate = Path(settings.snapshot_path) / filename
        if candidate.exists():
            image_file_path = candidate
        elif Path(image_path).exists():
            image_file_path = Path(image_path)
    elif snapshot_id:
        with get_db_context() as db:
            s = db.query(models.Snapshot).filter(models.Snapshot.id == snapshot_id).first()
            if s and s.image_path:
                filename = s.image_path.split("/")[-1]
                candidate = Path(settings.snapshot_path) / filename
                if candidate.exists():
                    image_file_path = candidate
    if image_file_path:
        return load_image_as_base64(image_file_path)
    return None
```

#### (2) バッチ実行ループの最適化
- バッチ開始時に `_sync_fetch_batch_prerequisites` を1回のみ呼び出し、アイテムごとの重複DBクエリを完全に排除。
- 画像が必要なアイテムのみ `await asyncio.to_thread(_sync_load_item_image, ...)` を呼び出す。

## 4. トレードオフ・リスク開示 (Trade-offs & Constraints)

1. **インメモリジョブ管理の永続性**:
   - ジョブ情報はメモリ内（`SpeechBatchManager`）で管理されるため、バックエンドプロセスの再起動時には未完了および過去のジョブは消失する。
   - *緩和策*: 将来的なDB永続化への移行を容易にするため、`SpeechBatchManager` のインターフェースを明確に抽象化しておく。
2. **履歴プルーニング上限（`max_history=100`）**:
   - 完了ジョブが上限（100件）を超えた場合、古いジョブから自動的にメモリから破棄される。非常に過去のジョブIDに対するポーリングは 404 となる。
   - *妥当性*: フロントエンドのUIは直近のアクティブジョブの監視が主用途であり、100件の保持で実用上十分かつメモリリークを確実に防止できる。
3. **スレッドプールへのディスパッチ負荷**:
   - `asyncio.to_thread` によるスレッドディスパッチのわずかなオーバーヘッドが生じるが、イベントループのブロッキング回避と並行リクエスト処理能力向上のメリットが圧倒的に上回る。

## 5. 検証方針 (Acceptance Criteria Mapping)

- **AC-1**: `SessionLocal()` の呼び出しが `get_db_context()` / `with SessionLocal() as db:` に統一され、例外発生時にも `db.close()` が実行されることをユニットテストで検証。
- **AC-2**: `SpeechBatchManager` に対して複数の非同期コルーチンから同時に cancel / retry / create を発行しても競合エラーが発生せず、`max_history` 超過時に古いジョブが適切に破棄されることをテスト。
- **AC-3**: `_sync_load_item_image` や `_sync_fetch_batch_prerequisites` が `asyncio.to_thread` を介して実行されることをモックテストで確認。
- **AC-4**: 全バックエンド既存テスト（`test_speech_batch.py` を含む204件以上）がパスすること。
