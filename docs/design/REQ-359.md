## 2. 要件・SSoT

実装不具合の根拠は [`incident_report_react-update-depth.md`](../incident_report_react-update-depth.md)。raw workflow を `generationWorkflow` に毎render渡して新しい参照を生成し、Anima effect がその参照を依存に含むため、全store購読による再renderと effect 再実行が循環する。

`SPEC_GENERATE.md` の REQ-358 節を維持する。raw workflow と mapping state を変更せず、生成用 clone の mappings は明示 `false` の slot のみ除外する。API、保存形式、既存 Generate UI の構成は変更しない。

## 3. 設計

1. `useWorkflowManagement` 内で `generationWorkflow(rawWorkflow)` を `useMemo` し、raw workflow の参照が同じ間は表示用 workflow の参照を安定させる。
2. Zustandの `isAnimaMode` を唯一の状態源として購読し、hook内の重複local stateをなくす。返却する `isAnimaMode` と画面のtoggleは既存と同じstore値/操作を使う。
3. `setIsAnimaMode` は `useCallback` で安定させ、現在のZustand値を読み、booleanまたはfunctional updateをその値から解決する。値が違う場合だけstore actionを1回呼ぶ。React state updater内でstore副作用を実行しない。
4. Anima effectはworkflow、baseModels、selectedWorkflowId、stable setterを依存にし、workflow/model取得完了後に一度判定する。workflow参照はmemoizedなので同じraw workflowの無関係なstore renderでは変わらない。workflow切替時は同じbase model IDであってもselectedWorkflowIdの変化でeffectを起動する。store actionの同値更新はsetterで抑止する。
5. `generationWorkflow` のclone/filter意味と raw workflow保持は変更しない。Zustand slice action はこの修正で変更しない。

### Seam Map

- **Integrated (real code)**: `useWorkflowManagement` hook、React `useMemo` / `useEffect`、`generationWorkflow`、実Zustand generation storeとaction。回帰hook test harnessは本番GeneratePageと同じ全store購読を追加してstore通知からの再renderを再現する。
- **Severed (external I/O only)**: 実API client、domain関数、request変換は維持し、既存テスト内でglobal `fetch` だけをstubする。HTTP server、ComfyUI、DBには接続しない。
- **Mock Level**: API module、workflow導出、hook、store業務ロジックはmockしない。`fetch` transport境界だけを切断する。
- **PBT Decision**: 不要。変更対象はworkflow参照とboolean同期で、parser・DSL・数値ロジックではない。
- **Fault Injection**: 外部統合を変更しないため対象外。データ取得遅延と workflow切替はhookテストで確認する。

### 期待する状態遷移

```tsx
const workflow = useMemo(
  () => rawWorkflow ? generationWorkflow(rawWorkflow) : undefined,
  [rawWorkflow],
)

const isAnimaMode = useGenerationStore((state) => state.isAnimaMode)
const setIsAnimaMode = useCallback((val: boolean | ((prev: boolean) => boolean)) => {
  const store = useGenerationStore.getState()
  const next = typeof val === 'function' ? val(store.isAnimaMode) : val
  if (next !== store.isAnimaMode) store.setIsAnimaMode?.(next)
}, [])

useEffect(() => {
  if (!workflow || !baseModels) return
  const selectedModel = baseModels.find((model) => model.id === workflow.target_base_model_id)
  setIsAnimaMode(!!selectedModel && selectedModel.name === 'Anima')
}, [selectedWorkflowId, workflow, baseModels, setIsAnimaMode])
```

Manual toggles update the Zustand SSoT and do not trigger the Anima detection effect because mode state is not an effect dependency. A later workflow selection or resolved workflow/baseModels change re-evaluates automatic mode. React Query may deliver a new raw workflow reference after a real refetch; memoization recomputes once and the guarded setter prevents repeated same-value writes.

## 5. Review対象の決定

PBI AC-3により、workflow選択後のAnima状態は選択中workflowのbase modelから決定する。手動toggleは現在の選択に対する一時的な上書きとして維持し、workflow選択またはworkflow/baseModels情報が変化した際は自動判定を再適用する。恒久的なユーザーoverrideは本PBIの要件ではなく追加しない。

ローカルBA監査の最終出力はこの挙動をCRITICALとして指摘したが、その根拠は「手動toggleはworkflow切替後も維持すべき」という解釈である。これはPBI AC-3の「workflow切替後も正しく更新」と衝突するため、設計ではPBIを優先する。監査実行履歴と評価を [`REQ-359-ba-audit-trace.json`](./REQ-359-ba-audit-trace.json) に記録した。Architect reviewはPASS。人間の設計レビュー後に実装を開始する。
