# REQ-059: 生成完了後に履歴画像からのプレビュー切り替え機能が動作しなくなる問題 詳細設計

## 1. システム変更の概要
画像生成中の一時的な進捗プレビュー状態（`previewImage`）が、生成完了後や履歴選択（`setSelectedImg`）後も残存することにより、履歴画像を選択した際にメインプレビューが切り替わらなくなるバグを解消します。

「生成中のみ一時的に `previewImage` を使用し、生成完了時および履歴手動選択時は `previewImage` をクリアして `selectedImg` の表示に一本化する」という方針で状態管理を整理します。

## 2. 影響範囲とコンポーネント構成
- **フロントエンド状態管理**: `frontend/src/store/useGenerationStore.ts` (状態 `previewImage` の設定・クリア処理)
- **プレビュー表示**: `frontend/src/pages/GeneratePage.tsx` (表示優先度 `previewImage || selectedImg` はそのまま維持)

## 3. 詳細設計

### 3-1. `useGenerationStore.ts` の修正

#### ① 生成完了時のクリア (`executed` イベントハンドラ)
生成完了時に `previewImage` を `null` にクリアします。これにより、プレビュー表示は `selectedImg` (完成画像) に切り替わります。

**修正前 (L431付近)**:
```typescript
                  set((state) => {
                    const nextImages = [...newUrls, ...state.batchImages.filter((x) => !newUrls.includes(x))].slice(0, 8)
                    const nextHistoryImages = [...newUrls, ...state.comfyHistoryImages.filter((x) => !newUrls.includes(x))].slice(0, 50)
                    localStorage.setItem(LS_KEYS.BATCH_IMAGES, JSON.stringify(nextImages))
                    localStorage.setItem(LS_KEYS.SELECTED_IMG, firstUrl)
                    return {
                      previewImage: firstUrl, // ⚠️ 完成画像を previewImage に残してしまっている
                      batchImages: nextImages,
                      comfyHistoryImages: nextHistoryImages,
                      selectedImg: firstUrl,
                      isGenerating: false,
                      currentPromptId: null,
                      activeClientId: null,
                    }
                  })
```

**修正後 (L431付近)**:
```typescript
                  set((state) => {
                    const nextImages = [...newUrls, ...state.batchImages.filter((x) => !newUrls.includes(x))].slice(0, 8)
                    const nextHistoryImages = [...newUrls, ...state.comfyHistoryImages.filter((x) => !newUrls.includes(x))].slice(0, 50)
                    localStorage.setItem(LS_KEYS.BATCH_IMAGES, JSON.stringify(nextImages))
                    localStorage.setItem(LS_KEYS.SELECTED_IMG, firstUrl)
                    return {
                      previewImage: null, // ✅ 生成完了したため進捗プレビューをクリア
                      batchImages: nextImages,
                      comfyHistoryImages: nextHistoryImages,
                      selectedImg: firstUrl,
                      isGenerating: false,
                      currentPromptId: null,
                      activeClientId: null,
                    }
                  })
```

*(※ 同様に、履歴 reconcileState 処理内の `previewImage: finalImg` (L270付近) も `previewImage: null` に修正します)*

#### ② 履歴手動選択時のクリア (`setSelectedImg` アクション)
手動で履歴が選択された場合も、安全のため `previewImage` を `null` にクリアします。

**修正前 (L676付近)**:
```typescript
    setSelectedImg: (img) => {
      set({ selectedImg: img })
      if (img && !img.startsWith('blob:')) {
        localStorage.setItem(LS_KEYS.SELECTED_IMG, img)
      } else {
        localStorage.removeItem(LS_KEYS.SELECTED_IMG)
      }
    },
```

**修正後 (L676付近)**:
```typescript
    setSelectedImg: (img) => {
      set({ selectedImg: img, previewImage: null }) // ✅ previewImage を null にクリア
      if (img && !img.startsWith('blob:')) {
        localStorage.setItem(LS_KEYS.SELECTED_IMG, img)
      } else {
        localStorage.removeItem(LS_KEYS.SELECTED_IMG)
      }
    },
```

## 4. 設計のトレードオフとリスク (Trade-off & Risk Disclosure)
- **リスク**: 生成中にユーザーが履歴をクリックしてプレビューを切り替えた場合、生成中の進捗プレビュー表示（WebSocketによる一時画像）がリセットされ、手動選択された画像が表示されるようになります。
- **トレードオフ**: これはユーザーの明示的な「過去画像を見たい」というインテントを優先するための意図的な設計であり、仕様的に正当な挙動です。
