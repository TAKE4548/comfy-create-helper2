# REQ-033 詳細設計書

## 1. 背景・目的
スマートフォン等の外部端末から IP アドレス指定でフロントエンドにアクセスした際、過去のスナップショット画像（データベース以外の永続化情報）がリンク切れとなって表示されない問題を解決する。

## 2. システム構成・変更概要
本修正では、バックエンド（FastAPI）で以下の2点を行います。
1. **画像のローカルダウンロード＆保存**: フロントエンドから受け取った ComfyUI 上の画像 URL をバックエンドで読み込み、`db/snapshots/` ディレクトリ内に保存する。
2. **静的ファイルの配信マウント**: 保存された画像ファイルを、FastAPI の `StaticFiles` ミドルウェアを用いて `/api/snapshots/images/<filename>` としてマウント・配信する。

これにともない、データベースに格納される `snapshots.image_path` は `http://localhost:8188/view?...` のような絶対 URL から、`/api/snapshots/images/<filename>` のような相対 URL へと変更されます。

## 3. 詳細設計

### 3.1 画像ダウンロードと保存ロジック
`backend/app/routers/snapshots.py` の `create_snapshot` 処理時に、以下のロジックを実行する。

- **トリガー条件**: `payload.image_path` が `http://` または `https://` で始まる場合。
- **処理**:
  1. `image_path` のクエリパラメータ（例: `filename=...`）からファイル名を抽出する。ファイル名が取得できない、あるいは不適切な場合は自動生成する。
  2. セキュリティと衝突回避のため、元のファイル名の末尾に UUID の一部などを結合して一意のファイル名を生成する（例: `ComfyUI_00001__a1b2c3d4.png`）。
  3. `urllib.request` 等を用いて、画像をダウンロードする。
  4. `settings.snapshot_path` （`../db/snapshots/`）配下に保存する。
  5. データベースに保存するパスを `/api/snapshots/images/<一意のファイル名>` に変更する。

### 3.2 静的ファイル配信 (FastAPI マウント)
`backend/app/main.py` にて、FastAPI アプリケーション起動時に静的ファイルパスのマウントを行う。

```python
from fastapi.staticfiles import StaticFiles
from app.config import settings

# 既存のルーター群の定義の後にマウントを追加
app.mount(
    "/api/snapshots/images",
    StaticFiles(directory=settings.snapshot_path),
    name="snapshots_images"
)
```

## 4. 影響範囲 (SSoT)
- **バックエンドコード**:
  - [main.py](file:///backend/app/main.py) (静的ファイル配信設定)
  - [routers/snapshots.py](file:///backend/app/routers/snapshots.py) (画像ダウンロードとパスの書き換え)
- **データベース**:
  - `snapshots` テーブルの `image_path` カラムに格納されるパス形式が、外部 URL から `/api/snapshots/images/<filename>` に変わる。
