# REQ-356: テストスイート再構成 (SPEC-TESTING v2.1 準拠) 詳細設計書

## 1. 概要と背景
Prompt Surgeon の継続開発に伴い、PBI番号を含むフラットなテストファイル（例: `test_req334_*.py`, `e2e_req347_*.test.tsx`）が増殖し、テスト実行時間が約113秒まで肥大化している。
また、単体/結合/E2Eの境界が曖昧であり、DB永続化や外部通信のモック境界がテストごとに個別実装されていた。
本設計書は、テストアーキテクチャ設計仕様書（`SPEC_TEST_ARCHITECTURE.md` / SPEC-TESTING v2.1）に沿って、テスト階層の再構成、Seam Mapに基づく多層防護隔離、PBIトレーサビリティ規約（`[REQ-xxx/AC-n]`）の適用、実行ゲート（Gate 1/2/3）の整備を行うための詳細設計を定義する。

## 2. SSoT 影響分析
- **正本仕様書**: `docs/specs/SPEC_TEST_ARCHITECTURE.md` (SPEC-TESTING v2.1)
- **関連仕様書**: `docs/specs/SPEC_COMMON.md`
- **影響範囲**:
  - `backend/tests/`: ディレクトリ構造を `conftest.py` + `unit/`, `integration/`, `governance/` に再構成。ファイル名から `req[0-9]+` を全廃 (AC-1, AC-2)。
  - `frontend/src/`: テストを責務ごとに隣接 `__tests__/` にコロケーション。フラットな `src/test/e2e_req*.test.tsx` を廃止し、共通ヘルパーを `frontend/src/test/utils/` に集約 (AC-1, AC-3)。
  - `frontend/e2e/`: Playwright による実ブラウザ E2E（Gate 3）を新設。`position: sticky` および実スクロール検証を移行 (AC-8)。
  - `scripts/`: テスト名命名規則（`[REQ-xxx/AC-n]`）検証スクリプト `scripts/verify_test_naming.py` の追加 (AC-15)。

## 5. 多層防護（Defense-in-Depth）実装詳細

### 5.1 Backend 第1層: SAVEPOINT + Commit Interceptor (AC-4)
- `backend/tests/conftest.py` にセッションスコープの `db_engine` (`sqlite:///:memory:`, `StaticPool`) を定義。
- 各テスト用 fixture `db_session` でトランザクションを開始し、直後に nested トランザクション（SAVEPOINT）を作成。
- サービス層やルーターで `session.commit()` が呼ばれた際、`after_transaction_end` イベントリスナーにより外側のトランザクションをコミットさせず、直ちに新規 SAVEPOINT を再生成。
- テスト終了時にアウター・トランザクションを完全ロールバックすることで、テスト終了時のDBを常に完全クリーンに保つ。

### 5.2 Backend 第2層: respx トランスポート遮断 (AC-5)
- ComfyUI (`http://127.0.0.1:8188`) および LM Studio (`http://127.0.0.1:1234`) への HTTP リクエストを `respx` で捕捉。
- allowlist 以外の未定義リクエストは即座に `respx.MockRouter(assert_all_called=False)` により例外を送出。

### 5.3 Backend 第3層: `tmp_path` サンドボックス (AC-5)
- `isolated_snapshot_dir` fixture により、`settings.snapshot_dir` を pytest の `tmp_path / "snapshots"` に動的差し替え。
- 実本番フォルダ `db/snapshots/` への物理書き込みを 100% 遮断。

### 5.4 Frontend 5層ステート完全分離 (AC-6, AC-7)
- `storeHelpers.ts`: `useGenerationStore.setState(initialState, true)` による全プロパティ完全上書きクリア。
- `queryHelpers.ts`: `QueryClient({ defaultOptions: { queries: { gcTime: 0, retry: false } } })` によるテスト毎のキャッシュ独立。
- `wsHelpers.ts`: `MockWebSocketController` によるイベントディスパッチの決定論的制御。
- `fake-indexeddb`: テスト終了時に DB 接続をクローズして全ストアをクリア。
- `networkGuard.ts`: `window.fetch` および `window.WebSocket` の実通信を監視し、モック外の通信が発生した場合はテストを即時フェイル。

## 6. PBI トレーサビリティと検証スクリプト (AC-9, AC-15)
- **テストケース命名フォーマット**: `[REQ-xxx/AC-n] <テスト説明文>`
- **検証スクリプト**: `scripts/verify_test_naming.py`
  - 対象: `frontend/src/**/*.{test,spec}.{ts,tsx}`, `frontend/e2e/**/*.spec.ts`, `backend/tests/**/*.py`
  - 判定ロジック & BA監査改善反映:
    1. テスト名（`it("...", ...)` / `test("...", ...)` / `def test_*(...):`）に PBI番号が含まれる場合、必ず `[REQ-\d+/AC-\d+]` 形式を満たしていること。
    2. テストファイルパスに `req\d+` や `REQ-\d+` が含まれていないこと（AC-1 準拠）。
    3. ガバナンステスト（`test_no_req_naming.py` 等）を含む PBI番号に紐付かない汎用テストは「PBI紐づけなし」として集計・一覧表示し、エラーとせず終了コード0で通過させる（AC-15 準拠、ガバナンスパラドックス防止）。
    4. 違反が0件であれば終了コード 0 を返却。

## 7. 実行ゲートと並列実行安全性 (AC-11, AC-12, AC-14)
- **Gate 1 (Unit & Static)**: `pytest tests/unit` および `vitest run src/utils src/components/**/__tests__` (目標: 3〜5秒)。DBや重厚jsdom環境を排した高速フィードバック。
- **Gate 2 (Integration)**: `pytest tests/integration` (SAVEPOINT Rollback) および `vitest run src/pages` (目標: 15〜20秒、旧113秒から大幅短縮)。必要に応じて並行起動スクリプトにより Frontend / Backend を同時実行。
- **Gate 3 (E2E & Red Team)**: Playwright による実ブラウザシナリオおよび境界値検証 (目標: 10秒前後)。Desktop / Mobile の各検証ごとに独立した新規 `BrowserContext` を生成し、Cookie・Storage 汚染を完全防止。
- **並列安全性 (AC-14)**: `pytest-xdist` (`pytest -n auto`) の各ワーカープロセスが完全に独立した `:memory:` DB インスタンスとプロセス固有の `tmp_path` を保持するため、プロセス間でのデータ競合なく決定論的にパスすることを保証する。
