## 2. 結合・シナリオ検証 (Integration Scenarios)

### シナリオ 1: プロンプト入力クリア・前回入力値保持 (AC-1)
1. プリセット一括編集モーダルを開き、「プロンプト」タブを選択。
2. 検索置換の「検索する文字列」に `"cat"`、「置換後の文字列」に `"dog, cute"` を入力。
3. 「クリア」ボタンが活性化していることを確認。
4. 「検索する文字列」の「クリア」ボタンを押下 -> `promptFindText` が即座に空になることを確認。
5. 「置換後の文字列」はクリアせずモーダルを一旦「×」で閉じる。
6. 再度プリセット一括編集モーダルを開く -> 「置換後の文字列」に `"dog, cute"` が保持されていることを確認。

### シナリオ 2: パラメータ選択の自動解除 (AC-2)
1. 「パラメータ」タブを選択。
2. `sampler_name` と `steps` のチェックボックスを ON にし、値を変更。
3. 「適用」ボタンを押下し、確認画面で「適用する」を実行。
4. 適用完了後、`sampler_name` および `steps` のチェックボックスが OFF（未選択）にリセットされていることを確認。
5. 意図しない再適用が発生しないことを確認。

### シナリオ 3: 適用後のモーダル維持およびESC終了制御 (AC-3)
1. プロンプトまたはパラメータの変更を一括適用する。
2. 適用完了後もモーダルが閉じずに表示されたまま維持されていることを確認。
3. 画面上に適用成功のトースト（または通知）が表示されることを確認。
4. キーボードの `Escape` キーを押下 -> モーダルが正常に閉じることを確認。

### シナリオ 4: 共通タグのサブセット抽出と動的再集計 (AC-4)
1. プリセット 1, 2, 3 を選択してモーダルを開く。
2. 「プロンプト」タブで操作タイプ「共通タグ編集・削除」を選択。
3. 対象プリセット絞り込みセクションでプリセット 3 のチェックを外す。
4. プリセット 1 と 2 のみに共通するタグが即時再計算されてチップ一覧に表示されることを確認。
5. タグ強度を変更し「適用」を実行。
6. プリセット 1 と 2 にのみ変更が反映され、プリセット 3 には影響しないことを検証。

### シナリオ 5: プロンプト対象欄のモード別排他制御 (AC-5)
1. 操作タイプ「検索・置換」を選択 -> 対象フィールドで「すべて対象」チェックボックスおよび複数フィールドの選択が可能なことを確認。
2. 複数フィールド（例: `positive`, `negative`）が選択された状態で、操作タイプを「先頭に追加」に変更。
3. 対象フィールドが単一排他的（ラジオボタン）となり、「すべて対象」が非表示になり、先頭の1件（`positive`）のみが選択状態として維持されていることを確認。
4. 別のフィールドをクリックすると、直前の選択が解除され、新たにクリックしたフィールドのみが選択されることを確認。

### シナリオ 6: パラメータインクリメンタル検索フィルタ (AC-6)
1. 「パラメータ」タブを選択。
2. パラメータ検索ボックスに `"sampler"` と入力。
3. `sampler_name` のみが表示され、他のパラメータが非表示になることを確認。
4. `sampler_name` のチェックボックスを ON にする。
5. 検索ボックスを空にする -> すべてのパラメータが再表示され、`sampler_name` のチェック状態が維持されていることを確認。
6. 検索ボックスに存在しないパラメータ名（例: `"xyz_unknown"`）を入力 -> 「該当するパラメータが見つかりません」が表示されることを確認。この状態でも適用を実行した場合、先ほどチェックした `sampler_name` が正常に適用ペイロードに含まれることを確認。

### シナリオ 7: 共通タグのサブメニュー編集統一 (AC-7)
1. 「共通タグ編集・削除」で共通タグチップを表示。
2. タグチップのテキスト部分をクリック -> 削除フラグは立たず、タグ編集サブメニュー（ポップオーバー）が開くことを確認。
3. サブメニュー内の強度増減ボタン（`+0.1`）を押下 -> 強度が更新されることを確認。
4. サブメニュー内のタグ名を編集して Enter -> 文言が更新されることを確認。
5. タグチップ右端の独立した削除アイコン（`X`）を押下 -> タグが取り消し線・赤色表示になり、削除対象としてマークされることを確認。

## 3. レッドチーミング・境界値・異常系 (Red Teaming Scenarios)

### Red Team 1: サブセットプリセット全解除時の境界値テスト
- **手順**: 共通タグ編集のサブセット選択で「全解除」を押下し、対象プリセットが 0 件の状態にする。
- **検証ポイント**:
  - `computeCommonTags` が空配列を安全に返し、クラッシュ（`TypeError`）しないこと。
  - 「共通タグが見つかりません」または対象プリセット未選択の警告メッセージが適切に表示されること。
  - ペイロード生成時に不正なリクエストが送出されず、UIが安全に防御すること。

### Red Team 2: 特殊文字・正規表現メタ文字によるパラメータ検索
- **手順**: パラメータ検索ボックスに `.*`, `[a-z`, `(`, `\\`, `???` 等の正規表現メタ文字を入力。
- **検証ポイント**:
  - 正規表現コンパイルエラー（SyntaxError）が発生せず、純粋な部分文字列一致（`string.includes`）として安全に処理されること。
  - UIの描画が崩れず、該当なしメッセージが正常に表示されること。

### Red Team 3: ESCキーのバブリングと多重クローズ境界値
- **手順**:
  1. 共通タグのサブメニュー（ポップオーバー）を開いた状態で `Escape` キーを押下。
  2. モーダル全体が閉じてしまうのではなく、**サブメニューのみが閉じる**ことを確認。
  3. サブメニューが閉じた状態で再度 `Escape` キーを押下した際に、**モーダル本体が閉じる**ことを確認。
- **検証ポイント**: `e.stopPropagation()` によるイベント階層の確実な分離。

### Red Team 4: 連続適用の高速連打と OCC 競合防止
- **手順**: モーダルを開いたまま連続して異なるパラメータを適用（例: 1回目の適用直後に2回目の適用を実行）。
- **検証ポイント**:
  - 1回目の適用で最新の `updated_at` がインメモリキャッシュに反映されているため、2回目の適用で 409 Conflict が誤検知されないこと。
  - `isApplying` ローディングガードにより、処理中の重複クリックがブロックされること。
