# REQ-152 詳細設計書: バッチ生成キュー登録時の不要オーバーヘッド削減およびキャンセル時状態復活デグレの修正

## 1. 概要 (Overview)
複数プリセット・バッチ生成のキュー投入中において、ユーザーが「一括キャンセル」または個別「キャンセル」を実行した際に、ストアの `activeBatch` がクリアされた直後に投入ループ側の `finally` 句によって未投入の仮ID（`pending-...`）を含むバッチ配列でストアが上書きされ、生成中ステータスが復活してしまうデグレ（REQ-141導入時）が発生していました。
また、ComfyUIへのHTTP投入通信（`POST /prompt`）に `AbortSignal` が連動しておらず、かつ投入ループ中にWebSocket経由の過剰な `fetchQueue()` や多重のReact再レンダリングが発生し、UI応答性が悪化していました。

本設計では、以下の改善を行い、確実なキャンセル中断と高速なキュー登録レスポンスを実現します：
1. **キャンセル中断時のステート復活防止 (`finally` ガード)**:
   - `handleGenerateSets` の `finally` 句において、`abortController.signal.aborted` が true の場合は `setActiveBatch` の上書きおよび `fetchQueue()` の呼び出しを完全に抑止。
   - `await queuePrompt` の完了直後にも `abortController.signal.aborted` をチェックし、中断後の配列更新を遮断。
2. **`queuePrompt` への `AbortSignal` 伝播**:
   - `queuePrompt` のオプションに `signal?: AbortSignal` を追加し、`fetch('/prompt', { signal })` に渡すことでネットワークレベルでの即時中断を実現。
   - 中断時の `AbortError` はエラートーストを出さずに安全に捕捉。
3. **逐次投入ループのステート更新最適化と不要通信抑制**:
   - バッチ投入中の中間ジョブ投入において不要な重いステート更新をスキップするオプション `isBatchIntermediate` を追加。
   - バッチ投入中に受信した WebSocket `status` による `fetchQueue()` をデバウンス/抑制し、メインスレッド負荷を低減。
4. **`cancelGeneration` および `handleGenerate` の中断連携強化**:
   - `cancelGeneration` でも `abortSubmission()` を呼び出し、単一生成ループ（`handleGenerate`）でも `AbortController` と `skipQueueFetch` を導入。

## 3. 詳細設計 (Detailed Design)

### 3.1 `useGenerateAction.ts` の改善

```typescript
const handleGenerateSets = async () => {
  if (!workflow) return
  const checkedSets = sets.filter((s) => s.checked)
  if (checkedSets.length === 0) return

  // 中断用 AbortController の作成とストア登録
  const abortController = new AbortController()
  setSubmissionAbortController?.(abortController)

  // 事前に全体の枠を構築して activeBatch を即時初期化 (0ms pending)
  const initialBatch: BatchJob[] = []
  checkedSets.forEach((setItem) => {
    for (let i = 0; i < setItem.batchSize; i++) {
      initialBatch.push({
        promptId: `pending-${setItem.name}-${i}-${Date.now()}`,
        setName: setItem.name,
        status: 'pending'
      })
    }
  })
  setActiveBatch(initialBatch)

  const currentBatch: BatchJob[] = [...initialBatch]
  const mappingsJson = localStorage.getItem('prompt-surgeon-prompt-to-set-map') || '{}'
  const mappings = JSON.parse(mappingsJson)

  const activeBypassNodeIds = Array.from(
    new Set(
      bypassProfiles
        .filter((p) => p.is_enabled)
        .flatMap((p) => p.bypassed_node_ids)
    )
  )

  let currentIdx = 0
  try {
    for (const setItem of checkedSets) {
      const syncedParamValues = applyParamSync(setItem.paramValues)
      for (let i = 0; i < setItem.batchSize; i++) {
        // キャンセル中断チェック (ループ前)
        if (abortController.signal.aborted) {
          console.log('Batch queueing aborted by user.')
          return
        }

        let wfJson = JSON.parse(JSON.stringify(workflow.json_body)) as Record<string, unknown>
        injectParams(wfJson, syncedParamValues, setItem.seedMode, setItem.seed, i)
        if (activeBypassNodeIds.length > 0) {
          wfJson = applyBypass(wfJson, activeBypassNodeIds, comfyObjectInfo)
        }
        
        let promptId: string | null = null
        try {
          promptId = await queuePrompt(
            wfJson,
            { paramValues: syncedParamValues, appliedAssets: setItem.appliedAssets },
            { skipQueueFetch: true, signal: abortController.signal, isBatchIntermediate: true }
          )
        } catch (err: any) {
          if (err?.name !== 'AbortError' && !abortController.signal.aborted) {
            console.error(`Failed to generate set ${setItem.name} (batch index ${i}):`, err)
          }
        }

        // キャンセル中断チェック (通信完了直後)
        if (abortController.signal.aborted) {
          console.log('Batch queueing aborted by user after prompt.')
          return
        }

        if (promptId) {
          mappings[promptId] = setItem.name
          currentBatch[currentIdx] = {
            ...currentBatch[currentIdx],
            promptId,
            status: 'pending',
          }
          setActiveBatch([...currentBatch])
        } else {
          const errorMsg = `[${setItem.name}] (${i + 1}/${setItem.batchSize}) のキュー投入に失敗しました`
          setErrorToast?.({ message: errorMsg, type: 'error' })
          currentBatch[currentIdx] = {
            ...currentBatch[currentIdx],
            status: 'failed',
          }
          setActiveBatch([...currentBatch])
        }
        currentIdx++
      }
    }
  } finally {
    localStorage.setItem('prompt-surgeon-prompt-to-set-map', JSON.stringify(mappings))
    setSubmissionAbortController?.(null)
    
    // 中断時はストアがすでにクリアされているため、上書きおよびフェッチを行わない
    if (!abortController.signal.aborted) {
      setActiveBatch([...currentBatch])
      await fetchQueue?.()
    }
  }
}
```

### 3.2 `useGenerationStore.ts` の改善

#### `queuePrompt` の AbortSignal 対応
```typescript
queuePrompt: async (workflow, metadata, options) => {
  if (!comfyUrl) return null
  const activeUrl = resolveComfyUrl(comfyUrl)
  try {
    const res = await fetch(`${activeUrl}/prompt`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ prompt: workflow, client_id: get().clientId }),
      signal: options?.signal,
    })
    if (!res.ok) {
      let errorMsg = `ComfyUI returned ${res.status}`;
      try {
        const errData = await res.json();
        if (errData && errData.error) {
          errorMsg = typeof errData.error === 'object' ? errData.error.message || errData.error.details || JSON.stringify(errData.error) : String(errData.error);
        }
      } catch {}
      get().setErrorToast({ message: errorMsg, type: 'error' });
      throw new Error(errorMsg);
    }
    const data = await res.json()
    const promptId = data.prompt_id ?? null
    
    // バッチ中間投入時は最低限の更新に抑えて再レンダリング頻度を抑制
    if (!options?.isBatchIntermediate) {
      set({
        isGenerating: true,
        previewImage: null,
        progress: null,
        currentPromptId: promptId,
        activeClientId: get().clientId,
        currentWorkflow: workflow,
      })
    } else {
      set({
        isGenerating: true,
        currentPromptId: promptId,
      })
    }
    
    if (promptId) {
      localStorage.setItem(LS_KEYS.CURRENT_PROMPT_ID, promptId)
      const metaKey = `prompt-surgeon-meta-${promptId}`
      const promptMetadata = {
        paramValues: metadata?.paramValues ?? get().paramValues,
        appliedAssets: metadata?.appliedAssets ?? get().appliedAssets,
        timestamp: Date.now()
      }
      localStorage.setItem(metaKey, JSON.stringify(promptMetadata))

      setTimeout(() => {
        try {
          const keys = Object.keys(localStorage).filter(k => k.startsWith('prompt-surgeon-meta-'))
          if (keys.length > 200) {
            const items = keys.map(k => {
              try {
                const val = JSON.parse(localStorage.getItem(k) || '{}')
                return { key: k, timestamp: val.timestamp || 0 }
              } catch {
                return { key: k, timestamp: 0 }
              }
            })
            items.sort((a, b) => a.timestamp - b.timestamp)
            const toDelete = items.slice(0, items.length - 200)
            toDelete.forEach(item => localStorage.removeItem(item.key))
          }
        } catch (e) {
          console.error('Failed to prune prompt metadata:', e)
        }
      }, 0)
    }
    if (!options?.skipQueueFetch) {
      await get().fetchQueue()
    }
    return promptId
  } catch (e: any) {
    if (e?.name === 'AbortError' || options?.signal?.aborted) {
      console.log('queuePrompt fetch aborted')
      return null
    }
    console.error('Failed to queue prompt:', e)
    get().setErrorToast({ message: e.message || 'Failed to queue prompt', type: 'error' });
    return null
  }
}
```

## 4. トレードオフ・リスクの開示 (Trade-off Disclosure)
- **中断時のComfyUI側タイミング問題**: HTTPリクエストがComfyUIサーバーに到着してキュー登録されたミリ秒後にクライアント側で中断シグナルが発火した場合、クライアントは即座に停止しますが、すでにComfyUI側に登録されたジョブは `cancelJob` / `cancelAllJobs` の `/queue` DELETE リクエストによって削除されます。このため、クライアント側とComfyUI側の双方で確実にキャンセルされます。
- **isBatchIntermediate によるステート軽量化**: バッチ投入中は `currentWorkflow` の store 更新を最終ジョブまたは `handleGenerateSets` 完了時までスキップすることで、Reactの再レンダリング回数を削減します。単一ジョブ投入時には従来通り即座に更新されます。
