# 設計書 - REQ-030: スナップショット一覧のアルバム表示不具合の修正

## 1. 目的と概要
現在、「History」画面の「Albums」タブを選択した際にアルバム一覧が何も表示されない不具合が発生しています。
これは、バックエンドのアルバム一覧取得 API（`GET /api/albums`）が `AlbumSummary` スキーマを返しているのに対し、フロントエンド側でアルバム内のスナップショット画像一覧（`items`）を直接参照（`album.items.slice(0, 3)`）しているために発生している、レスポンススキーマの不整合が原因です。
本設計では、`GET /api/albums` のレスポンスを `AlbumRead` スキーマに変更し、フロントエンド側で必要な `items` データを正しく返却するように改善します。

## 2. 詳細設計

### 2.1 バックエンド修正

1. **`list_albums` エンドポイントのレスポンススキーマ変更**:
   `backend/app/routers/albums.py` の `list_albums` 関数を以下のように修正します。
   * **レスポンスモデル変更**: `response_model=list[schemas.AlbumSummary]` から `response_model=list[schemas.AlbumRead]` に変更。
   * **シリアライズ処理**: Pydantic の `AlbumRead` スキーマが要求する `items` フィールドには、各 `AlbumItem` の `snapshot` に紐づく `image_path` が必要です。そのため、`get_album` エンドポイントと同様に、手動で `schemas.AlbumRead` オブジェクトを構築して返却するようにします。

   ```python
   @router.get("", response_model=list[schemas.AlbumRead])
   def list_albums(db: Session = Depends(get_db)):
       albums = db.query(models.Album).order_by(models.Album.name).all()
       return [
           schemas.AlbumRead(
               id=album.id,
               name=album.name,
               created_at=album.created_at,
               items=[
                   schemas.AlbumItemRead(
                       snapshot_id=item.snapshot_id,
                       sequence_order=item.sequence_order,
                       image_path=item.snapshot.image_path if item.snapshot else None,
                   )
                   for item in sorted(album.items, key=lambda x: x.sequence_order)
               ],
           )
           for album in albums
       ]
   ```

### 2.2 フロントエンド確認
フロントエンドの `HistoryPage.tsx` はすでに `albumsApi.list()` から返された `albums` を `Album[]` 型（`items` フィールドを含む）として処理しているため、APIのレスポンス修正のみで正常に動作するようになります。

## 3. 影響範囲
* `backend/app/routers/albums.py`: `list_albums` のエンドポイント実装。
