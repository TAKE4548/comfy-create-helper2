# REQ-412 詳細設計書: ヘッダーリソースモニタからのComfyUIメモリ解放アクション実行

## 1. 概要と受入基準

共通ヘッダー（`PageHeader` 右クラスタ）の `ResourceHoverMonitor` が表示する 2 つの詳細パネル（640px 以上のホバーカード `resource-hover-card`、640px 未満のタップオーバーレイ `mobile-resource-overlay`）に「ComfyUI メモリ解放」ボタンを追加する。送信・ガード・フィードバックは Settings system 欄（`ServiceConnectionCard`）の既存実装（REQ-380）を共有フックへ抽出して再利用し、Manager API（`POST http://<host>:8899/api/action {"action":"free-memory","service":"comfy"}`）とサーバー側 guard／lock は変更しない。

| AC | 要旨 | 主な仕組み |
|---|---|---|
| AC-1 | デスクトップのホバーカードにボタン表示、カード内移動で閉じず押下可能 | `HeaderFreeMemoryAction`（desktop）をカード末尾に配置。既存 `hoverBridge` と React portal のイベント伝播でホバー継続 |
| AC-2 | モバイルのオーバーレイにボタン表示・タップ可能 | 同コンポーネント（mobile）をオーバーレイ末尾に配置 |
| AC-3 | アイドル時に送信、応答確認まで disabled＋ローディング、二重送信防止 | 共有フック `useComfyFreeMemory` のモジュール共有ロック（同一タブ内の全インスタンスで共有）＋既存の送信後 status 2 回再取得 |
| AC-4 | 受付成功時に受付文言、完了断定なし | 既存文言「解放要求を受け付けました。空き容量は監視値で確認してください」を共有定数化 |
| AC-5 | 実行中・キュー待機・未接続・他操作中は disabled＋理由表示 | 既存 guard を純関数 `deriveFreeMemoryGuard` に抽出。`action_in_progress` に加えローカル共有ロックも「他操作中」と判定 |
| AC-6 | 切断・HTTP エラー・タイムアウトで「要求結果未確認」または失敗理由 | 既存 `systemManagerApi.freeMemory` のエラー分類を流用。未確認文言の先頭に「要求結果未確認」を付与 |
| AC-7 | ヘッダー下端＋6px と内部スクロールで末尾（ボタン）到達 | `HeaderDropdown`（SPEC_COMMON §4-4-1）を変更せず利用。ボタン群を各パネルの最終子要素にする |

## 3. アーキテクチャ設計

### 3.1 現状

- `ServiceConnectionCard.tsx` L32-L65 に free-memory の有効条件（`freeMemoryEnabled`）、理由文言（`freeMemoryReason`）、送信処理（`runFreeMemory`：`busyRef` ロック → `systemManagerApi.freeMemory()` → 文言設定 → `settings-vram` 無効化 → finally で `refetch()` を 2 回）がコンポーネント内に閉じている。
- `PageHeader` はすでに `useManagerStatus()`（モジュール共有の 2 秒ポーリングストア）を購読しているため、ヘッダーから同じストアを読んでも新たなポーリングは増えない。
- `ResourceHoverMonitor` のホバーカードは `role="tooltip"`。

### 3.2 方式: 共有フック `useComfyFreeMemory` への抽出

新規 `frontend/src/hooks/useComfyFreeMemory.ts` に以下を置く（D4 参照）。

1. **純関数 `deriveFreeMemoryGuard`**: 既存 L35-L41 の条件と理由文言をそのまま移す。`busy` には `status.action_in_progress != null` に加え、ローカル共有ロック `localOperation !== null` を含める。
2. **モジュール共有ストア**（`useSyncExternalStore`。`useManagerStatus` と同じ方式）: `operation: string | null`（同一タブ内の Manager 操作ロック）と `freeMemoryFeedback`（最新の結果文言）。ロックは `tryBeginManagerOperation(key)` / `endManagerOperation(key)` で同期的に取得・解放し、Settings のカードとヘッダーのどちらから押しても二重送信にならない。
3. **`useComfyFreeMemory(options)`**: `useManagerStatus()` と共有ストアを読み、`enabled`・`reason`・`pending`・`feedback`・`run()` を返す。`run()` は既存 `runFreeMemory` と同じ手順（ロック取得 → pending 文言 → `systemManagerApi.freeMemory()` → 成功時 `onAccepted` → finally で `refetch()` 2 回 → ロック解放）。
4. **結果文言**: 成功・送信中・失敗は既存文言を維持。未確認（`ManagerActionOutcomeUnknownError`）は SPEC_SETTINGS の「要求結果未確認」表示要件に合わせ、先頭に `要求結果未確認: ` を付ける。

`ServiceConnectionCard` はこのフックを使うよう置き換え、`runAction`（start/stop/restart）も同じ共有ロックを取得する。これでヘッダーからの解放中は Settings の操作ボタンも無効になり、Settings の操作中はヘッダーのボタンも「別のサービス操作中です。」で無効になる。

### 3.3 ヘッダー UI: `HeaderFreeMemoryAction`

新規 `frontend/src/components/common/header/HeaderFreeMemoryAction.tsx`（`variant: 'desktop' | 'mobile'`）。パネルの子として描画されるため、パネルが開いている間だけマウントされる。結果文言はモジュール共有ストアにあるため、カードが閉じてもリクエストは継続し、開き直すと結果を確認できる。

- ボタン: `type="button"`、アクセシブル名「ComfyUI メモリ解放」、`disabled={!enabled || pending}`、`aria-busy={pending}`、pending 中は `Loader2`（`animate-spin`）、通常時は `RefreshCw`（lucide-react）。`w-full min-h-[44px] touch-manipulation text-xs whitespace-nowrap`。
- 理由: `!enabled && !pending` のとき `reason` を `text-[11px] break-words` で表示（省略しない。SPEC_COMMON §1-5-4）。
- 結果: `role="status" aria-live="polite"` に `feedback.message`。
- 配置: 各パネルの**最終子要素**とし、区切り線 `border-t` の下に置く。

`ResourceHoverMonitor` のホバーカードは対話要素を含むため `HeaderDropdown` へ渡す `role="tooltip"` を外し、カードの children 全体を `<div role="group" aria-label="リソース詳細">` で包む（WAI-ARIA の tooltip は対話要素を含めない。`HeaderDropdown` は `aria-label` を受け取れず変更禁止のため、ラッパー方式とする）。デスクトップのボタン群はこの group の最終子要素になる。これに伴い REQ-346 の既存アサーション（単体 1 箇所、E2E 1 箇所）を更新する。

### 3.4 トレードオフとリスク

| 論点 | 採用 | 代替案と不採用理由 |
|---|---|---|
| ロジック再利用 | 共有フック＋純関数へ抽出し Settings も移行 | ヘッダー側へ複製: guard 文言・条件の二重管理になり乖離リスク。Settings を残したまま新フックだけ作る: 同一タブ内ロックが共有できない |
| 同一タブ内ロック | モジュール共有ストア | React Context: `PageHeader` と Settings 本体が別ツリー位置にあり Provider 追加が必要。既存テスト多数の render ラッパー変更を誘発する |
| `useQueryClient` | フックでは使わず `onAccepted` コールバックで注入 | フック内で直接使う: ヘッダーを描画する既存テスト（QueryClientProvider なし）が一斉に失敗する |
| フィードバック表示 | パネル内インライン（共有ストアで保持） | 全体トースト: 共通トースト基盤がなく範囲外。PBI の「望ましい」点はパネル再表示で確認できる形で満たす |
| ホバーカードの role | `tooltip` を外し内側を `group` で包む（REQ-346 アサーション更新） | `tooltip` 維持: 対話要素を含む tooltip は a11y 上不正。`dialog`: フォーカス管理が §4-4-1 非目標と衝突 |

リスク:
- **R1 無効ボタン上からの離脱**: 旧 Chromium では disabled 要素上でマウスイベントが発火しない場合があった。E2E（Red Team RT-3）で「無効ボタン上から外へ移動するとカードが閉じる」を確認する。
- **R2 Manager 8899 の CORS とルート**: E2E は 8899 を `page.route` で切断する。プリフライト（OPTIONS）と CORS ヘッダーを fulfill で明示する。
- **R3 既存 E2E（REQ-346/AC-3 ホバーカード末尾到達）**: カード内容が伸びるため、スクロール前提の既存ケースの数値が変わり得る。既存アサーションは「GPU 行がビューポート内」なので通る見込みだが、失敗時は T2 内で原因を調べ、アサーションの意図（末尾到達）を保って調整する。
- **R4 文言変更**: 未確認文言の先頭に「要求結果未確認: 」を加えるため、Settings 表示も変わる。既存テストは `/要求結果未確認/` を正規表現で照合しており影響は限定的。
- **R5 共有ストアのテスト間汚染**: モジュール状態のため `resetManagerOperationStoreForTests()` を公開し、該当テストの `afterEach` で呼ぶ。
- **R6 queue 確認と /free 間の外部投入競合**: Manager 側の既知の非原子性（server_manager_guide）であり本 PBI で変更しない。

### D4. 共有契約

`frontend/src/hooks/useComfyFreeMemory.ts`（T1 が実装、T2 が利用）:

```ts
import type { ManagerStatus } from '../api/domains/systemManager'

export const FREE_MEMORY_OPERATION_KEY = 'comfy:free-memory'
export const FREE_MEMORY_MESSAGES = {
  pending: '解放要求を送信中',
  accepted: '解放要求を受け付けました。空き容量は監視値で確認してください',
  unconfirmed: '要求結果未確認: 解放要求の結果を確認できません。状態を再取得します。操作は再送しません。',
  failedPrefix: '解放要求に失敗しました: ',
} as const

export type FreeMemoryFeedbackKind = 'none' | 'pending' | 'accepted' | 'unconfirmed' | 'failed'
export interface FreeMemoryFeedback { kind: FreeMemoryFeedbackKind; message: string }
export interface FreeMemoryGuardInput { status: ManagerStatus | null; available: boolean; localOperation: string | null }
export interface FreeMemoryGuard { enabled: boolean; reason: string }

export function deriveFreeMemoryGuard(input: FreeMemoryGuardInput): FreeMemoryGuard
export function tryBeginManagerOperation(key: string): boolean // 取得済みなら false
export function endManagerOperation(key: string): void // key 一致時のみ解放
export function useManagerOperation(): string | null
export function resetManagerOperationStoreForTests(): void
export interface UseComfyFreeMemoryOptions { onAccepted?: () => Promise<unknown> | void }
export interface UseComfyFreeMemoryResult extends FreeMemoryGuard {
  pending: boolean // operation === FREE_MEMORY_OPERATION_KEY
  feedback: FreeMemoryFeedback
  run: () => Promise<FreeMemoryFeedback | null> // ガード不成立・ロック取得失敗時は送信せず null
}
export function useComfyFreeMemory(options?: UseComfyFreeMemoryOptions): UseComfyFreeMemoryResult
```

- 理由文言（優先順・既存と同一）: Manager 不可 `Manager状態を確認できません。` → busy（`action_in_progress` または `localOperation`）`別のサービス操作中です。` → 非 LISTEN `ComfyUIが停止中または状態不明です。` → executing `ComfyUIで生成中です。` → queued/件数≠0 `ComfyUIのキューが空ではありません。` → その他 `ComfyUIの実行状態が不明です。`。enabled のとき `''`。
- Manager API 契約（不変）: `systemManagerApi.freeMemory(): Promise<ManagerActionResult>`、`ManagerActionOutcomeUnknownError`、`useManagerStatus(): { status; available; refetch }`。
- DOM 契約（T2）: ボタンのアクセシブル名 `ComfyUI メモリ解放`、`data-testid="resource-free-memory"`（ボタン群ラッパー。モバイルは `mobile-resource-overlay` の最終子要素）、`resource-free-memory-button`、`resource-free-memory-reason`、`resource-free-memory-status`。ホバーカード `resource-hover-card` は role 属性なし、その直下に `role="group"`・`aria-label="リソース詳細"` のラッパー（デスクトップの `resource-free-memory` はこの group の最終子要素）。既存の `data-testid`（`resource-hover-card`、`resource-hover-card-bridge`、`mobile-resource-overlay`、`mobile-vram-pill`、`mobile-overlay-close`）は不変。
