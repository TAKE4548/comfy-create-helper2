# REQ-413 設計書: マスタ無効化ステージバリアントの生成・パラメータ表示・ステージグループ除外

## 1. 概要と背景

### 1.1 現状の課題と原因
ノードマッピングマスタにおいて、あるロールの「通常 / Main」ステージバリアントが無効化（`MappingVariant.is_enabled = false`）されている場合（例: FaceDetailer, BboxThreshold, Upscale 等）、リマッピング画面（`RescanModal`）や Settings 配線画面（`WorkflowConnectionSection`）では当該スロットが非表示となる（`useMasterMappingRows` による `v.is_enabled !== false` フィルタ）。
しかし、過去に保存された既存ワークフローや V2 移行時に自動作成されたワークフローには、DB 上（`workflow_mappings`）に当該バリアントのマッピングレコードが残存している。

現在の生成画面実装では：
1. `useWorkflowManagement` が `mappingMasters` から `SlotDefinition` を構築する際、`variant.is_enabled` を確認せず `variantEnabled` を設定していない。
2. `generationWorkflow`（`workflowMappingState.ts`）はワークフロー個別の `mapping_slot_states`（明示 `false` のみ除外）しか評価せず、マスタ側のバリアント有効フラグを評価しない。
3. `groupMappingsByStage`（`mappingStageGroups.ts`）はバリアントを解決するが、`variant.is_enabled === false` のマッピングを除外しない。

この結果、リマッピング画面にはスロットが表示されずユーザーが割り当てを解除することもできないにもかかわらず、生成画面のパラメータ入力枠（ParamPanel）やプロンプト枠に表示され続け、生成実行時にも ComfyUI ワークフロー JSON へパラメータやプロンプトが注入され続ける（詳細は `docs/incident_report.md` 参照）。

### 1.2 本改修の解決方針 (AC-1〜AC-5 の達成)
本設計では、DB のマッピングレコード（マスタ側で再有効化された場合に即時復旧するため）は保持しつつ、以下の 3 つの変更により全受入基準を達成する：
1. **`SlotDefinition` の拡張とフラグ伝播 (`REQ-413-T1`, AC-1, AC-2)**:
   `SlotDefinition` に `variantEnabled?: boolean` を追加し、`useWorkflowManagement` で `mappingMasters` の各バリアントから `variant.is_enabled !== false` を渡す。
2. **`generationWorkflow` での除外選別 (`REQ-413-T1`, AC-1, AC-2, AC-3, AC-4)**:
   `generationWorkflow` において、`variantEnabled === false` のマッピング、および全バリアントが無効なマスタのレガシーマッピング（`variant_id == null`）を生成用 `workflow.mappings` から除外する。有効バリアント（`variantEnabled !== false`）かつ `mapping_slot_states` が `false` でないものは保持する（AC-3）。
3. **`groupMappingsByStage` でのステージグループ除外 (`REQ-413-T2`, AC-5)**:
   `groupMappingsByStage` において、解決されたバリアントが `is_enabled === false` のマッピングを除外し、ステージグループ表示および `buildParamSyncCandidates` による ParamSync 候補から排除する。

## 3. アーキテクチャ & 詳細設計

### 3.1 `SlotDefinition` への `variantEnabled` 追加 (`REQ-413-T1`)

[`frontend/src/utils/workflowMappingState.ts`](file:///frontend/src/utils/workflowMappingState.ts) の `SlotDefinition` インターフェースを拡張する：

```typescript
export type SlotDefinition = {
  masterId: number
  variantId?: number
  stageId?: number
  defaultEnabled: boolean
  role?: string | null
  legacyRole?: string | null
  variantEnabled?: boolean
}
```

### 3.2 `useWorkflowManagement.ts` におけるバリアント有効フラグ伝播 (`REQ-413-T1`)

[`frontend/src/pages/GeneratePage/hooks/useWorkflowManagement.ts`](file:///frontend/src/pages/GeneratePage/hooks/useWorkflowManagement.ts) の `slotDefinitions` 生成メモを更新する：

```typescript
const slotDefinitions = useMemo<SlotDefinition[]>(() => (mappingMasters ?? []).flatMap((master) => {
  const variants = 'variants' in master && Array.isArray(master.variants)
    ? (master as MappingMaster & Pick<MappingMasterV2, 'variants'>).variants
    : []
  return variants.length
    ? variants.map((variant) => ({
        masterId: master.id,
        variantId: variant.id,
        stageId: variant.stage_id,
        role: variant.computed_role,
        legacyRole: master.role,
        defaultEnabled: master.default_enabled !== false,
        variantEnabled: variant.is_enabled !== false,
      }))
    : [{
        masterId: master.id,
        defaultEnabled: master.default_enabled !== false,
        variantEnabled: master.default_enabled !== false,
      }]
}), [mappingMasters])
```

### 3.3 `generationWorkflow` における無効バリアント除外 (`REQ-413-T1`)

[`frontend/src/utils/workflowMappingState.ts`](file:///frontend/src/utils/workflowMappingState.ts) の `generationWorkflow` を更新する。
スロット定義 `slots` が与えられている場合、各マッピングに対応するスロットの `variantEnabled` を検証する：
1. `mapping.variant_id != null` の場合：
   `slots.find(s => s.masterId === mapping.master_id && s.variantId === mapping.variant_id)` を検索。当該スロットが存在し `variantEnabled === false` の場合は除外。
2. `mapping.variant_id == null`（レガシーマッピング）の場合：
   - 当該マスタに属する全スロット `masterSlots = slots.filter(s => s.masterId === mapping.master_id)` を確認。
   - `masterSlots.length > 0` かつ全スロットが `variantEnabled === false` の場合は除外。
   - `mappingSlotKey(mapping, slots)` で一意解決されたスロットが存在し、そのスロットが `variantEnabled === false` の場合は除外。
3. 既存の `mapping_slot_states` チェック（ワークフロー個別の明示 `false` の除外）も維持する。
   - ワークフロー側で明示的に `false` とされているスロットは、マスタ側の状態に関わらず除外される（ワークフロー側個別設定が最優先）。
   - `mapping_slot_states` が `false` でない（`true` または未定義）かつ `variantEnabled !== false` のマッピングは正常に保持される（AC-3）。

これにより：
- `useWorkflowManagement` の `workflow.mappings` から無効バリアントのマッピングが除外される。
- `paramMappings` および `textMappings`（`validMappings = workflow?.mappings.filter(...)` から派生）に無効バリアントが表示されなくなる（`AC-1`）。
- `handleGenerateSets` / `injectWorkflowParams` は `workflow.mappings` を参照するため、ComfyUI ワークフロー JSON へパラメータやプロンプトが注入されなくなる（`AC-2`）。
- 有効なバリアントで `mapping_slot_states` が `false` でないものは正常に維持される（`AC-3`）。
- レガシーマッピングも安全に除外される（`AC-4`）。

### 3.4 `groupMappingsByStage` における無効バリアント除外 (`REQ-413-T2`)

[`frontend/src/utils/mappingStageGroups.ts`](file:///frontend/src/utils/mappingStageGroups.ts) の `groupMappingsByStage` を更新する：
- マッピングをイテレートしてバリアント `match: ResolvedVariant` を解決した際、`match.variant.is_enabled === false` の場合はステージグループへの追加を行わずにスキップ（`return`）する。
- これにより、`groupMappingsByStage` の出力グループから無効バリアントが完全に除外される。
- `buildParamSyncCandidates` は内部で `groupMappingsByStage` を呼び出すため、無効バリアントが ParamSync の同期先候補・代表候補に出現しなくなる（`AC-5`）。

## 4. トレードオフ開示 (Trade-off Disclosure)

| 論点 | 採用方針 | 代替案と却下理由 |
|---|---|---|
| DB の `workflow_mappings` レコードの扱い | **DBレコードを保持し、生成・表示時に選別除外する**: マスタでバリアントが無効化されても DB のマッピングレコードは削除しない。 | **DB マイグレーションで物理削除する**: マスタ設定で一時的にバリアントをOFFにし、後で再度ONにした場合に、以前割り当てていたノードIDが失われ再マッピングを強要されるため不適（REQ-358/REQ-369の永続化方針とも整合）。 |
| フィルタ適用のレイヤー | **`generationWorkflow` および `groupMappingsByStage`（純粋関数レイヤー）で選別**: SSoT となるデータ生成関数でフィルタリングし、UIコンポーネント全体へ一貫した状態を提供する。 | **各 UI コンポーネント（ParamPanel, PromptPanel等）で個別フィルタ**: 漏れが生じやすく、生成注入（`handleGenerateSets`）へ確実に伝播しないリスクがあるため却下。 |
| スロット定義が存在しない場合の後方互換性 (AC-3, AC-4) | **`slots` 未指定時は既存動作（`mapping_slot_states` のみ）を維持し、`slots` 指定時は両方の条件を満たすマッピングを保持**: AC-3 の要件に基づき、ワークフローの `mapping_slot_states` が明示的に `false` ではなく（`true` または未定義）、かつマスタ側で `variantEnabled !== false`（`is_enabled = true`）であるマッピングのみが生成用 `workflow.mappings` に正常保持されパラメータ枠に正常表示される。レガシーマッピング（`variant_id == null`）も `mappingSlotKey` による解決先が無効なら安全に除外される（AC-4）。`slots: readonly SlotDefinition[] = []` のデフォルト引数を維持することで、既存の広範な単体テスト資産を破壊しない。 | **`slots` を必須引数に変更する**: 既存の広範な単体テストで `slots` のモック作成が大量に必要となり、修正範囲が不必要に拡大するため却下。 |

### D4: 共有インターフェース・型・データ構造契約
- **`SlotDefinition`** (`frontend/src/utils/workflowMappingState.ts`):
  `variantEnabled?: boolean` (オプショナルフィールド。マスタ側の `variant.is_enabled !== false` に基づき設定。`true`: 有効、`false`: 明示無効、`undefined`: 未指定/後方互換で有効扱い)。
- **`generationWorkflow<T extends MappingWorkflow>(raw: T, slots?: readonly SlotDefinition[]): T`**:
  戻り値の `mappings` は、マスタ側のバリアント有効フラグに基づく `slot.variantEnabled !== false` かつワークフロー個別の明示的無効化 `raw.mapping_slot_states?.[key] !== false` を共に満たす要素のみを格納した新しい配列。`raw` オブジェクトや元の配列はミューテーションしない。
- **`groupMappingsByStage(mappings, masters, stages): MappingStageGroup[]`**:
  解決されたバリアントが `is_enabled === false` の場合は結果の `MappingStageGroup.mappings` に含めない。
- **`buildParamSyncCandidates(mappings, masters, stages): ParamSyncCandidate[]`**:
  `groupMappingsByStage` に基づくため、無効バリアントは自動的に除外される。

### D7: 変更禁止スコープ (Prohibited Scope)
- バックエンドの DB スキーマ（`workflow_mappings` テーブル等）、マイグレーションファイル、バックエンドルーターの変更は禁止（DB レコードはマスタ再有効化時の復旧のために保持する）。
- `RescanModal.tsx`, `useMasterMappingRows.ts` のリマッピング時の未割当スロット保持ロジック（REQ-369 で確立された契約）の変更は禁止。
- ワークフロー個別無効化（`mapping_slot_states`）のキー命名規則（`v:<id>`, `m:<id>`）の変更は禁止。
