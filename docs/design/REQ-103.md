## 1. アーキテクチャ概要

### 基本方針

本機能は以下の3層で構成する。

```
[フロントエンド]
  SceneGeneratorModal.tsx  ← 専用の新規コンポーネント（モーダルUI）
  useSceneGenerator.ts     ← LLM呼び出し・差分マージ・キュー投入ロジック
  
[バックエンド]
  routers/llm_prompts.py   ← 既存ファイルに POST /api/llm-prompts/scene-generate を追加
  services/llm_service.py  ← 既存ファイルに run_scene_generate() 関数を追加
  schemas/audit.py         ← 既存ファイルに SceneGenerateRequest/Response スキーマを追加
```

### データフローの原則

- **Zustandグローバル状態（`paramValues`）は直接変更しない。**
- ベースプロファイルはモーダルオープン時に `paramValues` のスナップショットとしてローカルstateへコピーする。
- 差分マージ（finalParams合成）はキュー投入直前にメモリ上でのみ実施する。

#### `frontend/src/pages/GeneratePage/hooks/useSceneGenerator.ts` [NEW]

LLM通信とキュー投入の副作用ロジックを分離する。

**エクスポート関数:**
```typescript
export function useSceneGenerator(workflow: Workflow | undefined) {
  // generateDrafts: バックエンドへLLM要求を送信
  const generateDrafts = async (
    targetFields: string[],
    scenes: SceneItem[],
    baseParamValues: Record<string, string>
  ): Promise<SceneDraft[]>

  // submitAllScenes: 全シーンをComfyUIキューへ投入
  const submitAllScenes = async (
    baseParamValues: Record<string, string>,
    drafts: SceneDraft[]
  ): Promise<void>
}
```

**`generateDrafts` の実装ロジック:**
```typescript
// POST /api/llm-prompts/scene-generate
const response = await request<SceneGenerateResponse[]>(
  '/llm-prompts/scene-generate',
  {
    method: 'POST',
    body: JSON.stringify({
      target_fields: targetFields,
      base_params: Object.fromEntries(
        targetFields.map(f => [f, baseParamValues[f] ?? ''])
      ),
      scenes: scenes.map((s, i) => ({ id: s.id, summary: s.summary }))
    })
  }
)
```

**`submitAllScenes` の実装ロジック:**
```typescript
// 仕様書の pseudocode を忠実に実装
for (const draft of drafts) {
  const finalParams = { ...baseParamValues, ...draft.diff_params }
  const wfJson = JSON.parse(JSON.stringify(workflow.json_body))
  injectParams(wfJson, finalParams, baseSeedMode, baseSeed, idx)
  await queuePrompt(wfJson, { paramValues: finalParams, appliedAssets: baseAppliedAssets })
}
```

※ `injectParams` は `useGenerateAction.ts` の実装を参照し、同様のロジックを `useSceneGenerator` 内でも使用する（DRY化は後続タスクとする）。

## 3. バックエンド設計

### 3-1. 新規APIエンドポイント

#### `POST /api/llm-prompts/scene-generate`

**ファイル:** `backend/app/routers/llm_prompts.py` [MODIFY]

**リクエストスキーマ（`schemas/audit.py` または 新規 `schemas/scene.py` へ追加）:**
```python
class SceneItem(BaseModel):
    id: str
    summary: str

class SceneGenerateRequest(BaseModel):
    target_fields: list[str]
    base_params: dict[str, str]  # フィールド名 -> 現在値（LLMへの文脈情報）
    scenes: list[SceneItem]

class SceneDiffParams(BaseModel):
    scene_id: str
    diff_params: dict[str, str]
```

**レスポンス:** `list[SceneDiffParams]`

### 3-2. LLMサービス拡張

#### `backend/app/services/llm_service.py` [MODIFY]

`run_scene_generate()` 関数を追加する。

**システムプロンプト設計（デフォルト）:**
```
You are a scene description expert for AI image generation.
Given a scene summary in Japanese, analyze the intent and generate English prompts
for ONLY the specified target fields. You must decide which fields to modify
based on the scene's natural implication.

Output MUST be valid JSON. Do NOT include any fields not listed in target_fields.
Do NOT add explanations or markdown outside the JSON array.
```

**ユーザープロンプト構成:**
```
Target Fields: {target_fields}
Current Base Values: {base_params}

Scenes:
{scenes_list}

Return a JSON array:
[{"scene_id": "...", "diff_params": {"FieldName": "english, comma, separated, prompt"}}]
Only include fields you want to change. Fields with no change should be omitted.
```

**LLM出力のパース:** JSON.parse によりJSONを直接パース（XMLタグ不使用）。

## 5. 制約事項・注意点

- `injectParams` ロジックは `useGenerateAction.ts` と実質的に同じ処理が必要なため、`useSceneGenerator.ts` 内でも同等の実装を行う（将来的な共通化はREQ-103の後続タスクとして扱う）。
- シード値の扱いはベースプロファイルの `seedMode`/`seed` 設定に準拠する（仕様書 §5 に従う）。
- History保存はComfyUI WebSocket経由の既存フロー（`queuePrompt`コールバック）が自動的に処理するため、追加実装不要。
