# REQ-062 設計ドキュメント
# LoRA・タグセット管理画面改修、並び順永続化、カテゴリ管理機能

---

## 1. 概要 (Overview)

LoRA管理画面（`LoRAsPage.tsx`）を正とし、タグセット管理画面（`TagsPage.tsx`）のカードデザインを統一する。
さらに、両画面においてD&Dによる並び順変更と永続化、カテゴリのCRUD管理、および登録/編集モーダルからのインライン新規カテゴリ追加を実現する。

## 4. APIシグネチャ変更 (API Signature Changes)

### 新規エンドポイント

#### `PUT /api/loras/reorder`
```json
Request: { "ordered_ids": [3, 1, 5, 2, 4] }
Response: 204 No Content
```

#### `PUT /api/tag-sets/reorder`
```json
Request: { "ordered_ids": [2, 5, 1, 3] }
Response: 204 No Content
```

#### `PUT /api/lora-categories/{category_id}` (更新)
```json
Request: { "name": "新しいカテゴリ名" }
Response: { "id": 1, "name": "新しいカテゴリ名", "sort_order": 0 }
```

#### `PUT /api/tagset-categories/{category_id}` (更新)
```json
Request: { "name": "新しいカテゴリ名" }
Response: { "id": 1, "name": "新しいカテゴリ名", "sort_order": 0 }
```

### 既存エンドポイントの変更

#### `GET /api/loras`
- ソート順: `model_name` → `sort_order ASC, model_name ASC`（`sort_order`が同値の場合は`model_name`でソート）
- レスポンス: `LoraRead`に`sort_order: int`を追加

#### `GET /api/tag-sets`
- ソート順: `id DESC` → `sort_order ASC, id ASC`
- レスポンス: `TagSetRead`に`sort_order: int`を追加

#### `GET /api/lora-categories`, `GET /api/tagset-categories`
- レスポンス: `CategoryRead`に`sort_order: int`を追加

## 5. フロントエンド設計 (Frontend Design)

### 5.1 タグセットカードのLoRA化 (AC-1)

**現状（TagsPage）**:
- カードはテキストコンテンツ中心（画像なし）
- 編集/削除ボタンはカード内のヘッダー右にインライン配置
- グループ化（カテゴリ別セクション）表示

**変更後（LoRA方式に統一）**:
- 上部に `<ImageCarousel>` (aspect-square) を配置
- カルーセル内にホバー時の編集(Pencil)・削除(Trash2)ボタン
- 下部に名前・カテゴリバッジ・タグプレビューを表示
- **グループ化は廃止し、フラットなグリッド表示に統一**（フィルターバーのカテゴリボタンで代替）

### 5.2 D&Dによる並び替え (AC-2, AC-3)

**使用ライブラリ**: `@dnd-kit/core` + `@dnd-kit/sortable`（既存の`SettingsPage`実装を踏襲）

**実装パターン**:
```tsx
// LoRAsPage / TagsPage 共通パターン
const [items, setItems] = useState<Lora[]>([])
const reorder = useMutation({
  mutationFn: (ordered_ids: number[]) => lorasApi.reorder(ordered_ids),
})
const handleDragEnd = (event: DragEndEvent) => {
  const { active, over } = event
  if (over && active.id !== over.id) {
    const oldIdx = items.findIndex(x => x.id === Number(active.id))
    const newIdx = items.findIndex(x => x.id === Number(over.id))
    const reordered = arrayMove(items, oldIdx, newIdx)
    setItems(reordered)
    reorder.mutate(reordered.map(x => x.id))
  }
}
```

**グリッド内D&Dレイアウト**:
- `SortableContext` + `rectSortingStrategy` を使用（グリッドレイアウト対応のストラテジー）
- カードに `useSortable` フックを適用
- ドラッグ中のオーバーレイは `DragOverlay` で描画

**検索/フィルター中の動作**:
- 検索文字列またはカテゴリフィルターが適用されている場合はD&D禁止（UIで明示）
- フィルタークリア時に再有効化

### 5.3 カテゴリCRUDモーダル (AC-5)

**新規コンポーネント**: `CategoryManagerModal.tsx`

**Props**:
```tsx
interface CategoryManagerModalProps {
  type: 'lora' | 'tagset'
  onClose: () => void
}
```

**機能**:
- カテゴリ一覧表示（テーブル or リスト形式）
- 新規追加（名前入力 → POST）
- 名前のインライン編集（編集アイコンクリック → PUT）
- 削除（ゴミ箱アイコン → DELETE）

**アクセス方法**:
- `LoRAsPage`と`TagsPage`のフィルターバーに「カテゴリ管理」ボタン（FolderPlusアイコン等）を追加

### 5.4 インラインカテゴリ追加 (AC-6)

**新規コンポーネント**: `InlineCategorySelect.tsx`

**Props**:
```tsx
interface InlineCategorySelectProps {
  value: number | undefined
  onChange: (categoryId: number | undefined) => void
  categories: Category[]
  onCategoryCreated: (newCategory: Category) => void
  apiCreateFn: (name: string) => Promise<Category>
  accentColor?: string  // 'green' | 'purple'
}
```

**動作**:
1. 通常はドロップダウン（`<select>`）
2. 末尾に「+ 新規カテゴリ追加」オプション
3. 選択するとインライン入力フィールドに切替（「+ 新規」入力欄 + 保存ボタン）
4. 保存後、新しいカテゴリが即座に選択状態になる

## 8. トレードオフ・リスク (Trade-off Disclosure)

| 項目 | 内容 | 対策 |
|---|---|---|
| D&D中の検索フィルター | フィルタリング中にD&Dすると「見えているカード」の順序しか送信できず、非表示カードの順序が崩れる | 検索/フィルター適用中はD&Dを無効化（UIで明示）し、ユーザーに説明する |
| リアルタイム競合 | 複数タブで同時に並び替えると順序が競合する | ローカルツールなので単一ユーザー前提。楽観的更新で十分。 |
| sort_orderの初期値割り当て | 既存レコードに初期値を割り当てる際、一意性は不要（同値可）だが安定した初期順序が必要 | id昇順でrow_numberを割り当てる（`run_migrations`で対応） |
| TagsPageのグループ化廃止 | カテゴリ別セクション表示を廃止するため、既存の「グループ化」UIの知見が失われる | カテゴリフィルターボタンが代替手段となり、UX的には改善される |
| カテゴリ更新APIの欠如（現状） | 現状、カテゴリ更新（名称変更）のPUTエンドポイントが存在しない | T2で新規追加する |
