# REQ-173: セリフプリセット一覧表示における縦書き・横書き識別サフィックス自動付与および同名保存の許容

## 1. 背景と目的

REQ-172にてセリフプリセットへのテキスト保存機能が導入され、定型効果音（SE：「ドンッ」「あ…」など）をプリセットとして登録・再利用するユースケースが増加した。
しかし、吹き出しエディタにおいて以下の課題が存在している：

1. **文字方向の視覚的識別の欠如**: プリセット選択一覧において、プリセットの文字方向（縦書き/横書き）が明示されていないため、同音テキストや同名プリセットから目的の文字方向のプリセットを一目で判別できない。
2. **同名プリセット登録の一意制約制約**: データベースおよびAPI層においてプリセット名（`name`）に単独一意制約（`UNIQUE`）が設定されているため、同一テキスト・同一名称で「縦書き用」「横書き用」の2つのプリセットを保存しようとした際に制約違反エラーとなり保存できない。

本設計では、プリセット名の一意制約を「名前＋文字方向（`name` + `orientation`）」の複合一意制約（または同名許容）へと緩和し、フロントエンドのプリセット一覧表示において文字方向に応じた識別サフィックス `(縦)` / `(横)` を自動付与することで、直感的かつ円滑なプリセット管理・適用を実現する。

## 3. 詳細設計

### 3-1. バックエンド：複合一意制約とマイグレーション

#### (1) モデル変更 (`backend/app/models.py`)
- `SpeechBubblePreset.name` の `unique=True` を削除。
- `__table_args__ = (UniqueConstraint("name", "orientation", name="uq_speech_bubble_presets_name_orientation"),)` を定義。

```python
class SpeechBubblePreset(Base):
    __tablename__ = "speech_bubble_presets"
    __table_args__ = (
        UniqueConstraint("name", "orientation", name="uq_speech_bubble_presets_name_orientation"),
    )

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String, nullable=False)
    shape: Mapped[str] = mapped_column(String, nullable=False, default="oval")
    orientation: Mapped[str] = mapped_column(String, nullable=False, default="vertical")
    # ... 他フィールドは変更なし
```

#### (2) API 重複バリデーション (`backend/app/routers/speech_bubble_presets.py`)
- `create_speech_bubble_preset`:
  - 判定条件：`name == payload.name` かつ `orientation == payload.orientation` のレコードが存在する場合に 400 Bad Request を送出。
- `update_speech_bubble_preset`:
  - 判定条件：更新後の `name`（指定がなければ既存値）および `orientation`（指定がなければ既存値）の組み合わせが、自身（`id != preset_id`）以外の他レコードと重複する場合に 400 Bad Request を送出。

#### (3) データベースマイグレーション (`backend/app/main.py`)
- SQLite では既存テーブルのカラム制約（`UNIQUE`）のみを `ALTER TABLE DROP CONSTRAINT` できないため、テーブル再構築（または一時テーブルへの退避・複製）を行うマイグレーションを `run_migrations` に追加。
- 既存の `speech_bubble_presets` テーブルが存在し、`name` 単独一意制約が残っている場合：
  1. `speech_bubble_presets_old` にリネーム、または新規制約テーブルを作成してデータをコピー。
  2. 既存レコードを保持したまま `(name, orientation)` 複合一意制約を持つテーブルに安全に移行。

---

### 3-2. フロントエンド：サフィックス自動付与表示

#### (1) 表示層でのサフィックス付与 (`frontend/src/components/SpeechBubbleControls.tsx`)
- プリセット内部の `name` プロパティ（保存データ）自体は変更せず、描画時に文字方向判定を行ってサフィックスを付与する。
- サフィックス定義：
  - `p.orientation === 'horizontal' ? '(横)' : '(縦)'`
- 表示箇所：
  - プリセットチップ内の名称テキスト：
    ```tsx
    const orientationSuffix = p.orientation === 'horizontal' ? '(横)' : '(縦)'
    // ...
    <span className="truncate max-w-[120px]">{p.name} {orientationSuffix}</span>
    ```
  - チップの `title` 属性（ツールチップ）：
    ```tsx
    title={`${p.name} ${orientationSuffix}${p.text ? `\n💬 テキスト: ${p.text}` : ''} (クリックで適用)`}
    ```

#### (2) 新規保存・上書き保存時の挙動
- 新規保存モーダル・入力欄でユーザーが入力した名前（例：「叫び」）はそのまま `name` として送信。
- 現在エディタで選択されている `orientation`（縦書きまたは横書き）がバックエンドに送られ、一覧に即座に `叫び (縦)` または `叫び (横)` として反映。

## 4. テスト・検証設計

### 4-1. 自動テスト
1. **バックエンド API テスト (`backend/tests/test_speech_bubble_presets.py`)**:
   - 同名かつ異なる orientation（例: `name="SE"`, `orientation="vertical"` と `name="SE"`, `orientation="horizontal"`）が両方正常に登録できること。
   - 同名かつ同一 orientation の場合、400 Bad Request が返されること。
   - 既存プリセットの更新時、同名・同 orientation の別プリセットが存在する場合は更新が弾かれ、異なる orientation であれば更新できること。
   - `python -m pytest tests/test_speech_bubble_presets.py` で全テストがパスすること。
2. **フロントエンド ユニットテスト (`frontend/src/components/__tests__/SpeechBubbleControls.test.tsx`)**:
   - 縦書きプリセットに `(縦)`、横書きプリセットに `(横)` が付与されてレンダリングされること。
   - 同名で縦書き・横書きのプリセットが存在する場合、双方がそれぞれのサフィックス付きで一覧に表示されること。
   - プリセットクリック時に対応する文字方向とスタイル/テキストが正しく適用ハンドラに渡されること。
   - `npm test -- SpeechBubbleControls.test.tsx --run` で全テストがパスすること。
