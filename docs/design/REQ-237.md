# REQ-237: 巨大テストのリファクタリングと隔離性検証 (Phase 4) 設計仕様書

## 1. 概要とアーキテクチャ方針

本設計は、テスト監査（`tmp/test_framework_implementation_plan.md`）の Phase 4 に基づき、肥大化した単一テストファイル `frontend/src/store/__tests/useGenerationStore.test.ts` (65KB超, 1793行) を Zustand スライス構成に沿ったドメイン別テストファイルに分割・整理し、テストの保守性、決定性、およびテスト間状態隔離を検証・確立することを目的とする。

```
[現状: モノリシックテスト]
frontend/src/store/__tests/useGenerationStore.test.ts (65KB+, 1,793行)
  ├── REQ-059 preview reset / selectedImg
  ├── REQ-061/140/152/162/166/167/182/190/195 バッチ・キュー・履歴・キャンセラ
  ├── REQ-164/181/189 WebSocket・ノードタイトル解決
  └── REQ-220 promptChips / effectiveParamValues

                     ▼ リファクタリング (REQ-237)

[分割後: スライス別テスト構成]
frontend/src/store/__tests__/slices/
  ├── connectionSlice.test.ts  (WebSocket接続, 状態同期, ノードタイトル解決, プレビュー)
  ├── jobQueueSlice.test.ts    (バッチジョブ, キュー投入, 中断/キャンセル, 履歴最適化/重複排除, メタデータ)

```

## 3. テスト決定性・隔離性検証仕様

### 3-1. バックエンド決定性検証 (pytest-randomly)
- `pytest-randomly` による実行順序ランダム化を異なるシード値で実施:
  - `pytest --randomly-seed=12345` (検証済: 235 passed, 0 failures)
  - `pytest --randomly-seed=54321` (検証済: 235 passed, 0 failures)
  - `pytest --randomly-seed=auto` (実行時ランダムシード)
- テスト間の実行順序に依存したグローバル変数汚染や未クローズDB接続（REQ-234導入の `verify_db_pool_clean`）が存在しないことを保証。

### 3-2. フロントエンド隔離性検証 (Vitest Isolation)
- `frontend/vite.config.ts` の隔離設定 (`isolate: true`, `restoreMocks: true`, `clearMocks: true`, `mockReset: true`) の下で、全テストスイートを実行:
  - コマンド: `npm --prefix frontend test -- --run`
- 各スライステストにおいて:
  - `beforeEach`: `localStorage.clear()`, `useGenerationStore.setState(...)` 初期化
  - `afterEach`: `_resetWebSocketForTesting()`, `vi.clearAllMocks()`
  - モジュール変数や WebSocket インスタンスのリークによる予期せぬ失敗・状態汚染がゼロであることを保証。

## 5. Acceptance Criteria (受入基準) トレーサビリティ

- **AC-1**: `useGenerationStore.test.ts` が以下の4ドメイン別テストファイルに分割・整理されていること。
  - `connectionSlice.test.ts`
  - `jobQueueSlice.test.ts`
  - `multiSetSlice.test.ts`
  - `bypassSlice.test.ts`
- **AC-2**: 分割後の各ストアテストが既存と同等以上の網羅性を維持し、全てパスすること。
- **AC-3**: バックエンドテストにおいて、`pytest --randomly-seed=12345` および `pytest --randomly-seed=54321` など異なるシード値で実行しても100%成功し、順序依存性がないこと。
- **AC-4**: フロントエンド全テスト連続実行時において、テスト間の状態汚染やモジュール変数リーク（`ws` 等）による失敗がゼロであること。
