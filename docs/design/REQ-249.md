# REQ-249: 履歴表示パイプラインのデータソース正規化とリアルタイム同期基盤整備（完全移行） 詳細設計書

## 1. 背景と課題

現在、`GeneratePage` の履歴サムネイル表示および画像プレビュー機能は、`useGenerateDisplayState.ts` を通じて以下の3系統のデータソースをアドホックに合成・参照している：

1. **ローカル生成セッション画像**: `useGenerationStore` 内の `batchImages`（ローカルストレージ `ps_batch_images` 保持）
2. **ComfyUI 履歴画像**: `useGenerationStore` 内の `comfyHistoryImages`（`/history` API または WS `executed` イベントで更新）
3. **バックエンド永続化スナップショット**: TanStack Query (`useQuery(['snapshots', selectedWorkflowId])`)

### 構造的課題
- **Source of Truth の断片化**:
  画像リストの正本が Zustand ストア、TanStack Query キャッシュ、ローカルストレージに分散しており、複数箇所で手動の配列マージ・重複排除（`slice(0, 200)` 等）が重複実装されている。
- **過渡的二重管理の負債化**:
  段階的移行を待つ follow-up PBI が存在しないため、本PBIにおいて完全移行（Full Migration）を実施し、TanStack Query キャッシュ層を唯一の正本（SSoT）として確立する。
- **モーダルプレビューのインデックスジャンプ（1フレームチラつき）**:
  モーダル閲覧中に裏でキュー完了画像が先頭（Index 0）に挿入された際、React の state 更新ラグにより表示画像が一瞬別の画像にジャンプする現象を、`effectiveModalIndex`（URL ベースの即時インデックス特定）により完全防止する。

## 3. アーキテクチャと詳細設計

### 3-1. 完全移行後のデータフロー

```
[ ComfyUI WebSocket (executed) / リモート端末生成 / fetchHistory ]
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│        useGenerateDisplayState : addHistoryImage(url, isOwn)     │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ TanStack Query Cache (Single Source of Truth)                   │
│   queryKey: ['generateDisplayImages', { filterOwnSession }]     │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ displayImages: string[]                                         │
│   ├── sortedDisplayImages (sortOrder: 'desc' | 'asc')           │
│   │    ├── snapshotIdsForDisplay (snapshots 連動)                │
│   │    └── effectiveModalIndex (URLベース即時同期 / チラつきゼロ)│
│   └── otherSessionCount (他セッション履歴件数バッジ表示用)      │
└────────────────────────────────┬────────────────────────────────┘
                                 │
                    ┌────────────┴────────────┐
                    ▼                         ▼
          DesktopLayout.tsx           MobileLayout.tsx
```

### 3-2. プレビューチラつき対策（`effectiveModalIndex`）のメカニズム

- `currentModalUrlRef`: モーダルで現在閲覧している画像 URL を保持。
- `effectiveModalIndex`:
  ```typescript
  const effectiveModalIndex = useMemo(() => {
    if (!isModalPreviewOpen || !currentModalUrlRef.current) return modalPreviewIndex
    const newIdx = sortedDisplayImages.indexOf(currentModalUrlRef.current)
    return newIdx !== -1 ? newIdx : modalPreviewIndex
  }, [isModalPreviewOpen, modalPreviewIndex, sortedDisplayImages])
  ```
- 先頭に新規画像が追加された瞬間（再レンダリングの最中）に、URL から直接インデックスが再計算されるため、`useEffect` の発火待機（1フレームの遅延）による画像飛びが原理的に発生しない。
- レンダリング後に `useEffect` で `setModalPreviewIndex(effectiveModalIndex)` を呼び出し、内部 State も同期維持する。
