# PBI-165: プロンプト翻訳機能の外部APIプロキシ化・チャンクキャッシュおよび手動反映UI/UXの刷新

## 1. 概要 (Overview)
本設計は、画像生成プロンプトの翻訳機能において発生していた「意図しない自動上書き事故」および「ローカルLLM利用に伴うGPU VRAM枯渇・画像生成とのリソース競合」を根本解決するための仕様を定める。
バックエンドに外部翻訳API（Google翻訳 / DeepL等）へのプロキシ層とタグ単位のチャンクキャッシュ機構を構築し、フロントエンドでは「英→日確認プレビュー」と「日→英自由入力・明示的手動反映（追記/上書き）」を分離した安全で効率的なUI/UXへ刷新する。
さらに、**翻訳プロバイダー（Google無料/公開Web、Google Cloud API、DeepL等）およびAPIキー等の設定を「設定画面（SettingsPage）」から自由に設定・変更できるアーキテクチャ**とする。

---

## 2. 課題とアーキテクチャ方針 (Problem & Architectural Strategy)

### 2.1 現状の課題
1. **入力欄の意図しない自動上書き**:
   - 入力文字の変更やモーダル開閉時にデバウンスで双方向翻訳が自動実行され、`paramValues[role]` に直接書き込まれていたため、ユーザーが意図しないタイミングでプロンプトが破壊・上書きされる事故が発生していた。
2. **GPU VRAMの競合とパフォーマンス低下**:
   - 翻訳エンジンとしてローカルLLM（Ollama / LMStudio）を使用していたため、画像生成実行中に別プロファイルのプロンプトを調整・翻訳するとVRAMが枯渇し、生成と翻訳の双方に重大な遅延やクラッシュを引き起こしていた。
3. **API節約・キャッシュの欠如**:
   - プロンプト特有の「カンマ区切りタグの組み合わせ」「局所的な修正」に対して、プロンプト全体の再送・再計算が行われ、無駄なリソース消費が発生していた。
4. **ハードコード・設定の柔軟性の欠如**:
   - 翻訳エンジンやAPIキーがコード内固定だと、ユーザーが自身のアカウント（Google Cloud, DeepL）を使いたい場合や無料枠を使いたい場合の切り替えができない。

### 2.2 改善アーキテクチャ方針
```
【Frontend (SettingsPage)】
        │
        ├── 翻訳プロバイダー選択 (Google無料Web / Google Cloud API / DeepL / ローカルLLM)
        └── APIキー / エンドポイント設定 ──► DB保存 (llm_prompts テーブル)

【Frontend (GeneratePage)】                   【Backend (FastAPI)】                   【外部翻訳 (Google / DeepL)】
        │                                             │                                     │
        │ 1. POST /api/translate/prompt               │                                     │
        │    { prompt, source_lang, target_lang }     ├── 2. 設定取得 (DB / Env)            │
        ├────────────────────────────────────────────►│   (プロバイダー・APIキー判定)       │
        │                                             ├── 3. LoRA / 重み特殊構文の退避      │
        │                                             ├── 4. カンマ/改行でチャンク分割      │
        │                                             ├── 5. チャンク単位キャッシュ照合     │
        │                                             │      ・HIT  : キャッシュより取得    │
        │                                             │      ・MISS : 未翻訳のみ抽出        │
        │                                             ├── 6. 設定されたプロバイダーへ送信   │
        │                                             │      (GPU VRAM消費 0)               │
        │                                             ├────────────────────────────────────►│
        │                                             │◄────────────────────────────────────┤
        │                                             ├── 7. 訳文キャッシュ保存 & 特殊構文復元
        │ 8. レスポンス返却 (訳文 + キャッシュ統計)   │                                     │
        │◄────────────────────────────────────────────┤                                     │
        │                                                                                   │
        ├── 9. [英→日モード] プレビュー領域に表示（入力欄は変更しない）                     │
        └── 10. [日→英モード] ユーザーが「追記」or「上書き」ボタン押下時のみ入力欄へ反映     │
```

## 3. 詳細設計仕様 (Detailed Specifications)

### 3.1 翻訳プロバイダー設定とストレージ仕様

1. **DB設定レコード（`llm_prompts` テーブル利用）**:
   - `translation_provider`:
     - `'google_free'` (デフォルト: APIキー不要のGoogle翻訳Webプロキシ)
     - `'google_cloud'` (Google Cloud Translation API - 要APIキー)
     - `'deepl'` (DeepL API - 要APIキー)
     - `'llm'` (従来のローカルLLM)
   - `translation_api_key`: Google Cloud または DeepL のAPIキー（任意）
   - `translation_api_url`: カスタムエンドポイントURL（任意）

2. **設定画面 UI (`frontend/src/pages/SettingsPage.tsx`)**:
   - 「Translation Settings (翻訳設定)」セクションを新設。
   - プロバイダー選択ドロップダウン（Google無料 / Google Cloud API / DeepL / ローカルLLM）。
   - 選択されたプロバイダーに応じた API Key 入力欄（パスワード表示切替付き）。
   - 接続テストボタン（入力された設定で即座に疎通確認）。

---

### 3.2 バックエンド翻訳サービス・プロキシ (`backend/app/services/translation_service.py` & `backend/app/routers/translate.py`)

1. **エンドポイント定義**:
   - `POST /api/translate/prompt`
     - Request:
       ```json
       {
         "prompt": "1girl, <lora:face_v1:0.8>, (silver hair:1.2), cinematic lighting",
         "source_lang": "en",
         "target_lang": "ja"
       }
       ```
     - Response:
       ```json
       {
         "translated_prompt": "1人の女の子, <lora:face_v1:0.8>, (銀髪:1.2), 映画のような照明",
         "meta": {
           "total_chunks": 4,
           "cached_chunks": 3,
           "api_requested_chunks": 1,
           "billed_characters": 18
         }
       }
       ```
   - `POST /api/translate/test`: 設定の疎通テスト用エンドポイント。
   - `GET /api/translate/stats`: キャッシュ統計取得。
   - `POST /api/translate/clear-cache`: キャッシュクリア。

2. **プロバイダー別アダプター実装**:
   - **Google Free**: `https://translate.googleapis.com/translate_a/single?client=gtx&sl={src}&tl={tgt}&dt=t&q={text}`（非同期 `httpx` で安全にバッチ処理）。
   - **Google Cloud API**: `https://translation.googleapis.com/language/translate/v2?key={api_key}`（REST API経由）。
   - **DeepL API**: `https://api-free.deepl.com/v2/translate` または `https://api.deepl.com/v2/translate`（Auth-Keyヘッダー）。
   - **LLM Fallback**: 既存の `call_llm` を呼び出し。

3. **特殊構文の退避（サニタイズ）と復元**:
   - 対象構文:
     - LoRA構文: `<lora:[^>]+>`
     - 重み構文: `\(([^:()]+):([0-9.]+)\)` または `\(([^()]+)\)` / `\{([^{}]+)\}`
     - 埋め込み: `embedding:[^\s,]+`
   - 退避処理: 一時プレースホルダー `__TOKEN_LORA_0__`, `__TOKEN_WEIGHT_0__` に置換し、翻訳対象テキスト（内部タグ部分のみ）を抽出。
   - 復元処理: 翻訳完了後に元の構文ラッパー（LoRA名や重み数値）を再結合。

4. **チャンク分割・キャッシュロジック**:
   - デリミタ: カンマ（`,`）、読点（`、`）、改行（`\n`）
   - キャッシュキー: `sha256(chunk_text.strip().lower() + ":" + target_lang)`
   - ストレージ: スレッドセーフなインメモリ辞書（TTLまたは永続化対応可能設計）。

---

### 3.3 フロントエンド状態管理 (`usePromptTranslation.ts`)

1. **ステート管理の分離**:
   - `activeRole`: 現在翻訳対象のロール名（例: `'positive'`, `'negative'`）
   - `isOpen`: 翻訳ウィンドウ/モーダルの表示フラグ
   - `mode`: `'en_to_ja'`（確認プレビュー）または `'ja_to_en'`（日本語入力・追記）
   - `sourceText`: 入力中のテキスト
   - `translatedText`: 翻訳結果テキスト
   - `meta`: キャッシュヒット数・消費文字数等の統計情報
   - `isTranslating`: 翻訳中ローディングフラグ

2. **アクションロジック**:
   - `openTranslation(role, currentPromptText)`: 対象ロールを指定してウィンドウを開く。初期モードは `'en_to_ja'` で、現在のプロンプト内容をセット。
   - `executeTranslate()`: ユーザーが「翻訳」ボタンを押した際、または初回オープン時にオンデマンド実行。
   - `applyToPrompt(mode: 'append' | 'replace')`:
     - `'append'`: `paramValues[role]` の末尾に `, <translatedText>` を追記。
     - `'replace'`: `paramValues[role]` を `<translatedText>` で上書き。
     - いずれもユーザーの明示的なクリック時のみ実行。

---

### 3.4 UIコンポーネント刷新 (`PromptTranslationModal.tsx` & `SettingsPage.tsx`)

1. **モーダル/ポップオーバー構成 (`PromptTranslationModal.tsx`)**:
   - **ヘッダー**: ロール名バッジ、モード切替タブ（「英→日 確認」/「日→英 作成・追記」）、閉じるボタン
   - **モード 1: 英→日 確認プレビュー (`en_to_ja`)**:
     - 対象プロンプト表示
     - 「翻訳して確認」ボタン
     - 日本語訳プレビューボックス（コピー用ボタン付き）
     - ※プロンプト入力欄への自動書き込みは一切なし。
   - **モード 2: 日→英 自由入力・追記 (`ja_to_en`)**:
     - 日本語自由入力 textarea（例: `ツインテール, 青いドレス, カフェで読書`）
     - 「英語へ翻訳」ボタン
     - 翻訳結果（英語タグ）プレビュー
     - 操作ボタン群:
       - **「末尾に追記」**: 現在のプロンプトの末尾にカンマ区切りで追加。
       - **「入力欄を上書き」**: 現在のプロンプトをこの英語で置き換え。
       - **「クリップボードにコピー」**
   - **フッター**: キャッシュ統計表示

2. **設定画面 (`SettingsPage.tsx`)**:
   - 「Translation Settings (翻訳設定)」セクションを新設。
   - プロバイダー選択、APIキー設定、接続テスト実行機能を提供。

## 5. テスト・検証方針 (Testing Plan)
- バックエンドテスト (`backend/tests/test_translation_proxy.py`):
  - プロバイダー切り替え、特殊構文の退避・復元、チャンクキャッシュの検証。
- フロントエンドテスト (`frontend/src/pages/GeneratePage/hooks/__tests__/usePromptTranslation.test.ts`):
  - モード切替、手動反映（追記/上書き）時の `paramValues` 変更検証、自動上書きが発生しないことの検証。
- 手動検証:
  - 設定画面でGoogle無料/Google Cloud/DeepLを設定し、疎通テストが通ること。
  - プロンプト入力欄の翻訳・追記・上書き操作が正常に行えること。
