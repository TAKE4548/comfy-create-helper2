# REQ-431 詳細設計書: モバイル生成プレビューの左右スワイプ画像送りおよびボトムシートのスワイプダウン閉じる対応

## 1. 概要と受入基準 (AC-1〜AC-7)

Generate ページのモバイルレイアウト（画面幅 768px 未満）における画像ボトムシート（`MobileImageSheet`）および全画面ビューアに対し、以下を追加する。

- **AC-1 (ボトムシート左右スワイプ)**: 複数枚の履歴画像（index 0 が最新、index が増えるほど古い画像）において、左スワイプで1つ古い画像へ、右スワイプで1つ新しい画像へ切り替わり、先頭・末尾ではループせず停止すること。
- **AC-2 (全画面ビューア左右スワイプと復帰維持)**: 全画面ビューア表示中もボトムシートと同じ順序で左右スワイプ画像送りができ、全画面解除してボトムシートへ復帰した際も切り替え後の画像が表示され続けること。
- **AC-3 (アクション連動)**: スワイプで切り替えた状態で、`#download-btn-mobile` およびスナップショット保存ボタン（`mobile-sheet-save-btn`）が現在表示中の画像を対象に動作すること。
- **AC-4 (ボトムシートのスワイプダウン閉じ)**: モバイル表示（幅 767px 以下）で上部ハンドルまたはコンテンツ領域から下方向へ閾値以上（`80px` 以上、または移動量 `30px` 超かつ速度 `0.5px/ms` 超のフリック）ドラッグして離すとシートが閉じ、背後の履歴グリッドのスクロール位置が維持されること。閾値未満で離した場合は `translateY: 0` へ復帰し、上方向ドラッグは `0` にクランプされること。
- **AC-5 (全画面時の下スワイプ無効化と既存導線維持)**: 全画面ビューア表示中は下方向スワイプによるボトムシートのクローズを無効化し、既存の全画面解除操作（画像タップ・右上閉じるボタン・Esc・OS戻る）でボトムシートへ復帰できること。また、ボトムシート表示時の既存閉じる操作（閉じるボタン・Backdropタップ・Esc）も維持されること。
- **AC-6 (方向ロックと `scrollTop > 0` 優先)**:
  - `|deltaX| > |deltaY|` の横スワイプ時は画像送りのみが有効となりシート閉じ追従が起動しないこと。
  - `scrollTop === 0` での `deltaY > |deltaX|` の縦下スワイプ時はシート閉じ追従のみが動作し画像送りが発生しないこと。
  - 上方向ドラッグ時は移動量 `0` にクランプされ閉じる処理・画像送りが起動しないこと。
  - `scrollTop > 0` の内部縦スクロール中はコンテンツスクロールのみが優先され、スワイプダウン閉じも画像送りも起動しないこと。
- **AC-7 (履歴3列グリッド選択同期)**: ボトムシートを閉じた後、背後の履歴3列グリッド（`GenerationGallerySection`）の選択状態が、閉じる直前にプレビュー表示していた画像に同期していること。

## 3. アーキテクチャ設計とトレードオフ

### 3.1 `MobileImageSheet` の状態管理とジェスチャー制御（3枚ウィンドウ・指追従カルーセル方式）

1. **`viewMode` リセット不具合の回避**:
   - 現行 `MobileImageSheet.tsx` は `useEffect(() => { if (isOpen) { setViewMode('sheet'); setHasError(false) } }, [isOpen, image])` を持つため、全画面表示中に `image` が切り替わると強制的に `'sheet'` に戻ってしまう。
   - 本設計では `useEffect` を分離し、`[isOpen]` 変更時のみ `viewMode`・`translateY`・`dragOffsetX`・ジェスチャー状態をリセットし、`[isOpen, image]` 変更時は `hasError` のみをリセットする。
2. **3枚ウィンドウ・指追従カルーセル構成 (`mobile-image-carousel-track`)**:
   - ボトムシート表示時および全画面ビューア表示時の両方で、現在画像（`activeIndex`）に加え、前画像（`prevImage = images[currentIndex - 1]`）および次画像（`nextImage = images[currentIndex + 1]`）の最大3枚のみを DOM にマウントする。全スライドを `absolute inset-0`、`transform: translateX(${idx * 100}%)`、`key={`${idx}-${slideUrl}`}` で統一配置し（sheet モード時はコンテナ高さを `h-[60dvh]` 固定）、隣接画像には `alt=""` / `aria-hidden="true"` を付与してアクセシビリティおよび既存テストの `alt` テキスト一意性を維持する。
   - 水平ドラッグ中はトラック要素（`data-testid="mobile-image-carousel-track"`）に絶対インデックス基準の `transform: translateX(calc(${-activeIndex * 100}% + ${dragOffsetX}px))`（`transition: none`）をリアルタイム適用し、指の動きに追従して現在画像がスライドアウトし隣接画像が横からスライドインする視覚体験を提供する。
   - **端点抵抗（非ループ）**: 先頭（`currentIndex === 0`）での右ドラッグ（`deltaX > 0`）または末尾（`currentIndex === images.length - 1`）での左ドラッグ（`deltaX < 0`）時は、`deltaX * 0.25` の減衰抵抗のみを与え、指を離すと必ず中央（`0px`）へスナップ復帰する（ループしない）。
   - **スナップ復帰とスライド遷移**: 指を離した際、移動量が `HORIZONTAL_SWIPE_THRESHOLD`（`40px`）未満かつフリック条件（`velocityX > 0.4px/ms && |deltaX| > 20px`）未満の場合は `dragOffsetX = 0` とし、`transition: transform 0.2s cubic-bezier(0.16, 1, 0.3, 1)` で中央へ滑らかにスナップ復帰する。閾値以上かつ有効な隣接画像がある場合は、`touchEnd` 時に `setTimeout` なしで即座に `onSelectImage`・`setDragOffsetX(0)`・`setIsDraggingCarousel(false)` を同時実行し、1回の連続トランジションで目的地へスナップする。
3. **単一タッチ状態機械 (`gestureLockRef`)**:
   - タッチ開始 (`onTouchStart`) 時に単一タッチ（`e.touches.length === 1`）のみ受け付け、`startX`, `startY`, `startTime` を記録する。
   - `sheet` モード時は `isScrolledDown(e.target, sheetContentRef.current)`（`Modal.tsx` と同一の `scrollTop > 0` 判定）を実行し、`true` の場合は状態を `'blocked'` に遷移させ、縦スクロールを阻害せずスワイプダウン閉じ・左右画像送りの両方を抑止する。
   - `onTouchMove` で移動量が `DIRECTION_LOCK_SLOP`（`5px`）を超えた時点で主方向を確定し、`'horizontal'` または `'vertical'` にロックする（一度ロックしたら `touchend` まで他方向へ切り替わらない）。
   - `'horizontal'` ロック時は `translateY` を動かさず、`dragOffsetX` のみを更新する。
   - `'vertical'` ロック時は、`viewMode === 'fullscreen'` またはデスクトップ幅（`window.innerWidth >= 768`）では `'blocked'` としてクローズを抑止する。`sheet` モードかつモバイル幅では `Math.max(0, deltaY)` で上方向を `0` にクランプし、`onTouchEnd` 時に `deltaY >= 80` または `(velocity > 0.5 && deltaY > 30)` で `handleSheetClose()` を呼ぶ。閾値未満なら `translateY` を `0` へ戻し、`transition: transform 0.2s cubic-bezier(0.16, 1, 0.3, 1)` で滑らかに復帰させる。
   - 10px を超えるスワイプが発生した場合は `didSwipeRef.current = true` とし、直後の `onClick`（全画面遷移／全画面解除）を誤発火させない。

### 3.2 `MobileLayout` / Store 同期と `previewAutoFollow` の扱い

- `MobileLayout.tsx` は `state.sortedDisplayImages`（index 0 が最新）と `state.setSelectedImg` を `MobileImageSheet` の `images` と `onSelectImage` に接続する。
- スワイプにより `setSelectedImg(nextImage)` が即座に呼ばれるため、`MobileImageSheet` に渡る `image`（`selectedImg`）、ダウンロードリンク `#download-btn-mobile` の `href`、スナップショット保存ボタンの引数および `SaveSnapshotModal` の参照先（`selectedImg`）、およびシート閉鎖後の `GenerationGallerySection` のハイライト状態（`selectedImg === img`）が単一の真実のソース（`useGenerationStore.selectedImg`）を通じて常に一致する。
- **`previewAutoFollow` との整合**: PC版 `useImageNavigation`（矢印キー送り）およびサムネイル手動選択と同様、スワイプ画像送り自体は `previewAutoFollow` トグルを自動 OFF にしない。`previewAutoFollow === true` のまま新規生成が完了した場合は `useGenerateDisplayState` の `executed` ハンドラにより最新画像へ追従し、`false` の場合はスワイプで選んだ画像に留まる。

### 3.3 トレードオフとリスク開示

- **トレードオフ（3枚ウィンドウ・指追従カルーセル vs 全履歴マウント / 即時差し替え）**:
  - 履歴全件を DOM に並べる方式は履歴件数増加時にモバイルメモリ負荷・デコード負荷が増大し、逆に単一 `<img>` の `src` 即時差し替え方式は指追従の連続的な視覚フィードバックが欠如する。
  - 本設計では現在画像＋前後各1枚の**最大3枚ウィンドウ方式**を採用し、全履歴 DOM マウントを回避してメモリ負荷を一定に抑えつつ、指の `deltaX` に追従する `translateX` スライド・閾値未満スナップ復帰・隣接画像スライドイン・端点抵抗を両立する。
- **トレードオフ（共通 `useSwipe` 抽出 vs コンポーネント内実装）**: `Modal.tsx` は縦スワイプ専用であり横スワイプ方向ロックと競合するため、共通フック化は行わず `MobileImageSheet.tsx` 内に方向ロック付きジェスチャーを実装する（既存 `Modal.tsx` / `BottomSheet.tsx` への変更・回帰リスクをゼロにするため）。
- **リスク**:
  - タッチデバイスで `touch-action` 設定が不適切だとブラウザ標準の横スワイプバック（Safari 等）や Pull-to-Refresh と競合する可能性があるため、画像コンテナに `touch-pan-y` を付与するほか、シート表示中（`isOpen`）は `html` / `body` に `overscrollBehaviorY = 'contain'` を設定し、`{ passive: false }` のネイティブ `touchmove` リスナーで垂直方向ドラッグ時の `preventDefault()` によりブラウザの Pull-to-Refresh を確実に抑止する（クローズ時に復元）。
  - スライド完了時のチラつきやタイマー不整合を防ぐため、絶対インデックス基準の単一連続トランジション方式（`translateX(calc(${-activeIndex * 100}% + ${dragOffsetX}px))`）を採用し、`touchEnd` 時に `setTimeout` なしで即座に `onSelectImage` と `dragOffsetX = 0` を確定する。あわせて全スライドに `key={`${idx}-${slideUrl}`}` を付与して DOM ノードの同一性を維持し、`sheet` モード時の高さを `h-[60dvh]` 固定とすることで画像切替時のレイアウトガタつきを防止する。

## 4. Seam Map (`[W-DD-SEAM]`)

1. **Integrated (real code)**:
   - Unit/Component 層: `MobileImageSheet` のタッチイベント状態機械、方向ロック、`scrollTop` 判定、画像インデックス計算、エラー状態・全画面状態遷移。
   - Integration 層 (`MobileLayout.test.tsx`): `MobileLayout` + `GenerationGallerySection` + `MobileImageSheet` + `useGenerationStore`（`selectedImg` 同期）。
   - E2E 層 (`generateMobileGallery.spec.ts`): 実 Chromium モバイルビューポート (`375x812`) 上でのタッチ／ポインタースワイプ、DOM `translateY`・`scrollTop`・画像切替・グリッドハイライト・ダウンロードリンク確認。
2. **Severed (external I/O only)**:
   - Unit/Integration: `requestFullscreen` / `exitFullscreen` / `navigator.wakeLock` は既存のブラウザ API モック境界で遮断。
   - E2E: `/api/*` および `/api/ws`（WebSocket）は `page.route` / `page.routeWebSocket` で遮断し、`/view?filename=...` はインライン SVG/PNG ダミー画像で応答する。
3. **Mock Level**:
   - ビジネスロジックや内部フックのモンキーパッチは禁止。`useGenerationStore` および `MobileImageSheet` は実コードのまま実行する。
4. **PBT Decision**:
   - パーサー・DSL・数式エンジンではなく UI ジェスチャー状態遷移のため、Property-Based Testing は不要（境界値・異常系はユニットテストおよび Red Team ケースで網羅）。
5. **Fault Injection**:
   - 画像読込エラー状態（`hasError === true`）からの左右スワイプ復帰（次画像への切替で `hasError` がクリアされること）、単一画像（1枚のみ）や空配列でのスワイプ境界、マルチタッチ（`touches.length > 1`）や `touchCancel` 時の中断回復を検証する。

### D4. 共有契約

1. **`MobileImageSheetProps`** (`MobileImageSheet.tsx`):
   ```ts
   export interface MobileImageSheetProps {
     isOpen: boolean
     onClose: () => void
     image: string | null
     images?: string[]
     onSelectImage?: (imageUrl: string) => void
     onSaveSnapshot?: (imageUrl: string) => void
   }
   ```
2. **画像順序・カルーセル契約**: `images[0]` が最新画像、`images[images.length - 1]` が最古画像。最大3枚ウィンドウ（`prev`, `current`, `next`）を描画し、`mobile-image-carousel-track` の `translateX` で指追従する。左スワイプ（`deltaX <= -40` またはフリック `velocityX > 0.4 && |deltaX| > 20`）で `index + 1`、右スワイプで `index - 1`、境界外は減衰抵抗（`0.25x`）後に中央へスナップ復帰する（非ループ）。

4. **`previewAutoFollow` 契約**: スワイプによる画像切替は `selectedImg` のみを更新し、`previewAutoFollow` の ON/OFF 状態は変更しない。
