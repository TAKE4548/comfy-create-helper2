# Design Doc: REQ-231 Prompt SurgeonおよびComfyUIサービスの一括ライフサイクル管理

Windowsホスト（Frontend: Vite, Backend: FastAPI）とWSL2環境（ComfyUI: Python/PyTorch/ROCm-HIP）にまたがる複数サービスを一元管理し、ワンクリック起動・停止・再起動、ステータス確認、およびPC起動時の自動起動（常駐化）を実現するライフサイクル管理基盤の設計書。
さらに将来的なWeb UI拡張（ブラウザからの設定変更・サービス制御）を見据え、JSON API互換のCLI設計および軽量Webマイクロサービス（Web Control Panel）を包含する。

---

## 1. 問題の構造と背景

### 1-1. 現状の課題
1. **多重コンソール起動の運用摩擦**:
   - Prompt Surgeon の稼働には、Windows側のフロントエンド（`npm run dev`）、バックエンド（`uvicorn app.main:app`）、および WSL2 側の ComfyUI（仮想環境アクティベート、特定環境変数、最適化引数付き起動）を個別に起動する必要がある。
   - 起動順序やポート競合、プロセスの終了漏れ（ゾンビプロセスによるポート占有）が発生しやすく、開発・利用開始時の認知負荷と手動操作コストが高い。
2. **生成ログ確認と将来の拡張性**:
   - ComfyUI の生成進捗（プロンプト受付、ステップ進行、エラー等）を視覚的にリアルタイム監視したい。
   - 単なる固定バッチにとどまらず、将来的に特定サービスのみの再起動（reboot）、ログ確認（tail）、GUI/CLI ダッシュボード、さらには **ブラウザから設定編集・各種コマンドを実行できる軽量サービス** への拡張が容易な構造が求められている。

## 2. アーキテクチャ設計

### 2-1. 構成要素と責務分離

| コンポーネント | 実行環境 | デフォルトポート | 起動コマンド / 方式 | 画面表示モード / 役割 |
| :--- | :--- | :--- | :--- | :--- |
| **ComfyUI** | WSL2 (Linux) | 8188 | `bash -c "... && python main.py ..."` | 独立コンソール (Normal) / 背景 (Hidden) |
| **Backend (BE)** | Windows | 8000 | `.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000` | 独立コンソール (Normal) / 背景 (Hidden) |
| **Frontend (FE)** | Windows | 5173 | `npm run dev` (Vite) | 独立コンソール (Normal) / 背景 (Hidden) |
| **Controller Engine** | Windows (PowerShell) | - | `tools/server-manager/server-manager.ps1` | CLI / メニュー制御 / `-Json` 出力 |
| **Launchers** | Windows (Batch) | - | `*.bat` | ワンクリック実行 / タスクスケジューラ |
| **Web Manager API** | Windows (Python) | 8899 | `python tools/server-manager/server_api.py` | ブラウザからの設定編集・コマンド実行 |

```text
[ Web Browser ] (http://localhost:8899)
      │  (将来・拡張: 設定編集フォーム & サービス制御ボタン)
      ▼
[ Web Manager (server_api.py) ] (:8899)
      │
      ▼ (JSON API / CLI コール)
[ Controller (server-manager.ps1) ] ◄─── [ 1-Click Launchers (*.bat) / Task Scheduler ]
      │
      ├─ Reads/Writes: config.json (設定 SSoT)
      │
      ├─► React FE (Port: 5173) [Window: Visible or Hidden Log]
      ├─► Python BE (Port: 8000) [Window: Visible or Hidden Log]
      │
      └─► wsl.exe -d <distro> bash -c "..."
             │
             ▼
      [ WSL2 (Linux) ]
             └─► ComfyUI (Port: 8188) [Window: Visible Terminal for Progress]
```

### 2-2. 設計方針
1. **設定の外部化 (`config.json`)**:
   - ディストリビューション名、プロジェクトパス、起動オプション、ポート番号を設定ファイルに集約。スクリプト本体を改修せずとも環境差分に対応可能。
2. **JSON出力対応のプログラマブルCLI (`-Json`)**:
   - `server-manager.ps1 -Action status -Json` により、標準出力にステータス（ポート、PID、稼働状態）を整形された JSON 文字列で返却。
   - これにより、軽量 Web サービス（`server_api.py`）が追加のパース処理なしに直接ステータスを取得・Web UI に反映可能。
3. **軽量 Web 管理サービス (`server_api.py`) の準備**:
   - Python 標準ライブラリ（`http.server`）または軽量フレームワークのみで動作し、追加パッケージのインストールなしに即時起動可能。
   - エンドポイント:
     - `GET /`: ブラウザ向け Web コントロールパネル（HTML/CSS/JS、ダークモード）
     - `GET /api/status`: 全サービス稼働状況 JSON
     - `POST /api/action`: アクション実行 (`start`, `stop`, `restart`, `reboot-service`)
     - `GET /api/config`: 現在の `config.json` 取得
     - `POST /api/config`: `config.json` の更新保存（`.bak` バックアップ自動生成）
     - `GET /api/logs`: ログファイルの取得
4. **ハイブリッド実行モード（可視ウィンドウ vs バックグラウンド）**:
   - 手動実行時（通常モード）: ComfyUI および各サーバーを独立したコンソール画面で立ち上げ、進行ログを直接確認可能。
   - 自動起動・常駐時（`-Background` スイッチ）: `WindowStyle Hidden` でログファイル（`logs/*.log`）へ出力。
5. **ポート駆動の確実なプロセス監視・停止**:
   - `Get-NetTCPConnection` によるリッスン状態の判定と PID 特定強制終了。
   - WSL2 側は `pkill -f "python main.py.*8188"` およびポート監視を併用。

## 4. アクション仕様 (`server-manager.ps1`)

| アクション名 | 引数 | 動作内容 |
| :--- | :--- | :--- |
| `start` | `[-Background] [-Json]` | FE, BE, ComfyUI を順次起動。ポートリッスン確認まで待機。 |
| `stop` | `[-Json]` | ポート 5173, 8000 をリッスンする Windows プロセスおよび WSL ComfyUI プロセスを終了。 |
| `restart` | `[-Background] [-Json]` | `stop` 実行後 2 秒待機し、`start` を実行。 |
| `status` | `[-Json]` | FE (5173), BE (8000), ComfyUI (8188) の稼働状態と PID を出力（`-Json` 指定時は JSON 出力）。 |
| `toggle` | `[-Background]` | BE (8000) または ComfyUI (8188) が稼働中なら `stop`、全停止中なら `start` を実行。 |
| `reboot-service` | `-Service <fe\|be\|comfy> [-Json]` | 指定されたサービスのみを個別停止・再起動。 |
| `logs` | `-Service <fe\|be\|comfy>` | 指定されたサービスのログファイルを追跡表示 (`Get-Content -Wait -Tail 30`)。 |
| `menu` | なし | 対話型コンソールメニューを表示し、キー入力で各アクションを実行。 |

## 5. 常駐化・自動起動設計

1. **Windows タスクスケジューラ方式**:
   - タスク名: `PromptSurgeon_AutoStart`
   - トリガー: ユーザーログオン時、遅延時間 15 秒（WSL2 / ネットワーク立ち上がり待機）。
   - 実行内容: `powershell.exe -ExecutionPolicy Bypass -WindowStyle Hidden -File "...\server-manager.ps1" -Action start -Background`
2. **登録用スクリプト (`register_startup_task.ps1`)**:
   - `powershell.exe -File tools/server-manager/register_startup_task.ps1 -Action register` で自動登録、`-Action unregister` で解除可能。
