# REQ-236: 異常系・耐障害性（Red Teaming）テストの実装 (Phase 3) 設計仕様書

## 1. 概要とアーキテクチャ方針

本設計は、テスト拡充計画（`tmp/test_framework_implementation_plan.md`）の「Phase 3: 異常系・耐障害性（Red Teaming / Fault Tolerance）テスト」に基づき、Prompt Surgeon における外部サービス連携（ComfyUI、LM Studio/LLM、翻訳API）および中核パーサー/スキャナーに対する網羅的な障害注入テスト（Fault Injection）とプロパティベーステスト（Property-based Testing）を新設・体系化するものである。

### 1-1. 他Phaseとの並行性および競合防止
- **非破壊・テスト層新設中心**:
  - 本Phaseで新設するテストファイルはすべて独立した新規ファイル（`*.fault.test.ts`, `*.property.test.ts`, `test_*_fault.py`, `test_*_property.py`）として作成する。
  - プロダクションコードの修正は、AC-6 において hypothesis ファジングテストによって検出される破損ノードJSONに対する防御的ガード（`backend/app/services/workflow_scanner.py`）の最小限の修正のみに限定し、Phase 2 や Phase 4 とのコンフリクトを原理的に排除する。

```
[Phase 1: テスト基盤の構築 (REQ-234)] (Merged)
       │
       ├────── [Phase 2: 未カバー画面テスト (REQ-235)] (Merged / Independent)
       │
       ├────── [Phase 3: 異常系・耐障害性テスト (REQ-236)] ← 本設計対象
       │         ├── FE 障害注入: useGenerateAction.fault, usePromptTranslation.fault, useLlmAction.fault
       │         ├── BE 障害注入: test_comfy_proxy_fault.py, test_llm_service_fault.py
       │         └── プロパティテスト: useChipParser.property.test.ts, test_workflow_scanner_property.py
       │
       └────── [Phase 4: 巨大テスト分割・隔離検証 (REQ-237)] (Parallel)
```

## 2. 詳細設計仕様

### 2-1. フロントエンド障害注入仕様 (Task 1: MSW v2 活用)

#### A. ComfyUI キュー投入障害 (`useGenerateAction.fault.test.ts` - AC-1)
- **対象**: `frontend/src/pages/GeneratePage/hooks/useGenerateAction.ts` および `frontend/src/store/slices/jobQueueSlice.ts`
- **注入障害パターン**:
  1. **HTTP 503 Service Unavailable / HTTP 502 Bad Gateway**:
     - MSW: `http.post('/api/comfy/prompt', () => HttpResponse.json({ error: 'ComfyUI Server is starting up' }, { status: 503 }))`
     - 検証: `setErrorToast` が適切なエラーメッセージとともに発火すること。
     - ストア状態: `isGenerating` が `false`（または安全に復旧）、`isBatchSubmitting` が `false` にリセットされること。
  2. **ネットワーク切断 / Connection Reset**:
     - MSW: `http.post('/api/comfy/prompt', () => HttpResponse.error())`
     - 検証: エラートースト通知が表示され、未完了ジョブが `failed` ステータスとしてバッチに安全に記録されること。
  3. **部分失敗（バッチ投入中の途中エラー）**:
     - 2件中1件目が成功、2件目で503発生。
     - 検証: 1件目の promptId は保持され、2件目のみ `failed` マークされ、全体投入完了後に安全に復旧すること。

#### B. 外部翻訳APIタイムアウト・通信断 (`usePromptTranslation.fault.test.ts` - AC-2)
- **対象**: `frontend/src/pages/GeneratePage/hooks/usePromptTranslation.ts`
- **注入障害パターン**:
  1. **10秒タイムアウト / 504 Gateway Timeout**:
     - MSW: `http.post('/api/translate/prompt', () => HttpResponse.json({ detail: 'Translation upstream timed out after 10.0s' }, { status: 504 }))`
     - 検証: `isTranslating` が `false` に復帰し、`error` ステートにエラーが設定されること。
     - 原文テキスト保持: `sourceText` および `paramValues[role]` の既存テキストが消去・破損されず保持されること。
  2. **ネットワーク切断 (`HttpResponse.error()`)**:
     - 検証: 例外で UI がクラッシュせず、エラーメッセージが表示され、再試行可能な状態を維持すること。

#### C. LLM シーン生成 / 監査タイムアウト (`useLlmAction.fault.test.ts` - AC-3)
- **対象**: `frontend/src/pages/GeneratePage/hooks/useAuditAction.ts` および `frontend/src/components/SceneGeneratorModal.tsx` (`useSceneGenerator.ts`)
- **注入障害パターン**:
  1. **30秒タイムアウト / HTTP 504 (`/api/audit`, `/api/llm-prompts/scene-generate`)**:
     - MSW: `http.post('/api/audit', () => HttpResponse.json({ detail: 'Audit generation timeout' }, { status: 504 }))`
     - MSW: `http.post('/api/llm-prompts/scene-generate', () => HttpResponse.json({ detail: 'Scene generation timeout' }, { status: 504 }))`
     - 検証:
       - `useAuditAction`: `auditStatus` が `'error'` に遷移し、ローディングスピナー等のブロックが解除されること。
       - `SceneGeneratorModal`: `isDrafting` が `false` に解除され、モーダル内に警告エラーバナーが表示されること。

### 2-2. バックエンド障害注入仕様 (Task 2: respx 活用)

#### A. ComfyUI プロキシ障害注入 (`test_comfy_proxy_fault.py` - AC-4)
- **対象**: `backend/app/routers/comfy.py`
- **注入障害パターン**:
  1. **`httpx.ConnectTimeout`**:
     - `/api/comfy/object_info` 呼び出し時: `respx.get(f"{settings.comfy_url}/object_info").mock(side_effect=httpx.ConnectTimeout("Connect timeout"))`
     - 期待挙動: `HTTPException(status_code=503)` が送出され、明瞭なエラーメッセージが返却されること。
     - `/api/comfy/prompt` 呼び出し時: `respx.post(f"{settings.comfy_url}/prompt").mock(side_effect=httpx.ConnectTimeout("Connect timeout"))`
     - 期待挙動: `HTTPException(status_code=502)` が送出されること。
  2. **`httpx.ReadTimeout`**:
     - 各エンドポイントで ReadTimeout 発生時に 502/503 が返却されること。
  3. **不正・破損 JSON レスポンス**:
     - ComfyUI 側が HTML エラーページ（例: Nginx 502 画面）や壊れたバイト列を返却した場合、サーバーが 500 クラッシュせず 502/503 に変換してハンドリングすること。

#### B. LLM サービス障害注入 (`test_llm_service_fault.py` - AC-4)
- **対象**: `backend/app/services/llm_request.py`, `backend/app/services/llm_service.py`, `backend/app/routers/llm_prompts.py`
- **注入障害パターン**:
  1. **`httpx.ConnectTimeout` / `httpx.ReadTimeout`**:
     - `respx.post(f"{settings.llm_base_url}/chat/completions").mock(side_effect=httpx.ReadTimeout("LM Studio busy"))`
     - 期待挙動: `call_llm` が例外を適切に送出し、上位ルーター（`/scene-generate`, `/translate`）が 500/503 等の適切な HTTP エラーを返却すること。
  2. **不正 JSON / 壊れた choices 構造**:
     - `{"invalid_key": "no choices"}` や構文エラー JSON に対し、パーサーおよびサービスクラスが安全にエラーハンドリングし、システムダウンを防止すること。

### 2-3. プロパティベーステスト仕様 (Task 3: fast-check & hypothesis)

#### A. チップ構文パーサーのファジング (`useChipParser.property.test.ts` - AC-5)
- **対象**: `frontend/src/components/TagChipEditor/useChipParser.ts`
- **使用フレームワーク**: `fast-check`
- **プロパティ検証項目**:
  1. **クラッシュ耐性 (No-Crash Property)**:
     - `fc.assert(fc.property(fc.fullUnicodeString(), (str) => { parseToChips(str); return true }))`
     - 特殊文字、ゼロ幅スペース、極長文字列、改行混入、壊れた括弧等、いかなる入力に対しても例外をスローせず安全に `TagChip[]` を生成すること。
  2. **可逆性・恒等性 (Round-trip / Reversibility Property)**:
     - カンマを含まない有効タグ文字列配列から生成された `TagChip[]` に対し、`chipsToString(parseToChips(tags.join(', ')))` が空白正規化後のタグ順序と内容を完全に再現すること。
  3. **重み付け構文パースの堅牢性 (Weight Syntax Property)**:
     - `fc.assert(fc.property(fc.string(), fc.float({ min: 0.0, max: 10.0, noNaN: true }), (tag, weight) => ...))`
     - `formatTagWeight` と `parseTagWeight` の相互変換において、NaN や不正文字が混入しても安全にフォールバックすること。

#### B. ワークフロースキャナーの堅牢性検証 & 防護修正 (`test_workflow_scanner_property.py` - AC-6)
- **対象**: `backend/app/services/workflow_scanner.py`
- **使用フレームワーク**: `hypothesis` (`strategies as st`)
- **プロパティ検証項目**:
  1. **破損 node JSON に対する防御 (Robustness Property)**:
     - `_find_candidate_nodes` および `scan_workflow` に対し、`node_data` が壊れた型（`_meta` が文字列や数値、`class_type` が `None` や `int`、`inputs` がリスト等）の JSON を投入。
     - **期待値**: 例外（`AttributeError`, `TypeError`）でプロセスが停止せず、安全に `warnings`（`not_found` や適切なエラー構造）を返却すること。
  2. **プロダクション防護修正 (`workflow_scanner.py`)**:
     - `node_data.get("_meta", {})` の戻り値が `dict` でない場合の安全ガード。
     - `node_class_type` が `str` でない場合の安全ガード。
     - `title_patterns` / `expected_class_types` の要素が `str` でない場合の安全ガード。

## 4. トレードオフと制約 (Trade-offs & Constraints)

| 観点 | 内容 |
|---|---|
| **高速性と網羅性のトレードオフ** | プロパティベーステスト（fast-check / hypothesis）は数百パターンの乱数入力を検証するため、デフォルト設定ではテスト実行時間が伸びる傾向がある。<br>**対策**: CI / 通常実行で快適に完了するよう、fast-check の `numRuns: 100`、hypothesis の `max_examples=50` に設定し、1テストあたり 1 秒以内で高速終了するよう制限する。 |
| **MSW v2 ハンドラーの隔離性** | MSW のハンドラーをテストごとに書き換える際、他テストにモックが漏洩するリスクがある。<br>**対策**: `server.use()` による局所的オーバーライドを使用し、各テストスイートの `afterEach` で `server.resetHandlers()` を確実に呼び出す。 |
| **バックエンド ComfyUI クライアントのシングルトン** | `backend/app/routers/comfy.py` の `get_comfy_client()` はシングルトン `_client` を再利用するため、respx のコンテキストマネージャ内で適切にリクエストがインターセプトされる必要がある。<br>**対策**: `respx.mock` フィクスチャまたは `@respx.mock` デコレータを適切に適用し、コネクションプールに対してもモックトランスポートが有効に働くよう検証する。 |
