## 1. 設計概要

### 目標

全6画面にわたる「複数選択 + 一括操作」機能を、共通フックとUIコンポーネントとして設計・実装する。  
既存の @dnd-kit/sortable 構成（HistoryPage, LoRAsPage, TagsPage, SettingsPage で導入済み）を最大限に再活用する。

### 既存インフラ確認（マイグレーション不要）

> **[確認済み]** `sort_order` カラムは `Lora`, `TagSet`, `MappingMaster` の全モデルに既存。  
> `PUT /api/loras/reorder`, `PUT /api/tag-sets/reorder`, `PUT /api/mapping-masters/reorder` も全て実装済み。  
> **バックエンドの変更は一切不要**。フロントエンドからこれらの既存 API を呼び出すだけでよい。

### 設計方針

1. **共通フック `useMultiSelect`** をコア実装として作成し、全画面が再利用する。
2. **複数選択モード（Multi-Select Mode）** は2つのエントリポイントを持つ:
   - キーボード: `Ctrl + クリック`（個別追加/解除）、`Shift + クリック`（範囲選択）
   - タッチ/マウス: 対象アイテムの長押し（500ms）→ チェックボックスUI型の選択モードに遷移
3. **D&D の複数アイテム移動**は @dnd-kit の `DragOverlay` + `onDragEnd` グループ処理で対応する。選択アイテム群がカーソルに追従するオーバーレイを表示する。
4. 既存 `HistoryPage` の `bulkSelectMode` / `selectedItemsForDelete` パターンを共通化した上で拡張する。

## 2. 共通フック設計: `useMultiSelect`

### 2-1. ファイル

`frontend/src/hooks/useMultiSelect.ts` [NEW]

### 2-2. インターフェース定義

```typescript
interface UseMultiSelectOptions {
  totalItems: { id: number }[];   // 範囲選択のためにアイテム全量が必要
}

interface UseMultiSelectReturn {
  // 状態
  isMultiSelectMode: boolean;      // 複数選択モードか否か
  selectedIds: Set<number>;        // 選択中のID集合

  // 操作
  enterMultiSelectMode: (firstId?: number) => void; // 長押しで起動。firstId 指定時はそのアイテムを選択済みにする
  exitMultiSelectMode: () => void;
  handleItemClick: (id: number, event: React.MouseEvent) => void; // Ctrl/Shift 処理込み
  toggleItem: (id: number) => void;
  selectAll: () => void;
  clearSelection: () => void;
  isSelected: (id: number) => boolean;
}
```

### 2-3. 内部ロジック

```
handleItemClick(id, event):
  if isMultiSelectMode:
    if event.shiftKey AND lastSelectedId !== null:
      // 範囲選択
      from = totalItems.findIndex(id => id === lastSelectedId)
      to   = totalItems.findIndex(id => id === id)
      rangeIds = totalItems.slice(min(from,to), max(from,to)+1).map(i => i.id)
      selectedIds = union(selectedIds, rangeIds)
    else if event.ctrlKey OR event.metaKey:
      // 個別トグル
      selectedIds.toggle(id)
    else:
      // 通常クリック（モード中）= トグル
      selectedIds.toggle(id)
    lastSelectedId = id
  else:
    // 通常モード: Ctrl/Shift押下でモード遷移
    if event.ctrlKey OR event.metaKey:
      enterMultiSelectMode(id)
    else:
      return "通常クリックハンドラを呼ぶ（親から渡す）"
```

### 2-4. 長押し検出

各アイテムカードにて `useRef` + `setTimeout` で 500ms 長押しを検出。  
`enterMultiSelectMode(id)` を呼び出す。  
D&D センサーの `delay: 500` と競合しないよう、D&D側は複数選択モード中は無効化する。

## 3. D&D 複数アイテム移動設計

### 3-1. 課題

@dnd-kit は標準でグループ移動に対応していない。ドラッグした1アイテムのみが `onDragEnd.active` となる。

### 3-2. 実装方針（Group-Move + DragOverlay パターン）

複数選択中のD&Dでは、**`DragOverlay`** を使って選択アイテム群がカーソルに追従するビジュアルフィードバックを実装する。

```typescript
// DragOverlay 用の状態
const [activeId, setActiveId] = useState<number | null>(null);

function handleDragStart(event: DragStartEvent) {
  setActiveId(event.active.id as number);
}

function handleDragEnd(event: DragEndEvent) {
  const { active, over } = event;
  setActiveId(null);
  if (!over || active.id === over.id) return;

  if (isMultiSelectMode && selectedIds.has(active.id as number) && selectedIds.size > 1) {
    // グループ移動: 選択アイテムを抽出し、非選択アイテムの over.id 位置に挿入
    const selected = items.filter(i => selectedIds.has(i.id));
    const nonSelected = items.filter(i => !selectedIds.has(i.id));
    const insertAt = nonSelected.findIndex(i => i.id === over.id) + 1;
    const newOrder = [...nonSelected.slice(0, insertAt), ...selected, ...nonSelected.slice(insertAt)];
    setItems(newOrder);
    reorderMutation.mutate(newOrder.map(i => i.id));
  } else {
    // 単一移動（従来通り）
    const oldIndex = items.findIndex(i => i.id === active.id);
    const newIndex = items.findIndex(i => i.id === over.id);
    const newOrder = arrayMove(items, oldIndex, newIndex);
    setItems(newOrder);
    reorderMutation.mutate(newOrder.map(i => i.id));
  }
}
```

### 3-3. DragOverlay の表示内容

```tsx
<DragOverlay>
  {activeId && (
    <div className="relative">
      {/* ドラッグ中のカードのゴースト表示 */}
      <div className="opacity-90 scale-105 ring-2 ring-accent-green rounded-xl">
        {/* 先頭アイテムのカードをレンダリング */}
        <ItemCard item={items.find(i => i.id === activeId)!} isOverlay />
      </div>
      {/* 複数選択時: 「+N」バッジを右下に表示 */}
      {isMultiSelectMode && selectedIds.size > 1 && (
        <div className="absolute -bottom-2 -right-2 bg-accent-green text-black text-xs font-bold
                        rounded-full w-6 h-6 flex items-center justify-center">
          +{selectedIds.size - 1}
        </div>
      )}
    </div>
  )}
</DragOverlay>
```

```typescript
interface BulkEditField {
  key: string;
  label: string;
  type: 'category' | 'strength';         // category = セレクトボックス, strength = 数値入力 x2

  isOpen: boolean;
  onClose: () => void;
  fields: BulkEditField[];

```

## 5. 各画面ごとの適用設計

### 5-1. GeneratePage（生成履歴の一括スナップショット保存）

- D&D グループ移動（`DragOverlay` 含む） + `PUT /api/tag-sets/reorder`（**既存エンドポイント**）を呼び出し

## 6. バックエンド変更: なし

> **[確認済み]** 全ての並び替え永続化インフラは既に実装済みのため、バックエンドの変更は不要。

| 機能 | エンドポイント | ステータス |
|---|---|---|
| LoRA 並び替え | `PUT /api/loras/reorder` | ✅ 実装済み（`sort_order` カラム使用）|
| タグセット並び替え | `PUT /api/tag-sets/reorder` | ✅ 実装済み（`sort_order` カラム使用）|
| マッピングマスタ並び替え | `PUT /api/mapping-masters/reorder` | ✅ 実装済み（`sort_order` カラム使用）|

フロントエンド側の `reorderLoras.mutate(ids)` / `reorderTagSets.mutate(ids)` / `reorderMaster.mutate(ids)` が各ページで既存実装されており、グループ移動後も同じ mutationFn を呼ぶだけでよい。

## 9. トレードオフ開示

| # | 項目 | トレードオフ |
|---|---|---|
| 1 | **並び替え保存方針** | `display_order` カラム追加によりDBマイグレーションが必要。移行コストが生じるが、フィルタ・ソートと整合する最もシンプルな方法。代替（JSON で順序を別テーブル管理）より保守性が高い。 |
| 2 | **D&Dグループ移動** | @dnd-kit 標準機能外。`onDragEnd` でのグループ再配置アルゴリズムが複雑になる。ただし外部ライブラリ追加なしで対応できる。 |
| 3 | **GeneratePage の一括保存** | 複数枚を順次 `POST /api/snapshots` する（並列 or ループ）。バックエンドに一括保存エンドポイントがなく、現フェーズでは追加しない（既存API再利用優先）。将来的に `POST /api/snapshots/bulk` を追加するとパフォーマンスが改善する可能性がある。 |
| 4 | **HistoryPage の既存 bulkSelectMode の移行** | 既存実装を `useMultiSelect` に置き換えるため、リグレッションリスクが伴う。T5 でテストを拡充することで緩和する。 |
| 5 | **Ctrl/Shift クリックのキーボードのみ対応** | タッチデバイスでは長押しのみ。Ctrl/Shift は物理キーボードが必要なため、モバイルでは長押しエントリポイントが唯一の手段となる。 |
