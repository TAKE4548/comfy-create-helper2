# REQ-297: プリセット一括編集モーダルの利便性向上 詳細設計書

## 1. 概要 (Overview)
本設計は、生成画面（GeneratePage）におけるプリセット一括編集モーダル（ProfileBulkEditModal）の操作性および作業効率を抜本的に改善するための仕様である。
連続的な一括編集ワークフロー（プロンプト調整、パラメータ調整、共通タグ整理）を妨げていた自動モーダルクローズを撤廃し、入力・選択状態の明示的リセット、パラメータ検索、対象欄の排他制御、動的な共通タグサブセット抽出、およびタグ編集UIの統一を提供する。

- **usePresetState.ts (handleBulkEditApply)**:

  - 適用成功通知トースト（setErrorToast({ message: '...', type: 'success' })）を表示。

## 3. 機能別詳細仕様 (Functional Specifications)

### 3.1 AC-1: プロンプト入力クリアボタン
- **対象**: PromptOperationForm.tsx 内の promptFindText, promptReplaceText, promptValue。
- **仕様**:
  - 各入力欄の右端またはラベル横に「クリア」ボタンを配置。
  - 入力値が空文字（''）の場合はボタンを非活性化または非表示（DOM上に視覚的ノイズを与えない）。
  - ボタン押下時、即座に対応する state を '' にリセット。
  - モーダルを閉じて再度開いた場合、クリアを押していない限り前回の入力値がそのまま保持される（状態リセットは行わない）。

### 3.2 AC-2: パラメータ選択の自動解除
- **対象**: useProfileBulkEditState.ts, ProfileBulkEditModal/index.tsx。
- **仕様**:
  - useProfileBulkEditState に esetParamSelection() を定義：
    - enabledParams を

    - atchSizeEnabled を alse に初期化。
  - モーダルの handleConfirm で wait onApply(pendingPayload) が成功した直後に state.resetParamSelection() を呼び出し、パラメータの選択状態を解除。
  - 次回のパラメータ一括編集時に、意図しない前回の選択項目が誤適用されるリスクを排除する。

### 3.3 AC-3: 適用後のモーダル維持およびESC終了制御
- **対象**: usePresetState.ts, ProfileBulkEditModal/index.tsx。
- **仕様**:
  - usePresetState.ts の handleBulkEditApply から setIsBulkEditOpen(false) と setBulkTargetIds([]) を削除。
  - ulkTargetIds を保持することにより、モーダル内の selectedPresets が維持され連続編集が可能。
  - ProfileBulkEditModal に Escape キーリスナーを登録（ポップオーバー非表示時または優先度制御下で onClose() を呼出）。
  - クローズは「×」ボタン、「キャンセル」ボタン、または Escape キー押下時のみに限定。

### 3.4 AC-4: 共通タグのサブセット抽出と動的再集計
- **対象**: 	ypes.ts, useProfileBulkEditState.ts, CommonTagsSection.tsx, uildPayload.ts, usePresetState.ts。
- **仕様**:
  - BulkEditPayload に 	argetPresetIds?: number[] を追加。
  - useProfileBulkEditState に subsetPresetIds: Set<number> を管理（初期値は全 selectedPresets.map(p => p.id)）。
  - CommonTagsSection.tsx の上部に「対象プリセット絞り込み」セクションを新設：
    - 各プリセットのチェックボックス、プリセット名を表示。
    - 「全選択」「全解除」アクションを提供。
  - チェックされたプリセット群（subsetPresets = selectedPresets.filter(p => subsetPresetIds.has(p.id))）を基に computeCommonTags を即時再実行。
  - promptOp === 'remove_tags' の場合、uildBulkEditPayload は 	argetPresetIds: Array.from(subsetPresetIds) をペイロードに設定。
  - handleBulkEditApply 側で payload.targetPresetIds を参照し、選択されたプリセットにのみタグ変更を適用。

### 3.5 AC-5: プロンプト対象欄のモード別排他制御
- **対象**: TargetFieldsSelector.tsx, useProfileBulkEditState.ts。
- **仕様**:
  - promptOp === 'search_replace' の場合：
    - 「すべて対象」チェックボックスを有効化。
    - 対象フィールドは複数選択可能（チェックボックス動作）。
  - promptOp === 'overwrite' | 'prefix' | 'suffix' の場合：
    - 「すべて対象」チェックボックスは非表示/無効化。
    - 対象フィールドは単一排他的選択（ラジオボタン動作）。
    - 複数選択状態から単一排他モードへ遷移した場合、選択状態は先頭の1件（Array.from(promptTargetFields)[0] || textareaRoles[0]?.role）に自動フォールバック。

### 3.6 AC-6: パラメータ検索フィルタ
- **対象**: ParamBulkEditTab/index.tsx。
- **仕様**:
  - パラメータ一覧の最上部にインクリメンタル検索ボックスを設置。
  - プレースホルダー: パラメータを検索... (名称・キー)
  - 入力値 searchQuery に基づき、paramRoles（display_name, ole, param_name）およびバッチサイズ項目を部分一致フィルタリング。
  - 該当項目が0件の場合は「該当するパラメータが見つかりません」の空表示メッセージを表示。
  - 検索欄クリアボタンの提供。
  - **重要**: 検索フィルターによる非表示状態は、各パラメータの enabledParams（選択状態）および適用処理には一切干渉しない。非表示の選択済みパラメータもそのまま適用対象に含まれる。

### 3.7 AC-7: 共通タグのサブメニュー編集統一
- **対象**: CommonTagsSection.tsx, CommonTagSubmenu.tsx。
- **仕様**:
  - 旧仕様の「タグ本体クリックで削除トグル」を廃止。
  - タグチップ本体（テキスト部分）をクリックすると、TagChip（プロンプトエディタ）と同等のタグ編集サブメニュー（ポップオーバー）が開く。
  - サブメニュー構成:
    - タグ名入力欄（文言編集、Enter/Blurで反映）
    - 強度数値入力欄（直接入力）
    - ステップボタン（-0.3, -0.1, +0.1, +0.3）
    - 削除ボタン（対象から削除）
  - タグチップ本体の右端に独立した削除アイコン（X）を配置。削除アイコン押下またはサブメニュー内削除操作でのみ削除フラグ（	agsToRemove）を設定。
  - 削除フラグが立っているタグは取り消し線およびハイライト表示され、再押下で復帰可能。

## 5. トレードオフ開示 (Trade-off Disclosure)
1. **適用後のモーダル維持に伴うプリセット状態同期のトレードオフ**:
   - モーダルを閉じないため、連続して適用を行うと selectedPresets の各パラメータ値が直前の適用結果と乖離するリスクがある。
   - **対策**: qc.setQueryData および usePresetState 内のインメモリキャッシュを即時更新し、モーダルに渡る selectedPresets が最新の状態を反映するように設計。
2. **サブセット抽出時のタグ編集差分計算の複雑化**:
   - 全選択ではなく一部のプリセットのみを対象にした場合、共通タグの出現集合が変動する。
   - **対策**: subsetPresetIds に基づく computeCommonTags の純粋関数呼び出しに徹し、	argetPresetIds を明示的にペイロードへ注入することで、バックエンドおよびパッチャー側で正確に対象限定パッチを適用。
3. **パラメータ検索時の視認性と選択状態の乖離リスク**:
   - 検索フィルタによって隠れたパラメータにチェックが入っている場合、ユーザーが忘れたまま適用してしまう可能性がある。
   - **対策**: 検索ボックス下部または適用確認画面（BulkEditConfirmView）にて、現在有効化されている全パラメータ数を「有効: N件」と明示表示し、意図しない適用の事故を防ぐ。
