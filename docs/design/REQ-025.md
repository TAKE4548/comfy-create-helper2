# REQ-025 詳細設計書: スマホモード時のレイアウト崩れおよびボタン非活性/非表示の修正

## 1. 目的・背景
スマホ幅（768px未満）および `/mobile` パスにおいて、PC用の横並び2カラムレイアウト（左側設定入力、右側プレビュー）が適用されているため、左カラム（幅420px固定）が画面幅を超過し、右カラムにある画像プレビューや生成・スナップショット保存ボタンが画面外へはみ出して表示されず、操作できない問題が発生しています。
仕様書に定義されている「スマホ専用レイアウト」に切り替える実装を追加し、適切なレスポンシブ動作を可能にします。

## 2. システム設計
### 2.1 動的スマホモード判定 (Responsive Custom Hook / State)
コンポーネントマウント時の `window.innerWidth` だけでなく、ウィンドウのリサイズを動的に検知して `isMobile` 状態を更新する仕組みを `GeneratePage.tsx` に導入します。
* **ブレークポイント**: 768px 未満（`window.innerWidth < 768`）またはパスが `/mobile` で始まる場合。

```typescript
const [isMobile, setIsMobile] = useState(() => {
  return window.location.pathname.startsWith('/mobile') || window.innerWidth < 768;
});

useEffect(() => {
  const handleResize = () => {
    setIsMobile(window.location.pathname.startsWith('/mobile') || window.innerWidth < 768);
  };
  window.addEventListener('resize', handleResize);
  return () => window.removeEventListener('resize', handleResize);
}, []);
```

### 2.2 スマホ専用レイアウト (1カラム縦スクロール)
`isMobile === true` の場合、以下の1カラム縦スクロール構造（`flex flex-col`）をレンダリングします。
1. **ヘッダー**: ワークフロー選択、スナップショット履歴選択
2. **LLM Audit**: 折りたたみ可能なパネル（PCと同様）
3. **画像プレビューエリア & 進捗表示**:
   * PC版の右カラム（メインプレビュー）をスマホ幅に合わせて表示。アスペクト比を維持しつつ、高さの上限を設定（例: `max-h-[300px]` または `aspect-square`）。
   * 生成中は進捗バーを表示。
4. **履歴サムネイルストリップ**:
   * メインプレビューの下部に、横スクロールのサムネイルリスト（PCと同様）を表示。
5. **プロンプト入力エリア (仕様書準拠)**:
   * **横スクロール対応タブ**: `textMappings` をループし、タブ名（`display_name`）を並べた横スクロールコンテナ（`flex overflow-x-auto whitespace-nowrap gap-2 py-1`）。
   * **アクティブタブ管理**: 現在選択されているマッピングの `role` を state （`activePromptTab`）で管理する。
   * **共用テキストエリア**: 現在アクティブな `role` に対応するプロンプト内容（`paramValues[activePromptTab]`）を表示・編集する `textarea` を1つだけ配置する。
6. **アセットチップス**:
   * 現在アクティブなプロンプトタブに紐づいている appliedAssets をテキストエリアの下部に表示する。
7. **パラメータ設定カード**:
   * parameters 関連（CFG, Steps, Batch Size, Seed）を縦に並べるアコーディオンまたはカード。スマホ向けにパディング等を調整。
8. **アクションバー（下部固定）**:
   * 「Generate Batch」および「Save Snapshot」ボタンを配置。スマホのビューポート下部に固定（`sticky bottom-0 bg-surface border-t border-[rgba(255,255,255,0.06)] p-3`）することで、いつでもスクロールせずに押せるようにする。

### 2.3 PC用レイアウトとの切り替え
`GeneratePage.tsx` の `return` 内で、`isMobile` の真偽値に基づき、全体レイアウトを切り替えます。
* `isMobile === true` -> スマホ専用縦スクロールレイアウト（プレビューとプロンプト共用入力・タブ）
* `isMobile === false` -> デスクトップ用2カラムレイアウト（左：詳細入力、右：プレビュー・実行ボタン）
