# REQ-302: 未統一オーバーレイの前面化と不要なナビ回避余白の解消 詳細設計

## 1. 概要とアーキテクチャ方針

### 1.1 背景と現状課題 (As-Is: 2026-10-26棚卸し)
1. **スタッキング階層の未統一**:
   - `AppShell.tsx` のボトムナビゲーションは `--z-mobile-nav: 50`。
   - 共通Modal (`Modal.tsx` / `.modal-backdrop`) は `--z-modal: 100` で前面化済み。
   - しかし、Generate画面（LoRA設定、プリセット管理）、PresetConflictModal、MobileImageSheet、DatasetStudio（CreateProjectModal、NodeRemapModal、BenchmarkCellModal）、HistoryPage（一括削除確認）において、独自オーバーレイが `z-50` のまま残存しており、ボトムナビと同順位またはスタッキング文脈により背面ナビへのタップ抜けや重なり競合のリスクが存在する。
2. **基底 `.modal-backdrop` の旧ナビ回避余白**:
   - `frontend/src/index.css` の `.modal-backdrop` 基底に `padding-bottom: calc(var(--mobile-nav-height) + 1rem + env(safe-area-inset-bottom));` が残存。
   - モーダルが `--z-modal: 100` でボトムナビの前面を覆う仕様であるにもかかわらず、ナビを避けるための約64px余白が一律に加算されている。
   - さらに、768〜1023px の画面幅ではボトムナビは `md:hidden`（非表示）であるにもかかわらず、既存の除外条件（`:not(:has(> [role='dialog']))` や `.flex-col`）により、共通ModalやHistoryModalPreviewなどでナビ非表示時にも旧回避余白が残る不整合が発生している。
3. **操作性・アクセシビリティの未統一**:
   - 独自オーバーレイの一部で、Escapeキーハンドリング、フォーカストラップ、バックドロップクリックによる閉じる操作、起点へのフォーカス復帰が未実装。
4. **排他制御と明示的ネスト例外の整理**:
   - 共通規約（`SPEC_COMMON.md` §1-4）に基づきモーダルは原則排他。明示的に許可された唯一のネスト例外は `MappingMasterEditModal` 内の `WorkflowNodePicker`（`closeOnEsc={!isNodePickerOpen}`）。任意の二次モーダル追加を避け、排他切替の原則を徹底する。

### 1.2 解決方針 (To-Be)
1. **重なり順トークンの統一 (`--z-modal: 100`)**:
   - ボトムナビ（`--z-mobile-nav: 50`）に対し、すべてのモーダルダイアログ・下部シート・バックドロップを `--z-modal: 100`（または `z-[var(--z-modal)]` / `.modal-backdrop`）に統一。
   - トースト（errorToast等）は最前面通知レイヤーを維持。ヘッダーメニュー（`--z-header-menu: 60`）も維持。
2. **ナビ回避余白の完全撤廃とセーフエリア適正化**:
   - `.modal-backdrop` から `--mobile-nav-height` の加算を完全撤廃。
   - 768〜1023px およびデスクトップ（1024px+）における `padding-bottom: 1rem;` の適用条件を整理し、ナビ非表示時の不要余白を一掃。
   - モバイル（<768px）では、共通Modalの下部シート契約（上端16px角丸、`items-end`、`max-h-[calc(100dvh-env(safe-area-inset-top))]`、`pb-[env(safe-area-inset-bottom)]`）を適用。raw `100vh` は禁止し、`100dvh` を徹底。
   - 通常画面コンテンツがナビに隠れないための `AppShell.tsx` の余白（`pb-[calc(54px+env(safe-area-inset-bottom))] md:pb-0`）は維持。
3. **共通Modal (`Modal.tsx`) への統合**:
   - 独自実装されているモーダル（LoRA設定、新規プロファイル作成、PresetConflictModal、CreateProjectModal、NodeRemapModal、BenchmarkCellModal、一括削除確認）は、既存の共通 `Modal.tsx` を再利用する形へ整理。
   - これにより、Focus Trap、Escapeキー、Backdropクリック、スクロールロック（`lockBodyScroll`）、フォーカス復帰、`overscroll-contain` を標準保証。
4. **画像確認・全画面ビューア例外の保護**:
   - `MobileImageSheet.tsx`（下部画像プレビューシートおよび全画面ビューア）および `HistoryModalPreview.tsx` は画像閲覧例外として既存構造を維持し、機械的な通常Modal置換を行わない。z-indexのみ `--z-modal: 100` へ引き上げ、ナビ遮蔽と操作性を保証。
5. **排他原則とネスト例外の維持**:
   - `MappingMasterEditModal` と `WorkflowNodePicker` の既存ネスト例外を完全に保護。

### 3.2 CSS 回避余白の解消仕様 (`frontend/src/index.css`) (AC-2, AC-5, AC-6)

現行の基底 `.modal-backdrop` 定義:
```css
/* AS-IS */
.modal-backdrop {
  position: fixed;
  inset: 0;
  background-color: rgba(0, 0, 0, 0.7);
  backdrop-filter: blur(8px);
  -webkit-backdrop-filter: blur(8px);
  display: flex;
  align-items: center;
  justify-content: center;
  z-index: var(--z-modal);
  padding: 1rem;
  padding-bottom: calc(var(--mobile-nav-height) + 1rem + env(safe-area-inset-bottom)); /* ← 不要なナビ回避余白 */
}
```

改修後の定義:
```css
/* TO-BE */
.modal-backdrop {
  position: fixed;
  inset: 0;
  background-color: rgba(0, 0, 0, 0.7);
  backdrop-filter: blur(8px);
  -webkit-backdrop-filter: blur(8px);
  display: flex;
  align-items: center;
  justify-content: center;
  z-index: var(--z-modal);
  padding: 1rem;
  padding-bottom: calc(1rem + env(safe-area-inset-bottom, 0px));
}

@media (min-width: 768px) {
  .modal-backdrop {
    padding: 1rem;
    padding-bottom: 1rem;
  }
}
```
- `< 768px`: 共通Modalでは `Modal.tsx` 側が `p-0 pb-[env(safe-area-inset-bottom)]` を指定し、下部シート化（`items-end`）。`.modal-backdrop` のレガシー直接利用でも `padding-bottom: calc(1rem + env(safe-area-inset-bottom, 0px))` で安全な下部余白を確保。
- `768px〜1023px`: ボトムナビは非表示（`md:hidden`）。旧CSSの `:not(:has(> [role='dialog']))` や `:not(.flex-col)` 制限を撤廃し、一律 `padding-bottom: 1rem;` とすることで不要な余白を完全に解消。
- `>= 1024px`: デスクトップ表示として一律 `padding-bottom: 1rem;` を維持。

## 5. トレードオフとリスク分析 (Trade-offs & Risks)

1. **独自オーバーレイの共通Modal置換 vs 独自CSSでの前面化のみ**:
   - *代替案*: 既存の独自オーバーレイのクラスに `z-[var(--z-modal)]` を追記するだけの修正。
   - *採用理由*: `Modal.tsx` を再利用することで、Escapeハンドリング、Focus Trap、Body Scroll Lock、モバイル下部シート化（16px角丸、スワイプハンドル、safe-area処理）が自動的に統一され、コード重複と保守コストを大幅に削減できる。
2. **画像ビューア（`MobileImageSheet`, `HistoryModalPreview`）の通常Modal置換の不採用**:
   - *判断*: 画像確認シート・全画面ビューアはアスペクト比維持、WakeLock、全画面切り替えなどの特殊要件があるため、機械的に通常Modalへ置換せず、例外として維持しつつ z-index のみを統一する（AC-6遵守）。
3. **768〜1023px での余白解消リスク**:
