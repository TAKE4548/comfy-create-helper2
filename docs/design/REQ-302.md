# REQ-302 詳細設計: モバイル・レスポンシブ表示時におけるモーダルのボトムナビゲーション前面オーバーレイ化

## 1. 背景とアーキテクチャ方針

### 1.1 現状の課題 (As-Is)
1. **回避余白による縦幅圧迫**: 過去の改修でモーダルとボトムメニューの重なりを防ぐため、`.modal-backdrop` に `padding-bottom: calc(var(--mobile-nav-height) + 1rem + env(safe-area-inset-bottom));` が設定されていた。これにより、モバイル画面でモーダル下部に約64px（4rem）＋セーフエリア分の巨大な余白が一律確保され、縦長モーダル（フォームや画像選択、タグ一覧等）の表示領域（`max-h-full`）が過剰に圧迫され、スクロールしても下部アクションボタンが操作しにくい状況が発生していた。
2. **z-index の競合・潜り込み**: `frontend/src/index.css` において `--z-mobile-nav: 50;` と定義され、一部のモーダルコンポーネントが `z-50` を直書きしていた。React ツリー上で `<AppShell>` の `<nav>` が `<main>` の後にレンダリングされるため、同一 z-index（50）のコンテキストにおいてボトムメニューがモーダルより前面に描画され、モーダル下部が覆い隠されたり、誤タップが発生する不具合があった。
3. **ネストされた確認モーダルの階層順序**: モーダルからさらに開かれる確認ダイアログ（削除確認等）において、スタッキング階層の明示的な分離トークンが存在しなかった。

### 1.2 解決方針 (To-Be)
1. **スタッキング階層の明確化（z-index Design Tokens）**:
   - ページ内スクロール要素: `z-0` 〜 `z-30`
   - モバイルボトムナビゲーション: `--z-mobile-nav: 40;` (Tailwind: `z-mobile-nav` / 40)
   - 基本モーダル / バックドロップ: `--z-modal: 100;` (Tailwind: `z-modal` / 100)
   - ネスト・確認モーダル（最大2階層）: `--z-modal-nested: 110;` (Tailwind: `z-modal-nested` / 110)
   - 最前面トースト / システム通知: `--z-toast: 200;` (Tailwind: `z-toast` / 200)
   これにより、モーダル（100）がボトムナビゲーション（40）を確実に前面で覆い、二次確認モーダル（110）が一次モーダルを前面で覆う絶対ヒエラルキーを確立する。
2. **回避余白（Legacy Offsets）の完全撤廃**:
   - `.modal-backdrop` から `--mobile-nav-height` の加算を撤廃し、`padding-bottom: calc(1rem + env(safe-area-inset-bottom, 0px));` に統一する。
   - モバイル端末のセーフエリア（iOS ホームインジケーター）との適正クリアランス（34px等）を確保しつつ、画面下端までの全高を最大限に活用可能にする。
3. **背面操作遮断とアクセシビリティ**:
   - モーダルバックドロップが `fixed inset-0`（画面全体）を展開し、前面レイヤー（z-100）としてボトムメニューへのタッチ・クリック操作を完全に遮断。
   - バックドロップクリックによるクローズ機能および Esc キーによるモーダル終了を保証する。
4. **デスクトップ表示の不変性**:
   - デスクトップ幅（1024px以上）ではサイドバーナビゲーション（`aside`）が適用され、モーダルのセンタリングおよび `padding-bottom: 1rem;` は変更なし。デグレ皆無を保証する。

## 2. レイヤー設計とトークン仕様

### 2.1 CSS カスタムプロパティ (`frontend/src/index.css`)
```css
:root {
  /* Navigation */
  --mobile-nav-height: 4rem;
  --z-mobile-nav: 40;     /* 従来の50から40へ引き下げ */

  /* Modal Layers */
  --z-modal: 100;          /* 一次モーダル・バックドロップ */
  --z-modal-nested: 110;   /* 二次・確認ダイアログ（ネスト上限2段） */
  --z-toast: 200;          /* 最前面通知 */
}

/* モーダルバックドロップの改修 */
.modal-backdrop {
  position: fixed;
  inset: 0;
  background-color: rgba(0, 0, 0, 0.7);
  backdrop-filter: blur(8px);
  -webkit-backdrop-filter: blur(8px);
  display: flex;
  align-items: center;
  justify-content: center;
  z-index: var(--z-modal);
  padding: 1rem;
  /* --mobile-nav-height の回避余白を撤廃し、セーフエリアのみ付与 */
  padding-bottom: calc(1rem + env(safe-area-inset-bottom, 0px));
}

.modal-backdrop:fullscreen,
.modal-backdrop:-webkit-full-screen {
  padding: 0 !important;
}

@media (min-width: 1024px) {
  .modal-backdrop {
    padding-bottom: 1rem;
  }
}
```

### 2.2 Tailwind CSS 拡張 (`frontend/tailwind.config.js`)
Tailwind の JIT コンパイラとの親和性を担保するため、数値を直接定義しつつ CSS 変数との整合性を確保する：
```javascript
theme: {
  extend: {
    zIndex: {
      'mobile-nav': '40',
      'modal': '100',
      'modal-nested': '110',
      'toast': '200',
    },
  },
}
```

## 3. コンポーネントおよび画面の改修設計

### 3.1 `frontend/src/components/layout/AppShell.tsx`
- モバイルナビゲーション `<nav>` は既に `z-[var(--z-mobile-nav)]` を使用しているため、CSS 変数の 50 → 40 変更により自動的に `z-index: 40` となる。
- `<main>` タスク領域の `pb-[calc(var(--mobile-nav-height)+env(safe-area-inset-bottom))]` は通常コンテンツのスクロール余白として維持（通常ページ閲覧時にボトムナビと重なるのを防止）。

### 3.2 共通および個別モーダルの z-index 標準化
各モーダルコンポーネントがハードコードされた `z-50` を持っている箇所を、設計トークン `z-[var(--z-modal)]` または `z-[var(--z-modal-nested)]`、あるいは `.modal-backdrop` クラスに統一する。

1. **`BaseImageSelectModal.tsx`**:
   - `fixed inset-0 z-50 ...` → `fixed inset-0 z-[var(--z-modal)] pb-[calc(1rem+env(safe-area-inset-bottom,0px))] ...`
2. **`PresetConflictModal.tsx`**:
   - 二次確認モーダルとして `z-[var(--z-modal-nested)]` を適用。
3. **`ParamTypeMasterModal.tsx`**:
   - `z-50` → `z-[var(--z-modal)] pb-[calc(1rem+env(safe-area-inset-bottom,0px))]`
4. **`SceneSpeechModal.tsx`**:
   - モバイルボトムシート: `pb-[calc(1rem+env(safe-area-inset-bottom,0px))] z-[var(--z-modal)]`
5. **`GeneratePage.tsx`**:
   - `selectedLoraForModal`: `z-[var(--z-modal)]`
   - `isPresetManagerOpen`: `z-[var(--z-modal)]`
   - `isBulkDeleteConfirmOpen`: `z-[var(--z-modal-nested)]`
6. **`HistoryPage/index.tsx`**:
   - `isDeleteSnapshotsModalOpen`: `z-[var(--z-modal-nested)]`
   - `albumDeleteTarget`: `z-[var(--z-modal-nested)]`
7. **`PromptTranslationModal.tsx` & `SaveAsTagSetModal.tsx`**:
   - `z-50` → `z-[var(--z-modal)]`

## 4. セーフエリアおよびフォールバック設計

- **対象プロパティ**: `env(safe-area-inset-bottom, 0px)`
- **フォールバック**: 未対応ブラウザやデスクトップでは 2 番目の引数 `0px` が評価され、`calc(1rem + 0px) = 1rem`（16px）の均等なパディングとなる。
- **実機検証対応**: iOS Safari / ホームインジケーター搭載端末において、34px の inset が加算され `1rem + 34px = 50px` の下部余白となり、システムジェスチャーとの誤操作を物理的に防ぐ。

---

## 5. アクセシビリティ・イベント伝播設計

- **バックドロップ**: `onClick={(e) => { if (e.target === e.currentTarget && closeOnBackdropClick) onClose(); }}` または `onClick={onClose}` かつ内側ダイアログで `e.stopPropagation()`。
- **タッチ遮断**: モーダル展開中、画面下部のボトムナビゲーションに対するタップイベントは全画面固定バックドロップがキャプチャし、背後の `<NavLink>` に伝播しない。
- **キーボード Esc**: `window.addEventListener('keydown')` による Escape 監視を維持。Esc 押下でモーダルのみが閉じ、ページ遷移は発生しない。
- **ネスト制限**: モーダル階層は最大 2 段（Primary Modal → Confirmation Dialog）に限定し、多重スタックのフォーカス漏れや z-index インフレーションを防止する。
