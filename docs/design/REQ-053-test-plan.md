# REQ-053 テストプラン: 全画面プレビュークラッシュ修正およびモバイルパディング追加（自動化対応・完全版）

## 1. 環境設定
- **ブラウザ**: Chrome (最新版) または Edge
- **ツール**: Playwright / Selenium (または同等の自動化フレームワーク)
- **ターゲット URL**: `http://localhost:5173`

## 2. テストケース詳細

### TC-01: 全画面プレビューの正常表示（基本）
**目的**: クラッシュ防止、モーダル機能の動作確認。

| ステップ | アクション (Action) | 期待結果 (Expected Result - 数値/論理判定) |
| :--- | :--- | :--- |
| 1.1 | ページ遷移: `/generate` または `/history` | ステータスコード `200`, DOM 読み込み完了。 |
| 1.2 | 要素検索: `getByRole("button", { name: "Preview" })` (または画像クリック領域) | 要素が見つかる (`found=true`)。 |
| 1.3 | クリック: 要素の中央座標をクリック | **判定**: <br>1. ブラウザコンソールに `ReferenceError` や `Uncaught Exception` が出力されていないこと。<br>2. モーダル要素 (`.modal-overlay`) の `display` プロパティが `block` または `flex` になっていること。 |
| 1.4 | クローズ: モーダル内のクローズボタン (X) をクリック | **判定**: <br>モーダル要素の `display` が `none` に変化していること。<br>コンソールにエラーがないこと。 |

### TC-02: プレビュー時のキーボード操作・スワイプ
**目的**: 画像切り替え機能とスタック処理の確認。

| ステップ | アクション (Action) | 期待結果 (Expected Result - 数値/論理判定) |

### TC-03: モバイル表示時のボトムメニューバーとメインコンテンツの重なり解消（数値的厳密判定）
**目的**: レイアウト崩れ（パディング不足）の数値的・論理的検証。

| ステップ | アクション (Action) | 期待結果 (Expected Result - 数値/論理判定) |
| :--- | :--- | :--- |
| 3.1 | ウィンドウサイズ変更: `setViewportSize(width=375, height=667)` (iPhone SE 相当) | レスポンシブレイアウト適用完了。 |
| 3.2 | **静的検証**: メインコンテンツの最下部要素 (`.last-element`) の位置情報を取得（スクロール前）。 | **判定**: <br>`element.offsetTop` が `window.innerHeight - menuHeight` より小さいこと。<br>(誤差許容値: **0px**) |
| 3.3 | **動的検証 (重要)**:<br>1. ページを最下部までスクロール (`scrollIntoView({ behavior: 'smooth' })`)。<br>2. スクロール完了後、直ちに要素の位置情報を再取得。 | **判定**: <br>スクロール後の `element.offsetTop` が依然として `window.innerHeight - menuHeight` より小さいこと。<br>**ロジック**: <br>`if (new_offsetTop >= windowHeight - menuHeight) { FAIL: "Content overlaps with footer after scroll" }` |
| 3.4 | **パディング検証**: メインコンテンツのスタイルを確認。 | **判定**: <br>意図されたパディングクラス（例：`pb-16` 等）が適用されていること。<br>**数値的確認**: `getComputedStyle(element).paddingBottom` の値が、フッターの高さ (`menuHeight` = 64px) を考慮した適切な値であることを確認。 |

## 3. 回帰テスト範囲 (自動化スクリプト追加)
- **デスクトップ検証**: ウィンドウサイズを `1920x1080` に設定し、メインコンテンツ要素の `getComputedStyle(element).paddingBottom` を取得。パディング値がデスクトップ用に不要な `pb-16`（64px）を排除し、意図されたデフォルト値（`0px` または `8px` 等）に一致することを確認。
- **インフォモード検証**: モーダル内の「メタデータ表示/非表示」ボタンをクリックし、DOM 要素の存在有無とレイアウト崩れ（`overflow: hidden` の発生など）がないことを確認。

## 4. 失敗条件 (Failure Criteria)
以下のいずれかが満たされた場合、テストは **FAIL** と判定されます。
1. ブラウザコンソールに `Error`, `Warning`, `ReferenceError` が出力される。
2. 期待する DOM 要素が見つからない (`elementNotFound`).
3. 数値的閾値の不整合: 期待された座標差、スクロール位置、パディング高さの誤差が **1px を超える**場合。
