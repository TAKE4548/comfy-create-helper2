# 設計書: REQ-130 (Add Set 実行時の新規セット自動アクティブ化)

## 1. 概要・目的
生成画面（GeneratePage）で「Add Set」モーダルから新規セット（プロファイル）を作成した際、追加されたセットが自動的にアクティブ状態（選択タブ）になり、そのセットのパラメータに即時同期されるように修正する。

## 2. 対象ファイル
- `frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts`

## 3. 変更詳細仕様

### 3-1. `createPresetMutation.onSuccess` の修正
新規セット作成成功ハンドラ (`onSuccess`) において、以下の処理を追加・更新する：

1. `localStorage.setItem` および `openPreset?.(newPreset.id)` の呼び出しに続き、`setActiveSetId(newPreset.id)` を明示的に実行する。
2. 作成された `newPreset` の各パラメータ値（`param_values`, `applied_assets`, `batch_size`, `seed_mode`, `seed`）で React state (`paramValues`, `appliedAssets`, `batchSize`, `seedMode`, `seed`) を更新し、UI表記およびフォーム状態を即座に新セットの値に同期させる。

### 3-2. `presets` 状態同期エフェクト (`useEffect`) のロジック改善
`presets` 再取得（`qc.invalidateQueries`）時に発火する同期エフェクト内の `matchedPreset` 評価ロジックを改修する：

**改修前**:
```typescript
const matchedPreset = presets.find(
  p => String(p.id) === String(storedActiveStr) || String(p.id) === String(activeSetId)
)
```
**問題点**:
`storedActiveStr` に新セットIDが書き込まれていても、`activeSetId` に旧セットIDが保持されていると、`presets` 配列の並び順で前に位置する旧セットが `|| String(p.id) === String(activeSetId)` に引っかかり優先指定されてしまう。

**改修後**:
```typescript
const matchedByStored = storedActiveStr
  ? presets.find(p => String(p.id) === String(storedActiveStr))
  : undefined
const matchedByActive = activeSetId !== null
  ? presets.find(p => String(p.id) === String(activeSetId))
  : undefined
const matchedPreset = matchedByStored || matchedByActive
```
**効果**:
`storedActiveStr`（`localStorage` に記録された明示的なアクティブID）が `presets` 内に存在する場合は最優先で選択され、存在しない場合のみ既存の `activeSetId` にフォールバックする。

## 4. 影響範囲・リスク評価
- **影響範囲**: `useGeneratePageState.ts` の `createPresetMutation` および `presets` 同期エフェクト。
- **リスク**: 低リスク。既存のタブ切り替えや他プリセット選択、初期表示時のストレージ復元ロジックには悪影響を与えない。

## 5. Traceability Matrix (AC mapping)
- **AC-1**: `createPresetMutation.onSuccess` で `setActiveSetId` およびフォームパラメータ状態更新を行うことで実現。
- **AC-2**: `matchedByStored` を最優先とする検索評価順序変更により実現。
- **AC-3**: 既存の切り替え・削除・オートセーブロジックを破壊せず維持することで実現。
