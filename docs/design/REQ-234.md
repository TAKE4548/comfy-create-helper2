### 2-2. 共通テスト Fixture & 環境分離 (`backend/tests/conftest.py`)
- **`sys.path` 解決**: `backend` ディレクトリを検索パス最優先に追加し、カレントディレクトリに依存しないインポートを保証。
- **コネクションリーク検知 Fixture**:
  各テストの teardown 時に `engine.pool.checkedout() == 0` を検証。未クローズの `db.close()` やセッションリークを検知した場合にアサーションエラーとして即座に失敗させる。

```python
import os
import sys
import pytest

# Ensure backend root is on sys.path
sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), "..")))

from app.database import engine

@pytest.fixture(autouse=True)
def verify_db_pool_clean():
    """Ensure no SQLAlchemy connection leak exists after each test."""
    yield
    assert engine.pool.checkedout() == 0, (
        f"DB session/connection leak detected! Checked out connections: {engine.pool.checkedout()}"
    )
```

### 3-2. Vitest テスト環境隔離強化 (`frontend/vite.config.ts`)
テストスイート間のモック汚染や状態リークを防止するため、Vitest の分離・自動リストア設定を有効化する。
```typescript
test: {
  globals: true,
  environment: 'jsdom',
  setupFiles: './src/test/setup.ts',
  isolate: true,        // テストファイルごとの完全プロセス/環境分離
  restoreMocks: true,   // vi.spyOn をテストごとに自動リストア
  clearMocks: true,     // モックの呼び出し履歴を自動クリア
  mockReset: true,      // モックの実装を自動リセット
}
```

#### `frontend/src/test/setup.ts`
```typescript
import '@testing-library/jest-dom';
import { server } from './mocks/server';

beforeAll(() => {
  server.listen({ onUnhandledRequest: 'bypass' });
});

afterEach(() => {
  server.resetHandlers();
});

afterAll(() => {
  server.close();
});
```
※ `onUnhandledRequest: 'bypass'` を指定することで、既存の個別モックやテストに影響を与えず段階的にMSWへ移行可能とする。

## 4. トレードオフ・リスク開示 (Trade-offs & Constraints)

1. **Vitest `isolate: true` による実行時間増加**:
   - 各テストファイルを完全分離環境で実行するため、CPU/メモリ消費および実行時間（約20〜30%増）のトレードオフがある。
   - ただし、テスト間の状態汚染やグローバル変数リークに起因するデバッグコスト削減効果が大幅に上回る。
2. **MSW v2 と既存のベタモック（`vi.mock('../../api/client')`）の共存**:
   - 一度に既存テストのモックをすべて MSW に差し替えるとスコープ肥大化とデグレリスクが高まるため、`onUnhandledRequest: 'bypass'` を適用し、REQ-235/REQ-236 から順次 MSW ハンドラを活用する設計とする。
3. **`pytest-randomly` による予期せぬ既存テスト失敗**:
   - 既存テストの中に暗黙の順序依存がある場合、ランダム化によって露見する可能性がある。万一発生した場合は、conftestのDBリセットまたはフィクスチャのクリーンアップにより決定性を確保する。
