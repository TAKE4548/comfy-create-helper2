# REQ-061: バッチ生成ジョブの一括キュー登録による制御向上 設計書

## 1. システム構成・データモデル変更

### 1.1 Zustand Store 状態追加 (`useGenerationStore.ts`)
一括キュー登録されたバッチ生成処理の状態管理のため、`BatchJob` 型および `activeBatch` 状態を導入します。

```typescript
export interface BatchJob {
  promptId: string;
  setName: string;
  status: 'pending' | 'generating' | 'completed' | 'failed';
}

// GenerationState 内の追加フィールド
export interface GenerationState {
  // ...既存
  activeBatch: BatchJob[] | null;
  setActiveBatch: (batch: BatchJob[] | null) => void;
  updateBatchJobStatus: (promptId: string, status: BatchJob['status']) => void;
}
```

### 1.2 進捗インジケーター（UI）での進捗計算式
`activeBatch` が存在する場合、全体進捗 `percentage` は以下のように計算します。

$$ \text{completedCount} = \text{activeBatch.filter(j => j.status == 'completed' || j.status == 'failed').length} $$
$$ \text{currentVal} = \text{isGeneratingHere && progress ? (progress.value / progress.max) : 0} $$
$$ \text{percentage} = \text{Math.min}(100, \text{Math.round}\left(\frac{\text{completedCount} + \text{currentVal}}{N} \times 100\right)) $$

ここで $N$ は `activeBatch` 内の総ジョブ数です。

## 2. コントロールフローとイベントフロー

### 2.1 一括キュー登録シーケンス
1. ユーザーが「Generate Batch」をクリックします。
2. `handleGenerateSets` が呼び出され、選択（`checked`）されたすべてのセットのバッチ回数（`batchSize`）の総和分ループを回し、即座に `queuePrompt(wfJson)` を連続呼び出しします。
3. 取得した `promptId` 群を用いて `BatchJob[]` を構築し、`setActiveBatch(jobs)` で Zustand ストアに保存します。
4. UIは各入力エリアのロックを行いません（AC-5）。

### 2.2 WebSocketイベントによる状態更新
WebSocket からイベントを受信した際、以下の状態更新を行います：
- `execution_start` / `progress` / `executed` / `execution_complete` / `execution_error` イベント発生時、該当する `promptId` に一致する `BatchJob` の `status` を更新。
- 該当バッチ内のすべてのジョブの `status` が `completed` または `failed` に達したとき、`isGenerating = false`, `activeBatch = null`, `currentPromptId = null` にリセットします。

### 2.3 キャンセル・キュークリア検知（AC-4）
`fetchQueue` の応答（`queueRunning`, `queuePending`）を取得した際、`activeBatch` のうち `pending` または `generating` 状態のジョブが ComfyUI キュー内に全く存在しないかを判定します。
存在しない場合、ComfyUI 側でキューのクリア、またはジョブのキャンセルが行われたと判断し、進行中の生成セッション状態をキャンセルとしてリセットします。
