# REQ-310 詳細設計書: 設定画面における FuguMT（CPU軽量翻訳）プロバイダ統合

## 1. 概要と背景 (Overview & Background)

### 1-1. 課題認識
REQ-304 にて、完全CPU常駐・超低遅延（20〜30ms）・VRAM消費ゼロ（0MB）の `staka/fugumt-en-ja`（CTranslate2 int8形式）翻訳エンジン（`FuguMTService`）およびタグチップ和訳プレビュー（`TagChipTranslationCard`）が導入されました。

しかし、設定画面（`TranslationSettingsSection.tsx`）の翻訳プロバイダー選択肢は従来の `google_cloud` / `deepl` / `llm` の3択のままであり、UI 上から FuguMT を選択・保存する導線が欠如していました。
この結果、過去に設定画面で `llm` を保存していた環境では、SQLite DB（`llm_prompts` テーブル）に `translation_provider = 'llm'` が永続化されており、プロンプト翻訳実行時に常に LM Studio 経由のローカル LLM が呼び出され、以下の重大な問題が発生していました：
1. **深刻な応答遅延**: 単語1件の和訳でもローカルLLMのロード・推論に 30〜40 秒の待機時間が発生。
2. **外部依存・起動エラー**: LM Studio が未起動の場合やモデル未ロード時に `400 Bad Request` / `500 Internal Server Error` で翻訳が停止。
3. **GPU VRAM競合**: 画像生成（ComfyUI / Anima 等）と GPU リソースを取り合い、生成中のスワップやクラッシュの原因となる。

### 1-2. 改修のゴール
設定画面に **「FuguMT（CPU軽量和訳）」** を第4の選択肢（推奨）として追加し、UI からワンクリックで選択・保存・接続テストできるようにします。
これにより、ユーザーは GPU VRAM 競合と長時間の遅延から解放され、完全オフライン・超高速（20〜30ms）な和訳環境を利用可能となります。また、必要に応じて従来の LLM 翻訳や外部 API（Google Cloud / DeepL）へ切り替えられる柔軟性を維持します。

## 3. アーキテクチャおよび詳細設計

### 3-1. プロバイダー仕様比較と位置づけ

| プロバイダ | 実行環境 | レイテンシ | VRAM消費 | APIキー | 主なユースケース |
|---|---|---|---|---|---|
| **FuguMT (推奨)** | **CPU常駐 (6スレッド)** | **20〜30ms** | **0 MB** | **不要** | **自然文タグ・プロンプトの即時和訳（英⇒日）。完全オフライン・高速。** |
| **Local LLM** | GPU (LM Studio) | 5〜40秒 | VRAM使用 | 不要 | Danbooruタグ構文展開、高度な意訳・文脈補完 |
| **Google Cloud** | クラウド API | 150〜300ms | 0 MB | 必要 | GCP Translation API v2 による汎用和訳 |
| **DeepL** | クラウド API | 200〜400ms | 0 MB | 必要 | DeepL REST API による高精度自然言語翻訳 |

### 3-2. データフロー

```

      │

[PUT /api/llm-prompts/translation_provider]  (※apiKey / apiUrl は送信しない)
      │
      ▼ (2) SQLite DB (llm_prompts) に translation_provider = 'fugumt' を永続化
```

#### B. 入力フォームの表示制御
- `provider === 'fugumt'`:
  - API キー入力欄: **非表示**
  - API URL 入力欄: **非表示**
  - ガイドバナー: 「完全オフライン・CPU常駐推論のため、APIキーや外部URLの設定は不要です。」を表示。
- `provider === 'google_cloud' || provider === 'deepl'`:
  - 従来の API キーおよびエンドポイント入力欄を表示。
- `provider === 'llm'`:
  - API キー入力欄は非表示（LLM 設定セクションのモデル・URL を利用）。

#### C. 保存処理ロジック (`saveSettingsMutation`)
AC-2 に準拠し、FuguMT 選択時は `translation_provider` のみを保存し、不要な apiKey / apiUrl を送信しない。
```typescript
const saveSettingsMutation = useMutation({
  mutationFn: async () => {
    if (provider === 'fugumt') {
      await llmPromptsApi.update('translation_provider', { content: provider })
    } else {
      await Promise.all([
        llmPromptsApi.update('translation_provider', { content: provider }),
        llmPromptsApi.update('translation_api_key', { content: apiKey }),
        llmPromptsApi.update('translation_api_url', { content: apiUrl }),
      ])
    }
  },
  onSuccess: () => {
    qc.invalidateQueries({ queryKey: ['llm-prompts'] })
    setSaved(true)
    setTimeout(() => setSaved(false), 2000)
  },
})
```

#### D. 接続テスト処理 (`handleTestConnection`)
AC-3 に準拠し、FuguMT 選択時は `{ provider: 'fugumt' }` のみをペイロードとして送信。
```typescript
const handleTestConnection = async () => {
  setIsTesting(true)
  setTestResult(null)
  try {
    const res = await translateApi.testConnection({
      provider,
      api_key: (provider === 'google_cloud' || provider === 'deepl') ? (apiKey || undefined) : undefined,
      api_url: (provider === 'google_cloud' || provider === 'deepl') ? (apiUrl || undefined) : undefined,
    })
    setTestResult(res)
  } catch (err: any) {
    setTestResult({
      success: false,
      sample_translation: '',
      error: err.message || '接続テストに失敗しました',
    })
  } finally {
    setIsTesting(false)
  }
}
```

## 4. バックエンド連携仕様および初回自動ダウンロード設計

### 4-1. 初回自動ダウンロード・配置アーキテクチャ (`FuguMTService`)
ユーザーによるモデルファイルの手動配置作業を不要とし、完全なゼロコンフィグ（設定不要）体験を実現するため、初使用時に Hugging Face から CTranslate2 最適化モデルを自動取得・配置する。

```
[FuguMTService.initialize()]
       │
       ▼ model_dir ("models/fugumt-en-ja") が存在するか？
   ┌───┴───────────────────────────────────────┐
   │ [存在する]                                │ [存在しない]
   │                                           ▼
   │                                   auto_download == True か？
   │                                   ┌───────┴───────────────────────┐
   │                                   │ True                          │ False
   │                                   ▼                               ▼
   │                           [huggingface_hub.snapshot_download]     警告ログ出力 & return False
   │                           repo: jkawamoto/fugumt-en-ja-ct2
   │                           local_dir: models/fugumt-en-ja
   │                           (CTranslate2 int8 最適化済み, 約125MB)
   │                                   │
   ▼ [ロード処理] ◄────────────────────┘
[ctranslate2.Translator & AutoTokenizer.from_pretrained]
       │
       ▼
[_is_initialized = True] ──► 20〜30ms で即時推論可能
```

1. **取得元モデル仕様**: `jkawamoto/fugumt-en-ja-ct2`
   - CTranslate2 int8 量子化済みバイナリおよび MarianTokenizer 設定・語彙ファイル一式（計 11 ファイル、合計約 125MB）。
   - PyTorch 重みのダウンロードやローカル量子化変換が不要であり、ネットワーク負荷・ディスク消費を最小限（わずか数秒でダウンロード完了）に抑制。
2. **例外安全とフォールバック**:
   - オフライン時やネットワーク障害によりダウンロードが失敗した場合は例外をキャッチして `self._is_initialized = False; return False` とし、FastAPI サーバー自体の起動・稼働を阻害しない。
   - `test_connection` は安全に `TranslateTestResponse(success=False, error="FuguMT engine is not available")` を返却し、UI に明瞭なエラーメッセージを伝達。
3. **エンドポイント・設定連携**:
   - `POST /api/translate/test`（接続テスト）実行時に `initialize()` がトリガーされるため、ユーザーが設定画面で「疎通テスト」を押すだけで自動取得からテスト翻訳までが一貫して完了する。
   - DB の `translation_provider` が `"fugumt"` の場合、Generate 画面での和訳リクエストも自動的に本サービス経由で直接実行され、ローカル LLM 通信や VRAM ロードは一切発生しない（AC-4）。

## 5. 非機能要件・安全性・リソース設計

1. **VRAM 競合ゼロ (0MB)**:
   - FuguMT は純粋な CPU スレッド（`intra_threads=6`）で推論を行い、GPU VRAM を一切占有しない。ComfyUI での画像生成中も完全に独立して並行動作可能。
2. **高速応答 (< 100ms)**:
   - CTranslate2 の int8 量子化エンジンと SHA256 インメモリキャッシュにより、20〜30ms（初回でも 50ms 前後）の超低レイテンシで和訳を返却。AC-4 の 100ms 要件を余裕をもってクリア。
3. **完全オフライン動作**:
   - モデルは `models/fugumt-en-ja` ディレクトリにローカル保存されており、インターネット接続が途絶したオフライン環境でも正常動作。

### 7-1. 監査所見と設計反映
1. **データマイグレーションとレガシー値フォールバック**:
   - **所見**: DB 内に未知の文字列やレガシー値（`'google_free'` 等）が存在する場合の挙動の明確化。
   - **対応**: `TranslationSettingsSection.tsx` の初期化 `useEffect` において、`'google_free'` は `'google_cloud'` へ自動正規化し、未知の値や空値の場合は安全にフォールバックするロジックを担保。
2. **API コールのスキップ明確化**:
   - **所見**: 「送信しない」と「スキップする」の混同防止。
   - **対応**: `saveSettingsMutation` において、`provider === 'fugumt'` 時は `llmPromptsApi.update('translation_provider', { content: 'fugumt' })` のみを発行し、`translation_api_key` および `translation_api_url` に対する HTTP リクエスト自体を完全にスキップ（発行しない）することを明記。既存の API キーは DB 上に温存され、空文字での破壊的上書きを防止。
3. **型安全性の強化**:
   - **所見**: プロバイダー型の統一。
   - **対応**: `frontend/src/api/types.ts` において `TranslateTestRequest.provider` を `'google_cloud' | 'deepl' | 'llm' | 'fugumt'` として厳格化し、コンポーネント側の state 型と完全に一致させる。
4. **UI 判断ガイドの明瞭化**:
   - **所見**: FuguMT と Local LLM の使い分けの明示。
   - **対応**: FuguMT ラジオカードに「推奨 (CPU)」バッジと「VRAM 0MB・APIキー不要・20〜30ms」の説明を記載し、LLM 側には「LM Studio 経由・タグ展開・高度翻訳」と明記することで、ユーザーが用途に応じて迷わず選択できる導線を提供。
