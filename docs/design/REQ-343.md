# REQ-343 詳細設計書: ワークフローマッピング画面のRole×ステージ多段階対応および未設定選択のUI/データ整合

## 1. 概要とアーキテクチャ背景 (Architecture Context)

### 1.1 背景と課題
REQ-336にて、マッピングマスタ構造が「Role×Stage」の2軸モデル（MappingMaster と MappingVariant）に正規化された。
しかし、ワークフロー取り込み（UploadWorkflowModal）、再スキャン（RescanModal）、および配線設定画面（WorkflowConnectionSection）において以下の課題が存在していた：
1. **マッピング単位の乖離**: 画面側が従来の親マスタ単一選択（useMasterMappingRows）に依存しており、ワークフロー内で検出された複数ステージ（例: Main, Rough, Detail）に対してステージ別のノード選択スロットが展開されない。
2. **オプトアウト操作の欠落**: 多段階ワークフローにおいて、特定Roleとステージの組み合わせが不要な場合（例: Detailステージではプロンプトノードが存在しない等）、安全に「未設定」を選択・解除して保存するUXが不十分。
3. **データ永続化とバリデーションの不整合**: WorkflowConnectionSection.tsx の validateConfig で同一 master_id の重複がエラーとして遮断され、また variant_id が保存・インポート/エクスポート時に欠落してDBに永続化されない。
4. **バックエンド /api/workflows/scan の旧実装**: 既存の scan_workflow_variants を利用せず旧 scan_workflow が呼び出されており、ステージ別の variant_id や stage_key がスキャン結果に含まれていない。

### 1.2 解決方針
1. **バックエンドのスキャン・永続化改修**:
   - /api/workflows/scan で scan_workflow_variants を呼び出し、ステージ別・バリアント別のマッチング結果（variant_id, stage_id, stage_key）を返却。
   - WorkflowMappingCreate / WorkflowMappingRead スキーマに variant_id: Optional[int] を追加。
   - ワークフロー作成・更新・複製・ロールバック時に WorkflowMapping.variant_id をDBに正確に永続化。
2. **配線画面・設定保存パイプラインの整合**:
   - WorkflowConnectionSection.tsx の validateConfig で、同一 master_id であっても異なる variant_id を持つマッピングの共存を許容。
   - 設定JSONエクスポート/インポートおよび handleSaveLinks で variant_id を保持。
3. **フック useMasterMappingRows の多段階・オプトアウト拡張**:
   - ワークフロー内の有効ステージまたはスキャン結果の variant_id に応じて、Roleごとにステージ別スロット（Main, Rough等）を動的に展開。
   - スロットごとに「未設定」選択肢、推奨ノード（★バッジ）、候補一覧、およびワンクリック解除（クリア）ボタンを提供。
   - getMappings() で未設定（空文字）のスロットを除外して返却。
4. **UIモーダル（Upload & Rescan）のRole×Stageマルチスロット化**:
   - UploadWorkflowModal および RescanModal において、Role単位の親カード内に有効ステージスロットを整然と配置。
   - 不要な組み合わせをワンクリックで未設定化でき、エラーなく登録・更新可能とする。

## 3. 詳細モジュール設計

### 3.1 Backend: スキーマ・API・モデル永続化
- **backend/app/schemas/workflow.py**:
  ScanMatchedItem および ScanWarningItem に variant_id, stage_id, stage_key を追加。
  WorkflowMappingCreate および WorkflowMappingRead に variant_id: Optional[int] を追加。
- **backend/app/routers/workflows.py**:
  - scan_workflow_json: MappingVariant が存在する場合 scan_workflow_variants(payload.json_body, variants) を実行し、存在しない場合はフォールバックとして scan_workflow を実行。
  - create_workflow / update_workflow / copy_workflow / rollback_workflow: variant_id を受け取り models.WorkflowMapping(variant_id=m.variant_id, ...) として永続化・復元。
  - get_workflow: schemas.WorkflowMappingRead 生成時に variant_id=m.variant_id およびバリアント由来の computed_role を正確に設定。

### 3.2 Frontend: 型定義 & Settings 配線パイプライン
- **frontend/src/api/types.ts**:
  WorkflowMapping, WorkflowCreate, WorkflowUpdate, ScanMatchedItem, ScanWarningItem に variant_id を反映。
- **frontend/src/pages/SettingsPage/components/WorkflowConnectionSection.tsx**:
  - validateConfig: 重複チェックを uniqueKey = m.variant_id ? ${m.master_id}_ : ${m.master_id} に変更し、同一 master_id の複数バリアントを許容。
  - handleSaveLinks / setConfigMappings: variant_id を欠落させずに保持。
  - エクスポート/インポートJSONで variant_id を維持。

### 3.3 Frontend: フック useMasterMappingRows.ts
- 各Role（MappingMaster）に対して、ワークフロー内で検出されたアクティブステージまたはバリアントに応じたスロットを展開。
- スロットキー: variant_id ? _ : m_
- アクション: updateSlotNodeId, clearSlot, getMappings（未設定除外）。

### 3.4 Frontend: モーダルUI (UploadWorkflowModal & RescanModal)
- Roleカード内に各有効ステージのスロット（ドロップダウン＋クリアボタン）を展開。
- 先頭に「未設定」選択肢を配置。
- 不要な組み合わせを未設定にしたまま、安全に保存可能。

## 4. Acceptance Criteria (AC) トレーサビリティ

| AC ID | 要件概要 | 設計上の対応箇所 | 検証方法 |
|---|---|---|---|
| **AC-1** | Role×有効ステージの複数ノードマッピング | useMasterMappingRows.ts, UploadWorkflowModal.tsx, RescanModal.tsx | Main/Roughを含むWFで同一Roleに別々のノードを選択・割当できることを単体/結合テストで検証 |
