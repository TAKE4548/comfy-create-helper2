# 機械的検証用テスト計画書 - REQ-028 (最終修正版)

本テスト計画書は、AIエージェントおよび自動テストスクリプトが曖昧さを排除して機械的に検証（アサーション）を実行するための論理仕様および実装依存項を定義します。

## 1. 検証対象および観測可能な指標の定義

### 1.1 シード値の抽出定義 (`ExtractSeed`)
ComfyUI への `POST /prompt` リクエストの JSON ボディ内から、以下の手順でシード値を抽出します。
1. JSON ボディの各ノードオブジェクト（キーはノードID）を走査する。
2. `inputs` オブジェクト内に `seed` キーが存在するノードを見つける。
3. その `seed` の値（数値型）を抽出結果とする。

### 1.2 生成進行状態の観測定義 (`isGenerating`)
UI 外部からテストスクリプトが「生成進行中」を判定する指標として、以下を定義します。
- 生成ボタン（ID: `generate-btn` または `generate-btn-mobile`）のラベル内に、ローディングスピナー（クラス `animate-spin` を持つ要素）が存在する、または進捗表示テキスト（「Processing...」など）が表示されている状態。
- または、UI上の進捗プログレスバー要素（例: `.w-full.bg-gray-200` 等の進捗インジケーター）が表示されている状態。

---

## 2. 検証論理ロジックの定義

### ロジック A: バッチ送信数とシードの一意性（ランダムモード）
*   **入力**: 送信された `POST /prompt` リクエストのボディ配列 `requests`
*   **合格判定基準**: 
    - `len(requests) == 3`
    - `ExtractSeed(requests[0])`, `ExtractSeed(requests[1])`, `ExtractSeed(requests[2])` の3つの値がすべて互いに異なること（一意であること）。

### ロジック B: シードの連続性（固定値モード）
*   **入力**: 指定した初期シード $S_{\text{start}} = 1000$ で送信された `POST /prompt` リクエストのボディ配列 `requests`
*   **合格判定基準**:
    - `len(requests) == 3`
    - `ExtractSeed(requests[0]) == 1000`
    - `ExtractSeed(requests[1]) == 1001`
    - `ExtractSeed(requests[2]) == 1002`

### ロジック C: ボタン活性状態および表記の検証（生成中）
*   **入力**: 生成画面の「Generate Batch」ボタン要素の DOM オブジェクト `button_element`
*   **合格判定基準**:
    - `button_element.disabled` プロパティが `false` であること。
    - `button_element.textContent` に `"Generate Batch (キュー追加)"` という文字列が含まれていること（部分一致または完全一致）。

---

## 3. 実行ステップ

### ステップ 1: ランダムモード検証
1. 画面上の `Seed Mode` ドロップダウンで `random` を選択。
2. `Batch Size` 入力欄（ID: `batch-size-input` 等）に `3` を入力。
3. 生成ボタン（ID: `generate-btn` または `generate-btn-mobile`）をクリック。
4. **ログ記録**: `POST /prompt` への通信を監視し、送信された 3 つの JSON ボディを配列 `requests` に記録する。
5. **判定実行**: ロジック A の基準（リクエスト数が 3 回で、シード値が一意であること）をアサートする。

### ステップ 2: 固定値モード検証
1. `Seed Mode` を `fixed` に設定。
2. `Seed` 入力欄（ID: `seed-input` 等）に `1000` を入力。
3. `Batch Size` を `3` に設定。
4. 生成ボタンをクリック。
5. **ログ記録**: 送信された 3 つの `POST /prompt` リクエストの JSON ボディを記録する。
6. **判定実行**: ロジック B の基準（シード値が 1000, 1001, 1002 であること）をアサートする。

### ステップ 3: 生成中の活性チェックおよび追加キュー検証
1. `Batch Size` を `1` に設定し、生成ボタンをクリックして生成を開始。
2. UI上の進捗表示（「Processing...」またはローディングスピナーの表示）が出現し、生成進行状態になるまで待機。
3. **判定実行 (ロジック C)**:
   - 生成ボタン要素を取得し、`button_element.disabled` が `false` であることをアサート。
   - ボタン内のテキストが `"Generate Batch (キュー追加)"` を含むことをアサート。
4. その状態で生成ボタンを再度クリックし、追加の `POST /prompt` リクエストが即座に送信されることをアサート。
