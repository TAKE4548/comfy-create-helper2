# REQ-182: 生成中断処理（Abort / すべて中断）のレスポンス改善および実行中ジョブの確実な停止 詳細設計書

## 1. 概要と背景
生成処理の中断（個別キャンセル / すべて中断）において、以下の2つの問題が発生していました。
1. **「すべて中断」時に実行中の生成が停止しない**: ComfyUI の空ボディ 200 レスポンスに対して `client.ts` の `request()` が `res.json()` を実行して構文エラー（`SyntaxError`）をスローし、`cancelAllJobs()` 内の後続 `comfyApi.interrupt()` が呼び出されずに中断処理が失敗していた。
2. **Abort レスポンスの遅延・ステート更新**: `queuePrompt` 完了時に `options.signal.aborted` のガードがないため、中断後にもかかわらず `isGenerating: true` がセットされてしまっていた。
3. **バッチ投入の競合（すり抜け投入）**: `cancelAllJobs()` が送信中の `queuePrompt` 完了を待機せずに `deleteQueue` を呼んでいたため、待機キュー削除後にジョブが遅れて ComfyUI に登録されてしまっていた。

---

## 2. アーキテクチャ変更詳細

### 2.1 API クライアント層 (`frontend/src/api/client.ts`)
- `request()` 関数でレスポンス本文のパースを安全化:
  - ステータス 204 またはレスポンス本文が空（`""` / 空白）の場合、`res.json()` を呼ばずに `undefined` を返却。
  - テキストが存在する場合のみ `JSON.parse` を試行し、失敗時は生テキストを返却。

### 2.2 ストア層 (`frontend/src/store/useGenerationStore.ts`)
- **`activeSubmissionPromise` による通信追跡**:
  - `queuePrompt` 実行中の Promise を保持し、中断時に `await activeSubmissionPromise` で完了を待機可能にする。
- **`queuePrompt` の Abort ガード**:
  - 呼び出し前および完了後に `options?.signal?.aborted` をチェックし、中断時は `isGenerating: true` や localStorage 保存をスキップして即座に `null` 返却。
- **`cancelAllJobs()` の堅牢化**:
  1. `get().abortSubmission()` で後続ループを遮断。
  2. `if (activeSubmissionPromise) await activeSubmissionPromise` で通信中ジョブの着弾を待機。
  3. `await comfyApi.deleteQueue({ clear: true })` で待機キューを全削除。
  4. `await comfyApi.interrupt()` で実行中ジョブを確実に停止。
  5. 待機中だったジョブの履歴削除およびフロントエンドステートの完全リセット。

---

## 3. SSoT 影響分析
- `frontend/src/api/client.ts`: `request()` 関数のパースロジック改善
- `frontend/src/store/useGenerationStore.ts`: `queuePrompt`, `cancelAllJobs`, `cancelJob`, `clearPendingQueue` の改修
