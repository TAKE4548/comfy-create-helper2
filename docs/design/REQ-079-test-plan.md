## 2. 手動検証 (Manual Verification) - 厳密化版

### ケース 1: モバイル表示時の UI レイアウトと切り替え機能
*   **環境設定**: ブラウザのデベロッパーツールでビューポート幅を `375px` に固定する。
*   **手順**:
    1.  Generate View を開く。
    2.  プレビュー画像下部に「タブバー」要素が存在することを確認する。
    3.  タブバー内の各項目（プロファイル名）を順次タップする。
*   **判定基準 (Pass/Fail)**:
    *   [ ] 各タップ後、パラメータ入力欄の値が変更される。
    *   [ ] 変更された値は、選択したタブに対応するデフォルト設定と一致する。

### ケース 2: タブ追加時のコピー作成（ダイアログ）
*   **手順**:
    1.  「+ Add Set」ボタンをタップし、「新規プロファイル作成」ダイアログを表示させる。
    2.  コピー元として「既存のプロファイル A」を選択する。
    3.  ダイアログ内のパラメータフィールド（CFG Scale など）の値を確認する。
*   **判定基準**:
    *   [ ] 選択したプロファイルのパラメータ値が、ダイアログ内の入力欄に正確に反映されている。
    *   [ ] 「作成」ボタンを押下後、新しいタブが追加され、その中身がコピー元と同一である。

### ケース 3: サーバー永続化による状態同期検証
*   **手順**:
    1.  ブラウザ A でプロファイルのパラメータ（例: CFG Scale）を変更する。
    2.  ブラウザ A のネットワークタブで、該当パラメータの更新リクエストが完了し **HTTP 2xx レスポンス** が返却されるまで待機する（固定時間ではなくレスポンス確認）。
    3.  ブラウザを閉じ、シークレットウィンドウ（または別のブラウザ）を開く。
    4.  同じワークフローの Generate View を開き、そのプロファイルにアクセスする。
*   **判定基準**:
    *   [ ] UI 上に表示されるパラメータの値が変更後の値と一致していること。
    *   [ ] API エンドポイント `/api/workflow-presets` を直接叩いた際、レスポンスの該当プロファイルの値が更新されていること。

### ケース 4: バッチ生成ロジックと UI 状態連動検証
*   **手順**:
    1.  プロファイルリスト内のプロファイル A, B, C のチェックボックスを操作し、A と C のみが選択されている状態にする。
    2.  「Generate Batch」ボタンをタップする。
*   **判定基準**:
    *   [ ] バッチジョブキューが追加され、生成対象のプロファイルが A と C のみであること。
