# PBI-REQ-055 実行可能テスト計画 (QA Audit Compliance)

## 1. 環境設定
- **ブラウザ**: Chrome (最新版) または Edge
- **ターゲット URL**: `http://localhost:5173`
- **モック / 依存バックエンド**: ComfyUI ローカルサーバー（または WebSocket モック）が起動していること

## 2. テストケース詳細

### TC-01: マルチセットの作成・複製・削除・切り替え (UI & 状態遷移検証)
**目的**: セットのCRUD操作とZustandストアの状態同期が正しく機能することを検証する。

| ステップ | アクション (Action) | 期待結果 (Expected Result - 数値/論理判定) |
| :--- | :--- | :--- |
| 1.1 | ページ遷移: `/generate` を開く | デフォルトで「Set 1」のセットチップが表示され、アクティブ状態（スタイル強調）になっていること。 |
| 1.2 | パラメータ編集: CFGやSteps、プロンプトを変更する | 変更された値がローカルストレージおよびストア上の「Set 1」のデータに反映されていること。 |
| 1.3 | セット追加: 「+ 新規セット」ボタンをクリックする | 「Set 2」が作成され、アクティブに切り替わること。初期値の `paramValues` は `Set 1` とオブジェクト内容が完全一致し、かつ参照アドレスが異なる（深部コピーされている）こと。 |
| 1.4 | セット切り替え: 「Set 1」チップをクリックする | アクティブが「Set 1」になり、フォーム内の value が手順1.2の変更後パラメータと 50ms 以内に完全に一致すること（切り替え遅延の許容誤差 50ms）。 |
| 1.5 | セット名変更: 「Set 2」チップのテキストをダブルクリックし、"Custom Prompt" と入力してEnter | チップ表示名が "Custom Prompt" に更新されていること。 |
| 1.6 | セット削除: "Custom Prompt" の「削除 (X)」ボタンをクリックする | セットが削除され、チップ数が1に戻ること。アクティブセットが「Set 1」にフォールバックすること。 |

### TC-02: 一括選択およびバッチ数設定 (一括生成対象の設定検証)
**目的**: 各セット個別のバッチ数設定と全選択/全解除ボタンによる影響範囲の論理的検証。

| ステップ | アクション (Action) | 期待結果 (Expected Result - 数値/論理判定) |
| :--- | :--- | :--- |
| 2.1 | セットを合計3つ作成する（Set 1, Set 2, Set 3） | チップが3つ並ぶこと。 |
| 2.2 | 全解除操作: 「全解除 (Clear All)」をクリック | 全セットのチェックボックスが外れる（`checked = false`）こと。一括生成ボタンが非活性（`disabled === true`）になること。 |
| 2.3 | 全選択操作: 「全選択 (Select All)」をクリック | 全セットのチェックボックスがオンになる（`checked = true`）こと。一括生成ボタンが活性化（`disabled === false`）すること。 |
| 2.4 | 個別設定: 「Set 1」のバッチ数入力フィールドに `2` を入力しEnter、「Set 2」に `1`、「Set 3」に `3` を入力する | ストア上の各セットオブジェクト内の `batchSize` プロパティの型と値がそれぞれ `2` (整数), `1` (整数), `3` (整数) と完全一致すること (`typeof s.batchSize === 'number'`)。 |

### TC-03: 一括生成シーケンシャル処理とエラーハンドリング (統合生成検証)
**目的**: 選択した複数セットのシーケンシャル生成実行、画像との紐づけ、およびエラー発生時の継続処理を検証する。

| ステップ | アクション (Action) | 期待結果 (Expected Result - 数値/論理判定) |
| :--- | :--- | :--- |
| 3.1 | **エラー注入モック設定**: Mock WebSocket / API Server のレスポンスを制御し、セット2の `promptId` に関連する生成リクエストに対して `execution_error` メッセージを送信するように仕込む。 | モック設定が完了していること。 |
| 3.2 | セット1とセット2を選択し、「Generate Selected」を実行 | セット1（バッチ数2）のリクエストが順次投入されること。 |
| 3.3 | 生成中のWebSocketメッセージを監視 | 1. セット1 の2枚の画像生成が完了。<br>2. セット2 の生成要求が投入される。<br>3. セット2 の `execution_error` イベントを受信。<br>4. **判定**: セット2の失敗検知から 100ms 以内に、全体の生成ループが停止せず、次のセットの処理へ自動遷移または全体終了フェーズへ正常移行すること。 |
| 3.4 | 生成履歴サムネイルの検証 | サムネイルストリップ内の各画像の上に、生成元セット名（`Set 1` など）のバッジが正しく表示されること。 |

## 3. 失敗条件 (Failure Criteria)
以下のいずれかが満たされた場合、テストは **FAIL** と判定されます。
1. セットの作成や削除時に、UIコンポーネントが描画エラーでクラッシュ、またはアンマウントされる。
2. アクティブセット切り替え時の値 of 同期が 50ms 以上遅延する、または値が壊れる。
3. 一括生成時、エラーレスポンス受信後に全体ループがハングアップし、以降のキューイング処理が行われない。
4. サムネイルバッジのセット名が、実際の生成元のセット名と食い違う。
