# REQ-287 詳細設計書: TagSetModals & LoraModals の 1 コンポーネント 1 ファイル化と共通セレクター抽出

## 1. 概要と背景課題

フロントエンド肥大化解消計画（PBI-REF-06）の一環として、肥大化した2つの主要モーダルコンポーネント（`TagSetModals.tsx` 約844行、`LoraModals.tsx` 約696行）を、保守性と責務分離を高めるために「1コンポーネント1ファイル」のディレクトリ構造へ分割・再編成する。
また、両モーダルで重複して実装されているカテゴリ選択ロジック（`InlineCategorySelect`）およびベースモデル選択ロジック（チェックボックス群）を、`frontend/src/components/common/` 下の汎用セレクターコンポーネントとして抽出・共通化する。

### 現状の構造的課題
1. **巨大単一ファイル混載 (Monolithic Files)**:
   - `TagSetModals.tsx`: `TagSetFormFields`, `TagSetCreateModal`, `TagSetEditModal`, `TagSetDetailModal` が同居。
   - `LoraModals.tsx`: `LoraFormFields`, `LoraRegisterModal`, `LoraDetailModal` が同居。
   それぞれ800行前後におよび、コードの可読性やピンポイントでの改修・テスト容易性を阻害している。
2. **セレクターロジックの重複**:
   - カテゴリ選択（新規カテゴリのインライン作成機能含む）は現在 `InlineCategorySelect.tsx` として存在するが、コンポーネントディレクトリ直下に散乱し、汎用共通部品としての配置ルール（`common/`）に従っていない。
   - ベースモデル選択（Target Base Models のチェックボックス一覧、TanStack Query による一覧取得、選択 ID 配列のハンドリング）が TagSet と LoRA でほぼ同等のコードとして複製されている。
3. **安全な移行と下位互換性 (Zero Breaking Changes)**:
   - 既存の呼び出し元（`TagsPage.tsx`, `LoRAsPage.tsx`）および既存のテスト群（`TagSetModals.test.tsx`, `LoraModals.test.tsx`）が直接 `components/TagSetModals` や `components/LoraModals` を参照しているため、Facade（Barrel 再エクスポート）を配置して一切の呼び出し互換性を崩さずにリファクタリングを完遂する必要がある。

## 3. コンポーネント詳細設計

### 3.1 共通セレクター部品 (`components/common/`)

#### 3.1.1 `CategorySelect.tsx`
- **責務**: カテゴリのプルダウン選択、およびインラインでの「+ 新規カテゴリを追加」操作（API呼出とキャッシュ/親通知）。
- **インターフェース定義**:
```typescript
import type { Category } from '../../api/types'

export interface CategorySelectProps {
  id?: string
  value: number | undefined
  onChange: (categoryId: number | undefined) => void
  categories: Category[]
  onCategoryCreated: (cat: Category) => void
  apiCreateFn: (name: string) => Promise<Category>
  accentClass?: 'accent-green' | '[#7C6FDD]' | string
}
```
- **カラーリング**:
  - `accentClass?.includes('[#7C6FDD]')` の場合: 紫系（TagSet用 `focus:border-[#7C6FDD]/40`, `text-[#7C6FDD]`）
  - それ以外（デフォルト）: 緑系（LoRA用 `focus:border-accent-green/40`, `text-accent-green`）
- **Facade 役割分担**:
  - `CategorySelect.tsx` が本体実装（SSoT）。`InlineCategorySelect.tsx` は既存コードとの互換性維持のためのエイリアス Facade（`export { CategorySelect as InlineCategorySelect }`）として位置づける。

#### 3.1.2 `BaseModelSelect.tsx`
- **責務**: ベースモデル（BaseModel）のチェックボックスグリッド表示と、複数選択 ID 配列（`number[]`）の更新。
- **インターフェース定義**:
```typescript
import type { BaseModel } from '../../api/types'

export interface BaseModelSelectProps {
  idPrefix?: string
  selectedIds?: number[]
  onChange: (ids: number[]) => void
  baseModels?: BaseModel[] // Props優先。未指定時に useQuery で baseModelsApi.list() からフォールバック取得
  accentClass?: 'accent-[#7C6FDD]' | 'accent-accent-green' | string
  label?: string           // デフォルト: 'Target Base Models'
}
```
- **ロジック仕様とデータ優先順位**:
  - **優先順位**: `Props.baseModels`（親から明示的に渡された配列・モック） > 内部 `useQuery` フェッチ結果。
  - 各チェックボックスのトグル時に `onChange` をトリガー（追加時は `[...selectedIds, bm.id]`、解除時は `filter(id => id !== bm.id)`）。
  - 全解除時は空配列 `[]` を正確に保持。
  - 1件も存在しない（空配列または未取得）場合は `No base models configured.` を表示。

### 3.2 TagSetModals 分割設計 (`components/TagSetModals/`)

1. **`types.ts`**:
   - `TagSetFormState` の定義（`name`, `description`, `category_id`, `tags`, `thumbnail_path`, `subsets`, `target_base_model_ids`）。

3. **`TagSetCreateModal.tsx`**:
   - `TagSetFormFields` をラップし、「New Tag Set」ダイアログおよび「Create Tag Set」ボタンを提供。
4. **`TagSetEditModal.tsx`**:
   - 既存タグセットの編集用ダイアログ。`snapshotPaths` からのサムネイル選択ギャラリー連携を含む。
5. **`TagSetDetailModal.tsx`**:
   - タグセットの詳細閲覧（`TagChipViewer`）、コピー、スナップショット一覧カルーセル、および `isEditing` トグルによる編集モード統合ビュー。
6. **`index.ts` & `TagSetModals.tsx`**:
   - すべてのコンポーネントと型定義を再エクスポート。

## 4. 下位互換性および既存ファイルへの影響分析

1. **`frontend/src/components/TagSetModals.tsx`**:
   - 既存内容を `export * from './TagSetModals/index'` に置換（`SpeechBubbleEditorModal.tsx` と同一の Facade パターン）。
2. **`frontend/src/components/LoraModals.tsx`**:
   - 既存内容を `export * from './LoraModals/index'` に置換。
3. **`frontend/src/components/InlineCategorySelect.tsx`**:
   - 既存内容を `export { CategorySelect as InlineCategorySelect } from './common/CategorySelect'` に置換。
4. **`frontend/src/pages/TagsPage.tsx` / `LoRAsPage.tsx`**:
   - Facade を経由するため既存の import パスを変更する必要はないが、新パス (`components/TagSetModals`, `components/LoraModals`) からの直接 import にも完全対応。
5. **既存テスト `TagSetModals.test.tsx` / `LoraModals.test.tsx`**:
   - 100% 互換性を保ち、変更なしで全件 PASS することを保証。
