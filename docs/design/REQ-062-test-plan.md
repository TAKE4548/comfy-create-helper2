# PBI-REQ-062 実行可能テスト計画

本ドキュメントは、REQ-062（LoRA・タグセット管理画面改修、並び順永続化、カテゴリ管理機能）の検証プロセスおよびテスト項目を定義します。

---

## 1. 自動テスト (CLI Verification)

バックエンド側のスキーマ、マイグレーション、および新規APIエンドポイントの振る舞いを検証するため、`backend/tests/test_req_062.py` を作成し、以下の項目を網羅した自動テストを実行します。

### テスト内容:
1. **初期マイグレーション検証**: 既存の `loras` などのテーブルに `sort_order` カラムが追加され、id順に連番が割り振られることをシミュレート。
2. **LoRA/TagSet並び替え (Reorder) API**:
   - 正しいID順序の配列を送信すると、DB上の `sort_order` が指定 of インデックス順に更新されること。
   - 存在しないIDが含まれる場合のバリデーション。
3. **カテゴリ更新 (Update) API**:
   - `PUT /api/lora-categories/{id}` および `PUT /api/tagset-categories/{id}` を呼び出し、カテゴリ名が正しく更新され、レスポンスが取得できること。
4. **ソート順検証**:
   - `GET /api/loras` の結果が `sort_order ASC, model_name ASC` でソートされて返ってくること。
   - `GET /api/tag-sets` の結果が `sort_order ASC, id ASC` でソートされて返ってくること。

### 実行コマンド:
```bash
cd backend
.venv\Scripts\python.exe -m pytest tests/test_req_062.py -v
```

## 3. ブラウザ検証 (Browser Agent Verification)

フロントエンドのUI変更および操作性の検証シナリオです。

### 3.1 LoRAsPage / TagsPage: 並び順の永続化
- **対象URL**: `http://localhost:5173/loras` および `http://localhost:5173/tags`
- **操作手順**:
  1. 検索フィルターが適用されていない状態で、任意のLoRA（またはタグセット）カードを選択する。
  2. カードをドラッグし、別のカードの前にドロップして順序を入れ替える。
  3. ページをリロード（F5）する。
  4. 検索ボックスにテキストを入力した際、カードのつまみ（またはドラッグハンドル）やD&D操作が無効化され、移動できない旨のインジケータ（カーソル変更等）が表示されることを確認する。
- **判定基準**:
  - リロード後もドラッグ&ドロップで変更した並び順が維持されていること。
  - バックエンドへの `PUT /api/loras/reorder` / `PUT /api/tag-sets/reorder` リクエストがステータス204で成功していること。

### 3.2 登録・編集モーダル: インラインカテゴリ追加
- **対象URL**: `http://localhost:5173/loras` の「LoRA登録」または任意の編集ボタン
- **操作手順**:
  1. モーダルを開き、カテゴリのプルダウンをクリックする。
  2. プルダウンの選択肢から「+ 新規カテゴリを追加」を選択する。
  3. インラインに表示されるテキスト入力欄に新しいカテゴリ名（例: `TestCategory1`）を入力し、「追加」ボタンを押下する。
- **判定基準**:
  - 新規カテゴリがDBに登録され、ドロップダウンの選択肢に追加されると同時に、その新規カテゴリが即座に選択状態になること。

### 3.3 カテゴリ管理モーダル: CRUD操作
- **対象URL**: `http://localhost:5173/loras` および `http://localhost:5173/tags` のフィルターバー付近
- **操作手順**:
  1. 「カテゴリ管理」ボタン（フォルダアイコンまたは設定アイコン）をクリックしてモーダルを表示する。
  2. 一覧から既存のカテゴリの「編集（鉛筆）」をクリックし、名称を変更して保存する。
  3. 新規作成フォームに名称を入力して登録する。
  4. 任意のカテゴリの「削除（ゴミ箱）」をクリックし、確認ダイアログで「OK」を押下する。
- **判定基準**:
  - 作成、編集した内容が即座に一覧に反映されること。
  - 削除したカテゴリが、LoRAやタグセットのカテゴリ選択肢から消え、紐付いていたアイテムのカテゴリが「未設定（None）」になること。

### 3.4 TagsPage: カードデザイン統一
- **対象URL**: `http://localhost:5173/tags`
- **判定基準**:
  - カードがLoRA管理と同様に、画像カルーセル/プレビュー付きの正方形のアスペクト比のデザインになっていること。
  - カテゴリごとの見出しセクションが廃止され、全カードがフラットなグリッドに並んでいること。
  - フィルターバーにカテゴリのトグルボタンが表示され、LoRAsPageと同様に絞り込みができること。
