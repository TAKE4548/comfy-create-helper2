# REQ-135: プリセット一括編集へのアセット（LoRA・タグセット等）適用機能の追加 設計書

## 1. 概要
プリセットの一括編集モーダル（`ProfileBulkEditModal`）において、単体編集時の `AddAssetModal` と同等のアセット選択画面を呼び出し、複数プリセットに対して LoRA やタグセット等のアセットを一括で「追記 (Append)」または「置換 (Replace)」適用できるようにする。

## 2. 影響範囲
- `frontend/src/components/ProfileBulkEditModal.tsx`:
  - `tagSets` プロパティの受け渡しと `AddAssetModal` の組み込み
  - 一括適用アセットキュー（`assetOps`）の状態管理とUI（追記/置換トグル、選択中アセットの表示）
- `frontend/src/pages/GeneratePage/hooks/useGeneratePageState.ts`:
  - `handleBulkEditApply` にて `payload.assetOps` の一括反映ロジック追加
  - 重複チェック（同一アセット・同一内容のスキップ、異サブセットの許容）およびプロンプト文字列への自動反映 (`addAssetToPrompt`)
- `frontend/src/pages/GeneratePage.tsx`:
  - `ProfileBulkEditModal` への `tagSets` の受け渡し

## 3. 詳細設計

### 3.1 `ProfileBulkEditModal` の拡張
```typescript
export interface AppliedAssetOp {
  mode: 'append' | 'replace';
  role: string;
  assets: AppliedAsset[];
}

export interface BulkEditPayload {
  promptOps?: PromptOp[];
  paramPatch?: Record<string, string>;
  batchSize?: number;
  loraOps?: LoraOp[];
  assetOps?: AppliedAssetOp[];
}
```

### 3.2 一括適用ロジック (`useGeneratePageState.ts`)
1. 各対象プリセットに対し、`assetOps` に含まれるアセット操作を順次処理。
2. モード判別:
   - `replace`: 指定ロールの既存アセット配列をクリアして置き換え。
   - `append`: 既存のアセット配列を維持。
3. 重複判定 (AC-4):
   - 既存アセットと同一 `type`, `assetId`, `name`, `loraPromptString`, `tags` を比較。
   - 完全一致する場合は重複としてスキップ。
   - サブセット違い等、異なる構成要素を持つ場合はユニークIDを採番して追加。
4. プロンプト文字列同期:
   - アセット適用後、指定ロールのプロンプト（`newParamValues[op.role]`）に対して `addAssetToPrompt` を用いてアセットのタグおよび LoRA 読み込みタグを反映。

## 4. トレードオフおよびリスク (Trade-off Disclosure)
- **プロンプト文字列の競合**: 既に手動編集されたプロンプトに対して一括置換を行う場合、プロンプトテキスト内の既存タグとの調整が必要になる。標準ユーティリティ `addAssetToPrompt` を使用することで一貫性を保持する。
- **パフォーマンス**: 多数のプリセット（数十件以上）に同時適用する場合、`Promise.all` による API 呼び出しが増加する。現状の更新メカニズムを踏襲し、処理中のレスポンス状態（`isApplying`）を管理する。
