# REQ-369 設計書: リマッピング時の孤立マッピング除外・未割当ステージ保持・DB孤立データ浄化

## 1. 概要と背景

V2 マッピングマスタ移行（`REQ-336`）後に削除された旧ステージ別 `mapping_masters`（ID `33〜62`）を参照したまま残存した `workflow_mappings` の孤立レコード（Orphaned Mappings）と、`REQ-358` の無効ステージ保持ループ（[`useMasterMappingRows.ts`](file:///c:/Users/audih/ws/comfy-create-helper2/frontend/src/hooks/useMasterMappingRows.ts#L482-L486)）および `initFromScan` の未割当スロット自動埋めの組み合わせにより、既存ワークフローを `RescanModal` でリマッピング・保存すると以下の 2 つの不具合が同時発生する（詳細は [`docs/incident_report.md`](file:///c:/Users/audih/ws/comfy-create-helper2/docs/incident_report.md) 参照）：

1. **削除済み旧マスタ（`master_id: 33〜62`）の孤立マッピング再送信**:
   `useMasterMappingRows.getMappings` が `knownKeys` に含まれない `storedMappings.current` を `allDefinitions`（現行有効・無効マスタ/バリアント定義）との照合なしに無条件でペイロードへ追加するため、削除済みマスタの 28 件が再保存され、Generate 画面の [`MappingErrorPanel.tsx`](file:///c:/Users/audih/ws/comfy-create-helper2/frontend/src/pages/GeneratePage/components/MappingErrorPanel.tsx#L117-L120) で `m.role == null` により大量の「マッピングエラー検出」を引き起こす。
2. **既存ワークフローにおける未割当ステージスロットの無断自動割当**:
   `initFromScan` が `savedMappings.length > 0`（既存ワークフローのリマッピング）であっても、未割当のステージスロット（`Rough`, `Detail`, `FaceDetailer`, `PantiesDetailer`, `PussyDetailer`, `NipplesDetailer` 等）に `scanDefaults[slotKey]` を初期値として流し込むため、ユーザーが割り当てていない 39〜49 件のステージスロットが保存時に勝手なノード ID で登録される。

## 3. アーキテクチャ & 詳細設計

### 3.1 Backend: マイグレーション Step 031 による既存 DB 孤立マッピングの浄化 (`REQ-369-T1`)

[`backend/app/migrations/steps.py`](file:///c:/Users/audih/ws/comfy-create-helper2/backend/app/migrations/steps.py#L792-L811) に `step_031_cleanup_orphaned_workflow_mappings` を追加し、`ALL_MIGRATION_STEPS` の末尾（`"031"`）へ登録する。

- **浄化対象**:
  1. `workflow_mappings.master_id NOT IN (SELECT id FROM mapping_masters)`（削除済み旧マスタを参照する孤立行：本番 DB の 984 件を含む）
  2. `workflow_mappings.variant_id IS NOT NULL AND NOT EXISTS (SELECT 1 FROM mapping_variants mv WHERE mv.id = workflow_mappings.variant_id AND mv.master_id = workflow_mappings.master_id)`（削除済みバリアント、または別マスタのバリアントを参照する不整合行）
- **冪等性**:
  `DELETE FROM workflow_mappings WHERE ...` は 2 回目以降の実行で削除件数 0 件となり、有効な `mapping_masters` / `mapping_variants` を参照するマッピング（有効・無効バリアント双方を含む）は 1 件も変更しない。

### 3.2 Backend: ワークフロー保存・更新・コピー・ロールバック時の孤立マッピング除外 (`REQ-369-T1`)

[`backend/app/routers/workflows.py`](file:///c:/Users/audih/ws/comfy-create-helper2/backend/app/routers/workflows.py#L16-L69) にヘルパー関数 `_load_valid_mapping_refs(db: Session) -> tuple[set[int], set[tuple[int, int]]]` と `_is_valid_mapping_ref(master_id: int, variant_id: int | None, valid_master_ids: set[int], valid_variant_pairs: set[tuple[int, int]]) -> bool` を導入し、以下の全書込経路で適用する：

1. `create_workflow` (`POST /api/workflows`)
2. `update_workflow` (`PUT /api/workflows/{workflow_id}`)
3. `copy_workflow` (`POST /api/workflows/{workflow_id}/copy`)
4. `rollback_workflow` (`POST /api/workflows/{workflow_id}/rollback` — `workflow_history.mappings` JSON 内に残存していた旧マスタ ID がロールバックで復活することを防ぐ)

- **検証ルールと状態遷移**:
  - `master_id` が `mapping_masters.id` に存在しない場合は保存対象から除外（スキップ）する。
  - `variant_id is not None` の場合、`(master_id, variant_id)` の組が `mapping_variants (master_id, id)` に存在しない場合は保存対象から除外（スキップ）する。
  - `update_workflow` / `rollback_workflow` 完了後、フロントエンドは React Query の `['workflows']` / `['workflow', workflowId]` キャッシュを invalidate して `GET /api/workflows/{id}` を再取得するため、サニタイズ除外された孤立レコードがローカル State に残存して再送信されることはない。またロールバック後も有効なマッピング（`savedMappings.length > 0`）が存在するため、除外された旧マスタ分が未割当スロットの自動埋めを引き起こすこともない。

### 3.3 Frontend: `useMasterMappingRows.ts` における孤立マッピング除外と未割当スロット保持 (`REQ-369-T2`)

[`frontend/src/hooks/useMasterMappingRows.ts`](file:///c:/Users/audih/ws/comfy-create-helper2/frontend/src/hooks/useMasterMappingRows.ts#L41-L511) を以下のように修正する：

1. **保存済みマッピングの妥当性判定ヘルパー `isValidSavedMapping(mapping: SlotMapping, definitions: readonly SlotDefinition[]): boolean`**:
   - `mapping.variant_id != null` の場合:
     `definitions.some(d => d.masterId === mapping.master_id && d.variantId === mapping.variant_id)` が真であること。
   - `mapping.variant_id == null`（レガシーマッピング）の場合:
     `resolvedKey = mappingSlotKey(mapping, definitions)` を求め、`definitions.some(d => canonicalSlotKey(d.masterId, d.variantId) === resolvedKey && d.masterId === mapping.master_id)` が真であること。
2. **孤立マッピングの除外（受信時および送信時の二重防御、`AC-1`）**:
   - サーバーから受け取った `options.existingMappings` / `existingMappings` を `storedMappings.current` へ格納する際、および `initFromScan` の入口で `savedMappings = rawSavedMappings.filter(m => isValidSavedMapping(m, allDefinitions))` を適用する。
   - `getMappings` 内の未表示スロット保持ループ（L482-486）でも `isValidSavedMapping(saved, allDefinitions)` を満たすもののみを保持する。
   - これにより、`MappingVariant.is_enabled === false` や `MappingMaster.default_enabled === false` の**実在する**スロットの既存マッピングは `allDefinitions` に含まれるため確実に保持され、削除済みマスタ（例: `master_id: 33〜62`, `999`）や存在しない `variant_id` の孤立マッピングは確実に除外される。
3. **既存ワークフローの再スキャン時における未割当スロットの空欄維持 (`AC-2`, `AC-3`)**:
   - `initFromScan` において `savedMappings.length > 0`（有効な既存マッピングが存在するワークフローのリマッピング）のとき、未割当スロットには `scanDefaults` を**一切適用しない**：
     - バリアントあり（L393-395）: `existing` が存在しない（または空文字の）スロットは `initial[slotKey] = ''` とし、`scanDefaults[slotKey]` による勝手な自動埋めを行わない。
     - バリアントなし（L429-432）: `existing` が存在しない（または空文字の）マスタは `initial[\`m_${master.id}\`] = ''` / `initial[String(master.id)] = ''` とする。
     - `buildRows` においても、`rowState[slotKey]` が `''` として明示初期化されるため、未割当スロットは `node_id: ''` (`status: 'unassigned'` または `'not_found'`) となり、`candidates` / `recommendedNodeIds` のみがドロップダウン候補として提供される。
   - 一方、`savedMappings.length === 0`（新規ワークフロー登録 `UploadWorkflowModal` 等）の `else` 分岐（L435-464）は従来通り `scanDefaults` を初期値として自動セットする（`AC-3`）。

## 4. トレードオフ開示 (Trade-off Disclosure)

| 論点 | 採用方針 | 代替案と却下理由 |
|---|---|---|
| バックエンド API での孤立 `master_id` / `variant_id` の扱い | **サイレント・フィルタ（サニタイズ除外）**: 有効なマッピングのみを永続化し、孤立行を除外して `200 OK` / `201 Created` を返す | **422 Unprocessable Entity で拒否**: Generate 画面の [`MappingErrorPanel.handleUpdateMapping`](file:///c:/Users/audih/ws/comfy-create-helper2/frontend/src/pages/GeneratePage/components/MappingErrorPanel.tsx#L53-L63) は `workflow.mappings` 配列をコピーして 1 件ずつ修正・`PUT` するため、複数エラーがある状態で 1 件目を直した際に他の孤立行が原因で 422 失敗し、UI から修復不能になる。また OpenAPI スナップショットの不変性も維持できるため、サニタイズ除外を採用。 |
| `REQ-358/AC-29` テストケースの扱い | `WorkflowModalMultiStage.test.tsx` L500 の `master_id: 999` テストは「削除済みマスタを除外し、実在する非表示マスタ（`default_enabled: false` / `is_enabled: false`）を保持する」契約へ更新する | `master_id: 999` を保持し続ける: 削除済みマスタが永続的に `role: None` のマッピングエラーを生み続ける根本原因そのものであり、今回のバグ修正（`AC-1`）と直接矛盾するため更新が必要。 |
| 既存ワークフローのリマッピング時の未割当スロット初期値 | `savedMappings.length > 0` の場合は未割当スロットを `''`（未割当）にし、候補リスト（`recommendedNodeIds` / `candidates`）のみ提供する | スキャン一致ノードを自動入力する: マルチステージ定義（Rough/Detail/FaceDetailer 等）がある環境では、ユーザーが意図しないノード（Main 用のノードや無関係な KSampler 等）が全ステージへ一括自動割当・保存され、ワークフロー設定を破壊するため却下。 |
