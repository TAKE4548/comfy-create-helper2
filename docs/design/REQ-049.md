# REQ-049 設計書: JobManagementModal hooks 違反修正

## 1. 概要

`JobManagementModal.tsx` における React Rules of Hooks 違反を修正する。
`useMemo` フック（L25–26）が条件付き早期リターン（L20）の後に配置されているため、同一コンポーネントインスタンスで `isOpen: false → true` に遷移したときに React がクラッシュし、画面全体が真っ黒になる。

## 2. 変更対象

| ファイル | 変更種別 | 内容 |
|---|---|---|
| `frontend/src/components/JobManagementModal.tsx` | MODIFY | `useMemo` フックを早期リターンより前に移動 |

**バックエンド変更**: なし  
**API 変更**: なし  
**SSoT 文書更新**: なし（UI バグ修正のみ）

## 3. 変更前後の比較

### Before（違反コード）

```tsx
export const JobManagementModal: React.FC<JobManagementModalProps> = ({ isOpen, onClose }) => {
  const {
    queueRunning,
    queuePending,
    clientId,
    filterOwnSession,
    cancelJob,
    cancelAllJobs,
  } = useGenerationStore()

  if (!isOpen) return null   // ← L20: 早期リターン（ここより後にフックがある）

  // フィルター処理
  const filterJob = (job: any) => !filterOwnSession || job[3]?.client_id === clientId

  const visibleRunning = useMemo(() => queueRunning.filter(filterJob), [queueRunning, filterOwnSession, clientId])  // ← L25: 違反
  const visiblePending  = useMemo(() => queuePending.filter(filterJob), [queuePending, filterOwnSession, clientId])  // ← L26: 違反
  ...
}
```

### After（修正コード）

```tsx
export const JobManagementModal: React.FC<JobManagementModalProps> = ({ isOpen, onClose }) => {
  const {
    queueRunning,
    queuePending,
    clientId,
    filterOwnSession,
    cancelJob,
    cancelAllJobs,
  } = useGenerationStore()

  // ← useMemo を早期リターンより前に配置（filterJob の条件をインライン化）
  const visibleRunning = useMemo(
    () => queueRunning.filter(job => !filterOwnSession || job[3]?.client_id === clientId),
    [queueRunning, filterOwnSession, clientId]
  )
  const visiblePending = useMemo(
    () => queuePending.filter(job => !filterOwnSession || job[3]?.client_id === clientId),
    [queuePending, filterOwnSession, clientId]
  )

  if (!isOpen) return null   // ← 早期リターンをフックの後に移動
  ...
}
```

### 変更点の説明

1. `useMemo` × 2 を `if (!isOpen) return null` より**前**に移動する
2. `filterJob` ヘルパー関数は `useMemo` の外で参照されなくなるため、**インライン化**して削除する
3. `filterJob` をインライン化することで、`useMemo` の deps 配列も適切に保たれる
4. その他のロジック（`totalJobsCount`、ハンドラー関数）はすべて早期リターン後に残す
   - `totalJobsCount`、`handleCancelJob`、`handleCancelAll`、`formatPromptId` は通常の変数・関数（フックではない）のため、早期リターン後でも問題なし

## 4. 依存関係分析

- `useGenerationStore` は引き続き無条件に呼ばれるため変更なし
- `visibleRunning` / `visiblePending` は `isOpen=false` 時も計算されるが、
  空配列や小規模データ処理のため**パフォーマンス影響は無視できる**
- コンポーネントの外部インターフェース（props）は変更なし

## 5. リスク評価

| リスク | 評価 | 対策 |
|---|---|---|
| useMemo deps の誤り | 低 | `filterJob` のインライン化で deps が明確になる |
| モーダル表示内容の変化 | なし | ロジックは同一、順序変更のみ |
| 他コンポーネントへの影響 | なし | 変更は 1ファイル内のみ |
