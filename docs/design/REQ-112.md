# REQ-112: 生成画面のワークフロー・プリセット設定UIの整理と省スペース化 設計書

> **v3 (最終承認版)** — モックアップレビューを経て確定した設計

## 1. 概要
生成画面（GeneratePage）のヘッダー・タブバー・プリセット管理UIを抜本的に整理する。
「高頻度操作（プリセット切り替え・パラメータ編集）」と「低頻度操作（ワークフロー全体設定）」を明確に分離し、省スペース化と操作性向上を図る。

### 重要な前提認識
コードレベルで `presets`（DB）と `sets`（Zustand）は **完全に同一データ** である。
```ts
const mappedSets = presets.map((p) => ({ id: p.id, name: p.name, ...p.param_values }))
setSets?.(mappedSets)
```
そのため UI 上の「セット管理」と「プリセット管理」は **1つのモーダルに統合** する。

## 2. 最終UIレイアウト

### 2-1. ヘッダー (低頻度ワークフロー設定)
```
[Generate ●]                    [Workflow ▼] [⚙️]
```
- ヘッダーには **ワークフロー選択ドロップダウン + ⚙️ギアボタンのみ**
- ⚙️ クリックで `SettingsPopover` を展開。中身:
  - ComfyUI URL
  - ベースモデル選択
  - 名前変更 / コピー ボタン
  - ノードリマッピング ボタン
  - デフォルト保存 / リセット ボタン

### 2-2. タブバー (プリセットナビゲーション)
```
[☑ my_default ×] [☑ portrait ×] [☐ test ×]    [+ Add] [📑 管理]
```
- タブには **チェックボックスを残す**（生成対象の視覚的同期のため）
- チェックボックスはタブクリックでも、モーダル内でも双方向で切り替え可能
- `[+ Add]` = 新規プリセット作成（即時）
- `[📑 管理]` = 統合プリセット管理モーダルを開く
- **削除したもの**: 全選択/全解除ボタン（モーダル内へ移動）、Scene Generator ボタン（モーダル内へ移動）

### 2-3. Set Settings バー (アクティブプリセット操作)
```
[my_default]    [↩ Undo] [↪ Redo]
```
- **削除したもの**: セット名入力欄（タブ上の名前で十分）
- アクティブプリセット名をバッジ表示（読み取り専用）
- `[Presets ▼]` ポップオーバーを廃止 → 管理ボタンで代替

### 2-4. 統合プリセット管理モーダル (新設)
`[📑 管理]` ボタンから開くモーダル。以下を一か所で管理:

| 機能 | UI |
|-----|----|
| 生成対象の選択 | チェックボックス（タブと双方向同期） |
| 並び替え | ⠿ D&D（@dnd-kit 既存活用） |
| 名前変更 | インライン編集（既存ロジック流用） |
| 削除 | 🗑 ボタン |
| 上書き保存 | 「💾 上書き保存」ボタン |
| 別名保存 | 名前入力 + 保存ボタン |
| 新規追加 | 「+ 新規プリセット」ボタン |
| 全選択/全解除 | モーダル内テキストボタン |
| Scene Generator | 「🎬 Scene Generator」ボタン（モーダル内下部） |

## 4. 懸念点・トレードオフ (Trade-off Disclosure)
- **クリック数の増加**: ベースモデル設定・リマッピングが2クリックになるが、低頻度操作のためモバイル省スペース化のメリットが上回る
- **モーダル重さ**: 統合モーダルが多機能になるため、初期表示コストが若干増加する。遅延評価 or 軽量実装で対応
- **isWorkflowMenuOpen state の残存**: DesktopLayoutから削除後、`useGeneratePageState.ts` 内に定義が残るがデッドコードになる。後続リファクタリングで対応
