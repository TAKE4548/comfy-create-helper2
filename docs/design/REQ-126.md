# REQ-126 システム詳細設計書: パラメータ同期グループ設定と主従ノード項目連動機能

## 1. 概要
本機能は、ComfyUIワークフローにおける複数のパラメータ項目（CFG、Scheduler、Seed等）に対して主従関係（1:N）の同期グループ（`ParamSyncGroup`）を定義し、活性化（Active）時に主項目の値を従項目群に動的適用（実行時オーバーライドおよびUI上の入力無効化）する機能を提供する。
非活性化（Deactive）時は各項目の個別設定値を維持・編集可能とすることで、パラメータ一括調整の効率化と柔軟な個別カスタマイズを両立する。

## 2. アーキテクチャ設計・データ構造

### 2.1 データベースモデル (`backend/app/models.py`)
```python
class ParamSyncGroup(Base):
    __tablename__ = "param_sync_groups"

    id = Column(Integer, primary_key=True, index=True)
    workflow_id = Column(Integer, ForeignKey("workflows.id", ondelete="CASCADE"), nullable=False)
    name = Column(String(255), nullable=False)
    master_role = Column(String(255), nullable=False)
    slave_roles = Column(JSON, nullable=False, default=list) # List of role strings
    is_enabled = Column(Boolean, default=False, nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow)

    workflow = relationship("Workflow", back_populates="param_sync_groups")
```

### 2.2 REST API エンドポイント (`backend/app/routers/param_sync_groups.py`)
- `GET /api/workflows/{workflow_id}/param-sync-groups`
- `POST /api/workflows/{workflow_id}/param-sync-groups`
- `PUT /api/param-sync-groups/{group_id}`
- `DELETE /api/param-sync-groups/{group_id}`

### 2.3 フロントエンド API & Store (`frontend/src/api/types.ts`, `useGenerationStore.ts`)
- `ParamSyncGroup` 型定義および Zustand store での取得・登録・更新・削除・トグル状態切替アクションの実装。

### 2.4 UI/UX コンポーネント
- `ParamSyncModal.tsx` [NEW]:
  - BypassSettingsModalと共通デザインのダイアログモーダル。
  - 同期グループ名、主項目（master_role）、従項目群（slave_roles）のマルチセレクト設定。
- `ParamPanel.tsx`:
  - Bypassセクションと同等のスタイルで「Param Sync」トグルスイッチ群を配置。
  - Active状態の同期グループに含まれる `slave_roles` の入力フォームを `disabled`（グレーアウト）表示とし、主項目追従インジケーターを表示。
- `useGenerateAction.ts`:
  - 生成実行直前のパラメータマッピング処理にて、Activeな同期グループが存在する場合、`slave_roles` の送信値を `master_role` の最新入力値で上書きしてバックエンド/ComfyUI APIへ送信。
