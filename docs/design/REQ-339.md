# REQ-339: プレビューエリアのアスペクト比非依存・高さ基準動的マルチ表示レイアウトおよびリソースモニタ移設 詳細設計

## 1. 概要と背景
ComfyUIによる画像生成は1:1（正方形）、16:9（横長）、2:3/9:16（縦長）など多様なアスペクト比を扱う。
現行の `GenerateParallelPreview` は固定の2:3アスペクト比を前提としたカード枠（$Width = Height \times 2/3$）および静的な列数判定（2〜4列）を採用していたため、非2:3画像の表示時に大きなレターボックスや余白が生じていた。
また、プレビューエリア右上に半透明HUD（`ResourceGaugeHUD`）が常駐していたため、プレビューエリアを余白なく最大化すると画像右上が直接遮蔽される問題があった。

本改修では：
1. **高さ統一・アスペクト比非依存の動的マルチプレビュー**: プレビューコンテナの利用可能高さに全画像の高さを揃えた上で、各画像本来のアスペクト比に応じた幅を計算し、利用可能な横幅の許す限り動的に枚数を並べる。
2. **リソースモニタのヘッダー移設**: プレビューエリア内の重畳HUDを撤去し、デスクトップ常設ヘッダー（Global Header）にリソース監視チップ（`ResourceGaugeChips`）を統合してプレビュー領域の遮蔽を完全に排除する。

## 2. アーキテクチャ設計

### 2.1 動的レイアウト計算モデル (`GenerateParallelPreview.tsx`)
コンテナサイズ $(W, H)$、要素間ギャップ $G = 12$、各画像の自然アスペクト比 $AR_i = \text{width}_i / \text{height}_i$（未解決時はフォールバックとして $2/3$）とする。

1. **基準高さの決定とゼロ除算防壁**:
   - 基本描画高さ: $H_{\text{target}} = H$
   - ゼロ除算・異常アスペクト比防止: $\text{safeAR}_i = \max(0.1, \min(10.0, AR_i || (2/3)))$
   - 単一画像がコンテナ幅を超える超横長画像（パノラマ等）の場合:
     $H_{\text{target}} = \max(50, \min(H, (W - 16) / \text{safeAR}_0))$
2. **動的幅計算と枚数決定**:
   - 各画像の計算幅: $W_i = \max(80, H_{\text{target}} \times \text{safeAR}_i)$
   - 現在の `pageStart` から順にアイテムを追加し、累積幅 $S_k = \sum_{j=0}^{k-1} W_{\text{pageStart}+j} + (k-1) \times G$ を評価。
   - $S_k \le W$ を満たす最大 $k$ を表示枚数（`visibleCount`）とする（最低1枚は保証）。
3. **アスペクト比の取得・キャッシングと健全性**:
   - 外部Props `aspectRatios?: Record<string, number>` が渡された場合はそれを優先。
   - 未指定の場合は `<img>` の `onLoad` ハンドラで `event.currentTarget.naturalWidth / naturalHeight` を取得し、画像URLをキーとする内部マップに保存。
   - 自然解像度が取得できるまでは従来の基準比率（$2/3$）をフォールバックとして使用し、レイアウトシフトを防止するとともに既存テストとの100%の後方互換性を担保する。
4. **選択中画像の視覚的アンカー**:
   - リサイズや枚数変更時、`selectedImage` のインデックスを含むページ範囲（`pageStart`）を再計算し、選択中の画像が画面外に消えないようにアンカーを維持する。

### 2.2 リソースモニタのヘッダー移設 (`DesktopLayout.tsx`)
- **プレビューエリア**: `DesktopLayout.tsx` のプレビューコンテナ内にある `<ResourceGaugeHUD />`（絶対配置オーバーレイ）を削除。
- **デスクトップヘッダー**: 画面上部の `Global Header`（`div className="flex items-center justify-between px-5 py-3..."`）の右側コントロール群の手前に `<ResourceGaugeChips />` を配置。
- これにより、CPU/RAM/GPU/VRAMおよびストレージの監視ステータスを常時視認可能にしつつ、プレビューキャンバスの100%を画像表示領域として解放する。

## 3. インターフェース設計
```typescript
export interface GenerateParallelPreviewProps {
  images: string[]
  selectedImage: string | null
  onSelect: (image: string) => void
  onOpen: () => void
  aspectRatios?: Record<string, number>
}
```

## 4. 既存仕様・他デバイスとの整合性
- **モバイルレイアウト (`MobileLayout`)**: 既存の42vh `object-contain` プレビューおよび1段目ヘッダーの `ResourceGaugeChips` 配置をそのまま維持し、影響を与えない。
- **ショートカットキー・ページネーション**: `ArrowLeft` / `ArrowRight` による前後の画像ページ切り替え、および左右矢印ボタンによるナビゲーションはそのまま動作を維持。
