# REQ-041: アルバム内表示・編集機能 設計書

本機能は、アルバムの管理・閲覧性を向上させるため、アルバム内画像の確認・編集ページ、ドラッグ＆ドロップによる並び順の変更・永続化、ソート切り替え、および拡大ビューワー（矢印キー、左右ボタン、スワイプ操作対応）を追加するものです。

---

## 1. システム構成・データモデル変更

データベースおよびデータモデル自体に変更はありません。既存の `albums` および `album_items` テーブル、`sequence_order` カラムを使用します。

### API の拡張
アルバム内の画像をまとめて削除するために、一括削除エンドポイントを新しく追加します。

#### `POST /api/albums/{album_id}/items/delete` [NEW]
*   **概要**: アルバムから指定されたスナップショット画像を除外する。
*   **リクエストボディ**: `AlbumItemsDelete`
    ```json
    {
      "snapshot_ids": [10, 11]
    }
    ```
*   **処理フロー**:
    1. 該当する `AlbumItem` のレコードを削除する。
    2. 残ったアイテムの `sequence_order` を 0 から順に再計算して更新（詰め直し）する。
    3. 更新後の `AlbumRead` スキーマを返却する。
*   **レスポンス**: `AlbumRead` (200 OK)

## 2. フロントエンド設計

`HistoryPage.tsx` にアルバム詳細状態を導入し、ビューを切り替えます。

### 2-1. コンポーネントツリーと状態管理
*   `HistoryPage.tsx`
    *   `view === 'albums'` の状態で、あるアルバムをクリックした場合、`selectedAlbumId` に ID をセットし、詳細画面 (`AlbumDetailView`) に切り替えます。
    *   **状態**:
        *   `selectedAlbumId: number | null` (選択中のアルバムID)
        *   `isSelectMode: boolean` (一括削除のための複数選択モードトグル)
        *   `selectedItems: Set<number>` (一括削除用に選択された `snapshot_id` のセット)
        *   `sortBy: 'custom' | 'date-asc' | 'date-desc'` (ソート順。デフォルトは `'custom'`)

### 2-2. ドラッグ＆ドロップ (Dnd-kit)
`sortBy === 'custom'` の場合のみドラッグ＆ドロップ（DnD）を有効にします。
*   `@dnd-kit/core` および `@dnd-kit/sortable` を使用。
*   DnD終了時 (`onDragEnd`) に、入れ替わった `snapshot_ids` の配列をバックエンドの `PUT /api/albums/{album_id}/order` に送信して順序を永続化します。

### 2-3. クロップなし表示
*   アルバム内画像の一覧表示では、画像のアスペクト比を維持するため `object-contain` もしくは `aspect-square` 内に収めるスタイルを使用し、画像の切り抜き（クロップ）が発生しないようにします。

### 2-4. 拡大ビューワーの拡張 (`HistoryModalPreview.tsx`)
既存 of `HistoryModalPreview` に以下の機能を追加します：
*   **左右ボタン**: 画面両端に浮遊するナビゲーションボタン（`<` および `>`）を追加。
*   **キーボード操作**: `keydown` イベントを監視し、`ArrowLeft` で左（前）、`ArrowRight` で右（次）へ切り替え。
*   **順序同期**: アルバム詳細画面で適用されているソート条件 (`sortBy`) に従ってソートされた画像配列をビューワーに渡すことで、ソート順どおりの画像送りを実現。

## 5. Trade-off Disclosure (トレードオフとリスク)
*   **ドラッグ＆ドロップとソートの競合**: カスタム順以外のソート（登録順など）が選択されている時は、ドラッグ＆ドロップによる並び替えを無効化します。ソートした状態でのドラッグ操作は並び替え順の意図が曖昧になるためです。
*   **API の並行更新制御**: ドラッグ＆ドロップで素早く複数回の順序更新が発生した場合に備え、フロントエンドで更新 API の実行中（isPending）はドラッグ操作を一時無効化するか、ローカル状態を即時更新（楽観的更新）した上で API 送信を行う設計とします。
