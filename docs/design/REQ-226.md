# REQ-226 詳細設計書: 不具合解析・AI自律分析のためのログ永続化と1週間ローテーション機構

## 1. 背景と課題

現在、Prompt Surgeon（FE: React / BE: FastAPI）にはログをファイル等に永続化・保持する仕組みが存在しない。
- **BE**: 標準ライブラリの `logging.basicConfig` により標準出力（コンソール）へ出力しているのみであり、ターミナルを閉じたりスクロールバッファが流れると過去のログは消失する。また、リクエスト単位の相関IDや未処理例外の体系的記録も行われていない。
- **FE**: `console.error` 等をブラウザDevToolsに出力するのみであり、画面クラッシュ時やAPI失敗時のエラー情報がリロードで失われる。

ユーザーの要望として、障害発生後の原因特定および機能改善時の状況確認を効率化するため、**「人間による閲覧よりもAIエージェントの自律分析・抽出に最優先で最適化したログ機構」**を導入し、**約1週間（7日間分）**を安全にローテーション保持する構成を構築する。

### 2.2 ログフォーマット仕様（AI自律分析特化 JSON Lines）

ファイル出力は 1行につき1つの独立した JSON オブジェクト（JSON Lines / `.jsonl`）とし、AI が `grep`、`awk`、`jq`、Python スクリプト等で構造的に即座にフィルタリング・相関分析できるスキーマとする。

```json
{
  "timestamp": "2026-09-07T23:15:00.123+09:00",
  "level": "ERROR",
  "source": "backend",
  "logger": "app.routers.comfy",
  "message": "ComfyUI prompt execution failed",
  "request_id": "req-9a8b7c6d-5e4f",
  "http": {
    "method": "POST",
    "path": "/api/comfy/prompt",
    "status_code": 500,
    "client_ip": "127.0.0.1",
    "duration_ms": 42.5
  },
  "error": {
    "type": "RuntimeError",
    "message": "Connection refused to upstream ComfyUI",
    "stack_trace": "Traceback (most recent call last):\n  File ...\nRuntimeError: Connection refused"
  },
  "extra": {
    "workflow_id": 12,
    "prompt_id": "xyz-123"
  }
}
```

#### フィールド定義
| フィールド | 型 | 必須 | 説明 |
|---|---|---|---|
| `timestamp` | string (ISO 8601) | 必須 | 発生時刻（タイムゾーン付き） |
| `level` | string | 必須 | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `source` | string | 必須 | `backend` または `frontend` |
| `logger` | string | 必須 | ロガー識別名（モジュール名 / FEコンポーネント名） |
| `message` | string | 必須 | ログメッセージ本文 |
| `request_id` | string \| null | 任意 | リクエスト相関ID（FE/BE横断追跡用） |
| `http` | object \| null | 任意 | HTTP通信メタ情報（メソッド、パス、ステータス、レイテンシ） |
| `error` | object \| null | 任意 | エラー型、メッセージ、スタックトレース |
| `extra` | object \| null | 任意 | ドメイン固有の追加コンテキスト（パラメータ、プリセットID等） |

### 2.3 ローテーション及び保持ポリシー

- **ファイル出力先**: プロジェクトルートの `logs/app.jsonl`（`backend/app/config.py` の `settings.log_dir` で設定可能）
- **ハンドラー**: Python 標準ライブラリの `logging.handlers.TimedRotatingFileHandler`
- **ローテーション条件**:
  - `when="midnight"`（日次・深夜0時ローテーション）
  - `interval=1`（1日ごと）
  - `backupCount=7`（過去7日分のアーカイブファイルを保持し、8日以前のログは自動破棄）
  - `encoding="utf-8"`
- **コンソール（標準出力）との二重化**:
  - コンソール出力には `StreamHandler` を適用し、人間がターミナルで直感的に把握できる標準テキストフォーマット（`%(asctime)s [%(levelname)s] %(name)s: %(message)s`）を維持。
  - ファイル出力には `JSONFormatter` を適用し、AI解析用のリッチな JSON Lines を書き込む。

### 2.4 バックエンド設計

1. **`backend/app/config.py`**:
   - `log_dir: str = "../logs"` 設定を追加。
   - `log_level: str = "INFO"` 設定を追加。
   - `log_retention_days: int = 7` 設定を追加。
   - ディレクトリが存在しない場合は自動作成（`Path(self.log_dir).mkdir(parents=True, exist_ok=True)`）。

2. **`backend/app/logging_config.py`**:
   - `JSONFormatter`: `logging.Formatter` を継承し、`LogRecord` を辞書化して JSON 文字列へシリアライズ。
   - `setup_logging()`: ルートロガーに対して `StreamHandler` と `TimedRotatingFileHandler` をアタッチ。
   - `uvicorn.access` 等の外部ライブラリロガーの過剰な二重出力を抑制・集約。

3. **`backend/app/middleware/request_logging.py`**:
   - FastAPI ミドルウェアとしてリクエストごとに `request_id`（UUID4）を発行。
   - レスポンスヘッダーに `X-Request-ID` を付与。
   - 処理時間（`duration_ms`）を計測し、リクエスト完了時に構造化ログを出力。
   - 静的ファイル配信（`/api/snapshots/images/`）や `/health` は過度なログ肥大化を防ぐため DEBUG レベルまたは除外フィルタを適用。

4. **グローバル例外ハンドラー（`backend/app/main.py`）**:
   - 捕捉されなかった 500 エラーを拾い、リクエスト情報・相関ID・スタックトレースを ERROR レベルで完全記録。

5. **`backend/app/routers/system_logs.py`**:
   - `POST /api/system/client-logs` エンドポイントを提供。
   - フロントエンドから送られてきたエラー（メッセージ、スタックトレース、URL、コンポーネント等）を受け取り、`source="frontend"` の JSON ログとして同一ログファイルへ安全に書き出し。

### 2.5 フロントエンド設計

1. **`frontend/src/utils/logger.ts`**:
   - **Breadcrumbs（直近100件の操作・状態トレイル）**:
     - メモリ内に直近100件の行動履歴を保持するリングバッファ（配列）を管理。100件を超えた場合は古い順（FIFO）で押し出し。
     - `addBreadcrumb({ category, message, data })`:
       - カテゴリ: `navigation`（画面遷移）、`ui`（ボタン押下、モーダル開閉）、`preset`（プリセットやパラメータの確定）、`ws`（ComfyUI WebSocket接続/切断/実行状態）、`api`（API呼出結果）。
       - **ノイズ間引き**: スライダー等のドラッグ中イベントは除外して確定時のみ記録し、ComfyUIの細かなステップ進捗は最新値の上書きまたは開始/完了の節目のみ記録。
   - `logClientError(error: Error | string, context?: Record<string, unknown>)`:
     - 直近の `breadcrumbs`（最大100件）をコピーし、`context.breadcrumbs` として自動同封。
     - ログペイロードを整形し `POST /api/system/client-logs` へ非同期送信。
     - 同一エラーの連続送信を防ぐデバウンス／重複フィルタ（5秒間のレート制限）を実装。
     - ログ送信API自体が失敗した場合はループを防ぐためコンソール出力のみにとどめる（Fail-Safe）。
   - `logClientEvent(level: 'info' | 'warn', message: string, context?: Record<string, unknown>)`:
     - 画像生成開始やバッチ実行などの重要ビジネスイベントを単発でバックエンドに永続化するための関数。

2. **`frontend/src/components/GlobalErrorBoundary.tsx`**:
   - React ツリーの最上位（`AppShell` またはルート）を包括する Error Boundary。
   - 子コンポーネントのクラッシュを検知した際、`componentDidCatch` で `logClientError` を発火し、直前の操作トレイル（Breadcrumbs）とともにバックエンドへ送信。ユーザーには再読み込みボタン付きのエラーフォールバックUIを表示。

3. **グローバルイベントリスナー（`frontend/src/main.tsx`）**:
   - `window.addEventListener('error')`: リソース読み込み失敗や未キャッチの構文/実行時エラーを記録。
   - `window.addEventListener('unhandledrejection')`: `Promise` の未キャッチ拒否（非同期APIエラー等）を記録。

## 3. API 仕様 (`POST /api/system/client-logs`)

- **パス**: `/api/system/client-logs`
- **メソッド**: `POST`
- **リクエストボディ**:
  ```json
  {
    "level": "error",
    "message": "Uncaught TypeError: Cannot read property 'map' of undefined",
    "stack": "TypeError: Cannot read property 'map' of undefined\n    at GeneratePage ...",
    "url": "http://localhost:5173/",
    "component": "GlobalErrorBoundary",
    "context": {
      "active_workflow_id": 3,
      "breadcrumbs": [
        {"timestamp": "2026-09-07T23:15:01.000Z", "category": "navigation", "message": "Navigated to /"},
        {"timestamp": "2026-09-07T23:15:03.500Z", "category": "preset", "message": "Loaded preset 'Anime-V2'"},
        {"timestamp": "2026-09-07T23:15:05.120Z", "category": "ui", "message": "Clicked Generate button"},
        {"timestamp": "2026-09-07T23:15:06.010Z", "category": "ws", "message": "WebSocket status changed: executing"}
      ]
    }
  }
  ```
- **レスポンス**: `204 No Content` または `{"status": "ok"}`

## 4. トレードオフとリスクの開示 (Trade-off Disclosure)

1. **ファイルI/Oとパフォーマンス**:
   - すべてのHTTPリクエストおよびエラーをファイルに書き込むため微小なディスクI/Oが発生する。
   - **対策**: 高頻度でアクセスされる静的画像サムネイル配信（`/api/snapshots/images/`）はログレベルを `DEBUG` に設定し、通常稼働時のログ量とI/O負荷を最小化する。
2. **ログローテーションのタイミング**:
   - `TimedRotatingFileHandler` は「指定時刻を過ぎてから最初に来たログ書き込み時」にローテーションが実行される（Python標準の仕様）。
   - アプリが深夜に停止していた場合、翌日最初のアクセス時に前日分のファイル名切り替えが行われる。本プロジェクトのローカル環境運用において実用上問題ない。
3. **フロントエンドのエラー無限ループリスク**:
   - ログ送信API呼出自体が失敗した際に、それがさらに `unhandledrejection` やエラーハンドラをトリガーすると無限リクエストループに陥る危険がある。
   - **対策**: `logger.ts` 内でのAPI呼出は `try-catch` で完全に囲み、ログ送信処理自体のエラーは内部で握りつぶしてコンソール出力のみにとどめる。
