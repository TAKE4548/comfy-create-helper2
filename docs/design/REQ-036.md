# 設計書: REQ-036 LoRA登録時のモデルパス選択機能の追加

## 1. 概要
LoRA登録・編集フォームにおいて、モデルのファイルパスを手動で入力する手間を削減し、タイポによる参照エラーを防ぐため、ComfyUIで読み込まれているLoRAモデル一覧から選択できるコンボボックス形式の入力機能を追加します。
また、二重登録の防止や未登録モデルの優先表示など、視覚的・操作的にわかりやすい制御を導入します。

## 2. 影響範囲と依存関係
- **backend**:
  - `backend/app/routers/loras.py`: ComfyUIからLoRAモデル一覧を取得し、DB登録状態とマージして返す新規エンドポイント `/api/loras/comfy-models` の追加。
  - `backend/app/schemas/lora.py`: 返却データのPydanticスキーマ定義。
  - `backend/app/schemas/__init__.py`: スキーマのエクスポート。
- **frontend**:
  - `frontend/src/api/client.ts`, `frontend/src/api/types.ts`: APIクライアントメソッドおよびデータ型の追加。
  - `frontend/src/components/LoraModals.tsx`: パス入力フィールドをコンボボックス形式に変更、ComfyUIモデル一覧の取得と表示制御、登録状況に応じたグレーアウト・バッジ表示、自動入力支援機能の実装。

## 3. 詳細設計

### 3.1. Backend (API エンドポイント)
ComfyUIのモデルフォルダリストAPI `GET /api/models/loras` もしくは `GET /api/experiment/models/loras` からモデルファイル一覧（相対パス）を取得し、DB（`loras` テーブル）に既に登録されているファイルパス（`file_path`）と比較します。

#### 新規スキーマ: `schemas.ComfyLoraModel`
```python
class ComfyLoraModel(BaseModel):
    file_path: str          # 例: "folder/subfolder/model.safetensors"
    is_registered: bool     # DB登録済みか否か
    lora_id: Optional[int] = None  # 登録済みの場合はそのID
```

#### 新規エンドポイント: `GET /api/loras/comfy-models`
- ComfyUI API呼び出しの流れ:
  1. `settings.comfy_url` の `/api/models/loras` に対してGETリクエストを送信。
  2. 404やコネクションエラーの場合は、フォールバックとして `/api/experiment/models/loras` を試す。
  3. それでも取得できない場合は、空のリスト `[]` を返却する（ComfyUIが未起動でも登録画面がクラッシュしないようにするため）。
  4. 取得できたモデル名リスト（Windows形式の `\` は `/` に置換して正規化）と、DB上の `loras.file_path` を比較判定。
  5. **ソート順**: 未登録モデル (`is_registered == False`) を上位に配置、各グループ内は辞書順ソート。

### 3.2. Frontend (UI/UX)
- **コンボボックスコンポーネントの導入**:
  `LoraFormFields` 内で、`file_path` 用のカスタム入力UIを構築します。
  - 入力フォームクリック時に候補リスト（ドロップダウン）を表示。
  - ユーザーが入力したテキスト（インクリメンタル検索）による部分一致フィルタリング。
  - 選択肢リスト内:
    - 登録済みモデル: テキストをグレーアウトし、`pointer-events-none`（選択不可）にし、右側に「登録済み」バッジを表示。
    - 未登録モデル: クリック時に選択し、`form.file_path` にパスを代入。同時に `form.model_name` が空であれば、ファイル名（拡張子を除いた、あるいは拡張子付きのベース名）を自動抽出して設定（登録の手間を軽減）。
  - リストにない任意のパスの手動直接入力も許容します。
