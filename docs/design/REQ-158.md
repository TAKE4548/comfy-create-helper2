# REQ-158 詳細設計書: FEキャッシュ設計の最適化（マルチデバイス同期対応）

## 1. 概要 (Overview)
フロントエンドにおける冗長なバックエンド (BE) API コールを排除し、UI レスポンスの高速化とフリッカー/ラグの解消を図る。
同時に、複数デバイス（PC/モバイル等）や別タブでの利用を想定し、キャッシュによる即時描画（0ms表示）とバックグラウンド同期（Stale-While-Revalidate & Action Revalidation）を両立したマルチデバイス同期保証アーキテクチャを導入する。

---

## 2. マルチデバイス同期保証アーキテクチャ

### 2.1 即時表示 + バックグラウンド同期 (Stale-While-Revalidate)
1. **モーダル起動・タブ切替時の同期 (`refetchOnMount: "always"`)**:
   - モーダル（アルバム保存モーダル、セリフ編集、画像選択）を開いた瞬間、既存のキャッシュを使って **0ms で即座にUI・アルバム名・フォント等を描画**。
   - 同時に裏で BE に最新データをリクエストし、別デバイスで追加・編集されたアルバムやプリセットがあれば自動で差分更新。
2. **画面フォーカス時の同期 (`refetchOnWindowFocus: true`)**:
   - 別端末や別タブでの作業後、アプリ画面に戻ってきた（ブラウザウィンドウ/タブにフォーカスが当たった）際に自動でバックグラウンド検証を実行。
3. **ComfyUI 実行完了時の連動同期**:
   - WebSocket の生成完了（`execution_complete` / `executed`）時に、スナップショット一覧やアルバム情報を自動 invalidate して最新状態を同期。
4. **Zustand Store の Stale-While-Revalidate**:
   - ワークフロー切替時、キャッシュがあれば 0ms でプロファイルを即時適用しつつ、裏で BE から最新のバイパスプロファイル / パラメータ同期グループを取得してキャッシュとUIを更新。

## 4. 詳細設計 (Detailed Design)

### 4.1 `src/hooks/useAlbums.ts`
```typescript
import { useMemo } from 'react'
import { useQuery } from '@tanstack/react-query'
import { albumsApi } from '../api/client'
import { STALE_TIMES } from '../constants/staleTimes'
import type { AlbumSummary } from '../api/types'

export function useAlbums(enabled: boolean = true) {
  const query = useQuery<AlbumSummary[]>({
    queryKey: ['albums'],
    queryFn: () => albumsApi.list() as Promise<AlbumSummary[]>,
    staleTime: STALE_TIMES.ALBUMS,
    refetchOnMount: 'always', // キャッシュがあれば0msで即時返しつつ、裏で別デバイスの変更を検知
    refetchOnWindowFocus: true,
    enabled,
  })

  const albumMap = useMemo(() => {
    const map = new Map<number, string>()
    if (query.data) {
      for (const album of query.data) {
        map.set(album.id, album.name)
      }
    }
    return map
  }, [query.data])

  const getAlbumName = (id: number | null | undefined): string | null => {
    if (id == null) return null
    return albumMap.get(id) ?? null
  }

  return {
    ...query,
    albums: query.data ?? [],
    albumMap,
    getAlbumName,
  }
}
```

### 4.2 Zustand Store ワークフロー別 Stale-While-Revalidate (`useGenerationStore.ts`)
```typescript
fetchBypassProfiles: async (workflowId) => {
  // 1. キャッシュがあれば 0ms で即時反映（ユーザーを待たせない）
  const cached = get().bypassProfilesCache[workflowId]
  if (cached) {
    set({ bypassProfiles: cached })
  }
  // 2. 別デバイスでの更新を拾うため、常にバックグラウンドで最新データを取得
  try {
    const profiles = await bypassProfilesApi.list(workflowId)
    set((state) => ({
      bypassProfiles: profiles,
      bypassProfilesCache: {
        ...state.bypassProfilesCache,
        [workflowId]: profiles,
      },
    }))
  } catch (e) {
    console.error('Failed to fetch bypass profiles:', e)
  }
},

fetchParamSyncGroups: async (workflowId) => {
  const cached = get().paramSyncGroupsCache[workflowId]
  if (cached) {
    set({ paramSyncGroups: cached })
  }
  try {
    const groups = await paramSyncGroupsApi.list(workflowId)
    set((state) => ({
      paramSyncGroups: groups,
      paramSyncGroupsCache: {
        ...state.paramSyncGroupsCache,
        [workflowId]: groups,
      },
    }))
  } catch (e) {
    console.error('Failed to fetch param sync groups:', e)
  }
}
```

## 5. トレードオフ・リスク開示 (Trade-off Disclosure)
- **Trade-off (即時性 vs ネットワーク効率)**:
  - 完全キャッシュ（リクエストゼロ）ではなく、モーダル起動やワークフロー切替時に「即座にキャッシュを描画しつつ裏で軽量リクエストを送る」SWR方式を採用することで、マルチデバイス間の変更反映（数ミリ秒〜数十ミリ秒での同期）と、UI体感速度（0ms描画）を両立しています。
