# REQ-350 Design: Seed 専用型

## Feasibility and Boundary

AC-1〜AC-7は既存 React/Zustand/React Query、文字列型 input_type、既存 preset param_values、凍結 BatchRequest の境界で実現可能。DB列追加やエンドポイント追加は不要。人間の設計レビュー承認後に実装する。

Workspace/Git root は C:/Users/audih/ws/comfy-create-helper2。Target_Paths は同root下の frontend、backend、docs。Git_Root_Mismatch=No、外部データへの書込なし。context の GLOBAL_ROOT=<USER_HOME>/.gemini/antigravity、USER_HOME=C:/Users/audih より GLOBAL_SCRIPTS=C:/Users/audih/.gemini/antigravity/scripts と解決した。指定ツールのみ外部の共通CLIとして呼び出し、作業データと出力はworkspace内に限定する。

## Current Evidence

- SPEC_SETTINGS §4-1 に seed 型がなく、MappingMasterEditModal.DEFAULT_INPUT_TYPESにもない。custom ParamTypeMaster.widget_type の拡張とは別の標準型として追加する。
- MappingMasterCreatePayload.input_type:str、MappingMasterUpdate.input_type:Optional[str]、DBの既存文字列属性は seed を受け取れる。workflow GET は effective_master.input_type と variant_id を返す。保存・取得契約テストで確認する。
- ParamPanel は input_type/custom widget_type で入力を分岐する。通常float/intは数値欄。既存ランダム/固定トグルは独立したglobal Seed行にある。

- injectWorkflowParams は role === 'Sampler_Seed' 1件だけを seedOptions で後から注入する。全ノードを一律上書きしてはいない。専用型のMain/Roughへ独立ルールを適用する分岐が必要。
- handleGenerate と handleGenerateSets は generation item の graph/param_values を先に組み立てる。既存 buildGenerationRecord は最終graphのパラメータ実値を保持する。新Seedもこの経路に合流する。

doc_mapper は PBI・対象3実装pathから mapped documents を返さなかった。PBIが指定する2仕様書を直接絞って調査した。広範囲のdocs走査は行っていない。

## Decisions and Source of Truth

### Standard type

標準 MappingMaster.input_type = 'seed' を追加する。ParamTypeMaster.widget_typeは変更しない。判定は文字列の完全一致で、role名、param_name='seed'、float/intから推定しない。カスタム型名 seed は標準語として扱い、同値の選択肢を重複させない。既存DBデータ/seed_dataを一括変換せず、ユーザーがseedを選んだマスタのみ変更する。

### Per-slot state and compatibility

値は現在の完全roleをキーとする既存 paramValues[role] の10進整数文字列をSSoTにする。モードは以下の予約キーにJSON文字列を保存する。

~~~json
{
  "Sampler_Seed": "100",
  "Sampler_Seed_rough": "200",
  "__seed_modes_v1": "{\"version\":1,\"modes\":{\"master:10:variant:20\":\"fixed\",\"master:10:variant:21\":\"random\"}}"
}
~~~

slotKey = master:<master_id>:variant:<variant_id or legacy>。別variantは別modeを持つ。主キーが同じworkflowコピーやstage suffix変更でもrole文字列にmodeが拘束されない。variantを削除して作り直した場合は新スロットとして未設定mode=fixed。未知/削除済みスロットのmetadataは生成に使わない。

metadata不在の旧プリセットはfixedで既存数値を保持。専用型に切替済みの Sampler_Seed はglobal seedMode/seedと独立する。legacy非seed Sampler_Seedのみ既存global操作を残す。専用型しかないworkflowでは独立global Seed行を表示しない。通常float欄へのSeedトグル追加はない。

metadata schema version不明、JSON破損、使用slotのmode不正は説明付き生成エラー。randomに暗黙変換しない。予約キーとmapping.roleが一致した場合も拒否する。mode JSONはgraphには一切注入しない。

### Limits and batch semantics

- 専用seedを含むセットのbatchSizeは現行UIの1..8を生成前にも検証する。randomでも9以上/極大batchを抽選前拒否。専用seedを含まないlegacy生成への新規枚数制限は追加しない。
- 専用型の基準値・実使用値は0..4294967295の整数。fixed+indexのindexは各セット内0始まり。
- randomは既存 Math.floor(Math.random()*2**32) を使用。0/4294967295を含み、偶然の重複を許容する。暗号用途ではない。
- AC-4は randomUint32 を11/22/33のstubに差替えた検証条件。通常動作で特定乱数列を強制しない。
- fixedの基準値+batchSize-1が上限を超えたら、当該操作で対象となる全セットを含む要求を送らずエラー。ラップ、飽和、黙った枚数削減をしない。
- 空文字、負値、小数、指数表記、NaN/Infinity、安全整数外、0以下/非整数のbatchSize、欠損node/role、重複slot/role/書込先は送信前に拒否する。入力途中の空文字はUIで保持できる。
- 専用Seedがgraph-referenceで接続されている場合、参照配線を暗黙にリテラルへ置き換えずエラーとする。直接整数を入力するマッピングをユーザーが設定する。
- 専用型の32bit固定範囲は新しい設計判断。旧legacy global範囲は本PBIで変更しない。レビューで明示承認する。

### Synchronization and stage identity

無同期の Main/Seed=100、Rough/Seed=200 は100/101と200/201をそれぞれ注入する。global=999に変更しても専用値へ作用しない。

既存 ParamSyncGroup.master_role/slave_roles の完全role指定を利用する。seed->seed同期では親のmode・基準値・実使用値を共有する。randomは親1回の抽選を子へコピーする。slaveはUI上の値とmode操作をdisabledにし、親名を表示する。seedが関係するmixed型同期、循環、複数親は生成前拒否。seed以外だけの同期は既存経路を保つ。

stage suffix変更で数値roleは既存backend cascadeに従い、modeはstable slotを保つ。フロントの旧role復元は現在完全一致かprevious_suffixesから一意に対応する場合に限定し、base_keyだけの補正で別stageへ値を流用しない。stageごとの同期選択UI追加はREQ-351の責務。

### Defaults, persistence and replay

setParamValuesによる値/mode更新は既存activeSet更新とautosaveへ同時に渡す。preset.param_values APIはstring値の追加キーを許し、DBはJSON文字列を保持する。新しいmode用DB列を追加しない。

Save Defaultは基準値だけをgraphへ保存し、random modeでも乱数を抽選しない。Reset Defaultは現在workflowの専用seedをgraph値/fixedへ戻す。snapshot復元は保存された実Seedを各専用roleのfixed基準値にする。snapshot中の古いmode metadataでrandomへ戻さない。

生成item.param_valuesのseed roleは実使用値へ置き換える。元のセット基準値とmodeは変更しない。履歴のGenerationRecord.parametersは最終graphの実値を根拠とする。バイパス/欠損recordの既存識別を維持する。

## Contracts and flow

~~~typescript
type SeedMode = 'random' | 'fixed'
interface SeedSettings { mode: SeedMode; seed: number }
interface ResolvedSeedItem {
  seedsBySlot: Record<string, number>
  actualParamValues: Record<string, string>
}
interface PrepareSeedBatchOptions {
  workflow: Workflow
  paramValues: Record<string, string>
  batchSize: number
  paramSyncGroups?: ParamSyncGroup[]
  randomUint32?: () => number
}
function prepareSeedBatch(options: PrepareSeedBatchOptions): ResolvedSeedItem[]
function validateSeedBatch(options: PrepareSeedBatchOptions): void
function resolveSeedSyncRoots(mappings: WorkflowMapping[], groups: ParamSyncGroup[]): Record<string, string>
// InjectWorkflowParamsOptionsへ追加:
resolvedSeeds?: Record<string, number>
~~~

1. getLatestState直後にworkflow、対象セット、画面値、mode metadata、sync、bypassをdeep freeze-copyする。currentParamValues=cleanParams(freeze(state.paramValues))。その後にvalidation/計算を行い、入力変更は次回生成へ適用する。
2. 通常prompt/parameter同期を適用する。専用seedは通常同期から除外する。
3. 全セットの専用seed設定と最後のfixed値を検証する。全体に問題がなければ各indexの実Seedを抽選/計算する。
4. mapping slot別実Seedを注入する。param_nameが存在すればそのkey、無ければ既存value、さらに無ければparam_name||valueを対象とする。legacy global分岐は専用seedを除外する。
5. bypassを適用し、実Seedのparam_valuesとgraph根拠のGenerationRecordを付ける。
6. BatchRequestを凍結する。全検証成功後だけactiveBatch/submitting状態を更新し送信する。
7. 既存idempotency replay/VRAM待機中は同request_idと凍結graphを再利用する。新たに乱数を引き直さない。新規にGenerateを押す操作は新request_idの次回生成とし、現在の入力設定を使用する。

## Trade-offs and risks

予約mode JSONはDB/API変更を減らし、既存プリセット保存と競合検出に載せられる。ただし未知version・予約role衝突のvalidationが必要。専用DB列/型付けAPIは将来の拡張案として見送り、別PBIで移行可能。

slot ID方式はstage renameに強い。variantの削除/再作成でmodeがfixedに戻る制約を開示する。role値は既存cascadeと一意な履歴復元が必要。曖昧なkeyを他stageへ補正しない。

固定も32bitに制限しoverflowを全体拒否するため、極大固定Seedを利用していた既存workflowを専用型へ切替える際は入力調整が必要。代案のuint32 wrapは再現Seedの意図を変え、safe-integer/64bit拡張はComfyUI nodeごとの上限確認とprecision対策が必要になるため採用しない。

mixed型syncとgraph-reference Seedは説明付き拒否を選ぶ。暗黙な型変換/配線切断を避ける一方、利用者は直接整数のseed mappingまたはseed同士の同期に設定し直す必要がある。

既存random源を共通関数へ集約し差替え可能にする。暗号乱数へ変更するとglobalとの規則・testの意味が変わるため本PBIでは採用しない。独立欄の抽選が同値になることを異常扱いしない。

OpenAPI snapshotのV2 drift、ローカルBA監査サービスとGPU確認手段の稼働状況は実装成功とは別に記録する。下記監査が不成立の場合はPASSと表示せずreview時の制約として開示する。

## Human Review Gate and audit

設計変更は人間のレビューへ返す。承認対象は専用固定32bit範囲/overflow全体拒否、legacy globalとの独立、mode metadata保存形式、mixed sync/参照Seed拒否。PBI ACに追加変更はない。外部監査の実行・アンロード証跡は REQ-350-design-audit.md に記録する。監査未成立を実装完了や仕様PASSと扱わない。
