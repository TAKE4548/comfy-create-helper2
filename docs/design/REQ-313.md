# REQ-313 詳細設計書: Prompt Surgeon FuguMT翻訳エンジンの高度化（文末分割・強度タグ正規化・Danbooru辞書引き統合）

## 1. 概要と背景 (Overview & Background)

### 1-1. 課題認識
Prompt Surgeon（`comfy-create-helper2`）では、CPU 常駐・超低レイテンシ（20〜30ms）かつ GPU VRAM 消費ゼロ（0MB）の和訳エンジンとして `staka/fugumt-en-ja`（CTranslate2 int8形式）を採用し、プロンプト全文和訳およびドラッガブルタグチップ和訳カード（`TagChipTranslationCard`）を実現しました。
しかし、実際の画像生成プロンプト運用において以下の3つの重大な課題が存在していました：

1. **複数文の自然文プロンプトにおける訳抜け・途中打ち切り**:
   FuguMT（Marian-NMT）は文単位（Sentence-level）コーパスで学習された翻訳モデルであるため、ピリオド（`.`）で連結された複数文を1チャンクとして渡すと、後続の文が丸ごと脱落したり途中で翻訳が打ち切られる問題が発生する。
2. **強調・重み指定構文による推論阻害・未翻訳スキップ**:
   `((cat_ears:1.2))` や `[smile]`、`(masterpiece:1.2)` などの強度指定構文が、従来の `sanitize_and_tokenize` で丸ごとプレースホルダー（`__TOKEN_X__`）化されて未翻訳のままスキップされるか、多重括弧が漏れて記号混じりで FuguMT に渡り推論が乱れる。
3. **Danbooru 特有オタク語彙・アンダースコア結合語の誤訳**:
   `ahoge`（アホ毛）、`cat_ears`（猫耳）などの画像生成特有の定訳やアンダースコア結合語が、汎用機械翻訳モデルでは未知語や不自然な直訳になってしまう。

### 1-2. 改修のゴール
本改修では、`translation_service.py` の翻訳パイプラインを「構文退避 → 文分割 → 強度アンパック → 辞書引き → FuguMT推論 → 再パック・結合」に刷新し、以下の価値を提供します：
- ピリオドで区切られた複数文を正確に文単位分割し、訳抜けなく並行推論する。
- 強度括弧群・コロン重み数値をアンパックして芯の英単語のみを翻訳し、タグカード用には純粋な日本語、プロンプト置換用には元の強度構文を再パックして復元する。
- Civitai 配布の Danbooru 日英対訳辞書（ZIP/CSV）をインメモリ保持し、ヒット時は FuguMT 推論をスキップして即座（0ms）に定訳を採用する。
- 辞書未配置・読込失敗時でも FuguMT 単独推論へ安全にフォールバックする Graceful Degradation を担保する。

## 3. 詳細パイプライン設計 (Pipeline Architecture)

### 3-1. パイプライン全体フロー

```
入力プロンプト: "((cat_ears:1.2)), A girl smiles. She reads a book. <lora:animestyle:0.8>"
  │
  ▼ [Step 1: メタ構文保護] (sanitize_and_tokenize)
  "<lora:...>" を "__TOKEN_0__" に退避
  │
  ▼ [Step 2: チャンク・文分割] (SPLIT_PATTERN.split)
  Tokens: ["((cat_ears:1.2))", ", ", "A girl smiles", ". ", "She reads a book", " ", "__TOKEN_0__"]
  │
  ▼ [Step 3: 各チャンクの前処理] (unpack_tag)
  Chunk 1: ((cat_ears:1.2)) -> prefix="((", core="cat ears", weight=1.2, suffix="))"
  Chunk 2: A girl smiles   -> prefix="",   core="A girl smiles", weight=None, suffix=""
  Chunk 3: She reads a book -> prefix="",   core="She reads a book", weight=None, suffix=""
  Chunk 4: __TOKEN_0__     -> プレースホルダー（そのまま保持）
  │
  ▼ [Step 4: Danbooru 辞書照会]
  - "cat ears" -> 辞書 HIT: "猫耳" (0ms 確定, FuguMT 推論スキップ)
  - "A girl smiles" -> 辞書 MISS -> FuguMT バッチ推論キューへ
  - "She reads a book" -> 辞書 MISS -> FuguMT バッチ推論キューへ
  │
  ▼ [Step 5: FuguMT バッチ並行推論] (FuguMTService.translate_batch)
  FuguMT([ "A girl smiles", "She reads a book" ])
    -> ["少女が微笑む", "彼女は本を読む"] (20〜30ms)
  │
  ▼ [Step 6: 出力フォーマット制御 & 再パック] (repack_tag)
  [repack=True の場合 (プロンプト全文置換)]:
    - Chunk 1 -> "((猫耳:1.2))"
    - Chunk 2 -> "少女が微笑む"
    - Chunk 3 -> "彼女は本を読む"
  [repack=False の場合 (タグカード表示)]:
    - Chunk 1 -> "猫耳" (括弧・数値を省いた純粋日本語)
  │
  ▼ [Step 7: 区切り記号結合 & メタ構文復元] (restore_tokens)
  "((猫耳:1.2)), 少女が微笑む. 彼女は本を読む <lora:animestyle:0.8>"
```

### 3-2. 正規表現およびコアロジック仕様

#### A. 文末ピリオド・句読点分割正規表現 (`SPLIT_PATTERN`)
重み小数のピリオド（`:1.2` 等）や三点リーダー（`...`）を誤分割せず、直後が空白または終端であるピリオド、カンマ、改行、および日本語句読点・感嘆符・疑問符で分割する。
```python
SPLIT_PATTERN = re.compile(r"([,、\n\r]+\s*|(?<![\d.])\.(?![\d.])(?:\s+|$)|[。！？!?]+\s*)")
```
- `(?<![\d.])\.(?![\d.])(?:\s+|$)`:
  - 直前が数字でもピリオドでもないピリオド（`:1.2` や `...` を除外）
  - 直後が数字でもピリオドでもない（`1.5` や `...` を除外）
  - かつ直後が空白または文字列終端であること
- キャプチャグループ `(...)` を持たせることで、`re.split` の戻り値に区切り記号自体が保持され、再構築時に元のピリオドやカンマの配置を完全再現可能。

#### B. 強度タグのアンパックと再パック (`unpack_tag`, `repack_tag`)
```python
WEIGHT_TAG_REGEX = re.compile(r"^([(\[{]+)(.+?)(?::([0-9.]+))?([)\]}]+)$")

def unpack_tag(chunk: str) -> tuple[str, str, Optional[float], str]:
    raw = chunk.strip()
    match = WEIGHT_TAG_REGEX.match(raw)
    if match:
        prefix, core, weight_str, suffix = match.groups()
        cleaned_core = core.replace("_", " ").strip()
        weight_val = float(weight_str) if weight_str else None
        return prefix, cleaned_core, weight_val, suffix
    
    cleaned_core = raw.replace("_", " ").strip()
    return "", cleaned_core, None, ""

def repack_tag(translated_core: str, prefix: str, weight: Optional[float], suffix: str) -> str:
    if not prefix and not suffix and weight is None:
        return translated_core
    if weight is not None:
        weight_fmt = f"{weight:g}" if isinstance(weight, float) else str(weight)
        return f"{prefix}{translated_core}:{weight_fmt}{suffix}"
    return f"{prefix}{translated_core}{suffix}"
```

#### C. Danbooru 辞書ローダー設計 (`load_danbooru_dict`)

- **探索対象パス（優先順位）**:
  0. `DANBOORU_DICT_PATH` 環境変数が指定されている場合は最優先で検証
  1. `tmp/danbooruTagCompleteCsv_v1020250919.zip` (ZIP 直接オープン)
  2. `tmp/danbooru_extracted/danbooru_translations_jp.csv`
  3. `tmp/danbooru_translations_jp.csv`
  4. `tmp/danbooru_ja.csv`
  5. `tmp/danbooru.csv`
  6. `data/dictionaries/danbooru_ja.csv`
- **BOM耐性 & 安全デコード**:
  - `encoding="utf-8-sig"`（BOM除去）を標準とし、エラー時は `errors="replace"` でフォールバック。
- **代表訳の抽出**:
  CSV の対訳列（第2列または最終列）にカンマ区切りで複数の同義語（例: `猫耳,ネコミミ,ねこみみ,ネコ耳`）が含まれている場合、先頭の代表訳（`猫耳`）を抽出してインメモリ辞書に登録する。
- **キーの二重登録（Dual-key Normalization）**:
  単語登録時に `tag.lower().strip()`（アンダースコア維持）と `tag.lower().strip().replace("_", " ")`（空白化）の両方を登録し、照会側がどちらの形式であっても O(1) で確実にヒットするように保持する。
- **Graceful Degradation**:
  辞書ファイルが存在しない場合や破損している場合でも、警告ログを出力した上で `_DICT_LOADED = True` として 0 件で正常復帰し、FuguMT 単独推論へシームレスにフォールバックする。

## 4. REST API 仕様改修 (`/api/translate/prompt`)

### 4-1. リクエストモデル (`PromptTranslateRequest`)
```python
class PromptTranslateRequest(BaseModel):
    prompt: str
    source_lang: Optional[str] = "en"
    target_lang: Optional[str] = "ja"
    provider: Optional[str] = None
    repack: Optional[bool] = True  # デフォルト True で従来のプロンプト置換動作を完全互換
```

### 4-2. レスポンスモデル (`PromptTranslateResponse`)
既存のレスポンススキーマを変更せず維持：
```python
class PromptTranslateResponse(BaseModel):
    translated_prompt: str
    meta: TranslateMeta
```
- `repack=True`（プロンプト全体置換時）: `((猫耳:1.2)), 少女が微笑む`
- `repack=False`（タグチップカード表示時）: `猫耳`
- `meta.cached_chunks`: Danbooru 辞書ヒット件数およびインメモリキャッシュヒット件数が計上され、無駄な API / 推論呼出が 0 であることが透過的に追跡可能。

## 5. Trade-off Disclosure (トレードオフの開示)

| 検討事項 | 採用アプローチ | メリット | トレードオフ・リスクと対策 |
|---|---|---|---|
| **辞書フォーマット** | ZIP 内 CSV のインメモリ読み込み (約4.1万件) | 起動時 75ms でロード完了、メモリ消費わずか約 8MB、事前展開の手間なし | ZIP 解凍ライブラリ `zipfile` を使用するため、ZIP 構造が異なる場合は CSV パスへのフォールバックで吸収 |
| **同義語の扱い** | 先頭の代表訳を採用 (`row[1].split(',')[0]`) | プロンプト置換・タグカードに冗長な別名リストが混入するのを防止 | ユーザーが別表記（カタカナ等）を望む場合があるが、最も代表的な漢字/かな表記が先頭に定義されているため実用上最適 |
| **文末ピリオド判定** | `(?<![\d.])\.(?![\d.])(?:\s+\|$)` | 小数点 `:1.2` や三点リーダー `...` を破壊せず、自然文ピリオドのみを正確に分割 | 文末直後に空白がない誤記（`word.Next`）は英語構文上稀だが、カンマによる分割と併用することで実用性を担保 |
| **下位互換性** | `repack: bool = True` (デフォルト) | 既存のフロントエンド・テストが一切壊れず、安全に段階移行可能 | タグカード側で `repack: false` を明示的に指定する必要があるが、型定義の拡張で安全に結合可能 |
