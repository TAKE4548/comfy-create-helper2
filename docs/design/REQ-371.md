# REQ-371 設計書: モバイルGenerate：テキスト層による生成ボタンの被覆修正と固定方法の見直し

## 1. 概要と背景 (Executive Summary)

### 1.1 課題と背景
モバイル環境（画面幅 767px 以下）の Generate 画面において、プロンプト編集領域を上下にスクロールした際、テキストレイヤやタグチップが画面下部に固定配置されている生成ボタン領域（mobile-action-bar）に被って描画され、生成・保存・キュー管理のボタンが見えなくなる、あるいはタップ操作を背面のテキスト／チップに奪われて意図した操作ができないという不具合がユーザーの実画面報告により判明した。

### 1.2 根本原因の調査と特定 (Root Cause Analysis)
実画面コードおよび DOM / CSS 構造の調査により、以下の複合要因を特定した：
1. **未定義の Tailwind クラスによる z-index 脱落**:
   MobileLayout.tsx のアクションバーに付与されていた z-45 クラスは Tailwind CSS の標準プリセットに存在せず、tailwind.config.js にも定義されていない無効なクラスであった。そのため、ブラウザ描画時に z-index: auto となり、固有のスタッキングコンテキストが確立されていなかった。
2. **スタッキングコンテキストの逆転**:
   TagChip.tsx 内のテキストおよびドラッグハンドルは  relative z-10 を持ち、ドラッグ中はインラインスタイルで zIndex: 50 を適用していた。アクションバーが z-index: auto であったため、 relative z-10 を持つチップ内テキストやドラッグ中（z-50）のチップがアクションバーより手前に描画される構造となっていた。
3. **半透明背景とブラーによる背後コンテンツの透け見え**:
   アクションバーの背景が bg-surface/90 backdrop-blur となっており、背面の高輝度なプロンプトテキスト（text-zinc-200 や白文字）がスクロール時に透過してボタン直下に映り込み、視覚的な被覆・文字衝突を引き起こしていた。
4. **チップサブメニューの固定バーへの侵入・隠蔽**:
   TagChip.tsx の詳細編集サブメニューが常に下方展開（top-full mt-1.5）で表示されるため、画面下部付近のチップでサブメニューを開くと固定アクションバーと重複し、アクションバーの前面化によりサブメニューの操作ボタン（削除、強度調整、コピー等）が隠れて押せなくなる課題が存在した。

### 1.3 解決方針と受入基準 (AC) の充足サマリ
上記の原因を根本解決し、AC-1〜AC-8 を以下の技術的アプローチにより確実に充足する：
- **AC-1 (背面コンテンツの非透過・視認性保証)**: アクションバーを完全不透明サーフェス（bg-surface border-t border-[rgba(255,255,255,0.06)]）にし、新設スタッキングトークン --z-mobile-action-bar: 40; を適用。プロンプト欄スクロール時に背面文字がボタン直下に透けて見えないようにする。
- **AC-2 (固定バーのタップ単独捕獲)**: アクションバーに pointer-events-auto を適用し、ボタン（生成・保存・キュー）のタップを確実にボタン自身で捕捉。背面のテキストエリアやチップへのタップ漏洩・誤発火を完全に防ぐ。
- **AC-3 (ドラッグ中チップの背面通過)**: TagChip.tsx のドラッグ時インラインスタイル zIndex: isDragging ? 50 : undefined を zIndex: isDragging ? 30 : undefined へ変更。通常チップ（10）より前面にしつつ、固定バー（40）の背面に沈める。
- **AC-4 (下部チップサブメニューの上向き展開)**: 画面下部付近のチップでサブメニューを開いた際、下部余白不足（< 220px）を検知してクラスを bottom-full mb-1.5（上向き反転）に切り替え、固定バーに遮蔽されず全操作項目が利用可能とする。
- **AC-5 (360px・セーフエリア・ボトムナビ整合)**: bottom-[calc(54px+env(safe-area-inset-bottom)+env(keyboard-inset-height,0px))] によりボトムナビ（54px）直上に正確に配置し、隙間や二重パディングを生じさせない。
- **AC-6 (Tag Set / 共通部品非回帰)**: TagChipEditor の通常編集・削除・追加・無効化トグル等の機能を保持し、Tag Set や LoRA 画面での動作を完全保証する。
- **AC-7 (PC画面非回帰)**: 画面幅768px以上のデスクトップ表示や通常配置では従来のレイアウト・下向きサブメニューを完全維持する。
- **AC-8 (スクロール到達性・キーボード退避)**: pb-[calc(54px+env(safe-area-inset-bottom)+72px)] によりプロンプト末尾まで到達可能とし、キーボード表示時は isInputFocused による退避を正確に連動させる。

## 2. アーキテクチャ変更設計 (Architectural Design)

### 2.1 CSS スタッキング階層と z-index トークンの体系化
プロジェクト全体の階層ルール（frontend/src/index.css）に --z-mobile-action-bar を新設し、以下の階層関係を厳密に定義・固定する：

| レイヤ名 | CSS トークン / 値 | 用途 |
|---|---|---|
| チップ通常描画 | z-0 / z-10 | プロンプト入力欄内のタグチップおよび通常テキスト |
| チップドラッグ中 | z-[30] | 並べ替えドラッグ中のチップ（通常チップより前面、固定バーより背面） |
| **モバイル生成固定バー** | **--z-mobile-action-bar: 40;** | **Generate 画面の固定アクションバー (mobile-action-bar)** |
| モバイルボトムナビ | --z-mobile-nav: 50; | アプリ共通の最下部ナビゲーションバー (AppShell nav) |
| ヘッダー展開メニュー | --z-header-menu: 60; | ヘッダーのドロップダウンメニュー |
| モーダル・オーバーレイ | --z-modal: 100; | 共通モーダル、ボトムシート、バックドロップ |

これにより、通常テキスト（z-0）、チップテキスト（z-10）、ドラッグ中チップ（z-[30]）はすべてアクションバー（z-[40]）の背面に沈み、物理的被覆が完全に根絶される。また、共通モーダル（z-[100]）展開時はアクションバーおよびボトムナビが適切にバックドロップによって遮蔽・保護される。

### 2.2 固定アクションバーの構造・固定方式の見直し
MobileLayout.tsx の mobile-action-bar について以下の改修を行う：
- **完全不透明背景への変更**: bg-surface/90 backdrop-blur を廃止し、完全不透明な bg-surface border-t border-[rgba(255,255,255,0.06)] に統一。背面の文字が絶対に透けないサーフェスを確立。
- **スタッキングトークン適用**: z-45 を z-[var(--z-mobile-action-bar,40)] へ修正。
- **イベント単独捕獲の保証**: コンテナに pointer-events-auto を担保し、ボタンタップ時に背面のスクロール領域や入力欄へタッチ／クリックイベントが漏洩・貫通しない構造とする。
- **レイアウト整合性**: ボトムナビ上端（bottom-[calc(54px+env(safe-area-inset-bottom)+env(keyboard-inset-height,0px))]）の配置を維持し、仮想キーボード起動時の退避（isInputFocused ? 'hidden pointer-events-none' : 'flex'）を維持。スクロール末尾余白 pb-[calc(54px+env(safe-area-inset-bottom)+72px)] により最下部のタグや入力欄まで完全に到達・視認可能とする。

### 2.3 TagChip ドラッグ階層とサブメニュー上向き反転 (Flip)
TagChip.tsx において以下の改修を行う：
1. **ドラッグ時 z-index の適正化**:
   zIndex: isDragging ? 50 : undefined を zIndex: isDragging ? 30 : undefined へ変更。通常チップ（z-10）より前面を保ちつつ、固定バー（z-[40]）の背面を通過させる。
2. **サブメニューの上向き展開 (Flip)**:
   画面下端付近にあるチップでサブメニューを開いた際、画面外や固定バーの背面に潜り込むことを防止するため、スマートな上向き展開判定を導入。チップの位置（getBoundingClientRect）を検査し、下部余白が不足する場合（目安: 
ect.bottom + 220 > window.innerHeight - 126）は bottom-full mb-1.5 で上方向に展開する。これにより、サブメニュー内の操作項目（タグ名入力、強度変更、削除、コピー、翻訳）が常に遮蔽されず操作可能となる。

## 3. テストシームマップ (Seam Map [W-DD-SEAM])

1. **Integrated (本物のコードで実行する層)**:
   - MobileLayout: プロンプト入力欄、タグチップ一覧、セクション切替、固定アクションバーの描画およびイベント処理。
   - TagChipEditor / TagChip: チップ表示、ダブルクリック編集、並べ替えドラッグ、サブメニュー展開、強度変更。
   - index.css: CSSカスタムプロパティ階層定義。
2. **Severed (切断する層・外部I/O境界)**:
   - ComfyUI API / WebSocket 通信: テスト実行時は Zustand ストア（useGenerationStore）のモックおよびインメモリ状態管理で外部ネットワークを完全切断。
   - ルーティング・ナビゲーション: 
eact-router-dom をモック化。
3. **Mock Level (モック適用レベル)**:
   - 内部ロジックやコンポーネント実装のモンキーパッチは厳禁。外部状態供給（Zustand ストア初期値）およびブラウザAPI（getBoundingClientRect, isualViewport）の境界スタブに限定。
4. **PBT Decision (プロパティベーステスト要否)**:
   - 不要。本 PBI は CSS スタッキングコンテキスト、DOM 構造、ポインタ判定、およびビューポート座標判定に関わる UI インタラクション修正であり、数値計算・DSL構文解析等を含まないため。
5. **Fault Injection (異常系・フォールト注入)**:
   - アクションバー上の高速連続連打（Rapid Tap Spurring）による背面要素へのイベント漏洩テスト。
   - ビューポート極小（幅360px、高さ極小）境界における座標計算の非破綻テスト。

## 4. 設計書契約 (Design Document Contract D1-D7 [W-DD-BOUNDARY])

### D1: タスクごとの責任・スコープ・完了条件
- **REQ-371-T1**:
  - **責任**: CSS スタッキングトークンの新設、MobileLayout の固定アクションバーの z-index 修正、不透明背景化、イベント遮蔽、およびスクロール透過防止の単体・結合テスト。
  - **スコープ**: frontend/src/index.css, frontend/src/pages/GeneratePage/components/MobileLayout.tsx, frontend/src/pages/GeneratePage/components/__tests__/MobileLayout.test.tsx
  - **完了条件**: アクションバーの z-index が 40 となり、背景が完全不透明で背面テキスト・チップが一切被覆・透過せず、ボタンタップが確実に単独発火すること。
- **REQ-371-T2**:
  - **責任**: TagChip のドラッグ時 z-index 調整（30）、下部境界でのサブメニュー上向き反転（Flip）ロジックの実装、および共通利用画面（Tag Set / LoRA / PC画面）の非回帰テスト。
  - **スコープ**: frontend/src/components/TagChipEditor/TagChip.tsx, frontend/src/components/TagChipEditor/__tests__/TagChip.test.tsx
  - **完了条件**: ドラッグ中のチップがアクションバー手前に描画されず、下部付近のチップでサブメニューを開いた際に上向きに展開されて全項目が操作可能であり、PCおよび他画面で従来動作を維持すること。

### D2: タスク間の依存関係とその理由
- **依存関係**: REQ-371-T1 -> REQ-371-T2
- **理由**: T1 で CSS トークン --z-mobile-action-bar: 40; およびアクションバーの固定仕様が確定した上で、T2 がドラッグ時 z-index（30 < 40）およびサブメニューの干渉回避境界（126px マージン）を実装・検証するため。

### D4: 共有規約・インターフェース
- **CSS 変数規約**: :root に --z-mobile-action-bar: 40; を定義。
- **スタッキング規約**:
  - TagChip 通常要素: z-0〜z-10
  - TagChip ドラッグ要素: z-[30]
  - mobile-action-bar: z-[var(--z-mobile-action-bar,40)]
  - AppShell mobile nav: z-[var(--z-mobile-nav,50)]
  - Modal / Sheet: z-[var(--z-modal,100)]
- **サブメニュー Flip 規約**:
  - チップ下端からビューポート下端までの距離が 220px 未満（またはアクションバー高さを含めて安全に展開できない場合）は bottom-full mb-1.5 を適用。

### D6: エンジニアへの委譲裁量範囲 (Delegated Judgment)
- サブメニュー上向き反転（Flip）判定における微小なオフセット値（例: mb-1.5 や判定閾値の 5〜10px 程度の調整）の決定。
- テストコードにおけるモックデータ文字列（タグ名、プロンプトテキスト）の選定。
- ※スタッキングトークン値（40）、所有ファイル境界、禁止事項の変更は委譲されない。

### D7: 変更禁止スコープ (Prohibited Scope)
- DesktopLayout.tsx およびデスクトップレイアウト（幅 768px 以上）の DOM 構造・CSS の変更。
- AppShell.tsx のボトムナビゲーション構造および --z-mobile-nav: 50; / --z-modal: 100; のトークン値変更。
- モバイルレイアウトにおける 100dvh、overscroll-behavior-y: contain、およびキーボード退避フック構造（isTextInput 判定）の撤去。
- チップドラッグライブラリ（@dnd-kit）の差し替えやコア機能の改変。
