# REQ-238 詳細設計書: server-manager 起動時の Vite EPERM rmdir エラー解消および堅牢化

## 1. 概要と目的
本設計は、Windows環境において `server-manager` からの一括起動・再起動時、あるいは開発時の `npm run dev` 実行時に発生する以下の致命的起動エラーを根本解消し、プロセスの安全なライフサイクル管理を実現することを目的とする。

```text
error when starting dev server:
Error: EPERM: operation not permitted, rmdir 'frontend/node_modules/.vite/deps'
```

---

## 2. 根本原因の構造的分析
1. **Windows NTFS Read-Only 属性と Node.js `rmdir`**:
   - Windows 環境では、`.vite` 配下のディレクトリに `R` (Read-Only) 属性が付与される場合がある（初期作成時や継承設定など）。
   - Node.js の `fsp.rm(path, { recursive: true, force: true })` は、対象フォルダに `R` 属性が付与されていると内部ファイルの削除には成功するが、ディレクトリ自体の `rmdir` システムコールで `ERROR_ACCESS_DENIED` (`EPERM`) を発生させる。
2. **Vite のキャッシュ無効化判定とデッドロック**:
   - Vite は `_metadata.json` が欠落・不完全な場合に古いキャッシュの削除（`await fsp.rm(depsCacheDir)`) を試みる。
   - 上記 1 の制約により削除が失敗して Vite がクラッシュするため、起動不能ループ（デッドロック）が発生する。
3. **server-manager の単発プロセス強制終了**:
   - `server-manager.ps1` の `Stop-FrontendProcess` が `Stop-Process -Force` でポートリッスン中の PID（`node.exe`）のみを単発終了していたため、親の `cmd.exe` や子プロセス（esbuild等）が存続してファイルロックを残したり、Vite の依存関係最適化中の途中終了により `_metadata.json` が欠落しやすい状態となっていた。

---

## 3. アーキテクチャ設計・改修方針

### 方針 1: Frontend (Vite) 自律回復機構 (`frontend/vite.config.ts`)
- Vite の設定ファイル評価時（`vite.config.ts` の読み込み直後、Vite 内部のキャッシュ検証ルーチンが走る前）に、以下の事前サニタイズを実行する：
  1. `node_modules/.vite/deps` が存在する場合、`fs.chmodSync(depsDir, 0o777)` で Windows の `R` 属性を解除する。
  2. `deps/_metadata.json` が存在しない（空洞化または破損状態）場合、`fs.rmSync(depsDir, { recursive: true, force: true })` で安全に空フォルダを除去する（`chmodSync` 後なので `rmdir` が成功する）。
  3. 過去に失敗して残留した `deps_temp_*` 一時ディレクトリ群についても、同様に書き込み権限を付与してクリーンアップする。
- **効果**:
  - `server-manager` 経由だけでなく、エンジニアがコンソールから `npm run dev` や `npx vite`、`vitest`、`npm run build` を直接実行した場合でも、100% 確実に自動回復して正常起動する。

### 方針 2: server-manager プロセスライフサイクルと起動前クリーンアップの堅牢化 (`tools/server-manager/server-manager.ps1`)
1. **プロセスツリー終了 (`taskkill /T /F`)**:
   - `Stop-PortProcesses` において、単一プロセスの `Stop-Process -Force` だけでなく、`taskkill.exe /PID $p /T /F` を併用して対象プロセスおよびその配下のすべての子プロセス（`cmd.exe`, `node.exe`, `esbuild.exe` 等）をツリーごと確実に強制終了し、ファイルハンドルを完全解放する。
2. **起動前ディレクトリ属性解除 (`Start-FrontendProcess`)**:
   - Frontend プロセス起動直前に、PowerShell 側でも `frontend/node_modules/.vite` 配下の `ReadOnly` 属性ビットをチェック・解除し、空洞化した `deps` ディレクトリが存在する場合は先行削除する。

## 5. トレードオフ・リスク開示 (Trade-off Disclosure)

1. **Vite 起動時のごくわずかなオーバーヘッド**:
   - `vite.config.ts` でのディレクトリ存在確認および `chmodSync` により数ミリ秒未満の処理が発生するが、Vite 本体のビルド/バンドル処理（数百ms〜数秒）と比較して完全に無視できる範囲である。
2. **正常キャッシュの保護**:
   - `_metadata.json` が正常に存在する場合は `fs.rmSync` を実行せずキャッシュを維持するため、毎起動ごとのフルリビルドが発生するようなパフォーマンス低下は生じない。
3. **taskkill コマンドの依存性**:
   - `taskkill.exe` は Windows 標準の OS コマンド（`System32` 配下）であり、追加のツールインストール等は不要である。
